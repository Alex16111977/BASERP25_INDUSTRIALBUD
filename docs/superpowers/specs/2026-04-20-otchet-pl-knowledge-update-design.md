# Spec: Обновление knowledge для NotebookLM по А_ОтчетPL

Дата: 2026-04-20
Контекст: после правки сегодня в `Reports/А_ОтчетPL/` (новый СКД-параметр `ВключатьДочерние`) — обновить knowledge-базу так, чтобы NotebookLM правильно отвечал на вопросы про этот отчёт.

## Цель

NotebookLM сейчас не знает про А_ОтчетPL вообще (ни один из 8 текущих сорсов не покрывает этот отчёт). Нужен focused single-topic сорс, который даст полное понимание архитектуры, параметров, вариантов СКД и build-pipeline отчёта.

## Решение

### 1. Новый файл `_Rarzrabotki/notebook/knowledge/a_otchet_pl_overview.md`

Compact (~10 KB), focused для NotebookLM. Структура:

- **TL;DR** — 1 параграф: что отчёт делает, кто пользователь (фин), какая боль решается.
- **Архитектура запроса** — 4 источника (Документ.А_ОтчетPL, ПрочиеРасходы, ФинансовыеРезультаты+ПрочиеДоходы, А_ДвиженияДенегИзКазны), 7 CTE (без АДР-паритет деталей — на это есть `a_otchet_pl_adr_parity.md`).
- **Параметры СКД** — `Период` (StandardPeriod), `ВключатьДочерние` (Boolean, default=Ложь). Что фильтрует ВД (только `втPL`), что НЕ фильтрует (ЕРП-/Казна-блоки), почему такое разделение.
- **3 варианта СКД** — `Основной`, `А_ОтчетPL_РасшифровкаДокументаОтчетPL` (default ВД=Ложь), `А_ОтчетPL_РасшифровкаПоНаправлению` (default ВД=Истина).
- **Документная иерархия ЦО vs СВОД** — атрибут `Документ.ВключатьДочерние` маркирует одно из двух; СКД-параметр `ВключатьДочерние` выбирает какие документы показывать.
- **Кейс «097 vs 096 Производство»** — пример задвоения, как параметр решает.
- **Build/deploy** — путь `_Rarzrabotki/build/А_ОтчетPL/`, `db-load-xml -Mode Partial -UpdateDB`.
- **Anti-patterns** — 5-6 пунктов: не менять настройки вариантов из ИИ; не использовать отбор `Документ` через ПользовательскиеНастройки (ЕРП/Казна не имеют поля Документ); не использовать ВД как поле в ТЗ (ЕРП/Казна без связи с PL получат NULL); и т.д.
- **Cross-ref** — на `a_otchet_pl_adr_parity.md` (детали АДР-паритета), `pnl_pipeline_architecture.md` (pipeline), `report_open_from_form.md` (паттерн открытия).

### 2. Patch существующих knowledge-файлов

- `a_otchet_pl_adr_parity.md`: добавить раздел «СКД-параметр ВключатьДочерние» (~30 строк) после раздела «Структура вариантов СКД» (~стр.625).
- `pnl_pipeline_architecture.md`: краткое упоминание (1 параграф) что в отчёте теперь СКД-параметр для разделения ЦО/СВОД.
- `KNOWLEDGE_MAP.md`: добавить запись о новом файле в индекс.

### 3. Загрузка в NotebookLM

Через `mcp__notebooklm-studio__notebook_add_text` с `notebook_id="3303acdb-2d7f-4879-9f13-78705ab3fb8c"` загрузить содержимое `a_otchet_pl_overview.md` как 9-й сорс. Title: `a_otchet_pl_overview` (без .md). Не трогать существующие 8 сорсов.

### 4. Обновить memory `notebooklm_integration.md`

- Поднять счётчик источников: 8 → 9
- Добавить пункт 9: `a_otchet_pl_overview.md — custom report А_ОтчетPL: architecture, SCD parameters, variants, ВключатьДочерние filter logic`

## Acceptance criteria

1. Файл `a_otchet_pl_overview.md` создан, проходит markdown lint (нет битых ссылок, корректные заголовки).
2. NotebookLM содержит 9 сорсов (проверить через `mcp__notebooklm-studio__notebook_get` или `source_list_drive`).
3. Тестовый запрос к NotebookLM: «Как фильтрует параметр ВключатьДочерние в А_ОтчетPL?» — ответ должен сослаться на новый сорс и описать что фильтрует только PL-часть.
4. `KNOWLEDGE_MAP.md` содержит запись о новом файле.
5. `notebooklm_integration.md` обновлён.

## Out of scope

- Не трогать существующий `a_otchet_pl_adr_parity.md` контент (только добавить раздел про СКД-параметр).
- Не переписывать другие knowledge-файлы кроме перечисленных.
- Не менять настройки вариантов СКД в Template.xml (это ручная работа пользователя в Конфигураторе).
