# Дизайн: домиковый режим «Загрузки выполнения» — проект IRS (6 домов) в BaseERP

Дата: 2026-07-17. Статус: одобрено пользователем (чат). Продолжение
`2026-07-10-zagruzka-vypolneniya-vrm-razr-design.md` — та же обработка
«Загрузка А_ВыполнениеРаботМодулей» (`_Rarzrabotki/А_ПланФактныйПроизводствоПолный/По часам/`).

## Цель

Загрузить выполнение проекта IRS из
`_Rarzrabotki/Загрузка СС/Виробництво/ЗВіт  виконання IRS 15 м.кв..xlsx`
в **BaseERP** (решение пользователя): по листу-снимку «ЗВіт 10.07» создать и провести
**6 документов** `А_ВыполнениеРаботМодулей` от 10.07.2026 9:00 — по одному на каждый
домик-подразделение «МД IRS 2026 15 м №1…№6».

## Проверенные факты (разведка)

- СС «МД IRS 2026 15 м (МД IRS 2026)»: в обеих базах, 44 работы, Σплан 673.96 ч;
  реквизит **`КоличествоДомов` = 6** (без префикса А_; уже сохранён пользователем в обеих базах);
  `А_КоличествоМодулей` = 0 (BaseERP). У СС ВООЗ `КоличествоДомов = 1` → дискриминатор
  «>1» не задевает старое поведение.
- Подразделения-домики №1…№6 — **дети** подразделения СС «МД IRS 2026 15 м (МД IRS 2026)»
  в справочнике СтруктураПредприятия (обе базы); номер — в наименовании после «№».
- Excel: лист **«ЗВіт 10.07»** (БЕЗ скобок, без года); колонка факта уехала в **H**
  (заголовок «Факт виконання робіт по проекту  6 модулів»), т.к. добавилась колонка D.
  Проценты общие на все домики: «6 МОДУЛІВ 100%» (Нарізання деталей), «6 МОДУЛІВ 40%»
  (Збирання деталей), «в роботі»/пусто → нули. Лист «Зразок» не грузится.
- Документов ВРМ по СС IRS: 0 в обеих базах.

## Решение (подход A — одобрен)

**«Номер модуля = номер домика».** Ключ РС `А_ПроцентыВыполненияМодулей` — СС×Работа×НомерМодуля
(подразделения в нём нет): при НомерМодуля=k ключи домиков не пересекаются → дельты и
повторные снимки корректны; РН `А_ВыполнениеРаботМодулей` получает разрез
Подразделение=домик. Конфигурация не меняется — только обработка.

Отклонены: B (один документ с 6 модулями — нет разреза по домикам, противоречит требованию);
C (6 отдельных СС — дублирование плана и НСИ).

## Доработки обработки

### 1. Чтение Excel (клиент формы + smoke симметрично)
- Фильтр листов: имя начинается со «звіт» (НРег) И не равно голому «звіт»
  (покрывает «ЗВіт (19.06)» и «ЗВіт 10.07»; «Зразок» отсекается).
- Колонка факта: поиск в строке 1 заголовка, содержащего «факт виконання робіт» (НРег);
  не найден → колонка G (обратная совместимость ВООЗ). Важно: в IRS есть колонка F
  «Факт виконання» (другая!) — ключ поиска обязан включать «робіт».

### 2. Дата листа (`РазобратьДатуЛиста`)
Скобочный формат «(дд.мм)», затем fallback: первый пробельный токен имени, разбираемый
как «дд.мм» («ЗВіт 10.07» → 10.07.Год 9:00). Общий разбор «дд.мм» — одна функция.

### 3. Движок (`ЗагрузитьВыполнениеИзДанных`)
Дискриминатор: `СС.КоличествоДомов > 1` → домиковый режим:
- N = КоличествоДомов; проценты листа парсятся на N позиций (парсер не меняется);
- `ПодразделенияДомиков`: дети СС.Подразделение, номер из наименования после «№»;
  отсутствие любого k из 1..N — ошибка, пакет откатывается;
- на лист-дату × домик k: get-or-create по **СС + Подразделение_k + день**;
  шапка: Подразделение=домик_k, КоличествоМодулей=N;
  ТЧ: на каждую сопоставленную работу ОДНА строка — НомерМодуля=k,
  ПланЧасыМодуля=План/N, Процент=проценты[k−1], ЧасыВыполнение=План/N×%/100;
- проценты листа парсятся один раз на лист (не 6 раз); сообщения «не найдена в СС» — один раз;
- фикс А_КоличествоМодулей (0→параметр) — ТОЛЬКО в обычном режиме; в домиковом СС не меняется.

Обычный режим (КоличествоДомов ≤ 1) — поведение прежнее; `НайтиДокументСнимка` получает
опциональное условие по Подразделению (Неопределено → без условия, как раньше).

### 4. Rule #-1
Новые запросы (дети подразделения; поиск дока с Подразделением) — сперва Python COM на BaseERP.

## Ограничения (осознанные)

- Информационный шум: при проведении документа домика модуль документа предупреждает
  «в снимке отсутствуют работы/модули предыдущего снимка» — срез РС по СС видит ключи
  соседних домиков. Не отказ, на дельты не влияет (ключи не пересекаются).
- Разбивки процентов по конкретным домикам в Excel нет — «6 МОДУЛІВ 40%» означает все
  шесть по 40%; если появится частичная разбивка («2 будинки --100%…»), сегментный парсер
  разложит её по домикам №1..№N последовательно — как и для модулей ВООЗ.
- Год по-прежнему один на файл (параметр формы, 2026).
