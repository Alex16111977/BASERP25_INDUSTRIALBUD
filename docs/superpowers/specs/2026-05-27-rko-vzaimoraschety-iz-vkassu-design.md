## 1. Цель

При проведении `РасходныйКассовыйОрдер` (РКО) с заполненной ссылкой `Ведомость` типа `Документ.ВедомостьНаВыплатуЗарплатыВКассу` — заполнять регистр накопления `А_ВзаиморасчетыССотрудниками` **в разрезе подразделений** на основе ТЧ `ВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам` (а не из типовой ТЧ `РКО.ВыплатаЗаработнойПлаты`).

**Также:** одноразовый фикс — смена Кассы в ВКассу 000Ц-000009 на «2 Касса Спецтехника» (чтобы матчить РКО N0000052986), подбор ведомости в РКО и проведение.

---

## 2. Эталон: где уже реализовано в проекте

Регистр `А_ВзаиморасчетыССотрудниками` имеет 3 источника заполнения в `AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl`:

| Процедура | Источник | Подразделение |
|---|---|---|
| `ЗаполнитьИзОтраженияЗП` | ТЧ.НачисленнаяЗарплатаИВзносыПоФизлицам.ПодразделениеПредприятия + 2 свёртки | Из строки ТЧ (СтрПредпр) |
| `ЗаполнитьИзСписанияБезнал` | СБДС.РасшифровкаПлатежа → ВКассуВБанк → РН.ЗарплатаКВыплате | Из шапки СБДС.Подразделение (СтрПредпр) |
| `ЗаполнитьИзРКО` (текущая) | ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации | Из шапки РКО.Подразделение (СтрПредпр) |

Структура регистра:
- Измерения: Организация, ФизическоеЛицо, **Подразделение (Справочник.СтруктураПредприятия)**
- Ресурс: СуммаВзаиморасчетов
- Регистраторы: РКО, ПКО, СБДС, ОтражениеЗПвФинУчёте, ПостБезналДС

## 3. Изменение в `ЗаполнитьИзРКО` (ManagerModule регистра)

### Стратегия

Развилка по типу `ДокОбъект.Ведомость`:
- Если заполнена И тип = `Документ.ВедомостьНаВыплатуЗарплатыВКассу` → **новая логика** (источник = ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам)
- Иначе → **старая логика** (ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации) — без изменений

Это даёт обратную совместимость для существующих РКО, проводимых без ссылки на нашу ВКассу.

### Новый код (внутри `Процедура ЗаполнитьИзРКО`)

```bsl
// Развилка: если Ведомость = наша ВКассу → берём из А_Расшифровки
ЭтоНашаВКассу = Ложь;
Если ЗначениеЗаполнено(ДокОбъект.Ведомость) Тогда
    Попытка
        ЭтоНашаВКассу = (ТипЗнч(ДокОбъект.Ведомость) = Тип("ДокументСсылка.ВедомостьНаВыплатуЗарплатыВКассу"));
    Исключение
        ЭтоНашаВКассу = Ложь;
    КонецПопытки;
КонецЕсли;

Запрос = Новый Запрос;
Запрос.УстановитьПараметр("Док", ДокОбъект.Ссылка);

Если ЭтоНашаВКассу Тогда
    // НОВАЯ логика: источник = ВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.
    // Подразделение: ПодрОрг → СтрПредпр (через Рш.Подразделение.Подразделение).
    // Подразделение в шапке РКО игнорируем — берём реальное из строки А_Расшифровки.
    Запрос.Текст =
    "ВЫБРАТЬ
    |    Д.Организация КАК Организация,
    |    Рш.Подразделение.Подразделение КАК Подразделение,
    |    Рш.ФизическоеЛицо КАК ФизическоеЛицо,
    |    ЗНАЧЕНИЕ(ВидДвиженияНакопления.Расход) КАК ВидДвижения,
    |    СУММА(Рш.КВыплате) КАК СуммаВзаиморасчетов
    |ИЗ
    |    Документ.РасходныйКассовыйОрдер КАК Д
    |        ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.ВедомостьНаВыплатуЗарплатыВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам КАК Рш
    |            ПО Рш.Ссылка = Д.Ведомость
    |ГДЕ
    |    Д.Ссылка = &Док
    |СГРУППИРОВАТЬ ПО
    |    Д.Организация, Рш.Подразделение.Подразделение, Рш.ФизическоеЛицо
    |ИМЕЮЩИЕ СУММА(Рш.КВыплате) <> 0";
Иначе
    // СТАРАЯ логика (без изменений)
    Запрос.Текст =
    "ВЫБРАТЬ
    |    Д.Организация КАК Организация,
    |    Д.Подразделение КАК Подразделение,
    |    ТЧ.ФизическоеЛицо КАК ФизическоеЛицо,
    |    ЗНАЧЕНИЕ(ВидДвиженияНакопления.Расход) КАК ВидДвижения,
    |    СУММА(ТЧ.Сумма) КАК СуммаВзаиморасчетов
    |ИЗ
    |    Документ.РасходныйКассовыйОрдер КАК Д
    |        ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.РасходныйКассовыйОрдер.ВыплатаЗаработнойПлаты КАК ТЧ
    |            ПО ТЧ.Ссылка = Д.Ссылка
    |ГДЕ
    |    Д.Ссылка = &Док
    |    И Д.ХозяйственнаяОперация В (
    |        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыЧерезКассу),
    |        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыРаздатчиком),
    |        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыРаботнику))
    |СГРУППИРОВАТЬ ПО
    |    Д.Организация, Д.Подразделение, ТЧ.ФизическоеЛицо
    |ИМЕЮЩИЕ СУММА(ТЧ.Сумма) <> 0";
КонецЕсли;

Результат = Запрос.Выполнить().Выгрузить();
// ... (остаток процедуры без изменений — цикл по Результат + Запись.Добавить())
```

### Ключевая фишка — закрытие в разрезе подразделений

В шапке РКО Подразделение **одно** (например «Спецтехника»). Но в ТЧ.А_Расшифровка строки могут содержать **разные подразделения** (Производство, Глобино-2, ЦО и т.д.). Новая логика создаёт **N движений** регистра — по одному на каждое уникальное `(Орг, СтрПредпр, ФЛ)`. Это и есть «закрытие в разрезе подразделений».

## 4. Одноразовый фикс эталона

ВКассу 000Ц-000009 имеет `Касса = «Касса ЗП»`, РКО N0000052986 имеет `Касса = «2 Касса Спецтехника»` — типовой фильтр выбора ведомости в РКО не находит её.

**Действия:**

1. **Сменить Кассу в ВКассу 000Ц-000009** на «2 Касса Спецтехника» через Python COM:
   ```python
   vk.Касса = erp.Справочники.Кассы.НайтиПоНаименованию("2 Касса Спецтехника", True)
   vk.ОбменДанными.Загрузка = True  # не запускаем типовые проверки
   vk.Записать(erp.РежимЗаписиДокумента.Запись)
   ```

2. **Установить РКО.Ведомость и провести:**
   ```python
   rko.Ведомость = vk_ref
   rko.Записать(erp.РежимЗаписиДокумента.Проведение)
   ```

3. **Проверить движения А_ВзаиморасчетыССотрудниками:**
   - Кол строк = число уникальных (Сотр, СтрПредпр) в А_Расшифровке
   - Σ СуммаВзаиморасчетов = 348 800
   - Все ВидДвижения = Расход

**НЕ меняем алгоритм определения кассы в Ф2-кнопке** — пользователь явно указал «одноразово».

## 5. Поведение

| Сценарий | Результат |
|---|---|
| РКО проведён без `Ведомость` или с обычной ВКассу (не наша) | Старая логика: ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации, Подразделение из шапки РКО |
| РКО проведён с `Ведомость = наша ВКассу` (тип `Документ.ВедомостьНаВыплатуЗарплатыВКассу`) | НОВАЯ логика: А_Расшифровка ВКассу → N движений per (Орг, СтрПредпр, ФЛ), Σ КВыплате |
| ВКассу.Касса ≠ РКО.Касса | Типовой фильтр блокирует подбор. Пользователь либо меняет кассу в ВКассу, либо меняет в РКО, либо нажимает «Подобрать вручную». |

## 7. Тестирование

### 7.1 Python COM `test_rko_vzs_iz_vkassu.py`

Сценарий:
1. РКО N0000052986 (Σ=348 800), ВКассу 000Ц-000009 (Σ=348 800, 31 строка А_Расшифровки)
2. Сменить ВКассу.Касса → «2 Касса Спецтехника»
3. Установить РКО.Ведомость = ВКассу
4. Провести РКО
5. Запросить движения регистра `А_ВзаиморасчетыССотрудниками` по `Регистратор = РКО.Ссылка`
6. Проверки:
   - `Σ СуммаВзаиморасчетов = 348 800` (совпадает с Σ КВыплате)
   - Все `ВидДвижения = Расход`
   - Кол строк = кол уникальных (Сотр, СтрПредпр, ФЛ) в А_Расшифровке
   - У каждой строки `Подразделение` — это СтрПредпр (тип `Справочник.СтруктураПредприятия`)
7. Откат (опционально): распровести РКО, очистить РКО.Ведомость, вернуть ВКассу.Касса

### 7.2 Регрессия

Существующие тесты Ф2/ОтражениеЗП не задеты (мы расширяем процедуру `ЗаполнитьИзРКО`, не меняя старую ветку). Прогнать smoke для уверенности:

- ✅ В `AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl` процедура `ЗаполнитьИзРКО` имеет ветку для случая `Ведомость = наша ВКассу`.
