## 0. Зачем этот документ

Текущая логика — монолитная функция `СформироватьЗапросСверткиБаланса()` (длинная цепочка ВТ `втРасчКл/втРасчПост/втСебест/втДенБ/втДенН/втРегПАП/втОБ/втЗПСальдо/втЗПФЛ/втЗПОрг` + 3-частинний `ОБЪЕДИНИТЬ ВСЕ`). Один запрос трудно сопровождать, отлаживать и тестировать постатейно; `Source` инферится CASE-ом по приоритету матча регистра.

Требуется **модульная** логика по образцу `_Rarzrabotki/ERP_Pyramida/Documents/А_Баланс` (оркестратор + функция на источник) и зеркально штатной `Обработка.ДвиженияАктивовПассивов` (которая САМА строит `РегистрНакопления.ПрочиеАктивыПассивы` из регистров-источников). Каждый источник — отдельная процедура с запросом; взаиморасчёты клиенты+поставщики — одна процедура. Идея сверки: ПАП-остаток ↔ Σ расшифровки по регистрам; Σ по ПАП в проведённом регистре совпадает ВСЕГДА, расшифровка обрезается/добивается, расхождения помечаются.

Код **не правится** этим документом — это дизайн. Реализация — отдельным циклом writing-plans.

## 1. Изученное (факты, на которых строится дизайн)

### 1.1 Эталон `ERP_Pyramida/А_Баланс` (`Ext/ObjectModule.bsl`, 3139 строк)
- `ОбработкаПроведения` → `СтруктураШапкиДокумента {Ссылка,Дата,Дата1=НачМес,Дата2=КонМес,Организация}` → `ПровестиБалансУпр(...)`.
- `ПровестиБалансУпр` — оркестратор: `НаборДвижений.Выгрузить()`/`.Очистить()` → последовательно вызывает `Упр_СебестоимостьТоваров`, `Упр_ДенежныеСредства`, `Упр_РасчетыСКлиентами`, `Упр_РасчетыСПоставщиками`, `Упр_ПрочиеАктивыПассивы` и т.д. → `свернуть` → `НаборДвижений.Загрузить`.
- Каждая `Функция Упр_<X>(СтруктураШапки,Отказ) Экспорт` строит свой `Запрос` и через `Отразить_А_БалансУпр(Запрос.Выполнить().Выгрузить())` дописывает строки в общую `ТаблицаДвижения`.
- `Отразить_А_БалансУпр(Таблица)` — хелпер: `Для каждого … ЗаполнитьЗначенияСвойств(ТаблицаДвижения.Добавить(), СтрокаТЗ)`.

### 1.2 Штатная `Обработка.ДвиженияАктивовПассивов` (`DataProcessors/ДвиженияАктивовПассивов/Ext/ManagerModule.bsl`, 4856 строк)
- `ОтразитьДокументыВУправленческомБалансе` — строит `РегистрыНакопления.ПрочиеАктивыПассивы` **по регистратору ИЗ регистров-источников** через `ЗапросДвижений`.
- `БалансовыеРегистры()` → структура источников из `Перечисление.ИсточникиУправленческогоБаланса` (минус исключения; `РасчетыСКлиентами/Поставщиками` исключены в пользу `*ПоСрокам`/`*ПоДокументам` по ФО `НоваяАрхитектураВзаиморасчетов`).
- ~20 процедур `ДобавитьТекстЗапроса<Источник>` — каждая из своего регистра-источника формирует движения с `ЗНАЧЕНИЕ(Перечисление.ВидыИсточниковДвижений.ДвиженияБаланса) КАК ВидИсточника` и `&Источник` = конкретное значение `ИсточникиУправленческогоБаланса`.
- Есть собственный контроль: `ДобавитьТекстЗапросаВременныхТаблицКонтроляБаланса` → ВТ `КонтрольБаланса`: `СУММА(СуммаБаланса) ИМЕЮЩИЕ <> 0` по регистратору (двойная запись = 0 на документ).
- `ЗапросДвижений` фильтр: `НЕ Т.ВидИсточника В (&ВидОтложенногоРасчета, ЗНАЧЕНИЕ(Перечисление.ВидыИсточниковДвижений.РасчетБаланса))` — исключает отложенный/пересчётный слой, чтобы не задвоить.
- **Вывод:** ПАП ДЕРИВИРОВАН из источников ⇒ Σ расшифровки == ПАП **по построению**. Расхождения = edge-cases (ВводОстатков, ручные `ДвижениеПрочихАктивовПассивов`, закрытие П&У, онлайн-расчёты, округление).

### 1.3 Структура `РегистрНакопления.ПрочиеАктивыПассивы` (get_metadata_structure, 2026-05-16)

## 2. Проектные решения (DR-1 … DR-13) — одобрены пользователем

| # | Решение | Обоснование |
|---|---|---|
| **DR-1** | Декомпозиция **по регистру-источнику** (зеркало `ДвиженияАктивовПассивов`), НЕ по статье. Взаиморасчёты клиенты+поставщики — одна процедура. | Один источник питает несколько статей; ПАП так и строится ⇒ Σ==ПАП по построению. |
| **DR-2** | Суммы и `Источник` — из **ОСНОВНОЙ таблицы** `РегистрНакопления.ПрочиеАктивыПассивы` (не `.ОстаткиИОбороты`). НачОст=Σ signed до НачМес, Приход/Расход в периоде, КонОст=НачОст+Приход−Расход. | `Источник`/`ВидИсточника` — реквизиты, нет в виртуальных таблицах. Зеркало стандарта. |
| **DR-3** | `Source`: перетипизировать `Перечисление.А_ИсточникБаланса` → **`Перечисление.ИсточникиУправленческогоБаланса`**; кастомный `А_ИсточникБаланса` **удалить** (дубль). Значение = `ПАП.Источник` напрямую (без CASE). | Штатный маппинг уже на каждом движении ПАП. |
| **DR-4** | Новое измерение **`Расхождение` (Булево)** в `А_ОтчетБаланс_Свод`. | Помечает строки, где ПАП≠расшифровка / `Источник=""` / обрезка. |
| **DR-5** | Сверка per (Орг,Подр,Статья): расшифровка > ПАП → **пропорционально обрезать** строки коэф. `ПАП/Σрасшифр` (Σ-сохраняющий разнос); ПАП > расшифровки → **1 строка-добивка** на разницу с пустой аналитикой. Обе → `Расхождение=Истина`. Совпало → `Расхождение=Ложь`. | Σ==ПАП всегда; расшифровка не ломает баланс. |
| **DR-6** | Сверка по **каждому из 4 ресурсов** на гранулярности (Орг,Подр,Статья); допуск 0.01, «Оплата труда» 1.0. | Все 4 ресурса хранятся и используются downstream. |
| **DR-7** | `ВидИсточника` используется для отбора слоёв движений (первичный `ДвиженияБаланса` + рабочие; исключая `РасчетБаланса`/отложенный), чтобы Σ источника не задвоилась и == ПАП.ОстаткиИОбороты. **Точный набор `ВидИсточника` валидируется Rule #-1 Python COM пре-тестом** в реализации. | Стандарт исключает `РасчетБаланса`+отложенный; эмпирика показала 4 слоя. |
| **DR-8** | `ДокументДвижения` (уже добавлено финансистом) заполняется = `ПАП.Регистратор` (документ-первоисточник). | Drill-down к первичному документу. |
| **DR-9** | Сохраняются: фильтр OD-3 (исключение `Собственные средства`/`Доходы текущего периода`/`Расходы текущего периода`, closed-period-safe); Етап-4 «Оплата труда» — разнос по `ФизическоеЛицо` ∝ \|сальдо\| `ВзаиморасчетыССотрудниками` (отдельная процедура `Свод_ОплатаТруда`). | Канон v1.4 OD-3/Етап4; не регрессировать. |
| **DR-10** | Инвариант: Σ `СуммаКонечныйОстаток` по `Статья` == `ПАП.ОстаткиИОбороты` (тот же baseline, что штатный `Отчёт.УправленческийБаланс`) до копейки; Σ КонОст набора ≈ 0 (Актив=Пассив, закрытый период). | Acceptance v1.4 не меняется. |
| **DR-11** | Единый `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl`, логически разбит на `#Область` (как эталон `А_Баланс` и текущий код). | Документ-уровневая логика живёт в ObjectModule. |
| **DR-12** | Типовые регистры/обработки — **только чтение** (`ПрочиеАктивыПассивы`, `РасчетыС…ПоСрокам`, `СебестоимостьТоваров`, `ДенежныеСредства*`, `ВзаиморасчетыССотрудниками`, `ДвиженияАктивовПассивов`). Структуру `А_ОтчетБаланс_Свод`/enum правит **финансист вручную** (список — §3). | Канон §10; авторизация финансиста. |
| **DR-13** | OLAP downstream (`refresh_mapping`, `Fact_Balance` DDL: `Source`→ref нового enum, `+Расхождение bit`, `+ДокументДвижения`; `PL.pbix`) — **отдельный цикл после стабилизации 1С**. | Канон §10 YAGNI. |

## 5. Алгоритм `СверкаСПАП` (ядро идеи пользователя)

1. **Эталон** `ЭталонПАП`: `ПрочиеАктивыПассивы.ОстаткиИОбороты(&НачМес, КонецДня(&КонМес), Авто, , (орг+ВключатьДочерние) И НЕ Статья В ИЕРАРХИИ(&ИсключённыеСтатьи))`, сгруппировано по (Организация, Подразделение, Статья), 4 ресурса. Тот же ПАП-источник, что штатный `Отчёт.УправленческийБаланс` → acceptance-safe.
2. **Расшифровка** = `ТЗНакопитель`, свёрнутая по (Орг,Подр,Статья), 4 ресурса.
3. Полное соединение Эталон ⟗ Расшифровка по (Орг,Подр,Статья). По каждому из 4 ресурсов независимо, допуск `0.01` (для статьи «Оплата труда» — `1.0`):
   - **|Σрасшифр| > |ПАП|** (расшифровка превышает): коэффициент `k = ПАП / Σрасшифр` (по ресурсу); умножить ресурс всех строк расшифровки этой (Орг,Подр,Статья) на `k`; остаток округления добросить в наибольшую строку (Σ-сохранение до копейки); пометить `Расхождение=Истина`.
   - **|ПАП| > |Σрасшифр|** (ПАП больше): добавить 1 строку (Орг,Подр,Статья) с пустой аналитикой (все *_ID = ПустаяСсылка, Аналитика1/2/3=""), `Source` = доминирующий `Источник` статьи или НЕОПРЕДЕЛЕНО (для `Источник=""`), ресурс = (ПАП − Σрасшифр), `Расхождение=Истина`.
   - **Совпало** → строки как есть, `Расхождение=Ложь`.
4. **Пост-инвариант (жёсткий, проверяется тестом):** после `СверкаСПАП` Σ по (Орг,Подр,Статья) каждого ресурса == `ЭталонПАП` до копейки. Σ `СуммаКонечныйОстаток` всего набора ≈ 0 (Актив=Пассив, закрытый период). Иначе — регресс, откат.

> Источник="" движения ПАП попадают как нераспознанная расшифровка → либо своя процедура `Свод_ПрочиеАктивыПассивы_Прямой` (субконто из ПАП.Аналитика), либо чистая добивка (п.3 «ПАП больше») с `Расхождение=Истина`.

## 6. Acceptance, тесты (Rule #-1), регресс

- **Пер-источник Python COM пре-тест** (`_Rarzrabotki/Python/test/test_balans_src_<X>.py`): запрос 1:1 как в BSL; assert: rows>0; `КонОст ≈ НачОст+Приход−Расход` (0.01); ≤1 строка субконто на ключ; границы периода серверно (1С `НачалоПериода/КонецПериода`, не Python-наивные).
- **Acceptance (январь 2026 / ТОВ ІНДАСТРІАЛБУД):** Σ `СуммаКонечныйОстаток` по `Статья` в `А_ОтчетБаланс_Свод` == `ПАП.ОстаткиИОбороты` до копейки (ОТ 1.0); Σ КонОст ≈ 0 (Актив=Пассив). Контрольная по всем орг — 289 064 974,43.
- **Сверка со штатным `Отчет.УправленческийБаланс` (требование пользователя, основной acceptance-gate):** отдельный Python COM тест `_Rarzrabotki/Python/test/test_balans_vs_upr_balance_report.py` — программно выполнить штатный `Отчет.УправленческийБаланс` (СКД, `КомпоновщикНастроек` через `ПолучитьМакетКомпоновкиДанных`/`ПроцессорКомпоновкиДанных`) за тот же период/организацию (январь 2026/ТОВ), извлечь итоги по `Статья` (СуммаКонечныйОстаток / Актив-Пассив-секции), и сравнить с Σ по `Статья` проведённого `А_ОтчетБаланс_Свод` — **до копейки** (ОТ 1.0). Это сильнее, чем сверка только с `ПАП.ОстаткиИОбороты`: совпадение с фактическим отчётом, который ведёт финансист (тот же ПАП-источник + тот же фильтр исключения 3 групп / вариант «Не в группе из списка»). Точный способ запуска СКД отчёта валидируется Rule #-1 Python COM пре-тестом до написания BSL.
- **Контроль `Расхождение`:** Σ(`Расхождение=Истина`) + Σ(`Расхождение=Ложь`) == ПАП; в норме (январь/ТОВ) `Расхождение=Истина` только по `Источник=""`/добивке.
- **Регресс:** существующий `_Rarzrabotki/Python/test/test_balans_s4_verify.py` остаётся зелёным (тот же инвариант).
- **Идемпотентность:** перепроведение даёт идентичный набор; дублікат-захист не даёт двух документов на (Орг,Месяц,ВключатьДочерние).

## 7. Риски и митигация

| Риск | Митигация |
|---|---|
| Задвоение сумм через слои `ВидИсточника` | DR-7: точный набор `ВидИсточника` фиксируется Rule #-1 пре-тестом (Σ источника == ПАП.ОстаткиИОбороты по его статьям) ДО написания BSL |
