## 1. Задача

Печатная форма «Друк → Аналіз для цеху (з коментарем)» (`СформироватьПечатьАнализЦех`, макет СКД
`МакетАнализЦех`) выдаётся цеху с пустой колонкой «Коментар цеху». Цех вписывает обоснование
понаднормового расхода. Файл возвращается как `.xlsx`
(образец: `C:\Configuration_downloads\BASERP25\_Rarzrabotki\notebook\knowledge_Бухгалтерия_РасчетКомплектаций\Пример\Аналіз залишків для списання за СС.xlsx`).

Нужно:

1. Загрузить из файла **только** `РасчетКомплектаций.СписаниеСверхНормы.Причина`. Ни одна другая
   колонка документа не меняется (количества, суммы, цены, счета, склады — неприкосновенны).
2. Сохранить причины в **отдельной таблице-памяти**, чтобы «Розрахувати» (который очищает ТЧ списания)
   их не терял: после пересчёта причины должны сами подтянуться к номенклатуре, попавшей в
   `СписаниеСверхНормы`.
3. **При копировании документа причины не копируются.**

Бухгалтерский смысл: `Причина` — это обоснование перерасхода, попадающее в печать «Акт на списання
понаднормових матеріалів». Поэтому загрузка обязана быть либо точной, либо явно отказаться: поставить
чужое обоснование в строку хуже, чем не поставить ничего.

неоднозначности уходит в протокол как конфликт.

## 3. Объём изменений

### 3.1 Метаданные

Новая табличная часть `Документ.РасчетКомплектаций.ПричиниЦеху`:

| Реквизит | Тип | Смысл |
|---|---|---|
| `ОбщееНазвание` | `СправочникСсылка.ОбщиеНазванияНоменклатуры` | эталон (группа печати) |
| `Номенклатура` | `СправочникСсылка.Номенклатура` | конкретная позиция; **пусто** = причина уровня эталона |
| `Причина` | Строка 200 (перем.) | текст цеха; длина совпадает с `СписаниеСверхНормы.Причина` |
| `ДатаЗагрузки` | Дата (дата+время) | когда причина попала в документ |

Строки двух видов:
* **по номенклатуре** — `Номенклатура` заполнена (комментарий на нежирной строке файла);
* **по эталону** — только `ОбщееНазвание` (комментарий на жирной строке); работает и для номенклатур,
  которые появятся под этим эталоном при следующем пересчёте.

Ключ уникальности строки хранилища — пара (`ОбщееНазвание`, `Номенклатура`).

### 3.2 Печатная форма «Аналіз для цеху»

В `ДанныеВТаблицуПланФакт` добавляется колонка `Код`:
* для строки-номенклатуры — `Номенклатура.Код` (11 знаков);
* эталонный уровень получает `КодЭталона` = `ОбщееНазвание.Код` (9 знаков) — выводится на строке группы.

В макете `МакетАнализЦех` (строится скриптом `_Rarzrabotki/Python/test/doc_kompl_build_maket_ceh.py`)
добавляется колонка **«Код»** сразу после блока названия, перед «Норма СС». Порядок колонок печати:

```
Загальна назва/Номенклатура · Код · Норма СС · Видано · Одиниця виміру ·
В нормі · В нормі сума · Понад норму · Понад норму сума · Економія · Економія сума · Коментар цеху
```

Постобработка в `СформироватьПечатьАнализЦех` (ширина «Коментар цеху», рамки) ищет колонки по тексту
заголовка — сдвиг переживает без правок.

### 3.3 Движок загрузки (`Ext/ObjectModule.bsl`)

```
Функция ЗавантажитиПричиниЦехуЗФайлу(АдресФайлаУСховищі, ІмʼяФайлу) Экспорт → Структура-протокол
```

Алгоритм:

1. Данные из временного хранилища → временный файл (`ПолучитьИмяВременногоФайла` с расширением
   исходного файла) → `ТабличныйДокумент.Прочитать(ПутьВремФайла)`. Временный файл удаляется в
   `Попытка/Исключение`.
2. Допустимые расширения: `.xlsx`, `.ods`, `.mxl`. `.xls` (старый бинарный) платформа не читает —
   явное сообщение «пересохраніть у .xlsx», загрузка не начинается.
3. Поиск шапки: в первых 30 строках ищем ячейки с текстами `Загальна назва` (первая колонка),
   `Коментар цеху` (колонка комментария), `Код` (колонка кода, может отсутствовать). Нет «Коментар
   цеху» → отказ «це не той файл».
4. Индексы области документа строятся один раз по `ТабличнаяЧастьОстатков`:
   * `КодНоменклатуры → массив ссылок`, `ИмяНоменклатуры → массив ссылок`,
   * `КодЭталона → массив ссылок`, `ИмяЭталона → массив ссылок`.
   Массив длиннее 1 = неоднозначность.
5. Обход строк от строки под шапкой до конца таблицы; строка со значением «Итого» в первой колонке
   завершает обход:
   * `Шрифт.Жирный = Истина` → строка эталона, иначе строка номенклатуры (запоминаем текущий эталон);
   * текст комментария = `СокрЛП` ячейки колонки комментария; **пусто → строка пропускается**
     (существующая причина не затирается);
   * длина > 200 → обрезаем до 200, счётчик `Обрізано`;
   * ссылка ищется: по коду (если колонка кода есть и код найден в индексе), иначе по имени
     (номенклатура — в паре с текущим эталоном); ничего не нашли → счётчик `НеЗнайдено`; нашли больше
     одной → счётчик `Конфлікт`, строка **пропускается**.
6. Результат пишется в `ПричиниЦеху` (upsert по паре ключа, `ДатаЗагрузки = ТекущаяДатаСеанса()`),
   затем вызывается `ЗастосуватиПричиниЦеху()`.
7. Возврат: структура `Всього, Завантажено, Оновлено, БезЗмін, НеЗнайдено, Конфлікт, Обрізано,
   Повідомлення (Массив строк)`.

```
Процедура ЗастосуватиПричиниЦеху() Экспорт
```
Для каждой строки `СписаниеСверхНормы`: причина по номенклатуре (`ОбщееНазвание`+`Номенклатура`)
приоритетнее причины уровня эталона; найденная причина ставится **во все строки этой номенклатуры**
(включая разные склады/счета/организации); пустая причина в хранилище ничего не затирает.

### 3.4 Жизненный цикл

| Точка | Поведение |
|---|---|
| `ЗаполнитьТаблицыСписания()` (конец) | вызов `ЗастосуватиПричиниЦеху()` — «Розрахувати» больше не теряет причины |
| `ПередЗаписью` (после существующих проверок, под тем же guard `ОбменДанными.Загрузка`) | harvest ручных правок: для номенклатур, представленных в `СписаниеСверхНормы`, непустая `Причина` → upsert в `ПричиниЦеху`; если все строки номенклатуры очищены — строка хранилища удаляется. Строки хранилища по номенклатурам, которых сейчас нет в списании, не трогаются |
| `ОбработкаКопирования` (новая) | `ПричиниЦеху.Очистить()` + очистка `Причина` во всех строках `СписаниеСверхНормы` |

### 3.5 Форма документа

* Команда `ЗавантажитиКоментаріЦеху` («Завантажити коментарі цеху»), кнопка в командной панели рядом
  с «Друк»: `ДиалогВыбораФайла(Открытие)` с фильтром `*.xlsx;*.ods` → `ПоместитьФайл` во временное
  хранилище → сервер: `РеквизитФормыВЗначение("Объект")` → `ЗавантажитиПричиниЦехуЗФайлу` →
  `ЗначениеВРеквизитФормы` → `Модифицированность = Истина`; протокол выводится через
  `ОбщегоНазначенияКлиентСервер.СообщитьПользователю`.
* Новая закладка **«Причини цеху»**: ТЧ `ПричиниЦеху` (редактируемая) + локальные кнопки
  «Завантажити з Excel», «Застосувати до списання», «Очистити».
* Правки формы — **только точечный патч** текущего `Form.xml` (генератор `doc_kompl_build_form.py`
  не запускать), uuid обёртки формы сохраняется, id элементов/команд уникальны.

## 4. Границы (что НЕ делаем)

* Не трогаем количества, суммы, цены, счета, склады, организации — ни в `СписаниеСверхНормы`, ни в
  анализе, ни в документах-результатах.
* Не создаём строк в `СписаниеСверхНормы` по файлу: если цех прокомментировал позицию, которой нет в
  понаднорме, причина ложится в `ПричиниЦеху` (пригодится после пересчёта), но строка списания не
  появляется.
* Не вводим общий регистр сведений между документами (решение заказчика: причины живут внутри расчёта).
* Не меняем структуру типовых регистров и типовых объектов.

## 5. Приёмка (Python COM, инварианты)

Скрипт `_Rarzrabotki/Python/test/smoke_zagruzka_prichin_ceh.py`, расчёт-стенд — существующий документ
(get-or-create, без `Удалить()`), файл-образец готовится скриптом из печати самого документа:

1. **Печать** «Аналіз для цеху» содержит колонку «Код»; на строке эталона код 9 знаков, на строке
   номенклатуры — 11.
2. **Загрузка**: в подготовленный xlsx проставлены комментарии (несколько по номенклатуре, один по
   эталону, один по позиции без понаднормы, один длиной > 200 символов) → протокол совпадает с
   ожиданием по счётчикам; `ПричиниЦеху` содержит ожидаемые пары.
3. **Мультисклад**: номенклатура с двумя строками в `СписаниеСверхНормы` получает причину в **обеих**.
4. **Пересчёт не теряет причины**: `РассчитатьАнализ()` → те же строки снова с причинами.
5. **Пустая ячейка не затирает**: повторная загрузка файла с очищенным комментарием оставляет причину.
6. **Копия чистая**: копирование документа → `ПричиниЦеху` пуста и `Причина` пуста.
7. **Конфликт не гадает**: строка-тёзка без кода уходит в счётчик `Конфлікт`, чужая причина не
   проставлена.
8. **Остальные колонки не тронуты**: снимок `СписаниеСверхНормы` (количество/цена/сумма/счет/склад)
   до и после загрузки совпадает.

Тесты — на инвариантах, без зашитых сумм и без удаления документов.

## 6. Риски и грабли

* **Форма «живёт своей жизнью»** (её нормализовал Designer) → только точечные патчи `Form.xml`;
  перед сборкой — проверка уникальности id; uk-подписи парой `ru`+`uk`.
* **Конфигуратор пользователя с открытой базой откатывает загрузку** — перед `db-load-xml`/`db-update`
  проверить процессы `1cv8.exe` и предупредить пользователя.
* **git отстал от живой конфигурации**: `ObjectModule.bsl` в ветке 221 КБ против 363 КБ в основном
  каталоге, `Templates/МакетАнализЦех` вообще не в git. Правим основной каталог; в ветку кладём копии
  только тех файлов, которые трогали.
* **Дубли кодов/имён** — сопоставление ограничено областью документа, остаток идёт в протокол.
* **`.xls`** не читается платформой — явное сообщение пользователю.
