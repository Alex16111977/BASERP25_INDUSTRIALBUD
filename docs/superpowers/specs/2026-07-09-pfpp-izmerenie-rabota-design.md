# Спека: измерение «Работа» в отчёте А_ПланФактныйПроизводствоПолный

Дата: 2026-07-09. Источник задачи: `_Rarzrabotki/Отчеты/ПРОМТ_ИзмерениеРабота_ПланФактПроизводство.md` (основная конфигурация).
Выбор пользователя по развилке структуры: **вариант A** — структуру группировок по умолчанию не менять.

## Цель

В отчёте появляется самостоятельное измерение (разрез) **«Работа»** типа `СправочникСсылка.Номенклатура`,
доступное для группировки и отбора через «Настройки». Сейчас работа видна только внутри составного
измерения «Аналитика» у строк блока «1. Труд» вперемешку с физлицами (табель/ЗП); отдельный разрез
позволяет группировать/отбирать по работе, не смешивая с физлицами.

## Затрагиваемые файлы (исходники — основная конфигурация, зеркалятся в worktree)

- `_Rarzrabotki/Отчеты/А_ПланФактныйПроизводствоПолный/Ext/ObjectModule.bsl` — запрос + постобработки.
- `_Rarzrabotki/Отчеты/А_ПланФактныйПроизводствоПолный/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml` — схема СКД.
- `_Rarzrabotki/Отчеты/А_ПланФактныйПроизводствоПолный.erf` — пересборка.
- Новый Python-тест `_Rarzrabotki/Python/test/test_pfpp_rabota_razrez.py` (query-тест разреза, по шаблону `test_pfpp_kolvo_razrezy.py`).

## Изменения

### 1. Запрос (ObjectModule.bsl, `ПолучитьДанные`, строки ~100–330)

Пакетный запрос, ВТ_Детали собирается из **6 веток UNION ALL** (сопоставление колонок позиционное).
Во все 6 веток добавляется колонка `Работа` **сразу после `Этап`** (перед `ОбщееНазвание`):

| Ветка | Источник | Значение `Работа` |
|---|---|---|
| 1. Труд-план | `Справочник.А_СтруктураСебестоимости.Работы` | `Р.Работа КАК Работа` |
| 2. Материалы-план | `...Комплектующие` | `ЗНАЧЕНИЕ(Справочник.Номенклатура.ПустаяСсылка)` |
| 3. Табель-факт | `РН.А_ДанныеТабелирования` | пустая ссылка |
| 4. ЗП-факт | `РН.А_ВзаиморасчетыССотрудниками` | пустая ссылка |
| 5. Материалы-факт (закупки) | `РН.СебестоимостьТоваров` | пустая ссылка |
| 6. EV-выполнение | `РН.А_ВыполнениеРаботМодулей` | `ВРМ.Работа` |

Финальный SELECT: `ВТ_Детали.Работа КАК Работа` после `Этап` + поле в `СГРУППИРОВАТЬ ПО`.

Регрессия сумм на уровне запроса исключена: у веток 1/6 «Аналитика» уже равна работе
(добавление «Работы» в группировку не дробит строки — функциональная зависимость), у остальных
веток значение константно-пустое — грейн не меняется.

### 2. Постобработки BSL

- `СоздатьПустуюТаблицу()` — колонка `Работа` (`СправочникСсылка.Номенклатура`) после `Этап`.
- `ЗаполнитьПланНаФакт()` — синтетические строки EAC: `СинтСтрока.Работа = ПустаяНоменклатура`
  (переменная уже объявлена в процедуре).
- `ЗаполнитьЭтапФактМатериалов()` — не меняется (мутирует только Этап/Категорию).

### 3. Схема СКД (Template.xml)

Новое поле-измерение после поля `Этап` в наборе «Детали»:

```xml
<field xsi:type="DataSetFieldField">
	<dataPath>Работа</dataPath>
	<field>Работа</field>
	<title xsi:type="v8:LocalStringType"><v8:item><v8:lang>ru</v8:lang><v8:content>Работа</v8:content></v8:item></title>
	<valueType><v8:Type>cfg:CatalogRef.Номенклатура</v8:Type></valueType>
	<role><dcscom:dimension>true</dcscom:dimension></role>
</field>
```

Вариант A: `settingsVariant` («Основной») **не меняется** — структура по умолчанию
Подразделение → Блок → Категория → Этап → ОбщееНазвание → Аналитика → Единица → Документ остаётся.
В `selection` поле не добавляется (в этой схеме измерение колонкой не рендерится — известные грабли).

Правка Template.xml — **Python-скриптом** (файл с табами; Edit-инструменты табы теряют):
assert на ровно одну вставку, после — проверка well-formed (`xml.etree`).

## Процесс (правила проекта)

1. **Rule #-1:** изменённый запрос сначала прогоняется Python-COM на боевой BaseERP
   (`Srvr="SQLSERVER";Ref="BaseERP"`); проверяется: синтаксис, у труд-плана/EV `Работа = Аналитика`,
   у остальных пустая, суммы = суммам старого запроса.
2. Правка BSL и Template.xml → сборка `.erf` через `.claude/skills/epf-build/scripts/epf-build.ps1`
   (V8Path `C:\Program Files\1cv8\8.3.20.1914\bin`, серверная база SQLSERVER/BaseERP; Конфигуратор закрыт).
3. **Smoke после сборки** (COM: `ВнешниеОтчеты.Создать(erf)` → `ПолучитьДанные` → композиция с внешним
   набором «Детали»). Эталоны регрессии (весь период, менять нельзя):
   - СС «МД МХП ОРІЛЬ / СТІЛ МД МХП ОРІЛЬ»: Труд ПланЧасы=2795, ФактЧасы=2389;
     Материалы ФактГрн=1620137.97, ПланНаФактГрн=625675.03;
   - СС «МД Вооз ЕМS Мала 2026 / Цех_МД Вооз ЕМS Мала 2026»: Σ ВиконанняЧасы (блок Труд)=2401.52;
   - новая проверка: композиция ВООЗ с группировкой по «Работа» (блок Труд) — измерение заполнено,
     ВысотаТаблицы>0.
   - Подстраховка от живых данных: при расхождении абсолютов — сравнение старого и нового `.erf`
     на одних данных в одной сессии (diff должен быть нулевым).
4. **Rule #4:** исходники + `.erf` копируются в основную конфигурацию `C:\Configuration_downloads\BASERP25\`
   и в git-worktree; коммит в ветку `claude/*` (сообщение по-русски), push в origin.
5. Пользовательские настройки отчёта программно не предзаполняются. В финальной сводке — предупреждение:
   сохранённый вариант скрывает новые поля, нужно «Ещё → Установить стандартные настройки».
