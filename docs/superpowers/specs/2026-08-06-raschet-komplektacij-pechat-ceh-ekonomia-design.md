## 1. Контекст и постановка

Пользователь экспортировал печать №5 («Аналіз залишків для списання за СС», СКД `МакетАнализССОдна`)
в Excel, вручную убрал сумовые колонки, переименовал «Залишок»→«Видано», добавил пустую колонку
«Коментар цеху» и согласовал макет с Матвием
(`_Rarzrabotki/notebook/knowledge_Бухгалтерия_РасчетКомплектаций/Пример/Аналіз залишків для списання за СС (погодив з Матвієм).xlsx`).
Требуется: (а) добавить такую печатную форму штатной кнопкой; (б) разобраться с полем «Економія» —
«считает некорректно».

**Назначение формы (формулировка пользователя):** печать выдаётся **кладовщику в цех**; по ней он
должен объяснить, почему по позиции вышло «понад норму». Кладовщик работает **только с количеством**
— деньги в форме не нужны. Жёлтая подсветка выделяет именно понаднормовые строки, требующие
объяснения; объяснение пишется от руки в колонку «Коментар цеху».

Эталонный документ диагностики: РасчетКомплектаций **№00000000003** от 03.08.2026
(дом №1, склад «МД IRS 2026 15 м №1 Виробничий») — его цифры совпадают с Excel 1:1
(Разом: Видано 7 975.299 / В нормі 6 183.118 / Понад 1 792.181 / Економія 1 604.067).

## 2. Диагноз «Економія» (бухгалтерский разбор на живых данных дока №3)

Арифметика движка внутренне честная: на эталоне `Економія(кол) = НормаСС(групи) − Σ«В нормі»`,
зеркально к понаднорме (0 нарушений инвариантов). Некорректность — в подаче и в денежной формуле:

| # | Дефект | Пример (док №3) | Решение |
|---|--------|-----------------|---------|
| Д1 | Экономия эталона штампуется на строку-«представителя» и печатается на КАРТОЧКЕ | «Хомут…»: видано 2, економія 12; «Електричний водонагрівач»: видано 1, в нормі 1, економія 1 (жалоба пользователя) — 7 строк | В новой печати економія — **только на строке группы** «загальна назва» |
| Д2 | Норма группы в печати не видна («Згідно з СС» = 0 во всех 174 строках, т.к. читает по-карточную `НормаНоменкл`, а в этой СС 176/186 строк норм без номенклатуры) | «Бойлер: видано 1, економія 1» — числа «не бьются», норму 2 не видно | Колонка **«Норма СС»** (эталонная `Норма`) на строке группы |
| Д3 | `ЕкономіяСума = НормаСум − СуммаОстаткаЭталона` смешивает ценовую и количественную составляющие, клампится в 0 асимметрично | «Гайка»: перевитрата 5 шт, но «економія» 11 906 грн (дешёвый факт); «Саморіз»: економія 1 384 шт, но 0 грн (дорогой факт). Итог 109 073 грн вместо 34 691 грн чистой количественной | Формула в движке: `ЕкономіяСума = Економія(кол) × нормовая цена эталона` (п. 4) |
| Д4 | Эталоны СС без единой выдачи в отчёт не попадают (30 шт, 531 од., ~128.6 тыс грн по дому №1) → «Норма» итога плавает между домами (7 787 / 7 673 / 7 605 при одной СС) | генератор, комплект септика, тепла підлога… | **Решение пользователя: НЕ показывать** (как в Excel). Движок не трогаем |

Пояснение к жалобе «Бойлер: економии быть не может»: в СС «МД IRS 2026 15 м» бойлер — это
**две плановые позиции** (`НоменклатураСС` «Бойлер на 30 л» 1 шт × 5 600 и «Бойлер на 82 л»
1 шт × 9 200), норма группы = 2. Видано 1 → економія 1 корректна против СС; проблема была в
показе на карточке и невидимой норме (Д1+Д2). Подтверждено отчётом
`А_ОтчетПоСписаниюНаПроизводствоБухгалтерский` («по домику»): План 2 / Факт 1 / Відхилення −1 / 50%.

**Данные СС — передать техотделу (кодом не чиним):** 18 строк с `Количество = 0`
(из-за нулевого капа «Жалюзі» уходит в понаднорму при плановой карточке «Набір кілець…»).

## 3. Новая печатная форма (10-я)

**Название/заголовок:** «Аналіз залишків для списання за СС» (заголовок таб-дока — тот же
многострочный `ТекстЗаголовкаЗвіту`: Підрозділ / Залишки на / Склади / Специфікація / Організація).
Кнопка в попапе «Друк» формы документа: **«Аналіз для цеху (з коментарем)»**.

**Только количественные показатели — никаких сумовых колонок (решение пользователя).**

**Структура строк** (как Excel): группа «Загальна назва» → карточки «Номенклатура» с отступом,
в одной колонке. Эталоны без выдачи не показываются. Внизу — строка «Разом».

**Колонки:**

| Колонка | Источник (поле ТЗ `ДанныеВТаблицуПланФакт`) | Группа | Карточка |
|---|---|---|---|
| Загальна назва / Номенклатура | `ОбщееНазвание` / `Номенклатура` | ✓ | ✓ (отступ) |
| Норма СС | `Норма` (эталонный штамп, ресурс Σ) | ✓ | — (пусто) |
| Видано | `Остаток` (ресурс Σ) | ✓ | ✓ |
| Одиниця виміру | `ЕдиницаЕдина` | ✓ | ✓ |
| В нормі | `ВНорме` (ресурс Σ) | ✓ | ✓ |
| Понад норму | `ПонадНорму` (ресурс Σ) | ✓ | ✓ |
| Економія | `Экономия` (ресурс Σ) | ✓ | — (пусто) |
| Коментар цеху | пустое выражение `""` | ✓ (пусто) | ✓ (пусто) |

«Коментар цеху» — широкая колонка (~30 символов печатной ширины) под рукописное объяснение
кладовщика по понаднормовым строкам.

Чтение строки группы «Бойлер»: Норма СС 2 · Видано 1 · В нормі 1 · Економія 1 — числа бьются.

**Оформление под ч/б принтер:**
- строки группы — **жирный шрифт**; заливок «в нормі» (зелёных) нет вообще;
- **жёлтая заливка `#FFE699`** только на строках (группы и карточки), где `ПонадНорму > 0`
  (в ч/б печати станет серой);
- области применения условного оформления: `useInHeader/useInFieldsHeader/useInParameters = DontUse`
  (грабля §51); цвет только `#RRGGBB` (§36); поле-фильтр `ПонадНорму` есть в selection (§43).

**Итог «Разом»:** общие итоги СКД по Норма СС / Видано / В нормі / Понад норму / Економія
(единицы разноимённые — осознанное решение, как в согласованном Excel).

**Реализация:** дизайнерский СКД-макет **`МакетАнализЦех`** (клон `МакетАнализССОдна` по рецепту
знаний §08: новый UUID макета (§39), titles lang=uk (§34/§52), внешний набор «Данные»);
экспортная функция **`СформироватьПечатьАнализЦех(ДанныеАнализа)`** в `Ext/ObjectModule.bsl`
(копия каркаса печати №5 с другим макетом); в форме — команда + кнопка в попапе «Друк»
(**id с 574**), guard как у печатей 1–5 («Спочатку натисніть Розрахувати»).
Экономия/норма только на группе — раздельные selection у группировки `ОбщееНазвание` и у
детальных записей в settings СКД.

## 4. Движок: формула `ЕкономіяСума` (затрагивает печати 1–5, НЕ новую печать)

`Ext/ObjectModule.bsl`, `ЗафиксироватьЭкономиюЭталона` (~стр. 1055):

```bsl
// было: РазницаСум = НормаСумЭталона - СуммаОстаткаЭталона; кламп ≥ 0
// станет (неиспользованная норма по плановым ценам):
СтрокаЭталона.ЕкономіяСума = ?(ОстатокНормы > 0 И НормаЭталона > 0,
    Окр(ОстатокНормы * НормаСумЭталона / НормаЭталона, 2), 0);
```

Сигнатура процедуры меняется (нужна `НормаЭталона`, `СуммаОстаткаЭталона` больше не нужна) —
поправить оба вызова (смена эталона + хвост цикла). Новый инвариант:
`ЕкономіяСума > 0 ⟺ Економія > 0`. Распределение «В нормі / Понад норму», таблицы списания,
создаваемые документы — **не меняются**. Эффект: «Економія, грн» дома №1 в печатях с деньгами
станет ~34 691 грн вместо 109 073 грн; «Гайка» перестанет показывать 11.9 тыс грн экономии при
перевитрате. Пересчитанные ранее документы сохраняют старые цифры до повторного «Розрахувати».
