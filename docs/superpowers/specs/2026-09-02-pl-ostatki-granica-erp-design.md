# Отчёт А_ОтчетPL_ПолныйЕРП_Остатки: граница 30.06.2026, после — только ЕРП

**Дата:** 2026-09-02
**Объект:** `Отчет.А_ОтчетPL_ПолныйЕРП_Остатки` (BaseERP), модуль `Reports/А_ОтчетPL_ПолныйЕРП_Остатки/Ext/ObjectModule.bsl`
**Решение финансиста (02.09.2026):** документы `А_ОтчетPL` и `А_ВводОстатковОтчетаPL` больше не загружаются — остатки на 30.06.2026 разовые. После этой даты факт берётся только из регистров ЕРП.

## 1. Проблема

За период 01.07–31.08.2026 отчёт выводит только колонку «Август 2026», «PL с начала года» = остатки + август. Июль потерян у всех направлений в обоих режимах, потому что действующее правило (20.08.2026) читает не-последний месяц только из документов `А_ОтчетPL`, а июльских документов нет и не будет.

Отдельно: у направлений «Спецтехника» и «ЦО» нет объектного слоя (все документы и остатки — только свод), поэтому в объектном режиме их накопительные равны одному последнему месяцу.

## 2. Новый закон источника

Константа в модуле: `ГраницаОстатков = Дата(2026, 6, 30, 23, 59, 59)`. Из неё: `МесяцОстатков = 202606`, `НачалоЕРП = 01.07.2026 00:00:00`. Функция `МесяцДокументаОстатков()` и исключение «нет проведённого документа остатков» удаляются.

| Колонка | Месяцы ≤ 30.06.2026 | Месяцы ≥ 01.07.2026 |
|---|---|---|
| Месячные (ГГГГММ) | `Документ.А_ОтчетPL`, слой = `ВключатьДочерние` | регистры ЕРП (ПрочиеРасходы, ВыручкаИСебестоимостьПродаж, ПрочиеДоходы) |
| 890000 «PL с начала года» | `РН.А_ОстаткиОтчетаPL`, ресурсы `…СНачалаГода`, слой = `СводНаправления`; только если `ГОД(ГраницаОстатков) = ГОД(КонецПериода)` | + ЕРП за все месяцы с 01.07.2026 по конец периода, включая месяцы вне периода отчёта |
| 900000 «Накопительный PL» | `РН.А_ОстаткиОтчетаPL`, ресурсы `…Накопительно` | + те же ЕРП |
| 900100 «План объекта» | без изменений | без изменений |

Правила:
- Документы `А_ОтчетPL` с датой после границы не читаются ни в одну колонку.
- Внутри одного месяца источники не смешиваются.
- Период целиком до границы (например 01.01–30.04.2026): накопительные = остатки на 30.06.2026 как есть (в регистре нет помесячной разбивки).
- Период с концом в другом году (2027): 890000 = только ЕРП с января этого года; 900000 = остатки + ЕРП с 01.07.2026.

Принятые следствия: у периодов с концом ≤ июня последний месяц берётся из документа, а не из ЕРП (Глобино-2, май-2026: 43 049 236,83 → 43 605 205,86); амортизация появляется во всех ЕРП-месяцах; себестоимость августа = 0 до закрытия месяца; накопительные «плавают», пока последние месяцы живые.

## 4. Спецтехника и ЦО в объектном режиме

Новая временная таблица `втКорниБезОбъектногоСлоя`: корни направлений (`Родитель` пустой), у которых есть свод-слой (документы с `ВключатьДочерние` или остатки с `СводНаправления`) и нет ни одного объектного документа `А_ОтчетPL` и объектных остатков ни по самому корню, ни по подразделениям его поддерева (глубина до 4 уровней, как в `втПредкиПодразделений`). Сегодня это ровно Спецтехника и ЦО; вычисляется динамически.

Для таких корней в объектном режиме (`&СводыНаправлений = Ложь`) две ветки читают свод-слой:
- остатки: `Ост.СводНаправления = &СводыНаправлений ИЛИ (НЕ &СводыНаправлений И Ост.Подразделение В (ВЫБРАТЬ Подразделение ИЗ втКорниБезОбъектногоСлоя))`;
- документы в месячные колонки: аналогично по `Док.Подразделение`.

Карта уровней `втКартаУровней` не меняется: ЕРП-строки июля и далее остаются на дочерних подразделениях (машинах), история лежит на корне. В свод-режиме поведение не меняется.

Двойники документов остатков не создаются: они закрыли бы только накопительные, а месячные колонки январь–июнь у Спецтехники в объектном режиме остались бы пустыми.

## 5. Варианты отчёта

У вариантов `Справочник.ВариантыОтчетов` «PL: Месяц, PL с начала года (для свода)» и «PL: (без направления ЦО): Месяц, PL с начала года» в сохранённых настройках параметр `СводыНаправлений` = Истина (сейчас Ложь у всех пяти «PL: …»). Обработка выгрузки книги ставит Истина сама — интерактивная работа станет совпадать с книгой. Остальные три варианта не трогаются. Правка — COM-скриптом.

- СКД `Template.xml`, родительский отчёт `А_ОтчетPL_ПолныйЕРП` (остаётся на старом правиле), обработка `ВыгрузкаОтчетаPLвExcel` (код и .epf), Староконстантинов как вложенный свод-корень, дрейф остатков в существующих тестах.
