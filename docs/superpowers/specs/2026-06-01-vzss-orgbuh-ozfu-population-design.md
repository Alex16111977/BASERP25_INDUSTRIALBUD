# Дизайн: заполнение `ОрганизацияБухгалтерия` в дочернем ОЗФУ (СоздатьДокументОтражениеЗарплатыВФинансовомУчете)

> **Тип:** design / spec (superpowers brainstorming). Создан 2026-06-01.
> **Контекст:** в `РегистрНакопления.А_ВзаиморасчетыССотрудниками` добавлено 5-е измерение `ОрганизацияБухгалтерия` (заполняется для Форма1). Пользователь сам: (а) завёл измерение + реквизит в ТЧ дочернего ОЗФУ, (б) прописал движения регистра по ОЗФУ. **Движения регистра НЕ трогаем.**

## Цель

В процедуре `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl · СоздатьДокументОтражениеЗарплатыВФинансовомУчете()` **доделать заполнение реквизита `ОрганизацияБухгалтерия`** во всех 4 ТЧ дочернего `ОтражениеЗарплатыВФинансовомУчете`, где пользователь завёл поле: `НачисленнаяЗарплатаИВзносы` (свёртка), `НачисленнаяЗарплатаИВзносыПоФизлицам`, `НачисленныйНДФЛ`, `УдержаннаяЗарплата`.

## Вне scope

- ❌ Движения регистра `А_ВзаиморасчетыССотрудниками` (ManagerModule `ЗаполнитьИз*`) — сделано пользователем, не трогаем.
- ❌ Метаданные (реквизит/измерение) — заведены пользователем.
- ❌ Фикс −0.01 (`_ОтрЗП_ВыровнятьУдержаниеСНДФЛ`) — не трогаем.

## Принцип

Первоисточник ОргБух в документе — Ф1-строки «Зарплата управл» в `НачисленнаяЗарплатаИВзносыПоФизлицам` (родитель уже заполняет ОргБух через `_ОтрЗП_РаспределитьПоВесам`/`_ОтрЗП_ПроставитьОргБухВсемФорма1`). От них производим ОргБух для остальных ТЧ.

## Дизайн (по 4 ТЧ; всё внутри `СоздатьДокументОтражениеЗарплатыВФинансовомУчете`)

1. **`НачисленнаяЗарплатаИВзносыПоФизлицам`** — **без изменений**. `ЗаполнитьЗначенияСвойств(НоваяСтр, СтрБ)` уже копирует `ОрганизацияБухгалтерия` (имя совпадает с родителем, родитель заполнен для Ф1). Это источник истины.

2. **Карта `(ФЛ, Подр) → ОргБух`** — новая, строится ПОСЛЕ копирования `НачисленнаяЗарплатаИВзносыПоФизлицам`:
   - из её Ф1-строк, которые НЕ удержание (`Способ.А_ЭтоУдержание = Ложь`) и `ВзносыВсего = 0` («Зарплата управл»);
   - `Σ Сумма` per (ФЛ, Подр, ОргБух); на (ФЛ, Подр) берём **доминантный** ОргБух (макс. Σ Сумма) — для мульти-орг (есть 11 ФЛ с 2 ОргБух).
   - Доп. fallback-карта `(ФЛ) → ОргБух` (доминантный по ФЛ) — для строк, где по (ФЛ,Подр) ключа нет.

3. **`НачисленнаяЗарплатаИВзносы` (свёртка)** — добавить `ОрганизацияБухгалтерия`:
   - в колонки `ТЗСвертка`;
   - заполнять из `СтрПоФЛ.ОрганизацияБухгалтерия` (строки `ОЗ.НачисленнаяЗарплатаИВзносыПоФизлицам`);
   - добавить в **ключ свёртки** `ТЗСвертка.Свернуть(...)`;
   - `ЗаполнитьЗначенияСвойств(НоваяСвр, СтрС)` (уже есть) перенесёт в дочернюю строку (имя совпадает).
   - Точно: свёртка агрегирует строки, которые уже несут ОргБух → разбивка по ОргБух корректна.

4. **`НачисленныйНДФЛ`** — родитель ОргБух не содержит → брать из карты `(ФЛ, Подр)` (fallback `(ФЛ)`), присваивать `НоваяСтр.ОрганизацияБухгалтерия`.

5. **`УдержаннаяЗарплата`** — аналогично из карты, ПОСЛЕ существующего дозаполнения `ПодразделениеПредприятия` (`МапПодразПоФЛ`), fallback по (ФЛ).

## Критерии приёмки

1. ✅ После перепроведения родителя через **UI** во всех 4 ТЧ дочернего ОЗФУ `ОрганизацияБухгалтерия` заполнен для Ф1-строк (Ф2/ЕСВ — пусто, корректно).
2. ✅ Σ по (ФЛ, Подр) ОргБух в свёртке = в `НачисленнаяЗарплатаИВзносыПоФизлицам` (агрегат не теряет/не плодит).
3. ✅ Для single-org (ФЛ, Подр) ОргБух точный; для мульти-орг — доминантный (НДФЛ/Удержания — это не регистр-критичные ТЧ).
4. ✅ Σ сумм всех ТЧ не изменилась (ОргБух — только атрибут/ключ, суммы те же).
5. ✅ Движения регистра не изменены (регресс: пользовательская логика регистра нетронута).

## Тестирование (Rule #-1)

- Python COM **read-only на родителе**: проверить, что карта `(ФЛ,Подр)→доминантный ОргБух` строится корректно (сверка с `_ОтрЗП_ПостроитьОргБухКазныФорма1`).
- ⚠️ COM пересоздавать дочерний ОЗФУ **нельзя** (удвоение ТЧ — LESSONS §19). Приёмка — перепроведение родителя через UI, затем запрос проверки заполненности 4 ТЧ.
- Логику карты/доминантного выбора покрыть unit-проверкой на эталоне (Шишкіна + мульти-орг ФЛ, напр. Пономаренко/Производство).
