# Спека: отчёт «Сверка взаиморасчётов с сотрудниками ЕРП ↔ ЗУП (zup_2)»

Дата: 2026-06-11. Статус: дизайн утверждён пользователем (ЕРП-сторона = Ф1+Ф2 без фильтра).

## 1. Цель

Внешний отчёт `ExternalReport.А_СравнитьОстаткиВзаиморасчетыСотрудникиЕРПсЗУП` — диагностическая
сверка регистра ЕРП `А_ВзаиморасчетыССотрудниками` против регистра zup_2
`ВзаиморасчетыСРаботниками` за период, в разрезе ФизЛица. Аналог (паттерн-донор):
`_Rarzrabotki/Отчеты/А_СравнитьОстаткиВзаиморасчетыСотрудникиЕРПсBASБухгалтерия` (сверка с BuhBud).

Расположение: `_Rarzrabotki/Отчеты/А_СравнитьОстаткиВзаиморасчетыСотрудникиЕРПсЗУП.xml`
(+ одноимённая папка исходников, + собранный `.erf`).

## 2. Данные

| | ЕРП | ЗУП (zup_2, COM) |
|---|---|---|
| Источник | `РегистрНакопления.А_ВзаиморасчетыССотрудниками.ОстаткиИОбороты(&НП, &КП)` | `РегистрНакопления.ВзаиморасчетыСРаботниками.ОстаткиИОбороты(&НП, &КП)` |
| Фильтр | **без фильтра ФормаPL** (Ф1+Ф2 = «Общий») | — |
| Разрез | только ФизЛицо | `Физлицо` (единственное измерение регистра) |
| Показатели | НачОстаток / Начисления (Приход) / Выплаты (Расход) / КонОстаток из `СуммаВзаиморасчетов*` | те же из `СуммаУпр*` |
| Ключ слияния | `ФизическиеЛица.КодПоДРФО` | `Физлицо.КодПоДРФО` |

- Подключение zup_2: `Srvr="SQLSERVER";Ref="zup_2";Usr="cfo";Pwd="2442"` (как в
  `А_НачальнаяЗадолженностьПоЗарплатеФорма2` и `А_ОтражениеЗПпоКазне`).
- Ключ — `КодПоДРФО` (НЕ `А_ИдКод`, как в BuhBud-эталоне): по нему боевой код резолвит
  ФЛ zup_2↔ЕРП (`А_НачальнаяЗадолженностьПоЗарплатеФорма2/Ext/ObjectModule.bsl:220`).
  Python-фаза проверяет заполненность поля на обеих сторонах.
- Обоснование «Ф1+Ф2»: zup_2 хранит полное управленческое обязательство
  («Общий» = Форма1 + Форма2) — см. `knowledge_А_ОтражениеЗПпоКазне/19_forma2_nachalnaya_zadolzhennost.md`.

### 2.1 Знаки и направление Приход/Расход (открытый вопрос ДАННЫХ)

Конвенция ЕРП: `+ = долг работодателя`, Приход = начисление, Расход = выплата/удержание.
По эталону Буши (knowledge №19) есть подозрение, что в zup_2 начисление двигает сальдо
в противоположную сторону. Маппинг (возможная инверсия знака и/или swap Приход↔Выплаты)
устанавливается ЭМПИРИЧЕСКИ Python COM-тестом на эталонных ФЛ ДО написания BSL (Rule #-1)
и фиксируется в тесте. В отчёте обе стороны приводятся к конвенции ЕРП.
Критерий выверки: для выборки ФЛ без известных расхождений Δ кон.остатка ≈ 0,
и Начисления_ЗУП ≈ начислению-нетто месяца из `НачислениеЗарплатыРаботникам`.

## 3. Флаг «Только сотрудники из ЗУП»

- Булев параметр СКД `ТолькоСотрудникиИзЗУП`, заголовок «Только сотрудники из ЗУП»,
  **по умолчанию Истина**, `useRestriction=false` (виден в настройках), значение в
  `dataParameters` варианта с `userSettingID`.
- Семантика членства: ФЛ присутствует в **справочнике** `ФизическиеЛица` zup_2 с непустым
  `КодПоДРФО` (отдельный лёгкий COM-запрос всех непустых ДРФО), а НЕ «имеет движения за период».
  Сотрудник ЗУП без оборотов при включённом флаге остаётся в отчёте.
- Флаг выключен → полная картина, включая ЕРП-only строки (поведение эталона).
- Чтение в ObjectModule: `КомпоновкаДанныхКлиентСервер.ПолучитьПараметр(КомпоновщикНастроек, "ТолькоСотрудникиИзЗУП").Значение`.

## 4. Архитектура (копия паттерна эталона)

Метаданные: `DefaultForm=CommonForm.ФормаОтчета`, `DefaultSettingsForm=CommonForm.ФормаНастроекОтчета`,
`DefaultVariantForm=CommonForm.ФормаВариантаОтчета`, ChildObjects = только Template
`ОсновнаяСхемаКомпоновкиДанных`. Синонимы ru/uk. Help ru/uk.

ObjectModule (`ПриКомпоновкеРезультата`, СтандартнаяОбработка=Ложь):
1. `ПолучитьОстаткиЕРП(НП, КП)` — запрос А_ВзСС.ОстаткиИОбороты без ФормаPL,
   группировка по ФЛ + `ФизическоеЛицо.КодПоДРФО`.
2. COM-коннект zup_2 (Попытка → Сообщить + Возврат при ошибке, как эталон).
3. `ПолучитьОстаткиЗУП(V83, НП, КП)` — запрос ВзСР.ОстаткиИОбороты, группировка по
   `Физлицо.КодПоДРФО` (+`Физлицо.Наименование`); ТЗ только из примитивов →
   `V83.ЗначениеВСтрокуВнутр` + `ЗначениеИзСтрокиВнутр` (безопасно, как в эталоне).
4. `ПолучитьДРФОСправочникаЗУП(V83)` — все непустые `КодПоДРФО` справочника ФЛ zup_2
   (множество членства для флага).
5. `КонвертироватьТЗ_ЗУП` — ВТ + LEFT JOIN: ДРФО → `СправочникСсылка.ФизическиеЛица` ЕРП.
6. `ОбъединитьТаблицы` — Соответствие-индекс по ДРФО, 4 разницы (ЕРП − ЗУП),
   фильтр по флагу (если Истина — оставить только строки с ДРФО ∈ множеству из п.4).
7. Внешний набор `Сотрудники_Сравнение` → стандартный конвейер СКД (КомпоновщикМакета →
   ПроцессорКомпоновки → ПроцессорВывода).

Запретные имена BSL: не объявлять переменные `Ссылка`, `МетаДанные`, процедуру `Выполнить`.

## 5. СКД

Набор `Сотрудники_Сравнение` (DataSetObject), поля:
- `ФизическоеЛицо` (CatalogRef.ФизическиеЛица),
- `ФЛ_НаименованиеЗУП` (строка; отличие от эталона — чтобы ЗУП-only строки без пары в ЕРП
  не были безликими),
- 12 числовых (15,2): {НачальныйОстаток, Начисления, Выплаты, КонечныйОстаток} × {`_ЕРП`, `_ЗУП`, `Разница*`}.

Итоги: `Сумма()` по всем 12 числовым. Параметры: `Период` (StandardPeriod, ThisMonth),
`НачалоПериода` = `&Период.ДатаНачала`, `КонецПериода` = `КОНЕЦПЕРИОДА(&Период.ДатаОкончания,"ДЕНЬ")`
(оба useRestriction=true), `ТолькоСотрудникиИзЗУП` (булево, Истина, useRestriction=false).
Вариант «Основной»: группировка ФизическоеЛицо (без вложенных), 4 папки колонок
{Нач.остаток / Начисления / Выплаты и удержания / Кон.остаток} × {ЕРП, ЗУП, Разница}.
Заголовок: «Сверка взаиморасчётов с сотрудниками: ЕРП (Ф1+Ф2) ↔ ЗУП» (ru/uk).
НЕ добавлять корзины-периоды (День/Месяц/...) — их в эталоне нет.

## 6. Тесты и сборка (гейты)

1. `pretest` (Python COM, `_Rarzrabotki/Python/test/`): реальные имена колонок
   `ВзаиморасчетыСРаботниками.ОстаткиИОбороты` в zup_2; запрос ЕРП без ФормаPL;
   запрос справочника ФЛ zup_2 — все три 1:1 как будущий BSL (Rule #-1).
2. `pretest2`: знаковый маппинг на эталонных ФЛ (Буша ДРФО 2888011632 + 2–3 других),
   решение по инверсии/swap фиксируется в тесте и переносится в спеку реализации.
3. `acceptance`: COM-зеркало полного слияния; Σ 4 показателей обеих сторон; проверка
   флага — счёт строк с флагом и без, строки-ЕРП-only исчезают при Истина.
4. `erf-validate` + `erf-build` ПРОТИВ РЕАЛЬНОЙ BaseERP
   (`-InfoBaseServer "SQLSERVER" -InfoBaseRef "BaseERP" -UserName "Администратор" -Password "24043"`);
   стаб-база падает «формат 2.17» — известные грабли.
5. Кодировка исходников: UTF-8 BOM + CRLF. Python-логика — только в `.py`-файлах
   (inline `python -c` с кириллицей портится).
6. Rule #4: копия всех файлов из worktree в `C:\Configuration_downloads\BASERP25\`.

## 7. Вне скоупа

- Разрез ОргБух/ФормаPL (в zup_2 нет такого разреза; пользователь выбрал Σ Ф1+Ф2).
- Любые правки регистров/документов; отчёт read-only диагностический.
- Объяснение бизнес-расхождений (Ф2-премии из РаспределениеКазна отсутствуют в zup_2
  by-design — отчёт их просто покажет).
