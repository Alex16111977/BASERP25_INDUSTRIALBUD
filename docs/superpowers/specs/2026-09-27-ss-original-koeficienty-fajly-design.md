# СС: оригинал по модулям, коэффициенты пересчёта единиц, присоединённые Excel-файлы — дизайн

Дата: 2026-09-27. База: **BuhBud** (`Srvr="SQLSERVER";Ref="bas_industrialbud"`, cfo/2442), дамп `_Rarzrabotki/BASEBuh`.
Объект: `Справочник.СтруктураСебестоимости` (СС) + `Справочник.ОбщиеНазванияНоменклатуры`.

## 1. Проблема

У СС один рабочий слой — ТЧ `Комплектующие`. Её грузят из Excel (лист «Проект СС»), затем вручную
переводят в единицы закупки (труба м.п → т, вата м2 → пак, кабель м.п → км). Оригинал теряется:
у IRC 15/30 поля `ЕдиницаСС_Оригинал`/`КоличествоСС_Оригинал` пусты, исходные количества есть только
в Excel. Цепочка «файл → коэффициент → количество закупки» нигде не хранится, исходный файл к СС не приложен.

Факт из живой базы (IRC 15 м vs Excel): коэффициент **не** определяется одной «загальною назвою» —
«Профільна труба» м.п→т: 100*100*3 k=0.00851, 50*50*2 k=0.00296, 50*50*4 k=0.00556; «Лист ГК» м.кв→т
4/8/14 мм k=0.031/0.063/0.108; вата/кабель/плінтус — единый k на название.

## 2. Целевая модель (три слоя)

```
Excel (присоединённый файл СС, строка ФайлыОснования)
   └─► КомплектующиеПоМодульно   — ОРИГИНАЛ, после загрузки не меняется
          └─► КоэффициентыПересчета (ТЧ СС) — k на уникальную позицию, по умолчанию из ОбщиеНазванияНоменклатуры
                 └─► Комплектующие — количества в единицах закупки; Сумма НЕИЗМЕННА
```

Инварианты:
- И1. `Σ Комплектующие.Сумма` не меняется ни одной операцией этой доработки.
- И2. `КомплектующиеПоМодульно` после первичной заливки не редактируется кодом этой доработки.
- И3. «Перерахувати кількість» на старой СС (k подобраны по факту) не меняет ни одного `Количество`.
- И4. Строки `ДобавленоВручную = Истина` пересчётом не трогаются.

## 3. Изменения метаданных

### 3.1 Присоединённые файлы СС
- Новый `Справочник.СтруктураСебестоимостиПрисоединенныеФайлы` — структура 1:1 с типовым
  `ДоговорыКонтрагентовПрисоединенныеФайлы` (новые UUID, владелец = `СтруктураСебестоимости`).
- Добавить `CatalogRef/CatalogObject.СтруктураСебестоимостиПрисоединенныеФайлы` и `CatalogRef.СтруктураСебестоимости`
  в определяемые типы: `ВладелецПрисоединенныхФайлов`, `ПрисоединенныйФайл`, `ПрисоединенныйФайлОбъект`
  (и прочие DefinedTypes, куда входит эталон `ДоговорыКонтрагентовПрисоединенныеФайлы` — сверять по эталону).
- Права: роли, где есть эталонный справочник файлов, — те же права.
- Форма СС: команда «Файли» (штатная подсистема «Присоединённые файлы» БСП, как у эталона).

### 3.2 СС: ТЧ `ФайлыОснования`
| Реквизит | Тип | Смысл |
|---|---|---|
| Модуль | Число(10,0) | 0 = файл на всю СС; N = модуль N |
| Файл | СправочникСсылка.СтруктураСебестоимостиПрисоединенныеФайлы | оригинал xlsx |
| ДатаЗагрузки | Дата (дата+время) | |
| КоличествоСтрок | Число(10,0) | строк, записанных в `ПоМодульно` из файла |
| СуммаИтого | Число(15,2) | Σ Сумма этих строк (контроль) |

### 3.3 СС: ТЧ `КомплектующиеПоМодульно` — без изменений структуры
Модуль = 0 допускается и означает «вся СС».

### 3.4 СС: ТЧ `Комплектующие` — новый реквизит
`ДобавленоВручную` (Булево): строки, которых нет в оригинале.

### 3.5 СС: новая ТЧ `КоэффициентыПересчета`
Одна строка на уникальный ключ **Этап + ОбщееНазвание + НоменклатураСС(норм.) + ЕдиницаСС(норм.)** оригинала.
| Реквизит | Тип |
|---|---|
| Этап | СправочникСсылка.ЭтапыРабот |
| ОбщееНазвание | СправочникСсылка.ОбщиеНазванияНоменклатуры |
| НоменклатураСС | Строка(0 → 250) |
| ЕдиницаСС | Строка(50) — единица оригинала |
| КоличествоОригинал | Число(15,3) — Σ по всем модулям |
| ЕдиницаЗакупки | СправочникСсылка.КлассификаторЕдиницИзмерения (= ОбщееНазвание.Единица) |
| Коэффициент | Число(15,9) |
| ИсточникКоэффициента | ПеречислениеСсылка.ИсточникиКоэффициентаПересчетаСС |
| КоличествоПересчитанное | Число(15,3) — Окр(КоличествоОригинал × Коэффициент, 3), только просмотр |

Новое перечисление `ИсточникиКоэффициентаПересчетаСС`: `ПравилоТочное`, `ПравилоОбщее`,
`ЕдиницыСовпадают`, `Вручную`, `ПодобранПоФакту`, `НеНайден` (uk-синонимы: Правило точне / Правило загальне /
Одиниці збігаються / Вручну / Підібрано за фактом / Не знайдено).

### 3.6 `ОбщиеНазванияНоменклатуры`: новая ТЧ `КоэффициентыПересчета`
| Реквизит | Тип | Смысл |
|---|---|---|
| ЕдиницаСС | Строка(50) | единица Excel, хранится нормализованной |
| НоменклатураСС | Строка(250) | пусто = правило на всё название |
| Коэффициент | Число(15,9) | ЕдиницаСС × k = `ОбщиеНазванияНоменклатуры.Единица` |
| Комментарий | Строка(150) | напр. «вага 1 м.п профілю 100*100*3» |

Единица назначения — всегда `ОбщиеНазванияНоменклатуры.Единица` (отдельной колонки нет, чтобы правило
не расходилось с карточкой). Уникальность пары (ЕдиницаСС, НоменклатураСС) — проверка в `ОбработкаПроверкиЗаполнения`.
Форма элемента: страница «Коефіцієнти перерахунку».

## 4. Логика

### 4.1 Нормализация (единая функция, общий модуль `СтруктураСебестоимостиСервер`)
- Наименование: `СокрЛП` + схлоп пробелов + `НРег` (как существующий `НормализоватьНаименование`).
- Единица: то же + синонимы существующего `СинонимЕдиницы` (м.п/м.п./п.м/мп → пог.м; м.кв/м²/кв.м → м2; шт. → шт; куб.м → м3).
Логику нормализации модуля объекта СС перенести в общий модуль и вызывать оттуда (одна реализация на загрузку,
коэффициенты и признак вручную).

### 4.2 Поиск коэффициента (по ключу строки СС)
1. Правило ОН с (ЕдиницаСС, НоменклатураСС) → `ПравилоТочное`.
2. Правило ОН с (ЕдиницаСС, пусто) → `ПравилоОбщее`.
3. Норм(ЕдиницаСС) = Норм(ОбщееНазвание.Единица.Наименование) → k=1, `ЕдиницыСовпадают`.
4. Иначе k=0, `НеНайден`.
Правила всех ОН СС читаются одним запросом (кэш), без разыменований в цикле.

### 4.3 Команды формы СС (страница «Перерахунок»)
- **«Заповнити коефіцієнти»**: строит/дополняет `КоэффициентыПересчета` из свёртки `ПоМодульно` по ключу;
  новые строки и строки с источником `ПравилоТочное/ПравилоОбщее/ЕдиницыСовпадают/НеНайден` получают k по 4.2;
  `Вручную` и `ПодобранПоФакту` не перетираются; строки, ключа которых больше нет в оригинале, удаляются с сообщением.
- Правка `Коэффициент` пользователем → источник `Вручную`, пересчёт `КоличествоПересчитанное` на клиенте.
- **«Перерахувати кількість»** (сервер, транзакция, объект не записывается — записывает пользователь, как у кнопки загрузки):
  для каждой строки `Комплектующие` с `ДобавленоВручную = Ложь`, сопоставленной со строкой `КоэффициентыПересчета` с k>0
  по **ключу сопоставления = Этап + ОбщееНазвание + норм. НоменклатураСС** (без единицы: после пересчёта `ЕдиницаСС`
  в `Комплектующие` уже единица закупки; если ключу сопоставления соответствуют несколько строк коэффициентов с разными
  единицами — строка не пересчитывается, в протокол «неоднозначно»):
  `Количество = Окр(КоличествоОригинал × k, 3)` — если ключу соответствует несколько строк `Комплектующие`,
  количество распределяется пропорционально их `Сумма` (остаток округления — на последнюю строку);
  `Единица = ОбщееНазвание.Единица`, `ЕдиницаСС = СокрЛП(Единица.Наименование)`;
  `ЕдиницаСС_Оригинал`/`КоличествоСС_Оригинал` = оригинал; `Сумма` не трогается; `Цена` — существующий `ПередЗаписью`.
  Контроль: Σ Сумма до = после (иначе исключение и откат). Протокол: пересчитано / НеНайден / без строки в Комплектующих / вручную пропущено.
- **«Записати в довідник»** (по выделенной строке): переносит k в ТЧ правил ОН — точное (с НоменклатураСС) или общее
  (выбор пользователя в вопросе); существующее правило с той же парой перезаписывается после подтверждения.

### 4.4 Признак `ДобавленоВручную`
В `ПередЗаписью` СС (ветка НЕ `ОбменДанными.Загрузка`): если `КомплектующиеПоМодульно` не пуста —
`ДобавленоВручную = ключ строки (ОбщееНазвание + норм. НоменклатураСС) отсутствует в ПоМодульно`;
если пуста — признак не трогается (СС без оригинала: Вооз, МХП, ПРООН). Этап в ключ признака не входит
(ручной перенос строки между этапами не делает её «ручной»). Форма: строки с признаком — цветом.

### 4.5 Кнопка «Завантажити з Excel» формы СС (доработка существующей, движок отбора прежний)
После выбора файла — вопрос «Модуль (0 — вся СС)». Затем, в одной серверной операции:
1. `ОтобратьМатериалы` → строки (как сейчас).
2. `Комплектующие` заполняются как сейчас (`ЗаполнитьКомплектующиеИзСырыхСтрок`), дополнительно `_Оригинал`-поля = оригинал.
3. Строки модуля N в `ПоМодульно` заменяются отобранными (чужие модули сохраняются; модуль 0 заменяет всё).
4. Файл помещается во временное хранилище на клиенте и после записи СС присоединяется
   (`РаботаСФайлами.ДобавитьФайл`), строка `ФайлыОснования` модуля N заменяется.
Для новой СС (ещё не записанной) присоединение выполняется в `ПослеЗаписи` формы из сохранённого адреса хранилища.

## 5. Разовые операции на живых СС (скрипты COM, сухой прогон по умолчанию, `--write` для записи)

### 5.1 Заливка оригинала в `ПоМодульно` (где пусто) + прикрепление файлов
| СС | Файл | Модуль |
|---|---|---|
| МД IRС 2026 15 м (МД IRС 2026) | `Загрузка СС\IRC\Погоджений\IRC 15м2 …Коррект (1).xlsx` | 0 |
| МД IRС 2026 30 м (МД IRС 2026) | `Загрузка СС\IRC\Погоджений\IRC 30м2 …Коррект (2).xlsx` | 0 |
| МД ООН 2026 | `Загрузка СС\МД ООН 2026\14.07.2026 РАБОЧИЙ ООН_Б1…(002).xlsx` | 0 |
| МД ООН Админ | `СС ООН АДМИН\уніф СВ S1 / S3 Новий Шаблон 21.08.xlsx` | 1 / 3 — `ПоМодульно` уже есть, только файлы + `ФайлыОснования` |

Отбор — живой `ОтобратьМатериалы` СС (как в обработке «по двум файлам»). Количество/Сумма/ЕдиницаСС/НоменклатураСС
из Excel, `_Оригинал` = те же, ссылки ОН/Этап/Единица — как разрешает движок, `НеСовпадает` = Норм(ЕдиницаСС) ≠ Норм(ОН.Единица).
Контроль: `Комплектующие` не изменились (строки, Σ Кол, Σ Сумма, построчный хэш); Σ `ПоМодульно` = Σ отобранного Excel;
`ФайлыОснования` итоги = факт.

### 5.2 Подбор коэффициентов для старых СС (4 СС из 5.1)
В `КоэффициентыПересчета` — только ключи, где у строк `ПоМодульно` `НеСовпадает = Истина`.
`k = Σ Комплектующие.Количество / Σ ПоМодульно.Количество` по ключу сопоставления 4.3 (без единицы), источник `ПодобранПоФакту`.
Ключ в `Комплектующие` не найден → строка с k=0, `НеНайден`, в протокол. Ключи с совпадающими единицами не заносятся.
Контроль И3: симуляция «Перерахувати» на каждой СС даёт 0 изменений `Количество`.
Эмпирические k в справочник ОН **автоматически не пишутся** (разброс по объектам; перенос — кнопкой 4.3 осознанно).

### 5.3 Разметка `ДобавленоВручную`
По правилу 4.4 на 4 СС. Ожидание IRC 15 м: ~20 строк-заготовок + дозаведённые трубы. Список — в протокол.

## 6. Ошибки и границы
- Все серверные операции — транзакция, протокол-структура без re-raise, откат при нарушении И1.
- k с 9 знаками: обратный счёт по факту воспроизводит `Количество` после `Окр(,3)` (проверяется И3).
- `Количество` Число(15,3) — известная потеря точности малых значений (1,2 м.п → 0,005 т); расширение разрядности
  — отдельное решение, в объём не входит.
- Не в объёме: `ПередЗаписью` СС очищает `Комплектующие.Номенклатура` при каждой записи (строка 32 модуля) — сообщено
  пользователю, не трогается.
