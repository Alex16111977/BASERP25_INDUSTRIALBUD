## 1. Бизнес-задача

В управленческом учёте ERP — **одна** организация `ТОВ «ІНДАСТРІАЛБУД»` (зонтик). Начисление ЗП и налогов
делается на **реальном** подразделении работы сотрудника (Глобино-2, ЦО, Автокран XCMG, МК Кривий ріг…).
Но выплата идёт через кассы/счета только двух юр.лиц-каналов:

| Юр.лицо (ОргБух) | ЦелевоеПодразделение (`Организации.А_ПодразделениеЗарплатаБух`) |
|---|---|
| ТОВ «ІНДАСТРІАЛБУД» | `Строительство` |
| ДЖИ ТРИ КОНСТРАКШН ТОВ | `Строительство` |
| ІНДЕПТ СТІЛ ТОВ | `Производство` |
| (ВФ АССЕТС, І.П.С ТРЕЙД — поле **пустое**, требуют донастройки справочника) | — |

**Следствие:** обязательство (долг перед сотрудником + перед бюджетом по налогам + удержания) висит на реальном
подразделении, а выплата (РКО/СБДС) уменьшает обязательство на целевом → дисбаланс в управ.балансе **по
подразделениям**.

**Решение:** новый документ `Документ.А_ПередачаНачисленийМеждуПодразделениями` переносит **обязательства**
(не затраты!) с реального подразделения на целевое в двух регистрах:
`РегистрНакопления.ПрочиеАктивыПассивы` (ПАП — управ.баланс) + `РегистрНакопления.А_ВзаиморасчетыССотрудниками`.
Без бух.проводок (`Хозрасчетный`), без новых движений ДДС.

## 2. Что подтверждено пре-флайтом (Rule #-1)

### 2.1 `Организации.А_ПодразделениеЗарплатаБух` — УЖЕ существует и заполнен
Тип `СправочникСсылка.СтруктураПредприятия`. ТОВ ІНДАСТРІАЛБУД→Строительство, ДЖИ ТРИ→Строительство,
ІНДЕПТ СТІЛ→Производство. **meta-edit для этого реквизита НЕ нужен.**

### 2.2 Структура ПАП (`РегистрНакопления.ПрочиеАктивыПассивы`)
- Измерения: `Организация` (всегда ТОВ ІНДАСТРІАЛБУД — управ.орг), `Подразделение` (**`Справочник.СтруктураПредприятия`**),
  `НаправлениеДеятельности`, `Статья` (`ПланВидовХарактеристик.СтатьиАктивовПассивов`),
  `Аналитика` (составная: вкл. `Перечисление.ТипыНалогов`, `Справочник.ФизическиеЛица`, …).
- Ресурс: `Сумма`. Реквизиты: `Источник` (`Перечисление.ИсточникиУправленческогоБаланса`), `ВидИсточника`,
  `ИдентификаторФинЗаписи`.
- **Новый документ ещё НЕ в списке Регистраторов ПАП** → объявление `Движения` в ПАП правит метаданные
  только нового кастомного документа (структуру ПАП не трогаем). Это явно подразумевается в постановке.

### 2.3 Структура А_ВзСС (`РегистрНакопления.А_ВзаиморасчетыССотрудниками` — кастомный, balance)
- Измерения: `Организация × ФизическоеЛицо × Подразделение` (**`Справочник.СтруктураПредприятия`**). Ресурс: `СуммаВзаиморасчетов`.
- Регистраторы: РКО, ПКО, СБДС, ОЗФУ, ПостБезнал. Новый документ добавляется как 6-й регистратор (кастомный регистр — без ограничений).

### 2.4 Эталон — движения ПАП посчитанного `ОтражениеЗарплатыВФинансовомУчете 000Ц-000004` (апрель 2026)
Документ самобалансирующийся (Σ signed = 0,00):

| Статья | Источник | ВидИсточника | Signed | Аналитика | Что это |
|---|---|---|---:|---|---|
| Расходы текущего периода | ПрочиеРасходы | Расчет себестоимости и затрат | **+7 797 732,06** | — | затраты (**НЕ трогаем**) |
| Оплата труда | (пусто) | (пусто) | **−6 202 867,32** | — (нет ФЛ) | NET долг перед сотрудником |
| Налоги | (пусто) | (пусто) | **−1 571 501,70** | `ТипНалога` | долг перед бюджетом |
| Прочие пассивы | (пусто) | (пусто) | **−23 363,04** | — | удержания (recipient side) |

Разрез «Налоги» по `Аналитика=ТипНалога`: НДФЛ −635 724,30 · НачисленныйЕСВ −759 187,33 · ВоенныйСбор −176 590,07.

### 2.5 Доказанный инвариант `А_ВзСС = −ПАП(Оплата труда)` (per подразделение)
Глобино-2: ПАП(ОТ) net = −1 092 729,46 (Расход 1 284 793,28 − Приход 192 063,82); А_ВзСС = +1 092 729,46.
Точная инверсия по каждому подразделению (33+ подр). `Свод_ОплатаТруда` в `А_ФинРез_Баланс` читает оба
регистра и держит баланс на 0 плугов — поэтому новый документ ОБЯЗАН писать **оба** регистра согласованно.

## 3. Подходы (рассмотрено 3) — выбран A

- **A (выбран): новый документ `А_ПередачаНачисленийМеждуПодразделениями`**, пишет ПАП + А_ВзСС напрямую
  в `ОбработкаПроведения`. Один документ, аудируемые ТЧ, Find-Or-Create по `А_ДокументОснование`.
- **B: типовой `ДвижениеПрочихАктивовПассивов`** — не пишет А_ВзСС и не даёт разрез по ФЛ → нужен второй
  механизм, теряется аудит по ФЛ. Сложнее, отвергнут.
- **C (старый spec 2026-05-26): `ВзаимозачетЗадолженности`** между подразделениями-партнёрами — пишет
  `РасчетыСПартнерами`, а НЕ статьи «Оплата труда»/«Налоги»/«Прочие пассивы» → не лечит нужный дисбаланс.
  **Superseded.**

## 4. Структура документа

### 4.1 Шапка (6 реквизитов)

| Реквизит | Тип | Значение |
|---|---|---|
| `Дата` | Дата | стандарт |
| `Номер` | Строка(9), переменная, автонумерация | стандарт |
| `Организация` | `СправочникСсылка.Организации` | всегда ТОВ «ІНДАСТРІАЛБУД» (управ.орг = ПАП.Организация) |
| `А_ДокументОснование` | Составной: `ДокументСсылка.ОтражениеЗарплатыВФинансовомУчете` + `ДокументСсылка.А_ОтражениеЗПпоКазне` | документ-источник; ключ Find-Or-Create |
| `Комментарий` | Строка (неогр.) | стандарт |
| `Ответственный` | `СправочникСсылка.Пользователи` | стандарт |

### 4.2 ТЧ `Начисления` (NET ЗП per ФЛ × подразделение) → ПАП «Оплата труда» + А_ВзСС

| Поле | Тип | Источник |
|---|---|---|
| `ФизическоеЛицо` | `СправочникСсылка.ФизическиеЛица` | `НачисленнаяЗарплатаИВзносыПоФизлицам.ФизическоеЛицо` |
| `Сотрудник` | `СправочникСсылка.Сотрудники` | lookup по ФЛ |
| `ОрганизацияБухгалтерия` | `СправочникСсылка.Организации` | `НалогиБухгалтерия.Организация` (fallback `Сотрудник.ГоловнаяОрганизация`) |
| `ИсходноеПодразделение` | `СправочникСсылка.ПодразделенияОрганизаций` | `НачисленнаяЗарплатаИВзносыПоФизлицам.ПодразделениеПредприятия` |
| `ЦелевоеПодразделение` | `СправочникСсылка.СтруктураПредприятия` | `ОрганизацияБухгалтерия.А_ПодразделениеЗарплатаБух` |
| `ВидОперации` | `Перечисление.ВидыОперацийПоЗарплате` | копия из строки источника |
| `Сумма` | Число(15,2) | `НачисленнаяЗарплатаИВзносыПоФизлицам.Сумма`, Налог=Пустая, **минус 4 ВидОперации**¹ |
| `ПериодВзаиморасчетов` | Дата | `НачалоМесяца(Дата)` |
| `ДокОснованиеСтроки` | Составной: Документ.{НачислениеЗарплаты, ОтражениеЗарплатыВФинансовомУчете, А_ОтражениеЗПпоКазне} | конкретный документ-источник строки |
| `ИдентификаторСтроки` | УникальныйИдентификатор | устойчивость при перепроведении |

¹ Фильтр **1:1 с проверенной** `А_ВзаиморасчетыССотрудниками.ManagerModule.ЗаполнитьИзОтраженияЗП`:
исключить ВидОперации ∈ {ЕжегодныйОтпускОценочныеОбязательстваИРезервы, НачисленоСдельноДоход,
КомпенсацияЕжегодногоОтпускаОценочныеОбязательства, ЕжегодныйОтпускОценочныеОбязательства}. Это
гарантирует `Σ ТЧ Начисления по подр == ПАП(Оплата труда) по подр`.

### 4.3 ТЧ `Налоги` (НДФЛ/ВС/ЕСВ per ФЛ × налог × подразделение) → ПАП «Налоги»

| Поле | Тип | Источник |
|---|---|---|
| `ФизическоеЛицо`, `Сотрудник`, `ОрганизацияБухгалтерия`, `ИсходноеПодразделение`, `ЦелевоеПодразделение` | как в Начислениях | — |
| `ТипНалога` | `Перечисление.ТипыНалогов` (НДФЛ / ВоенныйСбор / НачисленныйЕСВ) | из источника → ПАП.Аналитика |
| `Налог` | `СправочникСсылка.Налоги` | конкретный налог (аудит) |
| `КодДохода` | `СправочникСсылка.ВидыДоходовНДФЛ` | для НДФЛ-строк (аудит) |
| `Сумма` | Число(15,2) | НДФЛ/ВС: `НачисленныйНДФЛ.Сумма`; ЕСВ: `НачисленнаяЗарплатаИВзносыПоФизлицам.ВзносыВсего` (Налог≈"ЕСВ%") |
| `ПериодВзаиморасчетов`, `ДокОснованиеСтроки`, `ИдентификаторСтроки` | как в Начислениях | — |

### 4.4 ТЧ `Удержания` (per ФЛ × подразделение) → ПАП «Прочие пассивы» *(добавлена по решению пользователя 2026-05-29)*

| Поле | Тип | Источник |
|---|---|---|
| `ФизическоеЛицо`, `Сотрудник`, `ОрганизацияБухгалтерия`, `ИсходноеПодразделение`, `ЦелевоеПодразделение` | как выше | — |
| `Получатель` | `СправочникСсылка.Контрагенты` (опц., аудит) | recipient удержания (в ПАП.Аналитика НЕ идёт — у статьи аналитика пустая) |
| `Сумма` | Число(15,2) | удержания, относящиеся к ПАП «Прочие пассивы» (`УдержанияБухгалтерия` родителя / `ОЗФУ.УдержаннаяЗарплата`) |
| `ПериодВзаиморасчетов`, `ДокОснованиеСтроки`, `ИдентификаторСтроки` | как выше | — |

> ⚠ Источник удержаний и его сходимость с ПАП «Прочие пассивы» — **пре-флайт-гейт** (§7). Если
> `УдержанияБухгалтерия` родителя не сходится → fallback на движения `ОЗФУ.УдержаннаяЗарплата` / ПАП(Прочие пассивы) дочернего ОЗФУ.

## 5. Карта движений регистров (ядро)

**Правило, гарантирующее net-zero и верные знаки:** на **исходном** подразделении — РЕВЕРС движения начисления
ОЗФУ; на **целевом** — КОПИЯ движения начисления. Подразделение исходное (`ПодразделенияОрганизаций`)
конвертируется в `СтруктураПредприятия` через реквизит `ПодразделенияОрганизаций.А_Подразделение` (knowledge 14,
Урок №1); целевое уже `СтруктураПредприятия`.

### 5.1 Движения ПАП (Организация = ТОВ ІНДАСТРІАЛБУД, `Источник = ПустаяСсылка`, `ВидИсточника = ПустаяСсылка`)

| Статья (ПВХ) | Аналитика | Исходное подр (СтрПредпр) | Целевое подр (СтрПредпр) | Источник суммы |
|---|---|---|---|---|
| Оплата труда | — (пусто) | **Приход** Σ | **Расход** Σ | ТЧ Начисления, агрегат по подр |
| Налоги | `ТипНалога` (Перечисление) | **Приход** Σ | **Расход** Σ | ТЧ Налоги, агрегат по (подр, ТипНалога) |
| Прочие пассивы | — (пусто) | **Приход** Σ | **Расход** Σ | ТЧ Удержания, агрегат по подр |

Все три статьи — пассивные; начисление ОЗФУ = Расход → реверс на исходном = **Приход**, копия на целевом = **Расход**.

### 5.2 Движения А_ВзСС (Организация = ТОВ ІНДАСТРІАЛБУД) — только для Начислений

| Измерение | Исходное подр (СтрПредпр) | Целевое подр (СтрПредпр) | Источник суммы |
|---|---|---|---|
| `ФизическоеЛицо` | **Расход** `СуммаВзаиморасчетов` | **Приход** `СуммаВзаиморасчетов` | ТЧ Начисления по (подр, ФЛ) |

А_ВзСС хранит **прямой** долг (Приход=рост) → инверсно ПАП(ОТ); поэтому на исходном **Расход**, на целевом **Приход**
(противоположно ПАП(ОТ)). Это сохраняет инвариант `А_ВзСС = −ПАП(ОТ)` per (подр, ФЛ).

«Налоги» и «Прочие пассивы» в А_ВзСС **не пишем** (это долг перед бюджетом/получателями, не перед сотрудником).
Их разрез в балансе даёт `Свод_ПрочиеАктивыПассивы_Прямой`, читая ПАП напрямую (для «Налоги» — по `ТипНалога`).

### 5.3 Net-zero (по построению)

Для каждой статьи и каждого подразделения: движение нового документа само по себе Σ по организации = 0
(Приход на исходном + равный Расход на целевом). После `ОЗФУ + новый документ`:
- исходное подразделение: начисление + реверс = **0** (обязательство ушло);
- целевое подразделение: копия начисления (обязательство пришло, его погасит РКО/СБДС).
Итог по ТОВ ІНДАСТРІАЛБУД **не меняется**. Затраты («Расходы текущего периода») остаются на реальном подразделении.

### 5.4 Размещение кода
- ПАП: движения строятся в `ОбработкаПроведения` нового документа (это движения самого документа).
- А_ВзСС: универсальная процедура `ЗаполнитьИзПередачиНачислений(ДокОбъект)` в
  `AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl`, вызывается из `ОбработкаПроведения`
  (паттерн как у остальных регистраторов — knowledge 14).

## 6. Заполнение ТЧ из родителя (А_ОтражениеЗПпоКазне на этом этапе)

```
0. GUARD: А_ДокументОснование заполнен; родитель проведён.
1. Если родитель = А_ОтражениеЗПпоКазне:
   - Начисления ← НачисленнаяЗарплатаИВзносыПоФизлицам (Налог=Пустая, − 4 ВидОперации) по (ФЛ, ПодразделениеПредприятия)
   - Налоги     ← НачисленныйНДФЛ (НДФЛ/ВС) + НачисленнаяЗарплатаИВзносыПоФизлицам.ВзносыВсего (ЕСВ) по (ФЛ, ТипНалога, подр)
   - Удержания  ← удержания, формирующие ПАП «Прочие пассивы» (источник уточняется пре-флайтом, §7)
2. Для каждой строки:
   - Сотрудник       ← lookup Справочник.Сотрудники по ФизическоеЛицо
   - ОрганизацияБухгалтерия ← НалогиБухгалтерия.Организация (fallback Сотрудник.ГоловнаяОрганизация)
   - ЦелевоеПодразделение  ← ОрганизацияБухгалтерия.А_ПодразделениеЗарплатаБух
   - GUARD: ЦелевоеПодразделение пусто → строку пропустить + Сообщить (ОргБух не настроена)
   - GUARD: А_Подразделение(ИсходноеПодразделение) = ЦелевоеПодразделение → пропустить (переносить некуда)
   - ИдентификаторСтроки ← Новый УникальныйИдентификатор (или сохранённый при перепроведении)
3. Поддержка родителя = ОтражениеЗарплатыВФинансовомУчете — отдельный этап (out-of-scope, §10).
```

## 7. Инварианты и пре-флайт-гейты (Rule #-1) — обязательны до BSL

| # | Гейт (Python COM / MCP, запрос 1:1 как в BSL) | Критерий |
|---|---|---|
| G1 | Σ ТЧ Начисления по (подр) | == ПАП(Оплата труда) дочернего ОЗФУ по (подр) до 0,01 |
| G2 | Σ ТЧ Налоги по (подр, ТипНалога) | == ПАП(Налоги) по (подр, ТипНалога) до 0,01 (апрель: НДФЛ 635 724,30 / ВС 176 590,07 / ЕСВ 759 187,33) |
| G3 | Σ ТЧ Удержания по (подр) | == ПАП(Прочие пассивы) по (подр) до 0,01 (апрель: Глобино-2 23 363,04) |
| G4 | конвертация ПодрОрг→СтрПредпр через `А_Подразделение` | непустая для всех исходных подразделений (иначе движение в неверном разрезе) |

Если G1–G3 не сходятся от родительских ТЧ → **fallback**: источник сумм = движения **дочернего ОЗФУ**
(А_ВзСС для ОТ, ПАП(Налоги)/ПАП(Прочие пассивы) для остального), что гарантирует сходимость по построению.

## 8. UI — кнопка в форме `Документ.А_ОтражениеЗПпоКазне`

Кнопка **«Создать передачу налогов и ЗП»** (образец — `СоздатьВедомостиВКассуПоОтражениюЗП`, knowledge 12):
`&НаКлиенте` обработчик → `&НаСервере` экспортная процедура `СоздатьПередачуНачисленийМеждуПодразделениями()`

### 13.6 Присвоение ЦелевогоПодразделения — ПРОПОРЦИОНАЛЬНОЕ дробление (решение пользователя 2026-05-29)

Пре-флайт показал: связь «сотрудник → юр.лицо-плательщик (ОргБух)» — **many-to-many** (75/178 ФЛ оплачены из >1 юр.лица в `РаспределениеКазна`; 150/298 пар (ФЛ×подр); 28/317 пар начислений нет в `РаспределениеКазна` по подразделению; есть юр.лицо «Управленческая организация» без `А_ПодразделениеЗарплатаБух`). Поэтому одно целевое на ФЛ присвоить нельзя.

**Решение (Q1=Пропорционально, Q2=доля «Управленческой» остаётся на исходном):**

1. **Суммы переноса — ТОЛЬКО из ОЗФУ** (net/налоги/удержания, доказано G1–G3 = ПАП до копейки). `РаспределениеКазна` суммы НЕ равны ПАП (7 530 371,76 ≠ net 6 202 867,32) — используются ТОЛЬКО как **веса**.
2. **Веса — на уровне ФЛ** (НЕ ФЛ×подр): `вес[ФЛ, Орг] = Σ РаспределениеКазна.Сумма` по всем Сотрудникам этого ФЛ, сгруппировано по Орг. **Покрытие ФЛ = 100%** (ФЛБезКарты=0), поэтому 28 подразделенческих несовпадений не теряют сотрудников.
3. **Дробление:** для каждой суммы ОЗФУ по (ФЛ, ИсхПодр[, ТипНалога]) → строки по каждому **Орг с заполненным `А_ПодразделениеЗарплатаБух`**: `сумма_строки = суммаОЗФУ × вес[ФЛ,Орг] / Σ_всех_весов[ФЛ]`, ЦелевоеПодразделение = `Орг.А_ПодразделениеЗарплатаБух`.
4. **Знаменатель = Σ ВСЕХ весов ФЛ** (включая «Управленческую» и любые без целевого). Доля «Управленческой»/без-целевого **НЕ переносится** → остаётся на исходном подразделении (управленческий учёт, идёт через кассу — отдельный механизм). Это означает: Σ перенесённого ≤ ПАП(ОТ) на исходном; остаток (доля без целевого) сохраняется.
5. **Округление (копейка):** дробление до 2 знаков методом наибольшего остатка — последней (наибольшей) строке добавляется остаток `round(суммаПереносимая) − Σ округлённых`, чтобы Σ строк = `round(суммаОЗФУ × Σ_целевых_весов / Σ_всех_весов)` точно.

**Влияние на структуру:**
- **ТЧ-грейн становится (ФЛ × ИсхПодр × ЦелПодр[× ТипНалога])** — одна пара (ФЛ, подр) даёт N строк (по целевым). `ИдентификаторСтроки` различает их. **Метаданные ТЧ (§4) НЕ меняются** — поля `ИсходноеПодразделение`/`ЦелевоеПодразделение` уже есть.
- **Движения ПАП (Task 4) и А_ВзСС (Task 3) НЕ меняются** — они уже группируют по (ИсходноеПодразделение, ЦелевоеПодразделение[, ТипНалога/ФЛ]); реверс на исходном/копия на целевом работает построчно, частичный перенос (остаток «Управленческой») обрабатывается естественно.
- **Net-zero держится** (каждая строка: реверс на исходном + копия на целевом = 0). Σ КО per организация не меняется. Исходное подразделение очищается на перенесённую долю; «управленческая» доля остаётся.
- Логика дробления живёт в `_ПНМП_Заполнить*` (Task 5). Smoke-тест (Task 8) проверяет: Σ строк по (ФЛ,ИсхПодр) = round(переносимой части); Σ движений = 0.
