# Спека: исправление количеств/единиц в СС «МД ООН Админ» (BaseERP)

Дата: 2026-08-28. Статус: понимание подтверждено пользователем («Да, делай»).

## Задача (роль: бухгалтер по исправлению СС)

Пользователь привёл количества строк СС к единицам измерения 1С в файле
`_Rarzrabotki/Загрузка СС/СС ООН АДМИН/Единиці изммерения/Список не співпадають одиниці.xlsx`
(лист TDSheet). Применить правку к ТЧ **Комплектующие** элемента `Справочник.А_СтруктураСебестоимости`
**«МД ООН Админ»** в живой **BaseERP** (Srvr=localhost/SQLSERVER, Ref=BaseERP).

## Проверенные факты (2026-08-28)

- СС в базе: 325 строк ТЧ, Σ Сумма 1 634 453.54 (материалы S1+S3 из загрузок 21.08); флаг `НеСовпадает` = Истина ровно у 100 строк.
- Файл: 100 строк (N 1..325) = ровно эти 100 строк базы; сверка по N + наименование + сумма: 100/100, 0 расхождений. Колонки: A=N, D=Номенклатура СС, E=Единица СС (старая, «шт»), F=Одиниця заг. назва, G=старое количество, **H=«Кількість заг» — пересчитанное количество**, I=Сумма, J=старая цена, K=«Не совпадает».
- H заполнена в **98** строках; 2 строки (N=18, N=203 «Заглушка ліва + права», комплект) без H — у общего названия нет единицы, **не трогать**.
- В строках базы ссылочная `Единица` и `ЕдиницаОбщееНазвание` уже заполнены единицей общего названия (напр. «куб»); несовпадение — в строковом поле `ЕдиницаСС` («шт»).
- Обмен: в правилах конвертации ERP↔BuhBud (195 правил, `notebook/knowledge/exchange_erp_buhbud.md`, `_exchange_rules_list.txt`) СтруктураСебестоимости НЕ участвует — правка в ERP штатным обменом не перезаписывается. Риск затирания — только повторная перезагрузка материалов из Excel (не делать вслепую).

## Правка (по каждой из 98 строк с заполненной H)

Ключ: `НомерСтроки = N` + контроль `НоменклатураСС` (нормализованно) + `Сумма` (допуск 0.01) — любое расхождение по строке = строка НЕ правится, в протокол; расхождение контрольных итогов = полный откат.

1. `Количество` ← Окр(H, 3) (квалификатор ТЧ — 3 знака, как в BuhBud; сверить по факту записи).
2. `Цена` ← Окр(Сумма / НовоеКоличество, 2). `Сумма` НЕ меняется.
3. `ЕдиницаСС` ← Строка(`ЕдиницаОбщееНазвание` строки) — «единица как в 1С»; если `ЕдиницаОбщееНазвание` пустая → строку не переводить на новую единицу: ЕдиницаСС не менять, `НеСовпадает` не снимать, предупреждение в протокол (количество/цену всё равно обновить — пользователь пересчитал H именно под единицу 1С только там, где она есть; по данным таких строк среди 98 нет).
4. Ссылочная `Единица` ← `ЕдиницаОбщееНазвание`, если пустая или отличается (обычно уже совпадает).
5. `НеСовпадает` ← Ложь.

## Страховка и контроль

- ДО правки: снимок всех 325 строк ТЧ в `Единиці изммерения/Бекап МД ООН Админ Комплектующие ДО 2026-08-28.xlsx` (все поля: N, Модуль, ОбщееНазвание, Номенклатура, Единица, Количество, Сумма, Цена, Этап, НоменклатураСС, ЕдиницаСС, ЕдиницаОбщееНазвание, НеСовпадает).
- Правка одной транзакцией (COM BeginTransaction/Commit/Rollback): число строк ТЧ не меняется (325), Σ Сумма до = после = 1 634 453.54 (допуск 0.01), обновлено ровно 98 строк.
- После записи — контрольный запрос: по каждой правленой строке Количество/Цена/ЕдиницаСС/НеСовпадает соответствуют ожиданию; Σ Сумма ТЧ прежняя.
- Протокол: N, наименование, количество старое→новое, цена старая→новая, единица старая→новая.

## Реализация

Одноразовый Python COM скрипт `_Rarzrabotki/Python/fix_ss_md_oon_admin_edinicy.py` (без .epf — YAGNI, правка разовая). Правила ключей/контроля — как в проверенном механизме «Обновить количество» (BuhBud, `ОбновитьКоличестваИзМассива`).
