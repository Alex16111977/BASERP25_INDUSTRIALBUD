- **Дата:** 2026-07-08
- **Ветка:** claude/hungry-mcnulty-ca2a24 (worktree pensive-maxwell-b838b2)
- **Целевая база:** BuhBud — `Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`, исходники `_Rarzrabotki/BASEBuh`
- **Файлы обработки:** `_Rarzrabotki/Загрузка СС/Загрузка материалов в СС.xml` (+ каталог с формой и модулями)
- **Образец-шаблон:** `_Rarzrabotki/Загрузка СС/Загрузка работ в СС` (см. [[zagruzka_rabot_v_ss]])

## 1. Задача

Внешняя обработка читает лист **«Проект СС»** из Excel-шаблона производства
(`IRC 15м2 …_.xlsx` / `IRC 30м2 …_.xlsx`) и заполняет табличную часть
**`Комплектующие`** выбранного элемента `Справочник.СтруктураСебестоимости` в
базе **BuhBud** строками-**материалами**.

Сейчас `Загрузка материалов в СС` — это байт-копия `Загрузка работ в СС`
(тот же UUID, тот же код, грузит в ТЧ `Работы`). Требуется полная переработка
модуля формы и модуля объекта.

## 2. Источник данных (лист «Проект СС»)

Проверено openpyxl на обоих шаблонах (15м2: 317 строк, 30м2: 319 строк).
Лист «Проект СС» — **3-й по счёту**, поэтому берём его **по имени**, а не
`WorkSheets(1)`.

Шапка (строка 1) и разбор колонок «глазами бухгалтера»:

| Кол | Заголовок | Назначение |
|-----|-----------|------------|
| A | № | иерархический номер (1.1.1) |
| B | Стаття в ДДС | статья ДДС |
| **C** | Робота/матеріал/додаткові | **тип строки — фильтр** |
| D | Виробництво/Будівництво | — |
| **E** | Тип робіт | **Этап** («Каркас», «Сантехника» …) |
| F | № з/п | дубль A |
| **G** | Найменування робіт/витрат/матеріалів | **НоменклатураСС** (наименование материала) |
| H | …узагальнена | обобщённое наименование (не грузим) |
| **I** | Од. вим. | **ЕдиницаСС** (шт, м.п, м2, кг …) |
| **J** | Кіль-кість | **Количество** |
| K | Вартість робіт за од. | — |
| L | Вартість матеріалів за од. | цена материала за ед. (не в мапинге) |
| M | Вартість робіт за повний обсяг | — |
| N | Вартість матеріалів за повний обсяг | — |
| **O** | Всього, грн. з ПДВ | **Сумма** |

**Фильтр:** в ТЧ попадают только строки, где `C = "Матеріал"`.
Факт: 184 материала (15м2) / 186 (30м2). Прочие значения C: `Робота` (70),
пусто (секции), `Робота/матеріал/додаткові` (заголовок r1) — все отсеиваются.

Единицы в колонке I неоднородны («шт», «м.п», «м.п.», «м2», «м.кв.», «кг»,
«лист», «балон», «л») — грузятся **как есть** в строковое поле `ЕдиницаСС`,
нормализация/классификация не требуется.

## 3. Приёмник (`Справочник.СтруктураСебестоимости.Комплектующие`, BuhBud)

Типы полей ТЧ проверены через COM-метаданные BuhBud:

| Поле ТЧ | Тип | Excel | Логика заполнения |
|---------|-----|-------|-------------------|
| `НоменклатураСС` | **Строка** | G | текст, `СокрЛП` |
| `ЕдиницаСС` | **Строка** | I | текст, `СокрЛП` |
| `Количество` | Число | J | `ЧислоИзЯчейки` (пусто/не число → 0) |
| `Сумма` | Число | O | `ЧислоИзЯчейки` |
| `Этап` | ссылка → `Справочник.ЭтапыРабот` | E | get-or-create по наименованию |
| `Номенклатура` | ссылка (Номенклатура) | — | **не заполняем** (пусто) |
| `ОбщееНазвание` | ссылка | — | **не заполняем** |
| `Единица` | ссылка (классификатор) | — | **не заполняем** |

Ссылочные поля `Номенклатура`/`ОбщееНазвание`/`Единица` осознанно остаются
пустыми — их матчат отдельным шагом после загрузки текстовых «СС»-полей.

**`Справочник.ЭтапыРабот`** (BuhBud, без префикса `А_`): неиерархический,
ДлинаНаименования=100, доп. реквизитов нет. Все 8 этапов из шаблона уже
существуют 1:1 (`Каркас`, `Электрика/Подогрев`, `Сантехника`, `Отделка`,
`Дополнительная Комплектация`, `Монтаж будинку`, `Фасад`, `Окна/двери`) →
на текущих данных создаваться не будут, но get-or-create оставляем для будущих
шаблонов.

## 4. Архитектура (класс A, как в «работах»)

Разделение «тонкая форма (клиент, COM Excel) + движок (ObjectModule)»:

### 4.1 Модуль формы `Forms/Форма/Ext/Form/Module.bsl` (`&НаКлиенте`)
- `ЗагрузитьМатериалы(Команда)` — проверка `Объект.ИмяФайла` и
  `Объект.ДокСтруктураСебестоимости`; чтение Excel → массив; вызов сервера;
  вывод протокола.
- `ПрочитатьExcelВМассив(ИмяФайла)`:
  - `Excel.Workbooks.Open`; `Лист = Excel.WorkSheets("Проект СС")` (**по имени**);
  - последняя строка через `SpecialCells(11)`;
  - цикл: брать только `СокрЛП(Cells(Ряд,3).Text) = "Матеріал"`;
  - пустое G (наименование) → пропуск;
  - структура `{Этап=E(5), НоменклатураСС=G(7), ЕдиницаСС=I(9), Количество=J(10), Сумма=O(15)}`;
  - корректное закрытие/`Quit` Excel в `Попытка/Исключение`.
- `ЧислоИзЯчейки(Значение)` — как в образце.
- `ЗагрузитьНаСервере(МассивСтрок)` (`&НаСервере`) — мост
  `РеквизитФормыВЗначение("Объект")` → `ЗагрузитьМатериалыИзМассива(...)`.
- `ВывестиПротокол` — «Загружено материалов / Создано этапов / Пропущено».

### 4.2 Модуль объекта `Ext/ObjectModule.bsl`
- Экспортная `ЗагрузитьМатериалыИзМассива(СтруктураСеб, МассивСтрок)`:
  - протокол `{Загружено, СозданоЭтапов, Пропущено, Ошибка, ТекстОшибки}`;
  - проверка `СтруктураСеб` заполнена;
  - `КэшЭтапов = ПостроитьКэшЭтапов()` (по `Справочник.ЭтапыРабот`,
    ключ = `НРег(НормализоватьНаименование(Наименование))`);
  - **транзакция**: `ОбъектСеб.Комплектующие.Очистить()` → цикл заполнения →
    `ОбъектСеб.Записать()` → `ЗафиксироватьТранзакцию()`; в `Исключение` —
    откат + `ЗаписьЖурналаРегистрации` + протокол с ошибкой (без re-raise);
  - на строку: пропуск пустого `НоменклатураСС`; `Этап` через
    `ПолучитьИлиСоздатьЭтап`; запись 5 полей ТЧ.
- Служебные: `ПолучитьЧисло`, `НормализоватьНаименование`,
  `ПостроитьКэшЭтапов`, `ПолучитьИлиСоздатьЭтап`.
- **Удаляется** весь механизм номенклатуры-работы: `НайтиГруппуРоботи`,
  `НайтиОбразецРаботы`, `ПостроитьКэшРабот`, `ПолучитьИлиСоздатьРаботу`.

### 4.3 Режим записи
**Очищать и перезаписывать** (решение пользователя): перед заливкой ТЧ
`Комплектующие` полностью очищается. Идемпотентно; повтор даёт тот же результат.

### 4.4 XML-обёртка
`ДокСтруктураСебестоимости` уже имеет тип
`cfg:CatalogRef.СтруктураСебестоимости` (без `А_`) — соответствует BuhBud,
менять не нужно. Синонимы/имя команды формы привести к «материалам»
(косметика, не влияет на работу).

## 5. Сборка и проверка

1. Python COM-тест запроса/логики на **BuhBud** до правки BSL (Rule #-1/#5):
   заполнение ТЧ на временном элементе `СтруктураСебестоимости`
   (get-or-create по границам, **без `Удалить()`** — см. [[feedback_no_doc_delete_in_tests]]).
2. `epf-build` против BuhBud; открыть/проверить .epf самому
   (см. [[feedback_epf_preflight_open_self]], [[epf_build_stub_isolation_gotcha]]).
3. win32com-smoke: `ВнешниеОбработки.Создать(.epf)` →
   `ЗагрузитьМатериалыИзМассива(temp, массив)`; сверка кол-ва строк (184/186) и
   Σ`Сумма` с Excel (см. [[win32com_epf_smoke_gotchas]]).
4. `1c-bsl-review` модулей; копирование в основной каталог BASEBuh.

## 6. Критерии готовности

- [ ] Лист «Проект СС» читается по имени; фильтр `C="Матеріал"` даёт 184/186 строк.
- [ ] ТЧ `Комплектующие` очищается и заполняется: НоменклатураСС=G, ЕдиницаСС=I,
      Количество=J, Сумма=O, Этап=E (ссылка, get-or-create).
- [ ] Ссылочные Номенклатура/ОбщееНазвание/Единица — пустые.
- [ ] Σ`Сумма` в ТЧ == Σ колонки O материалов из Excel.
- [ ] Идемпотентность: повторный запуск → те же строки, 0 новых этапов.
- [ ] .epf собран против BuhBud, smoke зелёный, файлы скопированы в `_Rarzrabotki/BASEBuh`.
