# Спека: отчёт «А_ОтчетПоСписаниюНаПроизводствоУправленческий» (BaseERP)

Дата: 2026-08-14. Статус: дизайн утверждён пользователем (4 развилки решены, см. §2).

## 1. Цель

Внешний СКД-отчёт для **BaseERP** — «форма СС по факту списания». Воспроизводит структуру
Excel-листа «Проект СС» (шаблоны `_Rarzrabotki\Загрузка СС\IRC\Погоджений\IRC 15м2|30м2 НОВИЙ
ШАблон СС Виробництво 16-06-2026_Коррект (1|2).xlsx`), но вместо плановых количеств —
**факт списания** из 1С:

- структура: **Етап робіт → Загальна назва → Номенклатура (как в 1С)**;
- колонки: **Од. вим. (единица 1С) / Кількість / Ціна з ПДВ / Сума з ПДВ**;
- **только материальная часть СС** (подтверждено пользователем 2026-08-14): блок «РОБОТА» листа,
  ТЧ `Работы` СС, табелирование/часы и любые трудовые источники в отчёте НЕ используются вообще;
- итоги по каждому этапу и общий итог (аналог «Разом по розділу»).

Факт — **по документам списания и комплектаций** (НЕ по закупкам, в отличие от
ПФПП-ветки 5): `СборкаТоваров` (= Комплектація из BuhBud) и
`ВнутреннееПотреблениеТоваров` (= передача малоценки из BuhBud).

## 2. Утверждённые решения (пользователь, 2026-08-14)

| # | Развилка | Решение |
|---|---|---|
| 1 | Вид отчёта | **СКД-отчёт** (типовой интерфейс, расшифровка, штатное сохранение в Excel), НЕ пиксельная печать листа |
| 2 | Деньги незакрытого месяца | **Себестоимость + fallback плановые цены**: `Сума` = `СТ.Стоимость` (с НДС); где 0 — `Кількість × планова ціна СС` (ключ «назва+одиниця») |
| 3 | Назва в нескольких этапах СС | **Первый по порядку строк ТЧ** (`НомерСтроки`) — материал ровно в одном этапе |
| 4 | Факт вне СС | Отдельный раздел **«Позапланово»** в конце отчёта |

## 4. Движок данных (донор — `_Rarzrabotki\Отчеты\А_ОтчетПоСписаниюНаПроизводство\Ext\ObjectModule.bsl`)

Программная компоновка, как у всего семейства:
`ПриКомпоновкеРезультата` → экспортная `СформироватьОтчет(ДокументРезультат, ДанныеРасшифровки)`
(нужна приёмке: COM не отдаёт обработчик события) → `ПолучитьДанные(Період)` → внешний набор
«Детали» → `КомпоновщикМакета/ПроцессорКомпоновки/ПроцессорВывода`. `ПолучитьЗначениеПараметра` —
безБСП-способ донора (в НЕ трогать: `КомпоновкаДанныхКлиентСервер.ПолучитьПараметр` есть не везде).

### 4.1 Драйверы и исполнители (1:1 с донором)

- Драйвер = `СС.ПодразделениеОбъекта` (fallback `Подразделение`) по всем активным не-групповым
  `А_СтруктураСебестоимости`; 15 м / 30 м не смешиваются (общий зонтик «МД IRC 2026» их не склеивает).
- `ПолучитьДанные` циклит по драйверам; СКД-отбор «Підрозділ» фильтрует внешний набор (доказано в ПФПП).

### 4.2 Факт (единственная ветка запроса — плановых строк в выводе НЕТ)

```
РегистрНакопления.СебестоимостьТоваров КАК СТ
ГДЕ  СТ.ВидДвижения = Расход
  И  СТ.РазделУчета = ТоварыНаСкладах
  И  СТ.Период МЕЖДУ &НачП И &КонП
  И  ТИПЗНАЧЕНИЯ(СТ.Регистратор) В (ТИП(Документ.СборкаТоваров), ТИП(Документ.ВнутреннееПотреблениеТоваров))
  И  СТ.Подразделение В ИЕРАРХИИ (&Драйвер)
```

- `Кількість` = `СТ.Количество`; `СумаСоб` = `СТ.Стоимость` (**брутто с НДС** — проверенный
  инвариант регистра, НЕ менять на `СтоимостьБезНДС`).
- `ВидДокумента`: СборкаТоваров → «1. Комплектація», иначе «2. Внутрішнє споживання».
- Исполнитель = `СТ.Подразделение` (домики «№1..№N»), `Подразделение` = драйвер.
- Границы периода: пустое начало → `'00010101'`, пустой конец → `КонецДня`/`'39991231'` (как донор).

### 4.3 Карта этапов — «первое вхождение» (ОТЛИЧИЕ от донора)

Запрос **только по ТЧ `Комплектующие`** (ТЧ `Работы` не читается) всех активных СС драйвера,
**УПОРЯДОЧИТЬ ПО К.Ссылка.Наименование, К.НомерСтроки** — детерминированный обход при
нескольких СС на драйвере (этапы у 15 м/30 м совпадают):

- назва строки = `К.Номенклатура.А_ОбщееНазваниеНоменклатуры.Наименование`, при пустой
  карточке — ТЧ-реквизит `К.ОбщееНазвание.Наименование` (паттерн донора);
- ключ карты = `ВРег(СокрЛП(имя))` (у донора карта этапов без ВРег — здесь унифицируем с картой цен);
- вставка в Соответствие **только если ключа ещё нет** → этап первого вхождения;
- `ЕтапНомер` этапа = порядковый номер ПЕРВОГО появления этого этапа в том же упорядоченном
  обходе (минимум по всем СС драйвера) → порядок разделов отчёта = порядок листа СС
  (Каркас → … → Монтаж будинку), НЕ алфавит;
- строки ТЧ с пустым этапом в карту не попадают.

Применение к факту: назва факта = `Номенклатура.А_ОбщееНазваниеНоменклатуры`; найдено →
`Етап`, `ЕтапНомер`, `ЕтапСтрока = Строка(Етап)`; не найдено (или назва пуста) →
`ЕтапСтрока = "Позапланово"`, `ЕтапНомер = 9999`, `Етап` — пустая ссылка.

### 4.4 Карта плановых цен и fallback (решение №2)

- Карта «`ВРег(СокрЛП(назва)) + "|" + ВРег(СокрЛП(имя единицы))` → {ПланКол, ПланГрн}» по ТЧ
  `Комплектующие` СС драйвера (суммы ТЧ с НДС; множитель Домов на цену не влияет — не тиражировать).
  Ключ единицы — по нормализованному ИМЕНИ (`УпаковкиЕдиницыИзмерения` подчинён владельцу,
  «шт» разных номенклатур — разные ссылки; ключи-хелперы донора `КлючОбщейНазвы`/`КлючЕдиницы` переиспользовать).
- Построчно: `СумаПлан = Кількість × (ПланГрн/ПланКол)` при найденном ключе с `ПланКол > 0`.
- Выводимая `Сума` = `СумаСоб`, если `СумаСоб <> 0`; иначе `СумаПлан`.
- `ДжерелоЦіни` (Строка 20): «Собівартість» (`СумаСоб <> 0`) / «Планова ціна» (fallback сработал) /
  «Без ціни» (`СумаСоб = 0` и цены нет — `Сума = 0`).

## 5. СКД

- Параметр: `Період` (StandardPeriod, трюк донора с пустыми границами).
- Поля-заголовки uk (+ru): ЕтапСтрока → «Етап робіт», ОбщееНазвание → «Загальна назва»,
  Аналитика → «Номенклатура», Единица → «Од. вим.», Кількість / «Ціна з ПДВ» / «Сума з ПДВ».
  Пост-патч дублирования `<v8:item>` uk (skd/семейный рецепт; на uk-интерфейсе ru-титулы игнорируются).
- Ресурсы: `Кількість`, `Сума`, `СумаСоб`, `СумаПлан` — СУММА;
  `Ціна` — totalField `ВЫБОР КОГДА СУММА(Кількість) = 0 ТОГДА 0 ИНАЧЕ СУММА(Сума)/СУММА(Кількість) КОНЕЦ`,
  формат ЧДЦ=2 (иначе 30 знаков).
- Дефолтная структура (settings по умолчанию в схеме): группировки
  **Підрозділ → ЕтапСтрока → ОбщееНазвание → Аналитика → Единица**; selection: Кількість, Ціна, Сума.
  Сортировка (orderItems): `ЕтапНомер` Возр (раздел «Позапланово» — последний), далее по представлению назвы.
  Единица — подуровень группировки под номенклатурой (грабля программной компоновки: не-ресурс
  колонкой не рендерится — проверено в ПФПП, там же рецепт).
- Доступные вне дефолта: ПодразделениеИсполнитель, ВидДокумента, Документ, Етап (ссылка),
  ДжерелоЦіни, НоменклатураНаименование, СумаСоб, СумаПлан.
- Расшифровка штатная (ДанныеРасшифровки прокидывается) — drill до номенклатуры/документа.

## 6. Тесты и приёмка (Rule #-1 обязателен)

1. **Python COM до BSL**: каждый запрос (факт, карта этапов с НомерСтроки, карта цен) — на живой
   BaseERP; сдвиг дат COM подбирать через `ГОД/МЕСЯЦ/ДЕНЬ/ЧАС(&Д)` (зависит от даты!).
2. **Smoke** `_Rarzrabotki/Python/test/smoke_spisanie_na_proizvodstvo_upr.py` (по образцу
   `smoke_spisanie_na_proizvodstvo.py`), полный путь пользователя: `ВнешниеОтчеты.Создать` →
   параметр Період → **`СформироватьОтчет`** (не только ПолучитьДанные). Инварианты
   (данные-независимые, без жёстких чисел):
   - Σ Кількість / Σ СумаСоб по драйверу == прямому COM-запросу регистра (та же фильтрация);
   - кросс-сверка с донором `А_ОтчетПоСписаниюНаПроизводство`: ФактКол/ФактГрнСоб по драйверу 1:1;
   - **каждая назва встречается ровно в одном ЕтапСтрока** (ключевой инвариант дедупа);
   - Σ по этапам + «Позапланово» == общий факт (ничего не потеряно/не задвоено);
   - `ДжерелоЦіни = "Планова ціна"` ⇔ `СумаСоб = 0` и ключ цены найден; `Сума = СумаСоб` при `СумаСоб <> 0`;
   - порядок ЕтапНомер строго возрастает по разделам вывода; «Позапланово» последний;
   - композиция: ВысотаТаблицы > 0, заголовки uk видны.
3. Сборка: `_Rarzrabotki/Python/build_spisanie_na_proizvodstvo/rebuild_upr.ps1`
   (skd-валидация → erf-build против BaseERPRazr → копия `.erf` в `_Rarzrabotki\Отчеты\`);
   в каталоге сборки не должно быть посторонних файлов (`.bak` ломает сборку).
4. Копирование исходников в основную конфигурацию `C:\Configuration_downloads\BASERP25\`
   (Rule #4) + git-финал по регламенту.

## 7. Известные дефекты данных (отчёт подсвечивает, не чинит)
