**Дата:** 2026-05-29
**Документ:** `А_ОтражениеЗПпоКазне`
**Файл правки:** `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`
**Связанные спеки:** `2026-05-27-otrazhenie-zp-vkassu-design.md` (исходный дизайн процедуры), `2026-05-27-rko-vzaimoraschety-iz-vkassu-design.md` (контракт «ВКассу как источник для РКО»).

## 1. Контекст и проблема

### 1.1. Текущее поведение
Процедура [`_ОЗП_СоздатьВКассуИзФ2(Ф2Ссылка, СтрокиРК)`](../../../Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl) (стр. 2723–2904) реализует Find-or-Create по обратной ссылке `Ф2 → ВКассу`. Запрос (стр. 2728–2734):

```
ВЫБРАТЬ ПЕРВЫЕ 1
    Д.Ссылка, Д.Проведен, Д.ПометкаУдаления
ИЗ Документ.ВедомостьНаВыплатуЗарплатыВКассу КАК Д
ГДЕ Д.А_РаспределениеФ2 = &Основание
```

При наличии существующей ВКассу процедура **безусловно**:
1. Снимает пометку удаления (стр. 2740–2742).
2. Распроводит её (стр. 2743–2750).
3. Очищает ТЧ `Зарплата`, `А_РасшифровкаВыплатыЗарплатаПоФизлицам`, `Состав` (стр. 2751–2753).
4. Полностью переписывает шапку и ТЧ, проводит заново (стр. 2758–2887).

### 1.2. Конфликт со «взятой в РКО» ВКассу
Когда РКО уже создан и проведён из такой ВКассу, документ [`РасходныйКассовыйОрдер.ПриЗаписи`](../../../Documents/РасходныйКассовыйОрдер/Ext/ObjectModule.bsl) (стр. 1123–1145) при ВКассу-операции «ВыплатаЗарплатыЧерезКассу» выполняет:

```bsl
ДокВедомость.А_Необновлять = Источник.Проведен;  // Истина для проведённого РКО
ДокВедомость.Записать();
ДокРаспределениеФ2.А_Необновлять = Источник.Проведен;
ДокРаспределениеФ2.Закрытый      = Источник.Проведен;
ДокРаспределениеФ2.Записать();
```

Флаг `А_Необновлять = Истина` означает: ВКассу «занята» — РКО уже отразил её в учёте, и любая перезапись разрушит уже сформированные движения.

Сегодня повторный запуск кнопки «Создать ВКассу по отражению ЗП» в форме `А_ОтражениеЗПпоКазне` затирает занятые ведомости, поэтому это нужно блокировать.

### 1.3. Сценарий, который мы защищаем
1. `А_ОтражениеЗПпоКазне` создаёт ВКассу из Ф2 (1-й прогон).
2. По ВКассу выпущен и проведён РКО → `ВКассу.А_Необновлять = Истина`.
3. Пользователь нажимает «Создать ВКассу по отражению ЗП» повторно (например, появилась новая Ф2 в шапке, нужно её сформировать).
4. **Ожидаемое поведение**: уже занятые ВКассу пропускаются и не модифицируются; новые/незанятые — создаются/обновляются.

## 2. Утверждённое решение

### 2.1. Точка вставки — внутри `_ОЗП_СоздатьВКассуИзФ2`
Проверка флага размещается внутри процедуры сразу после успешного `Find`, до любой модификации найденной ВКассу. Паттерн «ранний `Возврат` при `А_Необновлять = Истина`» уже используется в [`А_СобытияОбъектов.Module.bsl:87,558,579`](../../../CommonModules/А_СобытияОбъектов/Ext/Module.bsl) — мы повторяем его.

### 2.2. Поменять подпись процедуры на функцию
`Процедура _ОЗП_СоздатьВКассуИзФ2(Ф2Ссылка, СтрокиРК)` → `Функция _ОЗП_СоздатьВКассуИзФ2(Ф2Ссылка, СтрокиРК)`. Возвращаемое значение — **строковый код результата**:

| Код         | Смысл                                                                             |
| ----------- | --------------------------------------------------------------------------------- |
| `"Создано"` | Документ ВКассу был создан с нуля.                                                |
| `"Обновлено"` | Существующая ВКассу перезаписана (как сейчас).                                  |
| `"Пропущено"` | ВКассу существует и `А_Необновлять = Истина` — не модифицировали.               |
| `"Ошибка"`  | Поймали внутреннюю ошибку (не удалось распровести / провести / записать Ф2).      |

Альтернатива «параметр byref `Структура`» отклонена: код возврата короче, без побочного состояния, легче читать в вызывающей.

### 2.3. Изменение запроса find-or-create
В SELECT добавить поле `А_Необновлять`. Это безопасно: реквизит существует в метаданных (`Documents/ВедомостьНаВыплатуЗарплатыВКассу.xml`, uuid `7093b0ea-8f60-4699-b97a-9c11d0eeb563`).

```diff
 "ВЫБРАТЬ ПЕРВЫЕ 1
 |	Д.Ссылка КАК Ссылка,
 |	Д.Проведен КАК Проведен,
-|	Д.ПометкаУдаления КАК ПометкаУдаления
+|	Д.ПометкаУдаления КАК ПометкаУдаления,
+|	Д.А_Необновлять КАК А_Необновлять
 |ИЗ Документ.ВедомостьНаВыплатуЗарплатыВКассу КАК Д
 |ГДЕ Д.А_РаспределениеФ2 = &Основание";
```

### 2.4. Вставка проверки до модификации
Сразу после `Выб.Следующий()` (стр. 2738) — гард, и в каждой ветке find-or-create устанавливается `КодРезультата`:

```bsl
КодРезультата = "";

Если НЕ Результат.Пустой() Тогда
    Выб = Результат.Выбрать(); Выб.Следующий();

    // === НОВЫЙ ГАРД ===
    Если Выб.А_Необновлять Тогда
        Сообщить("Ф2 " + Строка(Ф2Ссылка) + " → ВКассу " + Строка(Выб.Ссылка)
            + " пропущена (А_Необновлять=Истина, занята РКО)");
        Возврат "Пропущено";
    КонецЕсли;
    // === КОНЕЦ НОВОГО ГАРДА ===

    ВыкВКассу = Выб.Ссылка.ПолучитьОбъект();
    Если Выб.ПометкаУдаления Тогда
        ВыкВКассу.УстановитьПометкуУдаления(Ложь);
    КонецЕсли;
    Если Выб.Проведен Тогда
        Попытка
            ВыкВКассу.Записать(РежимЗаписиДокумента.ОтменаПроведения);
        Исключение
            Сообщить("Не удалось распровести существующую ВКассу " + Строка(Выб.Ссылка) + ": " + ОписаниеОшибки());
            Возврат "Ошибка";
        КонецПопытки;
    КонецЕсли;
    ВыкВКассу.Зарплата.Очистить();
    ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Очистить();
    ВыкВКассу.Состав.Очистить();
    КодРезультата = "Обновлено";
Иначе
    ВыкВКассу = Документы.ВедомостьНаВыплатуЗарплатыВКассу.СоздатьДокумент();
    КодРезультата = "Создано";
КонецЕсли;
```

Важно: проверка **перед** `УстановитьПометкуУдаления(Ложь)`, `Записать(РежимЗаписиДокумента.ОтменаПроведения)` и `Очистить()` трёх ТЧ.

| Место                                                          | Старое                  | Новое                       |

| Гард в §2.4 (новый код)                                        | —                       | `Возврат "Пропущено";`      |
| `Исключение` при `ОтменаПроведения` найденной ВКассу (~2747)   | `Возврат;`              | `Возврат "Ошибка";`         |

### 2.6. Изменение вызывающей `СоздатьВедомостиВКассуПоОтражениюЗП`
Текущий блок (стр. 2703–2709):

```bsl
Попытка
    _ОЗП_СоздатьВКассуИзФ2(Ф2Ссылка, СтрокиРК);
    КолОбработано = КолОбработано + 1;
Исключение
    Сообщить("Ошибка создания ВКассу для " + Строка(Ф2Ссылка) + ": " + ОписаниеОшибки());
    КолОшибок = КолОшибок + 1;
КонецПопытки;
```

Превращается в:

```bsl
Попытка
    Код = _ОЗП_СоздатьВКассуИзФ2(Ф2Ссылка, СтрокиРК);
    Если      Код = "Пропущено" Тогда КолПропущеноБлок = КолПропущеноБлок + 1;
    ИначеЕсли Код = "Ошибка"    Тогда КолОшибок         = КолОшибок + 1;
    Иначе                              КолОбработано    = КолОбработано + 1;
    КонецЕсли;
Исключение
    Сообщить("Ошибка создания ВКассу для " + Строка(Ф2Ссылка) + ": " + ОписаниеОшибки());
    КолОшибок = КолОшибок + 1;
КонецПопытки;
```

Объявить `КолПропущеноБлок = 0;` рядом с `КолОбработано` и `КолОшибок` в начале процедуры.

### 2.7. Итоговая строка
Старая (стр. 2712–2717):

```bsl
ИтогТекст = "ОтражениеЗПпоКазне → ВКассу: создано/обновлено " + КолОбработано
    + ", ошибок " + КолОшибок;
Если ПропускТипов > 0 Тогда
    ИтогТекст = ИтогТекст + ", пропущено А_РаспределениеЗаработнойПлаты строк " + ПропускТипов;
КонецЕсли;
Сообщить(ИтогТекст);
```

Дополняется:

```bsl
Если КолПропущеноБлок > 0 Тогда
    ИтогТекст = ИтогТекст + ", пропущено заблокированных (А_Необновлять) " + КолПропущеноБлок;
КонецЕсли;
```

### 2.8. Обратная ссылка `Ф2.А_ВедомостьВКассу`
При пропуске **не трогаем**. Логика:
- ВКассу была создана этой же процедурой ранее → `Ф2.А_ВедомостьВКассу` уже указывает на неё.
- Если её перезаписывать — спровоцируем `ОбменДанными.Загрузка = Истина; Ф2.Записать()`, что приведёт к лишнему движению (и потенциально вызовет `РаспределениеФ2.ПередЗаписью` через подписки).

### 2.9. Поведение при пометке удаления + флаге
Если найденная ВКассу имеет одновременно `ПометкаУдаления = Истина` и `А_Необновлять = Истина` — гард срабатывает первым, и мы **не снимаем пометку**. Это согласуется с контрактом «не трогать». Технически такой случай маловероятен (РКО.ПередЗаписью не дал бы пометить занятую ВКассу), но мы не делаем дополнительных проверок ради этой аномалии.

### 2.10. Обратимость
Распроведение РКО автоматически выставит `ВКассу.А_Необновлять = Ложь` (формула `Источник.Проведен`). После этого повторный запуск `_ОЗП_СоздатьВКассуИзФ2` обновит ВКассу как раньше. Никаких отдельных «разблокировщиков» не требуется.
