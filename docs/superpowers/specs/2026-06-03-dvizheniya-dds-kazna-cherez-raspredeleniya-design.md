## 1. Задача в одном абзаце

Из `А_ОтражениеЗПпоКазне.РаспределениеКазна` сгруппировать суммы по `(ДокРаспределениеЗП, Подразделение, СтатьяДвиженияДенежныхСредств)`, залить их в ТЧ `А_ДвижениеДДС` соответствующего документа-распределения (Ф1 → `А_РаспределениеЗаработнойПлаты`, Ф2 → `РаспределениеФ2`) и провести документ; при проведении каждый документ пишет движения `А_ДвиженияДенегДоходыРасходы`, выводя недостающие измерения регистра (ТипДС, Организация, ОргБух, БанковскийСчетКасса) из типа документа и его реквизитов. Итог: Σ движений per `(Подразделение, Статья)` = Σ Казны (точное зеркало БДДС), но с обогащением ЕРП-измерениями.

## 2. Что есть (структуры, проверено через get_metadata_structure)

### 2.1 Регистр `А_ДвиженияДенегДоходыРасходы` (синоним «Движения ДС — Доходы/Расходы по Казне»)
- **Регистратор:** `Документ.РаспределениеФ2`, `Документ.А_РаспределениеЗаработнойПлаты`.
- **Измерения:** `БанковскийСчетКасса` (БанковскиеСчетаОрганизаций | Кассы), `Организация`, `А_ОрганизацияБухгалтерия`, `ТипДенежныхСредств` (Перечисление: Наличные, Безналичные, …), `СтатьяДвиженияДенежныхСредств`, `Подразделение` (СтруктураПредприятия).
- **Ресурс:** `Сумма`. (Без ВидДвижения — одна сумма.)

### 2.2 ТЧ `А_ДвижениеДДС` (на ОБОИХ документах, идентична)
`{Подразделение (СтруктураПредприятия), СтатьяДвиженияДенежныхСредств, Сумма}`. **Проще регистра** — остальные измерения выводятся при проведении.

### 2.3 `ОбработкаПроведения` обоих документов — **ПУСТЫЕ заглушки** (регистр в RegisterRecords объявлен, кода нет). Greenfield.

### 2.4 Источник `А_ОтражениеЗПпоКазне.РаспределениеКазна`
`{Организация, Сотрудник, СтатьяДвиженияДенежныхСредств, Подразделение (СтрПредпр, исправлено при загрузке), НаправленияДеятельности, Сумма, ДокРаспределениеЗП (составной: РаспределениеФ2 | А_РаспределениеЗаработнойПлаты), ФормаPL (Форма1/Форма2), …}`.

### 2.5 Реквизиты документов-распределения (для вывода измерений)
- `А_РаспределениеЗаработнойПлаты`: `Организация` (реальное юр.лицо), `Направление`, ТЧ `Сотрудники/Распределение/СотрудникиИсключения/А_ДвижениеДДС`. **Нет** прямого поля банк-счёта; **нет** флага `А_Необновлять`.
- `РаспределениеФ2`: `Организация`, `Направление`, **`А_ВедомостьВКассу`** (→ `.Касса`), `А_Необновлять`, `А_Начисление`, ТЧ `Сотрудники/Распределение/А_ДвижениеДДС`.

## 4. Часть A — заполнение (новый метод на `А_ОтражениеЗПпоКазне`)

Новый экспортный метод `СоздатьДвиженияДДСПоОтражениюЗП()` + кнопка в форме (по образцу `СоздатьВедомостиВКассуПоОтражениюЗП`):

```
0. GUARD: документ Проведён.
1. Запрос: РаспределениеКазна (Ссылка = ЭтотДокумент), ГДЕ ЗначениеЗаполнено(ДокРаспределениеЗП) И Сумма<>0,
   СГРУППИРОВАТЬ ПО ДокРаспределениеЗП, Подразделение, СтатьяДвиженияДенежныхСредств; СУММА(Сумма).
2. По ДокРаспределениеЗП построить Соответствие(Док → Массив строк {Подр, Статья, Сумма}).
3. Для каждого Док (А_РаспределениеЗаработнойПлаты | РаспределениеФ2):
   3.1 GUARD (только РаспределениеФ2): если А_Необновлять = Истина → пропустить + Сообщить (как ведомость, §15 knowledge).
   3.2 Об = Док.ПолучитьОбъект(); если Проведён → ОтменаПроведения; перечитать объект.
   3.3 Об.А_ДвижениеДДС.Очистить(); залить строки {Подр, Статья, Сумма}.
   3.4 Об.Записать(РежимЗаписиДокумента.Проведение).   // → движения через Часть B
4. Сообщить итог: обработано/пропущено/ошибок, Σ.
```
Идемпотентно (повторный вызов перезаливает ТЧ и движения, Δ=0).

> ⚠️ **Порядок (Ф2-касса):** `БанковскийСчетКасса` Ф2 берётся из `РаспределениеФ2.А_ВедомостьВКассу.Касса`. Поэтому ведомости в кассу должны быть созданы (`СоздатьВедомостиВКассуПоОтражениюЗП`) ДО движений ДДС, иначе касса пустая → fallback (§6 discovery #2).

## 5. Часть B — `ОбработкаПроведения` обоих документов (по образцу `А_ПередачаНачислений.ОбработкаПроведения`)

В каждом из `А_РаспределениеЗаработнойПлаты` и `РаспределениеФ2`:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	Движения.А_ДвиженияДенегДоходыРасходы.Записывать = Истина;
	Движения.А_ДвиженияДенегДоходыРасходы.Очистить();

	ТипДС    = Перечисления.ТипыДенежныхСредств.Безналичные; // для РаспределениеФ2 → .Наличные
	УпрОрг   = А_Привилегированный.А_ПолучитьОрганизациюУпр();
	БанкКасса = _ДДС_ОпределитьБанкКассу();   // Ф1: банк-счёт Организации; Ф2: А_ВедомостьВКассу.Касса

	Для Каждого Стр Из А_ДвижениеДДС Цикл
		Если Стр.Сумма = 0 ИЛИ НЕ ЗначениеЗаполнено(Стр.СтатьяДвиженияДенежныхСредств) Тогда Продолжить; КонецЕсли;
		Запись = Движения.А_ДвиженияДенегДоходыРасходы.Добавить();
		Запись.Период                     = Дата;
		Запись.БанковскийСчетКасса        = БанкКасса;
		Запись.Организация                = УпрОрг;
		Запись.А_ОрганизацияБухгалтерия   = Организация;          // реальное юр.лицо документа
		Запись.ТипДенежныхСредств         = ТипДС;
		Запись.СтатьяДвиженияДенежныхСредств = Стр.СтатьяДвиженияДенежныхСредств;
		Запись.Подразделение              = Стр.Подразделение;   // исходное
		Запись.Сумма                      = Стр.Сумма;           // положительная
	КонецЦикла;
КонецПроцедуры
```
- `ТипДС` — единственное отличие тел двух процедур (Безналичные / Наличные).
- `_ДДС_ОпределитьБанкКассу()` — служебная функция документа: Ф1 → основной банк-счёт `Организация`; Ф2 → `А_ВедомостьВКассу.Касса` (с fallback).
- **`ОбменДанными.Загрузка` guard в `ПередЗаписью`** (house style) — при загрузке обмена не пере-заполнять ТЧ; но движения проводятся стандартно.

## 6. Discovery (Rule #-1, ОБЯЗАТЕЛЬНО ПЕРЕД BSL)

1. **Основной банк-счёт юр.лица (Ф1 `БанковскийСчетКасса`):** `Справочник.Организации` НЕ имеет прямого атрибута. Источник — `Справочник.БанковскиеСчетаОрганизаций` (Владелец=Организация). Определить признак «основного» (флаг / РегистрСведений / первый по Коду) через Python COM/meta. Зафиксировать правило выбора.
2. **Ф2 касса fallback:** что если `РаспределениеФ2.А_ВедомостьВКассу` пуст (ведомость не создана) — оставить `БанковскийСчетКасса` пустым или взять кассу по умолчанию. Подтвердить порядок «ведомости → движения ДДС».
3. **Rule #5 / NotebookLM:** есть ли у `А_РаспределениеЗаработнойПлаты`/`РаспределениеФ2` скрытый флаг-защита от перезаписи обменом (как `А_Обработан`/`А_ВведенВЕРП` у ПКО/Приобретения) — чтобы запись `А_ДвижениеДДС` через COM/UI не затёрлась подпиской обмена `А_СобытияОбъектов`. Проконсультироваться с NotebookLM (notebook BAS ERP 2.5) о скрытых полях этих документов.
4. **Эталон + контрольные суммы:** на эталонном `А_ОтражениеЗПпоКазне` (№000000005 — 926 строк РаспределениеКазна, или №000000001) выгрузить Σ РаспределениеКазна per `(ДокРаспределениеЗП, Подразделение, Статья)` и per `ФормаPL`; это эталон для проверки движений.
5. **Запрос группировки** (Часть A) — прогнать через `mcp__1c-workerp__execute_query` ДО BSL.

## 7. Edge cases / грабли

| Случай | Поведение |
|---|---|
| `ДокРаспределениеЗП` пуст в строке РаспределениеКазна | пропустить (нет целевого документа) |
| `РаспределениеФ2.А_Необновлять = Истина` (занят проведённым РКО) | пропустить заполнение (как ведомость) |
| `А_ВедомостьВКассу` пуст (Ф2) | `БанковскийСчетКасса` пустой или fallback (§6 #2) |
| Нет основного банк-счёта у юр.лица (Ф1) | `БанковскийСчетКасса` пустой + `Сообщить` (не падать) |
| Документ-распределение не найден/помечен на удаление | пропустить + лог |
| Алиасы запросов | НЕ использовать `В`, `ПО`, `ИЗ`, `КАК` как алиасы (LESSONS §4); регистр — `ДДС`, подразделение — `Подр` |

## 10. TL;DR для исполнителя

1. **Discovery (§6):** основной банк-счёт юр.лица; флаг защиты обмена (NotebookLM); эталон-суммы; тест запроса группировки.
2. **Часть A (§4):** `СоздатьДвиженияДДСПоОтражениюЗП` — группировка РаспределениеКазна по (ДокРаспределениеЗП, Подр, Статья) → залить `А_ДвижениеДДС` целевого документа → провести; гард `А_Необновлять` (Ф2).
3. **Часть B (§5):** `ОбработкаПроведения` обоих документов → движения `А_ДвиженияДенегДоходыРасходы` (ТипДС по типу дока, Орг=управ, ОргБух=Организация, БанкКасса выводится, Подр/Статья/Сумма из ТЧ).
4. **Приёмка (§9):** Σ движений = Σ Казны per (Подр, Статья); ТипДС/Орг/ОргБух корректны; идемпотентно; копия в конфигурацию + загрузка.

**Главные ловушки:** Подразделение = исходное (НЕ корень); Сумма положительная; Организация=управ vs ОргБух=юр.лицо документа; флаг защиты обмена (Rule #5); все запросы — Python COM ПЕРЕД BSL.
