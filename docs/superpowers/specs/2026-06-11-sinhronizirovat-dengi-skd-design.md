## Цель (сценарий бухгалтера)

Открываю обработку → «Сформувати» → вижу **ту же таблицу, что в отчёте** (иерархия организаций/счетов, ЕРП | Бухгалтерия | Расхождение по 4 показателям, итоги). Вижу расхождение на конец месяца → **кликаю по ячейке** → внизу документы этого счёта (при «По дням» — за конкретный день) со статусами и действиями: что провести/распровести/переобменять. Жму «Синхронізувати» — выбранные действия выполняются (Фаза 3, как сейчас).

## Архитектура v6

1. **Макет СКД.** Скопировать `Templates/ОсновнаяСхемаКомпоновкиДанных` отчёта в обработку 1:1 (внешняя обработка поддерживает ChildObjects → Template). Не редактировать схему — единый источник правды с отчётом.
2. **Реквизиты.** В шапку добавить `ПоДням` (Булево). Удалить ТЧ `ТаблицаРасхождений` (плоская верхняя таблица упраздняется — её роль берёт СКД-вывод). ТЧ `ТаблицаДокументов` — без изменений.
3. **Модуль объекта.**
   - Скопировать из отчёта функции `ПолучитьОстаткиЕРП_Бух(Нач, Кон, ПоДням)` и `ПолучитьОстаткиBuhBud(V83, Нач, Кон, ПоДням)` как есть (боевой код: ссылки `БанковскиеСчетаОрганизаций`, валютные счета, 315-фоллбек, `А_Привилегированный.ПолучитьСправочникUID`). Существующие `ПолучитьОстаткиЕРП/ПолучитьОстаткиBuhBud/СвестиТаблицы` обработки удалить.
   - Новая экспортная `ПостроитьДанныеСравнения()` — возвращает структуру 4 таблиц для внешних наборов СКД (по флагу ПоДням «дневные» пустые/заполненные, как в отчёте).
   - `АнализДокументов_ПоСчету` параметризовать: `(V83, БанковскийСчетСсылка, НачПериода, КонПериода, УзелОбмена)` — вместо чтения строки ТЧ и реквизитов объекта. UID счёта — из ссылки. Логика Фаз 2–3 (переводы-пары, статусы, `ЕстьРасхождение`) не меняется.
4. **Форма.**
   - Верх: `ПолеТабличногоДокумента` (реквизит `РезультатСКД` типа ТабличныйДокумент) вместо таблицы расхождений; рядом флажок «По днях». Кнопки «Вибрати всі/Зняти виділення», УО и обработчики верхней таблицы удалить.
   - «Сформувати» (сервер): собрать настройки СКД (Период из `НачалоПериода/ОкончаниеПериода`, параметр `ПоДням`; если заполнен `ФильтрБанковскийСчет` — добавить отбор `БанковскийСчетКасса = счёт`), скомпоновать с `ДанныеРасшифровки` (адрес во временном хранилище формы), вывести в `РезультатСКД`.
   - **Расшифровка** (`РезультатСКДОбработкаРасшифровки`): из `ДанныеРасшифровкиКомпоновкиДанных.Элементы[Расшифровка].ПолучитьПоля()` достать `БанковскийСчетКасса` (и `ПериодДень` при ПоДням; поднимаясь по родителям элемента расшифровки, если поле не в ячейке). Если счёт получен → серверный вызов Фазы 2 с периодом = весь период или `НачалоДня(ПериодДень)..КонецДня(ПериодДень)` → нижняя таблица + фильтр по счёту. Если кликнули по группировке организации/счёта-бух — сообщение «оберіть банківський рахунок».
   - Кнопка **«Аналіз всіх розбіжностей»**: на сервере по таблицам сравнения собрать счета, где хотя бы одно из 4 расхождений ≠ 0 (свод ЕРП vs УПП по `БанковскийСчетКасса`), и прогнать Фазу 2 по каждому за весь период.
   - Нижняя таблица: фильтр = счёт последней расшифровки + «Тільки розбіжності» (по `ЕстьРасхождение`); «Синхронізувати» — как сейчас.
5. **Что удаляется** (никаких хвостов): ТЧ `ТаблицаРасхождений` из описателя, её колонки/обработчики/УО на форме, `СравнитьОстатки()/СвестиТаблицы()` и старые функции остатков из модуля, сортировка по |Різниці| (итоги и порядок даёт СКД).

## Критерии приёмки

- Таблица в обработке визуально и по цифрам совпадает с отчётом за тот же период (тот же макет СКД, те же данные).
- Клик по счёту с расхождением заполняет нижнюю таблицу документами этого счёта; при «По дням» — документами конкретного дня.
- Переводы-пары по-прежнему «Переказ: синхронно»/честные статусы (регрессия 1432, депозит).
- Фаза 3 работает без изменений.
