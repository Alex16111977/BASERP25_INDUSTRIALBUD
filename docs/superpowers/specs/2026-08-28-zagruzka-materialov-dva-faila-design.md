# Спека: обработка «Загрузка материалов СС по двум файлам в одну СС» (BuhBud)

Дата: 2026-08-28. Статус: дизайн утверждён пользователем («да пиши и сам делай»).

## Задача

Загрузить материалы из ДВУХ Excel-файлов (лист «Проект СС») в ОДНУ спецификацию — элемент `Справочник.СтруктураСебестоимости` базы **BuhBud** (`Srvr="SQLSERVER";Ref="bas_industrialbud"`, Usr cfo/2442):

- `_Rarzrabotki/Загрузка СС/СС ООН АДМИН/уніф СВ S1 Новий Шаблон 21.08.xlsx`
- `_Rarzrabotki/Загрузка СС/СС ООН АДМИН/уніф СВ S3 Новий Шаблон 21.08.xlsx`

Дорабатывается заготовка `_Rarzrabotki/Загрузка СС/Загрузка материалов СС по двум файлам в одну СС.xml` (+папка) — байт-копия «Загрузка материалов в СС».

**Решения пользователя:** поле Модуль в ТЧ Комплектующие НЕ добавляем (в BuhBud его нет, конфигурацию не меняем) → загрузка всегда объединённая с ПОЛНОЙ перезаписью ТЧ; файлов в таблице может быть N (не жёстко два).

## Проверенные факты (инспекция 2026-08-28)

- ТЧ `Комплектующие` (живая BuhBud): ОбщееНазвание, Номенклатура, Единица, Количество, Сумма, Этап, НоменклатураСС, ЕдиницаСС, НеСовпадает, ЕдиницаОбщееНазвание, Цена, НоменклатураСтарая. Поля Модуль НЕТ. Выгрузка `_Rarzrabotki/BASEBuh/Catalogs/СтруктураСебестоимости.xml` актуальна (совпадает с живой).
- Движок загрузки — в МОДУЛЕ ОБЪЕКТА справочника. Живые экспорты (проверено COM): `ОтобратьМатериалы(СырыеСтроки, ПротоколОтбора)`, `ЗаполнитьКомплектующиеИзСырыхСтрок(СырыеСтроки)`, `НормализоватьНаименование`. Экспортов `ЗаполнитьКомплектующиеОтобраннымиСтроками` / `НовыйПротоколЗагрузки` в живой базе НЕТ (память о них устарела — выгрузка BASEBuh здесь совпадает с живой базой).
- `ЗаполнитьКомплектующиеИзСырыхСтрок`: своя транзакция, внутри сам вызывает `ОтобратьМатериалы` (стоп-правило: Наименование=«№» или Единица=«Од. виміру»; наследование этапа; подхват строк без типа), затем `Комплектующие.Очистить()` + заполнение (get-or-create этапов/общих названий, дозаполнение единиц карточек) + контроль итогов. Объект НЕ записывает.
- .epf-обёртка (текущая «Загрузка материалов в СС») добавляет: внешнюю транзакцию, `Записать()`, сверку записанного с базой запросом.
- Клиентское чтение (форма текущей обработки): COM Excel ReadOnly, лист «Проект СС», сырые строки `{Ряд, Тип←C, Этап←E, ОбщееНазвание←H, Наименование←G, Единица←I, Количество←J(.Value), Сумма←O(.Value, колонка 15)}`.
- **Эталоны новых файлов** (правила отбора воспроизведены в Python):
  - S1: **188 строк** (65 по типу «Матеріал» + 123 подхвачено без типа), ΣКол 17 492.300, ΣСумма 842 274.68, стоп-строка 388;
  - S3: **137 строк** (60 + 77), ΣКол 17 893.060, ΣСумма 792 178.85, стоп-строка 430;
  - вместе: **325 строк, ΣСумма 1 634 453.53**.
  - Раздел «Загальновиробничі витрати» (S1 ряд 357, S3 ряд 399) НИЧЕГО не добавляет в отбор (его строки не проходят фильтр «потерянного материала») — отдельная граница не нужна.
  - Строки «Матеріал» с пустым наименованием: S1 — 32, S3 — 62 (пропускаются, как и раньше).

## Архитектура (подход «отбор per-файл + объединение», конфигурация BuhBud не меняется)

Обработка для каждого файла вызывает живой `ОтобратьМатериалы` (стоп-правило и подхват отрабатывают в границах СВОЕГО файла), объединяет отобранные строки и подаёт их в `ЗаполнитьКомплектующиеИзСырыхСтрок`, **замаскировав обратно под сырые**: `{Ряд, Тип:"Матеріал", Этап(уже разрешён), ОбщееНазвание, Наименование:НоменклатураСС, Единица:ЕдиницаСС, Количество, Сумма}`. Повторный отбор внутри движка пропускает такие строки 1:1 (тип задан, этап заполнен, стоп-строк нет). Протоколы отбора по каждому файлу обработка сохраняет и выводит сама (при втором проходе движка ПодхваченоБезТипа закономерно 0).

## Метаданные обработки

- Внутреннее имя `ЗагрузкаМатериаловССПоДвумФайлам`, синоним «Загрузка материалов СС по двум файлам в одну СС». Переименование в 4 местах: Name, GeneratedType, DefaultForm, тип реквизита Объект в Form.xml.
- Все GUID регенерировать (байт-копия!), ClassId не трогать.
- Реквизиты: оставить `ДокСтруктураСебестоимости` (`cfg:CatalogRef.СтруктураСебестоимости`); УДАЛИТЬ `ИмяФайла` и все 9 реквизитов контура «обновление количеств» (ИмяФайлаОбновления, ЛистОбновления, СтрокаШапки, ПерваяСтрокаДанных, КолонкаНомерСтроки, КолонкаНоменклатураСС, КолонкаЕдиницаЗагНазвы, КолонкаКоличество, КолонкаСумма) — YAGNI, этот контур остаётся в старой обработке.
- Новая ТЧ `Файлы`: `ИмяФайла` (Строка, переменная).
- Регистрация БСП (`СведенияОВнешнейОбработке`) сохранить: Наименование «Завантаження матеріалів у СС з двох файлів», версия 1.0.

## Форма

Поле СС; таблица «Файлы» (колонка «Имя файла», выбор через `ДиалогВыбораФайла`, фильтр `Книги Excel|*.xlsx;*.xls`); команда «Загрузить материалы». Валидации: СС выбрана, таблица не пуста, файлы указаны, дубли путей запрещены.

## Клиент

Для каждой строки ТЧ Файлы — чтение как в текущей обработке (COM Excel, `Open(файл, 0, Истина)` ReadOnly, лист «Проект СС» по имени; лист не найден → перечень листов в сообщении и отмена загрузки). Наборы сырых строк передаются на сервер ОДНИМ вызовом (массив структур `{ИмяФайла, СырыеСтроки}`).

## Сервер (ObjectModule обработки)

`ЗагрузитьМатериалыИзНаборов(СтруктураСеб, Наборы) Экспорт` — внешняя транзакция:
1. Для каждого набора: `ОтобратьМатериалы` движка (через непишущийся `СоздатьЭлемент()`), протокол отбора запоминается per файл; отобранные строки маскируются под сырые и накапливаются в общий массив.
2. `ОбъектСеб.ЗаполнитьКомплектующиеИзСырыхСтрок(ОбщийМассив)` — очистка ТЧ, заполнение, get-or-create, контроль итогов (внутри движка).
3. `Результат.Ошибка` → исключение → откат.
4. `ОбъектСеб.Записать()` + сверка записанного с базой (строк/ΣКол/ΣСумма — как в текущей .epf).
5. Протокол = протокол движка + блок по файлам: имя, строк по типу/подхвачено/стоп-строка, Σ Сумма файла; ошибка → откат всего.
