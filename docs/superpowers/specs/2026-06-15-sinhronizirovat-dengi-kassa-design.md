# Спецификация / ПРОМТ: обработка `СинхронизироватьДеньгиКасса` (ЕРП ↔ Казна, наличные/касса)

> Дата: 2026-06-15. Конфигурация: BAS ERP 2.5 (v2.13), ТОВ ІНДАСТРІАЛБУД.
> Это одновременно **дизайн-спецификация** и **готовый промт исполнителю**. Каждый запрос помечен как «черновик — сначала проверить через Python COM» согласно Rule #-1.

---

## 0. Цель

Создать НОВУЮ внешнюю обработку `_Rarzrabotki/Обработки/СинхронизироватьДеньгиКасса.xml`, которая **аналогично** существующей `СинхронизироватьДеньги` показывает расхождения и позволяет синхронизировать, но:

- сравнивает **кассу (наличные)** между базой **Казна (BuhKazn)** и базой **ЕРП (BaseERP)**;
- из сверки и анализа **исключает** документы ЕРП, у которых:
  - `А_ВведенВЕРП = Истина` (введён прямо в ЕРП, в Казне его нет), **ИЛИ**
  - заполнено `А_ОрганизацияБухгалтерия` (документ пришёл из базы Бухгалтерия, в Казне его нет).

Объём (утверждено заказчиком): **все 3 фазы** (сверка → анализ документов → выполнение действий).
База сравнения Фазы 1 (утверждено): **4 колонки** — НачОстаток / Приход / Расход / КонОстаток, **сторона ЕРП фильтруется** (исключения вычитаются и из остатков/оборотов, а не только из списка документов).

## 2. Подтверждённые факты (проверено на живой базе BaseERP через MCP)

1. **Касса в ЕРП** = `РегистрНакопления.ДенежныеСредстваНаличные`.
   - Измерения: `Касса` (Справочник.Кассы), `Организация`, `Подразделение`.
   - Ресурсы: `Сумма`, `СуммаУпр`, `СуммаРегл`. Для сверки используем **`Сумма`** (как виртуальная таблица остатков в отчёте-эталоне).
   - Стандартный реквизит `ВидДвижения` (Приход/Расход), `Активность`, `Регистратор`, `Период`.
   - Регистраторы за 2025–2026: **ПКО, РКО** (основная масса), `РасчетКурсовыхРазниц`, `ВводНачальныхОстатков`. Всего ~2763 записи (регистр маленький → фильтрованные расчёты дёшевы).
2. **ПКО (`ПриходныйКассовыйОрдер`) и РКО (`РасходныйКассовыйОрдер`)** оба имеют реквизиты:
   - `А_ВведенВЕРП` — Булево;
   - `А_ОрганизацияБухгалтерия` — Справочник.Организации.
3. **Узел обмена с Казной (в ЕРП)** = `ПланОбмена.КазначействоBASERP` (единственный с маской «Казн»).
4. **Касса в Казне** = `РегистрНакопления.ДенежныеСредства`, измерение `БанковскийСчетКасса` (составное), реквизит `ВидДенежныхСредств` (Перечисление.ВидыДенежныхСредств: Наличные/Безналичные). Для кассы фильтр `ВидДенежныхСредств = Наличные`.
5. **Маппинг кассы Казна→ЕРП** (из отчёта-эталона): `А_Привилегированный.ПолучитьСправочникUID("Кассы", <UUID Казна>)`; fallback `Справочники.Кассы.НайтиПоКоду` → `НайтиПоНаименованию`.
6. **Подключение к Казне**: `Srvr="SQLSERVER";Ref="BuhKazn";Usr="cfo";Pwd="2442"`.

> ⚠️ Дату-параметры в MCP/COM передавать как **настоящий тип Дата** на сервере 1С (`НАЧАЛОПЕРИОДА`/`КОНЕЦПЕРИОДА`), а не строкой — строковый параметр даёт пустой результат/tz-сдвиг (см. memory `feedback_balans_etalon_period_serverside`).

## 4. ФАЗА 1 — сверка остатков/оборотов по кассам

### 4.1. Сторона ЕРП — ФИЛЬТРОВАННАЯ (ключевое отличие)

Нельзя использовать виртуальную таблицу `.ОстаткиИОбороты` (она не даёт фильтр по реквизитам регистратора). Считаем на **уровне записей** `РН.ДенежныеСредстваНаличные`, агрегируя по кассе, **исключая** движения ПКО/РКО с флагами.

Период запроса: от начала истории до `&КонецПериода` (для расчёта нач.остатка). Регистр мал → допустимо.

Формулы по кассе:
- `НачОстаток = Σ( поток, где Период < НачалоПериода )`, где `поток = +Сумма` (Приход) / `−Сумма` (Расход)
- `Приход = Σ( Сумма, где Период∈[Нач;Кон] И ВидДвижения=Приход )`
- `Расход = Σ( Сумма, где Период∈[Нач;Кон] И ВидДвижения=Расход )`
- `КонОстаток = НачОстаток + Приход − Расход`

**Условие исключения (WHERE)** — НЕ включать запись, если её регистратор это ПКО/РКО с `А_ВведенВЕРП` ИЛИ заполненным `А_ОрганизацияБухгалтерия`:

```bsl
// ЧЕРНОВИК — ОБЯЗАТЕЛЬНО проверить через Python COM (NULL в цепочках ВЫРАЗИТЬ — классическая ловушка)
ВЫБРАТЬ
    Дв.Касса КАК Касса,
    СУММА(ВЫБОР КОГДА Дв.Период < &НачалоПериода
                 ТОГДА ВЫБОР КОГДА Дв.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
                              ТОГДА Дв.Сумма ИНАЧЕ -Дв.Сумма КОНЕЦ
                 ИНАЧЕ 0 КОНЕЦ) КАК НачОстаток,
    СУММА(ВЫБОР КОГДА Дв.Период >= &НачалоПериода И Дв.Период <= &КонецПериода
                   И Дв.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
                 ТОГДА Дв.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Приход,
    СУММА(ВЫБОР КОГДА Дв.Период >= &НачалоПериода И Дв.Период <= &КонецПериода
                   И Дв.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Расход)
                 ТОГДА Дв.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Расход
ИЗ
    РегистрНакопления.ДенежныеСредстваНаличные КАК Дв
ГДЕ
    Дв.Период <= &КонецПериода
    И Дв.Активность
    И НЕ ИСТ_ИсключёнДокумент   // см. ниже — раскрыть в подзапрос/ВЫБОР
СГРУППИРОВАТЬ ПО
    Дв.Касса
```

Реализация признака «исключён» (раскрыть `ИСТ_ИсключёнДокумент`):

```bsl
// флаг ВведенВЕРП (ЕСТЬNULL → ЛОЖЬ для не-ПКО/РКО регистраторов)
ЕСТЬNULL(ВЫРАЗИТЬ(Дв.Регистратор КАК Документ.ПриходныйКассовыйОрдер).А_ВведенВЕРП, ЛОЖЬ)
ИЛИ ЕСТЬNULL(ВЫРАЗИТЬ(Дв.Регистратор КАК Документ.РасходныйКассовыйОрдер).А_ВведенВЕРП, ЛОЖЬ)
// флаг ОрганизацияБухгалтерия заполнена (ЕСТЬNULL → ПустаяСсылка для не-ПКО/РКО)
ИЛИ ЕСТЬNULL(ВЫРАЗИТЬ(Дв.Регистратор КАК Документ.ПриходныйКассовыйОрдер).А_ОрганизацияБухгалтерия,
             ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)) <> ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)
ИЛИ ЕСТЬNULL(ВЫРАЗИТЬ(Дв.Регистратор КАК Документ.РасходныйКассовыйОрдер).А_ОрганизацияБухгалтерия,
             ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)) <> ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)
```

Если задан `ФильтрКасса` — добавить `И Дв.Касса = &Касса`.
Ключ результата — ЕРП-касса по UUID (`Строка(Касса.УникальныйИдентификатор())`).

### 4.2. Сторона Казна — наличные (через COM)

На основе `ПолучитьОстаткиКазна` из отчёта-эталона, но **только Наличные**:

```bsl
// ЧЕРНОВИК — выполняется в Казне через V83.NewObject("Запрос")
ВЫБРАТЬ
    ДС.БанковскийСчетКасса КАК Касса,
    ДС.СуммаНачальныйОстаток КАК НачОстаток,
    ДС.СуммаПриход КАК Приход,
    ДС.СуммаРасход КАК Расход,
    ДС.СуммаКонечныйОстаток КАК КонОстаток
ИЗ
    РегистрНакопления.ДенежныеСредства.ОстаткиИОбороты(&НачалоПериода, &КонецПериода, , ,
        ВидДенежныхСредств = ЗНАЧЕНИЕ(Перечисление.ВидыДенежныхСредств.Наличные)) КАК ДС
ГДЕ
    ДС.СуммаНачальныйОстаток <> 0 ИЛИ ДС.СуммаПриход <> 0
    ИЛИ ДС.СуммаРасход <> 0 ИЛИ ДС.СуммаКонечныйОстаток <> 0
```

Маппинг кассы Казна→ЕРП (как в отчёте): итерировать COM-ТЗ, для каждой строки:
`НС.Касса = А_Привилегированный.ПолучитьСправочникUID("Кассы", V83.String(СтрокаТЗ.Касса.УникальныйИдентификатор()))`;
если пусто — `Справочники.Кассы.НайтиПоКоду(СокрЛП(V83.String(СтрокаТЗ.Касса.Код)))` → `НайтиПоНаименованию`.
UUID-объекты Казны читать **в контексте Казны** через `V83.String(...)` (canon CLAUDE.md). Ссылки Казны НЕ сериализовать (`ЗначениеВСтрокуВнутр` ломает типы).

### 4.3. Свод

Слить ЕРП и Казна по UUID ЕРП-кассы (FULL OUTER через `Соответствие`, как `СвестиТаблицы` эталона). `Разница = ОстатокЕРП − ОстатокКазна`. Строка попадает в `ТаблицаРасхождений`, если округлённо (2 знака) различается **хотя бы одно** из: НачОстаток, Приход, Расход, КонОстаток. Сортировка по |Разница| убыв. `Синхронизировать = Истина` по умолчанию.

## 5. ФАЗА 2 — анализ документов по кассе

Точечный (`ИндексСтроки`) или по отмеченным строкам — как эталон.

### 5.1. Документы ЕРП по кассе

```bsl
// ЧЕРНОВИК — проверить через Python COM
ВЫБРАТЬ
    Об.Регистратор КАК Регистратор,
    ПРЕДСТАВЛЕНИЕ(Об.Регистратор) КАК РегистраторПредст,
    Об.СуммаПриход КАК Приход,
    Об.СуммаРасход КАК Расход,
    ЕСТЬNULL(ВЫРАЗИТЬ(Об.Регистратор КАК Документ.ПриходныйКассовыйОрдер).А_ВведенВЕРП, ЛОЖЬ)
        ИЛИ ЕСТЬNULL(ВЫРАЗИТЬ(Об.Регистратор КАК Документ.РасходныйКассовыйОрдер).А_ВведенВЕРП, ЛОЖЬ) КАК ВведенВЕРП,
    ЕСТЬNULL(ВЫРАЗИТЬ(Об.Регистратор КАК Документ.ПриходныйКассовыйОрдер).А_ОрганизацияБухгалтерия,
             ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)) <> ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)
        ИЛИ ЕСТЬNULL(ВЫРАЗИТЬ(Об.Регистратор КАК Документ.РасходныйКассовыйОрдер).А_ОрганизацияБухгалтерия,
             ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)) <> ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) КАК ИзБухгалтерии
ИЗ
    РегистрНакопления.ДенежныеСредстваНаличные.Обороты(&НачалоПериода, &КонецПериода, Авто,
        Касса = &Касса) КАК Об
```

Логика по строке:
- Если `ВведенВЕРП ИЛИ ИзБухгалтерии` → **ИСКЛЮЧИТЬ** (не добавлять в `ТаблицаДокументов`). Это и есть требование заказчика.
- Иначе — найти соответствие в Казне через `РегистрСведений.СоответствияОбъектовИнформационныхБаз`:
  ```bsl
  ВЫБРАТЬ ПЕРВЫЕ 1 Соотв.УникальныйИдентификаторПриемника КАК UIDКазна
  ИЗ РегистрСведений.СоответствияОбъектовИнформационныхБаз КАК Соотв
  ГДЕ Соотв.УникальныйИдентификаторИсточника = &ДокЕРП
      И Соотв.УзелИнформационнойБазы ССЫЛКА ПланОбмена.КазначействоBASERP
  ```
  - есть соответствие → по COM проверить документ Казны (тип определить через `Регистратор.Метаданные().Имя` Казны или по `СоответствияОбъектовИнформационныхБаз` приёмник-тип): помечен на удаление / не проведён / проведён → действия как эталон («Розпровести в ЕРП» / «На обмін в Казну» / «Переобмін»); если суммы по кассе совпали → Статус «ОК», Действие пусто.
  - нет соответствия → документ только в ЕРП (и НЕ исключён флагами) → Действие «Розпровести в ЕРП», Статус «Немає в Казні (немає відповідності)».

### 5.2. Обратная проверка — документы только в Казне

Для кассы (касса Казны = парная к ЕРП-кассе; нести `UIDКассаКазна` из Фазы 1, либо мапить ЕРП→Казна повторно) запросить в Казне обороты `РН.ДенежныеСредства` (Наличные) с периодичностью **Регистратор** по этой кассе. Для каждого регистратора:
- получить UUID (`V83.XMLСтрока(Рег.УникальныйИдентификатор())` — COM UUID Казны не конвертируется локально, см. CLAUDE.md);
- если UUID есть среди ЕРП-регистраторов (из 5.1) — пропустить;
- если чистый поток по кассе = 0 — пропустить;
- иначе — кандидат: проверить `СоответствияОбъектовИнформационныхБаз` (Приемник = UID Казны, узел КазначействоBASERP) → если есть ЕРП-источник: проведён без движений / не проведён → действия; если нет — Действие «На обмін в Казну», Статус «Тільки в Казні (немає в ЕРП)».

### 5.3. Признак расхождения

После анализа: `ЕстьРасхождение = НЕ (Статус = "ОК")`. Подсчёт ОК / с діями / потребують рішення — как эталон (для резюме формы).

## 6. ФАЗА 3 — выполнение действий

Диспетчер `ВыполнитьДействиеСтроки` — копия эталона, но «обмен» идёт в Казну:

| Действие | Реализация |
|---|---|
| `Розпровести в ЕРП` | по `UIDДокумента` + `ТипДокумента`: `ПолучитьСсылку` → `ПолучитьОбъект` → `Записать(РежимЗаписиДокумента.ОтменаПроведения)` (локально в ЕРП) |
| `Провести в ЕРП` | найти ЕРП-документ по `СоответствияОбъектовИнформационныхБаз` (Приемник = `UIDДокументаКазна`, узел КазначействоBASERP) → `Записать(Проведение)` |
| `На обмін в Казну` / `Переобмін` | COM в Казну: получить ссылку документа Казны по UUID и типу → `V83.ПланыОбмена.ЗарегистрироватьИзменения(<УзелОбменаКазны>, СсылкаКазны)` |
