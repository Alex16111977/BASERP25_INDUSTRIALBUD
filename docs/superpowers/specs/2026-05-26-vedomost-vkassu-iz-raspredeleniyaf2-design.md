## 1. Контекст и бизнес-сценарий

### 1.1 Что отменено

В двух предыдущих дизайнах:
- Триггер был на `А_ОтражениеЗПпоКазне` (родительский агрегатор)
- В шапке ВКассу — пусто (`FillChecking=DontCheck`)
- Дополнительная архитектура «передача между подразделениями» через `ВзаимозачетЗадолженности`

**Это слишком сложно для текущей задачи.** Пользователь хочет более прямой путь.

### 1.2 Новая идея (одобрена пользователем)

Триггер на самом **`Документ.РаспределениеФ2`** (зеркало Казны в ERP). При нажатии кнопки или при `ПриЗаписи` родителя — создаётся `ВедомостьНаВыплатуЗарплатыВКассу` 1:1 с этим Ф2.

**Бизнес-логика:**
- В Казне (BuhKazn) операционный пользователь создаёт `Документ.РаспределениеФ2` и на его основании сразу делает `Документ.РасходныйКассовыйОрдер` (наличная выплата).
- В ERP `Документ.РаспределениеФ2` приходит через ConvertERP с UUID 1:1.
- Нам нужно в ERP **из этого Ф2** автоматически создать `ВедомостьНаВыплатуЗарплатыВКассу`, чтобы РКО Казны (зеркало в ERP — `Документ.РасходныйКассовыйОрдер`) мог быть связан с ней по полю «Ведомость:».

### 1.3 Конкретный пример (с экрана пользователя)

| Документ | Реквизиты |
|---|---|
| **`РаспределениеФ2 №000000026`** от 10.12.2025 | Направление «Спецтехника», Период выплаты 01.11.2025 – 30.11.2025, Σ ТЧ Сотрудники = **348 800 UAH** (19 ФЛ) |
| **`РасходныйКассовыйОрдер №0000053046`** от 08.12.2025 | Операция «Выплата по ведомости через кассу», Касса «Касса ЗП», Статья ДДС «Оплата за выполненные работы», Подразделение «Спецтехника», Сумма 348 800 UAH. Поле **«Ведомость:» — пустое** |
| **`ВедомостьНаВыплатуЗарплатыВКассу №???`** | **СОЗДАЁТСЯ из Ф2**: шапка Подразделение=«ЦО», ТЧ Зарплата = 19 строк из ТЧ Сотрудники Ф2, ТЧ А_Расшифровка = по строкам ТЧ Распределение Ф2 (детализация по «Автокран XCMG» × «Спецтехника» × часы). После создания — её можно подставить в поле «Ведомость:» РКО (вручную или автоматически). |

### 1.4 Принцип

> 1 `РаспределениеФ2` ↔ 1 `ВедомостьНаВыплатуЗарплатыВКассу` (1:1)
> ↕
> 1 `РасходныйКассовыйОрдер` Казны (наличная выплата) ↔ 1 `Документ.РасходныйКассовыйОрдер` ERP (зеркало)
>
> Все эти 3 документа отражают одну и ту же выплату с разных сторон:
> - **Ф2** — кадровая операция «распределить выплату по сотрудникам и подразделениям»
> - **Ведомость** — учётная операция «зарегистрировать выплату через регистр ЗарплатаКВыплате»
> - **РКО** — кассовая операция «факт расхода наличных»

## 2. Архитектура решения

### 2.1 Образец-паттерн

Используется паттерн `Документ.А_ОтгрузкаПродукции.СоздатьДокументОказанияУслугМеждуПодразделениямиПоОтгрузкаПродукции()` (188 строк):

| Принцип паттерна | Применение к нашей задаче |
|---|---|
| Find-Or-Create по реквизиту-обратной-ссылке родителя | `ВедомостьВКассу.А_РаспределениеФ2 = Ссылка` (родитель) |
| Cleanup существующей дочки + подчинённых ей документов | Распровести + ТЧ.Очистить() для существующей ведомости |
| Триггер в `ПриЗаписи` родителя | `РаспределениеФ2.ПриЗаписи()` → вызов процедуры |
| + отдельная кнопка | `«Создать ведомость в кассу»` в форме Ф2 |
| Запись обратной ссылки в родителе через `ОбменДанными.Загрузка=Истина` | `РаспределениеФ2.А_ВедомостьВКассу = ВедомостьВКассу.Ссылка` |
| Σ из ТЧ родителя → СуммаДокумента дочки | `Σ(Сотрудники Ф2.СуммаНачисления) → ВедомостьВКассу.СуммаПоДокументу` |

### 2.2 Что меняется в основной конфигурации

| Объект | Правка |
|---|---|
| `Documents/ВедомостьНаВыплатуЗарплатыВКассу.xml` | + реквизит шапки `А_РаспределениеФ2` (тип `DocumentRef.РаспределениеФ2`). + ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам` (8 полей, см. §4). |
| `Documents/РаспределениеФ2.xml` | + реквизит шапки `А_ВедомостьВКассу` (тип `DocumentRef.ВедомостьНаВыплатуЗарплатыВКассу`) — обратная ссылка. |
| `Documents/РаспределениеФ2/Ext/ObjectModule.bsl` | + экспортная процедура `СоздатьВедомостьНаВыплатуВКассуПоРаспределениюФ2()` (по образцу А_ОтгрузкаПродукции). + вызов в `ПриЗаписи`. |
| `Documents/РаспределениеФ2/Forms/ФормаДокумента/Ext/Form.xml` | + кнопка «Создать ведомость в кассу». |
| `Documents/РаспределениеФ2/Forms/ФормаДокумента/Ext/Form/Module.bsl` | + обработчик кнопки → вызов процедуры. |

**Что НЕ меняется:**
- Типовое проведение ВедомостьВКассу — без изменений (стандартная ТЧ `Зарплата` пишет в регистр `ЗарплатаКВыплате` как обычно).
- Документ.РасходныйКассовыйОрдер — без изменений (поле «Ведомость:» заполняется вручную пока).
- Никаких CFE.

## 3. Структура новой ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам` в ВКассу

| Поле | Тип | Источник из Ф2 |
|---|---|---|
| `ФизическоеЛицо` | `СправФизическиеЛица` | `Сотрудник.ФизическоеЛицо` (lookup из ТЧ Распределение Ф2) |
| `Сотрудник` | `СправСотрудники` | `Распределение.Сотрудник` Ф2 |
| `Подразделение` | `СправПодразделенияОрганизаций` | Конвертация `Распределение.Подразделение` (СтруктураПредприятия) → ПодразделенияОрганизаций через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению` |
| `НаправлениеДеятельности` | `СправНаправленияДеятельности` | `Распределение.Направление` Ф2 (или шапка `РаспределениеФ2.Направление`) |
| `СтатьяДвиженияДенежныхСредств` | `СправСтатьиДДС` | `Сотрудник.СтатьяЗарплата` (как делает РаспределениеФ2.ОбработкаПроведения при движениях в БДДС) |
| `ОтработаноЧасов` | Число (10, 2) | `Распределение.ОтработаноЧасов` Ф2 |
| `Сумма` | Число (15, 2) | `Распределение.СуммаНачисления` Ф2 |
| `ИдентификаторСтроки` | УникальныйИдентификатор | `Новый УникальныйИдентификатор()` |

**Размер для Ф2 №000000026:** 2 строки в ТЧ Распределение → 2 строки в А_Расшифровке (по «Автокран XCMG» × «Спецтехника» × 26ч / 47ч).

⚠️ **Важно:** Σ в ТЧ А_Расшифровка ≠ Σ в ТЧ Зарплата ведомости (Σ Сотрудники Ф2). Это **не баг** — А_Расшифровка показывает разнесение часов/затрат по подразделениям, а Зарплата — общую сумму к выплате каждому ФЛ. Дополнительный инвариант: Σ А_Расшифровка по уникальным ФЛ может быть подмножеством Σ Зарплата (часть людей могут быть без распределения = идут по ЦО).

## 5. Алгоритм `СоздатьВедомостьНаВыплатуВКассуПоРаспределениюФ2()`

Размещение: `Documents/РаспределениеФ2/Ext/ObjectModule.bsl`, новая область `#Область ЕРП_СоздатьВедомостьНаВыплатуВКассу`.

### 5.1 Псевдокод (по образцу А_ОтгрузкаПродукции)

```bsl
Процедура СоздатьВедомостьНаВыплатуВКассуПоРаспределениюФ2() Экспорт

    // === 1. Найти существующую ведомость по обратной ссылке ===
    ЗапросСущ = Новый Запрос;
    ЗапросСущ.УстановитьПараметр("Основание", Ссылка);
    ЗапросСущ.Текст =
    "ВЫБРАТЬ Д.Ссылка КАК Ссылка, Д.Проведен КАК Проведен
    |ИЗ Документ.ВедомостьНаВыплатуЗарплатыВКассу КАК Д
    |ГДЕ Д.А_РаспределениеФ2 = &Основание";

    // === 2. Cleanup существующей: распровести + очистить ТЧ ===
    Результат = ЗапросСущ.Выполнить();
    Если НЕ Результат.Пустой() Тогда
        Выб = Результат.Выбрать(); Выб.Следующий();
        ВыкВКассу = Выб.Ссылка.ПолучитьОбъект();
        ВыкВКассу.УстановитьПометкуУдаления(Ложь);
        Если Выб.Проведен Тогда
            ВыкВКассу.Записать(РежимЗаписиДокумента.ОтменаПроведения);
        КонецЕсли;
        ВыкВКассу.Зарплата.Очистить();
        ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Очистить();
        ВыкВКассу.Состав.Очистить();
    Иначе
        ВыкВКассу = Документы.ВедомостьНаВыплатуЗарплатыВКассу.СоздатьДокумент();
    КонецЕсли;

    // === 3. Guard: документ Ф2 должен быть проведён ===
    Если НЕ Проведен Тогда
        Возврат;
    КонецЕсли;

    // === 4. Шапка ведомости ===
    ПодразделениеЦО = Справочники.ПодразделенияОрганизаций.НайтиПоНаименованию("ЦО");
    КассаЗП        = _ВЫК_ОпределитьКассу(Организация);   // утиль
    СпособЧерезКассу = Справочники.СпособыВыплатыЗарплаты.НайтиПоНаименованию("Через кассу");

    ВыкВКассу.Дата                = Дата;
    ВыкВКассу.ПериодРегистрации   = НачалоМесяца(КассаДатаС);
    ВыкВКассу.Организация         = Организация;
    ВыкВКассу.Подразделение       = ПодразделениеЦО;
    ВыкВКассу.Касса               = КассаЗП;
    ВыкВКассу.СпособВыплаты       = СпособЧерезКассу;
    ВыкВКассу.ПорядокЗаполненияНалогов = Перечисления.ПорядокЗаполненияНалогов.БезНалогов;
    ВыкВКассу.А_РаспределениеФ2   = Ссылка;
    ВыкВКассу.Ответственный       = Ответственный;
    ВыкВКассу.Комментарий         = "Сформировано из РаспределениеФ2 №" + Номер
                                  + " от " + Формат(Дата, "ДЛФ=DD")
                                  + " (Направление: " + Строка(Направление) + ")";

    // === 5. Кеш ФизЛица по Сотрудникам Ф2 ===
    КешСотрФЛ = _ВЫК_ПостроитьКешСотрудникФЛ(<массив сотрудников из Сотрудники Ф2>);

    // === 6. Кеш ПодразделенияОрганизаций по СтруктураПредприятия ===
    КешПодрОрг = _ВЫК_ПостроитьКешПодрОрг(<массив СтрПредпр из Распределение Ф2>);

    // === 7. ТЧ ЗАРПЛАТА (стандартная — для регистра ЗарплатаКВыплате) ===
    // Источник: ТЧ Сотрудники Ф2 (1 строка на ФЛ)
    Для каждого СтрСотр Из Сотрудники Цикл
        Если НЕ ЗначениеЗаполнено(СтрСотр.Сотрудник) Тогда Продолжить КонецЕсли;
        Если СтрСотр.СуммаНачисления = 0 Тогда Продолжить КонецЕсли;

        ФЛ = КешСотрФЛ[СтрСотр.Сотрудник];
        Если НЕ ЗначениеЗаполнено(ФЛ) Тогда
            Сообщить("Пропуск: для " + СтрСотр.Сотрудник + " не найдено ФизЛицо");
            Продолжить;
        КонецЕсли;

        НовСтр = ВыкВКассу.Зарплата.Добавить();
        НовСтр.Сотрудник = СтрСотр.Сотрудник;
        НовСтр.ФизическоеЛицо = ФЛ;
        НовСтр.Подразделение  = ПодразделениеЦО;        // шапка
        НовСтр.ПериодВзаиморасчетов = НачалоМесяца(КассаДатаС);
        НовСтр.КВыплате = СтрСотр.СуммаНачисления;
        НовСтр.ИдентификаторСтроки = Новый УникальныйИдентификатор();
        // ДокументОснование — оставляем пустым (нет НачислениеЗарплаты-ссылки)
        // СтатьяФинансирования/СтатьяРасходов — TBD: берём с настройки организации или пусто
    КонецЦикла;

    // === 8. НОВАЯ ТЧ А_РасшифровкаВыплатыЗарплатаПоФизлицам ===
    // Источник: ТЧ Распределение Ф2 (Сотр × Подр × Направление × Часы × Сумма)
    Для каждого СтрРасп Из Распределение Цикл
        Если СтрРасп.СуммаНачисления = 0 Тогда Продолжить КонецЕсли;
        Если НЕ ЗначениеЗаполнено(СтрРасп.Сотрудник) Тогда Продолжить КонецЕсли;

        ФЛ = КешСотрФЛ[СтрРасп.Сотрудник];
        ПодрОрг = КешПодрОрг[СтрРасп.Подразделение];   // СтрПредпр → ПодразделенияОрганизаций

        // Статья ДДС — из реквизита сотрудника (как в РаспределениеФ2.ОбработкаПроведения)
        СтатьяДДС = СтрРасп.Сотрудник.СтатьяЗарплата;
        Если НЕ ЗначениеЗаполнено(СтатьяДДС) И ЗначениеЗаполнено(СтрРасп.Сотрудник.Родитель) Тогда
            СтатьяДДС = СтрРасп.Сотрудник.Родитель.СтатьяЗарплата;  // fallback на родителя
        КонецЕсли;

        НовСтр = ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Добавить();
        НовСтр.ФизическоеЛицо = ФЛ;
        НовСтр.Сотрудник      = СтрРасп.Сотрудник;
        НовСтр.Подразделение  = ПодрОрг;
        НовСтр.НаправлениеДеятельности = ?(ЗначениеЗаполнено(СтрРасп.Направление), СтрРасп.Направление, Направление);
        НовСтр.СтатьяДвиженияДенежныхСредств = СтатьяДДС;
        НовСтр.ОтработаноЧасов = СтрРасп.ОтработаноЧасов;
        НовСтр.Сумма           = СтрРасп.СуммаНачисления;
        НовСтр.ИдентификаторСтроки = Новый УникальныйИдентификатор();
    КонецЦикла;

    // Свёртка дублей (если в Распределение Ф2 одинаковые ключи)
    ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Свернуть(
        "ФизическоеЛицо, Сотрудник, Подразделение, НаправлениеДеятельности, СтатьяДвиженияДенежныхСредств",
        "ОтработаноЧасов, Сумма");

    // === 9. ТЧ СОСТАВ (уникальные ФЛ из ТЧ Зарплата) ===
    НабФЛ = Новый Соответствие;
    Для каждого Стр Из ВыкВКассу.Зарплата Цикл
        Если ЗначениеЗаполнено(Стр.ФизическоеЛицо) Тогда
            НабФЛ.Вставить(Стр.ФизическоеЛицо, Истина);
        КонецЕсли;
    КонецЦикла;
    Для каждого КЗ Из НабФЛ Цикл
        НовСтр = ВыкВКассу.Состав.Добавить();
        НовСтр.ФизическоеЛицо = КЗ.Ключ;
        НовСтр.ИдентификаторСтроки = Новый УникальныйИдентификатор();
    КонецЦикла;

    // === 10. Σ СуммаПоДокументу = Σ ТЧ Зарплата ===
    ВыкВКассу.СуммаПоДокументу = ВыкВКассу.Зарплата.Итог("КВыплате");

    // === 11. Запись с проведением + fallback ===
    Попытка
        ВыкВКассу.Записать(РежимЗаписиДокумента.Проведение);
    Исключение
        Сообщить("Ошибка проведения ВКассу: " + ОписаниеОшибки());
        Попытка ВыкВКассу.Записать(РежимЗаписиДокумента.Запись);
        Исключение Сообщить("Не удалось сохранить: " + ОписаниеОшибки());
        КонецПопытки;
    КонецПопытки;

    // === 12. Обратная ссылка в шапку Ф2 (без рекурсии) ===
    Если А_ВедомостьВКассу <> ВыкВКассу.Ссылка Тогда
        ОбъектДляЗаписи = Ссылка.ПолучитьОбъект();
        ОбъектДляЗаписи.А_ВедомостьВКассу = ВыкВКассу.Ссылка;
        ОбъектДляЗаписи.ОбменДанными.Загрузка = Истина;
        ОбъектДляЗаписи.Записать();
    КонецЕсли;

    Сообщить("Создана/обновлена ВедомостьВКассу " + ВыкВКассу.Ссылка
        + " | Зарплата=" + ВыкВКассу.Зарплата.Количество()
        + " | Расшифровка=" + ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Количество()
        + " | Σ=" + Формат(ВыкВКассу.СуммаПоДокументу, "ЧДЦ=2"));

КонецПроцедуры
```

### 5.2 Утилитные процедуры (вынесем в этот же ObjectModule)

## 6. Триггер: кнопка + ПриЗаписи

### 6.1 Кнопка в форме РаспределениеФ2

Командная панель формы документа:
- Команда `СоздатьВедомостьВКассу` (id новой команды, например, id=`8`)
- Заголовок: «Создать ведомость в кассу»
- При нажатии — `Записать()` + проверка `Модифицированность` + вызов `СоздатьВедомостьНаВыплатуВКассуПоРаспределениюФ2()`

### 6.2 ПриЗаписи (автоматический триггер)

В `РаспределениеФ2.ПриЗаписи()` после стандартной обработки:
```bsl
Если НЕ ОбменДанными.Загрузка Тогда
    СоздатьВедомостьНаВыплатуВКассуПоРаспределениюФ2();
КонецЕсли;
```

Чтобы каждое перепроведение Ф2 автоматически пересоздавало/обновляло ведомость. ⚠️ Эту автоматику можно сделать **опциональной** через флаг шапки `А_СоздаватьВедомостьАвтоматически` (Булево, по умолчанию `Истина`) — если пользователь не хочет автоматики при импорте через ConvertERP.

⚠️ **Защита от рекурсии:** обратная ссылка `А_ВедомостьВКассу` пишется через `ОбменДанными.Загрузка = Истина` — это не вызывает повторного `ПриЗаписи`.

## 7. Связь с РасходныйКассовыйОрдер (на этом этапе — ручная)

В РКО ERP (зеркало РКО Казны) есть поле `Ведомость` (тип `Документ.ВедомостьНаВыплатуЗарплатыВКассу`). После создания нашей ведомости пользователь **вручную** подставляет её в это поле в РКО.

**В будущей итерации (out-of-scope сейчас):**
- Автосвязка через UUID Казны: РКО.ДокументОснование (Казна) = РаспределениеФ2 → найти соответствующую ВКассу через `А_РаспределениеФ2 = РКО.ДокументОснование_ERP` → подставить.

## 12. Риски и митигации

| Риск | Митигация |
|---|---|
| В ТЧ Сотрудники Ф2 есть ФЛ, не имеющие записи в `ЗарплатаКВыплате` ERP | ТЧ Зарплата заполняется напрямую из Сотрудники Ф2 (без сверки с регистром). Проведение всё-равно отработает — `ЗарплатаКВыплате` уйдёт «в минус» по таким ФЛ, что отразит «выплата без начисления». Если это нежелательно — фильтровать по остаткам перед заполнением (опция). |
| Подразделение «ЦО» не существует в `ПодразделенияОрганизаций` | Fallback на пустое + предупреждение. Документ создаётся, но проведение может упасть. Решение: автосоздание «ЦО» через привилегированный код. |
| Автотриггер в ПриЗаписи срабатывает при импорте через ConvertERP | Защита: внутри процедуры `Если ОбменДанными.Загрузка Тогда Возврат`. И опциональный флаг `А_СоздаватьВедомостьАвтоматически` на Ф2. |
| ТЧ Зарплата требует `ДокументОснование` (НачислениеЗарплаты) для корректной записи в регистр | Поставим композитную пустую ссылку или ссылку на сам Ф2 (если разрешено типом). Уточним при реализации первым smoke-тестом. |
| «Касса ЗП» имени нет в справочнике Кассы | Список fallback: `Орг.А_ОсновнаяКасса` → первая активная касса → пусто (с предупреждением). |
