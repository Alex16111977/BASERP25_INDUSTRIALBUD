# Спека: внешняя обработка «СинхронизироватьДеньги»

Дата: 2026-06-10
Статус: одобрена пользователем

## Цель

Специализированный инструмент контроля синхронизации **безналичных денежных средств** ERP (BaseERP) ↔ BAS Бухгалтерія (BuhBud). Создаётся на основе денежного раздела обработки `_Rarzrabotki/Обработки/СинхронизироватьТовары`, которая остаётся нетронутой.

Объём — только безналичные: ERP `РегистрНакопления.ДенежныеСредстваБезналичные` ↔ BuhBud `РегистрБухгалтерии.Хозрасчетный`, счета в иерархии `СчетаВБанках` (31x). Касса (наличные) — вне объёма.

## Архитектура: три фазы (как в исходнике)

1. **Сравнение остатков** — остатки+обороты за период с двух сторон, сведение FULL OUTER JOIN, расхождения в ТЧ `ТаблицаРасхождений`.
2. **Анализ документов** — для отмеченных расхождений: регистраторы ERP + сопоставление через `РегистрСведений.СоответствияОбъектовИнформационныхБаз` (узел `ПланОбмена.ОбменУправлениеПредприятиемБухгалтерия20` в BuhBud), обратная проверка BuhBud-only документов; результат с действиями в ТЧ `ТаблицаДокументов`.
3. **Синхронизация** — выполнение действий по отмеченным строкам.

## Структура объекта

Внешняя обработка `СинхронизироватьДеньги`.

**Реквизиты шапки:** `НачалоПериода` (Дата), `ОкончаниеПериода` (Дата), `ПоказыватьТолькоРасхождения` (Булево).
Убраны против исходника: `РазделТовары/РазделДеньги/РазделВзаиморасчеты`, `Номенклатура`, `Склад`.

**ТЧ `ТаблицаРасхождений`:**

## Перенос логики (1:1 из денежных функций исходника)

**Фаза 1:** `ПодключитьсяКBuhBud()` (COM `V83.COMConnector`, строка подключения BuhBud); `ПолучитьОстаткиЕРП()`; `ПолучитьОстаткиBuhBud()` с сохранением боевых особенностей:
- валютные счета: `ВЫБОР КОГДА Остатки.Счет.Валютный ТОГДА ВалютнаяСумма… ИНАЧЕ Сумма…`;
- фильтр организаций: `А_ВБалансе = ИСТИНА`, массив ЄДРПОУ передаётся в COM-запрос;
- **прямая итерация COM-таблицы без `ЗначениеВСтрокуВнутр`** — тип `Справочник.БанковскиеСчета` BuhBud не существует в ERP, сериализация ломает ссылки;
- спец-маппинг счёта 315: поиск `БанковскиеСчетаОрганизаций` по ЄДРПОУ + `А_СчетБухгалтерский=315` + `А_ПоУмолчаниюДляПустыхСчетовИзБухгалтерии`;
- остальные счета: UUID 1:1 через `А_Привилегированный.ПолучитьСправочникUID`, UUID читается в контексте BuhBud (`V83.String(...УникальныйИдентификатор())`).

`СвестиТаблицы()`: ключ — UUID банковского счёта; строка попадает в ТЧ только при ненулевой разнице любого из 4 показателей (Окр до 2 знаков).

**Фаза 2:** обороты `ДенежныеСредстваБезналичные.Обороты(…, Регистратор, БанковскийСчет=&Счет)` + LEFT JOIN `СоответствияОбъектовИнформационныхБаз`; обработка документов ERP:
- пропуск переводов между своими счетами (`ХозяйственныеОперации.ПоступлениеДенежныхСредствСДругогоСчета` / `ПеречислениеДенежныхСредствНаДругойСчет`) — в BuhBud это один документ, в ERP два;
- `ПроверитьДокументВBuhBud()`: состояние (ПометкаУдаления/Проведен) + сумма UNION ALL Дт/Кт по `СчетаВБанках` (`В ИЕРАРХИИ` запрещено в агрегатах);
- действия: «Розпровести в ЕРП» (нет соответствия / удалён / не найден в BuhBud), «На обмін в BuhBud» (не проведён в BuhBud), «Переобмін» (проведён, разница в движениях; при совпадении сумм — статус «ОК», галка снимается).

Обратная проверка BuhBud-only (`Хозрасчетный.ОстаткиИОбороты`, периодичность `Регистратор`, `Субконто1 = банковский счёт BuhBud`, найденный по IBAN):
- **исправление 1:** действие «На обмін в BuhBud» вместо мёртвого «Розпровести в BuhBud» из исходника (обработчика не существовало — строки молча пропускались);
- **исправление 2:** заполняется `ТипДокумента` из `Метаданные().Имя` регистратора BuhBud — без этого Фаза 3 не может получить ссылку для `ЗарегистрироватьИзменения` (в исходнике поле оставалось пустым);
- UUID регистратора — только через `V83.XMLСтрока(...)` (локальная `XMLСтрока` падает на COM-объекте).

**Фаза 3:** без изменений логики: «Розпровести в ЕРП» → `Записать(РежимЗаписиДокумента.ОтменаПроведения)`; «Провести в ЕРП» → поиск через `СоответствияОбъектовИнформационныхБаз` + `Записать(Проведение)`; «На обмін в BuhBud»/«Переобмін» → ленивое COM-подключение, узел `ОбменУправлениеПредприятиемБухгалтерия20`, `V83.ПланыОбмена.ЗарегистрироватьИзменения(Узел, Ссылка)`.

**Не переносится:** весь код разделов Товары/Взаиморасчеты, generic-ветвление по `Раздел`, все отладочные `Сообщить("DEBUG…")` (~30 шт.).

## Форма

Копия исходной `Форма` минус: флаги разделов, группа товарных фильтров (`ГруппаФильтрыТоваров`), колонки `Раздел`/`Измерение2`. Команды: Сформировать, АнализДокументов, Синхронизировать, ВыбратьВсе, СнятьВыделение; флажок ПоказыватьТолькоРасхождения (отбор строк ТЧ документов). Модуль формы — те же обработчики минус `УстановитьВидимостьФильтровТоваров`/`РазделТоварыПриИзменении`; проверка «выбран хотя бы один раздел» удаляется (проверка заполненности периода уже есть и сохраняется).

## XML-описатель

Копия исходного с заменой имени (`СинхронизироватьДеньги`), синонимов (ru/uk) и **генерацией новых UUID** для `ContainedObject.ClassId/ObjectId`, корневого `GeneratedType` и всех `TypeId/ValueId` табличных частей — во избежание конфликта типов с исходной обработкой в одной сессии.

## Обработка ошибок

Как в исходнике: `Попытка/Исключение` вокруг COM-вызовов с информативным `Сообщить`; ошибка подключения к BuhBud прерывает фазу; ошибка по строке в Фазе 3 пишется в `Статус` строки («ПОМИЛКА: …»), счётчики Оброблено/Помилок в итоговом сообщении.

## Тестирование

1. **Python COM тесты до BSL** (Rule #-1/#5), скрипт `_Rarzrabotki/Python/test/test_sinhronizirovat_dengi_queries.py`: 5 запросов (ERP остатки; BuhBud остатки 31x; ERP обороты по регистратору + соответствия; BuhBud обороты по регистратору с Субконто1; BuhBud UNION ALL Дт/Кт по регистратору).
2. `form-validate`, `/1c-bsl-review` модуля объекта.
3. Сборка `/epf-build` против BaseERP.
4. Smoke: Фаза 1 за короткий период через COM (открытие формы + СравнитьОстатки).
5. Фаза 3 на боевых документах автономно не выполняется — проверка кода на 1–2 документах максимум, массовые действия за пользователем.
