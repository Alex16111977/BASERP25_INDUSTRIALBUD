# Дизайн: обработка `СинхронизироватьТоварыТолькоТовары`

Дата: 2026-06-16
Статус: согласован пользователем (объём = только Товари; интерфейс = полный порт стиля Кассы)

## 1. Цель

Создать внешнюю обработку **`СинхронизироватьТоварыТолькоТовары`** — инструмент сверки
синхронизации **ERP ↔ BuhBud только по товарным остаткам/движениям номенклатуры**.

Получается из существующей `СинхронизироватьТовары` путём:
1. удаления денежного (`Гроші`) и взаиморасчётного (`Взаєморозрахунки`) разделов;
2. переделки формы в «удобный» интерфейс по эталону `СинхронизироватьДеньгиКасса`
   (включая достройку ObjectModule под per-row операции).

## 2. Исходное состояние

- `_Rarzrabotki/Обработки/СинхронизироватьТоварыТолькоТовары/` **уже существует**, но это
  **побайтовая копия** `СинхронизироватьТовары` (ObjectModule 127357 байт идентичен;
  деньги не вырезаны, интерфейс не переделан, дескриптор хранит идентификаторы источника).
  Работаем поверх этой копии (перезапись файлов), а не «с нуля».

### Источник `СинхронизироватьТовары` — карта
Три раздела, обобщённая модель данных:
- `ТаблицаРасхождений`: `Раздел`, `Измерение1`, `Измерение2`, `Нач/Приход/Расход/Остаток`
  (ЕРП и Бух), `Разница`, `Синхронизировать`, `Измерение1Ссылка`, `Измерение2Ссылка`.
- `ТаблицаДокументов`: `Раздел`, `Измерение1/2`, `ТипДокумента`, `ДокументЕРП`, `ДокументБух`,
  `КоличествоЕРП`, `КоличествоБух`, `UIDДокумента`, `UIDДокументаБух`, `ЕстьСоответствие`,
  `Действие`, `Статус`, `ЕстьРасхождение`, `Синхронизировать`.

Товарный раздел **самодостаточен** по 3 фазам:
- Фаза 1 (`СравнитьОстатки_Товары`): ЕРП `РегистрНакопления.ТоварыНаСкладах.ОстаткиИОбороты`
  (Номенклатура+Склад, `ТипНоменклатуры=Товар`) ↔ BuhBud `РегистрБухгалтерии.Хозрасчетный`
  (счета 281/20x/26/22x, субконто Номенклатура+Склад по `А_ИдКод`); свод FULL OUTER JOIN.
- Фаза 2 (`АнализДокументов_Товары` + `АнализДокументовBuhBud_Товары`): документы ЕРП через
  `РегистрСведений.СоответствияОбъектовИнформационныхБаз` + обратный анализ BuhBud-only.
- Фаза 3 (`ВыполнитьСинхронизацию` → `РаспровестиВЕРП`/`ПровестиВЕРП`/`ПоставитьНаОбменВBuhBud`):
  общий код, не зависит от раздела.

### Эталон интерфейса `СинхронизироватьДеньгиКасса`
Богаче исходной формы и опирается на методы ObjectModule, **которых нет** в `СинхронизироватьТовары`:
- `АнализироватьДокументы(ИндексСтроки = -1)` (анализ всех или одной строки);
- `ВыполнитьСинхронизациюСтроки(ИндексСтроки)` + `ВыполнитьДействиеСтроки(...)`,
  `УчестьРезультатСтроки(...)` (действие по одной строке).

Форма Кассы: резюме-надпись со счётчиками, условное оформление (серый/красный/зелёный),
выбор периода диалогом `ДиалогРедактированияСтандартногоПериода`, две связанные таблицы
(нижняя следует за активной строкой верхней), per-row команды, открыть документ ЕРП.

## 3. Объём (согласовано)

- **Только `Товари`.** `Гроші` (безналичные) и `Взаєморозрахунки` (расчёты с партнёрами) —
  убираем полностью (это долги/деньги, не товар).
- Интерфейс — **полный порт стиля Кассы (Подход A)**.

## 4. Изменения

### 4.1 Дескриптор `СинхронизироватьТоварыТолькоТовары.xml`
- `Name` → `СинхронизироватьТоварыТолькоТовары`; синоним «Синхронізувати товари ERP↔BuhBud».
- **Свежий `uuid`** у `ExternalDataProcessor` + исправить `GeneratedType`-имена
  (в копии остались `...СинхронизироватьТовары`).
- Удалить реквизиты `РазделТовары`, `РазделДеньги`, `РазделВзаиморасчеты` (обработка односекционная).
- Оставить: `НачалоПериода`, `ОкончаниеПериода`, `Номенклатура`, `Склад`,
  `ПоказыватьТолькоРасхождения`.
- ТЧ `ТаблицаРасхождений` / `ТаблицаДокументов` — **без изменений структуры**
  (обобщённые колонки: `Измерение1`=Номенклатура, `Измерение2`=Склад; `Раздел` остаётся
  константой «Товари», чтобы не ломать общий `ОбробитиДокументиЕРП`).

### 4.2 ObjectModule
**Оставить (товарная ветка + общий код):**
`ПодключитьсяКBuhBud`, `СравнитьОстатки`, `СравнитьОстатки_Товары`, `ПолучитьОстаткиЕРП_Товары`,
`ПолучитьОстаткиBuhBud_Товары`, `СвестиТаблицы_Товары`, `АнализДокументов_Товары`,
`АнализДокументовBuhBud_Товары`, `ОбробитиДокументиЕРП`, `ПроверитьДокументВBuhBud`,
`РаспровестиВЕРП`, `ПровестиВЕРП`, `ПоставитьНаОбменВBuhBud`.

**Удалить:**
- Процедуры/функции `*_Деньги`: `СравнитьОстатки_Деньги`, `ПолучитьОстаткиЕРП_Деньги`,
  `ПолучитьОстаткиBuhBud_Деньги`, `СвестиТаблицы_Деньги`, `АнализДокументов_Деньги`,
  `ПеревіритиДокументиBuhBud_Деньги`.
- Процедуры/функции `*_Взаиморасчеты`: `СравнитьОстатки_Взаиморасчеты`,
  `ПолучитьОстаткиЕРП_Взаиморасчеты`, `ПолучитьОстаткиBuhBud_Взаиморасчеты`,
  `КонвертироватьТЗ_Взаиморасчеты`, `СвестиТаблицы_Взаиморасчеты`, `АнализДокументов_Взаиморасчеты`.
- Ветки `Если РазделДеньги` / `Если РазделВзаиморасчеты` в `СравнитьОстатки`;
  ветки `Гроші` / `Взаєморозрах` в `АнализироватьДокументы`.
- Гроші-спец-блок «пропуск переказів між рахунками» внутри `ОбробитиДокументиЕРП`.
- Отладочные `Сообщить("DEBUG…")`.

**Достроить (порт стиля Кассы):**
- `АнализироватьДокументы` → сигнатура `(ИндексСтроки = -1)`: при `-1` анализ всех отмеченных
  строк расхождений, иначе — одной строки по индексу. Возвращает строку-итог.
- `ВыполнитьСинхронизациюСтроки(ИндексСтроки) Экспорт` + вспомогательные
  `ВыполнитьДействиеСтроки(...)` / `УчестьРезультатСтроки(...)` — действие по одной строке
  `ТаблицаДокументов` (порт паттерна Кассы на товарную фазу 3).

### 4.3 Форма (Form.xml + Module.bsl) — «удобный» интерфейс
По образцу `СинхронизироватьДеньгиКасса`, привязка к товарной модели:
- **Шапка:** период `с / по` + кнопка «Вибрати період» (`ДиалогРедактированияСтандартногоПериода`);
  фильтры `Номенклатура`, `Склад`; флажок «Тільки розбіжності»; резюме-надпись `НадписьРезюме`
  со счётчиками. Семантика «грн» заменяется на количество («позицій / шт») — товары это количества.
- **Условное оформление** (`НастроитьУсловноеОформление`): серый (снятая галка `Синхронизировать`
  или статус начинается с «ОК»/«Збігається»), красный (статус с «ПОМИЛКА»), зелёный (успешные
  действия: «Розпроведено/Проведено в ЕРП», «Зареєстровано на обмін в BuhBud»).
- **Две связанные таблицы:** верхняя `ТаблицаРасхождений` (Номенклатура=`Измерение1`,
  Склад=`Измерение2`, Остаток ЕРП/Бух, Разница, галка); нижняя `ТаблицаДокументов` следует за
  активной строкой верхней (`ПриАктивизацииСтроки` → `ПрименитьФильтрДокументов` по
  `Измерение1`+`Измерение2`).
- **Команды:** Сформувати, Аналіз документів, Аналіз поточної позиції, Синхронізувати,
  Дія по рядку, Відкрити документ ЕРП, Вибрати всі / Зняти / Інвертувати /
  Відмітити виділені / Зняти виділені.
- Убрать три переключателя разделов и `УстановитьВидимостьФильтровТоваров`.
- Цвет надписи задаётся кодом (`ЦветаСтиля.ПоясняющийТекст`) — `TextColor` в XML формы внешней
  обработки валит XDTO-загрузку (известные грабли).

- Не меняем структуру ТЧ, не переименовываем обобщённые колонки.
- Не добавляем разделы кроме товарного.
- Не оставляем DEBUG-логи.
