## 🎯 Бизнес-мета (CFO)

После правки 2026-05-28 (commit `b64145fe5`) три регистра управ.баланса (А_ВзСС §3.9, ПАП §3.11, ДСДохРасх §3.11) показывают зарплатную выплату per 12 СтрПредпр из ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам. Но **типовой регистр учёта физического движения денег в кассе** — `РегНак.ДенежныеСредстваНаличные` — всё ещё пишет одну строку с шапочным Подразделением:

```
Расход | 08.12.2025 14:54:56 | 2 Касса Спецтехника | ТОВ "ІНДАСТРІАЛБУД"
       | Спецтехника                                      ← общее (Касса.Подразделение)
       | 348 800,00 / 348 800,00 / 348 800,00
       | Выплата по ведомости через кассу
       | Оплата за выполненные работы                     ← общая статья из шапки РКО
       | (АналитикаПартнеров пусто, ОбъектРасчетов пусто)
```

CFO открывает отчёт по балансу денег / сальдо кассы по подразделениям — видит только агрегат «Спецтехника 348 800», а не разложение на 12 единиц техники как в А_ВзСС / ПАП. **Расшифровать выплату по СтрПредпр через типовой регистр невозможно** — теряется согласованность с трёмя соседними регистрами.

## 📋 Цель

| Поле | ДО | ПОСЛЕ |
|---|---|---|
| Количество строк | 1 | **12** |
| Подразделение | «Спецтехника» (Касса.Подразделение) | **12 реальных СтрПредпр** из Рш.Подразделение.А_Подразделение |
| СтатьяДДС | «Оплата за выполненные работы» (из шапки РКО) | **детальная** из БДДС Казны (`Рш.СтатьяДвиженияДенежныхСредств` — например «Зарплата механизаторов») |

| Σ всех строк | 348 800,00 | **348 800,00** (инвариант) |

Σ инвариант: Σ per (Касса) per Документ остаётся = СуммаДокумента (баланс физической кассы не страдает).

## 🛡 Защита от blast radius

### Жёсткий гард Локализации-1 (3 условия одновременно)

1. `ДанныеДокумента.Ссылка = &Ссылка` — только текущий РКО.
2. `ТИПЗНАЧЕНИЯ(ДанныеДокумента.Ведомость) = ТИП(Документ.ВедомостьНаВыплатуЗарплатыВКассу)` — только наша ВКассу.
3. `ХозяйственнаяОперация В (3 зарплатные)` — только зарплатные ХозОп.

### Sanity тесты

- **3 РКО с ХозОп = ПрочаяВыдачаДенежныхСредств** — Локализация-1 НЕ срабатывает (Гард FAIL), Часть 1 типовая работает как раньше → 1 строка с шапочным Подр.
- **РКО с ХозОп = СдачаДенежныхСредствВБанк** — попадает в Часть 2 (без изменений) → 1 строка как раньше.
- **РКО с зарплатной ХозОп но Ведомость = ВыплатаЗарплатыВБанк** (другой тип Ведомости) — Гард FAIL (тип Ведомости не ВКассу), Часть 1 типовая работает как раньше.

### Regression на §3.11 (вчерашняя правка)

Эта правка касается ДРУГОГО регистра (ДенежныеСредстваНаличные, не ПАП/ДСДохРасх). Влияние на ПАП — нулевое (источник истины не меняется). Но всё равно повторно прогнать verify по §3.11 для РКО N0000052986 — все 6 acceptance должны остаться PASS.
