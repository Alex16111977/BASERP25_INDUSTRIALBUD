## 3. Корневая причина

- «Зарплата управл» Ф1 `ОрганизацияБухгалтерия` берётся из Казны
  (`РаспределениеКазна.ДокРаспределениеЗП.Организация`) — **корректно**.
- Но **НДФЛ/ВС теряют организацию**: `_ОтрЗП_ЗаполнитьСтрокуНДФЛ` ставит `Организация = шапка документа`
  и НЕ заполняет `ОрганизацияБухгалтерия`. Точный per-org из `НалогиБухгалтерия.Организация` игнорируется.
- gross-up «Удержание» Ф1 (= НДФЛ, добавленный обратно для расчёта take-home в движении) у multi-org ФЛ
  садится на ОДНО юр.лицо (ОргБух тянулся из старых «Удержание»-строк, не из НДФЛ per-org).
- В движении А_ВзСС «Оплата труда»: `(НачисленнаяЗарплата вкл. «Удержание») − НачисленныйНДФЛ`,
  агрегировано по `ОрганизацияБухгалтерия`. Т.к. «Удержание» и НДФЛ на РАЗНЫХ юр.лицах — по юр.лицу
  не гасятся → разлёт = НДФЛ+ВС.

## 4. Принцип решения (подтверждён бухгалтером — ЯВНО по организации)

НДФЛ/ВС закреплены за юр.лицом из `НалогиБухгалтерия.Организация`. Это юр.лицо проходит сквозняком:
`А_ОтражениеЗПпоКазне.НачисленныйНДФЛ.ОрганизацияБухгалтерия` → ОЗФУ.НачисленныйНДФЛ.ОрганизацияБухгалтерия
→ движение `РегистрНакопления.А_ВзаиморасчетыССотрудниками` → `А_ПередачаНачисленийМеждуПодразделениями.Налоги`.
«Зарплата управл» НЕ трогаем (уже верна).

**Контроль (Воронцов):** по каждому юр.лицу `ЗПупр + Удержание − НДФЛ = выплата → 0`:
ДЖИ ТРИ `15 746,50 + 4 703,50 − 4 703,50 = 15 746,50` → **0**;
ІНД `123 200 + 36 800 − 36 800 = 123 200` → **0**.

## 5. Архитектура цепочки (проверено по коду 2026-06-04)

Заполнение ОЗФУ-ТЧ в `А_ОтражениеЗПпоКазне` (оркестратор `ЗаполнитьДляОтражения_ДокументОтражениеЗарплатыВФинансовомУчете`):
Op1 ФОТ/ЕСВ → Op2 NET → Op3 НДФЛ → РазметитьФормаPL → **ВыровнятьУдержаниеСНДФЛ** → ПроставитьОргБухВсемФорма1.

Ключевые факты, подтверждённые чтением живого кода:

1. **Метаданные готовы:** `НачисленныйНДФЛ` ТЧ содержит `ОрганизацияБухгалтерия` (11-й реквизит);
   `НалогиБухгалтерия` ТЧ содержит `Организация` (per-org источник). В БД поле попадёт только после `/db-load-xml`.
2. **Заполнитель движения А_ВзСС НЕ требует правки.** `AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl`,
   процедура `ЗаполнитьИзОтраженияЗП` (вызывается при проведении ОЗФУ): блок НДФЛ читает `НДФЛ.ОрганизацияБухгалтерия`
   (вычитает со знаком −), финальная группировка — по `(Организация, Подразделение, ФизическоеЛицо, ФормаPL, ОрганизацияБухгалтерия)`.
   Движение уже per-org-aware; нужно лишь, чтобы ОЗФУ.НачисленныйНДФЛ.ОргБух нёс верное значение.
3. **`_ОтрЗП_ПроставитьОргБухВсемФорма1` не конфликтует:** пропускает строки с уже заполненным ОргБух
   и итерирует только `НачисленнаяЗарплатаИВзносыПоФизлицам` (НДФЛ-ТЧ не трогает).
4. **`_ПНМП_ЗаполнитьНачисления` уже org-correct:** зеркалит движения регистра А_ВзСС проведённого ОЗФУ
   по `(ФЛ, Подразделение, ОргБух)`. Правка нужна только для ТЧ **Налоги** (`_ПНМП_ЗаполнитьНалоги`).

## 6. Реализация — 4 точечные правки в `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`

Номера строк примерные — искать по имени процедуры. Каждую правку сперва прогнать логикой через Python COM
(заполнение в памяти, БЕЗ записи).

### Правка 1 — `_ОтрЗП_ЗаполнитьСтрокуНДФЛ` (~2248)
Добавить присвоение per-org ОргБух (источник — `НалогиБухгалтерия.Организация` строки-источника `СтрокаНалога`):
```bsl
НоваяСтрока.ОрганизацияБухгалтерия = ?(ЗначениеЗаполнено(СтрокаНалога.Организация), СтрокаНалога.Организация, Организация);
```

### Правка 2 — `_ОтрЗП_ВыровнятьУдержаниеСНДФЛ` (~2278)
Сейчас НДФЛ агрегируется по ключу `(ФЛ|Подр)`, а ОргБух для пересоздаваемых «Удержание»-строк берётся
из карты старых «Удержание» (`ОргБухК`) — неверно для multi-org. Изменить:
- ключ агрегации НДФЛ → `(ФЛ|Подр|ОргБух)`; в структуру-значение добавить `ОргБух`
  (брать `Стр.ОрганизацияБухгалтерия` — заполнено Правкой 1);
- при пересоздании «Удержание» ставить `НовСтр.ОрганизацияБухгалтерия = З.ОргБух` (из ключа НДФЛ),
  убрав зависимость от карты `ОргБухК`.

Σ per ФЛ сохраняется (НДФЛДляФЛ = Σ НачисленныйНДФЛ). Число строк «Удержание» может вырасти (сплит по орг) —
аккумулируются в свёртке ОЗФУ и группировке регистра.

### Правка 3 — `СоздатьДокументОтражениеЗарплатыВФинансовомУчете` (~3215)
Сейчас при копировании НДФЛ в ОЗФУ — **явный override**: `НоваяСтр.ОрганизацияБухгалтерия = _ОЗП_ОргБухИзКарты(...)`
(карта строится из «Зарплата управл» — доминантная орг по max Σ). Заменить на приоритет per-org из строки-источника:
```bsl
НоваяСтр.ОрганизацияБухгалтерия = ?(ЗначениеЗаполнено(СтрБ.ОрганизацияБухгалтерия), СтрБ.ОрганизацияБухгалтерия, _ОЗП_ОргБухИзКарты(КартаОргБух, СтрБ.ФизическоеЛицо, СтрБ.ПодразделениеПредприятия));
```
Карта остаётся защитным fallback. (НачисленнаяЗарплата копируется 1-в-1 с сохранением ОргБух и свёртывается
с ключом по ОргБух — отдельной правки не требует; gross-up «Удержание» приходит из Правки 2.)

### Правка 4 — `_ПНМП_ЗаполнитьНалоги` (~3960)
Сейчас НДФЛ- и ЕСВ-строки берут ОргБух из `ОргБухПоФЛ[ФЛ]` (первая непустая орг). Изменить:
- НДФЛ-строки: `ОрганизацияБухгалтерия = Стр.ОрганизацияБухгалтерия` (из `НачисленныйНДФЛ`, заполнено Правкой 1);
- ЕСВ-строки: `ОрганизацияБухгалтерия = Стр.ОрганизацияБухгалтерия` (из `НачисленнаяЗарплатаИВзносыПоФизлицам`,
  заполнено `_ОтрЗП_ПроставитьОргБухВсемФорма1`).

Убрать использование «первой ОргБух» для налоговых строк. Сигнатуру с `ОргБухПоФЛ` можно сохранить ради удержаний.

## 7. Вне scope (осознанные ограничения)

- `_ПНМП_ЗаполнитьУдержания` и копирование `УдержаннаяЗарплата` в ОЗФУ (~3270) остаются на карте «первой орг».
  Это РЕАЛЬНЫЕ удержания (алименты и т.п.) без per-org источника в `НалогиБухгалтерия`. Для 11 A-ФЛ
  разлёт = ровно НДФЛ+ВС, значит прочих удержаний у них нет → на результат не влияет. Зафиксировать как известное ограничение.

## 8. Инварианты (регрессия — НЕ сломать)

Все 4 правки меняют **только тег `ОрганизацияБухгалтерия`, суммы не трогают** → математически Σ-preserving.

- **Σ(Ф1+Ф2) per ФЛ** неизменна; ФЛ-итог по каждому A-ФЛ как был 0, так и остаётся 0.
- Общий баланс свода/ПАП не двигается (меняется только распределение НДФЛ между юр.лицами внутри Ф1).
- **Батрак** (single-flow, фикс Op2b 2026-06-03): Форма1 Строительство 15 400→0, Форма2 Производство 20 300→0 — без изменений.
- Эталоны (№000000005 и др.): Σ ОЗФУ/ПАП — без изменений.
- Не сломать фикс Op2b (ветка через `_ОтрЗП_СоздатьСтрокиNETФЛ_Новый`).
