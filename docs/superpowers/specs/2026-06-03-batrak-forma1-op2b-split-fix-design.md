# Дизайн-спецификация: фикс сплита Форма1/Форма2 для Op2b-ФЛ (А_ОтражениеЗПпоКазне)

> Дата: 2026-06-03. Статус: на ревью.

## 1. Симптом

Отчёт «Взаиморасчёты с сотрудниками для баланса» и «Сверка ЕРП(Форма1) vs Бухгалтерия 661/663»
(`_Rarzrabotki/Отчеты/А_СравнитьОстаткиВзаиморасчетыСотрудникиЕРПсBASБухгалтерия`), декабрь 2025,
ФЛ **Батрак Віктор Володимирович**:
- Форма1 «Зарплата управл» = **17 717,12**, должно быть **15 400,00** (Δ = +2 317,12).
- Сверка: Кон.остаток ЕРП = 2 317,12, Бухгалтерия = 0 → расхождение 2 317,12.

## 2. Корневая причина (доказана на данных, не гипотеза)

Цепочка: `А_ОтражениеЗПпоКазне → ОЗФУ → РН.А_ВзаиморасчетыССотрудниками → ПередачаНачислений`.
Чинить в **истоке сплита** (`Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`), НЕ в ПередачаНач.

Батрак **не имеет ни одной строки `НачисленияУпр`** (zup_2) → он не обрабатывается корректным
сплиттером Op2a (`_ОтрЗП_СоздатьСтрокиNETФЛ_Новый`), а проваливается в **fallback Op2b**
(`_ОтрЗП_ЗаполнитьНачисленияЗП`, ветка `СумНачПоСотруднику`). Op2b **агрегирует `СуммаНачисления`
по сотруднику, схлопывая Ф1+Ф2 в один бакет** (теряя `ФормаPL`). Затем `_ОтрЗП_РазметитьФормаPL`
пытается восстановить сплит коэффициентом `Ф1 = Сумма × GROSSбух / ТоталNET`.

**Фингерпринт (до копейки):** база по подразделениям 35 700; `Коеф = 20 000 / 40 300 = 0,496278`;
`35 700 × 0,496278 = 17 717,12`. Знаменатель **40 300 = 35 700 («Зарплата управл») + 4 600
(«Удержание» gross-up, ошибочно включённые в `ТоталNET`)**.

Коэффициент-механизм несовместим с пост-§21 контрактом регистра: после выравнивания
`_ОтрЗП_ВыровнятьУдержаниеСНДФЛ` движение даёт `Приход(Ф1) = «Зарплата управл»`, значит «Зарплата управл»
обязана быть take-home (15 400), а коэффициент даёт долю от GROSS.

## 3. Blast radius (системно)

Реконсиляция 191 ФЛ документа №000000001 (`Python/test/diag_batrak_blast_radius.py`):

| Путь | ФЛ | с дефектом |
|---|---|---|
| Op2a (есть НачисленияУпр) | 63 | **0** |
| Op2b (нет → fallback Казна) | 128 | **47** |

Σ перекоса Ф1↔Ф2 = **92 911,51**. Все дефекты — только Op2b.

**Верификация источника истины** (`Python/test/verify_op2b_kazna_split.py`, все 127 Op2b-ФЛ):
- `ФормаPL` на `РаспределениеКазна` == тип `ДокРаспределениеЗП` — **0 расхождений**
  (Ф1 ⟺ `А_РаспределениеЗаработнойПлаты`, Ф2 ⟺ `РаспределениеФ2`).
- `Казна_Ф1` == `GROSSбух − НДФЛ` — **0 расхождений**.

Вывод: `РаспределениеКазна.ФормаPL` — самосогласованный авторитетный сплит; формула GROSS−НДФЛ и
прямой Казна-сплит численно тождественны на всей базе.

## 4. Решение (унификация на одном сплиттере)

В `_ОтрЗП_ЗаполнитьНачисленияЗП` ветку Op2b (агрегат `СумНачПоСотруднику` + распределение по
БазовыеНачисления + отдельные НДФЛ-строки) **заменить вызовом того же `_ОтрЗП_СоздатьСтрокиNETФЛ_Новый`**,
что и Op2a, с `NET = Σ РаспределениеКазна.СуммаНачисления` (все формы) для данного ФЛ.

Функция уже:
- делит Ф1 «Зарплата управл» по весам Казны Ф1Нач (= Казна Ф1 по подразделениям) с ОргБух;
- делит Ф2 «Зарплата управл» по весам Казны Ф2 (премии + остаток);
- создаёт «Удержание» Ф1 = НДФЛ.

При `NET = Казна-итог`: `Ф1Сумма = clamp(GROSSбух − НДФЛ, 0, NET) = Казна_Ф1` (доказано), `Ф2 = Казна_Ф2`.
То есть результат **тождественен прямому Казна-сплиту** (правило пользователя «Ф2 = РаспределениеФ2,
Ф1 = А_РаспределениеЗаработнойПлаты»), и по итогам, и по подразделениям (включая ФЛ с премиями —
Ф2Сумма = Σпремий + ΣФ2Непрем без потерь на clamp).

**Следствие:** коэффициент-ветка `_ОтрЗП_РазметитьФормаPL` (строки 1240–1272) для «Зарплата управл»
становится недостижимой (все строки приходят размеченными). Остаётся как нейтральный защитный
fallback (ЕСВ `ВзносыВсего≠0` и «Удержание» по-прежнему форсятся Ф1). На этапе GREEN подтвердить
0 строк, попадающих в коэффициент-ветку.

Альтернатива (рассмотрена, не выбрана): прямой Казна-сплит без переиспользования функции —
надёжнее к будущему рассинхрону zup_1/Казна, но дублирует логику. Связь GROSS−НДФЛ==Казна_Ф1
семантически верна (обе = официальный take-home) и охраняется per-run GREEN-реконсиляцией.

## 5. Инварианты (обязаны держаться)

- `Σ(Ф1+Ф2) per ФЛ` неизменна (= Σ Казна) → баланс свода/ПАП не сдвигается, меняется только сплит Ф1↔Ф2.
- Налоги (НДФЛ/ВС/ЕСВ) остаются Форма1.
- `Ф1 «Зарплата управл» take-home = GROSSбух − НДФЛ = Казна_Ф1`, клампится в `[0, NET]`.
- Контракт §18/§21 не нарушается: «Зарплата управл» + «Удержание» − НачисленныйНДФЛ = take-home.
