# DESIGN: внешний отчёт `А_СравнитьОстаткиНалоговЕРПсBASБухгалтерия`

Дата: 2026-06-20. Источник требований: `docs/superpowers/prompts/2026-06-20-otchet-sverka-nalogov-erp-buhbud.md`.
Статус: одобрен пользователем 2026-06-20.

## 1. Цель

Внешний отчёт `.erf` — сверка остатков по **налогам**: управленческий баланс ЕРП (`BaseERP`) ↔ бухгалтерия `BuhBud`.
Разрез **Организация × ВидНалога**, период из настроек. По каждой паре — 4 показателя, на каждый показатель тройка
**ЕРП / BuhBud / Разница (=ЕРП−Бух)**. Назначение — диагностика расхождений (незаполненный перенос остатков,
дельта «управленческий vs бухгалтерский»).

## 2. Дерискинг (почему дизайн безопасен)

Два уже сделанных и проверенных «родителя» дают точные паттерны 1:1:

| Сиблинг | Что переиспользуем |
|---|---|
| Отчёт `А_СравнитьОстаткиВзаиморасчетыСотрудникиЕРПсBASБухгалтерия` (DONE, verify PASS 2026-06-03/04) | гибрид СКД-макет + сборка в `ObjectModule`, кросс-базный COM к BuhBud, merge по ЕДРПОУ, орг-фильтр `А_ВБалансе`, знак Кт−Дт |
| Обработка `Перенос остатков налогов из бухгалтерии` (DONE, smoke PASS 2026-06-20) | BuhBud-запрос `Хозрасчетный.ОстаткиИОбороты` по счетам 64x/65x, карта Счёт→ТипНалога, статья «Налоги» в ПАП, ЕДРПОУ-фильтр |

Плейсхолдер `_Rarzrabotki/Отчеты/А_СравнитьОстаткиНалоговЕРПсBASБухгалтерия` подтверждён как **побайтовая копия отчёта по ОС**
(в `.xml`: `Name=…ОсновныхСредств…`, UUID `bd57ccb8-f1d1-42a8-a177-a6513fb8ff4e`, `GeneratedType=…ОсновныхСредств…`).
Существует только в основной конфигурации (untracked), в worktree его нет. → переписать **целиком** + переименовать.

## 3. Архитектура — гибрид (клон `…Сотрудники…`)

СКД используется как **макет** (`Template`); данные собираются в `ObjectModule.ПриКомпоновкеРезультата` и подаются как
`ВнешниеНаборыДанных`. Своей формы нет: `DefaultForm=CommonForm.ФормаОтчета`,
`DefaultSettingsForm=CommonForm.ФормаНастроекОтчета`, `DefaultVariantForm=CommonForm.ФормаВариантаОтчета`,
единственный `ChildObjects/Template=ОсновнаяСхемаКомпоновкиДанных`.

`ПриКомпоновкеРезультата`: `СтандартнаяОбработка=Ложь` → BSL строит ТЗ →
`КомпоновщикМакетаКомпоновкиДанных.Выполнить(Схема, Настройки, ДанныеРасшифровки)` →
`ПроцессорКомпоновкиДанных.Инициализировать(Макет, ВнешниеНаборыДанных, …)` → вывод в `ТабличныйДокумент`.

**Альтернатива (чистый СКД с двумя наборами-запросами) отвергнута:** BuhBud читается кросс-базным COM
(`V83.COMConnector`), что нельзя оформить набором данных СКД. Все 8 отчётов-сиблингов сделаны гибридом.

## 4. Источники данных и знак (единая конвенция Кт−Дт, пассив = плюс)

### 4.1 ЕРП-сторона (управленческий баланс)
`РегистрНакопления.ПрочиеАктивыПассивы.ОстаткиИОбороты(&НачалоПериода, &КонецПериода, , , Статья.Наименование = "Налоги")`
- разрез: Организация(`КодПоЕДРПОУ`) × Аналитика(`Перечисление.ТипыНалогов`);
- ресурс Сумма: Приход=+, Расход=− (ПАП уже пассив-плюс, совпадает с Кт−Дт);
- показатели: `СуммаНачальныйОстаток`, `СуммаПриход` (Начислено), `СуммаРасход` (Уплачено), `СуммаКонечныйОстаток`;
- **НДФЛ-схлопывание:** все подвиды НДФЛ\* → один бакет `НДФЛ`
  `ВЫБОР КОГДА Аналитика В (&СписокНДФЛ) ТОГДА ЗНАЧЕНИЕ(Перечисление.ТипыНалогов.НДФЛ) ИНАЧЕ Аналитика КОНЕЦ`.
  Точный список подвидов фиксируется pre-тестом (ожидаются: НДФЛ, НДФЛДоходыКонтрагентов, НФДЛДивиденды,
  НФДЛДивидендыСотрудникам, НДФЛДоначисленныйПоРезультатамПроверки, НДФЛПередачаЗадолженностиВНалоговыйОрган,
  НДФЛПрочиеРасчетыСПерсоналом). Без схлопывания — фантомы против единственного счёта 6411 BuhBud.

### 4.2 BuhBud-сторона (бухгалтерия, через COM)
`РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(&НП, &КП, , , Счет В ИЕРАРХИИ(&Счета), , )`,
`&Счета = НайтиПоКоду("641")/("642")/("651")` (иерархия покрывает 6411/6412/6413/6414/6415/6417),
фильтр `Ост.Организация.КодПоЕДРПОУ В (&МассивЕДРПОУ)`.
- разрез: Организация(`КодПоЕДРПОУ`) × Счёт.Код;
- сальдо `СуммаКонечныйОстатокКт − СуммаКонечныйОстатокДт` (Кт−Дт, пассив-плюс),
  начальный аналогично `НачальныйОстатокКт − НачальныйОстатокДт`;
- обороты `СуммаОборотКт` (Начислено) / `СуммаОборотДт` (Уплачено);
- ТЗ из BuhBud — **только примитивы** (строки/числа) → `V83.ЗначениеВСтрокуВнутр(ТЗ)`; в ЕРП `ЗначениеИзСтрокиВнутр`.

### 4.3 Карта Счёт.Код → ВидНалога (BSL, после выгрузки)
`6411→НДФЛ, 6412→НДС, 6413→НалогНаПрибыль, 6414→ЕдиныйНалог, 642→ВоенныйСбор, 651→НачисленныйЕСВ,
6415/6417/прочее→ДругиеНалоги`. Агрегация по (ЕДРПОУ × ВидНалога). Строки `ДругиеНалоги` могут быть **только**
со стороны Бух (6417 земельного в ЕРП нет как счёта) — by-design.

### 4.4 Орг-фильтр
`А_ВБалансе` есть **только в ЕРП**. ERP-side:
`ВЫБРАТЬ Орг.КодПоЕДРПОУ ИЗ Справочник.Организации ГДЕ Орг.А_ВБалансе И Орг.КодПоЕДРПОУ<>""` → массив ЕДРПОУ
(ожидаются 3 орг: 40645273 ІНДАСТРІАЛБУД, 41597184 ДЖИ ТРИ КОНСТРАКШН, 44590697 ІНДЕПТ СТІЛ) → передаётся в обе стороны.

## 5. Слияние и колонки результата (merge в BSL)

- Ключ строки: `СокрЛП(ЕДРПОУ) + "|" + XMLСтрока(ВидНалога)`; **FULL-merge** (видны и «только ЕРП», и «только Бух»).
- ЕДРПОУ → `CatalogRef.Организации`: после COM-выгрузки — ВТ `&ТЗ` + LEFT JOIN `Справочник.Организации` по
  `КодПоЕДРПОУ` (UUID организаций между базами НЕ совпадают — связка только по ЕДРПОУ).
- Измерения результирующей ТЗ: **Организация** (`CatalogRef.Организации`), **ВидНалога** (`EnumRef.ТипыНалогов`).
- 4 показателя × {ЕРП / BuhBud / Разница} = **12 числовых колонок**:
  НачальныйОстаток / Начислено / Уплачено / КонечныйОстаток.
- `ВнешниеНаборыДанных = Новый Структура("Налоги_Сравнение", ТаблицаСравнение)`.

## 6. СКД (`Template.xml`)

- dataSet `xsi:type=DataSetObject`, `dataSourceType=Local`, name/objectName = `Налоги_Сравнение`.
- Поля: `Организация`(CatalogRef.Организации), `ВидНалога`(EnumRef.ТипыНалогов) + 12 числовых
  (`xs:decimal`, `Digits=15`, `FractionDigits=2`, `AllowedSign=Any`), на каждое числовое — `totalField` Сумма.
- Параметры: `Период`(StandardPeriod) + `НачалоПериода`(`&Период.ДатаНачала`) +
  `КонецПериода`(`КОНЕЦПЕРИОДА(&Период.ДатаОкончания,"ДЕНЬ")`).
- `settingsVariant`: группировка **Организация → ВидНалога**; папки колонок по 4 показателям, в каждой тройка
  ЕРП / BuhBud / Разница.
- Период читается из `КомпоновщикНастроек`
  (`КомпоновкаДанныхКлиентСервер.ПолучитьПараметр(КомпоновщикНастроек,"Период").Значение`), **не** из `ПараметрыДанных`.

## 7. Принятые микрорешения

1. **ВидНалога = `EnumRef.ТипыНалогов`** (не строка): это ровно тип `Аналитика` в ПАП, и обработка переноса
   пишет `Перечисления.ТипыНалогов`; `ДругиеНалоги` — реальное значение перечисления (подтвердить pre-тестом).
2. **Дефолт периода** даёт `КонецПериода = КонецДня(31.12.2025)` (на 30.11 ЕРП-сторона пуста, на 31.12 обе ненулевые).
3. **Без условного оформления** (заливка Разница≠0) — как в эталонах (промт помечает «не обязательно»).
4. Плейсхолдер переписывается **целиком**, новые `Name/Synonym/UUID/GeneratedType/ContainedObject.ObjectId/
   MainDataCompositionSchema` (иначе конфликт с отчётом ОС).

   согласованность знака (пассив-плюс). tz: глоб. `Дата/КонецДня` через прокси недоступны → `datetime.datetime(...)`.
2. **Метаданные `.xml`** — переписать плейсхолдер (новые Name/Synonym/UUID/GeneratedType).
3. **`Template.xml`** — набор `Налоги_Сравнение`, поля/параметры/группировки.
4. **`ObjectModule.bsl`** — `ПриКомпоновкеРезультата` + `ПолучитьОстаткиЕРП` + `ПолучитьОстаткиBuhBud` (COM) +

5. **Сборка `.erf`** через `/erf-build` против **реальной BaseERP** (стаб-2.17 падает).
6. **Smoke** (`test_sverka_nalogov_smoke.py`): сформировать на 31.12.2025, сверить с эталонными числами

   Разница=ЕРП−Бух, все 3 орг присутствуют.
7. Копия в основную конфигурацию (Rule #4). Пользователь открывает `.erf` в UI, выбирает период, «Сформировать».

## 9. Запреты / грабли

- Типовые объекты НЕ менять — только внешний отчёт.
- Плейсхолдер переписать целиком + переименовать Name (иначе конфликт с отчётом ОС).
- НДФЛ\* схлопывать в НДФЛ на ЕРП-стороне (иначе фантомы против 6411).
- Орг-фильтр: `А_ВБалансе` только в ЕРП → ЕДРПОУ ERP-side, `КодПоЕДРПОУ В (&Список)` в обе стороны.
- 6417 (земельный) в ЕРП нет → строки `ДругиеНалоги` только со стороны Бух (by-design).
- Знак: единая конвенция Кт−Дт (пассив-плюс); виртуальная `.Остатки` даёт Дт−Кт — инвертировать;
  в `.ОстаткиИОбороты` использовать `КонечныйОстатокКт − КонечныйОстатокДт`.
- BuhBud-COM: `cfo/2442` захардкожена; ТЗ только примитивы; ссылки конвертировать ПОСЛЕ;
  в тексте запроса через COM `.Текст` НЕ оставлять префикс `|`.
- Период читать из `КомпоновщикНастроек`, НЕ из `ПараметрыДанных`.
- Сборка только `/erf-build` против реальной BaseERP.
- Файлы 1С — UTF-8 **BOM + CRLF**; никаких inline `python -c` с кириллицей (только `.py`-файлы).
