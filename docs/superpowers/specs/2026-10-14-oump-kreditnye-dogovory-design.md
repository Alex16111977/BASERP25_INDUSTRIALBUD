## 1. Цель

Собственник и директор **Воронцов Олександр Володимирович** кредитует проекты (подразделения) за счёт
нераспределённой прибыли, которая накоплена у ЦО «Строительство» (и «Производство»). Нужно:

1. В ТЧ `Деньги` ОУМП явно выбирать **контрагента** и **вид кредитного договора** для каждой стороны.
   Сейчас контрагент выводится только из подразделения или из статьи ДДС (`А_ПартнерРасчетов`).
2. У каждого подразделения — **своя цепочка договоров** с Воронцовым: тело кредита и проценты
   отдельно. Возвраты идут по тем же договорам, кредиты разных подразделений не смешиваются.
3. Все прочие операции подразделений идут, как сейчас, на один договор `X внутр.(…)`.
4. Остатки тела и процентов попадают в отчёт `А_УправленческийБалансЕРП` в статью
   «Задолженность по кредитам». Механизм баланса и `А_ОбработкаДисбалансаПоПодразделениям`
   при этом не ломаются.

**Критерий успеха:** долг каждого подразделения перед Воронцовым виден отдельно по телу и по
процентам; ручная правка получателя и договора в платёжках больше не нужна; обработка
дисбаланса не создаёт новых взаимозачётов по кредитным операциям.

## 2. Учётная схема (решение пользователя: «пока А, потом Б»)

- **Сейчас (А) — управленческая.** Воронцов — управленческий разрез на существующих договорах.
  Юридических дивидендов и займа нет, налоги не удерживаются. Нераспределённая прибыль ЦО
  уменьшается только в управленческом балансе через договор «Нераспределенная прибыль -- <ЦО>».
- **Позже (Б) — юридическая.** Решение участника о дивидендах → новация чистой суммы в заём
  (ст. 604/1053 ЦКУ) → транши по проектам (допсоглашения). Ложится на **те же** договоры:
  добавляются документы дивидендов, новации и удержаний. Структура договоров не меняется.
  В этот подпроект не входит.

Обе ноги кредита идут через Воронцова (решение пользователя):

| Нога | Документ | Подразделение | Контрагент | Договор |
|---|---|---|---|---|
| ЦО отдаёт прибыль собственнику | Списание безнал / РКО, `ОплатаПоставщику` | ЦО (Строительство) | Воронцов | `Нераспределенная прибыль -- Строительство` |
| Проект получает кредит | Поступление безнал / ПКО, `ПоступлениеОплатыОтКлиента` | проект X | Воронцов | `Кредитование от кредитора -- X` |
| Возврат тела | Списание X `ВозвратОплатыКлиенту` + Поступление ЦО | X / ЦО | Воронцов | те же два договора |

По Воронцову в целом по компании остаток равен нулю; у подразделений появляются свои позиции перед собственником.

## 3. Модель данных

### 3.1 Новое перечисление `А_ВидыКредитныхДоговоров`
Значения: `ТелоКредита`, `Проценты`, `НераспределеннаяПрибыль`.

### 3.2 Новые реквизиты
| Объект | Реквизит | Тип |
|---|---|---|
| `Справочник.ДоговорыКонтрагентов` | `А_ВидКредитногоДоговора` | `ПеречислениеСсылка.А_ВидыКредитныхДоговоров` |
| `Справочник.СтатьиДвиженияДенежныхСредств` | `А_ВидКредитногоДоговора` | то же; выводится на форму рядом с `А_ПартнерРасчетов` |
| ТЧ `Деньги` ОУМП | `КонтрагентРасход`, `КонтрагентПриход` | `СправочникСсылка.Контрагенты` |
| ТЧ `Деньги` ОУМП | `ВидДоговораРасход`, `ВидДоговораПриход` | `ПеречислениеСсылка.А_ВидыКредитныхДоговоров` |

Колонки выводятся на форму ОУМП в ТЧ `Деньги`.

### 3.3 Цепочка договоров на подразделение (контрагент — Воронцов О.В.)

| Вид | Наименование (существующая серия) | `ТипДоговора` | `А_СтатьяБаланса` | `А_ВидКонтрагента` |
|---|---|---|---|---|
| `ТелоКредита` | `Кредитование от кредитора -- <подр>` | `СПокупателем` | Задолженность по кредитам | Собственники |
| `Проценты` | `%% за использование от кредитора -- <подр>` | `СПоставщиком` | Задолженность по кредитам | Собственники |
| `НераспределеннаяПрибыль` | `Нераспределенная прибыль -- <подр>` | `СПоставщиком` | пусто (как сейчас) | Собственники |

Общие для всех трёх: `Подразделение = <подр>`, `А_ПодразделениеОказаниеУслугПодразделению` **пусто**,
`ПорядокРасчетов = ПоДоговорамКонтрагентов`, валюта — грн, ГФУ по типу договора.

Почему так:
- `ДоговорыКредитовИДепозитов` не используем: ветки остатков `А_УправленческийБалансЕРП` не
  читают `РасчетыПоФинансовымИнструментам`, и остатки кредитов пропали бы из отчёта.
- Подписка `А_СобытияОбъектов` (~стр. 281) переименовывает договор только при заполненных
  `Партнер.А_Подразделение` и `А_ПодразделениеОказаниеУслугПодразделению`. У Воронцова
  `А_Подразделение` пустое, поэтому имена кредитных договоров не затираются, а
  `А_ВидКонтрагента = Собственники` сохраняется.
- `А_ОбработкаДисбалансаПоПодразделениям` ищет только внутренних партнёров
  (`Партнеры.А_Подразделение`) и договоры `X внутр.`. Кредитные договоры она не трогает.

## 4. Логика

### 4.1 Заполнение колонок (`НачислитьУслугиНаСервере`, перенос из Казны)
Для каждой строки `Деньги`, где колонка пустая:
- `КонтрагентРасход` берётся из `СтатьяДвиженияДенежныхСредствРасход.А_ПартнерРасчетов`
  (контрагент партнёра выбирается по правилу 4.3), а `ВидДоговораРасход` — из
  `СтатьяДвиженияДенежныхСредствРасход.А_ВидКредитногоДоговора`.
- Для прихода — так же.
- Уже заполненное значение не перезаписывается: ручная правка пользователя сохраняется.

### 4.2 Создание оплат (`СоздатьОплатыНаСервере`)
Для каждой стороны строки:
1. **Контрагент.** Если колонка заполнена — берём её. Иначе работает текущая логика:
   `А_ПартнерРасчетовПоСтатье` → партнёр подразделения → контрагент.
2. **Договор.**
   - Если вид заполнен, ищем договор по ключу
     `Контрагент + Организация + Подразделение = <подразделение стороны> + А_ВидКредитногоДоговора = <вид> + НЕ ПометкаУдаления`.
     Если договора нет — создаём его по таблице 3.3 и сообщаем об этом.
   - Если вид пуст — работает текущий подбор: `X внутр.` по второй стороне или по статье. Регрессии нет.
3. **Хозяйственная операция.** Остаётся текущей. Ветка `ЭтоВозврат` для договора тела
   (`СПокупателем`) даёт `ВозвратОплатыКлиенту` в списании.
4. Договор передаётся в `РасшифровкаПлатежа.А_Договор` (безнал) или в шапку (касса), объекты
   расчётов заполняются процедурой `А_ЗаполнитьОбъектыРасчетовВРасшифровке`.

Код поиска и создания кредитного договора выносится в отдельную экспортную функцию
`А_НайтиИлиСоздатьКредитныйДоговор(Контрагент, Организация, Подразделение, ВидДоговора)`.
Подписку на договоры она не обходит.

### 4.3 Выбор контрагента по партнёру
У партнёра «Воронцов О.В. ФОП » несколько контрагентов, и есть тёзки. Поэтому из контрагентов партнёра выбираем
тот, у кого уже есть договоры с `А_ВидКредитногоДоговора`. Если таких нет — первый не помеченный
на удаление; ошибки нет.

### 4.4 Ошибки
| Ситуация | Поведение |
|---|---|
| Вид задан, контрагент не определён | строка пропускается, сообщение «Не задан контрагент для кредитного договора: <подр>, строка N» |
| Договор не найден | создаётся, сообщение «Создан кредитный договор: <имя>» |
| Найдено несколько договоров одного вида на подразделение | берём старший по дате, сообщение о дубле |

## 5. Перенос старых данных (разовая обработка, Python COM)
1. Разметить существующие договоры Воронцова по сериям из 3.3: проставить `А_ВидКредитногоДоговора`,
   `А_СтатьяБаланса`, `А_ВидКонтрагента`. Капсового «ВОРОНЦОВ…» и старые ПФД не трогать.
2. Разметить статьи ДДС:
   - «Финансовая помощь» → Воронцов + `НераспределеннаяПрибыль`;
   - «Получение финансовой помощи» → Воронцов + `ТелоКредита`;
   - «Возврат Финансовой помощи» → Воронцов + `ТелоКредита`.
3. По документам 575, 581, 582, 583 выполнить «Создать оплаты» в UI. Старые платёжки помечаются
   на удаление в фазе 1. Историю перепроводит пользователь.
4. Ошибочные остатки ручных правок в `Хозрасчетный` 3711 по договорам «МД IRC 2026 внутр.(Закупка)»
   (2 275 732) и «КРИВОЙ РОГ ЦЕМЕНТ-2 · Финансовая помощь» (476 608) должны уйти после шага 3:
   проверить, что остаток 0.

## 6. Сверка с балансом (схема А)
- В управленческом балансе: сумма остатков по договорам Воронцова вида `ТелоКредита` по всем
  подразделениям = сумма уменьшения по договорам вида `НераспределеннаяПрибыль`. Договоры вида
  `Проценты` сверяются отдельно в подпроекте 2: начисление минус выплата.
- Сверочная статья «Прибыль, размещённая во внутренние займы» нужна для перехода к статучёту
  (441): в этом подпроекте фиксируется контрольный запрос, без изменения отчёта.
- **Обязательная проверка:** платёжки ОУМП по кредитным договорам не уходят в BAS Бухгалтерію
  (BuhBud) как реальные расчёты с физлицом. Проверить флаги и правила обмена; если уходят —
  отдельный вопрос пользователю до загрузки.

## 7. Проверка (Rule #-1: каждый запрос — Python COM до BSL)
1. Запрос подбора кредитного договора выполняется на живой базе.
2. Идемпотентность: повторный «Создать оплаты» не увеличивает число договоров.
3. 581 (1 426 060,23):
   - Списание: Строительство → Воронцов, договор «Нераспределенная прибыль -- Строительство».
   - Поступление: МД IRC 2026 ← Воронцов, договор «Кредитование от кредитора -- МД IRC 2026».
   - ПАП в обоих документах сходится внутри подразделения.
   - В отчёте баланса у МД IRC 2026 появляется «Задолженность по кредитам» 1 426 060,23.
4. Регрессия:
   - 575 и 577 без колонок дают прежние договоры `X внутр.` (эталоны базы знаний);
   - для 000000575 движения пары — `ДенежныеСредстваБезналичные` 1, `РасчетыСПоставщиками` 4, `РасчетыСКлиентами` 4.
5. `А_ОбработкаДисбалансаПоПодразделениям`, режим «Анализ», за июль 2026: по документам Воронцова
   новых пар нет.
6. Гейт `bas-verify`: `meta-validate`, `form-validate`, `1c-bsl-review`, копирование в основную
   конфигурацию (Rule #4), загрузка Partial + `db-update`.
