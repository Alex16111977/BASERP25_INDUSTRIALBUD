# Архив «Общие названия номенклатуры» (BuhBud)

**Дата:** 2026-07-26
**База:** `bas_industrialbud` (BAS Бухгалтерія), `Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`
**Дамп конфигурации:** `_Rarzrabotki/BASEBuh/`

## 1. Цель

Снять снимок текущего контура общих названий номенклатуры перед его переработкой:

1. Перенести все элементы `Справочник.ОбщиеНазванияНоменклатуры` в справочник-архив `Справочник.ОбщиеНазванияНоменклатурыСтарая`.
2. Заполнить `Справочник.Номенклатура.ОбщееНазваниеНоменклатурыСтарая` архивным аналогом текущего значения `ОбщееНазваниеНоменклатуры`.

Оригинальный справочник и живой реквизит остаются нетронутыми — архив это копия, а не перенос.

## 2. Установленные факты

### Обмен и подписки

- Планы обмена, содержащие `Справочник.Номенклатура` в составе: 13, во всех авторегистрация = `Запретить`. `ОбщиеНазванияНоменклатуры` входит только в `ОбменУправлениеПредприятиемБухгалтерия20` (авторегистрация `Запретить`). `ОбщиеНазванияНоменклатурыСтарая` не входит ни в один план обмена.
- Реальные узлы есть только у `ПланОбмена.ОбменУправлениеПредприятиемБухгалтерия20` — 1 узел (ЕРП). У `Полный`, `ПоОрганизации`, `АвтономнаяРабота` узлов нет.
- Регистрация к выгрузке выполняется подпиской `ОбменДаннымиОбменЕРПБухгалтерия20ЗарегистрироватьИзменение` (ПередЗаписью) → `ОбменДаннымиСобытия.МеханизмРегистрацииОбъектовПередЗаписью("ОбменУправлениеПредприятиемБухгалтерия20", ...)` (`CommonModules/ОбменДаннымиСобытияЕРПБП/Ext/Module.bsl:10`). Значит запись 2 688 номенклатур «в лоб» может зарегистрировать их к выгрузке в ЕРП.
- Кастомная подписка `А_ДоработкаСправочникиПриЗаписи` (ПриЗаписи, 7 типов источника) → `УстановитьКодUUIDВСправочнике` (`.../Module.bsl:59`): если у справочника есть `А_ИдКод` и он не равен UUID — реквизит проставляется и объект перезаписывается рекурсивно с `ОбменДанными.Загрузка = Истина`. Для `Номенклатура` подписка применима, для обоих справочников общих названий — ранний выход (нет `А_ИдКод`).

## 3. Решение

Клон с сохранением UUID: каждый архивный элемент получает **ту же** ссылку-UUID, что и оригинал (`Справочники.ОбщиеНазванияНоменклатурыСтарая.ПолучитьСсылку(УИД)` + `Объект.УстановитьСсылкуНового(...)`).

Почему так:

- заполнение `Номенклатура.ОбщееНазваниеНоменклатурыСтарая` становится прямым пересчётом ссылки по UUID живого значения — таблица соответствий не нужна;
- операция идемпотентна: повторный прогон не плодит дубли, а находит уже перенесённый элемент по тому же UUID;
- архив — точное зеркало, сверка выполняется сравнением по ключу-UUID;
- UUID уникальны в пределах таблицы своего типа, коллизий между разными справочниками не бывает.

Поставка — Python COM скрипты (как остальные переносы данных в проекте), без изменений конфигурации:

| Файл | Назначение |
|---|---|
| `_Rarzrabotki/Python/test/test_onn_arhiv_dry_run.py` | шаг 0 — проверка механики в откатываемой транзакции |
| `_Rarzrabotki/Python/perenos_onn_v_arhiv.py` | шаги 1–2 — перенос и заполнение |
| `_Rarzrabotki/Python/proverka_onn_arhiv.py` | шаг 3 — независимая верификация |

## 4. Алгоритм

### Шаг 0 — прогон вхолостую (откатываемая транзакция)

Внутри `НачатьТранзакцию()` / `ОтменитьТранзакцию()`, на одном элементе и одной номенклатуре, проверить:

1. `УстановитьСсылкуНового` вызывается через COM и объект пишется с заданным UUID;
2. явная установка `Код` не приводит к срабатыванию префиксации (подписка `УстановитьПрефиксИнформационнойБазыКодуСправочника` висит на `ПриУстановкеНовогоКода` и при ручном присвоении кода не вызывается) — код в архиве совпадает с оригиналом;
3. запись `Номенклатура` с `ОбменДанными.Загрузка = Истина` **не** создаёт регистрацию на узле `ОбменУправлениеПредприятиемБухгалтерия20`.

Если пункт 3 не подтверждается — до основного прогона снимается baseline зарегистрированных ссылок номенклатуры на узле ЕРП, а после прогона регистрация снимается через `ПланыОбмена.УдалитьРегистрациюИзменений(узел, ссылка)` **только** для тех ссылок, которых в baseline не было.

Дополнительно замерить, у скольких из 2 688 номенклатур `А_ИдКод` не равен UUID — это те, где подписка `А_ДоработкаСправочникиПриЗаписи` вызовет вложенную перезапись. Число фиксируется в отчёте прогона.

### Шаг 1 — перенос 322 элементов

Источник — запрос к `Справочник.ОбщиеНазванияНоменклатуры`, упорядоченный так, чтобы родитель обрабатывался раньше потомка (сейчас групп 0, но код universal: обход по уровням иерархии).

Для каждого элемента:

- ссылка архива = `ПолучитьСсылку(УИД оригинала)`; если объект по ней уже существует — пропуск (идемпотентность);
- `ЭтоГруппа` — создаётся `СоздатьГруппу()` либо `СоздатьЭлемент()` соответственно;
- копируются: `Код`, `Наименование`, `ПометкаУдаления`, `Родитель` (ссылка архива по UUID родителя), `ОсновнаяНоменклатура`, `Единица`, `ЕдиницаРекомендуемая`, `НазваниеДляОбъединения`, `НеПроверятьВЗакупкахпоСС`;
- запись с `ОбменДанными.Загрузка = Истина` (обходит `ПроверитьЗаполнение` и БСП-обработчики; регистрации всё равно нет — справочник вне планов обмена);
- батчи по 200 объектов в транзакции, при исключении — откат батча, лог, продолжение со следующего батча; итоговый список ошибок в отчёте.

### Шаг 2 — заполнение `Номенклатура.ОбщееНазваниеНоменклатурыСтарая`

Выборка: `ОбщееНазваниеНоменклатуры` заполнено И архивное значение ещё не соответствует живому (сравнение по UUID на стороне Python — типы разные, в запросе не сопоставить). Оба реквизита объявлены как `ForItem`, поэтому в выборку попадают только элементы, группы номенклатуры не затрагиваются.

Для каждой номенклатуры:

- `ОбщееНазваниеНоменклатурыСтарая = Справочники.ОбщиеНазванияНоменклатурыСтарая.ПолучитьСсылку(УИД от живого значения)`;
- запись с `ОбменДанными.Загрузка = Истина`;
- батчи по 200 в транзакции, обработка ошибок как в шаге 1.

Порядок шагов обязателен: шаг 2 выполняется только после успешного шага 1, иначе архивные ссылки будут указывать на несуществующие объекты.

## 5. Побочные эффекты и как они гасятся

| Эффект | Гашение |
|---|---|
| Регистрация 2 688 номенклатур к выгрузке в ЕРП | запись с `ОбменДанными.Загрузка = Истина`; факт подавления подтверждается в шаге 0, иначе — снятие регистрации по разнице с baseline |
| Вложенная перезапись подпиской `А_ДоработкаСправочникиПриЗаписи` | безвредна и идемпотентна (пишет `А_ИдКод` = UUID один раз); объём замеряется в шаге 0 |

| Повторный запуск скрипта | идемпотентен на обоих шагах: пропуск уже перенесённых UUID и уже корректно заполненных реквизитов |

## 6. Верификация (критерии приёмки)

Отдельный скрипт `proverka_onn_arhiv.py`, читающий базу заново после прогона. Все проверки должны дать ноль расхождений:

1. `КОЛИЧЕСТВО(ОбщиеНазванияНоменклатурыСтарая) = 322`, при этом множество UUID архива совпадает с множеством UUID оригинала.
2. Для каждого UUID совпадают: `Код`, `Наименование`, `ПометкаУдаления`, `ЭтоГруппа`, `Родитель` (по UUID), `ОсновнаяНоменклатура`, `Единица`, `ЕдиницаРекомендуемая`, `НазваниеДляОбъединения`, `НеПроверятьВЗакупкахпоСС`.
3. Ноль номенклатур, где `ОбщееНазваниеНоменклатуры` заполнено, а `ОбщееНазваниеНоменклатурыСтарая` пусто (ожидаемое количество заполненных — 2 688).
4. Ноль номенклатур, где оба поля заполнены, но UUID не совпадают.
5. Ноль номенклатур, где `ОбщееНазваниеНоменклатурыСтарая` заполнено, а `ОбщееНазваниеНоменклатуры` пусто.
6. `КОЛИЧЕСТВО(ОбщиеНазванияНоменклатуры) = 322` — оригинал не изменился.

## 7. Вне скоупа

- **Формы архивного справочника не чиним** (решение пользователя от 2026-07-26). `Catalogs/ОбщиеНазванияНоменклатурыСтарая/Forms/ФормаЭлемента` — байт-копия рабочей формы: динамический список фильтрует по `Номенклатура.ОбщееНазваниеНоменклатуры = &Ссылка` (`Ext/Form.xml:197`), где параметр имеет архивный тип — список всегда пуст; кнопки «Подбор номенклатуры», «Удалить привязку», «Сделать основной» и drag-drop пишут в **живой** реквизит `ОбщееНазваниеНоменклатуры` (`Ext/Form/Module.bsl:67`, `:166`) и блокируют `Справочник.ОбщиеНазванияНоменклатуры` (`:246`). Риск: открыв карточку архива, пользователь может перезаписать боевую привязку. Отдельная задача.
- Архивные поля для `СтруктураСебестоимости.ТЧ.Комплектующие` и трёх ТЧ `РасчетКомплектаций` не создаются.
- Перенос контура в ЕРП (`А_ОбщиеНазванияНоменклатуры`) не затрагивается.
