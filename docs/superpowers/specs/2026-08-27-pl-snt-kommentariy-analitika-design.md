# Отчёт А_ОтчетPL_ПолныйЕРП: Комментарий в «Аналитике» для трёх служебных документов

Дата: 2026-08-27. Утверждено пользователем в два шага: сначала СписаниеНедостачТоваров,
затем (после ревизии всех регистраторов) добавлены ВнутреннееПотреблениеТоваров и
ПрочиеДоходыРасходы. Загрузка в конфигурацию — утверждена.

## Проблема

У строк `ПрочиеРасходы` от трёх типов документов аналитика пуста — веток в CASE поля
«Аналитика» нет вовсе (ИНАЧЕ NULL). Замер (регистр, январь–июль 2026):

| Тип | Доков | Сумма | С комментарием |
|---|---:|---:|---:|
| `СписаниеНедостачТоваров` | 1134 | 93,4 млн | ~450 (июль: 83 из 174) |
| `ВнутреннееПотреблениеТоваров` (представление зависит от операции: «Внутреннее потребление товаров» ИЛИ «Передача в эксплуатацию») | 629 (вся история) | 11,5 млн | 228 |
| `ПрочиеДоходыРасходы` (представление «Регистрация расходов») | 17 | 46,8 млн | 7 («Начисление комиссии ФА по документам Отчет PL», 11,9 млн) |

Ревизия остальных типов: ПТУ/СписаниеБезнал/Возвраты/ПКО — контрагент (уже информативно);
АвансовыйОтчет — подотчётник; ОтражениеЗарплаты — физлицо; РКО — контрагент/комментарий (v9);
РасчетКурсовыхРазниц и АмортизацияОС — комментариев 0, кидать нечего, остаются пустыми.

## Решение (паттерн v9, запрос `v10_full.sql`)

В CASE поля «Аналитика» `втЕРП_Расх_Детали` (ВЫБРАТЬ + копия в СГРУППИРОВАТЬ ПО, после
ветки РКО) добавляются три ветки — для каждого типа:

    КОГДА Р.Регистратор ССЫЛКА Документ.<Тип>
        ТОГДА ВЫРАЗИТЬ(ВЫРАЗИТЬ(… КАК Документ.<Тип>).Комментарий КАК Строка(200))

Условий по операции нет; пустой комментарий даёт пусто — поведение как сейчас.
CASE поля «Контрагент» не трогается, суммы не меняются.

## Попутная находка (вне scope)

~30 строк регистра (~0,8 млн, 2026) висят на битых регистраторах «<Объект не найден>» —
документы удалены, движения остались. Заведена отдельная задача (chip).

## Проверки

- RED (`test_otchetpl_v10_kommentarii_2026-08-27.py`): v10 == v9 построчно по ключу без
  аналитики; строковая аналитика только у РКО + трёх новых типов; по каждому типу все
  июльские пары (документ, комментарий) на месте, лишних нет.
- Регрессия: `acceptance_russkie_nazvaniya` (28) + `acceptance_rko_analitika` (3) +
  сверка док-код (перенацелить на v10).
- `.erf` через BaseERPRazr, зеркала; частичная загрузка МОДУЛЯ в BaseERP + UpdateDBCfg,
  контрольная выгрузка, смоук отчёта из конфигурации.
