# Дизайн: подотчётне удержание — правильный ВидОперации (типовое проведение в регистр) + Подразделение

> Дата: 2026-06-04. Продолжение `2026-06-04-podzvitne-*`. Период: декабрь 2025.
> Рабочая папка: `C:\Configuration_downloads\BASERP25` (ветка `claude/bas-doc-skills`). Навыки: Rule #-1, db-load-xml/db-update, verification. Перепроведение — только UI.

## 1. Постановка (открытие пользователя)

Типовой ОЗФУ **уже** умеет проводить удержание подотчётных в регистр `РегистрНакопления.ДенежныеСредстваУПодотчетныхЛиц` —
триггер: `УдержаннаяЗарплата.ВидОперации = УдержаниеНеизрасходованныхПодотчетныхСумм` (ManagerModule
`ТекстЗапросаТаблицаДенежныеСредстваУПодотчетныхЛиц` стр.4330-4352). Раньше код ставил `Алименты` → движение не формировалось.

3 задачи:
1. Заполнять подотчётную строку ОЗФУ с `ВидОперации = УдержаниеНеизрасходованныхПодотчетныхСумм` (счёт 3721, Субконто1=ФЛ).
2. НЕ передавать подотчётне в `А_ПередачаНачисленийМеждуПодразделениями` (ОЗФУ уже погасил на исходном подр.).
3. Исправить **баг типового запроса**: он не выбирает Подразделение → движение регистра с пустым подразделением (−400 «висит» на «без подразделения», +400 на КМД-2). Пользователь явно разрешил править типовой запрос.

## 2. Grounded факты (COM + код)

- `Перечисления.ВидыОперацийПоЗарплате.УдержаниеНеизрасходованныхПодотчетныхСумм` существует.
- ManagerModule ОЗФУ стр.563-564: ВидОперации=УдержаниеНеизрасходованных → счёт `РасчетыСПодотчетнымиЛицами` (3721).
- ManagerModule стр.3650/4089: эта ВидОперации ИСКЛЮЧЕНА из обычных удержаний-запросов (обрабатывается отдельным подотчётным запросом).
- Подотчётный запрос (4330-4352): пишет Расход, ПодотчетноеЛицо=`УдержаннаяЗарплата.ФизическоеЛицо`, ЦельВыдачи=`УдержаннаяЗарплата.ЦельВыдачи`, Сумма/Регл/Упр/КОтчету=Сумма, ХозОп=УдержаниеНеизрасходованных. **Подразделение НЕ выбирается** → пусто (баг).
- Регистр `ДенежныеСредстваУПодотчетныхЛиц`: измерения ПодотчетноеЛицо(ФизическиеЛица), Организация, Подразделение, ЦельВыдачи, Валюта.
- Открытый остаток Гуняги: КМД-2, UAH, Цель=пусто, Сумма=СуммаУпр=СуммаРегл=КОтчету=400. Закрывается Расходом 400 на КМД-2.
- ПАП «Денежные средства (у подотчетных лиц)» формируется через «Движения баланса» от регистра (эталон Авансовый отчёт ІБ00-000341), НЕ из СтатьиАктивовПассивов строки.

## 3. Правка 1 — ВидОперации (А_ОтражениеЗПпоКазне `ЗаписатьУдержанияВТЧ_Бух`)

Подотчётная ветка (`ЭтоПодотчетне = (КодВида="00009")`):
- `ВидОперации = Перечисления.ВидыОперацийПоЗарплате.УдержаниеНеизрасходованныхПодотчетныхСумм` (вместо общего ВидОперацииАлименты);
- `СчетУчета = 3721`, `Субконто1 = СотрудникERP.ФизическоеЛицо` (без изменений);
- **`СтатьяАктивовПассивов` НЕ ставить** (убрать `СтатьяПодотчетные`). Иначе ПАП «Денежные средства» задвоится (статья + Движения баланса).
- Алиментная ветка — `ВидОперации = ВидОперацииАлименты`, 6853, Прочие пассивы, Субконто1=Контрагент (без изменений).

Реализация: вынести `ВидОперации` из общей части в ветки; убрать кэш `СтатьяПодотчетные`.

## 4. Правка 2 — не передавать подотчётне (А_ОтражениеЗПпоКазне `_ПНМП_ЗаполнитьУдержания`)

Пропускать строки `Стр.ВидОперации = Перечисления.ВидыОперацийПоЗарплате.УдержаниеНеизрасходованныхПодотчетныхСумм`
(ОЗФУ закрыл подотчётне на исходном подразделении). Алименты переносятся как раньше.

## 5. Правка 3 — типовой запрос: добавить Подразделение (ОЗФУ ManagerModule)

В `ТекстЗапросаТаблицаДенежныеСредстваУПодотчетныхЛиц` добавить колонку
`УдержаннаяЗарплата.ПодразделениеПредприятия КАК Подразделение,`. Тогда Расход ляжет на КМД-2 (= подразделение строки)
и закроет открытый остаток. Пометить А_-комментарием (типовой объект; при обновлении конфигурации вендором может затереться).

## 6. Что НЕ трогаю

ПередачаНач B.2 (per-row статья, из `2026-06-04-podzvitne-subconto-peredacha`) — оставляю: подотчётне исключён в Правке 2,
для алиментов даёт «Прочие пассивы» (общая безопасная логика).
