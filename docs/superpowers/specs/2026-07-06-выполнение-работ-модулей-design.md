# Дизайн: Документ «А_ВыполнениеРаботМодулей» + EV-часы в отчёте план-факт

Дата: 2026-07-06. Утверждено пользователем.

## Задача

Фиксировать на дату **проценты выполнения** по каждому виду работ в разрезе **модулей**
(как Excel «ЗВіт_виконання_ВООЗ_ЕМС_Зачепилівка»: листы 19.06/26.06/03.07 — накопительные
снимки; строки = работы, «Факт виконання по проекту» = текст «6 модулів --100%; 2 модулі --30%»).
Документ пересчитывает план-часы работы через % в **EV-часы** («заработанные» часы =
План/КолМодулей × Σ%модулей), проводит их в регистр; отчёт `А_ПланФактныйПроизводствоПолный`
сравнивает EV-часы с фактом по табелю.

Тест-объект: СС «МД Вооз ЕМS Мала 2026 / Цех_МД Вооз ЕМS Мала 2026» (`А_КоличествоМодулей=8`,
44 работы, Σплан 2542 ч; Excel: 2540 ч, EV на 03.07 ≈ 2330 ч, табель 155 ч).

## Исследования (проведены, workflows)

**Rarus УСО2** (5 агентов + синтез):
- % нигде не хранится в регистрах — в регистр идёт натуральная величина (у нас часы), % первичен в документе.
- Модель «снимок в документе + дельта в регистре» (Документ.УСОERP_УчетВыполненныхРабот).
- Пары «НаНачало/Текущий» в ТЧ — перенос % между документами + контроль неубывания/100%.
- Формула EV в движениях: пропорция от плана (`Объем × Длительность / ОбъемВсего`) — 1:1 наша.
- Разреза модулей/секций/захваток у Rarus НЕТ (проверено grep) — модульную матрицу проектируем сами.
- Тип регистра: РН обороты (дельта EV-часов) — отчёт «EV vs табель» = обороты двух РН за период.

**Динамические колонки** (3 агента + синтез):
- **Эталон: `Документ.УстановкаЗначенийНефинансовыхПоказателей`** (типовой, в нашей конфигурации) —
  полный цикл «нормализованная ТЧ + программная матрица формы»:
  `ManagerModule.bsl:1604-1615` (ИзменитьРеквизиты → Элементы.Добавить → УстановитьДействие),
  pivot ТЧ↔матрица в ПриЧтенииНаСервере/ПередЗаписьюНаСервере (писать в ТекущийОбъект!),
  ПослеЗаписиНаСервере — повторный pivot; протокол пересоздания колонок «сохранить→перестроить→восстановить».
- Из `А_ТабельУчетаРабочегоВремени`: приём «один OnChange на таблицу + разбор ТекущийЭлемент.Имя»;
  его хранение (248 фиксированных реквизитов ТЧ) — антипример, НЕ копировать.
- Подводные камни: порядок ИзменитьРеквизиты→Элементы.Добавить (удаление зеркально);
  один вызов ИзменитьРеквизиты на всё; гард на существующие имена; ширины кодом;
  валидация программных колонок вручную с адресацией `Матрица[i].МN`; ТолькоПросмотр явно.

## Архитектура (3 объекта основной конфигурации + отчёт)

### 1. Документ `А_ВыполнениеРаботМодулей` — снимок накопленных % на дату

Шапка:
| Реквизит | Тип | Заполнение |
|---|---|---|
| Организация | Справочник.Организации | по умолчанию |
| СтруктураСебестоимости | Справочник.А_СтруктураСебестоимости | пользователь |
| Подразделение | Справочник.СтруктураПредприятия | авто из СС |
| КоличествоМодулей | Число(3,0) | фикс. из СС.А_КоличествоМодулей (0→1) |
| Ответственный | Справочник.Пользователи | текущий |
| Комментарий | Строка | — |

ТЧ `Работы` — **нормализованная (строка = работа × модуль)**, невидима пользователю:
| Реквизит | Тип | Смысл |
|---|---|---|
| Работа | Справочник.Номенклатура | вид работ |
| Этап | Справочник.А_ЭтапыРабот | из СС.Работы |
| НомерМодуля | Число(3,0) | 1..N |
| ПланЧасыМодуля | Число(10,2) | СС.Работы.Количество / N (фикс. при заполнении) |
| Процент | Число(5,2) | накопленный % модуля на дату |
| ПроцентНаНачало | Число(5,2) | кэш предыдущего снимка (справочно) |
| ЧасыВыполнение | Число(10,2) | ПланЧасыМодуля × Процент/100 |
| Комментарий | Строка(500) | колонка «Коментар» Excel (на всех строках работы одинаков) |

Нулевые клетки (Процент=0 и НаНачало=0) в ТЧ не пишутся.

### 2. Форма — динамическая Excel-матрица (эталон НФП)

`Робота | Етап | План,год | М1 | … | М_N | Виконання,год | Коментар`, одна строка = работа.
- Реквизит формы `Матрица` (ТаблицаЗначений) со статическими колонками Работа/Этап/ПланЧасы/
  ЧасыВыполнение/Комментарий; колонки М1..М_N создаются программно по КоличествуМодулей
  (`ИзменитьРеквизиты` одним вызовом → `Элементы.Добавить` → `УстановитьДействие`).
- Реестр созданных элементов/реквизитов для пересоздания при смене СС.
- Пересчёт «Виконання» строки при вводе % (один Подключаемый-обработчик, N из имени элемента);
  итог EV внизу; N без ограничений (8/10/12…).
- Команды: **Заполнить из СС** (работы+этапы+план), **Заполнить по предыдущему** (срез РС →
  проценты + НаНачало), **Процентовать** (одно значение на выделенные строки/все модули).
- Pivot: ПриЧтенииНаСервере/ПриСозданииНаСервере — ТЧ→матрица; ПередЗаписьюНаСервере —
  матрица→ТЧ (в ТекущийОбъект); ПослеЗаписиНаСервере — повторный pivot. Контроль дублей работ.

### 3. РегистрНакопления `А_ВыполнениеРаботМодулей` (Обороты) — основной, для отчёта

- Измерения: СтруктураСебестоимости, Работа (Номенклатура), НомерМодуля (Число 3,0);
  + Подразделение (для стыковки с отчётом без джойна к СС).
- Ресурс: **ЧасыВыполнение** (Число 15,2) — **дельта** за документ =
  ПланЧасыМодуля × (Процент − ПроцентПредыдущий_из_среза_РС)/100; может быть < 0 (корректировка вниз).
- Реквизит: Этап (для разреза отчёта).

### 4. РегистрСведений `А_ПроцентыВыполненияМодулей` — снимок % (вспомогательный)

- Периодический **по позиции регистратора**, подчинён регистратору (документу).
- Измерения: СтруктураСебестоимости, Работа, НомерМодуля; Ресурс: Процент (5,2).
- Назначение: СрезПоследних → «Заполнить по предыдущему», ПроцентНаНачало, контроль неубывания.
  % не восстанавливается из часов (план мутабелен) — снимок хранится явно.

### 5. Проведение (ОбработкаПроведения / ManagerModule по стилю bas-doc-new)

Один запрос-пакет: ТЧ + срез РС до документа (`НЕ Регистратор В (&Ссылка)` при перепроведении) →
дельта → движения РН (часы) + РС (снимок %). Защита деления на 0. Контроли
(мягко в форме + жёстко в ОбработкаПроверкиЗаполнения, ПутьКТабличнойЧасти):
1) Процент ≤ 100; 2) Процент ≥ предыдущий снимок (неубывание); 3) НомерМодуля ≤ КоличествоМодулей;
4) при проведении задним числом — предупреждение о более поздних документах той же СС.

### 6. Отчёт `А_ПланФактныйПроизводствоПолный` — блок «1. Праця»

Новые ресурсы (материалы/грн не трогаем):
- **ВиконанняЧасы** («Виконання, год») — обороты РН А_ВыполнениеРаботМодулей за период,
  Аналитика=Работа (те же строки, что план), Етап из регистра.
- **ОтклонениеВиконання** («Відхилення табель−виконання, год») = ФактЧасы − ВиконанняЧасы (totalField).
- **ПроцентВиконання** («% виконання») = ВиконанняЧасы/ПланЧасы×100 (totalField, ЧДЦ=1).
Сверка EV↔табель — на уровне Категорія/Підрозділ (в табеле нет разреза «Работа» — проверено:
РН.А_ДанныеТабелирования: Сотрудник/Подразделение/Состояние/Бригада).

## Порядок реализации и проверки

1. Метаданные (XML основной конфигурации): документ + РН + РС + регистрация в Configuration.xml
   (skills: bas-house-style → bas-doc-new / bas-register-new; meta-validate).
2. Модули: ObjectModule (проведение), форма-матрица (эталон НФП), команды заполнения.
3. Загрузка в BaseERP: db-load-xml + db-update (требует закрытого Конфигуратора).
4. Python COM (Rule #-1): все запросы проведения/заполнения — сначала COM-тест;
   затем создать документы 19.06/26.06/03.07 из Excel, провести, сверить:
   РН обороты на 03.07 ≈ 2330 EV-часов (лист 03.07), дельты между снимками, неубывание.
5. Отчёт: новая ветка EV в ПолучитьДанные (COM-тест) + поля/итоги в Template.xml → erf-build →
   СКД-smoke → копия в основную конфигурацию.
6. Adversarial review workflow (ultracode) → фиксы → commit/push.
