# Доработка форм «А_ПереносДвиженийИзКазны»

## Context

Документ `А_ПереносДвиженийИзКазны` создан и работает (заполняет ТЧ из Казны через COM, проводит движения в `РегистрНакопления.А_ДвиженияДенегИзКазны`). Однако формы документа и списка минимальны: в форме документа есть только кнопка «Заполнить из Казны» (нет даже кнопок «Провести и закрыть» / «Записать»), в форме списка нет колонок-индикаторов (сумма, кол-во строк) и нет явной кнопки «Движения документа».

**Цель:** привести обе формы к стандарту BAS ERP 2.5 (по образцу `РеализацияТоваровУслуг`, `ПриобретениеТоваровУслуг`, `А_БюджетМесяц`).

**Результат для пользователя:**
- Форма документа имеет полный набор стандартных команд: «Провести и закрыть», «Записать», «Провести», «Заполнить из Казны», «Движения документа», подменю «Создать на основании / Печать / Отчёты / Заполнить».
- Форма списка имеет явную кнопку «Движения документа» над таблицей (не только в контексте).

## 1. Метаданные документа — без изменений

`Документ.А_ПереносДвиженийИзКазны.xml` уже имеет:
- `<UseStandardCommands>true</UseStandardCommands>`
- `<RegisterRecords>` с `AccumulationRegister.А_ДвиженияДенегИзКазны`

Этого достаточно, чтобы платформа автоматически предоставляла стандартную команду «Движения документа» (через контекст-меню). Дополнительная работа — только сделать её **явной кнопкой**.

### 2.2 Команда «Движения документа» — реализация

В BAS ERP это реализуется через явную команду формы, которая открывает стандартный отчёт `Отчет.ДвиженияДокумента` с параметром-ссылкой на документ:

```bsl
&НаКлиенте
Процедура ДвиженияДокумента(Команда)
	Если НЕ ЗначениеЗаполнено(Объект.Ссылка) Тогда
		ПоказатьПредупреждение(, "Документ ще не записаний.");
		Возврат;
	КонецЕсли;
	ПараметрыФормы = Новый Структура("ОбъектОтчета", Объект.Ссылка);
	ОткрытьФорму("Отчет.ДвиженияДокумента.Форма", ПараметрыФормы);
КонецПроцедуры
```

Команда формы регистрируется в `<Commands>` Form.xml:

```xml
<Command name="ДвиженияДокумента">
    <Title>Движения документа</Title>
    <Action>ДвиженияДокумента</Action>
</Command>
```

Кнопка `ФормаДвиженияДокумента` ссылается на эту команду через `Form.Command.ДвиженияДокумента`.

> Альтернатива: использовать существующую общую команду `ОбщаяКоманда.ДвиженияДокумента` через `<CommandName>CommonCommand.ДвиженияДокумента</CommandName>`. При имплементации проверим, существует ли она в конфигурации; если да — используем её, тогда отдельную команду формы можно не создавать.

### 2.3 ChildItems — что остаётся

Те же группы (Шапка, ГруппаНомерДата, Комментарий, Таблица СтрокиДвижений) — без изменений. Подменю, которые сейчас лежат в `<ChildItems>` верхнего уровня (`ПодменюЗаполнить`, `ПодменюОтчеты`, `ФормаГлобальныеКоманды`, `ПодменюСоздатьНаОсновании`), переносятся в `<AutoCommandBar><ChildItems>`. Дубликаты в `<ChildItems>` верхнего уровня удаляются.

### 2.4 Module.bsl формы документа — добавления

К существующим обработчикам (`ЗаполнитьИзКазны`, `ВыполнитьЗаполнение`, …) добавляется одна процедура `ДвиженияДокумента(Команда)` (см. 2.2). Если используется общая команда — даже эта процедура не нужна.

## 5. Порядок реализации

> **Правило проекта (memory/feedback_query_pre_check.md):** любой 1С-запрос, который попадает в `.bsl` или `Form.xml`, **сначала** прогоняется через Python COM (`win32com.client`) или MCP `mcp__1c-workerp__execute_query`, проверяется что запрос валидный и возвращает ожидаемый результат, и **только потом** вставляется в код.
> В рамках этого плана отдельных запросов нет (только команды/кнопки), но если на этапе имплементации возникнет необходимость дополнить — pre-check обязателен.

1. **Проверить наличие общей команды** `ОбщаяКоманда.ДвиженияДокумента` в Configuration.xml через `mcp__1c-workerp__list_metadata_objects` (metaType=CommonCommands). Если есть — использовать её, иначе создать локальную команду формы с действием `ОткрытьФорму("Отчет.ДвиженияДокумента.Форма", ...)`.
2. Расширить **AutoCommandBar формы документа** (Edit на Form.xml — добавить 4 новых кнопки + 1 ПодменюПечать; перенести 4 существующие группы; конвертировать `ФормаГлобальныеКоманды` в `ButtonGroup` с `CommandSource`).
3. Удалить дубликаты подменю из верхнего `<ChildItems>` формы документа.
4. Дополнить **Module.bsl формы документа** процедурой `ДвиженияДокумента` (если используем не общую команду).
5. Добавить кнопку `СписокДвиженияДокумента` в `AutoCommandBar` таблицы формы списка.
6. Дополнить **Module.bsl формы списка** процедурой `ДвиженияДокумента`.
7. **Валидация** через [/form-validate](.claude/skills/form-validate) — обе формы.
8. **Загрузка в БД** через `db-load-xml` (partial; только наши Form.xml + Module.bsl).
9. **Smoke-тест:**
    - Открыть форму документа: проверить что есть «Провести и закрыть», «Заполнить из Казны», «Движения документа», подменю «Печать», «Отчёты», «Заполнение», «Создать на основании».
    - Кнопка «Движения документа» в проведённом документе открывает отчёт со строками регистра.
    - Открыть форму списка: над таблицей видна кнопка «Движения документа».
    - Кнопка работает по выделенной строке списка.
