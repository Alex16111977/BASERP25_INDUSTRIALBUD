# А_ПлановаяСебестоимость — внешний отчёт план‑факт себестоимости (BaseERP)

Дата: 2026-06-05
Статус: реализовано и верифицировано (RED→GREEN, headless‑компоновка СКД)

## 1. Цель

Аналог отчёта `ПланФактСС` (работает на BuhBud) для базы **BaseERP**. Сравнивает
**плановую** себестоимость (нормативная структура) с **фактической** себестоимостью
из регистра учёта, в разрезе **Подразделение → Общее название → Номенклатура**,
с расчётом отклонений по количеству и сумме.

Файл‑источник: `_Rarzrabotki/Отчеты/А_ПлановаяСебестоимость.xml` (+ папка с СКД, формами, модулем).
Тип объекта: внешний отчёт (ExternalReport), регистрируется как «Дополнительный отчёт».

## 2. Маппинг источников BuhBud → BaseERP

| Сторона | ПланФактСС (BuhBud) | А_ПлановаяСебестоимость (BaseERP) |
|---|---|---|
| План | `Справочник.СтруктураСебестоимости.Комплектующие` | `Справочник.А_СтруктураСебестоимости.Комплектующие` |
| Факт | `Документ.ПоступлениеТоваровУслуг.Товары` | `РегистрНакопления.СебестоимостьТоваров` (records‑level, ВидДвижения=Приход) |
| Общее название | `Номенклатура.ОбщееНазваниеНоменклатуры` | `Номенклатура.А_ОбщееНазваниеНоменклатуры` |
| Подразделение | `Справочник.Подразделения` | `Справочник.СтруктураПредприятия` |

Ни один объект **не участвует в обмене** ЕРП↔Бух — отчёт целиком на данных ERP, без COM.
Папка `ПравилаОбменаДаннымиЕРПБух` использовалась только как словарь имён (подтвердила отсутствие
этих объектов в обмене).

## 3. Решения (согласованы с заказчиком)

- Факт = `СебестоимостьТоваров`, **обороты Приход** (поступление в учёт).
- Ресурс стоимости = **СтоимостьБезНДС** (сопоставимо с плановой Суммой).
- Тип отчёта = **внешний .erf** (как оригинал, без правок типовой конфигурации).

## 4. Критические находки RED‑фазы (Rule #‑1, тест на реальной базе)

Тестирование запроса ДО написания кода (Python COM) выявило, что «канонический» паттерн
типового `АнализСебестоимостиТоваровРасширенный` **не подходит** к данным этой базы:

1. **Подразделение брать из РЕКВИЗИТА `Подразделение`, а не из измерения
   `АналитикаФинансовогоУчета`.** В этой базе `АналитикаФинансовогоУчета` для себестоимости
   **пустая** (`ВЫРАЗИТЬ(... КАК СтруктураПредприятия)` = NULL для всех 332 млн оборота).
   Плановые подразделения (`МД ПРООН Черкаси ДСНС`, `МД МХП ОРІЛЬ`) присутствуют именно в
   реквизите `Подразделение`.
2. **Виртуальная таблица `.Обороты` НЕ отдаёт реквизит `Подразделение`** («Поле не найдено»).
   Поэтому факт берём из **records‑level** таблицы регистра с `ВидДвижения=Приход` и
   `Период МЕЖДУ` — семантически эквивалентно оборотам Приход и даёт доступ к реквизиту.
3. **Фильтр `РазделУчета = ТоварыНаСкладах`** захватывает 100% Прихода плановых подразделений
   (8 608 403.33 с фильтром == без фильтра) → двойного счёта по разделам учёта нет.
4. **Номенклатура** резолвится через измерение `АналитикаУчетаНоменклатуры.Номенклатура`.

## 4a. ИСПРАВЛЕНИЕ: факт не отображался (баг связи)

Первая версия фильтровала факт по реквизиту `СТ.Подразделение` (см. §4 п.1). Оказалось:
у приходного движения регистра реквизит `Подразделение` **часто ПУСТ** (трассировка дока
СТ00-000701: СтоимостьБезНДС=161 930.83 в регистре, но `Подразделение`-реквизит пуст →
фильтр ловил 0). Плюс обязательный период (дефолт «этот месяц») обнулял факт.

**Фикс:** связь подразделения брать у **РЕГИСТРАТОРА** —
`ВЫРАЗИТЬ(Регистратор КАК Документ.ПриобретениеТоваровУслуг).Подразделение` +
`Регистратор ССЫЛКА Документ.ПриобретениеТоваровУслуг`; период сделать необязательным.

**Сверка (регистр через Регистратор ≈ документы, минус услуги):**

| Подразделение | Старый фильтр (реквизит) | Регистратор (фикс) | Документы (эталон) |
|---|---|---|---|
| МД МХП ОРІЛЬ | 518 974 ✗ | 1 058 117 | 1 062 232 |
| МД ПРООН Черкаси ДСНС | 8 089 430 ✗ | 4 886 432 | 5 330 029 (Δ=услуги) |

Источник остаётся регистр `СебестоимостьТоваров` (требование заказчика).

## 5. Запрос СКД (валидированный)

Пакет из 5 блоков (как в оригинале), временные таблицы:

1. `ТзПодр` — подразделения из `А_СтруктураСебестоимости` (НЕ ПометкаУдаления).
2. `ТзФакт` — `СебестоимостьТоваров` records‑level: `ВидДвижения=Приход`,
   `РазделУчета=ТоварыНаСкладах`, `Регистратор ССЫЛКА Документ.ПриобретениеТоваровУслуг`;
   **подразделение — у РЕГИСТРАТОРА**: `ВЫРАЗИТЬ(Регистратор КАК Документ.ПриобретениеТоваровУслуг).Подразделение В (ТзПодр)`
   (реквизит `Подразделение` движения часто ПУСТ — см. §4a); период **необязательный**:
   `(Период МЕЖДУ &НачалоПериода И &КонецПериода ИЛИ &КонецПериода = ДАТАВРЕМЯ(1,1,1))`;
   поля: Номенклатура (через `АналитикаУчетаНоменклатуры.Номенклатура`), ОбщееНазвание, Единица,
   `СУММА(Количество)`, `СУММА(СтоимостьБезНДС)`.
3. `СводнаяТаблица` = ОБЪЕДИНИТЬ ВСЕ: план (`Комплектующие` → КоличествоСС, СуммаСС) + факт (`ТзФакт`).
4. `Сводная` — группировка/суммирование по ключу (Подразделение, ОбщееНазвание, Номенклатура, Единица).
5. Финал — РазницаКоличество, РазницаСумма, ПроцентОтклонениеКол/Сум.

Ключ сопоставления план↔факт: **Подразделение + ОбщееНазвание + Номенклатура + Единица**.

## 6. Параметры СКД

- `Период` (СтандартныйПериод, по умолчанию ThisMonth).
- `НачалоПериода` / `КонецПериода` — производные (`&Период.ДатаНачала/ДатаОкончания`,
  useRestriction=true), фильтруют records‑level регистра.

`РазделУчета=ТоварыНаСкладах` зашит в запрос (захватывает 100% по проверке). При необходимости —
вынести в параметр.

## 7. Структура файлов (типовой отчёт, как АнализСебестоимостиТоваровРасширенный)

Отчёт использует **типовую ОбщаяФорма.ФормаОтчета** (БСП), без собственных форм:
```
_Rarzrabotki/Отчеты/А_ПлановаяСебестоимость.xml                       (ExternalReport: DefaultForm=CommonForm.ФормаОтчета,
                                                                        SettingsForm/VariantForm=типовые; ChildObjects=только Template)
_Rarzrabotki/Отчеты/А_ПлановаяСебестоимость/
   Ext/ObjectModule.bsl                                               (СведенияОВнешнейОбработке + ПриКомпоновкеРезультата с ДанныеРасшифровки — см. §11)
   Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml           (СКД: запрос + параметры + Период как быстрая настройка)
```
**НЕ** делать кастомную форму/ПриКомпоновкеРезультата (это давало старый интерфейс «Сформировать/Выбрать вариант»).
Интерфейс (Период, Настройки, варианты, быстрые отборы) даёт типовая ФормаОтчета.

## 9. Известные ограничения / развитие

- **Единицы:** план — `УпаковкиЕдиницыИзмерения`, факт — базовая `Номенклатура.ЕдиницаИзмерения`;
  сравнение «как есть» (как в оригинале). Пересчёт по коэффициенту — будущее улучшение.
- `РазделУчета` зашит на `ТоварыНаСкладах` (по проверке покрывает 100%); при изменении учётной
  политики — вынести в параметр.
- Организация не фильтруется (плановые подразделения принадлежат одной юр.лицу).

## 10. Развёртывание

Исходник — `_Rarzrabotki/Отчеты/А_ПлановаяСебестоимость.xml` (+ папка). Собранный артефакт —
`_Rarzrabotki/Отчеты/А_ПлановаяСебестоимость.erf` (собран против BaseERP, протестирован).
Загрузка пользователем: «НСИ и администрирование → Дополнительные отчёты и обработки» (или
открыть `.erf` напрямую). Пересборка при изменении исходника:
`/erf-build` против BaseERP (НЕ стаб — в нём нет ERP‑объектов).

## 11. Расшифровка до документа

В набор данных добавлено **составное поле `Документ`**: для строк ПЛАНа = `Справочник.А_СтруктураСебестоимости`,
для строк ФАКТа = `Документ.ПриобретениеТоваровУслуг` (регистратор прихода). Поле выводится в окне
«Выбор поля» расшифровки. Чтобы его получить, запрос НЕ агрегирует по документу полностью —
`Документ` входит в группировку всех ВТ (детальные записи на уровне документа; в отображении всё так же
свёрнуто до Номенклатуры). Использование: двойной клик по ячейке `Количество СС` или `Количество` →
Расшифровать → **Документ** → открывается источник (структура себестоимости / приходная накладная).
Проверено: поле `Документ` присутствует в наборе данных собранного `.erf`, суммы не изменились
(Σплан 5 699 881.55 / Σфакт 5 944 549.22).

**ВАЖНО (баг расшифровки):** у ВНЕШНЕГО отчёта типовая `ФормаОтчета` не формирует данные расшифровки
сама — «Расшифровать»/«Открыть» серые. Нужен хук `ПриКомпоновкеРезультата` со СТАНДАРТНЫМ выводом +
`ДанныеРасшифровки` (как в `АнализСебестоимости`): `СтандартнаяОбработка=Ложь`,
`КомпоновщикМакета.Выполнить(СхемаКомпоновкиДанных, КомпоновщикНастроек.ПолучитьНастройки(), ДанныеРасшифровки)`,
`ПроцессорКомпоновки.Инициализировать(Макет, , ДанныеРасшифровки, Истина)`. СКД расшифровку генерит
(проверено COM: 8486 элементов) — проблема была только в передаче её формой. Добавлено в ObjectModule.bsl.
