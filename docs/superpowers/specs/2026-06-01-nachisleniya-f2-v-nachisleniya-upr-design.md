# Дизайн: добавить начисления из РаспределениеФ2 (А_Начисление=Истина) в А_ОтражениеЗПпоКазне.НачисленияУпр

> Создан: 2026-06-01. Источник требований: `_Rarzrabotki/notebook/knowledge_А_ОтражениеЗПпоКазне/PROMPT_НачисленияФ2_в_НачисленияУпр.md` (самодостаточный промт-spec).

## Цель

При заполнении документа `А_ОтражениеЗПпоКазне` добавлять в ТЧ `НачисленияУпр` строки-начисления из документов `РаспределениеФ2`, у которых `А_Начисление = Истина` (премии/доплаты, выплачиваемые через кассу — Форма2). В zup_2 этих премий нет, поэтому управленческий NET был меньше реальных кассовых выплат.

## Архитектура

Одна новая приватная процедура `_ОтрЗП_ДобавитьНачисленияИзРаспределенияФ2()` в `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`, область `ЕРП_ЗагрузкаИзЗУП2`. Вызывается в конце существующей `ЗаполнитьНачисленияУпризЗуп2()` — **после** диагностики, **перед** `КонецПроцедуры` (≈стр. 1046).

Существующий код не меняется. Очистка `НачисленияУпр.Очистить()` остаётся одна — в начале процедуры (стр. 935). Ф2-строки **добавляются** к zup_2-строкам, не затирают их.

## Запрос (источник РаспределениеФ2)

Агрегация по всем Ф2 за период → одна строка на (ФизЛицо × ВидРасчёта). `Ф2.Ссылка` убрана из SELECT и GROUP BY (отличие от §4.1 промта — там группировка была per-документ).

```sql
ВЫБРАТЬ
    Ф2.А_ВидРасчета.Наименование КАК ВидРасчета,
    Ф2.А_ВидРасчета.Код          КАК КодВидРасчета,
    Стр.Сотрудник.ФизическоеЛицо КАК ФизЛицо,
    Стр.Сотрудник.Наименование   КАК ФИО,
    СУММА(Стр.СуммаНачисления)   КАК Сумма
ИЗ Документ.РаспределениеФ2 КАК Ф2
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.РаспределениеФ2.Сотрудники КАК Стр
    ПО Стр.Ссылка = Ф2.Ссылка
ГДЕ Ф2.А_Начисление = ИСТИНА
    И Ф2.Проведен = ИСТИНА
    И Ф2.КассаДатаС >= &НачалоПериода
    И Ф2.КассаДатаПо <= &КонецПериода
    И Стр.СуммаНачисления <> 0
СГРУППИРОВАТЬ ПО
    Ф2.А_ВидРасчета.Наименование, Ф2.А_ВидРасчета.Код,
    Стр.Сотрудник.ФизическоеЛицо, Стр.Сотрудник.Наименование
```

Параметры: `НачалоПериода = НачалоМесяца(Дата)`, `КонецПериода = КонецМесяца(Дата)` (как в существующей процедуре). Запрос локальный (ERP), не COM.

## Заполнение НачисленияУпр

| Реквизит | Значение из запроса |
|---|---|
| `ФизЛицо` | `Стр.ФизЛицо` (= `Сотрудник.ФизическоеЛицо`, без COM-маппинга по ДРФО) |
| `ФИО` | `СокрЛП(Стр.ФИО)` |
| `Сумма` | `Стр.Сумма` |
| `ВидРасчета` | `Стр.ВидРасчета` («Премія (Зарплата)») |
| `КодВидРасчета` | `СокрЛП(Стр.КодВидРасчета)` — **«ПРЕМ» из источника** (решение заказчика 2026-06-01; НЕ маппинг на «00020») |

Если `ФизЛицо` пусто — залогировать (`Сообщить`) и пропустить строку.

## Влияние на downstream

`_ОтрЗП_ОбчислитиNETПоФизЛицу()` (стр. 1379) итерирует `НачисленияУпр` целиком → Ф2-строки автоматически входят в `NETПоФизЛицу` → через Op 2 в `НачисленнаяЗарплатаИВзносыПоФизлицам.Сумма`. В разметке ФормаPL премия уходит в Форма2 (остаток `total − Ф1(GROSS)`).

## Критерии приёмки

1. Тест запроса (Rule #-1): на дек.2025 → Постернак / «Премія (Зарплата)» / «ПРЕМ» / 100 000; Σ Ф2 №000000034 = 2 209 500.
2. `ЗаполнитьНачисленияУпризЗуп2` расширена вызовом `_ОтрЗП_ДобавитьНачисленияИзРаспределенияФ2`; zup_2-строки сохранены.
3. На реальном `А_ОтражениеЗПпоКазне` дек.2025 у Постернака появляется строка «Премія (Зарплата) / ПРЕМ / 100 000» рядом с «Оклад по днях».
4. Σ `НачисленияУпр` выросла на сумму Ф2-начислений периода.
5. ФормаPL (Постернак): Ф1 (GROSS) не изменился; Ф2 вырос на премию.
6. Файл в основной конфигурации (Rule #4 — уже работаем в основной директории); загрузка `/db-load-xml -Mode Partial` + `/db-update -Dynamic+`.

## Антипаттерны (из промта §7)

- НЕ вызывать `НачисленияУпр.Очистить()` повторно перед Ф2-шагом.
- НЕ матчить ФизЛицо по ИНН — `Сотрудник` уже ссылка.
- НЕ брать Ф2 из `РаспределениеКазна.ДокРаспределениеЗП` (там ещё пусто на этом шаге) — только прямым запросом.
- Имя поля = `СуммаНачисления` («Перечисления» — синоним).
- НЕ объявлять переменную `Ссылка` (reserved).
- НЕ писать BSL без проверки запроса (Rule #-1).
