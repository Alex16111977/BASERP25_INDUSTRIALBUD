# Отчёт А_ОтчетPL_ПолныйЕРП: колонка «PL с начала года» (YTD)

Дата: 2026-08-24. Утверждено пользователем в диалоге (название, место, умолчание — его выбор).

## Что делаем

Новый разрез оси колонок — накопительный итог **с начала года**, рядом с существующим
«Накопительный PL» (вся деятельность). Управляется флажком в параметрах отчёта.

| Решение | Значение |
|---|---|
| Подпись колонки | **«PL с начала года»** |
| Место в оси | месяцы → **PL с начала года** → Накопительный PL → План итого |
| Ключ колонки (`КолонкаСорт`) | **890000** (месяцы < 890000 < 900000 < 900100) |
| `ВидКолонки` | новое значение «PL с начала года» |
| Параметр СКД | `ВыводитьСНачалаГода`, заголовок «Выводить: PL с начала года», булев |
| Умолчание | **Ложь** — существующие варианты не меняются, включается вручную |

## Семантика

С 1 января года, в котором лежит **конец** периода, по конец периода.
Правило источника — ЗАКОН без исключений (решение 20.08.2026): последний месяц периода —
ТОЛЬКО регистры ЕРП; более ранние месяцы года — ТОЛЬКО документы `А_ОтчетPL`; месяц без
документа — НОЛЬ. Конец периода в январе → колонка равна одному январю (регистры).

Инварианты: при периоде с 1 января «PL с начала года» = Σ месячных колонок;
«Накопительный PL» − «PL с начала года» = вклад месяцев прошлых лет.

## Реализация (подход A — утверждён)

1. **Запрос** (пакет `v8_full.sql`, Rule #-1 — сначала Python COM, потом inject скриптом):
   - `втКолонкиPL`: строка (890000, «PL с начала года») при `&ВыводитьСНачалаГода`;
   - новый параметр `&КлючНачалаГода` = ГОД(КонецПериода)·100 + 1;
   - фактовые ветки с условием `ИЛИ КЛ.КолонкаСорт = 900000` дополняются
     `ИЛИ (КЛ.КолонкаСорт = 890000 И Д.МесяцКлюч >= &КлючНачалаГода)`;
   - план (900100) и фиксы не трогаются; водопад/проценты/разметка per-column — подхватят сами.
2. **Модуль**: чтение флага, установка `&КлючНачалаГода`, `ВидКолонки` для 890000,
   валидация «включите хотя бы один блок» учитывает новый флаг.
3. **Template.xml**: параметр `ВыводитьСНачалаГода` (после `НазванияНаРусском`).
   Настройки предопределённых вариантов НЕ меняем.
4. **Риск-проверка ПЕРВОЙ**: отбор по «Вид колонки» в сохранённых вариантах пользователя —
   если он есть списком, колонка не пройдёт отбор даже при флаге; задокументировать.
