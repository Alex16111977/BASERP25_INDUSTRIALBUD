## 1. Контекст — бизнес-задача глазами бухгалтера

### 1.1 Реальный мир: 2+ юр.лица, 2 «канала», 1 управ.организация

В управленческом учёте ERP — **одна** организация `ТОВ "ІНДАСТРІАЛБУД"` (зонтик).

В реальном мире (бухгалтерский учёт, BAS Бухгалтерія) — **много** юр.лиц. Из них для зарплаты критичны:

| Юр.лицо (бух.учёт) | «Канал деятельности» | Подразделение в ERP (целевое) |
|---|---|---|
| **ТОВ "ІНДАСТРІАЛБУД"** (КодПоЕДРПОУ 40645273) | Строительство / Девелопмент | `Строительство` |
| **ІНДЕПТ СТІЛ ТОВ** | Производство (МК Глобино) | `Производство` |
| ДЖИ ТРИ КОНСТРАКШН ТОВ | Строительство | `Строительство` |
| ТОВ ВФ АССЕТС | Девелопмент | `Строительство` |
| І.П.С ТРЕЙД ТОВ | И.П.С. | (отдельное направление) |
| ...ещё ~5 | разные | разные |

**Каждое юр.лицо имеет:**
- Свой расчётный счёт (`Справочник.БанковскиеСчетаОрганизаций.А_ОрганизацияБухгалтерия`)
- Свою кассу
- Свой набор сотрудников (в базе ZUP_1 — реквизит `Сотрудник.Организация`)

### 1.2 Бизнес-проблема

После реализации `А_ОтражениеЗПпоКазне` + `СоздатьДокументНачисления` + `СоздатьДокументОтражениеЗПвФинУчёте` + (новое) `СоздатьВедомостиВКассуПоОтражениюЗП`:
- Начисление ЗП по факту делается **на сотрудника** в его реальном подразделении (например, ЦО, Глобино-2)
- Налоги (НДФЛ, ВС, ЕСВ) — также по реальному подразделению
- Ведомости в кассу созданы с шапкой `Подразделение=ПУСТО` и ТЧ Зарплата с реальными подразделениями

**Но платится** только через 2 банка/кассы:
- Расчётный счёт ТОВ "ІНДАСТРІАЛБУД" → канал `Строительство`
- Расчётный счёт ІНДЕПТ СТІЛ ТОВ → канал `Производство`

**Следствие:** деньги (нал и безнал) уходят с подразделения «Строительство» / «Производство», а начисления висят на других подразделениях («ЦО», «Глобино-2», и т.д.) → **дисбаланс в управ.балансе**.

### 1.3 Желаемое поведение

> Перед выплатой ЗП — «перебросить» все начисления (ФОТ + налоги + удержания) **по сотрудникам каждого юр.лица** с реального подразделения работы → **в целевое подразделение для выплаты** (`Строительство` или `Производство`), где есть банк/касса этой организации.

После переброса:
- На `Строительство` — все ФОТ + налоги по сотрудникам ТОВ "ІНДАСТРІАЛБУД" + ДЖИ ТРИ + ВФ АССЕТС + других «строительных» юр.лиц.
- На `Производство` — всё по сотрудникам ІНДЕПТ СТІЛ.
- Дальше — `ВедомостьНаВыплатуЗарплатыВКассу` / `ВедомостьНаВыплатуЗарплатыВБанк` ссылается на это **целевое** подразделение (а не на исходное).

Это устраняет дисбаланс: где платят — там и начислено.

### Универсальный паттерн «перенос между подразделениями»

Во всех существующих инструментах используется **один паттерн**:
```
Подразделение → Партнёр (по А_Подразделение) → Контрагент (по Партнёр) → Договор/ОбъектРасчетов
```

Для каждой пары (Подр_Источник, Подр_Целевой) создаются **парные документы**:
- РеализацияТоваровУслуг (со стороны источника) + ПриобретениеТоваровУслуг (со стороны целевого), ИЛИ
- СписаниеБезнал (источник) + ПоступлениеБезнал (целевой), ИЛИ
- ВзаимозачетЗадолженности (одним документом, без денежного движения)

## 3. Архитектура решения — 3 подхода + рекомендация

### Подход A — Расширить `А_ОказаниеУслугМеждуПодразделениями` (полная «продажа услуг»)

**Что:** для каждой пары (ИсхПодр, ЦелПодр) создаётся пара Реализация+Приобретение с номенклатурой «Услуги по содержанию аппарата управления».

✅ Используется существующий проверенный документ, бух.проводки 6311/3611, прозрачно в учёте.
❌ Избыточно (2 документа на пару), требует Номенклатуру, включает НДС-цепочку.

---

### Подход B — `ВзаимозачетЗадолженности` (минимальный, по образцу А_ОбработкаДисбаланса)

**Что:** для каждой пары (ИсхПодр, ЦелПодр, ОргБух) создаётся **один** `ВзаимозачетЗадолженности` со 2 строками: дебитор (целевое подразделение получает задолженность) и кредитор (исходное подразделение её отдаёт).

✅ Минимальный, не требует Номенклатуры/НДС, готовый паттерн в `А_ОбработкаДисбалансаПоПодразделениям`.
⚠️ Бух.учёт: проводки Дт 631 Кт 361 — нужно подобрать договор/группу финучёта подходящие под ЗП.

---

### Подход C — **Гибрид** ВзаимозачетЗадолженности + А_ПереносДвиженийИзКазны (рекомендую)

**Что:**
1. На `Документ.А_ПереносДвиженийИзКазны` (после `ЗаполнитьИзКазны()`) добавляется **новая экспортная процедура** `СоздатьПередачиЗПМеждуПодразделениями()`.
2. Эта процедура анализирует ТЧ `СтрокиДвижений` родителя:
   - Группирует строки по `А_ОрганизацияБухгалтерия × Подразделение` (исходное)
   - Σ суммы для каждой группы
3. Для каждого юр.лица определяется **целевое подразделение** (по `Организации.А_ЦелевоеПодразделениеДляЗП` или по `БанковскиеСчетаОрганизаций`)
4. Для каждой пары (ОргБух, ИсхПодр → ЦелПодр) с дельтой ≠ 0 создаётся `ВзаимозачетЗадолженности` (по образцу `А_ОбработкаДисбалансаПоПодразделениям.СоздатьВзаимозачет`)
5. Связь: реквизит-шапка `ВзаимозачетЗадолженности.А_ПереносДвиженийИзКазны` — для Find-Or-Create
6. После: на целевом подразделении (Производство/Строительство) делается `ВедомостьНаВыплатуЗарплатыВКассу/ВБанк` с фильтром по А_ОрганизацияБухгалтерия

**Плюсы:**
- ✅ Минимум кода — переиспользуем `СоздатьВзаимозачет` из обработки дисбаланса
- ✅ Кнопка-триггер на уже существующем документе
- ✅ Группировка идёт от реального источника (БДДС Казны)
- ✅ Find-Or-Create — идемпотентно
- ✅ После переноса прямой переход к ведомостям

**Минусы:**
- ⚠️ Нужен новый реквизит на `ВзаимозачетЗадолженности.А_ПереносДвиженийИзКазны`

### 4.4 Новая процедура на А_ПереносДвиженийИзКазны

Размещение: `Documents/А_ПереносДвиженийИзКазны/Ext/ObjectModule.bsl`, область `#Область А_СоздатьПередачиЗПМеждуПодразделениями`.

**Алгоритм:**

```
0. GUARD: Проведен; СтрокиДвижений.Количество() > 0

1. ВЫБОРКА исходных пар:
   ВЫБРАТЬ
       Т.А_ОрганизацияБухгалтерия КАК ОргБух,
       Т.Подразделение            КАК ИсхПодр,
       Т.СтатьяДвиженияДенежныхСредств,
       Т.НаправлениеДеятельностиКазна,
       СУММА(Т.Сумма)             КАК Сумма
   ИЗ Документ.А_ПереносДвиженийИзКазны.СтрокиДвижений КАК Т
   ГДЕ Т.Ссылка = &Ссылка
      И Т.СтатьяДвиженияДенежныхСредств.А_ОтноситсяКЗПДляПередачи = ИСТИНА
      И ЗначениеЗаполнено(Т.А_ОрганизацияБухгалтерия)
      И ЗначениеЗаполнено(Т.Подразделение)
   СГРУППИРОВАТЬ ПО ОргБух, ИсхПодр, СтатьяДДС, Направление

2. ДЛЯ КАЖДОЙ строки выборки:
   - ЦелПодр = ОргБух.А_ЦелевоеПодразделениеДляЗП
   - Если ИсхПодр = ЦелПодр — пропуск
   - Если ЦелПодр пуст — Сообщить "ОргБух не настроена" + продолжить
   - Если |Сумма| < 0.01 — пропуск
   
   - Партнёр_Источник = найти по А_Подразделение = ИсхПодр
   - Контрагент_Источник = найти по Партнер = Партнёр_Источник
   - Партнёр_Цель = найти по А_Подразделение = ЦелПодр
   - Контрагент_Цель = найти по Партнер = Партнёр_Цель
   
   - Find-Or-Create ВзаимозачётЗадолженности
       по (А_ПереносДвиженийИзКазны, ИсхПодр, ЦелПодр, ОргБух):
     Если не найдено — создать новый
     Если найдено — распровести, очистить ТЧ
   
   - Заполнить шапку:
       Дата, Организация = шапка родителя
       КонтрагентДебитор = Контрагент_Цель
       КонтрагентКредитор = Контрагент_Источник
       СуммаДокумента = ABS(Сумма), Валюта = грн
       А_ПереносДвиженийИзКазны = Ссылка
       А_ИсходноеПодразделение, А_ЦелевоеПодразделение, А_ОрганизацияБухгалтерия
   
   - Заполнить ТЧ ЗадолженностьДебитора (1 строка):
       Партнер = Партнёр_Цель, Договор/ОбъектРасчетов = find-or-create
       ТипРасчетов = РасчетыСПоставщиком, Сумма = ABS(Сумма)
   
   - Заполнить ТЧ ЗадолженностьКредитора (1 строка):
       Партнер = Партнёр_Источник, Договор/ОбъектРасчетов
       ТипРасчетов = РасчетыСКлиентом, Сумма = ABS(Сумма)
   
   - Записать(Проведение). Fallback Запись.

3. ОЧИСТКА «зайвых» ВзаимозачетЗадолженности:
   Найти все ВЗ с А_ПереносДвиженийИзКазны = Ссылка, НЕ обработанные в текущем цикле,
   пометить на удаление (по образцу А_ОбработкаДисбаланса).

4. ИТОГ: Сообщить "Создано N взаимозачётов на Σ M грн"
```

### 5.1 Инвариант сумм

После создания всех `ВзаимозачетЗадолженности` по одному родителю:
```
Σ(ВЗ.СуммаДокумента) по {ОргБух=X, ЦелПодр=Y}  =  
    Σ(А_ПереносДвиженийИзКазны.СтрокиДвижений.Сумма) 
    где А_ОрганизацияБухгалтерия=X И ИсхПодр<>Y И ЭтоЗПстатья=Истина
```

### 5.2 Регистр-инвариант (после проведения всех ВЗ)

В регистре `РегНакопл.РасчетыСПартнерами` / `РегНакопл.ПрочиеАктивыПассивы`:
- `Подразделение = Целевое` — положительный баланс по ОргБух
- `Подразделение = Исходное` — отрицательный того же модуля
- **Σ всех движений = 0** (взаимозачёт не создаёт денежного движения)

`А_ОтчетБаланс_Свод` (управ.баланс) на целевое подразделение увеличился, на исходное уменьшился. Итого по организации — **не изменился** (net-zero).

## 6. Связь с уже реализованной ВКассу (knowledge файлы 11/12/13)

Сейчас ВКассу создаётся через `А_ОтражениеЗПпоКазне.СоздатьВедомостиВКассуПоОтражениюЗП()` (файл 12) с шапкой `Подразделение=ПУСТО` и ТЧ Зарплата по реальным подразделениям.

**После реализации передачи** возможны два варианта эволюции ведомости:
- **Вариант A** (минимальный): ВКассу остаётся как сейчас (шапка пуста, ТЧ по реальным подр.). Передача ВЗ — отдельный механизм для управ.учёта.
- **Вариант B** (полная схема): ВКассу пересоздаётся с шапкой = ЦелевоеПодразделение + ТЧ Зарплата с фильтром по А_ОрганизацияБухгалтерия. N ведомостей = по числу (ЦелПодр × ОргБух).

Выбор — решение на этапе после реализации передачи. Spec оставляет оба варианта.
