# Доработка `Отчет.А_ОтчетPL` — колонки `СуммаДДСизКазны*` (касовий метод як довідка)

## Context

PnL-звіт `Отчет.А_ОтчетPL` працює методом **нарахування** (читає регістри `ПрочиеРасходы`, `ФинансовыеРезультаты`, `ПрочиеДоходы` ERP). Excel-PnL фінансиста ведеться **касовим методом** (показує реальні платежі). Виникають розбіжності — у клітинці Excel сума може бути взята фінансистом «з нарахування» або «з фактичного платежу Казни», і без перехресної довідки це не зрозуміти.

**Ціль:** додати в `Отчет.А_ОтчетPL` дві довідкові колонки **`СуммаДДСизКазныРасход`** і **`СуммаДДСизКазныПриход`** з нашого регістра `РегистрНакопления.А_ДвиженияДенегИзКазны` (заповнюється `Документом.А_ПереносДвиженийИзКазны` — див. `_Rarzrabotki/notebook/knowledge/perenos_dvizheniy_iz_kazny.md`). Сполучення — по `(Подразделение + СтатьяДДС)`.

**Користь:** у звіті поряд із сумою нарахування (СуммаЕРП) і PL (СуммаPL) фінансист побачить **фактичну витрату/прихід грошей з Казни** по тій самій статті ДДС → одразу зрозуміє джерело розбіжності.

**Pre-check (виконано через `execute_query` за Q1 2026):**
- 99 унікальних статей ДДС × 82 підрозділи в Казні
- Розхід 4,8 млрд / Прихід 4,8 млрд
- Зв'язано з PL-статтями через `Справочник.А_Статьи_PL`: −173 млн (нетто-розхід)
- Без зв'язку з PL: +160 млн (внутрішньогрупові, транзит)
- JOIN валідний.

## 1. Інженерні рішення (обґрунтування)

| # | Рішення | Обґрунтування |
|---|---|---|
| **Знак суми** | **Дві колонки**: `СуммаДДСизКазныРасход` (>0) + `СуммаДДСизКазныПриход` (>0) | Фінансисту критично бачити окремо відтік (платежі) і повернення/надходження. Один знак губить бізнес-сенс. |
| **JOIN** | По `(Подразделение + СтатьяДДС)` **без регістратора** | В А_ОтчетPL ЕРП-дані вже по цьому ключу. Реєстратор Казни ≠ реєстратор ERP. Перед JOIN — `СГРУППИРОВАТЬ ПО Подразделение, ДДС` щоб уникнути дублів. |
| **Розташування блоків** | Окремі тимчасові таблиці `втКазна_ПоПодрДДС`, `втКазна_ПоPL`, `втКазна_БезPL` (паттерн ідентичний `втЕРП_*`) | Консистентно з архітектурою звіту. |
| **Документ** | `NULL` у новому блоці (Казна не має документ-реєстратора звіту) | При розшифровці фінансист бачить рядок з порожнім Документом — дізнається що це довідка з Казни, а не реальний документ ERP. |
| **Імена ресурсів** | `СуммаДДСизКазныРасход`, `СуммаДДСизКазныПриход` | Корреспондує з `СуммаЕРП` у стилі проекту. Імʼя `СуммаДДСизКазны` (як просив користувач) розширено суфіксом знаку. |
| **Фільтр** | Не потрібен (окремі блоки несуть тільки Казну) | Нулі в існуючих рядках — нормальна поведінка. |

## 2. Зміни в `Reports/А_ОтчетPL/Ext/ObjectModule.bsl`

### 2.1 Новий CTE після `втЕРП_Доходы_Детали` (рядок 130)

```sql
// ======================================================================
// КАСА (довідка): обороти регістра А_ДвиженияДенегИзКазны
// згруповані до (Подразделение, ДДС). Без регістратора — Казна ≠ ERP.
ВЫБРАТЬ
    Каз.Подразделение                              КАК Подразделение,
    Каз.СтатьяДвиженияДенежныхСредств              КАК ДДС,
    СУММА(ВЫБОР КОГДА Каз.СуммаОборот < 0 ТОГДА -Каз.СуммаОборот ИНАЧЕ 0 КОНЕЦ) КАК СуммаКазнаРасход,
    СУММА(ВЫБОР КОГДА Каз.СуммаОборот > 0 ТОГДА  Каз.СуммаОборот ИНАЧЕ 0 КОНЕЦ) КАК СуммаКазнаПриход
ПОМЕСТИТЬ втКазна_ПоПодрДДС
ИЗ РегистрНакопления.А_ДвиженияДенегИзКазны.Обороты(&НачалоПериода, &КонецПериода, , ) КАК Каз
ГДЕ Каз.СтатьяДвиженияДенежныхСредств <> ЗНАЧЕНИЕ(Справочник.СтатьиДвиженияДенежныхСредств.ПустаяСсылка)
СГРУППИРОВАТЬ ПО Каз.Подразделение, Каз.СтатьяДвиженияДенежныхСредств
;
```

### 2.2 У всіх 5 існуючих фінальних блоків додати +2 колонки

У `втPL_Строки`, `втЕРП_ПоPL_Расх`, `втЕРП_ПоPL_Доходы`, `втЕРП_БезPL_Расх`, `втЕРП_БезPL_Доход`:

```sql
0 КАК СуммаДДСизКазныРасход,
0 КАК СуммаДДСизКазныПриход
```

(додати в кінець SELECT-списку перед `ПОМЕСТИТЬ`)

### 2.3 Два нових блоки перед фінальним UNION ALL

```sql
// ======================================================================
// Каса прив'язана до PL через ДДС (довідка для фінансиста)
ВЫБРАТЬ

    К.Подразделение.А_НаправлениеДеятельности                КАК НаправлениеДеятельности,
    ВЫРАЗИТЬ("" КАК Строка(150))                             КАК ПодразделениеСтрока,
    PLДДС.СтатьяPL.Группа                                    КАК Группа,
    PLДДС.СтатьяPL                                           КАК СтатьяPL,
    К.ДДС                                                    КАК ДДС,
    0 КАК СуммаФ1, 0 КАК СуммаФ2, 0 КАК СуммаPL,
    0 КАК СуммаЕРП, 0 КАК Разница,
    NULL                                                     КАК Документ,
    ВЫРАЗИТЬ("" КАК Строка(1000))                            КАК Комментарий,
    К.СуммаКазнаРасход                                       КАК СуммаДДСизКазныРасход,
    К.СуммаКазнаПриход                                       КАК СуммаДДСизКазныПриход
ПОМЕСТИТЬ втКазна_ПоPL
ИЗ втКазна_ПоПодрДДС КАК К
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ втPL_ДДС КАК PLДДС ПО PLДДС.ДДС = К.ДДС
;

// Каса БЕЗ зв'язку з PL (внутрішньогрупові, транзит — для повноти аналітики)
ВЫБРАТЬ
    К.Подразделение,
    К.Подразделение.А_НаправлениеДеятельности,
    ВЫРАЗИТЬ("" КАК Строка(150)),
    NULL КАК Группа, NULL КАК СтатьяPL,
    К.ДДС,
    0, 0, 0, 0, 0,
    NULL, ВЫРАЗИТЬ("" КАК Строка(1000)),
    К.СуммаКазнаРасход, К.СуммаКазнаПриход
ПОМЕСТИТЬ втКазна_БезPL
ИЗ втКазна_ПоПодрДДС КАК К
ГДЕ НЕ К.ДДС В (ВЫБРАТЬ PLД.ДДС ИЗ втPL_ДДС КАК PLД)
;
```

## 6. Verification

### 6.1 Прогнати звіт в 1С (smoke-тест)
- Період: січень 2026
- Перевірити що в шапці видно колонки «Каса (розхід)» / «Каса (прихід)»
- Знайти рядок де `СтатьяPL` = «Послуги сторонніх організацій» — переконатись що є числа в обох колонках (PL=X, ЕРП=Y, Каса.Розхід=Z)

### 6.2 Python-перевірка через `execute_query`
Якщо знаходимо в звіті дивне значення в колонці Каси — порівнюємо з прямим запитом до регістра:
```sql
ВЫБРАТЬ СУММА(СуммаОборот) ИЗ РегистрНакопления.А_ДвиженияДенегИзКазны.Обороты(
    ДАТАВРЕМЯ(2026,1,1), ДАТАВРЕМЯ(2026,1,31,23,59,59),
    Подразделение = &Подр И СтатьяДвиженияДенежныхСредств = &ДДС, )
```

### 6.3 Звірка з фактом
Фінансист порівнює свій Excel-PnL з новим А_ОтчетPL: розбіжність між колонками «PL» і «Каса (розхід)» = непогашені нарахування або платежі поза PL.
