# Дизайн: расшифровка документа А_ОтчетPL в отчёт сверки

**Дата:** 2026-04-17
**Автор:** Claude + пользователь (brainstorming skill)
**Статус:** в ревью

## 1. Контекст и проблема

В документе `Документ.А_ОтчетPL` (форма `ФормаДокумента`) есть кнопка **"Открыть сверку с 1С"**, которая должна открыть встроенный `Отчет.А_ОтчетPL` (сравнение PL vs 1С) с автоматической подстановкой параметров:

- Период = месяц, соответствующий `Объект.Дата` (1-й − последний день).
- Организация = `Объект.Организация`.
- Подразделение = `Объект.Подразделение`.

Сейчас реализация падает на этапе установки параметров:

```
Несоответствие типов (параметр номер '1')
{Документ.А_ОтчетPL.Форма.ФормаДокумента.Форма(103)}:
ПользПарам = Компоновщик.ПользовательскиеНастройки.ПолучитьОбъектПоИдентификатору(ИдПользовательский);
```

Причина — в моём коде `ИдентификаторПользовательскойНастройки` возвращается не как `Строка`, а в виде объекта (`УникальныйИдентификатор` или служебный тип), поэтому `ПолучитьОбъектПоИдентификатору(Строка)` падает с несоответствием типов.

Дополнительный фактор: я не проверил сценарий в рантайме (отчёт не был протестирован с реальным документом).

## 2. Решение (утверждённое бизнес-требованием)

Реализация **"A) Жёсткая установка параметров"**:
- Параметры Период / Организация / Подразделение применяются **неизменяемыми** фильтрами при открытии отчёта из документа.
- Пользователь не может менять их в UI отчёта (они отображаются, но заблокированы).
- Если нужно посмотреть другой месяц — пользователь открывает соответствующий документ PL и кликает кнопку там.

Ключевое уточнение пользователя: создать в отчёте **отдельный вариант настроек** с именем **`А_ОтчетPL_РасшифровкаДокументаОтчетPL`**, который открывается по умолчанию именно из документа. Обычный вариант "Основной" остаётся для ручного запуска отчёта.

## 3. Архитектура

### 3.1 Два варианта в СКД отчёта `Reports/А_ОтчетPL`

| Имя варианта | Презентация | Назначение | Поведение параметров |
|---|---|---|---|
| `Основной` (уже есть) | "Сравнение PL с 1С" | Ручной запуск из меню "Отчёты" | Пользователь задаёт сам |
| `А_ОтчетPL_РасшифровкаДокументаОтчетPL` (**новый**) | "Расшифровка документа PL" | Расшифровка из документа `А_ОтчетPL` | Подставляются документом, неизменяемы |

Второй вариант клонирует структуру первого (поля, группировки, отборы). Различие только в презентации — ну и в том, что откроется он через `ПараметрыФормы.ВариантКлюч + ФиксированныеНастройки`.

### 3.2 Механизм передачи параметров

Использовать `ПараметрыФормы.ФиксированныеНастройки` — объект `НастройкиКомпоновкиДанных`, сформированный на сервере. БСП `CommonForm.ФормаОтчета` применяет его к компоновщику и выключает редактирование соответствующих полей.

```
Форма документа
    │
    ├─ НаКлиенте: ОткрытьСверкуСЕРП(Команда)
    │        │
    │        └─ вызов НаСервере: СформироватьНастройкиОтчетаСверки(Дата, Организация, Подразделение)
    │                 │
    │                 ├─ схема = Отчеты.А_ОтчетPL.ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных")
    │                 ├─ вариант = схема.ВариантыНастроек.Найти("А_ОтчетPL_РасшифровкаДокументаОтчетPL")
    │                 ├─ настройки = вариант.Настройки                           ← чистый клон
    │                 ├─ настройки.ПараметрыДанных.УстановитьЗначениеПараметра(...)× 3
    │                 └─ возврат настройки
    │        │
    │        └─ ОткрытьФорму("Отчет.А_ОтчетPL.Форма", {
    │              ВариантКлюч = "А_ОтчетPL_РасшифровкаДокументаОтчетPL",
    │              ФиксированныеНастройки = настройки,
    │              СформироватьПриОткрытии = Истина
    │           })
    │
    └─ Отчет.А_ОтчетPL (форма отчёта)
           │
           └─ БСП ФормаОтчета применяет ФиксированныеНастройки
              → параметры не редактируются
              → отчёт сразу формируется
```

### 3.3 Почему именно `ФиксированныеНастройки`, а не `ПользовательскиеНастройки`

| Критерий | ФиксированныеНастройки | ПользовательскиеНастройки |
|---|---|---|
| Изменить в UI можно | Нет (главное требование) | Да |
| Нужен `userSettingID` в Template | Нет | **Да** (источник сегодняшней ошибки) |
| Метод установки | `УстановитьЗначениеПараметра(ИмяПараметра, Значение)` — принимает строку имени | `ПолучитьОбъектПоИдентификатору(UUID)` — UUID, не строка |
| Устойчив к ошибкам типа | Да | Нет (та самая ошибка) |
| Совпадает с бизнес-требованием (жёсткие фильтры) | **Да** | Нет |

## 5. Псевдокод ключевой функции

```bsl
&НаСервереБезКонтекста
Функция СформироватьНастройкиОтчетаСверки(Дата, Организация, Подразделение)

    Отчет = Отчеты.А_ОтчетPL.Создать();
    Схема = Отчет.СхемаКомпоновкиДанных;

    Вариант = Схема.ВариантыНастроек.Найти("А_ОтчетPL_РасшифровкаДокументаОтчетPL");
    Если Вариант = Неопределено Тогда
        Возврат Неопределено;  // вариант не загружен — в этом случае UI покажет предупреждение
    КонецЕсли;

    Настройки = Вариант.Настройки;  // клон, изменения не влияют на схему

    Период = Новый СтандартныйПериод;
    Период.ДатаНачала = НачалоМесяца(Дата);
    Период.ДатаОкончания = КонецМесяца(Дата);
    Настройки.ПараметрыДанных.УстановитьЗначениеПараметра("Период", Период);

    Если ЗначениеЗаполнено(Организация) Тогда
        Настройки.ПараметрыДанных.УстановитьЗначениеПараметра("Организация", Организация);
    КонецЕсли;

    Если ЗначениеЗаполнено(Подразделение) Тогда
        Настройки.ПараметрыДанных.УстановитьЗначениеПараметра("Подразделение", Подразделение);
    КонецЕсли;

    Возврат Настройки;  // тип: НастройкиКомпоновкиДанных

КонецФункции
```

Клиент открывает форму так:

```bsl
&НаКлиенте
Процедура ОткрытьСверкуСЕРП(Команда)
    Настройки = СформироватьНастройкиОтчетаСверки(Объект.Дата, Объект.Организация, Объект.Подразделение);
    Если Настройки = Неопределено Тогда
        ПоказатьПредупреждение(, "Вариант 'А_ОтчетPL_РасшифровкаДокументаОтчетPL' не найден в отчёте. Загрузите обновлённую конфигурацию.");
        Возврат;
    КонецЕсли;

    ПараметрыФормы = Новый Структура;
    ПараметрыФормы.Вставить("ВариантКлюч", "А_ОтчетPL_РасшифровкаДокументаОтчетPL");
    ПараметрыФормы.Вставить("ФиксированныеНастройки", Настройки);
    ПараметрыФормы.Вставить("СформироватьПриОткрытии", Истина);

    ОткрытьФорму("Отчет.А_ОтчетPL.Форма", ПараметрыФормы, ЭтаФорма);
КонецПроцедуры
```

## 7. Риски и их митигация

| Риск | Митигация |
|---|---|
| Копирование `<settingsVariant>` в Template XML с ошибками форматирования | Использовать прямой Edit с точечным добавлением через `Edit` в конец `<settingsVariant>Основной<...></settingsVariant>`. После правки — `cf-validate`. |
| `Отчеты.А_ОтчетPL.Создать()` требует прав или модели — может упасть в режиме `НаСервереБезКонтекста` | Фоллбэк: `ПолучитьМакет(...)` (возвращает схему без создания объекта). |
| Параметр "Период" в `ФиксированныеНастройки` не применится (тип `СтандартныйПериод`, не `Дата`) | Явно указать тип: `Настройки.ПараметрыДанных.УстановитьЗначениеПараметра("Период", Период)` — где `Период = Новый СтандартныйПериод`. Т.к. СКД параметр объявлен как `StandardPeriod`. |
| `ВариантКлюч` конфликтует с именем в маркетплейсе — игнорируется | Использовать строго то имя, что в Template `<dcsset:name>` — `А_ОтчетPL_РасшифровкаДокументаОтчетPL`. |

## 8. Вне объёма (не делаем)

- Не меняем существующий вариант `Основной` (только при необходимости удалим лишние `<dcsset:userSettingID>` для стабильности — по итогу ревью).
- Не делаем `Variants storage` / предопределённые варианты через БСП `ВариантыОтчетов` — достаточно SCD settingsVariant.
- Не меняем саму структуру отчёта (набор данных, группировки) — только добавляем settings variant и форму открытия.
- Не трогаем ТЧ документа А_ОтчетPL и Python-пайплайн.
