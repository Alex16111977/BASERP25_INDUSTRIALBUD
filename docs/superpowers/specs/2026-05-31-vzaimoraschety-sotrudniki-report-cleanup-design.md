# Доработка отчёта «А_ВзаиморасчетыССотрудникамиДляБаланса» — чистка СКД

**Дата:** 2026-05-31
**Тип:** доработка внешнего отчёта (ExternalReport, СКД)
**Объект:** `А_ВзаиморасчетыССотрудникамиДляБаланса` на регистре `РегистрНакопления.А_ВзаиморасчетыССотрудниками.ОстаткиИОбороты`

## Контекст

Отчёт создан мастером СКД и несёт авто-сгенерированный «мусор»: служебные поля
периодов-корзин и вводящий в заблуждение украинский синоним, скопированный из другого
отчёта. Пользователь просит убрать лишнее и оставить только нужное, ориентируясь на
типовые отчёты.

Сверка с типовым `ВедомостьРасчетовСПартнерами` (200 КБ): он держит `Регистратор`, но
**не** держит поля `ПериодДень/Месяц/Квартал/Год/Секунда` как отдельные корзины. Это
подтверждает, что доп. периоды в нашем отчёте — авто-мусор.

Структура регистра `А_ВзаиморасчетыССотрудниками`:
- Измерения: `Организация`, `ФормаPL` (Перечисление.А_ФормыPL: Форма1/Форма2), `Подразделение`, `ФизическоеЛицо`
- Ресурс: `СуммаВзаиморасчетов`
- Регистратор: 6 типов документов (РКО, ПКО, СписаниеБезналДС, ОтражениеЗПвФинУчете, А_ПередачаНачисленийМеждуПодразделениями, ПоступлениеБезналДС)

## Цель

Привести отчёт к чистому виду типовой ведомости остатков/оборотов. Состав данных и
поведение отчёта НЕ меняются — удаляются только неиспользуемые поля и исправляется текст.

Выбранный пользователем вид: **«Ведомость + документы»** (с детализацией до регистратора).

## Что убираем (лишнее)

1. **4 поля периодов-корзин** (роль `Additional`, periodNumber 3–6) — из определений полей
   СКД и из текста запроса:
   - `ПериодДень`, `ПериодМесяц`, `ПериодКвартал`, `ПериодГод`
   - В структуре/отборе варианта они не используются, в `totalField` отсутствуют — удаление безопасно.
2. **Неверный украинский синоним** отчёта:
   `«Відомість розрахунків з клієнтами (старий не використовувати)»`
   → `«Взаєморозрахунки зі співробітниками для балансу»` (по образцу синонима регистра).

## Что оставляем (что надо) — без изменений

- Измерения: `ФормаPL`, `Организация`, `Подразделение`, `ФизическоеЛицо`
- `Регистратор` + его `orderExpression` по `ПериодСекунда`
- **`ПериодСекунда`** — роль `Main` №2; на неё ссылается order у `Регистратора`.
  **КРИТИЧНО: не удалять — иначе ломается механизм периода и сортировка (подтверждено пользователем).**
- Ресурсы: `СуммаВзаиморасчетов` НачальныйОстаток / Приход / Расход / КонечныйОстаток + 4 `totalField`
- Параметры: `Период`, `НачалоПериода`, `КонецПериода`
- Вариант настроек: структура `ФормаPL → Подразделение → ФизическоеЛицо`, отбор по `ФизическоеЛицо`

- Не разойтись двум копиям файла — применять правки синхронно.
