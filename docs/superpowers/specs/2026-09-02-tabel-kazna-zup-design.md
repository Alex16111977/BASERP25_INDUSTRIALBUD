# Дизайн: часы «М» в табеле Казны + отчёт «Табели Казны и ЗУП»

> Дата: 02.09.2026. Базы: `kazna` (Казначейство 1.0.1.45), `zup` (БАС ЗУП 2.1, регламентная ЗП).
> Все факты ниже проверены на живых базах через COM; итоговые цифры повторяются в
> `_Rarzrabotki/Отчеты/PROMPT_ОтчетПоДаннымТабелейКазныиБазыЗУП.md`.

## 1. Проблема

Документ `ТабельУчетаРабочегоВремени` (Казна) при проведении разбирает ячейку дня так:
`В`/`Б`/`Н` дают своё Состояние с 0 часов, всё остальное непустое получает Состояние «Р»
и часы через `Число()` в Попытке. Для «8м» `Число("8М")` падает, в регистр
`ДанныеТабелирования` уходит строка «Р» с 0 часов. Так же теряются буквы О, К, С, М, Д.
Форма пропускает «8м» случайно: проверка `текЗначение >= "0" И <= "9"` строковая.

Бухгалтер по зарплате пользуется отчётом `ОтчетПоДаннымТабелей` как справкой: не
пропущен ли трудоустроенный человек при расчёте ЗП в ЗУП. Сейчас люди с «8м» в отчёте без часов.

Факты (январь–август 2026, проведённые табели): Н 10 335 ячеек, В 5 497, О 672, К 298,
Б 196, С 81, «8М» 51, «М» 25, опечатки «1О», «10-», «01», «10,5», «2.4», «4,5».
В августе 279 строк регистра «Р» с 0 часов у 46 сотрудников.

## 2. Легенда букв (выведена по ЗУП: тот же человек, тот же день)

| Казна | ЗУП в тот же день | Смысл |
|---|---|---|
| О | «в» відпустка 599 из 672, «д» 28 | отпуск |
| Б | «тн» хвороба 93, «р» 60 | больничный, треть в ЗУП ещё не оформлена |
| С | «на» відпустка б/о 57 из 81 | за свой счёт |
| К | «р» 223, «вд» відрядження 45 | командировка, в ЗУП рабочий день |
| Н | нет записи 1 584, «р» 1 346, «нз» 294 | неявка на объекте; часто в ЗУП день рабочий |
| В | нет записи 3 169 из 3 466 | выходной |
| 8М, М | «р» 61 из 76 | отработал, оплата официально через ЗУП, не по ставке Казны |
| Д | в данных 2026 не встречается | по легенде формы: декрет |

Решение пользователя: часы «М» специально не должны попадать в распределение ЗП Казны
и в план-факт производства ЕРП. ЕРП не меняем.

## 3. Регистр «Данные табелирования» (вариант B, принят)

- Новый ресурс `ЧасыОфициальные` (Число 10,1, синоним «Часы официальные (М)»). Метаданные
  Казны, только этот регистр. ЕРП-двойник `А_ДанныеТабелирования` и правила обмена не трогаем:
  документ уходит в ЕРП строками ТЧ и перепроводится там своим неизменённым модулем.
- Единый разбор ячейки в модуле менеджера документа, функция
  `РазобратьЗначениеЯчейки(Значение)` Экспорт возвращает Структуру
  `Состояние, ЧасыФакт, ЧасыОфициальные, Ошибка`:

| Ввод (после СокрЛП, ВРЕГ, латиница M/O/B/H/C/K в кириллицу, запятая в точку) | Состояние | ЧасыФакт | ЧасыОфициальные |
|---|---|---|---|
| пусто | «» (движение только если план больше 0) | 0 | 0 |
| число («8», «10.5») | Р | число | 0 |
| одна буква из О, Б, Н, В, С, К, М, Д | буква | 0 | 0 |
| число + М («8М») | М | 0 | число |
| иное («1О», «10-», «01М», «8К») | ? | 0 | 0, плюс Ошибка с текстом |

- `ОбработкаПроведения` вызывает разбор, пишет три ресурса; при Ошибке выдаёт
  сообщение «строка N, день D: …» без Отказа, чтобы история перепроводилась.
- Форма документа: проверка ввода через серверный вызов того же разбора; при Ошибке
  предупреждение «Допустимо: число, буква О/Б/Н/В/С/К/М/Д или число с М» и очистка ячейки.
  Итог «Всего часов» и «Всего грн» по-прежнему считают только `ЧасыФакт` (оплата по ставке).
- Потребители не меняются: распределение ЗП и Ф2 берут `Обороты()` с фильтром Состояние «Р».
  Виртуальная таблица отбрасывает строки с нулевыми ресурсами; строки «М» теперь в неё
  попадают, но отсекаются фильтром «Р».
- Штатный отчёт `ОтчетПоДаннымТабелей`: добавить поле и итог `ЧасыОфициальные`, вывести
  его в основном варианте рядом с «Часы факт».

## 4. Отчёт «Табели Казны и ЗУП» (внешний .erf, база Казна)

**Каркас:** `_Rarzrabotki/Отчеты/ОтчетПоДаннымТабелейКазныиБазыЗУП.xml` (сейчас копия
штатного). Имя `ОтчетПоДаннымТабелейКазныиБазыЗУП`, синонимы «Табелі Казни та ЗУП» /
«Табели Казны и ЗУП», типовые БСП-формы `CommonForm.ФормаОтчета`,
`ФормаНастроекОтчета`, `ФормаВариантаОтчета` (есть в Казне), внутренние GUID
перегенерировать, `СведенияОВнешнейОбработке` (ДополнительныйОтчет).

**Данные.** Два набора-объекта, наполняются в `ПриКомпоновкеРезультата`:
- Казна: физическая таблица `РегистрНакопления.ДанныеТабелирования` за период
  (границы `НачалоДня`/`КонецДня`, периоды регистра стоят на 23:59:59 дня), свёртка по
  сотруднику, состоянию и дню.
- ЗУП через COM (`V83.COMConnector`, строка подключения константой модуля по образцу
  `РаспределениеЗаработнойПлаты`: localhost / zup / АвтообменБУ, проверена 02.09.2026):
  `РегистрНакопления.РабочееВремяРаботниковОрганизаций` (по дням, вид времени
  `БуквенныйКод`) и `РегистрРасчета.ОсновныеНачисленияРаботниковОрганизаций`
  (Результат, ОтработаноДней, НормаДней, ВидРасчета). В ЗУП-запросах только строки и числа.
- Ключ: Казна `Сотрудники.ИНН` = ЗУП `ФизическиеЛица.КодПоДРФО`. Организации по `Код`,
  коды совпадают в обеих базах.

**Вариант «Сводно по сотрудникам»** (основной), строка = сотрудник Казны, плюс строки
ЗУП-людей с начислениями без табеля Казны:
- Казна: ИНН, Трудоустроен, организации и подразделения табелей (текст через запятую),
  дни и часы Р, дни и часы М, дни О, Б, С, К, Н, В, дни «?».
- ЗУП: ФИО ЗУП, организация ЗУП, актуален ли сотрудник, дни и часы «р», дни в, тн, на,
  вд, нз, прочие; начислено всего, отработано дней по начислениям, норма дней.
- Контроль (строка «Контроль» плюс булевы поля для оформления):
  1. `НетФлагаТрудоустроен`: Трудоустроен = Нет, а в ЗУП есть начисления или рабочие дни.
  2. `НетНачисленийЗУП`: Трудоустроен = Да, начислений в ЗУП нет.
  3. `НеПротабелированВЗУП`: в Казне есть Р или М, в ЗУП дней «р» нет.
  4. `БольничныйНеВЗУП`: дни Б есть, дней «тн» нет. Аналогично `ОтпускНеВЗУП` (О и в),
     `ЗаСвойСчетНеВЗУП` (С и на).
  5. `РасхождениеДней`: (Р + М + К) Казны минус «р» ЗУП, выводится числом.
  6. `НетИНН`: сверка невозможна.
  7. `НетТабеляКазны`: строка только из ЗУП.
  Строки с любым признаком подсвечиваются условным оформлением.

**Вариант «По дням»:** таблица сотрудник × день: значение Казны (состояние и часы),
код ЗУП, часы ЗУП, признак расхождения (Казна работал, ЗУП нет; ЗУП работал, Казна Н или пусто).

**Параметры:** Период (быстрый), «Только трудоустроенные» (Ложь), «Показывать сотрудников
ЗУП без табеля Казны» (Истина).

- Отчёт: наборы «Свод» и «ПоДням»; варианты «Сводно по сотрудникам», «Контроль», «По дням»

  отметке Н/Б/О/С/В/Д против рабочего дня ЗУП.
- Признаки сравнения с ЗУП считаются только для связанных с ЗУП строк (Трудоустроен, есть
  данные ЗУП, актуален в ЗУП или есть дни М); «Нет ИНН» только у трудоустроенных или с днями М.
- Август 2026 по смоку: 285 строк Казны (287 записей, 2 дубля ИНН) плюс 131 человек ЗУП без
  табеля, итого 416; без флага Трудоустроен 4 (Бутко, Заєць, Мусійченко, Штиченко); Чешко:

- Файл `_Rarzrabotki/Отчеты/ОтчетПоДаннымТабелейКазныиБазыЗУП.erf`; подключение в Казне через

- Уточнение семантики (пользователь, 02.09.2026): `ЧасыОфициальные` = ВСЕ отработанные часы =
  ЧасыФакт + часы «М». Числовая ячейка пишет оба ресурса, «8м» только официальные. В отчёте
  сверки колонки «Дни/Часы официальные (Р+М)» рядом с «Р» и «М»; сравнение с ЗУП от официальных.
