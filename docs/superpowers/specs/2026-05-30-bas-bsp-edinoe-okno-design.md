**Дата:** 2026-05-30
**Статус:** на ревью
**Автор:** brainstorming (Claude) + Alex16111977
**Конфигурация:** BAS ERP 2.5, `C:\Configuration_downloads\BASERP25`

## 1. Контекст и проблема

Кастомные скилы (`bas-doc-new`, `bas-catalog-new`, `bas-register-new`, `bas-house-style`,
`bas-doc-fill`, `bas-verify`) создают объекты `А_*`, **структурно** похожие на типовые, но:

1. **Форма выходит без командного меню.** Пример: `А_ПередачаНачисленийМеждуПодразделениями`
   — у формы `AutoCommandBar` стоит `Autofill=false` **и при этом пуста** → платформа ничего
   не рисует. Нет «Провести и закрыть», «Создать на основании», «Печать», «Отчёты», «Заполнить»,
   «Ещё». Это половинчатая ручная панель — «заплатка».
2. **Объекты не интегрированы с подсистемами БСП**, которые есть у каждого типового объекта
   (Свойства, Версионирование, Подключаемые команды, Файлы, Контактная информация). Именно
   эта интеграция даёт «одинаковое окно интерфейса» и стандартное поведение.

**Корневой вывод:** «единое окно» типовых документов — следствие того, что каждый объект
реализует **один и тот же набор контрактов БСП**. Скилы должны вшивать эти контракты, а не
просто скаффолдить структуру.

## 2. Цель

Новый `А_*` объект **неотличим от типового** — окном И поведением — потому что интегрирует те же
подсистемы БСП тем же способом. Скилы строятся **на БСП именно этой конфигурации** (вербатим из
`РеализацияТоваровУслуг`, `Контрагенты`, `Номенклатура`), без выдумок и без внешних ssl-репозиториев.

## 3. Принципы

- **Грунт на реальный код.** Все шаблоны контрактов берутся дословно из типовых объектов этой
  конфигурации. Источник истины — живой код, не память и не внешние БСП.
- **Области видимости (#std551).** Звать у БСП **только `Программный интерфейс`** через общий
  модуль нужного контекста: серверный (`УправлениеСвойствами`), клиентский (`…Клиент`),
  клиент-серверный (`…КлиентСервер`). Никогда — `Служебный программный интерфейс`/«Служебные…».
  Иначе обновление БСП ломает доработку.
- **Делегирование (БСП-канон).** Тонкие модули объекта/менеджера/формы делегируют прикладную
  логику в `А_<Объект>Сервер`.
- **Только новое.** Скилы применяются к вновь создаваемым/изменяемым `А_*` объектам. Массового
  ретрофита существующих нет. Типовые объекты не трогаем (read-only эталон).

## 4. Зафиксированные решения (из брейншторма)

| # | Тема | Решение |
|---|------|---------|
| 1 | Топология модулей | Модуль на объект `А_<Объект>Сервер` (БСП-канон), `…Клиент`/`…КлиентСервер` по нужде |
| 2 | Охват | Только вперёд-идущее (новые объекты), без массового ретрофита |
| 3 | Проведение | Движения пишет типовой `ПроведениеДокументов`; вся бизнес-логика **и** запрос движений — в `А_<Объект>Сервер`, модуль менеджера = тонкий форвардер |
| 4 | Контракты БСП | Базовый набор «единое окно» (см. §6–7) |
| 5 | Командная панель | Автозаполнение (как рабочий `А_ОказаниеУслугМеждуПодразделениями`) + явные вызовы подсистем; пиксель-точный `Autofill=false` — опционально |

## 5. Архитектура: 2 новых скила + правки 5 существующих

### 5.1 Новый скил `bas-common-module` — организация кода (БСП-стиль)
Отвечает на «где живёт логика».
- Регионы **#455**: общий модуль — `ПрограммныйИнтерфейс` / `СлужебныйПрограммныйИнтерфейс` /
  `СлужебныеПроцедурыИФункции`; модуль объекта/менеджера — `ОписаниеПеременных` /
  `ПрограммныйИнтерфейс` / `ОбработчикиСобытий` / `СлужебныйПрограммныйИнтерфейс` /
  `СлужебныеПроцедурыИФункции` / `Инициализация`.
- Нейминг/флаги **#469**: суффиксы `Сервер`/`Клиент`/`КлиентСервер`/`ВызовСервера`; запрет
  `#Если Клиент`-сплита (разносить по модулям).
- Видимость **#std551**: наш экспорт для формы/менеджера/объекта — в `ПрограммныйИнтерфейс`.
- Делегирование: модуль объекта (`ОбработкаЗаполнения`/`ОбработкаПроверкиЗаполнения`/`ПередЗаписью`)
  и менеджер (`ДанныеДокументаДляПроведения`) → форвардят в `А_<Объект>Сервер`. Проведение пишет
  `ПроведениеДокументов` (типовой движок не трогаем).

### 5.2 Новый скил `bas-bsp-form` — контракты «единое окно»
Отвечает на «какие подсистемы БСП вшить и как». Содержит вербатим-шаблоны (§6–7) для документа и
справочника: вставки в форму (`ПриСозданииНаСервере` и парные обработчики), парные `Подключаемый_*`
методы, контракт-методы менеджера, предопределённые группы/реквизиты в XML. **Это закрывает баг
пустого меню.**

### 5.3 Правки существующих скилов
- `bas-house-style` — ссылки на оба новых скила; принцип видимости #std551; убрать
  опциональность `// <Документ>Локализация // если нужна`.
- `bas-doc-new` — обязательный шаг: создать `А_<Объект>Сервер` + вшить контракт «единое окно»
  документа (§6).
- `bas-catalog-new` — обязательный шаг: `А_<Объект>Сервер` + контракт «единое окно» справочника
  (§7), включая Контактную информацию и запрет редактирования реквизитов.
- `bas-register-new` — уточнить: запрос движений документа живёт в `А_<Объект>Сервер`
  (форвард из менеджера).
- `bas-verify` — новый пункт гейта (§10).

## 6. Контракт «единое окно» — ДОКУМЕНТ (вербатим: `РеализацияТоваровУслуг`)

Источник: `Documents\РеализацияТоваровУслуг\Forms\ФормаДокумента\Ext\Form\Module.bsl`,

### 6.1 Модуль формы — `ПриСозданииНаСервере` (порядок строго):
```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    // 1. Свойства (доп. реквизиты/сведения)
    ДополнительныеПараметры = Новый Структура;
    ДополнительныеПараметры.Вставить("Объект", Объект);
    ДополнительныеПараметры.Вставить("ИмяЭлементаДляРазмещения", "ГруппаДополнительныеРеквизиты");
    ДополнительныеПараметры.Вставить("ОтложеннаяИнициализация", Истина);
    УправлениеСвойствами.ПриСозданииНаСервере(ЭтаФорма, ДополнительныеПараметры);

    // 2. Версионирование (ТОЛЬКО здесь)
    ВерсионированиеОбъектов.ПриСозданииНаСервере(ЭтотОбъект);

    // 3. Подключаемые команды (Печать/Отчёты/Создать на основании/Заполнить)
    ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект);

    // 4. Диспетчер событий формы (локальный фреймворк конфигурации)
    СобытияФорм.ПриСозданииНаСервере(ЭтаФорма, Отказ, СтандартнаяОбработка);

    // 5. Работа с файлами (присоединённые файлы)
    ПараметрыГиперссылки = РаботаСФайлами.ГиперссылкаФайлов();
    ПараметрыГиперссылки.Размещение = "КоманднаяПанель";
    РаботаСФайлами.ПриСозданииНаСервере(ЭтотОбъект, ПараметрыГиперссылки);
КонецПроцедуры
```

## 8. Командная панель — стратегия

**Рекомендация (надёжно + «без заплаток»):** `AutoCommandBar` формы с **автозаполнением**
(как рабочий `А_ОказаниеУслугМеждуПодразделениями`: `<AutoCommandBar .../>` без `Autofill=false`)
**плюс** явные вызовы подсистем из §6/§7. Это исключает баг «`Autofill=false` + пустая панель» и
даёт полное меню. Пиксель-точный вариант «как `РеализацияТоваровУслуг`» (`Autofill=false` +
кнопки вручную + контейнеры подменю) — **опциональный** режим скила для случаев, где нужен точный
порядок/иконки/единая кнопка «Провести и закрыть».

**Антипаттерн (запрещено):** `Autofill=false` без ручных кнопок (текущий баг).

## 9. Немедленный фикс как proof (`А_ПередачаНачисленийМеждуПодразделениями`)

Первое применение `bas-bsp-form` — чинит реальный объект и служит приёмочным тестом:
1. `Form.xml`: убрать `<Autofill>false</Autofill>` у `AutoCommandBar id="-1"` (→ автозаполнение);
   удалить лишний дубль `CommandBar id="1"` из `ChildItems`.
2. `Module.bsl` формы: вшить контракт документа §6 (вызовы подсистем + обработчики).
3. Менеджер: добавить `ПриОпределенииНастроекВерсионированияОбъектов`.
4. Проверить через `bas-verify`: меню не пустое, контракты на месте.

## 10. Верификация (`bas-verify` — новый пункт гейта)

- [ ] Командная панель не пустая (нет связки `Autofill=false` + пустой `AutoCommandBar`).
- [ ] Вшиты контракты §6 (документ) / §7 (справочник): вызовы в `ПриСозданииНаСервере` + парные
      обработчики жизненного цикла + `Подключаемый_*` методы.
- [ ] Регионы #455 и нейминг/флаги #469 у `А_<Объект>Сервер` и тонких модулей.
- [ ] Видимость #std551: вызовы БСП только из `Программного интерфейса`, модуль контекста верный
      (`Клиент`/`Сервер`/`КлиентСервер`).
- [ ] Менеджер: контракт-методы (`ПриОпределенииНастроекВерсионированияОбъектов`, при нужде
      `ПолучитьБлокируемыеРеквизитыОбъекта`).
- [ ] Запросы прогнаны Python COM (Rule #-1); `meta-validate`/`form-validate`; `1c-bsl-review`.
- [ ] Проверка свежим агентом: «создай документ X в типовом стиле» → меню и поведение как у типового.
- [ ] Файлы скопированы в основную конфигурацию; загрузка `db-load-xml`+`db-update`.

## 11. Вне scope

- Управление доступом / блокировки как обязательный контракт (отдельный этап; `УправлениеДоступом`
  через определяемые типы + подписки — большой объём).
- Массовый ретрофит существующих `А_*` объектов.
- Любые правки типовых объектов и типовых регистров.
