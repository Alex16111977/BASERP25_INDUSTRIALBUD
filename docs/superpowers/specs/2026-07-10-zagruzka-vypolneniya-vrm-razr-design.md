# Дизайн: режим «Загрузка выполнения» в обработке «Загрузка А_ВыполнениеРаботМодулей»

Дата: 2026-07-10. Статус: одобрено пользователем (чат). Попутный фикс формы списка документа — ОТКЛОНЁН пользователем (не делаем).

## Цель

В чистой базе `BaseERPRazr` нет ни одного документа `А_ВыполнениеРаботМодулей`. Обработка
(`_Rarzrabotki/А_ПланФактныйПроизводствоПолный/По часам/Загрузка А_ВыполнениеРаботМодулей`)
должна из Excel `Копия ЗВіт_виконання_ВООЗ_ЕМС_Зачепилівка.xlsx` создать и провести те же
3 снимка выполнения, что в BaseERP: 19.06 / 26.06 / 03.07 2026, 9:00, по СС
«МД Вооз ЕМS Мала 2026 / Цех_МД Вооз ЕМS Мала 2026». Существующий режим загрузки работ в СС — не трогать.

## Ключевые проверенные факты

- `ТабличныйДокумент.Прочитать(xlsx)` на 8.3.20 читает ТОЛЬКО первый лист книги
  (проверено COM-тестом: прочитался «Зразок», 144 строки; лист выбрать нельзя).
  → серверное чтение отпадает; чтение — COM Excel на клиенте (fallback, разрешён промтом задачи).
- Исходники обработки — недоделанный untracked-клон: XML объявляет `ИмяФайла` + `Подразделение`
  (СтруктураПредприятия), имя `ВнешняяОбработка1`, а модуль формы ссылается на
  `Объект.ДокСтруктураСебестоимости`. Приводим к консистентному виду.
- Эталон парсера текста факта и всей цепочки — `_Rarzrabotki/Python/test/test_vrm_e2e.py`
  (функции `парс_проценты`, `норм`; get-or-create; EV).
- В BaseERPRazr: СС ВООЗ есть (44 строки ТЧ Работы), группа `_Роботи` 0Ц-00000016 есть,
  документов 0, `СС.А_КоличествоМодулей = 0` (нужно 8 до создания документов).

## Архитектура (подход A — одобрен)

Клиент читает Excel через COM `Excel.Application` (как боевой режим 1) и передаёт на сервер
«сырые» данные; весь интеллект — на сервере в модуле объекта (тестируется smoke-ом через COM
без клиентского контекста).

```
Клиент (форма)                        Сервер (модуль объекта)
──────────────                        ────────────────────────
ПрочитатьЛистыВыполнения(файл)   →    ПроанализироватьЛисты(Параметры)      [предпросмотр]
  все листы «ЗВіт (dd.mm)»:      →    ЗагрузитьВыполнениеИзДанных(Параметры) [загрузка]
  A=наименование, G=текст факта         ├─ РазобратьДатуЛиста(Имя, Год, Время)   (экспорт)
                                        ├─ РазобратьПроцентыФакта(Текст, N)      (экспорт)
                                        ├─ кэш работ СС, get-or-create, ТЧ, проведение
                                        └─ протокол
```

## 1. Объект обработки (XML)

- Имя `ВнешняяОбработка1` → `ЗагрузкаА_ВыполнениеРаботМодулей` (Name, Synonym, DefaultForm,
  GeneratedType, тип основного реквизита в Form.xml).
- Реквизит `Подразделение` (мёртвый) — удалить.
- Реквизиты: `ИмяФайла` (строка, есть), `ДокСтруктураСебестоимости`
  (СправочникСсылка.А_СтруктураСебестоимости), `Год` (Число 4), `ВремяДокумента` (Дата, время),
  `Проводить` (Булево), `КоличествоМодулейПоУмолчанию` (Число 2).
- Дефолты (2026, 09:00, Истина, 8) — в `ПриСозданииНаСервере` формы (у внешних обработок
  нет значений по умолчанию в XML).

## 2. Форма

- Общие поля: `ИмяФайла` + кнопка выбора файла (асинхронно: `ПоказатьВыборФайла` с
  `ОписаниеОповещения`), `ДокСтруктураСебестоимости`.
- Страницы:
  - «Загрузка работ в СС» — существующая кнопка `ЗагрузитьРаботы`, поведение не меняется;
  - «Загрузка выполнения» — Год, ВремяДокумента, Проводить, КоличествоМодулейПоУмолчанию,
    таблица предпросмотра `ЛистыФайла` (Лист, Дата, СтрокВсего, Сопоставлено),
    кнопки «Прочитать файл» (только анализ) и «Загрузить выполнение» (перечитывает файл
    заново и грузит; от предпросмотра не зависит).
- Клиентское чтение: перебор `Workbook.Sheets`, берём листы с именем `ЗВіт (dd.mm)`;
  по строкам с 2-й: A (наименование; пропуск пустых, «Загальна…», «табель»), G (текст факта).
  Гарантированный `Excel.Quit()` в Исключении (паттерн боевого режима).

## 3. Движок в модуле объекта (новый регион; `ЗагрузитьРаботыИзМассива` не трогаем)

`ЗагрузитьВыполнениеИзДанных(Параметры)` Экспорт, Параметры — структура:
`{СтруктураСеб, Листы: Массив {ИмяЛиста, Строки: Массив {Наименование, ТекстФакта}}, Год,
Время, Проводить, КоличествоМодулейПоУмолчанию}`. Возврат-протокол:
`{Ошибка, ТекстОшибки, Сообщения: Массив, Документы: Массив {Лист, Дата, Ссылка, Строк, ЕВ, Действие}}`.

Шаги:
1. Валидация СС.
2. `СС.А_КоличествоМодулей = 0` → установить `КоличествоМодулейПоУмолчанию` (8), записать СС,
   строка в протокол. N модулей далее — из СС (после фикса).
3. Кэш работ СС: запрос `СУММА(Количество) КАК План, МАКСИМУМ(Этап)` СГРУППИРОВАТЬ ПО Работа;
   ключ = `НормКлючРаботы(Наименование)`.
4. Разбор дат листов (`РазобратьДатуЛиста`), листы без даты — пропуск с сообщением;
   сортировка по возрастанию даты.
5. Одна транзакция на пакет; для каждого листа по порядку:
   - get-or-create: поиск документа по СС + Дата МЕЖДУ НачалоДня И КонецДня
     (устойчиво к смене параметра времени); Дата всегда выставляется из параметров;
   - шапка: Организация (первая непомеченная по наименованию — в базе одна собственная),
     СтруктураСебестоимости, Подразделение (из СС), КоличествоМодулей = N, Комментарий;
   - ТЧ `Работы`: полная перезапись; для каждой работы СС, найденной в листе, — N строк
     (НомерМодуля 1..N, включая нули): `ПланЧасыМодуля = План/N`, `Процент`,
     `ЧасыВыполнение = ПланЧасыМодуля × Процент/100`; нераспознанный текст факта → нули;
     работа листа, не найденная в СС, → сообщение протокола, пропуск (работы НЕ создаём);
   - `Записать(Проведение | Запись)` по флагу Проводить.
6. Протокол: лист → документ (номер, дата), строк ТЧ, EV (Σ ЧасыВыполнение).

`ПроанализироватьЛисты(Параметры)` Экспорт — те же разбор и сопоставление без записи,
возврат данных для таблицы предпросмотра.

### Нормализация имён работ

`НормКлючРаботы` = НРег(СокрЛП + схлоп пробелов + удалить апострофы `'` и `’`) — эталон `норм()`
из test_vrm_e2e.py. ОТДЕЛЬНАЯ функция: старый режим использует `НормализоватьНаименование`
без удаления апострофов — его поведение не меняем.

### Парсер текста факта (`РазобратьПроцентыФакта(Текст, N)` Экспорт)

BSL без regex, эквивалент `парс_проценты`:
- сегменты «K модул* --P%» (разделители `;`, пробелы; дефисов 0..n; P — целое/дробное с `.`/`,`)
  заполняют модули последовательно М1..М_N, хвост — нули, излишек — усечение;
- одиночное «P%» без числа модулей → все N модулей = P (в т.ч. «0%» → нули);
- нераспознанное («в роботі», «не ставляться», пусто) → Неопределено (вызывающий пишет нули).
Гарантия корректности: сверка BSL↔Python по ВСЕМ значениям G всех листов файла в smoke.

## 4. Проверка запросов (Rule #-1)

Каждый запрос 1С — сначала Python COM на BaseERPRazr, потом в BSL: работы СС (группировка),
поиск документа по СС+интервалу дня, первая организация.

## 5. Сборка и приёмка

- `epf-build` против BaseERP (метаданные одинаковы; Конфигуратор закрыт).
- Smoke `_Rarzrabotki/Python/test/test_zagruzka_vrm_razr.py` на BaseERPRazr,
  `ВнешниеОбработки.Создать(epf)`:
  1) сверка парсера BSL↔Python по всем G;
  2) прогон `ЗагрузитьВыполнениеИзДанных` (сырые данные из openpyxl) →
     3 проведённых документа 19.06/26.06/03.07 2026 9:00;
  3) обороты РН `А_ВыполнениеРаботМодулей` накопительно к датам снимков =
     **501.78 / 1616.59 / 2401.53** (допуск 0.2, как в эталонном e2e);
  4) `СС.А_КоличествоМодулей = 8`;
  5) повторный прогон: обороты и число документов не изменились (идемпотентность).
- Данные BaseERP не менять; документы в тестах не удалять (get-or-create).

## 6. Git

Исходники обработки — основной каталог (Rule #4 автоматически). Коммит + push,
схема cherry-pick на origin/main (локальный main непушабелен — память проекта).

## Ограничения (осознанные)

- Листы «Зразок» и текущий «ЗВіт» (без даты в имени) не грузятся.
- Год один на файл (параметр); переход года внутри файла не поддерживается.
- Физическое чтение xlsx (клиентский COM Excel) не покрыто smoke — паттерн уже боевой в режиме 1;
  smoke кормит движок теми же сырыми данными через openpyxl.
- Работы СС, отсутствующие в листе, в документ не пишутся (как в эталоне); если у них был
  ненулевой % ранее — модуль документа сам предупредит при проведении.
- Смена параметра «Время» при повторном запуске обновит те же документы (поиск по дню)
  и передвинет их время.
