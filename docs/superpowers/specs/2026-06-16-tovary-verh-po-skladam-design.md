# Дизайн: верхняя таблица «по складам» (2 уровня) — СинхронизироватьТоварыТолькоТовары

Дата: 2026-06-16
Статус: согласован пользователем (вариант «2 уровня: Склади → Документи»)
Scope: **только эта правка**. Ночной авто-режим — Фаза 2, отдельной спецификацией ПОТОМ (вне текущего объёма).

## Проблема
Верхняя таблица показывает 922 позиции (Номенклатура×Склад) — невозможно анализировать. Итоги в подвале (сумма количеств разной номенклатуры) бессмысленны. За данными стоит ~83 склада — по складам обзор реален.

## Решение (2 уровня)
Верх = свод по складам (десятки строк, счётчики). Низ = документы (как сейчас, с колонкой Номенклатура). Позиции Ном×Склад остаются ВНУТРИ (движок анализа по ним), на форме не показываются.

## Изменения

### Дескриптор — новая ТЧ `ТаблицаСкладов`
Колонки: `Склад` (String+AnyRef, 250), `СкладКлюч` (String 36 — А_ИдКод склада для группировки/анализа), `Позицій` (Number 10), `СуммаРазницы` (Number 15,3 — Σ|Разница|), `Документів` (Number 10), `Дій` (Number 10), `ПотребуютьРішення` (Number 10), `Синхронизировать` (Boolean). Новый GeneratedType (TypeId/ValueId/Row) со свежими GUID.

### ObjectModule
- `СравнитьОстатки`: после `СравнитьОстатки_Товары` → `ЗаполнитьСводПоСкладам()`.
- Новая `ЗаполнитьСводПоСкладам()`: очистить `ТаблицаСкладов`; сгруппировать `ТаблицаРасхождений` по `Измерение2Ссылка` (СкладКлюч); на склад: `Склад`=Измерение2, `Позицій`=count, `СуммаРазницы`=Σ|Разница|, `Синхронизировать`=Истина, счётчики анализа=0.
- `АнализироватьДокументы(ИндексСклада = -1)`: теперь по складам. `>=0` — один склад `ТаблицаСкладов[ИндексСклада]`; иначе — все склады с `Синхронизировать`. Очистить `ТаблицаДокументов` и обнулить счётчики всех складов. Для каждого целевого склада: снять snapshot `ТаблицаДокументов.Количество()`, прогнать `АнализДокументов_Товары` по всем позициям `ТаблицаРасхождений` с этим `СкладКлюч`, затем по добавленным строкам посчитать `Документів`/`Дій`(ЕстьРасхождение И Действие заполнено)/`ПотребуютьРішення`(ЕстьРасхождение И Действие пусто) для строки склада. Признак `ЕстьРасхождение` ставится как сейчас.
- Фаза 3 (`ВыполнитьСинхронизацию`/`ВыполнитьСинхронизациюСтроки`/sync-процедуры) — БЕЗ изменений (работает по `ТаблицаДокументов`).
- `ТаблицаРасхождений` остаётся (внутренняя, не на форме).

### Форма
- Верхняя таблица: rebind `Объект.ТаблицаРасхождений` → `Объект.ТаблицаСкладов`. Колонки: Синхронизировать, Склад, Позицій, СуммаРазницы, Документів, Дій, ПотребуютьРішення. Footer — счётчики (складів/позицій), не суммы количеств.
- События верхней: `ТаблицаСкладовФормаПриАктивизацииСтроки`→фильтр низа, `ТаблицаСкладовФормаВыбор`→открыть Склад.
- Нижняя таблица (`ТаблицаДокументов`) — без изменений.
- Модуль: все операции верхней таблицы (ВыбратьВсе/Снять/Инвертировать/УстановитьГалочки/проверки «есть отмеченные») → по `ТаблицаСкладов`; `АнализТекущегоСчета`→индекс строки склада; `СформироватьНаСервере` сохраняет галки по `СкладКлюч`; `ПрименитьФильтрДокументов` фильтрует низ по `Измерение2` = Склад текущей строки; `ОбновитьРезюмеИЗаголовки`/`НастроитьУсловноеОформление` — по `ТаблицаСкладовФорма` (серый для снятой галки).
- Команды/кнопки те же, «Аналіз поточної позиції»→«Аналіз поточного складу».

## Что НЕ делаем
- Ночной авто-режим (Фаза 2) — вне scope.
- Позиции Ном×Склад на форме не показываем (счётчик `ПотребуютьРішення` — сигнал разбираться вручную).
- Типовые объекты не трогаем.
