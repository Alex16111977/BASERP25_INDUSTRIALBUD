# РаспределениеФ2 — построчные флаги расхождения + разделение общего флага на 2 измерения

> Дата: 2026-06-21. Расширение фичи контрольных сумм
> (см. `2026-06-21-raspredeleniyef2-kontrolnye-summy-design.md`).

---

## 1. Что добавляем (4 реквизита Булево, уже созданы в конфигурации)

| Реквизит | Где | Синоним | Смысл |
|---|---|---|---|
| `А_РасхождениеРаспределение` | ТЧ `Сотрудники` | «Расхождение (казна)» | у сотрудника этой строки `Начислено ≠ Распределение` |
| `А_РасхождениеДДС` | ТЧ `Сотрудники` | «Расхождение (ДДС)» | у сотрудника этой строки `Начислено ≠ ДДС` (когда ДДС построен) |
| `А_Расхождение` | шапка | «Расхождение общее распределение» | есть сотрудник с расхождением по распределению |
| `А_РасхождениеОбщееДДС` | шапка | «Расхождение общее ДДС» | есть сотрудник с расхождением по ДДС |

## 2. Изменение семантики `А_Расхождение`

Раньше единый `А_Расхождение` = «любое расхождение (распр **или** ддс)». Теперь по синониму он
**сужается до распределения**, а ДДС выносится в отдельный `А_РасхождениеОбщееДДС`. Единый флаг
**расщепляется на два измерения**. Пример: №082 (битые ссылки → расходится только ДДС) теперь даёт
`А_Расхождение = Ложь`, `А_РасхождениеОбщееДДС = Истина` (раньше единый флаг был Истина).

## 3. Алгоритм (расширение `_ЗаполнитьКонтрольныеСуммы`)

Карты `КартаНачислено / КартаРаспределение / КартаДДС` (Σ по сотруднику, пустой Сотрудник исключён) —
уже есть. Ключ — ссылка `Сотрудник` (ИНН/Код/СотрудникКазна пусты в 100% строк, fallback невозможен).

- **Построчно** (обход `Сотрудники`): для строки с заполненным сотрудником
  `А_РасхождениеРаспределение = Окр(ИтогНач − ИтогРаспр, 2) <> 0`,
  `А_РасхождениеДДС = ЕстьДвиженияДДС И Окр(ИтогНач − ИтогДДС, 2) <> 0`,
  где `ИтогНач/Распр/ДДС` — **агрегаты сотрудника**, а не строки. Пустая строка → оба `Ложь`.
- **Шапка** (обход объединения ключей трёх ТЧ): `А_Расхождение` = есть сотрудник с распр-расхождением;
  `А_РасхождениеОбщееДДС` = (`ЕстьДвиженияДДС` и есть сотрудник с ддс-расхождением).
- Колонки `СуммаПоРаспределение/СуммаПоДДС` — без изменений (итог в первой строке сотрудника).

## 4. Построчный флаг — по агрегату сотрудника, а не «голой» строки

Сравниваем агрегат сотрудника, потому что источники (Распределение/ДДС) агрегируются по сотруднику.
В 99% (одна строка на сотрудника) это совпадает с построчной сверкой; для дублей строк по одному
сотруднику — корректнее (сводящийся дубль НЕ даёт ложного флага). Одобрено пользователем.

## 5. Ограничение (orphan)

Если сотрудник есть в `Распределение`/`А_ДвижениеДДС`, но **нет строки** в `Сотрудники` (orphan —
напр. №043/018), флагнуть построчно негде → виден только в **шапке** (общий флаг). By-design:
строки в `Сотрудники` не добавляем.

## 6. Приёмка (Python COM регрессия)

Расширяем `regress_raspredeleniyef2_kontrol.py`: по всем 75 докам сверяем построчные флаги
(`А_РасхождениеРаспределение/ДДС`) и оба общих флага шапки (`А_Расхождение`,
`А_РасхождениеОбщееДДС`) + колонки с моделью. Цель: 75/75 PASS. Распределение общих флагов считаем.
