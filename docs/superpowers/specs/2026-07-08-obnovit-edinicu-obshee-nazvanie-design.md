# Дизайн: доработка обработки «Обновить единицу в общем названии» (BuhBud)

- **Дата:** 2026-07-08
- **База:** BuhBud (`Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`)
- **Файлы:** `_Rarzrabotki\Загрузка СС\Обновить единицу в общем названии.xml` (+ каталог)
- **Исходная версия:** написана пользователем 2026-07-08 (обход строк ТЧ с разыменованием,
  источник — только ТЧ.Единица, без защиты от конфликтов, last-write-wins)

## 1. Задача

Заполнить реквизит **`Единица`** справочника `ОбщиеНазванияНоменклатуры` (345 карточек,
заполнена 1) — чтобы «Загрузка материалов в СС» подтягивала Единицу в ТЧ Комплектующие.

## 2. Политика заполнения (решение пользователя-бухгалтера)

Только для карточек с ПУСТОЙ Единицей (заполненные не перезаписывать). Каскад:

**Приоритет 1 — ТЧ активных структур себестоимости** (`СтруктураСебестоимости.Активная`,
строки с заполненными ОбщееНазвание и Единица; заполнялись вручную по СС из Excel):
- значение = **наиболее частая единица по строкам** (мода);
- ничья голосов → НЕ заполнять, в протокол «конфликт»;
- все конфликтные названия (факт: 25 из 177, напр. «Пінопласт» — 3 единицы) — в протокол
  с выбранным значением и раскладом голосов.

**Приоритет 2 — привязанная номенклатура** (для карточек, оставшихся пустыми после П1):
- номенклатуры с реквизитом `ОбщееНазваниеНоменклатуры` = карточка (факт: 279 карточек
  имеют привязку, у 185 — несколько номенклатур);
- из них выбрать **самую закупаемую**: `СУММА(Количество)` по проведённым
  `Документ.ПоступлениеТоваровУслуг.Товары` за всё время; ничья → большая `СУММА(Сумма)`;
- значение = `БазоваяЕдиницаИзмерения` номенклатуры-лидера;
- **П2б fallback**: закупок нет ни по одной привязанной → если привязана РОВНО ОДНА
  номенклатура с непустой базовой единицей — взять её; если несколько — пропуск + протокол.

Ожидаемое покрытие: ~176 (П1) + ~103 (П2) из 344 пустых; остаток — протоколом.

## 3. Архитектура (переработка)

### ObjectModule.bsl — `ОбновитьВОбщемНазванииЕдиницу()` Экспорт
- Возвращает структуру-протокол `{ИзСтруктур, ИзНоменклатуры, Конфликтов, ОсталосьПустых,
  СписокКонфликтов (массив строк), СписокПустых (массив строк), Ошибка, ТекстОшибки}`.
- **Без разыменований в цикле** — два пакетных запроса (Rule #-1: каждый тестируется
  Python COM 1:1 до BSL):
  - П1: группировка `ОбщееНазвание × Единица` с `КОЛИЧЕСТВО(*) КАК Голосов` по строкам
    активных структур, `ИТОГИ ПО ОбщееНазвание`, порядок `Голосов УБЫВ`; отбор — только
    карточки с пустой Единицей. Обход по группировкам: первая строка = мода; вторая с теми
    же голосами = ничья.
  - П2 (выполняется ПОСЛЕ записи П1, повторный отбор «Единица пустая» сам исключает
    заполненные): группировка приходов по `ОбщееНазваниеНоменклатуры × Номенклатура`
    с `СУММА(Количество)`, `СУММА(Сумма)`, `ИТОГИ ПО`; порядок `Куплено УБЫВ, Сумма УБЫВ`.
  - П2б: запрос привязанных номенклатур без учёта закупок для карточек, не попавших в П2.
- Запись карточек: транзакция на весь прогон, `Попытка/Исключение` → откат + протокол +
  `ЗаписьЖурналаРегистрации`.
- Идемпотентность: повторный запуск заполняет 0 (все отборы «Единица пустая»).

### Форма
- Кнопка та же; `ВывестиПротокол` — счётчики + списки конфликтов/пустых (`Сообщить`).

### XML
- Корневой: `Name` `ВнешняяОбработка1` → `ОбновитьЕдиницуВОбщемНазвании` (синхронно:
  GeneratedType, DefaultForm, тип главного реквизита в Form.xml), синоним
  «Обновить единицу в общем названии»; **удалить** неиспользуемый реквизит
  `СпрСтруктураСебестоимости` (+ его InputField из Form.xml, если есть).
- GUID у обработки уже уникальные (создана в Designer) — не трогать.
