# Расшифровка статей «Расходы/Доходы текущего периода» через `СтатьяДоходыРасходы` — Design v2

**Дата:** 2026-05-26 (v1 → v2 после обратной связи пользователя)
**Документ:** `Документ.А_ФинРез_Баланс` → `РегистрСведений.А_ОтчетБаланс_Свод`
**Функции:** `Свод_ПрочиеРасходыДоходы` и `Свод_ПрочиеАктивыПассивы_Прямой` в `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl`
**Контекст:** Канон v2 modular redesign (см. [balanse_pattern_and_roadmap.md](../../_Rarzrabotki/notebook/knowledge_Balanse/balanse_pattern_and_roadmap.md))

## История

**v1 (отклонён):** Расшифровка через JOIN ПАП ⨝ `РегНакопл.ДвиженияДоходыРасходыПрочиеАктивыПассивы` (Turnovers) per (Регистратор, Период, Подр). Проблема: писал в РС много строк per Источник с ненулевыми накопленными signed Σ для НО/КО — много "плугов" с НО ≠ 0, бухгалтерски нелогично.

**v2 (принят):** Расшифровка через **специализированные расшифровывающие регистры** `РегНакопл.ПрочиеРасходы` и `РегНакопл.ПрочиеДоходы` (оба Balance, `.ОстаткиИОбороты(&НачМес, &КонМес)`) с фильтром `НО ≠ 0 ИЛИ КО ≠ 0`. Записываем только реально не закрытые на 01.04 или 30.04 строки.

## 1. Бухгалтерская логика (по объяснению пользователя)

**Регистры:**
- `РегНакопл.ПрочиеАктивыПассивы` (ПАП) — **первичный** регистр баланса. Содержит итог: «Расходы текущего периода» (Актив) и «Доходы текущего периода» (Пассив) в разрезе (Орг, Подр).
- `РегНакопл.ПрочиеРасходы` (Balance) — **расшифровывает первичный регистр** для статьи «Расходы текущего периода». Измерение `СтатьяРасходов` (ПВХ.СтатьиРасходов) — реальная статья затрат («Зарплата ИТР», «Будівельні матеріали», «Затраты на служебные командировки» и т.п.).
- `РегНакопл.ПрочиеДоходы` (Balance) — **расшифровывает первичный регистр** для статьи «Доходы текущего периода». Измерение `СтатьяДоходов` (ПВХ.СтатьиДоходов) — реальная статья доходов.

**Правило отбора (бухгалтерское):**
Из расшифровывающего регистра берём `.ОстаткиИОбороты(&НачМес, &КонМес)` per (Орг, Подр, СтатьяРасходов/СтатьяДоходов). Записываем в свод **только** те строки, у которых:
- НачальныйОстаток ≠ 0 (статья переходит с прошлого месяца — была "висеть" на 01.04), **ИЛИ**
- КонечныйОстаток ≠ 0 (статья остаётся незакрытой на 30.04).

Если **И НО = 0 И КО = 0** — строку не пишем (даже если в течение месяца Приход = Расход — она "прошла насквозь", в балансе её нет ни на начало ни на конец).

**Эталон апрель 2026 / Глобино-2:**
- Расшифровка регистра `ПрочиеРасходы` показывает 50+ строк где обороты были (Приход = Расход = 0 КО), и **ОДНУ** строку с НО=0 / Приход=2 400 / Расход=0 / КО=**2 400** — «Затраты на служебные командировки и содержание аппарата управления предприятием».
- В свод по (Глобино-2, Расходы текущего периода) пишется **только одна** эта строка.
- По (Глобино-2, Доходы текущего периода) в `ПрочиеДоходы` ни одной строки с НО ≠ 0 или КО ≠ 0 → в свод ничего не пишется.

## 2. Поля записи в РС `А_ОтчетБаланс_Свод`

Для каждой записи расшифровки:

| Поле | Значение |
|---|---|
| `Статья` | балансовая статья (Расх.тек.пер. или Дох.тек.пер., ПВХ.СтатьиАктивовПассивов) |
| `СтатьяДоходыРасходы` | реальная статья (ПВХ.СтатьиРасходов или СтатьиДоходов — измерение РС с составным типом) |
| `Аналитика1` | `ПРЕДСТАВЛЕНИЕ(СтатьяДоходыРасходы)` |
| `СуммаНачальныйОстаток` | НО из регистра расшифровки на &НачМес |
| `СуммаКонечныйОстаток` | КО из регистра расшифровки на &КонМес |
| `СуммаПриход` | 0 (канон §2 — только остатки) |
| `СуммаРасход` | 0 |
| `Source` | `ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ПустаяСсылка)` — Source не разрезается (как в УпрБалансе) |
| `Расхождение` | Ложь |
| `Организация`, `Подразделение` | из регистра расшифровки |
| `ТипПоказателя` | заполнится в оркестраторе (Актив для Расх.тек.пер., Пассив для Дох.тек.пер.) |
| прочие субконто (ОбъектыЭксплуатации, НМА, ТипНалога, и т.п.) | ПустаяСсылка |

## 3. Контрольный инвариант (Σ деталей == ПАП)

Для каждого ключа (Орг, Подр, Статья=РасхТекПер) на конец периода:
- **Σ КО деталей расшифровки** (запись в РС от `Свод_ПрочиеРасходыДоходы` ветвь A) = **ПАП.ОстаткиИОбороты.КО** для (Орг, Подр, Расх.тек.пер., все Источники)
- **Σ НО деталей** = **ПАП.ОстаткиИОбороты.НО** для (Орг, Подр, Расх.тек.пер., все Источники)

Это означает что регистр `ПрочиеРасходы.ОстаткиИОбороты` per (Орг, Подр) полностью покрывает ПАП для статьи «Расх.тек.пер.» (по архитектуре системы — оба обновляются одним документом-регистратором). Если есть расхождение — оно компенсируется плугом (Расхождение=Истина) с пустой СтатьяДоходыРасходы.

Аналогично для пары `ПрочиеДоходы` ↔ ПАП для статьи «Дох.тек.пер.».

## 4. Архитектурные изменения

### 4.1 `Свод_ПрочиеАктивыПассивы_Прямой` — добавить исключение

Текущий фильтр (`Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl` ~line 1100-1105):
```bsl
И Т.Источник = ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ПустаяСсылка)
И НЕ Т.Статья В ИЕРАРХИИ(&Искл)
И Т.Статья <> &ОТ
```

Новый:
```bsl
И Т.Источник = ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ПустаяСсылка)
И НЕ Т.Статья В ИЕРАРХИИ(&Искл)
И Т.Статья <> &ОТ
И Т.Статья <> &РасхТекПер
И Т.Статья <> &ДохТекПер
```

Эти статьи теперь обрабатывает только `Свод_ПрочиеРасходыДоходы`.

### 4.2 `Свод_ПрочиеРасходыДоходы` — переработать

**Ветвь A для статьи «Расходы текущего периода»:**
```sql
ВЫБРАТЬ
    ПР.Организация,
    ЕСТЬNULL(ПР.Подразделение, ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)) КАК Подразделение,
    &РасхТекПер КАК Статья,
    ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ПустаяСсылка) КАК Source,
    ПР.СтатьяРасходов КАК СтатьяДоходыРасходы,
    СУММА(ПР.СуммаНачальныйОстаток) КАК СуммаНачальныйОстаток,
    СУММА(ПР.СуммаКонечныйОстаток) КАК СуммаКонечныйОстаток
ИЗ РегистрНакопления.ПрочиеРасходы.ОстаткиИОбороты(&НачМес, &КонМес, Авто, ,
    Организация = &Орг) КАК ПР
СГРУППИРОВАТЬ ПО ПР.Организация, ПР.Подразделение, ПР.СтатьяРасходов
ИМЕЮЩИЕ
    СУММА(ПР.СуммаНачальныйОстаток) <> 0
    ИЛИ СУММА(ПР.СуммаКонечныйОстаток) <> 0
```

**Ветвь B для статьи «Доходы текущего периода»:**
Симметрично через `РегистрНакопления.ПрочиеДоходы.ОстаткиИОбороты` + `СтатьяДоходов`.

**Ветвь C для остальных статей источника {ПрочиеДоходы, ПрочиеРасходы, ПартииПрочихРасходов}:**
Сохраняем существующую логику через основную таблицу `РегНакопл.ПрочиеАктивыПассивы` с фильтром `Источник В (&Ист)` и `Статья <> &РасхТекПер И Статья <> &ДохТекПер`. Это ветвь B из v1 — статьи "Прочие пассивы", "Прибыли и убытки", и др. По-прежнему через ВЫРАЗИТЬ(ПАП.Аналитика).
