# Товары счетов Казны и оплата в отчёте «Прогноз виконання СС за потребою» — дизайн

**Дата:** 2026-10-15
**База:** BaseERP (`Srvr="localhost";Ref="BaseERP"`), источник счетов — Казна (`Srvr="localhost";Ref="kazna"`, = SQLSERVER)
**Отчёт:** `Отчет.А_ПрогнозВиконанняССЗаПотребою` (база знаний `_Rarzrabotki/notebook/knowledge_А_ПотребаЗавершенняПроекту/`)
**Подразделения:** «МД IRC 2026» (вместе с дочерними «15 м» и «30 м») и «МД ООН Админ»; период — 2026 год

## 1. Цель

Показать в отчёте, какие товары оплачены, а какие нет:
1. **«Оплачено, не надійшло»** — по позициям списка директора: товар оплачен по счёту, поступления ещё нет.
2. **«Оплачено» / «Борг»** — по закупленным товарам (строкам поступлений).

Колонки **только информационные**: прогноз и экономия считаются как раньше (решение пользователя 15.10.2026).

## 2. Как сейчас передаются счета (исследование 15.10.2026)

```
Казна: СчетНаОплатуПоставщика — товаров НЕТ (ТЧ: Визы, ТекущиеВизирующие, ПредварительныеВизы, СчетаОснования);
       скан счёта — Справочник.Файлы (ВладелецФайла = счёт)
   ↓ обмен Казна→ЕРП (правила живут в базе, РС ПравилаДляОбменаДанными)
ЕРП: ЗаявкаНаРасходованиеДенежныхСредств — А_НомерСчетаПоДаннымПоставщикаКазна, А_ДатаПоДаннымПоставщикаКазна;
     РасшифровкаПлатежа.ОбъектРасчетов.Объект = ЗаказПоставщику
ЕРП: ЗаказПоставщику — приходит из BuhBud (шапка); казначейское ПКО «ЗаказПоставщику» только догружает визы
     (НеСоздаватьЕслиНеНайден), ТЧ «Товары» в правиле нет
ЕРП: СписаниеБезналичныхДС.РасшифровкаПлатежа — ЗаявкаНаРасходование, ОбъектРасчетов, А_ЗаказПоставщику
ЕРП: ПриобретениеТоваровУслуг.ЗаказПоставщику — у 335 из 361 поступлений
```

Цифры по двум подразделениям:

| Документ | Количество | Что важно |
|---|---|---|
| Счета Казны | 435 на 15,8 млн | сканы у 352 счетов (555 файлов: pdf 262, xls 145, jpg 56, xlsx 42, doc 23, docx 16, png 9, rtf 2) |
| Заявки ЕРП | 353 | оплачены полностью 326, не проведены 27 |
| Заказы ЕРП | 362 | «Товары» пусты у 317 (сумма 0); у 45 заполнены и стоит `А_Необновлять` |

**Вывод.** Товары счёта можно взять только из скана. Оплата идёт по заказу целиком, строки в платеже не детализируются.

## 3. Хранение — регистр сведений `А_ТоварыСчетовПоставщиков` (подход C)

Почему не ТЧ «Товары» заказа:
- заказ проведён; заполнение «Товаров» меняет сумму заказа и расчёты «к оплате», а через них — баланс и РМ визирования;
- строка без номенклатуры не проводится.

Почему не новая ТЧ заказа: запись заказа запускает подписку `ЗаказПоставщику_ПередЗаписью` (организация и подразделение берутся из договора) и перепроведение.

Регистр не участвует в обмене с Казной и BuhBud, затереть его нечем.

Регистр **независимый, непериодический**:

| Вид | Поле | Тип |
|---|---|---|
| Измерение | `СчетКазнаУИД` | Строка(36) — UUID счёта Казны |
| Измерение | `НомерПозиции` | Число(5,0) |
| Ресурс | `Номенклатура` | `СправочникСсылка.Номенклатура` — только существующая, может быть пустой |
| Ресурс | `НазваниеВСчете` | Строка(500) |
| Ресурс | `Количество` | Число(15,3) |

Форма — стандартная (автогенерируемая): просмотр и ручная правка.

## 4. Загрузчик — Python-скрипт, повторный запуск безопасен

`_Rarzrabotki/Python/test/tovary_schetov_kazna/zagruzit_tovary_schetov.py`

1. **Счета:** Казна, `СчетНаОплатуПоставщика`, 2026 год, подразделения из п. 0, без пометки удаления.
2. **Файлы:** двоичные данные из Казны через COM (`Справочник.Файлы`, `ВладелецФайла` = счёт) → во временную папку.
3. **Распознавание строк** (название, количество, единица, цена, сумма):
   - xls / xlsx — openpyxl / xlrd;
   - doc / docx / rtf — текст и таблицы;
   - pdf с текстовым слоем — извлечение текста;
   - сканы (jpg / png / pdf-картинки) — распознаёт ИИ по изображению.

   Промежуточный результат — JSON на счёт в рабочей папке скрипта. По JSON можно перезаписать регистр без повторного распознавания.
4. **Контроль:** Σ строк = `СуммаСчета` ± 1 грн; иначе пометка в поле «Предупреждение».
5. **Заказ ЕРП** (по порядку, до первого совпадения):
   1. заявка ЕРП с `А_НомерСчетаПоДаннымПоставщикаКазна` и `А_ДатаПоДаннымПоставщикаКазна` счёта и тем же контрагентом → `РасшифровкаПлатежа.ОбъектРасчетов.Объект`, если это `ЗаказПоставщику`;
   2. РС `СоответствияОбъектовИнформационныхБаз`, узел Казначейства, по UUID счёта;
   3. иначе пусто.
6. **Номенклатура — только существующая, новых карточек не создавать:**
   1. позиции поступлений по найденному заказу;
   2. затем позиции поступлений этого контрагента;
   3. затем точное совпадение нормализованного наименования в справочнике.

   Не уверен — пусто + предупреждение.
7. **Запись:** набор записей регистра по `СчетКазнаУИД` целиком заменяется. Повторный запуск не плодит строки.
8. **Протокол** xlsx: счёт, файл, способ, строк, Σ строк / сумма счёта, заказ, строк без номенклатуры.

Пилот — 5–10 счетов разных форматов, затем массовый прогон.

## 5. Отчёт — новые поля (только информация)

Все суммы — на момент отчёта.

**По заказу:**
- `Счет` = Σ строк регистра;
- `Оплачено` = Σ сумм в `РасшифровкаПлатежа` проведённых списаний и РКО, где `ОбъектРасчетов.Объект` или `А_ЗаказПоставщику` = заказ;
- `Получено` = Σ поступлений с этим заказом;
- `ДоляОплаты` = min(1, Оплачено / Счет).

**«Оплачено, не надійшло»** (новый `ВидРядка` = «Рахунок оплачений, не надійшов», ресурс `ОплаченоНеНадійшло`):
- по строке счёта: `Max(0, Сумма − Σ ПТУ этого заказа с тем же общим названием) × ДоляОплаты`;
- группа — `КлючГруппы` по общему названию номенклатуры строки. Строки без номенклатуры — группа `|ТЕКСТ|` по названию из счёта.

**«Оплачено» / «Борг»** (ресурсы `Оплачено`, `Борг` в строках «Закупівля»):
- `Оплачено` строки ПТУ = Сумма × min(1, Оплачено по заказу / Получено по заказу);
- `Борг` = Сумма − Оплачено;
- ПТУ без заказа: `Оплачено` и `Борг` = 0, `ОзнакаОплати` = «оплата не визначена».

Прогноз, экономия и «Не докуповуємо» не меняются.
