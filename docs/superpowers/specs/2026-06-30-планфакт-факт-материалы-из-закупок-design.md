# Дизайн: А_ПланФактныйПроизводствоПолный — факт по материалам из закупок

Дата: 2026-06-30
Отчёт: `_Rarzrabotki/Отчеты/А_ПланФактныйПроизводствоПолный` (внешний `.erf`)

## Цель

Факт по материалам (`Блок = "2. Матеріали"`) брать **не из списания/остатков**
(`СебестоимостьТоваров.Расход` через `Документ.СборкаТоваров`), а **из закупок**
(`СебестоимостьТоваров.Приход` через `Документ.ПриобретениеТоваровУслуг`) — по образцу
отчёта `А_ПланФактныйАнализСебестоимости`.

## Решения (утверждено пользователем)

- **Категория Виробництво/Монтаж для факт-закупок** — «по этапу (как план)»: после привязки
  материала к `Етап` через `Номенклатура.А_ОбщееНазваниеНоменклатуры` категория =
  `Монтаж`, если имя этапа содержит «Монтаж», иначе `Виробництво`. Согласуется с тем, как
  категоризируется план (`К.Этап.Наименование ПОДОБНО "%Монтаж%"`) → план и факт сходятся в паре.
- **Объём закупок** — «все по подразделению СС»: все приходные материалы по подразделению
  структуры себестоимости за период (как в `А_ПланФактныйАнализСебестоимости`). Материалы вне
  плана отображаются с пустым `Етап`.

## Архитектура (подход A — точечная правка ObjectModule.bsl)

Отчёт остаётся **программной компоновкой СКД** (`ПриКомпоновкеРезультата` → внешний набор
«Детали»). Причина программности — маппинг факт-материалов на `Етап` через
`А_ОбщееНазваниеНоменклатуры`, который невозможен в чистом СКД-запросе на этой базе. Поэтому
меняем только BSL; схема СКД (`Template.xml`), разрезы и расшифровка — без изменений.

### 1. Новая 5-я ветка UNION в `ПолучитьДанные` (факт-материали)

Было:
```
ИЗ РегистрНакопления.СебестоимостьТоваров КАК СТ
  ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_СС
  ПО ВЫРАЗИТЬ(СТ.Регистратор КАК Документ.СборкаТоваров).А_СтруктураСебестоимости = ВТ_СС.СС
ГДЕ СТ.ВидДвижения = Расход
  И СТ.Регистратор ССЫЛКА Документ.СборкаТоваров
  И СТ.Период МЕЖДУ &НачП И &КонП
-- ресурс СтоимостьУпр → ФактГрн; Категория по складу СборкаТоваров.Склад = СкладМонт
```

Станет:
```
ИЗ РегистрНакопления.СебестоимостьТоваров КАК СТ
  ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_СС
  ПО ВЫРАЗИТЬ(СТ.Регистратор КАК Документ.ПриобретениеТоваровУслуг).Подразделение = ВТ_СС.Подр
ГДЕ СТ.ВидДвижения = Приход
  И СТ.РазделУчета = ЗНАЧЕНИЕ(Перечисление.РазделыУчетаСебестоимостиТоваров.ТоварыНаСкладах)
  И СТ.Регистратор ССЫЛКА Документ.ПриобретениеТоваровУслуг
  И СТ.Период МЕЖДУ &НачП И &КонП
-- ресурс СтоимостьБезНДС → ФактГрн; Категория = плейсхолдер "Виробництво", Этап = НЕОПРЕДЕЛЕНО
-- Аналитика = СТ.АналитикаУчетаНоменклатуры.Номенклатура
```

Изменения: `Расход → Приход`, `СборкаТоваров → ПриобретениеТоваровУслуг`, привязка
к СС → к **подразделению СС**, добавлен фильтр `РазделУчета = ТоварыНаСкладах`,
ресурс `СтоимостьУпр → СтоимостьБезНДС`. Категория ставится не в запросе, а в BSL (см. п.2).

### 2. Категория + Етап в BSL-постобработке

`МаппингОбщееНазваниеЭтап(СС)`: значение карты меняем со «ссылки на Этап» на
**структуру `{Этап, Категория}`**, где `Категория = ?(Этап.Наименование ПОДОБНО "%Монтаж%",
"Монтаж", "Виробництво")`. Категорию вычисляем один раз при построении карты (запрос уже
выбирает `К.Этап`; добавим `К.Этап.Наименование`).

`ЗаполнитьЭтапФактМатериалов(ТЗ, СС)`: для каждой факт-строки материала (`Блок="2. Матеріали"`,
`Этап` пуст, `Аналитика` — `СправочникСсылка.Номенклатура`) ставим **и `Этап`, и `Категория`**
из карты. Несопоставленные строки (нет общего названия в плане) остаются с пустым `Этап` и
категорией «Виробництво» (плейсхолдер из запроса).

Пересборка ТЗ не нужна: СКД сам агрегирует внешний набор по группировкам
(`Підрозділ → Блок → Категорія → Етап → Аналітика`), как и сейчас для `Этап`.

### 3. Без изменений

План-матеріали (`А_СтруктураСебестоимости.Комплектующие`), праця план (роботи) и факт
(табель `А_ДанныеТабелирования` + ОЗФУ `А_ВзаиморасчетыССотрудниками`), 8 ресурсов
часы/грн, схема СКД, настройки разрезов, штатная расшифровка по ссылочной `Аналітика`.
