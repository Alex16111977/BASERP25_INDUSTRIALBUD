# Spec: Унификация структуры ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам с ТЧ.Зарплата

## 1. Цель

Привести структуру ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам` (документ
`ВедомостьНаВыплатуЗарплатыВКассу`) к **единой логике** с типовой ТЧ
`Зарплата` того же документа — по образцу `НачисленнаяЗарплатаИВзносы` /
`НачисленнаяЗарплатаИВзносыПоФизлицам` в `ОтражениеЗарплатыВФинансовомУчете`.

**Зачем:** упростить поддержку, дать пользователю единый набор полей в обеих
ТЧ, обеспечить нативный матч строк между Зарплата и А_Расшифровка через
ИдентификаторСтроки.

---

## 2. Изменения структуры ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам

### Удалить
- `ОтработаноЧасов` (Число) — больше не используется

### Переименовать
- `Сумма` → `КВыплате` (Число) — сохраняем UUID реквизита, данные не теряются

### Добавить (6 новых полей — копия из ТЧ.Зарплата)

| Поле | Тип |
|---|---|
| `ПериодВзаиморасчетов` | Дата |
| `СтатьяФинансирования` | СправочникСсылка.СтатьиФинансированияЗарплата |
| `СтатьяРасходов` | СправочникСсылка.СтатьиРасходовЗарплата |
| `ДокументОснование` | composite ref (15 типов как в ТЧ.Зарплата) |
| `КомпенсацияЗаЗадержкуЗарплаты` | Число |
| `ГруппаУчетаНачислений` | СправочникСсылка.ГруппыУчетаНачисленийИУдержаний |

### Сохранить
- `ИдентификаторСтроки` (UUID)
- `ФизическоеЛицо`, `Сотрудник`, `Подразделение`
- `НаправлениеДеятельности` (наше специфичное)
- `СтатьяДвиженияДенежныхСредств` (наше специфичное, главное)

### Итог
13 полей вместо 8. Из них 11 — зеркало ТЧ.Зарплата, 2 — наши специфичные
(`НаправлениеДеятельности` + `СтатьяДвиженияДенежныхСредств`).

## 3. Изменения в коде

### 3.1 `Documents/ВедомостьНаВыплатуЗарплатыВКассу.xml`

Изменить определение ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам`:
- Удалить `<Attribute name="ОтработаноЧасов">`
- Переименовать `<Properties><Name>Сумма</Name>` → `<Name>КВыплате</Name>`, UUID сохранить (данные мигрируют)
- Добавить 6 новых `<Attribute>` блоков с новыми UUID

Точные типы и UUIDs:
- `ПериодВзаиморасчетов`: `xs:dateTime` + DateFractions=DateTime (как в ТЧ.Зарплата)
- `СтатьяФинансирования`: `cfg:CatalogRef.СтатьиФинансированияЗарплата`
- `СтатьяРасходов`: `cfg:CatalogRef.СтатьиРасходовЗарплата`
- `ДокументОснование`: 15 типов (точно как в ТЧ.Зарплата — копируем blob `<Type>` целиком)
- `КомпенсацияЗаЗадержкуЗарплаты`: `xs:decimal` (15, 2, Any)
- `ГруппаУчетаНачислений`: `cfg:CatalogRef.ГруппыУчетаНачисленийИУдержаний`

### 3.2 `Documents/РаспределениеФ2/Ext/ObjectModule.bsl`

**Шаг 8** (заполнение А_Расшифровки) полностью переписывается на новую логику:
**зеркалим уже заполненную ТЧ.Зарплата 1:1, добавляем только 2 наших поля.**

```bsl
// === 8. ТЧ А_Расшифровка — зеркало ТЧ.Зарплата + СтатьяДДС + Направление ===
Для Каждого СтрЗ Из ВыкВКассу.Зарплата Цикл
    НовСтр = ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Добавить();
    ЗаполнитьЗначенияСвойств(НовСтр, СтрЗ,
        "ИдентификаторСтроки, Сотрудник, ФизическоеЛицо, Подразделение,
         ПериодВзаиморасчетов, СтатьяФинансирования, СтатьяРасходов,
         ДокументОснование, КВыплате, КомпенсацияЗаЗадержкуЗарплаты,
         ГруппаУчетаНачислений");

    // НаправлениеДеятельности — из шапки Ф2.Направление
    НовСтр.НаправлениеДеятельности = Направление;

    // СтатьяДДС: 1) из словаря СтатьиДДСПоКлючу (новая кнопка ОтражениеЗПпоКазне),
    //             2) иначе fallback на Сотрудник.СтатьяЗарплата → Родитель.СтатьяЗарплата.
    Если СтатьиДДСПоКлючу <> Неопределено Тогда
        Ключ_СтД = ?(ЗначениеЗаполнено(СтрЗ.Сотрудник),
                    Строка(СтрЗ.Сотрудник.УникальныйИдентификатор()), "")
            + "|"
            + ?(ЗначениеЗаполнено(СтрЗ.Подразделение),
                    Строка(СтрЗ.Подразделение.УникальныйИдентификатор()), "");
        СтатьяДДС = СтатьиДДСПоКлючу.Получить(Ключ_СтД);
        Если СтатьяДДС = Неопределено ИЛИ НЕ ЗначениеЗаполнено(СтатьяДДС) Тогда
            СтатьяДДС = Справочники.СтатьиДвиженияДенежныхСредств.ПустаяСсылка();
            Сообщить("WARN: СтатьяДДС не найдена в ОтражениеЗПпоКазне для "
                + Строка(СтрЗ.Сотрудник) + " / " + Строка(СтрЗ.Подразделение));
        КонецЕсли;
    Иначе
        СтатьяДДС = СтрЗ.Сотрудник.СтатьяЗарплата;
        Если НЕ ЗначениеЗаполнено(СтатьяДДС) Тогда
            Попытка
                СтатьяДДС = СтрЗ.Сотрудник.Родитель.СтатьяЗарплата;
            Исключение
                СтатьяДДС = Справочники.СтатьиДвиженияДенежныхСредств.ПустаяСсылка();
            КонецПопытки;
        КонецЕсли;
    КонецЕсли;
    НовСтр.СтатьяДвиженияДенежныхСредств = СтатьяДДС;
КонецЦикла;
```

**Удалить:**
- Старый Шаг 8 (цикл по `Распределение Ф2`)
- `ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Свернуть(...)` — больше не нужна (1:1 со строками Зарплата, дубликатов нет)

### 3.3 `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`

**НЕ меняется.** Процедура `СоздатьВедомостиВКассуПоОтражениюЗП` вызывает
расширенную Ф2-процедуру — изменение в Ф2.bsl автоматически распространится.

### 3.4 Форма `А_ФормаСпискаРасшифровкиПоФЛ`

## 4. Доставка

**Структурное изменение ТЧ** — `-Dynamic+` обычно справляется с добавлением
полей и удалением полей. Если не справится, нужен полный update + перезапуск
сервера 1С.

Порядок:
1. `db-load-xml -Mode Partial -Files "Documents/ВКассу.xml,Documents/ВКассу/Forms/А_ФормаСпискаРасшифровкиПоФЛ.xml,Documents/РаспределениеФ2/Ext/ObjectModule.bsl"`
2. `db-update -Dynamic+`
3. Если не сработает → `db-update` без `-Dynamic+` (полный) → возможно перезапуск сервера.

## 5. Поведение для существующих данных

| Колонка | Что произойдёт |
|---|---|
| `ОтработаноЧасов` | **Удаляется** — числовые значения часов потеряются (не критично, не использовались) |
| `Сумма` → `КВыплате` | **Сохраняется** при сохранении UUID реквизита (1С мигрирует данные автоматически) |
| 6 новых полей | **Пустые** для существующих строк до перепроведения |

**Восстановление полноценного состояния:** перепровести Ф2 (или нажать кнопку
«Создать ведомости в кассу» в ОтражениеЗПпоКазне №000000006) — заполнит новые
поля во всех связанных ВКассу.

## 7. Acceptance критерии

- ✅ ТЧ А_РасшифровкаВыплатыЗарплатаПоФизлицам имеет 13 полей (из них 11 общих с Зарплата + 2 наших).
- ✅ Перепроведение Ф2 №000000026 → ВКассу с 31 строкой А_Расшифровки, у каждой заполнены все 13 полей (включая ПериодВзаиморасчетов, ГруппаУчётаНачислений, КВыплате).
- ✅ Кнопка «Создать ведомости в кассу» в ОтражениеЗПпоКазне №000000006 → 7 ВКассу с заполненными А_Расшифровками.
- ✅ СтатьяДДС в А_Расшифровке = из ТЧ.РаспределениеКазна (для пути через ОтражениеЗПпоКазне) или из Сотр.СтатьяЗарплата (для пути через Ф2-кнопку).
- ✅ Форма А_ФормаСпискаРасшифровкиПоФЛ показывает 13 колонок, все редактируемые.
- ✅ Все 6 регрессионных тестов PASS (smoke/idempotency/rashifrovka для Ф2 + smoke/idempotency/statyaddc для ОтражениеЗП).
- ✅ Подформа сохраняет ОК-возврат изменений с новыми полями.
