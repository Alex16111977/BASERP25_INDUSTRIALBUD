## 1. Задача

Три изменения в одном отчёте, все — решения пользователя 04.09.2026:

1. **Разрез «Аналітика» — строка.** План: `СокрЛП(К.НоменклатураСС)`; факт: `СокрЛП(Т.Номенклатура.Наименование)`.
   Ссылка на карточку номенклатуры сохраняется в **новом измерении «Номенклатура»**, заполненном только у факта.
2. **Общая назва плана — из строки СС** (`К.ОбщееНазвание`), а не из карточки номенклатуры.
   Карточная общая назва у плана — только запасной вариант при пустой строке СС. Факт по-прежнему
   классифицируется карточной общей назвой (`Т.Номенклатура.ОбщееНазваниеНоменклатуры`).
3. **Множитель домиков — реквизит `СС.КоличествоДомов`** (0 → 1), как в ЕРП. Подсчёт дочерних
   подразделений по имени карточки СС убирается.

ЕРП-отчёт не трогаем.

### 3.2. Запрос грейна (`ВыполнитьЗапросПоЗонтику`)

Пакет упрощается: `ВТ_Драйвер` уходит, `ВТ_СС` строится напрямую:

```
ВЫБРАТЬ
	СС.Ссылка КАК СС,
	СС.Подразделение КАК Подр,
	ВЫБОР КОГДА СС.КоличествоДомов > 0 ТОГДА СС.КоличествоДомов ИНАЧЕ 1 КОНЕЦ КАК Домиков
ПОМЕСТИТЬ ВТ_СС
ИЗ Справочник.СтруктураСебестоимости КАК СС
ГДЕ НЕ СС.ЭтоГруппа И СС.Активная И НЕ СС.ПометкаУдаления И СС.Подразделение = &Зонтик
```

Плановая ветка `ВТ_Детали`:

- `ОбщееНазвание` = `ВЫБОР КОГДА К.ОбщееНазвание <> ПустаяСсылка ТОГДА К.ОбщееНазвание ИНАЧЕ К.Номенклатура.ОбщееНазваниеНоменклатуры КОНЕЦ`;
- `Аналитика` = `СокрЛП(К.НоменклатураСС)`;
- `Номенклатура` = `ЗНАЧЕНИЕ(Справочник.Номенклатура.ПустаяСсылка)`;
- `ПланКол` = `К.Количество * ВТ_СС.Домиков`, `ПланГрн` = `К.Сумма * ВТ_СС.Домиков`.

Фактовая ветка:

- `ОбщееНазвание` = `Т.Номенклатура.ОбщееНазваниеНоменклатуры` (как было);
- `Аналитика` = `СокрЛП(Т.Номенклатура.Наименование)`;
- `Номенклатура` = `Т.Номенклатура`;
- сумма с НДС — формула без изменений (инвариант).

Итоговый `ВЫБРАТЬ … СГРУППИРОВАТЬ ПО` получает колонку `Номенклатура`.
Текст запроса до переноса в BSL прогоняется Python COM на bas_industrialbud (Rule #-1).

### 3.3. Маппинг «имя общей назвы → Етап» (`МаппингОбщееНазваниеЭтап`)

Ключ маппинга строится из той же общей назвы, что и у плана: `К.ОбщееНазвание.Наименование`,
при пустой строке — карточная. Иначе факт разносился бы по этапам по одной назве, а план стоял бы под другой.

### 3.4. Постобработки

- `ЗаполнитьЭтапИКатегориюФакта` — без изменений (ключ по имени ОН).
- `ЗаполнитьПланНаФакт`: у синтетической строки при заполненной ОН `Аналитика = ""`,
  `Номенклатура` и `Единица` — пустые ссылки; без ОН — `Аналитика` текстом образца,
  `Единица` образца, `Номенклатура` пустая.
- `КлючГруппыПланНаФакт`: ветка `НОМ|uuid` удаляется (ссылок в `Аналитика` больше нет);
  для строк без ОН ключ — `ТЕКСТ|ВРег(СокрЛП(Аналитика))` у обеих веток.
- `СоздатьПустуюТаблицу`: `Аналитика` → Строка(200); новая колонка `Номенклатура`;
  комментарий «8 измерений + 14 показателей».
- `ЗаполнитьПроизводные` — без изменений.

### 3.5. Схема СКД (`Template.xml`)

- Поле `Аналитика`: `valueType` только `xs:string` со `StringQualifiers` 200.
- Новое поле `DataSetFieldField` `Номенклатура`: `dataPath`/`field` = `Номенклатура`, титул ru и uk «Номенклатура»,
  роль `dimension`, тип `CatalogRef.Номенклатура`.
- Варианты/структура группировок — без изменений.

## 5. Известные последствия (приняты пользователем 04.09.2026)

1. План и факт с одинаковым текстом аналитики сливаются в одну строку «Аналітика» только при точном
   совпадении `СокрЛП`-текста (регистр учитывается; расхождений по регистру сегодня 2 из 460).
2. У 62 строк плана (все, кроме 5 строк «вати» в ООН Админ) общая назва строки СС — вольный синоним
   карточной («Вимикач» против «Автоматика / захисні пристрої»). После перехода плана на назву строки СС
   их факт останется под карточной назвой: план и факт таких позиций разъедутся по разным
   «Загальна назва», и «План на факт» по ним не неттуется. Лечится данными (выравнивание общих назв
   в СС или в карточках), не кодом. Список 67 расхождений выгружается отдельным файлом
   `_Rarzrabotki/Отчеты/ПланФактССБухгалтерія_расхождения_ОН.md` для чистки.
3. План IRS возвращается к множителю 6/7 (сейчас 2 из-за кириллической «С» в имени СС).
