# Дизайн: Регистр «А_НастройкиПодключенияБаз» — строки COM-подключения без хардкода в коде

Дата: 2026-07-13
Статус: утверждён пользователем (вариант A)
База: BaseERP (BAS ERP 2.5 INDUSTRIALBUD)

## 1. Проблема

В 14 объектах конфигурации (4 документа + 10 отчётов, 17 мест) строки подключения к внешним
базам (`zup_1`, `zup_2`, `BuhBud`, `BuhKazn`) захардкожены в BSL-коде вида:

```bsl
V83 = Connector.Connect("Srvr=""SQLSERVER"";Ref=""zup_2"";Usr=""cfo"";Pwd=""2442"";");
```

База регулярно копируется между рабочим сервером и сервером разработки. После копирования
хардкод `Srvr="SQLSERVER"` указывает не туда, и обмены/отчёты либо ломаются, либо (хуже)
ходят в чужую базу. Требование: **после копирования базы всё работает без правок кода,
независимо от того, на каком сервере запущено**.

## 2. Решение (утверждено)

Данные подключения (сервер, имя базы, пользователь, пароль) выносятся из кода в **регистр
сведений**. В коде остаётся только идентификатор базы:

```bsl
V83 = А_ПодключенияБазСервер.УстановитьСоединение("zup_2");
```

Сервер по умолчанию — `localhost`: весь затронутый код серверный (модули объектов документов
и отчётов), исполняется на сервере 1С, а все 5 баз живут в одном кластере на одной машине —
и на рабочем, и на dev-сервере. Данные регистра хранятся в самой базе → уезжают вместе с
копией и остаются корректными на любом сервере.

### Исследование prior art (выполнено)

- GitHub (REST /search/code, 181+31 результатов): единственное зрелое универсальное решение —
  сама БСП: регистр `НастройкиТранспортаОбменаДанными` + `ОбщегоНазначения.УстановитьВнешнееСоединениеСБазой()`.
  Отдельных сторонних библиотек «реестр подключений» нет.
- Штатный БСП-регистр НЕ подходит: ключ — узел плана обмена (zup_1/zup_2 не узлы), плюс БСП
  детектирует копию базы и чистит/блокирует настройки обмена — противоречит требованию.
- Из БСП переиспользуем **механику соединения**: `ОбщегоНазначения.УстановитьВнешнееСоединениеСБазой()`
  (CommonModules/ОбщегоНазначения/Ext/Module.bsl:2675) + конструктор параметров
  `ОбщегоНазначенияКлиентСервер.СтруктураПараметровДляУстановкиВнешнегоСоединения()`
  (CommonModules/ОбщегоНазначенияКлиентСервер/Ext/Module.bsl:1915) — бесплатно получаем
  экранирование кавычек в пароле и структурированные ошибки.

### Отклонённые варианты

- **БСП НастройкиТранспортаОбменаДанными** — привязка к узлам обмена, чистка при копии базы.
- **Константы (по одной на базу)** — новая база = изменение конфигурации, не масштабируется.

## 3. Новые объекты метаданных

### 3.1 РегистрСведений.А_НастройкиПодключенияБаз

Независимый, непериодический. Стандартные платформенные формы (кастомные формы не делаем).
Синоним: «Настройки подключения баз (А)». Пояснение: «Строки COM-подключения к внешним базам
1С. Заполняется на каждом сервере; Сервер = localhost работает после копирования базы».

| Поле | Тип | Роль | Комментарий |
|---|---|---|---|
| `ИдентификаторБазы` | Строка(50) | Измерение (ведущее, обязательное) | Ключ: `zup_1`, `zup_2`, `BuhBud`, `BuhKazn` |
| `Сервер` | Строка(100) | Ресурс | `localhost`; поддерживает `host:port` для нестандартного порта кластера |
| `ИмяБазы` | Строка(100) | Ресурс | Ref на сервере 1С (обычно = идентификатору) |
| `Пользователь` | Строка(100) | Ресурс | |
| `Пароль` | Строка(100) | Ресурс | Открытой строкой — осознанно (см. §7 Безопасность) |
| `Комментарий` | Строка(200) | Реквизит | Назначение базы |

### 3.2 ОбщийМодуль.А_ПодключенияБазСервер

Флаги: `Сервер = Истина`, `ВнешнееСоединение = Истина`, `Привилегированный = ЛОЖЬ`,
`ВызовСервера = Ложь`, `ПовторноеИспользование = Не использовать`.

**Почему не привилегированный модуль (проверено на платформе 8.3.20).** Платформа считает флаги
`Привилегированный` и `ВнешнееСоединение` несовместимыми: при загрузке XML с обоими она молча
оставляет привилегированный и снимает внешнее соединение; в Конфигураторе установка одной галки
снимает другую. Без `ВнешнееСоединение` модуль не виден в COM-контексте, и все 14 объектов
падают с «Переменная не определена (А_ПодключенияБазСервер)» при обращении по COM
(Python-скрипты перепроведения, кросс-базные обработки).

Права на чтение регистра обеспечиваются в коде: `УстановитьПривилегированныйРежим(Истина)`
внутри `НастройкиБазы()`. Это штатный приём БСП — типовой `ОбщегоНазначения` имеет ровно такие
же флаги (Сервер + ВнешнееСоединение, Привилегированный = Ложь) и 48 вызовов привилегированного
режима в коде. Запись в регистр (`ЗаполнитьНастройкиПоУмолчанию`) привилегированным режимом
НЕ оборачивается — настройка подключений остаётся админской операцией.

Экспортные функции:

```bsl
// Возвращает COM-соединение с внешней базой по идентификатору из регистра
// А_НастройкиПодключенияБаз. Делегирует установку соединения в
// ОбщегоНазначения.УстановитьВнешнееСоединениеСБазой() (V83.COMConnector внутри БСП).
// Если записи нет или соединение не установлено — ВызватьИсключение с понятным
// текстом (идентификатор, сервер, имя базы; ПАРОЛЬ В ТЕКСТ ОШИБКИ НЕ ВКЛЮЧАТЬ).
Функция УстановитьСоединение(Знач ИдентификаторБазы) Экспорт

// Возвращает готовую строку подключения "Srvr=""..."";Ref=""..."";Usr=""..."";Pwd=""..."";"
// для мест, где нужна строка как есть (фаза 2 — внешние обработки, диагностика).
// Кавычки в значениях экранируются удвоением.
Функция СтрокаПодключения(Знач ИдентификаторБазы) Экспорт

// Служебная: читает запись регистра, при отсутствии — исключение
// "Не заполнены настройки подключения к базе ""%1"". Заполните регистр
// сведений ""А_НастройкиПодключенияБаз"" (Все функции)."
Функция НастройкиБазы(Знач ИдентификаторБазы) // без Экспорт

// Сид 4 записей по умолчанию (Сервер = "localhost", Usr = "cfo", Pwd = "2442",
// ИмяБазы = идентификатору). СУЩЕСТВУЮЩИЕ ЗАПИСИ НЕ ПЕРЕТИРАЕТ — пишет только
// отсутствующие идентификаторы. Вызывается один раз при внедрении (Python COM)
// и доступна для повторного применения на новом сервере.
Процедура ЗаполнитьНастройкиПоУмолчанию() Экспорт
```

Реализация `УстановитьСоединение` (эскиз):

```bsl
Функция УстановитьСоединение(Знач ИдентификаторБазы) Экспорт
	Настройки = НастройкиБазы(ИдентификаторБазы);
	Параметры = ОбщегоНазначенияКлиентСервер.СтруктураПараметровДляУстановкиВнешнегоСоединения();
	Параметры.ВариантРаботыИнформационнойБазы = 1; // клиент-сервер
	Параметры.ИмяСервера1СПредприятия = Настройки.Сервер;
	Параметры.ИмяИнформационнойБазыНаСервере1СПредприятия = Настройки.ИмяБазы;
	Параметры.ИмяПользователя = Настройки.Пользователь;
	Параметры.ПарольПользователя = Настройки.Пароль;
	Результат = ОбщегоНазначения.УстановитьВнешнееСоединениеСБазой(Параметры);
	Если Результат.Соединение = Неопределено Тогда
		ВызватьИсключение СтрШаблон(
			НСтр("ru='Не удалось подключиться к базе ""%1"" (Srvr=%2; Ref=%3): %4';uk='Не вдалося підключитися до бази ""%1"" (Srvr=%2; Ref=%3): %4'"),
			ИдентификаторБазы, Настройки.Сервер, Настройки.ИмяБазы, Результат.ПодробноеОписаниеОшибки);
	КонецЕсли;
	Возврат Результат.Соединение;
КонецФункции
```

Примечание: точное имя поля результата БСП (`Соединение` / `ОписаниеОшибки` /
`ПодробноеОписаниеОшибки`) сверить по факту с
`ОбщегоНазначенияСлужебныйКлиентСервер.УстановитьВнешнееСоединениеСБазой()` и
проверить Python COM-тестом (Rule #-1) до правки BSL.

## 5. Рефакторинг — 17 мест в 14 объектах

Никаких переименований объектов, процедур и логики — меняются ТОЛЬКО строки получения
соединения. Два паттерна замены:

**Паттерн 1** — inline Connect (`Новый COMОбъект("V83.COMConnector")` + `Connect("Srvr=...")`):
обе строки заменяются на одну `<Перем> = А_ПодключенияБазСервер.УстановитьСоединение("<Ид>");`
Имена переменных соединения (`V83`, `СоединениеЗУП2`…) сохраняются как есть.

**Паттерн 2** — переменная-строка (`СтрокаПодключения = "Srvr=..."` + ниже `V8.Connect(...)`):
блок «строка + Новый COMОбъект + Connect» заменяется на тот же одиночный вызов
`УстановитьСоединение`. Существующие `Попытка/Исключение` вокруг подключения сохраняются
(наша функция бросает исключение — поведение обработчиков не меняется).

## 6. Фаза 2 — внешние обработки и отчёты `_Rarzrabotki` (ВЫПОЛНЕНО 2026-07-14)

35 объектов, 44 вхождения: 36 присваиваний строки подключения, 6 блоков параметров обмена
(`СерверОбмена`/`БазаОбмена`/`Логин`/`Пароль`) + их конкатенация в `Connect`, 2 комментария.

Шаблон замены — минимальное вмешательство: меняется ТОЛЬКО присваивание строки, окружающий код
(`Новый COMОбъект("V83.COMConnector")`, `Попытка/Исключение`, `Connect(...)`) остаётся как был:

```bsl
СтрокаПодключенияBuhBud = А_ПодключенияБазСервер.СтрокаПодключения("BuhBud");
```

Все 8 мест в модулях форм лежат в процедурах `&НаСервере` → серверный общий модуль доступен
напрямую, клиентские обёртки не нужны. Модули объектов обработок исполняются на сервере
(используют `Новый Запрос`), поэтому доступны так же.

**Учётка `1cAdmin` (10 мест: обмен ЕРП↔BuhBud, переносы остатков, заполнение счетов).** В коде
стояло `Usr="1cAdmin";Pwd=""` — проверка живым подключением показала: пользователь в BuhBud
существует, но пустой пароль не подходит («Неправильное имя или пароль»), то есть эти места
были нерабочими. У `cfo` в BuhBud есть право Администрирование и права изменения/проведения
документов, поэтому все 10 мест переведены на идентификатор `BuhBud` (cfo). Отдельная запись
регистра под 1cAdmin не заводится.

Пересобраны 12 объектов, у которых в репозитории лежат готовые файлы (8 `.epf` + 4 `.erf`);
smoke через COM (`ВнешниеОбработки.Создать(путь, Ложь)`) — 12/12 открываются и видят общий
модуль. Остальные 23 объекта существуют только как исходники. В справочнике
`ДополнительныеОтчетыИОбработки` ни одна из них не зарегистрирована — обработки открываются
как файлы, дополнительная загрузка в базу не нужна.

## 6.1 Не-цели

- Python-скрипты в `_Rarzrabotki/Python/` — не трогаем (у них свои строки подключения).
- Переименование объектов, процедур, переменных — не делаем.
- Кастомные формы регистра, подсистемы, роли — не делаем (доступ через «Все функции»).

## 7. Безопасность

Пароль хранится в регистре открытой строкой — осознанное решение:
- сейчас пароли лежат в исходном коде конфигурации (доступны всем, у кого есть Конфигуратор
  или выгрузка) — регистр как минимум не хуже;
- «безопасное хранилище» БСП завязано на механизм обнаружения копии базы и может чиститься
  при переносе — ломает главное требование «скопировал — работает»;
- пароль не должен попадать в тексты исключений и журнал регистрации.

## 9. Риски и допущения

- **Допущение:** обе площадки (рабочая и dev) держат все 5 баз в одном кластере на одной
  машине → `localhost` корректен для серверного кода. Если появится площадка с разнесёнными
  серверами — правится ЗАПИСЬ регистра на той площадке, код не трогается.
- **Риск:** `НачислениеЗарплаты` и `ОтражениеЗарплатыВФинансовомУчете` — типовые документы;
  меняем только уже доработанные ранее участки их модулей, метаданные типовых объектов не
  трогаем (feedback_no_typical_register_changes).
- **Риск:** порт кластера ≠ 1541 на одном из серверов → лечится значением `localhost:<порт>`
  в поле `Сервер`, код универсален.
- **Риск:** права на чтение регистра у обычных пользователей → закрыт вызовом
  `УстановитьПривилегированныйРежим(Истина)` в `НастройкиБазы()` (см. §3.2).
- **Грабли платформы 8.3.20:** частичная загрузка (`/LoadConfigFromFiles -partial`) применяет

  (`Метаданные.ОбщиеМодули.Найти(...)`), а не доверять XML.
