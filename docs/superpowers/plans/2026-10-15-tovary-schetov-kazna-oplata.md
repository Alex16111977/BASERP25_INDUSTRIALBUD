# Товары счетов Казны и оплата в прогнозе — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** хранить товарные строки счетов Казны (из сканов) в регистре ЕРП со ссылкой на заказ поставщику и показать в отчёте прогноза «Оплачено, не надійшло» и «Оплачено / Борг».

**Architecture:**
- Независимый регистр сведений `А_ТоварыСчетовПоставщиков`.
- Python-загрузчик: Казна (счета + файлы тома) → распознавание → сопоставление заказа и номенклатуры → запись в регистр + протокол xlsx.
- Отчёт читает регистр, платежи и ПТУ и выводит информационные колонки; прогноз не меняется.

**Tech Stack:** BAS ERP 2.5 (XML, BSL, СКД), Python 3 + win32com, openpyxl / xlrd / python-docx / pypdf, распознавание изображений — ИИ (Read по картинке).

**Spec:** `docs/superpowers/specs/2026-10-15-tovary-schetov-kazna-oplata-design.md`

## Global Constraints

- Подразделения: «МД IRC 2026» (+ «15 м», «30 м» и их дочерние) и «МД ООН Админ»; счета 2026 года.
- Новых карточек номенклатуры **не создавать**.
- Казну и правила обмена не менять: из Казны только чтение (COM-запросы и файлы тома `C:\Razrabotki\1cExchange\`).
- Источник истины кода — основной каталог; правка в worktree → `cp` в main; `Configuration.xml` — только через гейт
  `erp_preflight_config.py`; загрузка `db-load-xml -Mode Partial`.
- Каждый запрос — сначала Python COM (Rule #-1). Алиасы `В`, `И`, `ПО` запрещены.
- Новые колонки отчёта — только информация: прогноз, экономия, «Не докуповуємо» не меняются.
- Тексты отчёта — на украинском.

## Review Focus

1. Счёт с несколькими файлами (счёт + договор + доверенность): берётся файл с таблицей товаров; остальные — пропуск с пометкой. Тест: пилот на счёте с ≥2 файлами.
2. Сумма строк ≠ сумма счёта (скидка, доставка, НДС отдельной строкой): строки сохраняются, в «Предупреждение» — разница. Тест: протокол показывает расхождение.
3. Повторный запуск: набор по `СчетКазнаУИД` заменяется, число записей не растёт. Тест: два прогона пилота подряд, COUNT равен.
4. Заказ оплачен больше суммы счёта, или поступлений больше счёта: доли ограничены 1, «Борг» ≥ 0. Тест: инвариант в приёмке.
5. Отчёт без записей регистра (другие проекты): колонки 0, ошибок нет. Тест: приёмка на дату до загрузки — прогноз = эталон.
