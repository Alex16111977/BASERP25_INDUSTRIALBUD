    pair = f"{sotr}|{podr}"
    if pair in pairs_seen:
        continue
    pairs_seen.add(pair)
    print(f"    {sotr} / {podr} → {statya}")

print(f"\n  Уникальных пар (Сотр, Подр): {len(pairs_seen)}")

## 3. Уроки

### Урок №1: переиспользование вместо дублирования

Старая Ф2-процедура уже умеет Find-Or-Create + шапка + Состав + Зарплата + А_Расшифровка + проведение. Не дублируем эту логику — расширяем 2 опциональными параметрами. Альтернатива (отдельная процедура с copy-paste) — двойная поддержка и риск разъезда логики при будущих изменениях.

### Урок №2: ключ словаря (Сотр_UID|ПодрОрг_UID)

Связь строки А_Расшифровки ↔ строка ТЧ.РаспределениеКазна — по паре (Сотрудник, ПодрОрг). В ТЧ.РаспределениеКазна Подразделение — это `Справочник.СтруктураПредприятия`, а в А_Расшифровке Подразделение — `Справочник.ПодразделенияОрганизаций`. Конвертация СтрПредпр → ПодрОрг через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению` — обязательна **с обеих сторон**, иначе ключи не совпадут.

### Урок №3: тип реквизита `ДокРаспределениеЗП`

Поле composite: `Документ.РаспределениеФ2, Документ.А_РаспределениеЗаработнойПлаты`. Фильтруем строки **только тип РаспределениеФ2** через `ТипЗнч(...) = Тип("ДокументСсылка.РаспределениеФ2")`. Строки с А_РаспределениеЗаработнойПлаты пропускаем + счётчик `ПропускТипов` в финальном сообщении.

### Урок №4: обратная связь — через ВКассу.А_ОтражениеЗПпоКазне

Пользователь находит созданные ВКассу через стандартный механизм «Связанные документы» 1С. Дополнительной ТЧ в А_ОтражениеЗПпоКазне или явной кнопки навигации не нужно.
