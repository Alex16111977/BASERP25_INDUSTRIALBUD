# ОУМП: кредитные договоры Воронцова — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** в ТЧ `Деньги` ОУМП выбирать контрагента и вид кредитного договора, а «Создать оплаты» ведёт кредитные строки по цепочке договоров Воронцова на каждое подразделение (тело / проценты / нераспределённая прибыль).

**Architecture:** новое перечисление `А_ВидыКредитныхДоговоров` + реквизит вида у договора и статьи ДДС + 4 колонки в ТЧ `Деньги`. Колонки заполняются по статьям в `ПередЗаписью`. В `СоздатьОплатыНаСервере` сторона с заданным видом получает контрагента и договор из новой функции `А_КредитнаяСторона`; прежний подбор для неё не выполняется. Строки без вида идут прежним путём.

**Tech Stack:** 1С 8.3.20 BAS ERP 2.5 (XML-выгрузка, BSL), Python 3 + win32com (`V83.COMConnector`), скилы `meta-*`, `form-*`, `db-load-xml`, `db-update`.

**Spec:** `docs/superpowers/specs/2026-10-14-oump-kreditnye-dogovory-design.md`

## Global Constraints

- Источник истины кода — **основной каталог** `C:\Configuration_downloads\BASERP25` (незакоммиченный, новее git). Перед правкой каждый файл копируется main → worktree, после правки — worktree → main (Rule #4).
- Загрузка — только `db-load-xml -Mode Partial`. `Configuration.xml` грузится **только** после гейта `_Rarzrabotki/Python/test/erp_preflight_config.py` с `EXPECTED_NEW = {("Enum", "А_ВидыКредитныхДоговоров")}` и кодом выхода 0.
- Каждый запрос 1С сначала проверяется в Python COM (Rule #-1). Подключение: `Srvr="localhost";Ref="BaseERP";Usr="Администратор";Pwd="24043"`.
- Боевые платёжки через COM не проводить: «Создать оплаты» по 575/581/582/583 выполняет пользователь в UI. COM-проведение не создаёт `РегистраторРасчетов`.
- Не использовать переменную `Ссылка`, алиасы `ПО`/`В`/`И`.
- Тексты сообщений — на русском, как в модуле.

## Review Focus

1. Строка возврата тела (`ТипыРасчета = ВозвратДенежныхСредств`): списание по договору тела (`СПокупателем`, `ВозвратОплатыКлиенту`), поступление ЦО по договору НП (`СПоставщиком`). Тест: `А_КредитнаяСторона` с типом `СПокупателем` для вида `ТелоКредита` возвращает договор `Кредитование…`.
2. Вид задан, контрагент пуст и у статьи нет партнёра: строка пропускается с сообщением, документы не создаются и не падают. Тест: `А_КредитнаяСторона` → `Ошибка = Истина`.
3. Повторный запуск не плодит договоры: второй вызов `А_НайтиИлиСоздатьКредитныйДоговор` возвращает ту же ссылку. Тест: счётчик договоров до и после.
4. Тип договора не совпадает с типом серии (например, НП на стороне прихода, `СПокупателем`): создаётся отдельный договор с суффиксом типа, а не подбирается договор не того типа. Тест: имя содержит « (Реализация)».
5. Ручная правка колонок в строке не затирается `ПередЗаписью`. Тест: заполнить колонку вручную → `Записать` объекта в памяти не проводится; проверяем функцию заполнения на структуре строки.

		Имя = "Кредитование от кредитора -- " + Подр;

		ТипСерии = Перечисления.ТипыДоговоров.СПоставщиком;
	Иначе
		Имя = "Нераспределенная прибыль -- " + Подр;
