# Обратная загрузка «Коментар цеху» из Excel — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** загрузить из xlsx печатной формы «Аналіз для цеху (з коментарем)» только
`РасчетКомплектаций.СписаниеСверхНормы.Причина`, сохранив причины в ТЧ-памяти, переживающей «Розрахувати»,
и не копируя их при копировании документа.

**Architecture:** новая ТЧ `ПричиниЦеху` (память причин: эталон + номенклатура + текст) наполняется загрузчиком
в модуле объекта, который читает xlsx нативно через `ТабличныйДокумент.Прочитать`; применение памяти к
`СписаниеСверхНормы` вызывается в конце `ЗаполнитьТаблицыСписания()` (то есть после каждого пересчёта), ручные
правки собираются обратно в `ПередЗаписью`, а `ОбработкаКопирования` память чистит. В печать добавляется колонка
«Код» (код номенклатуры) как точный ключ сопоставления.

**Tech Stack:** 1С:Предприятие 8.3.20, BAS Бухгалтерія `bas_industrialbud`; BSL (модуль объекта + модуль формы),
СКД-макет `МакетАнализЦех`, XML-исходники конфигурации; Python 3 + `win32com` (`V83.COMConnector`) для приёмки;
скилы `meta-edit`/`form-validate`/`db-load-xml`/`db-update`.

**Спека:** `C:\Configuration_downloads\BASERP25\docs\superpowers\specs\2026-09-16-zagruzka-prichin-ceh-excel-design.md`

`ЗібратиПричиниЗіСписання()`, `ОчиститиПричиниЦеху()` (экспорт).

Ключевые правила: пустая ячейка не затирает; > 200 символов — обрезаем и считаем; неоднозначность —
в протокол, строка пропускается; комментарий эталона применяется к номенклатурам этого эталона,
а ссылка эталона берётся от его дочерних строк файла (имена эталонов имеют 2 дубля, коды — уникальны).

с `ГДЕ Ссылка В (&Массив)` — Ссылка, Код, Наименование. Никаких обращений `Стр.Номенклатура.Код` в цикле.

- [ ] **Шаг 4.3: Три точки вызова**

1. `ЗаполнитьТаблицыСписания()` — в конце `ЗастосуватиПричиниЦеху();`
