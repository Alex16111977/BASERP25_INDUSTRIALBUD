## 1. КОНТЕКСТ: что уже сделано и работает

Обмен между базами идёт **без окна помощника интерактивного обмена**. Работают две внешние обработки
(обе лежат в `C:\Configuration_downloads\BASERP25\_Rarzrabotki\Обработки\`):

### `А_ЗапуститьОбмен` — исполнитель («worker»)
- Файлы: `А_ЗапуститьОбмен.xml` (корень), каталог `А_ЗапуститьОбмен\`, собранная `А_ЗапуститьОбмен.epf`.
- Открывается **в базе-корреспонденте** (сейчас — BuhBud). В `ПриСозданииНаСервере` (СЕРВЕР)
  выполняет обмен текущей базы, пишет результат в форму и в Журнал регистрации
  (событие **`А_АвтоматическийОбмен`**), затем в `ПриОткрытии` через **5 секунд**
  вызывает `ЗавершитьРаботуСистемы(Ложь, Ложь)` — сессия закрывается сама.
- Обмен идёт серверным методом БСП `ОбменДаннымиСервер.ВыполнитьОбменДаннымиДляУзлаИнформационнойБазы`,
  поэтому окно помощника **физически не может** открыться.

### `А_АвтоматическийОбменДанными` — оркестратор
- Файлы: `А_АвтоматическийОбменДанными.xml`, каталог `А_АвтоматическийОбменДанными\`, `.epf`.
- **Запускается только в BaseERP** (использует регистр `А_НастройкиПодключенияБаз`, которого нет в других базах).
- Кнопка **«Запустить полный обмен»** гонит цепочку **BuhBud → ERP → BuhBud**:
  1. `ЗапуститьПриложение(1cv8.exe … /Execute А_ЗапуститьОбмен.epf, КаталогПрограммы(), Истина, КодВозврата)`
     — запуск толстого клиента BuhBud; ждёт, пока сессия сама закроется (код возврата 0).
  2. **Обмен ERP выполняется в текущей сессии** (обработка и так работает в ERP) — учётка ERP не нужна.
  3. Ещё раз запуск BuhBud (принять встречное сообщение от ERP).
- Кнопка **«Синхронизировать текущую базу»** — обмен только текущей базы.
- **Переносимость** (уже сделана): сервер/имя базы/логин/пароль берутся из регистра
  `РегистрСведений.А_НастройкиПодключенияБаз`; путь к `1cv8.exe` — из `КаталогПрограммы()`;
  путь к `А_ЗапуститьОбмен.epf` — реквизит формы `ПутьКОбработкеОбмена`.

**Общий модуль объекта (ObjectModule) у обеих обработок ИДЕНТИЧЕН** — держите его синхронным.

## 4. 🚨 ГРАБЛИ — ЧИТАТЬ ОБЯЗАТЕЛЬНО

### Грабля 1 — блок `<Events>` в Form.xml (ломает ВСЁ и МОЛЧА)
Обработчики событий **формы** (`ПриОткрытии`, `ПриСозданииНаСервере`, …) обязаны быть **объявлены в Form.xml**:
```xml
<AutoCommandBar .../>
<Events>
    <Event name="OnCreateAtServer">ПриСозданииНаСервере</Event>
    <Event name="OnOpen">ПриОткрытии</Event>
</Events>
<ChildItems>...
```
Без этого блока процедура в модуле **есть, но платформа её НИКОГДА не вызывает** — без ошибок, без следов.
Именно это полдня ломало автозапуск обмена. Кнопки при этом работают — команды подключаются
отдельно, через `<Action>` в `<Commands>`.
- Позиция: между `<AutoCommandBar>` и `<ChildItems>`. Имена событий английские: `OnOpen`, `OnCreateAtServer`.
- Скилл `epf-add-form` генерит Form.xml **БЕЗ** `<Events>` — **добавлять руками**.
- В обеих текущих обработках блок уже есть — **не потерять его при правке**.

### Грабля 2 — кириллическая мина в имени `КазначествоBASERP`
Пишется через «Казна**чей**ство» — буква **«й» (кодовая точка `0x439`)**. Легко написать «Казначество» —
и тогда: запрос падает «Таблица не найдена», `Метаданные.…Найти()` молча вернёт `Неопределено`, файл
«не находится». В этой сессии на этом спотыкались **трижды**.
- **Проверка написания:** codepoints первых 12 символов должны быть
  `0x41a 0x430 0x437 0x43d 0x430 0x447 0x435 0x439 0x441 0x442 0x432 0x43e`.
- В коде имя должно встречаться **ровно один раз** — в константе. Ни в каких `Тип("ПланОбменаСсылка.…")`.
- В Python/bash **не набирать руками** — резолвить глобом/из метаданных.

### Грабля 3 — флагу `Отказ` от БСП ДОВЕРЯТЬ НЕЛЬЗЯ
`ОбменДаннымиСервер.ВыполнитьОбменДаннымиДляУзлаИнформационнойБазы(Узел, П, Отказ)` ставит
`Отказ = Истина` даже когда обмен прошёл нормально, а принимать было просто **нечего**:
результат `Предупреждение_СообщениеОбменаБылоРанееПринято` не входит в его список «выполнено»
(см. `ОбменДаннымиСервер.РезультатВыполненияОбменаВыполнено` — там только `Выполнено`,
`ВыполненоСПредупреждениями`, `Неопределено`).

**Правильно** (уже реализовано — сохранить): читать **фактический** `РезультатВыполненияОбмена`
по каждому действию из `РегистрСведений.СостоянияОбменовДанными`, классифицируя **в самом запросе**:

| Результат БСП | Трактовка |
|---|---|
| `Выполнено`, `ВыполненоСПредупреждениями` | выполнено |
| `Предупреждение_СообщениеОбменаБылоРанееПринято` | **нечего принимать — НЕ ошибка** |
| `Ошибка`, `Ошибка_ТранспортСообщения`, `Отменено` | ОШИБКА |

Успех = отсутствие **реальных** ошибок.

### Грабля 4 — регистры транспорта в базах РАЗНЫЕ (поэтому ищем по ПЛАНУ)
| База | Регистр | Измерение |
|---|---|---|
| BaseERP, BuhBud | `НастройкиТранспортаОбменаДанными` | `Корреспондент` |
| **BuhKazn** | **`НастройкиТранспортаОбмена`** | **`Узел`** |

Текущий `СписокУзлов()` ищет узел через `НастройкиТранспортаОбменаДанными` + маску каталога —
**в BuhKazn такой таблицы нет**, запрос упадёт.
⇒ **Именно поэтому дизайн переведён на поиск ПО ПЛАНУ ОБМЕНА** (раздел 5). Регистр транспорта
после рефакторинга **не используется вообще** — заодно ничего не сломается при переносе папок обмена.

### Грабля 5 — сборка `.epf`
- Корневой XML обработки должен иметь **`version="2.13"`**. Скилл `epf-init` ставит `2.17` —
  платформа **8.3.20.1914 такое не грузит** («Неизвестная версия формата 2.17»). Понижать вручную.
- Stub-база `epf-build` тоже генерит Configuration.xml 2.17 → **не работает**. Собирать против живой базы:
  `-InfoBaseServer "SQLSERVER" -InfoBaseRef "BuhBud" -UserName "cfo" -Password "2442"` (или BaseERP).
- Если база **занята Конфигуратором** — сборка падает, а `.epf` остаётся **старым**. Всегда проверять
  размер результата: рабочие `.epf` тут ~9–13 КБ. **Размер ровно 65536 (64 КБ) = битый файл** (провал сборки).
- Сборка **не компилирует** BSL. Модули компилируются в рантайме → ссылку на объект, которого нет
  в базе сборки, можно спокойно собирать (но в рантайме в той базе оно упадёт).

### Грабля 6 — Python COM
- **Сравнение перечислений через COM НЕ РАБОТАЕТ** (`res == Перечисления.X` даёт мусор).
  Сравнивать **в запросе** (`ЗНАЧЕНИЕ(Перечисление.…)`) или по `ПРЕДСТАВЛЕНИЕ()`.
- `getattr(conn.ПланыОбмена, "…")` на некоторых кириллических именах падает — надёжнее через запрос.
- Поля **неограниченной длины** (напр. `FILEКаталогОбменаИнформацией`) в `ПОДОБНО`/сравнении требуют
  `ВЫРАЗИТЬ(… КАК СТРОКА(500))`.
- Обмен через COM реально гоняет данные — на прод-базе это нормальная синхронизация, но помнить об этом.

### Грабля 7 — безопасность внешних обработок
Любая пересборка `.epf` **меняет хеш** → 1С при первом запуске снова спросит разрешение.
Пользователь подтверждает **с «Запомнить»** — один раз на базу. Без доверия `/Execute`-запуск
уходит в safe mode, где **файловые операции заблокированы**, а FILE-обмен именно файловый.
**Для BuhKazn это первый запуск — предупредить пользователя явно.**

## 5. ДИЗАЙН (утверждён пользователем — реализовать именно так)

### 5.1. ObjectModule (общий, ИДЕНТИЧНЫЙ в обеих обработках) — поиск узла ПО ПЛАНУ

Заменить текущий `СписокУзлов()` (маска каталога + регистр транспорта) на поиск по плану обмена:

```bsl

// Имя плана обмена ERP <-> Казна (BuhKazn).
// ВНИМАНИЕ: «Казна-ЧЕЙ-ство» — буква «й» (0x439). Опечатка ломает всё МОЛЧА.

	Возврат "КазначествоBASERP";

// Узел-корреспондент указанного плана обмена в ТЕКУЩЕЙ базе.
// Имя плана — СТРОКА и ищется через метаданные, поэтому отсутствие плана в этой базе
// НЕ ломает компиляцию (в BuhBud нет плана Казны, в BuhKazn нет плана Бухгалтерии).
//
// Возвращаемое значение:
//  ПланОбменаСсылка - узел (≠ ЭтотУзел, не помечен на удаление), или Неопределено.
//
Функция УзелКорреспондентПлана(ИмяПлана) Экспорт

	Если Метаданные.ПланыОбмена.Найти(ИмяПлана) = Неопределено Тогда
		Возврат Неопределено; // плана нет в этой базе — это НЕ ошибка
	КонецЕсли;

	Менеджер = ПланыОбмена[ИмяПлана];

	Запрос = Новый Запрос;
	Запрос.УстановитьПараметр("ЭтотУзел", Менеджер.ЭтотУзел());
	Запрос.Текст =
	"ВЫБРАТЬ ПЕРВЫЕ 1
	|	Узлы.Ссылка КАК Узел
	|ИЗ
	|	ПланОбмена." + ИмяПлана + " КАК Узлы
	|ГДЕ
	|	Узлы.Ссылка <> &ЭтотУзел
	|	И НЕ Узлы.ПометкаУдаления";

	Выборка = Запрос.Выполнить().Выбрать();
	Если Выборка.Следующий() Тогда
		Возврат Выборка.Узел;
	КонецЕсли;

	Возврат Неопределено;

КонецФункции

// Выполняет обмен ТЕКУЩЕЙ базы по указанному плану обмена (если план в ней есть).
//
// Параметры:
//  ИмяПлана  - Строка - см. ПланБухгалтерии() / ПланКазны().
//  Сообщения - Массив - (возвращаемый) читаемые строки-результаты.
//
// Возвращаемое значение:
//  Булево - Истина, если РЕАЛЬНЫХ ошибок не было.
//           План отсутствует в базе -> Истина (нечего делать, это не ошибка).
//           «Нечего принимать» -> тоже НЕ ошибка (см. ДобавитьРезультатыПоУзлу).
//
Функция СинхронизироватьПоПлану(ИмяПлана, Сообщения = Неопределено) Экспорт

	Если Сообщения = Неопределено Тогда
		Сообщения = Новый Массив;
	КонецЕсли;

	Узел = УзелКорреспондентПлана(ИмяПлана);
	Если Узел = Неопределено Тогда
		Возврат Истина; // плана нет в этой базе — молча пропускаем
	КонецЕсли;

	ПараметрыОбмена = ОбменДаннымиСервер.ПараметрыОбмена();
	ПараметрыОбмена.ВидТранспортаСообщенийОбмена = Перечисления.ВидыТранспортаСообщенийОбмена.FILE;
	ПараметрыОбмена.ВыполнятьВыгрузку = Истина;
	ПараметрыОбмена.ВыполнятьЗагрузку = Истина;

	Отказ = Ложь;
	Попытка
		ОбменДаннымиСервер.ВыполнитьОбменДаннымиДляУзлаИнформационнойБазы(Узел, ПараметрыОбмена, Отказ);
	Исключение
		ЗаписьЖурналаРегистрации("А_АвтоматическийОбмен",
			УровеньЖурналаРегистрации.Ошибка, , Узел,
			ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
		Сообщения.Добавить("Обмен с " + Строка(Узел) + ": ИСКЛЮЧЕНИЕ — "
			+ КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат Ложь;
	КонецПопытки;

	// Флагу Отказ НЕ доверяем (см. граблю 3) — читаем фактический результат.
	Сообщения.Добавить("Обмен с " + Строка(Узел) + ":");
	Возврат ДобавитьРезультатыПоУзлу(Узел, Сообщения);

// Обмен по ВСЕМ известным планам, которые есть в текущей базе.
// BuhBud -> только Бухгалтерия; BuhKazn -> только Казна; BaseERP -> обе пары.
Функция СинхронизироватьТекущуюБазу(Сообщения = Неопределено) Экспорт

	Если Сообщения = Неопределено Тогда
		Сообщения = Новый Массив;
	КонецЕсли;

	Планы = Новый Массив;
	Планы.Добавить(ПланБухгалтерии());
	Планы.Добавить(ПланКазны());

	НайденХотяБыОдин = Ложь;
	ВсеУспешно = Истина;

		Если УзелКорреспондентПлана(ИмяПлана) = Неопределено Тогда
			Продолжить;
		КонецЕсли;
		НайденХотяБыОдин = Истина;
		Если НЕ СинхронизироватьПоПлану(ИмяПлана, Сообщения) Тогда
			ВсеУспешно = Ложь;
		КонецЕсли;
	КонецЦикла;

	Если НЕ НайденХотяБыОдин Тогда
		Сообщения.Добавить(НСтр("ru='В текущей базе не найдено ни одного узла обмена с ERP.'"));
		Возврат Ложь;
	КонецЕсли;

	Если ВсеУспешно Тогда
		Сообщения.Добавить("Итог: обмен выполнен успешно.");
	Иначе
		Сообщения.Добавить("Итог: обмен завершён С ОШИБКАМИ (см. Журнал регистрации).");
	КонецЕсли;

	Возврат ВсеУспешно;

КонецФункции

```

**`ДобавитьРезультатыПоУзлу(Узел, Сообщения)` — ОСТАВИТЬ КАК ЕСТЬ** (уже работает; классификация в запросе,
см. граблю 3). В BuhKazn регистр `СостоянияОбменовДанными` и перечисление `РезультатыВыполненияОбмена`
такие же — функция работает без изменений.

### 5.2. Worker `А_ЗапуститьОбмен` — без изменений логики

`ПриСозданииНаСервере` уже зовёт `СинхронизироватьТекущуюБазу(Сообщения)`. После рефакторинга (5.1)
она сама переберёт оба плана и отработает те, что есть в текущей базе:
- в **BuhBud** — только Бухгалтерия;
- в **BuhKazn** — только Казна;
- в **BaseERP** (ручное открытие) — обе пары.

**Один `.epf` обслуживает обе базы-корреспондента.** Никаких параметров запуска (`/C`) не вводить —
это уже пробовали, `ПариметрЗапуска` на сервере недоступен, а сам подход оказался хрупким.

Пересобрать `.epf` (грабля 5) и положить в `_Rarzrabotki\Обработки\`.

### 5.3. Оркестратор `А_АвтоматическийОбменДанными` — вторая кнопка

**Form.xml:**
- В `<Commands>` добавить команду `ЗапуститьПолныйОбменКазна` (Title: «Полный обмен с Казной (Казна → ERP → Казна)»).
- В `<AutoCommandBar><ChildItems>` добавить кнопку с `<CommandName>Form.Command.ЗапуститьПолныйОбменКазна</CommandName>`.
- Существующей кнопке дать явный заголовок «Полный обмен с Бухгалтерией (Бухгалтерия → ERP → Бухгалтерия)».
- **Блок `<Events>` НЕ ТРОГАТЬ** — он там есть (`OnCreateAtServer`), без него сломается путь к worker'у.
- Все `id` элементов/команд — уникальны.

**Модуль формы:** обобщить существующий оркестратор в один метод с параметрами:

```bsl
&НаКлиенте
Процедура ЗапуститьПолныйОбмен(Команда)          // существующая кнопка
	ВыполнитьЦепочку("BuhBud", ПланБухгалтерииКлиент(), "Бухгалтерией");
КонецПроцедуры

&НаКлиенте
Процедура ЗапуститьПолныйОбменКазна(Команда)     // НОВАЯ кнопка
	ВыполнитьЦепочку("BuhKazn", ПланКазныКлиент(), "Казной");
КонецПроцедуры
```

`ВыполнитьЦепочку(ИдентификаторБазы, ИмяПлана, Подпись)`:
1. `ПараметрыПодключенияБазы(ИдентификаторБазы)` — **существующая** функция `&НаСервереБезКонтекста`,
   читает регистр `А_НастройкиПодключенияБаз`. Если строки нет — понятное сообщение и выход.
2. Шаг 1 — `ШагЗапускаБазы(...)` (существующая): запуск толстого клиента базы-корреспондента
   с `А_ЗапуститьОбмен.epf`, ожидание закрытия (код возврата 0).
3. Шаг 2 — обмен **ERP в текущей сессии**: серверный вызов `Обработка.СинхронизироватьПоПлану(ИмяПлана, Сообщения)`
   (**именно по конкретному плану**, а не по всем — иначе кнопка «Казна» дёрнет и Бухгалтерию).
4. Шаг 3 — снова `ШагЗапускаБазы(...)`.
5. Лог каждого шага в форму и в Журнал регистрации (`ЗаписатьВЖурнал` — существующая).

Имена планов на клиенте: добавить `&НаКлиентеНаСервереБезКонтекста` функции-константы
(или получать с сервера) — **строку `КазначествоBASERP` писать ровно один раз**.

**Ничего из уже работающего не удалять:** кнопка «Синхронизировать текущую базу», чтение регистра,
`КаталогПрограммы()`, реквизит `ПутьКОбработкеОбмена`, блок `<Events>`.

## 7. ПРОВЕРКА (обязательна)

**COM, безопасно (без запуска обмена):**
```python
# .epf грузится и BSL компилируется во ВСЕХ трёх базах,
# УзелКорреспондентПлана даёт ожидаемое:
#   BaseERP : Бухгалтерия -> bas_industrialbud ; Казна -> Казна
#   BuhBud  : Бухгалтерия -> BAS ERP, ред. 2.5 ; Казна -> Неопределено
#   BuhKazn : Бухгалтерия -> Неопределено      ; Казна -> BAS ERP, ред. 2.5
obr = conn.ВнешниеОбработки.Создать(путь_к_epf, False)
```

**COM, с обменом (реальный обмен — это нормальная синхронизация):**
- `obr.СинхронизироватьПоПлану(obr.ПланКазны(), Массив)` в **BuhKazn** →
  ожидаем читаемый отчёт вида
  `Обмен с BAS ERP, ред. 2.5: / Выгрузка данных: выполнено / Загрузка данных: нечего принимать` и
  **возврат `Истина`** (а не «с ошибками» — грабля 3).

**Регрессия (критично):** пара **BuhBud↔ERP** должна продолжать работать —
`СинхронизироватьПоПлану(ПланБухгалтерии())` в BuhBud и в BaseERP.

**Интерактивно (делает пользователь):** открыть `А_ЗапуститьОбмен.epf` в **BuhKazn**,
подтвердить запрос безопасности **с «Запомнить»** → обмен выполнится, через 5 сек сессия закроется.
Затем в BaseERP нажать **«Полный обмен с Казной»** → в поле результата 3 шага, коды возврата 0.

## 8. КРИТЕРИИ ГОТОВНОСТИ

- [ ] `ObjectModule` ищет узел **по плану обмена** (`УзелКорреспондентПлана`), регистр транспорта
      и маска каталога **не используются**; модуль идентичен в обеих обработках (`md5sum` совпал).
- [ ] `А_ЗапуститьОбмен.epf` при открытии в **BuhKazn** обменивается с «BAS ERP, ред. 2.5» и закрывается.
- [ ] В оркестраторе **две** кнопки; «Казна» гонит цепочку BuhKazn → ERP → BuhKazn,
      параметры BuhKazn — из регистра `А_НастройкиПодключенияБаз`.
- [ ] Шаг ERP в цепочке «Казна» синхронизирует **только план Казны** (не задевает Бухгалтерию).
- [ ] Пара **BuhBud↔ERP не сломана** (проверено явно).
- [ ] «Нечего принимать» **не** показывается как ошибка.
- [ ] Обе `.epf` пересобраны (размер ~9–13 КБ, **не** 65536), лежат в основной конфигурации.
- [ ] Блок `<Events>` в обеих формах на месте.
- [ ] Пользователь предупреждён: хеш `.epf` изменился → при первом запуске подтвердить безопасность
      с «Запомнить» (в BuhKazn — впервые).
