## 1. Цель

В справочнике `Справочник.А_Статьи_PL` табличная часть `Статьи` имеет две колонки:

| Колонка ТЧ | Тип |
|---|---|
| `СтатьяДвиженияДенежныхСредств` | `СправочникСсылка.СтатьиДвиженияДенежныхСредств` |
| `СтатьяРасходов` | `ПланВидовХарактеристикСсылка.СтатьиРасходов` (добавлена, в базу загружена) |

Для `СтатьяДвиженияДенежныхСредств` в `ПередЗаписью` модуля объекта уже работает «правило 4»: одна ДДС не может стоять в ТЧ двух разных PL-статей, если по этой ДДС есть обороты в `РегистрНакопления.ПрочиеРасходы` за последние 12 месяцев. Без оборотов дубль разрешён (shared-ДДС).

**Нужно добавить такую же проверку для `СтатьяРасходов`**: одна статья расходов не может стоять в ТЧ двух разных PL-статей, если по ней есть обороты в `ПрочиеРасходы` за 12 месяцев. При нарушении — `ВызватьИсключение` с понятным текстом, запись отказывается.

## 2. Решение пользователя, которое нельзя пересматривать

1. **Автозаполнение остаётся всегда.** Строка в `ПередЗаписью`
   `СтрокаТЗ.СтатьяРасходов = СтрокаТЗ.СтатьяДвиженияДенежныхСредств.А_СтатьяРасходов;`
   не трогать: при каждой записи `СтатьяРасходов` перезаписывается из реквизита `А_СтатьяРасходов` выбранной ДДС. Ручной выбор на форме затирается — это осознанно.
2. **Проверка зеркалит правило 4 для ДДС**, включая исключение «дубль без оборотов разрешён».
3. **Проверка выполняется ПОСЛЕ автозаполнения.** Иначе она увидит значения до перезаписи.
4. **Последствие принято.** С момента загрузки перестанут записываться PL-статьи, у которых `СтатьяРасходов` уже дублируется с оборотами. Замер 2026-09-02 (окно 2025-09-01 … 2026-09-30):

   | СтатьяРасходов | В скольких PL | Обороты 12 мес, ₴ |
   |---|---|---|
   | Інші послуги | 9 | 10 983 212,72 |
   | Амортизація ОЗ | 2 | 2 053 367,51 |
   | Дозвільна документація | 2 | 100 390,00 |

   Итого 13 PL-статей. Их разводит финансист (правит `А_СтатьяРасходов` у ДДС или убирает строку из ТЧ). Ты обязан вывести актуальный список этих статей в финальном отчёте (см. п. 8).

Не входит в задачу: проверка на форме в момент выбора, чистка существующих дублей, изменения отчётов `А_ОтчетPL*` (они связывают PL с фактом через ДДС, `СтатьяРасходов` из ТЧ не читают), любые правки блока ДДС.
