# Промт: ВРМ в разделе «Производство» + права профиля «Менеджер производства»

## Задача

Документ `Документы.А_ВыполнениеРаботМодулей` (ВРМ):
1. Вывести команду списка в раздел **«Производство»**, группа **«Внутрицеховой учет»** (рядом с «Документы производства (все)»).
2. Дать пользователям профиля **«Менеджер производства»** (Справочник.ПрофилиГруппДоступа) право открывать, создавать и **проводить** документ — через новую роль, включённую в этот профиль.
3. Роль-маркер `А_ВыполнениеРаботПросмотрЧасов` таким пользователям НЕ выдавать — они не должны видеть колонки ПланЧасы/ЧасыВыполнение (механизм скрытия уже в БД, коммит `0f41cae14c`).
4. Прогнать тест на пользователе **«Менеджер ПТО»** (уже включён в группу доступа «Менеджер производства»).

Работать в worktree от текущего состояния; правки переносить в `C:\Configuration_downloads\BASERP25` (Rule #4). Перед финалом — `bas-verify`.

## Разведка уже сделана (2026-07-16, не переоткрывать — только перепроверить)

- Документ НЕ входит ни в одну подсистему (grep `А_ВыполнениеРаботМодулей` по `Subsystems/` — 0 совпадений) и НИ ОДНА роль не даёт на него прав (grep `Document.А_ВыполнениеРаботМодулей` по `Roles/` — 0). Сейчас его видят только полноправные.
- В `Documents/А_ВыполнениеРаботМодулей.xml`: `PostInPrivilegedMode=true`, `UnpostInPrivilegedMode=true` → права Update на регистры движений (РН `А_ВыполнениеРаботМодулей`, РС `А_ПроцентыВыполненияМодулей`) для проведения НЕ нужны. `RealTimePosting=Deny`.
- Подсистема раздела: `Subsystems/Производство.xml`, дочерние в `Subsystems/Производство/Subsystems/`; кандидат для размещения — **`ВнутрицеховойУчет.xml`** (без версионного суффикса, в отличие от `ВнутрицеховоеУправление2_1/2_2`). Перед правкой проверить через `subsystem-info`, что именно она даёт группу «Внутрицеховой учет» из скриншота пользователя, и посмотреть её Content.
- Профиль «Менеджер производства»: 135 ролей, среди них `ПодсистемаПроизводство` (раздел пользователю уже виден), `ДобавлениеИзменение*`-роли — типовая конвенция имён. Пользователь «Менеджер ПТО» существует, включён в группы «Менеджер по закупкам» и «Менеджер производства».
- Форма документа при заполнении читает запросом справочник `А_СтруктураСебестоимости` (ТЧ Работы: Работа/Количество/Этап) — запросы модуля формы идут с правами пользователя → роли нужен Read (+View для выбора в шапке) на этот справочник. Проверить через `meta-info` тип реквизита `Этап` ТЧ Работы документа: если ссылочный на кастомный объект — добавить Read/View и на него.
- Скрытие колонок часов работает через `УстановитьВидимостьЧасов()` в ПриСозданииНаСервере формы: `РольДоступна("ПолныеПрава") ИЛИ РольДоступна("А_ВыполнениеРаботПросмотрЧасов")`. У Менеджера ПТО не будет ни того, ни другого → колонки скроются. Ничего дорабатывать не нужно — только протестировать.

## Дизайн (утверждён)

### 1. Роль доступа `А_ДобавлениеИзменениеВыполненияРаботМодулей`

Синоним «А: Добавление и изменение выполнения работ модулей» (ru + uk, как у `А_ВыполнениеРаботПросмотрЧасов`). Права:
- `Document.А_ВыполнениеРаботМодулей`: Read, View, InputByString, Add, Update, Edit, InteractiveInsert, Posting, InteractivePosting, UndoPosting?, InteractiveUndoPosting? — проведение нужно обязательно; отмену проведения дать (иначе не исправить ошибочный снимок). Пресет `@edit` навыка role-compile + проверить, что Posting/InteractivePosting вошли.
- `Catalog.А_СтруктураСебестоимости`: @view (Read, View, InputByString).
- Регистры движений (`AccumulationRegister.А_ВыполнениеРаботМодулей`, `InformationRegister.А_ПроцентыВыполненияМодулей`): только **Read** (для «Движения документа» и отчётов; запись — привилегированная, Update не давать).
- Кастомный справочник Этапа (если реквизит ссылочный — по итогам meta-info): @view.
- RLS не задавать (доступ без ограничений по организациям — осознанно).

⚠️ Память [[role_compile_configuration_xml_gotcha]]: скрипт role-compile ПЕРЕЗАПИСЫВАЕТ весь Configuration.xml (нормализация `<X/>`→`<X />`). После генерации: `git checkout -- Configuration.xml` и вставить `\t\t\t<Role>Имя</Role>` хирургически PowerShell-заменой (якорь `<Role>А_ВыполнениеРаботПросмотрЧасов</Role>`, count=1, UTF8-BOM). В основной каталог Configuration.xml целиком НЕ копировать (там незакоммиченные объекты визирования) — только та же вставка одной строки.

### 2. Размещение в разделе

Добавить `Document.А_ВыполнениеРаботМодулей` в Content подсистемы `Производство` → `ВнутрицеховойУчет` через `subsystem-edit` (+ `subsystem-validate`). Командный интерфейс не трогать — команда появится в группе автоматически (видимость по ролям = авто); порядок настроить через `interface-edit` только если попадёт в неудачное место.

### 3. Включение роли в профиль (данные, не метаданные)

После загрузки конфигурации добавить роль в профиль «Менеджер производства» **COM-скриптом** (Python, `_Rarzrabotki/Python/test/`):
1. Найти в `Справочник.ИдентификаторыОбъектовМетаданных` элемент с `ПолноеИмя = "Роль.А_ДобавлениеИзменениеВыполненияРаботМодулей"`. Если не найден — новые идентификаторы регистрируются БСП при первом запуске клиента после обновления: открыть базу администратором (Start-Process, НЕ computer-use) и/или вызвать штатное обновление; перепроверить.
2. `ПрофильОбъект = <профиль>.ПолучитьОбъект()`; `СтрокаТЧ = ПрофильОбъект.Роли.Добавить(); СтрокаТЧ.Роль = <идентификатор>`; `Записать()` — БСП при записи пересчитает права групп доступа. Профиль пометится «изменён относительно поставляемого» — это ожидаемо, зафиксировать в ответе пользователю.
3. Контроль: перечитать ТЧ Роли профиля запросом; убедиться что роль-маркер `А_ВыполнениеРаботПросмотрЧасов` в профиле НЕ появилась.

### 4. Загрузка и порядок

1. Правки метаданных: роль (2 файла + строка в Configuration.xml) + подсистема `Subsystems/Производство/Subsystems/ВнутрицеховойУчет.xml`.
2. Перенос в основную конфигурацию (Rule #4; Configuration.xml — только вставка строки).
3. `db-load-xml` partial: `Configuration.xml, Roles/А_ДобавлениеИзменениеВыполненияРаботМодулей.xml, Subsystems/Производство/Subsystems/ВнутрицеховойУчет.xml` + `db-update` (монополия: Конфигуратор и клиенты закрыть; фоновые задания транзиентны — повторить с паузой).
4. COM-скрипт п.3.
5. Smoke COM: роль в метаданных; ТЧ Роли профиля содержит новую роль.

## Ограничения / заметки

- Роль даёт доступ к ВРМ без RLS-разрезов (организации/подразделения) — для этого контура приемлемо.
- Отмена проведения чужих периодов не ограничивается (дат запрета для ВРМ нет) — вне охвата.
- Часы остаются видны в отчёте план-факт — вопрос прав на отчёты вне охвата этой задачи.
