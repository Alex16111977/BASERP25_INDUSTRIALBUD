## 2. Цель

Создать в конфигурации **новый документ `РасчетКомплектаций`** (синоним «Розрахунок комплектацій за СС») — сохраняемое рабочее место списания материалов по нормам `СтруктураСебестоимости`. Документ повторяет логику обработки, но:

1. **Расчёт сохраняется в базе** — видно, по каким нормам/понаднорме/экономии были созданы комплектации и передачи малоценки;
2. Появляются **две новые закладки-ТЧ**: «Списання за нормами» (read-only) и «Списання понад норму» (**редактируемая**: менять количество, добавлять строки);
3. Документы `КомплектацияНоменклатуры` / `ПередачаМалоценныхАктивовВЭксплуатацию` создаются кнопками **из сохранённых таблиц списания** (ручные правки понаднормы попадают в документы);
4. Все 5 печатных форм обработки переносятся + **новая** «Акт на списання понаднормових матеріалів».

Сценарий пользователя: создать документ → заполнить настройки → «Розрахувати» → смотреть закладки «Загальний розрахунок» / «За нормами» / «Понад норму» (понаднорму при необходимости отредактировать) → «Створити документи» (3 режима) → печать.

## 3. Не-цели

- Обработку НЕ выводим из эксплуатации, её файлы НЕ трогаем (работает параллельно).
- Типовые объекты конфигурации структурно НЕ меняем (КомплектацияНоменклатуры, ПередачаМалоценныхАктивовВЭксплуатацию, регистры — только запись данных, как делала обработка).
- Документ НЕ проводится и НЕ делает движений (Posting=Deny) — учётное списание делают созданные комплектации/передачи.
- Математику распределения (жадный алгоритм, кап по эталону, приоритет норм-карточек, НДС ×1.2) НЕ меняем — порт 1:1.

## 4. Метаданные

### 4.1 Документ `РасчетКомплектаций`

Непроводимый (Posting=Deny), нумератор стандартный. Синонимы всех реквизитов/ТЧ/колонок — украинские (как в обработке).

**Шапка:**

| Реквизит | Тип | Примечание |
|---|---|---|
| `Спецификация` | CatalogRef.СтруктураСебестоимости | обязательный |
| `Период` | Дата | дата остатков; по умолчанию = дата документа |
| `Организация` | CatalogRef.Организации | опциональный, пусто = все (ИЛИ-паттерн, как в обработке) |
| `ИсключатьЭтапы` | Булево | |
| `Статус` | EnumRef.СтатусыРасчетаКомплектаций | см. 4.2; управляется движком |
| `Ответственный` | CatalogRef.Пользователи | текущий пользователь при создании |
| `Комментарий` | Строка (0) | |

**ТЧ — порт из обработки, имена и колонки 1:1** (включая украинские `ЕкономіяСума`, `ДокументиКомплектації`, `ДокументиМалоценки` — чтобы движок и СКД-макеты портировались без переименований):

| ТЧ | Колонки |
|---|---|
| `СкладыОстатков` | Склад |
| `СчетаОстатков` | Счет (ChartOfAccountsRef.Хозрасчетный); дефолт 20/28 при создании |
| `СчетаМалоценки` | Счет; дефолт 22 |
| `Этапы` | Этап (CatalogRef.ЭтапыРабот) |
| `ТабличнаяЧастьОстатков` | 19 колонок как в обработке: Номенклатура, ОбщееНазвание, Склад, Счет, Остаток, Норма, ВНорме, ПонадНорму, Экономия, Единица, ЕдиницаСС, СуммаОстатка, НормаСумма, ВНормеСумма, ПонадНормуСумма, ЕкономіяСума, НормаНоменкл, НормаСуммаНоменкл, Этап. Снапшот «Загальний розрахунок», read-only на форме |
| `ДокументиКомплектації` | Склад, ДокументПоНормам, ДокументДодаткова (DocumentRef.КомплектацияНоменклатуры) |
| `ДокументиМалоценки` | Склад, ДокументПоНормам, ДокументДодаткова (DocumentRef.ПередачаМалоценныхАктивовВЭксплуатацию), ФизЛицо, СпособОтраженияРасходов |

**ТЧ новые (суть задачи):**

| ТЧ | Колонки | Поведение |
|---|---|---|
| `СписаниеПоНормам` («Списання за нормами») | Номенклатура, ОбщееНазвание, Склад, Счет, Единица, Количество (15,3), Цена (15,2), Сумма (15,2) | read-only; заполняется расчётом из строк ВНорме>0 |

**Суммы в таблицах списания — БЕЗ НДС** (raw себестоимость, ровно то, что уйдёт в документы): Сумма = Окр(ВНормеСумма или ПонадНормуСумма / КоэффициентНДС(), 2); Цена = Сумма/Количество. (В `ТабличнаяЧастьОстатков` суммы остаются С НДС ×1.2 — как в обработке, для отчётов.)

### 4.2 Перечисление `СтатусыРасчетаКомплектаций`

Значения: `Черновик` («Чернетка»), `РасчетВыполнен` («Розрахунок виконано»), `ДокументыСозданы` («Документи створено»). При создании документа — Черновик.

## 5. Форма документа

«Единое окно» по контракту bas-bsp-form. Закладки:

1. **Налаштування** — Организация, Спецификация, Период, ИсключатьЭтапы; таблицы СкладыОстатков, СчетаОстатков, СчетаМалоценки, Этапы.
2. **Загальний розрахунок** — рабочее место как в обработке: форм-ValueTable `ТаблицаАнализа` поверх ТЧ + группа «Відбір» (ОтборСклад, ОтборЭталон, ТолькоПонадНорму, Пошук-substring) + группа «Підсумки» (Залишок/В нормі/Понад/Економія + суммы) + кнопки «Фільтр за полем»/«Скинути» + УО подсветка ПонадНорму>0. Паттерн `ПрименитьОтборИИтоги` (клиент) переносится 1:1.
3. **За нормами** — ТЧ СписаниеПоНормам (ViewOnly) + итоги в подвале (Количество, Сумма).
4. **Понад норму** — ТЧ СписаниеСверхНормы (редактируемая, добавление строк) + итоги в подвале.
5. **Документи** — таблицы ДокументиКомплектації и ДокументиМалоценки (у малоценки + ФизЛицо, СпособОтраженияРасходов).

**Командная панель:** кнопка **«Розрахувати»**; Popup **«Створити документи»** (Разом за нормами і понад / Тільки за нормами / Тільки понад норму); Popup **«Друк»** (6 команд: Друк аналізу, Друк аналізу СС, Друк аналізу СС (1 од.), Друк план-факту, Друк аналізу СС за етапами, **Акт на списання понаднормових матеріалів**).

Шапка формы: Номер/Дата/Статус (read-only, обновляется движком)/Ответственный/Комментарий.

Форма списка: стандартная + колонки Спецификация, Период, Статус, Ответственный.

## 6. Движок (модуль объекта документа)

Порт ObjectModule обработки → модуль объекта документа. Контекст `ЭтотОбъект` и имена реквизитов сохранены → дифф минимален. Убирается только `СведенияОВнешнейОбработке()` (БСП-регистрация не нужна документу).

- **`РассчитатьАнализ()`** — порт 1:1 (ПолучитьОстатки, ПолучитьНормы, ЗаполнитьАнализ, ДополнитьСкладыДокументов для обеих ТЧ документов) **+ новый шаг `ЗаполнитьТаблицыСписания()`**: очистить и заполнить СписаниеПоНормам (строки ВНорме>0) и СписаниеСверхНормы (ПонадНорму>0), суммы без НДС; Статус=РасчетВыполнен.
- **`ЗаполнитьДокументыПоАнализу(ЗаполнятьВНорме, ЗаполнятьПонад)`** — **ключевое отличие от обработки**: источник строк — ТЧ `СписаниеПоНормам` → ДокументПоНормам и `СписаниеСверхНормы` → ДокументДодаткова (т.е. ручные правки попадают в документы). Семейство по счёту строки: классификатор `СчетМалоценки()` (подъём по Родитель) → малоценка или комплектация — порт Фазы 17. Автозаполнение малоценки (НалоговоеНазначение=НДС_Облагаемая, ФизЛицо, НазначениеИспользования по Владелец+СпособОтраженияРасходов, кеш одним запросом) — порт Фазы 17b. Транзакционный оркестратор всё-или-ничего, структура-результат {Заповнено, Пропущено, БезЕдиниці, БезНазначення, Помилки}, лог ЖР, идемпотентность (Очистить ТЧ целевых документов) — 1:1. При успехе (Заповнено>0) Статус=ДокументыСозданы.
- **`СформироватьПечать*`** — 5 функций + `ДанныеВТаблицуПланФакт` + `ДанныеПоЭтапам` (по-этапная розшивка) + `ТекстЗаголовкаЗвіту` портируются; 4 СКД-макета → Templates документа (**новые уникальные UUID** — грабля §39!).
- **Новая `СформироватьПечатьАкт()`** — программный ТабличныйДокумент по ТЧ СписаниеСверхНормы: шапка «АКТ на списання понаднормових матеріалів № / дата», Организация, Спецификация, Склады, Период; таблица (№, Номенклатура, Склад, Рахунок, Од., Кількість, Ціна, Сума, Причина); итог; подписи «Голова комісії ___ / Члени комісії ___ ___ / МВВ ___». Грабли программного ТабДок известны (§ границы по сторонам, Объединить для шапки).
- **`ПередЗаписью`** — контроль дублей: другой не помеченный `РасчетКомплектаций` с той же Спецификацией, той же датой Период (день) и пересечением складов → предупреждение `Сообщить` (НЕ отказ). При новом документе `ПриЗаполнении` — Статус=Черновик, Ответственный=текущий, дефолтные счета 20/28 и 22.

## 7. Поведение формы (редактирование понаднормы)

- Изменение `Количество` в СписаниеСверхНормы → `Сумма = Окр(Количество × Цена, 2)`.
- Добавление строки: при выборе Номенклатуры (и Склада) — серверный автоподбор из остатков Хозрасчетного на дату Период по счетам обоих списков: Счет, Цена (raw без НДС = СуммаОстаток/КоличествоОстаток), Единица (базовая), ОбщееНазвание.
- Если Количество > доступного остатка (Номенклатура+Склад+Счет на Период) → предупреждение (НЕ блокировка).
- «Розрахувати» при Статус=ДокументыСозданы → вопрос-подтверждение («Документи вже створено, перезаповнити розрахунок?») перед перезаполнением.
- Причина — свободный текст, попадает в Акт.

## 11. Критерии приёмки

1. Документ создаётся в клиенте, расчёт по эталону FINDINGS даёт баланс 0 и заполненные три расчётные закладки.
2. Понаднорма редактируется (количество, новые строки с автоподбором), правки попадают в созданные документы.
3. Комплектации и передачи малоценки создаются по складам/режимам/семействам счетов, поля малоценки автозаполнены, суммы без НДС.
4. Ссылки на созданные документы хранятся в документе; Статус отражает этап; пересчёт после создания — только с подтверждением.
5. Все 6 печатных форм работают из документа.
6. Контроль дублей предупреждает.
7. Smoke-скрипты зелёные; `db-update` прошёл; обработка-источник не изменена.
