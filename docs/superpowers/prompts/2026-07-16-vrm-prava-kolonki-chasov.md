# Промт: права на просмотр часов в документе А_ВыполнениеРаботМодулей

## Задача

В документе `Документы.А_ВыполнениеРаботМодулей` (форма документа — динамическая матрица) скрыть колонки **Матрица.ПланЧасы** и **Матрица.ЧасыВыполнение** от пользователей, у которых нет специального права. Право реализовать штатным для конфигурации способом — ролью. Пользователь с полными правами или с новой ролью видит колонки; все остальные — нет.

Работать в worktree через `EnterWorktree`, ветка от `claude/main`. Перед любой правкой формы прочитать навык `bas-bsp-form`; перед финалом — `bas-verify`.

## Контекст объекта (изучить, но не переоткрывать)

- Документ: `Documents/А_ВыполнениеРаботМодулей/` (ObjectModule.bsl, ФормаДокумента, ФормаСписка).
- Это «снимок % выполнения по модулям»: ТЧ `Работы` нормализована (Работа × НомерМодуля × Процент + ПланЧасыМодуля + ЧасыВыполнение), на форме pivot в реквизит формы `Матрица` (ТаблицаЗначений, SavedData=true).
- В `Forms/ФормаДокумента/Ext/Form.xml` колонки матрицы СТАТИЧЕСКИЕ элементы:
  - `МатрицаРабота`, `МатрицаЭтап`, `МатрицаПланЧасы` (DataPath `Матрица.ПланЧасы`), `МатрицаЧасыВыполнение` (DataPath `Матрица.ЧасыВыполнение`), `МатрицаКомментарий`;
  - плюс поля итогов `ИтогоПланПоле` (DataPath `ИтогоПлан`) и `ИтогоВыполнениеПоле` (DataPath `ИтогоВыполнение`) — они показывают ТЕ ЖЕ часы, прятать вместе с колонками.
- Динамические колонки модулей `МатрицаМ1..М_N` создаются кодом в `Module.bsl` и вставляются ПЕРЕД `МатрицаЧасыВыполнение`:
  `Элементы.Переместить(Элементы["МатрицаМ" + Н], Элементы.Матрица, Элементы.МатрицаЧасыВыполнение)` (~строка 305).
  **Поэтому элементы колонок УДАЛЯТЬ НЕЛЬЗЯ — только `Видимость = Ложь`** (иначе якорь вставки пропадёт).
- Точки входа формы: `ПриСозданииНаСервере` (~стр. 10), `ПриЧтенииНаСервере` (~28, перестраивает матрицу), `ПослеЗаписиНаСервере` (~72). Видимость ставить ОДИН раз в `ПриСозданииНаСервере` — пересоздание динамических колонок видимость статических не трогает (проверить).
- В `ФормаСписка` колонок часов нет — не трогать.

## Как ведутся права в конфигурации (изучить перед кодом)

1. Ролей ~1211, все типовые + одна кастомная роль-маркер `А_Гермес` (`Roles/А_Гермес/Ext/Rights.xml`) — используется как флаг: `НЕ РольДоступна("А_Гермес")` в `CommonModules/А_СобытияОбъектов/Ext/Module.bsl:755,773`.
2. Типовой паттерн видимости/доступности по ролям в этой конфигурации:
   - `ВзаиморасчетыСервер:4977` — `РольДоступна("ЗачетОплаты") ИЛИ РольДоступна("ПолныеПрава")`;
   - `А_ВизированиеСервер:210` — `РольДоступна("ПолныеПрава") ИЛИ РольДоступна("А_ВизированиеАдминистратор")`.
3. Выдача ролей пользователям — через БСП «Управление доступом»: роль включается в **профиль групп доступа** (справочники `ПрофилиГруппДоступа` / `ГруппыДоступа`) в режиме предприятия. Кодом ничего выдавать не нужно — только создать роль в метаданных.
4. ⚠️ **Антипример — не повторять**: роль `А_ВизированиеАдминистратор` упоминается в коде, но в `Roles/` её XML НЕТ. `РольДоступна()` по несуществующей роли кидает исключение. Новую роль СНАЧАЛА создать в метаданных, ПОТОМ ссылаться в коде.
5. Данные ТЧ при этом остаются читаемыми (право Чтение на документ не режем): скрытие колонок — интерфейсная мера, часы по-прежнему видны в отчёте план-факт, через СКД/запросы. Это осознанное ограничение — RLS/урезание прав на объект НЕ делать (сломает проведение и отчёты).

## Дизайн решения (утверждён)

1. **Новая роль-маркер** `А_ВыполнениеРаботПросмотрЧасов`, синоним «А: Выполнение работ — просмотр часов». Прав на объекты НЕ содержит (пустой Rights.xml, как у роли-флага); `SetForNewObjects=false`, независимые права подчинённых объектов — как у `А_Гермес` (взять её Rights.xml за образец «пустой» роли).
2. **Форма документа**, `ПриСозданииНаСервере`, серверная функция/блок:

```bsl
ЧасыВидны = РольДоступна("ПолныеПрава") ИЛИ РольДоступна("А_ВыполнениеРаботПросмотрЧасов");
Элементы.МатрицаПланЧасы.Видимость        = ЧасыВидны;
Элементы.МатрицаЧасыВыполнение.Видимость  = ЧасыВидны;
Элементы.ИтогоПланПоле.Видимость          = ЧасыВидны;
Элементы.ИтогоВыполнениеПоле.Видимость    = ЧасыВидны;
```

   (точный вид блока — по месту; НЕ объявлять переменную `Ссылка`; стандарты — навык `1c-bsl-standards`).
3. Семантика: роль никому не выдана → часы видят только полноправные. Выдача — добавлением роли в профиль групп доступа администратором.

## Шаги

1. `EnterWorktree` → изучить перечисленные файлы (проверить актуальные номера строк, не верить слепо).
2. Создать роль: навык `role-compile` (образец пустых прав — `Roles/А_Гермес/Ext/Rights.xml`), включить в `Configuration.xml` (ChildObjects) через `cf-edit`. Проверка `role-validate`.
3. Править `Forms/ФормаДокумента/Ext/Form/Module.bsl` (только видимость, матричную логику не трогать). Проверки: `form-validate`, `/1c-bsl-review` на диф.
4. Rule #4: скопировать все изменённые файлы в `C:\Configuration_downloads\BASERP25\` (Configuration.xml, Roles/А_ВыполнениеРаботПросмотрЧасов.xml + Roles/А_ВыполнениеРаботПросмотрЧасов/Ext/Rights.xml, Module.bsl формы). Line endings — CRLF (память: после записи проверить, Designer чувствителен).
5. Загрузка в базу: навыки `db-load-xml` (partial: Configuration.xml + XML роли + файлы формы; грабли новых объектов — без Configuration.xml роль не появится) и `db-update` (нужна монополия: закрыть Конфигуратор и клиенты).
6. Smoke через Python COM (`_Rarzrabotki/Python/test/`): роль существует в метаданных (`erp.Метаданные.Роли.А_ВыполнениеРаботПросмотрЧасов`), `РольДоступна("А_ВыполнениеРаботПросмотрЧасов")` не падает под Администратором. Форму через COM не открыть — визуальную проверку колонок делает ПОЛЬЗОВАТЕЛЬ под тестовым пользователем без роли (клиент запускать `Start-Process`, скриншоты просить у пользователя — управление компьютером не перехватывать).
7. Финал: `bas-verify`, git-финал автономно (merge в `claude/main`), пользователю — короткая инструкция «как выдать право» (Администрирование → Настройки пользователей и прав → Профили групп доступа → добавить роль в нужный профиль).

## Критерии приёмки

- [ ] Роль `А_ВыполнениеРаботПросмотрЧасов` есть в метаданных, конфигурация БД обновлена без ошибок.
- [ ] Пользователь БЕЗ роли и без ПолныхПрав: в форме документа не видит колонок ПланЧасы/ЧасыВыполнение и полей итогов; матрица М1..М_N (проценты) работает как раньше, запись/проведение не сломаны.
- [ ] Пользователь с ролью или ПолныеПрава: видит всё как сейчас.
- [ ] Смена СС/перечитывание документа (пересоздание динамических колонок) не возвращает скрытые колонки.
- [ ] В ответе пользователю зафиксировано ограничение: это скрытие в форме, не запрет на данные (отчёты/СКД часы покажут).
