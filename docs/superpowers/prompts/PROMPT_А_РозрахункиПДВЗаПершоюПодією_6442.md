## 0. Проблема и факты (проверено на живой базе 28.09.2026)

**Счёт.** 6442 = `ПланСчетов.Хозрасчетный.НалоговыйКредитНеподтвержденный`. Субконто: Контрагенты / Договоры / Документы расчётов
с контрагентами (у нас это обычно «Рахунок на оплату постачальника» = «заказ»; пусто — договор «по договору в целом»).
Проводки первого события: поступление `Дт 6442 Кт 631` («…, первое событие»), оплата-аванс `Дт 6442 Кт 6441`
(«НДС: налоговый кредит, оплата»); второе событие — `Дт 6441 Кт 631` или без НДС. Регистрация ПН закрывает `Дт 6412 Кт 6442`.

**Кто решает «первое/второе».** `НалоговыйУчет.ДвиженияПоРегистрамНалоговогоУчетаУпрощенныйНалоговыйУчет` читает
`РегистрНакопления.ПриобретенияНалоговыйУчет.Остатки(&МоментВремени, ДоговорКонтрагента В (..) И Сделка В (..))` на момент
ДОКУМЕНТА и считает `ПС = max(поступл., оплаты)_после − max(поступл., оплаты)_до`. Ключ остатков: Организация,
ДоговорКонтрагента, Сделка, ВозвратнаяТара, СтавкаНДС, ДляХозяйственнойДеятельности, ВидДеятельностиНДС, Амортизируется.
Документ, проведённый в базе РАНЬШЕ своего «соседа» с более ранней датой, не видит его и навсегда остаётся первым событием →
задвоение 6442. Лечится только перепроведением позднего по дате документа пары. Автоматики нет.

**Пример пользователя (подтверждён):** ключ АВТОСВІФТ ТОВ / «Рахунки_перевез МД IRS 2026» / «Рахунок на оплату постачальника
ІБ00-003315 от 03.08.2026». ПТУ `ІБ00-003958` от 03.08.2026 — `Дт 6442 Кт 631 433,33` «первое событие»; списание с р/с
`000013825` от 23.09.2026 — «Оплата (аванс)» `Дт 631 Кт 311` + `Дт 6442 Кт 6441 433,33`. Сальдо 6442 по ключу 433,33 Дт.
Журнал регистрации: 28.09 06:07 ПТУ распроведено → оплата проведена → ПТУ проведено (порядок «в разнобой»).

**Детектор (прототип, 2026 год, гривневые договоры):** регистр `ПриобретенияНалоговыйУчет` пишется ОДИНАКОВО при любом порядке
(полные суммы событий), «Закриття місяця» сворачивает обе стороны на одну сумму (на ПС не влияет). Поэтому правильную ПС каждого
документа можно пересчитать хронологическим проходом и сравнить с фактом `ОжидаемыйИПодтвержденныйНДСПриобретений`
(`КодОперации = ОжидаемыйНДС`, событие `Возврат` — со знаком «−»). Итог прогона прототипа с полным ключом регистра:
12 757 документов, **62 ошибочных в 34 ключах**, чистый излишек ПС ≈ **508 тыс. грн** (крупнейший ключ — АЛМЕТ/ІБ00-000707
+306 тыс.; ~12 ключей — сентябрь, т.е. открытый период; остальные ≤ 31.08). Пример 000013825 пойман: ожидалось 0, факт 433,33.
Есть ключи с нулевым итогом, но ошибочными документами (возврат товара + возврат оплаты одним документом, «ничьи» одинакового
времени) — показывать, но сортировать по |Отклонение|. Кроме ПТУ/ССРС ошибаются: Коригування боргу, Повернення постачальнику, Надходження на р/р
(повернення оплати), Надходження дод. витрат. Валютных движений в регистре 6 из 24 тыс. — **валютные договоры исключить**
(ОиП для них не пишется → ложные срабатывания).

**Прочее:**
- Объём «полного месяца»: ~1 500–1 800 документов-регистраторов `ПриобретенияНалоговыйУчет` (июль 1 790, август 1 610).
- Штатная последовательность `ДокументыОрганизаций` бесполезна как индикатор: ~34 тыс. документов «з порушенням послідовності».
- Дата запрета изменения «Для всіх користувачів» = **31.08.2026** (`РегистрСведений.ДатыЗапретаИзменения`), у `cfo` — 01.01.2020.
- **Перепроведение в BuhBud ставит документ в очередь обмена на узел «BAS ERP, ред. 2.5»**
  (`ПланОбмена.ОбменУправлениеПредприятиемБухгалтерия20`, код «Ц»; авторегистрация «Запретить» — регистрирует подписка/правила).
  Проверено на паре из примера. Штатно в очереди сейчас 29 ПТУ и 152 ССРС. **ЕРП не изучать** — не нужно (указание пользователя).

### 2.2 `Функция Анализировать() Экспорт` — детектор
Запросы брать из прототипа 1:1 (`QUERY_MOVES`, `QUERY_FACT`), добавить отборы `Организация`/`Контрагент`/`Договор` (если заданы).
1. Вход: остатки `ПриобретенияНалоговыйУчет.Остатки(&ДатаНачала, ДоговорКонтрагента.ВалютаВзаиморасчетов = &Гривня)` по ключу и
   `Событие` + движения за `[ДатаНачала; КонецДня(ДатаОкончания)]`, `Активность`, гривневые договоры.
   **Порядок внутри ключа — `Рух.МоментВремени`** (как видит конфигурация: остатки на МоментВремени документа исключают
   документы с тем же `Период` и бóльшей ссылкой). Прототип сортирует по Регистратору — в BSL сортировать по МоментВремени.
2. Проход по ключу: `O` = Поступление − ВозвратПоставщику, `P` = Оплата − ВозвратОплаты (по `СуммаНДС`). Вход и движения
   `ЗакрытиеМесяца` меняют O/P **без** ожидаемой ПС. По каждому прочему документу (суммы его строк по ключу):
   `Ожидаемо = max(O+dO, P+dP) − max(O, P)`; `Факт` = сумма ОиП `ОжидаемыйНДС` этого регистратора по ключу
   (`СобытиеНДС = Возврат` → минус). Расхождение: `|Факт − Ожидаемо| > 0,05`.
3. Результат: в `Ключи` — только ключи, где есть хотя бы один документ с расхождением; в `Документы` — **все** документы этих
   ключей хронологически (контекст), с `ЕстьРасхождение`. `Сальдо6442` — остаток 6442 на `КонецДня(ДатаОкончания)` по
   (Организация, Субконто1 = Владелец договора, Субконто2 = Договор, Субконто3 = Сделка-или-пусто).
4. Галки по умолчанию: `Документы.Отметка = ЕстьРасхождение И (НЕ ЗакрытыйПериод ИЛИ РазрешитьЗакрытыйПериод)`;
   `Ключи.Отметка = есть отмеченные документы ключа`. `ЗакрытыйПериод = Дата ≤ ГраницаЗапрета`.
5. Возврат: Структура(`КлючейСРасхождением, ДокументовСРасхождением, Отклонение, ВсегоДокументов`).
Проход — в BSL по `Выборке` (не ТЗ в памяти целиком), `Соответствие` состояний по ключу, ключ-строка через `XMLСтрока` по 8 измерениям.

### 2.3 Перепроведение — одно ядро для формы и ночи
`Функция ПерепровестиДокументы(МассивДокументов) Экспорт` → ТЗ протокола. Документы упорядочить по `МоментВремени`.
Для каждого — `ПровестиДокументСЗащитойОбмена(ДокСсылка)`:
1. Узлы: все `ПланОбмена.ОбменУправлениеПредприятиемБухгалтерия20` где `НЕ ЭтотУзел И НЕ ПометкаУдаления`.
2. **До записи** запомнить по каждому узлу `ПланыОбмена.ИзменениеЗарегистрировано(Узел, ДокСсылка)` (или запрос к
   `Документ.<Имя>.Изменения` — как в `РегистрацияИзмененийДляОбменаДанными`).
3. Провести как штатное групповое перепроведение: `ДокОбъект = ДокСсылка.ПолучитьОбъект()` (Неопределено → «ПОМИЛКА: битая
   ссылка»); `ДополнительныеСвойства.Вставить("ГрупповоеПерепроведение", Истина)`; `ПроверитьЗаполнение()`;
   `Записать(РежимЗаписиДокумента.Проведение, РежимПроведенияДокумента.Неоперативный)`. Каждый документ — своя `Попытка`,
   ошибка не останавливает прогон; сообщения пользователю собрать в статус (`ПолучитьСообщенияПользователю(Истина)`).
4. **После записи**: если документ НЕ был зарегистрирован на узле — `ПланыОбмена.УдалитьРегистрациюИзменений(Узел, ДокСсылка)`.
   Если был — не трогать (там настоящее изменение). В протокол: `БылВОчередиОбмена`, `СнятСОчереди`.
5. Пропуск: `Дата ≤ ГраницаЗапрета И НЕ РазрешитьЗакрытыйПериод` → «Пропущено: закритий період». Непроведённые/помеченные на
   удаление — «Пропущено: не проведений» (не проводить то, что пользователь распровёл).
6. Идемпотентность: строки со статусом «Перепроведено…» повторно не перепроводить.

`Функция ПерепровестиОтмеченные() Экспорт` — берёт отмеченные `Документы` (включая скрытые отбором — считать и показывать их
число в вопросе), вызывает ядро, пишет статус в строки, затем **повторный `Анализировать()` с сохранением галок по `КлючИД`**
и ставит в `Ключи.Статус`: «Виправлено» / «Залишилась розбіжність …».
**Гипотеза H1 (проверить в приёмке):** достаточно перепровести только ошибочные документы (регистр ПНУ от порядка не зависит).
Если на тестовом ключе H1 не подтвердится — ядро для ключа с остатком расхождения перепроводит «хвост» ключа от первого
ошибочного документа (открытый период) и снова анализирует.

`Функция ДокументыМеханизмаЗаПериод(Начало, Конец) Экспорт` — различные регистраторы `ПриобретенияНалоговыйУчет` за период
(кроме `Документ.ЗакрытиеМесяца`), с отбором по организации, упорядоченно по `МоментВремени`.

`Функция ГраницаЗапретаИзменения() Экспорт` — общая дата запрета «для всех пользователей» из `ДатыЗапретаИзменения`
(API БСП 3.0.1 — см. §4.3). Используется и формой, и ночью.

## 4. БСП: регистрация, ночной режим

### 4.1 Команды (`СведенияОВнешнейОбработке`)
| Идентификатор | Представление | Тип | Назначение |
|---|---|---|---|
| `Открыть` | «Розрахунки ПДВ за першою подією (6442)» | ОткрытиеФормы | рабочее место |
| `НочьВыравнивание` | «Нічне: розумне вирівнювання 6442» | ВызовСерверногоМетода | окно = с начала ПРОШЛОГО месяца по сегодня; анализ → перепровести ошибочные документы открытого периода → повторный анализ → при остатке — «хвост» ключа (H1) → итог в журнал |
| `НочьМесяц` | «Нічне: перепровести ПДВ-документи поточного місяця» | ВызовСерверногоМетода | все `ДокументыМеханизмаЗаПериод(НачалоМесяца(ТекущаяДатаСеанса()), КонецДня(...))` открытого периода → контрольный анализ → итог в журнал |

«Выбор режима в настройках» (решение пользователя) = **какой из двух ночных команд в карточке доп. обработки поставить
расписание** (можно обеим, разное время). Ночные команды: без диалогов, всё в `Попытка`, `ЗаписьЖурналаРегистрации(
"А_РозрахункиПДВЗаПершоюПодією", Уровень, , , Текст)` — сводка (ключей до/после, документов перепроведено/ошибок/пропущено,
снято с очереди обмена) + по строке на каждый ошибочный документ. `РазрешитьЗакрытыйПериод` ночью всегда `Ложь`.

Служебная скрытая команда (`Скрыть = Истина`) `ФонПерепровести` (ВызовСерверногоМетода) — фон перепроведения из формы.
`СведенияОВнешнейОбработке`: `ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке("3.0.1.437")` — **ВерсияБСП из 4 частей**
(иначе `ВыполнитьКоманду` вызывается с одним параметром), `БезопасныйРежим = Ложь` (регистрирует только полноправный).

### 4.2 `ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполнения) Экспорт`
Диспетчер `НочьВыравнивание` / `НочьМесяц` / `ФонПерепровести`; итог кладётся в `ПараметрыВыполнения.РезультатВыполнения.Итог`
(для фона — ТЗ протокола; БСП сам помещает `РезультатВыполнения` во временное хранилище). Регламентное задание
`ЗапускДополнительныхОбработок` гасит исключения — поэтому собственный протокол в журнал регистрации (каждая ошибка — отдельной записью).

### 4.3 Дата запрета
Запрос `РегистрСведений.ДатыЗапретаИзменения ГДЕ Пользователь = ЗНАЧЕНИЕ(Перечисление.ВидыНазначенияДатЗапрета.ДляВсехПользователей)`
+ `ДатыЗапретаИзмененияСлужебный.ДатаЗапретаПоОписанию(ОписаниеДатыЗапрета, ДатаЗапрета)` (в `Попытка`), максимум по строкам.
`ДополнительныеСвойства.ПропуститьПроверкуЗапретаИзменения` и `ОбменДанными.Загрузка` НЕ использовать (тихий обход закрытого периода).
Пользователя регламентного задания БСП не задаёт — ставится вручную (иначе проверка по общей дате 31.08).

### 4.4 Фон
- Из формы (обработка зарегистрирована в БСП, `Параметры.ДополнительнаяОбработкаСсылка` заполнен):
  `ДополнительныеОтчетыИОбработкиКлиент.ПараметрыВыполненияКомандыВФоне(Ссылка)` + `ИдентификаторКоманды = "ФонПерепровести"`,
  `Документы`, `РазрешитьЗакрытыйПериод` → `ДополнительныеОтчетыИОбработкиВызовСервера.ЗапуститьДлительнуюОперацию(УникальныйИдентификатор, ПК)`
  → `ДлительныеОперацииКлиент.ОжидатьЗавершение` с `ВыводитьПрогрессВыполнения = Истина` (прогресс шлёт `ДлительныеОперации.СообщитьПрогресс`
  каждые 10 документов) → `ПолучитьИзВременногоХранилища(Результат.АдресРезультата).Итог`.
  `ДлительныеОперации.ВыполнитьВФоне("ВнешняяОбработка.X...")` в фон НЕ уходит (выполняется синхронно) — не использовать.
- Открыта «Файл → Відкрити» (без ссылки) — синхронный серверный вызов.
- Тесты/служебно: `Процедура ПерепровестиВФоне(Параметры, АдресРезультата) Экспорт` через
  `ДлительныеОперации.ВыполнитьВФоне("ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки", Структура(ЭтоВнешняяОбработка=Истина,
  ИмяОбработки=<полный путь к .epf на сервере>, ИмяМетода="ПерепровестиВФоне", ПараметрыВыполнения))`.

## 5. Инварианты / защиты (нарушение = переделка)
1. Перепроведение НЕ оставляет документ в очереди обмена на узел ЕРП, если до перепроведения его там не было; если был — не трогает.
2. Ночь НЕ трогает документы с `Дата ≤ ГраницаЗапрета`; форма — только при явной галке «Дозволити закритий період».
3. Непроведённые / помеченные на удаление документы не проводятся.
4. Обрабатываются только отмеченные строки; число в вопросе = фактическое число к перепроведению (включая скрытые отбором).
5. Никакой записи данных документов (только `Проведение` существующих). Никаких `Удалить()`.
6. Проверка результата — инвариант «после перепроведения `|Факт − Ожидаемо| ≤ 0,05` по ключу», а не «было → стало».
