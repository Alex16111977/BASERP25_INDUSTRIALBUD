# Промт: РКО движения ПАП(ОТ) + ПАП(ДенСр) + ДСДохРасх — детализация по подразделениям из ВКассу.А_Расшифровки

**Дата создания:** 2026-05-28
**Назначение:** скопировать целиком в новую сессию AI как стартовый промт
**Длительность:** ~2 рабочие сессии (правка BSL + тесты)
**Промт self-contained** — у новой сессии нет контекста этой беседы.

## 🎯 Роль

Ты — **1С-разработчик BAS ERP 2.5 + финансист-CFO**:

- **Инженер 1С (роль 1):** работаешь чисто, без заплаток (пост-обработок, дублирующих SQL CASE-логик, мёртвого кода). Используешь стандартные точки расширения BAS ERP — пишешь новые процедуры как естественное расширение существующего пайплайна типовой обработки `DataProcessors.ДвиженияАктивовПассивов`.
- **Финансист-CFO (роль 2):** твоя задача — **бухгалтерский баланс должен сходиться per (Организация, Подразделение)**. Активы (Денежные средства) = Пассивы (Оплата труда — обязательство работодателя). Когда выплачивается зарплата: касса ↓, долг ↓, баланс per подразделение сохраняется. Это бизнес-цель.

Конфигурация: **BAS ERP 2.5 (v2.13)**, **1С:Предприятие 8.3.20**.
Организация: **ТОВ ІНДАСТРІАЛБУД** (КодПоЕДРПОУ 40645273).
БД: **BaseERP** (SQLSERVER), пользователь Администратор / 24043.

## 📋 Бизнес-цель (финансистская)

Финансист видит в текущей БД **3 регистра** связанные с проведением РКО зарплатной выплаты:

1. **РегНак.ПрочиеАктивыПассивы** (статья «Оплата труда») — пассивная статья учёта обязательства.
2. **РегНак.ПрочиеАктивыПассивы** (статья «Денежные средства (наличные)») — актив учёта денег.
3. **РегНак.ДвиженияДенежныеСредстваДоходыРасходы** — статистика операций по кассам.

**Проблема:** в первых двух подразделение либо пусто (ОТ), либо общее «Спецтехника» (ДенСр). В третьем — общее «Спецтехника» + общая Статья ДДС. Итог: **баланс per Подразделение НЕ сходится** → подсистема балансировки пишет плуги «Вывод/Вложения собственных средств» по периоду конец дня. Управленческий баланс по направлениям и подразделениям ломается.

**Решение:** все три регистра должны видеть **одни и те же** 12 СтрПредпр (по ФизЛицу), что уже есть в кастомном регистре `РегНак.А_ВзаиморасчетыССотрудниками` (А_ВзСС). А_ВзСС — это **источник истины** для подразделений в этой задаче.

После правки: баланс активов (Σ Расход ДенСр per Подр) = баланс пассивов (Σ Приход ОТ per Подр) **до копейки per каждое из 12 СтрПредпр**.

## 🏗 Архитектура решения (две правки в двух типовых файлах)

### Правка №1 + №2: `DataProcessors/ДвиженияАктивовПассивов/Ext/ManagerModule.bsl`

**Точка интеграции:** новая процедура `ДобавитьТекстЗапросаПАП_РКО_ВКассу(Запрос)` в области `#Область ТекстыЗапросовДвиженийПоРегистрам` (после line 3729). Вызывается из `ЗапросДвижений` (line 227) **после** `ДобавитьТекстЗапросаДвиженийАктивовПассивов` (line 242).

**Логика:** формирует **24 строки движений ПАП** (12 Приход ОТ + 12 Расход ДенСр) — но **только** для документов, удовлетворяющих жёсткому гарду.

#### Жёсткий гард (защита от blast radius):

```sql
ГДЕ
    -- 1. Только РКО
    ТИПЗНАЧЕНИЯ(<Регистратор>) = ТИП(Документ.РасходныйКассовыйОрдер)
    -- 2. Только наша ВКассу
    И ТИПЗНАЧЕНИЯ(ВЫРАЗИТЬ(<Регистратор> КАК Документ.РасходныйКассовыйОрдер).Ведомость)
       = ТИП(Документ.ВедомостьНаВыплатуЗарплатыВКассу)
    -- 3. Только зарплатные ХозОп
    И ВЫРАЗИТЬ(<Регистратор> КАК Документ.РасходныйКассовыйОрдер).ХозяйственнаяОперация В (
        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыЧерезКассу),
        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыРаздатчиком),
        ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыплатаЗарплатыРаботнику))
```

**Три условия должны выполниться одновременно** — если любое FALSE, наша логика не срабатывает, типовые движения работают как раньше.

## 🛡 Защита от blast radius

Поскольку `DataProcessors.ДвиженияАктивовПассивов` — общая обработка для **всех** документов (РКО, ПКО, ПриобретениеТоваровУслуг, РеализацияТоваровУслуг, СписаниеБезналичныхДенежныхСредств, ОЗФУ, etc.), любая ошибка в гарде может задеть посторонние документы. **Гарды должны быть жёсткими, sanity-тесты — широкими.**

### Жёсткие гарды (3 условия одновременно)
1. `ТИПЗНАЧЕНИЯ(<Регистратор>) = ТИП(Документ.РасходныйКассовыйОрдер)` — только РКО.
2. `ТИПЗНАЧЕНИЯ(РКО.Ведомость) = ТИП(Документ.ВедомостьНаВыплатуЗарплатыВКассу)` — только наша ВКассу.
3. `РКО.ХозяйственнаяОперация В (3 зарплатные)` — только зарплатные ХозОп.

### Sanity-тесты должны покрывать
- РКО **с** нашей ВКассу — проверка позитивного сценария.
- РКО **без** Ведомости (например, ПрочаяВыдачаДенежныхСредств) — должно работать как раньше.
- РКО **с другой** Ведомостью (ВедомостьНаВыплатуЗарплатыВБанк, Перечислением) — должно работать как раньше.
- **Не-РКО** документы: ОЗФУ (Отражение зарплаты в финансовом учёте), СБДС (Списание безналичных), ПриобретениеТоваровУслуг — их движения ПАП должны быть НЕ зачеплены.

    after = pap_snap(ref)
    if before == after:

assert not failures, f"Sanity FAIL: {len(failures)} не-РКО документов зачеплены"
print("\n✅ Sanity не-РКО PASS — наша правка не зачепила другие типы документов")
