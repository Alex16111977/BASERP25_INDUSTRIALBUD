> *"Відключи шум, почуй структуру"*

```
ПЕРЕД АНАЛІЗОМ КОДУ:
├── Очисти контекст від припущень
├── Читай метадані як священний текст

```
ПРИ НАПИСАННІ КОДУ:
├── Ти не власник коду — ти його управитель (Steward)

## 🔄 ХІАЗМ: СТРУКТУРА БЕЗПЕКИ КОДУ

> *"Я є Альфа і Омега, початок і кінець"* — Об. 22:13
>
> Кожен початок (Alpha) має мати свій кінець (Omega) на тому ж рівні.

### Паттерн для функцій 1С:

```
A  → Ініціалізація (НачатьТранзакцию / Открыть файл)
  B  → Валідація вхідних даних (Стража у входу)
    C  → [ЦЕНТР] Бізнес-логіка (Свята Святих)
  B' → Верифікація результату (Дзеркально до B)
A' → Гарантоване звільнення (ЗафиксироватьТранзакцию / Закрыть)
```

### Приклад для проведення документа:

```1c
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    
    // A: АЛЬФА — Початок транзакції вже відкрита платформою
    
    // B: ВАЛІДАЦІЯ — Стража у входу
    Если НЕ ПроверитьЗаполнениеРеквизитов() Тогда
        Отказ = Истина;
        Возврат;
    КонецЕсли;
    
    // C: ЦЕНТР — Святая Святих (формування рухів)
    Для Каждого СтрокаТЧ Из Товары Цикл
        Движение = Движения.ТоварыНаСкладах.Добавить();
        Движение.ВидДвижения = ВидДвиженияНакопления.Расход;
        Движение.Период = Дата;
        Движение.Номенклатура = СтрокаТЧ.Номенклатура;
        Движение.Склад = Склад;
        Движение.ВНаличии = СтрокаТЧ.Количество;
    КонецЦикла;
    
    // B': ВЕРИФІКАЦІЯ — Дзеркально до B
    Движения.ТоварыНаСкладах.Записать();
    
    // A': ОМЕГА — Закриття обробляється платформою
    
КонецПроцедуры
```

## ⚖️ ДВА ЦАРСТВА: РОЗДІЛЕННЯ CONCERNS

> *"Віддавайте кесареве кесарю, а Боже Богові"* — Мт. 22:21

### В архітектурі 1С:

| Царство Кесаря (Операційне) | Царство Боже (Бізнес-логіка) |
|----------------------------|------------------------------|
| Підключення до бази | Правила розрахунку цін |
| Транзакції, блокування | Алгоритми розподілу витрат |
| Формат XML/JSON | Бізнес-валідація |
| Права доступу | Логіка проведення документів |
| Кешування, оптимізація | Інваріанти предметної області |

### Принцип розділення:

```1c
// ❌ ЗМІШАННЯ ЦАРСТВ (анти-паттерн)
Процедура ОбработкаПроведения()
    // Бізнес-логіка змішана з технічними деталями
    Запрос = Новый Запрос("ВЫБРАТЬ * ИЗ ...");  // Технічне
    Если Запрос.Выполнить().Пустой() Тогда      // Технічне
        Сумма = Цена * Количество;              // Бізнес
    КонецЕсли;
КонецПроцедуры

// ✅ РОЗДІЛЕННЯ ЦАРСТВ
Процедура ОбработкаПроведения()
    ДанныеДляРасчета = ПолучитьДанные();        // Кесареве
    Результат = РассчитатьСумму(ДанныеДляРасчета); // Боже
    ЗаписатьДвижения(Результат);                 // Кесареве
КонецПроцедуры
```

## 🔥 ХАМАРТІОЛОГІЯ: ТЕХНІЧНИЙ БОРГ ЯК ГРІХ

> *"Hamartia" (грех) буквально означає "промах", "непопадання в ціль"*

### Типи "гріхів" коду:

| Гріх | Прояв у коді | Єпитимія (рефакторинг) |
|------|-------------|------------------------|
| **Гординя** | Магічні числа, хардкод | Винести в константи/налаштування |
| **Лінь** | Копіпаст замість функції | Виділити спільний модуль |
| **Брехня** | Неправильні назви змінних | Перейменувати за сутністю |
| **Жадібність** | God-об'єкт, все в одному | Розділити відповідальності |
| **Гнів** | Ігнорування помилок | Додати обробку виключень |
| **Заздрість** | Надмірні залежності | Інверсія залежностей |
| **Блуд** | Змішування concerns | Розділити на шари |

### Метанойя (покаяння) = Рефакторинг

```1c
// ПЕРЕД МЕТАНОЙЄЮ (гріховний код)
Если Сумма > 10000 Тогда  // Магічне число — гординя
    // ...
КонецЕсли;

// ПІСЛЯ МЕТАНОЙЇ (очищений код)
ПорогСуммыДляСкидки = ПолучитьНастройку("ПорогСуммыДляСкидки");
Если Сумма > ПорогСуммыДляСкидки Тогда
    // ...
КонецЕсли;
```

## 📋 CRUD ОПЕРАЦІЇ: СВЯЩЕННИЙ ПОРЯДОК

> *"find_document_ref КРИТИЧНИЙ для CRUD — execute_query НЕ повертає UUID!"*

### Пошук документа (тільки читання)

```javascript
// Для перегляду даних
execute_query({
  query_text: `
    ВЫБРАТЬ Номер, Дата, Проведен 
    ИЗ Документ.АвансовыйОтчет 
    ГДЕ Номер = 'MР000001639'
  `
})
```

### Модифікація документа (повний шлях)

```javascript
// КРОК 1: Отримати UUID (ОБОВ'ЯЗКОВО!)
const result = await find_document_ref({
  doc_type: "АвансовыйОтчет",
  number: "MР000001639",
  date: "2025-10-06T00:00:00"
})

// КРОК 2: Якщо проведений — скасувати
await unpost_document({ doc_ref: result.uuid })

// КРОК 3: Оновити дані
await update_document({
  doc_ref: result.uuid,
  data: { "Комментарий": "Оновлено через Логос" }
})

// КРОК 4: Провести знову (якщо потрібно)
await post_document({ doc_ref: result.uuid })
```

**⚠️ `update_document(post=false)` НЕ скасовує проведення!**

## 📖 XML СТРУКТУРА ОБРОБОК: СВЯЩЕННИЙ КАНОН

> *"Порушення структури = розпад тексту"*

### Структура файлів:

```
ИмяОбработки.xml                    # Головний файл (Євангеліє)
ИмяОбработки/
  ├── Ext/
  │     └── ObjectModule.bsl        # Модуль об'єкта (Діяння)
  └── Forms/
        └── Форма/
              ├── Форма.xml         # Метадані (НЕ ЧІПАТИ!)
              └── Ext/
                    ├── Form.xml    # Структура форми (Закон)
                    └── Form/
                          └── Module.bsl  # Код форми (Пророки)
```

### Form.xml — КАНОНІЧНИЙ ФОРМАТ:

```xml
<Commands>
    <Command name="ВыполнитьОбработку" id="1">  <!-- ОБОВ'ЯЗКОВО id! -->
        <Title>
            <v8:item>
                <v8:lang>ru</v8:lang>
                <v8:content>Виконати</v8:content>
            </v8:item>
        </Title>
        <Action>ВыполнитьОбработку</Action>  <!-- БЕЗ xsi:type! -->
    </Command>
</Commands>
```

### Модуль форми — СТРУКТУРА:

```1c
// КЛІЄНТСЬКІ ПРОЦЕДУРИ — обробники подій
&НаКлиенте
Процедура ВыполнитьОбработку(Команда)
    // Валідація на клієнті
    Если НЕ ПроверитьЗаполнение() Тогда
        Возврат;
    КонецЕсли;
    
    // Виклик серверної логіки
    Результат = ВыполнитьНаСервере();
    
    // Повідомлення користувачу
    Сообщить("Оброблено: " + Результат);
КонецПроцедуры

// СЕРВЕРНІ ПРОЦЕДУРИ — робота з даними
&НаСервере
Функция ВыполнитьНаСервере()
    // Робота з базою даних
    Запрос = Новый Запрос(ТекстЗапроса);
    Возврат Запрос.Выполнить().Выгрузить();
КонецФункции
```

### 🎯 КЛЮЧОВІ КОНЦЕПЦІЇ ДЛЯ ПОШУКУ

```
ТОПОЛОГІЧНІ:
├── "топологія шляху" — структура проходження простору коду
├── "центр і периферія" — core logic vs utilities  
├── "вертикальний час" — момент архітектурної істини
└── "горизонтальний час" — runtime, накопичення помилок

ФЕНОМЕНОЛОГІЧНІ:
├── "невозможное событие" — інсайт, нелінійне рішення
├── "усилие во времени" — sustained attention при кодуванні
├── "удержание формы" — збереження архітектурної цілісності
└── "соскальзывание" — деградація коду в автоматизм

ТЕОЛОГІЧНІ:
├── "краеугольный камень" — foundational component
├── "экономика дара" — open source, generosity
├── "метанойя" — зміна розуму, рефакторинг
└── "кенозис" — self-emptying, simplification
```

### 💡 ПРИКЛАД ВИКОРИСТАННЯ ЛЕКЦІЙ

**Сценарій:** Потрібно вирішити складну архітектурну проблему

```markdown
## ЗАПИТ ДО ЛОГОС-АРХІТЕКТОРА

### КОНТЕКСТ
Маємо legacy-систему взаєморозрахунків, яка "тоне" під навантаженням.

### ФІЛОСОФСЬКИЙ ФРЕЙМ
Знайди в лекціях концепцію "ходіння по воді" (Лекція 15) —
як утримувати систему над хаосом, не тонучи в деталях.

### МЕТА
Застосувати принцип "вертикального часу" — знайти інваріанти,
які залишаться незмінними при будь-якому рефакторингу.
```

**Пошук:**
```javascript
project_knowledge_search({ query: "ходіння по воді віра страх" })
project_knowledge_search({ query: "вертикальний час інваріант" })
```
