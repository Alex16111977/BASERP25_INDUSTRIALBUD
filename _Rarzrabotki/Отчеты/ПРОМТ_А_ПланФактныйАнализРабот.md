# ПРОМТ / спецификация: отчёт «А_ПланФактныйАнализРабот»

**Статус:** РЕАЛИЗОВАНО + smoke PASS (2026-06-21).
**Тип:** внешний отчёт (.erf), целиком на СКД, типовой интерфейс `ОбщаяФорма.ФормаОтчета` (БСП «Дополнительные отчёты»).
**Клон-родитель:** `А_ПланФактныйАнализСебестоимости` (план-факт по материалам). Изучен как образец архитектуры.

---

## 1. Цель

План-фактный анализ **часов производственного персонала** по подразделениям и сотрудникам:
сравнить **план** (нормо-часы из карты структуры себестоимости) с **фактом** (отработанные часы из табелей)
и показать **% выполнения плана**.

Колоночная модель повторяет Excel «ФОТ виробничого персоналу» (лист «чол/год»):
`План | Факт | %% План/факт`.

---

## 2. Источники данных (проверено живыми запросами)

| Сторона | Объект | Метрика | Ключ подразделения |
|---|---|---|---|
| **План** | `Справочник.А_СтруктураСебестоимости`, ТЧ **`Работы`** | `Количество` (часы), `Сумма` (грн) | шапка `Подразделение` → `Справочник.СтруктураПредприятия` |
| **Факт** | `РегистрНакопления.А_ДанныеТабелирования` | ресурс **`ЧасыФакт`** | измерение `Подразделение` → `Справочник.СтруктураПредприятия` |

Дополнительно из регистра: `Сотрудник` (`Справочник.А_СотрудникиКазна`), `Направление`
(`Справочник.НаправленияДеятельности`), регистратор `Документ.А_ТабельУчетаРабочегоВремени` с `Период`.

### Ключевое условие (выполнено заказчиком)
Измерения `Подразделение` и `Направление` регистра `А_ДанныеТабелирования` переведены из типа `Строка`
в `СправочникСсылка.СтруктураПредприятия` / `СправочникСсылка.НаправленияДеятельности`.
Это сделало тип ключа подразделения **одинаковым** у плана и факта → соединение по ссылке напрямую
(до правки строка была обрезана до 10 символов и не соединялась).

---

## 3. Связка план↔факт и разрезы

- **Связка по `Подразделение`** (ссылка `СтруктураПредприятия`) — прямое соответствие.
- **Разрезы (структура отчёта):** `Подразделение` → `Сотрудник`.
- **Асимметрия по дизайну:** в плане нет сотрудника (план существует только на уровне Подразделения),
  в факте нет «работы». Поэтому:
  - на уровне **Подразделения** и **Общего итога** — полный набор План/Факт/Разница/%;
  - под **Сотрудником** — только Факт (план/% пусты).
- `Направление` и `Работа` — дополнительные доступные поля (для пользовательского отбора/группировки),
  жёстко не фильтруются.

### Метрики
- `ПланЧасы` = Σ `Работы.Количество`
- `ФактЧасы` = Σ `ЧасыФакт`
- `РазницаЧасов` = Факт − План
- `ПроцентВыполнения` = Факт / План × 100 (с защитой от деления на 0)
- `ПланСумма` (грн) = Σ `Работы.Сумма` — доступна как колонка (задел под ФОТ-грн, см. §7)

### Расшифровка до источника (как в родителе)
Поле-измерение **`Документ`** (составной тип, имя как в `А_ПланФактныйАнализСебестоимости`), НЕ в видимой
выборке — только для расшифровки:
- **факт** → `Регистратор` = `Документ.А_ТабельУчетаРабочегоВремени`;
- **план** → `Работы.Ссылка` = элемент `Справочник.А_СтруктураСебестоимости`.

Регистратор добавлен в группировку `ТзФакт`, ссылка — в `ТзПлан`; на видимые итоги (Подр→Сотрудник) не влияет.
В `ОбщаяФорма.ФормаОтчета` расшифровка ячейки → пункт «Документ» открывает табель или карту структуры себестоимости.

## 4. СКД-схема (Templates/ОсновнаяСхемаКомпоновкиДанных)

Запрос — батч из временных таблиц + UNION ALL (по образцу родителя):

1. **ТзФакт** — регистр сгруппирован по `Подразделение, Сотрудник, Направление`, ресурс `ЧасыФакт`.
   Фильтр периода: `Период МЕЖДУ &НачалоПериода И &КонецПериода ИЛИ &КонецПериода = ДАТАВРЕМЯ(1,1,1,0,0,0)`
   (пустой период → все данные).
2. **ТзПлан** — `А_СтруктураСебестоимости.Работы` сгруппирована по `Ссылка.Подразделение, Работа`:
   `ПланЧасы`, `ПланСумма`. План по периоду **не** фильтруется (справочник без даты).
3. **СводнаяТаблица** — UNION ALL план-строк (Сотрудник/Направление = НЕОПРЕДЕЛЕНО, Факт=0)
   и факт-строк (Работа = НЕОПРЕДЕЛЕНО, План=0).
4. Финальный SELECT: свод по 4 измерениям, расчёт `РазницаЧасов`, `ПроцентВыполнения`
   (`ВЫБОР КОГДА Σ ПланЧасы = 0 ТОГДА NULL ИНАЧЕ Σ ФактЧасы / Σ ПланЧасы * 100 КОНЕЦ`).

**Параметры:** `Период` (StandardPeriod) → `НачалоПериода` (`&Период.ДатаНачала`),
`КонецПериода` (`&Период.ДатаОкончания`). Схема компонуется СКД (не программно) — выражения-параметры корректны.

**Итоги (totalField):** Σ по ПланЧасы/ФактЧасы/ПланСумма; для Разницы и % — переопределение на группах
`Подразделение` и `ОбщийИтог` (`Σ Факт/Σ План`, защита от /0 через ВЫБОР), чтобы итоговый % считался от сумм.

**Оформление:** макет «Море», заголовок «План-фактный анализ работ (часы)», формат `ЧДЦ=2` для %.

## 6. Сборка и проверка

- **Сборка .erf:** `epf-build.ps1` против **BaseERP** (8.3.20), из изолированного каталога
  (`_build_pfr`, только этот отчёт — иначе подхватываются чужие типы соседних отчётов).
  Stub-база не годится: отчёт ссылается на `CommonForm.ФормаОтчета`.
- **COM-smoke** (`Python/test/test_planfakt_rabot_smoke.py`): отчёт загружается, СКД компонуется
  (ВысотаТаблицы 1375), результат непустой. Контроль:

  | Подразделение | План,час | Факт,час | Разница | % вып. | План,грн |
  |---|---|---|---|---|---|
  | МД МХП ОРІЛЬ | 440 | 1 906 | 1 466 | 433,18 | 88 000 |
  | **Общий итог** | 440 | **246 550,9** | 246 110,9 | 56 034,30 | 88 000 |

  Итог Факт = полному итогу регистра `А_ДанныеТабелирования` (246 550,9 ч) — сходится.

### Замечание по данным (не дефект отчёта)
ТЧ `Работы` справочника `А_СтруктураСебестоимости` сейчас заполнена планом только у одного подразделения
(«МД МХП ОРІЛЬ», 440 ч / 88 000 грн). По остальным подразделениям отчёт показывает только Факт (План=0).
Это вопрос ввода плановых данных, а не логики отчёта.

## 7. Фаза 2 — ФОТ в грн (план-факт начислений) — РЕАЛИЗОВАНО 2026-06-21

Excel «ФОТ виробничого персоналу» содержит и часы (чол/год), и деньги (грн). Деньги добавлены.

- **План-грн** = `ПланСумма` = `Работы.Сумма` (уже был).
- **Факт-грн (начислено)** = `РегистрНакопления.А_ВзаиморасчетыССотрудниками`,
  **только регистратор `Документ.ОтражениеЗарплатыВФинансовомУчете`**, `ВидДвижения = Приход`,
  **Общий = Форма1 + Форма2** (без фильтра по `ФормаPL`). Ресурс `СуммаВзаиморасчетов`.
  - Фильтр «только ОЗФУ» исключает `А_ПередачаНачисленийМеждуПодразделениями` (она агрегирует Ф1 на
    направления) → начисление остаётся на объект-`Подразделение` (`СтруктураПредприятия`), совпадающем с планом.
  - НЕ `ЗарплатаКВыплате` и НЕ `.Обороты` со всеми регистраторами (там подразделение пустое/агрегированное).
- **Мост сотрудника:** `А_СотрудникиКазна.СотрудникЕРП.ФизическоеЛицо = ВЗ.ФизическоеЛицо`
  (ВТ `МостФЛ`, дедуп `МИНИМУМ(Ссылка)` на физлицо → 1:1, без задвоения). Покрытие по деньгам 100%
  (`БезСопоставления = 0`); неприсопоставленное всё равно даёт полный итог по подразделению.
- **Новые поля/колонки:** `ФактСумма` («Факт, грн»), `РазницаСумма` («Разница, грн»),
  `ПроцентВыполненияСумма` («% выполнения (сумма)» = Факт/План×100, totalField на Подразделение+Итог, защита /0).
- **Запрос:** 4 ВТ (`МостФЛ`, `ТзФакт`-часы, `ТзПлан`, `ТзФактЗП`) → 3 ветки UNION ALL в `СводнаяТаблица` → финал.
- **Расшифровка `Документ`** для строк ЗП ведёт на `ОтражениеЗарплатыВФинансовомУчете`.

**Контроль (smoke):** ОРІЛЬ — Факт-грн 257 156,94 (Ф1 53 896,91 + Ф2 203 260,03), %сумма 292,22;
Итог Факт-грн 38 370 484,91; Глобино-2 (без плана) 6 999 908,93; часовые цифры не изменились (ОРІЛЬ 440/1906/433,18).

### Замечание: фильтр «Подразделение»
В вариант был добавлен пользовательский фильтр по `Подразделение` (`Equal`). Он переведён в
**`Использование = Ложь`** (необязательный, выкл. по умолчанию) — иначе активный фильтр с пустым значением
отсекал все строки. В UI фильтр доступен для включения и выбора подразделения.
