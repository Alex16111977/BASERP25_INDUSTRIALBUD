# ПРОМТ / ТЗ: отчёт «А_РасшифровкаПартийСписаннойНоменклатуры»

**Статус:** ТЗ, готов к реализации (дизайн согласован 2026-06-30).
**База:** BAS Бухгалтерія **BuhBud** — `Srvr="SQLSERVER";Ref="BuhBud";Usr="cfo";Pwd="2442"`.
**Файл-болванка для перезаписи:** `_Rarzrabotki/Отчеты/А_РасшифровкаПартийСписаннойНоменклатуры.xml`
(сейчас внутри лежит ЧУЖОЙ отчёт `ПланФактСС` — **переписать ПОЛНОСТЬЮ**: имя объекта, GeneratedType, формы, СКД, реквизиты).
**Тип:** внешний отчёт `.erf`, **типовая форма** `ОбщаяФорма.ФормаОтчета` (как у отчётов BuhBud, см. образцы ниже).

---

## 1. Цель

По выбранной **Реализации** показать, **из какой первичной приходной накладной** (Надходження товарів і послуг) пришла каждая списанная позиция. Проблема: в проводках списания/реализации партия номенклатуры — это **документ Перемещение** (товар гонялся между складами), а не приход. Нужно пройти цепочку партий назад через перемещения до первичного прихода, чтобы потом по нему найти оригинал накладной от поставщика.

**Эталон (проверено COM):** для Реализації `ІБ00-000113 от 24.06.2026`, номенклатура **«Біта РН 2*50 мм»** партія приходної накладної = **«Надходження товарів і послуг ІБ00-007655 от 24.12.2025 17:52:35»**.
Цепочка: `Реализация → Переміщення ІБ00-001311 → Переміщення ІБ00-000189 → Надходження ІБ00-007655`.

---

## 2. Вход / выход

**Параметр шапки (единственный обязательный):**
- `ДокументРеализации` — тип `ДокументСсылка.РеализацияТоваровУслуг`. Без него — отчёт пуст с сообщением «Виберіть документ реалізації».

**Группировка отчёта (строго):**
```
Документ (Реализация)
└─ Номенклатура
   └─ ПартіяСписання          (партия в документе = ближайшее Перемещение на Кт реализации)
      └─ ПартіяПриходу         (первичный документ-источник: Надходження / інше)
```
**Ресурсы:** `Количество`, `Сумма` (себестоимость списания). Итоги по группировкам.

---

## 3. Модель данных (✅ ПРОВЕРЕНО живым COM-зондом, не выдумано)

**Регистр** `РегистрБухгалтерии.Хозрасчетный`. Списание себестоимости в Реализации: проводка `Дт 902 — Кт 221/281/201` (товарный счёт). Именно на **Кт-строке товарного счёта** висят субконто:

| ВидСубконто (Кт) | Тип значения | Роль |
|---|---|---|
| **Партії** | составной, здесь `ДокументСсылка.ПеремещениеТоваров` (или `…ПоступлениеТоваровУслуг` и др.) | партия = документ-источник |
| **Номенклатура** | `СправочникСсылка.Номенклатура` | товар |
| **Склади** | `СправочникСсылка.Склады` | склад |

- Партия-перемещение: документ `Перемещение` своими проводками `Дт <товарн.счёт> Партія=<сам Перемещение>` / `Кт <товарн.счёт> Партія=<партия-источник>` **подменяет** партию (создаёт новую партию = себя), а на Кт указывает партию-предшественника. Поэтому цепочку надо разворачивать рекурсивно по Кт.

> **🚨 Грабля BuhBud (ОБЯЗАТЕЛЬНО учесть):** субконто Хозрасчетного **НЕ доступны в запросе СКД** (`СубконтоКт1`, `СубконтоКт.Номенклатура` → «Поле не знайдено») — подтверждено на этой базе ранее (обработка «Заполнить … по списанию»). Поэтому проводки и субконто читать **только через `НаборЗаписей` + итерацию `Запись.СубконтоКт`** (искать значение по `ТипЗнч`/`ПолноеИмя()`), а НЕ запросом. Это и диктует архитектуру (BSL-движок строит ТЗ → СКД только выводит).

## 4. Алгоритм трейса (псевдокод, проверен на эталоне)

```
ВходНоменклатураФильтр = пусто (все позиции реализации)

// 1. строки реализации
строкиРеал = []
НаборРеал = Хозрасчетный.СоздатьНаборЗаписей(); Отбор.Регистратор=ДокументРеализации; Прочитать()
для Запись из НаборРеал:
    если Запись.КоличествоКт == 0: continue
    ном = найтиВСубконтоКт(Запись, Тип Номенклатура)
    парт = найтиВСубконтоКт(Запись, "Партії")   // документ
    если ном == Неопределено ИЛИ парт == Неопределено: continue   // отсекаем не-товарные строки (702/641)
    строкиРеал.добавить({Ном, ПартіяСписання=парт, Кол=КоличествоКт, Сум=Сумма})

// 2. для каждой строки — рекурсивный трейс до первичного прихода
для стр из строкиРеал:
    приходы = ТрейсДоПрихода(стр.Ном, стр.ПартіяСписання)   // множество терминальных документов
    для прих из приходы:
        результат.добавить({Документ, стр.Ном, стр.ПартіяСписання, ПартіяПриходу=прих, стр.Кол, стр.Сум})

// рекурсия
функция ТрейсДоПрихода(Ном, Партія, посещённые={}, глубина=0):
    если глубина > 50 ИЛИ Партія в посещённые: вернуть {Партія}      // защита от циклов
    посещённые.добавить(Партія)
    если ТипЗнч(Партія) != Документ.ПеремещениеТоваров:
        вернуть {Партія}                                            // терминал: первый не-Перемещение
    // Партія — Перемещение: читаем его Кт-партии по той же номенклатуре
    источники = {}
    Набор = Хозрасчетный.СоздатьНаборЗаписей(); Отбор.Регистратор=Партія; Прочитать()
    для Запись из Набор:
        если Запись.КоличествоКт == 0: continue
        н = найтиВСубконтоКт(Запись, Тип Номенклатура)
        п = найтиВСубконтоКт(Запись, "Партії")
        если н == Ном И п != Неопределено: источники.добавить(п)
    если источники пусто: вернуть {Партія}                          // тупик — показываем само перемещение
    итог = {}
    для и из источники: итог += ТрейсДоПрихода(Ном, и, посещённые, глубина+1)
    вернуть итог
```

**Терминал цепочки = первый документ, который НЕ `ПеремещениеТоваров`** (Надходження, Оприбуткування, ВводОстатков, Звіт виробництва і т.п.) — согласовано с заказчиком.

**Multi-batch (зафиксировано):** если перемещение собрало номенклатуру из нескольких партий-источников → трейс даёт **несколько `ПартіяПриходу`** (все приходы-кандидаты). Количество/сумма атрибутируются на уровень `ПартіяСписання` (точное FIFO-распределение по количеству — вне ТЗ; при желании — отдельная доработка). На лист-строках `ПартіяПриходу` Кол/Сум можно дублировать или оставить пустыми — на усмотрение (в эталоне 1 приход на позицию).

**Кэш:** один и тот же документ-перемещение встречается многократно — кэшировать прочитанные наборы записей (Соответствие Регистратор→массив строк) ради скорости.

## 5. Архитектура (как у типовых СКД-отчётов BuhBud)

- **Движок** строит данные **программно в BSL** (НаборЗаписей + рекурсия §4) → `ТаблицаЗначений` колонок `Документ, Номенклатура, ПартіяСписання, ПартіяПриходу, Количество, Сумма` → передаётся в **СКД как внешний набор данных «Данные»**. СКД только группирует/выводит.
- **Где живёт движок:** программная компоновка в `ПриКомпоновкеРезультата` модуля отчёта (как `А_ПланФактныйПроизводствоПолный`: читает параметр `ДокументРеализации`, строит ТЗ, `КомпоновщикМакета.Выполнить(Схема, Настройки, …)` + `ВнешниеНаборыДанных = Структура("Данные", ТЗ)` + `ПроцессорКомпоновкиДанных.Инициализировать(Макет, ВнешниеНаборы, …, Истина)`).
- **СКД** (`Templates/ОсновнаяСхемаКомпоновкиДанных`): набор данных «Объект» (Данные), поля `Документ/Номенклатура/ПартіяСписання/ПартіяПриходу` (ссылочные → расшифровка из коробки), ресурсы `Количество/Сумма` (Сумма по группировкам). Вариант по умолчанию: структура группировок Документ→Номенклатура→ПартіяСписання→ПартіяПриходу. Заголовок «Розшифровка партій списаної номенклатури».
- **Форма:** типовая `ОбщаяФорма.ФормаОтчета`; `ObjectModule` = регистрация для БСП (`СведенияОВнешнейОбработке`/хуки `ОтчетыСервер.ПодключитьСхему`, как у образцов) + параметр `ДокументРеализации` в быстрых настройках (Использование, на форме).

**Образцы для копирования раскладки (.erf/СКД/форма/Template-обёртка):**
- `_Rarzrabotki/Отчеты/` — `А_ПланФактныйПроизводствоПолный` (программная компоновка ПриКомпоновкеРезультата + внешний набор + типовая форма) — **главный образец движка**.
- `Reports/А_ПланФактныйАнализРабот` (в конфигурации) — чистый СКД + БСП-хуки + типовая форма.

## 7. Rule #-1 / Контроль (ОБЯЗАТЕЛЬНО перед BSL и при приёмке)

1. **Python-COM тест** алгоритма §4 на реальной базе ПЕРЕД переносом в BSL (готовый зонд-прототип: `_Rarzrabotki/Python/test/_probe_partii.py` — расширить до полного прохода всех строк реализации).
2. **Эталон:** Реализация `ІБ00-000113` (2026), «Біта РН 2*50 мм» → `Надходження ІБ00-007655 от 24.12.2025`. Должно совпасть 1:1.
3. Проверить ещё ≥2 номенклатуры этой же реализации (напр. «Відрізний диск Standard Inox 230x1,9», «Маркер») — у каждой должен получиться не-перемещение терминал.
4. `skd-validate` схемы; СКД-smoke (Создать .erf → ПолучитьДанные → есть строки, h>0).
5. **Номер документов НЕ уникален** (есть тёзки по годам!) — в тестах искать по `Номер + Дата` (год), не только по номеру.
