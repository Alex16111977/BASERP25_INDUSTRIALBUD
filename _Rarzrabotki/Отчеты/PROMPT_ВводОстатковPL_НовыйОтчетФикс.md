# ПРОМТ: Контур «Ввод остатков PL» — новый документ + новый отчёт с фиксированными накопительными + доработка выгрузки в Excel

Дата постановки: 28.08.2026. Заказчик — финансист. Решения заказчика (утверждены в диалоге):
- документ остатков заводится **СТРОГО ОДИН РАЗ на 30.06.2026** (23:59:59);
- отчёт — **НОВАЯ КОПИЯ** (действующий `А_ОтчетPL_ПолныйЕРП` НЕ трогать);
- в документе фиксируются **ОБА СЛОЯ**: объектные строки И свод-строки направлений

  138 434 185 против 129 087 048 у детей).

## 0. Зачем (финансовая суть)

Как в бухгалтерии вводят остатки при старте учёта (образец — типовой
`Документ.ВводОстатков`, ТЧ `ФинансовыйРезультатДоходы/Расходы`: Направление × Статья ×
Сумма, движения в `ПрочиеРасходы`/`ФинансовыеРезультаты`), так для управленческого PL
фиксируется переходная база на 30.06.2026: по каждому подразделению и статье PL —
«PL с начала года» (обороты 01.01–30.06.2026) и «Накопительный PL» (вся деятельность
по 30.06.2026). Дальше эти цифры НЕ пересчитываются из сотен документов `А_ОтчетPL`
и не зависят от перепроведений, состава регистра выгрузки и закрытых проектов.

## 2. Архитектура (три блока, делать по порядку)

### Блок А — Документ `А_ВводОстатковОтчетаPL` + регистр (объекты КОНФИГУРАЦИИ)

Скиллы: bas-house-style → bas-doc-new / bas-register-new → bas-bsp-form → bas-form-layout.

**Документ** (префикс А_, стиль типовых):
- Шапка: `Организация` (дефолт ТОВ «ІНДАСТРІАЛБУД»), `Ответственный`, `Комментарий`.
  Дата документа = дата остатков (для нашего кейса 30.06.2026 23:59:59).
- ТЧ `Остатки`: `Подразделение` (СтруктураПредприятия), `СводНаправления` (Булево —
  слой строки: Ложь = объектная, Истина = свод-строка направления с накладными),
  `СтатьяPL` (А_Статьи_PL), `СуммаФ1СНачалаГода`, `СуммаФ2СНачалаГода`,
  `СуммаФ1Накопительно`, `СуммаФ2Накопительно` (числа 15,2). Итоги в подвале ТЧ.
- Команда формы «Заполнить из документов А_ОтчетPL»: по обоим слоям
  (`Док.ВключатьДочерние` = слой), Ф1/Ф2 из `СуммаФома1`/`СуммаФорма2` (ВНИМАНИЕ:
  реквизит ТЧ называется «СуммаФома1» — опечатка в метаданных, НЕ чинить);
  СНачалаГода = доки 01.01.2026–30.06.2026; Накопительно = вся история ≤ 30.06.2026.
  Ручная правка строк после заполнения разрешена — документ для того и создан.
- Проведение → **регистр накопления `А_ОстаткиОтчетаPL`** (обороты): измерения
  `Подразделение`, `СтатьяPL`, `СводНаправления`; ресурсы 4 суммы (как в ТЧ).
  Контроль «строго один раз»: при проведении — отказ, если существует другой
  проведённый документ этого типа (сообщение с номером существующего).

**🔴 Деплой новых объектов метаданных** — это НЕ частичная правка модуля:
- обязателен бэкап: `db-dump-cf` рабочей базы ПЕРЕД загрузкой;
- состав конфигурации меняется → `Configuration.xml` участвует в загрузке; помнить
  аварию 05.08.2026 (частичная загрузка с Configuration.xml УДАЛЯЕТ объекты) —
  перед загрузкой выполнить аудит по памятке `config_xml_partial_load_deletes_objects`;
  безопасный путь: добавить объекты в XML-выгрузку, обновить Configuration.xml
  (только ДОБАВЛЕНИЕ узлов), частичная загрузка списком: Configuration.xml + все
  файлы новых объектов; либо через Designer вручную с последующей выгрузкой;
- UpdateDBCfg с реструктуризацией — конфигуратор закрыт, пользователей предупредить;
- после загрузки: контрольная выгрузка и сверка, смоук создания/проведения документа.

## 3. Обязательный процесс (Rule #-1 — без исключений)

1. Каждый новый/изменённый запрос — СНАЧАЛА Python COM тест на живой базе
   (`localhost/BaseERP`, Администратор/24043), потом BSL. Тесты в
   `_Rarzrabotki\Python\test\`.
2. RED-тесты контура:
   - **Заполнение документа**: суммы ТЧ по слоям = прямым запросам к докам А_ОтчетPL
     за периоды; КОНТРОЛЬНАЯ СВЕРКА С ЧЕРВНЕВОЙ КНИГОЙ по свод-листам и объектным
     листам (списки закрытых и их суммы — в таблице раздела 1; расхождения — в отчёт,
     дозаполнение строк закрытых объектов по их объектным докам, если свод-доки
     неполны). Итоговые строки документа обязаны дать целевые цифры сводов.
   - **Новый отчёт**: (а) для строк 890000/900000 суммы = остатки из документа +
     июль из регистров, построчно по (слой, подразделение, статья, Ф1/Ф2);
     (б) месячные колонки байт-в-байт равны старому отчёту (копия не сломана) —
     агрегатная сверка по ключу; (в) сообщение об отсутствии документа остатков.
   - **Выгрузка**: июльская книга — своды равны целям из таблицы раздела 1
     (Ф1 и Ф2 отдельно); объектные листы не изменились. Использовать/расширить

3. Порядок работ: Блок А (документ+регистр, деплой, заполнение, сверка с книгой) →

   После каждого блока — коммит.

## 4. Грабли (боевые, не пропускать)

- `СуммаФома1` — опечатка в имени реквизита ТЧ А_ОтчетPL, НЕ чинить, использовать как есть.
- Свод ≠ сумма детей; слои НЕ складывать (двойной счёт). В регистре остатков слой —
  измерение, отчёт всегда фильтрует по `&СводыНаправлений`.
- Закон источника для месячных колонок НЕИЗМЕНЕН (последний месяц — только регистры,
  ранее — только доки PL, месяц без документа — ноль).
- Комментарии/безлимитные строки в запросах — только через ВЫРАЗИТЬ(Строка(N));
  алиасы В/ПО/ИЗ/КАК запрещены; переменные Ссылка/Выполнить запрещены.
- Строки регистра с пустым подразделением в отчёт не попадают (карта уровней).
- CRLF+BOM у .bsl; инжект запроса скриптом по маркеру содержимого; grep-чек
  `КонецФункция\b` после правок.
- Запись данных в базу из скриптов может блокировать классификатор разрешений —
  заполнение документа делать интерактивной кнопкой формы (пользователь нажимает сам)
  или отдать пользователю готовый сценарий.
- Загрузка новых объектов метаданных: бэкап .cf, аудит Configuration.xml, закрытый
  конфигуратор (см. блок А). Частичная загрузка модулей БЕЗ Configuration.xml —
  только для последующих правок кода.
- Эталоны червневой книги: таблица PL листа — строки 5..87, ниже приложение по
  договорам — его не сверять. У каждого свода червневой книги СВОЙ охват
  накопительного блока (Строительство — 2026; Производство — с 10.2023; Логистика —
  2022–2026): для сверки YTD-2026 брать сумму месячных блоков января–июня.
