# ПРОМТ / спецификация: отчёт «А_ПланФактныйПроизводствоПолный»

**Статус:** РЕАЛИЗОВАНО + smoke PASS (2026-06-25). `.erf` собран против BaseERP, COM-smoke на Оріль зелёный (51 кол × 6 строк). Загрузить в карточку «Додаткові обробки» (вид — звіт).

**Отклонения от Excel (by-design):**
- `МонтГрнПлан = 868ч × 350 = 303 800` (карта), а не 302 400 (Excel брал 864ч — вручную исключил 4ч фикс-стоимости). Виробництво наоборот = все 1927ч. Отчёт использует полные часы карты по обеим категориям (консистентно).
- Факт списания материалов = `СебестоимостьТоваров.СтоимостьУпр` (управленческая). Регл (`Стоимость`) даёт иную сумму; ни одна не совпадает 1:1 с историческим Excel-снимком 4 106 111,26 (себестоимость пересчитывается помесячно — живая цифра дрейфует). При желании сменить на регл — одна строка в `СтоимостьСписанияМатериалов`.
- Грабли пути (исправлены): `Знач` — зарезерв. слово (параметр→`Значение`); слияние ячеек = `Область.Объединить()`, НЕ `ТабДок.ОбъединитьЯчейки`; свойства `ПолеЗаголовок` у ТабличногоДокумента нет.
- Реальная ЗП берётся прямым запросом по `Подразделение` (мост ФЛ из `А_ПланФактныйАнализРабот` НЕ нужен — отчёт на уровне подразделения). Smoke (пустой период): часы 2229, ЗП 257 156,94.

---

**Изначальная спецификация (дизайн):**
**Тип:** внешний отчёт (.erf), **программный `ТабличныйДокумент`** (без MXL-макета), кастомная управляемая форма.
**Образцы изучены:** `А_ПланФактныйАнализРабот` (план-факт часов/ФОТ, источники факта), `А_ПланФактныйАнализСебестоимости` (родитель-СКД). Печатная форма `СозданиеКомплектацийБух` — образец построения `ТабличныйДокумент` целиком кодом.
**Целевой образ:** Excel `_Rarzrabotki/notebook/knowledge_ОтчетПроизводстваПоТабелях/Звіт_виробництва_по_табелях_30_04_2026.xlsx`, лист **«Оріль»** (база заполнения / тест-эталон).

## 1. Цель

Воспроизвести в 1С «Звіт виробництва по табелях» — широкую план-фактную матрицу производства по одной структуре себестоимости (проекту). Сравнить **план** (карта `А_СтруктураСебестоимости`) с **фактом** (табель часов, начисленная ЗП, списание материалов) в разрезе **Виробництво / Монтаж**, по двум временным срезам (весь проект / выбранный месяц).

**Охват (решение заказчика):** одна СС/подразделение за прогон. Параметры `Період` + `СтруктураСебестоимости`. Тест — Оріль; на остальные подразделения отчёт распространяется тем же прогоном при выборе их СС.

## 2. Источники данных (проверено живыми запросами на BaseERP, 2026-06-25)

| Сторона | Объект | Что берём |
|---|---|---|
| **План — работы** | `Справочник.А_СтруктураСебестоимости`, ТЧ **`Работы`** | `Количество` (часы), `Цена`, `Сумма`; флаг **`НаВыезде`** (Ложь=Виробництво, Истина=Монтаж) |
| **План — материалы** | `Справочник.А_СтруктураСебестоимости`, ТЧ **`Комплектующие`** | `Сумма`; разрез по **`Этап`** (`Справочник.А_ЭтапыРабот`) |
| **Шапка СС** | `А_СтруктураСебестоимости` | `Подразделение` (`СтруктураПредприятия`), `Склад`, **`СкладПроизводство`**, **`СкладМонтаж`** |

| **Факт — ЗП (начислено)** | `РегистрНакопления.А_ВзаиморасчетыССотрудниками` | `СуммаВзаиморасчетов`; **только регистратор `Документ.ОтражениеЗарплатыВФинансовомУчете`**, `ВидДвижения=Приход`, Общий Ф1+Ф2; мост сотрудника `А_СотрудникиКазна.СотрудникЕРП.ФизическоеЛицо` (как в `А_ПланФактныйАнализРабот`) |
| **Факт — списание материалов** | себестоимость списания по `Регистратор = Документ.СборкаТоваров` | сумма списания; разрез по `Склад` документа |

> **Rule #-1:** точный регистр/поле для «факта списания материалов» (кандидат — `РегистрНакопления.СебестоимостьТоваров`, `ВидДвижения=Расход`, выражение `Регистратор КАК Документ.СборкаТоваров`; см. memory `baserp_sebestoimost_register_query`) ОБЯЗАТЕЛЬНО подтвердить Python-COM-тестом на реальных документах ПРООН (`ІБ00-000076/078/098/099/100/101`, факт-эталон Excel `4 106 111,26`) ПЕРЕД переносом в BSL.

## 3. Правила классификации Виробництво / Монтаж (ключевая логика — проверено)

| Что делим | Правило | Контроль Оріль |
|---|---|---|
| **Работы (часы)** | по флагу строки `Работы.НаВыезде`: Ложь→Виробництво, Истина→Монтаж | Виробництво 1927 ч / Монтаж 868 ч |
| **Материалы план (грн)** | по `Этап`: этап-монтаж (наименование содержит «Монтаж», по умолч. «Монтаж будинку») → Монтаж; остальные этапы → Виробництво | Монтаж 206 605 / Виробництво 1 711 992 (Σ=1 918 597,96) |
| **Материалы факт (списание)** | по складу документа `СборкаТоваров`: `Склад = СС.СкладПроизводство` → Виробництво; `Склад = СС.СкладМонтаж` → При монтажу | (Оріль фактов пока нет; правило проверяется на ПРООН) |

- Материалы по `НаВыезде` НЕ делятся — в карте все `Комплектующие.НаВыезде=Ложь`; деление только по `Этап`.
- `А_ЭтапыРабот` своего флага монтажа не имеет → классификация по наименованию этапа; вынести в **параметр-список этапов монтажа** (дефолт — этапы с «Монтаж» в наименовании), без правок метаданных.
- **Ставка чол/год** = модальная цена по часам внутри категории (цена, на которую приходится больше всего часов): Виробництво 200, Монтаж 350. (У Оріль есть единичные строки с ценой 15000/5200 на 3–4 ч — это фикс-стоимостные позиции, на ставку не влияют.)

### Блок 3 — «ФОТ виробничого персоналу, Проект» (накопительно ≤ конец `Період`)
Структура (для Виробництво и Монтаж, в чол/год и грн):
| Подблок | План | Факт | %% |
|---|---|---|---|
| чол/год Виробництво (U/V/W) | = I | Σ `ЧасыФакт` (накоп.) | Факт/План |

## 5. Семантика периода

- Параметр **`Період`** (StandardPeriod, месяц отчёта). Определяет: границу «месяца» (блок 4) и верхнюю границу «проекта».
- **«Проект»** (блоки 3 «Проект», 5) = накопительно от начала и до **конца** `Період` (нижней границы нет — весь срок проекта). При необходимости позже добавить параметр `ДатаНачалаПроекта`.
- **«<місяць>»** (блок 4) = только в границах `Період.ДатаНачала … Період.ДатаОкончания`.
- Заголовок месячных блоков формируется из `Період` (название месяца/года).

## 6. Архитектура

**Объект:** внешний `.erf` `А_ПланФактныйПроизводствоПолный` (репозиторная папка-скаффолд — клон `А_ПланФактныйАнализРабот`). Переименовать `Name`/`Synonym`/`GeneratedType`, GUID оставить уникальными (у клона уже свои).

**Почему программный `ТабличныйДокумент`, а не СКД:** фиксированная широкая матрица с объединённой 3-уровневой шапкой (5 блоков × тройки План/Факт/%%) и фактически одной строкой данных. СКД такую шапку строит мучительно; СКД-механизм избыточен для одной строки. Программный `ТабличныйДокумент` (как в печатной форме `СозданиеКомплектацийБух` — без MXL) даёт точную раскладку и привычен.

**Состав:**
- **Форма** (кастомная управляемая, НЕ `CommonForm.ФормаОтчета`): реквизиты `Період`, `СтруктураСебестоимости` (+ необяз. override `СтавкаВиробництво`/`СтавкаМонтаж`, `ЭтапыМонтажа`), кнопка «Сформувати», `ПолеТабличногоДокумента` (результат). Регистрация в БСП «Дополнительные отчёты» через `СведенияОВнешнейОбработке()`.
- **ObjectModule (экспортный «движок»):**
  - `ПолучитьДанныеАнализа(Период, СС, …)` → структура со всеми метриками (план/факт по блокам). Запросы: план (Работы/Комплектующие из карты), факт-часы (`А_ДанныеТабелирования` ×2 среза), факт-ЗП (`А_ВзаиморасчетыССотрудниками` ×2 среза), факт-материалы (себест. списания по `СборкаТоваров`).
  - `СформироватьТабличныйДокумент(Данные)` → строит шапку (объединения областей, границы `Новый Линия(ТипЛинииЯчейкиТабличногоДокумента.Сплошная)` — память: `.Граница` не ставится напрямую) и строку «Розрахунок в 1С».
- Модуль формы тонкий: `РеквизитФормыВЗначение`/`ЗначениеВРеквизитФорме` → вызов движка → вывод в `ПолеТабличногоДокумента` (паттерн «тонкая форма + ObjectModule», memory `obr-obrabotka`).
- SKD-Template скаффолда не используется (можно удалить из состава или оставить пустым).
