## 2. Инварианты — НЕ НАРУШАТЬ

1. 🔴 **Факт по материалам — всегда С НДС.** План (`Комплектующие.Сумма`) заведён с НДС.
   Формула: `ВЫБОР КОГДА Д.СуммаВключаетНДС ТОГДА Т.Сумма ИНАЧЕ Т.Сумма + Т.СуммаНДС КОНЕЦ`.
   Свести к `Т.Сумма` — сломать «Відхилення», «План на факт» и прогноз. Так факт брал СТАРЫЙ
   отчёт `ПланФактСС`, на месте которого сделан этот (голое `СУММА(Товары.Сумма)`) — отсюда
   и жалоба, что цена факта без НДС.
   `ЦенаФакт = ФактГрн / ФактКол` наследует НДС автоматически, отдельной правки не требует.

   ⚠️ **Никакого «просто × 1,2».** Замер по IRS на 06.08.2026 (207 строк факта):
   22 строки идут с `СуммаВключаетНДС = Истина` (сумма уже с НДС), 137 — с НДС отдельной
   суммой (формула его прибавляет), 48 — с нулевым НДС (поставщики-неплательщики).
   Умножение всей суммы на 1,2 даёт 4 771 077,20 вместо верных 4 595 459,79 — завышение
   175 617,41 (3,8 %): на 159 строках налог начислился бы второй раз, на 48 — появился бы
   из ниоткуда. **Решение пользователя 06.08.2026: строки с нулевым НДС оставляем как есть**
   (закупка у неплательщика реально дешевле плана, экономия настоящая).
2. 🔴 **Факт не двоить.** Сбор идёт **циклом по зонтикам** (`&Зонтик` — параметр запроса),
   факт берётся один раз на подразделение. Две карточки IRS на одном зонтике удвоили бы его.
   `В ИЕРАРХИИ (столбец ВТ)` платформой запрещено — только параметр или подзапрос.
3. 🔴 **Факт = ЗАКУПКИ, не списание.** Списание — другой отчёт
   (`А_ОтчетПоСписаниюНаПроизводствоБухгалтерский`).
4. 🔴 **Плановые строки без номенклатуры не терять.** Общая назва берётся из
   `Номенклатура.ОбщееНазваниеНоменклатуры`, а при пустой номенклатуре — из ТЧ-реквизита
   `К.ОбщееНазвание`; аналитика — из `К.НоменклатураСС` (текст). У IRS так заведено почти всё.
   **С 04.09.2026 правило обратное: назва плана ВСЕГДА из строки СС, карточная — запасной вариант (§0a п.2).**
5. 🔴 **Ключ ETC-группы — БЕЗ Етапу и Категорії** (иначе перерасход одного этапа не гасит
   остаток другого, ETC завышается).
6. 🔴 **Правило 3 ETC — ровно сумма плана**, без round-trip через цену: бухгалтеру нужен
   точный отчёт, «не играться с копейками».
7. **С ЕРП не сверять.** Расхождение факта +0,65 % и плана по количеству −0,12 — известно,
   решение пользователя: не отвлекаться, отчёт не для сверки баз.

## 3. Архитектура

Программная компоновка СКД: BSL строит плоскую ТЗ, СКД получает её внешним набором
`"Детали"` (`DataSetObject`). Причины программности:
- «План на факт» (ETC) — синтетические строки, которых нет в грейне;
- разнос факта по Етапу требует карты «имя общей назвы → Етап».

Образец для копирования стиля: `_Rarzrabotki/Отчеты/А_ОтчетПоСписаниюНаПроизводствоБухгалтерский/Ext/ObjectModule.bsl`.

Точка входа — `ПриКомпоновкеРезультата` → делегирует в **экспортную** `СформироватьОтчет`,
чтобы приёмка могла прогнать полный путь пользователя через COM (COM-прокси не отдаёт
обработчик события).

## 4. Набор «Детали»

### 4.1. Измерения (7)

| Поле | Тип | Титул uk | Заполнено |
|---|---|---|---|
| `Подразделение` | `СправочникСсылка.Подразделения` | Підрозділ | всегда = зонтик `СС.Подразделение` |
| `Категория` | Строка(50) | Категорія | `Виробництво` / `Монтаж` |
| `Этап` | `СправочникСсылка.ЭтапыРабот` | Етап | план; факт — после постобработки |
| `ОбщееНазвание` | `СправочникСсылка.ОбщиеНазванияНоменклатуры` | Загальна назва | обе ветки |
| `Аналитика` | составной: `СправочникСсылка.Номенклатура` + Строка(200) | Аналітика | план: номенклатура или текст `НоменклатураСС`; факт: номенклатура |
| `Единица` | `СправочникСсылка.КлассификаторЕдиницИзмерения` | Од. вим. | обе ветки |
| `Документ` | составной: `СправочникСсылка.СтруктураСебестоимости` + `ДокументСсылка.ПоступлениеТоваровУслуг` | Документ | план → карточка СС, факт → накладная |

Типы «пустых» значений — **типизированные пустые ссылки**
(`ЗНАЧЕНИЕ(Справочник.X.ПустаяСсылка)`), не `НЕОПРЕДЕЛЕНО`.

### 4.2. Ресурсы (14) и формулы `totalField`

| Поле | Титул uk | Формула итога |
|---|---|---|
| `ПланКол` | План, к-сть | `Сумма(ПланКол)` |
| `ЦенаПлан` | Ціна план, грн | `ВЫБОР КОГДА Сумма(ПланКол)=0 ТОГДА 0 ИНАЧЕ Сумма(ПланГрн)/Сумма(ПланКол) КОНЕЦ` |
| `ПланГрн` | План, грн | `Сумма(ПланГрн)` |
| `ФактКол` | Факт, к-сть | `Сумма(ФактКол)` |
| `ЦенаФакт` | Ціна факт, грн | `ВЫБОР КОГДА Сумма(ФактКол)=0 ТОГДА 0 ИНАЧЕ Сумма(ФактГрн)/Сумма(ФактКол) КОНЕЦ` |
| `ФактГрн` | Факт, грн | `Сумма(ФактГрн)` |
| `ОтклонениеКол` | Відхилення, к-сть | `Сумма(ФактКол) - Сумма(ПланКол)` |
| `ОтклонениеГрн` | Відхилення, грн | `Сумма(ФактГрн) - Сумма(ПланГрн)` |
| `ПроцентКол` | % вик. (к-сть) | `ВЫБОР КОГДА Сумма(ПланКол)=0 ТОГДА 0 ИНАЧЕ Сумма(ФактКол)/Сумма(ПланКол)*100 КОНЕЦ` |
| `ПроцентГрн` | % вик. (грн) | `ВЫБОР КОГДА Сумма(ПланГрн)=0 ТОГДА 0 ИНАЧЕ Сумма(ФактГрн)/Сумма(ПланГрн)*100 КОНЕЦ` |
| `ПланНаФактГрн` | План на факт, грн | `Сумма(ПланНаФактГрн)` |
| `ПрогнозГрн` | Прогноз, грн | `Сумма(ФактГрн) + Сумма(ПланНаФактГрн)` |
| `ОтклонениеПрогнозГрн` | Відхилення прогнозу, грн | `Сумма(ФактГрн) + Сумма(ПланНаФактГрн) - Сумма(ПланГрн)` |
| `ПроцентПрогнозГрн` | % вик. прогнозу | `ВЫБОР КОГДА Сумма(ПланГрн)=0 ТОГДА 0 ИНАЧЕ (Сумма(ФактГрн)+Сумма(ПланНаФактГрн))/Сумма(ПланГрн)*100 КОНЕЦ` |

### 4.3. Параметр

`Період` — `СтандартныйПериод`. Границы независимы: пустое начало → `'00010101000000'`,
пустой конец → `'39991231235959'`; конец берётся как `КонецДня(...)`.

## 6. Постобработки

Порядок обязателен: `ЗаполнитьЭтапИКатегориюФакта` → `ЗаполнитьПланНаФакт` → `ЗаполнитьПроизводные`.

### 6.1. `ЗаполнитьЭтапИКатегориюФакта(ТЗ, Зонтик)`

Карта `нормализованное имя ОН → Структура{Этап, Категория}` по плановым строкам этого зонтика:

```sql
ВЫБРАТЬ
	ВЫБОР
		КОГДА К.Номенклатура = ЗНАЧЕНИЕ(Справочник.Номенклатура.ПустаяСсылка)
			ТОГДА К.ОбщееНазвание.Наименование
		ИНАЧЕ К.Номенклатура.ОбщееНазваниеНоменклатуры.Наименование
	КОНЕЦ КАК ОбщееНазвание,
	К.Этап КАК Этап,
```

Ключ — `СокрЛП(Наименование)`, **не ссылка**: в справочнике ОН есть дубли карточек с одним
именем. При нескольких этапах одного имени берётся максимум по `Строка(Этап)` (детерминизм).

Несопоставленные остаются с пустым Етапом и категорией-плейсхолдером «Виробництво» — это норма.

### 6.2. `ЗаполнитьПланНаФакт(ТЗ)` — ETC/EAC

Ключ группы нетто строится так (первое подходящее правило):

| Условие | Ключ |
|---|---|
| `ОбщееНазвание` заполнено | `Строка(Подразделение.УникальныйИдентификатор()) + "|ОН|" + ВРег(СокрЛП(ОбщееНазвание.Наименование))` |
| иначе, `Аналитика` — `СправочникСсылка.Номенклатура` | `... + "|НОМ|" + Строка(Аналитика.УникальныйИдентификатор())` |
| иначе (`Аналитика` — текст `НоменклатураСС`) | `... + "|ТЕКСТ|" + ВРег(СокрЛП(Аналитика))` |

**Етап и Категорія в ключ не входят** — иначе перерасход одного этапа не гасит остаток другого.

Для каждой группы — суммы `ПланКол, ФактКол, ПланГрн, ФактГрн`, далее по приоритету:

1. `ПланГрн <= 0` → пропустить;
2. `ПланКол <= 0` → `ПланНаФакт = Макс(0, ПланГрн − ФактГрн)`;
3. `ФактКол <= 0` → `ПланНаФакт = ПланГрн` (ровно сумма, без пересчёта через цену);
4. иначе → `Макс(0, ПланКол − ФактКол) × (ПланГрн / ПланКол)`.

Синтетическая строка добавляется в ТЗ с единственным заполненным ресурсом
`ПланНаФактГрн = ПланНаФакт`; `ПрогнозГрн` и `ОтклонениеПрогнозГрн` посчитает
`ЗаполнитьПроизводные`, которая идёт следом (DRY — формула прогноза живёт в одном месте).
Категорія/Етап/ОбщееНазвание — с плановой строки группы с максимальным `ПланГрн`;
Аналитика/Единица — типизированные пустые ссылки; `Документ` — пустая ссылка
`Документ.ПоступлениеТоваровУслуг`. При fallback без ОН — Аналитика/Единица берутся с плановой строки.

### 6.3. `ЗаполнитьПроизводные(ТЗ)`

На каждой строке грейна:
`ЦенаПлан = ?(ПланКол = 0, 0, ПланГрн / ПланКол)`,
`ЦенаФакт = ?(ФактКол = 0, 0, ФактГрн / ФактКол)`,
`ОтклонениеКол = ФактКол − ПланКол`, `ОтклонениеГрн = ФактГрн − ПланГрн`,
`ПроцентКол = ?(ПланКол = 0, 0, ФактКол / ПланКол * 100)`,
`ПроцентГрн = ?(ПланГрн = 0, 0, ФактГрн / ПланГрн * 100)`,
`Прогноз = ФактГрн + ПланНаФактГрн`,
`ПрогнозГрн = Прогноз`,
`ОтклонениеПрогнозГрн = Прогноз − ПланГрн`,
`ПроцентПрогнозГрн = ?(ПланГрн = 0, 0, Прогноз / ПланГрн * 100)`.

Обрабатываются ВСЕ строки, включая синтетические: у них `ПланГрн = 0`, поэтому
`ПрогнозГрн = ОтклонениеПрогнозГрн = ПланНаФакт`, а проценты = 0.

## 10. Грабли

- В программной компоновке колонками рендерятся **только ресурсы**; измерение колонкой
  поставить нельзя — только уровнем группировки.
- Сохранённый пользовательский вариант прячет новые поля → «Ещё → Установить стандартные настройки».
- `КомпоновкаДанныхКлиентСервер.ПолучитьПараметр` в бухбазе может отсутствовать — писать
  собственный `ПолучитьЗначениеПараметра(Настройки, Имя)`, как в бухблизнеце по списанию.
- `Справочник.Подразделения` — иерархия **элементов**, реквизита `ЭтоГруппа` НЕТ.
- `ПРЕДСТАВЛЕНИЕ()` нельзя в `УПОРЯДОЧИТЬ ПО`/группировке — брать `.Наименование`.
- `Ссылка` — **запретное** имя переменной в BSL (конфликт с системным свойством).
- `КонецФункция` не компилируется, ошибка вылезает на СЛЕДУЮЩЕЙ строке — grep-чек парности
  `Функция/КонецФункции` и `Процедура/КонецПроцедуры` перед сборкой.
- COM-датам доверять нельзя (теряют день) — границы периода в тестах строить серверно
  (`ВЫБРАТЬ ДАТАВРЕМЯ(...)`).
- После правки — копировать файлы в основную конфигурацию `C:\Configuration_downloads\BASERP25\`
  (Rule #4): Designer читает оттуда, worktree он не видит.
