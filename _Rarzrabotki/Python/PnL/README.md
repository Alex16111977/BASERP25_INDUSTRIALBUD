# PnL import pipeline — Excel → 1С (Документ.А_ОтчетPL)

Импорт PL-отчётов компании **ТОВ "ІНДАСТРІАЛБУД"** из Excel в документы `Документ.А_ОтчетPL` через JSON промежуточный слой.

Один лист Excel = один документ = одно подразделение. Все документы создаются на организацию **ТОВ "ІНДАСТРІАЛБУД"**, без проведения.

## Источники

- `C:\Configuration_downloads\BASERP25\_Rarzrabotki\PL\Декабрь_25\!PL по компании Декабрь 2025.xlsx`
- `C:\Configuration_downloads\BASERP25\_Rarzrabotki\PL\Январь_26\!PL по компании Январь 2026.xlsx`

Конфиг путей: `config.py` → `EXCEL_FILES`.

## Требования

```bash
pip install openpyxl rapidfuzz pywin32
```

Python 3.13 (или 3.11 с `pywin32`). Запуск на Windows с установленным 1С:Enterprise 8.3, есть COM connector `V83.COMConnector`.

```
    ├── utils/
    │   ├── com_connect.py                 # V83.COMConnector, uuid_str (через XMLСтрока)

    ├── 01_extract_excel_to_json.py        # Excel → 01_raw_sheets.json
    ├── 02_extract_unique_articles.py      # → 02_unique_articles.json (дедуп по смыслу)
    ├── 03_extract_dds_from_erp.py         # СтатьиДвиженияДенежныхСредств → 04_dds_articles.json
    ├── 04_match_articles.py               # fuzzy → 05_mapping_pl_to_dds.json (1:N)
    ├── 05_build_groups.py                 # группы PL из Excel → 03_groups_pl.json
    ├── 06_extract_struct_from_erp.py      # СтруктураПредприятия → 06_struct_predpr.json
    ├── 07_match_sheets_to_struct.py       # fuzzy листы↔подразделения → 07_mapping_sheet_to_struct.json
    ├── 08_prepare_documents.py            # собирает документы с uuid → 08_documents_to_import.json
    ├── 10_upload_groups.py                # в 1С: Справочник.А_ГруппаСтатей_PL
    ├── 11_upload_articles.py              # в 1С: Справочник.А_Статьи_PL (ТЧ Статьи 1:N + реквизит шапки = 1-я строка ТЧ)
    ├── 12_upload_documents.py             # в 1С: Документ.А_ОтчетPL (--limit N для теста, --dry-run)
    ├── 15_sync_catalog_to_json.py         # 1С → JSON: подтягивает связки из А_Статьи_PL (locked) в JSON-мапинги
    └── _mass_set_manual_flag.py           # разово проставить А_РучнаяКорректировка=Истина всем существующим
```

## Порядок запуска

```bash
# Фаза A (разбор Excel)
python scripts/01_extract_excel_to_json.py
python scripts/02_extract_unique_articles.py

# Фаза B (сопряжение со статьями ДДС)
python scripts/03_extract_dds_from_erp.py
python scripts/04_match_articles.py
# [ручная правка] data/json/05_mapping_pl_to_dds.json для статей с match_type=none

python scripts/05_build_groups.py

# Фаза C (сопряжение подразделений)
python scripts/06_extract_struct_from_erp.py
python scripts/07_match_sheets_to_struct.py
# [ручная правка при необходимости] data/json/07_mapping_sheet_to_struct.json

# Фаза D (сборка документов в JSON)
python scripts/08_prepare_documents.py

# Фаза E (загрузка в 1С через COM)
python scripts/10_upload_groups.py
python scripts/11_upload_articles.py

# Сначала тест на одном документе
python scripts/12_upload_documents.py --limit 1

# Потом полный прогон
python scripts/12_upload_documents.py
```

## Маппинг колонок Excel → документ

| Excel (шапка строки 4) | Поле документа / ТЧ |
|---|---|
| колонка `B` (Статья) | `ДанныеОтчета.Статья` (ссылка на `А_Статьи_PL`) |
| `C` (Сумма по Ф1, грн) | `СуммаФома1` |
| `D` (Сумма по Ф2, грн) | `СуммаФорма2` |
| `E` (Сумма итого, грн) | `Сумма` |
| `G` (Комментарии) | `ДанныеОтчета.Комментарий` |

Итоговые строки (ВАЛОВАЯ ПРИБЫЛЬ, Маржинальный доход, %, и т.д.) и группы (Операционный доход, Административные затраты и т.д.) — **пропускаются** при импорте. Группы создаются как элементы `А_ГруппаСтатей_PL` и указываются в реквизите `А_Статьи_PL.Группа`.

## Защита ручных правок финансиста (флаг `А_РучнаяКорректировка`)

Справочник `А_Статьи_PL` имеет Булево-реквизит **`А_РучнаяКорректировка`** — чекбокс «Ручная корректировка» на форме элемента. **Ручные правки в 1С имеют наивысший приоритет:**

- Если `А_РучнаяКорректировка = Истина` → скрипты `11_upload_articles.py`, `_apply_dds_assignments.py`, `_fix_a_statii_pl_dds.py`, `_fix_pl_integrity.py` **полностью пропускают элемент** (ничего не перезаписывают).
- После массового развёртывания реквизита флаг выставлен `Истина` у всех 67 существующих статей (см. `scripts/_mass_set_manual_flag.py`).
- Новые статьи, которые скрипт создаёт автоматически (отсутствующие в 1С, но появившиеся в Excel), пишутся с `А_РучнаяКорректировка = Ложь`. **После проверки финансист должен поставить галку в 1С**, иначе следующий прогон пайплайна перезапишет её.
- При запуске `11_upload_articles.py` новые статьи помечаются в логе сообщением `NEW … << проверьте и поставьте галку «Ручная корректировка» в 1С!`.

**Как снять защиту** (вернуть скрипту возможность обновлять элемент): открыть статью в 1С → снять галку «Ручная корректировка» → записать. Следующий прогон пайплайна перезапишет ТЧ `Статьи`, шапочную ДДС, `Группу`, `ТипСтатьи`, `СтатьюДоходов` из Excel.

**Массовая простановка флага** (разовая, после развёртывания реквизита):
```bash
python scripts/_mass_set_manual_flag.py --dry-run  # проверить
python scripts/_mass_set_manual_flag.py              # боевой прогон
```
Скрипт обходит `ПередЗаписью` через `ОбменДанными.Загрузка = Истина` — иначе целостностные проверки (уникальность ДДС, обязательная шапочная ДДС для расходов) могут сорвать запись.

### Синхронизация 1С → JSON (`scripts/15_sync_catalog_to_json.py`)

После того как пайплайн однажды перешёл на «1С = источник истины», нужно чтобы и JSON-мапинги отражали реальное состояние справочника. Иначе `04_match_articles.py` каждый раз перетирает мапинг fuzzy-версией, и `08_prepare_documents.py` строит документы на устаревших связках.

Скрипт `15_sync_catalog_to_json.py` читает из 1С все защищённые статьи (`А_РучнаяКорректировка = Истина`) и **перезаписывает** JSON-файлы:

| JSON-файл | Что обновляется | Поле признака |
|-----------|-----------------|----------------|
| `05_mapping_pl_to_dds.json` | `dds_items` ← ТЧ `Статьи` (1:N связи к ДДС) | `match_type = "catalog_lock"` |
| `10_mapping_statya_dohodov.json` | `statya_dohodov_uuid/_name` ← `СтатьяДоходов` | `match_type = "catalog_lock"` |
| `02_unique_articles.json` | `uuid`, `group`, `type_statii` | — |

Запуск:
```bash
python scripts/15_sync_catalog_to_json.py --dry-run  # посмотреть diff
python scripts/15_sync_catalog_to_json.py            # записать
```

**Когда запускать:** каждый раз после серии ручных правок в 1С (до следующего прогона пайплайна). Для полной автоматизации можно встроить вызов в конец `04_match_articles.py` / `04b_match_statya_dohodov.py`.

Скрипт идемпотентный — повторный запуск без правок в 1С показывает `Изменений: 0`.

## Правила

- Связь статьи PL ↔ ДДС — **1:N** через ТЧ `А_Статьи_PL.Статьи` (как ожидает отчёт `АнализДоходовРасходов`). Реквизит шапки `СтатьяДвиженияДенежныхСредств` заполняется первой строкой ТЧ.
- Fuzzy-сопряжение: `ratio` / `token_set_ratio` / `partial_ratio` (rapidfuzz). Порог автомачта 85, кандидатов — 70.
- Дата документа — последний день месяца Excel-файла (23:59:59), берётся из `config.EXCEL_FILES[].period`.
- Подразделение: ссылка на `СтруктураПредприятия` (если нашли по смыслу) + текст в `ПодразделениеСтрока` всегда.
- `ОбменДанными.Загрузка = True` при записи документа — обход обработчиков модуля объекта.
- Документы **не проводятся** — только записываются.

## Неснятые вопросы

- 7 статей без пары ДДС: см. `data/reports/unmapped_articles.txt`. Можно вручную добавить маппинг в `05_mapping_pl_to_dds.json` (поле `dds_items`) и перезапустить `11_upload_articles.py`.
- Уникальность при повторном запуске: `11_upload_articles.py` и `10_upload_groups.py` идемпотентны (поиск по имени → update), `12_upload_documents.py` **не проверяет дубли** — создаст новый документ на каждую сборку.

## Налаштування CoGS-маркера в А_ОтчетPL (доробка 2026-04-25)

З 2026-04-25 у звіті `А_ОтчетPL`:
- Виручка береться з `РегистрНакопления.ВыручкаИСебестоимостьПродаж` (тільки документи Реалізація — без службових РасчетСебестоимостиТоваров).
- Себестоимість продаж (CoGS) виноситься окремим CTE на ту саму PL-статтю, у якій ТЧ Статьи містить ДДС з прапором `А_ПриёмникСебестоимостиПродажPL`.

### Один раз перед використанням нового звіту фінансист робить:

1. Відкрити **Справочник «Статті руху грошових коштів»** → знайти або створити статтю, призначену «тримати» суму CoGS у звіті PL (наприклад «Будівельні матеріали»).
2. Поставити галочку **«Приёмник себестоимости продаж (PL)»**, записати.
   - Платформа сама перевірить, що в системі тільки одна ДДС має цей прапор.
3. Відкрити **Справочник «Статті PL»** → потрібну PL-статтю (наприклад «Будівельні матеріали») → ТЧ «Статті» → додати створену ДДС, записати.
4. Сформувати **Отчет А_ОтчетPL** за потрібний період — у вибраній PL-статті з'явиться сума CoGS (по Підрозділах і Реалізаціях).

Якщо помилилися у виборі ДДС — змінити прапор у довіднику, переформувати звіт. Код не чіпається.
