## Context

Перша реалізація (комміти `a6a61408c..85e80896c`) використала ресурси **БезНДС** (`СуммаВыручкиБезНДС`, `СтоимостьУпрБезНДС`). Стандартний звіт «Доходы и расходы предприятия» (з НДС) показує:

| Метрика | Стандартний звіт (с НДС) | Наш А_ОтчетPL (БезНДС/Упр) |
|---|---:|---:|
| Виручка від продажу Глобино-2 лютий 2026 | **38 432 968.66** | 32 027 473.91 |
| Себестоимість продаж Глобино-2 лютий 2026 | **13 687 175.04** | 11 405 979.18 |

Фінансист працює з еталонним звітом «Доходы и расходы предприятия» — наш звіт мусить давати **ті самі цифри**.

---

## Рішення

Замінити 2 SQL-поля у `Reports/А_ОтчетPL/Ext/ObjectModule.bsl`:

| CTE | Поле БУЛО | Поле СТАЛО |
|---|---|---|
| `втЕРП_Доходы_Детали` (підзапит ВиР) | `Выр.СуммаВыручкиБезНДС` | `Выр.СуммаВыручки` |
| `втЕРП_CoGS_Детали` | `Выр.СтоимостьУпрБезНДС` | `Выр.Стоимость` |

WHERE-фільтри теж міняються: `СуммаВыручкиБезНДС <> 0` → `СуммаВыручки <> 0`, `СтоимостьУпрБезНДС <> 0` → `Стоимость <> 0`.

Інше (поля, JOIN, UNION ALL, CASE для Контрагент) **не змінюється**.

### Чому саме `СуммаВыручки` + `Стоимость`

Перевірено через MCP `execute_query` за лютий 2026 по Глобино-2:

```
СуммаВыручки         = 38 432 968.66  ← збігається з еталоном
СуммаВыручкиБезНДС   = 32 027 473.91  ← БезНДС (поточний код)
Стоимость            = 13 687 175.04  ← збігається з еталоном
СтоимостьУпр         = 11 405 979.18  ← Упр-облік
СтоимостьУпрБезНДС   = 11 405 979.18  ← БезНДС-Упр (поточний код)
```

Узгоджено з фінансистом: **використовувати `СуммаВыручки` + `Стоимость`** (с НДС).

## Drill-down до документів Реалізації (поза скоупом)

Поле `Документ` у результаті — типу `Документ.РеализацияТоваровУслуг` (стандартне посилання). Drill-down працює через СКД (стандартна поведінка для посилальних полів).

Якщо у самій формі звіту drill-down не відкриває Реалізації — це окрема проблема в **СКД-варіанті** (треба перевірити налаштування «Действие» для поля Документ у конкретному варіанті). **Поза цим скоупом** — спочатку фіксуємо суми, drill-down перевіряємо після.
