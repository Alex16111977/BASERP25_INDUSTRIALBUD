# Реестр фейк-статей PL (как не грузить служебные строки финансиста)

**Проблема:** в листах Excel финансист пишет служебные строки, которые НЕ являются статьями
отчёта PL: договоры подряда, объекты, заметки с суммами в имени. При импорте они ошибочно
создавались как `Справочник.А_Статьи_PL` и попадали в `Документ.А_ОтчетPL`.

**Решение — два слоя фильтра** (оба отсеивают строку как `summary` → в каталог/документ не идёт):

## 1. Структурный фильтр (основной) — «всё после итогов = мусор»

Фейки лежат **ниже финальных итоговых строк** листа. Как только парсер встречает строку из
`config.REPORT_END_MARKERS` (`прибыль в распоряжении компании`, `рентабельность`), он ставит
`report_ended=True`, и **все последующие detail-строки пропускаются** — независимо от имени.

Реальные промежуточные итоги (валовая прибыль, маржинальный доход, операционная прибыль) — НЕ
конец отчёта, они выше и по-прежнему идут в `ИтогиОбщие`. Реальные detail выше итогов (Дивиденды,
Затраты на налог на прибыль) сохраняются.

> Если у нового листа структура иная (мусор выше «рентабельности») — добавь подходящий маркер в
> `config.REPORT_END_MARKERS` (подстрочное совпадение, casefold).

Код: `scripts/utils/excel_parser.py` → `parse_workbook` (флаг `report_ended`).

## 2. Реестр имён (вторичный) — `data/fake_articles.json`

Точечный отсев по имени (на случай мусора НЕ после итогов или как страховка). Три вида правил:

| Ключ | Что | Пример |
|---|---|---|
| `substrings` | подстрока в имени (casefold) | `"Договір підряду"` |
| `exact_names` | точное имя (casefold) | — |
| `regexes` | регулярка (`flags:"i"` = ignorecase) | `№\d\d/\d\d` (номер договора), `\d…(грн\|млн\|тыс)` (сумма+валюта) |

Хелпер: `scripts/utils/fake_articles.py` → `match_fake(name) -> reason|None`. Вызывается в
`excel_parser.classify_row` (после `TOTAL_ROW_KEYWORDS` / `EXTRA_COMMENT_NAMES`).

## Как добавить новый фейк (без правок кода)

1. Открой `data/fake_articles.json`.
2. Добавь запись в нужный раздел:
   ```json
   {"pattern": "<подстрока или regex>", "reason": "почему фейк", "added": "YYYY-MM-DD", "example": "..."}
   ```
   - устойчивый кусок имени → `substrings`;
   - точное полное имя → `exact_names`;
   - шаблон (номер/сумма/код) → `regexes` (+ `"flags":"i"`).
3. Перегони `01_extract_excel_to_json.py` → `02_extract_unique_articles.py` — фейк исчезнет из
   `02_unique_articles.json`. Если он уже создан в 1С — пометь статью на удаление.

## Проверка

```bash
python scripts/01_extract_excel_to_json.py
python scripts/02_extract_unique_articles.py
# в 02_unique_articles.json не должно быть отфильтрованных имён
```
