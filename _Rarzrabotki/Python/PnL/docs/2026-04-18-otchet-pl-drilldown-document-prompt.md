## 1. Задача

Доработать **Отчёт.А_ОтчетPL** (`Reports/А_ОтчетPL/`) так, чтобы:

### 1.1 Drill-down до документа
Добавить поле `Документ` (тип `ДокументСсылка.А_ОтчетPL`) в dataset. Это позволит финансисту из отчёта щелчком открывать конкретный документ А_ОтчетPL (стандартная расшифровка СКД сработает при правильной типизации).

### 1.2 Колонка Комментарий
Добавить поле `Комментарий` (тип `Строка(1000)`) из ТЧ `Документ.А_ОтчетPL.ДанныеОтчета.Комментарий`. Финансист хранит там построчные заметки типа «Служба Єдиного Замовника - 16 640,0» — их нужно видеть в отчёте сверки.

В варианте `А_ОтчетPL_РасшифровкаПоНаправлению` дополнительно добавить `Документ` как группировку в строках (между `Подразделение` и `Группа`), чтобы в сводном представлении видеть какие документы вошли в итог по направлению.

## 3. Детальный план реализации (по шагам)

### Шаг 3.1: Правка ObjectModule.bsl

**Файл:** `Reports/А_ОтчетPL/Ext/ObjectModule.bsl`.

**В CTE `втPL`:**
- Добавить в `ВЫБРАТЬ`:
  ```
  ТЧ.Ссылка КАК Документ,
  МАКСИМУМ(ТЧ.Комментарий) КАК Комментарий
  ```
- `Документ` добавить в `СГРУППИРОВАТЬ ПО` (один документ = один лист/подразделение за месяц → не размножает).
- `МАКСИМУМ(Комментарий)` — потому что разные строки одной статьи могут иметь разные комментарии; MAX берёт один (обычно это приемлемо; если нужна склейка — делать постобработкой ТЗ, но по умолчанию MAX).

**В CTE `втPL_сЕРП` (итоговая PL-таблица):**
- Пробросить `PL.Документ КАК Документ` и `PL.Комментарий КАК Комментарий` рядом с другими полями.

**В CTE `втЕРП_БезPL_Доходы` и `втЕРП_БезPL_Расходы` (ветки ЕРП-без-PL):**
- Добавить колонки с типизированными пустыми значениями (UNION ALL требует совпадения типов, просто `NULL` не годится):
  ```
  ЗНАЧЕНИЕ(Документ.А_ОтчетPL.ПустаяСсылка) КАК Документ,
  ВЫРАЗИТЬ("" КАК Строка(1000)) КАК Комментарий
  ```

**ВАЖНО:** сохранить модификатор `Экспорт` у функции `ПолучитьОбъединенныеДанные` — он используется Python COM-интеграцией (`_verify_pl_parity_adr.py`).

### Шаг 3.2: Типизация колонок Object dataset (в той же ObjectModule.bsl)

Object dataset не передаёт типы колонок в СКД автоматически. Перед `ВнешниеНаборыДанных = Новый Структура("Данные", ТаблицаДанных);` нужно **явно типизировать колонки**:

```bsl
ТаблицаДанных.Колонки.Документ.ТипЗначения = Новый ОписаниеТипов("ДокументСсылка.А_ОтчетPL");
ТаблицаДанных.Колонки.Комментарий.ТипЗначения = Новый ОписаниеТипов("Строка", Новый КвалификаторыСтроки(1000));
```

Без этого клик на Документ не откроет форму документа (СКД не поймёт что это ссылка).

## 5. Критичные нюансы (не потерять!)

1. **Типизация Object dataset** — см. шаг 3.2. Без `ТипЗначения` на колонке Документ drill-down не сработает.
2. **UNION ALL требует совпадения типов колонок** — для пустых веток использовать `ЗНАЧЕНИЕ(Документ.А_ОтчетPL.ПустаяСсылка)` и `ВЫРАЗИТЬ("" КАК Строка(1000))`, а не просто `NULL`.
3. **`МАКСИМУМ(Комментарий)`**, не `Комментарий` в GROUP BY — иначе одна PL-статья разобьётся на несколько строк по разным комментариям.
4. **Сохранить `Экспорт`** у `ПолучитьОбъединенныеДанные` — ломает Python-тесты паритета.
5. **Имя параметра формы — `КлючВарианта`** (не `ВариантКлюч`), если придётся править клиентский код ОткрытьСверкуСЕРП — см. NotebookLM source `14581045-be96-43d4-8c8b-8cba20e7afed`.
6. **Реквизит в ТЧ называется `Комментарий`** (Строка, длина в метаданных) — проверить через MCP `get_metadata_structure("Documents", "А_ОтчетPL")` ТЧ ДанныеОтчета.
7. **Регистры источников фактов (важно при рефакторинге запроса):** `РегистрНакопления.ПрочиеРасходы.Обороты` (ресурс `СуммаРеглПриход`), `РегистрНакопления.ПрочиеДоходы.Обороты` (ресурс `СуммаРеглПриход`), `РегистрНакопления.ФинансовыеРезультаты.Обороты` (ресурс `ДоходыРеглБезНДСОборот`). НЕ использовать `Движения*ДоходыРасходы` (legacy).
