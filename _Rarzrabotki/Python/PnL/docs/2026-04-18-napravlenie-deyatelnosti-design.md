# Дизайн: НаправлениеДеятельности в документах PnL

**Проект:** BAS ERP 2.5 INDUSTRIALBUD
**Дата:** 2026-04-18
**Статус:** Утверждён пользователем, готов к передаче в writing-plans
**Цель:** Сделать сводный лист Excel (PL_Логистика, PL_Производство_СВОД, PL_ЦО_Логистика и т.п.) сопоставимым со сводом по Направлению деятельности в типовом отчёте `АнализДоходовРасходов`.

---

## 1. Контекст и мотивация

Финансист ведёт PnL в Excel: каждый лист = один документ `Документ.А_ОтчетPL` в 1С. Через документ-маппинг `Документ.А_РасшифровкаЛистов` лист привязывается к конкретному подразделению.

**Проблема:** некоторые листы Excel — не элементы, а свод. Например `PL_Логистика` объединяет цифры по MAN №3, MAN №4, MAN №5, Экспедирование + сама Логистика. Сегодня такая строка привязана к одному «корневому» подразделению «Логистика», но в отчёте `А_ОтчетPL` (сверка Excel ↔ ERP) она сравнивается с данными только одного подразделения, а не с агрегатом. Это мешает сверять свод.

Типовой отчёт `АнализДоходовРасходов` (вариант «Направление-Подразделение-рабочая») уже умеет группировать по направлению через фильтр `Подразделение.А_НаправлениеДеятельности = Логистика` и раскладывать MAN'ы по колонкам. Нужно, чтобы `А_ОтчетPL` умел то же самое.

## 3. Принятые решения (обсуждены и утверждены)

| № | Развилка | Решение | Обоснование |
|---|---|---|---|
| **1.1** | `Подразделение` vs `НаправлениеДеятельности` в ТЧ `Расшифровка` | **Оба заполнены у сводных** | Сохраняет логику поиска А_ОтчетPL по `(ПодразделениеСтрока + Подразделение)`. `Подразделение` — якорь в дереве, `Направление` — бизнес-ось. |
| **3.1** | Один вариант СКД с условием vs два варианта | **Два отдельных варианта СКД** | Сводный режим требует иной группировки (разворот по дочерним в колонках). Чистое разделение, проще поддерживать. |
| **4.1** | Только сводная цифра vs разбивка по дочерним | **Разбивка по дочерним в колонках** | Соответствует UX типового `АнализДоходовРасходов`, финансист сразу видит источник расхождения. |
| **5.6** | Миграция старых А_ОтчетPL | **Разовый скрипт** | Детерминированная операция, 100% покрытие за один прогон. |

**Дополнительно:** перечисление `А_ТипРасшифровки` **не добавляется** (YAGNI — двух булевых сигналов `ВключатьДочерние + есть ли Подразделение` достаточно).

## 4. Целевая архитектура

### 4.1 Документ.А_РасшифровкаЛистов — ТЧ `Расшифровка`

Добавить 2 реквизита:

| Реквизит | Тип | Семантика |
|---|---|---|
| `НаправлениеДеятельности` | `СправочникСсылка.НаправленияДеятельности` | Направление, к которому относится лист Excel |
| `ВключатьДочерние` | `Булево` | Строка-свод: агрегирует все подразделения направления |

**Правила заполнения:**

| Роль строки | `Подразделение` | `НаправлениеДеятельности` | `ВключатьДочерние` |
|---|---|---|---|
| Элемент (Крушинка, MAN №3) | заполнено | `Подразделение.А_НаправлениеДеятельности` | `Ложь` |
| Свод направления (ЦО_логистика → Логистика) | корневое напр. (Логистика) | Логистика | `Истина` |
| Суб-свод (PL_ЦО_Строительство) | корневое напр. (Строительство) | Строительство | `Истина` |
| Общий итог (PL_Свод) | пусто | пусто (все направления) | `Ложь` (обрабатывается иначе — вне скоупа) |
| Служебное (Метрики, Индекс) | пусто | пусто | `Ложь` |

### 4.2 Документ.А_ОтчетPL — шапка

Добавить 2 реквизита в шапку:

| Реквизит | Тип | Семантика |
|---|---|---|
| `НаправлениеДеятельности` | `СправочникСсылка.НаправленияДеятельности` | Направление этого листа |
| `ВключатьДочерние` | `Булево` | Документ-свод по направлению |

**Автоподстановка на форме документа** (`ПриИзмененииПодразделения` / `ОбработкаЗаполнения`):
- При выборе `Подразделение` → `НаправлениеДеятельности = Подразделение.А_НаправлениеДеятельности` (если пусто).
- `ВключатьДочерние` пользователь ставит руками (или скрипт при импорте).

### 4.3 Отчёт.А_ОтчетPL — новый вариант СКД

**Имя:** `А_ОтчетPL_РасшифровкаПоНаправлению`

**Отличия от существующего `А_ОтчетPL_РасшифровкаДокументаОтчетPL`:**
1. Отбор: вместо `Подразделение = &Подразделение` → `Подразделение.А_НаправлениеДеятельности = &НаправлениеДеятельности`.
2. Добавлено поле `Подразделение` как **группировка в колонках** — для разворота по дочерним (MAN №3, №4, №5, Экспедирование, Логистика).
3. Параметр `НаправлениеДеятельности` типа `СправочникСсылка.НаправленияДеятельности` — включён по умолчанию.
4. Остальная логика (соединение документов А_ОтчетPL с регистрами ERP, колонка «Расхождение») — идентична существующему варианту.

### 4.4 Форма Документа.А_ОтчетPL — кнопка «Открыть сверку с ЕРП»

Логика выбора варианта и отбора:

```bsl
// Псевдокод — реализуется в plan
Если Объект.ВключатьДочерние И ЗначениеЗаполнено(Объект.НаправлениеДеятельности) Тогда
    ПараметрыФормы.Вставить("ВариантКлюч", "А_ОтчетPL_РасшифровкаПоНаправлению");
    Отбор.Вставить("НаправлениеДеятельности", Объект.НаправлениеДеятельности);
ИначеЕсли ЗначениеЗаполнено(Объект.Подразделение) Тогда
    ПараметрыФормы.Вставить("ВариантКлюч", "А_ОтчетPL_РасшифровкаДокументаОтчетPL");
    Отбор.Вставить("Подразделение", Объект.Подразделение);
КонецЕсли;
```

## 6. Критерии приёмки

### 6.1 Структурные (проверка метаданных через MCP)
- `Документ.А_РасшифровкаЛистов.Расшифровка` содержит реквизиты `НаправлениеДеятельности`, `ВключатьДочерние`.

- `Отчет.А_ОтчетPL` содержит вариант `А_ОтчетPL_РасшифровкаПоНаправлению`.

### 6.2 Данные (проверка через MCP query)
- Во всех 3-х документах А_РасшифровкаЛистов ≥ 95% непустых строк ТЧ имеют заполненное `НаправлениеДеятельности`.
- Для строк с `ВключатьДочерние = Истина` обязательно заполнено `НаправлениеДеятельности`.
- Все существующие А_ОтчетPL (не помеченные к удалению) имеют заполненное `НаправлениеДеятельности` (либо явно, либо через автоподстановку в скрипте 14).

### 6.3 Функциональные (проверка в клиенте 1С)
- На форме документа А_ОтчетPL выбор `Подразделение = Крушинка` → автоматически заполняется `НаправлениеДеятельности`.
- Для PL_Логистика (`ВключатьДочерние = Истина`) клик «Открыть сверку с ЕРП» → открывается вариант «ПоНаправлению», в колонках — MAN №3, №4, №5, Экспедирование, Логистика.
- Для элементного листа (Крушинка) клик → открывается существующий вариант, отбор по Подразделению.
- Сводная цифра из нового варианта А_ОтчетPL совпадает с колонкой «Итого» в `АнализДоходовРасходов` за то же направление и период.

### 6.4 Идемпотентность
- Повторный запуск `13_fill_rasshifrovka_listov.py` не меняет данные (если 07_mapping не менялся).
- Повторный запуск `14_migrate_otchetpl_napravlenie.py` не меняет данные, отчитывается «0 обновлено».

## 9. Риски и нюансы

|---|---|
