## Прецеденты и риски

### Риск 1: Филиалы появились позже января 2025

Некоторые подразделения (например, МД ВООЗ 2025, МД ООН 2025) могли быть открыты не с начала года. В Excel колонки за Январь 2025 у них пусты.

**Что произойдёт:** `excel_parser.find_month_columns` найдёт колонку, но в `01_raw_sheets.json` для этого листа `rows=[]`. В `08_prepare_documents.py` документ собирается только если есть строки → пропускается. Это **не ошибка**, а правильное поведение.

### Риск 2: Локированные статьи в 1С — финансист поправил вручную

Если финансист после первой загрузки декабря 2025 правил статьи в 1С (выставил `А_РучнаяКорректировка=Истина` или подменил ДДС-маппинг), `11_upload_articles.py` корректно их пропустит (`LOCK` в логе). Тестировать не нужно.

### Риск 3: ДДС-конфликт у новой статьи

Если 2025 год принёс новую статью, у которой fuzzy-маппинг ДДС конфликтует с уже существующей PL-статьёй («ДДС не может использоваться одновременно…»), `11` сделает `SKIP-CONFLICT`. Финансисту нужно вручную создать статью в 1С с корректной ДДС.

### Риск 4: Нумерация документов А_РасшифровкаЛистов

Номера не привязаны к дате (`Дата=31.01.2025` ≠ `Номер №6`). Сортировка по дате — единственный надёжный способ. Это нормально для 1С (автонумерация хронологическая, не по дате документа).

### Риск 5: Случайно запустили `13` без `--month`

Если запустить `13_fill_rasshifrovka_listov.py` БЕЗ фильтра, скрипт пройдётся по всем `EXCEL_FILES` (теперь 16!) и **затрёт** ТЧ Расшифровка всех документов №1–№5 + создаст 11 новых. Это **уничтожит ручные правки финансиста** в декабре 2025 (например, ручной маппинг `PL_ЦО_Строительство → Строительство` который НЕТ в 07_mapping). Backup сохранится в `data/json/13_backup_*.json`, восстановление — вручную через клиента 1С.

**Жёстко:** каждый запуск `13` должен иметь `--month YYYY-MM`. Перед боевым прогоном — обязательно `--dry-run`.

- **НЕ копировать** `path` декабрьского Excel в новый файл «Январь 2025.xlsx» (создание физических копий не нужно — pipeline различает по `month_header`).
