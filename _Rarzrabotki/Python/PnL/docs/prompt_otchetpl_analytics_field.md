## Цель — сквозная (от регистра до отчёта)

В отчёте `Отчет.А_ОтчетPL` строки фактических расходов (`СуммаЕРП`) сейчас расшифровываются до **Подразделение + ДДС + Документ-регистратор + Контрагент**. Финансист просит добавить **колонку «Аналитика»** в расшифровку, которая показывает **исполнителя/получателя** в зависимости от типа документа-регистратора:

| Тип регистратора | Что показывать в «Аналитика» |
|---|---|
| `ПриобретениеТоваровУслуг`, `РасходныйКассовыйОрдер`, `СписаниеБезналичныхДенежныхСредств`, `АктВыполненныхРабот`, `ВозвратТоваровПоставщику`, `ПриходныйКассовыйОрдер`, `ПоступлениеБезналичныхДенежныхСредств`, `ВозвратТоваровОтКлиента` | **Контрагент** (как сейчас в колонке Контрагент) |
| `АвансовыйОтчет` | **ПодотчетноеЛицо** (`Документ.АвансовыйОтчет.ПодотчетноеЛицо` → Справочник.ФизическиеЛица) |
| `ОтражениеЗарплатыВФинансовомУчете` | **ФизическоеЛицо** — из реквизита `РегистрНакопления.ПрочиеРасходы.А_ФизическоеЛицо` (он есть в метаданных, но **СЕЙЧАС ПУСТОЙ** — никто его не заполняет при проведении ОЗП!) |

**Подзадача 1 (предусловие)**: расширить процедуру проведения документа `ОтражениеЗарплатыВФинансовомУчете` так, чтобы в движениях по регистру `ПрочиеРасходы` заполнялся `А_ФизическоеЛицо`. Источник физлица — три ТЧ документа: `НачисленнаяЗарплатаИВзносыПоФизлицам`, `НачисленныйНДФЛ`, `УдержаннаяЗарплата` (как уже сделано в `А_ВзаиморасчетыССотрудниками.ЗаполнитьИзОтраженияЗП` — образец полностью рабочий).

**Подзадача 2**: после правки модуля менеджера ОЗП — перепровести существующие документы ОЗП за нужный период (минимум 2024+2025+2026 Q1), чтобы заполнить `А_ФизическоеЛицо` ретроспективно.

**Подзадача 3**: в отчёте `А_ОтчетPL` (ObjectModule + варианты СКД) расширить CTE `втЕРП_Расх_Детали` — добавить поле `Аналитика` через `CASE` по типу регистратора. В вариантах СКД добавить группировку/выбор/настройку видимости новой колонки.

## Архитектура решения

### Этап A — расширить ManagerModule ОЗП (заполнение `А_ФизическоеЛицо` в ВТ)

Файл: `Documents/ОтражениеЗарплатыВФинансовомУчете/Ext/ManagerModule.bsl`.
Функция: `ТекстЗапросаТаблицаВтИсходныеПрочиеРасходы` (строка 2991).

**Стратегия (рекомендуемая — минимальное вмешательство):**

1. **НЕ менять** ключ группировки в основной СТЕ ВтИсходныеПрочиеРасходы (это сломает Σ-инвариант с типовыми регистрами).
2. После формирования основной СТЕ — добавить **второй CTE/UPDATE-шаг**, который добавит колонку `А_ФизическоеЛицо` через JOIN с детализирующей подтаблицей по (Подразделение, СтатьяРасходов) → один-к-многим. Если на одну группу (Подразделение, СтатьяРасходов) приходится несколько физлиц с разной суммой — суммы пропорционально распределяются.

**Альтернатива (проще, но меняет структуру движений):** в SELECT/GROUP BY добавить `Н.ФизическоеЛицо` (из `ВТНачисленнаяЗарплатаИВзносы`, которая уже включает `ВТНачисленнаяЗарплатаИВзносыПоФизлицам`). Тогда строк станет больше, но движения будут детализированы до физлица. **Внимание**: суммы должны остаться корректными (сумма движений = типовая сумма). Проверить test'ом на одном документе.

**Выбор подхода — за разработчиком.** Перед выбором — открыть `ВТНачисленнаяЗарплатаИВзносы` (см. функцию `ТекстЗапросаВтНачисленнаяЗарплатаИВзносы` в том же модуле), посмотреть включает ли она физлицо. Если нет — пересобрать через JOIN с `ВТНачисленнаяЗарплатаИВзносыПоФизлицам`.

**Обязательно**:
- Сохранить Σ-инвариант: сумма движений по регистру не должна измениться (только разнесение по ФЛ).
- НЕ заполнять `А_ФизическоеЛицо` для строк выработки по прочим работам (`ВтТаблицаВыработкаСотрудников`) если нет однозначного физлица — оставить пусто.

### Этап B — перепровести существующие документы ОЗП

После правки модуля менеджера регистр `ПрочиеРасходы.А_ФизическоеЛицо` останется пустым для уже проведённых документов. Нужно перепровести.

**Способ (через Python COM):**

```python
# scripts/_reprovesti_ozp.py (создать в _Rarzrabotki/Python/)
import win32com.client
v8 = win32com.client.Dispatch("V83.COMConnector")
erp = v8.Connect('Srvr="SQLSERVER";Ref="BaseERP";Usr="Администратор";Pwd="24043"')

q = erp.NewObject("Запрос")
q.Text = """
ВЫБРАТЬ Ссылка
ИЗ Документ.ОтражениеЗарплатыВФинансовомУчете
ГДЕ Проведен И Дата МЕЖДУ &НМ И &КМ
УПОРЯДОЧИТЬ ПО Дата
"""
q.SetParameter("НМ", erp.Дата(2024, 1, 1))
q.SetParameter("КМ", erp.Дата(2026, 4, 30, 23, 59, 59))
tz = q.Execute().Выгрузить()

mode = erp.РежимЗаписиДокумента.Проведение
for i in range(tz.Количество()):
    obj = tz.Получить(i).Ссылка.ПолучитьОбъект()
    try:
        obj.Записать(mode)
        print(f"OK {obj.Номер} {obj.Дата}")
    except Exception as e:
        print(f"FAIL {obj.Номер}: {e}")
```

**Объём:** документы ОЗП обычно один на месяц на организацию. За 28 месяцев = ~28 документов на ТОВ ІНДАСТРІАЛБУД (`Организация` фильтровать через `Орг.КодПоЕДРПОУ = "40645273"` если нужно сузить).

**Проверка**: после перепровода
```sql
ВЫБРАТЬ КОЛИЧЕСТВО(*) КАК ВсегоДвижений,
       СУММА(ВЫБОР КОГДА А_ФизическоеЛицо <> ЗНАЧЕНИЕ(Справочник.ФизическиеЛица.ПустаяСсылка) ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК СФизЛицом
ИЗ РегистрНакопления.ПрочиеРасходы
ГДЕ Регистратор ССЫЛКА Документ.ОтражениеЗарплатыВФинансовомУчете
```
Ожидается: `СФизЛицом` > 0 (для типов начислений с фиксированным физлицом).
