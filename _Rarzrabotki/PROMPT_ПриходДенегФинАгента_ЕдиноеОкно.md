## 1. Контекст документа (что это и что нельзя ломать)

`А_ПриходДенегОтФинАгента` — кастомный (`А_`) документ: приход денег от **финансового агента** (факторинг),
интегрирован с **Казной** через механизм обмена. UUID `75960e1c-6c23-4ae2-b1b0-97ffcd9e94f7`.

**Движения (проведение):** единственный регистр — `РегистрНакопления.А_ДенежныеСредстваФинАгенты`
(ВидДвижения = `Расход`), строки берутся из ТЧ `РасшифровкаПлатежа` (строки с `Сумма<=0` пропускаются).

**Две табличные части:**
- `А_РасшифровкаФинАгент` — **входная** ТЧ (заполняется пользователем/в форме). Колонки:
  ФинАгент / ДокументПередачи (`СписаниеБезналичныхДенежныхСредств`) / Направление / Сумма / СуммаКомиссииФА.
- `РасшифровкаПлатежа` — **производная** ТЧ, наполняется кодом `ОбновитьПриходДенегОтФинАгентаПослеОбмена()`
  (Очистить + пересборка из `А_РасшифровкаФинАгент`).

> Имена полей двух ТЧ различаются: входная `А_РасшифровкаФинАгент.ДокументПередачи` vs производная
> `РасшифровкаПлатежа.ДокСписаниеБезналичныхДенежныхСредств` — форму документа править по **входной** ТЧ,
> не по именам из кода проведения.

**⚠ НЕ СЛОМАТЬ (инварианты модуля объекта — `Documents/А_ПриходДенегОтФинАгента/Ext/ObjectModule.bsl`):**
- **Флаг `А_Обработан` = гейт идемпотентности.** `ОбновитьПриходДенегОтФинАгентаПослеОбмена()` при
  `А_Обработан=Истина` делает ранний `Возврат`. Если форма/доработка **сбросит `А_Обработан` в Ложь**
  у уже обработанного документа — при следующей записи `РасшифровкаПлатежа` будет **очищена и пересобрана**,
  ручные правки потеряются. **Доработка форм не должна трогать/сбрасывать `А_Обработан`.**
- `ПередЗаписью` вызывает `ОбновитьПриходДенегОтФинАгентаПослеОбмена()` **ДО** гарда `ОбменДанными.Загрузка`
  (метки `//***ERP`, сознательная архитектура — порядок не трогать).
- `ПриЗаписи` (когда НЕ `Загрузка`) вызывает `СоздатьПриходДенегПоФинАгенту()` — **создаёт/перепроводит
  веер дочерних ПКО/РКО/ПриобретениеТоваровУслуг** (тяжёлая логика). Доработка формы **не должна провоцировать
  лишние `Записать()`** документа.
- **Итоги в подвалах ТЧ — нативные** (`<Footer>true</Footer>` + `<FooterDataPath>…TotalСумма</FooterDataPath>`,
  уже в форме). Кодом **не** пересчитывать — модуль объекта итоги ТЧ не считает (подтверждено).
- В модуле объекта **нет** обработчиков `ОбработкаПроверкиЗаполнения`/`ПриКопировании`/`ОбработкаЗаполнения` —
  опираться на них нельзя.

## 5. Задача A — Форма документа: `Form.xml`

### 5.1 Командная панель (инвариант формы документа)

Сделать в `Form.xml` формы документа:

1. **`<CommandSet>` перед `<AutoCommandBar>`** — глушит автодубли заменённых кнопками команд.
   Эталон `АмортизацияОС` — ровно 3 команды (НЕ исключать `SetDeletionMark` — «Пометка» придёт в «Ещё»
   автозаполнением):
   ```xml
   <CommandSet>
       <ExcludedCommand>Post</ExcludedCommand>
       <ExcludedCommand>PostAndClose</ExcludedCommand>
       <ExcludedCommand>Write</ExcludedCommand>
   </CommandSet>
   ```
2. **`<AutoCommandBar name="ФормаКоманднаяПанель" id="-1">` — `Autofill` НЕ выставлять** (оставить по умолчанию =true;
   именно автозаполнение дотягивает «Пометка»/«Печать»/«Ещё»). Содержимое панели (порядок как у эталона):
   - `<Button name="ФормаПровестиИЗакрыть">` `Representation=Text`, `DefaultButton=true`,
     `CommandName=Form.Command.ПровестиИЗакрыть`;
   - `<Button name="ФормаЗаписать">` `Representation=Picture`, `CommandName=Form.Command.ЗаписатьДокумент`;
   - `<Button name="ФормаПровести">` `Representation=Picture`, `CommandName=Form.Command.ПровестиДокумент`;
   - `<Popup name="ПодменюСоздатьНаОсновании">` (Picture `CommonPicture.ЗаполнитьПоШаблону`) с 3 подгруппами
     `ПодменюСоздатьНаОснованииВажное/Обычное/СмТакже`;
   - `<ButtonGroup name="ФормаГлобальныеКоманды">` с `<CommandSource>FormCommandPanelGlobalCommands</CommandSource>`;
   - `<Popup name="ПодменюОтчеты">` (Picture `CommonPicture.Отчеты`, `Representation=PictureAndText`) с 3 подгруппами
     `ПодменюОтчетыВажное/Обычное/СмТакже`;
   - `<Popup name="ПодменюЗаполнить">` (Picture `CommonPicture.ЗаполнитьФорму`, без подгрупп).
   > `ПодменюПечать` и `ФормаСправка` в явном XML эталона **отсутствуют** — приходят автозаполнением.
   > Можно не объявлять.
3. **`<Events><Event name="OnCreateAtServer">ПриСозданииНаСервере</Event> … </Events>`** — + события
   жизненного цикла из §6 (каждое событие → процедура в модуле).
4. **Раздел `<Commands>`** — 3 команды формы (отображение Text/Picture задаётся **на КНОПКЕ**, не на команде).
   Вербатим из `АмортизацияОС`:

### 5.2 Перенести меню-контейнеры из тела в `AutoCommandBar` (исправить антипаттерн)

В текущем `Form.xml` группы `ПодменюСоздатьНаОснованииВажное/Обычное/СмТакже`, `ФормаГлобальныеКоманды`,

- перенести **внутрь** `<AutoCommandBar>` (как `<Popup>`/`<ButtonGroup>` по §5.1);
- из тела формы **удалить**;
- имена контейнеров **каноничны — не переименовывать** (БСП ищет по имени).

> **Контрольная греп-проба после правки (обязательна):** `name="ПодменюОтчеты"` должно встречаться

> `<UsualGroup name="Подменю…">`/`ФормаГлобальныеКоманды`.

### 5.3 Тело формы — данные (сохранить как есть, + контейнер Свойств)

Тело оставить ТОЛЬКО с данными: группа «Номер и дата», шапка (ФинАгент/СтатьяДДС/Организация/Касса/…),

## 9. Грабли / анти-паттерны (из `bas-bsp-form` + памяти проекта)

- ❌ **Меню-контейнеры (`Подменю…`/`ФормаГлобальныеКоманды`) в теле формы** вместо `AutoCommandBar` —
  главный дефект текущей формы документа. Перенести (§5.2), греп-проба обязательна.
- ❌ **Чистый `Autofill=true` без `CommandSet`/команд/кнопок** на форме документа → «Записать»/«Провести» текстом,
  читаются как «Провести дважды». Нужен явный контракт §5.1.
- ❌ **Dangling `<Event>`**: каждый `<Event name="…">Имя</Event>` обязан иметь `Процедура Имя(…)` в модуле,
  иначе рантайм «обработчик события не найден». Финальная греп-сверка `<Event` ↔ `Процедура`.
  (Боевой кейс памяти: у `А_ОтражениеЗПпоКазне` ФормаДокумента 5 `<Event>` но 1 обработчик — латентно годами.
  Поэтому `А_ОтражениеЗПпоКазне` как образец Казна-документа использовать осторожно, эталон — `АмортизацияОС`.)
- ❌ **`ПодключаемыеКомандыКлиент.ОбновитьКоманды`** — такого метода нет; `ОбновитьКоманды` у
  `ПодключаемыеКомандыКлиентСервер`.
- ❌ Вызов **служебного модуля/области БСП** вместо `Программного интерфейса` (#std551) — ломается при обновлении БСП.
- ❌ Имена контейнеров подменю / `Подключаемый_*` **отличны от каноничных** — БСП не находит.
- ❌ **`Edit`-инструментом по XML конфигурации** — теряет табы. Только Python-regex со счётчиком замен.
- ❌ **Массовое перепроведение** документов `А_ПриходДенегОтФинАгента` для «проверки» — `ПриЗаписи` создаёт/перепроводит
  веер дочерних ПКО/РКО/Приобретение (тяжело + риск регрессий взаиморасчётов). **Историю перепроводит пользователь
  сам в UI** (память `feedback_user_reposts_history_self`); код+проверка — на 1–2 документах максимум.
- ⚠ `form-validate`: ложные WARN по версии 2.13 и `~Список.X not found` (динсписки) — НЕ дефекты
  (память `form_validate_tilde_spisok_false_positive`). Гейт — сравнить с прогоном по рабочему эталону.
