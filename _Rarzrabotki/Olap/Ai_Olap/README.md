# Ai_Olap

ETL orchestrator that loads **BAS ERP 2.5** (`Ref="BaseERP"` 1С cluster, MSSQL backend) into the BI database **OlapBASERP** (24 tables) for Power BI dashboards.

This is **Stage 3** of the 5-stage BI pipeline:

```
Stage 1 (DONE)  8 new 1С objects in BaseERP
                  Перечисление.А_ИсточникPL/А_ИсточникDDS/А_РазделыCFS,
                  Реквизит А_РазделCFS, РегистрСведений.А_ОтчетPL_Свод/А_ОтчетDDS_Свод,
                  Документ.А_ФинРез_PL/А_ФинРез_DDS
        |
        v
Stage 2 (DONE)  24 SQL tables in OlapBASERP (3 Fact + 16 Dim + 1 Bridge + 4 Util)
        |
        v
Stage 3 (THIS)  Python ETL Ai_Olap                  <-- you are here
        |
        v
Stage 4 (TODO)  Power BI PBIX (PnL + Cashflow dashboards)
        |
        v
Stage 5 (TODO)  Windows Task Scheduler 02:00 nightly
```

## Architecture: SQL-first, COM as a fallback

The 1С platform stores everything in MSSQL with auto-generated table names
(`_Reference329` for Справочник.Организации, `_InfoRg55970` for А_ОтчетPL_Свод
and so on). This pipeline reads those tables **directly with pyodbc**, which
is multiple times faster than going through the 1С Server / V83.COMConnector.
COM is reserved for virtual tables (`.Остатки`, `.Обороты`, `.ОстаткиИОбороты`)
where the platform layers in computed columns the raw tables cannot reproduce.

The mapping `1С_object → SQL_table + {1С_field: SQL_column}` is generated by
`mapping/refresh_mapping.py` (Python wrapper around the platform method
`ПолучитьСтруктуруХраненияБазыДанных()`) and committed as
`mapping/baserp_storage.json`. Refresh after any 1С configuration change.

```
+------------------+     pyodbc      +-------------+    pyodbc    +-------------+
|  BaseERP MSSQL   | <-------------- | sql_backend | -----------> |  OlapBASERP |
|  (_Reference*,   |                 | extractor   |              |  (24 tables)|
|   _InfoRg*, ...) |                 +-------------+              +-------------+
|                  |
|                  |     V83 COM      +-------------+
|  via 1С Server   | <--------------- | com_extr.   |   (only for .Остатки/.Обороты)
+------------------+                  +-------------+
```

## Quickstart

```bash
cd _Rarzrabotki/Olap/Ai_Olap

# 1. venv (one-off)
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 2. .env (copy + fill in passwords)
cp .env.example .env

# 3. refresh the SQL mapping (one-off, plus after any 1С config change)
.venv/Scripts/python.exe mapping/refresh_mapping.py

# 4. validate pipelines and run dim load
.venv/Scripts/python.exe main.py --validate
.venv/Scripts/python.exe main.py --run-once dim_catalogs

# 5. load a Fact table for one month
.venv/Scripts/python.exe main.py --run-once fact_pnl    --period 2026-02
.venv/Scripts/python.exe main.py --run-once fact_cashflow --period 2026-02

# 6. acceptance check
.venv/Scripts/python.exe -m pytest tests/ -v
```

## CLI

```
python main.py --validate
python main.py --run-once <pipeline_id> [--period YYYY-MM]
python main.py --scheduled
python main.py --refresh-mapping
```

| flag | what it does |
|------|--------------|
| `--validate`        | parses every `pipelines/*.json` against the JSON schema |
| `--run-once ID`     | runs one pipeline by file stem; pass `--period YYYY-MM` for Fact pipelines |
| `--scheduled`       | starts an APScheduler `BlockingScheduler` daemon using each pipeline's cron |
| `--refresh-mapping` | drops the in-memory mapping cache; next run re-reads `mapping/baserp_storage.json` |

## Available pipelines

| file | what it does | schedule |
|------|--------------|----------|
| `pipelines/dim_catalogs.json`        | full reload of 16 Dim_* + 1 Bridge       | `0 1 * * *` |
| `pipelines/fact_pnl.json`            | idempotent reload of Fact_PnL per month  | `0 2 1 * *` |
| `pipelines/fact_cashflow.json`       | idempotent reload of Fact_Cashflow       | `0 2 1 * *` |
| `pipelines/fact_cf_balance.json`     | balance via `.ОстаткиИОбороты` (COM)     | `0 3 1 * *` |
| `pipelines/etl_runs_keepalive.json`  | daily heartbeat into ETL_Runs            | `0 6 * * *` |

A pipeline file lists `steps[]`; each step has an `extractor` (`sql_backend`,
`raw_sql`, or `com`), an optional `transformer.steps` chain (registry in
`ai_olap/transformers/pipeline.py`), and a `loader` (`full_reload`,
`idempotent_period`, or `append`).

## Troubleshooting

### `mapping/baserp_storage.json not found`
Run `python mapping/refresh_mapping.py`. It needs the COM connector and a
running 1С session for the `BaseERP` infobase.

### `Поле не знайдено` / `Field not in mapping`
Either the metadata changed in 1С (refresh the mapping) or the field requested
is a system column the platform method does not return (`_Folder`,
`_ParentIDRRef`, `_Period`). Use `extra_columns` in the extractor or rely on
`column_mapper.defaults` to fill the gap.

### Acceptance gate fails (Глобино-2)
First check the `Source` distribution in `Fact_PnL` — if it is no longer 7
distinct values, the source register changed. Then compare per-Source totals
to the etalon table in
`_Rarzrabotki/notebook/knowledge_Olap/olap_acceptance_etalons.md`.

### `_Date_Time` returns rows in year 4026
That is correct: BaseERP cluster backend stores dates with a **+2000 year
offset**. `auto_period_params=true` in the extractor config (default for Fact
pipelines) handles the shift automatically; if you write a custom raw_sql
filter, add 2000 yourself.

### APScheduler doesn't fire
Ensure `--scheduled` is running; `EtlScheduler` uses `BlockingScheduler` so
the process must stay alive. Check `logs/etl_YYYY-MM-DD.log` for `job
registered` and the pipeline's cron expression.
