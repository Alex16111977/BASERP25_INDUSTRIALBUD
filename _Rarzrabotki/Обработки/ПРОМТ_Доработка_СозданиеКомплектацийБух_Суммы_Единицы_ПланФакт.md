1. **`РегистрБухгалтерии.Хозрасчетный` ресурсы:** `Количество`, **`Сумма`**, `ВалютнаяСумма`, `СуммаНУ`. → у остатков есть `СуммаОстаток` (деньги) рядом с `КоличествоОстаток`. Цена = СуммаОстаток/КоличествоОстаток.
2. **Единица номенклатуры:** `Справочник.Номенклатура.БазоваяЕдиницаИзмерения` тип `КлассификаторЕдиницИзмерения` (у классификатора реквизит только `НаименованиеПолное` — **своего коэффициента НЕТ**). Остатки `КоличествоОстаток` — в этой базовой единице.
3. **Коэффициенты единиц** живут в ТЧ `Справочник.Номенклатура.ЕдиницыИзмерения` (реквизиты `ЕдиницаИзмерения` + `Коэффициент`) — это упаковки относительно базовой (базовая = коэф.1). Приведение: `Кол_базовое = Кол_в_единице × Коэффициент_этой_единицы` (искать строку ТЧ ЕдиницыИзмерения с нужной ЕдиницаИзмерения).
4. **Спецификация:** `Справочник.СтруктураСебестоимости.Комплектующие` реквизиты: `ОбщееНазвание`, `Номенклатура`, **`Единица`** (КлассификаторЕдиницИзмерения), `Количество`, **`Сумма`** (деньги-план), `Этап`.
5. **🔑 ВАЖНО:** в спец `000000005` `Комплектующие.Единица` **СОВПАДАЕТ** с `Номенклатура.БазоваяЕдиницаИзмерения` у **ВСЕХ 107/107 строк** → на практике остаток и норма УЖЕ в одной (базовой) единице, пересчёт не требуется. **Доследовать** на других спецификациях; если встретится `Единица ≠ БазоваяЕдиницаИзмерения` — применить коэффициент из п.3 (иначе сравнение норма↔остаток будет в разных единицах). Минимум — реализовать safeguard + лог-предупреждение при расхождении.

## ЧАСТЬ A — суммы в обработке

### A1. Запрос остатков (`ПолучитьОстатки`) — добавить Сумму и базовую единицу
В SELECT/GROUP запроса остатков (см. knowledge 02) добавить:
- `СУММА(Ост.СуммаОстаток) КАК СуммаОстатка`
- `ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура).БазоваяЕдиницаИзмерения КАК Единица`
(группировать по этим же выражениям, кроме агрегата Суммы). Субконто/организация/счёт — как сейчас (LESSONS §1-4). **Pre-check в Python COM.**

### A2. Нормы (`ПолучитьНормы`) — вернуть Σ Количество И Σ Сумма по ОбщееНазвание
Изменить `ПолучитьНормы`: возвращать не одно число, а структуру/2 соответствия — `НормаКол` и `НормаСум` (Σ `К.Количество` и Σ `К.Сумма` по ОбщееНазвание). Этап-фильтр — как сейчас (incl/excl).

### A3. ТЧ `ТабличнаяЧастьОстатков` (манифест) — новые колонки
+ `СуммаОстатка` (decimal 15,2), + `Единица` (`CatalogRef.КлассификаторЕдиницИзмерения`), + `НормаСумма` (decimal 15,2), + `ВНормеСумма` (decimal 15,2), + `ПонадНормуСумма` (decimal 15,2), + `ЕкономіяСума` (decimal 15,2). (Python-патч манифеста по uuid-якорю, см. knowledge 09 + LESSONS §16.)

### A4. `ЗаполнитьАнализ` — распределение сумм ПРОПОРЦИОНАЛЬНО количеству
Распределение остаётся жадным **по количеству** (НЕ менять). Суммы распределять **пропорционально доле количества** (деньги следуют за количеством):
```
ЦенаСтроки = ?(Стр.Остаток <> 0, Стр.СуммаОстатка / Стр.Остаток, 0);
ВНормеСумма   = ВНорме    * ЦенаСтроки;     // округлить до 2 знаков (Окр(..,2))
ПонадНормуСумма = Стр.СуммаОстатка - ВНормеСумма;
```
Норма-сумма (план) на строку эталона: `НоваяСтрока.НормаСумма = ?(НовыйЭталон, НормаСумЭталона, 0)` (как Норма по количеству — только на первой строке эталона). `ЕкономіяСума = max(0, НормаСумЭталона − Σ СуммаОстатка_эталона)` (зеркало, через `ЗафиксироватьЭкономиюЭталона` — добавить туда работу с суммой; остаточная норма-сумма как остаточная норма-кол).
Колонку `Единица` заполнять из строки остатка (`НоваяСтрока.Единица = Стр.Единица`).
⚠️ Альтернатива (если заказчик захочет): независимое жадное распределение по суммам `мин(СуммаОстатка, ОстатокНормыСум)`. По умолчанию — пропорционально (деньги = стоимость распределённого количества). **Уточнить у заказчика при сомнении.**

### A5. Форма + друк
- Закладка «Аналіз залишків»: + колонки `Сума залишку`, `Одиниця`, `Понад норму (грн)`, `Економія (грн)` (+ опц. План-сума). Подсумки «Підсумки»: + Σ суми. `ПрименитьОтборИИтоги` — перенести новые колонки + суммировать итоги (см. knowledge 06).
- Друк (`СформироватьПечать`): + колонки Одиниця + суммы (программный ТабличныйДокумент, стиль/грабли — knowledge 06, LESSONS §8-11).
- **Заполнение документов** (`Комплектующие`): поле `Сумма` строки — ставить `СтрД.СуммаСтроки` (= ВНормеСумма или ПонадНормуСумма соответствующей категории). Протащить сумму через `НакопитьСтроку`/`РаспределитьВДокумент` (доп. колонка «Сумма»), писать `НС.Сумма`. (КомплектацияНоменклатуры.Комплектующие имеет реквизит `Сумма` — knowledge FINDINGS.)

## ЧАСТЬ B — единица измерения (приведение к базовой)

- **Базовая единица = `Номенклатура.БазоваяЕдиницаИзмерения`**, в ней уже считаются остатки. Колонку `Единица` показывать в анализе/друке/отчёте.
- Норма `Комплектующие.Количество`: если `Комплектующие.Единица == БазоваяЕдиницаИзмерения` (на практике 107/107) — брать как есть. Если **различается** — пересчитать в базовую через `Номенклатура.ЕдиницыИзмерения`: найти строку ТЧ с `ЕдиницаИзмерения = Комплектующие.Единица`, `Кол_базовое = Кол × Коэффициент`; базовая единица имеет коэф.1. Если строки нет — лог-предупреждение, брать как есть. **Доследовать** реальные случаи расхождения на всех спецификациях (запрос: `Комплектующие.Единица <> Номенклатура.БазоваяЕдиницаИзмерения`).
- Суммы (деньги) — единиц не имеют, пересчёт не нужен.

## ЧАСТЬ C — новый отчёт «План-факт по матеріалах»

### Назначение
Сравнить **план** (норма из спецификации: Кол + Сума) и **факт** (остаток из базы: Кол + Сума), вывести проценты выполнения и превышения, с группировкой.

### Что показать (на эталон = ОбщееНазвание)
| Метрика | Формула |
|---|---|
| Одиниця | базовая единица эталона |
| Кількість план | `НормаКол` (Σ Комплектующие.Количество по эталону, в базовой ед.) |
| Кількість факт | `Σ Остаток` по эталону |
| **% викон. (кількість)** | `Факт_кол / План_кол × 100` |
| Сума план | `НормаСум` (Σ Комплектующие.Сумма по эталону) |
| Сума факт | `Σ СуммаОстатка` по эталону |
| **% викон. (сума)** | `Факт_сум / План_сум × 100` ← **общий % план-факт по деньгам** |
| Понад норму (грн) | `Σ ПонадНормуСумма` по эталону |
| **% превышения в деньгах** | `ПонадНорму_сум / План_сум × 100` (или `/ Факт_сум` — **уточнить базу %**) |

Защита от деления на 0 (План=0 → % = 0 или «—»).

### Группировка по уровням
- **Уровень 1: ОбщееНазвание (эталон)** — план/факт/% (план есть только тут — норма per-эталон).
- **Уровень 2: Номенклатура** (дети) — факт Кол/Сума, Понад норму (грн) per номенклатура; план на этом уровне отсутствует (показывать «—» или долю).
- **Общий итог** — Σ план/факт + общий % по деньгам.

### Реализация — РЕКОМЕНДАЦИЯ
**Второй программный `ТабличныйДокумент` в самой обработке** (кнопка «Друк план-факт» рядом с «Друк»), т.к. он переиспользует уже посчитанные обработкой данные (ТабличнаяЧастьОстатков с кол+сума+нормами+распределением) и группирует их по ОбщееНазвание→Номенклатура. Метод `СформироватьПечатьПланФакт(ДанныеАнализа) Экспорт` (по образцу `СформироватьПечать`, knowledge 06): шапка + группы с подытогами + проценты + общий итог; стиль (жирные группы, фон, ширины, АвтоМасштаб) — как в knowledge 06.
⚠️ **Альтернатива (если заказчик хочет отдельный объект):** внешний отчёт `.erf` со схемой СКД, который САМ повторяет запросы остатков+норм (дублирование логики) или получает данные из обработки. По умолчанию — встроенная печатная форма (без дублирования). **Уточнить тип объекта у заказчика.**
