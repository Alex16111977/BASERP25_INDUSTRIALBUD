# 01. Архитектура: документ vs обработка

## Документ — это порт обработки

`Документ.РасчетКомплектаций` = **сохраняемый вариант** внешней обработки `СозданиеКомплектацийБух`.
Движок (`Ext/ObjectModule.bsl`) — **порт `ObjectModule` обработки 1:1**: имена процедур, реквизитов и ТЧ
сохранены, включая украинские (`ЕкономіяСума`, `ДокументиКомплектації`, `ДокументиМалоценки`) — благодаря
этому СКД-макеты и код при портировании не переименовывались, а регрессия обработки не ломалась.

| | Обработка `СозданиеКомплектацийБух` | Документ `РасчетКомплектаций` |
|---|---|---|
| Хранение | ничего не хранит (расчёт в памяти) | **сохраняет** расчёт в БД (ТЧ документа) |
| Тип | внешняя обработка `.epf` | документ конфигурации, **`Posting=Deny`** |
| Главный реквизит формы | `Объект` типа `ExternalDataProcessorObject.…` | `Объект` типа `DocumentObject.РасчетКомплектаций` |
| Списание | сразу из анализа в документы | через **редактируемые ТЧ** `СписаниеПоНормам`/`СписаниеСверхНормы` |
| Семейства целей | только `КомплектацияНоменклатуры` | + `ПередачаМалоценныхАктивовВЭксплуатацию` (малоценка) |
| Статусы | нет | перечисление `СтатусыРасчетаКомплектаций` |
| Дубли | нет | `НайтиДубликатыРасчета` + предупреждение в `ПередЗаписью` |
| Печати | 5 (плоский + 4 СКД) | **7** (+ Акт + Розбіжності одиниць) |

Обработка **живёт параллельно** и не тронута (её база знаний — [`../knowledge_Создания комплектаций для бух учета/`](../knowledge_Создания%20комплектаций%20для%20бух%20учета/)).
При правке общего движка сверяйся с обеими: математику см. там, документные надстройки — здесь.

## Непроводимый документ

`Posting=Deny`, `RealTimePosting=Deny` → документ **не делает движений** по регистрам. Он не «проводится»;
он рассчитывает, хранит и заполняет ДРУГИЕ документы. Поэтому:
- нет модуля набора записей, нет `ОбработкаПроведения`;
- «нерасчётный» с точки зрения взаиморасчётов → `Курс/Кратность/А_Обработан/А_ВведенВЕРП` НЕ нужны
  (в отличие от Реализация/ПКО; см. `../knowledge/document_hidden_fields.md`);
- запись целевых документов идёт `РежимЗаписиДокумента.Запись` (без проведения) — их проводит пользователь.

## Модуль объекта ↔ форма (делегирование)

Логика — в **модуле объекта** `Ext/ObjectModule.bsl`, разбит на регионы:
- `#Область ПрограммныйИнтерфейс` — экспортные `РассчитатьАнализ`, `ЗаполнитьДокументыПоАнализу`, `СформироватьПечать*`, `ДанныеОстаткаДляСтроки`, `НайтиДубликатыРасчета`, `ТекстЗаголовкаЗвіту`;
- `#Область СлужебныеПроцедурыИФункции` — запросы (`ПолучитьОстатки`/`ПолучитьНормы`), ядро (`ЗаполнитьАнализ`), раскладка (`ПодготовитьСтрокиПоДокументам`/`СформироватьДокументыПоСоответствию`), таблицы списания, кэши;
- `#Область ОбработчикиСобытий` — `ОбработкаЗаполнения`, `ПередЗаписью`.

**Форма** (`Forms/ФормаДокумента/Ext/Form/Module.bsl`, 465 строк) — тонкий диспетчер. Мост объект↔форма:

```bsl
ОбъектОбработки = РеквизитФормыВЗначение("Объект");   // DocumentObject из данных формы
ОбъектОбработки.РассчитатьАнализ();                    // работаем на объекте
ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект");     // вернуть в форму
```

Именно поэтому вся бизнес-логика в модуле объекта COM-инспектируема (`Документы.РасчетКомплектаций.СоздатьДокумент()`),
а форма — нет (управляемую форму COM headless не рендерит; проверять в клиенте BuhBud). Подробно про UI — [10](10_forma_dokumenta.md).

## Макеты (4 СКД-схемы)

`Documents/РасчетКомплектаций/Templates/`: `МакетПланФакт`, `МакетПланФактЕтапи`, `МакетАнализСС`, `МакетАнализССОдна`
(`TemplateType=DataCompositionSchema`, дизайнерские схемы из `skd-compile`). Плоский «Друк» и Акт/Розбіжності —
**программные `ТабличныйДокумент`** (без макета). См. [08](08_pechatnye_formy.md).

## Регистрация в конфигурации

- **`Configuration.xml`** — документ в `<Documents>` (строка ~3261; вставляется автоматически `meta-compile`).
- **Подсистема** `Склад/СкладГлавное` — документ добавлен в `Content` + `CommandInterface` (OpenList) → появляется в разделе «Склад».
- **Роли:**
  - `ДобавлениеИзменениеДанныхБухгалтерии` — полный доступ (Read/Insert/Update/Delete/View/Edit) **без RLS** (важно: `Организация` в документе **опциональна**, RLS по организации сломал бы пустую орг);
  - `ЧтениеДанныхБухгалтерии` — Read/View/InputByString;
  - `ПолныеПрава` — `setForNewObjects=true`, отдельно прописывать не нужно.
- **`DefaultObjectForm`** = `Document.РасчетКомплектаций.Form.ФормаДокумента`. Форма списка — автогенерируемая (кастомную не делали, YAGNI).

## Пайплайн создания (повторяемый, только через скрипты)

Документ создан скриптовым пайплайном (`_Rarzrabotki/Python/test/doc_kompl_*.py`); **правки — только перегенерацией**, не ручным редактированием XML:

1. `doc_kompl_meta.json` → `meta-compile` (шапка + ТЧ + перечисление);
2. `doc_kompl_patch_meta.py` — пост-патч uk-синонимов, `FoldersAndItems`, `DefaultObjectForm` (последовательный обход узлов);
3. `doc_kompl_build_module.py` — генерит `ObjectModule.bsl` из исходника обработки (≈10 хирургических операций);
4. `doc_kompl_build_form.py` — transform-порт `Form.xml` (тип главного реквизита, минус Title/AutoTitle/Save-блок, +шапка/страницы/кнопки/OnOpen, id с 400) — **БОЛЬШЕ НЕ ЗАПУСКАТЬ** (затрёт «живую» форму, см. [10](10_forma_dokumenta.md));
5. `doc_kompl_copy_templates.py` — тела макетов как есть, обёртки с новым uuid4;
6. `doc_kompl_register.py` — Configuration.xml + подсистема + роли.

Загрузка в живую базу: `db-load-xml` (Partial) + `db-update -Dynamic+` — принимает **добавление** новых объектов
без монопольного режима (обновилось на живой базе с активными пользователями). ⚠ Перед загрузкой — проверять
процессы `1cv8.exe`: открытый Конфигуратор с устаревшей копией **откатывает** загрузку при «Обновить конфигурацию БД»
(случалось дважды — см. [LESSONS](LESSONS.md)).

## COM-smoke (проверка движка)

```python
import win32com.client, datetime
buh = win32com.client.Dispatch("V83.COMConnector").Connect(
    'Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"')
doc = buh.Документы.РасчетКомплектаций.СоздатьДокумент()
doc.Период = datetime.datetime(2026, 7, 7, 23, 59, 59)
doc.Спецификация = buh.Справочники.СтруктураСебестоимости.НайтиПоКоду("000000004")
doc.СкладыОстатков.Добавить().Склад = <ссылка на склад>
doc.РассчитатьАнализ()
print("рядків аналізу:", doc.ТабличнаяЧастьОстатков.Количество())
```

Движок работает на несохранённом объекте (расчёт не требует записи). Запись/заполнение реальных документов —
**только с явного разрешения пользователя** (тесты используют маркеры в `Комментарий`, документы не удаляют). См. [FINDINGS](FINDINGS.md).
