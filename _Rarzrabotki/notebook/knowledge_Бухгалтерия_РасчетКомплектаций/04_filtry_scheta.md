# 04. Фильтры и счета

Фильтры задаются реквизитами шапки и ТЧ-списками; в запросы подставляются в модуле объекта.

## Склады — `СкладыОстатков` → `СкладыСписком()`

ТЧ `СкладыОстатков` (колонка `Склад`). `СкладыСписком()` собирает заполненные в массив → параметр `&Склады`
(фильтр во внешнем `ГДЕ` по субконто3, см. [02](02_istochniki_zaprosy.md)). Пустой список → `РассчитатьАнализ`
бросает «Не вибрані склади залишків».

## Счета: два семейства

Документ разносит остатки на **два семейства** целевых документов, поэтому счета разделены на две ТЧ:

| ТЧ | Функция | Default (если пусто) | Семейство |
|---|---|---|---|
| `СчетаОстатков` | `СчетаСписком()` | группы **20, 28** | материалы → `КомплектацияНоменклатуры` |
| `СчетаМалоценки` | `СчетаМалоценкиСписком()` | счёт **22** | малоценка → `ПередачаМалоценныхАктивовВЭксплуатацию` |

- Остатки грузятся **одним запросом** по объединению `ВсеСчетаСписком()` (комплектация + малоценка), `Счет В ИЕРАРХИИ(&Счета)`.
- Default-счета преднаполняются в `ОбработкаЗаполнения` (при создании) и дублируются fallback'ом в `СчетаСписком`/`СчетаМалоценкиСписком` (на случай очистки).
- Счета задаются **группами** (20/28/22), `В ИЕРАРХИИ` раскрывает в субсчета (201/281/221…).

## Классификация строки: комплектация или малоценка

Строка анализа несёт конкретный субсчёт (напр. `221`), а список малоценки задан группой (`22`). Принадлежность
определяется **подъёмом по родителю**:

```bsl
Функция СчетМалоценки(Счет, МножинаМалоценки)   // МножинаМалоценки = МножинаСчетовМалоценки()
    ТекСчет = Счет;
    Пока ЗначениеЗаполнено(ТекСчет) Цикл
        Если МножинаМалоценки.Получить(ТекСчет) <> Неопределено Тогда Возврат Истина; КонецЕсли;
        ТекСчет = ТекСчет.Родитель;
    КонецЦикла;
    Возврат Ложь;
КонецФункции
```

`МножинаСчетовМалоценки()` = Соответствие `счёт малоценки → Истина` из `СчетаМалоценкиСписком()`. Используется в
`ПодготовитьСтрокиПоДокументам` для выбора семейства ([06](06_zapolnenie_dokumentov.md)).

## Организация — реквизит `Организация` (опционально)

`CatalogRef.Организации`, пусто = все. В запросе — **ИЛИ-паттерн** (не в условии ВТ!):
`(&Организация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) ИЛИ Ост.Организация = &Организация)`.
На одном складе остатки могут быть у разных юрлиц → орг-фильтр разделяет. Группировка остатков идёт **без** Организации.
⚠ Роль `ДобавлениеИзменениеДанныхБухгалтерии` дана **без RLS** — RLS по организации сломал бы пустую (все) орг.

## Этапы — ТЧ `Этапы` + флаг `ИсключатьЭтапы`

`ЭтапыСписком()` → `&Этапы`. Динамическое условие в `ПолучитьНормы`:
- `ИсключатьЭтапы = Ложь` → `И К.Этап В (&Этапы)` (включать только эти);
- `ИсключатьЭтапы = Истина` → `И НЕ К.Этап В (&Этапы)` (исключать эти);
- пусто → все этапы.

Источник этапа — `СтруктураСебестоимости.Комплектующие.Этап`. Инвариант: `include + exclude = все`.

## Счёт-на-строку (per-row `СчетУчетаБУ`)

Каждая строка остатка несёт свой `Счет` (колонка `Счет` в `ТабличнаяЧастьОстатков` и таблицах списания). При
заполнении документа `НС.СчетУчетаБУ = СтрД.Счет` — материал на 201 пишется счётом 201, на 221 — счётом 221.
Ни одного «сводного» счёта комплектации нет (скрытый реквизит `СчетКомплектации` из ранних фаз обработки удалён).
