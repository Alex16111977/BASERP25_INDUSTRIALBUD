# 06. Заполнение документов ★

`ЗаполнитьДокументыПоАнализу(ЗаполнятьВНорме = Истина, ЗаполнятьПонад = Истина)` — экспортный оркестратор.
**Читает сохранённые ТЧ списания** (`СписаниеПоНормам`/`СписаниеСверхНормы`), НЕ анализ напрямую → ручные правки доходят.
Опциональные булевы дают 3 режима (обе / только в норме / только понад) и обратную совместимость.

## Поток

```
ЗаполнитьДокументыПоАнализу
  └ проверка: обе таблицы пусты → Помилки «Спочатку натисніть Розрахувати»
  └ ПодготовитьСтрокиПоДокументам  → Соответствие «документ → ТЗ строк»
  └ НачатьТранзакцию / Попытка
       СформироватьДокументыПоСоответствию  → пишет строки в ТЧ документов, Записать()
       ЗафиксироватьТранзакцию
     Исключение → ОтменитьТранзакцию + ЗаписьЖурналаРегистрации + Результат.Помилки  (НЕ re-raise)
  └ если Помилки=0 И Заповнено>0 → Статус = ДокументыСозданы
```

## Роутинг — `ПодготовитьСтрокиПоДокументам(Результат, ЗаполнятьВНорме, ЗаполнятьПонад)`

Из ТЧ `ДокументиКомплектації` и `ДокументиМалоценки` строятся 4 карты `склад → документ`:
`ДокПоНормамКомпл`, `ДокДопКомпл`, `ДокПоНормамМал`, `ДокДопМал`.

**КОНТРАКТ карты заполнения (с 25.08.2026):** каждый целевой документ активного режима
предсоздаётся в карте с ПУСТОЙ ТЗ (`ПредсоздатьСтрокиДокументов` + `ТаблицаСтрокДокумента`).
Пустой состав — тоже состав: в `СформироватьДокументыПоСоответствию` такой документ
ОЧИЩАЕТСЯ, а проведённый — РАСПРОВОДИТСЯ (`ОтменаПроведения`), счётчик `Результат.Очищено`
+ `Сообщить` по каждому. Раньше карта строилась лениво (`НакопитьСтроку`) — документ без
строк в новом расчёте не перезаписывался вовсе и проводился со СТАРОЙ ТЧ (дефект нашёл
заказчик 25.08.2026; smoke: `smoke_doc_kompl_ochistka.py`, сценарий «понаднорма снята →
Додаткова очищена»).

Затем построчно:

| Источник | Категория | Семейство (по `СчетМалоценки(Стр.Счет)`) | Целевая карта |
|---|---|---|---|
| `СписаниеПоНормам` | ПоНормам | комплектация | `ДокПоНормамКомпл` → `ДокументПоНормам` |
| `СписаниеПоНормам` | ПоНормам | малоценка | `ДокПоНормамМал` → `ДокументПоНормам` |
| `СписаниеСверхНормы` | Додаткова | комплектация | `ДокДопКомпл` → `ДокументДодаткова` |
| `СписаниеСверхНормы` | Додаткова | малоценка | `ДокДопМал` → `ДокументДодаткова` |

- Строки с `Количество ≤ 0` пропускаются.
- `РаспределитьВДокумент`: документ для склада не выбран → склад в `ПропущенныеСклады` (счётчик `Результат.Пропущено`). НЕ используется `Неопределено`-ключ (LESSONS §7).
- `НакопитьСтроку` копит `{Номенклатура, Количество, Счет, Сумма}` по ключу-документу.

## Запись — `СформироватьДокументыПоСоответствию(СтрокиПоДокументам, Результат)` (внутри транзакции)

Для каждого документа: `ДокОбъект = ДокСсылка.ПолучитьОбъект()`, `ТабЧасть.Очистить()`, добавить строки, `ДокОбъект.Записать(РежимЗаписиДокумента.Запись)` (без проведения), `Результат.Заповнено++`.

**Ветвление по типу документа — через `Если/Иначе`, НЕ `?()`** (оператор `?()` вычислил бы обе ветки и упал на несуществующей у документа ТЧ):

```bsl
Если ЭтоМалоценка Тогда              // ТипЗнч(ДокСсылка) = Тип("ДокументСсылка.ПередачаМалоценныхАктивовВЭксплуатацию")
    ТабЧасть = ДокОбъект.МалоценныеАктивы;
Иначе
    ТабЧасть = ДокОбъект.Комплектующие;
КонецЕсли;
```

Общие поля строки: `Номенклатура`, `Коэффициент = 1`, `СчетУчетаБУ = СтрД.Счет`, `Количество = СтрД.Количество`.

### Ветка «комплектация» (`КомплектацияНоменклатуры.Комплектующие`)
- `НС.Сумма = СтрД.Сумма` (у малоценки реквизита `Сумма` нет!);
- `НС.ЕдиницаИзмерения = Номенклатура.БазоваяЕдиницаИзмерения`; если пусто → `Результат.БезЕдиниці++` + лог-предупреждение.

### Ветка «малоценка» (`ПередачаМалоценныхАктивовВЭксплуатацию.МалоценныеАктивы`)
- `НС.НалоговоеНазначение = НалоговыеНазначенияАктивовИЗатрат.НДС_Облагаемая` (предопред.);
- `НС.ФизЛицо = ФизЛицоДок` (МВО из ТЧ `ДокументиМалоценки`), если заполнено;
- `НС.НазначениеИспользования` = поиск в кэше по `(Номенклатура, СпособОтраженияРасходов)`;
  **промах + заполненный Способ → АВТОСОЗДАНИЕ карточки прямо при заполнении**
  (`НайтиИлиСоздатьНазначение` → страховка `НайтиПризначенняЗаСпособом` → ядро
  `СоздатьКарточкуПризначення`: МШП, строк 12, Кількість/Коефіцієнт 1, счета 00, печать 231,
  единица базовая; те же константы, что в пакетном `СоздатьОтсутствующиеНазначения` — ядро общее,
  с 25.08.2026). Счётчик `Результат.СтвореноПризначень` + `Сообщить`. Способ пуст или запись
  карточки упала → старый путь `БезНазначення++` (двухпроходный «крок 3а/3б» формы «Оновити
  документи» становится no-op при заполненном способе). Смок: `smoke_doc_kompl_malocenka.py`;
- **без `Сумма`** (в `МалоценныеАктивы` нет реквизита суммы).

`СпособОтраженияРасходов` и `ФизЛицо` заполняет **пользователь** в ТЧ `ДокументиМалоценки` (наследуются обоими
документами склада: ПоНормам + Додаткова). Без `Способ` не находится `НазначениеИспользования` → счётчик `БезНазначення`.

Кэш назначений — `ПодготовитьКэшНазначенийИспользования` (один запрос по всем номенклатурам/способам, [02](02_istochniki_zaprosy.md)).
`МетаданныеДокументовМалоценки()` — соответствие «документ малоценки → {ФизЛицо, Способ}».

## Структура-результат

`НовыйРезультатЗаполнения()` = `Структура("Заповнено, Пропущено, БезЕдиниці, БезНазначення, Помилки")` (Помилки — Массив).
Форма показывает через `ВывестиРезультатЗаполнения` (Сообщить по каждому счётчику + ошибки). Транзакционный откат
пишет ошибку в журнал регистрации и в `Результат.Помилки`, НЕ бросает исключение (паттерн «всё-или-ничего» без re-raise).

## Авто-склады — `ДополнитьСкладыДокументов()`

В конце `РассчитатьАнализ` добавляет в **обе** ТЧ (`ДокументиКомплектації` + `ДокументиМалоценки`) склады из
`СкладыОстатков`, которых там ещё нет (документы «ПоНормам»/«Додаткова» пользователь выбирает сам). **Идемпотентно**
(Соответствие по ссылке склада — повтор не дублирует).

## Автопроставление признака ПоНорме (доработка 2026-08-25)

`СформироватьДокументыПоСоответствию` перед `Записать()` ставит каждому документу реквизит
**`ПоНорме`** («За нормою», есть у обоих видов): из колонки `ДокументПоНормам` → Истина,
из `ДокументДодаткова` → Ложь. Карта — `ПризнакиПоНормеДокументов()` (обход обеих ТЧ документов).
По признаку отчёт `_Rarzrabotki/Отчеты/А_ОтчетПоСписаниюПоНормам_Бухгалтерский` делит факт
списания на «в нормі»/«понад норму». Флаг проставляется ТОЛЬКО при заполнении (документы там
и так перезаписываются); ручной выбор документа в ТЧ и запись расчёта флаг не трогают.
Smoke: `smoke_doc_kompl_ponorme.py`. Диагностика/фикс исторических пропусков:
`report_ponorme_mismatch.py` / `fix_ponorme_mismatch.py`.

## Флаги документов

Целевые `КомплектацияНоменклатуры` / `ПередачаМалоценныхАктивовВЭксплуатацию` — **нерасчётные** документы:
`Курс/Кратность/А_Обработан/А_ВведенВЕРП` НЕ нужны (в отличие от Реализация/ПКО, `../knowledge/document_hidden_fields.md`).
Пишутся `РежимЗаписиДокумента.Запись`; проводит их пользователь.
