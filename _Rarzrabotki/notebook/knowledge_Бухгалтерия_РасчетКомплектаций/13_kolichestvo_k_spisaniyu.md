# 13. Списание понаднормы частями — `СписаниеСверхНормы.КоличествоКСписанию` ★

Понаднормове списание не всегда списывают целиком в текущем периоде. Бухгалтер в строке понаднормы задаёт, **сколько реально списать сейчас**; документы «Додаткова» создаются именно на это количество и **пропорциональную сумму**. Остаток понаднормы остаётся к списанию на будущее.

> Реализовано и проверено COM 2026-07-21. Исходное ТЗ — [PROMPT_dorabotka_KolichestvoKSpisaniyu.md](PROMPT_dorabotka_KolichestvoKSpisaniyu.md).

## Реквизиты (добавлены в живой базе пользователем)

| Реквизит | Тип | Роль |
|---|---|---|
| `СписаниеСверхНормы.КоличествоКСписанию` | Число (15,3) | сколько понаднормы списать сейчас; **≤ `Количество`** |
| `КоличествоКСписаниюАвтоматическиЗаполнять` (шапка) | Булево | при расчёте ставит `КоличествоКСписанию = Количество`, иначе 0 |
| Форма: InputField `ССНКоличествоКСписанию` id=542, CheckBox `КоличествоКСписаниюАвтоматическиЗаполнять` id=545 | | |

⚠ **Флаг шапки НЕ попал в дамп `Documents/РасчетКомплектаций.xml`** — при доработках устаревший `.xml` шапки **не грузить** (перезатрёт реквизит). Грузить только модули/форму.

## Что изменено (3 точки, типовое не тронуто)

**T1 — автозаполнение.** `ObjectModule.bsl` → `ЗаполнитьТаблицыСписания()` (ветка `ПонадНорму > 0`): добавленная строка `СписаниеСверхНормы` захватывается в переменную, затем
`КоличествоКСписанию = ?(КоличествоКСписаниюАвтоматическиЗаполнять, Количество, 0)`. `СписаниеПоНормам` не трогается (общий филлер `ЗаполнитьСтрокуСписания` не меняли).

**T2 — создание документов.** `ObjectModule.bsl` → `ПодготовитьСтрокиПоДокументам()`, **цикл понаднормы**: фильтр `Если НЕ Стр.КоличествоКСписанию > 0 Тогда Продолжить`; в документ распределяется `Стр.КоличествоКСписанию` и
`СуммаКСписанию = ?(Стр.Количество > 0, Окр(Стр.Сумма * Стр.КоличествоКСписанию / Стр.Количество, 2), 0)`
(при `КоличествоКСписанию = Количество` даёт исходную `Сумму` без дрейфа). Цикл «в норме» не изменён. Дальше — существующий `РаспределитьВДокумент` → `СформироватьДокументыПоСоответствию` (там `ТабЧасть.Очистить()` + `НС.Количество = СтрД.Количество`, `НС.Сумма = СтрД.Сумма`).

**T3 — проверка ≤ Количество.**
- Форма, новый `&НаКлиенте СверхНормыКоличествоКСписаниюПриИзменении` (подключён к id=542 `OnChange`): `< 0 → 0`, `> Количество → = Количество` (clamp + сообщение).
- Форма, в `СверхНормыКоличествоПриИзменении` после пересчёта Суммы — подрезка `КоличествоКСписанию` до нового `Количество`.
- Сервер, `ПередЗаписью`: цикл по `СписаниеСверхНормы`, при `КоличествоКСписанию > Количество` — **кликабельное** сообщение на ячейку (`СписаниеСверхНормы[i].КоличествоКСписанию`, `ЭтотОбъект`, `"Объект"`) + `Отказ = Истина`. Блокирует **любую** запись (не только проведение), т.к. документ непроводимый.

## Загрузка

`db-load-xml` Partial (`Srvr="localhost";Ref="bas_industrialbud";Usr="cfo"`), список: `Documents/РасчетКомплектаций/Ext/ObjectModule.bsl` + корневой `Documents/РасчетКомплектаций/Forms/ФормаДокумента.xml` (платформа сама подтянет `Ext/Form.xml` + `Ext/Form/Module.bsl` — **root-форму, не под-файлы**) → `db-update -Dynamic+`. Оба exit 0 (значит BSL скомпилировался с новыми реквизитами).

## Проверка (COM, scratch-документы `KKS_*`, помечены на удаление)

| Тест | Результат |
|---|---|
| T3 отказ | `КоличествоКСписанию > Количество` → `Записать()` отклонён; `= Количество` → проходит |
| T1 автозаполнение | flag=True → у всех понад-строк `КоличествоКСписанию = Количество`; flag=False → `= 0` (19 строк, эталон «мшп») |
| T2 документы | источник `Количество=10, КоличествоКСписанию=4` → в «Додаткова» кол=4, сумма=0.8 (пропорц. ×0.4); `=3` → кол=3, сум=0.6 |
| T2 «0 не списывается» | `КоличествоКСписанию=0` → строка в целевой документ не попадает |

**Грабли теста:** документ, для которого ничего не распределилось (все `КоличествоКСписанию=0`), в наборе `СтрокиПоДокументам` отсутствует → его ТЧ **не очищается** (`Очистить()` только для документов набора) — при проверке «0 не пишется» целевой документ чистить **до** заполнения, иначе видно остаток предыдущего прогона (штатное поведение, не дефект). COM `Новый Дата(г,м,д,...)` через `NewObject` не создаётся («Недопустимое число параметров») — дату брать запросом `ВЫБРАТЬ ДАТАВРЕМЯ(...)`. `Комментарий` (неогранич.) в запросе — только `ВЫРАЗИТЬ(Комментарий КАК Строка(N)) = &М`.
