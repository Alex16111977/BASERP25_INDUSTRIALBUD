# KNOWLEDGE MAP — knowledge_Бухгалтерия_РасчетКомплектаций

Entry-point для ИИ-сессий. **Прочитать первым** перед любой доработкой документа.

> `Документ.РасчетКомплектаций` (синоним «Списание по СС» / «Списання по СС»).
> База: **BuhBud** — `Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`. Дамп: `_Rarzrabotki/BASEBuh`. НЕ BaseERP.
> Источник истины — **живой код** `_Rarzrabotki/BASEBuh/Documents/РасчетКомплектаций/`, а не эта база знаний.

## TL;DR за 60 секунд

Документ — **сохраняемое рабочее место** «розрахунок комплектацій за структурою собівартості». Движок = порт
обработки `СозданиеКомплектацийБух` 1:1; документ добавляет сохранение, статусы, редактируемое понаднормовое
списание, семейство малоценки, дубли и Акт. **Непроводимый** (`Posting=Deny`).

1. **Источник остатков** — `РегистрБухгалтерии.Хозрасчетный.Остатки` по счетам класса 2: `СчетаОстатков`
   (материалы, default группы **20/28**) + `СчетаМалоценки` (default **22**). Субконто1=**Номенклатура**,
   Субконто3=**Склад**. Товарного накопит.регистра в BuhBud НЕТ. Сумма остатка ×1.2 (норма с НДС, счёт без).
2. **Норма** — `Справочник.СтруктураСебестоимости` (реквизит `Спецификация`), ТЧ `Комплектующие`. **Кап** розподілу —
   **Σ `Количество` по `ОбщееНазвание` (эталон)**. Мост карточка→эталон: `Номенклатура.ОбщееНазваниеНоменклатуры`.
   План по номенклатуре списывается первым. Фильтр по `Этап`.
3. **Расчёт** (`РассчитатьАнализ`): остаток → норма эталона → жадное распределение `min(Остаток, ОстатокНормы)`→`ВНорме`,
   излишек→`ПонадНорму`; `Економія = max(0, Норма − Σ Остаток)` на эталон. Результат → ТЧ `ТабличнаяЧастьОстатков`,
   затем **раскладывается в 2 сохраняемые таблицы списания** (`ЗаполнитьТаблицыСписания`). Статус → `РасчетВыполнен`.
4. **Правка** (только `СписаниеСверхНормы`): бухгалтер меняет количество/цену, добавляет строки (счёт/цена
   автоподбираются из остатков — `ДанныеОстаткаДляСтроки`), пишет `Причина`.
5. **Заполнение документов** (`ЗаполнитьДокументыПоАнализу`): читает **сохранённые** `СписаниеПоНормам`/`СписаниеСверхНормы`
   (ручные правки доходят!), роутит: `ПоНормам`→`ДокументПоНормам`, `СверхНормы`→`ДокументДодаткова`; семейство
   по счёту строки (малоценка/комплектация). Пакет пишется **в одной транзакции**. Статус → `ДокументыСозданы`.

6. **Печать М-29** (`СформироватьПечатьМ29`, [14](14_m29_pechat.md)) — единственная печать, которая читает
   **факт бухучёта**: проводки `Хозрасчетный` всех **проведённых** документов расчёта, два блока
   Матеріали/МШП. Не зависит от «Розрахувати» и от ТЧ расчёта вообще.

7. **Цикл будинку** ([15](15_cikl_budinku.md), вересень 2026) — надбудова над розрахунком: карта хронології
   руху комплекту у двох ТЧ (`ДокументыОтрузкиИДосписания` + `ХронологияПеремещений`), регламентна сітка дат
   D (відвантаження) / M (монтаж), автостворення переміщення комплекту, реалізації і вимоги **копією документа
   попереднього будинку**, «Світлофор будинків» у журналі і 4 команди «Звіти» (варіанти одного звіту
   `А_ОтчетПоСписаниюПоНормам_Бухгалтерский`).

**Архитектура:** движок в `Ext/ObjectModule.bsl` (экспорт `РассчитатьАнализ`/`ЗаполнитьДокументыПоАнализу`/`СформироватьПечать*`/`ДанныеОстаткаДляСтроки`/`НайтиДубликатыРасчета`),
модуль формы делегирует через `РеквизитФормыВЗначение("Объект")` / `ЗначениеВРеквизитФормы`. **Суммы:**
анализ — **с НДС** (×1.2), таблицы списания и документы — **без НДС** (÷1.2), как на счетах;
**М-29 — прямо из проводок** (в учётной оценке, никаких ×1.2/÷1.2).

не скриптами. `Перевірив` и `Інженер` содержат украинскую «і» (U+0456) — обращаться точным написанием (§Д3).
