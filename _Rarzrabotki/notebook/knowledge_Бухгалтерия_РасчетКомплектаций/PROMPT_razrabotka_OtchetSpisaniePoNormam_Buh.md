## 1. Смысл задачи (роль финансиста)

Механизм «Списання по СС» (`Документ.РасчетКомплектаций`) списывает материалы на объект двумя парами документов
на каждый склад: «По нормам» и «Понад норму» (`КомплектацияНоменклатуры` и `ПередачаМалоценныхАктивовВЭксплуатацию`).
У обоих видов документов есть реквизит-признак **`ПоНорме`** (Булево, синоним «За нормою»).

Нужен отчёт, который по каждому **объекту-домику** (= `Склад.Подразделение` складов списания, напр.
«МД IRC 2026 15 м №1») внутри проекта (подразделение верхнего уровня, напр. «МД IRC 2026») показывает:

- **что стояло в нормах** — норму СС (`Справочник.СтруктураСебестоимости.Комплектующие`, кількість і сума);
- **что списано в нормі** — факт бухгалтерских списаний документами с `ПоНорме = Истина`;
- **что списано понад норму** — факт документами с `ПоНорме = Ложь`;
- итоги, відхилення, % виконання, економію.

Суммы в СС заведены **З ПДВ**, бухгалтерские проводки списания (Кт 20/22/28) — **БЕЗ ПДВ**, поэтому к факту
применяется коэффициент ПДВ по ставке НОМЕНКЛАТУРЫ (20% → ×1.2, 14% → ×1.14, 7% → ×1.07, без/не ПДВ → ×1) —
ровно как в отчёте-доноре (там это параметр «Факт і залишки з ПДВ (як план)»).

Вторая часть задачи: сам документ «Списання по СС» флаг `ПоНорме` при создании документов **не проставляет**
(проверено grep по живому модулю) — флаг ставили руками, и уже есть пропуск (см. §2, документ ІБ00-000135).
Доработать заполнение документов, чтобы флаг ставился автоматически.

**Решения заказчика (сняты вопросами 2026-08-25, не пересматривать):**
1. Документ дорабатываем: автопроставление `ПоНорме` при создании/заполнении документов из расчёта.
2. Отчёт учитывает ТОЛЬКО `КомплектацияНоменклатуры` + `ПередачаМалоценныхАктивовВЭксплуатацию`
   (у `ТребованиеНакладная`/`СписаниеТоваров` реквизита `ПоНорме` нет — их в отчёт НЕ включать).
3. К шаблону добавляется колонка «Списано понад норму, грн» (в Excel-шаблоне была только «кіл»).
4. Хвостовой блок «План, грн»/«Факт, грн» — дубли значений «Норма СС, грн»/«Всього списано, грн»
   (сводный жирный блок для читабельности; из него же «Відхилення, грн» и «% викон. (грн)»).

## 6. Грабли домена (из памяти и живой диагностики 2026-08-25)

- **Кириллица vs латиница**: «МД IR**С**…» (карточки СС, склады Виробничий) — С кириллическая; «МД IR**C**…»
  (подразделения, склады Відвантажено) — латиница. Хвостовые пробелы: узел «МД IRC 2026 30 м », домики 15 м №2..№6.
  НИКОГДА не сравнивать/искать по именам — только ссылки.
- **`ЕСТЬNULL(ВЫРАЗИТЬ(...), ВЫРАЗИТЬ(...))`**: несовпадающий ВЫРАЗИТЬ даёт NULL — потому склад ищется в двух
  субконто; разыменование `.Подразделение` — внутри каждого ВЫРАЗИТЬ, не поверх ЕСТЬNULL.
- **Норма в бухбазе — на ОДИН дом** (в ЕРП уже ×КоличествоДомов). Множителей не вводить.
- **`Справочник.Подразделения`** — иерархия элементов, `ЭтоГруппа` НЕТ; у `СтруктураСебестоимости` — ЕСТЬ.
- **`ПолучитьЗначениеПараметра`** оставить самописным (БСП-метода в базе нет — боевой инцидент донора).
- **Факт НЕ соединять с ВТ_СС/Викон** («ПО ИСТИНА» умножит факт на число карточек — комментарий в модуле донора).
- **«В ИЕРАРХИИ (столбец ВТ)» запрещено платформой** — только параметр/подзапрос.
- **СКД**: `title` дублировать `lang=uk`; `xs:boolean` = `true/false`; `DateFractions=DateTime` у Периода;
  поле-измерение нельзя выбирать в чужой группировке (лечение — реквизиты поля, `Документ.Дата` и т.п.).
- **ТЗ ↔ СКД**: порядок и типы колонок внешнего набора «Детали» обязаны совпадать — рассинхрон молчалив.
- **COM**: даты сдвигаются на −3 часа (сезонно) — подбирать; перечисления сравнивать через `str()`-представление
  ссылки (память `python_com_enum_str_gotcha`); `Дата()`/`Тип()` глобального контекста COM не отдаёт.
- **Запретные имена локальных переменных BSL**: `Ссылка`, `Выполнить`, `Наименование` (в модуле объекта
  затеняет реквизит).
- **Тесты ничего не удаляют** (`feedback_no_doc_delete_in_tests`); боевой 00000000003 НЕ перезаполнять —
  для Т1-приёмки только scratch-расчёт.
- **Сборка**: посторонние файлы (`.bak`) в папке исходников ломают erf-build; ClassId не регенерировать;
  конфигуратор занят → сборка через BaseERP из temp-каталога.
