## 1. Смысл задачи (роль бухгалтера)

Документ `РасчетКомплектаций` — рабочее место расчёта списаний за структурой собівартості. В нём две таблицы списания: **`СписаниеПоНормам`** (в норме) и **`СписаниеСверхНормы`** (понаднорма). При проведении по ним создаются документы: понаднорма → «Додаткова» (`КомплектацияНоменклатуры` / `ПередачаМалоценныхАктивовВЭксплуатацию`).

Понаднормове списание не всегда списывают целиком в текущем периоде. Бухгалтеру нужно в строке понаднормы указать, **сколько реально списать сейчас** (`КоличествоКСписанию` ≤ `Количество`), и создавать документы «Додаткова» именно на это количество и **пропорциональную сумму**. Остаток понаднормы остаётся к списанию на будущее.

## 3. Задачи

### T1 — Автозаполнение при расчёте
Файл `_Rarzrabotki/BASEBuh/Documents/РасчетКомплектаций/Ext/ObjectModule.bsl`, процедура `ЗаполнитьТаблицыСписания()` (стр. 1174):

- Если `Ложь` → `КоличествоКСписанию = 0` (бухгалтер введёт вручную).
- **`СписаниеПоНормам` не трогать** — `КоличествоКСписанию` только у понаднормы.
- ⚠ `ЗаполнитьСтрокуСписания(НС, СтрАнализа, Количество, Сумма)` (стр. 1191) — **общий** филлер для обеих таблиц. Флаг применять только к понаднорме. **Рекомендуемый минимальный путь:** проставлять `КоличествоКСписанию` прямо в `ЗаполнитьТаблицыСписания` в ветке `Если Стр.ПонадНорму > 0` сразу после `ЗаполнитьСтрокуСписания(СписаниеСверхНормы.Добавить(), …)`, взяв ссылку на добавленную строку. (Не добавлять флаговый параметр в общий филлер, чтобы не задеть ПоНормам.)

Текущий код:
```bsl
Процедура ЗаполнитьТаблицыСписания()
```

### T2 — Использовать `КоличествоКСписанию` при создании документов понаднормы
Та же `ObjectModule.bsl`, функция `ПодготовитьСтрокиПоДокументам` (стр. 754), **цикл понаднормы (795-808)**. Цикл «в норме» (780-793) **НЕ менять**.

Текущий цикл понаднормы:
```bsl
	Если ЗаполнятьПонад Тогда
		Для Каждого Стр Из СписаниеСверхНормы Цикл
			Если НЕ Стр.Количество > 0 Тогда
				Продолжить;
			КонецЕсли;
			Если СчетМалоценки(Стр.Счет, МножинаМал) Тогда
				ДокКарта = ДокДопМал;
			Иначе
				ДокКарта = ДокДопКомпл;
			КонецЕсли;
			РаспределитьВДокумент(СтрокиПоДокументам, ПропущенныеСклады,
				ДокКарта.Получить(Стр.Склад), Стр.Склад, Стр.Номенклатура, Стр.Количество, Стр.Счет, Стр.Сумма);
		КонецЦикла;
	КонецЕсли;
```
Целевой:
- фильтр по `Стр.КоличествоКСписанию > 0` (вместо `Стр.Количество > 0`);
- в `РаспределитьВДокумент` передавать `Стр.КоличествоКСписанию` и **пропорциональную сумму без дрейфа** (при `КоличествоКСписанию = Количество` сумма = `Стр.Сумма` точно):
```bsl

			РаспределитьВДокумент(СтрокиПоДокументам, ПропущенныеСклады,
				ДокКарта.Получить(Стр.Склад), Стр.Склад, Стр.Номенклатура, Стр.КоличествоКСписанию, Стр.Счет, СуммаКСписанию);
```
(Сигнатуры `РаспределитьВДокумент`/`НакопитьСтроку` не менять — они уже принимают Количество/Сумма.)

### T3 — Проверка `КоличествоКСписанию` ≤ `Количество` (нельзя списать больше понаднормы)

**Форма** `_Rarzrabotki/BASEBuh/Documents/РасчетКомплектаций/Forms/ФормаДокумента/Ext/Form/Module.bsl`:

- Подключить это событие к InputField `ССНКоличествоКСписанию` (id=542) в `Form.xml`: блок `<Events><Event name="OnChange">СверхНормыКоличествоКСписаниюПриИзменении</Event></Events>` (по образцу других колонок ТЧ в этом же Form.xml — соблюсти формат, порядок дочерних элементов и уникальность имён).
- В существующей `СверхНормыКоличествоПриИзменении(Элемент)` (стр. 362) — после пересчёта `Сумма` добавить: если `Стр.КоличествоКСписанию > Стр.Количество` → подрезать до `Стр.Количество` (иначе после уменьшения `Количество` понаднорма к списанию останется завышенной). Текущий обработчик:
```bsl
Процедура СверхНормыКоличествоПриИзменении(Элемент)

		ПроверитьОстатокСтрокиНаСервере(Стр.Номенклатура, Стр.Склад, Стр.Количество);

```

**Сервер** `ObjectModule.bsl`, `ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)` (стр. 1593) — добавить перед/после проверки дублей цикл по `СписаниеСверхНормы`: если `Стр.КоличествоКСписанию > Стр.Количество` → кликабельное сообщение на строку + `Отказ = Истина`.
