## 1. Смысл задачи (роль бухгалтера)

В документе «Списання по СС» (`РасчетКомплектаций`) таблица **`СписаниеСверхНормы`** показывает, что списывается
**сверх нормы** структуры собівартості. Бухгалтеру при анализе понаднормы нужно видеть ПРЯМО В СТРОКЕ, **сколько
этой позиции было заложено в СС** — количество и сумму нормы — чтобы визуально оценить разницу «норма ↔ сверх нормы»
и обосновать причину.

Для этого заказчик уже добавил в ТЧ `СписаниеСверхНормы` два **справочных** реквизита (только показать, ни на что
не влияют):

| Реквизит | Тип | Синоним | Значение |
|---|---|---|---|
| `КоличествоСС` | Число 15,3 | «Кількість в СС» | норма количества из СС |
| `СуммаСС` | Число 15,2 | «Сумма СС (без ПДВ)» | норма суммы из СС, **приведённая к БЕЗ НДС** |

**🔴 НДС — сердце задачи.** СС (`Справочник.СтруктураСебестоимости.Комплектующие.Сумма`) забита в базу **С НДС 20%**.
Колонки таблиц списания (`Сумма`, `Цена`) — **БЕЗ НДС** (как счета учёта). Поэтому `СуммаСС` обязана делиться на
`КоэффициентНДС()` (= 1.2), иначе бухгалтер будет сравнивать несравнимое. Это НЕ догадка — так устроен весь движок
(модуль `Ext/ObjectModule.bsl`):

- `КоэффициентНДС()` (стр. ~958): `Возврат 1.2` с комментарием «Норми у Структурі Собівартості введені з ПДВ 20%,
  рахунки обліку — без ПДВ»;
- `ПолучитьОстатки()`: остатки бухучёта **умножаются ×1.2** → вся анализная ТЧ `ТабличнаяЧастьОстатков`
  (`СуммаОстатка`, `ВНормеСумма`, `ПонадНормуСумма`, `НормаСумма`, `НормаСуммаНоменкл`) живёт **С НДС**;
- `ЗаполнитьТаблицыСписания()` (стр. ~1795): в обе ТЧ списания суммы кладутся **÷ КоэффНДС** (без НДС).

Значит: `КоличествоСС` = норма количества как есть (НДС количества не касается), `СуммаСС` = **норма суммы (с НДС)
÷ 1.2, Окр(,2)** — делить ровно ОДИН раз.

## 2. Правило значения (решение, зафиксировано)

**В колонки идёт норма ЭТАЛОНА (общего названия) строки** — `Норма` / `НормаСумма` эталона:

- понаднорма в движке считается ИМЕННО против эталонной нормы (`ЗаполнитьАнализ`, стр. ~1114: `ОстатокНормы =
  НормаЭталона`, размазывается по строкам эталона; превышение = `ПонадНорму`). Показывать рядом надо ту норму,
  против которой возникло превышение;
- 176 из 186 строк СС IRS вообще без номенклатуры — норма живёт на общем названии; номенклатурная норма
  (`НормаНоменкл`) — редкость, для колонки не годится;
- эталона нет в СС (fact-only позиция) → `КоличествоСС = 0`, `СуммаСС = 0` — честный ответ «в СС этого не было»;
- у всех строк одного эталона значения ОДИНАКОВЫ (это норма эталона, не строки) → **Σ по колонке бессмысленна —
  итогов в подвале НЕ делать** (Total* НЕ добавлять ни в форму, ни в код);
- норма может быть «кривой» в самой СС (18 строк IRS 15 м с `Количество=0` при ненулевой сумме) — показываем как
  есть, не выдумываем.

**⚠️ Грабля-первопричина:** в анализной ТЧ эталонная норма **штампуется только на ПЕРВОЙ строке эталона**
(`НоваяСтрока.Норма = ?(НовыйЭталон, НормаЭталона, 0)` — чтобы СКД-Σ не задваивал). Брать `Стр.Норма` из текущей
строки анализа НЕЛЬЗЯ — у большинства строк там 0. Сначала собрать карту «ОбщееНазвание → {Норма, НормаСумма}»
из штампованных строк.

## 7. Грабли этого домена

- **Штамп нормы на первой строке эталона** (п. 2) — главный источник ошибки «у половины строк норма 0».
- **НДС делить один раз**: `НормаСумма` анализа УЖЕ с НДС (нативно из СС); `ПонадНормуСумма` тоже с НДС.
  Не делить дважды и не умножать обратно.
- **Единицы**: норма в СС может быть в `ЕдиницаСС`, отличной от базовой единицы остатка — движок норму
  «без перерахунку» (осознанно, см. лог «одиниця норми не збігається»), расхождение подсвечивается розовым
  (`РасхождениеЕдиниц`). `КоличествоСС` показываем КАК В СС, не пересчитывать.
- **Имена локальных переменных ≠ имена реквизитов ТЧ/объекта** (`Наименование`-грабля) и запретные `Ссылка`,
  `Выполнить` — молчаливые сбои.
- **UUID обёртки формы стабильный** при partial-load; Designer «нормализует» форму — точечные патчи текущего
  Form.xml, генераторы формы НЕ перезапускать.
- **meta-edit пересериализует весь XML** документа (LF, `<Comment />`) — для правок формы/модуля им не пользоваться,
  только точечные Edit.
- Тестовые данные не удалять — помечать маркером в Комментарии, пользователь сам чистит
  (`feedback_no_doc_delete_in_tests`).
- Печать «Акт на списання понаднормових матеріалів» и «Аналіз для цеху» колонки СС НЕ показывают — если заказчик
  захочет, это отдельная задача (макеты в `08_pechatnye_formy.md`).
