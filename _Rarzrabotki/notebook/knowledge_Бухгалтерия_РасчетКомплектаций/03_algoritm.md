# 03. Алгоритм распределения ★

Ядро — процедура `ЗаполнитьАнализ(ТЗОстатки, Нормы)` в модуле объекта. Портирована из обработки без изменений
математики. Оркестратор — `РассчитатьАнализ()`:

```
СкладыСписком → ПолучитьОстатки → ПолучитьНормы
→ ДополнитьНоменклатуройБезОстатков   (норм-картки плана без остатка)
→ ЗаполнитьАнализ                      (жадное распределение → ТабличнаяЧастьОстатков)
→ ДополнитьСкладыДокументов            (авто-склады в ДокументиКомплектації/ДокументиМалоценки)
→ ПопередитиПроРозбіжністьОдиниць      (лог, если единицы норм ≠ базовым)
→ ЗаполнитьТаблицыСписания             (ТабличнаяЧастьОстатков → СписаниеПоНормам/СписаниеСверхНормы)
→ Статус = РасчетВыполнен
```

## Модель: кап по эталону

Норма-**кап** для распределения считается **на общий остаток всех выбранных складов по эталону**
(`ОбщееНазвание`), НЕ по конкретной номенклатуре. Номенклатуры-карточки закупаются/списываются в пределах
нормы своего эталона `Справочник.ОбщиеНазванияНоменклатуры`. Мост карточка→эталон: `Номенклатура.ОбщееНазваниеНоменклатуры`.

## Порядок обработки строк

Перед распределением `ТЗОстатки` сортируется:

```bsl
ТЗОстатки.Колонки.Добавить("ПорядокПлан");     // 0 = номенклатура есть в плане (Нормы.Номенкл), 1 = нет
ТЗОстатки.Сортировать("ОбщееНазвание Возр, ПорядокПлан Возр, Остаток Убыв");
```

→ внутри эталона: сначала **плановые** номенклатуры (потребляют кап первыми), потом остальные по **убыванию остатка**.
Само греди-ядро при этом не меняется.

## Жадное распределение (построчно)

Для каждой строки (Номенклатура × Склад × Счёт) в порядке выше:

```bsl
ВНорме      = мин(Остаток, ОстатокНормы)   // но не < 0
ПонадНорму  = Остаток - ВНорме
ОстатокНормы = ОстатокНормы - ВНорме        // «съедаем» кап

ЦенаСтроки     = СуммаОстатка / Остаток      // сумма уже с НДС ×1.2
ВНормеСумма    = Окр(ВНорме * ЦенаСтроки, 2)
ПонадНормуСумма = СуммаОстатка - ВНормеСумма  // баланс по строке вычитанием
```

- При смене эталона кап переинициализируется: `ОстатокНормы = НормаЭталона` (= `Нормы.Эталон[ОбщееНазвание].Кол`).
- Эталон без нормы (`ДанныеНормы = Неопределено`) → `НормаЭталона = 0` → всё уходит в `ПонадНорму`.
- `Норма`/`НормаСумма` эталона штампуются **только на первой строке** эталона (`?(НовыйЭталон, …, 0)`) — чтобы Σ по СКД не задваивался.

## Економія (зеркало ПонадНорму)

При смене эталона и в конце цикла — `ЗафиксироватьЭкономиюЭталона(ПерваяСтрокаЭталона, ОстатокНормы, НормаСумЭталона, СуммаОстаткаЭталона)`:

```bsl
СтрокаЭталона.Экономия    = ?(ОстатокНормы > 0, ОстатокНормы, 0);          // неиспользованная норма (кол)
// с 2026-08-06 сумма — КОЛИЧЕСТВЕННАЯ оценка по плановым ценам СС (решение бухгалтера):
СтрокаЭталона.ЕкономіяСума = ?(ОстатокНормы > 0 И НормаЭталона > 0,
    Окр(ОстатокНормы * НормаСумЭталона / НормаЭталона, 2), 0);
```

⚠ Старая формула `НормаСум − СуммаОстаткаЭталона` подмешивала ЦЕНОВУЮ разницу план/факт:
«Гайка» показывала 11 906 грн «економії» при перевитрате 5 шт (дешёвый факт), «Саморіз» —
0 грн при экономии 1 384 шт (дорогой факт); по дому №1 итог был 109 073 грн вместо честных
~34 691 грн. Новый инвариант: `ЕкономіяСума > 0 ⟺ Економія > 0`. Переменная
`СуммаОстаткаЭталона` удалена из движка. Smoke: `smoke_doc_kompl_ekonomia_summa.py`.

Пишется на **представительную (первую) строку** эталона. На каждом эталоне либо `Економія > 0`, либо `ΣПонад > 0`
(зеркало): норма не «съедена» полностью ⟺ есть неиспользованный остаток нормы.

## План по номенклатуре (`НормаНоменкл`)

`НормаНоменкл`/`НормаСуммаНоменкл` штампуются **1 раз на номенклатуру** (`БаченіНоменклатури` — Соответствие),
Σ на эталоне не задваивается по складам. Это **отображаемая** норма (по картке) в форме и печатях; поля
`Норма`/`НормаСумма` (эталон) остаются в ТЧ, но НЕ отображаются. Субститут (есть в остатках, нет в нормах) = `НормаНоменкл` 0.

## Норм-картки без остатка — `ДополнитьНоменклатуройБезОстатков(ТЗОстатки, Нормы)`

Перед `ЗаполнитьАнализ` в `ТЗОстатки` добавляются строки плановых номенклатур, которых НЕТ в остатках
(`Остаток=0`, `Склад/Счет=Неопределено`, Эталон/Единица из `Нормы.НоменклаДані`) — чтобы в отчётах были видны ВСЕ
запланированные карточки. **Безопасно:** `Остаток=0` → `ВНорме=0`/`ПонадНорму=0` → в раскладку по документам НЕ
маршрутизируются (условия `Если …Количество > 0`); сортировка `Остаток Убыв` ставит их после остатковых.

## Инварианты (стабильны при дрейфе живых данных)

| Инвариант | Формула |
|---|---|
| Баланс по строке | `ВНорме + ПонадНорму = Остаток` |
| Баланс сумм по строке | `ВНормеСумма + ПонадНормуСумма = СуммаОстатка` |
| Економія ⟺ не понад | на эталоне: `Економія > 0` ⟺ `ΣПонад_эталона = 0` |
| Нет строк без счёта | каждая строка остатка несёт `Счет` (счёт-на-строку) |
| НормаНоменкл раз/номенкл | штамп 1× (иначе СКД-Σ задвоился бы) |

Числа `ВНорме`/`ПонадНорму` **дрейфуют** с живыми данными (нормы спецификации / остатки меняются) — smoke-тесты
проверяют **инварианты**, не «магические» абсолютные значения (см. [FINDINGS](FINDINGS.md), LESSONS §28).

## Связь с таблицами списания

После `ЗаполнитьАнализ` результат из `ТабличнаяЧастьОстатков` раскладывается в сохраняемые
`СписаниеПоНормам` (по `ВНорме > 0`) и `СписаниеСверхНормы` (по `ПонадНорму > 0`) с приведением сумм **÷1.2**
(без НДС, как пойдут в документы). Это — [05](05_tablicy_spisaniya.md).
