# LESSONS — антипаттерны и грабли

Три категории: **документ-специфичные** (§Д1-Д17), **грабли М-29 / проводок** (§Д18-Д27) и
**наследованные от обработки** (движок 1:1 — полный список в базе знаний обработки).
Нарушение каждого = реальная ошибка в Designer/Enterprise или сломанная загрузка.

> Самый дорогой из списка — **§Д18**: загрузчик BSL не компилирует код, «EXITCODE=0» ничего не гарантирует.

## Документ-специфичные грабли

**§Д1. UUID обёртки формы при частичной перезагрузке — СТАБИЛЬНЫЙ.** Перегенерация обёртки формы с новым `uuid4`
→ «нельзя добавлять объекты метаданных без загрузки родительского объекта». **Фикс:** переиспользовать uuid из
существующего файла; при смене uuid грузить ВМЕСТЕ с родительским `Documents/РасчетКомплектаций.xml`.

**§Д2. `Комментарий` — `Строка(0)` (неограниченная).** В запросах только `ВЫРАЗИТЬ(Д.Комментарий КАК Строка(200)) = &М`
(иначе «поле неограниченной длины»; память `query_unlimited_string_fields`).

**§Д3. `meta-validate` ложно ругается на укр. «і» в идентификаторе** (`ЕкономіяСума` = invalid identifier). **Ложное
срабатывание** — платформа принимает (загрузчик `1cv8` съел). Украинские имена (`ЕкономіяСума`/`ДокументиКомплектації`/
`ДокументиМалоценки`) сохранены намеренно (порт 1:1 с обработкой — макеты/код не переименовывались).

**§Д4. Ветвление ТЧ документа — `Если/Иначе`, НЕ `?()`.** Оператор `?()` вычисляет **обе** ветки → упадёт на
`ДокОбъект.МалоценныеАктивы` для `КомплектацияНоменклатуры` (нет такой ТЧ) и наоборот. Выбор ТЧ (`МалоценныеАктивы`
vs `Комплектующие`) — через `Если ЭтоМалоценка … Иначе … КонецЕсли` ([06](06_zapolnenie_dokumentov.md)).

**§Д5. Статус `ДокументыСозданы` — ПОСЛЕ `КонецПопытки`.** Транзакция заполнения = «Зафиксировать последней строкой
Попытки»; смена статуса идёт следующим шагом, по результату (`Результат.Помилки=0 И Заповнено>0`). Не переносить внутрь транзакции.

**§Д6. Дубли — предупреждение, НЕ `Отказ`.** `ПередЗаписью` только сообщает о похожем расчёте (`Сообщить`), документ
сохраняется. Ранний выход при `ОбменДанными.Загрузка` (не мешать обмену) ([07](07_statusy_dubli.md)).

**§Д7. Форма «живёт своей жизнью» — build-генераторы формы НЕ перезапускать.** Designer нормализовал Form.xml
(DataPath `Объект.Number`/`Объект.Date`, дефолты AutoTime/UsePostingMode, переиндентация). `doc_kompl_build_form.py`
затрёт «живую» форму → только **точечные патчи** (`doc_kompl_patch_*.py`). ⚠ Партиальный дамп объекта **форму НЕ
включает** — сверять форму только Full/выгрузкой пользователя.

**§Д8. Конфигуратор пользователя со старой копией в памяти ОТКАТЫВАЕТ загрузки** при «Обновить конфигурацию БД»
(случилось дважды). Перед `db-load-xml`/`db-update` — проверять `Get-CimInstance Win32_Process -Filter "Name='1cv8.exe'"`.

**§Д9. `meta-edit` ПЕРЕсериализует ВЕСЬ xml документа** (LF, `<Comment />` с пробелом) → последующие Python-патчи
учитывать новую сериализацию. Порядок-зависимые smoke (печать требовала причину от заполнения) → делать
самодостаточными (причина ставится в памяти теста).

**§Д10. `db-update -Dynamic+` принимает ДОБАВЛЕНИЕ новых объектов** без монопольного режима (обновилось на живой
базе с активными пользователями). Изменение существующих может требовать монополии.

**§Д11. Bash `python -c` с кириллическими путями ломается** (кодировка) → скрипт-файл + `python-runner` полным путём
к `.py` (иначе другой интерпретатор без win32com; наследованный §27).

**§Д12. Область печати:** enum `ГоризонтальноеПоложение.Центр` (НЕ `ГоризонтальноеПоложениеТекста`); `ШиринаКолонки`
ставить на **необъединённой** строке (в Акте — на строке 2, до объединений).

**§Д13. `РасхождениеЕдиниц` — сравнение по `СокрЛП(Наименование)`, НЕ по ссылке.** В классификаторе дубли одной
единицы (`" шт"`/`"шт"`), заказчик документы не правит. Регистр сознательно НЕ игнорируется (`"пач"`≠`"пак"`). И во
флаге, и в запросе `КількістьРозбіжностейОдиниць` ([09](09_edinicy_rashozhdenie.md)).

**§Д14. Роль `ДобавлениеИзменениеДанныхБухгалтерии` — БЕЗ RLS.** `Организация` в документе опциональна (пусто=все) →
RLS по организации сломал бы пустую орг.

**§Д15. Целевые документы — нерасчётные.** `КомплектацияНоменклатуры`/`ПередачаМалоценныхАктивовВЭксплуатацию` не
требуют `Курс/Кратность/А_Обработан/А_ВведенВЕРП` (в отличие от Реализация/ПКО).

**§Д16. `ДанныеОстаткаДляСтроки` — цена БЕЗ НДС.** ×1.2 тут НЕ применять (в отличие от `ПолучитьОстатки`): таблицы
списания хранятся без НДС, а эта функция подбирает цену для строки списания.

**§Д17. Write LF vs 1C CRLF.** Файлы, которые пишет ИИ, — LF; 1С хранит CRLF. После `db-load` — контрольный дамп,
чтобы не плодить diff по концам строк (память `bsl_write_lf_crlf_canon`).

## Грабли М-29 (2026-08-03, [14](14_m29_pechat.md))

**§Д18. ⚠⚠ Загрузчик BSL НЕ КОМПИЛИРУЕТ КОД.** `/LoadConfigFromFiles -partial` и `/UpdateDBCfg` вернули
**EXITCODE=0** на модуле с несуществующей функцией `Абс()`. Ошибка вылезла только на **исполнении**:
`Ошибка инициализации модуля … Процедура или функция с указанным именем не определена (Абс)`.
Документ был нерабочим (нельзя открыть/записать) до догрузки фикса.

**Следствие:** «загрузка прошла» ≠ «код рабочий». Обязателен COM-smoke, который **инстанцирует объект**
(`Ссылка.ПолучитьОбъект()`) и **вызывает** новый метод. Без вызова ошибка дойдёт до пользователя.
Минимальный детектор:
```python
try:
    об = ссылка.ПолучитьОбъект()   # тут падает вся инициализация модуля
except Exception as e:
    print("МОДУЛЬ СЛОМАН:", e.excepinfo[2])
```

**§Д19. `Абс()` в BSL не существует.** Модуль абсолютного значения — только `?(X < 0, -X, X)`.
(В языке запросов тоже нет; там `ВЫБОР КОГДА X < 0 ТОГДА -X ИНАЧЕ X КОНЕЦ`.)

**§Д20. ⚠ Малоценка пишет ДВА комплекта проводок — фильтр обязателен.**
`ПередачаМалоценныхАктивовВЭксплуатацию` при проведении даёт:
- балансовые `Дт 231 Кт 221` (Сумма + КоличествоКт, `СубконтоКт1`=Номенклатура);
- забалансовые `Дт МЦ` с **пустым `СчетКт`** и `КоличествоКт = 0` — на **ту же сумму**.

Без `ГДЕ Х.СчетКт <> ЗНАЧЕНИЕ(ПланСчетов.Хозрасчетный.ПустаяСсылка)` сумма МШП **удваивается**
(проверено: 1 308,94 → 2 617,88). Номенклатура в забалансовой строке сидит в `СубконтоДт2`, не в Кт.

**§Д21. У `ПередачаМалоценныхАктивовВЭксплуатацию.МалоценныеАктивы` НЕТ реквизита `Сумма`.**
Только `Количество`. Себестоимость появляется исключительно после проведения — в проводках.
Любой отчёт по стоимости МШП обязан читать регистр, ТЧ бесполезна (2743 документа в базе, во всех так).

**§Д22. `СубконтоДт1..3` / `СубконтоКт1..3` есть ТОЛЬКО в `ДвиженияССубконто`.** В основной таблице
`РегистрБухгалтерии.Хозрасчетный` этих полей нет — `Поле не найдено "Х.СубконтоКт1"`. Полный список полей
основной таблицы: Период, Регистратор, НомерСтроки, Активность, СчетДт, СчетКт, Организация, ВалютаДт/Кт,
НалоговоеНазначениеДт/Кт, Сумма, ВалютнаяСуммаДт/Кт, КоличествоДт/Кт, СуммаНУДт/Кт, Содержание,
НомерЖурнала, СчетДополнительный, НеКорректироватьСтоимостьАвтоматически, НомерИсходнойПроводки.

**§Д23. ТЧ документа ≠ проводка (FIFO).** ІБ00-000115: `Комплектующие.Сумма` = 1 013 776,70, проводка
`Дт 26 Кт 2051` = **1 009 403,18** (121 строка проводок против 74 строк ТЧ). Позиционно: «Брус 50*50*3,0»
ТЧ 71 502,73 против проводки 69 270,84. **Для отчётности о фактических затратах — только проводки.**

**§Д24. Не фильтровать проводки по `КоличествоКт <> 0`.** Суммовая доводка партии (количество 0, сумма ≠ 0) —
легитимная проводка; фильтр по количеству молча теряет деньги. Достаточно фильтра по `СчетКт`.
От деления на ноль защищаться в расчёте цены (`ВЫБОР КОГДА Количество <> 0 …`).

**§Д25. Цена = Сумма/Количество с 2 знаками ломает проверку умножением.** Мелкая цена на большом количестве:
1000 шт × 0,08 = 80,00 при сумме 83,36 (реально 0,08336). 6 строк из 81 на боевом расчёте.
**Фикс:** подбирать точность 2..6 знаков — минимальную, при которой `Цена × Кол` сходится с суммой
до копейки (`ЦенаДляПечатиМ29`). В Excel-эталоне заказчика та же беда — не копировать её.

**§Д26. `git status -- <каталог>` НЕ показывает файл-сосед `<каталог>.xml`.** Pathspec
`Documents/РасчетКомплектаций` — это директория; манифест `Documents/РасчетКомплектаций.xml` лежит рядом и
в выборку не попадает. Из-за этого можно решить, что реквизиты шапки уже закоммичены, и не перенести их.
Проверять `git status --short` без pathspec либо явно перечислять оба пути.

**§Д27. Ширины колонок и «умные» хранилища.** `ШиринаКолонки` ставить на **необъединённой** строке
(в М-29 — на строке нумерации 1..13, она единственная неслитая). Не использовать `ТабДок.ФиксацияСверху`
как «переменную» для передачи номера строки между процедурами — передавать параметром.

## Подписки на события и частичная загрузка (контроль единиц, [12](12_kontrol_edinic_postuplenie.md))

**§Д18. У общего модуля-обработчика подписки ОБЯЗАТЕЛЕН флаг «Внешнее соединение».** Если снят — через COM
**любой** объект подписанного документа не создаётся: `СоздатьДокумент()`/`ПолучитьОбъект()` падают с
«При подписке … произошла ошибка. **Обработчик события не найден**», **при том что тонкий клиент работает нормально**.
Ломается программное создание документов и обмен через COM. Диагностика: другие типы документов через COM создаются ОК,
падает только подписанный; `Метаданные.ОбщиеМодули.Найти(X).ВнешнееСоединение = False`.
**Урок: не диагностировать «сломан прод» по COM — сначала проверить в клиенте** (боевой кейс 2026-07-20: поднята ложная тревога).

**§Д19. Частичная загрузка общего модуля — подавать ОБА файла:** `CommonModules/X.xml` **и** `CommonModules/X/Ext/Module.bsl`.
Загрузка одного `.bsl` рапортует exit 0, но не применяется (аналог грабли гранулярности форм в `db-load-xml`).

**§Д20. ConfigDumpInfo пропускает файл с прежним хешем** — повторная загрузка неизменённого содержимого молча ничего
не делает. Чтобы форсировать — изменить содержимое (комментарий-маркер).

**§Д21. Новый top-level объект при частичной загрузке требует в списке `Configuration.xml`** (родитель), иначе
«нельзя добавлять объекты метаданных без загрузки родительского объекта». Перед загрузкой `Configuration.xml`
в живую базу — сверить состав зарегистрированных объектов дампа с базой (не разрегистрируется ли что-то).

**§Д22. Открытый Конфигуратор на базе блокирует любую пакетную загрузку** («Ошибка блокировки информационной базы
для конфигурирования» + имя компьютера/сеанса в логе).

**§Д28. Auto-selection уровня СКД = поля группировки + РЕСУРСЫ, а НЕ глобальный selection.**
Вычисляемое поле без totalField в вывод уровней не попадает. И наоборот: при ЯВНЫХ level-selection
без поля группировки пропадает колонка названий (дерево «Загальна назва/Номенклатура» даёт только Auto).

**§Д29. Не-ресурсные поля СКД выводит ПЕРЕД ресурсами** — колонка «прыгает» в начало таблицы.
Чтобы пустая колонка («Коментар цеху») стояла последней — сделать её РЕСУРСОМ (`Максимум(Поле)`).

**§Д30. Значение «только на группе»** — не убирать поле из selection, а глушить на детальном уровне
СА группировки: `<dcsset:selection>` со списком полей + параметр **«Текст» = ""** (жирность группы —
тем же приёмом с параметром «Шрифт», `v8ui:Font ... bold="true"`, флаги useIn* = DontUse).

**§Д31. Текстовое резание XML: у `<field xsi:type=…>` внутри лежит однострочный `<field>Имя</field>`,
у СА-`<dcsset:item>` — вложенные item'ы фильтра.** Закрывающий якорь искать С ОТСТУПОМ
(`\n\t\t</field>`) или резать с балансом вложенности; у `РизницяСС`/`ПроцВиконанняСС` есть ещё
и totalField-агрегаты — вырезать оба слоя.

**§Д32. Подпись строки общих итогов локализует ПЛАТФОРМА по языку сеанса**: COM (ru) → «Итого»,
укр-клиент → «Разом». Smoke принимает оба.

**§Д33. Worktree-ветка от `main` может НЕ содержать живой код** (М-29/акты жили в чужой ветке и
основной папке некоммичеными): перед правкой объекта — diff worktree ↔ основная папка, отставание
затягивать sync-коммитом, иначе загрузка снесёт чужие доработки. Максимальный id формы смотреть
только в ЖИВОМ Form.xml (573 из знаний оказался занят до 609).
