## Печать №10 «Аналіз для цеху» (2026-08-06)

Кількісна форма для КЛАДОВЩИКА: по жовтих (понаднормових) рядках він пише пояснення
від руки в широку колонку «Коментар цеху». Сум НЕМАЄ — рішення бухгалтера.

- Колонки: Загальна назва/Номенклатура (дерево) | **Норма СС** | **Видано** (= `Остаток`) |
  Одиниця виміру | В нормі | Понад норму | Економія | Коментар цеху (порожня, ширина 35 —
  ставится КОДОМ после вывода СКД: пошук клітинки заголовка + `ШиринаКолонки` на клітинці даних).
- **«Норма СС» і «Економія» — ТІЛЬКИ на рядку групи** (щоб не було «Хомут: видано 2, економія 12»
  на картці): на детальному рівні їх глушить СА з параметром **«Текст» = ""** по полях.
- Оформлення під ч/б принтер: групи **жирні** (СА групування, `v8ui:Font bold`), заливка
  `#FFE699` лише при `ПонадНорму > 0`, зеленої заливки немає, «в нормі» — без заливки.
- Макет `МакетАнализЦех` будує скрипт `_Rarzrabotki/Python/test/doc_kompl_build_maket_ceh.py`
  (трансформація `МакетАнализССОдна`, стабільний UUID обёртки). Уровни структуры — Auto-selection
  (единая колонка-дерево); `КоментарЦеху` — вычисляемое поле `""` И РЕСУРС `Максимум()` (иначе
  Auto его не включает, а не-ресурс выводится ПЕРЕД ресурсами — §Д29).
- Итог «Разом» подписывается платформой по языку сеанса: COM(ru) → «Итого», укр-клієнт → «Разом».
- Smoke: `smoke_doc_kompl_pechat_ceh.py` (43 проверки, включая кросс-сверку «Норма СС» с `ПланКол`
  отчёта `А_ОтчетПоСписаниюНаПроизводствоБухгалтерский` по исполнителю).

## Три источника данных — не путать

| Источник | Печати | Что показывает | Нужен «Розрахувати» |
|---|---|---|---|
| `ТаблицаАнализа` (реквизит формы, отфильтрованная копия) | 1–5 | **план** расчёта | да |
| ТЧ объекта (`СписаниеСверхНормы` / `ТабличнаяЧастьОстатков`) | 6, 7 | **сохранённое** состояние | нет |
| **Проводки `Хозрасчетный`** проведённых документов | **8 (М-29)** | **факт бухучёта** после проведения | нет |

Печати 6–8 работают после переоткрытия документа без пересчёта. М-29 вдобавок не зависит от ТЧ расчёта
вообще — читает базу по ссылкам из `ДокументиКомплектації`/`ДокументиМалоценки` ([14](14_m29_pechat.md)).

## Вызов из формы

Каждая кнопка → `Печать*НаСервере()` → `РеквизитФормыВЗначение("Объект").СформироватьПечать*(...)` → `ТабДок.Показать(заголовок)`.
Guard: печати 1–5 требуют непустую `ТаблицаАнализа` («Спочатку натисніть Розрахувати»); Акт — непустую `Объект.СписаниеСверхНормы`
(«Таблиця Списання понад норму порожня»); Розбіжності — непустую `ТабличнаяЧастьОстатков`;
М-29 — записанный документ + непустые ТЧ документов, дальше движок сам проверяет наличие **проведённых**.

## НДС в аналитических печатях

Факт (`СуммаОстатка` и производные) — **с НДС ×1.2** (норма в СС с НДС, остатки без → факт приводится к базе нормы).
Норму (`НормаСуммаНоменкл`) НЕ умножать — она уже с НДС. Документы и таблицы списания — без НДС (÷1.2). См. [03](03_algoritm.md), [05](05_tablicy_spisaniya.md).

⚠ **М-29 к этому не относится**: суммы берутся прямо из проводок, где они уже в учётной оценке (без НДС).
Никаких ×1.2 / ÷1.2 в М-29 нет.

## Программный ТабДок (печати 1, 6, 7, 8)

- Строки — через `ВывестиСтрокуПечати(ТабДок, НомерСтроки, МассивЗначений, Жирный, ЦветФонаСтроки, ЦентрироватьВсе)`:
  рамки **по сторонам** (`ГраницаСверху/ГраницаСнизу/ГраницаСлева/ГраницаСправа = Новый Линия(…Сплошная)`) — свойства
  `.Граница` НЕ существует; первые 4 колонки влево, числа вправо.
- Шапка-на-всю-ширину: `Область(r,1,r,N).Объединить()` → `.Текст` (без `Объединить` текст задвоится во все ячейки).
- Стиль: `Шрифт(,14,Истина)` + `ГоризонтальноеПоложение.Центр` (заголовок); фон шапки `Новый Цвет(210,224,240)`,
  итогов `Новый Цвет(232,232,232)`; `ШиринаКолонки` на любой ячейке колонки; `ТабДок.АвтоМасштаб = Истина`.
- `ТабличныйДокумент` COM-инспектируем (`ВысотаТаблицы`, `Область(r,c).Текст`, `.Шрифт.Жирный`, `.ЦветФона.R/G/B`) → smoke реален.

## СКД-печати (2–5): рабочий рецепт

Схемы — **дизайнерские** (`skd-compile` JSON → `Templates/<Имя>/Ext/Template.xml`), НЕ программная сборка (программная даёт пустой вывод, LESSONS §32). Рантайм:

```bsl
Схема = ПолучитьМакет("МакетПланФакт");
Настройки = Схема.НастройкиПоУмолчанию;
УстановитьЗаголовокЗвіту(Настройки, "План-факт по матеріалах");   // динамический заголовок
Макет = КомпоновщикМакета.Выполнить(Схема, Настройки, , , Тип("ГенераторМакетаКомпоновкиДанных"));
Процессор.Инициализировать(Макет, Новый Структура("Данные", ТЗ), , Истина);  // внешний набор
ПроцессорВывода.УстановитьДокумент(ТабДок); ПроцессорВывода.Вывести(Процессор);
```

- **Внешний набор**: ключ Структуры = `ИмяОбъекта` дизайнерского набора (`"Данные"`).
- **`ДанныеВТаблицуПланФакт`** строит ТЗ (18 колонок: Этап/ОбщееНазвание/Номенклатура/Единица/ЕдиницаСС/ЕдиницаЕдина/Норма/НормаНоменкл/Остаток/ВНорме/ПонадНорму/Экономия/суммы…). `ЕдиницаЕдина = ?(ЕдиницаСС заполнена, ЕдиницаСС, Единица)` — коалесцентная колонка для «одной одиниці».
- **`ДанныеПоЭтапам`** (только для #3) — корректная по-этапная розшивка (Этап×Эталон): норма реальная по-этапная из СС, факт/ВНорме/Понад ∝ по-этапной норме, економія по (эталон, этап) ∝ норме, резидуум округления → первая строка группы (Фаза 16, LESSONS §53).

### Динамический заголовок
`УстановитьЗаголовокЗвіту(Настройки, Назва)` → `ТекстЗаголовкаЗвіту` собирает многострочный (`Символы.ПС`):
Назва + Підрозділ + «Залишки на: дата» + Склади + Специфікація + Організація. Параметр «Заголовок» должен быть в `outputParameters` схемы.

### Грабли СКД (наследованы, [LESSONS](LESSONS.md))
- UUID макета `Templates/*.xml` **уникален** — реюз → макет молча выпадает (§39).
- `calculatedField.title` lang=ru при uk-интерфейсе = пустой заголовок → пост-замена `ru→uk` в Template.xml (UTF-8 **без BOM**, §34/§52).
- Цвет СКД только `#RRGGBB` (web:/style: рендерятся не-абсолютно, COM `ЦветФона.R=-1`) (§36).
- `conditionalAppearance` красит, только если поле-фильтр есть в `selection` (§43); группы красятся условием по значению (`Норма>0`), не `notFilled` (§37).
- Не красить шапку — сузить область применения оформления (`useInHeader/useInFieldsHeader/useInParameters=DontUse`, §51).
- Норму НЕ выносить на уровень группы `Этап` (неделима, §42) — но в #3 используется корректная по-этапная норма (`ДанныеПоЭтапам`).

## Акт (#6) — `СформироватьПечатьАкт()`

Программный ТабДок по `СписаниеСверхНормы`. Шапка: «АКТ на списання понаднормових матеріалів», параметры
(Документ №/дата, Організація, Специфікація, Залишки на дату, Склади). Таблица 9 колонок: №, Номенклатура, Склад,
Рахунок (`.Код`), Одиниця, Кількість, Ціна, Сума, **Причина (обґрунтування)**. Итог «Разом» по сумме. **Блок подписей
комиссии**: Голова комісії / Член комісії ×2 / МВО. Причина берётся из редактируемой ТЧ ([05](05_tablicy_spisaniya.md)).

## М-29 (#8) — `СформироватьПечатьМ29()`

Форма № М-29/1 «ЗВІТ про витрати основних матеріалів у будівництві в співставленні з виробничими нормами».
Программный ТабДок, 13 колонок, ландшафт. Два блока — **Матеріали** (проводки документов `КомплектацияНоменклатуры`)
и **МШП** (проводки `ПередачаМалоценныхАктивовВЭксплуатацию`), без деления на норму/понаднорму.

Ключевое: суммы **только из проводок** — у `МалоценныеАктивы` реквизита `Сумма` нет вообще, а у комплектации
ТЧ-сумма расходится с проводкой (FIFO по партиям). Обязателен фильтр `СчетКт <> ПустаяСсылка`: малоценка пишет
двойные проводки и без фильтра МШП удваивается.

Полное описание, запрос, макет, адаптивная точность цены, контрольные числа — **[14](14_m29_pechat.md)**.
