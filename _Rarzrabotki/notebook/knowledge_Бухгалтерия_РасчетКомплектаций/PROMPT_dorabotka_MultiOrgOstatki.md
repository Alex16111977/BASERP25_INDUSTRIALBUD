## 1. Смысл задачи (роль бухгалтера)

Проект строится СИЛАМИ ДВУХ организаций: материалы на домики приходуют и ТОВ «ІНДАСТРІАЛБУД», и
ТОВ «ІНДЕПТ СТІЛ» — у каждого домика может быть несколько складов, принадлежащих разным организациям
(например, «ІС  МД IRС 2026 15 м №1 Виробничий» — склад ІНДЕПТ СТІЛ, «МД IRС 2026 15 м №1 Виробничий» и
«…Відвантажено» — ІНДАСТРІАЛБУД). Домик списывает на себя материалы С ЛЮБОГО из своих складов, независимо
от организации-владельца остатка.

Сейчас документ «Списання по СС» считает остатки ТОЛЬКО по одной организации из шапки — остатки второй
организации в расчёт не попадают. Заказчик добавил метаданные (УЖЕ в конфигурации и в живой базе):

| Что | Где | Тип |
|---|---|---|
| ТЧ `ОрганизацииОстатков` (колонка `Организация`) | Документ.РасчетКомплектаций | СправочникСсылка.Организации |
| Реквизит `А_Организация` | Справочник.Склады | СправочникСсылка.Организации |

Требуется: расчёт остатков, заполнение/создание документов списания, ручные строки, проверки и печатные
формы должны работать в разрезе «склад × организация» по СПИСКУ организаций из ТЧ `ОрганизацииОстатков`.
Документ-приёмник (КомплектацияНоменклатуры / ПередачаМалоценныхАктивовВЭксплуатацию) юридически
одноорганизационный — строки должны разноситься по документам СВОЕЙ организации.

## 3. Ключевое проектное решение (зафиксировано, не менять без заказчика)

**Организация строки остатка/списания берётся ИЗ РЕГИСТРА (`Ост.Организация` Хозрасчетного), а НЕ из
`Склады.А_Организация`.** Регистр не врёт: на складе могут оказаться остатки НЕ той организации, что
указана в карточке склада (перемещения, история, ошибки ввода), а списывать остаток можно только от
организации-владельца — иначе проведение упадёт «Не списано…». А_Организация — намерение («чей склад»),
регистр — факт («чей остаток»); расчёт и роутинг строк ведутся по факту.

Роли `Склады.А_Организация`: (а) автозаполнение ТЧ `ОрганизацииОстатков` (организация шапки + различные
А_Организация складов из ТЧ СкладыОстатков); (б) значение по умолчанию организации НОВОГО целевого
документа для склада, у которого ещё нет остатков. На расчёт остатков А_Организация НЕ влияет.

Пустая ТЧ `ОрганизацииОстатков` = старое поведение (фильтр по организации шапки; пустая шапка — без
фильтра) — обратная совместимость для 8 существующих документов.

## 4. Задачи

### T1 — метаданные: колонка `Организация` в рабочих ТЧ (правка XML дампа + формы)

Разрез «склад × организация» требует организацию В СТРОКЕ. Добавить реквизит `Организация`
(СправочникСсылка.Организации) в ТЧ:
- `ТабличнаяЧастьОстатков` (анализ; сейчас 20 колонок);
- `СписаниеПоНормам` (8 колонок) и `СписаниеСверхНормы` (12 колонок);
- `ДокументиКомплектації` (Склад, ДокументПоНормам, ДокументДодаткова, ПроведенПоНормам, ПроведенДодаткова)
  и `ДокументиМалоценки` — семейство целевых документов становится ключом **Склад × Организация**.

Правки — в XML дампа по образцу соседних ссылочных реквизитов ТЧ (uuid новые; НЕ meta-edit — он
пересериализует весь XML). На форму документа вывести колонки «Организация» в таблицы анализа и списаний
(ReadOnly) и в таблицы документов; грузить корневой `Documents/РасчетКомплектаций.xml` + форму корневым
`Forms/ФормаДокумента.xml` ОДНИМ пакетом с модулями.

### T2 — расчёт остатков: `ПолучитьОстатки(СкладыМассив)`

Текущий фильтр (якорь):
```bsl
	|	И (&Организация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) ИЛИ Ост.Организация = &Организация)
```
Целевое: параметр `&Организации` (массив из ТЧ ОрганизацииОстатков; пустая ТЧ → массив из организации
шапки; и шапка пустая → без фильтра):
```bsl
	|	И (&БезФильтраОрганизаций ИЛИ Ост.Организация В (&Организации))
```
Плюс в ВЫБРАТЬ/СГРУППИРОВАТЬ добавить `Ост.Организация КАК Организация` — строки остатков разрезаются по
организациям. `ЗаполнитьАнализ` переносит Организация в строку анализа; распределение нормы ВНорме/
ПонадНорму по строкам эталона идёт как раньше (порядок сортировки дополнить организацией для
детерминизма: «ОбщееНазвание Возр, ПорядокПлан Возр, Остаток Убыв» — организацию добавить ПОСЛЕДНЕЙ,
чтобы не менять существующее распределение на одноорганизационных данных!).
`ЗаполнитьТаблицыСписания`/`ЗаполнитьСтрокуСписания` — копируют Организация в строки списаний
(карта норм эталонов и колонки СС не меняются).

### T3 — целевые документы: роутинг по (Склад × Организация)

- `ДополнитьСкладыДокументов`/`ДополнитьСкладыВТаблицу`: строки семейств добавлять на КАЖДУЮ пару
  (склад из СкладыОстатков × организация), где пара реально встречается в остатках/списаниях; для склада
  без остатков — одна строка с организацией `Склады.А_Организация` (fallback организация шапки).
  Идемпотентность сохранить (не плодить дубли пар).
- **Миграция существующих строк семейств** (колонки Организация у них пустые): организацию строки
  проставлять ПО ОРГАНИЗАЦИИ УЖЕ ВПИСАННОГО ДОКУМЕНТА строки (`ДокументДодаткова`/`ДокументПоНормам`
  → его реквизит Организация: СТ00-000088 → ІНДЕПТ СТІЛ, ІБ00-* → ІНДАСТРІАЛБУД), и лишь при пустых
  обеих ссылках — по `Склады.А_Организация` (fallback шапка). Выбор пользователя главнее галочки склада.
- `ПодготовитьСтрокиПоДокументам` → `РаспределитьВДокумент(СтрокиПоДокументам, ПропущенныеСклады,
  ДокСсылка, Склад, …)`: карта документов (`ЦелевыеДокументы`/`ТаблицаСтрокДокумента`) ключуется по
  Склад+Организация строки списания; строка попадает в документ СВОЕЙ организации.
- `ПредсоздатьСтрокиДокументов`/`СформироватьДокументыПоСоответствию` (создание НОВЫХ целевых
  документов): `ДокОбъект.Организация = Организация строки семейства`. Найти фактическое место, где
  СЕЙЧАС заполняется шапка создаваемых документов (в модуле нет присвоения `.Организация` — выяснить,
  откуда она берётся: ОбработкаЗаполнения приёмника/копирование, и закрыть явно).
- `ОбновитьСостояниеДокументов`, `РаспровестиДокументы`/`ПровестиДокументы`, `ПересчитатьИПровести` —
  пройтись по ним: логика по семействам должна пережить новый ключ (правки в основном механические).
- `НайтиДубликатыРасчета` — не трогать логику, но проверить, что она не падает.

### T4 — ручные строки и проверки

`ДанныеОстаткаДляСтроки(Номенклатура, Склад)` (подбор ручной строки понаднормы + `ПроверитьОстатокСтрокиНаСервере`):
фильтр организации → `В (&Организации)` (как T2); в Результат добавить `Организация` (организация
найденного остатка; при нескольких — остаток с максимальным количеством, как выбирается первая строка
сейчас) — форма проставляет её в строку. В форме `ПодобратьДанныеСтрокиСверхНормы` — присвоение.

### T5 — печатные формы

Шапки всех печатей выводят «Організація: …» из шапки документа — заменить на перечень: организация шапки
+ организации ТЧ (уникальные, через запятую). Точки: `ТекстЗаголовкаЗвіту` (СКД-печати: ПланФакт,
ПланФактЕтапи, АнализСС, АнализССОдна, АнализЦех), `ВывестиШапкуАкта` (Акт план/факт),
`СформироватьПечатьРозбіжностіОдиниць`, шапка М29 (`ВывестиШапкуМ29` — проверить, есть ли там организация).
Данные актов и М-29 идут ПО ПРОВОДКАМ регистраторов (`ДанныеАктаПоПроводкам`, `ДанныеМ29ПоБлоку`) без
фильтра организации — мультиорг уже совместимы, данные не трогать. В печати «Аналіз залишків» (АнализСС/
Цех) организацию в колонки НЕ добавлять (кількісна печать) — только шапка.

### T6 — умолчания и форма

- Автозаполнение ТЧ `ОрганизацииОстатков`, если пуста, при «Розрахувати» (в `РассчитатьАнализ` до
  `ПолучитьОстатки`): организация шапки + различные `А_Организация` складов из СкладыОстатков.
  Явно заполненную ТЧ не трогать.
- ТЧ на форме уже выведена пользователем (скриншот 31.08) — проверить и ничего не ломать.

### Не трогать
Механику норм/СС-колонок/КоличествоКСписанию/подтверждения; обработку `А_РекомендацииПеремещенийПоСС`
и отчёт `А_ОтчетПоСписаниюПоНормам_Бухгалтерский` (у них своя организация — отдельная задача, отметить
заказчику); типовые объекты.

## 5. Обязательный процесс и приёмка

1. Партиальный db-dump документа из живой базы, сверка с дампом (параллельные сессии!).
2. Rule #-1: целевой запрос остатков (T2) прогнать Python COM в ДВУХ вариантах: список [ІНДАСТРІАЛБУД,
   ІНДЕПТ СТІЛ] и старый (одна шапка) — на трёх складах примера результаты обязаны СОВПАСТЬ (остатков
   ІНДЕПТ СТІЛ пока нет).
3. Правки метаданных/модуля/формы → db-load-xml Partial (корневые файлы!) + db-update -Dynamic+
   (конфигуратор закрыт; проверить процессы 1cv8).
4. **Приёмка на scratch-копии** (маркер SMOKE_MULTIORG_v1, копия №3; ⚠️ `Скопировать()` сбрасывает Дату;
   боевые НЕ пересчитывать — затирает ручные правки):
   - [ ] инвариант ДО==ПОСЛЕ: анализ/списания/суммы scratch-расчёта с ТЧ орг [ІБ, ІС] == прогону старой
     логики (снять свод ДО загрузки правок);
   - [ ] ТЧ орг = [ІНДЕПТ СТІЛ] → остатков нет, анализ только «немає залишків» по нормам;
   - [ ] ТЧ орг пуста → автозаполнилась (шапка + А_Организация складов), расчёт как в п.1;
   - [ ] строки анализа/списаний несут Организация = ІНДАСТРІАЛБУД (сегодняшние данные);
