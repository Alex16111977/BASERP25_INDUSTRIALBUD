# 05. Таблицы списания ★ (документ-специфично)

Ключевое отличие от обработки: **между анализом и документами появился редактируемый сохраняемый слой** —
две ТЧ списания. Обработка заполняла документы прямо из анализа; документ заполняет их из этих таблиц, поэтому
**ручные правки бухгалтера доходят до документов**.

## Две таблицы

| ТЧ | В форме | Колонки | Что содержит |
|---|---|---|---|
| `СписаниеПоНормам` | **read-only** | Номенклатура, ОбщееНазвание, Склад, Счет, Единица, Количество, Цена, Сумма | Списание «за нормами» (`ВНорме`) |
| `СписаниеСверхНормы` | **редактируемая** | + `Причина` | Списание «понад норму» (`ПонадНорму`) |

Суммы в обеих — **БЕЗ НДС** (÷1.2 от анализных), как пойдут в счета/документы. `Цена = Сумма / Количество` (без НДС).

**Почему так:** списание за нормами не редактируют — оно жёстко по спецификации. Понаднормовое — бухгалтер
обосновывает (меняет количество/цену, добавляет строки, пишет `Причина`), и оно попадает в «Акт на списання
понаднормових матеріалів» ([08](08_pechatnye_formy.md)).

## Заполнение из анализа — `ЗаполнитьТаблицыСписания()`

Вызывается в конце `РассчитатьАнализ` (перезаполняет обе таблицы из `ТабличнаяЧастьОстатков`):

```bsl
Для Каждого Стр Из ТабличнаяЧастьОстатков Цикл
    Если Стр.ВНорме > 0 Тогда
        ЗаполнитьСтрокуСписания(СписаниеПоНормам.Добавить(), Стр,
            Стр.ВНорме, Окр(Стр.ВНормеСумма / КоэффНДС, 2));      // ÷1.2
    КонецЕсли;
    Если Стр.ПонадНорму > 0 Тогда
        ЗаполнитьСтрокуСписания(СписаниеСверхНормы.Добавить(), Стр,
            Стр.ПонадНорму, Окр(Стр.ПонадНормуСумма / КоэффНДС, 2)); // ÷1.2
    КонецЕсли;
КонецЦикла;
```

`ЗаполнитьСтрокуСписания(НС, СтрАнализа, Количество, Сумма)` — общий филлер: копирует Номенклатура/ОбщееНазвание/
Склад/Счет/Единица, ставит `Количество`, `Сумма`, `Цена = ?(Количество > 0, Окр(Сумма/Количество, 2), 0)`.

⚠ `ЗаполнитьТаблицыСписания` **очищает** обе ТЧ перед заполнением → повторный «Розрахувати» затёр бы ручные
правки понаднормы. С 16.09.2026 `Причина` от этого защищена памятью `ПричиниЦеху` (см. ниже); количество/цена — нет. В форме `Рассчитать` при статусе `ДокументыСозданы` спрашивает подтверждение (см. [07](07_statusy_dubli.md), [10](10_forma_dokumenta.md)).

## Редактирование `СписаниеСверхНормы` в форме

Обработчики модуля формы (`Forms/ФормаДокумента`):

| Событие | Что делает |
|---|---|
| `СверхНормыКоличествоПриИзменении` | `Сумма = Окр(Количество * Цена, 2)`; + `ПроверитьОстатокСтрокиНаСервере` (предупредить, если кол > остатка) |
| `СверхНормыЦенаПриИзменении` | `Сумма = Окр(Количество * Цена, 2)` |
| `СверхНормыНоменклатураПриИзменении` / `СверхНормыСкладПриИзменении` | `ПодобратьДанныеСтрокиСверхНормы()` — автоподбор |

### Автоподбор для ручной строки — `ПодобратьДанныеСтрокиСверхНормы()`

При вводе Номенклатура+Склад форма зовёт сервер → `ДанныеОстаткаДляСтроки(Номенклатура, Склад)` (модуль объекта,
[02](02_istochniki_zaprosy.md)) и заполняет строку:

```bsl
Стр.Счет = Данные.Счет;
Стр.Единица = Данные.Единица;
Стр.ОбщееНазвание = Данные.ОбщееНазвание;
Стр.Цена = Данные.Цена;              // без НДС
Стр.Сумма = Окр(Стр.Количество * Стр.Цена, 2);
```

Если остатка нет — сообщение «Залишок за цією номенклатурою на складі не знайдено (рахунок/ціну не підібрано)»;
строку можно оставить (списание без покрытия остатком — предупреждение, не запрет).

### Проверка остатка — `ПроверитьОстатокСтрокиНаСервере`

Не блокирует, только предупреждает: «залишку немає — списуємо без покриття» либо «кількість N перевищує залишок M».

## Куда идут таблицы дальше

`ЗаполнитьДокументыПоАнализу` читает **эти сохранённые ТЧ** (не анализ): `СписаниеПоНормам` → документы «ПоНормам»,
`СписаниеСверхНормы` → документы «Додаткова». Семейство (комплектация/малоценка) — по `Счет` строки. См. [06](06_zapolnenie_dokumentov.md).

## Память причин — ТЧ `ПричиниЦеху` (16.09.2026)

`Причина` — единственная колонка понаднормы, которую пишет НЕ бухгалтер, а цех: он получает печать
«Аналіз для цеху (з коментарем)», вписывает обоснование перерасхода и возвращает файл `.xlsx`.
Обратная загрузка берёт из файла **только** `Коментар цеху` — количества, цены, суммы, счета и склады
документа она не трогает вообще.

| Что | Где |
|---|---|
| Память причин | ТЧ `ПричиниЦеху`: `ОбщееНазвание`, `Номенклатура`, `Причина` (200), `ДатаЗагрузки` |
| Загрузка | `ЗавантажитиПричиниЦехуЗФайлу(АдресФайла, ИмяФайла)` — экспорт, регион `ПричиниЦеху` модуля объекта |
| Применение | `ЗастосуватиПричиниЦеху()` — вызывается в конце `ЗаполнитьТаблицыСписания()`, т.е. после каждого «Розрахувати» |
| Сбор ручных правок | `СобратьПричиныИзСписания()` — в `ПередЗаписью` |
| Очистка | `ОчиститиПричиниЦеху()` — чистит И память, И колонку `Причина` в списании |
| UI | кнопка «Завантажити коментарі цеху» рядом с «Друк» + закладка «Причини цеху» |

**Строки памяти двух видов:**
* по номенклатуре (`ОбщееНазвание` + `Номенклатура`) — комментарий на обычной строке файла;
* по эталону (только `ОбщееНазвание`) — комментарий на ЖИРНОЙ строке группы; действует и на те
  номенклатуры, которые появятся под этим эталоном при следующем пересчёте.
Приоритет при применении: причина по номенклатуре > причина по эталону. Причина ставится **во все**
строки списания этой номенклатуры (одна позиция часто лежит на двух складах).

**Жизненный цикл**

| Событие | Поведение |
|---|---|
| «Розрахувати» | ТЧ списания перезаполняются, затем `ЗастосуватиПричиниЦеху()` возвращает причины |
| Запись документа | ручные правки `Причина` уходят в память; очищенная вручную причина — удаляет строку памяти; причина, пришедшая с уровня эталона, по номенклатуре НЕ дублируется |
| **Копирование документа** | `ОбработкаКопирования` чистит `ПричиниЦеху` **и** `Причина` в списании — обоснования чужого расчёта в копию не едут (требование заказчика) |
| Обмен (`ОбменДанными.Загрузка`) | хуки под существующим guard в `ПередЗаписью` |

**Как читается файл.** `ТабличныйДокумент.Прочитать(<xlsx>)` — штатно платформой, без Excel и COM
(проверено: файл-образец 333×13). Колонки ищутся по ТЕКСТУ заголовков («Загальна назва», «Код»,
«Коментар цеху») — сдвиг колонок переживается. Уровень строки определяется по **жирности** первой
колонки (после чтения xlsx флаг сохраняется). `.xls` (старый бинарный) платформа не читает — загрузчик
говорит об этом явно. Поддерживаются и адрес временного хранилища (из формы), и прямой путь к файлу
(скрипты приёмки, пакетные сценарии).

**Ключ сопоставления и почему он такой.** Сначала `Код` номенклатуры (колонка печати с 16.09.2026),
затем пара «эталон + название», в крайнем случае — само название. Область поиска — ТОЛЬКО
`ТабличнаяЧастьОстатков` этого расчёта. Замер по базе: в `Справочник.Номенклатура` **57 дублей кода**
и **602 тезки по имени**; внутри расчётов тёзки реально встречаются (расчёт №10, «Рейка 50*50*3000» —
две разные номенклатуры под эталонами «Брус» и «Рейка»). Неоднозначность НЕ угадывается: строка идёт
в счётчик `Конфлікт` и в протокол, причина не проставляется. Пустая ячейка комментария ничего не
затирает; текст длиннее 200 символов обрезается со счётчиком `Обрізано`.

**Протокол загрузки:** `Всего / Загружено / Обновлено / БезИзменений / НеНайдено / Конфликт /
Обрезано / Применено / Ошибка / Сообщения` (до 30 пояснений).
