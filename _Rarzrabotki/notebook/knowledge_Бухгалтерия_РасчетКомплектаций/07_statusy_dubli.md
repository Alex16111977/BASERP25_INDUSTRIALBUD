# 07. Статусы и дубли ★ (документ-специфично)

## Перечисление `СтатусыРасчетаКомплектаций`

3 значения (uk-синонимы для интерфейса BuhBud):

| Значение | Синоним uk | Когда ставится |
|---|---|---|
| `Черновик` | Чернетка | `ОбработкаЗаполнения` (при создании нового документа) |
| `РасчетВыполнен` | Розрахунок виконано | в конце `РассчитатьАнализ()` (последняя строка) |
| `ДокументыСозданы` | Документи створено | в конце `ЗаполнитьДокументыПоАнализу()`, **только если** `Помилки = 0 И Заповнено > 0` |

Переходы линейные: Черновик → РасчетВыполнен → ДокументыСозданы. Статус — это индикатор стадии рабочего места,
он **не** делает движений (документ непроводимый).

⚠ **Статус `ДокументыСозданы` ставится ПОСЛЕ `КонецПопытки`** (после `ЗафиксироватьТранзакцию`), а не внутри:
транзакция заполнения — это «Зафиксировать последней строкой Попытки», а смена статуса идёт следующим шагом,
уже по результату (`Результат.Помилки`/`Результат.Заповнено`). Не переносить установку статуса внутрь транзакции.

## `ОбработкаЗаполнения` (модуль объекта)

При создании документа:
```bsl
Статус = Перечисления.СтатусыРасчетаКомплектаций.Черновик;
Период = НачалоДня(ТекущаяДата());
Ответственный = Пользователи.ТекущийПользователь();
// дефолт-счета, если ТЧ пусты:
СчетаОстатков ← 20, 28   (НайтиПоКоду)
СчетаМалоценки ← 22
```

## `ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)` (модуль объекта)

```bsl
Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;          // не мешать обмену
Если НЕ ЗначениеЗаполнено(Статус) Тогда Статус = …Черновик; КонецЕсли;
Дубли = НайтиДубликатыРасчета();
Если Дубли.Количество() > 0 Тогда
    Сообщить("Увага: вже існує розрахунок за цією специфікацією/датою/складами: " + …);  // ПРЕДУПРЕЖДЕНИЕ
КонецЕсли;
```

- **`ОбменДанными.Загрузка` → ранний выход** — запись из обмена не трогает статус/дубли (канон).
- **Дубли — предупреждение, НЕ `Отказ`**. `Отказ` не ставится: документ сохраняется, пользователь лишь уведомлён,
  что похожий расчёт уже есть. Это осознанное решение (пользователь может вести несколько расчётов на одну дату).

## Дубликаты — `НайтиДубликатыРасчета()` Экспорт

Другие документы `РасчетКомплектаций` по той же **спецификации**, тому же **дню остатков** (`Период МЕЖДУ НачалоДня И КонецДня`)
и **пересечению складов** (`ВНУТРЕННЕЕ СОЕДИНЕНИЕ … СкладыОстатков`, `Склады.Склад В (&Склады)`), кроме самого себя
(`Док.Ссылка <> &Ссылка`) и помеченных на удаление. Запрос — [02](02_istochniki_zaprosy.md) §6.

⚠ Не объявлять локальную переменную `Ссылка` — конфликт с системным свойством (использовать `&Ссылка` как параметр). Тут используется `Ссылка` (реквизит документа) как значение параметра — это ок.

## Пересчёт при уже созданных документах (форма)

Кнопка «Розрахувати» в форме (`Рассчитать`): если статус уже `ДокументыСозданы` — **вопрос-подтверждение**
(`ПоказатьВопрос`, «Документи вже створено за цим розрахунком. Перезаповнити розрахунок?»). Пользователь
подтверждает → `РассчитатьНаСервере` + `ПрименитьОтборИИтоги` + `Записать`. Иначе расчёт идёт сразу.

Причина вопроса: `РассчитатьАнализ` → `ЗаполнитьТаблицыСписания` **очищает** обе ТЧ списания → **ручные правки
понаднормы теряются**, а связанные документы уже заполнены по старому расчёту. См. [05](05_tablicy_spisaniya.md), [10](10_forma_dokumenta.md).
