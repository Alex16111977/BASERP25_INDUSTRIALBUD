# 11. Как дорабатывать ★

Общий порядок (Rule #-1 / Golden Sequence): **Python COM тест → BSL → db-load-xml Partial → db-update -Dynamic+ →
проверить в клиенте BuhBud**. Правки метаданных/формы — **только перегенерацией скриптами** (не ручной XML).

## Рецепт: + колонка анализа

1. Манифест `Documents/РасчетКомплектаций.xml` — добавить реквизит в ТЧ `ТабличнаяЧастьОстатков` (uuid — новый, не реюзить).
2. Движок: заполнить колонку в `ЗаполнитьАнализ` (или в запросе `ПолучитьОстатки`/`ПолучитьНормы`).
3. Форма: добавить копию колонки в реквизит-VT `ТаблицаАнализа` + строку `НС.X = Стр.X` в `ПрименитьОтборИИтоги`.
4. Если колонка нужна в СКД-печатях — добавить в `ДанныеВТаблицуПланФакт` (+ `ДанныеПоЭтапам` для #3) и в JSON макета (`skd-compile` → ru→uk).
5. Плоский «Друк»: добавить в `Заголовки`/`Значения`/`Итоги` `СформироватьПечать` + ширину колонки.

## Рецепт: + фильтр

1. Реквизит шапки (или ТЧ-список) в манифесте.
2. Хелпер-«списком» в движке (как `СкладыСписком`/`ЭтапыСписком`) + условие в запрос (внешний `ГДЕ` / ИЛИ-паттерн; см. [02](02_istochniki_zaprosy.md), [04](04_filtry_scheta.md)).
3. Форма: поле на вкладку «Параметри».

## Рецепт: + статус / изменить переходы

1. Значение в перечисление `Enums/СтатусыРасчетаКомплектаций.xml` (ru+uk синонимы, новый uuid).
2. Установка статуса — в оркестраторе (`РассчитатьАнализ` / `ЗаполнитьДокументыПоАнализу`); помнить: `ДокументыСозданы` **после** `КонецПопытки`, по результату ([07](07_statusy_dubli.md)).

## Рецепт: + печать

- **Программная** (как Акт/Розбіжності): экспортная `СформироватьПечать<Имя>()` в движке (шапка `Объединить`+`.Текст`, `ВывестиСтрокуПечати`, границы по сторонам, `АвтоМасштаб`) + команда/кнопка в форме + `*НаСервере` + guard непустоты.
- **СКД** (как ПланФакт): `skd-compile` JSON → `Templates/<Имя>/Ext/Template.xml` + `Templates/<Имя>.xml` (**уникальный uuid**, §39) + `<Template>` в манифест + ru→uk (§34) + экспортная compose-функция (`ПолучитьМакет` → `КомпоновщикМакета.Выполнить` → внешний набор `Структура("Данные", ТЗ)`) + кнопка. См. [08](08_pechatnye_formy.md).

## Рецепт: правка общего движка

Движок — порт обработки. Перед правкой сверить с базой знаний обработки
([`../knowledge_Создания комплектаций для бух учета/`](../knowledge_Создания%20комплектаций%20для%20бух%20учета/), файлы 02/03).
Математику распределения ([03](03_algoritm.md)) не трогать без пересчёта инвариантов. По возможности держать имена
идентичными обработке (регрессия обработки должна оставаться зелёной).

## Чек-лист сборки

- [ ] Запрос протестирован в Python COM (Rule #-1)?
- [ ] Новые uuid (реквизиты ТЧ, макеты, обёртки форм) — **уникальны**, не реюз?
- [ ] uk-синонимы для новых объектов (перечисление/реквизиты)?
- [ ] СКД: ru→uk в Template.xml, UTF-8 **без BOM**?
- [ ] Форму НЕ перегенерировал build-скриптом (только точечный патч)?
- [ ] Проверка уникальности id в Form.xml (Designer задваивает)?
- [ ] Комментарий в запросах — `ВЫРАЗИТЬ КАК Строка(N)`?
- [ ] Ветвление ТЧ документа — `Если/Иначе`, не `?()`?
- [ ] Соответствие без `Неопределено`-ключей?
- [ ] Копия изменённых файлов в основной каталог (CLAUDE.md Rule #4), контрольный дамп LF→CRLF?
- [ ] db-load-xml Partial + db-update -Dynamic+ (перед загрузкой — нет открытого Конфигуратора)?
- [ ] Проверено в клиенте BuhBud (форму COM не рендерит)?
- [ ] Smoke `smoke_doc_kompl_*.py` зелёные + регрессия обработки (`smoke_komplektacii_summy.py`) цела?

## Загрузка в живую базу

- `db-load-xml` Partial (объект) — если менялся uuid обёртки формы, грузить с родительским `Documents/РасчетКомплектаций.xml`.
- `db-update -Dynamic+` — принимает **добавление** объектов без монопольного режима (обновлялось на живой базе с пользователями).
- ⚠ Перед загрузкой: `Get-CimInstance Win32_Process -Filter "Name='1cv8.exe'"` — открытый Конфигуратор откатит загрузку.
- ⚠ `epf`-сборка (если трогаешь обработку-прародитель) — из изолированного каталога против BuhBud/BaseERPRazr.
