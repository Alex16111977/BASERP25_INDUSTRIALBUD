# GLOSSARY — словарь терминов «Разработка связей»

> Термины сгруппированы по смыслу. В колонке «Где» — объект 1С (база BuhBud `bas_industrialbud`, если не сказано иное), поле JSON или файл папки. Числа — грн с ПДВ по цене СС, если не сказано иное.

## 1. Нормативная сторона (что положено)

| Термин | Что это | Где |
|---|---|---|
| **СС** (структура собівартості) | Норматив материалов и работ на один дом проекта. Мастер — в BuhBud. ERP хранит копию, которую обмен переносит из BuhBud | `Справочник.СтруктураСебестоимости` (синоним «Структура собівартості»); копия в ERP — `Справочник.А_СтруктураСебестоимости`, правило обмена `ExchangeRules.xml`, стр. 4742 |
| **Карточка СС** | Один элемент справочника СС: проект или тип дома, число домов, склад, флаги контроля | 000000009 «МД IRС 2026 30 м (МД IRС 2026)»: 7 домов, 170 строк, 1 009 864,74 на дом. 000000008 «… 15 м»: 6 домов, 190 строк, 704 612,01. `data/demo_svyaz_ss_30m.json` → `card` |
| **Строка СС** | Одна строка ТЧ `Комплектующие` карточки СС: позиция норматива с этапом, ОН, количеством, суммой (с ПДВ) и единицей | `СтруктураСебестоимости.Комплектующие`; в прототипе — `mapping[]` (поля `n`, `etap`, `on`, `text`, `unit`, `norm_q`, `norm_uah`) |
| **НоменклатураСС** | Текст позиции из Excel-шаблона СС, колонка G. Это строка, а не ссылка | `Комплектующие.НоменклатураСС` (Строка 200); в прототипе — `mapping[].text`. Опечатки сохраняются как есть: «Копмлпект септика», «Порфлист ПК 10 Стіни» |
| **`Комплектующие.Номенклатура`** | Ссылка на одну карточку номенклатуры в строке СС. В IRC и ООН пуста во всех строках. В июле загрузчик заполнял её из `ОсновнаяНоменклатура` ОН; сейчас её стирает `ПередЗаписью` СС при каждой записи, кроме обмена (ObjectModule СС, стр. 34; [01](01_kak_ustroena_svyaz_seychas.md) §1.1), поэтому для связи она не годится | 0/170, 0/190 (`card.lines_with_nomenclature_filled` = 0) |
| **ОН** (загальна назва, «Узагальнена назва») | Группа карточек номенклатуры. Сейчас это единственное звено между строкой СС и фактом: строка СС → ОН ← много карточек. По сути связь «многие-ко-многим» | `Справочник.ОбщиеНазванияНоменклатуры` (синоним в базе «Загальні назви номенклатуры»; 353 элемента, групп нет, 5 помечены на удаление, `НазваниеДляОбъединения` пусто у всех — COM рецензента 03.10); у строки — `Комплектующие.ОбщееНазвание`; у карточки — `Номенклатура.ОбщееНазваниеНоменклатуры` |
| **Эталон** | Синоним ОН в коде контроля ПТУ и в выгрузке причин (`аналіз_норма_еталон`). Тип ошибки `ЭталонНеВСС` — ОН карточки нет в СС подразделения | `../12_kontrol_edinic_postuplenie.md`; `data/prichiny_ponad_normu_irc.json` |
| **`КоэффициентыПересчета` (ТЧ СС)** | Коэффициент пересчёта единиц на позицию СС: `ЕдиницаСС × k = единица закупки`. Ключ — Этап + `НоменклатураСС` | `../16_ss_original_koeficienty_fajly.md`; 34 строки у 000000009 |
| **`ДобавленоВручную`** | Строка СС, добавленная бухгалтером, часто с нулевой нормой. Нужна, чтобы ОН прошла контроль закупок | В СС 15 м — 22 такие строки с количеством 0 |
| **Групповая норма** | Строки СС одной ОН взаимозаменяемы, поэтому контроль идёт суммой по группе, а не по строкам. В прототипе это только «Гвинтові кріплення»: 9 строк, 8 166,05 на дом, 8 карточек | `mapping.py`, `GROUP_ON`; `coverage.by_method` «групова норма»; роль связи «Групова» |

## 5. Связь «строка СС ↔ карточка»

| Термин | Что это | Где |
|---|---|---|
| **Аліас** | Карточка под другой ОН, которая фактически закрывает строку СС, иногда с коэффициентом единиц. Пример: «Держак ринви Profil пласт.» → «кріплення ринви», «Плінтус на стільницю 3 м» → «Меблевий кутик» (1 шт = 3 м) | `mapping.py`, `ALIAS`; роль «Аналог»; метод «аліас / пересорт» — 16 строк, 62 322,72 на дом |
| **Пересорт** | Выдали другую карточку вместо нормативной. Внутри одной ОН Шахматка гасит его сама. Между ОН он даёт пару «ложное понад + ложная економія» | Причины цеха, тип A: 65 622,25 без ПДВ по 9 домам ([research/prichiny_workflow_itog.md](research/prichiny_workflow_itog.md)) |
| **Типы A–G причин** | A — пересорт между ОН; B — одна строка СС на 2+ материала (1:N); C — комплект септика; D — позиции нет в СС; E — норма занижена; F — групповой перерасход; G — между домами / варианты; G-МШП — инструмент | `scripts/01_analiz_tekushchey_svyazi/tab_types.md`, `scripts/02_prichiny_ponad_normu/cls2.py` |
| **1:N, N:1** | В диалоге и проекте 06 порядок «строка : карточка»: 1:N — одна строка СС закрывается несколькими карточками (з'єднувач ринви + з'єднувач труби); N:1 — одна карточка закрывает несколько строк (труба каналізаційна 110/3000 → строки 118 и 117, по приоритету). **В прототипе порядок обратный**: метод «N:1 за ОН» значит «N карточек : 1 строка» — дубли/варианты одной позиции под единственной строкой ОН (6 строк, 13 карточек, 9 081,16 на дом), и в `caveats[15]` «N:1» — тоже «карточки → строка» | [research/dialog_2026-10-03.md](research/dialog_2026-10-03.md), «Так закрываются все три случая»; [06_proekt_mehanizma.md](06_proekt_mehanizma.md) §3.2 (`Приоритет`); `coverage.by_method`, `mapping.py`, `build()` (пометка «за ОН N:1») |
| **Комплект** | Строка СС, которая означает набор деталей. Сейчас один такой случай: строка 170 «Копмлпект септика», 1 компл. = 12 000,00 | Метод «комплект»; `mapping.py`, `KIT_COMP` |
| **Количество в комплекте** | Сколько штук детали на 1 комплект: днище ×1, кільце ×2, люк ×1, плита ×1 (по ІБ00-000174) | `mapping.py`: `KIT_COMP`, поле `per_kit` в связях `MAP[код]["links"]` (в JSON поля нет — количество записано в `links[].note`); собрано комплектов = min(деталь / кол-во в комплекте). Состав ІБ00-000174 перепроверен COM рецензентом 03.10 |
| **Напівфабрикат** | Карточка собранного комплекта на счёте 2051: «Комлпект септика» 00-00023184. У неё та же ОН, что у деталей, поэтому без связи комплект учитывается дважды | В прототипе — роль «Виключена» с `coef` 0; в проекте 06 — отдельная роль `ПолуфабрикатКомплекта` «Напівфабрикат комплекту» (06 §3.3, §4.4). Считаются детали, собранные в неё (14 304,17 нетто на №1) |
| **Службова (служебная) комплектація** | Документ сборки, у которого стоит галочка «Службова»: внутреннее перемещение Дт 2051 Кт 2051, а не списание на дом. Флаг не читает ни один модуль (обращений `.Служебная` в BSL дампа BuhBud — 0). В базе он стоит у одного документа — ІБ00-000174 от 29.09.2026 (COM рецензента 03.10: 1 из 484 документов). Парная сборка ІБ00-000175 от 01.09 флага не имеет | `Документ.КомплектацияНоменклатуры`, реквизит `Служебная` (XML, стр. 858; форма, стр. 943) |
| **Роль связи** | Как карточка участвует в строке. Основна — нормативная карточка. Аналог — замена или аліас с k. Складова комплекту — деталь комплекта. Виключена — карточка не идёт в строку; в прототипе это единственная связь с такой ролью — напівфабрикат «Комлпект септика» в строке 170 (в проекте 06 для него отдельная роль `ПолуфабрикатКомплекта`). «Шпилька 10×1000» в прототипе не «Виключена», а «поза СС» (`mapping.py`, `POZA`); «Виключена» для строки 9 — только предложение ([08_otkrytye_voprosy.md](08_otkrytye_voprosy.md) §4.7). В прототипе есть ещё классы карточек без связи: «поза СС», «МШП», «Групова». В проекте 06 это перечисление `А_РолиСоответствияНоменклатурыСС`: Основная, Аналог, СоставляющаяКомплекта, ПолуфабрикатКомплекта, Исключена, ВнеСС, МШП, ГрупповаяНорма и др. | `mapping[].links[].role`; `MAP[c]["kind"]`; [06_proekt_mehanizma.md](06_proekt_mehanizma.md) §3.3 |
