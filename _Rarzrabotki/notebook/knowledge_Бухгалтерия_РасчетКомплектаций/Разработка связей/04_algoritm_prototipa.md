## 3. Склады, факт, остатки, ПДВ, цены (`base.py`)

### 3.1 Классы складов — `wcls()` (`base.py:35–47`)

| Класс | Правило | Комментарий |
|---|---|---|
| `P` — склад проекта | имя точно входит в `PROJECT_W` (`:11`): «ІБ _МД IRC 2026», «ІС _МД IRC 2026», «МД IRС 2026», «Цех МД IRS 2026», «МД IRS 2026» | в «МД IRС 2026» буква «С» кириллическая, в «ІС» — тоже кириллица. Сверка v2 сравнивала только «ІБ _МД IRC 2026» и сошлась до копейки. Отсюда вывод, что остальные 4 имени на снимке дали 0; отдельно это **не проверялось** |

### 3.2 Материальные счета и свёртки (`base.py:50`, `:104–121`)

- Материальный счёт: `is_mat` = первые 2 символа кода ∈ {20, 22, 28}. Счёт **26 в запросе есть, но материалом не считается**. Поэтому Кт 20/22/28 → Дт 26 со склада дома тоже считается списанием.
- `st[код][класс] = [кол, нетто, брутто]`: по Дт материального счёта плюс на склад Дт, по Кт минус со склада Кт. Период — весь 2026 год, проект IRC начат в 2026, поэтому `st` — это остаток на 31.12.2026. Проверка v2 сверила его с `Хозрасчетный.Остатки` на 31.12.2026 по каждой карточке: 0 расхождений (JSON `caveats[14]`).
- `cons[код][дом]` = **F (списано на дом)**: Кт материального счёта со склада дома, Дт — не материальный счёт.
- `views.ASM[(компонент, дом)]` (`views.py:11–18`) — сборка септика: Кт компонента → Дт карточки KIT, оба счёта материальные, склад Кт — дом. `base.asm` (`:121`) считается, но дальше не используется.

### 3.3 ПДВ партии — `Vat.ratio(партия, код, склад)` (`base.py:53–88`)

Брутто движения = `Сумма × (1 + ratio)`. Правила проверяются по порядку:

1. Есть строки ПТУ этой партии и этой карточки → ΣНДС / Σнетто.
2. Есть ПТУ этой партии (любые карточки) → ΣНДС / Σнетто документа.
3. Партия «Авансовий звіт…» → 0.
4. Есть перемещения мат→мат в (партия, код, склад) → средневзвешенная по сумме ставка источников, рекурсия с глубиной < 12.
5. Запасной вариант по ставке номенклатуры: пусто или «20%» → 0,2; «7%» → 0,07; иначе 0. Такой ключ попадает в `VAT.fallback`.

Нетто ПТУ = `Сумма − НДС`, если `СуммаВключаетНДС`, иначе `Сумма`. Это упрощённый перенос `Vat` из `C:/Configuration_downloads/BASERP25/_Rarzrabotki/Python/test/moy_byudzhet_11_irc_fakt.py:289` (без параметра `amount`). В документах РК ПДВ считается коэффициентом ×1,2, поэтому их «понад» отличается от прототипа (JSON `caveats[8]`).

### 3.4 Цены

- **Цена СС** строки = `Комплектующие.Сумма / Количество`; Сумма уже с ПДВ (`mapping.py:9–11`, JSON `totals.basis`). Для ОН («как сейчас») берётся ΣСумма / ΣКол строк этой ОН (`views.py:37–39`). Для групповой нормы — ΣNs / ΣN.
- **Последняя закупка** `LAST[код]` (`base.py:131–140`) — самая поздняя проведённая строка ПТУ с `Кол ≠ 0`: `price_g = (нетто + НДС) / Кол`. Количество взято в единице документа. Совпадает ли она с базовой единицей карточки, **не проверено**.
  - Вид «как сейчас»: по ОН берётся карточка с самой поздней закупкой (`now_last_price`, `views.py:99–106`).
  - Вид «со связью»: карточка строки с наименьшим приоритетом, при равных — с самой поздней закупкой; цена делится на коэффициент (`line_last_price`, `views.py:264–272`).
  - Нет закупки → цена СС (`final.py:239`, `:256`).

## 5. Шаги связывания (`mapping.build`, `:102–141`)

Каждая карточка проходит ветки сверху вниз, срабатывает **первая**. Порядок важен: например, аліас перебивает МШП и размер.

| # | Условие | Kind / метод | Что получает карточка |
|---|---|---|---|
| 1 | код = `KIT` 00-00023184 «Комлпект септика» | Виключена / комплект | ничего: вместо неё считаются складові |
| 2 | код ∈ `KIT_CARDS` (6 кодов) | Складова комплекту / комплект | строка 170, coef 1, prio 1, high, группа и `per_kit` |
| 3 | код ∈ `ALIAS` (19 кодов) | Аналог / аліас | 1…N строк, коэффициент из словаря, prio = 2, 3, … |
| 4 | код ∈ `POZA` (13 кодов) | поза СС | ничего |
| 5 | код ∈ `MSHP_EXTRA` (2) или ОН карточки = «мшп» | МШП | ничего |
| 6 | ОН ∈ `GROUP_ON` = {«гвинтові кріплення»} | Групова | ничего, карточка идёт в пул группы |
| 7 | код ∈ `SIZE` (55 кодов) | Основна / за розміром | 1 строка, coef 1, prio 1, довіра из словаря |
| 8 | у ОН карточки ровно 1 строка СС | Основна / за ОН | эта строка, coef 1, prio 1, high |
| 9 | у ОН ≥ 2 строк, кода нет в `SIZE` | не визначено / ручна | ничего (на 30 м таких 0) |
| 10 | у ОН карточки нет строк в СС | поза СС | ничего (примечание «ОН картки не має строки в СС 30 м») |

После прохода по всем карточкам: если на одну строку пришло ≥ 2 карточек методом «за ОН», им ставится метод «за ОН N:1» (`:131–140`). ОН сравнивается через `K()` (`base.py:27`): NBSP заменяется пробелом, пробелы схлопываются, применяется `casefold`.

Итог по 225 карточкам (JSON `coverage.cards_by_method`): за ОН 65, за ОН N:1 13, за розміром 55, аліас 19, комплект 5 (KIT и 4 складові; 2 кода из `KIT_CARDS` — 00-00005944 кільце и 00-00017426 плита — в универсум не вошли), групова 8, МШП 36, поза СС 24 (13 из `POZA` и 11 «ОН без строки в СС»). Ветка «ручна» сработала 0 раз.

### 5.1 Метод и довіра строки СС (`line_method :147–162`, `line_conf :165–170`)

Метод строки определяется по приоритету:

1. Строка 170 → «комплект».
2. ОН строки ∈ `GROUP_ON` → «групова норма».
3. Связей нет → «без карточки».
4. Среди методов связанных карточек есть «аліас» → «аліас / пересорт».
5. Иначе есть «за розміром» → «за розміром».
6. Иначе есть «за ОН N:1» → «N:1 за ОН».
7. Иначе → «1:1 за ОН».

Довіра строки — худшая из довір её связей (high < medium < low). Строка требует ручного решения, если она «без карточки» или её довіра medium/low (`final.py:90`).

Следствие. У строки 28 «Обрізний диск 230 мм» есть основная карточка «за ОН» (00-00000071, high) и аналог «Круг відрізний» (00000006053, medium). Поэтому строка получает метод «аліас / пересорт» и довіру medium (JSON `mapping[27]`).

## 6. Распределение

### 6.1 Вклад карточек в строки — `contributions(cls)` (`views.py:137–179`)

Класс `cls` ∈ {`F:дом` — списано, `S:дом` — лежит на складе дома, `P` — склад проекта}.

- Карточка с одной связью отдаёт в свою строку `(q × coef, брутто)`.
- Карточка с несколькими связями (на 30 м такая одна: 00-00013067 труба 110/3000) обрабатывается так:
  - связи сортируются по `prio`;
  - для каждой связи свободное место = норма строки **на один дом** − уже внесённое;
  - `take = min(остаток × coef, место) / coef`;
  - всё, что осталось после последней связи, уходит **на первую строку**.

  Пример с трубой 110/3000 (шт, 1 шт = 3 м): сначала строка 118 «Труба ПВХ д110 (3000мм)» до нормы 3 м (1 шт). Затем строка 117 «д110 (500мм)» до 0,5 м (1/6 шт). Остаток снова идёт на 118. На №1 и №2 списано по 4 шт (`explore.txt`). По коду это 12 м при норме двух строк 3,5 м, и излишек 8,5 м ложится на строку 118 как «понад». Это расчёт по формуле: построчный вывод в JSON не выгружен.
- Поза СС, МШП и карточки без связи накапливаются в `extra[poza|mshp|unmapped]`, групповые — в пул `group`. Сама карточка KIT пропускается.

### 6.2 FIFO склада проекта по домам №3→№7

`TODO = [30-3 … 30-7]`, `DONE = [30-1, 30-2]` (`views.py:7–8`). Для каждого ключа (ОН или строка СС):

```
Sp  = max(0, количество на складе P)       # «со связью» — уже в единицах строки СС (× coef)
rem = Sp
для h в №3, №4, №5, №6, №7:
    move_h = min(D_h, rem); rem -= move_h; buy_h = D_h - move_h
Перемістити = min(ΣD, Sp);  Докупити = max(0, ΣD - Sp)
```

Остаток `rem` после №7 никуда не идёт: это излишек склада проекта, он не уменьшает потребность по другим строкам. Исключение — септик: запасные детали считаются по группам (§5.4). Порядок домов и FIFO такие же, как у G_h бюджета v3 (JSON `vs_budget_v3.basis`).

Сопоставимое число «со связью» — `totals.mapped.ponad_split.po_strokah_ss` = 65 943,68.
2. Отчёт складывает дефицит по всем домикам с план-строками, включая отгруженные №1–№2: дефицит связки «объект + виконавець + ОН» = План − Факт − Остаток считает `ЗаполнитьПотребностьПозиций` (стр. 257, формула стр. 287), а суммирует по всем домикам `ЗаполнитьАнализПоДомикам` (`СуммаДефицита`, стр. 457). Прототип, кеш f41 и бюджет v3 считают «треба» только по №3–№7. С №1–№2 Докупити было бы 1 533 536,50 (JSON `totals.now.dokupyty_yakby_treba_i_po_1_2_uah`).

### 7.3 Хибне / приховане

- **Понад** (`over_diff`, `final.py:167–175`): разница считается по карточке, семейство септика объединено. Если «сейчас − со связью» > 0, это хибне понад, которое уходит; если < 0 — приховане понад, которое появляется. На уровне дома выполняется тождество `сейчас − хибне + приховане = со связью`.
- **Економія** (`econ_diff`, `:178–189`): разница по ОН строки.
- **Докупити** (`flows`, `final3.py:14–37`): разница по ОН между «со связью» и «как сейчас». Из прироста выделяется часть, которая приходится на строки СС, по которым на №1–№2 не выдано ни одной единицы. Признак `q12` (`final.py:227–228`): для строки — F = Sh = 0 на №1 и №2; для ОН — так по всем её строкам.

**Допущения и края логики** (на этих данных не сработали, но в механизме их надо закрыть):

- Многострочная связь заполняет строки до нормы **одного** дома и делает это отдельно для каждого класса (F, S, P). Для склада проекта правильнее брать потребность всех оставшихся домов. На 30 м не повлияло: на складе P труб 110/3000 нет (`explore.txt`: P 0).
- `greedy` пропускает строки с q ≤ 0. В многострочной связи карточка с q = 0 и ненулевой суммой теряет сумму. Инвариант v6 сошёлся, значит таких случаев не было.
- `ASM` считает компоненты, собранные в KIT на доме, «списанными», даже если сам KIT ещё не списан. На №1 KIT списан целиком, поэтому на этих данных это верно.
- Цена комплекта по цене СС раскладывается на детали пропорционально последним ценам деталей (§5.4).
- В «как сейчас» ОН сравнивается по нормализованному имени (`K()`), в отчёте — по ссылке.
- Сигнатура размера на 30 м не автоматизирована (§5.3).
