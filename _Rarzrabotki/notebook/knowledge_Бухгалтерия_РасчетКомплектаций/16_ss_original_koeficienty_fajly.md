# 16. СС: оригинал по модулям, коэффициенты пересчёта единиц, файлы-основания

Сделано 2026-09-27 (BuhBud `bas_industrialbud`). Спека/план: `docs/superpowers/{specs,plans}/2026-09-27-ss-original-koeficienty-fajly*.md`.

## Модель данных `Справочник.СтруктураСебестоимости`

| Слой | Где | Что хранит | Кто меняет |
|---|---|---|---|
| Файл | `СтруктураСебестоимостиПрисоединенныеФайлы` (БСП) + ТЧ `ФайлыОснования` {Модуль, Файл, ДатаЗагрузки, КоличествоСтрок, СуммаИтого} | исходный xlsx; **Модуль 0 = файл на всю СС** | кнопка загрузки / скрипт |
| Оригинал | ТЧ `КомплектующиеПоМодульно` | строки листа «Проект СС» как в Excel (единицы, количества, суммы), `НеСовпадает` = единица оригинала ≠ единица общего названия | только загрузка модуля |
| Коэффициенты | ТЧ `КоэффициентыПересчета` {Этап, ОН, НоменклатураСС, ЕдиницаСС, КоличествоОригинал, ЕдиницаЗакупки, Коэффициент(15,9), ИсточникКоэффициента, КоличествоПересчитанное} | k на позицию оригинала с несовпадающими единицами | «Заповнити», ручная правка |
| Рабочий | ТЧ `Комплектующие` (+`ДобавленоВручную`) | количества в единицах закупки; **Сумма не меняется никогда** | «Перерахувати кількість», бухгалтер |

Правила по умолчанию — ТЧ `ОбщиеНазванияНоменклатуры.КоэффициентыПересчета` {ЕдиницаСС, НоменклатураСС, Коэффициент, Комментарий}:
`ЕдиницаСС × k = ОбщиеНазванияНоменклатуры.Единица`; пустая НоменклатураСС — правило на всё название.
Уникальность пары (нормализованные единица+наименование) — `ОбработкаПроверкиЗаполнения` карточки.

## Ключи (главное знание)

- **Позиция = Этап + НоменклатураСС (нормализованное, НРег).** Общее название в ключ НЕ входит: бухгалтер
  переназначает его в Комплектующие (IRC 15 м — 54 из 168 позиций, IRC 30 м — 68 из 170). Единица не входит:
  после пересчёта ЕдиницаСС строки Комплектующие = единица закупки.
- Коэффициент строки = позиция + единица оригинала (`КлючЕдиницы`: синонимы м.п./п.м → пог.м, м.кв./м² → м2 …).
- «Додано вручну» = НоменклатураСС строки Комплектующие нет в оригинале (этап не учитывается). Ставит
  `ПередЗаписью`; если оригинала нет вовсе — не трогает (Вооз, МХП, ПРООН).
- Ссылки оригинала (ОН, Номенклатура, Единица) берутся из строки Комплектующие той же позиции
  (`ПривестиСсылкиОригиналаККомплектующим`), иначе — как разрешил движок по «узагальненій назві» файла.

## Поиск коэффициента (`НайтиКоэффициент`)
точное правило (ед+номенклатура) → общее правило (ед) → единицы совпадают (1) → «Не знайдено» (0, строка не пересчитывается).
Источники «Вручну» и «Підібрано за фактом» кнопкой «Заповнити» не перезаписываются.

## Пересчёт (`ПересчитатьКоличество(Объект, НомерСтрокиКоэф = 0)`)
Кол-во = Окр(КоличествоОригинал × k, 3); несколько строк одной позиции — распределение по
КоличествоСС_Оригинал → Количество → Сумма → поровну (остаток округления — последней). Контроль Σ Сумма
до=после, иначе ТЧ восстанавливается.

**Позиция в двух единицах (доработка 2026-09-30).** Одна НоменклатураСС может прийти из разных модулей в
разных единицах (МД ООН Админ: «IZOVAT 100; стіни» — модуль 1 7,733 м3, модуль 3 66,6 м2) → две строки
коэффициента. Раньше позиция целиком уходила в «неоднозначно» и не пересчитывалась даже с ручным k.
Теперь `ГруппыПоЕдиницам` разводит строки Комплектующие по `КлючЕдиницы(ЕдиницаСС_Оригинал)` → каждая
строка коэффициента пересчитывает только «свои» строки. «Неоднозначно» остаётся, только если строку нельзя
отнести к единице (пустая/чужая ЕдиницаСС_Оригинал) или единице не досталось ни одной строки (строки
слиты вручную) — в протоколе причина и № строки. k=0 у одной единицы пропускает только её группу.
То же разведение — в `ПодобратьКоэффициентыПоФакту`.

**Кнопка «Перерахувати рядок»** (страница «Перерахунок», команда `ПересчитатьСтроку`): активная строка
КоэффициентыПересчета → `ПересчитатьКоличество(Объект, НомерСтроки)` — меняются только строки Комплектующие
этой позиции+единицы; протокол «<позиция>, м3: 7,733 × 1,637931034 = 12,666 пак → рядки № 34». Без
выбранной строки / при k ≤ 0 — предупреждение, ничего не меняется. Объект не записывается.

Приёмка `test/test_ss_pereraschet_po_edinicam.py` (без записи): одна строка м3/м2 меняет ровно одну строку
Комплектующих, Σ Сумма неизменна, k=0 — без изменений, полный пересчёт по сохранённым k не меняет ни одного
количества в 4 СС (И3 сохранён).

## Код
- Общий модуль `А_СтруктураСебестоимостиСервер` (Server + ExternalConnection): вся логика + нормализация/синонимы
  единиц (модуль объекта СС делегирует `НормализоватьНаименование`/`СинонимЕдиницы`).
- Модуль объекта СС: движок загрузки параметризован приёмником (`ЗаполнитьТЧПоСтрокам(ТЧ, …, Модуль)`), новый
  экспорт `ЗаполнитьОригиналИзСырыхСтрок(Сырые, Модуль)` — Комплектующие не трогает. Старые экспорты
  (`ОтобратьМатериалы`, `ЗаполнитьКомплектующиеИзСырыхСтрок`, `НормализоватьНаименование`) — сигнатуры прежние.
- Форма СС: кнопка «Файли» (CommonCommand.ПрисоединенныеФайлы), страница «Перерахунок» (3 команды), мини-таблица
  «Файли підстави», колонка «Додано вручну» + условное оформление кодом. «Завантажити з Exel»: модуль → запись
  новой СС → оригинал модуля → (вопрос) перестроить Комплектующие из оригинала всех модулей → присоединить файл.

## Грабли
- **Движок загрузки фиксирует свою транзакцию** (get-or-create этапов и общих названий). «Сухой прогон» без
  внешней транзакции создаёт карточки в базе: первый прогон создал 9 ОН (коды 469–477), помечены на удаление.
  Любой пробный вызов — во внешней `НачатьТранзакцию/ОтменитьТранзакцию`.
- meta-edit пишет тип ссылки на новый объект как `xmlns:d5p1 … d5p1:CatalogRef.X` — грузится, но канон
  (контрольная выгрузка) другой; после загрузки принимать выгрузку.
- Частичная выгрузка формы работает путём `Справочник.X.Форма.Y`.
