# Производственное бюджетирование ETO/MTO-производителя: материалы по BOM, закупки с lead time и предоплатой, прямой труд, накладные → бюджет ДДС

Контекст применения: ООО «Індастріалбуд» — модульные дома (МД: карта себестоимости = BOM материалов 0,7–1,6 млн грн с НДС на дом + работы в чел/час, частично наличными по Форме 2 через финагента +15% + прочие работы + накладные на дом: транспорт ~52 тыс., аренда крана/экскаватора, проживание и проезд монтажников) и металлоконструкции (МК: ставки на тонну — труд 7 649, МШП 4 125, логистика 1 736, услуги 1 453 грн/т при цене 32 900 грн/т). Цель — помесячный бюджет ДДС по проектам на октябрь–декабрь 2026. Обозначения в формулах: `p` — проект, `t` — месяц, `S_p(t)` — отгрузка (домов или тонн) в месяце `t`, `k` — сдвиг в месяцах «до отгрузки» (k>0 — раньше отгрузки, k<0 — позже).

## 1. Как получить выплаты за материалы из BOM × графика выпуска с lead time L и условиями поставщиков; как откалибровать L и долю предоплаты по факту ДДС против отгрузок

### Takeaway
Классическая цепочка — план выпуска → потребность (BOM × объём) → закупки = потребность + целевой конечный запас − начальный запас, сдвинутые влево на lead time (MRP offset) → платежи по схеме «доля при заказе (предоплата) + остаток при поставке/с отсрочкой» + отдельный график погашения уже существующей КЗ. Для проектного производства с проектными закупками практичнее сразу задать «ядро оплат» φ_k — долю BOM дома, оплачиваемую за k месяцев до отгрузки, — и калибровать его по факту денег (проект × статья × месяц с 01.2026) против месяцев отгрузки; бюджет Q4 строить как «остаток к оплате по проекту», разнесённый ядром только на будущие месяцы (так автоматически учитываются уже оплаченное и КЗ, без двойного счёта).

### Cited Findings
- Базовая формула бюджета закупок материалов: материалы на производство + плановый конечный запас = общая потребность; минус начальный запас = объём к закупке. — [AccountingTools: Material budgeting](https://www.accountingtools.com/articles/material-budgeting-direct-materials-budget); то же в виде «закупка в ед. = потребление + желаемый конечный запас − начальный запас» — [eFinanceManagement: Direct Materials Budget](https://efinancemanagement.com/budgeting/direct-materials-budget)

### Inferences
**1.1. Классическая цепочка, переписанная помесячно (реализуемо в pandas/numpy).**
```
Q_p(t)      = Σ_j w_j · S_p(t + j)                 # выпуск в цехе: профиль цикла w_j (доля работ за j мес. до отгрузки)
U_p(t)      = Σ_i BOMqty_i,p · Q_p(t)              # потребление материалов (ед./грн по норме СС)
EndInv(t)   = SS_fix + c · U(t+1)                  # политика запаса: страховой + c% следующего месяца (для общих материалов)
Receipt(t)  = U(t) + EndInv(t) − EndInv(t−1)       # поступление на склад
Order(t)    = Receipt(t + L)                       # MRP offset: заказ за L мес. до поступления
Pay(t)      = α · Order(t)                         # предоплата при заказе
            + (1−α) · Receipt(t − c)               # остаток через c мес. после поставки (c=0 — оплата по факту)
            + PayoffAP0(t)                         # погашение входящей КЗ (только по позициям, НЕ включённым в "остаток к оплате", см. 1.3)
```
Для проектных (уникальных) материалов МД страховой запас ≈ 0 и `EndInv` фактически = «материалы, закупленные под дома следующих месяцев». Для общих позиций (металлопрокат, крепёж, утеплитель, МШП) имеет смысл правило «покрытие c% потребности следующего месяца» по образцу AccountingTools.

**1.2. Компактная форма для ETO — «ядро оплат относительно отгрузки».** Всю цепочку w_j → L → α → c можно свернуть в одно ядро φ_k:
```
M_p(t)     = BOM_p(грн с НДС) · S_p(t)                  # «материальная стоимость» отгрузок месяца t
PayMat_p(t)= Σ_k φ_k · M_p(t + k),   Σ_k φ_k = 1
# связь с параметрами: если заказ за L мес. до отгрузки с предоплатой α, остаток — при поставке за d мес. до отгрузки
# с отсрочкой c, то φ_L = α, φ_(d−c) = 1−α. Средний «опережающий лаг» оплат: L̄ = Σ_k k·φ_k
```
Ядро можно сделать разным для групп материалов (длинный lead — металл/окна/сэндвич-панели; короткий — расходники), если статьи ДДС или номенклатура это позволяют. Ядро свёртывается с профилем цеха: `φ = conv(w, ядро_закупки)` (`numpy.convolve`).

**1.3. Как строить бюджет Q4 без двойного счёта уже оплаченного и КЗ («остаток к оплате»).** Для каждого проекта:
```
Need_p      = K_p · BOM_p · N_p_total                     # полная потребность материалов проекта (K_p — коэфф. коррекции нормы, см. п.4)
Paid_p      = Σ_{t ≤ сен.2026} CashMat_p(t)               # факт денег по статьям материалов (вкл. 2025, если есть)
Remain_p    = max(0, Need_p − Paid_p)                     # остаток к оплате; КЗ поставщикам по проекту уже ВНУТРИ Remain_p
Profile_p(t)= Σ_k φ_k · M_p(t + k)  только для t ≥ окт.2026, нормированный на 1
PayMat_p(t) = Remain_p · Profile_p(t)
# ограничение снизу: в октябре оплатить не меньше просроченной КЗ по проекту (AP0_overdue_p)
```
Ключевые следствия: (а) горизонт отгрузок должен выходить за декабрь на max(k) месяцев — при L = 2–3 нужен план отгрузок на январь–март 2027 (иначе декабрь будет занижен на авансы под дома 1 кв. 2027); (б) существующую КЗ поставщикам нельзя прибавлять поверх Remain_p — она уже является частью «неоплаченной потребности»; отдельно (через `PayoffAP0`) гасится только КЗ по непроектным/общим закупкам; (в) если `Paid_p > Need_p` — либо норма занижена (поднять K_p), либо деньги проекта пошли на склад/другие проекты.

**1.4. Калибровка L и доли предоплаты по факту ДДС (данных с 01.2026 мало — 9 месяцев, поэтому от простого к сложному):**
1. *Метод центров масс (робастный, 1 число на проект).* Для проектов, у которых материальные платежи и отгрузки целиком попали в окно данных: `L̄_p = (Σ_t t·S_p(t)·BOM_p)/(Σ S_p·BOM_p) − (Σ_t t·CashMat_p(t))/(Σ CashMat_p)`. Взвешенное среднее по проектам — оценка L̄. Покрытие `Cov_p = Σ CashMat_p / (BOM_p·Σ S_p)` показывает, сходится ли BOM с реальными деньгами (≈1 — норма адекватна).
2. *Деконволюция NNLS (пул проектов).* Строки — (p, t) с t ∈ [01.2026; 09.2026], столбцы — k ∈ [−2; 6]: `X[(p,t),k] = BOM_p·S_p(t+k)`, `y = CashMat_p(t)`; `φ̂ = scipy.optimize.nnls(X, y)`. Для k>0 в регрессоры попадают будущие отгрузки — берём их из плана (это и есть авансы под будущие дома). Для k<0 нужны отгрузки 2025. `Σφ̂` = покрытие; при мультиколлинеарности (ровный план отгрузок) сократить число лагов или наложить гладкость (ridge по разностям φ_k). Число лагов держать малым — см. предупреждение Wooldridge.
3. *Доля предоплаты α напрямую.* Если в ERP платежи разделены на «предоплата» и «погашение долга» (в архитектуре взаиморасчётов BAS ERP это разрезы расчётов по срокам; конкретный регистр по поставщикам проверить по метаданным) — `α = Σ предоплат / Σ оплат поставщикам материалов` по проекту/группе. Альтернатива — по документам: доля оплат, у которых дата платежа < даты поступления товаров (метод «сопоставления счёт–платёж» из патента US 10489865).
4. *Отсрочка c и DPO по общим закупкам:* `DPO = КЗ_ср / Закупки_за_период × дни`; помесячно — доля начальной КЗ, погашенной в месяце `ρ = Оплата_по_КЗ(t)/КЗ(t−1)` → `PayoffAP0(t) = ρ·КЗ(t−1)`.
5. *Тождество-проверка (обязательно):* `Закупки(t) = Оплаты(t) + ΔКЗ(t) − ΔАвансы_выданные(t)`. Если по проекту деньги не объясняются BOM × отгрузками, расхождение должно быть видно в ΔКЗ/ΔАвансах или в переносах остатков (например, материалы со склада, закупленные до 2026).

**1.5. Специфика инфляции/военного положения.** При ~10% годовой инфляции (≈0,8% в месяц, (1,10)^(1/12)−1) заказ за L месяцев фиксирует цену раньше — предоплата защищает от удорожания; но альтернативная стоимость денег при учётной ставке 15,5% ≈ 1,3% в месяц выше инфляционного выигрыша. Значит, предоплата оправдана, когда поставщик даёт скидку/фиксирует цену, или для дефицитных long-lead позиций (риск срыва отгрузки дороже процентов); в бюджете цену материалов, оплачиваемых через L месяцев, индексировать: `Price(t) = Price_СС · (1+π_m)^(t − t_СС)`. Если заказчик проекта — бюджетный (программы жилья для ВПЛ и т.п.), его аванс ограничен 30% годового объёма и должен быть «освоен» на материалы за 3 месяца (Постанова 1070) — это задаёт естественный верхний предел L ≤ 3 для материалов, финансируемых таким авансом.

## 2. Прямой труд: нормы чел/час против факта, календарь выплат (аванс/зарплата, месячный лаг), сдельщина в цехах

### Takeaway
Бюджет прямого труда = Σ (норма часов на единицу × объём выпуска) × часовая ставка; при сдельщине — Σ (расценка × объём), где расценка = часовая ставка × норма времени. Начисление привязывается к месяцу выполнения работ (а не отгрузки), затем на него накладывается календарь выплат: официальная часть — по ст. 115 КЗпП (первая половина месяца до 22-го числа текущего, вторая — до 7-го следующего) плюс налоги; наличная часть по Форме 2 через финагента — отдельный канал «нетто × 1,15» со своим лагом, откалиброванным по факту Казны.

### Cited Findings
- Нормативные часы на фактический выпуск (standard hours allowed) и отклонение по производительности: `LEV = (SH − AH) × SR` (или наоборот по знаку) — сравнение фактических и нормативных часов на фактический выпуск. — [Lumen: Calculations for Direct Materials and Labor](https://courses.lumenlearning.com/suny-managacct/chapter/calculations-for-direct-materials-and-labor/); [Beancount: Standard costing and variance analysis (2026)](https://beancount.io/blog/2026/05/17/standard-costing-variance-analysis-manufacturers-material-price-quantity-labor-rate-efficiency-overhead-variances-guide)

**2.1. Начисление по нормам (МД) и по тоннажу (МК).**

```
H_p(t)     = Σ_j w_j · S_p(t + j) · Norm_h_p          # Norm_h_p — чел/час на дом из карты СС; w_j — профиль цикла цеха

# сдельщина в цехе (факт → прогноз): Accr(t) = Σ_работы Qty_j(t) · Расценка_j, Расценка_j = Ставка_разряда · НормаВремени_j
# МК: Accr_MK(t) = Tonnes(t) · 7 649 грн/т  (труд ≈ 23% цены 32 900 грн/т)
```
Профиль w_j (когда в цехе реально делается дом относительно отгрузки) калибруется по документам выполнения работ цеха (по модулям/домам) против дат отгрузки; монтажные работы на объекте идут ПОСЛЕ отгрузки (k<0) и требуют своего профиля.

**2.2. Перевод начисления в деньги (ядро выплат λ).**
```
# официальная часть: доля a — за первую половину месяца (выплата в том же месяце, до 22-го), 1−a — до 7-го следующего
NetOff(t)  = Accr_off(t) · (1 − 0.18 − 0.05)

           + (0.18+0.05)·[a·Accr_off(t) + (1−a)·Accr_off(t−1)]     # ПДФО+ВЗ уплачиваются вместе с выплатой
           + 0.22·Accr_off(t−1)                                    # ЕСВ: срок уплаты проверить (см. Gaps), допущение — следующий месяц
# Форма 2 (наличные через финагента): своё ядро ψ_k по факту Казны
CashF2(t)  = 1.15 · Σ_k ψ_k · NetF2(t − k)
# полное ядро труда относительно отгрузки: κ = conv(w, λ)  → CashLab_p(t) = Σ_k κ_k · LaborStd_p · S_p(t + k)
```
Долю a (часть заработка, выплачиваемая в месяце начисления) и ядро ψ_k для Ф2 оценивать по факту: `a ≈ Σ выплат за месяц t в месяце t / Σ начислений месяца t`; для Ф2 — сопоставлением месяца «заработано» (табель/акт цеха) и месяца выплаты по карточкам Казны.

**2.3. Нормы против факта.** Отклонение по производительности считать по завершённым домам: `SH = Norm_h × домов_изготовлено`, `AH` — фактические часы из табеля/актов цеха; `E = SH/AH`. Отклонение по ставке `(AR − SR)·AH` в 2026 будет систематически отрицательным (дорожает труд: реальный рост >12% плюс инфляция ~10% — грубо более +20% номинально г/г) — это «плановое» отклонение, норму ставки нужно индексировать, а не ждать «экономии». Дополнительно — проверка мощности: `H(t) ≤ Численность(t) × Часы_мес × E`; если плановый выпуск превышает мощность, сдвигать отгрузки (и все деньги, привязанные к ним ядрами), а не только труд.

## 3. Накладные: разделение постоянных и переменных, гибкий бюджет, затраты «на отгрузку» (логистика, монтажники: проезд и проживание)

### Takeaway
Каждую статью накладных привязать к драйверу: на тонну (МК), на отгруженный дом (транспорт), на смонтированный дом/бригадо-день (кран/экскаватор, проживание, командировочные), на месяц (постоянные). ### Cited Findings
- Построение гибкого бюджета: выделить постоянные затраты; определить, как переменные меняются с драйвером активности; зафиксировать постоянные, переменные задать на единицу/в %; подставить фактическую активность после периода. ## 4. Нормативный метод и анализ отклонений для корректировки норм при калибровке бюджета: когда доверять норме, а когда истории

### Takeaway
Отклонения раскладываются на цену и расход (материалы), ставку и производительность (труд), расходы и эффективность (переменные ОПР), расходы (постоянные ОПР). Устойчивые однонаправленные отклонения — «плановые» (устаревшая норма: инфляция, смена конструктива, поставщика) и требуют пересмотра нормы; случайные «операционные» — норму не трогают. Для ETO: количественная структура BOM (что и сколько) — доверять норме, особенно для новых/изменённых проектов; тайминг (лаги, предоплата), цены (с индексацией) и систематические коэффициенты перерасхода — доверять истории.

### Cited Findings
- Отклонение по цене материалов = (факт. цена − норм. цена) × фактическое закупленное количество; отклонение по расходу = (факт. кол-во − норм. кол-во на фактический выпуск) × норм. цена; расходное отклонение не содержит ценового эффекта. — [AccountingCoach: Standard costing](https://www.accountingcoach.com/standard-costing/explanation)
- Общее отклонение по материалам = ценовое + по расходу. — [eFinanceManagement: Material variance](https://efinancemanagement.com/budgeting/material-variance)
- Отклонение по производительности труда = (нормативные часы на факт. выпуск − факт. часы) × нормативная ставка. — [Lumen: Calculations for Direct Materials and Labor](https://courses.lumenlearning.com/suny-managacct/chapter/calculations-for-direct-materials-and-labor/)
- Достижимые (attainable) нормы учитывают нормальные потери, простои и усталость — считаются наиболее полезными для мотивации и оценки; базовые (basic) нормы не меняются долго и годятся лишь для анализа трендов, но не для текущего контроля. — [PastPaperHero: ACCA PM — types of standards](https://www.pastpaperhero.com/resources/acca-pm-setting-standards-and-flexing-types-of-standards-and-attainable-benchmarks)
- Разделение на плановые и операционные отклонения: плановое = (исходная норма − пересмотренная норма) × факт. объём/количество — неконтролируемая часть из-за нереалистичной/устаревшей нормы; операционное = (пересмотренная норма − факт) × тот же объём — контролируемая часть. Если плановые отклонения стабильно велики — пересматривать порядок установления норм (скользящие бюджеты, более частый пересмотр). — [PastPaperHero: ACCA PM — planning vs operational variances](https://www.pastpaperhero.com/resources/acca-pm-advanced-variances-and-reconciliation-mix-and-yield-planning-vs-operational-variances)
- Отклонения по ОПР: переменные — по расходам (ставка) и эффективности (база распределения), постоянные — по расходам. — [AccountingTools: Overhead variances](https://www.accountingtools.com/articles/overhead-variances)
- Внешний фон для «плановых» отклонений в 2026: инфляция ~10%, ускоренный рост затрат на оплату труда (НБУ); новые правила определения текущих цен ресурсов в строительных сметах в условиях военного положения (Постанова 1512). — [DTKT: звіт НБУ](https://news.dtkt.ua/finance/banks/113606-infliaciia-prisvidsitsia-do-10-u-2026-roci-ale-povernetsia-do-cili-5-u-2028-zvit-nbu); [Mediaresource: Постанова 1512](https://mediaresource-pz.com.ua/osnovni-zminy-scho-vplyvayut-na-diyalnist-zamovnykiv-pid-chas-vyznachennya-vartosti-budivnytstva-v-umovah-voennoho-stanu/)

### Inferences
**4.1. Коэффициенты коррекции норм по завершённым домам/партиям (Python).**
```
# Материалы (нужны количества: списание на производство по проекту vs BOM карты СС)
K_usage  = Σ(AQ·SP) / Σ(SQ·SP)           # >1 — перерасход количества против BOM
K_price  = Σ(AQ·AP) / Σ(AQ·SP)           # >1 — цены выше норм СС (инфляция/смена поставщика)
K_mat    = K_usage · K_price = Σ(AQ·AP)/Σ(SQ·SP)
# Если количеств нет — только суммарный K_mat = Факт материалов (грн) / (BOM_p · домов) — но это смешивает цену и расход
# Труд
E        = SH / AH ;  K_rate = AR / SR ;  K_lab = K_rate / E
# Ценовую часть разложить на «плановую» (индекс рынка) и «операционную» (закупочная работа):
PlanVar  = (SP_old − SP_rev)·AQ,  SP_rev = SP_old·Idx(t_покупки)/Idx(t_СС)
OpVar    = (SP_rev − AP)·AQ
```
**4.2. Правило «норма или история» (эвристика, не из источников).**
- Новый тип дома/изменённый конструктив/< 3 завершённых домов → норма СС (BOM, чел/час) с ценовой индексацией; история не репрезентативна.
- ≥ 3 завершённых домов одного типа и отклонение одного знака подряд → «плановое» → пересмотреть норму (умножить на K). Можно смешивать: `K_прим = Z·K_ист + (1−Z)·1`, `Z = n/(n + n0)` (n — число завершённых домов, n0 ≈ 3–5) — взвешивание достоверности, чтобы один «странный» дом не переворачивал бюджет.
- Тайминг (L, α, лаги зарплаты/Ф2, оплата перевозчиков) — только по истории: в норме СС его нет.
- Перед доверием истории проверить, что «перерасход» не является артефактом учёта: материалы на склад/другие проекты, переносы остатков, двойные статьи, оплаты КЗ прошлых периодов. Тождество `Закупки = Оплаты + ΔКЗ − ΔАвансы` и покрытие `Cov_p` (п.1.4) — фильтр перед расчётом K.
- Для бюджета ДДС отклонение по цене важнее, чем по расходу: деньги платятся по цене момента заказа (t − L), поэтому индексировать от даты СС до даты платежа, а не до отгрузки.

### Gaps
- Специальных источников по калибровке норм именно в ETO (единичные/малосерийные изделия, мало наблюдений) в этом проходе не найдено; правило «Z = n/(n+n0)» — вывод по аналогии с методами взвешивания достоверности, а не цитируемая практика.
- Не проверено, есть ли в данных клиента фактическое количество материалов по дому (а не только суммы) — без этого цена и расход не разделяются.

## 5. Какие 3–5 приёмов принять и с какими данными

### Takeaway
Рекомендуется пять приёмов: (1) ядро оплат материалов относительно отгрузки (MRP-смещение L + доля предоплаты α), откалиброванное по факту ДДС, и расчёт Q4 как «остаток к оплате по проекту»; (2) роллфорвард КЗ/авансов выданных как контрольное тождество и график погашения непроектной КЗ; (3) трудовой бюджет по нормам/расценкам с привязкой к месяцу выполнения работ и календарём выплат (ст. 115 КЗпП + налоги + отдельное ядро Формы 2 × 1,15); (4) драйверная матрица накладных и гибкий бюджет (тонна / дом отгружен / дом смонтирован / бригадо-сутки / месяц); (5) коэффициенты коррекции норм с разделением плановых (инфляция, конструктив) и операционных отклонений и ценовой индексацией до месяца платежа.

**Порядок внедрения (минимальный путь к бюджету Q4).**
1. Собрать «куб» `проект × месяц`: отгрузки (факт 2025–09.2026 + план 10.2026–03.2027), BOM/нормы из СС, факт ДДС по статьям (материалы / труд офиц. / Ф2 / транспорт / техника / жильё / проезд / прочее), КЗ и авансы на 30.09.2026.
2. Приём 2 как фильтр качества: тождество закупок и покрытие `Cov_p` — исключить проекты с явными артефактами (переносы остатков, оплаты не по проекту).
3. Приём 1: L̄ и α центрами масс на «чистых» проектах; при достаточном числе проектов — NNLS-ядро φ_k (k ∈ [−1; 4]).
4. Приём 5: K по завершённым домам → `Remain_p`.
5. Приёмы 3 и 4: профили w_j (цех), λ/ψ (выплаты), θ (накладные) → помесячный ДДС окт.–дек. 2026 по проектам; сверка: сумма по проекту за весь горизонт = остаток к оплате по каждой статье.
6. Чувствительность: L ± 1 мес., α ± 20 п.п., сдвиг отгрузок на +1 мес. — показывает, сколько денег «переезжает» между декабрём и январём.

**Ключевые риски модели.** Мало истории (9 месяцев, немного домов) → предпочитать грубые, но устойчивые оценки (центры масс, одно ядро на группу) вместо многопараметрических; горизонт плана отгрузок короче L недооценивает декабрь; добавление КЗ поверх «остатка к оплате» даёт двойной счёт; индексация цены до отгрузки вместо даты платежа искажает сумму при высокой инфляции.

### Gaps
- Нет внешней валидации, что ядровой подход (φ_k относительно отгрузки) даёт лучшую точность, чем классическая цепочка «закупки → AP-график» именно для ETO; это вывод на основе MRP-логики и практики моделирования лагов оплат.
- Без доступа к данным клиента невозможно сказать, хватит ли числа завершённых домов для NNLS-оценки ядра; минимум наблюдений — открытый вопрос, решать по устойчивости оценок (бутстрэп по проектам).
