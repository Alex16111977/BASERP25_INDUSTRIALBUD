# LESSONS — грабли доработки (14.10.2026)

1. **Worktree отстаёт от основного каталога.** Код ОУМП (`А_ПартнерРасчетов`, касса, объекты расчётов) жил только в
   незакоммиченном main. Перед правкой — `cp` main → worktree и отдельный коммит, иначе копирование обратно откатит
   живой код.
2. **Новое перечисление = загрузка `Configuration.xml`.** Сначала гейт `erp_preflight_config.py` с `EXPECTED_NEW`.
   Частичная загрузка неполного `Configuration.xml` удаляет объекты из базы вместе с данными.
3. **`db-update` при открытом тонком клиенте падает** («Ошибка исключительной блокировки»). Не повторять в цикле —
   попросить пользователя закрыть клиент.
4. **У `ДоговорыКонтрагентов` и `Контрагенты` нет поля `Код`.** Запрос с `УПОРЯДОЧИТЬ ПО Дог.Код` падает. Это поймал
   Python-тест до загрузки. Сортировка: `Дата, Наименование` / `Ссылка`.
5. **`НайтиПоНаименованию("Финансовая помощь")` возвращает группу** (УТ-001143), а не статью (УТ-001144). В тестах и
   скриптах статьи искать по коду или запросом с `НЕ ЭтоГруппа`.
6. **`НайтиПоНаименованию` регистронезависим:** «ВОРОНЦОВ …» находит «Воронцов …».
7. **COM-ссылки в Python нельзя сравнивать `==`** — это разные обёртки. Сравнивать
   `erp.String(ref.УникальныйИдентификатор())`.
8. **Алиас `И` в запросе зарезервирован** («Ожидается имя»). Использовать `Изм`, `Дог`, `Контр`.
9. **Партнёр стороны — из договора, не из контрагента.** У карточки «Воронцов Олександр Володимирович» два партнёра,
   один из них с хвостовым пробелом.
10. ~~Боевые платёжки через COM не проводить~~ — **опровергнуто 15.10.2026:** `СоздатьОплатыНаСервере()` через COM
    создаёт `РегистраторРасчетов` и записи «ПоСрокам». 16.10.2026 так же перенесены 13 ОУМП на договоры пар.
11. **Реквизит, добавленный пользователем в Конфигураторе, есть только в базе.** Перед правкой объекта —
    `db-dump-xml -Mode Partial -Objects "Документ.…"`, иначе загрузка из файлов его удалит. Конфигуратор должен быть
    закрыт (иначе «Ошибка блокировки… для конфигурирования»).
12. **После загрузки платформа переписывает XML в свой формат** (`<Comment />` → `<Comment/>`, `UTF-8`). Main
    отличается от git «по форме», а не по содержанию — сверять смыслом, а не побайтно.
13. **Сначала понять, кто заёмщик.** В первой версии на приход тоже ставился Воронцов. Пользователь: кредитор —
    Воронцов, заёмщик — контрагент подразделения (как плательщик во входящей платёжке).

## 16.10.2026 — договоры пар «ЦО → заёмщик»

14. **Ключ поиска кредитного договора должен различать пары.** Без получателя в ключе все выдачи ЦО ложились на один
    договор Воронцова, и из оборотки не было видно заёмщика. Получатель — `А_ПодразделениеОказаниеУслугПодразделению`,
    заполняется только у стороны кредитора; пустой получатель → `ПустаяСсылка` в параметре (не `Неопределено`).
15. **Прежний подбор тоже может подхватить договор пары.** Документ без «Кредитование» с кредиторской статьёй: партнёр
    берётся из `А_ПартнерРасчетов` (Воронцов), и запрос договора поставщика (`Подразделение` = ЦО, получатель = приход)
    найдёт «Кредит: ЦО → X». Это правильный договор, но помнить: обычный путь не «изолирован» от кредитных договоров.
16. **«Создать оплаты» по ОУМП с наличной строкой помечает на удаление ВСЕ кассовые ордера документа** (у ордеров нет
    кода строки). Только безнал → убрать наличные строки в памяти и не записывать документ (`--beznal-only`), плюс
    проверка, что непомеченных РКО/ПКО у документа нет.
17. **`--dry` создаёт недостающие договоры** — `А_КредитнаяСторона` ищет-или-создаёт. Договоры пар появились на сухом
    прогоне; на результат это не влияет (кнопка создала бы те же).
18. **Перенос на новый договор не меняет итог** — регистратор расчётов старого договора пересчитывается при проведении
    платёжки на новом. Контроль после первого документа: сумма остатков старого и новых договоров = 7 000 370,10.
19. **Частичная выгрузка справочника (`db-dump-xml -Mode Partial -Objects "Справочник.X"`) не выгружает формы** —
    только XML объекта, модули и команды. Для правки формы выгружать форму отдельно.
20. **Авто-режим может запретить пакетную запись в рабочую базу** даже при разрешении на один документ. Не обходить:
    остановиться, описать, что сделано и что осталось, и спросить пользователя.
