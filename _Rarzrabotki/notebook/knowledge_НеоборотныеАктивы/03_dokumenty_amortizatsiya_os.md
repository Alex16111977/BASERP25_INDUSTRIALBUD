## ★ КОРНЕВАЯ ПРИЧИНА: задвоение в РН.ПрочиеРасходы — ИСПРАВЛЕНА

При проведении документа АмортизацияОС (2.1) формируется **2 строки амортизации на 1 ОС** в РН.ПрочиеРасходы.

### Пример: Гайковерт BOSCH 18B (Глобино-2)

```
СТРОКА #1 «БОБА» (бух/нал):
  Период            = 31.03.2026 23:59:59
  Подразделение     = Глобино-2
  СтатьяРасходов    = Амортизація ОЗ
  НалоговоеНазнач.  = Обл. НДС
  Аналитика         = Гайковерт BOSCH 18B GDS 18V-1050 H 2*5Ah
  Сумма             = 22 806,29   ← стоимость БЕЗ НДС ÷ СПИ (1 мес) = 100%
  СуммаУпр          = 22 806,29   ← такая же (БОБА строка единая для всех учётов)
  СуммаРегл         = 22 806,29   ← такая же
  СуммаБезНДС       = 0           ← (не заполнено)

СТРОКА #2 «УПР» (управ):
  Период            = 31.03.2026 23:59:59
  Подразделение     = Глобино-2
  СтатьяРасходов    = Амортизація ОЗ
  Аналитика         = Гайковерт BOSCH 18B GDS 18V-1050 H 2*5Ah
  Сумма             = 27 367,55   ← стоимость С НДС = 22 806,29 × 1,20
  СуммаУпр          = 27 367,55   ← заполнено
  СуммаРегл         = 0           ← пусто ← маркер «только управ»
```

### Откуда берётся УПР строка

`Python/test/05b_drill_os_params.py` показал по 3-м ОС:

| ОС | СПИ_БУ | СтоимостьДляВычисл_БУ | × 1,20 | УПР строка |
|---|---:|---:|---:|---:|
| Гайковерт BOSCH | 1 мес | 22 806,29 | 27 367,55 | **27 367,55** ✓ |
| Вышка 1,2*2,0 (x2) | 1 мес | 20 416,67 | 24 500,00 | **24 500,00** ✓ |
| Фильтр ECOSOFT | 1 мес | 21 410,83 | 25 693,00 | **25 693,00** ✓ |

**Точное совпадение пропорции +20%** = НДС 20% Украины.

### Кто формирует УПР строку

В коде `Documents/АмортизацияОС/Ext/ObjectModule.bsl` логики формирования УПР строки **НЕТ**. Поиск ничего не показал.

Формирование происходит в **типовых модулях** редакции 2.1 BAS ERP, видимо:
- `УчетОСВызовСервера.НачисленнаяАмортизация(...)` — общий модуль (тип. 1С)
- `ВнеоборотныеАктивыЛокализация` — украинская локализация
- `ПроведениеДокументов.ОбработкаПроведенияДокумента(...)` — типовой механизм

**Логика типового кода (гипотеза):** для ОС с НДС в учёте, при проведении амортизации создаётся 2 строки в РН.ПрочиеРасходы:
- Бух/нал амортизация на сумму **без НДС** (потому что НДС возмещается)
- Управ амортизация на сумму **с НДС** (потому что в управ.учёте НДС не возмещается)

Цель — раздельный учёт. Но дальше:
- Штатная `Обработка.ДвиженияАктивовПассивов` (при закрытии месяца) суммирует обе строки → задвоение в Дт «Расходы текущего периода»
- Кастомная `А_СформироватьДвиженияАктивовПассивов` (наша доработка) берёт только Σ СуммаРегл → асимметрия с Кт ОС

## Связь с проблемами на других ОС

Объекты **БЕЗ задвоения** (в нашем 000Ц-000003): Чорноморськ Платформа роликова (× 4), Чорноморськ Ключ TOPTUL, Чорноморськ Електропила, МХП Краскопульт, АВРОРА Електропила. Для них одна строка БОБА с СуммаУпр=СуммаРегл, без УПР строки.

**Гипотеза:** эти ОС закуплены **без НДС** (либо НДС не отделён в учёте), поэтому типовой механизм НДС-добавки не сработал. Подтверждение требует проверки документов поступления.

**Следствие:** проблема **не системная** на уровне всех ОС, она зависит от налоговой настройки конкретного ОС. Это объясняет почему Δ = 102 060,55 только по 4 ОС из 24.
