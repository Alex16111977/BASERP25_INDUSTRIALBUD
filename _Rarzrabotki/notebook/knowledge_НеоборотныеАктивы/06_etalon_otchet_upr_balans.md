# 06. Эталон — Отчёт.УправленческийБаланс + УправленческийБалансКонтроль

## Два связанных отчёта

| Отчёт | Назначение | Источник данных |
|---|---|---|
| **УправленческийБаланс** | Сальдо по статьям активов/пассивов на конец периода (актив/пассив, плановый «нормальный» отчёт) | СКД, читает РН.А_ОтчетБаланс_Свод (через ОстаткиИОбороты) |
| **УправленческийБалансКонтроль** | Выявление асимметрии Дт ≠ Кт по документам-источникам (диагностический «контрольный» отчёт) | СКД, читает РН.А_ОтчетБаланс_Свод (с группировкой по `ДокументДвижения`) |

---

## Структура отчётов (метаданные)

```
Reports/УправленческийБаланс/Ext/
  ├── ManagerModule.bsl     ← вспомогательные функции (для подсистемы Варианты отчётов)
  ├── ObjectModule.bsl (220 строк) — обработчик ПриКомпоновкеРезультата, настройка параметров
  └── Templates/ОсновнаяСхемаКомпоновкиДанных/ (СКД YAML/XML)

Reports/УправленческийБалансКонтроль/Ext/
  └── ObjectModule.bsl (69 строк) — упрощённая компоновка
```

**Ни один из двух отчётов не содержит логики Свода** — они только читают уже посчитанный РН.А_ОтчетБаланс_Свод. Свод считается заранее **проведением документа `А_ФинРез_Баланс`** за нужный месяц/организацию (см. [02_formula_svod_pap_pryamoy.md](02_formula_svod_pap_pryamoy.md) и [knowledge_Balanse/balanse_pattern_and_roadmap.md]).

## Формула Контроля баланса (упрощённо)

```
ContrBalansa(Регистратор) = Σ(СуммаПриход для Регистратора) − Σ(СуммаРасход для Регистратора)
```

Где `Регистратор` для записи в РН.А_ОтчетБаланс_Свод — это `Документ.А_ФинРез_Баланс`. Но **отображается** в отчёте имя оригинального документа-источника через специальное поле `ДокументДвижения` (это нестандартное поведение, специфичное для этой кастомной архитектуры).

**Ключевой момент:** Контроль баланса группирует данные по **ДокументДвижения** (т.е. по реальному документу-источнику), а не по `Регистратор` (который для всех записей за месяц = одному А_ФинРез_Баланс).

**Это значит:** если документ Амортизация ОС положил Дт = 241 388 на статью «Расходы текущего периода», а Кт = 139 327 на статью «Основные средства», отчёт покажет:

```
Амортизация ОС (2.1) 000Ц-000003 ...   241 388,07    139 327,52    102 060,55
  Основные средства                                   139 327,52
  Расходы текущего периода             241 388,07
```

И **сумма ItemВ всегда = разница Дт/Кт по этому документу** — потому что один документ должен по идее давать симметричную проводку.

## Когда отчёт врёт (методологические нюансы)

### 1. Закрытие месяца не сделано
Если за исследуемый месяц нет проведённого `А_ФинРез_Баланс` → РН.А_ОтчетБаланс_Свод не содержит данных → Контроль баланса покажет 0 (это **техническое** 0, а не реальное «всё сошлось»).

### 2. Документ не вошёл в Свод
Если документ-источник проведён ПОСЛЕ проведения А_ФинРез_Баланс за тот же месяц — его движения не попадут в Свод до повторного проведения А_ФинРез_Баланс. Контроль баланса не покажет асимметрию пока пересвод не сделан.

**Митигация:** для повторного контроля — **сначала перепровести А_ФинРез_Баланс**, потом смотреть.

### 3. Перечисление статей-исключений
Свод_ПрочиеАктивыПассивы_Прямой исключает статьи через `НЕ Статья В ИЕРАРХИИ(&Искл)` (см. [02]). Список Исключённых сатей зашит в функции `ИсключенныеСтатьи()` модуля А_ФинРез_Баланс. Если документ работает с «исключённой» статьей — она не попадёт в Свод этой функции, а должна попасть в другой Свод_*.

**Митигация:** если возникает странное Δ — проверить, не попала ли статья в список исключений (например, для денежных статей это нормально, для статей зарплаты тоже).

## Что отчёт НЕ умеет (важно для нашего расследования)

- ❌ Не показывает разницу СуммаУпр / СуммаРегл в источнике РН.ПрочиеРасходы — это нужно смотреть руками через `02_compare_prochie_rashody_vs_pap.py`
- ❌ Не различает, какая часть проводки (Дт или Кт) пришла от кастомной А_-процедуры vs от штатной Обработки.ДвиженияАктивовПассивов
- ❌ Не подсказывает корневую причину — только показывает Δ

## Шаги при появлении нового Δ в Контроле баланса

1. Открыть Контроль баланса за период, скопировать **тип документа** и **номер** проблемной строки
2. `find_document_ref` → получить UUID документа
3. Запустить `01_drill_<имя>.py` (адаптированный) → увидеть все строки в РН.ПрочиеАктивыПассивы по этому документу
4. Если в ПАП симметричные строки, но Контроль показывает Δ — это **баг Свода** (см. подобные кейсы в [[knowledge_Balanse_money]])
5. Если в ПАП асимметричные строки — это **баг документа** (наш случай). Запустить `02_compare_*.py` чтобы найти откуда асимметрия (СуммаУпр vs СуммаРегл? Сумма с НДС vs без НДС?)
6. Прочитать соответствующий `Documents/<имя>/Ext/ObjectModule.bsl`, найти кастомную А_-процедуру → проблема
7. Решение → см. FINDINGS §5 «Варианты фикса» (адаптировать под конкретный документ)
