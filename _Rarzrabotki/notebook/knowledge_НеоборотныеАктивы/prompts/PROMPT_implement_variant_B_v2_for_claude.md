## §3. Граница «можно/нельзя» — строго соблюдать

### 🚫 НЕ ТРОГАТЬ

| Что | Почему |
|---|---|
| **РБ.Хозрасчетный** | Бухгалтерский регистр, проводки Дт 92 Кт 131/1321 на сумму без НДС — корректное штатное поведение для регл.отчётности и налоговой декларации |
| **СуммаРегл, СуммаРеглБезНДС, НДСРегл** в РН.ПрочиеРасходы | Регл/нал учёт, читается налоговыми отчётами |

| **РС.ПараметрыАмортизацииОСБУ** | Бух/нал параметры (СПИ, стоимость) — только читаем, не пишем |
| **РС.ПервоначальныеСведенияОС** | Бух/нал — не трогаем |
| **РС.ПараметрыАмортизацииОСУУ** | Версия 2_4, не используется |
| **Документы *ОС2_4 / *НМА2_4** | Пустые ObjectModule.bsl, не функционируют |
| **`РеглУчетПроведениеСервер.ОтразитьДокумент(...)`** в ObjectModule.bsl:84 | Формирует Хозрасчетный, не трогать вызов |

// {А_Доработка v2 2026-05-25} Расчёт правильной управ.амортизации с НДС.

// ИСКЛЮЧАЯ свой регистратор (чтобы не учитывать движения, которые сейчас перезаписываем).

### Процедура №2 — правка РН.ПрочиеРасходы (только управ-колонки)

```bsl
// {А_Доработка v2 2026-05-25} Коррекция управ.сумм в РН.ПрочиеРасходы.
//
// Правит ТОЛЬКО колонки Сумма / СуммаУпр / СуммаУпрБезНДС в БОБА строках.
// СуммаРегл / СуммаРеглБезНДС / НДСРегл НЕ ТРОГАЕМ — бух/нал сохраняется.
//
// Принцип:
//   - ОС с УПР строкой (СуммаРегл=0): обнуляем Сумма/СуммаУпр в БОБА.
//     УПР строка уже содержит правильную сумму с НДС.
//   - ОС без УПР строки: меняем Сумма/СуммаУпр в БОБА на правильную управ-сумму.
//     Если ОС имеет несколько строк (например 4 единицы Платформы) — каждой
//     присваиваем равную долю от Карта[ОС].Сумма (которая уже посчитана функцией №1
//     с учётом Σ всех Приходов по этому ОС в РН.ПАП).
Процедура А_СкорректироватьПрочиеРасходыНаНДС(КартаУправАморт) Экспорт
    НаборЗап = РегистрыНакопления.ПрочиеРасходы.СоздатьНаборЗаписей();
    НаборЗап.Отбор.Регистратор.Установить(Ссылка);
    НаборЗап.Прочитать();

    // 1) Группируем строки по ОС: есть ли УПР строка для каждой Аналитики
    ЕстьУПР_ПоОС = Новый Соответствие;
    Для Каждого Зап Из НаборЗап Цикл
        Если Зап.ВидДвижения <> ВидДвиженияНакопления.Приход
            ИЛИ НЕ ЗначениеЗаполнено(Зап.АналитикаРасходов) Тогда
            Продолжить;
        КонецЕсли;
        Если Зап.СуммаРегл = 0 И Зап.СуммаУпр > 0 Тогда   // признак УПР строки
            ЕстьУПР_ПоОС.Вставить(Зап.АналитикаРасходов, Истина);
        КонецЕсли;
    КонецЦикла;

    // 2) Считаем количество БОБА-строк по каждой Аналитике (для распределения суммы)
    КолвоБОБА_ПоОС = Новый Соответствие;
    Для Каждого Зап Из НаборЗап Цикл
        Если Зап.ВидДвижения = ВидДвиженияНакопления.Приход
            И ЗначениеЗаполнено(Зап.АналитикаРасходов)
            И Зап.СуммаРегл > 0 И Зап.СуммаУпр > 0 Тогда   // признак БОБА строки
            ОС = Зап.АналитикаРасходов;
            КолвоБОБА_ПоОС.Вставить(ОС, ?(КолвоБОБА_ПоОС[ОС] = Неопределено, 1, КолвоБОБА_ПоОС[ОС] + 1));
        КонецЕсли;
    КонецЦикла;

    // 3) Корректируем БОБА строки
    Для Каждого Зап Из НаборЗап Цикл
        Если Зап.ВидДвижения <> ВидДвиженияНакопления.Приход
            ИЛИ НЕ ЗначениеЗаполнено(Зап.АналитикаРасходов) Тогда
            Продолжить;
        КонецЕсли;
        ЭтоБОБА = (Зап.СуммаРегл > 0 И Зап.СуммаУпр > 0);
        Если НЕ ЭтоБОБА Тогда Продолжить; КонецЕсли;   // УПР строки НЕ трогаем

        ОС = Зап.АналитикаРасходов;
        Если ЕстьУПР_ПоОС[ОС] = Истина Тогда
            // Есть УПР строка → обнуляем Сумма/СуммаУпр в БОБА (СуммаРегл оставляем!)
            Зап.Сумма = 0;
            Зап.СуммаУпр = 0;
            Зап.СуммаУпрБезНДС = 0;
        Иначе
            // Нет УПР строки → ставим правильную управ-сумму с НДС
            Инфо = КартаУправАморт.Получить(ОС);
            Если Инфо <> Неопределено Тогда
                КолвоСтр = КолвоБОБА_ПоОС[ОС];
                Если КолвоСтр > 0 Тогда
                    ДоляПравильная = Окр(Инфо.Сумма / КолвоСтр, 2);
                    Зап.Сумма = ДоляПравильная;
                    Зап.СуммаУпр = ДоляПравильная;
                    Зап.СуммаУпрБезНДС = 0;
                    // Зап.СуммаРегл, СуммаРеглБезНДС, НДСРегл НЕ ТРОГАЕМ
                КонецЕсли;
            КонецЕсли;
        КонецЕсли;
    КонецЦикла;

    НаборЗап.Записать(Истина);
КонецПроцедуры
```

## §8. Anti-patterns (НЕ делать)

| Антипаттерн | Почему опасно |
|---|---|
| ❌ Править колонку СуммаРегл в РН.ПрочиеРасходы | Сломает регл/нал.учёт, налоговую декларацию по налогу на прибыль |
| ❌ Изменять РБ.Хозрасчетный или вызов `РеглУчетПроведениеСервер.ОтразитьДокумент(...)` | Сломает бух.отчётность |
| ❌ Удалять/добавлять строки в РН.ПрочиеРасходы (менять только колонки!) | Может сломать другие отчёты (себестоимость, OLAP). Меняем только Сумма/СуммаУпр |
| ❌ Пропустить бэкап ObjectModule.bsl | Невозможно откатить если что-то пойдёт не так |
| ❌ Перепровести через `obj.Записать(РежимЗаписиДокумента.Проведение)` без проверки `obj.Проведен` после | Не убедимся что проведение прошло |
| ❌ Продолжать на массовый перепровод закрытых периодов без явного OK пользователя | Может сломать данные за дек 2025 / янв-фев 2026, изменить уже сданную отчётность |
| ❌ Использовать MCP `post_document` если он падает с «сессионные параметры» | Использовать Python COM напрямую (см. CLAUDE.md «MCP Posting Limitation») |
| ❌ Применять для других документов амортизации (АмортизацияНМА, ПереоценкаОС) без отдельного анализа | Каждый документ может иметь свою специфику. Текущий промт только для АмортизацияОС (2.1) |
