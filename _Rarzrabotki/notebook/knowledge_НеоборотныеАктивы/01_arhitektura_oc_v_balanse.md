## Где может быть «плуг» в управ.балансе

| Место | Возможная причина | Симптом |
|---|---|---|
| L1 | Документ пишет асимметричные данные (Сумма ≠ Сумма парной строки) | Σ Дт ≠ Σ Кт по документу в РН.ПАП |
| L2 | Штатная обработка взяла другую базу суммы, чем кастомная процедура | Σ(СуммаУпр) ≠ Σ(СуммаРегл) для одной аналитики |
| L3 | Свод_* функция фильтрует/группирует не так, как другие | Расхождение=ИСТИНА (плуг) в А_ОтчетБаланс_Свод |
| L4 | Отчёт использует фильтр, который теряет данные | Видимый Δ в Контроле баланса |

**На уровне L3 для ОС плуг не возникает** (Свод_ПрочиеАктивыПассивы_Прямой сравнивает один регистр сам с собой). Поэтому когда Контроль баланса показывает Δ — корень всегда в L1 или L2.

## Ключевые регистры (метаданные)

### РН.ПрочиеАктивыПассивы (синоним: «Активы и пассивы»)
- **Тип:** Остатки (балансовый)
- **Измерения:** Организация, Подразделение, Статья (ПВХ.СтатьиАктивовПассивов), Аналитика (составной тип), Источник (Перечисление.ИсточникиУправленческогоБаланса), …
- **Ресурсы:** Сумма
- **ВидДвижения:** Приход (Дт), Расход (Кт)

### РН.А_ОтчетБаланс_Свод
- **Тип:** Обороты + Остатки (универсальный)
- **Регистратор:** Документ.А_ФинРез_Баланс
- **Особенность:** Регистратор НЕ в ключе уникальности → для разделения месяцев используется `ДокументДвижения` (см. ObjectModule.bsl:76-82 заполняется ссылкой на сам А_ФинРез_Баланс)
- **Ресурсы:** СуммаНачальныйОстаток, СуммаПриход, СуммаРасход, СуммаКонечныйОстаток

### РН.ПрочиеРасходы
- **Тип:** Обороты (для амортизации) — база расчёта
- **Ресурсы:** Сумма, СуммаУпр, СуммаРегл, СуммаБезНДС, СуммаУпрБезНДС, СуммаРеглБезНДС, НДСРегл

**КЛЮЧЕВО:** для амортизации ОС наполняется через документ АмортизацияОС:
- ВидДвижения=Приход → начисление амортизации на расходы
- СтатьяРасходов с типом «Амортизация ОЗ»
- 3 разные суммы (Сумма / СуммаУпр / СуммаРегл) — могут отличаться, см. **FINDINGS §2**
