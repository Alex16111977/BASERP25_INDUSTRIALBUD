## §1 ★ Корневая причина (версия 2)

Документ АмортизацияОС (2.1) пишет в РН.ПрочиеРасходы **2 строки амортизации на 1 ОС**:

```
СТРОКА #1 «БОБА» (бух/нал):
  Сумма       = 22 806,29   ← стоимость БЕЗ НДС  ÷ СПИ (СПИ=1 мес = метод «100%»)
  СуммаУпр    = 22 806,29   ← такая же (БОБА строка едина для всех учётов с одной суммой)
  СуммаРегл   = 22 806,29   ← такая же

СТРОКА #2 «УПР» (управ):
  Сумма       = 27 367,55   ← стоимость С НДС (= 22 806,29 × 1,20)
  СуммаУпр    = 27 367,55   ← заполнена
  СуммаРегл   = 0           ← пуста ← маркер «только управ»
```

**Что попадает в РН.ПрочиеАктивыПассывы:**

```
Штатная Обработка.ДвиженияАктивовПассивов:
  Σ Сумма(обеих) → Дт «Расходы текущего периода» = 50 173,84  ← ★ ЗАДВОЕНИЕ

Кастомная А_СформироватьДвиженияАктивовПассивов() [ObjectModule.bsl:280-328]:
  Σ СуммаРегл → Кт «Основные средства» = 22 806,29  ← только БОБА часть
```

**Δ = 50 173,84 − 22 806,29 = 27 367,55** = ровно «лишняя» УПР строка.

По всему документу: **Δ = 102 060,55 = Σ УПР строк** по 4 ОС (Гайковерт, Вышка x2, Фильтр ECOSOFT).

## §3 Принцип НДС в управ.балансе

Из запроса пользователя:

> «А когда метод начисления амортизации Прямолинейный — правильный. Сумму берёт **с НДС**.»
> «Бухгалтерское списание НДС не учитывает полное списание стоимости в управленческом учёте. Смотри управленческий баланс — принцип отражения: там берётся **сумма с НДС**.»

**Методология (как должно быть):**
- Управ.учёт ОС включает НДС в стоимость (НДС не возмещается на уровне управ.финансов)
- Бух/нал.учёт ОС включает НДС отдельно (можно возмещать)
- Для управ.баланса должна браться **стоимость С НДС** = бух.стоимость × 1,20

**Что сейчас (сломано):**
- В РН.ПрочиеРасходы дублирующая запись: и бух (без НДС), и управ (с НДС)
- Штатная обработка суммирует их → задвоение
- Кастомная А_-процедура читает только бух часть → асимметрия

**Что должно быть:**
- Для управ.баланса: только УПР строка (27 367,55 = с НДС)
- БОБА строка (22 806,29 = без НДС) для управ.баланса НЕ нужна

## §6 Варианты решения (на ваш выбор, БЕЗ автоматической правки)

> **🚫 Бухгалтерский и налоговый учёт НЕ ТРОГАЕМ.** Что меняется и что нет:
> - **РН.ПрочиеАктивыПассывы** (управ.баланс) — **полная перезапись** через `Очистить()` + симметричная пара Дт/Кт. Затрагивается только этот регистр.

> - **РН.СтоимостьОС, РН.АмортизацияОС, РС.ПараметрыАмортизацииОСУУ** — не трогаются (документ 2.1 туда не пишет вообще).

### Вариант B v2 ★ — корректирующая А_-процедура для ДВУХ регистров (рекомендую)

Этот подход **решает обе стороны проблемы И корректирует PnL**:
- Правит **РН.ПрочиеРасходы** (Сумма + СуммаУпр в БОБА строках) → А_ФинРез_PL и Свод_ПрочиеАктивыПассывы видят корректную управ.амортизацию с НДС
- Правит **РН.ПрочиеАктивыПассывы** (Очистить + симметричная перезапись) → Контроль баланса = 0, остаток ОС = 0
- НЕ трогает СуммаРегл / СуммаРеглБезНДС / НДСРегл → бух/нал.учёт сохраняется

**Источник истины** — остаток ОС в РН.ПАП на начало месяца (там лежит стоимость с НДС из СписаниеТоваров/ПринятиеКУчету). Делим на СПИ_БУ → правильная управ.амортизация.

#### Связь с А_ФинРез_PL

Документ `А_ФинРез_PL.ObjectModule.bsl:183` читает амортизацию через:
```
СУММА(Р.СуммаПриход) ИЗ РегистрНакопления.ПрочиеРасходы.Обороты(...)
```
То есть Σ колонки **Сумма** по ВидДвижения=Приход. Если эту колонку не править — PnL покажет неправильную сумму амортизации (с задвоением или недоамортизацией). Поэтому Вариант B v2 правит **именно Сумма и СуммаУпр** в РН.ПрочиеРасходы.

// Принцип:
//   - Для ОС с УПР строкой (СуммаРегл=0): обнуляем Сумма/СуммаУпр в БОБА строках,
//     УПР строку оставляем как есть (она уже содержит правильную сумму с НДС).
//   - Для ОС без УПР строки (Платформа): меняем Сумма/СуммаУпр в БОБА строке
//     на ПравильнаяУправ-Амортизация-С-НДС из остатка РН.ПАП.
Процедура А_СкорректироватьПрочиеРасходыНаНДС(КартаУправАморт)
    НаборЗап = РегистрыНакопления.ПрочиеРасходы.СоздатьНаборЗаписей();
    НаборЗап.Отбор.Регистратор.Установить(Ссылка);
    НаборЗап.Прочитать();

    // Группируем строки по ОС: есть ли УПР строка для каждой Аналитики
    ЕстьУПР_ПоОС = Новый Соответствие;
    Для Каждого Зап Из НаборЗап Цикл
        Если Зап.ВидДвижения <> ВидДвиженияНакопления.Приход ИЛИ
             НЕ ЗначениеЗаполнено(Зап.АналитикаРасходов) Тогда
            Продолжить;
        КонецЕсли;
        Если Зап.СуммаРегл = 0 И Зап.СуммаУпр > 0 Тогда  // УПР строка
            ЕстьУПР_ПоОС.Вставить(Зап.АналитикаРасходов, Истина);
        КонецЕсли;
    КонецЦикла;

    // Корректируем БОБА строки в зависимости от наличия УПР
    Для Каждого Зап Из НаборЗап Цикл
        Если Зап.ВидДвижения <> ВидДвиженияНакопления.Приход ИЛИ
             НЕ ЗначениеЗаполнено(Зап.АналитикаРасходов) Тогда

            Зап.Сумма = 0;
            Зап.СуммаУпр = 0;
            Зап.СуммаУпрБезНДС = 0;

            // Нет УПР строки (Платформа): нужно проставить управ-сумму с НДС
            Инфо = КартаУправАморт.Получить(ОС);
            Если Инфо <> Неопределено Тогда
                // Распределяем правильную сумму равномерно по строкам этого ОС
                // (для Платформы 4 строки на 4 единицы — каждая получит 5 458,00)
                // Считаем количество БОБА-строк по этому ОС
                КолвоСтр = 0;
                Для Каждого З2 Из НаборЗап Цикл
                    Если З2.АналитикаРасходов = ОС И З2.ВидДвижения = ВидДвиженияНакопления.Приход
                         И З2.СуммаРегл > 0 Тогда
                        КолвоСтр = КолвоСтр + 1;
                    КонецЕсли;
                КонецЦикла;
                // Каждая строка получит свою долю
                ДоляПравильная = ?(КолвоСтр > 0, Окр(Инфо.Сумма / КолвоСтр, 2), 0);
                Зап.Сумма = ДоляПравильная;
                Зап.СуммаУпр = ДоляПравильная;
                Зап.СуммаУпрБезНДС = 0;
                // Зап.СуммаРегл, СуммаРеглБезНДС, НДСРегл НЕ ТРОГАЕМ
            КонецЕсли;
        КонецЕсли;
    КонецЦикла;

    НаборЗап.Записать(Истина);
КонецПроцедуры

- Это значит для этих ОС **не было применено** добавление НДС к стоимости (видимо приобретены без НДС либо НДС включён в стоимость уже на этапе приёма)

**Следствие:** проблема **не системная** — она возникает только для ОС, у которых:
- Метод амортизации = "100%" (СПИ=1 мес)
- Стоимость в карточке БЕЗ НДС (НДС возмещался отдельно при приёмке)
- Кто-то (локализация или доработка) добавил +20% НДС для управ.учёта в РН.ПрочиеРасходы

## §11 ✅ v3 фикс: защита от задвоения УПР строк (коммит `cd059c503`)

### Проблема, обнаруженная после v2

После применения v2 пользователь повторно перепровёл документ 000Ц-000003 (через UI 1С Enterprise или ещё один цикл MCP). Скриншот показал:

```
Регистр накопления "Прочие расходы" для Гайковерта BOSCH (3 строки вместо 2):
  #1 Приход   СуммаРегл=22 806,29              Сумма=0  СуммаУпр=0          ← БОБА (обнулено v2)
  #2 Приход   Сумма=27 367,55  СуммаУпр=27 367,55                            ← УПР (правильно)
  #3 Приход   Сумма=27 367,55  СуммаУпр=27 367,55                            ← УПР #2 — ЛИШНЯЯ
```

**Σ Сумма по Гайковерту = 0 + 27 367,55 + 27 367,55 = 54 735,10** (вместо 27 367,55)
→ В PnL Гайковерт попал бы задвоенным на 27 367,55

### Корневая причина

При повторном проведении документа АмортизацияОС типовая обработка `ПроведениеДокументов.ОбработкаПроведенияДокумента` **добавляет** новую УПР строку поверх существующей (вместо очистки+перезаписи).

Наша v2 процедура `А_СкорректироватьПрочиеРасходыНаНДС` обрабатывала только БОБА строки → дубликаты УПР оставались.

**Процедура была неидемпотентной** — повторные перепроводы накапливали задвоение.

### Фикс v3

В процедуре `А_СкорректироватьПрочиеРасходыНаНДС` добавлен блок (+30 строк) защиты от дубликатов УПР:

```bsl
// {А_Доработка v3 2026-05-26} Защита от задвоения УПР строк при повторных перепроводах.
УПР_Обработана_ПоОС = Новый Соответствие;
Для Каждого Зап Из НаборЗап Цикл
    Если Зап.ВидДвижения <> ВидДвиженияНакопления.Приход
        ИЛИ НЕ ЗначениеЗаполнено(Зап.АналитикаРасходов) Тогда
        Продолжить;
    КонецЕсли;
    ЭтоУПР = (Зап.СуммаРегл = 0 И Зап.СуммаУпр > 0);
    Если НЕ ЭтоУПР Тогда Продолжить; КонецЕсли;

    ОС = Зап.АналитикаРасходов;
    Если УПР_Обработана_ПоОС[ОС] = Истина Тогда
        // Дубликат — обнуляем управ-колонки
        Зап.Сумма = 0;
        Зап.СуммаУпр = 0;
        Зап.СуммаУпрБезНДС = 0;
    Иначе
        // Первая УПР строка — оставляем, помечаем обработанной
        УПР_Обработана_ПоОС.Вставить(ОС, Истина);
    КонецЕсли;
КонецЦикла;
```

**Граница ответственности (как и в v2):** СуммаРегл / СуммаРеглБезНДС / НДСРегл не трогаем → бух/нал сохранён.

### Эффект

Процедура стала **идемпотентной** — повторные перепроводы документа АмортизацияОС безопасны, задвоение не возникает.

После применения v3:
```

  #2 Приход   Сумма=27 367,55  СуммаУпр=27 367,55                            ← УПР (оставлена)
  #3 Приход   Сумма=0  СуммаУпр=0                                            ← УПР #2 (обнулена)
Σ Сумма = 27 367,55 ✓
```
