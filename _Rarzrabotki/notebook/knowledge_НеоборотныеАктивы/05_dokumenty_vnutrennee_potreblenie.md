# 05. Документ.ВнутреннееПотреблениеТоваров

## Метаданные

- **Имя:** `Документ.ВнутреннееПотреблениеТоваров`
- **XML:** `Documents/ВнутреннееПотреблениеТоваров.xml`
- **ObjectModule:** `Documents/ВнутреннееПотреблениеТоваров/Ext/ObjectModule.bsl`
- **Версии 2.4 в виде отдельного документа в нашей конфигурации нет** (в отличие от АмортизацияОС/ПринятиеКУчетуОС)

## Назначение

Списывает товарно-материальные ценности (ТМЦ) во внутреннее потребление: материалы со склада → расходы подразделения / расходы на изготовление продукции / расходы на нужды офиса и т.п.

Документ может попадать в баланс по нескольким статьям ПВХ:
- **Расходы текущего периода** (списание в текущие затраты)
- **Расходы будущих периодов** (списание капитализируемых затрат — например, ремонт ОС, который будет амортизироваться)
- **Вложения в необоротные активы** (если ТМЦ идёт на формирование стоимости ВНА — например, монтаж нового оборудования)

## ★ Ключевое отличие от АмортизацияОС

**`Документ.ВнутреннееПотреблениеТоваров.ObjectModule.bsl` НЕ упоминает `ПрочиеАктивыПассивы`** (grep подтвердил).

Документ сам в РН.ПрочиеАктивыПассивы НЕ пишет. Все движения в ПАП формируются **штатной Обработкой.ДвиженияАктивовПассивов** при закрытии месяца — она же создаёт обе стороны (Дт списания + Кт уменьшения товаров на складе) симметрично.

## Подтверждение симметрии (Март 2026)

`Python/test/03_scan_march2026.py` показал:

```
=== ВнутреннееПотреблениеТоваров ===
  Всего документов: 89, асимметричных: 0, Σ|Δ|: 0,00
  Σ ΣДт = 937 280,10, Σ ΣКт = 937 280,10, нетто Δ = 0,00
```

89 документов за Март 2026, **все симметричные**, общий оборот 937 280,10 грн (примерно 1 млн материалов списано во внутр.потребление).

## Какие регистры документ двигает

(Точный перечень — через `get_metadata_structure`. Основные:)

| Регистр | Что записывает |
|---|---|
| РН.ТоварыНаСкладах | Расход: уменьшает остатки ТМЦ на складе |
| РН.ТоварыОрганизаций | Расход по партиям |
| РН.СебестоимостьТоваров | Расход: списывает себестоимость |
| РН.ПрочиеРасходы | Приход: накопление расходов по статьям |
| РН.ВложенияВНеоборотныеАктивы | Приход (если статья = ФормированиеСтоимостиВНА) |
| РБ.Хозрасчетный | Проводки Дт 23/91/93 Кт 20/22/25 и т.п. |

## Связь с амортизацией ОС

Если ВнутреннееПотреблениеТоваров списывает ТМЦ на статью с типом «Формирование стоимости ВНА», эти расходы потом капитализируются в стоимость нового ОС. Цепочка:

```
1. ВнутреннееПотреблениеТоваров → РН.ПрочиеРасходы (Приход, статья «Формирование стоимости ВНА»)
                                 → РН.ВложенияВНеоборотныеАктивы (Приход)
                                 → штатная обработка ДвиженияАктивовПассивов
                                    → РН.ПрочиеАктивыПассивы (Дт «Вложения в ВНА» / Кт «Товары на оптовых складах»)
2. ПринятиеКУчетуОС → переводит вложения в стоимость ОС
                    → штатная обработка
                       → РН.ПрочиеАктивыПассивы (Дт «Основные средства» / Кт «Вложения в ВНА»)
3. АмортизацияОС → начисляет амортизацию (★ здесь баг асимметрии)
```

## Когда искать здесь причину Δ в Контроле баланса

- **Никогда** для штатной механики (если 03_scan_march показал Σ|Δ| = 0)
- **Только** если внутри ObjectModule.bsl появится кастомный код, пишущий в РН.ПрочиеАктивыПассивы напрямую (по аналогии с А_СформироватьДвиженияАктивовПассивов в АмортизацияОС)

## Связь с регистром РН.ВложенияВНеоборотныеАктивы

Этот регистр — посредник между «накоплением затрат на новые ОС» и «приёмом ОС в учёт». Если в нём накапливаются движения, которые потом не сворачиваются ПринятиеКУчетуОС, то они «висят» как капитальные вложения в балансе. Это **отдельная** статья «Вложения в необоротные активы» (00000000040 «Вложения собственных средств» в ПВХ?), и она НЕ источник асимметрии нашего конкретного документа Амортизации.
