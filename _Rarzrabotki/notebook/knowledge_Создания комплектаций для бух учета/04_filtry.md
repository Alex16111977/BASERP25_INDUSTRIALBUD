# 04. Фильтры (склады / счета / организация / этапы) и счёт-на-строку

Все фильтры — реквизиты/ТЧ обработки на закладке «Параметри». Логика — в `ПолучитьОстатки`/`ПолучитьНормы` (см. [02](02_istochniki_zaprosy.md)).

## Склады — ТЧ `СкладыОстатков`

`СкладыСписком()` собирает заполненные `Стр.Склад` в Массив → параметр `&Склады` (внешний `ГДЕ` через субконто3). Пусто → исключение «Не вибрані склади залишків».

## Счета — ТЧ `СчетаОстатков` (мультивыбор, default 20/22/28)

```bsl
Функция СчетаСписком()
	Результат = Новый Массив;
	Для Каждого Стр Из СчетаОстатков Цикл
		Если ЗначениеЗаполнено(Стр.Счет) Тогда Результат.Добавить(Стр.Счет); КонецЕсли;
	КонецЦикла;
	Если Результат.Количество() = 0 Тогда                 // fallback
		Для Каждого Код Из СтрРазделить("20,22,28", ",") Цикл
			Сч = ПланыСчетов.Хозрасчетный.НайтиПоКоду(Код);
			Если ЗначениеЗаполнено(Сч) Тогда Результат.Добавить(Сч); КонецЕсли;
		КонецЦикла;
	КонецЕсли;
	Возврат Результат;
КонецФункции
```
- Запрос: `Счет В ИЕРАРХИИ(&Счета)` — группы 20/22/28 раскрываются в субсчета.
- Колонка ТЧ `Счет` тип `ChartOfAccountsRef.Хозрасчетный`, `ChoiceFoldersAndItems=FoldersAndItems` (чтобы выбирать счета-группы).
- **Преднаполнение 20/22/28 — в форме** (`ПриСозданииНаСервере`, если ТЧ пуста), т.к. в клиенте удобнее видеть. В коде (`СчетаСписком`) — fallback на случай пустого набора (COM/прямой вызов).

## Организация — реквизит `Организация`

Опц. фильтр через **ИЛИ-паттерн** в запросе (см. [02](02_istochniki_zaprosy.md)): пусто=все орг. ⚠️ В условии виртуальной таблицы Организация недоступна — только внешний `ГДЕ`. Группировка остатков БЕЗ организации; на одном складе бывают остатки разных юрлиц, поэтому орг-фильтр важен.

## Этапы — ТЧ `Этапы` + флаг `ИсключатьЭтапы` (include / exclude)

```bsl
Функция ЭтапыСписком()
	Результат = Новый Массив;
	Для Каждого Стр Из Этапы Цикл
		Если ЗначениеЗаполнено(Стр.Этап) Тогда Результат.Добавить(Стр.Этап); КонецЕсли;
	КонецЦикла;
	Возврат Результат;
КонецФункции
```
- В `ПолучитьНормы`: пусто → все этапы; список + `ИсключатьЭтапы=Ложь` → `И К.Этап В (&Этапы)`; список + `Истина` → `И НЕ К.Этап В (&Этапы)`.
- Реализует «выбрать один этап и исключить его» вместо перечисления всех остальных.
- Колонка `Этап` тип `CatalogRef.ЭтапыРабот` (синоним «Етапи робіт»). Источник — `СтруктураСебестоимости.Комплектующие.Этап`.

## Счёт-на-строку (per-row `СчётУчётаБУ`)

С Фазы 4 счёт едет ПО СТРОКЕ от остатка до компонента документа:
```
Хозрасчетный.Остатки → Ост.Счет
  → ТабличнаяЧастьОстатков.Счет           (ЗаполнитьАнализ)
  → ТЗ строки документа.Счет              (НакопитьСтроку, доп.колонка "Счет")
  → НС.СчетУчетаБУ = СтрД.Счет            (СформироватьДокументыПоСоответствию)
```
Материал на 201 пишется счётом 201, на 221→221, на 2051→2051. **Единый счёт не навязывается.** Старый скрытый реквизит `СчетКомплектации` и функция `ПолучитьСчетКомплектации` — УДАЛЕНЫ (Фаза 4).

✅ Read-only верифицировано: счёт строки анализа = счёт остатка (128/128, `verify_scheta_readonly.py`). Персист после собственной записи документа `КомплектацияНоменклатуры` (его `ПередЗаписью`) — НЕ проверялся записью (по решению юзера). Код ставит верный счёт прямо перед `Записать()`.

## Фильтры на самой таблице анализа (закладка «Аналіз залишків»)

Отдельный механизм от параметров — фильтрация ОТОБРАЖЕНИЯ: `ОтборСклад`/`ОтборЭталон` (равенство), `Пошук` (substring по Номенклатура+Эталон+Склад+Счёт), `ТолькоПонадНорму` (флаг). Реализованы пересбором формы-ValueTable `ТаблицаАнализа` из полного `Объект.ТабличнаяЧастьОстатков` (см. [06](06_forma_druk.md)).
