# 01. Архитектура и сборка

## Файловая структура .epf

```
Создания комплектаций для бух учета.xml          ← манифест ExternalDataProcessor (реквизиты + ТЧ + Templates)
Создания комплектаций для бух учета/
├── Ext/ObjectModule.bsl                          ← ★ движок (вся логика, экспортные методы)
└── Forms/Форма/
    ├── Ext/Form.xml                              ← управляемая форма (закладки, таблицы, команды, Popup-меню)
    └── Ext/Form/Module.bsl                       ← тонкий модуль формы (диспетчер)
Создания комплектаций для бух учета.epf           ← собранный артефакт (для клиента)
```

## Принцип: тонкая форма ↔ движок в ObjectModule

Вся бизнес-логика — в `ObjectModule.bsl` (экспортные методы на `ЭтотОбъект`). Форма только дёргает их и рисует. Мост значения объекта обработки ↔ форма:

```bsl
// в модуле формы (&НаСервере):
ОбъектОбработки = РеквизитФормыВЗначение("Объект");   // форма -> объект-значение
ОбъектОбработки.РассчитатьАнализ();                    // вызов движка
ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект");     // объект -> обратно в форму
```

Главный реквизит формы `Объект` имеет тип `ExternalDataProcessorObject.СозданиеКомплектацийБух`; пути к данным на форме — `Объект.X` (напр. `Объект.ТабличнаяЧастьОстатков`).

⚠️ **Важно:** методы движка работают с реквизитами/ТЧ объекта **без префикса** (`СкладыОстатков`, `ТабличнаяЧастьОстатков`, `Спецификация`, `Организация`, `ИсключатьЭтапы`), т.к. они выполняются в контексте `ЭтотОбъект`.

## Экспортные методы движка (`#Область ПрограммныйИнтерфейс`)

| Метод | Назначение |
|---|---|
| `СведенияОВнешнейОбработке()` | Регистрация в БСП «Додаткові звіти і обробки» (см. [07](07_bsp_podklyuchenie.md)) |
| `РассчитатьАнализ()` | Остатки → нормы → `ЗаполнитьАнализ` → авто-склады. Вызывается кнопкой «Розрахувати» |
| `ЗаполнитьДокументыПоАнализу(ЗаполнятьВНорме=Истина, ЗаполнятьПонад=Истина)` | Запись ТЧ Комплектующие выбранных документов (в транзакции). Опц. булевы = 3 режима |
| `СформироватьПечать(ДанныеАнализа)` | Возвращает `ТабличныйДокумент` (отчёт анализа). Принимает строки (форма передаёт `ТаблицаАнализа`) |

## Сборка `.epf` — `epf-build` из ИЗОЛИРОВАННОГО каталога

⚠️ **Собирать ТОЛЬКО из изолированного каталога** (иначе загрузчик подтянет чужие типы соседних обработок из `_Rarzrabotki/Обработки/`):

```bash
rm -rf /c/temp_epf_kompl && mkdir -p /c/temp_epf_kompl
cp "/c/.../Обработки/Создания комплектаций для бух учета.xml" /c/temp_epf_kompl/
cp -r "/c/.../Обработки/Создания комплектаций для бух учета" /c/temp_epf_kompl/
```
```powershell
powershell -File .claude/skills/epf-build/scripts/epf-build.ps1 `
  -InfoBaseServer "SQLSERVER" -InfoBaseRef "BuhBud" -UserName "cfo" -Password "2442" `
  -SourceFile "C:\temp_epf_kompl\Создания комплектаций для бух учета.xml" `
  -OutputFile "C:\...\Обработки\Создания комплектаций для бух учета.epf"
```
Сборка против **BuhBud** (а не stub) — иначе ссылочные типы (`CatalogRef.СтруктураСебестоимости`, `ChartOfAccountsRef.Хозрасчетный`…) не разрешатся. `EXITCODE=0` = форма + оба модуля скомпилировались.

⚠️ Перед каждой пересборкой **re-sync изолированного каталога из основной конфигурации** (`cp` свежих файлов), иначе соберётся старый код. После правок пользователя в Конфигураторе — особенно (Designer переформатирует Form.xml).

## COM-smoke (валидация без клиента)

Управляемую форму COM headless **НЕ рендерит** — закладки/УО/друк проверяются только открытием в клиенте BuhBud. Но через COM проверяемо: загрузка `.epf`, `РассчитатьАнализ`, `ТабличнаяЧастьОстатков`, `СформироватьПечать` (`ТабличныйДокумент` COM-инспектируем — `ВысотаТаблицы`, `Область(r,c,r,c).Текст`, `.Шрифт.Жирный`, `.ШиринаКолонки`).

```python
import win32com.client
buh = win32com.client.Dispatch("V83.COMConnector").Connect('Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"')
обр = buh.ВнешниеОбработки.Создать(r"C:\...\Создания комплектаций для бух учета.epf", False)
# задать Период / Спецификация / Организация / СчетаОстатков / СкладыОстатков -> РассчитатьАнализ() -> читать ТабличнаяЧастьОстатков
```
