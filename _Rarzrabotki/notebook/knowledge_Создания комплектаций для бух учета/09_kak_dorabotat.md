# 09. Как правильно дорабатывать обработку (рецепты)

Чек-лист и проверенные паттерны для расширения. **Перед любым запросом** — Python COM тест (Rule #-1), потом BSL.

## Универсальный чек-лист доработки

1. **Запрос** (если есть) — сперва прогнать в Python COM на BuhBud, добиться нужного результата, потом переносить в BSL.
2. **Манифест `.xml`** — новые реквизиты/ТЧ/колонки. Python-патч по `re.subn` на уникальном якоре (uuid) + `xml.dom.minidom.parse` (валидность). UUID можно hand-authored (`c1000000-…`, `a2000000-…008/009`) — загрузчик 1cv8 принимает.
3. **ObjectModule** — логика. Регионы `#ПрограммныйИнтерфейс` (экспорт) / `#СлужебныеПроцедурыИФункции`. Проверка парности `Процедура/Функция == Конец…`, `#Область == #КонецОбласти`.
4. **Form.xml** — элементы/команды. ID **уникальны в пределах формы** (текущий max растёт; проверять `re.findall(r'id="(\d+)"')` на дубли). Python-патч по якорям + `xml.dom.minidom.parse`.
5. **Form module** — обработчики. Тонкие, делегируют в ObjectModule через `РеквизитФормыВЗначение`.
6. **Сборка** — re-sync изолированного каталога из основной конфигурации → `epf-build` против BuhBud → exit 0.
7. **COM-smoke** — регрессия (`smoke_komplektacii_ekonomiya.py` и др.) + новый тест фичи.
8. **Клиент** — открыть `.epf` в BuhBud (форму/УО/друк COM не рендерит).

## Рецепт: + колонка в анализ (как «Економія»)

1. Манифест: + колонка в ТЧ `ТабличнаяЧастьОстатков` (decimal 15,3).
2. Form.xml: + колонка в форм-ValueTable `ТаблицаАнализа` (Columns) + InputField в таблице + (опц.) поле в «Підсумки» + (опц.) форм-реквизит `Итого…`.
3. ObjectModule `ЗаполнитьАнализ`: заполнить `НоваяСтрока.<Колонка>`. Если метрика per-эталон (как Норма/Економія) — писать на первой строке эталона.
4. Form module `ПрименитьОтборИИтоги`: перенести колонку в `ТаблицаАнализа` + (опц.) суммировать в `Итого…`.
5. (Опц.) Друк `СформироватьПечать`: добавить колонку в Заголовки/Значения/Итоги.

## Рецепт: + фильтр остатков (как организация/счета)

- Реквизит → внешний `ГДЕ` (для измерений Хозрасчетный: Организация — только внешний ГДЕ; счёт — в условии ВТ через `В ИЕРАРХИИ`). Опциональность через ИЛИ-паттерн `(&П = ЗНАЧЕНИЕ(…ПустаяСсылка) ИЛИ Поле = &П)`.
- ТЧ-мультивыбор → `Массив` → `Поле В (&Параметр)` (или `В ИЕРАРХИИ`).
- Фильтр норм (этапы) → динамическое условие в тексте `ПолучитьНормы`.

## Рецепт: + кнопка / режим заполнения (как 3 режима)

- Параметризовать экспортный метод **опц. параметрами по умолчанию** (`Функция …(П1 = Истина, П2 = Истина)`) — старые вызовы/smoke не ломаются.
- Form.xml: выпадающее меню = `<Popup name=… id=…><Title/><ChildItems><Button…><CommandName>Form.Command.X</CommandName>…</Button></ChildItems></Popup>` (эталон `.claude/skills/bas-bsp-form/reference/document-contract.md`). 1 кнопка = 1 команда = 1 обработчик формы.

## Рецепт: печать/отчёт

- **Программный `ТабличныйДокумент`** (НЕ MXL-макет) — нет XDTO-риска при сборке .epf, COM-инспектируем (smoke). Стиль/грабли — см. [06](06_forma_druk.md).

## НЕ трогать (by-design)

- Математику распределения (`ЗаполнитьАнализ`: ВНорме/ПонадНорму) и `УПОРЯДОЧИТЬ ПО ОбщееНазвание, Остаток УБЫВ`.
- Норму по эталону (`ОбщееНазвание`), не по номенклатуре.
- Субконто-`ВЫРАЗИТЬ` (1=Номенклатура, 3=Склад) + склад во внешнем ГДЕ.
- Транзакционный оркестратор, структуру-результат, идемпотентность `Комплектующие.Очистить`.
- Документы не создавать/не проводить (только `Записать`).
