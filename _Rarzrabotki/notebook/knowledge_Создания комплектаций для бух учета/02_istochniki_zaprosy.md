# 02. Источники данных и запросы

Два запроса: **остатки** (`ПолучитьОстатки`) и **нормы** (`ПолучитьНормы`). Оба тестировать в Python COM ПЕРЕД переносом в BSL (Rule #-1).

## Запрос остатков — `ПолучитьОстатки(СкладыМассив)`

Источник: `РегистрБухгалтерии.Хозрасчетный.Остатки`. В BuhBud товарного накопит.регистра нет — только бухгалтерские остатки.

```bsl
Запрос.УстановитьПараметр("НаДату", ?(ЗначениеЗаполнено(Период), КонецДня(Период), КонецДня(ТекущаяДата())));
Запрос.УстановитьПараметр("Склады", СкладыМассив);          // Массив CatalogRef.Склады
Запрос.УстановитьПараметр("Счета", СчетаСписком());          // Массив ChartOfAccountsRef (пусто->20/22/28)
Запрос.УстановитьПараметр("Организация", Организация);        // CatalogRef.Организации (м.б. пустая)
Запрос.Текст =
"ВЫБРАТЬ
|	ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура) КАК Номенклатура,
|	ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура).ОбщееНазваниеНоменклатуры КАК ОбщееНазвание,
|	ВЫРАЗИТЬ(Ост.Субконто3 КАК Справочник.Склады) КАК Склад,
|	Ост.Счет КАК Счет,
|	СУММА(Ост.КоличествоОстаток) КАК Остаток
|ИЗ
|	РегистрБухгалтерии.Хозрасчетный.Остатки(&НаДату, Счет В ИЕРАРХИИ(&Счета), , ) КАК Ост
|ГДЕ
|	Ост.КоличествоОстаток > 0
|	И (&Организация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) ИЛИ Ост.Организация = &Организация)
|	И ВЫРАЗИТЬ(Ост.Субконто3 КАК Справочник.Склады) В (&Склады)
|СГРУППИРОВАТЬ ПО
|	ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура),
|	ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура).ОбщееНазваниеНоменклатуры,
|	ВЫРАЗИТЬ(Ост.Субконто3 КАК Справочник.Склады),
|	Ост.Счет
|УПОРЯДОЧИТЬ ПО
|	ОбщееНазвание,
|	Остаток УБЫВ";
```

### Ключевые факты запроса остатков

- **Субконто едино для ВСЕХ счетов класса 2**: `1=Номенклатура, 2=Партії, 3=Склади` (проверено для 201/205/2051/221/281/207/209). Поэтому `ВЫРАЗИТЬ(Субконто1 КАК Номенклатура)` и `ВЫРАЗИТЬ(Субконто3 КАК Склады)` работают для всех счетов — не нужен coalesce по позициям.
- **Счёт — в условии виртуальной таблицы**: `Остатки(&НаДату, Счет В ИЕРАРХИИ(&Счета), , )`. `В ИЕРАРХИИ` раскрывает группы 20/22/28 → их субсчета (201..209, 221, 281, 2051…). `Счет` — измерение, в условии ВТ работает.
- **Склад — во ВНЕШНЕМ `ГДЕ`** (`ВЫРАЗИТЬ(Субконто3 КАК Склады) В (&Склады)`), НЕ в условии ВТ. Субконто в условии ВТ Хозрасчетный.Остатки → «Неверные параметры»/«Поле не найдено».
- **Организация — во внешнем `ГДЕ` через ИЛИ-паттерн** (опциональность): `(&Организация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) ИЛИ Ост.Организация = &Организация)`. Пусто → первая часть TRUE → фильтр снят (все орг). Заполнено → фильтр по орг. ⚠️ `Организация` в УСЛОВИИ ВТ недоступна («Поле не найдено») — только внешний ГДЕ.
- **`Ост.Счет` в SELECT и GROUP** (счёт-на-строку). ⚠️ `Ост.Счет.Код` нельзя в `СГРУППИРОВАТЬ ПО` («Поле не входит в группу») — группировать по `Ост.Счет`, код читать после.
- **`УПОРЯДОЧИТЬ ПО ОбщееНазвание, Остаток УБЫВ`** — обязательно для жадного распределения. НЕ менять.
- Один и тот же склад может иметь остатки **разных юрлиц** → организация важна (на МХП ОРІЛЬ: 2051 у ІНДАСТРІАЛБУД И у ІНДЕПТ СТІЛ).

## Запрос норм — `ПолучитьНормы()`

Источник: `Справочник.СтруктураСебестоимости.Комплектующие`. Норма Σ по `ОбщееНазвание` (эталон), НЕ по номенклатуре. Фильтр по этапам (динамическое условие):

```bsl
МассивЭтапов = ЭтапыСписком();
УсловиеЭтапа = "";
Если МассивЭтапов.Количество() > 0 Тогда
	УсловиеЭтапа = ?(ИсключатьЭтапы, " И НЕ К.Этап В (&Этапы)", " И К.Этап В (&Этапы)");
КонецЕсли;
Запрос.УстановитьПараметр("Спецификация", Спецификация);
Запрос.УстановитьПараметр("Этапы", МассивЭтапов);
Запрос.Текст =
"ВЫБРАТЬ
|	К.ОбщееНазвание КАК ОбщееНазвание,
|	СУММА(К.Количество) КАК Норма
|ИЗ
|	Справочник.СтруктураСебестоимости.Комплектующие КАК К
|ГДЕ
|	К.Ссылка = &Спецификация" + УсловиеЭтапа + "
|СГРУППИРОВАТЬ ПО
|	К.ОбщееНазвание";
// результат -> Соответствие ОбщееНазвание -> Норма
```

### Ключевые факты запроса норм
- Норма агрегируется **по `ОбщееНазвание`** (эталон `Справочник.ОбщиеНазванияНоменклатуры`). Связь карточка→эталон в остатках через `Номенклатура.ОбщееНазваниеНоменклатуры`.
- `Этап` — реквизит ТЧ `Комплектующие`, тип `CatalogRef.ЭтапыРабот`. Фильтр include (`Этап В`) / exclude (`НЕ Этап В`) по флагу `ИсключатьЭтапы`. Пусто → все этапы.
- Динамическое условие через конкатенацию строки запроса (стандартный BSL `"..." + Перем + "..."`).
- Параметр `&Этапы` устанавливается всегда; если условие пустое — `&Этапы` в тексте нет, лишний параметр безвреден.

## Грабли запросов (см. также [LESSONS.md](LESSONS.md))
- `ЗначениеЗаполнено` — НЕ функция языка запросов (только BSL); пустоту проверять в коде.
- 1С-литерал в Python-`'''...'''` запросе = одинарные двойные кавычки `"2051"` (не `""2051""`); в BSL — `""2051""`.
- Python-список как `&параметр В (...)` → нужен `buh.NewObject("Массив")`.
