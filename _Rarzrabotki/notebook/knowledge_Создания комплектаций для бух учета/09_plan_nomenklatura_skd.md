# 09. Фаза 7 — план по номенклатурі + пріоритет списання + СКД-звіт

DONE 2026-06-25. Продовження Фази 6. **Розподіл кількості (кап по эталону) НЕ змінено по суті — лише порядок.**

## Рішення замовника
1. План — **по номенклатурі** (усі 107 рядків спец 000000005 мають `Номенклатура`). Кап норми лишається **по эталону** (Σ по `ОбщееНазвание`), але планові номенклатури списуються **першими**.
2. Звіт «План-факт» — **через СКД**, **вбудована** в обробку (зовнішній набір даних = таблиця аналізу).
3. План (кількість з норми) і **одиниця — по кожній номенклатурі**.

## A. Модель норми + пріоритет

- `ПолучитьНормы()` повертає `Структура("Эталон, Номенкл, ПланМассив")`:
  - `Эталон` = Соответствие ОбщееНазвание → {Кол, Сум} (кап, як Фаза 6);
  - `Номенкл` = Соответствие Номенклатура → {Кол, Сум} (план по номенклатурі — показ + flag «в плані»);
  - запит групує `(ОбщееНазвание, Номенклатура)`.
- **Пріоритет у `ЗаполнитьАнализ`**: перед жадібним циклом додати колонку `ПорядокПлан` (0 якщо `Нормы.Номенкл` містить номенклатуру, інакше 1) і `ТЗОстатки.Сортировать("ОбщееНазвание Возр, ПорядокПлан Возр, Остаток Убыв")`. Греді-ядро капу эталону — **без змін**; планові номенклатури йдуть першими → споживають норму першими, fact-only добирають залишок, далі Понад. `ПолучитьОстатки` НЕ чіпали (порядок задається в BSL сортуванням, щоб уникнути `ГРУППИРОВАТЬ ПО ВЫБОР…В(…)`).
- **План по номенклатурі на рядок**: `НормаНоменкл`/`НормаСуммаНоменкл` (нові колонки ТЧ/форм-VT, decimal 15,3 / 15,2) проставляються **на ПЕРШОМУ рядку кожної номенклатури** (Соответствие `БаченіНоменклатури`) — щоб СКД-Σ не задвоював (номенклатура трапляється на кількох складах).
- Документи (`КомплектацияНоменклатуры`) — заповнення без змін коду, але `ВНорме`/`ПонадНорму` тепер відображають пріоритет плану (значення зсуваються; баланс цілий).

## B. Звіт через СКД (вбудована, зовнішній набір даних) — РОБОЧИЙ РЕЦЕПТ

**Схема — ДИЗАЙНЕРСЬКА (Макет), НЕ програмна.** Програмна побудова `СхемаКомпоновкиДанных`+`НастройкиПоУмолчанию` у BSL давала **порожній вивід** (0×0 / лише заголовок) і для зовнішнього, і для запитового набору — не варто витрачати час. Рішення:

1. **`skd-compile`** (JSON → `Templates/МакетПланФакт/Ext/Template.xml`): набір типу **objectName** «Данные»; поля; `calculatedFields` ПроцКільк/ПроцСума/ПроцПеревищ (з `Окр(…,1)`); `totalFields` — Σ для ресурсів + **% як ресурс з агрегатним виразом** `Окр(ВЫБОР КОГДА Сумма(База)=0 ТОГДА 0 ИНАЧЕ Сумма(Факт)/Сумма(База)*100 КОНЕЦ, 1)`; `settingsVariants.structure` — об'єктна форма `[{groupFields:["ОбщееНазвание"], children:[{groupFields:["Номенклатура","Единица"]}]}]`.
2. **Маніфест**: `<Template>МакетПланФакт</Template>` у ChildObjects + файл `Templates/МакетПланФакт.xml` (метадані: Name/Synonym/TemplateType=**DataCompositionSchema**, hand-uuid). Зразок — звіт `Отчеты/А_ПланФактныйПроизводствоПолный`.
3. **ru→uk пост-обробка Template.xml** (LESSONS §14 діє і для СКД-заголовків): `<v8:lang>ru</v8:lang>` → `uk`, UTF-8 без BOM. Інакше `calculatedField.title` (lang=ru) при uk-інтерфейсі = **порожній заголовок колонки**.
4. **Рантайм** (`СформироватьПечатьПланФакт`):
```bsl
ТЗ = ДанныеВТаблицуПланФакт(ДанныеАнализа);            // ТаблицаЗначений з 8 колонок
Схема = ПолучитьМакет("МакетПланФакт");                // DataCompositionSchema
КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
Макет = КомпоновщикМакета.Выполнить(Схема, Схема.НастройкиПоУмолчанию, , , Тип("ГенераторМакетаКомпоновкиДанных"));
Процессор = Новый ПроцессорКомпоновкиДанных;
Процессор.Инициализировать(Макет, Новый Структура("Данные", ТЗ), , Истина);  // ключ = ИмяОбъекта набору
ТабДок = Новый ТабличныйДокумент;
ПВ = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
ПВ.УстановитьДокумент(ТабДок); ПВ.Вывести(Процессор);
Возврат ТабДок;
```
Форма: кнопка «Друк план-факт» → `Показать()` (як Фаза 6).

### Граблі СКД (нове — у LESSONS §31-35)
- **Python COM не вміє `Тип()`** (`buh.Тип` відсутній, рядок/NewObject не приймаються) → СКД-схему програмно в COM НЕ прототипувати; писати BSL + перевіряти COM-викликом (повертає ТабличныйДокумент, COM-інспектується).
- **Програмні `НастройкиПоУмолчанию` крихкі** (порожній вивід) → дизайнерська схема (Макет/skd-compile).
- **Зовнішній набір**: ключ `Структура` = `НаборДанных.ИмяОбъекта`; працює з дизайнерським objectName-набором.
- **Не-ресурсне не-групувальне поле (Единица) не виводиться** на рівні групи → додати `Единица` у `groupFields` групування Номенклатура.
- **% = ресурс з агрегатним виразом** (не звичайне обчислюване поле), `Окр(…,1)` для формату; захист `ВЫБОР КОГДА Сумма(База)=0`.

## Фаза 7c — умовне оформлення обох СКД-звітів (DONE 2026-06-25)

Замовник: «виділення рядків немає, читати важко» → дизайн обох звітів.

- **Палітра (traffic-light, через `conditionalAppearance` СКД):** зелений `#E2EFDA` — план у межах норми (`НормаСуммаНоменкл > 0`); янтар `#FFE699` + текст `#843C0C` — перевитрата (`НормаСуммаНоменкл > 0 І ПонадНормуСумма > 0`); білий — без плану. Діє і на рядки-групи (еталон/етап), і на деталі (за агрегатним планом групи).
- **🪤 ГРАБЛІ СКД-оформлення (LESSONS §36-38):**
  - **Колір ТІЛЬКИ HEX (`#RRGGBB`), НЕ `web:Name`.** skd-compile серіалізує `web:`/`style:` як `v8ui:Color`, але при програмному `ПроцессорВыводаРезультата…ВТабличныйДокумент` web-палітра рендериться як НЕ-абсолютний колір → COM `ЦветФона.R/.G/.B = -1` (невидимо/невіряємо). `#HEX` → абсолютний колір, рендериться, COM читає RGB. (Калібрування: ручний `Новый Цвет(210,224,240)` COM читає 210,224,240; `web:` читає -1.)
  - **Рядки-ГРУПИ фарбуються лише умовами ПО ЗНАЧЕННЮ** (`Норма > 0`), а НЕ `notFilled`. `Номенклатура notFilled` для виділення підсумкових рядків групи у програмній композиції НЕ спрацьовує; value-условие на агрегат групи — спрацьовує (еталон-рядок «Вимикач» отримав зелений #E2EFDA). Тому банди груп робимо через агрегатний план-статус, а не через targeting рівня.
  - skd-compile **не підтримує per-group `appearance`** у структурі (тільки name/groupItems/order/selection/filter/outputParameters) → крізь conditionalAppearance.
- Перевірка `smoke_komplektacii_design.py`: обидва звіти мають зелені + янтарні клітинки; структура звітів не змінилась (planfakt/planfaktetapy smoke зелені).
