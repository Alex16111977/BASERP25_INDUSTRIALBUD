# LESSONS — антипаттерны и грабли

Накоплено за фазы 1–5. Нарушение каждого = реальная ошибка в Designer/Enterprise или сломанная сборка.

## Запросы (Хозрасчетный.Остатки)

**§1. Субконто склада — во внешнем `ГДЕ`, не в условии ВТ.** Фильтр склада по субконто в Условии виртуальной таблицы `Хозрасчетный.Остатки` → «Неверные параметры». Переносить: `ГДЕ ВЫРАЗИТЬ(Субконто3 КАК Справочник.Склады) В (&Склады)`.

**§2. `Организация` в условии ВТ недоступна** («Поле не найдено Организация»), хотя это измерение регистра. Только внешний `ГДЕ Ост.Организация = …`. Опциональность — ИЛИ-паттерн `(&Организация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка) ИЛИ Ост.Организация = &Организация)`; `&Организация` можно ссылать дважды (норма).

**§3. `Ост.Счет.Код` нельзя в `СГРУППИРОВАТЬ ПО`** («Поле не входит в группу»). Группировать по `Ост.Счет` (ссылка), `.Код` читать после в коде.

**§4. Субконто счетов класса 2 ЕДИНО**: `1=Номенклатура, 2=Партії, 3=Склади` (201/205/2051/221/281/207/209). Не нужен coalesce по позициям — одно `ВЫРАЗИТЬ` на тип работает для всех счетов кл.2.

**§5. `ЗначениеЗаполнено` — НЕ функция языка запросов** (только BSL). Пустоту в запросе так не проверить.

**§6. 1С-литерал в Python vs BSL**: в Python-`'''…'''` запросе двойные кавычки одинарные (`"2051"`); в BSL-строке — удвоенные (`""2051""`). Python-список как `&параметр В (...)` → `buh.NewObject("Массив")`.

## Соответствие / структуры

**§7. `Соответствие` с ключом `Неопределено` в СКОМПИЛИРОВАННОМ модуле .epf молча теряет записи.** Standalone-COM хранит и итерирует Неопределено-ключ, но в .epf маршрутизация строк под ключ Неопределено «исчезает» (счётчик Пропущено был всегда 0). **Фикс**: не использовать Неопределено как ключ — считать `ПропущенныеСклады` явно (real ref-ключи) в `РаспределитьВДокумент`.

## ТабличныйДокумент (печать)

**§8. `ОбластьТабличногоДокумента.Граница` НЕ существует/не ставится** («Поле объекта не обнаружено (Граница)»). Границы — по сторонам: `Обл.ГраницаСверху/ГраницаСнизу/ГраницаСлева/ГраницаСправа = Новый Линия(ТипЛинииЯчейкиТабличногоДокумента.Сплошная)`.

**§9. `Область(r,1,r,9).Текст = X` на НЕобъединённой многоячеечной области ДУБЛИРУЕТ X** во все 9 ячеек (в печати 9 копий «Період/Склади/…»). Шапку-на-всю-ширину: сначала `Обл.Объединить()`, потом `Обл.Текст = X`.

**§10. Стиль работает**: `ЦветФона`, `ШиринаКолонки` (на любой ячейке колонки задаёт ширину колонки), `Шрифт(,размер,Жирный)`, `ТабДок.АвтоМасштаб=Истина` (вписать по ширине) — все COM-проверены. `ТабличныйДокумент` COM-инспектируем (`ВысотаТаблицы`, `Область().Текст`, `.Шрифт.Жирный`) — в отличие от управляемой формы.

**§11. Печать — программным `ТабличныйДокументом`, НЕ MXL-макетом.** MXL-файл в .epf несёт XDTO-риск при сборке (как `<TextColor>`). Программная сборка ячеек — гарантированно собирается + smoke-тестируема.

## Форма / Form.xml

**§12. `<TextColor>` в Form.xml внешней обработки → XDTO-ошибка сборки .epf.** Цвет (УсловноеОформление/ЦветФона) — только КОДОМ в `ПриСозданииНаСервере`.

**§13. `ЦветаСтиля.*` эталонных ERP-рабочих мест в BuhBud НЕ гарантированы** (`ВысокийПриоритетДокумента` и т.п. — ERP-токены). Использовать `Новый Цвет(r,g,b)`.

**§14. uk-подписи**: при uk-интерфейсе BuhBud `<v8:lang>ru</v8:lang>` БЕЗ uk-сиблинга рендерится ПУСТО. form-compile эмитит `ru` → пост-замена `ru→uk` по всему Form.xml (UTF-8 **без BOM** — `[System.IO.File]::WriteAllText(.., New UTF8Encoding($false))`; PS5.1 `Set-Content -Encoding UTF8` ставит BOM).

**§15. form-compile грабли**: НЕ добавлять `"group"` к объекту `"page"` (компилятор делает `<UsualGroup>` вместо `<Page>` → форма пустая). НЕ эмитит `<ShowTitle>` — вставлять regex'ом после `<Representation>`. `handlers:{Selection}` на таблице игнорит.

**§16. Designer задваивает id при сохранении формы.** Если пользователь открыл форму в Конфигураторе и сохранил — Designer переформатирует Form.xml, добавляет авто-элементы (ContextMenu/ExtendedTooltip) с новыми id и может **столкнуть id** с «ручными» XML-элементами (был дубль `id=162`: авто-подсказка ↔ команда Печать). Перед сборкой после правок в Designer — прогнать проверку уникальности id (`re.findall(r'id="(\d+)"')`), перенумеровать конфликт.

**§17. Designer хранит Title как ru+uk пару.** При сохранении в Конфигураторе переведённые колонки получают ДВА `<v8:item>` (ru и uk с одинаковым uk-текстом). uk-сиблинг уже работает; «ru→uk» = удалить лишний ru-item (НЕ менять lang ru→uk — будет два uk-item = невалидно).

## Заполнение документов

**§18. Пустой `Исключение` — антипаттерн.** Старый код глушил ошибку единицы измерения пустым `Исключение`. Заменено на `ЗначениеЗаполнено(ЕдиницаИзмерения)` + счётчик `БезЕдиниці` + лог-Предупреждение.

**§19. `ЗаполнитьДокументыПоАнализу` — опц. параметры по умолчанию** (`(ЗаполнятьВНорме = Истина, ЗаполнятьПонад = Истина)`), иначе старые smoke (вызов без аргументов) сломаются.

**§20. `Комплектующие.Очистить()` ПЕРЕД добавлением строк** — идемпотентность (повторное заполнение не задваивает).

**§21. Транзакция — без re-raise.** Оркестратор ловит исключение → ОтменитьТранзакцию + ЗаписьЖурналаРегистрации(ПодробноеПредставлениеОшибки) + структура.Помилки + возврат структуры (НЕ ВызватьИсключение). Паттерн рабочего места `ПомощникПродаж`. Форма показывает Помилки.

**§22. Документ не пишет себе А_-флаги.** `КомплектацияНоменклатуры` — нерасчётный → `Курс/Кратность/А_Обработан/А_ВведенВЕРП` НЕ нужны (в отличие от Реализация/ПКО, см. `knowledge/document_hidden_fields.md`).

## БСП / сборка

**§23. Подключение как доп.обработка требует `СведенияОВнешнейОбработке()` Экспорт** (иначе «Метод объекта не обнаружен (СведенияОВнешнейОбработке)»). См. [07](07_bsp_podklyuchenie.md).

**§24. Собирать .epf из ИЗОЛИРОВАННОГО каталога** (только наша .xml + папка) против BuhBud, иначе чужие типы соседних обработок. Перед каждой сборкой — re-sync из основной конфигурации.

**§25. COM-перепроведение/запись документов блокируется auto-классификатором, если не санкционировано пользователем.** Верификацию заполнения делать read-only (счёт строки = счёт остатка); запись в реальные документы — только с явного разрешения юзера.

## Фаза 6 (суми / одиниця / план-факт)

**§26. Python COM: `buh.КонецДня` / `buh.Дата` НЕ существуют** на объекте соединения (это глобальные функции контекста 1С, не члены COMConnector). В Python строить дату через `datetime.datetime(год, мес, день, 23, 59, 59)` (для &НаДату — конец дня). В BSL `КонецДня`/`ТекущаяДата` работают как обычно.

**§27. `python-runner`: тесты запускать ТОЛЬКО `python "<полный путь к .py>"`.** `python -c "…"` и `cd … && python rel.py` подхватывают ДРУГОЙ интерпретатор без win32com (`ModuleNotFoundError: win32com`). Полный путь к файлу → venv с win32com.

**§28. Регрессионные smoke с «магическими» абсолютными числами хрупкие** — ломаются от дрейфа живых данных или перекладки печати. Переводить на инварианты: `_otbor` — баланс (НЕ `Остаток == 34378.91`, дрейф→35458.91); `_ekonomiya` — ширина кол2 `> 0` (НЕ `== 45`, печать стала 13-колоночной). FINDINGS уже предупреждал: числа дрейфуют, стабилен баланс.

**§29. Добавление атрибута в `СГРУППИРОВАТЬ ПО` не меняет суммы, если он функционально определён уже сгруппированным полем.** `БазоваяЕдиницаИзмерения` определяется `Номенклатура` (уже в GROUP) → добавление `Единица` в группировку безопасно (granularity/итоги не меняются).

**§30. Группировка отчёта по `Соответствие` — НЕ полагаться на порядок итерации.** Для дочерних строк (номенклатура внутри эталона) вести отдельный `Массив` ключей в порядке первого появления; эталоны рендерить однопроходно по уже упорядоченным данным. `Структура`-аккумулятор итогов передаётся по ССЫЛКЕ (мутации сохраняются), номер строки (число) — по значению (возвращать).

## Фаза 7 (план по номенклатуре / СКД-отчёт)

**§31. Python COM НЕ умеет `Тип()`** (`buh.Тип` отсутствует на соединении; строка/`NewObject` как тип отвергаются: «Несоответствие типов»). → СКД-схему программно в COM НЕ прототипировать. Писать СКД в BSL (там `Тип()` работает) и проверять COM-вызовом метода (возвращает `ТабличныйДокумент`, COM-инспектируем).

**§32. Программная сборка `СхемаКомпоновкиДанных`+`НастройкиПоУмолчанию` в BSL ХРУПКА — даёт пустой вывод** (ВысотаТаблицы 0×0 или только заголовок-`ПараметрВывода`) даже без исключения, и для объектного, и для запросного набора. Потеряно ~12 циклов сборки. **Решение — ДИЗАЙНЕРСКАЯ схема**: `skd-compile` (JSON→XML) → `Templates/<Имя>/Ext/Template.xml` + метаданные `Templates/<Имя>.xml` (TemplateType=DataCompositionSchema) + `<Template>Имя</Template>` в манифесте. Рантайм: `ПолучитьМакет` → `КомпоновщикМакета.Выполнить(Схема, Схема.НастройкиПоУмолчанию, , , Тип("ГенераторМакетаКомпоновкиДанных"))` → `ПроцессорКомпоновкиДанных.Инициализировать(Макет, ВнешниеНаборы, , Истина)` → `ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент`.

**§33. Внешний набор данных СКД**: `ВнешниеНаборыДанных = Новый Структура(ИмяОбъектаНабора, ТаблицаЗначений)` — ключ = `НаборДанных.ИмяОбъекта` дизайнерской схемы. Работает с objectName-набором из skd-compile.

**§34. СКД-заголовки `calculatedField.title` (lang=ru) при uk-интерфейсе = ПУСТОЙ заголовок колонки** (LESSONS §14 распространяется на СКД). Поля НАБОРА без title рендерят авто-имя (работает); calc-поля с ru-title — пусто. Фикс: ПОСТ-замена `<v8:lang>ru</v8:lang>`→`uk` по Template.xml (UTF-8 без BOM) после skd-compile.

**§36. СКД-оформление: цвет ТОЛЬКО `#RRGGBB` (hex), НЕ `web:Name`/`style:Name`.** При программном `ПроцессорВыводаРезультата…ВТабличныйДокумент` web-палитра рендерится как НЕ-абсолютный цвет → COM `ЦветФона.R/.G/.B = -1` (не видно/не верифицируемо). `#HEX` = абсолютный цвет → рендерится + COM читает RGB. Калибровка: ручной `Новый Цвет(210,224,240)` COM читает 210,224,240; `web:Honeydew` читает -1. (skd-compile эмитит `xsi:type="xs:string"` для `#HEX` и `v8ui:Color` для `web:` — но рендерится именно hex/xs:string.)

**§37. Рядки-ГРУППЫ в СКД красятся условием ПО ЗНАЧЕНИЮ (`Поле > 0`), а НЕ `notFilled`.** conditionalAppearance с `Номенклатура notFilled` для выделения подытоговых строк группы в ПРОГРАММНОЙ композиции НЕ применяется; value-условие на агрегат группы — применяется (эталон-строка получает цвет). Банды групп делать через агрегатный статус, не через targeting уровня (skd-compile не поддерживает per-group appearance + ОбластьИспользования).

**§38. Семантическая подсветка план-факт** (traffic-light): зелёный `#E2EFDA` = `Норма>0` (в норме), янтарь `#FFE699`+текст `#843C0C` = `Норма>0 И Понад>0` (перевитрата), белый = без плана. Порядок: зелёный, потом янтарь (перекрывает). Красит и группы, и детали.

**§35. Не-ресурсное не-группировочное поле НЕ выводится на уровне группы СКД** (Единица «исчезала»). → добавить такое поле (функционально зависимое от группировки) в `groupFields` группировки (напр. `["Номенклатура","Единица"]`). **Проценты — РЕСУРС с агрегатным выражением** (`Окр(ВЫБОР КОГДА Сумма(База)=0 ТОГДА 0 ИНАЧЕ Сумма(Факт)/Сумма(База)*100 КОНЕЦ, 1)`), а не обычное вычисляемое поле, иначе на группах не считается; `Окр(…,1)` — иначе «хвост» цифр.

## Фазы 8-12 (Аналіз СС / норма-відображення / кольори / заголовок / НДС)

**§39. UUID макета `Templates/*.xml` має бути УНІКАЛЬНИМ.** Реюз `d4000000-…-002` (зайнятий іншим макетом) → **колізія**: `epf-build` exit 0, але новий макет МОВЧКИ випадає (`обр.Метаданные().Макеты` = дубль сусіда), runtime `ПолучитьМакет("X")` = «Недопустимое значение параметра (параметр номер '1')». Діагностика — ітерувати `обр.Метаданные().Макеты`. Перед білдом: `grep -o 'Template uuid' Templates/*.xml`. (Фаза 8)

**§40. Form.xml id — сканувати РЕАЛЬНИЙ max перед вставкою.** Після фаз id доходять до 272+ (НЕ 265). Завжди `grep -o 'id="[0-9]*"' | sort -n | tail`, брати наступні вільні. (Фаза 8)

**§41. СКД «ресурс лише на групі еталона» — 3 механізми:** (а) `totalField "group":["ОбщееНазвание","ОбщийИтог"]` (Рассчитывать по) НЕ гасить ресурс на дочірній групі (показує представницький рядок); (б) **per-group `selection`** (виключити поле з `selection` групи-деталі) ГАСИТЬ — робочий; (в) АЛЕ explicit per-group selection ЗАМІНЯЄ `SelectedItemAuto` → **зникають назви груп (caption порожній)**; фікс — включити **ПОЛЕ ГРУПУВАННЯ** (ОбщееНазвание/Номенклатура/Единица) в explicit selection кожної групи. Перевірка — ТІЛЬКИ COM-рендер ТабДок (`Область(r,c).Текст`), headless не ловить. (Фаза 9)

**§42. У звіті «з етапами» норму НЕ виносити на рівень групи `Этап`.** Норма еталона неподільна (штамп 1× під ПЕРШИМ етапом картки) → для мультиетапних еталонів вся норма під одним етапом, 0% під іншим при наявному факті (мисатрибуція). Норм-колонки селектити лише на групі `ОбщееНазвание`, НЕ на `Этап`. (Фаза 9b)

**§43. `conditionalAppearance` застосовується ЛИШЕ якщо поле-фільтр присутнє в `selection`.** Коли відображення норми перевели з `НормаСуммаНоменкл` (яке було у selection) на інше поле, фільтр оформлення по `НормаСуммаНоменкл` МОВЧКИ перестав фарбувати (0 кольорових клітинок; COM `ЦветФона.R=-1`). Фільтрувати по полю, що ЗАВЖДИ у selection усіх рівнів (`СуммаОстатка>0` зелений / `ПонадНормуСумма>0` янтар, правило після зеленого перекриває). (Фаза 10)

**§44. Норм-картки без залишку — union у ТЗОстатки** (`ДополнитьНоменклатуройБезОстатков`, Остаток=0, Склад/Счет=Неопределено, Эталон/Единица з `ПолучитьНормы.НоменклаДані`; виклик між `ПолучитьНормы` і `ЗаполнитьАнализ`). **Безпечно**: рядки Остаток=0 → ВНорме=0/Понад=0 → у `ПодготовитьСтрокиПоДокументам` НЕ маршрутизуються (`Если ...ВНорме>0`/`Если ...ПонадНорму>0`) → документи без порожніх рядків; кап/Економія/пріоритет (сорт Остаток Убыв ставить їх після залишкових) цілі. (Фаза 10)

**§45. Динамічний заголовок СКД:** `Настройки = Схема.НастройкиПоУмолчанию; ЭлЗаг = Настройки.ПараметрыВывода.НайтиЗначениеПараметра(Новый ПараметрКомпоновкиДанных("Заголовок")); ЭлЗаг.Значение = ТекстЗаголовка; ЭлЗаг.Использование = Истина; Выполнить(Схема, Настройки, …)`. Параметр «Заголовок» має бути в `outputParameters` схеми. `Символы.ПС` для багаторядковості. (Фаза 10)

**§46. Норма ПО КАРТЦІ vs еталон-рівень — ФІНАЛ по картці.** Еволюція: 7d по картці → 9 еталонна (бо втрата несклад.норм-карток) → **11 знову по картці** (коректно, бо Ф10 додала всі норм-картки → Σ карток = еталонна норма). `НормаНоменкл` штампується 1× на номенклатуру (`БаченіНоменклатури`), Σ на еталоні не задвоюється по складах. Форма: rebind DataPath колонки `ТАНорма`/`ТАНормаСумма` на `.НормаНоменкл`/`.НормаСуммаНоменкл` (VT має ці колонки). Субститут (в залишках, не в нормах) = 0. (Фаза 11)

**§47. НДС-нормалізація сум.** Норми у `СтруктураСебестоимости` введені **з ПДВ**, залишки на рахунках — **без ПДВ**. Факт ×1.2: `КоэффициентНДС()=1.2`; `ПолучитьОстатки`: `СУММА(Ост.СуммаОстаток) * &КоэффНДС КАК СуммаОстатка` (множення агрегату на параметр у 1С-запиті — валідне). Похідні (`ВНормеСумма`/`ПонадНормуСумма`/`ЕкономіяСума`) пропорційно з ПДВ. **БОНУС-ФІКС** `ЕкономіяСума` (було `Норма-зПДВ − Σ-безПДВ` = змішення баз). **Норму (`НормаСуммаНоменкл`) НЕ множити** — вона вже з ПДВ (інакше подвійний ПДВ у %вик/Різниця). Документи ÷1.2 (`Окр(Стр.ВНормеСумма/КоэффициентНДС(),2)`) = собівартість без ПДВ; допуск ±0.01/split-рядок (окр незалежно, різні документи, інформаційно). (Фаза 12)

**§48. Кольори/заголовок/форм-колонки — ТІЛЬКИ COM-рендер ТабДок** (`ЦветФона.R/G/B`, `Область().Текст`); керована ФОРМА headless НЕ рендериться → перевіряти в клієнті BuhBud. **Python `str(comRef)` = garbage** (НЕ назва) → завжди `ref.Наименование`; `str(uuid())` = garbage → `buh.String(uuid())`. (Фази 8-12)

**§49. `epf-build` падає «Ошибка блокировки информационной базы для конфигурирования», якщо відкритий Конфігуратор BuhBud.** Просити користувача закрити Конфігуратор (клієнт-підприємство не заважає). Діагностика: `Get-CimInstance Win32_Process -Filter "Name='1cv8.exe'"` → рядок `DESIGNER /IBName"BuhBud"` (інтерактивний, без `LoadExternal…`). (Фази 9-12)

## Фаза 13 (дві одиниці / порядок колонок / колір шапки)

**§50. Інлайн-колонка з посилання/рядка у СКД = РЕСУРС (`Максимум`), а НЕ поле-групування.** Поле у `groupFields` завжди рендериться як caption-колонка ЗЛІВА (row-header), і `selection` НЕ переставляє його в потік даних-колонок. Щоб ref/string-значення (одиниця виміру) стало ІНЛАЙН-колонкою на потрібній позиції: (1) у зовнішньому наборі писати рядком (`Строка(ref)`); (2) поле `string` БЕЗ `@dimension`, прибрати з `groupFields`; (3) додати `totalField` `Максимум(Поле)` (СКД `Максимум` валідний на рядках); (4) поставити у `selection` де треба. Числові міри інлайн саме тому, що вони ресурси (`Сумма`). (Фаза 13, спайк)

**§51. Пряме присвоєння `ЦветФона`/`ЦветТекста` на вже виведеному СКД-ТабДок НЕ перебиває умовне оформлення** (перевірено COM: навіть явний білий не змінює клітинку). Пост-BSL-скид кольору шапки — марний. Щоб оформлення (traffic-light) НЕ фарбувало шапку-заголовок/заголовки полів/параметри, а лише дані — звузити **область застосування** у `<dcsset:item>` conditionalAppearance: `<dcsset:useInFieldsHeader>DontUse</…>`, `<dcsset:useInHeader>DontUse</…>`, `<dcsset:useInParameters>DontUse</…>` (після `</dcsset:appearance>`; групи/деталі лишаються Auto → дані фарбуються). skd-compile це не емітить → пост-інжект (`postprocess_skd_appearance.py`). Еталон XML: `BASEBuh/Reports/РеестрДокументов/…/Template.xml`. Перевірка ТІЛЬКИ COM `ЦветФона.R/G/B` (шапка -1/-1/-1). (Фаза 13)

**§53. По-етапна розшивка звіту, коли факт не має розрізу «Этап».** Остатки (Хозрасчетный) не мають этапу — тільки норма (СС `Комплектующие.Этап`). Колапс картки на перший этап (Фаза 7b) спотворює по-етапні норму/факт/економію для багатоетапних карток/еталонів. Коректна модель (Этап×Еталон, `ДанныеПоЭтапам`): норма — реальна по-етапна з СС; факт/ВНорме/Понад картки розкидати **∝ по-етапній нормі** (Коеф=Кол_s/ΣКол, множенням БЕЗ Окр → Σ зберігається з точністю до float-шуму ~1e-9, ховається форматуванням СКД — прийнятий допуск, adversarial review Ф16); економія по (еталон,этап) ∝ нормі, **резидуум округлення на 1-й рядок групи** (точний Σ; residuum ловить і key-mismatch між нормо-этапами та фрагмент-групами). Еталон-рівневі `Норма`/`НормаСумма` у per-stage ТЗ не заповнюються — схема etapy їх НЕ читає (немає у fields). Валідувати Python-прототипом (Σфрагментів=Σкарток) ДО BSL; COM-перевірка: підсумки «Итого» == не-етапний звіт. **§7-нюанс:** порожній этап як ключ Соответствия → рядковий сентинел (`"__БЕЗЭТАПУ__"`), НЕ Неопределено; мапити сентинел→Неопределено лише у ЗНАЧЕННІ колонки Этап (для «без этапу» групи СКД). Розширювати `ПолучитьНормы` тільки АДИТИВНО (нові поля у Структуру-повернення; старі ключі цілі → інші звіти не ламаються). (Фаза 16)

**§52. skd-compile додає BOM у Template.xml** — типові макети БЕЗ BOM. Пост-скрипт має читати `utf-8-sig` (прибирає BOM) і писати `utf-8` без BOM (`open(...,'w',encoding='utf-8',newline='')`). Інакше BOM накопичується. (Фаза 13)
