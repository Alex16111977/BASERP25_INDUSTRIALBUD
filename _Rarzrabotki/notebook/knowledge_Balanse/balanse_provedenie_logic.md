## 0. Головний принцип (3 правила)

1. **Суми — ЗАВЖДИ з `РегистрНакопления.ПрочиеАктивыПассивы.ОстаткиИОбороты`** (ПАП). Жодного UNION з регістрів-джерел задля сум. Це той самий ПАП, що бере штатний `Отчёт.УправленческийБаланс`.
2. **Субконто — гібрид:** `ПАП.Аналитика` декодується через `ВЫРАЗИТЬ` (типи, що мають окремий вимір); решта розшифровки приходить **LEFT JOIN із предагрегованих типових регістрів за `Регистратор`** (fill-when-unique).
3. **`Регистратор` (не `ИдентификаторФинЗаписи`!)** — ключ зв'язку ПАП↔джерело. `ВЫРАЗИТЬ` тільки в SELECT; `СГРУППИРОВАТЬ ПО Б.Аналитика` (composite як-є) — винесення `ВЫРАЗИТЬ` у GROUP BY злило б групи через NULL і втратило Σ.

**Пост-інваріант:** Σ `СуммаКонечныйОстаток` по `Статья` після згортки == ПАП по `Статья` до копійки. Розклад «Оплата труда» зберігає Σ (Σ ваг = 1).

## 1. Структура запиту: ланцюг тимчасових таблиць (ВТ)

`СформироватьЗапросСверткиБаланса()` будує один великий запит із серії `ПОМЕСТИТЬ`-ВТ, далі 3-частинний `ОБЪЕДИНИТЬ ВСЕ`.

### 1.1. Предагреговані субконто-джерела (по `Регистратор`, ≤1 рядок на ключ)

| ВТ | Джерело | Дає субконто | Логіка унікальності |
|---|---|---|---|
| `втРасчКл` | `РегистрНакопления.РасчетыСКлиентами` | `ОбъектРасчетов` | `МИНИМУМ(ОбъектРасчетов)` + `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ОбъектРасчетов) КАК Кол`, `СГРУППИРОВАТЬ ПО Регистратор` |
| `втРасчПост` | `РегистрНакопления.РасчетыСПоставщиками` | `ОбъектРасчетов` | те саме |
| `втСебест` | `РегистрНакопления.СебестоимостьТоваров` | `Номенклатура` (`АналитикаУчетаНоменклатуры.Номенклатура`), `Склад` (`…МестоХранения` ВЫРАЗИТЬ Склады) | `МИНИМУМ` + `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ)` КолНом/КолСкл, `СГРУППИРОВАТЬ ПО Регистратор` |
| `втДенБ` | `РегистрНакопления.ДенежныеСредстваБезналичные` | `ДенСр` = `БанковскийСчет` | `МИНИМУМ(БанковскийСчет)` + КолДС, по Регистратор |
| `втДенН` | `РегистрНакопления.ДенежныеСредстваНаличные` | `ДенСр` = `Касса` | `МИНИМУМ(Касса)` + КолДС, по Регистратор |

Усі — за `Период МЕЖДУ &НачалоПериода И &КонецПериода`. **`Кол`/`КолНом`/…** — лічильники різноманіття: субконто підставляється **тільки якщо унікальне на регістратор** (`Кол=1`), інакше порожнє (свёд балансовий, не детальні взаєморозрахунки).

### 1.2. `втРегПАП` — регістратори ПАП у періоді

```
ВЫБРАТЬ РАЗЛИЧНЫЕ Б.Регистратор, Б.Статья, Б.Организация, Б.Подразделение, Б.Аналитика
ПОМЕСТИТЬ втРегПАП
ИЗ РегистрНакопления.ПрочиеАктивыПассивы.Обороты(
    &НачалоПериода, &КонецПериода, Регистратор,
    (орг+ВключатьДочерние) И НЕ Статья В ИЕРАРХИИ(&ИсключенныеСтатьи)) КАК Б
```
Дає набір (Регистратор, Статья, Орг, Підр, Аналітика) — «хто і по якій статті рухав ПАП».

### 1.3. `втОБ` — зведена картка субконто на (Орг, Підр, Стаття, Аналітика)

`втРегПАП` **LEFT JOIN** усі 5 предагрегованих ВТ по `Регистратор`, групування по (Организация, Подразделение, Статья, Аналитика). Накопичує по групі:
- `КолОР`/`ОбъектРасчетов` = `ЕСТЬNULL(К.ОбъектРасчетов, П.ОбъектРасчетов)` (клієнти або постачальники);
- прапори `ЕстьКл`/`ЕстьПост`/`ЕстьСеб`/`ЕстьДенБ`/`ЕстьДенН` = чи був матч відповідного регістра по Регистратору;
- `КолНом`/`Номенклатура`, `КолСкл`/`Склад`, `КолДС`/`ДенСр`.

### 1.4. ВТ розкладу «Оплата труда» (Етап 4)

| ВТ | Зміст |
|---|---|
| `втЗПСальдо` | `РегистрНакопления.ВзаиморасчетыССотрудниками` за `Период <= &КонецПериода`, групування по (Организация, ФизическоеЛицо), `Сальдо = Σ(Приход: +Сумма, інакше −Сумма)`, `ИМЕЮЩИЕ Сальдо <> 0` (кумулятив до кінця періоду) |
| `втЗПФЛ` | `Вес = |Сальдо|` по (Организация, ФизическоеЛицо) |
| `втЗПОрг` | `СумВес = Σ Вес` по Организация |

Розклад: сума «Оплата труда» по орг множиться на `Вес / СумВес` per ФізОсоба. **`Σ ваг = СумВес/СумВес = 1`** → Σ по статті зберігається == ПАП.

## 2. Фінальний `ОБЪЕДИНИТЬ ВСЕ` — 3 частини

### Частина A — усі статті КРІМ «Оплата труда» (Етапи 1-3)

Джерело сум: `ПАП.ОстаткиИОбороты(&НачП, &КонП, Авто, , (орг) И НЕ Статья В ИЕРАРХИИ(&ИсключенныеСтатьи) И Статья <> &СтатьяОплатаТруда)` **LEFT JOIN `втОБ`** по (Организация, Подразделение, Статья, Аналитика).

Субконто-виміри (з `ВЫРАЗИТЬ(Б.Аналитика КАК …)` + `втОБ` fill-when-unique):
- `Номенклатура` = `ОБ.Номенклатура` якщо `КолНом=1`, інакше ПустаяСсылка;
- `Контрагент` = `ЕСТЬNULL(ВЫРАЗИТЬ(Аналитика КАК Контрагенты), ВЫРАЗИТЬ(Аналитика КАК Организации))`;
- `Партнер` = `ВЫРАЗИТЬ(Аналитика КАК Партнеры)`;
- `Склад` = `ОБ.Склад` якщо `КолСкл=1`;
- `ОбъектыЭксплуатации` = `ВЫРАЗИТЬ(Аналитика КАК ОбъектыЭксплуатации)`;
- `ФизическоеЛицо` = `ВЫРАЗИТЬ(Аналитика КАК ФизическиеЛица)`;
- `ДенежныеСредства` = `ОБ.ДенСр` якщо `КолДС=1`;
- `НематериальныйАктив` = `ВЫРАЗИТЬ(Аналитика КАК НематериальныеАктивы)`;
- `Договор` = ПустаяСсылка (не заповнюється у свёде);
- `ОбъектРасчетов` = `ОБ.ОбъектРасчетов` якщо `КолОР=1`.

**`Source` — динамічний CASE по пріоритету** (ключова відмінність від плану):
```
ВЫБОР
  КОГДА ОБ.ЕстьКл=1   ТОГДА Перечисление.А_ИсточникБаланса.РасчетыСКлиентами
  КОГДА ОБ.ЕстьПост=1 ТОГДА Перечисление.А_ИсточникБаланса.РасчетыСПоставщиками
  КОГДА ОБ.ЕстьСеб=1  ТОГДА Перечисление.А_ИсточникБаланса.СебестоимостьТоваров
  КОГДА ОБ.ЕстьДенБ=1 ТОГДА Перечисление.А_ИсточникБаланса.ДенежныеСредстваБезналичные
  КОГДА ОБ.ЕстьДенН=1 ТОГДА Перечисление.А_ИсточникБаланса.ДенежныеСредстваНаличные
  ИНАЧЕ Перечисление.А_ИсточникБаланса.ПрочиеАктивыПассивы
КОНЕЦ
```
`Аналитика1=""`, `Аналитика2=""`, `Аналитика3=ПРЕДСТАВЛЕНИЕ(Б.Аналитика)` (аудит-рядок). 4 ресурси = `Σ` НачОст/Приход/Расход/КонОст з ПАП. `ИМЕЮЩИЕ` відсікає рядки, де всі 4 суми = 0.

### Частина B1 — «Оплата труда», організації З `ВзаиморасчетыССотрудниками`

`ПАП.ОстаткиИОбороты(… И Статья = &СтатьяОплатаТруда)` **ВНУТРЕННЕЕ СОЕДИНЕНИЕ** `втЗПОрг` + `втЗПФЛ` по Организация. Кожна сума множиться на `ЗПФЛ.Вес / ЗПОрг.СумВес`, групування додатково по `ЗПФЛ.ФизическоеЛицо`. Усі інші виміри — ПустаяСсылка; `ФизическоеЛицо` заповнено; `Source = ПрочиеРасходы`; `Аналитика3 = ПРЕДСТАВЛЕНИЕ(Б.Аналитика)`.

### Частина B2 — «Оплата труда», організації БЕЗ `ВзаиморасчетыССотрудниками`

`ПАП.ОстаткиИОбороты(… И Статья = &СтатьяОплатаТруда)` **LEFT JOIN `втЗПОрг`**, `ГДЕ ЗПОрг.Организация ЕСТЬ NULL` → 1 рядок на (Орг,Підр,Стаття,Аналітика), повна сума, `ФизическоеЛицо` порожнє, `Source = ПрочиеРасходы`.

> B1+B2 разом дають Σ по «Оплата труда» == ПАП (розклад зберігає суму; орг без ВЗ — нерозкладена повна сума).

## 3. Виключені статті (канон OD-3, closed-period-safe)

`ИсключенныеСтатьи` = `СтатьиАктивовПассивов` за `Наименование В ("Собственные средства","Доходы текущего периода","Расходы текущего периода")`. Застосовується `НЕ Статья В ИЕРАРХИИ(&ИсключенныеСтатьи)` у ВСІХ ПАП-вибірках. Повторює робочий **варіант** штатного `Отчёт.УправленческийБаланс` «Не в группе из списка».

**Чому не ламає Актив=Пасив:** свёд проводиться лише за **закриті** місяці, де ці 3 групи мають `КонОст=0` (поточний P&L згорнуто) → Σ КонОст з фільтром = без фільтра = 0.00. У відкритому місяці `Расходы текущего периода` ще накопичується → фільтр зламав би баланс (тому свёд тільки для закритих періодів; контроль — Σ КонОст≈0 у Test 3).

`Прибыли и убытки` **НЕ виключається** (окрема коренева стаття, лишається в балансі).

## 4. Етапи (усі реалізовані та live)

| Етап | Що додає | Механізм |
|---|---|---|
| **1** | суми всіх статей + субконто прямо з `ПАП.Аналитика` для ОЗ/НМА; `Source=ПрочиеАктивыПассивы`; 0 JOIN | базова `ПАП.ОстаткиИОбороты` + `ВЫРАЗИТЬ` |
| **2** | `ОбъектРасчетов` для статей із рухами клієнтів/постачальників; `Source=РасчетыС…` | `втРасчКл`/`втРасчПост` LEFT JOIN по Регистратор |
| **3** | `Номенклатура`/`Склад`/`ДенежныеСредства` для товарних/грошових; `Source=Себест/ДенСр…` | `втСебест`/`втДенБ`/`втДенН` |
| **4** | «Оплата труда» → `ФизическоеЛицо` пропорційно сальдо; `Source=ПрочиеРасходы` | `втЗПСальдо`→`втЗПФЛ`→`втЗПОрг`, UNION B1/B2 |

**Етапи не фіксують Source per-стаття.** Source — наслідок того, який типовий регістр матчиться з `Регистратор`-ом конкретного руху ПАП. Тому одна стаття може мати кілька Source одночасно (емпірика — у [balanse_mapping_actual_vs_planned.md](balanse_mapping_actual_vs_planned.md) §3).
