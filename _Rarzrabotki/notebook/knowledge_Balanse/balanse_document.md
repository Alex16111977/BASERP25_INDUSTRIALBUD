# Документ `А_ФинРез_Баланс` — призначення, реквізити, заповнення, проведення

> Джерело: `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl` (live, проведено). Канон §2, §6.
> Тип файлу: ПОСТІЙНИЙ (змінюється тільки при правці модуля/реквізитів).

---

## 1. Призначення

`Документ.А_ФинРез_Баланс` — **кастомний** (`А_`-префікс) службовий документ, який **раз на місяць по організації** формує згортку управлінського балансу та записує її у `РегистрСведений.А_ОтчетБаланс_Свод` (документ є **Регистратором** цього регістра відомостей).

Призначення — дати OLAP/Power BI готову фактаблицю балансу по статтях з аналітикою, **не змінюючи** типові регістри (вся логіка згортки інкапсульована у проведенні цього кастомного документа). Свёд повторює ПАП-джерело штатного `Отчёт.УправленческийБаланс`, але з розшифровкою субконто.

---

## 2. Реквізити шапки

| Реквізит | Тип | Призначення |
|---|---|---|
| `Организация` | Справочник.Организации | За якою юр.особою формувати баланс |
| `Месяц` | Дата | Місяць згортки (період = `НачалоМесяца(Месяц)` … `КонецМесяца(Месяц)`) |
| `ВключатьДочерние` | Булево | `Истина` → `Организация В ИЕРАРХИИ(&Организация)`; `Ложь` → строго `= &Организация` |
| `Ответственный` | — | службовий |
| `Комментарий` | Строка | службовий |

Структуру **веде фінансист вручну** — AI не змінює реквізити документа/виміри регістра (канон §10, OD-9).

## 3. `ОбработкаЗаполнения`

```bsl
Процедура ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)
    Если НЕ ЗначениеЗаполнено(Организация) Тогда
        Организация = А_Привилегированный.А_ПолучитьОрганизациюУпр();
    КонецЕсли;
    Если НЕ ЗначениеЗаполнено(Месяц) Тогда
        Месяц = НачалоМесяца(ТекущаяДатаСеанса());
    КонецЕсли;
КонецПроцедуры
```

- `Организация` за замовч. — управлінська організація з `А_Привилегированный.А_ПолучитьОрганизациюУпр()`.
- `Месяц` за замовч. — початок поточного місяця.

## 4. `ОбработкаПроведения` — потік (інваріант для всіх етапів)

Послідовність (повний код — у [balanse_provedenie_logic.md](balanse_provedenie_logic.md)):

1. **Межі періоду:** `НачМесяца = НачалоМесяца(Месяц)`, `КонМесяца = КонецМесяца(Месяц)`.
2. **Дублікат-захист** (див. §5) — якщо за цю Організацію+Місяць+ВключатьДочерние вже є проведений документ → `Отказ = Истина`, повідомлення, `Возврат`.
3. **Виключені статті** (канон OD-3): `ИсключенныеСтатьи` = посилання на 3 групи `СтатьиАктивовПассивов` за `Наименование В ("Собственные средства","Доходы текущего периода","Расходы текущего периода")`.
4. **Стаття «Оплата труда»:** `СтатьяОплатаТруда` = `ПланВидовХарактеристик.СтатьиАктивовПассивов` з `Наименование = "Оплата труда"` (для Етапу 4 — окремий розклад по ФізОсобі).
5. `Движения.А_ОтчетБаланс_Свод.Записывать = Истина;`
6. Текст запиту = `СформироватьЗапросСверткиБаланса()`; параметри: `&НачалоПериода=НачМесяца`, `&КонецПериода=КонецДня(КонМесяца)`, `&Организация`, `&ВключатьДочерние`, `&ИсключенныеСтатьи`, `&СтатьяОплатаТруда`.
7. `Движения.А_ОтчетБаланс_Свод.Загрузить(Запрос.Выполнить().Выгрузить());` — наповнення регістра однією дією (`Загрузить`, не порядкова запис).

> Параметр `&КонецПериода` = `КонецДня(КонМесяца)` — щоб захопити всі рухи останнього дня місяця.

## 5. Дублікат-захист (анти-подвійне проведення)

Перший крок проведення — перевірка, що за цю ж `Организация` + `Месяц` (між `НачМесяца` і `КонМесяца`) + `ВключатьДочерние` ще немає **іншого** проведеного непомеченого документа:

```bsl
ВЫБРАТЬ ПЕРВЫЕ 1 ФР.Номер, ФР.Дата
ИЗ Документ.А_ФинРез_Баланс КАК ФР
ГДЕ ФР.Ссылка <> &ТекущийДок И НЕ ФР.ПометкаУдаления И ФР.Проведен
    И ФР.Организация = &Организация
    И ФР.Месяц МЕЖДУ &НачМесяца И &КонМесяца
    И ФР.ВключатьДочерние = &ВключатьДочерние
```

Якщо знайдено — проведення відхиляється з повідомленням «Не можна провести: за &Месяц (Організація &Орг) вже проведено документ №&Номер від &Дата».

## 7. Особливості

- **Перепроведення ідемпотентне:** регістр повністю перезаписується рухами (`Загрузить`), дублікат-захист не дає двох документів на період.
- **`ОбменДанными.Загрузка`** не використовується — це кастомний документ, не бере участі в обміні.
- **Типові регістри лише читаються** (канон §10): жодних рухів/змін структури `ПрочиеАктивыПассивы`, `РасчетыС*`, `СебестоимостьТоваров`, `ДенежныеСредства*`, `ВзаиморасчетыССотрудниками` — лише `SELECT`/`.ОстаткиИОбороты`/`.Обороты`.
- Дати у Python — **опівдні** (`12:00`/`14:00`), не північ, щоб уникнути TZ-зсуву через границю періоду (задокументовано в каноні §5/§7).
