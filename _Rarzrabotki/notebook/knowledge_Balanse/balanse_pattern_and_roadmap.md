## §2 КАНОН-ОБРАЗЕЦЬ: `Свод_СебестоимостьТоваров` (2026-05-17)

**Сигнатура (НЕ міняти):** `Функція Свод_СебестоимостьТоваров(СтруктураШапки,
Отказ) Экспорт ... Отразить_Свод(Запрос.Выполнить().Выгрузить()); Возврат
Истина; КонецФункции`

**Параметри:** `Орг`=СтруктураШапки.Организация, `НачМес`=СтруктураШапки.НачМес,
`КонМес`=СтруктураШапки.КонМес, `Искл`=`ИсключенныеСтатьи()` (пишеться через
«е»; масив ПВХ.СтатьиАктивовПассивов «Собственные средства»/«Доходы текущего
периода»/«Расходы текущего периода» — фільтр OD-3).

**Структура запиту — ОДИН пакет з 4× `ПОМЕСТИТЬ` + фінальний `ОБЪЕДИНИТЬ ВСЕ`:**

1. `ПОМЕСТИТЬ втСеб` — детальна розшифровка ПО ЗАЛИШКАХ з
   `РегистрНакопления.СебестоимостьТоваров.ОстаткиИОбороты(&НачМес,&КонМес,,,
   Организация=&Орг И (РазделУчета=ТоварыНаСкладах ИЛИ ТоварыПереданныеНаКомиссию))`
   `ЛЕВОЕ СОЕДИНЕНИЕ Справочник.КлючиАналитикиУчетаНоменклатуры`.
   - Подразделение = `ЕСТЬNULL(Аналитика.МестоХранения.Подразделение,
     ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка))`
   - Статья = малий `ВЫБОР` по `ТипСклада`/`ТипМестаХранения`
     (ТоварыВРознице / ТоварыНаОптовыхСкладах /
     ТоварыКОформлениюОтчетовКомитенту / ТоварыПереданныеНаКомиссию)
   - Source = `ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.СебестоимостьТоваров)`
   - Номенклатура = Аналитика.Номенклатура; Склад = `ВЫРАЗИТЬ(Аналитика.
     МестоХранения КАК Справочник.Склады)`
   - СуммаНачальныйОстаток/СуммаКонечныйОстаток = `СУММА(Стоимость +
     ДопРасходы + Трудозатраты + ПостатейныеПостоянныеСНДС +
     ПостатейныеПеременныеСНДС [Начальный/Конечный]Остаток)`
2. `ПОМЕСТИТЬ втСебСт` — `СУММА` втСеб по `(Организация,Подразделение,Статья)`.
3. `ПОМЕСТИТЬ втПАП` — `РегистрНакопления.ПрочиеАктивыПассивы` ОСНОВНА
   таблиця, signed: НО=Σ(signed де Период<&НачМес), КО=Σ(signed по
   Период<=&КонМес), signed = `ВЫБОР Приход +Сумма ИНАЧЕ -Сумма`,
   фільтр `Источник=ЗНАЧЕНИЕ(...СебестоимостьТоваров) И НЕ Статья В
   ИЕРАРХИИ(&Искл)`, групування `(Орг,ЕСТЬNULL(Подр,пуста),Статья)`.
4. `ПОМЕСТИТЬ втКлючи` — `ВЫБРАТЬ РАЗЛИЧНЫЕ (Орг,Подр,Статья)` з
   `ОБЪЕДИНИТЬ ВСЕ втПАП ∪ втСебСт` (емуляція FULL JOIN — у мові 1С немає).
5. Фінал `ОБЪЕДИНИТЬ ВСЕ`:
   - **деталі** `ИЗ втСеб` (Расхождение=ЛОЖЬ, Приход=Расход=0,
     ДокументДвижения порожній);
   - **плуги**: `втКлючи ЛЕВОЕ втПАП ЛЕВОЕ втСебСт`, рядок-плуг де
     `|ЕСТЬNULL(втПАП.НО,0)-ЕСТЬNULL(втСебСт.НО,0)|>0.01` АБО по КО:
     Номенклатура/Склад = `ЗНАЧЕНИЕ(...ПустаяСсылка)`, **Расхождение=ИСТИНА**,
     СуммаНачальныйОстаток=Δ_НО, СуммаКонечныйОстаток=Δ_КО.

**Принцип плуга (за побудовою):** Σ(деталі+плуг) на ключі =
`втСебСт + (втПАП − втСебСт) = втПАП` → точна рівність ПАП на кожному
`(Орг,Подр,Статья)`. Аномалії розшуку миттєво знаходяться фільтром
`Расхождение=Истина` (порожні Ном/Склад). На січень/ТОВ розлёт=0 → **плугів 0**
(розшифровка вже точно сходиться), але механізм реалізований і доведений.

**Інваріант (остатки-only):** `СуммаПриход=0`, `СуммаРасход=0`,
`ДокументДвижения` порожній у ВСІХ рядків Себестоимости; деталі
`Расхождение=Ложь` зі заповненими Ном/Склад; плуги `Расхождение=Истина`
з порожніми Ном/Склад.

## §4 Знахідки сесії 2026-05-17 (критичні, не виводяться з коду)

### 4.1 «Запись с такими ключевыми полями существует!» — це СИРОТИ РС, не баг свода

`РегистрСведений.А_ОтчетБаланс_Свод` — `WriteMode=RecorderSubordinate`,
непериодичний; ключ уникальності фактично **глобальний по вимірах**. Якщо
в регістрі лежать записи від **видалених** документів (регістратор =
`<Объект не найден>`), будь-який новий запис із тим самим набором вимірів
падає дублем — навіть запис ОДНОГО рядка нового регістратора.

**Причина накопичення:** `Документ.А_ФинРез_Баланс.Удалить()` (через
`ОбменДанными.Загрузка=Истина`) **НЕ видаляє рухи підлеглого регістру** —
залишаються сироти. Тестові прогони з `Удалить()` їх накопичують.

**Діагностика першочергова:** при дублі ключа спершу
`ВЫБРАТЬ КОЛИЧЕСТВО(*), КОЛИЧЕСТВО(РАЗЛИЧНЫЕ Регистратор) ИЗ
РегистрСведений.А_ОтчетБаланс_Свод` та типи регістраторів — НЕ правити
запит свода. **Очищення сирот:** по кожному РАЗЛИЧНЫЙ Регистратор —
`СоздатьНаборЗаписей()` з відбором по регістратору → `Записать()` порожнім.
Скрипт: `_Rarzrabotki/Python/cleanup_otchetbalans_svod_orphans.py`.

### 4.1бис РЕШЕНО 2026-05-18 — постійний фікс (валідні документи, не лише сироти)

Глобальна уникальність по вимірах ламала проведення і для ВАЛІДНИХ
документів: 2-й+ місяць (січень блокував грудень/лютий) через org-рівневі
рядки-плуги (Расхождение=Истина, Подр/субконто порожні), однакові щомісяця.
**Фікс БЕЗ зміни структури РС і без зміни канон-`Свод_*`:** в оркестраторі
`ПровестиБалансСвод` перед `мТЗСвод.Свернуть(...)` додано
`мТЗСвод.ЗаполнитьЗначения(СтруктураШапки.Ссылка, "ДокументДвижения");`.
`ДокументДвижения` — наявний вимір РС (складений DocumentRef з
Документ.А_ФинРез_Баланс, вже у списку Свернуть; ETL `fact_balance.json`
його НЕ читає → OLAP не зачеплено). Кожен документ → своя ссилка →
рядки унікальні між документами, місяці співіснують. Перевірено:
грудень2025+січень2026+лютий2026 проведено, 3 регістратори (22644 рядки),
січень без регресії (Себест 83 627 719,44 / ДенСр 75 265 344,95 / клієнти
12 338 631,09 / постач −62 806 237,00). Тести
`post_balans_multi_dec_jan_feb.py` / `verify_jan_regression_after_fix.py`.
Структурну правку РС (Регистратор у ключ) харнес-класифікатор блокує —
обходити не можна; цей фікс через наявний вимір її замінює. **Сироти від
`Удалить()` — окрема історія (4.1), фіксяться cleanup-скриптом.**

### 4.2 Харнесс тестів проведення — НЕ `Удалить()`, а перепроведення

У `test_balans_s3b_seb_subconto_verify.py` (та аналогічних): **не**
видаляти документи; брати існуючий `А_ФинРез_Баланс` за період (get-or-
create) і **перепроводити** (`Записать(РежимЗаписиДокумента.Проведение)`
штатно замінює рухи регістратора, сирот НЕ плодить). Пошук документа —
**по межах місяця** (`Месяц >= &НМ И Месяц <= &КД`), бо реквізит `Месяц`
зберігається як НачалоМесяца `00:00:00`, а параметр-дата періоду —
опівдні `12:00:00`; точне `Месяц=&М` не знаходить → створює дубль →
спрацьовує штатний дубль-захист `ОбработкаПроведения`.
