## §2 КАНОН-ОБРАЗЕЦЬ: `Свод_СебестоимостьТоваров` (2026-05-17)

**Сигнатура (НЕ міняти):** `Функція Свод_СебестоимостьТоваров(СтруктураШапки,
Отказ) Экспорт ... Отразить_Свод(Запрос.Выполнить().Выгрузить()); Возврат
Истина; КонецФункции`

**Параметри:** `Орг`=СтруктураШапки.Организация, `НачМес`=СтруктураШапки.НачМес,
`КонМес`=СтруктураШапки.КонМес, `Искл`=`ИсключенныеСтатьи()` (пишеться через
«е»; масив ПВХ.СтатьиАктивовПассивов «Собственные средства»/«Доходы текущего
периода»/«Расходы текущего периода» — фільтр OD-3).

**Структура запиту — ОДИН пакет з 4× `ПОМЕСТИТЬ` + фінальний `ОБЪЕДИНИТЬ ВСЕ`:**

1. `ПОМЕСТИТЬ втСеб` — детальна розшифровка ПО ЗАЛИШКАХ з
   `РегистрНакопления.СебестоимостьТоваров.ОстаткиИОбороты(&НачМес,&КонМес,,,
   Организация=&Орг И (РазделУчета=ТоварыНаСкладах ИЛИ ТоварыПереданныеНаКомиссию))`
   `ЛЕВОЕ СОЕДИНЕНИЕ Справочник.КлючиАналитикиУчетаНоменклатуры`.
   - Подразделение = `ЕСТЬNULL(Аналитика.МестоХранения.Подразделение,
     ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка))`
   - Статья = малий `ВЫБОР` по `ТипСклада`/`ТипМестаХранения`
     (ТоварыВРознице / ТоварыНаОптовыхСкладах /
     ТоварыКОформлениюОтчетовКомитенту / ТоварыПереданныеНаКомиссию)
   - Source = `ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.СебестоимостьТоваров)`
   - Номенклатура = Аналитика.Номенклатура; Склад = `ВЫРАЗИТЬ(Аналитика.
     МестоХранения КАК Справочник.Склады)`
   - СуммаНачальныйОстаток/СуммаКонечныйОстаток = `СУММА(Стоимость +
     ДопРасходы + Трудозатраты + ПостатейныеПостоянныеСНДС +
     ПостатейныеПеременныеСНДС [Начальный/Конечный]Остаток)`
2. `ПОМЕСТИТЬ втСебСт` — `СУММА` втСеб по `(Организация,Подразделение,Статья)`.
3. `ПОМЕСТИТЬ втПАП` — `РегистрНакопления.ПрочиеАктивыПассивы` ОСНОВНА
   таблиця, signed: НО=Σ(signed де Период<&НачМес), КО=Σ(signed по
   Период<=&КонМес), signed = `ВЫБОР Приход +Сумма ИНАЧЕ -Сумма`,
   фільтр `Источник=ЗНАЧЕНИЕ(...СебестоимостьТоваров) И НЕ Статья В
   ИЕРАРХИИ(&Искл)`, групування `(Орг,ЕСТЬNULL(Подр,пуста),Статья)`.
4. `ПОМЕСТИТЬ втКлючи` — `ВЫБРАТЬ РАЗЛИЧНЫЕ (Орг,Подр,Статья)` з
   `ОБЪЕДИНИТЬ ВСЕ втПАП ∪ втСебСт` (емуляція FULL JOIN — у мові 1С немає).
5. Фінал `ОБЪЕДИНИТЬ ВСЕ`:
   - **деталі** `ИЗ втСеб` (Расхождение=ЛОЖЬ, Приход=Расход=0,
     ДокументДвижения порожній);
   - **плуги**: `втКлючи ЛЕВОЕ втПАП ЛЕВОЕ втСебСт`, рядок-плуг де
     `|ЕСТЬNULL(втПАП.НО,0)-ЕСТЬNULL(втСебСт.НО,0)|>0.01` АБО по КО:
     Номенклатура/Склад = `ЗНАЧЕНИЕ(...ПустаяСсылка)`, **Расхождение=ИСТИНА**,
     СуммаНачальныйОстаток=Δ_НО, СуммаКонечныйОстаток=Δ_КО.

**Принцип плуга (за побудовою):** Σ(деталі+плуг) на ключі =
`втСебСт + (втПАП − втСебСт) = втПАП` → точна рівність ПАП на кожному
`(Орг,Подр,Статья)`. Аномалії розшуку миттєво знаходяться фільтром
`Расхождение=Истина` (порожні Ном/Склад). На січень/ТОВ розлёт=0 → **плугів 0**
(розшифровка вже точно сходиться), але механізм реалізований і доведений.

**Інваріант (остатки-only):** `СуммаПриход=0`, `СуммаРасход=0`,
`ДокументДвижения` порожній у ВСІХ рядків Себестоимости; деталі
`Расхождение=Ложь` зі заповненими Ном/Склад; плуги `Расхождение=Истина`
з порожніми Ном/Склад.

## §4 Знахідки сесії 2026-05-17 (критичні, не виводяться з коду)

### 4.1 «Запись с такими ключевыми полями существует!» — це СИРОТИ РС, не баг свода

`РегистрСведений.А_ОтчетБаланс_Свод` — `WriteMode=RecorderSubordinate`,
непериодичний; ключ уникальності фактично **глобальний по вимірах**. Якщо
в регістрі лежать записи від **видалених** документів (регістратор =
`<Объект не найден>`), будь-який новий запис із тим самим набором вимірів
падає дублем — навіть запис ОДНОГО рядка нового регістратора.

**Причина накопичення:** `Документ.А_ФинРез_Баланс.Удалить()` (через
`ОбменДанными.Загрузка=Истина`) **НЕ видаляє рухи підлеглого регістру** —
залишаються сироти. Тестові прогони з `Удалить()` їх накопичують.

**Діагностика першочергова:** при дублі ключа спершу

До вже наявного субконто `ОбъектРасчетов` додано 3 виміри РС

**той самий `РегистрСведений.АналитикаУчетаПоПартнерам`**, що вже
приєднаний у `Свод_РасчетыСПартнерами` як `АП` через
`ПО Р.АналитикаУчетаПоПартнерам = АП.КлючАналитики` (1:1 штатній
аналітиці, як звіт `ВедомостьРасчетовСПартнерами`). У ВСІ 4 гілки
`втРасч` (SELECT + СГРУППИРОВАТЬ ПО) і фінальний детальний SELECT додано:

- `Партнер = АП.Партнер` (Справочник.Партнеры — збігається з виміром РС)
- `Контрагент = ЕСТЬNULL(ВЫРАЗИТЬ(АП.Контрагент КАК Справочник.Контрагенты), ЗНАЧЕНИЕ(Справочник.Контрагенты.ПустаяСсылка))`
- `Договор = ЕСТЬNULL(ВЫРАЗИТЬ(АП.Договор КАК Справочник.ДоговорыКонтрагентов), ЗНАЧЕНИЕ(Справочник.ДоговорыКонтрагентов.ПустаяСсылка))`

`АП.Контрагент` складений (`Организации|Контрагенты`), `АП.Договор`
складений (`ДоговорыМеждуОрганизациями|ДоговорыКонтрагентов`) — `ВЫРАЗИТЬ`
у тип виміру РС, не той тип → NULL → `ЕСТЬNULL` у ПустаяСсылка (канон).
Плуги (`Расхождение=Истина`) — `ЗНАЧЕНИЕ(Справочник.{Партнеры|Контрагенты|
ДоговорыКонтрагентов}.ПустаяСсылка)`, як `ОбъектРасчетов`. Оркестратор/
`Свернуть` НЕ чіпали (`Контрагент,Партнер,Договор` вже у списку Свернуть).

**Граблі переносу в BSL:** у `СГРУППИРОВАТЬ ПО` останній елемент був
`Р.ОбъектРасчетов` БЕЗ коми → при вставці треба додати кому до нього, а
**останній** доданий елемент групування — БЕЗ коми (інакше «висяча» кома
перед `ОБЪЕДИНИТЬ ВСЕ`/`;`). У SELECT-гілках кома вже є (далі `СУММА(...)`).

**Інваріант (sum-invariant):** Контрагент/Договор/Партнёр — це субконто,
дробить деталі дрібніше, але `втРасчСт`/`втПАП`/`втКлючі` НЕ змінено →
плуг = `втПАП − втРасчСт` без змін → `Σ(деталі+плуг)` per
`(Орг,Подр,Статья,Source)` == ПАП **не змінилася** (доведено пре-тестом
до копійки; повний баланс Актив=\|Пассив\| незмінний). Янв2026/ТОВ:

60 888 300,36 / ПередПоставщиками −131 478 882,01 == ПАП.ОстаткиИОбороты.

### 4.5 Заповнення `Аналитика1/2/3` у 6 `Свод_*` (2026-05-19) — sum-invariant

Рядкові виміри РС `Аналитика1/2/3` (Строка, `_Fld56116/56117/56118`)
заповнено `ПРЕДСТАВЛЕНИЕ(<субконто>)` за таблицею пріоритетів (деталі —
де субконто заповнене, інакше `""`; ячейки з кількома — COALESCE; плуги —
все `""`):

| Свод_* | Аналитика1 | Аналитика2 | Аналитика3 |
|---|---|---|---|
| РасчетыСПартнерами | Контрагент | Договор | ОбъектРасчетов |
| СебестоимостьТоваров | Склад | Номенклатура | `""` |
| ДенежныеСредства | COALESCE(ДенежныеСредства→ФизическоеЛицо) | `""` | `""` |
| ПрочиеРасходыДоходы | COALESCE(ТипНалога→ОбъектыЭксплуатации→НематериальныйАктив) | `""` | `""` |
| ПрочиеАктивыПассивы_Прямой | COALESCE(ТипНалога→ОбъектыЭксплуатации→НематериальныйАктив→**ПРЕДСТАВЛЕНИЕ(Подразделение) для статті "Прибыли и убытки"** rev 2026-05-20) | `""` | `""` |
| ОплатаТруда (rev 2026-05-20) | **ПРЕДСТАВЛЕНИЕ(ФизическоеЛицо)** через А_ВзаиморасчетыССотрудниками | `""` | `""` |

**Чому sum-invariant БЕЗПЕЧНІШЕ §4.4:** у ВСІХ 6 функцій ДЕТАЛЬНА гілка
фіналу — **чиста проекція з ВТ** (`ИЗ втРасч/втСеб/втДС/втПРД/втПрям/втОТ`,
**БЕЗ `СГРУППИРОВАТЬ ПО`**). Аналитика1/2/3 — похідні рядкові вирази
`ВЫБОР … ПРЕДСТАВЛЕНИЕ(…) ИНАЧЕ "" КОНЕЦ` поверх колонок, що ВЖЕ є у ВТ;
`втРасчСт/втПАП/втКлючі`, плуги і групування НЕ зачеплені → `Σ(деталі+плуг)`
per `(Орг,Подр,Статья,Source)` тотожна. Граблі §4.4 з комами у
`СГРУППИРОВАТЬ ПО` тут НЕ виникають (групування детальної гілки немає).
У BSL query-порожній рядок — `""""` (як `""Оплата труда""`); плуги
отримують 3× `""""` на тій самій позиції, що Аналитика у деталях.

## §6.5 КАНОН-ОБРАЗЕЦЬ #2: `Свод_ОплатаТруда` (rev 2026-05-20)

Другий повний канон-приклад розшифровки через **кастомний балансовий регістр-розшифровку** з **інверсією знаку**.

### Особливості vs Свод_ДенежныеСредства

| Аспект | Свод_ДенежныеСредства | Свод_ОплатаТруда (rev) |
|---|---|---|
| Джерело розшифровки | 3 типові регістри `.ОстаткиИОбороты` (Безнал/Нал/Підзвіт) | 1 кастомний `А_ВзаиморасчетыССотрудниками.ОстаткиИОбороты` |
| Знак сум | Прямий (Σ ДС = Σ ПАП ДенСр) | **ІНВЕРСНИЙ** (Σ А_ВзСС = −Σ ПАП ОТ) → множимо на −1 у втВзСС |
| Дзеркальні аналітики | Каса/БанкСчёт + Підотчетник→ФизЛицо | Лише `ФизическоеЛицо` |
| Інверсія | НЕ потрібна | **ОБОВ'ЯЗКОВА** — без неї Σ виходить з протилежним знаком |
| Source | 4 значення Перечисление (Безнал/Нал/Путі/Підзвіт) | 1 значення (ПустаяСсылка — для ОТ) |
| Підрозділ | З того ж регістру (Касса.Подразделение, БанкСчёт.Подразделение) | З того ж регістру А_ВзСС (там же як у ПАП) |

### Чому інверсія

| Сутність | Семантика | Знак signed для тих самих рухів |
|---|---|:---:|
| ПАП(Статья=ОплатаТруда) | Пассивна стаття — Расход = ріст зобов'язання, Приход = погашення | **−** (для активного боргу ФЛ) |
| А_ВзаиморасчетыССотрудниками | Прямий борг працедавця перед ФЛ — Приход = борг ↑, Расход = борг ↓ | **+** (для того ж боргу) |

Тому в `втВзСС` суми домножуються на −1 щоб збігалось з `втПАП` у форматі signed (Приход +Сумма / Расход −Сумма).

| Регістр-розшифровка | `СебестоимостьТоваров.ОстаткиИОбороты(&НачМес,&КонМес)` | `А_ВзаиморасчетыССотрудниками` (пряма таблиця) | **`ПрочиеРасходы`/`ПрочиеДоходы`.ОстаткиИОбороты(&НачМес,&КонМес)** |

| Правило відбору (HAVING) | завжди беремо | завжди беремо | **`НО≠0 АБО КО≠0`** (бухгалтерське правило: тільки незакриті) |

### Бухгалтерська логіка (від фінансиста)

«Расходы текущего периода» (Актив) і «Доходы текущего периода» (Пассив) — це **статті поточного періоду**. Вони повинні закриватися щомісяця на «Прибыли и убытки» через регламент закриття місяця, тобто **не мати переходящих остатків**. Якщо стаття затрат всередині місяця прийшла і повністю закрилася (Приход=Расход → НО=КО=0) — у балансі її НЕ показуємо. Залишаємо лише ті статті у яких є **реальний незакритий остаток** на початок або кінець місяця.

**Контрольний приклад (Глобино-2, апрель 2026):**

Оборотка `РегНакопл.ПрочиеРасходы` показує:
- ~50 статей з оборотами (Приход = Расход = X, КО=0) → НЕ пишемо
- **1 стаття** «Затраты на служебные командировки и содержание аппарата управления предприятием»: Приход=2 400 / Расход=0 / КО=**2 400** → ПИШЕМО

У свод-документі А_ФинРез_Баланс 00000000004 від 30.04.2026 для (Глобино-2, Расх.тек.пер.) — **РОВНО ОДНА строка-деталь** з СтатьяДоходыРасходы=«Затраты на служебные командировки...», НО=0, КО=2 400.

### Ключовий BSL-шаблон (ветка A `Свод_ПрочиеРасходыДоходы`)

```sql
ВЫБРАТЬ

ПОМЕСТИТЬ втПРД
```

### Структура втПАП — фільтр по статтям

Канон #3 потребує **окремої обробки** статей Расх/Дох тек.пер. у втПАП (свертка для плугів):
```sql
ВЫБОР КОГДА Т.Статья = &РасхТекПер ИЛИ Т.Статья = &ДохТекПер
    ТОГДА ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ПустаяСсылка)
    ИНАЧЕ Т.Источник
КОНЕЦ КАК Source,
...
ГДЕ
    Т.Организация = &Орг И Т.Период <= &КонМес
    И ((Т.Статья = &РасхТекПер ИЛИ Т.Статья = &ДохТекПер)              -- без фільтра Источник
       ИЛИ (Т.Источник В (&Ист) И Т.Статья <> &РасхТекПер И Т.Статья <> &ДохТекПер))
    И НЕ Т.Статья В ИЕРАРХИИ(&Искл)
```

### Інваріант
- Σ(деталі + плуг) per (Орг, Подр, Статья=Расх/Дох тек.пер., Source=ПустаяСсылка) == ПАП.ОстаткиИОбороты per same до 0.01
- Плуг (СтатьяДохРасх=NULL) компенсує випадки де ПАП має руху не покриті регістром-розшифровкою (наприклад «Амортизація ОС» пише в ПАП з Источник=ПустаяСсылка, але не в РегНакопл.ПрочиеРасходы — типове розхождение в Производство/ЦО, в сумі по організації нейтралізується)
