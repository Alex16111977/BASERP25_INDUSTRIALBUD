### Как создаётся строка плуга (механизм)

В функции `Свод_РасчетыСПартнерами` (live BSL):

```
1. втРасч = РасчетыСКлиентамиПоСрокам.ОстаткиИОбороты + РасчетыСПоставщикамиПоСрокам.ОстаткиИОбороты
            4 ветки UNION ALL: Долг/Предоплата × Клиенты/Поставщики
            JOIN с РегистрСведений.АналитикаУчетаПоПартнерам по КлючАналитики
            → детали (Орг, Подр, Статья, ОбъектРасчетов, Контрагент, Партнер, Договор, КО)

2. втРасчСт = Σ втРасч по (Орг, Подр, Статья) — сумма деталей

3. втПАП = РегистрНакопления.ПрочиеАктивыПассивы (СИНГЛ источник истины, signed)
           ГДЕ Источник = ЗНАЧЕНИЕ(...РасчетыСКлиентамиПоСрокам) — фильтр по конкретному источнику
                И НЕ Статья В ИЕРАРХИИ(&ИсключенныеСтатьи) — OD-3 фильтр
                И Период МЕЖДУ &НачМес И &КонМес
           → одна строка на (Орг, Подр, Статья)

4. втКлючи = ВЫБРАТЬ РАЗЛИЧНЫЕ (Орг, Подр, Статья) ИЗ ОБЪЕДИНИТЬ втПАП ∪ втРасчСт

5. ФИНАЛ — ОБЪЕДИНИТЬ ВСЕ:
   - детальные строки ИЗ втРасч → Расхождение=ЛОЖЬ
   - плуги: втКлючи ЛЕВОЕ СОЕДИНЕНИЕ втПАП И втРасчСт
            ГДЕ |ЕСТЬNULL(втПАП.КО, 0) − ЕСТЬNULL(втРасчСт.КО, 0)| > 0.01
            → строка с Расхождение=ИСТИНА, ОбъектРасчетов=ПустаяСсылка,
              Сумма = (втПАП.КО − втРасчСт.КО)
```

**Σ-инвариант (доказано):** для любого (Орг, Подр, Статья) → Σ(деталей + плуг) = втПАП. Это значит свёртка точно сходится с штатным `Отчет.УправленческийБаланс`. Плуг — **механизм согласования** деталей с источником истины, а НЕ ошибка.

### Знак плуга в нашем случае

```
Плуг = втПАП.КО − втРасчСт.КО = −7 194 594,73
⇓
втПАП.КО − втРасчСт.КО = −7 194 594,73
втРасчСт.КО = втПАП.КО + 7 194 594,73
```

**Перевод**: детальная расшифровка `втРасч` для (ТОВ ІНДАСТРІАЛБУД, Глобино-2, «Задолженность клиентов») **превышает** ПАП-сумму ровно на 7 194 594,73 ₽. Поскольку строка 2 193 имеет ровно эту сумму с ОбъектРасчетов = «Строительство внутр.(Реализация)» — это **избыточная** запись в `РасчетыСКлиентамиПоСрокам`, которой **нет** в `ПрочиеАктивыПассивы` под Источник=РасчетыСКлиентамиПоСрокам.

## Главные гипотезы корня (упорядочены по вероятности)

| # | Гипотеза | Как проверить | Если подтверждена |
|---|---|---|---|
| **H1** | **Внутригрупповая реализация (Контрагент=Глобино-2 — само подразделение)**. В `РасчетыСКлиентамиПоСрокам` движение есть, в ПАП под Источник=`РасчетыСКлиентамиПоСрокам` его нет — потому что ПАП либо вообще не пишется для внутригруппы, либо пишется с Источник=`ПустаяСсылка`/`ПрочиеРасходы` (не в фильтре свода). | SQL 1: найти ОбъектРасчетов UUID. SQL 2: найти Регистратор в РСК с этим ОР. SQL 3: проверить ПАП по этому Регистратору — есть ли движения и какой `Источник`. | **by-design**: задокументировать в `balanse_pattern_and_roadmap.md` (новая §4.6 «Внутригрупповые реализации создают расхождение Свод_РасчетыСПартнерами»). НЕ менять код. |
| **H2** | **Классификационная ошибка**: документ-источник записал в РСК под статью «Задолженность клиентов», но в ПАП — под другую статью (например, «Прочие расчёты»). | SQL: получить Статья из РСК и из ПАП для того же Регистратора → сравнить. | **финансистский фикс**: попросить финансиста поправить статью в карточке документа → перепровести А_ФинРез_Баланс. |
| **H3** | **Баг проведения типовой ERP**: документ пишет в РСК, но НЕ в ПАП вообще. | SQL: проверить наличие движений в ПАП для этого Регистратора. Если 0 → баг. | **эскалировать**: разработчик типового. Временный обход — отдельный плуг для этого Регистратора. |
| **H4** | **Старые данные** с пустой статьёй (предыдущие версии регистра, до Stage v2). | Дата Регистратора + наличие пустого `_Fld<статья>RRef` | **миграционный скрипт** для перепроведения первичных документов. |

**Самая вероятная — H1** (внутригрупповая реализация). Признаки:
- Контрагент = Партнёр = Глобино-2 (=Подразделение). В нормальной финансистской логике Контрагент ≠ подразделение.
- Договор «Строительство **внутр.(Реализация)**» — слово «внутр.» прямо в наименовании.
- Аналогичная строка «МК Глобино внутр.(Реализация)» с +226 760,13 (строка 1 364) **не** даёт плуга — потому что её Σ < tolerance 0.01 от ПАП (вероятно, ПАП включает и эту операцию по правилам платформы).

**Анализ результата**:
- **Если 0 строк** → H3 (типовой не записал в ПАП). Это БАГ типового. Эскалация.

- **Если есть строки, но Статья ≠ «Задолженность клиентов»** → **H2 подтверждена** (классификационная ошибка).

## Что в коде Свод_РасчетыСПартнерами делает Источник-фильтр

Открыть `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl`, найти функцию `Свод_РасчетыСПартнерами`. В блоке `втПАП` есть условие:

```bsl
ГДЕ Р.Источник В (ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.РасчетыСКлиентамиПоСрокам),
                  ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.РасчетыСПоставщикамиПоСрокам))
    И НЕ Р.Статья В ИЕРАРХИИ(&ИсключенныеСтатьи)
```

Если внутригрупповые операции пишут в ПАП с `Источник = ПустаяСсылка` или другим (например, `ПрочиеАктивыПассивы`), они **попадают** в `Свод_ПрочиеАктивыПассивы_Прямой` (другая Свод-функция), а **НЕ** в `Свод_РасчетыСПартнерами`. Это нормально — финансист видит их в общем балансе под другой Source. Но в детализированной расшифровке `РасчетыСПартнерами` остаётся плуг-расхождение.

    print(f"   {r.Регистратор} | Статья={conn.String(r.СтатьяПАП)} | Источник={conn.String(r.ИсточникПАП)} | Σ={float(r.Σsigned):>15,.2f}")

# === ВЫВОД ===
print("\n=== Дерево решений ===")
if пап.Количество() == 0:
    print("→ H3 БАГ: ПАП не записан этим документом. Эскалация на разработчика типового.")
else:
    источники = {conn.String(r.ИсточникПАП) for r in пап}
    статьи_пап = {conn.String(r.СтатьяПАП) for r in пап}
    статьи_рск = {conn.String(r.СтатьяРСК) for r in рег}
    if "РасчетыСКлиентамиПоСрокам" not in источники:
        print(f"→ H1 ВНУТРИГРУППА: ПАП пишет с Источниками {источники}, а Свод_РасчетыСПартнерами фильтрует только 'РасчетыСКлиентамиПоСрокам'.")
        print(f"   Это by-design — внутригрупповая операция исключена из расчёта с партнерами.")
        print(f"   Финансист может задокументировать как 'Внутригрупповые реализации создают плуг'.")
    elif статьи_пап != статьи_рск:
        print(f"→ H2 КЛАССИФИКАЦИЯ: статья в РСК {статьи_рск} ≠ в ПАП {статьи_пап}.")
        print(f"   Финансисту: правьте статью в документе-источнике, перепроведите А_ФинРез_Баланс.")
    else:
        print("→ Углубление: суммы совпадают, но плуг есть. Проверь ВидИсточника, OD-3 фильтр, Аналитика.")

## Anti-patterns (не делать)

| Антипаттерн | Почему плохо | Правильно |
|---|---|---|
| «Уберём строку Расхождение из регистра — она путает» | Σ-инвариант нарушается, Σ ≠ ПАП, баланс не сходится | Понять корень. Если внутригруппа — оставить и задокументировать. |
| Менять фильтр `Источник` в `Свод_РасчетыСПартнерами` чтобы включить ПустуюСсылку | Удвоение деталей: ПАП с пустым Источник попадёт и в `Свод_ПрочиеАктивыПассивы_Прямой`, и в `Свод_РасчетыСПартнерами` | НЕ менять. Структура источников консистентна. |
| Править первичный документ задним числом | Может сломать другие отчёты (отчёт по партнёру, акт сверки) | Только с одобрения финансиста по конкретному документу. |
| Игнорировать расхождение «потому что Σ компенсирует» | Финансист видит цифру и тревожится. Лучше показать что это by-design и что это нормально. | Задокументировать паттерн → финансист понимает. |
