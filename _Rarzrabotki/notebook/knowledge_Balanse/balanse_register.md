## 4. `Перечисление.А_ИсточникБаланса` — 7 значень

> ⚠️ Канон v1.4 §2 згадує «3 значення» (ПрочиеАктивыПассивы, РасчетыСКлиентами, РасчетыСПоставщиками) — це стан до Етапів 3-4. **Фактично фінансист розширив enum до 7** (Етапи 3-4). Поточний реальний склад (`Enums/А_ИсточникБаланса.xml`, порядок = `_EnumOrder` 0…6):

| order | Значення | Що означає (з якого регістра взято розшифровку рядка) |
|---|---|---|
| 0 | `ПрочиеАктивыПассивы` | базовий — субконто прямо з `ПАП.Аналитика` (немає матчу типового регістра) |
| 1 | `РасчетыСКлиентами` | розшифровку дав `РегНак.РасчетыСКлиентами` (→ОбъектРасчетов) |
| 2 | `РасчетыСПоставщиками` | розшифровку дав `РегНак.РасчетыСПоставщиками` (→ОбъектРасчетов) |
| 3 | `СебестоимостьТоваров` | розшифровку дав `РегНак.СебестоимостьТоваров` (→Номенклатура/Склад) |
| 4 | `ДенежныеСредстваБезналичные` | розшифровку дав `РегНак.ДенежныеСредстваБезналичные` (→ДенСр=БанкСчет) |
| 5 | `ДенежныеСредстваНаличные` | розшифровку дав `РегНак.ДенежныеСредстваНаличные` (→ДенСр=Касса) |
| 6 | `ПрочиеРасходы` | «Оплата труда» розкладена по `ФизическоеЛицо` (ВзаиморасчетыССотрудниками) |

`Source` — **не вимір розрізу Актив/Пасив**. Це індикатор регістра-розшифровки для drill-down у Power BI (OD-1 гібрид). Один рядок = один Source; **одна стаття може мати кілька Source** (різні регістратори).

## 5. `Перечисление.ВидыСтатейУправленческогоБаланса` — атрибут `СтатьиАктивовПассивов.АктивПассив`

Розріз Актив/Пасив **не зберігається в регістрі** (OD-9) — береться downstream з реквізиту `ПланВидовХарактеристик.СтатьиАктивовПассивов.АктивПассив`:

| order | Значення | Сенс |
|---|---|---|
| 0 | `Актив` | стаття-актив |
| 1 | `Пассив` | стаття-пасив |
| 2 | `АктивПассив` | двостороння (напр. `Налоги`, `Лизинг`) — у Power BI ділиться по знаку сальдо |
