## 1. Что это за кейс и зачем «подъём»

**СозданиеКомплектацийБух** — внешняя обработка пользователя для базы **BuhBud** (BAS Бухгалтерія, `cfo/2442`). Делает ровно то, что относится к классу A «запрос → анализ → заполнение документов»: читает количественные остатки сч.2051 «Хозрасчетный» по дате и набору складов, группирует по эталону (`ОбщееНазваниеНоменклатуры`), сопоставляет с нормой из спецификации (`СтруктураСебестоимости.Комплектующие`), жадно распределяет остаток «в норме / понад норму» и заполняет ТЧ `Комплектующие` до 4 документов `КомплектацияНоменклатуры` (2 склада × {по нормам, дополнительная}).

> ⚠️ **Это ПРИМЕР пользователя, а не эталон.** Обработка рабочая и уже несёт хорошие зёрна (тонкая форма + мост `РеквизитФормыВЗначение`/`ЗначениеВРеквизитФормы`, итоги по поиску). Но по планке tier-5 это **tier 1–2**: монолит в `ObjectModule`, хардкод-литералы в запросе, голая запись документов без транзакции, проглоченные `Исключение`. **Эталон для сравнения** — класс A РМ `ПомощникПродаж` / `ОбеспечениеПотребностей`: их доминирующий сценарий ровно такой же («набрал условия → одним действием сформировал/заполнил пакет документов»), поэтому именно их паттерны прикладываем как «как должно быть профессионально».

| Что уже сделано в Фазе 1–2 | Состояние |
|------|------|
| **Фаза 1 — движок** | `ObjectModule` с 2 экспортными методами `РассчитатьАнализ()` / `ЗаполнитьДокументыПоАнализу()`; тонкая форма-диспетчер через мост; smoke на BuhBud (спец `000000003`/ПРООН/`07.04.2026`) = 126 строк, баланс 0 (`34378.91 = 17735.65 + 16643.26`) |
| **Фаза 2 — рабочее место** | Закладка **«Аналіз залишків»**: группа «Відбір» + read-only `ТаблицаАнализа` + панель «Підсумки» (3 итога); наложенный поиск-фильтр + подытоги «по отбору» клиентским кодом; uk-подписи; подсветка итогов цветом кодом |

Реквизиты объекта (ПРИМЕР): `Спецификация`(СправочникСсылка.СтруктураСебестоимости), `Период`(Дата); ТЧ `СкладыОстатков{Склад}`, `ТабличнаяЧастьОстатков{Номенклатура, ОбщееНазвание, Склад, Остаток, Норма, ВНорме, ПонадНорму}`, `ДокументиКомплектації{Склад, ДокументПоНормам, ДокументДодаткова}`. Внутреннее имя метаданных — `СозданиеКомплектацийБух` (`Name`/тип `ExternalDataProcessorObject.СозданиеКомплектацийБух`), хотя папка названа «Создания комплектаций для бух учета».

## 2. Что уже сделано ХОРОШО (зёрна эталонности в примере)

Прежде чем поднимать, зафиксируем, что в примере уже совпадает с каноном класса A — это НЕ трогать.

### 2.1 Мост форма↔движок (тонкая форма) — совпадает с каноном

ПРИМЕР делает ровно тот «мост», что предписывает хаб-скил `obr-obrabotka`: форма материализует объект, дёргает экспортный метод движка под `Попытка`, заливает результат обратно. Вербатим из **ПРИМЕРА** (`Forms/Форма/Ext/Form/Module.bsl:24-34`):

```bsl
&НаСервере
Процедура РассчитатьНаСервере()
	ОбъектОбработки = РеквизитФормыВЗначение("Объект");
	Попытка
		ОбъектОбработки.РассчитатьАнализ();
	Исключение
		Сообщить(КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат;
	КонецПопытки;
	ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект");
	Сообщить("Розраховано позицій: " + Объект.ТабличнаяЧастьОстатков.Количество());
КонецПроцедуры
```

Это правильный каркас «тонкая форма + движок». **ЭТАЛОН класса A это подтверждает:** в `ПомощникПродаж` клиентская обёртка кнопки «Создать документы» тоже сначала гейтит, потом дёргает серверный оркестратор и строит человекочитаемое оповещение по счётчику. Вербатим из **ЭТАЛОНА** (`_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl:6441-6477`):

```bsl
&НаКлиенте
Процедура СоздатьДокументыКлиентФрагмент(Знач Оповещение)
	ОчиститьСообщения();
	ПередЗаписьюНаКлиентеСервер();
	Если ПроверитьЗаполнение() Тогда                       // ← гейт ПЕРЕД сервером
		КоличествоСозданныхДокументов = СоздатьДокументыСервер();
		Если КоличествоСозданныхДокументов > 0 Тогда
			ТекстСообщения = НСтр("ru='Созданы документы (%КоличествоСозданныхДокументов%)';uk='Створені документи (%КоличествоСозданныхДокументов%)'");
			ТекстСообщения = СтрЗаменить(ТекстСообщения, "%КоличествоСозданныхДокументов%", КоличествоСозданныхДокументов);
		КонецЕсли;
		ПоказатьОповещениеПользователя(ТекстСообщения, , , БиблиотекаКартинок.Информация32);
	КонецЕсли;
	ВыполнитьОбработкуОповещения(Оповещение);
КонецПроцедуры
```

> 🔑 **Разрыв «до→эталон» №1:** у примера перед записью документов **нет** `ПроверитьЗаполнение()`-гейта и оповещение строится `Сообщить()` (не виден в фоне). Эталон ставит гейт ДО серверного вызова и шлёт `ПоказатьОповещениеПользователя` с двуязычным `НСтр`. Поднять — добавить гейт заполнения перед `ЗаполнитьДокументыНаСервере` и перейти на `ПоказатьОповещениеПользователя`.

### 2.2 Итоги «по поиску» в видимой таблице — уже эталонный приём

Полный результат живёт в `Объект.ТабличнаяЧастьОстатков` (ТЧ объекта), а `ТаблицаАнализа` (`ReadOnly`, `Footer`, реквизит формы) — фильтрованная видимая копия. Один проход и фильтрует, и копит подытоги без БД. Вербатим из **ПРИМЕРА** (`Forms/Форма/Ext/Form/Module.bsl:108-150`):

```bsl
&НаКлиенте
Процедура ПрименитьОтборИИтоги()
	ИтогоЗалишок = 0; ИтогоВНорме = 0; ИтогоПонад = 0;
	ТаблицаАнализа.Очистить();
	ТекстПошуку = ВРег(СокрЛП(Пошук));
	Для Каждого Стр Из Объект.ТабличнаяЧастьОстатков Цикл
		Если ЗначениеЗаполнено(ОтборСклад) И Стр.Склад <> ОтборСклад Тогда Продолжить; КонецЕсли;
		Если ЗначениеЗаполнено(ОтборЭталон) И Стр.ОбщееНазвание <> ОтборЭталон Тогда Продолжить; КонецЕсли;
		Если ТолькоПонадНорму И НЕ (Стр.ПонадНорму > 0) Тогда Продолжить; КонецЕсли;
		Если НЕ ПустаяСтрока(ТекстПошуку) Тогда
			Ціль = ВРег(Строка(Стр.Номенклатура) + " " + Строка(Стр.ОбщееНазвание) + " " + Строка(Стр.Склад));
			Если СтрНайти(Ціль, ТекстПошуку) = 0 Тогда Продолжить; КонецЕсли;
		КонецЕсли;
		НС = ТаблицаАнализа.Добавить(); // ... перенос 7 колонок
		ИтогоЗалишок = ИтогоЗалишок + Стр.Остаток;
		ИтогоВНорме  = ИтогоВНорме  + Стр.ВНорме;
		ИтогоПонад   = ИтогоПонад   + Стр.ПонадНорму;
	КонецЦикла;
КонецПроцедуры
```

Подытоги считаются **в том же цикле**, что и фильтр → пользователь видит сумму именно отфильтрованных строк. Это приём «итоги по поиску» из `obr-forma-otbory-itogi`, и здесь он сделан правильно. **Разрез из эталона:** в `ОбеспечениеПотребностей` клиентский фильтр строк таблицы делается через `ОтборСтрок = Новый ФиксированнаяСтруктура(...)` (`Forms/Форма/Ext/Form/Module.bsl:4358-4393`, **ЭТАЛОН**) — это альтернатива, когда не нужны подытоги «по отбору»; для подытогов же ручной проход примера корректен.

> 🔑 **«Видимая ТЗ ≠ полный набор»** — фундамент: документы заполняются из ПОЛНОГО `Объект.ТабличнаяЧастьОстатков`, фильтр на «Аналіз» на заполнение **не влияет** (диагностика для бухгалтера).

## 4. Подъём по разрывам: пример «до» → эталонный паттерн → «как профессионально»

### 4.1 ⭐ Транзакционный оркестратор вместо голого `Записать()` в цикле

**ПРИМЕР (до)** — `ObjectModule.bsl:51-74`: запись каждого документа без обёртки, сбой на N-м документе оставляет первые N-1 записанными (half-applied):
```bsl
Счет2051 = ПланыСчетов.Хозрасчетный.НайтиПоКоду("2051");
Для Каждого КЗ Из СтрокиПоДокументам Цикл
	ДокОбъект = ДокСсылка.ПолучитьОбъект();
	ДокОбъект.Комплектующие.Очистить();
	Для Каждого СтрД Из КЗ.Значение Цикл
		НС = ДокОбъект.Комплектующие.Добавить(); // ...
	КонецЦикла;
	ДокОбъект.Записать(РежимЗаписиДокумента.Запись); // ← без Попытка, без транзакции
КонецЦикла;
```

**ЭТАЛОН класса A** — `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl:5863-6344`, `СоздатьДокументыСервер` (цепочка до 12 типов документов атомарно):
```bsl
Функция СоздатьДокументыСервер()
	// ОтменаПроведенияРанееСозданныхДокументов (идемпотентность повторного «Создать»)
	НачатьТранзакцию();
	Попытка
		Отказ = Ложь;
		МассивНайденныхДокументов = Новый Массив;
		// ... ветвление по варианту оформления, ЗаписатьЗаказ/ЗаписатьСчётНаОплату/ЗаписатьПКО ...

		Если Отказ Тогда
			ВызватьИсключение НСтр("ru='Ошибка завершения создания документов';uk='Помилка завершення створення документів'", ОбщегоНазначенияКлиентСервер.КодОсновногоЯзыка());
```

**Как поднять `ЗаполнитьДокументыПоАнализу`:** обернуть весь цикл записи в `НачатьТранзакцию/Попытка/ЗафиксироватьТранзакцию`; в `Исключение` — `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации(..., ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))`; возвращать счётчик заполненных (как уже делает пример строкой-отчётом, но дополнить структурой результата). Перед записью — снять проведение ранее заполненных (у примера документы заводит пользователь сам, проведение не трогается — см. §4.8 — поэтому здесь достаточно `Комплектующие.Очистить()` для идемпотентности, что в примере **уже есть** — это зерно эталонности).

> ⚠️ Документы `КомплектацияНоменклатуры` в BuhBud — **нерасчётные** (комплектация, не взаиморасчёты). Поэтому `А_`-флагов обмена / `Курс=1` / `Кратность=1` / `СуммаВзаиморасчетов` из чек-листа `bas-doc-fill` здесь **НЕ нужно** (в отличие от расчётных Реализация/Приобретение/ПКО/РКО). Транзакция и журнал — нужны.

### 4.2 ⭐ Вынос логики в общий модуль `А_СозданияКомплектацийСервер` (БСП-стиль)

**ПРИМЕР (до):** запросы остатков/норм, жадный `ЗаполнитьАнализ`, формирование документов — всё inline в `ObjectModule.bsl` обработки. Обработка = и UI-обёртка, и движок одновременно → не переиспользуется, тестируется только через COM целиком.

**ЭТАЛОН класса A:** тяжёлые куски делегируются в `*Сервер`-хелперы и общие модули. Вербатим из **ЭТАЛОНА** (`ПомощникПродаж/...Module.bsl:3348-3398`, `УстановитьУсловноеОформление`) — типовое делегируется, своё остаётся программно:
```bsl
// Делегирование типовым серверам оформления:
НоменклатураСервер.УстановитьУсловноеОформлениеЕдиницИзмерения(ЭтаФорма);
// get-or-create документа — тоже в общий модуль (ПомощникПродаж:4768-4778):
ДокументОбъект = Продажи.НайтиСоздатьДокумент(ЭтотОбъект, Документы.ЗаказКлиента,
	Тип("ДокументСсылка.ЗаказКлиента"), МассивНайденныхДокументов, СозданНовыйДокумент, СтрокаТаблицы);
```

**Как поднять (`bas-common-module`):** создать общий серверный модуль `А_СозданияКомплектацийСервер`, перенести в него `ПолучитьОстатки`/`ПолучитьНормы`/`ЗаполнитьАнализ`/формирование документов экспортными процедурами; `ObjectModule` обработки оставить тонкой UI-обёрткой, делегирующей в модуль. Выигрыш: логика переиспользуема, тестируется автотестом/Python COM изолированно, конвенция `А_<Объект>Сервер` (вводится проектом — прецедента в типовой нет, но это прямой аналог `*Сервер`-хелперов эталона).

### 4.3 ⭐ Параметризовать счёт 2051, не хардкодить литералом в тексте запроса

**ПРИМЕР (до)** — `ObjectModule.bsl:51, 112`: счёт зашит дважды — литералом в тексте запроса и `НайтиПоКоду`:
```bsl
|	РегистрБухгалтерии.Хозрасчетный.Остатки(&НаДату, Счет.Код = ""2051"", , ) КАК Ост
...
Счет2051 = ПланыСчетов.Хозрасчетный.НайтиПоКоду("2051");
```
Литерал в тексте запроса = грабли удвоенных/одинарных кавычек (`""2051""` в BSL ↔ `"2051"` в Python COM, уже зафиксировано в памяти проекта); смена плана счётов тихо ломает оба места.

**Как поднять:** счёт получить один раз (`СчётКомплектации = ПланыСчетов.Хозрасчетный.НайтиПоКоду(...)` либо реквизит/константа обработки) и передать в запрос через `Запрос.УстановитьПараметр("Счёт", СчётКомплектации)`, а в тексте — `ГДЕ Ост.Счет = &Счёт` (или `В ИЕРАРХИИ(&Счёт)`). Имена метаданных (типы) — через `ЗНАЧЕНИЕ(...)`, как в эталонном товарном сверщике `СинхронизироватьТоварыТолькоТовары` (`Счет В ИЕРАРХИИ (ЗНАЧЕНИЕ(ПланСчетов.Хозрасчетный.Товары))`). Перед переносом в BSL — Python COM pre-check запроса (Rule #-1).

### 4.4 ⭐ Пустой `Исключение` глушит ошибку → собрать в отчёт-результат

**ПРИМЕР (до)** — `ObjectModule.bsl:67-70`: ошибка присвоения `ЕдиницаИзмерения` молча проглатывается:
```bsl
Попытка
	НС.ЕдиницаИзмерения = СтрД.Номенклатура.БазоваяЕдиницаИзмерения;
Исключение
КонецПопытки;
```
Пустой `Исключение` — антипаттерн (фиксируется `/1c-bsl-review`): нет следа в журнале, бухгалтер не узнает, что у части номенклатуры единица не проставилась.

**ЭТАЛОН класса A** — `ПомощникПродаж:6544-6600`, пакетное действие ведёт счётчик и в худшем случае логирует:
```bsl
Пока Сч > 0 Цикл
	// ...
	ПометитьНаУдалениеДокумент(СтрокаТаблицы, ДокументНеПомеченНаУдаление);
	Если ДокументНеПомеченНаУдаление Тогда Отказ = Истина;
	Иначе КоличествоИзмененныхДокументов = КоличествоИзмененныхДокументов + 1; КонецЕсли;
КонецЦикла;
Если Отказ Тогда
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление'"),
		УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	Возврат 0;
КонецЕсли;
```

**Как поднять:** даже для «допустимого» пропуска единицы — не глушить молча, а накапливать в счётчик `БезЕдиницы` и приписывать к тексту-отчёту (как пример уже делает для `Пропущено`). Минимум — `ЗаписьЖурналаРегистрации(..., УровеньЖурналаРегистрации.Предупреждение, ...)`. Возвращать структуру `{Заповнено, Пропущено, БезЕдиниці, Помилки[]}` вместо одной строки.

### 4.5 ⭐ Цвет/оформление — программно через `УсловноеОформление` + `ЦветаСтиля`, не `Новый Цвет(RGB)`

**ПРИМЕР (до)** — `Forms/Форма/Ext/Form/Module.bsl:7-9`: метрики красятся RGB-литералом:
```bsl
Элементы.ИтогоВНорме.ЦветФона = Новый Цвет(214, 240, 214);
Элементы.ИтогоПонад.ЦветФона  = Новый Цвет(250, 235, 200);
```
Это **уже лучше**, чем `<TextColor>style:…` в Form.xml (тот валит `epf-build` «Исключение XDTO» во внешней обработке — см. §6 грабля «цвет XDTO»). Но RGB-хардкод не темо-зависим и не масштабируется на правила по данным.

**ЭТАЛОН класса A** — `ПомощникПродаж:3348-3398`: оформление по данным строится программно через `УсловноеОформление.Элементы` (Отбор + Поля + Оформление), цвета — `ЦветаСтиля.*`:
```bsl
Элемент = УсловноеОформление.Элементы.Добавить();
ОтборЭлемента = Элемент.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
ОтборЭлемента.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.ВариантОформленияДокументов");
ОтборЭлемента.ВидСравнения = ВидСравненияКомпоновкиДанных.ВСписке;
Элемент.Оформление.УстановитьЗначениеПараметра("Видимость", Ложь);
```
(аналог — сосед `СинхронизироватьТоварыТолькоТовары`: оформление статусов целиком в `НастроитьУсловноеОформление()` через `WebЦвета`/`ЦветаСтиля`).

**Как поднять:** подсветку строк `ТаблицаАнализа` по правилу «ПонадНорму > 0» вынести в программное `УсловноеОформление` (Отбор `ТаблицаАнализа.ПонадНорму > 0` → `ЦветаСтиля.ПолеПомеченноеНаУдаление` или иной стилевой цвет), а не RGB на статичных метриках. Для самих метрик-итогов RGB допустим как косметика, но тема-зависимый `ЦветаСтиля` предпочтительнее.

### 4.6 ⭐ Кандидат на фоновую операцию (если период/склады крупные)

**ЭТАЛОН класса A** — `ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl:1469-1506, 1813-1843`, стандартная БСП-триада:

Для текущего объёма — не нужно; зафиксировано как направление масштабирования.

### 4.7 ⚠️ Отборы — опционально на СКД-панель

**ПРИМЕР (до):** отборы — простые поля формы (`ОтборСклад`/`ОтборЭталон`/`ТолькоПонадНорму`), фильтрация клиентским проходом. Для tier-2 «диагностика бухгалтеру» этого достаточно.

**ЭТАЛОН класса A** — `ОбеспечениеПотребностей:3837-3851, 4029-4076`: гибкие отборы на временной СКД через `КомпоновщикНастроек` + `ОтразитьПростойОтборВОтборахКомпоновки`. Поднимать только если потребуется произвольный набор условий (по группам, иерархии, нескольким полям) — для двух равенств + поиска текущая схема примера проще и уместнее. **Не плодить СКД ради двух фильтров.**

### 4.8 ⚠️ By-design ограничения примера (НЕ дефекты, не «поднимать»)

- **Документы НЕ создаются и НЕ проводятся.** По дизайну пользователь заранее заводит по 2 пустых `КомплектацияНоменклатуры` на склад и выбирает в ТЧ `ДокументиКомплектації`; склад без выбранного документа → строки молча в счётчик `Пропущено`. Запись — **без проведения** (`Записать(РежимЗаписиДокумента.Запись)`). Идемпотентность через `Комплектующие.Очистить()` перед добавлением — **уже сделано правильно** (повтор перезаписывает, не задваивает).
- **Норма — по ЭТАЛОНУ, не по номенклатуре.** `ПолучитьНормы()` группирует `СтруктураСебестоимости.Комплектующие` по `ОбщееНазвание`; `Нормы.Получить(Стр.ОбщееНазвание)`; нет эталона/нормы → 0 → всё в «понад норму».
- **`УПОРЯДОЧИТЬ ПО ОбщееНазвание, Остаток УБЫВ` — НЕ косметика.** Жадный `ЗаполнитьАнализ` полагается на сортировку: при смене эталона сбрасывается `ОстатокНормы`, первыми в норму попадают позиции с наибольшим остатком (`мин(остаток, остаток нормы)`). Менять порядок нельзя.
- **BuhBud-only.** `РегистрБухгалтерии.Хозрасчетный` сч.2051 в ERP нет; тестировать против BuhBud (`cfo/2442`) по Rule #-1.

## 6. Грабли и находки (для журнала доучивания)

### 6.1 ⭐ Штатный «Найти» по таблице не порождает события — фильтр через поле-поиск
**Симптом:** хочется фильтровать read-only `ТаблицаАнализа` штатным поиском платформы (`SearchStringAddition`/Ctrl+F), но «фильтр не срабатывает» и итоги не пересчитываются.
**Причина:** платформенный поиск — UI-навигация (подсветка/скролл), **без обработчика** в модуле формы; перехватить «применён фильтр» нельзя.
**Решение:** собственное поле-поиск (реквизит `Пошук` типа Строка) + `Event OnChange` → клиентская `ПрименитьОтборИИтоги`, перестраивающая видимую таблицу из полного набора и считающая подытоги. Отборы — тоже поля с `OnChange`, не штатный «Настроить список». См. §2.2.

### 6.2 ⭐ Цвет элемента внешней обработки — только кодом, не `<TextColor>`-XML
**Симптом:** `<TextColor>style:…</TextColor>` в `Form.xml` внешней обработки валит `epf-build` «Исключение XDTO» (в формах конфигурации работает).
**Причина:** XDTO-сериализация `<TextColor>style:…` отвергается загрузчиком Form.xml именно **внешней** обработки.
**Решение:** цвет — кодом в `ПриСозданииНаСервере` (пример: `Элементы.ИтогоВНорме.ЦветФона = Новый Цвет(...)`, `Forms/Форма/Ext/Form/Module.bsl:7-9`). Профессиональнее (§4.5) — `ЦветаСтиля.*` через программное `УсловноеОформление`. Подтверждение: память [epf_load_xdto_textcolor.md]; та же грабля в `СинхронизироватьТоварыТолькоТовары`.

### 6.3 ⚠️ uk-подписи: пост-замена ru→uk в Form.xml (UTF-8 без BOM)
**Симптом:** клон/`form-compile` несёт подписи на языке исходного JSON.
**Причина:** `form-compile` эмитит подписи исходного языка; uk-локализация — правка `<v8:content>`/`Title`/`InputHint`.
**Решение:** uk-подписи проставлены прямо в Form.xml («Аналіз залишків», «Відбір», «Склад», «Еталон», «Пошук», «Тільки понад норму», «Фільтр за полем», «Скинути»). Файл сохранять **UTF-8 без BOM**. Грабля повторяется во всех рабочих местах — вынесена в `obr-forma-otbory-itogi`.

### 6.4 ⭐ `УПОРЯДОЧИТЬ ПО ОбщееНазвание, Остаток УБЫВ` обязательно для жадного распределения
**Симптом:** при смене порядка строк норма распределяется «не туда».
**Причина:** `ЗаполнитьАнализ` при смене эталона сбрасывает `ОстатокНормы`; первыми норму «отъедают» позиции с наибольшим остатком.
**Решение:** в запросе остатков (`Ext/ObjectModule.bsl:116-122`) — `СГРУППИРОВАТЬ ПО` эталону + `УПОРЯДОЧИТЬ ПО ОбщееНазвание, Остаток УБЫВ`. Субконто — `ВЫРАЗИТЬ(Ост.Субконто1 КАК Справочник.Номенклатура)`; фильтр складов — **внешним `ГДЕ`** `ВЫРАЗИТЬ(Ост.Субконто3 КАК Справочник.Склады) В (&Склады)` (субконто как измерение в `.Остатки()` недоступно). Литерал счёта в BSL — `Счет.Код = ""2051""` (удвоенные кавычки), в Python COM — `"2051"`. Подъём литерала → §4.3.

### 6.5 ⚠️ Голая запись документов без транзакции/журнала (главный разрыв «до→эталон»)
**Симптом:** при сбое на N-м документе первые N-1 уже записаны — half-applied.
**Причина:** `ДокОбъект.Записать(...)` в цикле без `НачатьТранзакцию`/`Попытка` (`ObjectModule.bsl:72`).
**Решение:** транзакционный оркестратор по образцу `ПомощникПродаж.СоздатьДокументыСервер` (§4.1): весь пакет в `НачатьТранзакцию/Попытка/ЗафиксироватьТранзакцию`, `Исключение`→`ОтменитьТранзакцию`+`ЗаписьЖурналаРегистрации(ПодробноеПредставлениеОшибки(...))`.

### 6.6 ⚠️ Пустой `Исключение` глушит ошибку единицы измерения
**Симптом:** часть номенклатуры остаётся без `ЕдиницаИзмерения`, бухгалтер не знает.
**Причина:** `Попытка ... Исключение КонецПопытки` с пустым телом (`ObjectModule.bsl:67-70`).
**Решение:** §4.4 — счётчик `БезЕдиниці` в отчёт-результат + `ЗаписьЖурналаРегистрации(..., Предупреждение, ...)`; не глушить молча.

### 6.7 ⚠️ BuhBud-only + хрупкая привязка к коду счёта
**Симптом:** запросы «не работают» против ERP.
**Причина:** источник `РегистрБухгалтерии.Хозрасчетный` сч.2051 есть только в BuhBud; `НайтиПоКоду("2051")` — допущение базы.
**Решение:** тестировать против BuhBud (`cfo/2442`) по Rule #-1; счёт параметризовать (§4.3).

## 8. Q&A

**Q:** Это эталонная обработка?
A: Нет. `СозданиеКомплектацийБух` — **ПРИМЕР пользователя** (tier 1–2), который мы поднимаем до **эталона класса A** РМ `ПомощникПродаж`/`ОбеспечениеПотребностей` (tier-5). У примера уже есть правильные зёрна (тонкая форма + мост, итоги по поиску — §2), но запись документов без транзакции/журнала, монолит-`ObjectModule`, хардкод счёта и пустой `Исключение` — это разрывы «до→эталон» (§3, §4).

**Q:** Что конкретно взять из эталона класса A?
A: §4.1 транзакционный оркестратор `НачатьТранзакцию/Попытка/ЗафиксироватьТранзакцию`+`ЖурналРегистрации` (из `ПомощникПродаж.СоздатьДокументыСервер`); §4.2 вынос логики в общий модуль `А_СозданияКомплектацийСервер` (делегирование, как `НоменклатураСервер.*`/`Продажи.НайтиСоздатьДокумент`); §4.5 программное `УсловноеОформление`+`ЦветаСтиля`; §4.6 фон `ДлительныеОперации` (из `ОбеспечениеПотребностей`).

**Q:** Почему встроенный поиск по таблице нельзя использовать для фильтра?
A: Штатный «Найти» только подсвечивает совпадение и **не даёт события** в модуле формы — нельзя ни сузить состав строк, ни пересчитать итоги. Решение — поле-поиск `Пошук` + `OnChange`, перестраивающее видимую таблицу из полного набора (§2.2, грабля 6.1).

**Q:** Видимая таблица и ТЧ объекта — одно и то же?
A: Нет. Полный набор — `Объект.ТабличнаяЧастьОстатков`; `ТаблицаАнализа` — фильтрованная read-only копия. Документы заполняются из **полного** набора, фильтр на «Аналіз» на заполнение не влияет (§2.2, §4.8).

**Q:** Почему документам комплектации не нужны `Курс=1`/`Кратность=1`/`А_`-флаги из `bas-doc-fill`?
A: `КомплектацияНоменклатуры` в BuhBud — **нерасчётный** документ комплектации, а не ERP-документ взаиморасчётов. Чек-лист `bas-doc-fill` (Курс/Кратность/суммы/флаги обмена) обязателен для расчётных (Реализация/Приобретение/ПКО/РКО), здесь не применим. Нужны транзакция и журнал (§4.1) — это применимо всегда.

**Q:** Где брать вербатим?
A: ПРИМЕР — `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/` (`Ext/ObjectModule.bsl` 203 стр, `Forms/Форма/Ext/Form/Module.bsl` 151 стр, `Forms/Форма/Ext/Form.xml`). ЭТАЛОН класса A — `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl` и `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl`. Все имена/строки сверены с живым кодом (Rule #-1).
