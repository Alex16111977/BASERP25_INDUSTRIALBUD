## 1. TL;DR (самое важное за 30 секунд)

1. **Тонкая форма = диспетчер UX** (отборы/итоги/действия/цвета/диалоги/запуск фона), тяжёлая логика — в движке. Эталон тонкой формы-диспетчера — оба РМ класса A.
2. **Видимая ТЗ ≠ полный набор**: фильтр и итоги формы строятся по `Объект.ТабличнаяЧастьX` на клиенте; документы заполняются из ПОЛНОГО набора, фильтр на них не влияет.
3. **Два механизма итогов — не путать**: авто-подвал `Footer`/`FooterDataPath` = «итог по ВСЕЙ ТЧ»; реквизиты-итоги в цикле фильтра = «итог по отбору/поиску». **Хочешь «итог как на экране» — считай в том же цикле, что строишь видимую таблицу** (§4).
4. **Отборы РМ — равенство + текст-поиск** (`СтрНайти` по `ВРег()`); серверные гибкие отборы — через `КомпоновщикНастроек` на временной СКД (эталон `ОбеспечениеПотребностей`, §3.2).
5. **Действия по строке**: мутирующее одиночное → заменить **массовой** операцией по `ВыделенныеСтроки`; навигационное (открыть документ) → под гардом `ТипЗнч <> Тип("Строка")`.
6. **Условное оформление — ТОЛЬКО кодом** (`УсловноеОформление.Элементы.Добавить()`, цвета через `ЦветаСтиля`/`Новый Цвет`); `<TextColor>` в `Form.xml` внешней обработки валит `epf-build` (Исключение XDTO).
7. **Master-detail**: лёгкий — `ОтборСтрок = ФиксированнаяСтруктура` в `OnActivateRow` (эталон `ОбеспечениеПотребностей`); деталь по активной строке — через **debounce** `ПодключитьОбработчикОжидания(...,0.1,Истина)`.
8. **Тяжёлый расчёт/массовое создание — в фон** (`ДлительныеОперации.ВыполнитьВФоне` ↔ `ДлительныеОперацииКлиент.ОжидатьЗавершение` ↔ `*Завершение`); тяжёлая запись — в транзакцию. Эталон фона — `ОбеспечениеПотребностей`.

## 3. Отборы

### 3.1 Серверный гибкий отбор: СКД внутри формы (ЭТАЛОН РМ)

Профессиональный способ дать пользователю настраиваемые отборы на источник данных РМ — **реквизит формы типа `НастройкиКомпоновщикаКомпоновкиДанных`** + СКД-макет, выгруженный из самой обработки. Это полноценная панель отборов без отдельного отчёта; предзаданные значения проставляются хелпером.

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl` (инициализация ~3837–3851; применение простых отборов ~60–76).

```bsl
&НаСервере
Процедура ИнициализироватьКомпоновщикНастроекДляОтборов(ДоступныеТипыОбеспечения)
	Обработка = РеквизитФормыВЗначение("Объект");
	СхемаКомпоновкиДанных = Обработка.ПолучитьМакет("МакетКомпоновкиДляСерверныхОтборов");
	УстановитьДоступныеТипыИсточникиОбеспеченияВСКД(СхемаКомпоновкиДанных, ДоступныеТипыОбеспечения);
	АдресСхемыКомпоновкиДанных = ПоместитьВоВременноеХранилище(СхемаКомпоновкиДанных, УникальныйИдентификатор);
	ИсточникНастроек = Новый ИсточникДоступныхНастроекКомпоновкиДанных(АдресСхемыКомпоновкиДанных);
	КомпоновщикНастроекДляОтборов.Инициализировать(ИсточникНастроек);
	КомпоновщикНастроекДляОтборов.ЗагрузитьНастройки(СхемаКомпоновкиДанных.НастройкиПоУмолчанию);
	КомпоновщикНастроекДляОтборов.Восстановить(СпособВосстановленияНастроекКомпоновкиДанных.ПроверятьДоступность);
КонецПроцедуры
// предзаданные значения — хелпером, НЕ ручной правкой ПользовательскихНастроек:
ОтразитьПростойОтборВОтборахКомпоновки(КомпоновщикНастроекДляОтборов, "Подразделение", ОтборПоПодразделению, Ложь);
```

**Разбор:**
1. Источник доступных настроек = СКД-макет, помещённый во временное хранилище → `ИсточникДоступныхНастроекКомпоновкиДанных(адрес)`.
2. Простое предзаданное значение проставлять `ОтразитьПростойОтборВОтборахКомпоновки(Компоновщик, ИмяПоля, Значение, ЭтоОтборПоГруппе)`: он сам ставит `Использование=ЗначениеЗаполнено(Значение)`, `ВидСравнения=Равно/ВИерархии`, `ПравоеЗначение`.
3. В фон/запрос передавать `КомпоновщикНастроекДляОтборов.ПолучитьНастройки()` / `.Настройки.Отбор` (а не парсить элементы вручную).

> Когда применять: РМ с богатым набором фильтров (тип обеспечения, подразделение, склад, организация). Для простой обработки на 1–2 фильтра достаточно §3.2.

### 3.2 Отборы-равенство + текст-поиск (ПРИМЕР → паттерн)

Для лёгкой обработки на 1–2 фильтра гибкая СКД избыточна. **ПРИМЕР** `СозданиеКомплектацийБух` решает это клиентским отбором по реквизитам формы — паттерн рабочий и читаемый, оставляем как есть.

**ПРИМЕР-обработка** (НЕ эталон). Источник: `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/Forms/Форма/Ext/Form/Module.bsl`.

```bsl
&НаКлиенте
Процедура ПрименитьОтборИИтоги()
	ИтогоЗалишок = 0; ИтогоВНорме = 0; ИтогоПонад = 0;          // (1) сброс итогов
	ТаблицаАнализа.Очистить();
	ТекстПошуку = ВРег(СокрЛП(Пошук));
	Для Каждого Стр Из Объект.ТабличнаяЧастьОстатков Цикл
		Если ЗначениеЗаполнено(ОтборСклад) И Стр.Склад <> ОтборСклад Тогда Продолжить; КонецЕсли;
		Если ЗначениеЗаполнено(ОтборЭталон) И Стр.ОбщееНазвание <> ОтборЭталон Тогда Продолжить; КонецЕсли;
		Если ТолькоПонадНорму И НЕ (Стр.ПонадНорму > 0) Тогда Продолжить; КонецЕсли;
		Если НЕ ПустаяСтрока(ТекстПошуку) Тогда
			Ціль = ВРег(Строка(Стр.Номенклатура) + " " + Строка(Стр.ОбщееНазвание) + " " + Строка(Стр.Склад));
			Если СтрНайти(Ціль, ТекстПошуку) = 0 Тогда Продолжить; КонецЕсли;
		КонецЕсли;
		НС = ТаблицаАнализа.Добавить(); // ... перенос колонок
		ИтогоЗалишок = ИтогоЗалишок + Стр.Остаток;                 // (2) итог в том же цикле
		ИтогоВНорме  = ИтогоВНорме  + Стр.ВНорме;
		ИтогоПонад   = ИтогоПонад   + Стр.ПонадНорму;
	КонецЦикла;
КонецПроцедуры
```

**Разбор паттерна:**
1. Источник — `Объект.ТабличнаяЧастьОстатков` (полный набор), приёмник — `ТаблицаАнализа` (реквизит формы, видимая ТЗ, `ReadOnly`).
2. Равенство → `ЗначениеЗаполнено(ОтборX) И Стр.Поле <> ОтборX → Продолжить`. Пустой отбор = «не фильтровать».
3. Предикат-флаг → `ТолькоПонадНорму И НЕ (Стр.ПонадНорму > 0) → Продолжить`.
4. Текст-поиск → `СтрНайти(ВРег(конкатенация полей), ВРег(СокрЛП(Пошук))) = 0 → Продолжить`. Регистронезависимо через `ВРег()` с обеих сторон.
5. **Реактивность:** у каждого поля отбора `OnChange → ПрименитьОтборИИтоги` — фильтрация мгновенная, без кнопки «Применить».

✏️ **Как поднять до эталона, если фильтров станет много** (>3 или нужны иерархия/«в списке»): перейти на §3.1 (СКД-компоновщик), а тяжёлый перезапрос убрать с клиента в движок/фон (§7). Пока фильтров 1–3 — клиентский проход дешевле и проще, ломать его не нужно.

### 3.3 Контекстный «Фільтр за полем» (по ячейке под курсором)

**ПРИМЕР-обработка** (НЕ эталон). Источник: `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/Forms/Форма/Ext/Form/Module.bsl`.

```bsl
&НаКлиенте
Процедура ПрименитьФильтрПоКолонке(ИмяКолонки, СтрокаДанных)
	Если СтрокаДанных = Неопределено Тогда Возврат; КонецЕсли;
	Если ИмяКолонки = "ТАСклад" Тогда
		ОтборСклад = СтрокаДанных.Склад;
	ИначеЕсли ИмяКолонки = "ТАОбщееНазвание" Тогда
		ОтборЭталон = СтрокаДанных.ОбщееНазвание;
	ИначеЕсли ИмяКолонки = "ТАНоменклатура" Тогда
		Пошук = Строка(СтрокаДанных.Номенклатура);
	Иначе
		Возврат; // числовые колонки игнорируем
	КонецЕсли;
	ПрименитьОтборИИтоги();
КонецПроцедуры
```

**Идея:** `ТекущийЭлемент.Имя` колонки + `ТекущиеДанные` → ставим соответствующий реквизит-отбор; числовые колонки игнорируем. «Скинути» обнуляет все фильтры и зовёт `ПрименитьОтборИИтоги()`.

> ⚠️ Имена в `ИмяКолонки` — это **имена элементов формы** (`ТАСклад`, `ТАОбщееНазвание`), а НЕ имена реквизитов ТЗ. Сверять по Form.xml через [form-info](#) перед правкой.

## 4. Итоги (включая 🔑 ИТОГИ ПО ПОИСКУ — детальный разбор и рецепт)

Два независимых механизма итогов — **не путать**:

| Механизм | Что считает | Где задаётся | Реагирует на отбор/поиск? |
|---|---|---|---|
| **Авто-итоги подвала** (`Footer`/`FooterDataPath`) | сумму по **всей** ТЧ объекта | XML формы (декларативно) | ❌ НЕТ — считает платформа по полной ТЧ |
| **Итоги-реквизиты** («по отбору»/«по поиску») | сумму по **отфильтрованным** строкам | код, в цикле фильтра | ✅ ДА — пересчёт в том же проходе |

### 4.1 🔑 Кейс «итоги по поиску» — проблема и рецепт

🚫 **Симптом:** бухгалтер вводит текст в `Пошук`, видимая таблица сжимается до 5 строк, а сумма в подвале по-прежнему показывает итог по всем 126 строкам. «Итог не сходится с тем, что на экране».

**Причина:** подвальные `Total*` (через `FooterDataPath`) платформа считает по **полной** ТЧ (`Объект.ТабличнаяЧастьОстатков`), а отбор/поиск выкидывает строки только из **видимой** копии (`ТаблицаАнализа`). Подвал ТЧ физически не знает про клиентский фильтр — он привязан к данным таблицы, а не к её визуальному состоянию.

✅ **Рецепт «итоги по поиску»** (3 шага):

1. **Завести отдельные реквизиты-итоги формы** (не подвал ТЧ): `ИтогоЗалишок`, `ИтогоВНорме`, `ИтогоПонад` — числовые, `ReadOnly`, вынести на метрик-панель (группа «Підсумки», `Horizontal/StrongSeparation`, `TitleLocation=Top`).
2. **Считать их В ТОМ ЖЕ цикле фильтра** `ПрименитьОтборИИтоги` (§3.2): после прохождения всех предикатов (включая `СтрНайти` поиска) строка `Добавить()`-ится в видимую ТЗ И прибавляется к `ИтогоX`. Значит итог автоматически = «сумма по поиску».
3. **Обнулять итоги в начале каждого прохода** (`ИтогоЗалишок = 0; …` до цикла) — иначе при повторном вводе текста они накапливаются поверх прошлого результата.

```bsl
// каркас «итоги по поиску» — итог считается ТОЛЬКО по строкам, прошедшим поиск
ИтогоЗалишок = 0; ИтогоВНорме = 0; ИтогоПонад = 0;   // (1) сброс
Для Каждого Стр Из Объект.ТабличнаяЧастьОстатков Цикл
	// ... все предикаты отбора + СтрНайти(поиск) с Продолжить ...
	НС = ТаблицаАнализа.Добавить();                   // прошла поиск → видна
	ИтогоЗалишок = ИтогоЗалишок + Стр.Остаток;        // (2) и попала в итог
КонецЦикла;
```

> ⭐ **Правило-памятка:** хочешь «итог как на экране» — считай итог в том же цикле, что строишь видимую таблицу. Подвальный `Footer`/`FooterDataPath` — это «итог по всем данным», для «итога по отбору/поиску» он не годится в принципе.

**Связь с эталоном.** В РМ класса A та же идея реализована как **«деталь по активной строке»**: эталон `ОбеспечениеПотребностей` пересчитывает надписи-реквизиты формы (остаток/единица и т.д.) **по текущей строке** в обработчике ожидания `ЗапасыПриАктивизацииСтрокиОбработчикОжидания` (§6.1). Это тот же класс задачи — «показать число, согласованное с текущим состоянием грида»; разница лишь в гранулярности (по поиску vs по активной строке).

### 4.2 Авто-итоги подвала ТЧ (когда поиска НЕТ) — ЭТАЛОН

Когда таблица показывает **весь** набор (фильтр не клиентский, а через `ОтборСтрок`/перезапрос), итоги дешевле задать декларативно: на `Table` — `Footer=true`, на суммовой колонке — `FooterDataPath` на авто-реквизит `Total<Имя>`. Так оформлены подвалы в РМ класса A (`ПомощникПродаж`, `ОбеспечениеПотребностей`).

**ПРИМЕР-обработка** (форма, оформлена этим способом). Источник: `_Rarzrabotki/Обработки/А_ОбработкаДисбалансаПоПодразделениям/Forms/Форма/Ext/Form.xml`.

```xml
<InputField name="ДокументыДисбалансаСуммаДокумента" id="37">
	<DataPath>Объект.ДокументыДисбаланса.СуммаДокумента</DataPath>
	<EditMode>EnterOnInput</EditMode>
	<FooterDataPath>Объект.ДокументыДисбаланса.TotalСуммаДокумента</FooterDataPath>
</InputField>
```

Платформа сама суммирует колонку. В `СинхронизироватьТовары` так оформлены `TotalПозиций/TotalСуммаРазницы/TotalДокументов/TotalДействий/TotalТребуютРешения` на верхней таблице складов.

> ⚠️ `FooterDataPath` указывает на **полный путь** `Объект.ТЧ.Total<Реквизит>` (имя `Total` + имя реквизита). Если ошибиться (напр. `TotalДоговоров` вместо реального имени) — `form-compile` соберёт, но подвал не заполнится. Грабли уже ловились в `СинхронизироватьВзаиморасчеты` (фикс `FooterDataPath`).

### 4.3 Итоги по выделенным строкам (ЭТАЛОН — дерево/мультивыбор)

Когда нужен «итог по выделенным» (вес/объём/сумма для мультивыбора) — обход `ВыделенныеСтроки`. ⚠️ **Асимметрия платформы**: у **дерева/таблицы формы** `ВыделенныеСтроки` = массив **идентификаторов** (нужен `НайтиПоИдентификатору`); у **динсписка** — массив **ссылок** (готов к серверному методу, §5.2).

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/РабочееМестоМенеджераПоДоставке/Forms/Форма/Ext/Form/Module.bsl:3618-3636`.

```bsl
&НаКлиенте
Процедура ПересчитатьИтогиПоРаспоряжениямНаДоставку()
	Вес = 0; Объем = 0;                                  // сброс аккумуляторов
	Для Каждого ИД Из Элементы.РаспоряженияНаДоставку.ВыделенныеСтроки Цикл
		Стр = РаспоряженияНаДоставку.НайтиПоИдентификатору(ИД);
		Вес = Вес + Стр.Вес;
		Объем = Объем + Стр.Объем;
	КонецЦикла;
КонецПроцедуры
```

> 🩹 **Грабли платформы (эталонный обход):** события «выделили все строки» (Ctrl+A) НЕТ. РМ доставки ловит это `ПодключитьОбработчикОжидания(...,1.3,Ложь)`, сравнивая `ВыделенныеСтроки.Количество()` с запомненным счётчиком и пересчитывая итоги только при расхождении (`…ОбработчикОжидания`, ~3598–3607). Если нужен «итог по любому выделению, включая Ctrl+A» — копировать этот приём.

## 5. Действия по строкам и массовые операции

### 5.1 Действие по строке: навигация под гардом типа (ПРИМЕР → паттерн)

Действие по строке = операция над **одной** записью видимой таблицы (открыть документ, перейти к источнику). Главный гард — **тип реквизита**, потому что составной реквизит может хранить либо ссылку, либо строковое представление.

**ПРИМЕР-обработка** (НЕ эталон). Источник: `_Rarzrabotki/Обработки/СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`.

```bsl
// «Відкрити документ ЕРП» / двойной клик: открываем ТОЛЬКО если это ссылка, а не строка
Если ТипЗнч(ТекущиеДанные.ДокументЕРП) <> Тип("Строка") И ЗначениеЗаполнено(ТекущиеДанные.ДокументЕРП) Тогда
	ПоказатьЗначение(, ТекущиеДанные.ДокументЕРП);
КонецЕсли;
```

**Паттерн:** `ТипЗнч(...) <> Тип("Строка") И ЗначениеЗаполнено(...)` → `ПоказатьЗначение`. Без проверки типа открытие строкового представления упадёт.

> 🚫 **Антипаттерн «Дія по рядку».** В `СинхронизироватьТовары` была кнопка «Дія по рядку» (действие-мутация по одной строке) — её **убрали** как неудобную; функция `ВыполнитьСинхронизациюСтроки` оставлена в `ObjectModule` лишь для совместимости, UI её не вызывает. Вывод (подтверждён эталоном — оба РМ класса A делают массовые действия над выделением, а не построчно): одиночные **мутирующие** действия по строке заменяй **массовой** операцией по галкам (§5.2). Одиночные **навигационные** (открыть документ) — оставляй.

### 5.2 Массовые операции (галки / выделенные строки)

Две разновидности массовых кнопок. **ПРИМЕР-обработка** показывает UX-сбор галок; **ЭТАЛОН** показывает, как профессионально обернуть само массовое выполнение.

**A. По всем строкам таблицы** (верхний грид) — прямой цикл по всей ТЧ. ПРИМЕР `СинхронизироватьТовары`:

```bsl
&НаКлиенте
Процедура ВибратиВсі(Команда)
	Для Каждого Стр Из Объект.ТаблицаСкладов Цикл
		Стр.Синхронизировать = Истина;
	КонецЦикла;
КонецПроцедуры
```

**B. По выделенным строкам** (нижний грид) — только то, что выделено мышью. ПРИМЕР `СинхронизироватьТовары`:

```bsl
Для Каждого ИдСтроки Из Элементы.ТаблицаДокументовФорма.ВыделенныеСтроки Цикл
	СтрокаТЗ = Объект.ТаблицаДокументов.НайтиПоИдентификатору(ИдСтроки);
	Если СтрокаТЗ <> Неопределено Тогда
		СтрокаТЗ.Синхронизировать = Истина;
	КонецЕсли;
КонецЦикла;
```

**Паттерн B:** `Элементы.<Таблица>.ВыделенныеСтроки` (для таблицы формы — ИД) → `ТЧ.НайтиПоИдентификатору(Ид)` → мутация поля-галки.

✅ **ЭТАЛОН — как профессионально выполнить массовое действие над выделением (транзакция + счётчик).** Источник: `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl` (~6544–6600).

```bsl
&НаСервере
Функция УстановитьПометкуУдаленияСервер(ВыделенныеДокументы)
	Сч = ВыделенныеДокументы.Количество();
	КоличествоИзмененныхДокументов = 0;
	Отказ = Ложь;
	НачатьТранзакцию();
	Попытка
		Пока Сч > 0 Цикл
			Сч = Сч - 1;
			ДокументНеПомеченНаУдаление = Ложь;
			СтрокаТаблицы = Объект.Документы.НайтиПоИдентификатору(ВыделенныеДокументы[Сч]);
			Если СтрокаТаблицы = Неопределено Тогда Продолжить; КонецЕсли;
			ПометитьНаУдалениеДокумент(СтрокаТаблицы, ДокументНеПомеченНаУдаление);
			Если ДокументНеПомеченНаУдаление Тогда
				Отказ = Истина;
			Иначе
				КоличествоИзмененныхДокументов = КоличествоИзмененныхДокументов + 1;
			КонецЕсли;
		КонецЦикла;
		Если Отказ Тогда
			ОтменитьТранзакцию();
			ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление';uk='Позначка документів на видалення'"),
				УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
			Возврат 0;
		КонецЕсли;
		ЗафиксироватьТранзакцию();
	Исключение
		ОтменитьТранзакцию();
		ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление';..."),
			УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат 0;
	КонецПопытки;
	Возврат КоличествоИзмененныхДокументов;
КонецФункции
```

**Эталонные конвенции (брать дословно):**
- Всё выделение — в **одной транзакции**: любой сбой → `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации(...,ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))` + `Возврат 0` (никаких half-applied состояний).
- Серверная функция **возвращает счётчик** обработанных → клиент строит человекочитаемое `НСтр`-оповещение (`Показано документов (N)`).
- Тексты двуязычные `НСтр("ru=…;uk=…")`.

**Подтверждение перед массовой записью** (ПРИМЕР `СинхронизироватьТовары`) — `ПоказатьВопрос` с числом выбранных и дефолтом «Нет»:

```bsl
ТекстВопроса = "Синхронізувати вибрані документи (" + КолВыбрано + ")?";
ПоказатьВопрос(Новый ОписаниеОповещения("ПослеВопросаСинхронизация", ЭтотОбъект),
	ТекстВопроса, РежимДиалогаВопрос.ДаНет, , КодВозвратаДиалога.Нет);
```

✏️ **Как поднять пример до эталона:** UX-сбор галок (`ВибратиВсі`/`ВыделенныеСтроки`) у примера хорош и остаётся; **само выполнение** массового действия (провести/пометить/обмен) обернуть в транзакцию со счётчиком и `ЗаписьЖурналаРегистрации` по образцу `ПомощникПродаж` выше, а ошибки НЕ глушить пустым `Исключение`. Рецепт перепроведения помеченных и обязательный перечит объекта — см. [obr_sverka_sinhronizaciya.md](obr_sverka_sinhronizaciya.md).

## 6. Master-detail (две связанные таблицы)

### 6.1 Деталь по активной строке — через debounce-обработчик ожидания (ЭТАЛОН)

Когда выбор строки в мастере должен перерисовать детальную панель/итоги — прямое обновление в `ПриАктивизацииСтроки` тормозит при быстрой прокрутке. Эталонное решение: в событии только `ПодключитьОбработчикОжидания(...,0.1,Истина)` (третий параметр `Истина` = однократно), а вся отрисовка детали — в обработчике ожидания. Это **debounce**: отрабатывает только последняя активная строка.

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl` (событие ~796–806; обработчик ~2188–2240).

```bsl
&НаКлиенте
Процедура ЗапасыПриАктивизацииСтроки(Элемент)
	Если Элементы.СтраницыТаблицаПотребностей.ТекущаяСтраница = Элементы.СтраницаТаблицаЗапасы Тогда
		ПодключитьОбработчикОжидания("ЗапасыПриАктивизацииСтрокиОбработчикОжидания", 0.1, Истина);
	КонецЕсли;
КонецПроцедуры

&НаКлиенте
Процедура ЗапасыПриАктивизацииСтрокиОбработчикОжидания()
	Строка = Элементы.Запасы.ТекущиеДанные;
	Если Строка = Неопределено Тогда
		Элементы.ПанельРекомендаций.ТекущаяСтраница = Элементы.СтраницаНеВыделенаСтрока;
	Иначе
		Остаток = НадписьВФормате(Строка.Остаток, Строка.ЕдиницаИзмерения, "ЧДЦ=3; ЧН=0.000");
		// ... заполнение надписей-реквизитов формы из ТекущиеДанные, переключение ТекущаяСтраница панели деталей ...
	КонецЕсли;
КонецПроцедуры
```

### 6.2 Лёгкий master-detail фильтр: ОтборСтрок = ФиксированнаяСтруктура (ЭТАЛОН + ПРИМЕР)

Связь верхней (мастер) и нижней (деталь) таблиц делается **не** через «Связи» формы, а через `ОтборСтрок = ФиксированнаяСтруктура`, пересобираемую при активизации строки. `ФиксированнаяСтруктура` поддерживает только **равенство** — для master-detail этого достаточно.

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl` (~4358–4393).

```bsl
Процедура ОтборЗаказыНаСервере()
	СтруктураОтбора = Новый Структура();
	Если ФильтрОтметкаЗаказы Тогда СтруктураОтбора.Вставить("Отметка", Истина); КонецЕсли;
	Если ФильтрНеОбеспеченные Тогда СтруктураОтбора.Вставить("УдовлетворяетОтбору", Истина); КонецЕсли;
	Если ЗначениеЗаполнено(ФильтрПриоритет) Тогда СтруктураОтбора.Вставить("Приоритет", ФильтрПриоритет); КонецЕсли;
	Если ЗначениеЗаполнено(СтруктураОтбора) Тогда
		Элементы.ЗаказыКОбеспечению.ОтборСтрок = Новый ФиксированнаяСтруктура(СтруктураОтбора);
	Иначе
		Элементы.ЗаказыКОбеспечению.ОтборСтрок = Неопределено;
	КонецЕсли;
КонецПроцедуры
```

**ПРИМЕР-обработка** (тот же приём, мастер=склад → деталь=документы). Источник: `_Rarzrabotki/Обработки/СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`.

```bsl
// master-detail фільтр нижньої таблиці при активізації рядка складу
СтруктураОтбора = Новый Структура;
Если ТекущиеДанные <> Неопределено Тогда СтруктураОтбора.Вставить("Склад", ТекущиеДанные.Склад); КонецЕсли;
Если Объект.ПоказыватьТолькоРасхождения Тогда СтруктураОтбора.Вставить("ЕстьРасхождение", Истина); КонецЕсли;
Элементы.ТаблицаДокументовФорма.ОтборСтрок = Новый ФиксированнаяСтруктура(СтруктураОтбора);
```

**Паттерн (общий):** `OnActivateRow`/кнопка фильтра → собрать `Структура` **только из заполненных** условий (равенство) → `ОтборСтрок = Новый ФиксированнаяСтруктура(...)`; пустая структура → сбросить в `Неопределено`.

> Для **3-уровневого дерева** master-detail строится иначе — программным деревом из плоского упорядоченного запроса (`СледующийПоЗначениюПоля` → `ПолучитьЭлементы().Добавить()`), эталон `РабочееМестоМенеджераПоДоставке`. Это уже tier-5 визуализатор (класс B), для обработок «запрос→документы» обычно избыточно — см. [obr_arhitektura_obrabotki.md](obr_arhitektura_obrabotki.md) §дерево.

## 7. Фоновые операции (тяжёлый расчёт / массовое создание)

🚨 **Правило:** тяжёлый расчёт таблиц или массовое создание документов **не должно блокировать сеанс** — выносить в фон стандартной БСП-триадой. Тяжёлая запись — дополнительно в транзакцию (§5.2). Эталон фоновых операций — `ОбеспечениеПотребностей`.

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl` (запуск ~1469–1506; завершение ~1813–1843).

```bsl
&НаСервере
Функция ПолучениеТаблицыСпособовОбеспеченияВФоне()
	ПараметрыПроцедуры = Новый Структура;
	ПараметрыПроцедуры.Вставить("Настройки", КомпоновщикНастроекДляОтборов.ПолучитьНастройки());
	ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор);
	ПараметрыВыполнения.НаименованиеФоновогоЗадания = НСтр("ru='Формирование заказов: получение таблицы способов обеспечения';uk='...'");
	Возврат ДлительныеОперации.ВыполнитьВФоне("Обработки.ОбеспечениеПотребностей.ТаблицаСпособовОбеспечения",
		ПараметрыПроцедуры, ПараметрыВыполнения);
КонецФункции

&НаКлиенте
Процедура Далее(Команда)
	ДлительнаяОперация = ПолучениеТаблицыСпособовОбеспеченияВФоне();
	ПараметрыОжидания = ДлительныеОперацииКлиент.ПараметрыОжидания(ЭтаФорма);
	ДлительныеОперацииКлиент.ОжидатьЗавершение(ДлительнаяОперация,
		Новый ОписаниеОповещения("ПолучениеТаблицыСпособовОбеспеченияВФонеЗавершение", ЭтаФорма),
		ПараметрыОжидания);
КонецПроцедуры

&НаКлиенте
Процедура ПолучениеТаблицыСпособовОбеспеченияВФонеЗавершение(Результат, ДополнительныеПараметры) Экспорт
	Если Результат = Неопределено Тогда
		Возврат;                                              // отменено пользователем
	ИначеЕсли Результат.Статус = "Ошибка" Тогда
		ПоказатьПредупреждение(, Результат.КраткоеПредставлениеОшибки);
	ИначеЕсли Не ДалееКШагуНастройкаСпособовОбеспеченияНаСервере(Результат) Тогда
		СообщитьОбОтсутствииПотребностей();
	КонецЕсли;
КонецПроцедуры
```

**Эталонные конвенции (брать дословно):**
- Сервер: `ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор)` (+`НаименованиеФоновогоЗадания`), затем `ВыполнитьВФоне("Обработки.<Имя>.<Метод>", ПараметрыПроцедуры, ПараметрыВыполнения)`. Метод фона — **экспортная процедура менеджера обработки**.
- Результат фона передаётся **только через временное хранилище** (`ПоместитьВоВременноеХранилище(Результат, ПараметрыМетода.АдресРезультата)`); большие структуры напрямую не возвращать.
- Клиент: `ДлительныеОперацииКлиент.ОжидатьЗавершение(..., Новый ОписаниеОповещения("…Завершение", ЭтаФорма), ПараметрыОжидания)`.
- В `*Завершение` разобрать три исхода: `Результат = Неопределено` (отменено) / `Результат.Статус = "Ошибка"` (`ПоказатьПредупреждение` по `КраткоеПредставлениеОшибки`) / успех.

> ⭐ **Единый диспетчер нескольких фоновых операций** (несколько типов фона в одной форме): держать реквизит `ТекущаяФоноваяОперация` и ветвить ОДИН обработчик `*Завершение` по нему (`Если ТекущаяФоноваяОперация = "Расчёт" … ИначеЕсли = "Запись" …`). Эталон — `ПооперационноеПланирование2_2` (4 типа фона через один `Подключаемый_ПроверитьВыполнениеЗадания`).

✏️ **Как поднять примеры до эталона:** в `СозданиеКомплектацийБух`/`СинхронизироватьТовары` расчёт и заполнение идут синхронно в `&НаСервере` (форма «замирает» на тяжёлой выборке). Если набор строк/документов растёт — вынести `РассчитатьАнализ`/`ЗаполнитьДокументы` в фон по триаде выше, передавая результат через временное хранилище. Само транзакционное создание документов (обяз. поля взаиморасчётов `Курс=1`/`Кратность=1`, флаги обмена `А_Обработан`/`А_ВведенВЕРП`) — см. [obr_zaprosy_zapolnenie.md](obr_zaprosy_zapolnenie.md) + навык `bas-doc-fill`.

## 8. Условное оформление и подсветка — ТОЛЬКО кодом

🚫 **Главный антипаттерн внешних обработок:** `<TextColor>style:…</TextColor>` в `Form.xml` **внешней** обработки валит сборку `epf-build` с «Исключение XDTO» (в формах конфигурации работает, в .epf — нет). Поэтому **весь** цвет — в коде `ПриСозданииНаСервере` (см. память `epf_load_xdto_textcolor`).

### 8.1 Программное условное оформление таблицы (ЭТАЛОН)

Профессиональный способ — строить `УсловноеОформление.Элементы` кодом: `Поля` (что оформляем) + `Отбор` (`ЛевоеЗначение`=ПолеКД, `ВидСравнения`, `ПравоеЗначение`) + `Оформление` (`УстановитьЗначениеПараметра`). Типовые куски делегировать в `*Сервер.УстановитьУсловноеОформление*(ЭтаФорма)`.

**ЭТАЛОН РМ.** Источник: `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl` (~3348–3398).

```bsl
Процедура УстановитьУсловноеОформление()
	УсловноеОформление.Элементы.Очистить();                         // идемпотентность
	// подсветка обязательных незаполненных — типовым хелпером:
	ОбщегоНазначенияУТ.УстановитьСнятьОтметкуНезаполненного(УсловноеОформление,
		"ТоварыСклад", "Склад", "Товары", "СкладОбязателен");
	// своё правило — скрытие колонки по списку перечислений:
	Элемент = УсловноеОформление.Элементы.Добавить();
	ПолеЭлемента = Элемент.Поля.Элементы.Добавить();
	ПолеЭлемента.Поле = Новый ПолеКомпоновкиДанных(Элементы.ТоварыВариантОбеспечения.Имя);
	ВариантыОформленияДокументов = Новый СписокЗначений;
	ВариантыОформленияДокументов.Добавить(Перечисления.ВариантыОформленияДокументовПродажи.РеализацияТоваровУслуг);
	ОтборЭлемента = Элемент.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
	ОтборЭлемента.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.ВариантОформленияДокументов");
	ОтборЭлемента.ВидСравнения = ВидСравненияКомпоновкиДанных.ВСписке;
	ОтборЭлемента.ПравоеЗначение = ВариантыОформленияДокументов;
	Элемент.Оформление.УстановитьЗначениеПараметра("Видимость", Ложь);
	НоменклатураСервер.УстановитьУсловноеОформлениеЕдиницИзмерения(ЭтаФорма);    // делегирование типового
КонецПроцедуры
```

**ПРИМЕР-обработка** (тот же приём, окраска строк по статусу). Источник: `_Rarzrabotki/Обработки/СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`.

```bsl
// Помилки — червоним
Отбор.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.ТаблицаДокументов.Статус");
Отбор.ВидСравнения  = ВидСравненияКомпоновкиДанных.НачинаетсяС;
Отбор.ПравоеЗначение = "ПОМИЛКА";
Элемент.Оформление.УстановитьЗначениеПараметра("ЦветТекста", WebЦвета.Красный);
```

> ⚠️ **Грабли примера (поднять до эталона):** в `СинхронизироватьТовары` отбор оформления привязан к **тексту** статуса (`НачинаетсяС "ПОМИЛКА"/"ОК"`). Любая правка формулировки тихо ломает подсветку. Эталонно — окрашивать по **отдельному числовому/булевому реквизиту-коду состояния** (`КодСтану`), а не по человекочитаемому тексту; тогда перевод/переформулировка сообщений не ломает оформление.

### 8.2 Подсветка отдельного поля фоном

**ПРИМЕР-обработка** (НЕ эталон). Источник: `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/Forms/Форма/Ext/Form/Module.bsl`.

|---|---|---|

## 9. Подвал ТЧ + метрик-панель (как выбрать)

Два способа показать итоги — выбирать по тому, нужна ли реакция на отбор/поиск (см. §4):

- **Footer ТЧ** (`Footer=true` на `Table` + `FooterDataPath`→`Total<Имя>`) — авто-сумма по **всей** ТЧ. Применять, когда видна вся таблица (нет клиентского фильтра/поиска). Эталон — подвалы РМ класса A.
- **Метрик-панель** — отдельные `ReadOnly`-реквизиты-итоги (`TitleLocation=Top`), считаются **кодом в цикле фильтра**. Применять, когда есть клиентский отбор/поиск (§4.1).

В `СозданиеКомплектацийБух` используются ОБА: у `ТаблицаАнализа` `Footer=true`, а рядом — группа «Підсумки» с 3 кодовыми итогами как «итог по отбору».

## 10. Чек-лист UX-формы рабочего места (гейт перед «готово»)

- [ ] Полный набор — в ТЧ объекта; видимая таблица (`ReadOnly`) — отдельный реквизит формы?
- [ ] Отборы: 1–3 фильтра — клиентский проход (равенство + `СтрНайти` по `ВРег()`); много/иерархия — `КомпоновщикНастроек` на СКД (§3.1)?
- [ ] У клиентских полей отбора `OnChange → Применить…` (реактивность)?
- [ ] «Итог по поиску/отбору» нужен? → итоги-реквизиты считаются **в цикле фильтра**, со сбросом в 0 в начале (НЕ подвал ТЧ)?
- [ ] «Итог по всем данным» → `Footer=true` + `FooterDataPath` на `Total<Имя>` (имя реквизита совпадает)?
- [ ] Мутирующее действие по строке заменено массовой кнопкой по выделению? Навигационное — под гардом `ТипЗнч <> Тип("Строка")`?
- [ ] Массовое выполнение обёрнуто в транзакцию + счётчик + `ЗаписьЖурналаРегистрации` (НЕ пустой `Исключение`), под `ПоказатьВопрос` с дефолтом «Нет» (эталон `ПомощникПродаж`)?
- [ ] Тяжёлый расчёт/массовое создание — в фон (`ВыполнитьВФоне`↔`ОжидатьЗавершение`↔`*Завершение`, результат через врем. хранилище)?
- [ ] Master-detail: деталь по активной строке — через debounce `ПодключитьОбработчикОжидания(...,0.1,Истина)`; фильтр — `ОтборСтрок = ФиксированнаяСтруктура` (равенство), не «Связи»?
- [ ] Весь цвет — кодом в `ПриСозданииНаСервере`; оформление строк — по **коду состояния**, не по тексту статуса (НЕ `<TextColor>` в XML внешней обработки)?
- [ ] Имена колонок в коде = имена **элементов формы**, сверены по `form-info`?
- [ ] Гейт: `form-validate` (ложные «~Список.X»/External-type для внешних обработок — НЕ дефекты) → `bas-verify`?

**Q&A**

**Q: Почему итог в подвале не сходится с тем, что вижу после поиска?**
A: Подвал (`FooterDataPath`) суммирует **всю** ТЧ, поиск режет только видимую копию. Нужен «итог по поиску» → считай отдельные реквизиты-итоги в цикле фильтра (§4.1), а не через `Footer`.

**Q: Где взять «как профессионально» для отборов/действий — в обработках пользователя?**
A: Нет. ПРИМЕР-обработки (`СозданиеКомплектацийБух`, `СинхронизироватьТовары`) — это то, что **поднимаем** до эталона. Планка — РМ класса A (`ПомощникПродаж`/`ОбеспечениеПотребностей`): транзакционные массовые действия со счётчиком, СКД-отборы, фоновые операции, debounce master-detail.

**Q: Можно задать цвет строки через атрибут в Form.xml?**
A: В формах конфигурации — да, во **внешней** обработке `<TextColor>` ломает `epf-build` («Исключение XDTO»). Только кодом: `УсловноеОформление` для строк (по коду состояния, не по тексту), `Элементы.X.ЦветФона/ЦветТекста = ЦветаСтиля.*` для полей (§8).

**Q: Действие-мутация по одной строке — делать кнопкой «по строке»?**
A: Нет (антипаттерн «Дія по рядку» убрана; эталон тоже работает над выделением). Мутации — массовой кнопкой по выделенным строкам в транзакции (§5.2). Кнопка «по строке» оправдана только для навигации (открыть документ под гардом `ТипЗнч <> Тип("Строка")`).

**Q: Тяжёлый расчёт/много документов — считать прямо в `&НаСервере`?**
A: Нет — выносить в фон (`ДлительныеОперации.ВыполнитьВФоне` ↔ `ОжидатьЗавершение` ↔ `*Завершение`, результат через временное хранилище), эталон `ОбеспечениеПотребностей` (§7). Синхронный `&НаСервере` у примеров — допустимо лишь пока наборы малы.

**Q: Master-detail — через «Связи» формы?**
A: Нет, через `ОтборСтрок = Новый ФиксированнаяСтруктура(...)` в `OnActivateRow` мастера (§6.2, только равенство), а деталь рисовать в debounce-обработчике ожидания (§6.1). «Связи» формы для РМ-анализатора не используем.

**Q: `ВыделенныеСтроки` — это строки или идентификаторы?**
A: Зависит от типа таблицы: у **дерева/таблицы формы** — массив **идентификаторов** (нужен `НайтиПоИдентификатору`); у **динсписка** — массив **ссылок** (готов к серверному методу). Эта асимметрия — частый источник ошибок (§4.3).
