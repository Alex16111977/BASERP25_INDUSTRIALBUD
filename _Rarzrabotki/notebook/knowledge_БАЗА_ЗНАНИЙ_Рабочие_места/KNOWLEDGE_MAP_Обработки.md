# KNOWLEDGE MAP — База знаний: скилы `obr-*` для инженерии рабочих обработок 1С

> **Назначение:** on-disk база знаний о комплекте скилов `obr-*`, которые учат ИИ **создавать и
> дорабатывать рабочие внешние обработки 1С** класса «**запрос в базу → анализ → заполнение/создание
> документов**» с UX формы (отборы, итоги, действия по строкам, фоновые расчёты) — **на
> профессиональном уровне**. Цель базы — чтобы ИИ мог развивать эти скилы и давать обратную связь по
> их выполнению (где сгенерированная обработка не дотянула до эталона — проследить до скила и поправить
> reference).
>
> Аналог структуры: `_Rarzrabotki/notebook/knowledge_БСП/`. Для разработчика-инженера обработок 1С.

## Текущее состояние (2026-06-22)

Создан комплект из **4 скилов `obr-*`** + **10 файлов знаний** (этот манифест + 9 тематических). Грунт —
**на ЭТАЛОНЕ** (tier-5 РМ класса A + `БАЗА_ЗНАНИЙ_Рабочие_места_1С.md`), вербатим-сниппеты со ссылками на
файлы-источники и диапазоны строк; обработки пользователя фигурируют строго как **примеры для подъёма**.

**Вербатим-кирпичики из эталонов** (примеры заземления): транзакционный оркестратор пакетного создания
документов (`ПомощникПродаж` ~5863-6344), длительная фоновая операция (`ОбеспечениеПотребностей`
~1469-1843), master-detail debounce, серверные СКД-отборы + пакетные действия над выделением,
программное условное оформление через `ЦветаСтиля`, динсписки с подменой `ТекстЗапроса`
(`РегистрацияИзмененийДляОбменаДанными`).

## Скилы `obr-*` (4)

| Скил | Назначение | Триггеры |
|---|---|---|
| **`obr-obrabotka`** (ХАБ) | Каркас профессиональной обработки: тонкая форма-диспетчер + движок `ObjectModule` + мост; когда фон; `.epf`→epf-build+smoke | «новая обработка», «доработать обработку», «движок обработки», «АРМ» |
| **`obr-zapros-zapolnenie`** | Запросы 1С (Остатки/Обороты/соединения/ВЫРАЗИТЬ, Rule #-1) → заполнение/создание документов: обяз.поля, `А_`-флаги, Курс/Кратность, транзакционный оркестратор, идемпотентность | «запрос остатков», «заполнить документ кодом», «создать документ из обработки» |
| **`obr-forma-otbory-itogi`** | UX по образцу РМ: отборы (равенство+текст), итоги (вкл. по поиску), действия/массовые (`ВыделенныеСтроки`), условное оформление кодом, master-detail, фоновые пересчёты | «фильтр в обработке», «итоги по поиску», «деталь по активной строке», «подсветка кодом» |
| **`obr-sverka-sinhronizaciya`** | Сверка двух баз (ЕРП↔Казна/BuhBud) через COM/UUID 1:1/нетование/фазность/перепровод из UI | «сверка двух баз», «синхронизация ЕРП Казна», «перепровести помічені» |

Хаб `obr-obrabotka` читается первым (REQUIRED BACKGROUND у трёх ветвей). Переиспользуют существующие
`epf-init/epf-build/epf-add-form/form-compile/form-edit/form-patterns/skd-compile/bas-doc-fill`. Гейт
качества — существующий **`bas-verify`** (новый НЕ создаётся).

## TL;DR (самое важное за 30 секунд)

1. **4 скила `obr-*`** учат строить обработки «запрос→анализ→заполнение документов» **профессионально**:
   `obr-obrabotka` (хаб: каркас) → `obr-zapros-zapolnenie` (данные) + `obr-forma-otbory-itogi` (UX) +
   `obr-sverka-sinhronizaciya` (сверка).
2. **Эталон = рабочие места** (`_Rarzrabotki/Рабочие места/` + `БАЗА_ЗНАНИЙ_Рабочие_места_1С.md`),
   особенно класс A. **Обработки пользователя — примеры для подъёма, НЕ эталон.**
3. **Грунт на реальном коде** эталонов (Rule #-1): вербатим со ссылкой на источник, не из памяти.
4. **Профессиональные кирпичики:** транзакционный оркестратор документов, фоновые длительные операции,
   master-detail, программное условное оформление, отборы/итоги, пакетные действия над выделением.
5. **Гейт `bas-verify`** (Python COM запросы, epf-build, smoke win32com) — перед «готово».
6. **Обратная связь = петля приёмки:** дать скил свежему агенту + задачу «подними обработку X до
   профессионального уровня» → проверить вывод → зафиксировать пробел → поправить reference (файл 7).
