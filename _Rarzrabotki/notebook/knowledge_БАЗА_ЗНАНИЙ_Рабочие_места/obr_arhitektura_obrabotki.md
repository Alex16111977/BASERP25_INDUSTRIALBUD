## 1. TL;DR (самое важное за 30 секунд)

1. **Профессиональная планка задаётся ЭТАЛОНОМ РМ класса A** (`ПомощникПродаж`, `ОбеспечениеПотребностей` — оба tier-5). Их доминирующий сценарий = «набрать корзину/условия → ОДНИМ действием сформировать и провести ПАКЕТ документов» — ровно задача «запрос→документы».
2. **Три слоя**: движок (`ObjectModule.bsl`/общий модуль, экспортные методы — запросы/расчёт/формирование документов) ↔ тонкая форма (`Forms/Форма/Ext/Form/Module.bsl` — события, навигация, диалоги, запуск фона, отрисовка) ↔ мост (`РеквизитФормыВЗначение("Объект")` → метод движка → `ЗначениеВРеквизитФормы(...,"Объект")`).
3. **Запись пакета — всегда транзакция**: `НачатьТранзакцию()` → идемпотентная отмена ранее созданного → собрать массив документов → `Записать`/`Провести` → `ЗафиксироватьТранзакцию()`; ветка `Исключение` ВСЕГДА делает `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации(ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))` (эталон — `ПомощникПродаж`, §4.1).
4. **Когда фон**: тяжёлый расчёт/массовое формирование → длительная фоновая операция (`ДлительныеОперации.ВыполнитьВФоне` ↔ `ДлительныеОперацииКлиент.ОжидатьЗавершение` ↔ обработчик `*Завершение`), результат — ТОЛЬКО через временное хранилище (эталон — `ОбеспечениеПотребностей`, §5).
5. **Видимая ТЗ ≠ полный набор**: фильтр/итоги формы — на клиенте; документы заполняются из ПОЛНОГО набора, фильтр на запись не влияет.
6. **Сервер возвращает счётчик → клиент строит оповещение** (`Созданы документы (N)`); все тексты двуязычные `НСтр("ru=...;uk=...")` (эталон класса A).
7. **Цвет/оформление — только кодом** (`УсловноеОформление.Элементы` + `ЦветаСтиля.*` или `Новый Цвет(...)` в `ПриСозданииНаСервере`); `<TextColor>` в `Form.xml` внешней обработки валит `epf-build` (Исключение XDTO).

## 2. Канон класса A: «тонкий слой UI + делегирование в движок»

«Профессионально» в терминах этой базы = совпасть с анатомией РМ класса A. Доминирующий сценарий класса A («операционный формирователь-корзина»): менеджер роли набирает корзину/условия и **ОДНИМ действием формирует и проводит пакет документов в одной транзакции**. Эталоны — `ПомощникПродаж` (цепочка до 12 типов документов в одной транзакции) и `ОбеспечениеПотребностей` (мастер из 5 шагов + фоновое формирование заказов).

| Слой | Где живёт | Ответственность | НЕ делает |
|---|---|---|---|
| **Движок** | `Ext/ObjectModule.bsl` / `Ext/ManagerModule.bsl` / общий модуль `А_<Объект>Сервер` | Запросы, алгоритмы анализа, формирование/правка/проведение документов; экспортные методы; читает свои реквизиты/ТЧ напрямую | Ничего не знает про форму, `Элементы.*`, цвета |
| **Форма** | `Forms/Форма/Ext/Form/Module.bsl` | Тонкий UI/оркестрация: события, wizard-навигация, отборы/итоги, запуск фона, диалоги, оповещения, отрисовка детали | Не содержит тяжёлой бизнес-логики (запросов/записи документов) |
| **Мост** | `РеквизитФормыВЗначение` / `ЗначениеВРеквизитФормы` | Материализовать объект-обработку → вызвать метод движка под `Попытка` → перелить ТЧ обратно в форму | — |

⭐ **Эталонный размер ролей** (калибровка планки): модули форм РМ класса A огромны (`ПомощникПродаж` ~10000+ строк, `ОбеспечениеПотребностей` ~5500+), но это код **оркестрации** (события/навигация/фон/оформление), а не бизнес-логика — тяжёлое (запись пакета, фоновый расчёт) уходит в серверные функции/общие модули. Тонкая форма ≠ маленькая форма; тонкая = «без бизнес-логики».

### 2.1 Мост форма→движок (минимальный, ПРИМЕР-обработка — отправная точка)

В простой обработке-примере мост выглядит так (это БАЗА, которую дальше доводят до класса A транзакцией/фоном):

```bsl
&НаСервере
Процедура РассчитатьНаСервере()
	ОбъектОбработки = РеквизитФормыВЗначение("Объект");
	Попытка
		ОбъектОбработки.РассчитатьАнализ();
	Исключение
		Сообщить(КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат;
	КонецПопытки;
	ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект");
	Сообщить("Розраховано позицій: " + Объект.ТабличнаяЧастьОстатков.Количество());
КонецПроцедуры
```
*Роль: **ПРИМЕР-обработка** (НЕ эталон). Источник: `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/Forms/Форма/Ext/Form/Module.bsl`.*

⭐ **Что здесь уже верно (оставляем):** материализация объекта через `РеквизитФормыВЗначение`, вызов под `Попытка`, обязательный `ЗначениеВРеквизитФормы` обратно.
⚠️ **Что поднимать до класса A (см. §3–§4):** запись документов должна идти транзакцией с журналом, оповещение — через возврат счётчика + `НСтр("ru=...;uk=...")`, тяжёлый расчёт — в фон.

### 2.2 Делегирование «класс A»: клиентская обёртка → серверный оркестратор

Эталонная точка входа кнопки «Создать документы» (ЭТАЛОН РМ): гейт `ПроверитьЗаполнение()` ПЕРЕД серверным вызовом (чтобы транзакция не стартовала на негодных данных), сервер возвращает число → клиент строит человекочитаемое оповещение.

```bsl
&НаКлиенте
Процедура СоздатьДокументыКлиентФрагмент(Знач Оповещение)
	Перем КоличествоСозданныхДокументов, МаксДатаАванса;
	РассчитатьИтоговыеПоказатели(ЭтаФорма);
	ОчиститьСообщения();
	ПередЗаписьюНаКлиентеСервер();
	Если ПроверитьЗаполнение() Тогда
		КоличествоСозданныхДокументов = СоздатьДокументыСервер();
		Если КоличествоСозданныхДокументов > 0 Тогда
			ТекстСообщения = НСтр("ru='Созданы документы (%КоличествоСозданныхДокументов%)';uk='Створені документи (%КоличествоСозданныхДокументов%)'");
			ТекстСообщения = СтрЗаменить(ТекстСообщения, "%КоличествоСозданныхДокументов%", КоличествоСозданныхДокументов);
		КонецЕсли;
		ПоказатьОповещениеПользователя(ТекстСообщения, , , БиблиотекаКартинок.Информация32);
	КонецЕсли;
	ВыполнитьОбработкуОповещения(Оповещение);
КонецПроцедуры
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl` (6441-6477).*

## 3. Профессиональные «кирпичики» (что строить НА УРОВНЕ эталона)

Обработка «запрос→документы» класса A собирается из готовых кирпичиков РМ. Для каждого — роль источника помечена явно. Глубокие разборы кирпичиков — в [obr_forma_otbory_itogi.md](obr_forma_otbory_itogi.md) (отборы/итоги/действия/фон) и [obr_zaprosy_zapolnenie.md](obr_zaprosy_zapolnenie.md) (запросы/заполнение).

### 3.1 ⭐ Транзакционный оркестратор пакетного создания документов (ядро класса A)

Самый важный кирпичик. Весь пакет — атомарно: или все провелись, или откат. Перед транзакцией — снять проведение ранее созданных (идемпотентность повторного «Создать»). Любой `Отказ` → `ВызватьИсключение` → ветка `Исключение` делает `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации`. Возврат — число созданных (управляет текстом оповещения).

```bsl
Функция СоздатьДокументыСервер()
	// ОтменаПроведенияРанееСозданныхДокументов — идемпотентность
	Если ДокументыСформированы Тогда
		МассивДокументов = Новый Массив;
		Для Каждого ТекСтрока Из Объект.Документы Цикл
			МассивДокументов.Добавить(ТекСтрока.ПолучитьИдентификатор());
		КонецЦикла;
		ПровестиОтменитьПроведениеДокументовСервер(МассивДокументов, Ложь);
	КонецЕсли;
	НачатьТранзакцию();
	Попытка
		Отказ = Ложь;
		МассивНайденныхДокументов = Новый Массив;
		// ... ветвление по ВариантОформленияДокументов, вызовы ЗаписатьЗаказ/ЗаписатьСчетНаОплату/ЗаписатьПКО ...
		// ПометкаНаУдалениеЛишнихДокументов (не вошедших в МассивНайденныхДокументов)
		Если Отказ Тогда
			ВызватьИсключение НСтр("ru='Ошибка завершения создания документов';uk='Помилка завершення створення документів'",
				ОбщегоНазначенияКлиентСервер.КодОсновногоЯзыка());
		КонецЕсли;
		ЗафиксироватьТранзакцию();
	Исключение
		ОтменитьТранзакцию();
		ЗаписьЖурналаРегистрации(
			НСтр("ru='Ошибка завершения создания документов';uk='Помилка завершення створення документів'"),
			УровеньЖурналаРегистрации.Ошибка,,,
			ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	КонецПопытки;
	// ... финал: счётчик в подвал + блокировка формы в режим просмотра ...
	Возврат МассивНайденныхДокументов.Количество();
КонецФункция
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `_Rarzrabotki/Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl` (5863-6344).*

**get-or-create реестрового документа** внутри оркестратора (берёт существующий при повторном формировании ИЛИ создаёт новый, регистрирует в `МассивНайденныхДокументов`):
```bsl
ДокументОбъект = Продажи.НайтиСоздатьДокумент(ЭтотОбъект, Документы.ЗаказКлиента,
```

### 3.2 ⭐ Длительные фоновые операции — КОГДА и КАК

**Когда фон обязателен:** расчёт таблиц/анализа или массовое формирование документов длительны и не должны блокировать сеанс. Триада БСП: `ВыполнитьВФоне` → `ОжидатьЗавершение` → `*Завершение`; параметры — через `Структура`, результат — ТОЛЬКО через временное хранилище.

```bsl
&НаСервере
Функция ПолучениеТаблицыСпособовОбеспеченияВФоне()
	ПараметрыПроцедуры = Новый Структура;
	ПараметрыПроцедуры.Вставить("Настройки", КомпоновщикНастроекДляОтборов.ПолучитьНастройки());
	ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор);
	ПараметрыВыполнения.НаименованиеФоновогоЗадания = НСтр("ru='Формирование заказов: получение таблицы способов обеспечения';uk='...'");
	Возврат ДлительныеОперации.ВыполнитьВФоне("Обработки.ОбеспечениеПотребностей.ТаблицаСпособовОбеспечения",
		ПараметрыПроцедуры, ПараметрыВыполнения);
КонецФункции

&НаКлиенте
Процедура Далее(Команда)
	ДлительнаяОперация = ПолучениеТаблицыСпособовОбеспеченияВФоне();
	ПараметрыОжидания = ДлительныеОперацииКлиент.ПараметрыОжидания(ЭтаФорма);
	ДлительныеОперацииКлиент.ОжидатьЗавершение(ДлительнаяОперация,
		Новый ОписаниеОповещения("ПолучениеТаблицыСпособовОбеспеченияВФонеЗавершение", ЭтаФорма),
		ПараметрыОжидания);
КонецПроцедуры

&НаКлиенте
Процедура ПолучениеТаблицыСпособовОбеспеченияВФонеЗавершение(Результат, ДополнительныеПараметры) Экспорт
	Если Результат = Неопределено Тогда
		Возврат; // отменено
	ИначеЕсли Результат.Статус = "Ошибка" Тогда
		ПоказатьПредупреждение(, Результат.КраткоеПредставлениеОшибки);
	ИначеЕсли Не ДалееКШагуНастройкаСпособовОбеспеченияНаСервере(Результат) Тогда
		СообщитьОбОтсутствииПотребностей();
	КонецЕсли;
КонецПроцедуры
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `_Rarzrabotki/Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl` (1469-1506, 1813-1843).*

**Единый диспетчер нескольких фоновых операций** (когда фоновых операций 2+): реквизит `ТекущаяФоноваяОперация` ветвит один обработчик завершения — не плодить по обработчику на операцию.
```bsl
&НаКлиенте
Процедура ПриЗавершенииОперации(Результат, ДопПараметры) Экспорт
	Если Результат = Неопределено ИЛИ Результат.Статус = "Отменено" Тогда Возврат; КонецЕсли;
	Если Результат.Статус = "Ошибка" Тогда ОбработатьОшибку(Результат); Возврат; КонецЕсли;
	Если    ТекущаяФоноваяОперация = "Расчёт"  Тогда ЗавершитьРасчёт(Результат.АдресРезультата);
	ИначеЕсли ТекущаяФоноваяОперация = "Запись" Тогда ЗавершитьЗапись(Результат.АдресРезультата);
	КонецЕсли;
КонецПроцедуры
```
*Роль: **ЭТАЛОН РМ**. Паттерн `ПооперационноеПланирование2_2` (4 типа фоновых операций через один обработчик).*

⚠️ **Грабли фона:** результат фоновой процедуры кладётся `ПоместитьВоВременноеХранилище(Результат, ПараметрыПроцедуры.АдресРезультата)` и читается в `*Завершение` — нельзя возвращать большие структуры напрямую из фонового задания.

### 3.3 Master-detail: деталь по активной строке через debounce

Когда выбор строки в мастер-таблице должен перерисовать детальную панель/итоги. Прямое обновление в `ПриАктивизацииСтроки` тормозит при быстрой прокрутке — `ПодключитьОбработчикОжидания(..., 0.1, Истина)` даёт debounce (отрабатывает только последняя активная строка).

```bsl
&НаКлиенте
Процедура ЗапасыПриАктивизацииСтроки(Элемент)
	Если Элементы.СтраницыТаблицаПотребностей.ТекущаяСтраница = Элементы.СтраницаТаблицаЗапасы Тогда
		ПодключитьОбработчикОжидания("ЗапасыПриАктивизацииСтрокиОбработчикОжидания", 0.1, Истина);
	КонецЕсли;
КонецПроцедуры

&НаКлиенте
Процедура ЗапасыПриАктивизацииСтрокиОбработчикОжидания()
	Строка = Элементы.Запасы.ТекущиеДанные;
	Если Строка = Неопределено Тогда
		Элементы.ПанельРекомендаций.ТекущаяСтраница = Элементы.СтраницаНеВыделенаСтрока;
	Иначе
		// заполнение надписей-реквизитов формы из ТекущиеДанные (НадписьВФормате)
	КонецЕсли;
КонецПроцедуры
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `ОбеспечениеПотребностей/.../Module.bsl` (796-806, 2188-2240).*

### 3.4 Пакетные действия над выделением — в транзакции

Массовые кнопки над выделенными строками (пометить/снять удаление, провести/отменить пачкой). Всё выделение — в одной транзакции: любой сбой → откат всех + `Возврат 0`. На клиенте собрать `Элементы.<Таблица>.ВыделенныеСтроки`, передать на сервер; сервер ведёт `КоличествоИзмененныхДокументов`, при `Отказ` — `ОтменитьТранзакцию()` + журнал + `Возврат 0`.

```bsl
&НаСервере
Функция УстановитьПометкуУдаленияСервер(ВыделенныеДокументы)
	Сч = ВыделенныеДокументы.Количество();
	КоличествоИзмененныхДокументов = 0;
	Отказ = Ложь;
	НачатьТранзакцию();
	Попытка
		Пока Сч > 0 Цикл
			Сч = Сч - 1;
			СтрокаТаблицы = Объект.Документы.НайтиПоИдентификатору(ВыделенныеДокументы[Сч]);
			Если СтрокаТаблицы = Неопределено Тогда Продолжить; КонецЕсли;
			ДокументНеПомеченНаУдаление = Ложь;
			ПометитьНаУдалениеДокумент(СтрокаТаблицы, ДокументНеПомеченНаУдаление);
			Если ДокументНеПомеченНаУдаление Тогда Отказ = Истина;
			Иначе КоличествоИзмененныхДокументов = КоличествоИзмененныхДокументов + 1; КонецЕсли;
		КонецЦикла;
		Если Отказ Тогда ОтменитьТранзакцию(); Возврат 0; КонецЕсли;
		ЗафиксироватьТранзакцию();
	Исключение
		ОтменитьТранзакцию();
		ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление';uk='...'"),
			УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат 0;
	КонецПопытки;
	Возврат КоличествоИзмененныхДокументов;
КонецФункции
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `ПомощникПродаж/.../Module.bsl` (6544-6600).*

### 3.5 Программное условное оформление кодом (НЕ XDTO TextColor)

Когда правила зависят от данных/перечислений (подсветка обязательных пустых, скрытие колонок ТЧ). Вызывается из `ПриСозданииНаСервере`; начинать с `УсловноеОформление.Элементы.Очистить()` (идемпотентность). Цвета — через `ЦветаСтиля.*`.

```bsl
Процедура УстановитьУсловноеОформление()
	УсловноеОформление.Элементы.Очистить();
	// Подсветка обязательных незаполненных — типовой хелпер:
	ОбщегоНазначенияУТ.УстановитьСнятьОтметкуНезаполненного(УсловноеОформление,
		"ТоварыСклад", "Склад", "Товары", "СкладОбязателен");
	// Скрытие колонки по отбору ВСписке:
	Элемент = УсловноеОформление.Элементы.Добавить();
	ПолеЭлемента = Элемент.Поля.Элементы.Добавить();
	ПолеЭлемента.Поле = Новый ПолеКомпоновкиДанных(Элементы.ТоварыВариантОбеспечения.Имя);
	ОтборЭлемента = Элемент.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
	ОтборЭлемента.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.ВариантОформленияДокументов");
	ОтборЭлемента.ВидСравнения = ВидСравненияКомпоновкиДанных.ВСписке;
	ОтборЭлемента.ПравоеЗначение = ВариантыОформленияДокументов; // СписокЗначений
	Элемент.Оформление.УстановитьЗначениеПараметра("Видимость", Ложь);
	// Типовые куски — делегировать в *Сервер-хелперы:
	НоменклатураСервер.УстановитьУсловноеОформлениеЕдиницИзмерения(ЭтаФорма);
КонецПроцедуры
```
*Роль: **ЭТАЛОН РМ** (класс A). Источник: `ПомощникПродаж/.../Module.bsl` (3348-3398). Объём УО в эталонах: ~570 строк в `ОбеспечениеПотребностей`, ~380 в `ПомощникПродаж`.*

🚫 **Цвет НЕ через `<TextColor>` в Form.xml** — XDTO-сериализация `<TextColor>style:...</TextColor>` в форме ВНЕШНЕЙ обработки валит `epf-build` («Исключение XDTO»). Только `ЦветаСтиля.*`/`Новый Цвет(R,G,B)` в коде (память: `epf_load_xdto_textcolor.md`).

### 3.6 Отборы в форме (СКД без отдельного отчёта) + клиентский ОтборСтрок

*Роль: **ЭТАЛОН РМ**. Источник: `ОбеспечениеПотребностей/.../Module.bsl` (3837-3851, 4029-4076).*

**Быстрый клиентский фильтр строк** уже загруженной ТЧ формы — `ОтборСтрок = Новый ФиксированнаяСтруктура(СтруктураОтбора)` (только равенство по реквизитам строки):
```bsl
СтруктураОтбора = Новый Структура();
Если ФильтрОтметкаЗаказы Тогда СтруктураОтбора.Вставить("Отметка", Истина); КонецЕсли;
Если ЗначениеЗаполнено(ФильтрПриоритет) Тогда СтруктураОтбора.Вставить("Приоритет", ФильтрПриоритет); КонецЕсли;
Если ЗначениеЗаполнено(СтруктураОтбора) Тогда
	Элементы.ЗаказыКОбеспечению.ОтборСтрок = Новый ФиксированнаяСтруктура(СтруктураОтбора);
Иначе
	Элементы.ЗаказыКОбеспечению.ОтборСтрок = Неопределено;
КонецЕсли;
```
*Роль: **ЭТАЛОН РМ**. Источник: `ОбеспечениеПотребностей/.../Module.bsl` (4358-4393).* Детали отборов/итогов/действий — [obr_forma_otbory_itogi.md](obr_forma_otbory_itogi.md).

## 4. Жизненный цикл «запрос → анализ → документы»

```
[Пользователь] → задаёт параметры/корзину (период, организация, фильтры)
       │
       ├─(1) «Рассчитать/Анализ» (читающая фаза, в форму) ─────────────┐
       │     лёгкий расчёт:  &НаСервере РеквизитФормыВЗначение("Объект")  │
       │                     → Движок.РассчитатьАнализ() → ЗначениеВРеквизитФормы → отрисовка
       │     тяжёлый расчёт:  ДлительныеОперации.ВыполнитьВФоне → ОжидатьЗавершение → *Завершение → отрисовка
       │
       └─(2) «Создать/Заполнить документы» (пишущая фаза, в движке) ─────┐
             ПроверитьЗаполнение() (гейт)                                 │
             → СоздатьДокументыСервер(): НачатьТранзакцию → отмена ранее созданных
               → собрать массив (get-or-create) → Записать/Провести → ЗафиксироватьТранзакцию
               (Исключение → ОтменитьТранзакцию + ЗаписьЖурналаРегистрации)
             → возврат счётчика → ПоказатьОповещениеПользователя("Созданы документы (N)")
```

**Сквозные конвенции класса A** (вшивать в любую обработку «запрос→документы»):
1. Транзакция оборачивает ЛЮБУЮ пакетную запись; ветка `Исключение` всегда `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации(ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))`.
2. Серверные функции возвращают счётчик обработанных → клиент строит `НСтр`-оповещение.
3. Все тексты двуязычные `НСтр("ru=...;uk=...")`.
4. Тяжёлый расчёт → фон; тяжёлая запись → транзакция.
5. Типовое оформление/УО делегируется в `*Сервер`-хелперы; своё — программно через `УсловноеОформление.Элементы.Добавить()`.
6. **Видимая ТЗ vs полный набор**: фильтр/итоги — для UI; документы заполняются из ПОЛНОГО набора `Объект.ТЧ`, фильтр на запись не влияет.

Двухбазовая сверка (фазность ЕРП↔Казна/BuhBud, COM/UUID/нетование) — [obr_sverka_sinhronizaciya.md](obr_sverka_sinhronizaciya.md).

## 5. Состав обработки (что внутри)

### 5.1 Главный реквизит `Объект`
Точка входа: в `Form.xml` — `MainAttribute=true`, тип `cfg:ExternalDataProcessorObject.<ВнутреннееИмя>`.
```xml
<Attribute name="Объект" id="1">
  <Type><v8:Type>cfg:ExternalDataProcessorObject.СозданиеКомплектацийБух</v8:Type></Type>
  <MainAttribute>true</MainAttribute>
  <Save><Field>Объект.НачалоПериода</Field></Save>
</Attribute>
```
⚠️ **Грабли имени (ПРИМЕР-обработки):** внутреннее имя метаданных часто = неочищенный клон-плейсхолдер (`ВнешняяОбработка2`/`ВнешняяОбработка3`), хотя файл/папка названы по делу. В типе реквизита и коде формы фигурирует внутреннее имя — при сборке `.epf` ловить рассинхрон. Определять тип объекта по `MainAttribute`, не по имени файла.

### 5.2 Реквизиты-параметры (шапка-отборы)
Реквизиты **объекта обработки**, сохраняемые между сеансами через `<Save>` + `AutoSaveDataInSettings=Use`. У эталонов класса A — это шапка wizard-шага (партнёр/организация/склад/период) с зависимыми `СвязиПараметровВыбора`.

### 5.3 ТЧ результата и ТЧ документов
- **ТЧ результата/анализа** — табличная часть объекта (`DataPath=Объект.ТабличнаяЧастьX`); полный набор для записи.
- **ТЧ `Документы`** (класс A) — список сформированных документов с состоянием; над ней массовые действия (§3.4) и сортировка `Состояние, Порядок`.

### 5.4 Итоги и команды
- **Итоги** — авто-подвал ТЧ (`Footer=true` + `FooterDataPath=Объект.ТЧ.Total<Реквизит>`) ИЛИ реквизиты формы (`ReadOnly`), считаемые в проходе фильтра. Детали — [obr_forma_otbory_itogi.md](obr_forma_otbory_itogi.md).
- **Команды** — `AutoCommandBar` формы, `Autofill=false`; кнопка `CommandBarButton` через `CommandName=Form.Command.<Имя>`; `Command` имеет уникальный `id` и `Action` без `xsi:type`.

## 6. Пример-«до» → эталон-«стало» (подъём кода пользователя до класса A)

Ниже — реальный код пользователя (роль: **ПРИМЕР-обработка**, НЕ эталон) и как применить эталонный паттерн РМ класса A. Полные кейсы — [case_sozdanie_komplektacij.md](case_sozdanie_komplektacij.md), [case_sinhronizirovat_tovary.md](case_sinhronizirovat_tovary.md).

### 6.1 ⭐ «Голая» запись документа без транзакции/журнала → транзакционный оркестратор (§3.1)

**ПРИМЕР-обработка `Создания комплектаций для бух учета` (ObjectModule):**
```bsl
ДокОбъект.Записать(РежимЗаписиДокумента.Запись); // без Попытка/транзакции вокруг записи пакета
```
*Источник: `_Rarzrabotki/Обработки/Создания комплектаций для бух учета/Ext/ObjectModule.bsl`.*

**Симптом:** при сбое на N-м документе первые N-1 уже записаны — half-applied состояние; повторный прогон плодит дубли; ошибка не попадает в журнал.
**Решение (ЭТАЛОН РМ §3.1):** обернуть запись ВСЕГО пакета в `НачатьТранзакцию()/Попытка/ЗафиксироватьТранзакцию()`, перед транзакцией снять проведение ранее созданных (идемпотентность), в `Исключение` — `ОтменитьТранзакцию()` + `ЗаписьЖурналаРегистрации(...,ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))`; вернуть счётчик созданных.

### 6.2 ⭐ Хардкод-литерал счёта в тексте запроса → параметр движка

**ПРИМЕР-обработка (ObjectModule):**
```bsl
Счет2051 = ПланыСчетов.Хозрасчетный.НайтиПоКоду("2051");
// ... и одновременно в тексте запроса литералом:
|	РегистрБухгалтерии.Хозрасчетный.Остатки(&НаДату, Счет.Код = ""2051"", , ) КАК Ост
```
**Симптом:** счёт зашит в двух местах строковым литералом (граблями двойных/одинарных кавычек в py-тесте, уже зафиксировано в памяти проекта); дублирование = рассинхрон.
**Решение:** вынести счёт в реквизит/константу/перечисление, в запрос передавать `ПланыСчетов...НайтиПоКоду(...)` один раз как `&параметр`. Перед BSL — Python COM pre-check запроса (Rule #-1). Разбор запросов — [obr_zaprosy_zapolnenie.md](obr_zaprosy_zapolnenie.md).

### 6.3 Ручные итоги/цвет на клиенте → авто-подвал + УО кодом (§3.5)

**ПРИМЕР-обработка (форма):**
```bsl
Элементы.ИтогоВНорме.ЦветФона = Новый Цвет(214, 240, 214); // хардкод RGB
// ... три итога считаются вручную циклом по Объект.ТабличнаяЧастьОстатков в клиентской процедуре
```
**Решение:** итоги — штатным подвалом колонок (`FooterDataPath=...Total<Колонка>`) или `ОтображатьИтоги`, а не ручным циклом; цвет/оформление — через `УсловноеОформление` + `ЦветаСтиля.*` (как в соседней `Синхронизировать`), а не `Новый Цвет(RGB)`. Детали — [obr_forma_otbory_itogi.md](obr_forma_otbory_itogi.md).

### 6.4 Round-trip всего объекта на каждую кнопку → тяжёлое в фон/на сервер (§3.2)

**ПРИМЕР-обработка (форма):** каждая команда делает `РеквизитФормыВЗначение("Объект")` → метод → `ЗначениеВРеквизитФормы` (сериализует ВЕСЬ объект ради одного вызова), результат — голым `Сообщить()`.
**Решение:** для лёгких операций — оставить мост; для тяжёлого расчёта/массового формирования — длительная фоновая операция (§3.2) с передачей лишь нужных данных через `Структура`; оповещение — `ОбщегоНазначения.СообщитьПользователю` (работает и в фоне, с привязкой к полю), а не голый `Сообщить`.

### 6.5 «Магические» строки-статусы и порожні `Исключение` (СинхронизироватьТовары)

**ПРИМЕР-обработка `СинхронизироватьТоварыТолькоТовары` (ObjectModule):** статус/действие моделируются вільними рядками (`"Перепровести в ЕРП"`, `"ПОМИЛКА: ..."`), диспетчер — ланцюг `Если СтрДок.Действие = "..."`; COM-доступ обёрнут в `Попытка ... Исключение КонецПопытки` с ПОРОЖНІМ блоком (помилки тихо ковтаються).
**Решение:** строки-стани → перелік/іменовані константи, диспетчер → `ВЫБОР`/карта `{ВидДії→Обработчик}`; результат дії → структура `{Успіх, Текст}` замість парсингу префікса. Порожній `Исключение` — антипаттерн (`/1c-bsl-review`): мінімум `ЗаписьЖурналаРегистрации(...,УровеньЖурналаРегистрации.Ошибка, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))`. Перед COM-запитами — Python COM pre-check (Rule #-1). Сверка/COM — [obr_sverka_sinhronizaciya.md](obr_sverka_sinhronizaciya.md).

| Сборка `.epf` из XML | `epf-build` | после правок |
| Сборка `.erf` (если объект-отчёт) | `erf-build` | для объектов с `ExternalReportObject.*` |
| Заполнение документов кодом | `bas-doc-fill` (обязательные поля/Курс/Кратность/флаги) | при создании расчётных документов |
| Гейт качества | **`bas-verify`** (существующий, новый НЕ создавать) | перед «готово» |

🚫 **`<TextColor>` в Form.xml** → `epf-build` «Исключение XDTO»; цвет только кодом (§3.5).
⚠️ **Lock Designer**: когда Designer держит конфигурацию, сборка `.epf` против stub-cfg (патч версии 2.17→2.13) — бинарник конфиг-независимый, но stub-база падает на `CommonForm.ФормаОтчета` для отчётов.

→ `bas-verify`: Python COM тест запросов (Rule #-1) · `form-validate`/`meta-validate` · `1c-bsl-review` · копирование в основную конфигурацию (Rule #4) · COM-smoke `ВнешниеОбработки.Создать(...)`.

## 8. Anti-patterns

- 🚫 **Тяжёлая бизнес-логика в модуле формы вместо движка** → нельзя тестировать изолированно (Python COM / `ВнешниеОбработки.Создать`). Решение: экспортные методы в `ObjectModule`/общий модуль, форма — тонкий диспетчер (эталон класса A).
- 🚫 **Запись пакета документов без транзакции** → half-applied состояние при сбое + дубли при повторе. Решение: транзакционный оркестратор §3.1 (отмена ранее созданных → запись → фиксация; `Исключение` → откат + журнал).
- 🚫 **Тяжёлый расчёт/массовое формирование синхронно на сервере** → блокировка сеанса, таймаут. Решение: длительная фоновая операция §3.2 (`ВыполнитьВФоне`/`ОжидатьЗавершение`/`*Завершение`).
- 🚫 **Возврат большой структуры из фонового задания напрямую** → не доходит. Решение: `ПоместитьВоВременноеХранилище` по `АдресРезультата`, читать в `*Завершение`.
- 🚫 **Забыли `ЗначениеВРеквизитФормы` после метода движка** → изменения ТЧ не появляются на форме. Решение: всегда `РеквизитФормыВЗначение` → метод → `ЗначениеВРеквизитФормы`.
- 🚫 **Заполнять документы из ВИДИМОЙ (отфильтрованной) таблицы** → теряются строки вне фильтра. Решение: из ПОЛНОЙ `Объект.ТЧ`.
- 🚫 **Голый `Сообщить` вместо возврата счётчика** → нет двуязычного оповещения, не работает в фоне. Решение: сервер возвращает число → клиент строит `НСтр("ru=...;uk=...")`; в фоне — `ОбщегоНазначения.СообщитьПользователю`.
- 🚫 **`<TextColor>` в Form.xml внешней обработки** → `epf-build` «Исключение XDTO». Решение: `ЦветаСтиля.*`/`Новый Цвет(...)` в `ПриСозданииНаСервере`.
- 🚫 **Порожній/«магічні» статуси та порожній `Исключение`** (ПРИМЕР `СинхронизироватьТовары`) → крихкість + проковтнуті помилки. Решение: перелік-стани + журнал помилок (§6.5).

## 9. Q&A

**Q: Что значит «профессиональная обработка» в этой базе?**
A: Совпасть с анатомией РМ класса A (`ПомощникПродаж`/`ОбеспечениеПотребностей`): тонкий слой UI + делегирование тяжёлого в движок, запись пакета — транзакцией с журналом, тяжёлый расчёт — фоном, оповещение — через возврат счётчика. Обработки пользователя (`СозданиеКомплектацийБух` и др.) — это «до», которое поднимают до этого уровня.

**Q: Где должна жить бизнес-логика?**
A: В движке (`ObjectModule`/`ManagerModule`/`А_<Объект>Сервер`) экспортными методами. Форма — события, навигация, фон, оформление, оповещения. Тонкая ≠ маленькая: у эталонов класса A форма на тысячи строк, но это оркестрация, не запросы/запись.

**Q: Когда нужна фоновая операция?**
A: Когда расчёт анализа или массовое формирование/проведение документов длительны (блокировали бы сеанс). Триада `ВыполнитьВФоне`/`ОжидатьЗавершение`/`*Завершение`, результат — через временное хранилище (§3.2). Лёгкий расчёт — синхронно через мост.

**Q: Почему запись документов обязательно в транзакции?**
A: Пакет должен быть атомарным (все или ничего), иначе при сбое остаётся half-applied состояние и дубли при повторе. Эталон — `СоздатьДокументыСервер` (§3.1): отмена ранее созданных → запись → фиксация; `Исключение` → `ОтменитьТранзакцию()` + журнал.

**Q: Как форма передаёт управление движку?**
A: Мост: `ОбъектОбработки = РеквизитФормыВЗначение("Объект")` → `ОбъектОбработки.МетодДвижка()` (под `Попытка`) → `ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект")`. Последний шаг обязателен.

**Q: Почему видимая таблица и `Объект.ТЧ` — разные сущности?**
A: Полный результат живёт в ТЧ объекта; видимая таблица — фильтрованная копия для UI. Документы заполняются из ПОЛНОГО набора, фильтр на запись не влияет.

**Q: Объект-обработка или объект-отчёт?**
A: Смотреть `MainAttribute` тип в `Form.xml`: `ExternalDataProcessorObject.*` → `epf-build`; `ExternalReportObject.*` → `erf-build`. По папке/файлу определять нельзя.
