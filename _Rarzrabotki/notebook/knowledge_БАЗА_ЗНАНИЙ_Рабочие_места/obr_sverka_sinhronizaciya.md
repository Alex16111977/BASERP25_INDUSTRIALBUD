**Ключевой факт перепроведения (граблина #1):** перепроводить документы можно ТОЛЬКО из интерактивной UI-сессии 1С Enterprise. В коде ПРИМЕРА-обработки это зафиксировано комментарием «вызывается ТОЛЬКО из UI».

**Ключевой факт моста баз (граблина #2):** связь между базами — по реквизиту `А_ИдКод` (номенклатура/склад/договор) и по UID документов через `РС.СоответствияОбъектовИнформационныхБаз` / прямой UUID 1:1 — НИКОГДА по ссылкам (ссылки в разных базах не совпадают). **Ключевой факт перечитки (граблина #3):** после `Записать(РежимЗаписиДокумента.ОтменаПроведения)` ОБЯЗАТЕЛЬНО `ДокОбъект = СсылкаДок.ПолучитьОбъект()` заново перед повторной записью — иначе падение на закрытом менеджере временных таблиц (memory `feedback_delete_doc_obmen_zagruzka`).

## TL;DR (самое важное за 30 секунд)

1. **3 фазы.** Фаза 1 — сверка остатков/оборотов (FULL OUTER по `А_ИдКод`, нетование сторон). Фаза 2 — анализ документов через `РС.СоответствияОбъектовИнформационныхБаз` (прямой + обратный). Фаза 3 — синхронизация (провести/распровести/перепровести в ЕРП либо поставить на обмен в BuhBud).
2. **Запись пакета — транзакционным оркестратором ЭТАЛОНА РМ.** Любое массовое изменение состояния документов оборачивается `НачатьТранзакцию`/`Попытка`/`ЗафиксироватьТранзакцию`, ветка `Исключение` → `ОтменитьТранзакцию` + `ЗаписьЖурналаРегистрации(ПодробноеПредставлениеОшибки(...))`, серверная функция возвращает СЧЁТЧИК обработанных → клиент строит НСтр-оповещение (вербатим из `ПомощникПродаж`, см. §6).
3. **Мост — по `А_ИдКод` + UID, НЕ по ссылкам.** Ссылки баз не совпадают; UUID правила обмена сохраняют 1:1.
4. **COM-сторона: сериализация `ЗначениеВСтрокуВнутр` НА УДАЛЁННОЙ базе** (`V83.ЗначениеВСтрокуВнутр(ТЗ)`) → локально `ЗначениеИзСтрокиВнутр`. Чужую ТЗ напрямую не итерировать. Параметры COM-запроса — объектами удалённой базы (`V83.NewObject("Массив")`).
5. **Нетование** считается так, что Δ=0 при совпадении: ЕРП `Приход−Расход` ↔ BuhBud `ОборотДт−ОборотКт` (или `КоличествоПриход−КоличествоРасход`); сравнение через `Окр(...,2)=0`.
6. **Перепровод — ТОЛЬКО из UI.** COM-перепровод ломает `РегистраторРасчётов`. После `ОтменаПроведения` — обязательный `ПолучитьОбъект()` заново.
7. **Цвета/оформление — КОДОМ** (`УсловноеОформление`, `ЦветаСтиля`/`WebЦвета`). `<TextColor>` в Form.xml внешней обработки валит `epf-build` (Исключение XDTO).
8. **Тяжёлая сверка (полная база, тысячи строк) — в ФОН по образцу `ОбеспечениеПотребностей`** (`ДлительныеОперации.ВыполнитьВФоне` ↔ `ДлительныеОперацииКлиент.ОжидатьЗавершение` ↔ `*Завершение`), результат — через временное хранилище. См. §9.

## 1. Архитектура: каркас сверочной обработки

Сверочная обработка — частный случай хаба `obr-obrabotka` и класса A ЭТАЛОНА РМ: **тонкая форма + движок `ObjectModule` + мост**. Особенность семейства — второй источник данных читается через COM, а результат двухуровневый (свод по складам/контрагентам сверху + детализация документов снизу), связанные master-detail.

| Слой | Где | Что держит | Эталон-планка |
|---|---|---|---|
| Форма (тонкая) | `Forms/Форма/Ext/Form/Module.bsl` | отборы периода, master-detail фильтр, итоги/резюме, массовые галки, открытие документа, условное оформление кодом | `ОбеспечениеПотребностей` (master-detail, фон, отборы СКД) |
| Движок | `Ext/ObjectModule.bsl` | 3 фазы, все запросы, COM-подключение, перепровод; делегаты `*Сервер` | `ПомощникПродаж` (транзакционный оркестратор записи) |
| Мост | `&НаСервере` процедуры формы | `РеквизитФормыВЗначение("Объект")` → метод движка → `ЗначениеВРеквизитФормы(мОбъект,"Объект")` | оба РМ + `Создания комплектаций` (тонкая форма) |

> ⚠️ Внутри `ObjectModule` всех сверочных обработок — `УстановитьПривилегированныйРежим(Истина)` (чтение/правка по двум базам без RLS-помех).

### Где живёт логика (урок ЭТАЛОНА РМ)

В ЭТАЛОНЕ РМ форма **тонкая**: вся тяжёлая логика (запрос, расчёт анализа, транзакционная запись) — в экспортных методах движка/общих модулей; форма лишь дёргает их через мост. Так же должна жить и сверочная обработка.

**ПРИМЕР-«до» (что поднять).** В `Создания комплектаций для бух учета` бизнес-логика (запросы к Хозрасчетный, расчёт норм, запись документов) живёт прямо в `ObjectModule.bsl` обработки, а форма на каждую команду гоняет ВЕСЬ объект через `РеквизитФормыВЗначение`/`ЗначениеВРеквизитФормы`:
```bsl
// ПРИМЕР-обработка (Создания комплектаций/Forms/Форма/Ext/Form/Module.bsl) — round-trip всего объекта на каждое действие:
ОбъектОбработки = РеквизитФормыВЗначение("Объект");
ОбъектОбработки.РассчитатьАнализ();
ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект");
Сообщить("Розраховано позицій: " + Объект.ТабличнаяЧастьОстатков.Количество());
```
> Роль: ПРИМЕР-«до». **Как поднять до ЭТАЛОНА РМ:** тяжёлую логику — в отдельный серверный общий модуль БСП-стиля (`А_<Объект>Сервер`, см. навык `bas-common-module`), а форма-обёртка вызывает его; round-trip всего объекта на каждую кнопку заменить на `&НаСервереБезКонтекста`-расчёт с передачей только нужных данных; результат/ошибки — структурой `{Оброблено, Помилки[]}` + `ОбщегоНазначения.СообщитьПользователю` (с привязкой к полю), а не голым `Сообщить`.

### Мост + сохранение галок при переформировании

`ЗначениеВРеквизитФормы` ПОЛНОСТЬЮ пересоздаёт ТЧ — пользовательские галки выбора надо снять в `Соответствие` по бизнес-ключу ДО и восстановить ПОСЛЕ:

```bsl
&НаСервере
Процедура СформироватьНаСервере()
	// Зберегти галки вибору складів — повторне формування не повинно скидати роботу
	КартаГалок = Новый Соответствие;
	Для Каждого Стр Из Объект.ТаблицаСкладов Цикл
		КартаГалок.Вставить(СокрЛП(Стр.СкладКлюч), Стр.Синхронизировать);
	КонецЦикла;
	мОбъект = РеквизитФормыВЗначение("Объект");
	мОбъект.СравнитьОстатки();
	ЗначениеВРеквизитФормы(мОбъект, "Объект");
	Если КартаГалок.Количество() > 0 Тогда
		Для Каждого Стр Из Объект.ТаблицаСкладов Цикл
			БылоЗначение = КартаГалок.Получить(СокрЛП(Стр.СкладКлюч));
			Если БылоЗначение <> Неопределено Тогда Стр.Синхронизировать = БылоЗначение; КонецЕсли;
		КонецЦикла;
	КонецЕсли;
	ОбновитьРезюмеИЗаголовки();
КонецПроцедуры
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`). **Почему:** повторная сверка не сбрасывает работу бухгалтера. Перетаскивается на любую сверочную обработку с галками выбора.

## 2. COM-канал к второй базе

### Точка входа

```bsl
Функция ПодключитьсяКBuhBud() Экспорт
	СтрокаПодключенияBuhBud = "Srvr=""SQLSERVER"";Ref=""BuhBud"";Usr=""cfo"";Pwd=""2442""";
	V8 = Новый COMОбъект("V83.COMConnector");
	Попытка
		V83 = V8.Connect(СокрЛП(СтрокаПодключенияBuhBud));
	Исключение
		Сообщить("Помилка підключення до BuhBud: " + ОписаниеОшибки());
		Возврат Неопределено;
	КонецПопытки;
	Возврат V83;
КонецФункции
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Ext/ObjectModule.bsl`). **Грабли:** `COMConnector` требует сервера 1С с COM; при ошибке возвращает `Неопределено` — вызывающий ОБЯЗАН проверить. Все фазы лениво создают/освобождают `V83 = Неопределено`. **Как поднять:** строку подключения (особенно `Pwd`) НЕ хардкодить в `.bsl` (она уходит в git-выгрузку) — выносить в реквизит обработки / константу / БСП `БезопасноеХранилищеДанных`; поиск узла обмена — одним приватным методом `ПолучитьУзелОбмена(V83)`, а не дублировать текст запроса в каждой фазе (DRY).

| База | Строка подключения (в коде, кавычки удвоены) |
|---|---|
| ЕРП `BaseERP` | `Srvr="SQLSERVER";Ref="BaseERP";Usr="Администратор";Pwd="24043"` |
| BuhBud (товары/взаиморасчёты) | `Srvr="SQLSERVER";Ref="BuhBud";Usr="cfo";Pwd="2442"` |
| BuhBud (`ЗаполнитьСчетУчетаВДоговоре`) | ⚠️ `Usr="1cAdmin";Pwd=""` — пустой пароль, отличается; зависит от COM-доступа конкретной BuhBud |

### Передача `ТаблицаЗначений` между базами — сериализация Внутр

Чужой COM-объект `ТаблицаЗначений` нельзя итерировать в локальном контексте — сериализуем НА СТОРОНЕ V83, десериализуем локально:

```bsl
стр_ТЗ = V83.ЗначениеВСтрокуВнутр(ТЗ);          // вызывается на V83 (удалённая база), строки 323-324
ТаблицаBuhBud = ЗначениеИзСтрокиВнутр(стр_ТЗ);  // локальная десериализация → родная локальная ТЗ
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Ext/ObjectModule.bsl:323-324`). Колонки заранее описаны через `ОбщегоНазначения.ОписаниеТипаЧисло` / `ОписаниеТипов`. **Грабли:** для параметра-массива в запрос BuhBud нужен `V83.NewObject("Массив")` — питоновский/локальный массив не подойдёт.

```bsl
МассивСчетов = V83.NewObject("Массив");
Для Каждого КодСчета Из СтрРазделить(СчетаВзаиморасчетов, ",", Ложь) Цикл
	МассивСчетов.Добавить(СокрЛП(КодСчета));
КонецЦикла;
Запрос.УстановитьПараметр("СписокСчетов", МассивСчетов);
ТЗОбороты = Запрос.Выполнить().Выгрузить();
стр_ТЗ = V83.ЗначениеВСтрокуВнутр(ТЗОбороты);
V83 = Неопределено; V8 = Неопределено;        // освободить ДО десериализации
ТаблицаОборотов = ЗначениеИзСтрокиВнутр(стр_ТЗ);
```
> Роль: ПРИМЕР-обработка (`ЗаполнитьСчетУчетаВДоговоре/Ext/ObjectModule.bsl`). **Грабли:** при исключении обязательно обнулять `V83`/`V8` перед `ВызватьИсключение`, иначе висит коннект.

## 3. Мост сущностей между базами

### 3.1. Справочники/измерения — по `А_ИдКод`

Ссылки баз не совпадают. Бизнес-ключ обмена — реквизит `А_ИдКод` (есть у Номенклатуры, Складов, Договоров, Контрагентов). На бухучётной стороне субконто (Номенклатура/Склад/Договор) стоят на РАЗНЫХ позициях у разных счетов → позиция определяется динамически соединением с `ПланСчетов.Хозрасчетный.ВидыСубконто`:

```bsl
ВЫБОР
	КОГДА ПозицияНоменклатуры.НомерСтроки = 1
		ТОГДА ВЫРАЗИТЬ(Остатки.Субконто1 КАК Справочник.Номенклатура).А_ИдКод
	КОГДА ПозицияНоменклатуры.НомерСтроки = 2
		ТОГДА ВЫРАЗИТЬ(Остатки.Субконто2 КАК Справочник.Номенклатура).А_ИдКод
	КОГДА ПозицияНоменклатуры.НомерСтроки = 3
		ТОГДА ВЫРАЗИТЬ(Остатки.Субконто3 КАК Справочник.Номенклатура).А_ИдКод
	ИНАЧЕ ""
КОНЕЦ КАК НоменклатураИдКод,
...
```

### 3.3. Прямой UUID 1:1 (Казна ↔ ЕРП, COM)

Когда документ читается из другой базы COM-объектом, UUID извлекается через английский lowercase `V83.string(...)` (см. CLAUDE.md «Cross-base UUID lookup»):

НЕ объявлять локальную переменную `Ссылка` (конфликт с системным `.Ссылка`). Узел Казны — `ПланОбмена.КазначействоBASERP` (с буквой **Й**). ## 4. Нетование сторон (Δ=0 при совпадении)

Цель сверки — посчитать разницу так, чтобы при идентичных данных она была ровно 0. Стороны приводятся к одной знаковой модели «Приход − Расход»:

| Сущность сверки | ЕРП-сторона | BuhBud-сторона | Нетование |
|---|---|---|---|
| Товары | `РН.ТоварыНаСкладах`: `ВНаличииПриход − ВНаличииРасход` | `Хозрасчетный`: `КоличествоПриход` (Дт) − `КоличествоРасход` (Кт) | Δ = (Приход−Расход)ЕРП − (Приход−Расход)Бух |
| Взаиморасчёты | Контрагент×Договор×Валюта: `Приход − Расход` | `СуммаОборотДт − СуммаОборотКт` | Δ = 0 для обеих сторон (1249+169 пар проверено) |
| Касса | `РН.ДенежныеСредстваНаличные` (Касса) | Казна `РН.ДенежныеСредства` (Наличные) | по UID 1:1 |

> ⚠️ В виртуальной таблице `.Обороты()`/`.ОстаткиИОбороты()` поля имеют префиксы `Приход/Расход/Оборот` — НЕ `Дебет/Кредит` буквально. Для бухучёта: `СуммаОборотДт`/`СуммаОборотКт`, `КоличествоПриход`/`КоличествоРасход`. Проверять реальные имена через Python COM (Rule #-1) ПЕРЕД BSL.

### Обратный анализ BuhBud (документы без пары в ЕРП)

```bsl
// вложенный Хозрасчетный.ОстаткиИОбороты с периодичностью Регистратор,
// ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВидыСубконто по Номенклатуре + ЛЕВОЕ по Складу,
// внешний СГРУППИРОВАТЬ ПО Регистратор, ИМЕЮЩИЕ СУММА(СуммаНетто)<>0,
// ресурс СУММА(КоличествоПриход)-СУММА(КоличествоРасход) КАК КоличествоИтого
УИДБух = V83.string(V83_Рез.Регистратор.УникальныйИдентификатор()); // внутри Попытка (см. грабли ниже)
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Ext/ObjectModule.bsl`). **Грабли:** UID берётся внутри `Попытка`; сравнение UID везде через `ВРег(СокрЛП(...))` для регистронезависимого матчинга. ⚠️ **Как поднять (грабли #5 из feedback-журнала):** пустой блок `Исключение` (тихое глотание ошибки COM/типизации) — антипаттерн `/1c-bsl-review`. Минимум — `ЗаписьЖурналаРегистрации(...,УровеньЖурналаРегистрации.Ошибка, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()))` + заполнять `Статус`/`КодСтану` строки диагностикой, а не оставлять поле пустым без следа.

## 6. Фаза 3 — синхронизация: транзакционный оркестратор (ЭТАЛОН РМ)

> Сверочные обработки НЕ создают расчётные документы и НЕ заполняют товары — только меняют состояние существующих (провести/распровести/перепровести) и регистрируют на обмен. Поэтому `Курс=1`/`Кратность=1`/`СуммаВзаиморасчетов` здесь НЕ нужны (это не создание расчётного документа; для создания — навык `bas-doc-fill` + [obr_zaprosy_zapolnenie.md](obr_zaprosy_zapolnenie.md)).

### 6.1. Каркас записи пакета — дословно из ЭТАЛОНА РМ

Любое массовое изменение состояния (пометить/провести/перепровести группу) оборачивается транзакцией; ветка `Исключение` ВСЕГДА откатывает и пишет в журнал; серверная функция возвращает **счётчик** обработанных, по которому клиент строит оповещение.

```bsl
&НаСервере
Функция УстановитьПометкуУдаленияСервер(ВыделенныеДокументы)
	Сч = ВыделенныеДокументы.Количество();
	КоличествоИзмененныхДокументов = 0;
	Отказ = Ложь;
	НачатьТранзакцию();
	Попытка
		Пока Сч > 0 Цикл
			Сч = Сч - 1;
			ДокументНеПомеченНаУдаление = Ложь;
			СтрокаТаблицы = Объект.Документы.НайтиПоИдентификатору(ВыделенныеДокументы[Сч]);
			Если СтрокаТаблицы = Неопределено Тогда Продолжить; КонецЕсли;
			ПометитьНаУдалениеДокумент(СтрокаТаблицы, ДокументНеПомеченНаУдаление);
			Если ДокументНеПомеченНаУдаление Тогда
				Отказ = Истина;
			Иначе
				КоличествоИзмененныхДокументов = КоличествоИзмененныхДокументов + 1;
			КонецЕсли;
		КонецЦикла;
		Если Отказ Тогда
			ОтменитьТранзакцию();
			ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление';uk='Позначка документів на видалення'"),
				УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
			Возврат 0;
		КонецЕсли;
		ЗафиксироватьТранзакцию();
	Исключение
		ОтменитьТранзакцию();
		ЗаписьЖурналаРегистрации(НСтр("ru='Пометка документов на удаление';uk='Позначка документів на видалення'"),
			УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
		Возврат 0;
	КонецПопытки;
	Возврат КоличествоИзмененныхДокументов;
КонецФункции
```
> Роль: **ЭТАЛОН РМ** (`Рабочие места/ПомощникПродаж/Forms/Форма/Ext/Form/Module.bsl:6544-6600`, аналог `СоздатьДокументыСервер` 5863-6344). Это образец для серверной функции синхронизации сверочной обработки: вся пачка — в одной транзакции (любой сбой → откат всех + 0 изменённых), per-row `НайтиПоИдентификатору`+`Продолжить`, `ВыделенныеСтроки` собираются на клиенте. **Клиентская обёртка (ЭТАЛОН РМ):** `ОчиститьСообщения()` → `ПроверитьЗаполнение()` (гейт ПЕРЕД серверным вызовом, чтобы транзакция не стартовала на негодных данных) → серверная функция → `ПоказатьОповещениеПользователя` со счётчиком через НСтр-шаблон (`ПомощникПродаж` строки 6441-6477).

### 6.2. Распровести / провести в ЕРП

```bsl

СсылкаДок   = МенеджерДок.ПолучитьСсылку(Новый УникальныйИдентификатор(UID));

```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Ext/ObjectModule.bsl`).

### 6.3. Перепровести (КЛЮЧЕВОЙ паттерн — обязательный перечит)

```bsl
Если ДокОбъект.Проведен Тогда
	ДокОбъект.Записать(РежимЗаписиДокумента.ОтменаПроведения);
	ДокОбъект = СсылкаДок.ПолучитьОбъект();   // ОБЯЗАТЕЛЬНЫЙ перечит!
```

> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Ext/ObjectModule.bsl`). **Грабли:** без перечитки `ПолучитьОбъект()` после `ОтменаПроведения` повторная запись падает на закрытом менеджере временных таблиц (memory `feedback_delete_doc_obmen_zagruzka`). 🚫 Вызывать ТОЛЬКО из UI-сессии — COM-перепровод в новой архитектуре теряет `РегистраторРасчётов`.

Когда сверка чинит обратные ссылки (а не движения) — пишут через `ОбменДанными.Загрузка`:

```bsl
ДокПВОбъект = ДокПВ.ПолучитьОбъект();
ДокПВОбъект.ОбменДанными.Загрузка = Истина;   // без ПередЗаписью/проведения
// ... заполнение А_Платежка*
Если ТребуетсяЗапись Тогда ДокПВОбъект.Записать(); КонецЕсли;
```

> Роль: ПРИМЕР-обработка (`Заполнить документы ПокупкаПродажаВалюты/Forms/Форма/Ext/Form/Module.bsl`). **Грабли:** не добавлять сюда заполнение учётных полей, рассчитываемых проведением. Каждый документ — в собственной транзакции с исключительной `БлокировкаДанных` по `Ссылка`; ошибка одного дока не валит цикл.

### 6.7. Идемпотентность сверки

Совпадение `К-ть ЕРП = К-ть Бух` (`Окр(...,2)=0`) → строка помечается `Дія=''`, `Статус='ОК'/'Збігається'`, `Синхронизировать=Ложь`. Повторный прогон не предлагает действий по уже синхронным документам. То же делает ЭТАЛОН РМ перед записью: `ОтменаПроведенияРанееСозданных` + `НайтиСоздатьДокумент` (get-or-create) — повторный запуск не плодит дубли (`ПомощникПродаж`).

### 6.8. ПРИМЕР-«до»: магические строки состояния → поднять до перечисления

В `СинхронизироватьТоварыТолькоТовары` статус/действие смоделированы вольными украинскими строками, диспетчер ветвится цепочкой их сравнений, признак ошибки ловится по префиксу:
```bsl
// ПРИМЕР-обработка (Ext/ObjectModule.bsl:1052+) — диспетчер по «магическим» строкам:
Если СтрДок.Действие = "Розпровести в ЕРП" Тогда
	...
ИначеЕсли СтрДок.Действие = "Провести в ЕРП" Тогда
	...
ИначеЕсли СтрДок.Действие = "На обмін в BuhBud" ИЛИ СтрДок.Действие = "Переобмін" Тогда
	...
// а признак ошибки: Если СтрНачинаетсяС(СтрДок.Статус, "ПОМИЛКА") Тогда
```
> Роль: ПРИМЕР-«до». **Как поднять:** заменить строки-состояния на перечисление (`Перечисление.А_ВидДействияСинхронизации` / `А_СтатусСинхронизации`) или именованные константы модуля; диспетчер — на `ВЫБОР`/структуру-карту `{ВидДії → Обработчик}`; результат действия возвращать структурой `{Успіх:Булево, Текст}`, а не парсить префикс `"ПОМИЛКА"`; условное оформление формы привязывать к числовому/булеву реквизиту `КодСтану`, а не к тексту `Статус` — тогда переформулировка/перевод сообщений не ломает подсветку (устраняет крихкість «одна правка текста → три рассинхрона»).

## 7. UX формы сверки (master-detail + оформление)

### Master-detail через `ОтборСтрок` (только равенство)

```bsl
СтруктураОтбора = Новый Структура;
Если ТекущиеДанные <> Неопределено Тогда СтруктураОтбора.Вставить("Склад", ТекущиеДанные.Склад); КонецЕсли;
Если Объект.ПоказыватьТолькоРасхождения Тогда СтруктураОтбора.Вставить("ЕстьРасхождение", Истина); КонецЕсли;
Элементы.ТаблицаДокументовФорма.ОтборСтрок = Новый ФиксированнаяСтруктура(СтруктураОтбора);
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`). **Почему:** связь верх↔низ реализована НЕ через связи формы, а через `ОтборСтрок=ФиксированнаяСтруктура`, пересобираемую при активизации строки и переключении флага «Тільки розбіжності». **Эталонная параллель (ЭТАЛОН РМ):** `ОбеспечениеПотребностей` строит тот же клиентский фильтр `ОтборСтрок=Новый ФиксированнаяСтруктура(СтруктураОтбора)` из заполненных полей-фильтров (через `ЗначениеЗаполнено`), а саму перерисовку детали по активной строке делает с **debounce** — `ПриАктивизацииСтроки` ставит только `ПодключитьОбработчикОжидания("...", 0.1, Истина)`, а заполняет деталь уже обработчик ожидания. Если сверка тормозит при быстром перемещении курсора — взять этот приём из РМ.

### Условное оформление КОДОМ (по префиксу статуса)

```bsl
// Помилки — червоним
Элемент = УсловноеОформление.Элементы.Добавить();
Поле = Элемент.Поля.Элементы.Добавить();
Поле.Поле = Новый ПолеКомпоновкиДанных("ТаблицаДокументовФорма");
Отбор = Элемент.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
Отбор.ЛевоеЗначение  = Новый ПолеКомпоновкиДанных("Объект.ТаблицаДокументов.Статус");
Отбор.ВидСравнения   = ВидСравненияКомпоновкиДанных.НачинаетсяС;
Отбор.ПравоеЗначение = "ПОМИЛКА";
Элемент.Оформление.УстановитьЗначениеПараметра("ЦветТекста", WebЦвета.Красный);
// успехи — ВСписке (Розпроведено/Проведено/Зареєстровано на обмін/Перепроведено) → ЗеленыйЛес
// «спокойные» (НачинаетсяС "ОК"/"Збігається") → Серый
Элементы.НадписьРезюме.ЦветТекста = ЦветаСтиля.ПоясняющийТекст;   // цвет резюме — кодом
```
> Роль: ПРИМЕР-обработка (`СинхронизироватьТоварыТолькоТовары/Forms/Форма/Ext/Form/Module.bsl`). 🚫 **Грабли:** `<TextColor>style:...</TextColor>` в Form.xml внешней обработки валит `epf-build` (Исключение XDTO, memory `epf_load_xdto_textcolor`). Только `УсловноеОформление` + `Элементы.X.ЦветТекста` кодом через `ЦветаСтиля`/`WebЦвета`. **Эталонная параллель (ЭТАЛОН РМ):** `ПомощникПродаж.УстановитьУсловноеОформление` так же программно добавляет элементы `УсловноеОформление.Элементы` (`Поля`+`Отбор`+`Оформление`), а простую подсветку незаполненного делегирует типовому хелперу `ОбщегоНазначенияУТ.УстановитьСнятьОтметкуНезаполненного(...)` — для сверки тоже лучше делегировать типовое, своё писать кодом. ⚠️ **ПРИМЕР-«до»** `Создания комплектаций` задаёт цвет метрик `Новый Цвет(214,240,214)` хардкодом RGB — поднять до `ЦветаСтиля.*`/`УсловноеОформление` (как уже сделано в сверочной).

### Массовые галки и резюме

| Уровень | Кнопки | Реализация |
|---|---|---|
| Верхняя таблица (склады) | Вибрати всі / Зняти / Інвертувати | цикл по всем строкам `Объект.ТаблицаСкладов` |
| Нижняя таблица (документы) | Відмітити / Зняти відмітки виділених | `Элементы.ТаблицаДокументовФорма.ВыделенныеСтроки` + `НайтиПоИдентификатору` |
| Подвал верхней | авто-`Total*` | `Footer=true` + `FooterDataPath` (платформа считает сама) |
| Резюме под шапкой | текст | `ОбновитьРезюмеИЗаголовки()`: «Складів з розбіжностями: N (позицій: M). Документів: K (з діями: D, рішення бухгалтера: Q)» |

> ⚠️ **ПРИМЕР-«до»** `Создания комплектаций`: три итога считаются ручным циклом в клиентской процедуре `ПрименитьОтборИИтоги`. **Как поднять:** итоги таблицы — штатно через подвал колонок (`Footer`/`FooterDataPath`/`ОтображатьИтоги`), а не ручным циклом (эталон UX-итогов — [obr_forma_otbory_itogi.md](obr_forma_otbory_itogi.md) + навык `bas-bsp-form`).
> Подтверждение перед массовой записью: «Синхронізувати» → `ПоказатьВопрос` (Да/Нет, дефолт Нет) с числом выбранных. Старая кнопка «Дія по рядку» убрана; `ВыполнитьСинхронизациюСтроки` оставлена в `ObjectModule` как застарелая (UI её не вызывает).

## 8. Anti-patterns (журнал реального опыта)

| 🚫 Антипаттерн | Последствие | Решение |
|---|---|---|
| Мост по ссылкам между базами | ссылки баз не совпадают → пусто | мост по `А_ИдКод` + UID через `РС.СоответствияОбъектовИнформационныхБаз` / прямой UUID 1:1 |
| COM-перепровод документов | теряется `РегистраторРасчётов` → РСППС=0, нет парной проводки ПАП | перепроводить ТОЛЬКО из UI 1С Enterprise |
| Повторная запись без перечитки после `ОтменаПроведения` | падение на закрытом менеджере ВТ | `ДокОбъект = СсылкаДок.ПолучитьОбъект()` заново |
| Итерация чужой COM-`ТаблицаЗначений` напрямую | ошибка контекста | `V83.ЗначениеВСтрокуВнутр` на V83 → локально `ЗначениеИзСтрокиВнутр` |
| Локальный массив в параметр COM-запроса | тип не принимается удалённой базой | `V83.NewObject("Массив")` |
| `<TextColor>` в Form.xml внешней обработки | `epf-build` Исключение XDTO | цвет/оформление КОДОМ (`ЦветаСтиля`/`WebЦвета`) |
| `XMLСтрока(V83_UUID)` / `Строка(V83_UUID)` для UID | Исключение XML / пусто | `V83.string(...)` (англ. lowercase) |
| Жёсткая привязка к `СубконтоN` в Хозрасчетном | ломается на части счетов | соединение с `ПланСчетов.Хозрасчетный.ВидыСубконто` + `ВЫБОР ПО НомерСтроки` |
| Анализ обменных складов / чужих орг | ложные расхождения | гарды `А_ЭтоОбмен=Истина` (исключить), `А_ВБалансе=Истина` (только свои) |
| Сравнение сумм без `Окр(...,2)` | копеечный дрейф ломает Δ=0 | `Окр(Разница, 2) = 0` |
| Массовая запись без транзакции (документ за документом) | half-applied при сбое в середине | транзакционный оркестратор ЭТАЛОНА РМ (§6.1): `НачатьТранзакцию`/`Исключение`→`ОтменитьТранзакцию`+журнал, возврат-счётчик |
| Пустой блок `Исключение` (тихое глотание COM/типизации) | поля молча не заполнены, диагноза нет | `ЗаписьЖурналаРегистрации(...,Ошибка, ПодробноеПредставлениеОшибки(...))` + статус-диагностика в строку |
| Магические строки состояния («Розпровести в ЕРП», префикс «ПОМИЛКА») | правка текста в одном месте ломает диспетчер/оформление | перечисление `А_ВидДействия*`/`КодСтану` + структура результата `{Успіх, Текст}` |
| `Pwd=...` хардкодом в `.bsl` | пароль уходит в git-выгрузку | реквизит обработки / БСП `БезопасноеХранилищеДанных` |
| Round-trip всего объекта на каждую кнопку | лишняя сериализация ТЧ | логика в `А_<Объект>Сервер` (`bas-common-module`), форма передаёт только данные |

## 9. Тяжёлая сверка в фоне (когда поднимать до ЭТАЛОНА РМ)

Если сверка — по полной базе (тысячи строк, два COM-запроса, минуты расчёта), синхронный прогон блокирует сеанс. ЭТАЛОН РМ `ОбеспечениеПотребностей` показывает штатную БСП-триаду — её надо взять для тяжёлой фазы 1/2:

```bsl
&НаСервере
Функция ПолучениеТаблицыСпособовОбеспеченияВФоне()
	ПараметрыПроцедуры = Новый Структура;
	ПараметрыПроцедуры.Вставить("Настройки", КомпоновщикНастроекДляОтборов.ПолучитьНастройки());
	ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор);
	ПараметрыВыполнения.НаименованиеФоновогоЗадания = НСтр("ru='Сверка: расчёт';uk='Звірка: розрахунок'");
	Возврат ДлительныеОперации.ВыполнитьВФоне("Обработки.<Имя>.<Метод>",
		ПараметрыПроцедуры, ПараметрыВыполнения);
КонецФункции

&НаКлиенте
Процедура Далее(Команда)
	ДлительнаяОперация = ПолучениеТаблицыСпособовОбеспеченияВФоне();
	ПараметрыОжидания = ДлительныеОперацииКлиент.ПараметрыОжидания(ЭтаФорма);
	ДлительныеОперацииКлиент.ОжидатьЗавершение(ДлительнаяОперация,
		Новый ОписаниеОповещения("РасчётВФонеЗавершение", ЭтаФорма), ПараметрыОжидания);
КонецПроцедуры

&НаКлиенте
Процедура РасчётВФонеЗавершение(Результат, ДополнительныеПараметры) Экспорт
	Если Результат = Неопределено Тогда Возврат;                       // отменено
	ИначеЕсли Результат.Статус = "Ошибка" Тогда ПоказатьПредупреждение(, Результат.КраткоеПредставлениеОшибки);
	Иначе ЗагрузитьРезультатНаСервере(Результат.АдресРезультата);     // из временного хранилища
	КонецЕсли;
КонецПроцедуры
```
> Роль: **ЭТАЛОН РМ** (`Рабочие места/ОбеспечениеПотребностей/Forms/Форма/Ext/Form/Module.bsl:1469-1506, 1813-1843`). **Грабли:** метод фона кладёт результат ТОЛЬКО через `ПоместитьВоВременноеХранилище(Результат, ПараметрыПроцедуры.АдресРезультата)` — нельзя возвращать большую ТЗ напрямую. Если фоновых операций несколько (фаза 1 / фаза 2 / запись), ветвить один обработчик `*Завершение` по реквизиту `ТекущаяФоноваяОперация` (диспетчер из `ПооперационноеПланирование2_2`). ⚠️ Внутри метода фона COM-подключение к BuhBud открывается заново (фоновое задание — отдельный сеанс).

## 10. Проверка (гейт)

→ `bas-verify`: тест ВСЕХ запросов через Python COM на реальной базе ПЕРЕД BSL (Rule #-1; для COM-запросов BuhBud — против `BuhBud`); `epf-build` + COM smoke (нетование Δ=0 на парах); `form-validate`/`1c-bsl-review` (ловит пустой `Исключение`, хардкод пароля, магические строки); копирование в основную конфигурацию (Rule #4). Финал — пользователь открывает обработку в UI 1С Enterprise и перепроводит помеченные (перепровод только из UI).

> **Как ИИ должен развивать этот файл:** при новой сверочной обработке или новой граблине — дописать строку в Anti-patterns (§8) с решением, вербатим-сниппет со ЯВНОЙ пометкой роли (ЭТАЛОН РМ / ПРИМЕР-обработка) и ссылкой на путь, и обновить «Текущее состояние» с коммитом. Грунт — только из живого кода (Rule #-1), не из памяти. Планка «как профессионально» — класс A ЭТАЛОНА РМ (`ПомощникПродаж`/`ОбеспечениеПотребностей`); ПРИМЕРЫ-обработки — материал для подъёма, НЕ эталон.
