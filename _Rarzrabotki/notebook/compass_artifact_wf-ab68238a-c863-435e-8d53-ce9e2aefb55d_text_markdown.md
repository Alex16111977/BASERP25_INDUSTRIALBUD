## 1. ТОП-20 ПРАВИЛ ХОРОШЕГО КОДА 1С

### Правило 1 — Код пишется на русском языке

Весь код BSL — на русском. Английский допустим только для имён веб-сервисов, их методов и параметров, а также ключей внешних JSON-структур. Буква **ё** не используется — всегда **е** (для единообразия поиска).

### Правило 2 — PascalCase для всех идентификаторов

Имена переменных, процедур, функций, реквизитов формируются удалением пробелов между словами, каждое слово начинается с заглавной буквы. Предлоги и однобуквенные местоимения тоже с заглавной.

```bsl
// ✅ ПРАВИЛЬНО
Перем КоличествоПачекВКоробке;
Перем ЕстьОшибки;

// ❌ НЕПРАВИЛЬНО
Перем _с;
Перем количество_пачек;
```

### Правило 3 — Процедуры именуются глаголами, функции — описанием результата

Процедуры называют инфинитивом глагола: `ЗагрузитьКонтрагента()`. Функции описывают возвращаемое значение, **без** префикса «Получить»: `ПолноеИмя()`, а не `ПолучитьПолноеИмя()`. Конструирующие функции начинаются с «Новый/Новая/Новое»: `НовыеПараметрыЗаполнения()`. Булевы проверки — с «Это» или причастием: `ЭтоВнешняяЗадача()`, `ДокументПроведен()`.

```bsl
// ✅ ПРАВИЛЬНО
Процедура ЗагрузитьКонтрагента()
Функция ДатаНачалаСеанса()
Функция НовоеПолеФормы()

// ❌ НЕПРАВИЛЬНО
Процедура ЗагрузкаКонтрагента()       // существительное вместо глагола
Функция ПолучитьПолноеИмя()           // префикс «Получить»
Функция ПолучитьМассивРолей()         // тип в имени
```

### Правило 4 — Структура модулей по стандартным областям (#std455)

Каждый модуль использует фиксированный набор областей. Пустые области не создаются.

**Модуль формы:**
```bsl
#Область ОписаниеПеременных
#КонецОбласти
#Область ОбработчикиСобытийФормы
#КонецОбласти
#Область ОбработчикиСобытийЭлементовШапкиФормы
#КонецОбласти
#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>
#КонецОбласти
#Область ОбработчикиКомандФормы
#КонецОбласти
#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

**Общий модуль:**
```bsl
#Область ПрограммныйИнтерфейс       // Экспортные процедуры для внешних вызовов
#КонецОбласти
#Область СлужебныйПрограммныйИнтерфейс  // Экспортные только для своей библиотеки
#КонецОбласти
#Область СлужебныеПроцедурыИФункции  // Внутренняя реализация
#КонецОбласти
```

### Правило 5 — Именование общих модулей по контексту (#std469)

| Тип модуля | Суффикс | Пример |
|---|---|---|
| Серверный (внутренний) | без суффикса или `Сервер` | `ОбщегоНазначения` |
| Серверный (вызов с клиента) | `ВызовСервера` | `РаботаСФайламиВызовСервера` |
| Клиентский | `Клиент` | `ОбщегоНазначенияКлиент` |
| Клиент-Серверный | `КлиентСервер` | `СтроковыеФункцииКлиентСервер` |
| Переопределяемый | `Переопределяемый` | `РаботаСФайламиПереопределяемый` |
| Повторное использование | `ПовтИсп` | `ОбщегоНазначенияПовтИсп` |

### Правило 6 — Предпочитать &НаСервереБезКонтекста вместо &НаСервере

`&НаСервере` сериализует **все** данные формы (включая табличные части) на сервер и обратно. Форма с 100 000 строк — каждый вызов гоняет мегабайты. `&НаСервереБезКонтекста` передаёт только явные параметры.

```bsl
// ❌ НЕПРАВИЛЬНО — передаёт ВСЮ форму на сервер и обратно
&НаСервере
Процедура УстановитьСклад()
    СкладПоУмолчанию = Справочники.Склады.НайтиПоНаименованию("Основной");
КонецПроцедуры

// ✅ ПРАВИЛЬНО — передаёт только результат
&НаСервереБезКонтекста
Функция ПолучитьСкладПоУмолчанию()
    Возврат Справочники.Склады.НайтиПоНаименованию("Основной");
КонецФункции
```

### Правило 7 — Директивы компиляции указываются явно

Для каждой процедуры/функции в модуле формы — обязательная директива. В общих модулях директивы **не используются** — контекст определяется свойствами модуля.

| Директива | Где выполняется | Контекст формы | Когда использовать |
|---|---|---|---|
| `&НаКлиенте` | Клиент | Доступен | Взаимодействие с UI |
| `&НаСервере` | Сервер | Доступен (передаётся!) | Нужна БД + данные формы |
| `&НаСервереБезКонтекста` | Сервер | НЕ доступен | Нужна БД, не нужна форма — **предпочтительно** |
| `&НаКлиентеНаСервереБезКонтекста` | Оба | НЕ доступен | Чистые вычисления |

### Правило 8 — НачатьТранзакцию() ПЕРЕД Попытка, ЗафиксироватьТранзакцию() — последняя строка в Попытка

Это **самый критичный паттерн** в 1С. Неправильная работа с транзакциями — причина №1 «невоспроизводимых» ошибок.

```bsl
// ✅ ПРАВИЛЬНО — эталонный паттерн
НачатьТранзакцию();
Попытка
    ДокументОбъект = Документы.ПриходнаяНакладная.СоздатьДокумент();
    // ... заполнение ...
    ДокументОбъект.Записать();
    ЗафиксироватьТранзакцию();  // ПОСЛЕДНЯЯ строка в Попытка
Исключение
    ОтменитьТранзакцию();  // ПЕРВАЯ строка в Исключение
    ЗаписьЖурналаРегистрации("МойМодуль.Ошибка",
        УровеньЖурналаРегистрации.Ошибка,,,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение;  // ВСЕГДА пробрасываем дальше!
КонецПопытки;

// ❌ НЕПРАВИЛЬНО — НачатьТранзакцию внутри Попытка
Попытка
    НачатьТранзакцию();  // ОШИБКА: если упадёт сама НачатьТранзакцию
    ДокументОбъект.Записать();
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();  // вызов на несуществующей транзакции!
КонецПопытки;
```

### Правило 9 — Никогда не глотать исключения

Каждый блок `Исключение` **обязан**: (1) записать в журнал регистрации через `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, (2) либо `ВызватьИсключение`, либо осмысленно обработать ошибку. Пустой блок `Исключение` — грубейшее нарушение.

```bsl
// ❌ НЕПРАВИЛЬНО — ошибка полностью скрыта
Попытка
    Объект.Записать();
Исключение
КонецПопытки;

// ✅ ПРАВИЛЬНО
Попытка
    Объект.Записать();
Исключение
    ЗаписьЖурналаРегистрации("МойМодуль",
        УровеньЖурналаРегистрации.Ошибка,,,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение;
КонецПопытки;
```

### Правило 10 — Запросы НИКОГДА не выполняются в циклах

Каждый запрос = обращение к СУБД (разбор → план → выполнение → возврат). Документ с 1000 строк генерирует 1000 SQL-запросов. Вместо этого — **один** пакетный запрос с временной таблицей.

### Правило 11 — Максимальная длина строки кода: 120 символов

Отступы — табуляция (4 символа). Один оператор на строке. `Процедура`/`КонецПроцедуры` — в нулевой колонке. Директивы компиляции и препроцессора — в нулевой колонке.

### Правило 12 — Удалять мёртвый код

Закомментированный код, неиспользуемые процедуры, маркеры `// TODO`, `// debug` — всё удаляется. Комментарий `//` всегда с пробелом после.

### Правило 13 — Экспортные процедуры обязательно документируются (#std453)

```bsl
// Возвращает полное имя объекта метаданных по переданной ссылке.
//
// Параметры:
//  Ссылка - ЛюбаяСсылка - ссылка на объект базы данных.
//
// Возвращаемое значение:
//  Строка - полное имя объекта метаданных.
//
Функция ИмяОбъектаМетаданных(Ссылка) Экспорт
```

### Правило 14 — Не вызывать обработчики событий напрямую из кода

Создайте отдельную процедуру и вызывайте её из обработчика. Прямой вызов одного обработчика из другого — нарушение.

```bsl
// ❌ НЕПРАВИЛЬНО
&НаКлиенте
Процедура ПоАвторуПриИзменении(Элемент)
    ПоИсполнителюПриИзменении(Неопределено);
КонецПроцедуры

// ✅ ПРАВИЛЬНО
&НаКлиенте
Процедура ПоАвторуПриИзменении(Элемент)
    УстановитьОтбор();
КонецПроцедуры

&НаКлиенте
Процедура ПоИсполнителюПриИзменении(Элемент)
    УстановитьОтбор();
КонецПроцедуры
```

### Правило 15 — COM-объекты освобождаются в обратном порядке создания

Присваивайте каждый промежуточный COM-объект переменной. Освобождайте через `= Неопределено` в обратном порядке. **Никогда** не используйте `Для Каждого` на COM-коллекциях — только `Для ... По ... Цикл` с `Получить(Индекс)`.

### Правило 16 — ВЫРАЗИТЬ() для составных типов в запросах

Обращение к реквизитам через составной тип (особенно `Регистратор`) без `ВЫРАЗИТЬ()` генерирует LEFT JOIN ко **всем** таблицам типа. Для регистра с 56 типами регистраторов — 56 JOIN'ов в SQL.

### Правило 17 — В 1С нет вложенных транзакций

Вызов `НачатьТранзакцию()` внутри уже открытой транзакции увеличивает счётчик, но не создаёт вложенную транзакцию. После первой ошибки внутри транзакции она «отравлена» — `ЗафиксироватьТранзакцию()` всегда упадёт. Не перехватывайте ошибки записи внутри цикла в рамках одной транзакции с продолжением.

### Правило 18 — Инициализировать переменные до условных ветвлений

1С не требует объявления переменных. Если переменная присваивается только внутри `Если/ИначеЕсли`, она может остаться `Неопределено` для непредвиденных значений.

```bsl
// ✅ ПРАВИЛЬНО
Коэффициент = 0;  // значение по умолчанию
Если Вариант = 0 Тогда
    Коэффициент = 1;
КонецЕсли;
```

### Правило 19 — Модуль объекта = бизнес-логика, модуль менеджера = операции с коллекцией

Модуль объекта: валидация, проведение, запись, бизнес-правила конкретного экземпляра. Модуль менеджера: поиск, создание, статические операции. Общий модуль: алгоритмы, разделяемые между несколькими объектами.

### Правило 20 — Минимизировать серверные вызовы

Объединяйте несколько серверных операций в один вызов. Каждый переход клиент→сервер — это сериализация, сетевой раунд-трип, десериализация. На веб-клиенте и мобильных устройствах это критично.

## 2. ПРАВИЛА ОПТИМАЛЬНЫХ ЗАПРОСОВ 1С

### 2.1 Параметры виртуальных таблиц — ВСЕГДА для измерений

Фильтрация измерений через `ГДЕ` (WHERE) после виртуальной таблицы означает, что платформа **сначала** построит таблицу для ВСЕХ измерений, а **потом** отфильтрует. Параметры виртуальной таблицы применяются **во время** построения — кратно быстрее.

```bsl
// ❌ НЕПРАВИЛЬНО — фильтр ПОСЛЕ построения всей виртуальной таблицы
ВЫБРАТЬ ТоварыОстатки.КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, ) КАК ТоварыОстатки
ГДЕ ТоварыОстатки.Склад = &Склад

// ✅ ПРАВИЛЬНО — условие применяется ПРИ построении
ВЫБРАТЬ ТоварыОстатки.КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК ТоварыОстатки
```

Ресурсы (не измерения) фильтровать **через ГДЕ** — в параметры ВТ они не принимаются:

```bsl
// Смешанный подход: измерения в параметрах ВТ, ресурсы в ГДЕ
ВЫБРАТЬ Остатки.Номенклатура, Остатки.КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
ГДЕ Остатки.КоличествоОстаток > 0  // ресурс — только в WHERE
```

### 2.2 Запросы в циклах — как исправить

```bsl
// ❌ КАТАСТРОФА — запрос на каждую строку документа
Для Каждого СтрокаТЧ Из Объект.Товары Цикл
    Запрос = Новый Запрос;
    Запрос.Текст = "ВЫБРАТЬ ТоварыОстатки.КоличествоОстаток
    |ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(,
    |   Номенклатура = &Номенклатура И Склад = &Склад) КАК ТоварыОстатки";
    Запрос.УстановитьПараметр("Номенклатура", СтрокаТЧ.Номенклатура);
    Запрос.УстановитьПараметр("Склад", СтрокаТЧ.Склад);
    Результат = Запрос.Выполнить();
КонецЦикла;

// ✅ ПРАВИЛЬНО — один пакетный запрос с временной таблицей
Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = Новый МенеджерВременныхТаблиц;
Запрос.Текст =
"ВЫБРАТЬ
|   Товары.Номенклатура КАК Номенклатура,
|   Товары.Склад КАК Склад,
|   Товары.Количество КАК Количество
|ПОМЕСТИТЬ ВТ_Товары
|ИЗ &Товары КАК Товары
|ИНДЕКСИРОВАТЬ ПО Номенклатура, Склад
|;
|ВЫБРАТЬ
|   ВТ.Номенклатура, ВТ.Склад, ВТ.Количество КАК Требуется,
|   ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ ВТ_Товары КАК ВТ
|   ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(,
|       Номенклатура В (ВЫБРАТЬ Т.Номенклатура ИЗ ВТ_Товары КАК Т)
|       И Склад В (ВЫБРАТЬ Т.Склад ИЗ ВТ_Товары КАК Т)
|   ) КАК Остатки
|   ПО ВТ.Номенклатура = Остатки.Номенклатура
|   И ВТ.Склад = Остатки.Склад";
Запрос.УстановитьПараметр("Товары", Объект.Товары.Выгрузить());
Результат = Запрос.Выполнить();
```

### 2.3 Никогда не JOIN'ить напрямую с виртуальными таблицами

Виртуальная таблица в SQL превращается в подзапрос. При JOIN с подзапросом СУБД не может оптимально использовать индексы. Решение — **материализация** во временную таблицу.

```bsl
// ❌ НЕПРАВИЛЬНО — прямой JOIN с виртуальной таблицей
ВЫБРАТЬ Спр.Ссылка, Остатки.КоличествоОстаток
ИЗ Справочник.Номенклатура КАК Спр
ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
ПО Спр.Ссылка = Остатки.Номенклатура

// ✅ ПРАВИЛЬНО — материализация во временную таблицу
ВЫБРАТЬ Остатки.Номенклатура, Остатки.КоличествоОстаток
ПОМЕСТИТЬ ВТ_Остатки
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
ИНДЕКСИРОВАТЬ ПО Номенклатура
;
ВЫБРАТЬ Спр.Ссылка, ВТ.КоличествоОстаток
ИЗ Справочник.Номенклатура КАК Спр
ЛЕВОЕ СОЕДИНЕНИЕ ВТ_Остатки КАК ВТ
ПО Спр.Ссылка = ВТ.Номенклатура
```

### 2.4 ВЫРАЗИТЬ() для составного типа Регистратор

```bsl
// ❌ КАТАСТРОФА — LEFT JOIN к КАЖДОЙ из 56+ таблиц документов
ВЫБРАТЬ Движения.Регистратор.Номер, Движения.Регистратор.Дата
ИЗ РегистрНакопления.Продажи КАК Движения

// ✅ ПРАВИЛЬНО — JOIN только к одной таблице
ВЫБРАТЬ
    ВЫРАЗИТЬ(Движения.Регистратор КАК Документ.РеализацияТоваровУслуг).Номер,
    ВЫРАЗИТЬ(Движения.Регистратор КАК Документ.РеализацияТоваровУслуг).Дата
ИЗ РегистрНакопления.Продажи КАК Движения
ГДЕ Движения.Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

Оператор `ССЫЛКА` фильтрует строки, но **не убирает** лишние JOIN'ы. Только `ВЫРАЗИТЬ()` явно указывает платформе, к какой единственной таблице делать JOIN.

### 2.5 Индексирование временных таблиц

Временные таблицы **обязательно** индексируются по полям, которые используются в последующих JOIN и WHERE. Для маленьких таблиц (< 100 строк) индекс может дать overhead.

```bsl
ВЫБРАТЬ Товары.Номенклатура, Товары.Склад
ПОМЕСТИТЬ ВТ_Товары
ИЗ &Товары КАК Товары
ИНДЕКСИРОВАТЬ ПО Номенклатура, Склад  // обязательно для JOIN!
```

### 2.6 OR в условиях заменять на ОБЪЕДИНИТЬ ВСЕ

`OR` в WHERE может заблокировать использование индексов СУБД, приводя к полному сканированию таблицы.

```bsl
// ❌ Может не использовать индексы
ГДЕ Регистр.Склад = &Склад1 ИЛИ Регистр.Склад = &Склад2

// ✅ Лучше: два запроса через ОБЪЕДИНИТЬ ВСЕ
// Или использовать оператор В():
ГДЕ Регистр.Склад В (&СписокСкладов)
```

### 2.7 ВидДвижения — системное перечисление, не пользовательское

```bsl
// ❌ ОШИБКА — нет такого перечисления
ГДЕ Регистр.ВидДвижения = ЗНАЧЕНИЕ(Перечисление.ВидыДвижений.Приход)

// ✅ ПРАВИЛЬНО — системное перечисление ВидДвиженияНакопления
ГДЕ Регистр.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
```

`ВидДвижения` существует **только** в регистрах типа «Остатки». В виртуальных таблицах (Остатки, Обороты) поле `ВидДвижения` недоступно — оно уже агрегировано.

### 2.8 СГРУППИРОВАТЬ ПО vs ИТОГИ

**СГРУППИРОВАТЬ ПО** — уменьшает количество строк, убирая детальные записи. Для обработки данных.
**ИТОГИ** — добавляет итоговые строки, сохраняя детальные. Для отчётов и сводных таблиц. Не использовать ИТОГИ без необходимости — увеличивает объём данных.

### 2.9 Не обращаться к реквизитам через точку в циклах

```bsl
// ❌ НЕПРАВИЛЬНО — каждое обращение через точку = запрос к БД
Для Каждого Строка Из ТаблицаЗначений Цикл
    Наименование = Строка.Номенклатура.Наименование;  // запрос к БД!
КонецЦикла;

// ✅ ПРАВИЛЬНО — получить все данные в запросе
Запрос.Текст = "ВЫБРАТЬ Т.Номенклатура,
    |ПРЕДСТАВЛЕНИЕ(Т.Номенклатура) КАК Представление,
    |Т.Номенклатура.ЕдиницаИзмерения КАК ЕдИзм
    |ИЗ ...";
```

### 2.10 Золотые правила (сводная таблица)

| Антипаттерн | Почему плохо | Решение |
|---|---|---|
| Запросы в циклах | N раунд-трипов к СУБД вместо 1 | Пакетный запрос + временные таблицы |
| JOIN с виртуальной таблицей | ВТ → подзапрос, нет индексов | Материализация ВТ в ПОМЕСТИТЬ |
| Фильтр ВТ через ГДЕ | Полное построение ВТ перед фильтрацией | Параметры виртуальной таблицы |
| Точка через составной тип | LEFT JOIN ко ВСЕМ таблицам типа | ВЫРАЗИТЬ() |
| OR в WHERE | Блокирует индексы | ОБЪЕДИНИТЬ ВСЕ или В() |
| Подзапросы в JOIN | СУБД не оптимизирует вложенные | Временные таблицы |
| SELECT * | Лишний I/O и память | Только нужные поля |

## 4. АНТИПАТТЕРНЫ — ЧЕКЛИСТ ДЛЯ CODE REVIEW

### Критический уровень (блокирует merge)

1. **Запросы внутри циклов** — `Запрос.Выполнить()` или `Запрос = Новый Запрос` внутри `Для`/`Для Каждого`/`Пока`. Решение: пакетный запрос с временной таблицей.

2. **Неправильная транзакция** — `НачатьТранзакцию()` внутри `Попытка`, или `ЗафиксироватьТранзакцию()` не последняя строка в `Попытка`, или `ОтменитьТранзакцию()` не первая строка в `Исключение`, или отсутствие `ВызватьИсключение`.

3. **Проглоченные исключения** — пустой блок `Исключение` или отсутствие `ЗаписьЖурналаРегистрации`.

4. **Перехват ошибок внутри транзакции с продолжением** — `Попытка/Исключение` с `Продолжить` внутри цикла в рамках открытой транзакции. После первой ошибки транзакция «отравлена» — все последующие итерации бессмысленны.

5. **Обращение к реквизитам составного типа без ВЫРАЗИТЬ()** — `Регистратор.Номер`, `Регистратор.Контрагент` без `ВЫРАЗИТЬ(Регистратор КАК Документ.ИмяДокумента)`.

### Высокий уровень (требует исправления)

6. **&НаСервере вместо &НаСервереБезКонтекста** — когда контекст формы не нужен, но используется контекстный вызов, передавая всю форму.

7. **Фильтрация виртуальных таблиц через ГДЕ вместо параметров ВТ** — приводит к полному построению виртуальной таблицы.

8. **JOIN с виртуальной таблицей напрямую** — виртуальная таблица в SQL превращается в подзапрос. Нужна материализация через ПОМЕСТИТЬ.

9. **Циклические ссылки в объектах** — `Данные.Вставить("Ключ", Данные)` или `Об = ЭтотОбъект` без последующего `Об = Неопределено`. Вызывает утечку памяти.

10. **COM-объекты не освобождаются** — нет присвоения `= Неопределено` в обратном порядке создания. Использование `Для Каждого` на COM-коллекциях (создаёт неосвобождаемый итератор).

### Средний уровень (рекомендовано исправить)

11. **Обращение к реквизитам через точку в циклах** — `Строка.Номенклатура.Наименование` — каждое обращение = запрос к БД. Получать в запросе через ПРЕДСТАВЛЕНИЕ() или через точку в SELECT.

12. **Неинициализированные переменные в условных ветвях** — переменная присваивается только внутри `Если`, может остаться `Неопределено`.

13. **Прямой вызов обработчиков событий** — один обработчик вызывает другой обработчик напрямую. Нужна отдельная процедура.

14. **Отсутствие документирования экспортных процедур** — нет комментария с описанием параметров и возвращаемого значения.

15. **Магические числа и даты** — константы в коде без пояснений. Выносить в параметры, перечисления или константы.

16. **Подзапросы в условиях JOIN** — СУБД не может оптимизировать. Заменять на временные таблицы.

17. **Отсутствие проверки ОбменДанными.Загрузка** — в обработчиках ПередЗаписью/ПриЗаписи документов и справочников обязательна проверка `Если ОбменДанными.Загрузка Тогда Возврат;`.

## 5. ПАТТЕРНЫ БСП (Библиотека Стандартных Подсистем)

### Три зоны видимости кода БСП — критически важно

**Только `ПрограммныйИнтерфейс`** — единственная зона кода БСП, безопасная для внешних вызовов. Код из `СлужебныйПрограммныйИнтерфейс` и `СлужебныеПроцедурыИФункции` сломается при обновлении версии БСП.

### Расширение типовых механизмов

БСП предоставляет три основных механизма расширения без изменения конфигурации:

**Переопределяемые модули** (`*Переопределяемый`) содержат процедуры-точки входа, куда разработчик вставляет свою логику. БСП вызывает эти процедуры в определённые моменты. Пример: `ОбщегоНазначенияПереопределяемый`, `РаботаСФайламиПереопределяемый`.

**Определяемые типы** позволяют расширять состав типов. Добавление своего документа в определяемый тип автоматически подключает его к механизмам БСП (управление доступом, версионирование и др.).

**Подключаемые команды** (`ПодключаемыеКоманды`, `ПодключаемыеКомандыПереопределяемый`) позволяют динамически добавлять кнопки/команды на управляемые формы без изменения конфигурации.

### Подписки на события — правила

Подписки определяются в `Общие → Подписки на события`. Одна подписка может обслуживать множество типов объектов. Порядок выполнения — **сверху вниз** по списку в конфигураторе. С платформы **8.3.17** подписки можно добавлять через расширения — предпочтительный способ, сохраняющий конфигурацию «на замке». Не создавайте зависимости между подписками по порядку выполнения — при обновлении конфигурации порядок может измениться.

### Регламентные задания — лучшие практики

- Обработчик — серверный общий модуль с экспортной процедурой
- Код обработчика **всегда** в `Попытка/Исключение` с записью в `ЖурналРегистрации`
- Использовать `КлючУникальности` для предотвращения дублирования экземпляров
- В файловом режиме: только один клиент вызывает `ВыполнитьОбработкуЗаданий()`
- Перед обновлением базы блокировать регламентные задания через консоль кластера
- Тестировать на копии базы, никогда на продакшене
- БСП предоставляет инфраструктуру управления через модуль `РегламентныеЗаданияСервер`

### Типичные API-вызовы БСП

```bsl
// Управление доступом
УправлениеДоступом.ПроверитьПраво("Чтение", СсылкаНаОбъект);

// Версионирование объектов
ВерсионированиеОбъектов.ЗаписатьВерсиюОбъекта(Объект);

// Присоединённые файлы
ПрисоединенныеФайлы.ДобавитьФайл(ВладелецФайла, ИмяФайла, ДанныеФайла);

// Дополнительные реквизиты и сведения
ДополнительныеРеквизитыИСведения.ПолучитьЗначениеСвойства(Объект, Свойство);

// Управление печатью
УправлениеПечатью.ВывестиТабличныйДокументВФормуВыбора(ТабДок, ...);
```

## 6. СПЕЦИФИКА ДЛЯ BAS ERP 2.5

### Что такое BAS ERP

**BAS (Business Automation Software)** — украинский бренд продуктов на платформе 1С, запущен в декабре 2017. BAS ERP — украинский аналог 1С:ERP Управление предприятием 2, локализованный под украинское законодательство, стандарты бухгалтерского учёта и отчётности.

Архитектурно BAS ERP **идентичен** 1С:ERP: та же платформа 8.3.x, та же БСП, те же паттерны разработки. Отличия — в локализации: украинский налоговый кодекс (ПДВ, ЄСВ), курсы НБУ, украинская отчётность, стандарты НСБУ.

### Масштаб конфигурации и подходы

При **400+ документах** и **185+ регистрах накопления** ключевые правила:

**Движения документов** генерируются в отдельных процедурах, сгруппированных по блокам регистров. Для каждой группы регистров — своя процедура формирования движений, вызываемая из общего обработчика проведения.

**Функциональные опции** интенсивно используются для включения/отключения блоков функциональности без изменения кода. При разработке проверяйте, включена ли нужная функциональная опция.

**Отложенное проведение** (ОтложенноеПроведение) — механизм ERP для оптимизации производительности: часть расчётов выполняется асинхронно в фоновом задании.

**Закрытие месяца** — цепочки сложных расчётов. Изменения в документах и регистрах, участвующих в закрытии месяца, требуют особого внимания к производительности и корректности.

**СКД (Система Компоновки Данных)** — все отчёты и аналитика строятся через СКД. Для нестандартных отчётов используйте программное заполнение СКД.

### COM vs HTTP-сервисы для интеграции

Для новых интеграций **HTTP-сервисы и REST API** предпочтительнее COM: кросс-платформенны, не требуют совпадения версий, поддерживают веб и мобильные клиенты. COM остаётся для legacy-интеграций на одном сервере.

| Технология | Плюсы | Минусы | Когда использовать |
|---|---|---|---|
| HTTP-сервисы | Кросс-платформа, JSON/XML | Нужна публикация веб-сервера | Новые интеграции, API |
| REST API (OData) | Автогенерация CRUD | Медленные сложные выборки | Внешние системы |
| COM | Прямой доступ к объектам | Только Windows, версиозависимость, лицензия | Legacy, тот же сервер |

### Расширения конфигурации — предпочтительный способ доработок

С платформы **8.3.6** расширения позволяют дорабатывать типовую конфигурацию без её снятия с поддержки. Используйте перехват через аннотации `&Перед`, `&После` (безопаснее) и `&Вместо` (с осторожностью). С **8.3.17** — подписки на события через расширения. С **8.3.20** — определяемые типы, предопределённые элементы. Всегда используйте только публичный API БСП (`ПрограммныйИнтерфейс`) для устойчивости к обновлениям.

```
   ОтменитьТранзакцию() — ПЕРВАЯ строка в Исключение; ВСЕГДА ВызватьИсключение в конце
6. Для составных типов (Регистратор, Владелец) в запросах — ВСЕГДА ВЫРАЗИТЬ()
7. Параметры виртуальных таблиц (Остатки, Обороты) для фильтрации измерений, не WHERE
8. Не обращайся к реквизитам через точку от ссылки в циклах — получай в запросе
9. Используй ПРЕДСТАВЛЕНИЕ() для строковых представлений ссылок
10. Индексируй временные таблицы по полям JOIN/WHERE
11. Процедуры — инфинитив глагола; функции — описание результата без «Получить»
12. Экспортные процедуры обязательно документируй (// Параметры: / Возвращаемое значение:)
13. Используй стандартные области (#Область ПрограммныйИнтерфейс и т.д.)
14. Различай СправочникМенеджер и СправочникОбъект
15. Для БСП — используй ТОЛЬКО код из области ПрограммныйИнтерфейс
```

```
Требования:
- Используй параметры виртуальных таблиц для фильтрации измерений
- Если нужны данные из табличной части документа — используй временную таблицу через &ПараметрТаблицы
- Индексируй временные таблицы по полям JOIN
```

### 7.5 AI-инструменты для 1С разработки (экосистема 2025-2026)

**1С:Напарник** (code.1c.ai) — официальный AI от 1С, плагин для EDT. Автокомплит, объяснение кода, генерация комментариев. Бесплатно до октября 2026. Качество пока уступает Cursor/Claude Code.

**MCP-1C** (github.com/feenlace/mcp-1c) — MCP-сервер подключающий Claude/Cursor/VS Code к живой базе 1С. AI видит реальные метаданные конфигурации и генерирует контекстно-точный код. 9 инструментов: метаданные, запросы, поиск по коду, аудит безопасности.

**1C Processor Generator** (github.com/SERGIUSH-UA/1c-processor-generator-ce) — генерация готовых внешних обработок (.epf) из YAML + BSL. AI генерирует YAML, генератор конвертирует в валидный XML 1С с UUID'ами. Решает проблему невозможности прямой генерации формата 1С.

**Mini AI 1C** (github.com/hawkxtreme/mini-ai-1c) — AI-ассистент с встроенным BSL-линтером, поддержкой Ollama/OpenAI/Anthropic/DeepSeek, интеграцией 1С:Напарника как MCP-сервера.

**Рейтинг моделей для BSL-кода** (по бенчмаркам Habr 2025): Gemini 2.5 Pro ≈ Claude Sonnet 3.7/4 (лучшие) >> ChatGPT 4o > DeepSeek V3 > GigaChat >> YandexGPT ≈ Copilot (худшие). Все модели галлюцинируют на BSL — **обязательна** ревью человеком.

**Оптимальный workflow:** MCP-сервер (mcp-1c) предоставляет AI реальные метаданные конфигурации → Claude/Cursor генерирует BSL → компиляция → ошибки возвращаются AI → автоисправление. Этот цикл валидации кратно повышает качество генерации.
