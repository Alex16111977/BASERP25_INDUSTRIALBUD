# 07. Связанные объекты конфигурации и данных

## Справочник `А_СтруктураСебестоимости` (СС) — источник ПЛАНА

Карточка проекта («МД Вооз ЕМS Мала 2026 / Цех_МД Вооз ЕМS Мала 2026»...). Реквизиты, важные
отчёту: `Подразделение` (ось соединения факта!), `А_КоличествоМодулей` (для EV-документа),
`СкладПроизводство`/`СкладМонтаж` (исторические, после перехода факта на закупки в отчёте
не используются, но остаются в ВТ_СС).
- ТЧ `Работы`: Работа(Номенклатура), Этап(А_ЭтапыРабот), НаВыезде(Булево→Категорія Монтаж),
  Количество (часы на ВСЕ модули), Сумма (план ФОТ).
- ТЧ `Комплектующие`: Этап, Номенклатура (+её ОбщаяНазва/Единица), Количество, Сумма.
- Наполнение из Excel — обработка «Загрузка А_ВыполнениеРаботМодулей» (режим загрузки работ)
  и «Загрузка работ в СС для базы ЕРП».
- ⚠️ Дубли карточек СС и общих назв с одинаковыми именами — легальны; весь маппинг в отчёте
  строковый по именам.

## Документ `А_ВыполнениеРаботМодулей` — источник «Виконання» (EV)

Снимок НАКОПЛЕННЫХ % выполнения работ по модулям на дату (оцифровка Excel
«ЗВіт_виконання...»: строки-работы × колонки М1..М_N). Модель «снимок в документе + дельта
в регистре». Форма — динамическая матрица (колонки по `СС.А_КоличествоМодулей`, программные).
- **РН `А_ВыполнениеРаботМодулей`** (обороты): СС/Подразделение/Работа/НомерМодуля + Этап →
  `ЧасыВыполнение` (15,3) = ДЕЛЬТА `ПланЧасыМодуля × (Процент − пред.снимок)/100`.
  Отчёт читает именно его (ветка 6, `МЕЖДУ НачП И КонП` — семантика симметрична табелю).
- **РС `А_ПроцентыВыполненияМодулей`** (по позиции регистратора): снимок % для среза/переноса
  «по предыдущему»; пред. снимок при проведении — `СрезПоследних(&Граница Исключая
  МоментВремени(Дата, Ссылка))` (корректно для одной секунды и перепроведения).
- Хронология: документы проводить по возрастанию дат; поздние снимки после правки задним
  числом перепроводит пользователь (предупреждения встроены).
- Полная база знаний документа — память `vrm_vypolnenie_rabot_modulej.md` + спец
  `docs/superpowers/specs/2026-07-06-выполнение-работ-модулей-design.md`.

## Регистры-источники факта

| Регистр | Роль в отчёте | Грабли |
|---|---|---|
| `РН.А_ДанныеТабелирования` | ФактЧасы (Период = КАЖДЫЙ ДЕНЬ табеля, регистратор `А_ТабельУчетаРабочегоВремени`) | нет разреза Работа |
| `РН.А_ВзаиморасчетыССотрудниками` | ФактГрн ФОТ (только Приход от ОЗФУ) | по Подразделению напрямую |
| `РН.СебестоимостьТоваров` | ФактКол/ФактГрн закупок | обязательно `РазделУчета=ТоварыНаСкладах` + `Регистратор ССЫЛКА ПриобретениеТоваровУслуг`; ресурс `СтоимостьБезНДС` (единый базис НДС с планом) |
| `РН.А_ВыполнениеРаботМодулей` | ВиконанняЧасы | дельты; отрицательные при корректировке вниз |

## Родственные отчёты/обработки

- **`А_ПланФактныйАнализСебестоимости`** — референс методики «факт материалов = закупки»
  и кросс-чек сумм (по подразделению обязана совпадать копейка в копейку).
- **`А_ПланФактныйАнализРабот`** — эталон СКД-обвязки (клонировался Template).
- **Обработка «Загрузка А_ВыполнениеРаботМодулей»** (`_Rarzrabotki\А_ПланФактныйПроизводствоПолный\По часам\`):
  режим 1 — загрузка работ в СС из Excel (создаёт работы/этапы по образцу: группа `_Роботи`
  0Ц-00000016, образец артикул 1.1.1); режим 2 (промт от 10.07.2026) — создание документов
  выполнения из листов `ЗВіт (dd.mm)` в т.ч. в чистую базу BaseERPRazr.
- Excel-источник данных выполнения: `...\По часам\Копия ЗВіт_виконання_ВООЗ_ЕМС_Зачепилівка.xlsx`
  (парсер «N модулів --P%» — эталон в `test_vrm_e2e.py`).
