# 05. Постобработки: Етап/Категорія для факт-материалов

После выполнения запроса `ПолучитьДанные` мутирует ТЗ двумя процедурами (порядок важен):
`ЗаполнитьЭтапФактМатериалов(ТЗ, СС)` → `ЗаполнитьПланНаФакт(ТЗ)` (см. 04).

## ЗаполнитьЭтапФактМатериалов — зачем

Факт-закупки (ветка 5) не знают этапа: в `РН.СебестоимостьТоваров` нет ни Етапа, ни привязки
к плану. Разнос делается через **общую назву номенклатуры**: у плановой строки
`Комплектующие` есть и Этап, и (с 04.09.2026) собственная назва в ТЧ-реквизите `ОбщееНазвание`
(`Справочник.А_ОбщиеНазванияНоменклатуры`) — строим карту и применяем её к факту.

## МаппингОбщееНазваниеЭтап(СС) — карта «имя общей назвы → {Етап, Категорія}»

**С 04.09.2026 карта строится по ТЧ-реквизиту строки, обращения к карточке номенклатуры
убраны** (было: `К.Номенклатура.А_ОбщееНазваниеНоменклатуры.Наименование`):

```bsl
ВЫБРАТЬ К.ОбщееНазвание.Наименование КАК ОбщееНазвание,
        К.Этап,
        ВЫБОР КОГДА К.Этап.Наименование ПОДОБНО "%Монтаж%" ТОГДА "Монтаж" ИНАЧЕ "Виробництво" КОНЕЦ КАК Категория
ИЗ Справочник.А_СтруктураСебестоимости.Комплектующие КАК К
ГДЕ К.Ссылка.Наименование = &Имя  // ← по ИМЕНИ СС, не по ссылке!
  И ЗначениеЗаполнено(К.ОбщееНазвание) И <этап заполнен>
```

Ключевые решения (не менялись 16.07.2026 → 04.09.2026):
- **Ключ карты — нормализованное ИМЯ** (`СокрЛП`) общей назвы, не ссылка: в справочнике
  `А_ОбщиеНазванияНоменклатуры` есть дубли карточек с одним именем; по ссылке план и факт
  могут указывать на разные карточки и не сойтись.
- **Отбор по ИМЕНИ СС** (`К.Ссылка.Наименование = &Имя`): дубли карточек самой СС с одним
  именем объединяются в одну карту.
- При нескольких этапах одного имени берётся МАКСИМУМ (`Строка(Этап)` сравнение) — детерминизм.
- Категорія считается ТЕМ ЖЕ выражением, что у плана (`ПОДОБНО "%Монтаж%"`) — план и факт
  гарантированно попадают в одну категорию.

**Проверено на живой базе 04.09.2026:** имён общих назв, которые есть ТОЛЬКО у карточек
номенклатуры (а не у строк спецификации), — ноль (у карточек 168 уникальных имён, у строк
ТЧ — 299); переход карты на ТЧ-реквизит ничего не теряет.

## Применение к строкам факта

**С 04.09.2026 строка факта определяется по `ЗначениеЗаполнено(СтрокаТЗ.Номенклатура)`**
(было: `ТипЗнч(Аналитика) = Тип("СправочникСсылка.Номенклатура")` — Аналитика факта теперь
текст, признак «это строка номенклатуры» переехал в новую колонку `Номенклатура`). Для строк
`Блок="2. Матеріали"` с пустым Етапом: `ОбщееНазвание = СтрокаТЗ.ОбщееНазвание` (было
`Аналитика.А_ОбщееНазваниеНоменклатуры` — карточное) → ключ → из карты ставятся `Этап` И
`Категория`. Несопоставленные строки (нет общей назвы или её нет в плане) остаются
с пустым Етапом и категорией-плейсхолдером «Виробництво».

## Изменения 04.09.2026: ключ группы и синтетическая строка (см. также 04)

- **`КлючГруппыПланНаФакт(СтрокаТЗ)`** — сигнатура БЕЗ параметра типа; ветка «по ссылке»
  читает `СтрокаТЗ.Номенклатура` (раньше проверялся тип значения `Аналитика`); ветка
  «по тексту» — без изменений.
- **`ЗаполнитьПланНаФакт`** — группа хранит `Аналитика` образца ВМЕСТО `Номенклатура`;
  синтетическая строка получает `Номенклатура` = пустая ссылка и `Аналитика` = `""` при
  заполненной загальній назві, иначе — текст образца.

## Пустые уровни в выводе

У строк труда пустые ОбщееНазвание/Единица/Документ, у несопоставленных материалов — Етап:
СКД рисует пустые узлы-строки (без подписи) — это норма архитектуры, не дефект.
Аналогично «Виконання» и факт-табель живут на РАЗНЫХ строках одной группировки
(Работа vs ФизЛицо в Аналитике) — сходятся только на итогах уровня Категорія/Підрозділ.
