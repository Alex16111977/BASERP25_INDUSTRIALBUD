# 02. Источники данных: 6 веток UNION

Пакет запроса: `ВТ_СС` → `ВТ_РаботыСС` → `ВТ_Детали` (6 веток ОБЪЕДИНИТЬ ВСЕ) → финальная
группировка. Все ветки обязаны иметь **одинаковый набор и порядок из 18 колонок** (см. ниже) —
рассинхрон = битые данные без ошибки.

**С 16.07.2026 факт табеля/ЗП собирается ПО ИЕРАРХИИ подразделения СС** (табелируют на
вложенные «№1..№N», спецификация — на родителе): в ветках 3/4 соединение
`ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_СС ПО ИСТИНА` + `ГДЕ <рег>.Подразделение В ИЕРАРХИИ
(ВЫБРАТЬ ВТ_СС.Подр ИЗ ВТ_СС КАК ВТ_СС)`. Колонка `Подразделение` у ВСЕХ веток остаётся
`ВТ_СС.Подр` (родитель) — план-факт сходится на нём, ключи ПланНаФакт не дробятся; реальное
подразделение регистра идёт во 2-ю колонку `ПодразделениеИсполнитель` (ветка 6 — `ВРМ.Подразделение`,
план/материалы — `ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)`).

## Подготовительные ВТ

| ВТ | Что | Зачем |
|---|---|---|
| `ВТ_СС` | Ссылка, Подразделение, СкладПроизводство, СкладМонтаж, **Домов** (`ВЫБОР КОГДА КоличествоДомов>0 ... ИНАЧЕ 1`) выбранной СС | параметр всех соединений + множитель плана (нормы на 1 дом) |
| `ВТ_РаботыСС` | Работа → МАКСИМУМ(НаВыезде) по СС.Работы | Категорія для EV-ветки |

### ⚠️ Исторические решения (НЕ откатывать)

- **Факт материалов = закупки, НЕ списание.** До 30.06.2026 ветка 5 была
  `Расход`/`Документ.СборкаТоваров` (списание в производство по складу СС) — заменена по
  требованию заказчика на закупки по подразделению. Сверка: `А_ПланФактныйАнализСебестоимости`
  (тот же источник) — суммы обязаны совпадать по подразделению копейка в копейку.
- **Труд-план даёт часы И грн одной строкой** (Количество+Сумма из одной строки ТЧ Работы).
- **Ветки 3/4 не имеют разреза «Работа»** — в табеле его физически нет (измерения:
  Сотрудник/Подразделение/Состояние/Бригада) → сверка «Виконання ↔ табель» валидна на итогах.

## 18 колонок грейна ВТ_Детали (порядок обязателен; с 16.07.2026)

`Подразделение, ПодразделениеИсполнитель, Блок, Категория, Этап, Работа, ОбщееНазвание,
Документ, Аналитика, НоменклатураНаименование, Единица, ПланЧасы, ФактЧасы, ВиконанняЧасы,
ПланКол, ФактКол, ПланГрн, ФактГрн` (+ в финальном SELECT вычисляются Отклонение*/Процент*/
ПланНаФактГрн=0/ПрогнозГрн/ОтклонениеПрогнозГрн/ПроцентПрогнозГрн).

⚠️ Непустой `ПодразделениеИсполнитель` ДРОБИТ грейн: труд-план и EV по одной работе, ранее
сливавшиеся в одну строку, теперь идут двумя (план — пустой исполнитель, EV — заполнен);
в СКД-группировках сходятся обратно, итоги идентичны. Регрессию сравнивать на агрегатах.

Типы «пустых» значений в ветках, где измерение не применимо:
- ссылочные — ТИПИЗИРОВАННАЯ пустая ссылка (`ЗНАЧЕНИЕ(Справочник.X.ПустаяСсылка)`), НЕ НЕОПРЕДЕЛЕНО
  (иначе составной тип поля ломается / в расшифровке мусор); исключение — `Документ` и `Етап`
  в ветках труда = НЕОПРЕДЕЛЕНО (составные поля);
- `НоменклатураНаименование` — Строка(150), заполняется ТОЛЬКО в ветке 5 (наименование
  номенклатуры закупки; служит для сортировки/поиска по тексту).

Финальная группировка — по всем 10 измерениям; `СУММА()` по ресурсам; проценты через
`ВЫБОР КОГДА СУММА(План*) = 0 ТОГДА 0` (защита деления).
