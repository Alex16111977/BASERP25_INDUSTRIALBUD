## Структура группировок по умолчанию (вариант «Основной»)

`Підрозділ → Блок → Категорія → Етап → Загальна назва → Аналітика → Од. вим. → Документ`

- «Работа» в структуру по умолчанию НЕ входит — доступное поле для пользовательских
  группировок/отборов (добавлено ~15.07.2026, вариант «А»: дефолтный вид не менять).
- «Підрозділ-виконавець» (16.07.2026) — тоже вариант «А»: в дефолт НЕ входит, пользователь
  добавляет уровнем под «Підрозділ» через «Настройки», когда нужен разрез по вложенным
  подразделениям. У строк плана/материалов пуст (план не детализирован по вложенным).
- «Номенклатура» (04.09.2026) — тоже вариант «А»: доступное поле для пользовательских
  группировок/отборов, в дефолтную структуру НЕ входит. У труд-плана/EV/табеля всегда пуста,
  заполнена только у факт-закупок (план материалов ставит пустую ссылку).
- «Од. вим.» — УРОВЕНЬ группировки (подстрока под номенклатурой), не колонка: см. LESSONS
  про рендер измерений.

## Язык интерфейса отчёта

Титулы и значения группировок — **украинские** (возвращены 16.07.2026 после временного
русского перевода 09–10.07): заголовок «Виробництво: план-факт (за табелями)», грамматика
«за табелями» / «Відхилення прогнозу» / «% вик. прогнозу» / «Структура собівартості».
⚠️ Переводить можно ТОЛЬКО `v8:content` (титулы) и строковые ЗНАЧЕНИЯ в BSL-запросе
(`"1. Праця"`, `"Виробництво"`...). Служебные имена (`dataPath`, `field`, `dcsset:field`,
`parameter name`, идентификаторы BSL типа `СкладПроизводство`) — НЕ трогать (см. LESSONS).
Тесты `test_pfpp_*.py` сравнивают значения блоков — при смене языка синхронизировать.

## Сохранённые настройки пользователя (частая «пропажа» колонок)

Платформа применяет сохранённый пользователем вариант ПОВЕРХ нового дефолта из .erf:
после каждой доработки новые колонки/титулы могут «не появиться». Лечение на стороне
пользователя: **Ещё → Установить стандартные настройки** → Сформировать.
Программно настройки пользователя НЕ трогаем (конвенция проекта).
