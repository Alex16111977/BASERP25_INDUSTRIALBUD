14. **⚠️ ОТКРЫТО: EV («Виконання») в шкале «один дом»** — план теперь × КоличествоДомов, а ветка
    ВРМ множителя НЕ имеет (осознанно). Один документ `А_ВыполнениеРаботМодулей` при 100% всех
    модулей даёт EV = НОРМА ОДНОГО дома («Заполнить из СС» ставит ПланЧасы без ×Домов,
    КоличествоМодулей лишь делит по колонкам). Следствие для СС с Домов>1 (IRS15/30):
    - вести ВРМ **ПО-ДОМНО** (документ на каждый дом-подразделение, как табели) → EV домов
      суммируется до шкалы плана, «% виконання» корректен — РЕКОМЕНДУЕМАЯ модель;
    - если вести ОДИН документ на проект — «% виконання» упрётся в 100/Домов (16,7% у IRS15),
      «Відхилення табель-виконання» сравнит проектный факт с EV одного дома → нужен будет
      множитель в EV-ветке (НЕ добавлять, пока модель ведения не подтверждена — риск двойного
      счёта при по-домном ведении). Сегодня латентно: движения ВРМ только у ВООЗ (Домов=1).
    Найдено адверсариальной верификацией 16.07.2026.

23. **Факт закупок переведён на «с НДС» + добавлены ресурсы Ціна план/факт** (24.07.2026). Было: ветка 5 факт =
    `СТ.СтоимостьБезНДС` (нетто). Стало: **`СТ.Стоимость`** (брутто). Сверено бухгалтерски: `Стоимость`
    (2 686 837,22 IRS) = `Товары.СуммаСНДС` документа-закупки = `СтоимостьБезНДС (2 262 214,37) + НДСРегл (424 622,85)`
    копейка в копейку (пользователь дал скрин: закупка ІБ00-003099 НДС 3 724,78 / Всего с НДС 22 348,66; строка
    Грунт-емаль факт 16 099,08 — без НДС). План (Комплектующие.Сумма) уже с НДС (подтв. пользователем) → сравнение
    брутто↔брутто корректно. Эффект: IRS факт 2 262 214,37 → **2 686 837,22**, ОРІЛЬ 1 767 592,35 → 2 099 780,61.
    **Новые ресурсы** `ЦенаПлан`=`Сумма(ПланГрн)/Сумма(ПланКол)`, `ЦенаФакт`=`Сумма(ФактГрн)/Сумма(ФактКол)` —
    середньозважені, реализованы как `<totalField>` в схеме (как `Процент*`) + вычисляемые колонки в финальном
    SELECT + колонки в СоздатьПустуюТаблицу; на строках без кол-ва = 0. Провалидировано COM-smoke .erf (факт брутто;
    ЦенаФакт/ЦенаПлан = Сума/Кількість на примерах 138/66/2648/340/3460; compose с отбором IRS+новые поля OK h=1872).
    ⚠️ `ПланКол/ФактКол` в ТЗ хранятся (18,2) — на строках с 3-знач. кол-вом (тонны) leaf-price точнее (запрос делит
    полное кол-во регистра), групповой totalField использует округлённое кол-во (на агрегате погрешность
    пренебрежима: 2 686 837,22/42 524,41 = 63,18). ЦенаПлан/ЦенаФакт тип (18,2). (24.07.2026)

24. **Плановая ветка материалов переведена ПОЛНОСТЬЮ на ТЧ `Комплектующие`, обращения к

    под «вату 50». После правки (`ОбщееНазвание=К.ОбщееНазвание`, `Аналитика=СокрЛП(К.НоменклатураСС)`,
    `Единица=К.ЕдиницаОбщееНазвание`, новая колонка `Номенклатура`=пустая ссылка): план «вата 100»
    = 1000 пач / 392 993,96, «вата 50» = 180 пач / 75 810,32 (×КоличествоДомов=4); факт — 198 и
    54 пач соответственно.
    ⚠️ **Это ПРЯМАЯ отмена решения §18** (16.07.2026 полный перевод на ТЧ-ОН был откачен именно
