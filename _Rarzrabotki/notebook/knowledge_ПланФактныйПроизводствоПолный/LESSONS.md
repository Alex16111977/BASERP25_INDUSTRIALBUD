# LESSONS — грабли и как их обходить

## 🚨 Бизнес-инварианты (НЕ МЕНЯТЬ — уже ломалось в бою)

1. **🔴 ФАКТ ПО МАТЕРИАЛАМ — ВСЕГДА «С НДС».** Ветка 5 тянет `РегистрНакопления.СебестоимостьТоваров.Стоимость`
   (брутто, с НДС). **НИКОГДА не менять на `СтоимостьБезНДС`** (и не на `СтоимостьРегл`/`СтоимостьУпр` — они без НДС).
   План (`Комплектующие.Сумма`) заведён с НДС → факт обязан быть с НДС, иначе план↔факт и EAC врут. Сверка:
   `Стоимость` = `Товары.СуммаСНДС` документа = `СтоимостьБезНДС + НДСРегл`. **Ошибка уже допускалась (факт без НДС)
   и исправлялась вручную — при доработке ветки 5 ОСТАВЬ `Стоимость`.** Полностью: KNOWLEDGE_MAP §1, FINDINGS §23.

## СКД / программная компоновка

1. **Колонки = только ресурсы.** В полностью-сгруппированном отчёте с внешним набором
   (DataSetObject) поле-ссылку/строку НЕЛЬЗЯ вывести колонкой: в отчётной selection —
   молча не рендерится, в selection группировки — рантайм-ошибка «Поле … не может быть
   использовано в группировке …». Показывать атрибуты — только уровнем группировки.
2. **Рассинхрон веток UNION = тихая порча данных.** 6 веток × 18 колонок: пропуск/сдвиг одной
   колонки не падает, а кладёт числа в чужие поля. При любой правке — пересчитать колонки во
   ВСЕХ ветках + прогнать COM-репликацию запроса (Rule #-1).
3. **Пустые значения измерений** — типизированная пустая ссылка, не НЕОПРЕДЕЛЕНО (кроме
   заведомо составных Документ/Етап в ветках труда). Синтетические строки с НЕОПРЕДЕЛЕНО
   в Аналитике плодят по 3 пустых дубля в расшифровке.
4. **Схема ↔ ТЗ ↔ СоздатьПустуюТаблицу** — три места объявления колонок; новая колонка
   добавляется во все три (пустая таблица — fallback при незаполненной СС).

## Переводы / языки

5. **Переводить только `v8:content` и строковые ЗНАЧЕНИЯ BSL.** Массовая замена слов ломает:
   (а) служебные теги схемы (`dataPath`/`field`/`dcsset:field`/`parameter` — «не найдено поле
   набора»); (б) идентификаторы BSL (`СкладПроизводство` → `СкладВиробництво`); (в) пути
   файлов в тестах (`*ПроизводствоПолный.erf`). Замены — только с якорями (`>слово<`) и
   пост-контролем «укр/рус остатки вне content».
6. **Тесты зависят от языка значений** («1. Праця» vs «1. Труд») — менять синхронно.

## Правки файлов

7. **Template.xml — только Python-скриптом** с assert на число замен: файл на табах,
   Edit-инструменты табы теряют; после правки — `xml.etree.parse` контроль.
8. **BSL-файлы выгрузки** — UTF-8 BOM + CRLF; писать через `encoding='utf-8-sig', newline=''`
   c ручным `\r\n`.
9. **Cyrillic-пути ломают инструменты** — рабочая схема: копия файла в ASCII-scratchpad →
   правка → копия обратно (в основную конфигурацию И в git-worktree — Rule #4).

## Сборка / деплой

10. **Сборка .erf требует ЗАКРЫТОГО Конфигуратора** (эксклюзивная блокировка ИБ) — главный
    блокер сессий; просить пользователя закрыть, не убивать чужие сеансы.
    **Обход (16.07.2026): собирать через ЛЮБУЮ БСП-базу** — при
    `/LoadExternalDataProcessorOrReportFromFiles` платформа валидирует ТОЛЬКО ссылки
    DefaultForm/DefaultSettingsForm/DefaultVariantForm (`CommonForm.ФормаОтчета` и т.п.),
    типы полей СКД (`d5p1:CatalogRef.X`) не проверяются. Stub-база epf-build падает именно
    на общих формах; `bas_industrialbud` собрала .erf без замечаний (учётные данные — локальный
    `.v8-project.json`), работоспособность подтверждена smoke на BaseERP. Изолировать исходники
    во временный каталог всё равно нужно.
11. **`.erf` новее исходников — сверить перед правкой**: файл мог собираться из более свежих
    исходников (или наоборот). Git-история `ObjectModule.bsl` vs `.erf` показывает дрейф.
12. **Сохранённый пользовательский вариант** прячет новые поля/титулы — после деплоя
    напоминать: «Ещё → Установить стандартные настройки».

## Методология показателей

13. **ETC без «игры с копейками»**: при ФактКол=0 брать ровно ПланГрн (round-trip
    кол-во × средняя цена теряет копейки — бухгалтер сверяет копейка в копейку).
14. **Неттинг остатка — по «Загальній назві», без Етапа/Категорії** (иначе завышение), ключ —
    нормализованное ИМЯ (дубли карточек), fallback — Номенклатура (не выбрасывать безымянные).
15. **Не выбрасывать группы молча**: две «безобидные» строки-фильтра (`НЕ ЗначениеЗаполнено(ОН)
    ИЛИ ПланКол<=0 → Продолжить`) стоили 106 887,27 в прогнозе. Любой фильтр в агрегации —
    обосновать и покрыть тестом-инвариантом.
16. **Эталоны живой базы дрейфуют** (закупки/табели приходят ежедневно) — регрессию мерить
    парой «до/после» в одной сессии, стабильные инварианты формулировать относительно
    (ПнФ=План при Факт=0; отчёт==прямой запрос), а не абсолютными числами.

## COM-тесты

17. `СтандартныйПериод` через COM: даты ставить прямым присвоением `п.ДатаОкончания = datetime`
    — обращение к перечислению `ВариантСтандартногоПериода.Произвольный` через COM-прокси
    нестабильно (кириллические имена).
18. COM-ошибки 1С приходят в cp1251 и корёжатся в консоли — писать `excepinfo[2]` в utf-8
    файл и читать его.
19. Подключения с 15.07.2026 — `Srvr="localhost"` (BaseERP, BaseERPRazr; учётные данные — см. CLAUDE.md).
20. **`В ИЕРАРХИИ` принимает подзапрос из ВТ** — `ГДЕ Т.Подразделение В ИЕРАРХИИ
    (ВЫБРАТЬ ВТ_СС.Подр ИЗ ВТ_СС КАК ВТ_СС)` работает (проверено 16.07.2026); включает сам
    элемент. Джойн при этом `ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_СС ПО ИСТИНА` (ВТ_СС всегда 1 строка).
    `УПОРЯДОЧИТЬ ПО Поле ПРЕДСТАВЛЕНИЕ` — НЕ синтаксис 1С (ошибка), сортировать без модификатора.
21. **pywin32 не конвертирует даты с годом ~3980+** в COM VARIANT (`OSError: Invalid argument`)
    — для «всего периода» в параметрах запроса брать `datetime(2000,1,1)..datetime(2100,12,31)`.

## Сверка исходников и тестов (04.09.2026)

22. **Git может отставать от рабочих файлов на диске на несколько волн доработок**: версия в
    git была позади текущей на диске (факт без НДС, join с `ВТ_СС` вместо `ВТ_Подр1`, не было
    `ПодразделениеЗакупки`/`КоличествоДомов`/`ПодразделениеОбъекта`). Источник истины — файлы на
    диске (`_Rarzrabotki/Отчеты/…` и `Reports/…`), НЕ git. Перед правкой — сверять обе копии
    отчёта друг с другом и с git; при расхождении рабочая версия восстанавливается из копии на
    диске (в этом случае — из конфигурационной `Reports/…`), правки накладываются на неё.
23. **Эталоны факта в тестах дрейфуют вместе с запросом**: жёсткий числовой эталон в
    `test_pfpp_edinica.py` заменён кросс-контролем с регистром `СебестоимостьТоваров` — суммы
    сверяются копейка в копейку, по количеству допуск 0,1 (таблица отчёта округляет до 2 знаков,
    регистр хранит 3). В `test_pfpp_koef_domov.py` карточки СС ищутся по префиксу с нормализацией
    кириллической «С» → латинской «C» (имена карточек IRС набраны с кириллической «С»).
24. **Сигнатура `ПолучитьДанные` может меняться без предупреждения** (04.09.2026 подтверждено):
    метод принимает ОДИН параметр `Период` и строит данные сразу по ВСЕМ подразделениям; тесты,
    которые раньше звали его с двумя параметрами под одну СС, переписаны на фильтрацию строк
    результата по подразделению. Перед правкой/чтением теста — проверить актуальную сигнатуру в
    живом `ObjectModule.bsl`, не полагаться на память или старые тесты. Новый контрактный тест:
    `_Rarzrabotki/Python/test/test_pfpp_query_plan_iz_ss.py`.
