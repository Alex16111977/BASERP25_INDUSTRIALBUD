# 01. Архитектура: программная компоновка СКД

## Почему отчёт программный (не чистый СКД-запрос)

1. Разнос факт-материалов по Етапу идёт через `Номенклатура.А_ОбщееНазваниеНоменклатуры` →
   план `Комплектующие.Этап`. Соединение по справочнику `А_ОбщиеНазванияНоменклатуры` в запросе
   СКД на этой базе не работает (1С-квирк) + у справочника есть ДУБЛИ карточек с одинаковым
   именем → сопоставление возможно только по нормализованному ИМЕНИ в BSL (`Соответствие`).
2. «План на факт» (ETC) требует синтетических строк «залишок плану», которые вычисляются
   правилами (см. 04) и добавляются в таблицу ПОСЛЕ запроса.

История: отчёт начинался как программная матрица 51×6, 2026-06-25 по требованию заказчика
переведён на типовой вид СКД с расшифровкой; программным остался сбор данных.

## Поток данных

```
ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)
  СтандартнаяОбработка = Ложь; УстановитьПривилегированныйРежим(Истина)
  Настройки = КомпоновщикНастроек.ПолучитьНастройки()
  Период, СС = параметры компоновщика ("Период" СтандартныйПериод, "СтруктураСебестоимости" CatalogRef)
  ТЗ = ПолучитьДанные(Период, СС)            // запрос 6 веток + постобработки
  ВнешниеНаборыДанных = Структура("Детали", ТЗ)
  КомпоновщикМакетаКомпоновкиДанных.Выполнить(СхемаКомпоновкиДанных, Настройки, ДанныеРасшифровки)
  ПроцессорКомпоновкиДанных.Инициализировать(Макет, ВнешниеНаборыДанных, ДанныеРасшифровки)
  ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент → ДокументРезультат
```

Расшифровка штатная: `ДанныеРасшифровки` прокидываются, ссылочные измерения (Аналитика,
Документ, Етап…) дают drill-down до объекта.

## ПолучитьДанные(Период, СС) — контракт

- `СС` пустая → возвращается пустая ТЗ (`СоздатьПустуюТаблицу()`, типы колонок = полям схемы).
- **Границы периода независимы**: пустое начало → `'00010101'`, пустой конец → `'39991231'`.
  Открытый период «— 19.06» работает по концу (фикс 06.07.2026: раньше при пустом начале конец
  игнорировался и показывался весь срок).
- Порядок: запрос → `ЗаполнитьЭтапФактМатериалов(ТЗ, СС)` → `ЗаполнитьПланНаФакт(ТЗ)` → возврат.

## Схема (Template.xml)

- Один `dataSet xsi:type="DataSetObject"` c `objectName = "Детали"` — поля ОБЪЯВЛЯЮТСЯ,
  данные приходят из BSL. Типы полей обязаны совпадать с колонками ТЗ (и с
  `СоздатьПустуюТаблицу` — fallback).
- `totalField` — все итоговые формулы (см. 03). `settingsVariant "Основной"` — структура
  группировок по умолчанию (см. 06).
- Параметр СКД ссылочного типа объявляется как `cfg:CatalogRef.А_СтруктураСебестоимости`
  (нужен xmlns:cfg в корне DataCompositionSchema).

## Регистрация и запуск

- `СведенияОВнешнейОбработке()`: Вид=«ДополнительныйОтчет», версия 3.0, БезопасныйРежим=Истина.
  В справочнике «Додаткові звіти й обробки» БД **НЕ зарегистрирован** (проверено 10.07.2026) —
  пользователь открывает `.erf` напрямую (Файл → Открыть). Поэтому после пересборки достаточно
  заменить файл на диске.
- Вывод отчёта — типовая `ОбщаяФорма.ФормаОтчета` платформы.
