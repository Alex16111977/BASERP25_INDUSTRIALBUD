# 08. Тесты, сборка, эталонные числа

## Процесс доработки отчёта (Rule #-1 и далее)

1. **Каждый новый/изменённый 1С-запрос** — сначала Python-COM тест на живой базе
   (`V83.COMConnector`, `Srvr="localhost";Ref="BaseERP"` (учётные данные — внутренние, см. CLAUDE.md проекта)),
   только потом в BSL.
2. Template.xml править Python-скриптом (табы! Edit-инструменты их теряют) + `xml.etree` парс-контроль.
3. Сборка: `.claude/skills/epf-build/scripts/epf-build.ps1 -V8Path "C:\Program Files\1cv8\8.3.20.1914\bin"
   -InfoBaseServer localhost -InfoBaseRef BaseERP -SourceFile <корневой .xml> -OutputFile <.erf>` —
   требует ЗАКРЫТОГО Конфигуратора (и это главный блокер — просить пользователя закрыть).
4. Smoke собранного .erf через COM: `ВнешниеОтчеты.Создать(erf)` (компиляция модуля) →
   `отчет.ПолучитьДанные(СтандартныйПериод, СС)` → композиция:
   `КомпоновщикМакетаКомпоновкиДанных.Выполнить(схема, отчет.КомпоновщикНастроек.ПолучитьНастройки())`
   → `ПроцессорКомпоновкиДанных.Инициализировать(макет, Структура("Детали", ТЗ))` → вывод в
   ТабличныйДокумент, `ВысотаТаблицы > 0`; сканирование текстов ячеек — проверка титулов шапки.
5. Копия .erf и исходников в основную конфигурацию + git-ветка `claude/*` + push.
