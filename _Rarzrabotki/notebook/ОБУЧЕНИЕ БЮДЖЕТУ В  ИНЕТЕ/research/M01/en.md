# M01. Генеральный бюджет и связка БДР–БДДС–ББЛ — международные основы (трек EN)

Трек: master budget, three-statement model, прямой/косвенный ДДС, прогнозный баланс, balance checks,
roll-forward (corkscrew), кредитная линия с неснижаемым остатком и цикличность процентов.
Дата: 02.10.2026. Опирается на уже имеющиеся заметки
`knowledge_ПредварительныйРасчет_БюджетированияИ_PL/research/research_notes/Методики бюджета ДДС проектного производства/01_master_budget.md`
(далее — «заметки 01») и метод `07_moy_metod_raschetnogo_byudzheta.md` (далее — «метод 07»). Здесь НЕ повторяются:
канонический порядок мастер-бюджета, профили инкассации ACCA/LibreTexts, налоговый календарь Украины, таблица из 12
проверок и примеры A/B/C заметок 01 — только углубление.

Обозначения: AR — дебиторка (безусловное право на оплату); CA — актив по договору (contract asset, «дом отгружен,
но не принят»); AdvR — авансы полученные (contract liability); AP — кредиторка поставщикам; AdvP — авансы выданные;
Inv — запасы/НЗП/ГП по себестоимости; RCF — кредитная линия (revolver); C — деньги; C_min — неснижаемый остаток.
Все примеры с числами — **наши иллюстративные расчёты на условных данных**, если не указан источник.

## 1. Главные выводы

1. **Генеральный бюджет замыкается прогнозным балансом, а не БДДС.** Учебники управленческого учёта прямо называют
   прогнозный баланс последним шагом мастер-бюджета: каждая его строка «приходит» из какого-то бюджета (деньги — из
   кассового, дебиторка — из графика инкассации, запасы — из бюджета производства/материалов, кредиторка — из графика
   оплат, нераспределённая прибыль — из БДР) ([Lumen SUNY](https://courses.lumenlearning.com/suny-managacct/chapter/budgeted-financial-statements/);
   [Lumen WM](https://courses.lumenlearning.com/wm-managerialaccounting/chapter/budgeted-balance-sheet/)). Его задача —
   показать, «поддерживается ли» бюджет финансово (например, не требует ли он большого долга)
   ([AccountingTools](https://www.accountingtools.com/articles/budgeted-balance-sheet)).
2. **Существует четыре классических способа прогнозировать деньги** — прямой «поступления и выплаты» (R&D), и три
   косвенных: скорректированная прибыль (ANI), прогнозный баланс (PBS) и метод обращения начислений (ARM). Прямой —
   для горизонта до ~13 недель/90 дней, косвенные — для месяцев и лет
   ([Wikipedia: Cash flow forecasting](https://en.wikipedia.org/wiki/Cash_flow_forecasting);
   [AFP](https://www.financialprofessionals.org/training-resources/resources/articles/Details/selecting-a-cash-forecasting-methodology)).
   Наш горизонт окт–дек 2026 попадает ровно на стык — значит, нужны **оба** и их сверка.
3. **Зрелая практика — не выбирать метод, а сверять:** прямой для ближних недель, косвенный для дальнего плана,
   сравнение двух взглядов в окне перекрытия 1–3 месяца ([Kyriba, вендор](https://www.kyriba.com/resources/insights/cash-flow-forecasting-maturity-framework/)).
4. **Любая статья баланса моделируется «штопором» (corkscrew):** начало = конец прошлого периода; конец = начало +
   приток − отток. FAST Standard требует накапливать остатки только штопором, а не нарастающими суммами
   ([FAST Standard 02a](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf);
   [CFI: corkscrew](https://corporatefinanceinstitute.com/resources/excel/corkscrew-calculation/)).
5. **Деньги в модели не «подгоняются».** Деньги — последняя рассчитанная строка (из ДДС), а единственный
   допустимый «балансир» — кредитная линия с явным правилом неснижаемого остатка
   ([CFI: 3-statement model](https://corporatefinanceinstitute.com/resources/financial-modeling/3-statement-model/);
   [CFI: 10 причин дисбаланса](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).
6. **Каждая изменяющаяся строка баланса должна попасть в ДДС ровно один раз и с правильным знаком**; рост актива =
   отток денег, рост обязательства = приток ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/);
   [FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).
7. **Проверки — часть конструкции, а не «потом».** ICAEW Financial Modelling Code: проверка равенства для каждой
   пары независимо посчитанных величин (баланс!), допуск на округление, единая «мастер-проверка», запрет
   «балансирующих» вычислений ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).
8. **Цикличность процентов лучше не допускать:** FAST — «никогда не выпускать модель с намеренной цикличностью»;
   ICAEW — отключить итерации, решать алгебраически или упрощающим допущением (проценты на остаток на начало
   периода) ([FAST](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf);
   [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx);
   [BIWS: debt schedule](https://samples-breakingintowallstreet-com.s3.us-east-1.amazonaws.com/Mastery/12-15-90-Minute-LBO-Part-4-Debt-Schedule.pdf)).
9. **Для проектного производства есть три разных «дебиторских» строки, а не одна:** аванс полученный (обязательство
   по договору), актив по договору (право на оплату обусловлено ещё чем-то, кроме времени — например, приёмкой) и
   дебиторка (безусловное право, ждём только срок) ([CPDbox](https://www.cpdbox.com/036-contract-asset-vs-account-receivable/);
   [IFRS 15 IE](https://www.ifrs.org/content/dam/ifrs/publications/html-standards/english/2024/issued/ifrs15-ie.html)).
   У «Індастріалбуд» это ровно цепочка «аванс 30 % → 20 % после поставки → 50 % после приёмки».
10. **Дни оборачиваемости (DSO/DIO/DPO) — инструмент санитарной проверки, а не основной драйвер для
    «рваных» проектов.** Отраслевой ориентир строительства и инжиниринга (FY24): DSO 58,6 дн., DIO 27,9 дн.,
    DPO 59,0 дн., половина выборки финансировала разрыв «платим поставщикам быстрее, чем получаем от клиентов»
    ([McGrathNicol](https://www.mcgrathnicol.com/working-capital-report-2024/construction-engineering/)).
11. **Неснижаемый остаток задаётся политикой и проверяется стрессом:** ориентиры практиков — от ~1–1,5 месяца
    операционных расходов ([Financial Rhythm, блог](https://financialrhythm.com/how-to-set-cash-balance-targets/)) до
    «дней буфера» = ликвидность / среднедневной чистый отток с целевыми 45–90 днями и стресс-сценарием DSO +8–10 дн.
    ([Umbrex](https://umbrex.com/resources/company-analysis/finance/cash-buffer-days/)).
12. **Типовые ошибки трёхотчётной модели повторяются:** забытая связь, двойной счёт, перевёрнутый знак, ручные
    константы в прогнозе, начальное значение вместо конечного, «затычки» (plugs) вместо поиска причины
    ([CFI](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models);
    [BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)). Приём «разделить
    расхождение пополам» находит ошибку знака: перевёрнутый знак удваивает ошибку
    ([FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).
13. **Стандарты отчётности поддерживают нашу логику:** IAS 7 разрешает оба метода (прямой поощряется — по
    сниппету [ICAEW](https://www.icaew.com/technical/corporate-reporting/corporate-reporting-resources/by-all-accounts/articles/2025/cash-flow-accounting-standards-the-direct-or-indirect-method)), сверку
    прибыли с операционным потоком требует только при косвенном, а US GAAP — всегда; с 2027 (IFRS 18) косвенный
    метод начинается с операционной прибыли ([Deloitte DART](https://dart.deloitte.com/USDART/home/publications/deloitte/additional-deloitte-guidance/roadmap-ifrs-us-gaap-comparison/chapter-4-presentation/4-3-statement-cash-flows);
    [IFRS.org IAS 7](https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/)).
    Для управленческого бюджета берём строгий вариант US GAAP: прямой БДДС **всегда** сверяется с косвенным.

## 2. Понятия и формулы

### 2.1. Связка трёх бюджетов (одна формула на всё)

Для любой балансовой статьи `X` за период `t`:

```
X_кон(t) = X_нач(t) + Начислено_в_БДР(t) − Оплачено_в_БДДС(t) ± Зачёты/переносы(t),   X_нач(t) = X_кон(t−1)
```

Отсюда прямой ↔ косвенный:

```
ЧДП_операц = Прибыль(БДР) + Неденежные расходы (аморт., резервы)
             − ΔAR − ΔCA − ΔInv − ΔAdvP              (рост активов = отток)
             + ΔAP + ΔAdvR + ΔЗП_к_выплате + ΔНалоги_к_уплате   (рост обязательств = приток)
```

Правило знаков из учебника: прибавляются уменьшение оборотных активов и рост текущих обязательств, вычитаются
рост оборотных активов и уменьшение текущих обязательств
([Lumen SUNY: direct/indirect](https://courses.lumenlearning.com/suny-finaccounting/chapter/direct-and-indirect-methods-for-preparing-a-statement-of-cash-flows/);
[CFI №6](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).
Пример пересчёта статьи прямого метода из учёта: поступления от покупателей = выручка − прирост дебиторки
(100 000 − 5 000 = 95 000) ([Lumen SUNY](https://courses.lumenlearning.com/suny-finaccounting/chapter/direct-and-indirect-methods-for-preparing-a-statement-of-cash-flows/)).
Статьи прямого метода по IAS 7: от покупателей, поставщикам, работникам, прочие операционные, проценты, налоги
([BDO IAS 7 at a glance](https://www.bdo.global/getmedia/45a1e16d-dd6c-4530-9b30-14df8b5b4ca0/IAS-7-AAG.pdf.aspx)).

### 2.2. Corkscrew (штопор, roll-forward)

- Четыре строки: начало, приток, отток, конец; начало каждого периода — ссылка на конец предыдущего; название — от
  «винтовой» связи между периодами ([CFI: corkscrew](https://corporatefinanceinstitute.com/resources/excel/corkscrew-calculation/)).
- FAST: остатки накапливать только штопором (не `СУММ` с полуякорем); формы — 4-строчный, 7-строчный с флагом
  периода и 7-строчный с долей неполного периода (PPF); логика времени — только через отдельные флаги, а не через
  вложенные `ЕСЛИ` ([FAST Standard 02a, 2.02](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf)).
- Знаки: на рабочих листах — «нормально положительная» конвенция (все потоки положительные, направление — в
  названии строки: «поступило», «оплачено»); на презентационных — притоки «+», оттоки «−»
  ([FAST 1.01](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf)). ICAEW: конвенцию
  выбрать одну на всю модель, подписать у каждой строки и **не** использовать бухгалтерскую «дебет +/кредит −»
  ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).

### 2.3. Три «клиентские» строки проектного договора (IFRS 15)

| Строка | Когда возникает | Что двигает деньги | Источник |
|---|---|---|---|
| **AdvR — обязательство по договору** | деньги получены до исполнения (аванс) | приток при получении; при отгрузке — только зачёт, денег нет | [IFRS 15 IE, пример 38](https://www.ifrs.org/content/dam/ifrs/publications/html-standards/english/2024/issued/ifrs15-ie.html); [WSP: deferred revenue](https://www.wallstreetprep.com/knowledge/deferred-revenue/) |
| **CA — актив по договору** | исполнение есть, но право на оплату **условное** (ждёт приёмки/вехи) | денег нет до выполнения условия; затем переходит в AR | [CPDbox](https://www.cpdbox.com/036-contract-asset-vs-account-receivable/); [IFRS 15 IE, пример 39](https://www.ifrs.org/content/dam/ifrs/publications/html-standards/english/2024/issued/ifrs15-ie.html) |
| **AR — дебиторка** | право безусловное, ждём только срока | приток в срок оплаты | там же, пример 40 |

- Пример CPDbox: объект на 100 000 за 9 месяцев с оплатой только по завершении; через 6 месяцев готовность 70 % →
  выручка 70 000 признаётся, но в **активе по договору**, а не в дебиторке, потому что оплата зависит от завершения;
  по завершении 100 000 переходят в дебиторку (70 000 из актива по договору + 30 000 выручки)
  ([CPDbox](https://www.cpdbox.com/036-contract-asset-vs-account-receivable/)).
- Пример CPDbox по стройке: цена 12 млн, затраты 10 млн (окна 6 млн + прочее 4 млн); за год выручка 7,5 млн
  (окна 6 по себестоимости + 25 % × 6 млн остальной части), получено 8 млн → по договору нетто-позиция −0,5 млн =
  **обязательство** ([CPDbox: construction](https://www.cpdbox.com/example-construction-contracts-ifrs-15/)).
  Вывод: в отчётности CA и AdvR одного договора сворачиваются в одну строку; в кассовом бюджете их надо держать
  раздельно (у них разные даты «разворота» — наша интерпретация).
- Остаток «отложенной выручки»/авансов: `нач + полученные авансы − признанная выручка = кон`; рост — приток денег
  ([WSP: deferred revenue](https://www.wallstreetprep.com/knowledge/deferred-revenue/)).

### 2.4. Формулы оборачиваемости (для проверки разумности)

```
DSO = AR / Выручка × дни;   DIO = Inv / Себестоимость × дни;   DPO = AP / Себестоимость × дни
CCC = DSO + DIO − DPO;      AR_прогноз = Выручка/дни × DSO (обратное применение)
```

([financial-modeling.com, вторичный](https://www.financial-modeling.com/working-capital-modeling-excel/);
[JP Morgan WCI 2024](https://www.jpmorgan.com/content/dam/jpmorgan/images/payments/working-capital-index/increasing-efficiency-working-capital-index-2024-ada.pdf)).
Типовые ошибки: делить кредиторку на выручку вместо себестоимости; задавать AR и запасы «% от выручки» вместо дней;
не делать обратную проверку «какие DSO/DIO/DPO подразумевает модель»
([financial-modeling.com](https://www.financial-modeling.com/working-capital-modeling-excel/)).
Для помесячной модели количество дней = дни месяца (или дни горизонта при квартальном расчёте) — наша поправка; в
источнике разобран только годовой базис 365.

### 2.5. Кредитная линия (revolver) и неснижаемый остаток

```
Деньги_до_финансирования(t) = C_кон(t−1) + ЧДП_до_финансирования(t) − Проценты(t) − Обязательные_погашения(t)
Излишек/дефицит(t)          = Деньги_до_финансирования(t) − C_min
Если Излишек ≥ 0: Погашение_RCF = MIN(Излишек, RCF_нач)          (не больше долга)
Если Излишек < 0: Выборка_RCF = −Излишек (≤ свободного лимита)
RCF_кон = RCF_нач + Выборка − Погашение ≥ 0;     C_кон = Деньги_до_фин. + Выборка − Погашение
```

Логика «если излишек — гасим меньшее из излишка и долга, иначе берём недостающее» и «деньги на начало + поток −
обязательные погашения − минимальный остаток» — [BIWS: debt schedule](https://samples-breakingintowallstreet-com.s3.us-east-1.amazonaws.com/Mastery/12-15-90-Minute-LBO-Part-4-Debt-Schedule.pdf);
[WSP: debt schedule](https://www.wallstreetprep.com/knowledge/debt-schedule/). Кредитная линия — «пробка» модели,
которая включается только когда деньги ниже минимума; не может уйти в минус; проценты — на выбранную часть,
комиссия за резервирование — на невыбранную; доступный лимит часто ограничен «базой заимствования»
(у WSP пример: 80 % ликвидационной стоимости запасов + 90 % дебиторки)
([WSP: revolver](https://www.wallstreetprep.com/knowledge/modeling-revolving-credit-line-excel-free-template/)).
Досрочное погашение «излишком» задают процентом (cash sweep), линия обычно погашается первой
([Macabacus](https://macabacus.com/operating-model/debt-characteristics);
[WSP: debt schedule](https://www.wallstreetprep.com/knowledge/debt-schedule/)).

### 2.6. Цикличность процентов

Механика петли: проценты → прибыль → поток на погашение → конечный долг → средний долг → проценты
([Macabacus](https://macabacus.com/operating-model/debt-characteristics)). Способы:

| Способ | Суть | Оценка источников |
|---|---|---|
| Проценты на остаток **на начало** периода | петли нет | BIWS использует именно это «чтобы избежать цикличности» ([BIWS](https://samples-breakingintowallstreet-com.s3.us-east-1.amazonaws.com/Mastery/12-15-90-Minute-LBO-Part-4-Debt-Schedule.pdf)); ICAEW — «упрощающее допущение» ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)) |
| Алгебраическое решение | выразить проценты без конечного остатка | «изящно», но реально только для простых случаев ([Forecast](https://forecast.global/insight/demystifying-the-circularity-of-interest/); [Simplex](https://simplexct.com/avoid-circularity-in-financial-models)); Бодмер рекомендует его первым ([edbodmer](https://edbodmer.com/circular-references-in-corporate-finance/)) |
| Итерации Excel + «выключатель» | флаг 1/0 обнуляет проценты при отладке | распространено у банкиров ([WSP: debt schedule](https://www.wallstreetprep.com/knowledge/debt-schedule/)), но FAST запрещает выпускать такие модели, ICAEW просит отключать итерации |
| Ручные итерации/копирование значений | цикл заменён повторными шагами | Simplex рекомендует «ручные итерации» без включения цикличности ([Simplex](https://simplexct.com/avoid-circularity-in-financial-models)) |

**Закрытая формула для процентов на средний остаток (наш вывод).** Пусть `O` — долг на начало, `N` — дефицит до
процентов (сколько нужно выбрать без учёта процентов), проценты выбираются из линии же, `r` — ставка за период:
`I = r·(O + C)/2`, `C = O + N + I` ⇒ `I·(1 − r/2) = r·(2O + N)/2` ⇒ **`I = r·(2O + N)/(2 − r)`**.
Это тот же тип решения, что у Бодмера (знаменатель `1 − r/2`) ([edbodmer](https://edbodmer.com/circular-references-in-corporate-finance/)).
В Python-калькуляторе цикличности нет вообще: можно считать в цикле по месяцам либо по этой формуле.

### 2.7. Таксономия методов прогноза денег

| Метод | Как работает | Горизонт | Слабость |
|---|---|---|---|
| R&D (прямой) | графики поступлений и выплат на кассовой основе | до ~30–90 дней (до года с потерей точности) | ошибки накапливаются с горизонтом |
| ANI (скорр. прибыль) | EBIT/EBITDA ± изменения AR, AP, запасов | месяцы–годы | только помесячно/поквартально; книжные деньги ≠ банк |
| PBS (прогнозный баланс) | деньги = то, что остаётся после прогноза всех прочих статей баланса | месяцы–годы | «деньги верны, если все остальные статьи верны» |
| ARM (обращение начислений) | крупные начисления «разворачиваются» статистическими распределениями лагов | средний | сложнее ANI/PBS, зато допускает недели и дни |

([Wikipedia](https://en.wikipedia.org/wiki/Cash_flow_forecasting); [AFP](https://www.financialprofessionals.org/training-resources/resources/articles/Details/selecting-a-cash-forecasting-methodology)).
AFP: прямой метод = графики на кассовой основе (не начисления), данные выплат — из кредиторки с поправкой на то,
что платежи проходят не в день выписки; при выборе — принцип KISS: модель на 90 % надёжности, которую легко
поддерживать, ценнее модели на 95 % ([AFP](https://www.financialprofessionals.org/training-resources/resources/articles/Details/selecting-a-cash-forecasting-methodology)).
Наш «метод 07» по сути — гибрид ARM (лаги, откалиброванные по факту) + R&D (известные долги) + PBS-ограничители.

## 3. Алгоритмы и правила для бюджета

### 3.1. Порядок сборки связанной модели (адаптация CFI 8 шагов)

CFI: (1) исторические данные; (2) допущения (рост, маржи, капвложения, условия оборотного капитала);
(3) БДР до EBITDA; (4) график ОС; (5) график финансирования; (6) достроить БДР амортизацией и процентами;
(7) баланс без денег; (8) ДДС и сверка денег — деньги считаются последними
([CFI: 3-statement model](https://corporatefinanceinstitute.com/resources/financial-modeling/3-statement-model/)).
Для проектного производителя на квартал:

```
Шаг 0. ПРОВЕРЕННЫЙ входящий баланс на 30.09 (по проектам): C, AR, CA, AdvR, Inv/НЗП, AdvP, AP, ЗП и налоги к уплате, RCF.
       Входящий капитал/результат проекта = Активы − Обязательства (не вводится руками).
Шаг 1. Операционный план в натуре: дома по месяцам (цех → отгрузка → монтаж → приёмка), тонны МК; + 1–2 месяца за горизонтом.
Шаг 2. БДР по проектам: выручка по событию признания, себестоимость = норма × отгруженное, накладные, проценты (позже).
Шаг 3. Штопоры оборотного капитала: AdvR, CA, AR (вехи договора), Inv/НЗП (производство), AdvP, AP (условия поставщиков),
       ЗП к выплате (календарь), налоги к уплате (налоговый календарь).
Шаг 4. Прямой БДДС = «оплаченные» строки всех штопоров (+ входящие остатки, погашаемые в горизонте).
Шаг 5. Деньги до финансирования → сравнение с C_min → выборка/погашение RCF → проценты (на остаток на начало).
Шаг 6. Прогнозный баланс на конец каждого месяца; деньги = конец БДДС; капитал = нач + прибыль − проценты − распределения.
Шаг 7. Проверки (раздел 3.4), мастер-проверка = 0 по каждому проекту и месяцу.
Шаг 8. Косвенный ДДС из БДР и Δбаланса; сверка с прямым (должно совпасть до копейки).
```

### 3.2. Как прогнозировать каждую денежную статью баланса

| Статья | Драйвер (что двигает) | Лучший метод для «Індастріалбуд» | Санитарная проверка |
|---|---|---|---|
| AdvR (авансы полученные) | график авансов договора; зачёт при отгрузке | по вехам договора: `зачёт = доля_аванса × цена × отгружено` | AdvR ≥ 0; AdvR_кон = доля аванса × неотгруженные дома |
| CA (отгружено, не принято) | отгрузка → приёмка | `+ (1 − аванс − доля_после_поставки) × цена × отгружено`; `− переход в AR при приёмке` | CA_кон = доля «после приёмки» × дома «отгружены, не приняты» |
| AR | безусловные вехи и CA после приёмки | лаг «веха → деньги» из факта | Σ поступлений по договору ≤ цена договора |
| Inv/НЗП/ГП | производство (EV-часы, BOM) и отгрузка | `нач + затраты производства − себестоимость отгруженного` | Inv в днях не «улетает» от факта |
| AdvP | условия предоплаты поставщику | `+ предоплаты − зачёт при поставке` | AdvP ≥ 0 |
| AP | поставки × условия оплаты, входящая кредиторка | старение (aging) входящей + лаги новых поставок | AP_кон ≈ поставки последнего лага |
| ЗП и налоги к уплате | начисление ЗП, календарь выплат | календарь (заметки 01) | остаток = начислено − выплачено |
| RCF | дефицит под C_min | раздел 2.5 | 0 ≤ RCF ≤ лимит |
| ОС | капвложения, амортизация | штопор ОС | амортизации в БДДС нет |
| Капитал | прибыль, распределения | штопор нераспределённой прибыли | ΔКапитал = Прибыль − распределения |

Почему «вехи и лаги», а не «дни»: модели на днях (DSO/DIO/DPO) удобны для стабильных бизнесов; при 2–8 домах в месяц
одна веха (приёмка УВБК ООН) меняет DSO в разы. Для 13-недельного прогноза практики строят поступления из старения
дебиторки и счетов по конкретным клиентам, а выплаты — из штопора кредиторки и платёжного календаря ЗП
([WSP: 13-week cash flow](https://www.wallstreetprep.com/knowledge/demystifying-the-13-week-cash-flow-model-in-excel/)).

### 3.3. Алгоритм неснижаемого остатка и финансирования

1. Определить `C_min` политикой: базовый вариант — 1–1,5 месяца **обязательных** оттоков (ЗП, налоги, ЦО), см.
   ориентиры [Financial Rhythm](https://financialrhythm.com/how-to-set-cash-balance-targets/) (блог); проверить
   «днями буфера»: `ликвидность / среднедневной чистый отток` на горизонтах 30/60/90 дн., ликвидность считать
   только из реально доступных денег (без «запертых» и без минимальных операционных остатков)
   ([Umbrex](https://umbrex.com/resources/company-analysis/finance/cash-buffer-days/)).
2. Посчитать деньги до финансирования по месяцам (а для октября — по неделям: прямой метод).
3. Применить правило RCF (2.5); проценты — на остаток на начало месяца.
4. Если лимит исчерпан и `C < C_min` — не «рисовать» деньги, а вывести **алерт** (FAST: проверять отсутствие
   сходимости, например нехватку лимита, — это часто отражает коммерческую реальность)
   ([FAST 1.01-11](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf)) и перейти к
   управленческим мерам: ускорение поступлений, перенос дискреционных оплат, финансирование группы.
5. Стресс: DSO +8–10 дн., DIO +5–7 дн., DPO −5 дн., выручка −10 % ([Umbrex](https://umbrex.com/resources/company-analysis/finance/cash-buffer-days/)).
   Для нас естественный стресс — «приёмка УВБК ООН на 1 месяц позже» (метод 07 уже даёт ±4,7 млн за квартал).

### 3.4. Набор проверок и мастер-проверка (дополнение к 12 проверкам заметок 01)

ICAEW: проверка равенства для каждой пары независимо посчитанных величин; допуск на мелкие расхождения
(округление); выделение цветом; отдельная сводка проверок и **мастер-проверка**, видимая на всех листах; кроме
ошибок модели — «алерты» о бизнес-проблемах (нарушение ковенантов, убытки)
([ICAEW Code, принципы 17–18](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).

Дополнительные проверки, которых нет в заметках 01:

### 3.5. Алгоритм поиска ошибки, если баланс не сходится

1. Посчитать `Активы − (Обязательства + Капитал)` по каждому месяцу и посмотреть на **форму** расхождения:
   постоянное — забыли связь в одном периоде; меняется на одну и ту же величину — ошибка формулы в одном периоде;
   хаотичное — несколько ошибок ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)).
2. Разделить расхождение на 2 и искать движение такого размера: перевёрнутый знак удваивает ошибку
   ([FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).
3. Пройти по каждой изменяющейся строке баланса: она в ДДС ровно один раз, со знаком «актив — вычитаем, пассив —
   прибавляем», не задвоена с соседней строкой; затем — по каждой строке ДДС: нет ли «сирот» без строки баланса
   ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)).
4. Проверить связи «прибыль → капитал» и «конец ДДС → деньги баланса», а также что исторические деньги не
   захардкожены ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/);
   [FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).
5. Тест чувствительности: резко изменить одно допущение — при верных связях расхождение не должно меняться
   ([FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).
6. Если не нашлось — временно упростить баланс до 5–6 строк с каждой стороны
   ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)).
7. **Никогда** не закрывать расхождение «прочими»/«корректировкой»: затычка маскирует причину; если нужен
   балансир — это кредитная линия по правилу ([CFI №8](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models);
   [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).

### 3.6. Прямой ↔ косвенный: как организовать сверку на нашем горизонте

- Октябрь — прямой метод снизу (счета, долги, платёжный календарь, при необходимости по неделям), ноябрь–декабрь —
  драйверы и лаги; затем **косвенный** за весь квартал из БДР и прогнозного баланса; в окне перекрытия они должны
  «рассказывать одну историю» ([Kyriba](https://www.kyriba.com/resources/insights/cash-flow-forecasting-maturity-framework/)).
- Ошибки прямого метода, найденные регулятором у реальных отчётов: нетто-показ движений «одной суммой» без анализа,
  непоследовательная классификация процентов, неденежные операции в ДДС
  ([ICAEW: tips and pitfalls](https://www.icaew.com/-/media/corporate/files/technical/audit-and-assurance/audit-and-assurance-faculty/webcasts/tips-and-common-pitfalls-webinar.ashx)).
  Для нас: транзит «финагент ↔ касса ↔ банк» — это перемещение между видами денег, а не поток; в ДДС проекта такие
  пары не должны давать нетто-эффекта (в IAS 7 движения между составляющими денежных средств не являются
  денежными потоками — п. 9 стандарта, страница стандарта открывалась только в кратком изложении, деталь — по
  памяти стандарта, сверить).
- Овердрафт можно включать в «деньги» только если он — неотъемлемая часть управления денежными средствами;
  иначе это финансирование ([ICAEW: tips and pitfalls](https://www.icaew.com/-/media/corporate/files/technical/audit-and-assurance/audit-and-assurance-faculty/webcasts/tips-and-common-pitfalls-webinar.ashx)).
  Для нас: кредитную линию держать отдельной строкой финансирования, не смешивать с остатком денег.
- Потоки показывать **gross** (поступления и выплаты отдельно), сворачивание — только в узких случаях
  ([BDO IAS 7](https://www.bdo.global/getmedia/45a1e16d-dd6c-4530-9b30-14df8b5b4ca0/IAS-7-AAG.pdf.aspx)).

### 3.7. Правила качества модели (для ИИ-бюджетиста)

- Каждое допущение вводится один раз; повторное использование — ссылкой, а не повтором расчёта
  ([FAST 1.01](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf)).
- Единицы подписаны у каждой величины (грн, тыс. грн, т, дома); масштабирование (месяц → квартал) — отдельным
  шагом от базового расчёта ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).
- Не округлять в промежуточных расчётах; округлять только вывод; **не** делать «балансирующих» расчётов, чтобы
  округлённые списки сходились к цели ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).
  Контрпример из учебника: прогнозный баланс GelSoft закрыт поправкой округления 19 долл. в нераспределённой
  прибыли ([Lumen WM](https://courses.lumenlearning.com/wm-managerialaccounting/chapter/budgeted-balance-sheet/)) —
  в учебнике допустимо, в рабочей модели — нет.
- Тестировать ожидания: изменить вход → сравнить сдвиг выхода с ожидаемым ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx)).
- Одинаковый метод расчёта во всех периодах (не «% в одном месяце, константа в другом»)
  ([CFI №2, №9](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).

## 4. Числовые примеры и бенчмарки

### 4.1. Учебные прогнозные балансы (как «приходят» строки)

- **Leed Company:** деньги 188 000 — из кассового бюджета; дебиторка 400 000 = 40 % продаж IV квартала
  1 000 000; сырьё 60 000 = 30 000 фунтов × 2; ГП 123 000 = 6 000 ед. × 20,50; кредиторка 43 500 = 20 % закупок
  IV квартала 217 500; налог к уплате 142 500 — из БДР, платится в следующем квартале; нераспределённая прибыль
  1 135 000 = 400 000 + 855 000 − 120 000 дивидендов; накопленная амортизация зданий 480 000 = 400 000 + 80 000
  ([Lumen SUNY](https://courses.lumenlearning.com/suny-managacct/chapter/budgeted-financial-statements/)).
- **GelSoft:** дебиторка 629 748 = 40 % × 1 574 370; кредиторка 268 063 = 20 % × 1 340 313 (80 % оплаты в
  квартале закупки, 20 % — в следующем); сырьё 123 200 = 11 200 кг × 11; ГП 364 176 = 16 200 × 22,48; итог
  баланса 3 483 588 ([Lumen WM](https://courses.lumenlearning.com/wm-managerialaccounting/chapter/budgeted-balance-sheet/)).
- Урок: строка баланса = **неоплаченный хвост последнего лага** соответствующего графика. Это и есть быстрый
  способ проверить прогнозный баланс: «AR_кон должен равняться доле последних отгрузок, которая по условиям ещё не
  оплачена».

### 4.2. Сквозной пример: проект модульных домов, IV квартал (наш расчёт, тыс. грн, без НДС)

**Условия (условные, по образцу условий УВБК ООН из метода 07).** Договор: 8 домов × 2 000 = 16 000. Аванс 30 % =
4 800 получен в сентябре. Отгрузки: окт 2, ноя 2, дек 2, янв 2. По каждому дому: при отгрузке 30 % зачитывается
против аванса; 20 % — безусловное право, оплата в месяце `t+1`; 50 % — после приёмки (приёмка в `t+1`, оплата в
`t+2`). Выручка — по отгрузке (управленческая политика). Себестоимость дома 1 300 = материалы 1 000 + труд 300;
дом производится в месяце `t−1`; материалы поставляются в месяце производства; поставщик: 50 % предоплата за
2 месяца до поставки, 50 % — в месяце после поставки; труд оплачивается в месяце производства. Деньги на 30.09 —
1 500; `C_min` = 1 000; кредитная линия 18 % годовых (1,5 % в месяц), проценты на остаток на начало месяца.

**Входящий баланс 30.09:** AdvP 2 000 (предоплата под октябрьскую и ноябрьскую поставки), Inv 2 600 (2 дома
сентябрьского производства), C 1 500 → активы 6 100; AdvR 4 800, AP 1 000 (50 % сентябрьской поставки) →
обязательства 5 800; капитал (результат проекта) = 6 100 − 5 800 = **300** (выводится, а не вводится).

**Клиентские штопоры:**

| | Окт | Ноя | Дек | Квартал |
|---|---|---|---|---|
| Выручка (отгрузка × 2 000) | 4 000 | 4 000 | 4 000 | 12 000 |
| AdvR: нач / зачёт / кон | 4 800 / −1 200 / 3 600 | 3 600 / −1 200 / 2 400 | 2 400 / −1 200 / **1 200** | −3 600 |
| CA: нач / +50 % отгрузки / → AR / кон | 0 / +2 000 / 0 / 2 000 | 2 000 / +2 000 / −2 000 / 2 000 | 2 000 / +2 000 / −2 000 / **2 000** | +2 000 |
| AR: нач / +20 % / +из CA / −оплата / кон | 0 / +800 / 0 / 0 / 800 | 800 / +800 / +2 000 / −800 / 2 800 | 2 800 / +800 / +2 000 / −2 800 / **2 800** | +2 800 |
| **Поступления** | **0** | **800** | **2 800** | **3 600** |

Контроль: `12 000 = 3 600 (зачёт аванса) + 2 400 (в AR при отгрузке) + 6 000 (в CA)`;
косвенно: `12 000 − ΔAR 2 800 − ΔCA 2 000 + ΔAdvR (−3 600) = 3 600` ✔. Конечные остатки «объяснимы»: AdvR 1 200 =
30 % январских домов; CA 2 000 = 50 % декабрьских (не приняты); AR 2 800 = 20 % декабрьских + 50 % ноябрьских
(приняты в декабре, оплата в январе).
Наивные модели: «100 % в месяц отгрузки» — 12 000 (завышение в 3,3 раза); «70 % в месяц отгрузки (аванс уже
пришёл)» — 8 400 (завышение на 4 800).

**Поставщики, запасы, труд:**

| | Окт | Ноя | Дек | Квартал |
|---|---|---|---|---|
| Поставка материалов | 2 000 | 2 000 | 2 000 | 6 000 |
| AdvP: нач / +предоплата / −зачёт / кон | 2 000 / +1 000 / −1 000 / 2 000 | 2 000 / 0 / −1 000 / 1 000 | 1 000 / 0 / −1 000 / **0** | −2 000 |
| AP: нач / +поставка − зачёт / −оплата / кон | 1 000 / +1 000 / −1 000 / 1 000 | 1 000 / +1 000 / −1 000 / 1 000 | 1 000 / +1 000 / −1 000 / **1 000** | 0 |
| Оплаты материалов | 2 000 | 1 000 | 1 000 | 4 000 |
| Труд (оплата = начисление) | 600 | 600 | 600 | 1 800 |
| Inv: нач / +производство / −себест. / кон | 2 600 / +2 600 / −2 600 / 2 600 | 2 600 / +2 600 / −2 600 / 2 600 | 2 600 / +2 600 / −2 600 / **2 600** | 0 |

**Прибыль vs деньги:** прибыль = 12 000 − 7 800 = **+4 200**; операционный поток прямо = 3 600 − 4 000 − 1 800 =
**−2 200** (окт −2 600; ноя −800; дек +1 200). Косвенно: `4 200 − 2 800 (ΔAR) − 2 000 (ΔCA) − 3 600 (ΔAdvR) −
0 (ΔInv) + 2 000 (−ΔAdvP) + 0 (ΔAP) = −2 200` ✔. Прибыльный квартал «съедает» 2,2 млн, потому что (а) аванс
4,8 млн уже пришёл в сентябре и теперь только зачитывается, (б) 50 % цены «заперты» в CA до приёмки.

**Финансирование (правило 2.5, проценты на остаток на начало):**

| | Окт | Ноя | Дек |
|---|---|---|---|
| Деньги на начало | 1 500,00 | 1 000,00 | 1 000,00 |
| Операционный поток | −2 600,00 | −800,00 | +1 200,00 |
| Проценты (1,5 % × RCF на начало) | 0,00 | −31,50 | −43,97 |
| Деньги до финансирования | −1 100,00 | 168,50 | 2 156,03 |
| Излишек/дефицит к `C_min` 1 000 | −2 100,00 | −831,50 | +1 156,03 |
| Выборка (+) / погашение (−) RCF | +2 100,00 | +831,50 | −1 156,03 |
| RCF на конец | 2 100,00 | 2 931,50 | 1 775,47 |
| Деньги на конец | 1 000,00 | 1 000,00 | 1 000,00 |

**Прогнозный баланс 31.12:** активы = C 1 000 + AR 2 800 + CA 2 000 + AdvP 0 + Inv 2 600 = **8 400**;
обязательства = AdvR 1 200 + AP 1 000 + RCF 1 775,47 = 3 975,47; капитал = 300 + 4 200 − 75,47 = 4 424,53;
итого **8 400,00** ✔. Деньги: `1 500 − 2 200 − 75,47 + 1 775,47 = 1 000` ✔.

**Проценты на средний остаток (формула 2.6, `N` < 0 при погашении):** октябрь `0,015 × (0 + 1 100)/1,985 = 8,31`;
ноябрь `0,015 × (2·2 100 + 800)/1,985 = 37,78` (проверка: выборка 837,78, RCF кон 2 937,78, средний 2 518,89 ×
1,5 % = 37,78 ✔); декабрь (излишек 1 200 до процентов, `N = −1 200`) `0,015 × (2·2 931,5 − 1 200)/1,985 ≈ 35,24`.
Против 0 / 31,50 / 43,97 при «остатке на начало»: +8,3 / +6,3 / −8,7 — в сумме за квартал ≈ 6 тыс. (приблизительно:
открывающие остатки взяты из варианта «на начало»), т.е. упрощение несущественно для решения, а модель остаётся
без цикла.

**Диагностика ошибки знака.** Если в косвенном методе взять ΔAdvP со знаком «как у актива, но наоборот»
(−2 000 вместо +2 000), косвенный поток станет −6 200, баланс «разъедется» на 4 000; 4 000 / 2 = 2 000 =
|ΔAdvP| — ошибка найдена правилом «пополам» ([FMWC](https://fmworldcup.com/my-3-way-financial-model-doesnt-balance-whats-wrong/)).

**Хвост за горизонтом.** Если бы договор продолжался (дома в феврале–марте), предоплаты поставщику 50 % «за 2
месяца» легли бы в ноябрь и декабрь (+1 000 и +1 000) — без плана производства на январь–февраль эти 2 млн оттока
квартала просто не появились бы, и AdvP_кон = 0 выглядел бы «правдоподобно».

**Подразумеваемые дни (проверка 17):** `(AR + CA)/Выручка × 92 = 4 800/12 000 × 92 ≈ 37 дн.`; за вычетом
авансов `(4 800 − 1 200)/12 000 × 92 ≈ 28 дн.` — ниже отраслевого DSO строительства 58,6 дн.
([McGrathNicol](https://www.mcgrathnicol.com/working-capital-report-2024/construction-engineering/)), что
объяснимо крупным авансом; если бы модель дала, скажем, 5 дней — это сигнал «нарисованных» поступлений.

## 5. Ошибки и ловушки (новые относительно заметок 01)

1. **«Деньги — затычка баланса».** Деньги как разница активов и пассивов скрывают любую ошибку штопоров. Деньги
   считаются из ДДС, баланс проверяется ([CFI](https://corporatefinanceinstitute.com/resources/financial-modeling/3-statement-model/);
   [BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)).
2. **«Прочие» как балансир** — CFI №8: заменить на кредитную линию и найти причину
   ([CFI](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).
3. **Двойной учёт изменения оборотного капитала:** одна и та же Δ одновременно в «изменении оборотного капитала»
   и отдельной строкой ([BIWS](https://breakingintowallstreet.com/kb/3-statement-models/balance-sheet-not-balancing/)).
   У нас: «погашение долгов поставщикам» отдельной строкой И внутри «остатка к оплате по норме» (метод 07 это
   уже учитывает: кредиторка внутри остатка, не сверху — правило надо сохранять).
4. **Ссылка на начальный остаток вместо конечного** для накопительных статей (капитал, RCF)
   ([CFI №10](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).
5. **Захардкоженные плановые значения** — только факт/входящие остатки могут быть константами
   ([CFI №9](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models)).
   У нас «Вручную» (кредитная линия, НДС, премии из 00008) — допустимо, только если каждая сумма в реестре с
   источником и попадает в штопор соответствующей статьи (иначе ББЛ не сойдётся).
6. **Смешение CA и AR.** Если «50 % после приёмки» положить в AR с «обычным» сроком, деньги придут на 1–2 месяца
   раньше; если «20 % после поставки» держать как CA — позже. Право безусловно или нет — решает договор
   ([CPDbox](https://www.cpdbox.com/036-contract-asset-vs-account-receivable/)).
7. **Аванс как источник денег в горизонте.** Аванс, полученный до начала горизонта, в горизонте даёт только
   зачёт (контракт-обязательство уменьшается), но не деньги ([IFRS 15 IE](https://www.ifrs.org/content/dam/ifrs/publications/html-standards/english/2024/issued/ifrs15-ie.html);
   [WSP](https://www.wallstreetprep.com/knowledge/deferred-revenue/)).
8. **Неденежные операции в ДДС** (взаимозачёты, бартер, реструктуризация долга как «оплата»)
   ([ICAEW pitfalls](https://www.icaew.com/-/media/corporate/files/technical/audit-and-assurance/audit-and-assurance-faculty/webcasts/tips-and-common-pitfalls-webinar.ashx)).
   У нас: взаимозачёты внутригрупповых МК-расчётов — в штопорах AR/AP есть, в БДДС их быть не должно.
9. **Нетто-показ «одной суммой» без анализа движения** (из баланса на начало и конец)
   ([ICAEW pitfalls](https://www.icaew.com/-/media/corporate/files/technical/audit-and-assurance/audit-and-assurance-faculty/webcasts/tips-and-common-pitfalls-webinar.ashx)).
   Косвенный метод даёт верный итог, но не показывает, кто и когда заплатит — для управления недостаточно.
10. **Намеренная цикличность** (итерации Excel) — ошибки становятся невидимыми, предупреждения отключены
    ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel/financial-modelling-code.ashx);
    [Simplex](https://simplexct.com/avoid-circularity-in-financial-models)).
11. **Кредитная линия без лимита** — модель «находит» деньги в любом объёме. Нужны лимит, база заимствования и
    алерт об исчерпании ([WSP: revolver](https://www.wallstreetprep.com/knowledge/modeling-revolving-credit-line-excel-free-template/);
    [FAST 1.01-11](http://www.fast-standard.org/wp-content/uploads/2015/03/FASTStandard_02a.pdf)).
12. **Дни оборачиваемости на «рваных» проектах.** DSO, подобранный по году, размазывает крупную веху по месяцам
    и прячет кассовый провал месяца — использовать только как проверку итога (наш вывод, согласуется с заметками 01).
13. **Неоднородность метода по периодам** (октябрь снизу, ноябрь–декабрь драйверами — это нормально, но тогда
    сверка прямого и косвенного в октябре обязательна, иначе стык методов создаёт «ступеньку»)
    ([CFI №2](https://corporatefinanceinstitute.com/resources/financial-modeling/common-causes-imbalanced-3-statement-models);
    [Kyriba](https://www.kyriba.com/resources/insights/cash-flow-forecasting-maturity-framework/)).
14. **Прибыль в «плюсе» как аргумент «денег хватит».** Пример 4.2: прибыль +4,2 млн, поток −2,2 млн — разрыв
    объясняется ростом CA/AR и зачётом ранее полученного аванса (то же у реального октября −10,7 млн в методе 07).

## 6. Что применимо к нам и как

**6.1. Перевести «метод 07» из «прямого БДДС с ограничителями» в полноценную трёхсвязную модель проекта.**
Сейчас ограничители мини-баланса есть (поступления ≤ остатка договора, погашение ≤ кредиторки), но нет явных
штопоров. Минимальный набор штопоров на проект × месяц: AdvR, CA, AR, AdvP, AP, Inv/НЗП, ЗП к выплате, налоги к
уплате; на компанию — C, RCF, капитал. Источники входящих остатков на 30.09.2026:

| Строка | Где взять | Комментарий |
|---|---|---|
| AR, AdvR | `РасчетыСКлиентамиПоСрокам` (`ДолгРегл`, `ПредоплатаРегл`) | по проекту/договору; новая архитектура взаиморасчётов (CLAUDE.md) |
| CA (отгружено, не принято) | документы отгрузки vs акты приёмки по проекту; для «по факту освоения» — ВРМ/EV-часы | управленческий признак, в регистрах расчётов его может не быть — нужно правило |
| AP, AdvP | `РасчетыСПоставщикамиПоСрокам` | «Долги Коррект» метода 07 — частный случай AP |
| Inv/НЗП | `ТоварыОрганизаций`, `СебестоимостьТоваров` + освоенные часы ВРМ | материалы на объектах — отдельная подстрока |
| C | остатки банк/касса + `А_ДвиженияДенегИзКазны` (факт по проекту) | транзит ФА — не поток |
| RCF | договор кредитной линии ЦО | в методе 07 суммы «Вручную» (−838 000 окт, −4 711 809 дек) |

**6.2. Правило признания и разметка вех УВБК ООН / IRC в терминах IFRS 15.**
УВБК ООН: аванс 30 % → AdvR; 20 % «после поставки» → AR при отгрузке (если право безусловно) с лагом из факта
(ООН Админ №1: 12 дней); 50 % «после приёмки» → CA до акта приёмки, затем AR с лагом ~30 дней. IRC «100 % через
15–43 дня» → AR при отгрузке. МК (тонны) → AR при отгрузке, лаг +1 мес.; аванс Каменца 50,41 % → AdvR с
зачётом по тоннам. Эта разметка делает автоматическими проверки 14–15 и сразу показывает, сколько денег «заперто»
в CA на конец каждого месяца.

**6.3. Кредитная линия и неснижаемый остаток — как правило, а не ручные суммы.**
Задать `C_min` (предложение для обсуждения: 1–1,5 месяца обязательных оттоков ЗП + налоги + ЦО по факту 07–09;
проверить «днями буфера» на 30/60 дн.), лимит линии, ставку; выборка/погашение — по формулам 2.5, проценты — на
остаток на начало месяца. Тогда октябрьский провал −10,7 млн (метод 07) превратится в явную «потребность в
финансировании» с алертом «лимит исчерпан / источник не найден», а не в отрицательный остаток или ручную строку.

**6.4. Прямой ↔ косвенный по каждому проекту.** К расчётчику добавить косвенный ДДС: прибыль проекта (по событию
признания) ± Δ штопоров. Сверка должна дать 0 по проекту и кварталу; расхождение = пропущенная статья (типично:
транзит ФА, «Вручную» без штопора, налоги без начисления).

**6.5. Октябрь — прямой метод по неделям (13-недельная логика), ноябрь–декабрь — драйверы.**
Октябрь собрать из старения AR/AP и платёжного календаря ЗП ([WSP 13-week](https://www.wallstreetprep.com/knowledge/demystifying-the-13-week-cash-flow-model-in-excel/));
затем сравнить с драйверной версией октября — разница показывает качество лагов. Точность вести по статьям (MAPE
план-факт по статье ДДС) ([Kyriba](https://www.kyriba.com/resources/insights/cash-flow-forecasting-maturity-framework/)).

**6.6. Конвенции для Python-калькулятора** (FAST/ICAEW): в расчётах все потоки положительные с говорящими
именами (`поступило`, `оплачено`, `зачтено`); знак — только при выводе в БДДС; входящие остатки и допущения — в
одном месте; мастер-проверка с допуском 0,01 грн; никаких «балансирующих» строк; нет итераций — проценты на
остаток на начало либо по закрытой формуле.

**6.7. Сценарий «хвост».** План отгрузок и производства на январь–февраль 2027 обязателен для оттоков
ноября–декабря (предоплаты материалов) и для AdvR/CA/AR на 31.12 — уже видно в методе 07 (за горизонтом
поступления IRC 1,46 млн, ООН Админ 3,16 млн, ООН 2026 6,94 млн — это и есть AR+CA на 31.12).
