## 1. Зачем это бюджетисту

Кредиторка (КЗ) — выплаты, уже предопределённые прошлыми поставками и договорами; вместе с ЗП и налогами это бо́льшая часть бюджета выплат. Ошибки здесь пяти типов. **Двойной счёт**: стартовую КЗ ставят строкой «погасить долги» поверх «остатка к оплате», хотя она внутри него; предоплату прошлого месяца снова ставят как «30 % при заказе». **Тайминг**: вся стартовая КЗ — в первый месяц; выплаты по дате счёта вместо срока оплаты; или «хоккейная клюшка» — всё непомещающееся молча уезжает в последний месяц. **Иллюзия бесплатного финансирования**: растягивание без договорённости. В Украине юридическая цена просрочки — до ~45 % годовых (пеня до двойной учётной ставки НБУ + 3 % + инфляционные), а поставщик в ответ поднимает цену или требует предоплату. **Пропуски**: начисленное без счёта (кран, транспорт прошлого месяца), ЗП и налоги «средним» вместо известных сумм. **Несверенный источник**: расчёты в ERP и в казначейском учёте расходятся (у нас 8,88 против 4,25 млн на 01.10.2026, §8.2).

Для «Індастріалбуда» ставка высокая. Метод 07 показывает операционный провал октября **−9,87 млн грн** (v2 сценария 00009): материалы под дома ООН 2026 / ООН Админ / IRC 8,9 млн, ЗП производственного персонала 3,6 млн с задолженностью за выполненное (вся ЗП с налогами и комиссией ФА — 4,77 млн, §4.6), долги поставщикам вне остатка материалов 1,77 млн — всё в октябре. Модуль превращает одно число в управленческие: **сколько нужно внешнего финансирования** на неотложные выплаты, **о чём и на сколько договориться с поставщиками** по уже возникшей КЗ (с ценой каждой отсрочки в гривнах в месяц) и **что решает группа** (внутригрупповые выплаты). Будущие закупки под ближайшие отгрузки — не «переговорная кредиторка»: долга по ним нет, их перенос — это сдвиг отгрузок.

## 3. Формулы и алгоритмы

### 3.1. Слои обязательства и «остаток к оплате»

| Слой | Что это | Источник | Месяц выплаты в бюджете |
|---|---|---|---|
| L0 начислено | услуга оказана, первички нет | акты, путевые листы | ожидаемый счёт + срок договора |
| L1 КЗ | поставлено, не оплачено | расчёты с поставщиками, книга долгов | **срок оплаты** + проскальзывание; просроченное — первый месяц или по подписанному графику |
| L2 заказ | заказ есть, поставки нет | заказы, график оплат договора | предоплата — в дату заказа; остаток — поставка + отсрочка − выданный аванс |
| L3 не заказано | потребность по норме | норма × план домов | ядро относительно отгрузки (у нас — за 1 месяц до отгрузки) |
| A аванс выданный | деньги ушли | расчёты (предоплата) | **0 денег** при поставке; зачитывается против L1 |

Связь со «остатком к оплате» по материалам проекта p:

```
Остаток_p = Норма_p × K − Оплачено_p                 # K = 1,00 (калибровка 06)
Остаток_p = L1_p + (L2_p − A_p) + L3_p               # тот же остаток по слоям
Оплачено_p + L1_p − A_p = Поставлено_p               # тождество за весь срок проекта
```

Метод «норма − оплачено» верен по **сумме**, но схлопывает слои; тайминг точнее по слоям. КЗ по материалам, входящим в норму, — **внутри** остатка. КЗ по тому, что в норму не входит (транспорт, автокран, МШП, услуги, закрытые проекты, ЦО), — **вне** остатка, отдельной строкой.

### 3.2. Roll-forward КЗ и авансов выданных

На месяц по договору (группе «поставщик × проект»): `D` — поставки с НДС, `Pre` — предоплаты, `Off` — зачёт аванса, `Pay` — оплата долга, `Corr` — возвраты и взаимозачёты.

```
Аванс_кон = Аванс_нач + Pre − Off,      Off = min(Аванс_нач + Pre, D)
КЗ_кон    = КЗ_нач + D − Off − Pay ± Corr
Выплаты   = Pre + Pay = D − ΔКЗ + ΔАванс        # тождество (при Corr = 0)
```

Зачёт — **по договору или поставщику**, не по компании: иначе аванс одного поставщика «гасит» долг другому. Рост КЗ — приток в операционном потоке, рост аванса — отток раньше поставки.

```python
def ap_rollforward(ap0, adv0, deliveries, prepay, pay_wanted):
    """Помесячно по договору/группе. Возвращает выплаты и остатки, проверяет тождество."""
    ap, adv, rows = ap0, adv0, []
    for d, pre, want in zip(deliveries, prepay, pay_wanted):
        ap_prev, adv_prev = ap, adv
        adv += pre
        off = min(adv, d); adv -= off        # поставка гасит аванс — денег нет
        ap += d - off
        pay = min(want, ap); ap -= pay       # нельзя заплатить больше долга
        cash = pre + pay
        assert abs(cash - (d - (ap - ap_prev) + (adv - adv_prev))) < 0.01
        rows.append(dict(предоплата=pre, зачёт=off, оплата_долга=pay, выплаты=cash,
                         КЗ_кон=ap, аванс_кон=adv, перенос=want - pay))
    return rows
```

`перенос` не исчезает: это КЗ следующего периода со статусом «согласовано / переговоры / одностороннее» (3.8).

### 3.3. Стартовый снимок кредиторки

Для каждой строки остатка расчётов с поставщиками на дату среза (у нас — начало 01.10.2026):

1. **Знак**: долг и предоплата — раздельно, без сальдирования по контрагенту (иначе прячутся висящие авансы и просрочка).
2. **Слой**: L0, L1 или L2.
3. **Внутри / вне остатка проекта**: позиция входит в норму домов проекта → внутри (не прибавлять); иначе → отдельная строка.
4. **Срок оплаты** из договора или книги долгов → корзина старения; спорные — отдельно.
5. **Tier** (T0–T4, 3.8), **природа** — (а) существующая КЗ L0/L1 или (б) будущая закупка L2/L3 — и **цена задержки** в % в месяц (3.6, 3.8).
6. **Природа контрагента**: внешний / внутригрупповой / связанное лицо.

Проверки: Σ строк = сальдо источника до копейки; по проекту `Оплачено + КЗ − Аванс = Поставлено`. Не сходится — деньги ушли на склад или в другие проекты, либо не все поставки оформлены (L0).

### 3.4. Прогноз выплат по слоям

```
Выплаты[m] = Σ_L1 сумма_i · 1[срок_i + проскальзывание_i ∈ m]
           + Σ_L2 ( Pre_j · 1[заказ_j ∈ m] + (Сумма_j − A_j − Pre_j) · 1[поставка_j + отсрочка_j ∈ m] )
           + Σ_L3 Остаток_L3,p · Ядро_p(m)  +  Σ_L0 начислено_k · 1[счёт_k + срок_k ∈ m]  +  Регулярные[m]
```

- Дата — **срок оплаты**, не дата документа. **Проскальзывание** поставщика = медиана (оплата − срок) по закрытым счетам за 6–12 месяцев: календарь строится по реальным датам.
- Точность падает с горизонтом: недели 1–2 — запланированные платежи, 2–5 — утверждённые счета, 5–13 — конверсия заказов; целевая точность ~5 % на 1–2 недели, 10–15 % на 3–6, 15–25 % дальше.
- L2 + L3 проекта ≤ его остатка к оплате. Детализация — по существенности (строка в 20 % потока нужна, в 2 % — нет).

```python
def payments_by_layer(L1, L2, L3, L0, months):
    """L1: [(сумма, мес)], L2: [(сумма, аванс_выдан, предоплата, мес_заказа, мес_остатка)],
       L3: [(остаток, {мес: доля})], L0: [(сумма, мес)]. Месяцы — строки 'YYYY-MM'."""
    out = {m: 0.0 for m in months}; out['за горизонтом'] = 0.0
    first, last = months[0], months[-1]
    def put(m, x):
        k = first if m < first else ('за горизонтом' if m > last else m)   # прошлое -> первый месяц
        out[k] += x
    for s, m in L1: put(m, s)
    for s, a, pre, m_ord, m_rest in L2:
        put(m_ord, pre); put(m_rest, s - a - pre)
    for rest, kernel in L3:
        assert abs(sum(kernel.values()) - 1) < 1e-9
        for m, w in kernel.items(): put(m, rest * w)
    for s, m in L0: put(m, s)
    return out
```

### 3.5. DPO и countback-DPO

```
DPO = Средняя КЗ / База × Дней;   Оборачиваемость = Закупки в кредит / Средняя КЗ
КЗ_прогноз = DPO / 365 × База_год                    # только для годовой модели
```

Пример CFI: КЗ 800 тыс., себестоимость 8,5 млн → 34,35 дня. В проектном производстве база — **закупки**: материалы под будущие дома куплены, а себестоимость появится при отгрузке, и DPO через себестоимость завышен. При малом числе крупных счетов средний DPO скачет — нужны старение и countback. Месячный бюджет строится от сроков; DPO — контроль на конец горизонта.

```python
def countback_dpo(ap_end, purchases, days):
    """purchases, days — [текущий месяц, предыдущий, ...]."""
    rest, dpo = ap_end, 0.0
    for p, d in zip(purchases, days):
        if p <= 0: dpo += d; continue
        if rest <= p: return dpo + d * rest / p
        rest -= p; dpo += d
    return dpo    # КЗ старше окна — сигнал просрочки или спора
```

Ориентиры: DPO крупнейших компаний США — 59 дней, Европы — 72,6 (Hackett 2025) — это сила гигантов, не цель. В ЕС B2B-срок по умолчанию 30 дней, свыше 60 — только при явном согласии (Директива 2011/7/EU). В Украине без срока в договоре — 7 дней с момента требования (ст. 530 ЦК). Главный ориентир — собственный фактический DPO по группам поставщиков.

### 3.6. Цена торгового кредита и цена просрочки

**Скидка** `d` за оплату на `Δt` дней раньше; **наценка** `μ` за отсрочку на `Δt` дней:

```
r_скидки = d / (1 − d) × 365 / Δt          r_eff = (1 + d/(1 − d))^(365/Δt) − 1
d*       = (r_денег·Δt/365) / (1 + r_денег·Δt/365)      # безубыточная скидка
r_наценки = μ × 365 / Δt                                # платим P(1+μ) позже вместо P сейчас
```

Решение: (1) посчитать годовую ставку предложения; (2) сравнить со **стоимостью денег** — ставкой кредита, если платёж придётся финансировать, доходностью свободных денег, если они есть, или ценой альтернативы (пеня, срыв отгрузки), если нет ни того, ни другого; (3) брать скидку, если `r > r_денег` **и** ни один день 13-недельного окна не пробивает неснижаемый остаток; (4) для предоплаты добавить премию за риск аванса; (5) отсрочку за наценку принимать, только если `r_наценки < r_денег`. Обычно проигрывает: по BCG поставщики закладывают +5–8 % к цене за +15–30 дней сверх нормы — это 60–195 % годовых.

**Просрочка** (компоненты взыскиваются одновременно):

```
Пеня         = Долг × ставка_пени × Дней / 365       # ставка ≤ 2 × учётная ставка НБУ периода
3 % годовых  = Долг × 0,03 × Дней / 365               # ст. 625 ЦК
Инфляционные = Долг × (Π ИПЦ_мес − 1)                 # полные месяцы просрочки
r_late ≈ ставка_пени + 3 % + π                        # годовых, верхняя граница
```

- Пеня по договору ≤ 2 × учётной ставки НБУ (Закон 543/96-ВР). После отмены Хозяйственного кодекса (утратил силу 28.08.2025, Закон 4196-IX) ст. 549 ЦК дополнена: должник **по требованию кредитора** платит пеню в размере двойной учётной ставки НБУ, договор может установить **меньший** размер. Пеня может следовать из закона, а не только из договора; аналога прежнего 6-месячного ограничения в тексте не найдено. Применимость к договорам до 28.08.2025 — проверить у юриста; в бюджете — худший случай.
- 3 % и инфляционные — не санкция: вина и убытки не доказываются, невозможность платить не освобождает, суд их не уменьшает (неустойку — может).
- Учётная ставка НБУ — **16,0 % с 18.09.2026** (15,5 % с 31.07.2026). Пеня до 32 %; с инфляцией ~10 % в год (~0,8 % в месяц) верхняя граница **~45 % годовых ≈ 3,7 % в месяц**; без пени ≈ 13 % годовых ≈ 1,07 % в месяц.
- Давность — 3 года, по неустойке — 1 год; течение давности, приостановленное с 02.04.2020 (карантин, затем военное положение), возобновлено Законом 4434-IX с 04.09.2025. По долгам, возникшим **до** 02.04.2020, засчитывается уже истёкшая часть срока, течёт остаток. По долгам, возникшим **во время приостановления** (02.04.2020–03.09.2025), трёхлетний срок начинается заново с 04.09.2025 и истекает не раньше 04.09.2028. Поэтому почти вся «старая» КЗ 2020–2025 годов остаётся востребуемой ещё минимум до осени 2028. В горизонте её не платить без требования кредитора, но и не «забывать» и не списывать как безнадёжную.
- Налоги (подробно M09): штраф 5 % при задержке до 30 дней, 10 % — свыше (ст. 126 ПКУ, по Головбуху); пеня по задекларированным суммам — с 91-го дня, 100 % учётной ставки НБУ годовых, по доначисленным — 120 % (ст. 129 ПКУ).
- ЗП: задержка ≥ 1 месяца — компенсация нетто × (индекс инфляции − 1) (Закон 2050-III); штраф 3 минимальные ЗП (ст. 265 КЗпП); при увольнении — средний заработок за день задержки, не более 6 месяцев (ст. 117). В военное положение освобождение от ответственности — только при доказанной связи с боевыми действиями (Закон 2136-IX); обязанность выплатить остаётся.

### 3.7. ЗП и налоги — кредиторка с юридическим календарём

| Обязательство | Срок денег | Источник |
|---|---|---|
| ЗП, первая половина месяца | не реже 2 раз в месяц, интервал ≤ 16 дней (пары дат 1/16, 5/20, 7/22) | ст. 115 КЗпП |
| ЗП, вторая половина | не позже 7 дней после окончания периода | там же |
| НДФЛ 18 % + ВС 5 % | одновременно с выплатой через банк; наличными — 3 банковских дня; начислено и не выплачено — ≤ 30 дней после месяца | ПКУ ст. 168, ДПС |
| ЕСВ 22 % | одновременно с выплатой ЗП, не позднее 20 числа следующего месяца | Закон 2464-VI ст. 9 |
| НДС | декларация — 20 дней после месяца, оплата — ещё 10 дней | ПКУ ст. 49, 57 |

Алгоритм: (1) стартовые суммы — **из регистров**: ЗП второй половины сентября, ЕСВ за сентябрь (до 20.10), НДС за сентябрь (до ~30.10) — октябрьские выплаты известной суммы; (2) будущие начисления — драйвером (часы × ставка, норма × дома) по ядру месяца работы; (3) нетто, НДФЛ+ВС, ЕСВ — разными строками и датами; задержка ЗП почти не экономит денег на налогах; (4) задолженность по ЗП на дату бюджета — в первый месяц, если нет согласованного графика; (5) наличная ЗП через финагента (Ф2) — по фактическому ядру «Казны». Её задержка ведёт к уходу людей и падению темпа цеха (EV-часы), а значит — к сдвигу отгрузок и поступлений. Поэтому Ф2 цеха — тоже T0.

**Механика денег Ф2 (метод 07, раздел 3).** С банковских счетов компании уходит **безналичная оплата финагенту**, а не «наличные»:

```
Ф2_деньги = Нал_выплаты × (1 + 14,12 % комиссия ФА + 1,58 % банк)    # ставки — факт 01–09.2026 без внутренних оборотов (v2; в v1 8,33 % / 0,93 %)
```

- **Пара ФА** — внутренний оборот: «поступление от ФА (нал)» = «оплата ФА (безнал)», статьи УТ-001082 / УТ-001096, нетто 0. В лимит, в tiers и в операционный поток она **не входит** (как в разделе 5 метода 07 — «без пары ФА»). Иначе возникает двойной счёт: поступление от ФА ложно увеличит лимит, а нал-выплата и безнал-оплата ФА обе попадут в выплаты.
- В T0 заявкой стоит одна сумма на каждую гривну Ф2: нал-выплата (она представляет безнал-оплату ФА) плюс комиссия ФА (УТ-001097) и банк (УТ-001063). Задержка Ф2 сдвигает и комиссию с банком.
- Комиссия начисляется на **все** наличные расходы проекта-месяца, а не только на ЗП. Например, у ЦО в базе комиссии есть и аренда квартиры, и коммунальные наличными. Поэтому комиссию и банк разносят пропорционально наличным: к Ф2 (T0) — доля ЗП, к прочим наличным — их доля (пример — 4.6).
- **НДФЛ+ВС и ЕСВ по Ф2 не начисляются.** Налоговый календарь и инвариант K14 применяются только к официальной (банковской) ЗП.

### 3.8. Лимит, очередность, цена задержки

```
Лимит[w] = Остаток_нач[w] + Поступления_подтверждённые[w] − Неснижаемый − Обслуживание_долга[w]
           − Резерв(ЗП и налоги следующих 2 недель)             # для недельного прогона
Обслуживание_долга[w] = погашение + проценты − подтверждённые новые транши
```

- **Подтверждённые поступления** — только те, событие которых уже произошло: дом отгружен, тонны отгружены, дебиторка числится в учёте. Поступления от событий горизонта (отгрузки текущего месяца, приёмки, авансы новых договоров) в лимит не входят. Их показывают отдельной строкой риска: «если придут в срок, потребность в финансировании меньше на X».
- **Обслуживание долга — только в формуле лимита.** Заявкой в реестре и строкой tier оно не стоит, иначе резерв и выплата задвоятся (инвариант K16). Пара финагента в лимит не входит ни поступлением, ни выплатой (3.7).

Заявки входят в реестр по приоритету, пока не исчерпан лимит; остаток реестра **переносится с пометкой** — это переходящая КЗ. Неделя ниже «пола» ликвидности требует задокументированного решения: транш, перенос КЗ, перенос капзатрат. Источники (FM magazine AICPA/CIMA, IBS, «Моё дело», FD Capital, Stampli) сходятся в порядке «ЗП → налоги → критичные поставщики → прочие → дискреционные»:

| Tier | Что | Правило |
|---|---|---|
| T0 | ЗП: официальная (нетто, НДФЛ+ВС, ЕСВ) и Ф2 цеха = безнал-оплата ФА с комиссией и банком (без пары ФА, 3.7); налоги с жёсткой датой; исполнительные документы | не урезается; нехватка = внешнее финансирование |
| T1 | материалы и услуги под дома с отгрузкой в этом и следующем месяце (tier — по месяцу отгрузки из драйвера); логистика, техника, проживание отгрузок месяца; критичные поставщики | платить; частично — только если поставщик продолжит отгрузки |
| T2 | аренда, коммунальные, охрана, связь, страхование, регулярные расходы ЦО | по сроку; короткий перенос — по договорённости |
| T3 | (а) существующая КЗ (L0/L1) некритичным, просрочка; (б) закупки и предоплаты (L2/L3) под отгрузки через 2+ месяца, «впрок» | (а) переговоры: график, частичная оплата, письменно; (б) не заказывать раньше срока |
| T4 | (а) внутригрупповая КЗ; дискреционные; (б) предоплаты под отдалённые поставки | заморозить до решения казначейства / группы |
| Г | внутригрупповые выплаты без КЗ и без контрагента (в v1 сценария 00009 так стояли наличные ЦО «внутригрупповые» ~1 млн/мес — оказались дублем ЗП Ф2, урок в 4.6; в v2 строк Г нет) | отдельная строка «решение группы» (M10): не КЗ и не переговоры с поставщиком |

**Tier материалам проекта назначается по месяцу отгрузки дома из драйвера**, а не экспертно. Дом отгружается в этом или следующем месяце → T1, через 2+ месяца → T3 (б), за горизонтом → T4 (б). По правилу метода 07 материалы платятся за 1 месяц до отгрузки, поэтому в бюджете месяца m оказываются только дома с отгрузкой в m (догоняющая оплата) и m+1, то есть T1. Строки «впрок» и «под январь» в октябрьском бюджете по методу 07 появиться не могут: материалы домов января попадают в декабрь.

**Тест критичного поставщика** (практика critical vendor): нет замены даже дороже; без оплаты старого долга не будет поставок; ущерб от остановки несоразмерен платежу; альтернативы нет. Для нас: «без него не уйдёт дом ООН/IRC в этом или следующем месяце».

Внутри tier — по **цене задержки** на 1 грн в месяц. Формула зависит от природы:

```
(а) КЗ L0/L1:                 c_i = r_late_i × 30/365 + P_stop_i × Loss_i / A_i
(б) будущая закупка L2/L3:    c_i = g_i × 30/365     + P_stop_i × Loss_i / A_i      # r_late = 0: долга нет
(г) решение группы:           c_i = 0 в консолидации (M10)
# g — годовой рост цены поставщика; P_stop — вероятность остановки поставок (экспертно);
# Loss — потеря от сдвига отгрузки и поступлений на месяц (стоимость денег на сдвинутых поступлениях,
#        штраф заказчика, простой бригады)
```

**С кредитом сравнивается только (а).** Кредит заменяет долг. Перенос (б) — это не финансирование, а решение о графике закупок и производства: обязательство не возникает, если не заказывать. Его цена — риск цены плюс сдвиг отгрузок и поступлений, а не пеня.

```python
def allocate(limit, items, urgent_max_tier=2):
    """limit — уже за вычетом неснижаемого и обслуживания долга (долг — не заявка, K16).
    items: dict(name, amount>0, tier, kind, r, p_stop, loss, ship). kind: 'а' — КЗ L0/L1 (r = r_late),
    'б' — будущая закупка L2/L3 (r = рост цены g за год), 'г' — решение группы (r = 0);
    ship — месяц отгрузки дома 'YYYY-MM' (для T1 — из драйвера) или ''.
    Возвращает план, нехватку неотложных (T0..urgent_max_tier) и цену переноса по природе, грн/мес."""
    for it in items:
        it['c'] = it['r'] * 30 / 365 + it['p_stop'] * it['loss'] / it['amount']
    plan, short_urgent, defer = [], 0.0, {'а': 0.0, 'б': 0.0, 'г': 0.0}
    for it in sorted(items, key=lambda x: (x['tier'], x['ship'] or '9999', -x['c'])):
        pay = min(limit, it['amount']); limit -= pay
        rest = it['amount'] - pay
        plan.append((it['name'], pay, rest))
        if it['tier'] <= urgent_max_tier: short_urgent += rest     # внешний источник до переговоров
        elif rest: defer[it['kind']] += rest * it['c']
    return plan, short_urgent, defer         # с кредитом сравнивать только defer['а']
```

Внутри T1 раньше оплачивается более ранняя отгрузка (`ship`), поэтому при нехватке переносятся материалы под дома следующего месяца, а не текущего.

Разрыв закрывать от быстрого и дешёвого к дорогому: ДЗ и авансы клиентов (M03) → договорённости с поставщиками → очередность → излишки запасов (M05) → закупки → неприоритетное → деньги группы → внешнее финансирование (M10). Регламент: прогоны в фиксированные дни, маршрут по суммам, в кризисе — еженедельный «кэш-штаб».

**Реструктуризация просрочки.** Крупному кредитору — часть сразу, остаток равными долями на 2–3 месяца в обмен на отказ от пени и 3 %. В бюджет как договорённость идёт **только подписанный график**; неподписанный — сценарий, со строкой «риск санкций» = c_i × вероятность иска. Предупреждать рано, начинать с топ-10 поставщиков по объёму.

### 3.9. Авансы выданные

1. Закупка — **одна сущность** (договор/заказ), из неё: предоплата (БДДС, месяц заказа), остаток (БДДС, поставка + срок), запас (ББЛ), себестоимость (БДР, месяц отгрузки дома).
2. Σ оплат по договору = сумма договора; предоплата ≤ договорной доли аванса; зачёт — в месяце поставки.
3. Аванс — необеспеченный риск: при неплатёжеспособности поставщика теряются деньги и товар. Защита: лимит на поставщика, вехи, банковская гарантия возврата аванса, страхование авансов (покрытие до 95 %).
4. Флаг: аванс без поставки дольше срока поставки + 30 дней.
5. НДС: по правилу первого события предоплата даёт налоговый кредит при регистрации накладной поставщиком — НДС к уплате снижается месяцем раньше (M09).

### 3.10. Стресс-тест и SCF

**«Кредиторка исчезает»** — поставщики переводят на оплату по факту или предоплату (Toys R Us: отгрузки только за немедленную оплату):

```
ΔCash_разово = Закупки_в_день × (DPO_текущий − DPO_новый);   DPO_новый = −(дней предоплаты до поставки)
```

Сценарии: ключевой поставщик материалов МД; все критичные; отзыв внутригрупповой отсрочки.

**Supply chain finance.** Финансист платит поставщику досрочно со скидкой по риску **покупателя**, покупатель возвращает в срок или позже. IFRIC (12.2020): это торговая КЗ, только если сохраняется природа оборотного капитала, иначе — отдельная строка или заимствования; с 01.01.2024 раскрытия по IAS 7 / IFRS 7 обязательны. Moody's считает 90 дней верхом торговой природы, S&P относит КЗ под SCF сверх 90 дней к долгу; отзыв программ ускорил крах Carillion и Greensill. **Правило бюджета**: отсрочку от финансиста или группы показывать как финансирование с датой возможного отзыва и стресс-тестом. Малому производителю классический SCF недоступен; реалистичны товарный кредит дистрибьютора (ставка по 3.6), внутригрупповое финансирование (M10) и факторинг ДЗ надёжных заказчиков (M03).

### 5.2. Правила

1. Каждая строка сверенного снимка — ровно в одном месте: внутри остатка проекта **или** отдельной строкой.
2. Даты — по сроку оплаты с проскальзыванием; просроченное — в первый месяц или по подписанному графику.
3. Выплаты по материалам проекта ≤ остатка к оплате; погашение стартовой КЗ ≤ её суммы.
4. Предоплата и поставка — из одной сущности «договор»; поставка против аванса = 0 денег.
5. ЗП и налоги — по юридическому календарю, разными строками, стартовые суммы фактические.
6. При нехватке — лимит по подтверждённым поступлениям, tiers, цена задержки и два числа: потребность в финансировании (нехватка T0–T2) и переговорные переносы существующей КЗ (а) с ценой. Сдвиги будущих закупок (б) и решения группы (Г) показываются отдельно.
7. Внутригрупповые КЗ и отсрочки SCF — строками «финансирование» с датой возможного отзыва; внутригрупповые выплаты без КЗ — строкой «решение группы».
8. Пара финагента — вне лимита и выплат; Ф2 — одной суммой «нал × (1 + комиссия + банк)».

## 6. Типичные ошибки и ловушки

1. **КЗ сверху «остатка к оплате»** — ловить флагом K8 и неравенством K5.
2. **Аванс учтён дважды** — сентябрьская предоплата снова как «30 % при заказе» (пример 4.4); ловить K2, K3.
3. **Дата счёта вместо срока оплаты** — поток смещён влево; сравнивать в снимке «дата документа vs срок».
4. **Вся стартовая КЗ — в первый месяц** без старения — или обратная «клюшка» (всё на последний месяц); ловить старением, K9, K12.
5. **Пропуск L0** — услуги прошлого месяца без счёта; сверять регулярные услуги факта со снимком КЗ.
6. **ЗП и налоги средним** — теряется пик (сентябрьская ЗП + ЕСВ до 20.10 + НДС до ~30.10); ловить K14.
7. **«Отложим ЗП — сэкономим налоги»** — нет, налоги платятся от начисления (4.9).
8. **Просрочка как бесплатный кредит** — до ~45 % годовых плюс риск предоплаты; у каждого переноса должна быть цена.
9. **Растягивание проектных закупок у единственного поставщика** — скрытая наценка и срыв графика; это T1, не T3.
10. **DPO через себестоимость** при наращивании запасов и НЗП — ложный «запас» по кредиторке.
11. **Сальдирование долга и аванса** без договора — прячет висящие авансы и просрочку.
12. **Отсрочка группы или SCF как бессрочный ресурс** — при отзыве мгновенный отток.
13. **Скидка ценой пробоя неснижаемого остатка** — экономия 2 % оборачивается дорогим кредитом.
14. **Неучтённые ковенанты** при отсрочке банку — дефолт и кросс-дефолт. Обслуживание кредита вычитается из лимита до распределения и заявкой T1 не ставится, иначе резерв задвоится (K16).
15. **Приоритет «своим»** при дефиците — удар по внешним критичным поставщикам; внутригрупповое — T4.
16. **`ДатаПлановогоПогашения` из ERP как договорный срок** — у нас она равна дате возникновения (§8.2), вся КЗ выглядит «просроченной».
17. **Безнадёжная КЗ «забыта»** — кредитор может предъявить в пределах давности; списание — доход и НДС-корректировка. По долгам 2020–2025 давность после Закона 4434-IX течёт заново с 04.09.2025 (3.6).
18. **Будущие закупки как «переговорная кредиторка»** — материалы под ближайшие отгрузки ставят в T3/T4 «впрок» или «под январь» и сравнивают с кредитом. Долга нет, перенос — это сдвиг отгрузок и поступлений; потребность в финансировании занижается в разы. Ловить разметкой (а)/(б) и K17.
19. **Пара финагента в лимите и выплатах** — поступление от ФА завышает лимит, нал-выплата и безнал-оплата ФА задваивают Ф2; или Ф2 без комиссии 14,12 % и банка 1,58 % (v2). Ловить K10, K16.
20. **Прогнозные поступления в лимите** — лимит строят на поступлениях от событий горизонта, и при их сдвиге обнуляются T0–T1. Ловить K17.

## 7. Чек-лист для ИИ при составлении бюджета

1. Сними снимок КЗ и авансов выданных на дату среза по договорам, без сальдирования; сверь сумму с источником.
2. Сверь ERP-расчёты с книгой долгов и фактом «Казны»; расхождения объясни построчно или возьми сверенный источник.
3. Присвой каждой строке слой, флаг «внутри / вне остатка», срок, корзину старения, tier и цену задержки.
4. Добавь слой L0 — регулярные услуги прошлого месяца без счёта.
5. Посчитай остаток к оплате по материалам проекта и разложи его на L1 + (L2 − A) + L3.
6. Ставь даты по сроку оплаты с проскальзыванием поставщика, не по дате документа.
7. Веди roll-forward КЗ и авансов по договору помесячно; проверяй `Выплаты = D − ΔКЗ + ΔАванс`.
8. Не прибавляй КЗ «внутри остатка» отдельной строкой и не ставь заново выданную предоплату.
9. ЗП, НДФЛ+ВС, ЕСВ и НДС ставь по юридическому календарю разными строками, стартовые суммы — фактические. Ф2 ставь одной суммой «нал. выплаты + комиссия ФА + банк», пару ФА исключи, налоги к Ф2 не начисляй.
10. Считай лимит выплат каждого месяца (недели) по подтверждённым поступлениям, с неснижаемым остатком, обслуживанием долга (только здесь, не заявкой) и резервом под ЗП.
11. При нехватке распределяй заявки по tiers, внутри — по месяцу отгрузки и цене задержки; T0 не урезай. Tier материалам назначай по месяцу отгрузки дома из драйвера, не экспертно; каждой строке T3/T4 присвой природу (а) КЗ или (б) будущая закупка.
12. Выдай два числа: потребность во внешнем финансировании (нехватка T0–T2, при лимите по подтверждённым поступлениям; неподтверждённые — риск-строкой) и переговорные переносы существующей КЗ (а) с ценой в грн/мес. Сдвиги будущих закупок (б) с ценой сдвига отгрузок и строку «решение группы» (Г) покажи отдельно.
13. Каждому переносу присвой статус; одностороннее покажи отдельно как риск.
14. Сравни с кредитом цену отсрочки только существующей КЗ (а); КЗ с пеней, которая дороже кредита, предложи закрыть кредитом. Для (б) сравнивай «финансировать закупку» против «сдвинуть отгрузку» с ценой сдвига поступлений.
15. Скидки, наценки и предоплаты оценивай годовой ставкой против стоимости денег при условии неснижаемого остатка.
16. Внутригрупповую КЗ и отсрочки группы показывай строкой T4 с признаком «финансирование»; внутригрупповые выплаты без КЗ — отдельной строкой «решение группы», предварительно проверив, что это не дубль уже учтённых выплат (у нас наличные ЦО УТ-001042 оказались дублем ЗП Ф2, урок в 4.6).
17. Посчитай стресс-тест «критичные поставщики требуют предоплату».
18. На конец горизонта проверь countback-DPO, долю просрочки и инварианты K1–K17.
19. В расшифровке каждой суммы выплат укажи слой, поставщика или группу, срок и правило даты.

Метод даёт верную **сумму** и консервативный **тайминг**; модуль добавляет сроки, tiers, цену переносов и проверки roll-forward. Квартал (−7,75 млн в v2; в v1 −10,59 млн) почти не меняется — меняются месяцы и появляется план финансирования.

### 8.5. Что не менять

- «Остаток к оплате = норма × домов − оплачено» и K_mat = 1,00: сумма верна, модуль уточняет время и очередность.
- Лаги поступлений заказчиков — тема M03, здесь это вход «подтверждённые поступления».
- Типовые регистры ERP не трогать; сроки — через договоры и документы.
- Подтверждённые разовые (кредитная линия, НДС, премии) — вручную, как в 07.

## 9. Вопросы для самопроверки

1. **Почему КЗ по материалам проекта нельзя ставить строкой рядом с «остатком к оплате»?** Остаток = норма − оплачено уже включает всё неоплаченное, в том числе поставленное в кредит; отдельная строка задваивает КЗ (4.4).
2. **Аванс 300 000 выдан в сентябре, поставка 1 000 000 — 20 октября, остаток через 14 дней. Сколько денег в октябре?** Ноль: поставка гасит аванс без денег, КЗ 700 000 оплачивается 03.11. Проверка: `1 000 000 − 700 000 − 300 000 = 0`.
3. **Какое тождество проверяет roll-forward?** `Выплаты = Поставки − ΔКЗ + ΔАванс_выданный` по договору и месяцу.
4. **Почему DPO через себестоимость у нас вводит в заблуждение?** Материалы под будущие дома куплены, а себестоимость появится при отгрузке: знаменатель занижен, DPO завышен. База — закупки, лучше countback.
5. **Сколько стоит отказ от 2/10 net 30 и брать ли скидку при кредите 22 % и пробое неснижаемого остатка?** 37,24 % простых (44,59 % сложных) — выгоднее кредита, но при пробое неснижаемого — не брать.
6. **Верхняя граница цены просрочки поставщику в Украине на октябрь 2026?** Пеня до 2 × 16 % = 32 % + 3 % + инфляция ~10 % ≈ 45 % годовых ≈ 3,7 % в месяц; без пени ≈ 13 %.
7. **Можно ли сэкономить на налогах, задержав ЗП?** Нет: НДФЛ+ВС по начисленной — ≤ 30 дней после месяца, ЕСВ — до 20 числа; отложить можно только нетто (63 % стоимости ФОТ) и с компенсацией.
8. **Неотложные выплаты (T0–T2) больше лимита — что делать?** Показать нехватку как потребность во внешнем финансировании до переговоров. Лимит считать по подтверждённым поступлениям, неподтверждённые дать риск-строкой. Переносить по подписанным договорённостям с ценой только существующую КЗ (а). Сдвиг будущих закупок (б) — это решение о графике отгрузок с ценой сдвига поступлений; внутригрупповые выплаты — решение группы. Октябрь 2026 (4.6, v2): T0–T2 15 505 395,93 против лимита 6 647 974,72 → финансирование **8 857 421,21** (6 181 443,21, если придут неподтверждённые 2 675 978,00). Ещё 1 770 216,78 — переговоры по КЗ; строк «решение группы» нет. Все материалы МД (8,9 млн) — T1, потому что дома отгружаются в октябре–ноябре.
9. **Почему просроченную КЗ с пеней выгоднее закрыть кредитом?** ~3,7 % в месяц против ~1,8 % по кредиту 22 %; в 4.7 экономия 11 581,39 грн/мес на 612 638,39 грн.
10. **ERP показывает всю КЗ производства «просроченной». Верить?** Нет: `ДатаПлановогоПогашения` = `ДатаВозникновения`, это возраст с поставки. Сроки — из договоров или книги.
11. **Как поставщики «отзывают» кредиторку и сколько это стоит?** Переводят на предоплату: разовый отток = закупки в день × (DPO_старый − DPO_новый); 3 млн/мес. с net 14 на предоплату за 30 дней — 4,4 млн.
12. **Где показывать отсрочку от группы или финансиста SCF?** Отдельной строкой «финансирование» с датой возможного отзыва и стресс-тестом, не как бессрочную торговую КЗ (IFRIC 2020, IAS 7 / IFRS 7).
