# Назначение и контекст отчёта

## Зачем отчёт нужен

В BAS ERP 2.5 INDUSTRIALBUD управленческий баланс ведётся в разрезе подразделений
(`РегистрНакопления.ПрочиеАктивыПассивы`, ПАП). Когда первичный документ (закупка,
перемещение товара, списание недостач, ПКО/РКО, передача начислений) делает движения,
по которым одно подразделение оказывается «дебитором» (+актив или +расход), а другое
«кредитором» (−актив или −расчёт), управ.баланс **по организации сходится в 0**, но
по **подразделениям внутри организации** — нет.

Этот дисбаланс закрывается автоматически создаваемым документом
`Документ.ВзаимозачетЗадолженности`. Делает это обработка
`DataProcessors.А_ОбработкаДисбалансаПоПодразделениям`: контрагенты-дебитор/кредитор
взаимозачёта — это **служебные контрагенты-партнёры подразделений** (партнёр с
заполненным `Партнеры.А_Подразделение`), а реквизит `А_СтатьяДисбалансаПоПодразделению`
должен хранить пару статей баланса, на которой произошёл дисбаланс.

**Проблема для бухгалтера:** глядя на готовый документ `ВзаимозачетЗадолженности`,
не видно ПОЧЕМУ он создан. Какой склад? Какой договор с каким контрагентом-поставщиком?
Какая статья расходов? Какой банк-счёт?

Раньше бухгалтер открывал «Связанные документы» / «Движения документа» вручную, листал
4–6 регистров и собирал картину сам. Если хранимый реквизит
`А_СтатьяДисбалансаПоПодразделению` заполнен неверно (а такое было до правки
обработки 2026-06-17), картина ещё и вводила в заблуждение.

**Отчёт `А_РасшифровкаЗадолженностиПодразделений` решает обе проблемы:**

1. Для каждого взаимозачёта периода поднимает фактические движения ПАП
   документа-основания.
2. Определяет ФАКТ-пару статей дисбаланса (дебиторская = статья с максимальным
   signed-сальдо в подразделении дебитора, кредиторская — минимальная в кредиторе).
3. Сверяет с хранимой `А_СтатьяДисбалансаПоПодразделению` → флаг расхождения.
4. Для каждой стороны декодирует Аналитику по `Источник` (склад/контрагент/договор/
   касса/счёт/физлицо/статья расходов).
5. Делит сумму на Приход (увеличение долга) и Расход (уменьшение).
6. Группирует по контрагенту, договору, встречному подразделению, хранимой статье,
   взаимозачёту → бухгалтер видит «откуда копится долг» на каждом уровне.

## Целевой пользователь

**Бухгалтер ввода документов / менеджер первичной документации.** Открывает отчёт
после закрытия месяца (когда обработка дисбаланса отработала) или в текущем месяце
для проверки корректности проведения первичных документов. Видит:

- свои контрагенты-партнёры (=подразделение, за которое отвечает);
- каким договорам/складам соответствуют дисбалансы;
- куда «утекают» суммы (зарплата / товар / услуга / аванс / оплата).

**Аудитор / финансист (вторичный пользователь).** Использует флаг расхождения
хранимая/факт как маркер документов, по которым обработка дисбаланса заполнила
реквизит неверно (если расхождение есть — значит, требуется перепрогон обработки
или ручная коррекция реквизита).

## Бизнес-проблема: история

В декабре 2025 обнаружились два показательных случая, которые и стали эталонами
для проектирования отчёта:

| Взаимозачёт | Основание | Сумма | Хранимая (бывшая) | Факт из ПАП |
|---|---|---:|---|---|
| 000Ц-000511 | Приобретение услуг и прочих активов СТ00-000023 | 8 800,20 | «Товары на оптовых складах – Товары на оптовых складах» ❌ | «Товары на оптовых складах – Задолженность перед поставщиками» |
| 000Ц-000510 | Списание недостач товаров ВН-СТ00-000367 | 21 522,29 | «Товары – Товары» ❌ | «Расходы текущего периода – Товары на оптовых складах» |

Хранимый реквизит врал в обоих случаях. Бухгалтер, глядя на взаимозачёт, видел
«Товары↔Товары», но никаких товаров там не было — была закупка услуг с услугой
на одно подразделение (Производство) и расчёт с внешним поставщиком (ТСК) через
другое (Цех металлоконструкций). Отчёт-расшифровка делает эту ситуацию очевидной:

```
Контрагент: Производство
└ Договор: РАХУНКИ внутр.(Закупка)
   └ Встречное подразделение: Цех металлоконструкций
      └ Хранимая статья: Товары – Товары
         └ Взаимозачёт 000Ц-000511 (8 800,20)
            ├ ⚠ Реквизит врёт: факт = «Товары ↔ Задолженность поставщикам»
            ├ 🟢 Дебитор / Производство / Товары на оптовых складах / Себестоимость
            │   Аналитика: СТІЛ Основной склад / Реле теплове + КонтакторСЕМ / +8 800
            └ 🔴 Кредитор / Цех металлоконст. / Задолж. поставщикам / Расчёты
                Аналитика: ТОВ «ІНДАСТРІАЛ СОЛЮШН ТСК» / Договор РАХУНКИ / −8 800
```

Параллельно с отчётом был выпущен фикс обработки
`А_ОбработкаДисбалансаПоПодразделениям`, который пересчитал хранимые статьи.
Поэтому на текущих данных флаг расхождения почти везде «Нет» — но отчёт всё равно
полезен как **расшифровка причины** и как **детектор** будущих расхождений.

## Третий эталон — 000Ц-000548 (грабли «дублирующих сторон»)

Документ 000Ц-000548 (190 грн, пара MAN №3 ↔ Логистика) возник из закупки
ІБ00-007892, которая на самом деле породила **3 взаимозачёта** одновременно
(MAN №3, MAN №4, MAN №5 — все против Логистики). До фикса `128c86212` отчёт под
взаимозачётом MAN №3 ↔ Логистика показывал стороны ВСЕХ трёх MAN, потому что
читал ПАП по основанию без фильтра по подразделениям пары. Фикс:
`ПолучитьСтороныПАП(Основание, ПодрДеб, ПодрКред)` теперь фильтрует
`ПАП.Подразделение В (&ПодрДеб, &ПодрКред)`, и каждый взаимозачёт видит только
свои две стороны. См. [`rzp_data_logic.md`](rzp_data_logic.md).

## Связь с Power BI

Поля `Аналитика1/2/3` в этом отчёте формируются **по тому же рецепту**, что в
`Документ.А_ФинРез_Баланс` → `РегистрСведений.А_ОтчетБаланс_Свод` → SQL
`Fact_Balance` → Power BI. Поэтому бухгалтер видит ту же аналитику, что в PBI-отчёте
«Управ.баланс с расшифровкой» / страница «Дубликат Внутренние подразделения». См.
[`rzp_analytics_decoding.md`](rzp_analytics_decoding.md).

## Что отчёт НЕ делает (вне scope)

- НЕ перепроводит первичные документы.
- НЕ исправляет реквизит `А_СтатьяДисбалансаПоПодразделению` — это задача обработки
  `А_ОбработкаДисбалансаПоПодразделениям` (отдельный workflow выпущен 2026-06-17).
- НЕ работает по свёртке `А_ОтчетБаланс_Свод` — только живой ПАП (свёртка не хранит
  первичный документ для всех случаев, и работает только по закрытым месяцам).
- НЕ показывает разрез «Вид контрагента» (Внешние/Внутренние/Внутригрупповые) — отчёт
  по природе ограничен партнёрами-подразделениями, внешние контрагенты появляются
  только в детальной аналитике (Аналитика2).
- НЕ выгружает данные в Power BI — у PBI свой ETL через `А_ОтчетБаланс_Свод`.

## Доп. разрезы, которые НЕ вошли (Roadmap)

- Параметр «только взаимозачёты с непустыми движениями ПАП».
- Колонка «Тип статьи (актив/пассив)» — инвертировать Приход/Расход для пассивных
  статей, чтобы «увеличение долга» всегда означало «бизнес-долг вырос», а не «движение
  было приходом».
- Drill-down → открыть сам `ВзаимозачётЗадолженности` для ручной правки реквизита.
- Переключатель «период по дате основания», когда взаимозачёт создан позже месяца.

Эти идеи зафиксированы в `KNOWLEDGE_MAP.md` → Roadmap, не реализованы, по запросу.
