# Декодирование `Аналитика1/2/3` по `Источник`

## Контекст

`Документ.А_ФинРез_Баланс` (модуль `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl`)
проводит управленческий баланс в `РегистрСведений.А_ОтчетБаланс_Свод`. Свод имеет
текстовые поля `Аналитика1/2/3`, заполняемые по-разному в зависимости от `Source`
(`Перечисление.ИсточникиУправленческогоБаланса`). Эти поля выгружаются в SQL
`Fact_Balance` и используются в Power BI как пользовательские разрезы.

**Отчёт `А_РасшифровкаЗадолженностиПодразделений` использует ТОТ ЖЕ рецепт**, чтобы
бухгалтер видел те же значения, что в Power BI «Управ.баланс з розшифровкою».

## Рецепт (зеркало `А_ФинРез_Баланс`)

| Источник (ПАП.Источник) | Регистр-декодер | Аналитика1 | Аналитика2 | Аналитика3 |
|---|---|---|---|---|
| Себестоимость товаров | `РегистрНакопления.СебестоимостьТоваров` → `Справочник.КлючиАналитикиУчетаНоменклатуры` | Склад.Подразделение | Склад (=МестоХранения) | Номенклатура (СтрСоединить «; ») |
| Расчёты с клиентами по срокам | `РегистрНакопления.РасчетыСКлиентамиПоСрокам` (по `ДокументРегистратор`) | Договор.А_ПодразделениеОказаниеУслугПодразделению | Контрагент (СтрСоединить) | Договор (СтрСоединить) |
| Расчёты с поставщиками по срокам | `РегистрНакопления.РасчетыСПоставщикамиПоСрокам` (по `ДокументРегистратор`) | Договор.А_ПодразделениеОказаниеУслугПодразделению | Контрагент | Договор |
| Прочие расходы | `РегистрНакопления.ПрочиеРасходы` (фильтр по подразделению стороны) | СтатьяРасходов (СтрСоединить) | — | — |
| Партии прочих расходов | то же | СтатьяРасходов | — | — |
| Денежные средства (безналичные/наличные/в пути/у подотчётных лиц) | `ПАП.Аналитика` через `ПРЕДСТАВЛЕНИЕ` | Банк-счёт / Касса / ФизЛицо | — | — |
| Оплата труда / Зарплатные | `ПАП.Аналитика` (= ФизЛицо) | ФизЛицо | — | — |
| Прочее (ОС, НМА, Налоги, прочие пассивы) | `ПАП.Аналитика` через `ПРЕДСТАВЛЕНИЕ` | ОС / НМА / Тип налога / «Без аналитики» | — | — |

## Диспетчер — `ДекодироватьСторону(Основание, Сторона)`

```bsl
Функция ДекодироватьСторону(Основание, Сторона)
    Результат = Новый Структура("Аналитика1, Аналитика2, Аналитика3", "", "", "");
    Источник = Сторона.Источник;
    ПеречИст = Перечисления.ИсточникиУправленческогоБаланса;

    Если Источник = ПеречИст.СебестоимостьТоваров Тогда
        ДекодСебестоимость(Основание, Сторона.Подразделение, Результат);

    ИначеЕсли Источник = ПеречИст.РасчетыСПоставщикамиПоСрокам
        ИЛИ Источник = ПеречИст.РасчетыСКлиентамиПоСрокам Тогда
        ДекодРасчеты(Основание, Источник, Результат);

    ИначеЕсли Источник = ПеречИст.ПрочиеРасходы
        ИЛИ Источник = ПеречИст.ПартииПрочихРасходов Тогда
        ДекодПрочиеРасходы(Основание, Сторона.Подразделение, Результат);

    ИначеЕсли Источник = ПеречИст.ДенежныеСредстваБезналичные
        ИЛИ Источник = ПеречИст.ДенежныеСредстваНаличные
        ИЛИ Источник = ПеречИст.ДенежныеСредстваВПути
        ИЛИ Источник = ПеречИст.ДенежныеСредстваУПодотчетныхЛиц Тогда
        ДекодПоАналитикеПАП(Основание, Источник, Результат);

    Иначе
        // Оплата труда (А_ВзаиморасчетыССотрудниками) и прочие — берём ПАП.Аналитика
        ДекодПоАналитикеПАП(Основание, Источник, Результат);
    КонецЕсли;

    Возврат Результат;
КонецФункции
```

## Хелпер 1 — `ДекодСебестоимость`

Запрос:

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПРЕДСТАВЛЕНИЕ(Себ.АналитикаУчетаНоменклатуры.МестоХранения.Подразделение) КАК СкладПодразделение,
    ПРЕДСТАВЛЕНИЕ(Себ.АналитикаУчетаНоменклатуры.МестоХранения)                КАК Склад,
    ПРЕДСТАВЛЕНИЕ(Себ.АналитикаУчетаНоменклатуры.Номенклатура)                 КАК Номенклатура
ИЗ РегистрНакопления.СебестоимостьТоваров КАК Себ
ГДЕ Себ.Регистратор = &Основание
  И Себ.АналитикаУчетаНоменклатуры.МестоХранения.Подразделение = &Подразделение
```

> **Фильтр по подразделению стороны** — критически важен. Если основание касается
> нескольких складов на разных подразделениях, без фильтра запрос вернёт ВСЕ склады
> и аналитика смешается между сторонами.

В цикле Выборки:
- `Склад`, `СкладПодр` берутся последние непустые (обычно одно значение).
- `Номенклатуры` накапливаются в массив (различные) → `СтрСоединить(Номенклатуры, "; ")`.

Пример (000Ц-000511, основание СТ00-000023, сторона Производство):
- Аналитика1 = `Производство`
- Аналитика2 = `СТІЛ Основной склад`
- Аналитика3 = `КонтакторСЕМ 40.11 230V АС; Реле теплове RE 67.1D-50 (32-50А)`

## Хелпер 2 — `ДекодРасчеты`

Запрос (динамический выбор регистра):

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПРЕДСТАВЛЕНИЕ(Расч.АналитикаУчетаПоПартнерам.Контрагент) КАК Контрагент,
    ПРЕДСТАВЛЕНИЕ(Расч.ОбъектРасчетов.Договор)                КАК Договор,
    ПРЕДСТАВЛЕНИЕ(Расч.ОбъектРасчетов.Договор.А_ПодразделениеОказаниеУслугПодразделению) КАК ПодрУслуг
ИЗ РегистрНакопления.<РасчетыСКлиентамиПоСрокам|РасчетыСПоставщикамиПоСрокам> КАК Расч
ГДЕ Расч.ДокументРегистратор = &Основание
```

> **`ДокументРегистратор`, не `Регистратор`!** В расчётах по срокам `Регистратор` это
> служебный `РегистраторРасчётов`, а `ДокументРегистратор` — первичный документ. См.
> `knowledge_Balanse_klient/LESSONS.md` раздел 5.

Накопление в массивы → `СтрСоединить`:
- Аналитика1 = `ПодрУслуг` (последнее непустое — обычно одно значение, для внутренних договоров)
- Аналитика2 = Контрагенты «; »
- Аналитика3 = Договоры «; »

Пример (000Ц-000511, сторона Цех металлоконструкций, источник «Расчёты с поставщиками по срокам»):
- Аналитика2 = `ТОВ "ІНДАСТРІАЛ СОЛЮШН "ТСК"`
- Аналитика3 = `РАХУНКИ`

## Хелпер 3 — `ДекодПрочиеРасходы`

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПРЕДСТАВЛЕНИЕ(ПР.СтатьяРасходов) КАК СтатьяРасходов
ИЗ РегистрНакопления.ПрочиеРасходы КАК ПР
ГДЕ ПР.Регистратор = &Основание
  И ПР.Подразделение = &Подразделение
```

- Аналитика1 = `СтрСоединить(Статьи, "; ")`
- Аналитика2/3 — пусто.

Пример (000Ц-000510, сторона Цех металлоконструкций, основание ВН-СТ00-000367):
- Аналитика1 = `Будівельні матеріали`

## Хелпер 4 — `ДекодПоАналитикеПАП`

Универсальный декодер для денег / зарплаты / прочих источников.

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПРЕДСТАВЛЕНИЕ(ПАП.Аналитика) КАК Аналитика
ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК ПАП
ГДЕ ПАП.Регистратор = &Основание
  И ПАП.Источник = &Источник
```

- Аналитика1 = СтрСоединить (одно или несколько значений).
- Аналитика2/3 — пусто.

Примеры:
- Безналичные ДС: Аналитика1 = «ПриватБанк UA111… 980» (банк-счёт)
- Касса: Аналитика1 = «Основная касса»
- Зарплата: Аналитика1 = «Иванов И.И.» (ФизЛицо)
- Налоги: Аналитика1 = «НДФЛ; Начисленный ЕСВ; Военный сбор»

## Совпадение с `Документ.А_ФинРез_Баланс` (источник истины)

Соответствия конкретных строк кода `Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl`:

| Строки в `А_ФинРез_Баланс` | Назначение | Аналог в отчёте |
|---|---|---|
| 396–398 | Расчёты: Аналитика1=Договор.А_ВидКонтрагента, А2=Контрагент, А3=Договор | `ДекодРасчеты` (но А1 = ПодрУслуг, а не ВидКонтрагента — см. ниже) |
| 578–580 | Себестоимость: А1=Склад.Подр, А2=Склад, А3=Номенклатура | `ДекодСебестоимость` |
| 829–831 | Деньги: А1=ДенежныеСредства|ФизЛицо | `ДекодПоАналитикеПАП` |
| 1086–1088 | Налоги/прочее | `ДекодПоАналитикеПАП` |
| 1445–1447 | Зарплата: А1=ФизическоеЛицо | `ДекодПоАналитикеПАП` |

**Отличие в А1 для расчётов:** в `А_ФинРез_Баланс` идёт `Договор.А_ВидКонтрагента`
(«Внутригрупповые» / «Внешние» / «Внутренние подразделения»). В отчёте это
**намеренно** заменено на `Договор.А_ПодразделениеОказаниеУслугПодразделению` — нам
интересна вторая сторона дисбаланса (подразделение, которому должны/которое должно),
а вид контрагента в межподразделенческом отчёте всегда «внутренний» и неинформативен.

## Грабли декодирования

1. **Фильтр по подразделению стороны** обязателен для `ДекодСебестоимость` и
   `ДекодПрочиеРасходы` — иначе аналитика «смешается» между сторонами.
2. **`ДокументРегистратор`, не `Регистратор`** для расчётов по срокам — потому что
   `Регистратор` там — `РегистраторРасчётов` (служебный).
3. **`ПРЕДСТАВЛЕНИЕ(...)` обязателен** для составных типов (`ПАП.Аналитика`,
   ссылки в выходе MCP `execute_query`), иначе будет ошибка сериализации JSON.
4. **СтрСоединить с разделителем «; »** не «,», потому что наименования номенклатуры
   могут содержать запятые («Реле теплове RE 67.1D-50 (32-50А)»).
5. **Если декодер вернул пусто** (нетипичная связка `Источник` + регистр) —
   соответствующая Аналитика остаётся «», и в отчёте просто пусто. Не ошибка.

## Когда декодер пуст — почему

- `Источник = ПрочиеАктивыПассивы` (т.е. ПАП пишет напрямую без расшифровки через
  типовой регистр) — `ДекодПоАналитикеПАП` отработает, но если `Аналитика` тоже
  пустая → все три поля пусты. Бухгалтер по контексту (статья + источник) поймёт,
  но Аналитика не добавит информации.
- `Источник = Себестоимость` НО основание не попало в `СебестоимостьТоваров`
  (редкий случай при перепроведении / коррекции) → `ДекодСебестоимость` вернёт пусто.

В таких случаях факт-пара статей всё равно показывается из ПАП — так что отчёт
остаётся информативным даже с пустой Аналитикой.
