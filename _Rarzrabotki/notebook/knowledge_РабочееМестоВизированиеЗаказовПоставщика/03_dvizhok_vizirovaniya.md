# 03. Движок визирования (`А_ВизированиеСервер` + `А_ВизированиеВызовСервера`)

> Все запросы движка прогнаны через Python COM ПЕРЕД переносом в BSL (Rule #-1):
> `_Rarzrabotki\Python\test\test_vizirovanie_queries.py` (14/14).

---

## 1. Машина состояний — `А_ВизированиеСервер.УстановитьСостояние(ДокОбъект, Состояние, ДопПараметры)`

Возвращает `Структура {Успех, ТекстОшибки}` (исключений не бросает).

| Переход | Что делает |
|---|---|
| → `Черновик` | очищает `А_Визы`, ставит `Инициатор` текущей ролью |
| → `Утвержден` (первый раз инициатором) | **строит маршрут**: подбирает схему, разворачивает роли в `А_Визы`, заполняет `А_ПредварительныеВизы`, ставит первую роль в `А_ТекущиеВизирующие` → `НаВизировании` |
| → `Утвержден` (следующая роль) | продвигает маршрут; если это была последняя роль → `Утвержден` + **`УстановитьСтатус("Подтвержден")`** |
| → `Отклонено` | возвращает мяч инициатору → **`УстановитьСтатус("Согласован")`** (движения `КОформлению` уходят) |
| → `ПустаяСсылка()` | предварительная («отложенная») виза — подпись до своей очереди |

**🔑 Контракт записи: движок документ НЕ ПИШЕТ.** Он только меняет объект в памяти (реквизиты `А_Виза_*`,
ТЧ, и через типовой `ДокОбъект.УстановитьСтатус(...)` — реквизит `Статус`) и возвращает результат.
**Записывает вызывающий.** Это в точности контракт типового `УстановитьСтатусДокументов` (`:110` меняет,
`:116` пишет). Перед типовым `УстановитьСтатус` ставится `ДокОбъект.ДополнительныеСвойства.Вставить("А_ВизаДвижок", Истина)`.

## 2. Адресация — `ПолучитьМассивПользователей(ДокОбъект, Роль)`
Запрос к `РС.А_ИдентификацияВизирующихПоРолям` с ветвлением по `Роль.ВидАдресации`
(`Объект В (&Подразделения)` / `(&Организации)` / `(&Направления)`). Подразделение разворачивается
**вверх по иерархии** (+ пустая ссылка = «любой»). Учитывает **переадресацию**: если `Переадресация=Истина`
и текущая дата в `[ПереадресацияС; ПереадресацияДо]` — добавляет `Переадресант`.

## 3. Выбор схемы — `ПолучитьСхемуВизирования(ДокОбъект)`
Запрос-кандидаты по `РС.А_ОпределениеСхемыВизирования` (`Т.Сумма <= &СуммаДокумента`, измерения через
иерархию/пустую ссылку). Специфичность («Глубина») считается **в BSL**, не в запросе:

```bsl
Функция ГлубинаИзмерения(Ссылка)
    Если НЕ ЗначениеЗаполнено(Ссылка) Тогда Возврат 0; КонецЕсли;
    Возврат 100 + 10 * Ссылка.Уровень();   // Уровень() монотонен по иерархии
КонецФункции
Глубина = 1000 + ГлубинаИзмерения(СтатьяДДС) + ГлубинаИзмерения(Подразделение);
```
> ⚠️ Формула Казны `СтрДлина(ПолныйКод())` НЕ годится: падает на пустой ссылке и немонотонна по уровню
> → общее правило перебивало частное. См. [FINDINGS.md](FINDINGS.md) A3. `НаправлениеДеятельности` в
> «Глубину» не входит (справочник плоский).

Сортировка выбора: `ПриоритетСхемы Возр, Глубина Убыв, Сумма Убыв, Организация Убыв, ФормаОплаты Убыв`.

## 4. Права — `ДоступныеСостояния(ДокСсылка, ДопПараметры)` → `{Состояния: СписокЗначений, ВКонтуре}`
По текущему состоянию + роли пользователя (инициатор / в очереди / админ) отдаёт разрешённые переходы.
Пустое `А_Виза_Состояние` → `ВКонтуре=Ложь` (визировать нельзя).

## 5. Пакетный движок — `А_ВизированиеВызовСервера.УстановитьВизуДокументов(Массив, ИмяСостояния, ДопПараметры)` → Число
Калька `УстановитьСтатусДокументов`. По каждому документу: запрос-проверка (вне контура / помечен /
не проведён / состояние совпадает) → `ДоступныеСостояния` → `ЗаблокироватьДанныеДляРедактирования` →
`УстановитьСостояние` → **`Записать(Проведение)` (пишет ИМЕННО этот движок, один раз)**. Ошибки построчно
через `СообщитьПользователю(текст, Ссылка)`, пакет **не** в одной транзакции (ошибка одного не откатывает
остальных). `ИмяСостояния = "Предварительная"` → пустая ссылка состояния (отложенная виза).

Это движок массовых команд рабочего места (`05_rabochee_mesto.md`) и кнопок формы документа
(`04_forma_dokumenta.md`).
