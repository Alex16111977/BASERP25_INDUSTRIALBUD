# 05. Рабочее место `А_ВизированиеЗаказовПоставщику.epf` (журнал на динамическом списке)

> Пересобрано 15.07.2026 (ПРОМТ3) «как в Казне» (эталон `СчетНаОплатуПоставщика.ФормаСписка_Визирование`):
> вместо таблицы значений — **ДинамическийСписок** с ручным запросом. Инженерия отборов/подсветки — по
> типовому ЕРП (`ЗаявкаНаРасходованиеДенежныхСредств.ФормаСпискаЗаявокКСогласованию`). Собрано `epf-build`
> (формат **2.13**), smoke `test_viza_epf_smoke.py` 5/5, визуально проверено в клиенте.

---

## 1. Динамический список `Список`

- Реквизит `Список` (`DynamicList`): `ManualQuery=Истина`, `DynamicDataRead=false`,
  `ОсновнаяТаблица = Документ.ЗаказПоставщику`.
- **Текст запроса** — проверен Python COM ДО вставки (Rule #-1): `test_vizirovanie_dynlist_query.py`, 3/3
  режима. Поля: Ссылка, Номер, Дата, ПометкаУдаления, Организация, Подразделение, Партнер, Контрагент,
  СуммаДокумента, Статус, Автор, Менеджер, НаправлениеДеятельности, ВизаСостояние, ВизаТекущаяРоль,
  ВизаТекущиеВизирующие, ВизаДата, Комментарий (`ВЫРАЗИТЬ ... СТРОКА(200)`).
- Контур: `А_Виза_Состояние <> ПустаяСсылка`. Очереди — **подзапросами по ТЧ** (`Т.Ссылка В (ВЫБРАТЬ ...)`),
  НЕ `СГРУППИРОВАТЬ ПО` (в динсписке запрещено — ломает основную таблицу/2-клик).
- **Параметры списка** (ставятся в `ПриСозданииНаСервере` и при сменах): `РежимОчереди`,
  `ТекущийПользователь`, `Состояние_НаВизировании`, `ПоказыватьПомеченные`.
- Порядок по умолчанию — `Дата Убыв` кодом (`КомпоновщикНастроек.Настройки.Порядок`).
- Движок обработки (`ObjectModule`) сохранён: `ЗаполнитьИсториюВиз` — для master-detail;
  `ЗаполнитьТаблицуЖурнала` — больше не используется UI (остался для COM/smoke).

## 2. Визуал списка (как Казна `Виза_Список`)

- **Двухстрочные ячейки** — `ColumnGroup` (по умолчанию вертикальная) со вложенной горизонтальной:
  «Организация / (Дата + Номер)», «Партнёр / Контрагент», «Состояние визы / Текущая роль»,
  «Визирующие / Дата визы», «Статус заказа / Подразделение», «Автор / Комментарий»; отдельно «Сумма».
- **Штатный поиск** (`SearchStringAddition` + `SearchControlAddition`) и меню «Ещё» — нативные.
- Открытие заказа: 2-клик (`Selection` → `СтандартнаяОбработка=Ложь; ПоказатьЗначение(, ВыбраннаяСтрока)` —
  у динсписка выбранная строка = ссылка).
- **Подсветка строк — ТОЛЬКО кодом** через `Список.КомпоновщикНастроек.Настройки.УсловноеОформление`
  в `ПриСозданииНаСервере` (ЕРП-паттерн :271–341), поле отбора `ВизаСостояние`:
  НаВизировании → фон `Новый Цвет(255,248,220)`; Утвержден/УтвержденСКомментариями → фон `(214,240,214)`;
  Отклонено → текст `ЦветаСтиля.ПросроченныйДокумент`; Анулировано → текст `ЦветаСтиля.ЗакрытыйДокумент`.

## 3. Режимы очереди — радио `РежимОчереди` (как Казна `Виза_НаВизуМне`)

`RadioButtonField` с ChoiceList `0 Все · 1 Мне на визирование · 2 Пред. виза`; **дефолт 1** (ставится в
`ПриСозданииНаСервере`, между сеансами не сохраняется). `ПриИзменении` → серверная
`УстановитьПараметрыСписка()`. Чекбокс `ПоказыватьПомеченные` — параметр запроса (работает в режиме «Все»).

## 4. Отборы — сохраняются между сеансами (типовой механизм ЕРП)

Панель из двух строк: Подразделение (**в иерархии**), Организация, Партнёр, Автор; Состояние визы,
Статус заказа, Период с/по.

- Реквизиты формы названы **именами полей списка** (`Подразделение`, `Организация`, `Партнер`, `Автор`,
  `ВизаСостояние`, `Статус`) + `<Save>` в XML + `AutoSaveDataInSettings=Use` — это требование хелперов.
- `ПриИзменении` → `ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбораДинамическогоСписка(...)`;
  восстановление — `ПриЗагрузкеДанныхИзНастроекНаСервере` через
  `ОтборыСписковКлиентСервер.ОтборПоЗначениюСпискаПриЗагрузкеИзНастроек(Список, Имя, Реквизит,
  Неопределено, Настройки[, , ВидСравнения])` (СтруктураБыстрогоОтбора=Неопределено → читает Настройки).
- **Период** — два отбора по одному полю `Дата` (>= НачалоДня и <= КонецДня): типовой хелпер НЕ подходит
  (ищет только по имени поля, второй вызов перезаписал бы первый) → свой
  `УстановитьЭлементОтбораПериода` с поиском по **полю + виду сравнения** в
  `ФиксированныеНастройки.Отбор` (`&НаКлиентеНаСервереБезКонтекста`).

## 5. Массовые действия — по выделенным строкам (ссылки!)

Кнопки с иконками на панели списка: **Утвердить** (`ВыполненоУспешно`), **Отклонить** (`ОтменитьОперацию`),
**Подписать заранее** (`ВыполнитьРегламентноеЗаданиеВручную`), **В черновик** (`РедактироватьФайл`),
**Аннулировать** (`ВыполненоСОшибками`).

Паттерн: `ОбщегоНазначенияУТКлиент.ПроверитьПолучитьВыделенныеВСпискеСсылки(Элементы.Список)` (у
динсписка `ВыделенныеСтроки` — уже **ссылки**; хелпер отсеивает группировки и сам предупреждает о пустом
выделении) → для Отклонено/Анулировано `ПоказатьВводСтроки` причины → `ПоказатьВопрос` («… (заказов: N)?»,
дефолт Нет) → `А_ВизированиеВызовСервера.УстановитьВизуДокументов(Ссылки, ИмяСостояния, Допы)` (ВызовСервера,
с клиента; для «Подписать заранее» `ИмяСостояния="Предварительная"` + `Допы.ЭтоИзФормы=Истина`) →
`Элементы.Список.Обновить()` → оповещение «Для N из M …».

## 6. Панель «Всего выбрано» (как Казна `Выделено_Виза`)

Реквизит-надпись `Выделено`. `СписокПриАктивизацииСтроки` → пересчёт по `Элементы.Список.ВыделенныеСтроки`
через `Элементы.Список.ДанныеСтроки(Строка)` (паттерн Казны `ПолучитьСуммуКолонок`); показывается при
выделении >1 строки: «Всего выбрано N: Сумма 11 437,34».

## 7. Master-detail «История виз (по активной строке)»

Таблица `ИсторияВиз` (ТЗ формы: Роль, Пользователь, ДатаВизы, Состояние, Авто, Комментарий) под списком.
`СписокПриАктивизацииСтроки` → дебаунс `ПодключитьОбработчикОжидания("ОбновитьИсториюВизОжидание", 0.2,
Истина)` → сервер: `РеквизитФормыВЗначение("Объект").ЗаполнитьИсториюВиз(ТекущаяСтрока)`
(`Элементы.Список.ТекущаяСтрока` = ссылка).

- Rule #-1: запрос динсписка — `test_vizirovanie_dynlist_query.py` (3/3 ДО вставки в XML).
- Smoke `test_viza_epf_smoke.py` — 5/5 (движок ObjectModule жив).

  сохранены платформой 1:1.
