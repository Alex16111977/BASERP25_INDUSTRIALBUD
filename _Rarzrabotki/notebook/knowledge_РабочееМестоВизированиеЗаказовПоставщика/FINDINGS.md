## 🔑 Решение по объёму (15.07.2026): виза НИЧЕГО не блокирует

Гейт запрета обхода (перевод в `Подтвержден` только через визу) — **отменён**. Виза по-прежнему сама
ставит `Подтвержден` при полном согласовании (удобство + аудит-след), но не блокирует другие пути:
АРМы (`ОбеспечениеПотребностей`, `ФормированиеЗаказовПоставщикам`, `ФормированиеЗаказовПоставщикуПоПлану`),
ручную установку статуса, поступления. Врезка `ПроверитьЗапретОбходаВизирования` в `ПередЗаписью` стоит
**закомментированной**; сама процедура оставлена как неиспользуемая.

## Подтверждённые опоры (не переоткрывать)

- **Дискриминатор контура работает:** движок КД 2.0 `УниверсальныйОбменДаннымиXML:6406` создаёт документ
  через `СоздатьДокумент()` и НИ РАЗУ не зовёт `.Заполнить(` (0 на 14 650 строк) ⇒ `ОбработкаЗаполнения`
  при обмене не срабатывает ⇒ обменный заказ с пустой визой = вне контура. **Миграция не нужна.**
- **Все создатели заказа в ЕРП зовут `Заполнить()`** (4 места) ⇒ ни один заказ не выпадает из контура случайно.
- **`УстановитьСтатус` документ не пишет** — пишет вызывающий; хелперы `ОбщегоНазначенияУТКлиент` вызываемы из `.epf`.
- **`ВнешнееСоединение=Истина`** у обоих визовых общих модулей — иначе запись заказа через COM падает.
- **`РН.ТоварыКПоступлению` заказами не пишется** — 0 на 10 061; рубеж = `КОформлению`.
- **ФО `ИспользоватьСтатусыЗаказовПоставщикам` = Истина** — при выключении статус не гейтит движения.
- **Типовое «Согласование заказов поставщикам»** (`БизнесПроцесс.СогласованиеЗакупки`) включено, но
  **мёртвое** (0 БП, 0 задач, адресация пуста) — не переиспользуем, не трогаем.
