# 01. Объекты метаданных визирования (8 шт.)

> Все с префиксом `А_`. Созданы через `meta-compile`, провалидированы `meta-validate` (0 ошибок),
> загружены в BaseERP. Загрузка BuhBud не касается — механизм только в ЕРП.

---

## 1. `Перечисление.А_Визы_Состояния`

| Значение | Смысл |
|---|---|
| `Черновик` | заказ создан в ЕРП, ещё не отправлен на визирование (входная точка контура) |
| `НаВизировании` | маршрут построен, ждём подписи текущей роли |
| `Утвержден` | маршрут пройден целиком → заказ переведён в статус `Подтвержден` |
| `УтвержденСКомментариями` | то же + комментарий визирующего |
| `Отклонено` | отклонён → заказ возвращён в статус `Согласован` |
| `Анулировано` | визирование аннулировано |
| `ОтложеноСКомментарием` | зарезервировано (пока не используется активно) |

**Пустая ссылка перечисления = документ ВНЕ контура визирования** (обменный/исторический заказ).
Это дискриминатор — на нём стоит вся логика (гейт, журнал).

## 2. `Перечисление.А_ВидыАдресацииРолейВизирования`
`ПоПодразделению` · `ПоОрганизации` · `ПоНаправлению`. Определяет, по какому измерению искать
пользователей роли в `РС.А_ИдентификацияВизирующихПоРолям`.

## 3. `Справочник.А_РолиВизирования`

| Реквизит | Тип | Назначение |
|---|---|---|
| `ВидАдресации` | `EnumRef.А_ВидыАдресацииРолейВизирования` | по чему адресуется роль |
| `Приоритет` | Число(5,0) | порядок роли |
| `Комментарий` | Строка(500) | описание |

**Предопределённый элемент `Инициатор`** — движок ссылается на него напрямую
(`Справочники.А_РолиВизирования.Инициатор`): это роль автора/менеджера заказа, первая строка истории виз.

## 4. `Справочник.А_СхемыВизирования`
Маршрут согласования = упорядоченная цепочка ролей.

| Реквизит / ТЧ | Тип | Назначение |
|---|---|---|
| `Комментарий` | Строка(500) | описание схемы |
| ТЧ `Роли`.`Роль` | `CatalogRef.А_РолиВизирования` | **порядок строк = порядок визирования** |

## 5. `РС.А_ИдентификацияВизирующихПоРолям` (непериодический, независимый)
«Кто визирует под какой ролью» + замещение на отпуск.

| | Имя | Тип |
|---|---|---|
| Измерение | `Роль` | `CatalogRef.А_РолиВизирования` |
| Измерение | `Объект` | **составной**: `СтруктураПредприятия` / `Организации` / `НаправленияДеятельности` |
| Измерение | `Пользователь` | `CatalogRef.Пользователи` |
| Ресурс | `Переадресация` | Булево — включено замещение |
| Ресурс | `ПереадресацияС`, `ПереадресацияДо` | Дата — интервал замещения (пустая граница = без ограничения) |
| Ресурс | `Переадресант` | `CatalogRef.Пользователи` — кто замещает |

`Объект` интерпретируется по `Роль.ВидАдресации`: `ПоПодразделению` → элемент `СтруктураПредприятия` и т.д.

## 6. `РС.А_ОпределениеСхемыВизирования` (непериодический, независимый)
Выбор схемы по реквизитам заказа. Пустое измерение = «любой». `Сумма` — нижняя граница (порог):
правило срабатывает при `Т.Сумма <= СуммаЗаказа`.

| | Имя | Тип |
|---|---|---|
| Измерение | `Подразделение` | `CatalogRef.СтруктураПредприятия` |
| Измерение | `Организация` | `CatalogRef.Организации` |
| Измерение | `СтатьяДвиженияДенежныхСредств` | `CatalogRef.СтатьиДвиженияДенежныхСредств` |
| Измерение | `ФормаОплаты` | `EnumRef.ФормыОплаты` |
| Измерение | `Сумма` | Число(15,2) — порог «свыше N» |
| Измерение | `НаправлениеДеятельности` | `CatalogRef.НаправленияДеятельности` |
| Ресурс | `СхемаВизирования` | `CatalogRef.А_СхемыВизирования` |
| Ресурс | `Приоритет` | Число(5,0) |

> **`Должность` НЕ используется** (в Казне была измерением): резолвер «пользователь→должность» в ЕРП даёт
> 0% покрытия (`ФизическоеЛицо` пусто у всех пользователей). См. [FINDINGS.md](FINDINGS.md) A4.

## 7. `ОбщийМодуль.А_ВизированиеСервер` (Сервер, **ВнешнееСоединение=Истина**)
Движок: `УстановитьСостояние`, `ДоступныеСостояния`, адресация (`ПолучитьМассивПользователей`),
выбор схемы (`ПолучитьСхемуВизирования`), `ПредставлениеТекущихВизирующих`. См. [03_dvizhok_vizirovaniya.md](03_dvizhok_vizirovaniya.md).

> ⚠️ **`ВнешнееСоединение=Истина` обязателен** — модуль документа его вызывает, и без флага любая запись
> `ЗаказПоставщику` через COM падает на компиляции. `Привилегированный` при этом ставить нельзя (несовместимо).

## 8. `ОбщийМодуль.А_ВизированиеВызовСервера` (Сервер + ВызовСервера + ВнешнееСоединение=Истина)
Пакетный движок массовой визы `УстановитьВизуДокументов(Массив, ИмяСостояния, ДопПараметры)` → Число.
Точная калька типового `ОбщегоНазначенияУТВызовСервера.УстановитьСтатусДокументов`: блокировка объекта,
построчные проверки/сообщения, счётчик. Это движок массовых команд рабочего места и кнопок формы документа.

## + `Роль.А_ВизированиеАдминистратор`
Права на визовые объекты + право обхода (админ может менять визу/статус в обход очереди).
