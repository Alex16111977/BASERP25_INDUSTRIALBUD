# 02. Какие реквизиты и ТЧ `Документ.ЗаказПоставщику` использует виза

> Виза добавила в типовой документ **6 реквизитов шапки + 3 табличные части** и **4 врезки в модули**.
> Типовые реквизиты/движения/проведение НЕ менялись. Реструктуризация прошла на 10 060 заказах без потерь.

---

## 1. Новые реквизиты шапки (6)

| Реквизит | Тип | Назначение |
|---|---|---|
| `А_Виза_Состояние` | `EnumRef.А_Визы_Состояния` | текущее состояние визы. **Пусто = вне контура** (обменный/исторический заказ) |
| `А_Виза_ТекущаяРоль` | `CatalogRef.А_РолиВизирования` | чья очередь подписывать сейчас |
| `А_Виза_ТекущиеВизирующие` | Строка(250) | денормализация «кто сейчас должен подписать» — для колонки журнала |
| `А_Виза_Дата` | Дата | дата последнего изменения визы |
| `А_Виза_Причина` | Строка(1024) | причина отклонения / комментарий |
| `А_ПриоритетнаяСхемаВизирования` | `CatalogRef.А_СхемыВизирования` | принудительная схема (перебивает автоподбор) |

## 2. Новые табличные части (3)

### `А_Визы` — маршрут и история
| Реквизит | Тип | Назначение |
|---|---|---|
| `Роль` | `CatalogRef.А_РолиВизирования` | шаг маршрута |
| `Пользователь` | `CatalogRef.Пользователи` | кто подписал |
| `ДатаВизы` | Дата | ⚠️ **имя `ДатаВизы`, НЕ `Дата`** (конфликт со стандартным реквизитом ТЧ) |
| `Виза_Состояние` | `EnumRef.А_Визы_Состояния` | результат шага (пусто = ещё не пройден) |
| `Авто` | Булево | виза поставлена автоматически (по предварительной подписи) |
| `Комментарий` | Строка(1024) | комментарий шага |

Строки без проставленного `Виза_Состояние` — ещё не пройденные шаги маршрута.

### `А_ТекущиеВизирующие` — чья очередь
| Реквизит | Тип |
|---|---|
| `Пользователь` | `CatalogRef.Пользователи` |

По этой ТЧ работает фильтр журнала «Мне на визирование».

### `А_ПредварительныеВизы` — отложенные подписи
| Реквизит | Тип | Назначение |
|---|---|---|
| `Пользователь` | `CatalogRef.Пользователи` | кто может подписать заранее |
| `Утверждено` | Булево | подписал заранее |
| `ДатаУтверждения` | Дата | когда |
| `Роли` | Строка(250) | под какими ролями будет подписывать |
| `Комментарий` | Строка(1024) | комментарий |

## 3. Типовые реквизиты, которые ЧИТАЕТ движок (не меняет)

| Реквизит | Как используется |
|---|---|
| `Статус` (`СтатусыЗаказовПоставщикам`) | **точка интеграции**: виза двигает `Согласован ↔ Подтвержден` через типовой `УстановитьСтатус` |
| `Подразделение`, `Организация`, `НаправлениеДеятельности` | измерения адресации ролей и выбора схемы |
| `А_СтатьяДвиженияДенежныхСредств`, `ФормаОплаты`, `СуммаДокумента` | измерения выбора схемы (сумма — порог) |
| `Автор`, `Менеджер` | инициаторы (роль `Инициатор`) |

## 4. Врезки в модули (обрамлены `//++ А_Визирование` / `//-- А_Визирование`)

### `ObjectModule.bsl`
| Место | Что делает |
|---|---|
| `ИнициализироватьДокумент` (конец) | **вход в контур**: если `А_Виза_Состояние` пусто → `Черновик`. Именно здесь (не в `ОбработкаЗаполнения`), т.к. вызывается и при `ПриКопировании` — иначе копия выпала бы из контура |
| `ПриКопировании` (перед `ИнициализироватьДокумент()`) | сброс визы копии (иначе унаследует чужую визу с историей) |
| `ПередЗаписью` (после `Если ОбменДанными.Загрузка Тогда Возврат`) | пересчёт `А_Виза_ТекущиеВизирующие`. **Гейт запрета обхода закомментирован — отменён (см. FINDINGS §Решение).** |
| новый метод `А_Виза_УстановитьСостояние(Состояние, ДопПараметры)` | тонкая обёртка над `А_ВизированиеСервер.УстановитьСостояние` (документ не пишет — пишет вызывающий) |

### `ManagerModule.bsl`
`А_Виза_ДоступныеСостояния(ДокСсылка, ДопПараметры)` — обёртка над `А_ВизированиеСервер.ДоступныеСостояния`.

> **Дискриминатор контура работает потому**, что `ОбработкаЗаполнения` при загрузке обменом (КД 2.0)
> НЕ вызывается: движок `УниверсальныйОбменДаннымиXML` создаёт документ через `СоздатьДокумент()` без
> `Заполнить()`. Поэтому обменный заказ приходит с пустым `А_Виза_Состояние` = вне контура. Доказано:
> `.Заполнить(` — 0 вхождений на 14 650 строк движка обмена.
