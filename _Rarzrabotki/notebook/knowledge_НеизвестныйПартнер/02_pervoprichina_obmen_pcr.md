# 02. Первопричина — правила обмена Бух→ЕРП (PCR)

## Где живут правила

`_Rarzrabotki/ExChange/ПравилаОбменаДаннымиЕРПБух/`:
- `ExchangeRules.xml` (~1.46 МБ) — правила конвертации объектов (ПКО) и свойств (ПКС).
- `CorrespondentExchangeRules.xml`, `RegistrationRules.xml`.

Правила генерируются из конфигурации **«Конвертация данных» (КД 2.x)** и периодически перезагружаются. ⚠️ **Прямая правка XML — временное решение (перезатрётся при следующей выгрузке правил).** Поэтому окончательный фикс делаем в НАШЕМ коде (`А_СобытияОбъектов`), а не в XML — см. [04_profilaktika_chast_a.md](04_profilaktika_chast_a.md).

## ★ Корень: PCR свойства «Партнер» у Контрагентов (ExchangeRules.xml ~стр. 1307-1314)

```xml
<Свойство>
  <Код>31</Код>
  <Наименование>--&gt; Партнер</Наименование>
  <Источник Имя="" Вид=""/>                         <!-- ИСТОЧНИКА НЕТ -->
  <Приемник Имя="Партнер" Вид="Реквизит" Тип="СправочникСсылка.Партнеры"/>
  <ПередВыгрузкой>Значение = "НеизвестныйПартнер";</ПередВыгрузкой>  <!-- хардкод -->
</Свойство>
```

**Смысл:** при выгрузке контрагента из Бухгалтерии свойству «Партнер» БЕЗУСЛОВНО присваивается строка `"НеизвестныйПартнер"` (в Бухгалтерии понятия «партнёр» нет — есть только контрагент). Строка резолвится отдельным ПКО Партнёров в предопределённый `Справочники.Партнеры.НеизвестныйПартнер`.

**Итог:** КАЖДЫЙ контрагент, пришедший обменом, получает `Партнер = Неизвестный`.

## Распространение в документы (ПослеЗагрузки правил)

Документы при загрузке выводят партнёра из контрагента — но с fallback на заглушку. Примеры:

`ВозвратТоваровПоставщику` (ExchangeRules.xml ~стр. 10414):
```bsl
Объект.Организация = Параметры.Организация;
Если ЗначениеЗаполнено(Объект.Контрагент) Тогда
    Объект.Партнер = ДенежныеСредстваСервер.ПолучитьПартнераПоКонтрагенту(Объект.Контрагент);
    Если НЕ ЗначениеЗаполнено(Объект.Партнер) Тогда
        Объект.Партнер = Справочники.Партнеры.НеизвестныйПартнер;   // ← fallback
    КонецЕсли;
КонецЕсли;
```

`ПоступлениеБезналичныхДенежныхСредств` (~стр. 11481) — то же, но построчно по `РасшифровкаПлатежа`:
```bsl
ПартнерПоКонтрагенту = ДенежныеСредстваСервер.ПолучитьПартнераПоКонтрагенту(Объект.Контрагент);
Для Каждого Строка Из Объект.РасшифровкаПлатежа Цикл
    Если НЕ ЗначениеЗаполнено(Строка.Партнер) ... Тогда
        Строка.Партнер = ПартнерПоКонтрагенту;
        Если НЕ ЗначениеЗаполнено(Строка.Партнер) Тогда
            Строка.Партнер = Справочники.Партнеры.НеизвестныйПартнер;   // ← fallback
        КонецЕсли;
    КонецЕсли;
КонецЦикла;
```

Поскольку контрагент уже пришёл с `Партнер=Неизвестный` (п. выше), `ПолучитьПартнераПоКонтрагенту` возвращает Неизвестного, и документ наследует заглушку.

## Полные места хардкода заглушки в ExchangeRules.xml

`Объект.Партнер = Справочники.Партнеры.НеизвестныйПартнер` / `Строка.Партнер = ...` встречаются на строках: **1313 (PCR), 10418, 10722, 11007, 11489, 12082, 12737 (Поставщик), 13271, 13864, 14588, 15361, 16752** (и закомментированная 20925).

## Почему старая обработка «не доводила до конца»

Старая внешняя обработка сканировала метаданные и искала только реквизиты типа `СправочникСсылка.Партнеры`. Но в 23 регистрах партнёр хранится НЕ напрямую, а через **ключ аналитики** `КлючиАналитикиУчетаПоПартнерам` (тип измерения — этот ключ, а не Партнеры). Сканирование по типу эти регистры/ключи **не находило** → партнёр в них «оставался». Подробно — [03_arhitektura_klyuchi_analitiki.md](03_arhitektura_klyuchi_analitiki.md).

## Как чинить источник (резюме)

Окончательно — на гейте `ПередЗаписью` контрагента/договора/документа в `CommonModule.А_СобытияОбъектов` (наш код, переживает регенерацию правил, срабатывает и на загрузке обмена). НЕ править XML, НЕ перепроводить массово. См. [04_profilaktika_chast_a.md](04_profilaktika_chast_a.md).
