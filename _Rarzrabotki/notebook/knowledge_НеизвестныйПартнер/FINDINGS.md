# FINDINGS — детектив-лог расследования «Неизвестный партнер»

Хронология находок (2026-06-16). Цифры — с живой базы BaseERP.

## Ф0. Симптом
Старая внешняя обработка замены: жмёшь «Заменить партнеров» — «Неизвестный» остаётся. Управленческие отчёты по партнёрам массово показывают «Неизвестного».

## Ф1. Полный срез ссылок (НайтиПоСсылкам)
`НайтиПоСсылкам([Неизвестный])` → **305-306 ссылок в 16 объектах**. Сразу видно главное: основная масса — НЕ прямые поля документов, а:
- 65 `КлючиАналитикиУчетаПоПартнерам` (ключи),
- 55 `АналитикаУчетаПоПартнерам` (кэш),
- 70 `РеестрДокументов`.
→ Старое сканирование по типу `Партнеры` их не видело. **Нужен `НайтиПоСсылкам`.**

## Ф2. Архитектура: партнёр в ключах → 23 регистра
`Справочник.КлючиАналитикиУчетаПоПартнерам` (Партнер,Орг,Контр,Договор,Направление) — измерение в 23 регистрах накопления (РасчётыСКлиентами/Поставщиками+По*, ДенежныеСредства*, Выручка/Себестоимость, НДС*). Подтверждено grep по `CatalogRef.КлючиАналитикиУчетаПоПартнерам` в `AccumulationRegisters/`.

## Ф3. Связь Партнёры↔Контрагенты
`Контрагент.Партнер → Партнеры`, N:1, односторонняя. `ПолучитьПартнераПоКонтрагенту` = читает `Контрагент.Партнер`. Значит первоисточник — поле контрагента.

## Ф4. «Многие-ко-многим»
15 контрагентов с `Партнер=Неизвестный`; партнёр-тёзка только у 2 («Цмокаленко Н.В.», «Чер»); 1 нашёлся по ЕДРПОУ; 12 — реального партнёра нет (создавать). → Единый `ЗаменитьСсылки(Неизв→ОдинПартнёр)` НЕ годится; нужен резолв per-контрагент.

## Ф5. ★ Первопричина — PCR обмена
`ExchangeRules.xml:1307-1314`: свойство «Партнер» Контрагентов имеет пустой источник + `<ПередВыгрузкой>Значение="НеизвестныйПартнер"`. → Каждый контрагент из обмена получает заглушку. Документы при загрузке (ПослеЗагрузки, ~10414/11481) выводят из контрагента → Неизвестный (fallback). `КонтрагентыПередЗаписью` раньше партнёра не исправлял.

## Ф6. Структуры ОбъектыРасчетов / РеестрДокументов
`ОбъектыРасчетов`: два вида (сделочный по Объекту / остаточный Объект=НЕОПР). Серверные функции поиска эталона: `НайтиНовыйОбъектРасчетов`, `НайтиОбъектРасчетовПоАналитикеУчетаПоПартнерам`.
`РеестрДокументов`: Партнер-измерение, Контрагент=`КлючиРеестраДокументов`, регистратор=Ссылка.
Партийная аналитика: поле `Поставщик`.

## Ф7. Параметры ЗаменитьСсылки
`ОбщегоНазначения.ПараметрыЗаменыСсылок()` → `СпособУдаления`, `УчитыватьПрикладныеПравила`, `ВключатьБизнесЛогику`, `ЗаменаПарыВТранзакции`, `ПривилегированнаяЗапись`. Для RAW (без перепроведения): `СпособУдаления=""/"Пометить"`, `ВключатьБизнесЛогику=Ложь`.

## Ф8. Прогон каскада на «ФОП Чміль» (31 ссылка)
Свёртка ключей: 12 дублей слиты в 1. Остаток по контрагенту = 0. Балансы РСК/РСП в моменте не изменились (но на живой базе Σ дрейфует — сверка ненадёжна).

## Ф9. После формы «Замінити всі»: осталось 171, разбор
Диагностика остатка по метаданным + помечен/непомечен:
```
64  РеестрДокументов            (не обрабатывался движком)
54  КлючиАналитики (ВСЕ помечены) (слиты, но НЕ удалены физически → НайтиПоСсылкам считает)
28  СписаниеБезнал (7 помеч.+21) (партнёр в ТЧ, шапка-контрагент пуста)
14  ЗаявкаНаРасход (непомеч.)
 …
```
→ Статус «Обработан» был **ложным** (ОстатокПоКонтрагенту не проверял РеестрДокументов/ТЧ-документы).

## Ф10. ★ Почему 8 ключей «застряли»
`НайтиПоСсылкам` по каждому застрявшему ключу: 7 держит `АналитикаУчетаПоПартнерам.КлючАналитики` (1 ссылка), 1 — ещё ТЧ документов (СписаниеБезнал/ЗаявкаНаРасход) + РегистраторРасчётов. Эталон есть у всех. **Баг:** `ПеренестиКэшАналитики` писал кэш со СТАРЫМ КлючАналитики → кэш держал помеченный ключ. **Фикс:** КлючАналитики→канонический + удалить освобождённые.

## Ф11. Платежи и РеестрДокументов — не выводится
`РасшифровкаПлатежа`: ОбъектРасчетов=0, шапка-Контрагент пуста, 14 строк «НИЧЕГО». `РеестрДокументов`: 0 регистраторов с выводимым контрагентом. Все 14 СписаниеБезнал — ПометкаУдаления=True. → Это платежи без бизнес-партнёра / навигационный реестр; авто-вывод невозможен (см. [06_ostatok_i_roadmap.md](06_ostatok_i_roadmap.md)).

## Ф12. Валидация фикса кэша (без перепроведения)
На одном застрявшем ключе: кэш-запись перенаправлена на канонический ключ → ключ освобождён (1→0 ссылок) → удалён. Логика подтверждена.
