# 04. Часть A — профилактика (перекрытие источника на ПередЗаписью)

**Цель:** новые данные из обмена больше не получают «Неизвестного». Фикс в НАШЕМ модуле `CommonModule.А_СобытияОбъектов` (переживает регенерацию правил обмена; срабатывает и при загрузке обмена — подписки `ПередЗаписью` отрабатывают независимо от `ОбменДанными.Загрузка`).

**Статус: ВНЕДРЕНО** (загружено в конфигурацию `/db-load-xml -Mode Partial` + `/db-update -Dynamic+`, smoke PASS).

## Подписки событий (срабатывают и на обмене)

| Подписка (EventSubscription) | Событие | Источник (выдержка) | Обработчик |
|---|---|---|---|
| `А_ДоработкаСправочникиПередЗаписью` | BeforeWrite | Контрагенты, ДоговорыКонтрагентов, Партнеры, … | `А_СобытияОбъектов.А_ДоработкаСправочникиПередЗаписью` |
| `А_ДоработкаДокументыПередЗаписью` | BeforeWrite | СписаниеБезнал, ПоступлениеБезнал, ЗаказПоставщику, ПриобретениеТовУсл, АктВыполненныхРабот, ЗаказКлиента, **ЗаявкаНаРасход** (добавлен), … | `А_СобытияОбъектов.А_ДоработкаДокументыПередЗаписью` |

## 1. КонтрагентыПередЗаписью (диспетчер → процедура `КонтрагентыПередЗаписью`)

После блока ЮрФизЛицо добавлено:
```bsl
// Профилактика: контрагент не должен оставаться с «Неизвестным» партнёром.
Неизв = Справочники.Партнеры.НеизвестныйПартнер;
Если НЕ ЗначениеЗаполнено(Источник.Партнер) ИЛИ Источник.Партнер = Неизв Тогда
    Рек = Новый Структура(
        "Наименование,НаименованиеПолное,ЮрФизЛицо,КодПоЕДРПОУ,НалоговыйНомер,ГоловнойКонтрагент,Партнер",
        Источник.Наименование, Источник.НаименованиеПолное, Источник.ЮрФизЛицо,
        Источник.КодПоЕДРПОУ, Источник.НалоговыйНомер, Источник.ГоловнойКонтрагент, Источник.Партнер);
    НовыйП = А_Привилегированный.ОбеспечитьРеальногоПартнераПоКонтрагенту(Источник.Ссылка, Рек, Истина);
    Если ЗначениеЗаполнено(НовыйП) И НовыйП <> Неизв Тогда
        Источник.Партнер = НовыйП;
    КонецЕсли;
КонецЕсли;
```
> Передаём `Рек` (in-memory реквизиты) — для НОВОГО контрагента стораджа ещё нет, читать `ЗначенияРеквизитовОбъекта(Ссылка)` нельзя.

## 2. ДоговорыКонтрагентовПередЗаписью

После установки ВариантОформленияЗакупок/ХозОперации:
```bsl
Неизв = Справочники.Партнеры.НеизвестныйПартнер;
Если (НЕ ЗначениеЗаполнено(Источник.Партнер) ИЛИ Источник.Партнер = Неизв)
    И ЗначениеЗаполнено(Источник.Контрагент) Тогда
    ПартнерК = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Источник.Контрагент, "Партнер");
    Если ЗначениеЗаполнено(ПартнерК) И ПартнерК <> Неизв Тогда
        Источник.Партнер = ПартнерК;
    Иначе
        Источник.Партнер = А_Привилегированный.ОбеспечитьРеальногоПартнераПоКонтрагенту(Источник.Контрагент, Неопределено, Истина);
    КонецЕсли;
КонецЕсли;
```

## 3. Документный гард — `А_ИсправитьНеизвестногоПартнераВДокументе`

Вызов в начале `А_ДоработкаДокументыПередЗаписью` (после `А_ПроверкаНаРазрешенияПроведенияВУчете`):
```bsl
// ТОЛЬКО на загрузке обмена и только правка поля Партнёр — проведения нет,
// риска для взаиморасчётов (РСППС) нет; движения регенерирует сам обмен.
Если Источник.ОбменДанными.Загрузка Тогда
    А_ИсправитьНеизвестногоПартнераВДокументе(Источник);
КонецЕсли;
```

Процедура обходит ВСЕ реквизиты шапки и строки всех ТЧ типа `Партнеры`; где `= Неизвестный` → выводит партнёра из контрагента строки (`СтрТЧ.Контрагент`) или шапки (`Источник.Контрагент`) через резолвер. Закрывает гонку «документ загружен раньше своего контрагента».

> ⚠️ Гард сознательно ограничен `ОбменДанными.Загрузка` — на интерактивной записи документов он НЕ работает (при загрузке нет проведения → невозможна регрессия РСППС, которую ловили при правках write-пути Приобретения).

## Резолвер (общий для Части A и обработки-чистки)

`CommonModule.А_Привилегированный.ОбеспечитьРеальногоПартнераПоКонтрагенту(КонтрагентСсылка, Реквизиты = Неопределено, Создавать = Истина)` — приоритеты 0-4 (см. [01_partnery_kontragenty_svyaz.md](01_partnery_kontragenty_svyaz.md)). Вспомогательные: `А_ЭтоРеальныйПартнер`, `А_НайтиПартнераПоНалоговым`.
