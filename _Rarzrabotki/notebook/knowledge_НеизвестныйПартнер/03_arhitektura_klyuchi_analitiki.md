# 03. Где хранится партнёр: ключи аналитики → 23 регистра, кэши, ОбъектыРасчётов

## Главное: партнёр в регистрах хранится ЧЕРЕЗ ключ, а не напрямую

```
Документ → проводится → пишет в 23 регистра накопления
                              │
                              │ измерение «АналитикаУчетаПоПартнерам»
                              │ типа СправочникСсылка.КлючиАналитикиУчетаПоПартнерам
                              ↓
              Справочник.КлючиАналитикиУчетаПоПартнерам   ← вот ГДЕ партнёр
                 (денормализует Партнёр + Орг + Контр + Договор + Направление)
```

Поэтому отчёты по партнёрам читают `Регистр.АналитикаУчетаПоПартнерам.Партнер` (через ключ). Сканирование документов по типу `Партнеры` эти регистры НЕ видит. **Только `НайтиПоСсылкам([Неизвестный])` находит ключи и всё, что через них завязано.**

## Справочник.КлючиАналитикиУчетаПоПартнерам

Реквизиты (= сигнатура уникальности ключа):
`Партнер`, `Организация`, `Контрагент`, `Договор`, `НаправлениеДеятельности`.

**23 регистра накопления** используют тип `CatalogRef.КлючиАналитикиУчетаПоПартнерам` как измерение/реквизит:
```
СебестоимостьТоваров, ВыручкаИСебестоимостьПродаж,
РасчетыСКлиентами,  РасчетыСКлиентамиПоСрокам,  РасчетыСКлиентамиПоДокументам,
                    РасчетыСКлиентамиПланОтгрузок, РасчетыСКлиентамиПланОплат,
РасчетыСПоставщиками, РасчетыСПоставщикамиПоСрокам, РасчетыСПоставщикамиПоДокументам,
                     РасчетыСПоставщикамиПланПоставок, РасчетыСПоставщикамиПланОплат,
РасчетыПоЭквайрингу, РасчетыПоФинансовымИнструментам,
ДенежныеСредстваНаличные, ДенежныеСредстваБезналичные,
НДСРеестрВыданныхНалоговыхДокументов, НДСРеестрПолученныхНалоговыхДокументов,
НДСРасчетНалоговыхОбязательств, НДСРасчетНалоговогоКредита,
НДСНоменклатурныйСоставДляНалоговыхНакладных,
НДССоставПоставкиДляРегистрацииВходящихНалоговыхДокументов,
КнигаДоходовРасходовПоЕдиномуНалогу
```

## РегистрСведений.АналитикаУчетаПоПартнерам (КЭШ)

Сопоставление аналитики → партнёр + ключ. ⚠️ `Партнер` здесь **ИЗМЕРЕНИЕ** (не ресурс).

| Поле | Роль | Тип |
|---|---|---|
| `Партнер` | **измерение** | СправочникСсылка.Партнеры |
| `Организация`, `Контрагент`, `Договор`, `НаправлениеДеятельности` | измерения | … |
| `КлючАналитики` | **ресурс** | СправочникСсылка.КлючиАналитикиУчетаПоПартнерам |

**Следствие:** партнёра в кэше нельзя поменять «на месте» (он в ключе записи) — нужно удалить старую запись и записать новую с `Партнер=цель`. И при этом `КлючАналитики` надо ставить на **канонический** ключ (см. грабли в [LESSONS.md](LESSONS.md)).

## Партийная аналитика (поле называется «Поставщик»!)

Параллельная система для партий ТМЦ:
- `Справочник.КлючиАналитикиУчетаПартий` — поле партнёра **`Поставщик`** (НЕ «Партнер»). Сигнатура: `Поставщик, ГруппаФинансовогоУчета, Контрагент, НалоговоеНазначение, СтавкаНДС, ВидЦенности, КодСтроки`.
- `РегистрСведений.АналитикаУчетаПартий` — измерение **`Поставщик`** + ресурс `КлючАналитики` → `КлючиАналитикиУчетаПартий`.

> ⚠️ Запрос `... ГДЕ Партнер=&P` к партийным объектам падает «Поле не найдено Партнер» — там поле `Поставщик`.

## Справочник.ОбъектыРасчетов (два вида)

Идентичность включает Партнёра → при замене партнёра возникает дубль → нужна **свёртка**.

| Вид | Признак | Сигнатура уникальности | Функция поиска эталона |
|---|---|---|---|
| **Сделочный** | `Объект` заполнен (сделка/документ) | Объект, Организация, Контрагент, Партнер, ТипРасчетов | `ОбъектыРасчетовСервер.НайтиНовыйОбъектРасчетов(Реквизиты)` |
| **Остаточный** | `Объект = НЕОПРЕДЕЛЕНО`, `ТолькоОстатки` | Организация, Партнер, Контрагент, Договор, НаправлениеДеятельности, ТипРасчетов, Валюта | `ОбъектыРасчетовСервер.НайтиОбъектРасчетовПоАналитикеУчетаПоПартнерам(Параметры)` |

`ОбъектыРасчетов` ссылается масса регистров (РасчётыСКлиентами/Поставщиками через `ОпределяемыйТип.ОбъектРасчетов*` + легаси-колонки `УдалитьЗаказ`/`УдалитьОбъектРасчетов` в ДенежныеСредства/НДС/ДвиженияКонтрагентДоходыРасходы — см. `ОбъектыРасчетовСервер.ТекстПоискаВРегистрахНакопления`).

## РегистрСведений.РеестрДокументов (навигационный реестр)

`Партнер` — **измерение**. НО: `Контрагент` здесь типа `Справочник.КлючиРеестраДокументов` (не Контрагенты!), а регистратор — `Ссылка` (документ). **Контрагент для вывода партнёра напрямую не достаётся** (см. [06_ostatok_i_roadmap.md](06_ostatok_i_roadmap.md)). Это реестр для навигации/«Реестр документов», не учётные суммы.

## Движок замены/свёртки = `ОбщегоНазначения.ЗаменитьСсылки`

Как в типовой «ПоискИУдалениеДублей» (`Обработки.ПоискИУдалениеДублей`, вызывает `ОбщегоНазначения.ЗаменитьСсылки(ПарыЗамен, Параметры)`):

```bsl
Соотв = Новый Соответствие;  Соотв.Вставить(старыйКлюч, эталонКлюч);
Парам = ОбщегоНазначения.ПараметрыЗаменыСсылок();
Парам.СпособУдаления      = "Пометить";   // "" | "Пометить" | "Удалить"
Парам.ВключатьБизнесЛогику = Ложь;          // RAW, БЕЗ перепроведения
ОбщегоНазначения.ЗаменитьСсылки(Соотв, Парам);
```

`ЗаменитьСсылки` заменяет ссылку во ВСЕХ местах (ТЧ документов, измерения регистров), суммируя движения накопления — без перепроведения. Это решает и «многие-ко-многим» по ключам, и свёртку дублей.

> Параметры (`ОбщегоНазначения.ПараметрыЗаменыСсылок()`): `СпособУдаления`, `УчитыватьПрикладныеПравила`, `ВключатьБизнесЛогику`, `ЗаменаПарыВТранзакции`, `ПривилегированнаяЗапись`.
