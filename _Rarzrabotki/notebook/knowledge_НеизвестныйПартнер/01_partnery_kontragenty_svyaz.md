# 01. Связь Партнёры ↔ Контрагенты

## Направление и кардинальность

```
Справочник.Контрагенты.Партнер ──→ Справочник.Партнеры
        (реквизит, тип СправочникСсылка.Партнеры)

   • Связь ОДНОСТОРОННЯЯ: у Партнеры обратной ссылки на контрагентов НЕТ.
   • Кардинальность N:1 — у партнёра может быть несколько контрагентов
     (юрлиц), у контрагента — ровно один партнёр.
```

Это ключевой факт: **«какому партнёру принадлежит контрагент» определяется только полем `Контрагент.Партнер`**. Заглушка «Неизвестный» — это просто значение этого поля, проставленное обменом, когда реального партнёра нет.

## Канонический вывод партнёра по контрагенту

`CommonModule.ДенежныеСредстваСервер.ПолучитьПартнераПоКонтрагенту(Контрагент, ХозяйственнаяОперация = Неопределено)` (стр. 1517):

```bsl
// упрощённо: читает Контрагент.Партнер + проверяет флаг по типу хозоперации
ВЫБРАТЬ РАЗРЕШЕННЫЕ Контрагенты.Партнер
ИЗ Справочник.Контрагенты КАК Контрагенты
ГДЕ Контрагенты.Ссылка = &Контрагент
  И (ВЫБОР
       КОГДА &ХозОперация В (ПоступлениеОплатыОтКлиента, ВозвратОплатыКлиенту)
            ТОГДА Контрагенты.Партнер.Клиент
       КОГДА &ХозОперация В (ПеречислениеТаможне, ...Кредиты/Депозиты/Займы...)
            ТОГДА Контрагенты.Партнер.ПрочиеОтношения
       ИНАЧЕ Контрагенты.Партнер.Поставщик
     КОНЕЦ ИЛИ &ХозОперация = НЕОПРЕДЕЛЕНО ИЛИ &ИспользоватьПартнеровКакКонтрагентов)
```

**Вывод:** функция возвращает `Контрагент.Партнер`, но с проверкой флага (Клиент/Поставщик/ПрочиеОтношения) по характеру операции. Если партнёр контрагента = «Неизвестный», она вернёт «Неизвестного» — и документ при загрузке унаследует заглушку. Поэтому фикс должен быть на уровне САМОГО контрагента.

## Структура Справочник.Партнеры (ключевые реквизиты)

| Реквизит | Тип | Назначение |
|---|---|---|
| `Наименование` | Строка | Рабочее наименование |
| `НаименованиеПолное` | Строка | Публичное наименование |
| `Родитель` | СправочникСсылка.Партнеры | Иерархия/группа |
| `Клиент` | Булево | Признак — клиент |
| `Поставщик` | Булево | Признак — поставщик |
| `ПрочиеОтношения` | Булево | Прочие отношения (кредиты/депозиты/займы) |
| `Конкурент`, `Перевозчик` | Булево | Прочие роли |
| `ЮрФизЛицо` | Перечисление.**КомпанияЧастноеЛицо** (Компания / ЧастноеЛицо) | Юр/физ |
| `А_Подразделение` | Справочник.СтруктураПредприятия | Кастомное (партнёр-подразделение) |
| `А_Организация` | Справочник.Организации | Кастомное |

## Структура Справочник.Контрагенты (ключевые реквизиты)

| Реквизит | Тип | Назначение |
|---|---|---|
| `Наименование` | Строка | Рабочее наименование |
| `Партнер` | СправочникСсылка.Партнеры | **связь с партнёром** |
| `ГоловнойКонтрагент` | СправочникСсылка.Контрагенты | Иерархия контрагентов (филиалы) |
| `ЮрФизЛицо` | Перечисление.**ЮрФизЛицо** (ЮрЛицо / ФизЛицо / ЮрЛицоНеРезидент / ИндивидуальныйПредприниматель) | Юр/физ |
| `КодПоЕДРПОУ`, `НалоговыйНомер` | Строка | Идентификаторы субъекта |
| `А_ИдКод`, `А_КодПереноса` | Строка | Кастомные коды обмена |

> ⚠️ ДВА РАЗНЫХ перечисления: у Партнёра `КомпанияЧастноеЛицо` (Компания/ЧастноеЛицо), у Контрагента `ЮрФизЛицо` (ЮрЛицо/ФизЛицо/ЮрЛицоНеРезидент/ИндивидуальныйПредприниматель). При создании зеркального партнёра нужно мапить: ФизЛицо/ИП → ЧастноеЛицо, иначе → Компания.

## Создание партнёра кодом — проверенный шаблон

`CommonModule.А_Привилегированный.ОбеспечитьПартнераПоПодразделению` (стр. ~994) — эталон минимально-валидного создания:

```bsl
НовыйПартнер = Справочники.Партнеры.СоздатьЭлемент();
НовыйПартнер.Наименование       = ...;
НовыйПартнер.НаименованиеПолное  = ...;
НовыйПартнер.Родитель            = РодительПартнера;  // группа
НовыйПартнер.Клиент              = Истина;
НовыйПартнер.Поставщик           = Истина;
НовыйПартнер.ПрочиеОтношения     = Истина;            // чтобы проходить все флаговые проверки
НовыйПартнер.ЮрФизЛицо           = Перечисления.КомпанияЧастноеЛицо.Компания;
НовыйПартнер.Записать();
```

Минимум: `Наименование` + `ЮрФизЛицо` + флаги. `ГруппаДоступа`, контактная информация — не обязательны для записи.

## Резолвер «правильного» партнёра (наш)

`CommonModule.А_Привилегированный.ОбеспечитьРеальногоПартнераПоКонтрагенту(КонтрагентСсылка, Реквизиты = Неопределено, Создавать = Истина)` — приоритеты:

1. **`Контрагент.Партнер`**, если уже реальный (≠ Неизвестный, без пометки).
2. **`Контрагент.ГоловнойКонтрагент.Партнер`**, если реальный (филиал наследует партнёра головного).
3. **Партнёр-тёзка** по `Наименованию`.
4. **Партнёр другого контрагента** с тем же `КодПоЕДРПОУ` / `НалоговымНомером` (тот же субъект под другим контрагентом).
5. **Создать зеркального** партнёра по данным контрагента (шаблон выше).

Приоритеты 1-4 переиспользуют существующих партнёров (минимизируют создание дублей); п.5 гарантирует, что контрагент не останется без партнёра.

> На живой базе из 15 «битых» контрагентов: 2 имели партнёра-тёзку, 1 нашёлся по ЕДРПОУ (ХОХЛОВ А.Ю.→«ХОХЛОВ АКІМ ЮРІЙОВИЧ»), 12 потребовали создания зеркального.
