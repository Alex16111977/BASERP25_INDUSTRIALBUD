# LESSONS — грабли по проблеме «Неизвестный партнер»

Уроки, добытые расследованием/реализацией (2026-06-16). Каждый — антипаттерн + как правильно.

## 1. Партнёр в регистрах — через КЛЮЧ, а не напрямую
Сканирование документов по типу `СправочникСсылка.Партнеры` **не находит** партнёра в 23 регистрах — там измерение `КлючиАналитикиУчетаПоПартнерам`. **Правильно:** платформенный `НайтиПоСсылкам([партнёр])` — видит ключи, кэши, регистры, ТЧ. Это единственный полный срез.

## 2. Python COM: сравнение ссылок 1С через `==` НЕ работает
`ref1 == ref2` в Python сравнивает COM-обёртки, не значения ссылок 1С → всегда даёт неверный результат (фильтр «не Неизвестный» молча пропускал всё). **Правильно:** сравнивать по UUID — `erp.String(a.УникальныйИдентификатор()) == erp.String(b.УникальныйИдентификатор())`. См. `_common_neizv.same()`. (Связано с [[python_com_enum_str_gotcha]].)

## 3. `ЗаменитьСсылки` НЕ помечает уже-сироту
`ОбщегоНазначения.ЗаменитьСсылки(дубль→эталон, СпособУдаления="Пометить")` помечает источник, только если ему было что заменять. Если у дубля уже 0 ссылок (предыдущий прогон), он НЕ помечается и остаётся с `Партнер=Неизв` → `НайтиПоСсылкам` его считает. **Правильно:** после `ЗаменитьСсылки` помечать/удалять дубль ЯВНО; гейт «остаток» считать только НЕпомеченные (`И НЕ ПометкаУдаления`).

## 4. ★ Кэш `АналитикаУчетаПоПартнерам`: `КлючАналитики` → КАНОНИЧЕСКИЙ ключ
`Партнер` в этом РС — **измерение**, нельзя менять на месте → удаляем+пишем новую запись. ГЛАВНЫЙ БАГ первой версии: новую запись писали со СТАРЫМ `КлючАналитики` (скопированным из старой) → кэш продолжал держать помеченный ключ → ключ не удалить (8 «застрявших»). **Правильно:** новой записи ставить `КлючАналитики` = канонический ключ (с реальным партнёром, те же измерения, не помечен) через `НайтиКлючПоИзмерениям`. Тогда старый ключ освобождается → удаляем.

## 5. Платёжные ТЧ `РасшифровкаПлатежа` — поле Партнёр БЕЗ контрагента
Запрос `ГДЕ Контрагент=&К И Партнер=&P` по шапке НЕ находит документы, где партнёр в строках ТЧ, а шапка-контрагент пуста. И в самой ТЧ контрагента НЕТ (только Партнер + ОбъектРасчетов). **Следствие:** для многих платежей партнёра вывести не из чего (см. [06_ostatok_i_roadmap.md](06_ostatok_i_roadmap.md)). Не выдумывать партнёра.

## 6. Партийная аналитика: поле называется `Поставщик`, не `Партнер`
`КлючиАналитикиУчетаПартий` и `РС.АналитикаУчетаПартий` хранят партнёра в поле **`Поставщик`**. Запрос `... ГДЕ Партнер=&P` к ним падает «Поле не найдено Партнер». **Правильно:** карта «таблица → имя поля партнёра».

## 7. `РеестрДокументов`: `Партнер` — измерение, `Контрагент` — НЕ Контрагенты
`РеестрДокументов.Контрагент` имеет тип `Справочник.КлючиРеестраДокументов`, а не `Контрагенты`. Контрагент для вывода партнёра берётся из регистратора (`Ссылка`), но у этих регистраторов он часто пуст/тип Организации → не выводится. Это навигационный реестр; чистится перепроведением.

## 8. EPF: `epf-build` НЕ компилирует модуль формы
`LoadExternalDataProcessorOrReportFromFiles` только УПАКОВЫВАЕТ XML→.epf. Ошибки модуля формы вылезают только при ОТКРЫТИИ. (Связано с [[feedback_epf_preflight_open_self]].)
- **Компиляционные:** `Функция СтрНачинаетсяС` — дубль встроенной ГЛОБАЛЬНОЙ функции платформы 8.3.20 → «Процедура или функция с указанным именем уже определена». `&НаКлиенте`-функция, зовущая серверную → «не определена».
- **Рантайм «Поле объекта не обнаружено (X)»:** несуществующий член глобали — `WebЦвета.СинийСтальной` НЕ существует (есть `Синий`/`Серый`/`Красный`/`ЗеленыйЛес`). Ловится пре-флайтом `preflight_epf_refs.py` (COM-резолв членов).

## 9. Перепроведение боевых документов — только пользователь в UI
Авто-массовый `ЗаменитьСсылки` с `ВключатьБизнесЛогику=Истина` (= перепроведение) запрещён (граница проекта; регрессии РСППС/РегистраторРасчётов; защитный гард среды его блокирует). **Правильно:** чистка через `ЗаменитьСсылки` с `ВключатьБизнесЛогику=Ложь` (RAW, без проведения); историю перепроводит пользователь сам. (Связано с [[feedback_user_reposts_history_self]], [[feedback_com_repost_skips_registrator_raschetov]].)

## 10. Правка XML правил обмена — временное решение
`ExchangeRules.xml` генерируется из «Конвертации данных» и перезагружается → правка PCR перезатрётся. **Правильно:** фикс в нашем `А_СобытияОбъектов` (ПередЗаписью) — переживает регенерацию.

## 11. Документный гард — ТОЛЬКО на `ОбменДанными.Загрузка`
Гард `А_ИсправитьНеизвестногоПартнераВДокументе` обёрнут в `Если Источник.ОбменДанными.Загрузка`. На интерактивной записи он НЕ работает → при загрузке нет проведения → нет риска регрессии РСППС в write-пути Приобретения/Реализации. На массовых типовых документах правку write-пути делать осторожно.

## 12. Замена рефов/атрибутов НЕ меняет суммы регистров
`ЗаменитьСсылки` (raw) и правка денормализованного поля Партнёр не трогают ресурсы регистров. Поэтому «сверка баланса до/после» на живой базе ненадёжна (живой дрейф других пользователей); корректность гарантирована построением, а гейт — «НайтиПоСсылкам=0» + «нет дублей по сигнатуре».
