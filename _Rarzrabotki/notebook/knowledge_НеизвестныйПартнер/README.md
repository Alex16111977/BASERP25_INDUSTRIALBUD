# knowledge_НеизвестныйПартнер

База знаний по проблеме партнёра-заглушки **«Неизвестный партнер»** в BAS ERP 2.5 INDUSTRIALBUD: откуда он берётся, как связаны Партнёры с Контрагентами, как перекрыт источник (профилактика) и как чистится история (обработка `Обработки.А_ОбработкаНеизвестногоПартнера`).

**Партнёр-заглушка:** `Справочник.Партнеры`, Наименование «Неизвестный партнер», UUID `7185991a-6ea2-11f0-a2de-bccbaebe2890` (предопределённый `Справочники.Партнеры.НеизвестныйПартнер`).

**Источник заказа:** в управленческих отчётах/балансе по партнёрам массово фигурирует «Неизвестный партнер»; старая внешняя обработка замены «не доводила до конца».

---

## 🎯 Главная находка — причинная цепочка (доказано на коде и живой базе)

```
┌─ ОБМЕН Бух→ЕРП (Конвертация данных 2.x) ────────────────────────────────────┐
│  PCR Контрагентов в ExchangeRules.xml (~стр.1307-1314):                       │
│  свойство «Партнер»: <Источник Имя=""/> + <ПередВыгрузкой>                     │
│       Значение = "НеизвестныйПартнер";                                        │
│  → каждому импортируемому контрагенту БЕЗУСЛОВНО ставится заглушка            │
│    (в Бухгалтерии партнёров нет — есть только Контрагент)                     │
└──────────────────────────────────────────────────────────────────────────────┘
                          ↓
   Контрагент.Партнер = «Неизвестный партнер»
   (обработчик А_СобытияОбъектов.КонтрагентыПередЗаписью раньше это НЕ исправлял)
                          ↓
   Документы при загрузке (ПослеЗагрузки правил, напр. ExchangeRules.xml:10414, 11481):
   ДенежныеСредстваСервер.ПолучитьПартнераПоКонтрагенту(Контрагент) → читает
   Контрагент.Партнер → «Неизвестный»; fallback в правиле явно ставит Неизвестного
                          ↓
   «Неизвестный» расползается через КЛЮЧИ АНАЛИТИКИ
   (Справочник.КлючиАналитикиУчетаПоПартнерам) в 23 регистра накопления,
   в кэши (РС.АналитикаУчетаПоПартнерам), договоры, ОбъектыРасчётов, РеестрДокументов
                          ↓
   Старая обработка искала ТОЛЬКО реквизиты типа СправочникСсылка.Партнеры →
   ключи и регистры через них НЕ видела → «Неизвестный остаётся»
```

**Живой срез `НайтиПоСсылкам([Неизвестный])` (старт расследования): 305-306 ссылок в 16 объектах метаданных.**

## 🔧 Решение — две части

### Часть A — ПРОФИЛАКТИКА (перекрытие источника, ВНЕДРЕНО в конфигурацию)
Гейт `ПередЗаписью` в нашем модуле `CommonModule.А_СобытияОбъектов` (переживает регенерацию правил обмена, срабатывает и при загрузке обмена):
- `КонтрагентыПередЗаписью` / `ДоговорыКонтрагентовПередЗаписью` — если Партнёр пуст/Неизвестный → подставить реального через резолвер;
- `А_ИсправитьНеизвестногоПартнераВДокументе` (вызов в `А_ДоработкаДокументыПередЗаписью`, **только при `ОбменДанными.Загрузка`**) — закрывает гонку «документ раньше контрагента»;
- резолвер `А_Привилегированный.ОбеспечитьРеальногоПартнераПоКонтрагенту`.

**Эффект:** новые данные из обмена больше не получают заглушку. Подробно — [04_profilaktika_chast_a.md](04_profilaktika_chast_a.md).

### Часть B — ЧИСТКА ИСТОРИИ (обработка `Обработки.А_ОбработкаНеизвестногоПартнера`)
- обнаружение через `НайтиПоСсылкам` (видит ключи/регистры);
- резолв реального партнёра по контрагенту;
- замена прямых полей + **свёртка дублей** ключей/`ОбъектыРасчетов` через `ОбщегоНазначения.ЗаменитьСсылки` (как «ПоискИУдалениеДублей»), **без перепроведения**;
- фикс кэша `АналитикаУчетаПоПартнерам.КлючАналитики` на канонический ключ + удаление освобождённых дублей.

Подробно — [05_obrabotka_chistka.md](05_obrabotka_chistka.md).

## ⚖️ Главные принципы (НЕ нарушать)

- **Бухгалтерский/налоговый учёт не трогаем** — меняем только ссылку на партнёра.
- **Перепроведение боевых документов — только пользователь в UI.** Авто-массовый перепровод запрещён (регрессии РСППС/РегистраторРасчётов). Чистка через `ЗаменитьСсылки` с `ВключатьБизнесЛогику=Ложь` (RAW, без перепроведения).
- **Замена ссылок/атрибутов сумм регистров НЕ меняет** (по построению) — балансы сохраняются.
- Партнёрам платежей без бизнес-контрагента (налоги/зарплата/внутренние) **выдуманного партнёра не навязываем** — это была бы порча данных (см. [06_ostatok_i_roadmap.md](06_ostatok_i_roadmap.md)).
