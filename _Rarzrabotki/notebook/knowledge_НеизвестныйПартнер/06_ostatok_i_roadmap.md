# 06. Остаток, который не выводится автоматически + Roadmap полного убирания

## Что остаётся после чистки контрагент-связанных ссылок

После прогона обработки (контрагентные ключи/ОР/мастер-данные/документы исправлены, дубль-ключи слиты+удалены) остаются ссылки, у которых **нет контрагента для вывода партнёра** (доказано диагностиками):

| Объект | Природа | Почему авто-замена невозможна |
|---|---|---|
| `РегистрСведений.РеестрДокументов` | навигационный реестр | у регистратора нет `Контрагент` типа Контрагенты (поле `Контрагент` там — `КлючиРеестраДокументов`); это не учётные суммы |
| `СписаниеБезнал`/`ПоступлениеБезнал`/`ЗаявкаНаРасход` (строки `РасшифровкаПлатежа`) | платежи | в ТЧ НЕТ колонки Контрагент, `ОбъектРасчетов` пуст, шапка `Контрагент` пуста → выводить партнёра не из чего |
| помеченные на удаление документы/договоры (не нашей пометкой) | мусор | уйдут штатной «Удаление помеченных объектов» |
| `РегистрСведений.ИерархияПартнеров` | служебная иерархия партнёра-заглушки | не учётная |

**Вывод:** часть платежей — это операции **без бизнес-партнёра** (налоги, зарплата, внутренние перечисления). Для них «Неизвестный партнер» может быть нормой; навязывать выдуманного партнёра — **порча данных**.

> Диагностика (на момент расследования): из ~46 платёжных строк — 14 «НИЧЕГО» (ни ОР, ни шапки-контрагента); из 64 `РеестрДокументов` — 0 с выводимым контрагентом.

## Roadmap полного убирания «Неизвестного» (для дальнейшей доработки ИИ)

### Шаг 1 — добить контрагент-связанное (готово движком)
Прогнать обработку `Замінити всі`, затем штатное **«Видалення помічених об'єктів»** (удалит слитые дубль-ключи/ОР и помеченные документы, освободив их ссылки на «Неизвестного»).

### Шаг 2 — РеестрДокументов и платёжные документы через ПЕРЕПРОВЕДЕНИЕ (пользователь в UI)
Эти объекты — производные от проведения документов. Если документ **перепровести** (в UI, в сессии 1С Предприятие — НЕ через COM, НЕ массово автономно), его движения (вкл. РеестрДокументов и взаиморасчётные ключи) сформируются заново уже с **исправленным** партнёром контрагента (Часть A гарантирует, что контрагент теперь с реальным партнёром).
- Перечень регистраторов взять из `НайтиПоСсылкам([Неизвестный])` (`Данные.Ссылка` для РеестрДокументов).
- ⚠️ Перепроведение боевых документов — решение и действие пользователя (граница проекта; риск регрессий РСППС/РегистраторРасчётов при неаккуратном перепроведении).

### Шаг 3 — платежи без контрагента: бизнес-решение
Для платежей, где контрагент-партнёр отсутствует по сути (налоги/зарплата/внутренние):
- либо оставить «Неизвестного» (семантически корректно для платежей без партнёра);
- либо завести и назначить выделенного технического партнёра (напр. «Бюджет»/«Внутренние») — по решению финансиста, точечно;
- либо проставить партнёра вручную в конкретных документах.
ИИ НЕ должен сам выбирать — это бизнес-решение.

### Шаг 4 — проверка «ноль»
`НайтиПоСсылкам([Неизвестный])` после Шагов 1-3:
- цель: 0 НЕпомеченных ссылок среди учётных объектов (ключи, ОР, расчёты, кэши, договоры, контрагенты);
- допустимый остаток: платежи без бизнес-партнёра (по решению Шага 3) + сам предопределённый `Справочники.Партнеры.НеизвестныйПартнер` (его не удаляем — на него настроен fallback обмена).

## Идея «самоисцеления» (отвергнута)
Авто-чистку ссылок прямо в `ПриЗаписи` контрагента (НайтиПоСсылкам + каскад внутри транзакции) **не делать** — тяжело, риск блокировок/таймаутов на обмене. Профилактика на `ПередЗаписью` (лёгкая) + пакетная чистка (обработка) — правильное разделение.

## Метрики «здоровья» (для мониторинга)
```sql
-- сколько контрагентов всё ещё с Партнер=Неизвестный (должно стать 0 после Части A на новых)
ВЫБРАТЬ КОЛИЧЕСТВО(Ссылка) ИЗ Справочник.Контрагенты ГДЕ Партнер = &Неизв
-- сколько НЕпомеченных ключей с Неизвестным (учётный носитель; цель 0)
ВЫБРАТЬ КОЛИЧЕСТВО(Ссылка) ИЗ Справочник.КлючиАналитикиУчетаПоПартнерам ГДЕ Партнер = &Неизв И НЕ ПометкаУдаления
```
