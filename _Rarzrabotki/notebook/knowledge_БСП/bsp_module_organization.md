# Организация кода в БСП-стиле (#455 / #469 / #std551 + делегирование)

> Тип файла: ПОСТОЯННЫЙ. Полный вербатим — в `.claude/skills/bas-common-module/reference/module-structure.md`.

---

## 1. Принцип «модуль на объект»

Логика объекта живёт **не** в модуле объекта/формы, а в персональном общем модуле **`А_<Объект>Сервер`**
(всегда; `…Клиент`/`…КлиентСервер` — по необходимости). Модули объекта/менеджера/формы — **тонкие**,
делегируют.

⚠️ **Честный факт:** конвенция «модуль на объект» — **вводимая проектом**. В базе прецедента нет:
кастомные модули (`А_Виробництво`, `А_Привилегированный`, `А_СобытияОбъектов`) её не следуют, а типовые
держат логику в модулях на **подсистему/область** (`ПродажиСервер`, `НоменклатураСервер`). Поэтому
готового `<Документ>Сервер` в конфигурации **не ищи — ты его создаёшь**.

## 2. Регионы (#std455)

| Модуль | Регионы (по порядку) |
|--------|----------------------|
| Общий модуль `А_<Объект>Сервер` | `ПрограммныйИнтерфейс` / `СлужебныйПрограммныйИнтерфейс` / `СлужебныеПроцедурыИФункции` |
| Модуль объекта / менеджера | `ОписаниеПеременных` / `ПрограммныйИнтерфейс` / `ОбработчикиСобытий` / `СлужебныйПрограммныйИнтерфейс` / `СлужебныеПроцедурыИФункции` / `Инициализация` |
| Модуль формы | `ОбработчикиСобытийФормы` / `…ЭлементовШапкиФормы` / `…ЭлементовТаблицыФормы<Имя>` / `ОбработчикиКомандФормы` / `СлужебныеПроцедурыИФункции` |

## 3. Нейминг и флаги (#std469)

| Модуль | Суффикс | Флаги | Когда |
|--------|---------|-------|-------|
| `А_<Объект>Сервер` | `Сервер` | Сервер (Вызов сервера OFF) | всегда |
| `А_<Объект>Клиент` | `Клиент` | Клиент(упр.) | есть клиентская логика формы |
| `А_<Объект>КлиентСервер` | `КлиентСервер` | Клиент+Сервер | расчёт одинаков на клиенте и сервере |
| `А_<Объект>ВызовСервера` | `ВызовСервера` | Вызов сервера ON | редко: клиент зовёт сервер напрямую |

**Жёсткое правило:** ветвление клиент/сервер — **не** через `#Если Клиент` препроцессор, а **разными
модулями** соответствующего типа.

---

## 4. Области видимости (#std551)

Три области по убыванию доступности:
1. `ПрограммныйИнтерфейс` — экспорт для любых внешних потребителей.
2. `СлужебныйПрограммныйИнтерфейс` — экспорт только для модулей этой же библиотеки/подсистемы.
3. `СлужебныеПроцедурыИФункции` — внутри той же подсистемы.

**Следствия:**
- Наш экспорт для формы/менеджера/объекта → `ПрограммныйИнтерфейс` модуля `А_<Объект>Сервер`.
- У **БСП** зови **только `Программный интерфейс`** нужного контекста (`УправлениеСвойствами` /
  `…Клиент` / `…КлиентСервер`). Служебные области БСП **не зови** — обратная совместимость
  гарантирована только для Программного интерфейса; при обновлении БСП сломается.

## 5. Делегирование (тонкие модули → `А_<Объект>Сервер`)

**Документ — модуль объекта (тонкий):**
```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    ПроведениеДокументов.ОбработкаПроведенияДокумента(ЭтотОбъект, Отказ);  // движок пишет движения
КонецПроцедуры
Процедура ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)
    А_<Объект>Сервер.ОбработкаЗаполнения(ЭтотОбъект, ДанныеЗаполнения);     // логика — в общем модуле
КонецПроцедуры
```
**Документ — модуль менеджера (форвардер):**
```bsl
Функция ДанныеДокументаДляПроведения(Документ, Регистры, ДопПараметры) Экспорт
    Возврат А_<Объект>Сервер.ДанныеДляПроведения(Документ, Регистры, ДопПараметры);
КонецФункции
```

- Движения пишет типовой `ПроведениеДокументов` (не трогаем). Запрос движений живёт в `А_<Объект>Сервер`.
- **Конвенция сигнатур:** первый параметр — объект (`ЭтотОбъект`/`Документ`) → тестируемо из COM/обработок.

## 6. Anti-patterns

- Логика inline в модуле объекта/формы → выноси в `А_<Объект>Сервер`.
- `#Если Клиент`-сплит в одном модуле → разные модули по типу.
- Один модуль-«бог» на все объекты → модуль на объект.
- Ручные движения в `ОбработкаПроведения` → делегируй в `ПроведениеДокументов`.
- Вызов служебной области/модуля БСП → только Программный интерфейс (#std551).

## 7. Q&A

**Q: Где искать пример `А_<Объект>Сервер` в базе?** Нигде — это новая конвенция проекта, создаёшь сам.
Эталон-вдохновение — типовые `*Сервер` модули (на подсистему), но мы дробим на объект для изоляции.
**Q: Куда положить запрос движений документа?** В `А_<Объект>Сервер.ДанныеДляПроведения`; менеджер форвардит.
**Q: Можно ли логику проведения писать в модуле объекта?** Нет (кроме делегирующего вызова). Вся логика — в `А_<Объект>Сервер`.
**Q: ОбработкаПроверкиЗаполнения — inline или делегировать?** Оба работают; в `bas-common-module` —
делегирование в `А_<Объект>Сервер`; типовые часто держат inline (допустимо).
