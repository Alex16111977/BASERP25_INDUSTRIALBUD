> **Назначение:** on-disk база знаний о комплекте скилов `bas-*`, которые создают кастомные
> `А_*` документы/справочники, **неотличимые от типовых** (командное меню + подсистемы БСП), и

## Текущее состояние (2026-05-30)

Создан/обновлён комплект из **7 скилов** (2 новых + 5 правок), чтобы новый `А_*` объект был
**неотличим от типового**: командное меню + подсистемы БСП на форме + БСП-стиль организации кода.
Грунт — **1:1 на БСП самой конфигурации** (вербатим из `РеализацияТоваровУслуг`, `Контрагенты`,
`Номенклатура`), без выдумок.

**Сквозная приёмка пройдена:** свежий агент по связке скилов спроектировал новый документ
**без галлюцинаций** (autofill-меню + контракт + `А_<Объект>Сервер` + тонкие модули). Найдены и
закрыты 2 диссонанса (см. `bsp_skills_feedback_loop.md`).

**Ключевой факт меню:** «единое окно» даёт `AutoCommandBar Autofill=true` + контейнеры подменю +
`ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект)` + 4 обработчика `Подключаемый_*`. **Баг
пустого меню** = `Autofill=false` при пустой панели.

## TL;DR (самое важное за 30 секунд)

1. **7 скилов** делают `А_*` объект как типовой: `bas-house-style` (хаб) → `bas-common-module`
   (код) + `bas-bsp-form` (форма/меню); оркестраторы `bas-doc-new`/`bas-catalog-new`/
   `bas-register-new`; гейт `bas-verify`.
2. **«Единое окно»** = интеграция подсистем БСП (ПодключаемыеКоманды, Свойства, Версионирование,
   Файлы, КонтактнаяИнформация) тем же способом, что у типовых → одинаковый интерфейс.
3. **Грунт на реальном коде** конфигурации (Rule #-1): вербатим из типовых объектов, не из памяти.
4. **Конвенция `А_<Объект>Сервер`** (модуль на объект) — **вводимая проектом**; в базе прецедента
   нет (типовые держат логику в модулях на подсистему). Это нормально — её создаёшь, не ищешь.
5. **Эталон меню** `А_ПередачаНачисленийМеждуПодразделениями` — **ТОЛЬКО форма/меню**; его
   проведение пишет движения руками и нет `А_<Объект>Сервер` = legacy, не копировать. Полный
   эталон — `РеализацияТоваровУслуг`; справочник — `Контрагенты`/`Номенклатура`.
6. **Обратная связь = петля приёмки:** дать скил свежему агенту + задачу → проверить вывод →
   зафиксировать пробел → поправить reference скила → повторить (детали в файле 5).
