## 2. Эталон ПРОСТОГО документа = `АмортизацияОС` (ключевая находка)

Для простого документа (шапка Организация/Ответственный/Комментарий, без товарных ТЧ) ближайший типовой
эталон — **`Документ.АмортизацияОС.ФормаДокумента`**, а не товарный `ПриобретениеТоваровУслуг`.

**ВАЖНО — реальный контракт `АмортизацияОС` отличается от идеализированного в первой редакции
`document-contract.md`.** Сверка с живым файлом (Rule #-1: грунт на реальный код, не на память/док):

| Элемент | Идеализированный док (было) | **Реальный `АмортизацияОС`** (взято за истину) |
|---------|------------------------------|------------------------------------------------|
| `CommandSet` | Post/PostAndClose/**SetDeletionMark**/Write (4) | **Post/PostAndClose/Write (3)** — без `SetDeletionMark` |
| Кнопка «Пометка удаления» | отдельная `ФормаУстановитьПометкуУдаленияДокумента` (InAdditionalSubmenu) | **нет отдельной кнопки** — Пометка приходит в «Ещё» автозаполнением |
| `Autofill` формы документа | `false` | **не задан (=true по умолчанию)** — исключённые 3 команды заменены кнопками, остальные (Пометка и пр.) автозаполняются |
| Команда `ПровестиИЗакрыть` | с `<Picture>WriteAndClose` | **без `<Picture>`**, с `<Shortcut>Ctrl+Enter` |
| Команда `ЗаписатьДокумент` | Picture Write + Ctrl+S | так же (Picture Write, Ctrl+S) ✓ |
| Команда `ПровестиДокумент` | Picture Post | так же ✓ |

**Почему это даёт нужный вид без `Autofill=false`:** `CommandSet` глушит ровно те 3 команды
(Post/PostAndClose/Write), которые заменены явными кнопками → нет текстовых дублей «Провести». Остальные
стандартные команды (в т.ч. «Установить пометку удаления») приходят автозаполнением в «Ещё». Итог пиксельно
совпадает с типовым: «Провести и закрыть» (Text+DefaultButton, по Enter), «Записать»/«Провести» иконками.

> Все три формы (`АмортизацияОС`, `А_ФинРез_Баланс`, ретрофит `А_Передача`) теперь несут **идентичный**
> контракт. Консистентность важнее идеализированного описания.

## 3. Контрольные точки (имена — копировать дословно)

**ФормаДокумента (Уровень 1):**
- `CommandSet`: `<ExcludedCommand>` = `Post`, `PostAndClose`, `Write`.
- Кнопки в `AutoCommandBar` (`Autofill` НЕ ставим в false): `ФормаПровестиИЗакрыть`(Type=CommandBarButton,
  Representation=**Text**, **DefaultButton=true**, CommandName=`Form.Command.ПровестиИЗакрыть`);
  `ФормаЗаписать`(Representation=**Picture**, `Form.Command.ЗаписатьДокумент`);
  `ФормаПровести`(Representation=**Picture**, `Form.Command.ПровестиДокумент`).
- Команды (`<Commands>`): `ПровестиИЗакрыть`(Shortcut=Ctrl+Enter, Action=ПровестиИЗакрыть),
  `ЗаписатьДокумент`(Shortcut=Ctrl+S, Picture=StdPicture.Write, Action=ЗаписатьДокумент),
  `ПровестиДокумент`(Picture=StdPicture.Post, Action=ПровестиДокумент). У всех `ModifiesSavedData=true`,
  `CurrentRowUse=DontUse`.
- `<Events>`: только `OnCreateAtServer`→`ПриСозданииНаСервере` и `OnOpen`→`ПриОткрытии` (под чистый модуль
  Уровня 1). **`<Events>` обязан 1:1 совпадать с процедурами модуля** — иначе «обработчик события не найден».
- Модуль: `ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект)` + `ПриОткрытии`(НачатьОбновлениеКоманд) +
  3 обработчика команд (`ОбщегоНазначенияУТКлиент.Записать/Провести/ПровестиИЗакрыть(ЭтаФорма)`) +
  `ВыполнитьКомандуНаСервере` + 4 `Подключаемый_*` (источник `Объект`).
- Шапка без зазора: группы `Representation=None`+`ShowTitle=false`, поля `Объект.Number`/`Объект.Date`.
- Флажок Булево = элемент `<CheckBoxField>` с `<CheckBoxType>Auto</CheckBoxType>` (эталон — `А_ОтчетPL`).

**ФормаСписка:** `CommandSet`(26 исключений 1:1 из `ПриобретениеТоваровУслуг`); форменная панель
`AutoCommandBar id="-1"` `Autofill=false` пустая; меню на панели **таблицы**-списка (`СписокКоманднаяПанель`):
`ПодменюСоздатьНаОсновании`(+3)/`ПодменюОтчеты`(+3)/`ГруппаГлобальныеКоманды`→`ПодменюПечать`/`ГруппаКомандыФормы`;
`OnActivateRow`→`СписокПриАктивизацииСтроки`; модуль источник `Элементы.Список`; `MainTable=Document.А_ФинРез_Баланс`.

## 4. Грабли и находки (для журнала доучивания)

### 4.1 ⭐ Партиальная загрузка НОВОЙ формы: в listFile — ТОЛЬКО обёртка, НЕ Ext-файлы
**Симптом:** `db-load-xml -Mode Partial` падает (exit 1):
`Неизвестный объект метаданных Document.X.Form.ФормаДокумента.Ext`.
**Причина:** в списке файлов перечислены Ext-файлы формы напрямую
(`Documents/X/Forms/ФормаДокумента/Ext/Form.xml` и `.../Ext/Form/Module.bsl`).
**Решение:** для новой формы перечислять **только обёртку** `Documents/X/Forms/ФормаДокумента.xml` —
платформа сама подтягивает Ext-поддерево из иерархической выгрузки. (Так и в примере listFile скила
`db-load-xml`.) Воспроизводилось для **обоих** документов → это про механизм, не про конкретный объект.

```
# ПЛОХО (роняет загрузку):
Documents/А_ФинРез_Баланс/Forms/ФормаДокумента/Ext/Form.xml
Documents/А_ФинРез_Баланс/Forms/ФормаДокумента/Ext/Form/Module.bsl
# ХОРОШО:
Documents/А_ФинРез_Баланс.xml
Documents/А_ФинРез_Баланс/Forms/ФормаДокумента.xml
Documents/А_ФинРез_Баланс/Forms/ФормаСписка.xml
```
Для НОВОЙ формы в списке нужен и **документ-`.xml`** (он регистрирует форму в `ChildObjects` +
`DefaultObjectForm`/`DefaultListForm`), и **обёртка(и) формы**.

### 4.2 `-updateConfigDumpInfo` перегенерирует ВЕСЬ ConfigDumpInfo.xml
После партиальной загрузки `ConfigDumpInfo.xml` изменился на ~37 тыс. строк (`configVersion` у ВСЕХ
объектов, не только наших форм). Это штатно для флага `-updateConfigDumpInfo`. **В фича-коммит не включать** —
это шумный артефакт тулинга, не относящийся к формам. Оставить в рабочем дереве / управлять отдельно.

### 4.3 Кодировка: UTF-8 **BOM** + **CRLF** обязательны
Эталонные файлы конфигурации — UTF-8 с BOM и CRLF. `Copy-Item` и инструмент `Edit` сохраняют их 1:1.
Инструмент `Write` пишет UTF-8 **без BOM** и с **LF** → после Write модуля нужно пересохранить с BOM и
конвертировать LF→CRLF (иначе git ругается LF→CRLF и расходится с конвенцией).

### 4.4 `<Events>` Form.xml ⇆ процедуры модуля
При копии-адаптации эталона с прикладной логикой (`АмортизацияОС`: ДекорацияОшибки, ОрганизацияПриИзменении и
т.п.) — удалить из `<Events>` лишние обработчики (`OnReadAtServer`/`BeforeWriteAtServer`/`AfterWriteAtServer`)
и соответствующие элементы/реквизиты формы, иначе при чистом модуле Уровня 1 платформа не найдёт обработчик.

### 4.5 Формы эталона `А_Передача` были untracked + отсутствовали в базе
`Documents/А_ПередачаНачисленийМеждуПодразделениями/Forms/` в git был `??` (untracked), а в конфигурации
BaseERP формы не были зарегистрированы (документ использовал автоформу). Поэтому для ретрофита грузили
**документ-`.xml` + обе обёртки форм** (а не только изменённую `ФормаДокумента`) — чтобы набор форм документа
стал консистентным.

### 4.6 «Связанные документы» — БСП «ВариантыОтчеты»: менеджер + ОБЯЗАТЕЛЬНАЯ регистрация (3 неверные попытки!)
«Связанные документы» (Ctrl+Shift+S) и контекстные отчёты в меню «Отчёты» зависят **НЕ от формы** и **НЕ от
`CommonCommand.СвязанныеДокументы.CommandParameterType`** — это были ложные пути (стоили 3 неверных попыток:
CommandParameterType; «модуль менеджера сам по себе»; «кэш сессии»). Реальный механизм — БСП-подсистема
**«ВариантыОтчеты»**, нужны **ДВА** условия (оба обязательны):
1. В **модуле менеджера** документа (`Ext/ManagerModule.bsl`):
   `Процедура ДобавитьКомандыОтчетов(КомандыОтчетов, Параметры) Экспорт` →
   `ВариантыОтчетовУТПереопределяемый.ДобавитьКомандуСтруктураПодчиненности(КомандыОтчетов);`.
2. **Регистрация** документа в `ВариантыОтчетовПереопределяемый.ОпределитьОбъектыСКомандамиОтчетов`:
   `Объекты.Добавить(Метаданные.Документы.<Док>);` (рядом с другими кастомными `А_*`).

**Доказательство в коде:** `CommonModule.ВариантыОтчетов` стр.2483-2492 — менеджерский `ДобавитьКомандыОтчетов`
вызывается ТОЛЬКО если `ОбъектыСКомандамиОтчетов().Найти(Метаданные) <> Неопределено`, а этот список =
`ОпределитьОбъектыСКомандамиОтчетов` + `ИнтеграцияПодсистемБСП`. Без п.2 хук не зовётся → команды нет.
**Только п.1 (модуль менеджера без регистрации) НЕ работает.** «Движения документа» — платформенная, от списка
не зависит (поэтому есть всегда). Эталон — `Documents/ПриобретениеТоваровУслуг/Ext/ManagerModule.bsl`
(`ДобавитьКомандыОтчетов`) + регистрация в `ОпределитьОбъектыСКомандамиОтчетов`. **Проверено пользователем —
заработало после п.1+п.2 + F7.** Применять нужно в свежей сессии (динамическое обновление не перестраивает
командный интерфейс уже открытой сессии).

### 4.7 В списке не видно «Проведён»/«Помечен на удаление» — RowPictureDataPath (найдено на smoke)
Форма списка без `<RowPictureDataPath>Список.DefaultPicture</RowPictureDataPath>` на `<Table>` НЕ показывает
пиктограмму состояния документа. `DefaultPicture` — стандартное поле динсписка (значок проведён / не проведён /

Скил §1.3 этого не содержал — **добавлено**. Фикс применён к ФормаСписка `А_ФинРез_Баланс` и `А_Передача`.

## 6. Q&A

**Q: Какой эталон брать для формы простого документа `А_*` (без ТЧ)?**
A: `Документ.АмортизацияОС.ФормаДокумента` — простой документ с готовым явным контрактом. Не товарный
`ПриобретениеТоваровУслуг` (у него ТЧ и прикладная логика).

**Q: Обязательно `Autofill=false` на форме документа?**
A: Нет. Реальный типовой паттерн (`АмортизацияОС`): `Autofill` по умолчанию (true) + `CommandSet`
исключает 3 команды, заменённые кнопками. «Пометка удаления» и пр. приходят автозаполнением в «Ещё».
`Autofill=false` — только у ФОРМЕННОЙ панели формы СПИСКА (там меню на панели таблицы).

**Q: Почему партиальная загрузка новой формы падает «Неизвестный объект … .Ext»?**
A: В listFile перечислены Ext-файлы формы. Нужно перечислять только обёртку `Forms/X.xml` (+ документ-`.xml`).
См. §4.1.

**Q: ConfigDumpInfo.xml изменился на десятки тысяч строк — это баг?**
A: Нет, штатно для `-updateConfigDumpInfo`. В фича-коммит не включать (§4.2).

**Q: Сколько команд в `CommandSet` формы документа — 3 или 4?**
A: **3** (Post/PostAndClose/Write) — как в живом `АмортизацияОС`. `SetDeletionMark` НЕ исключают (иначе без
отдельной кнопки Пометки её негде взять).
