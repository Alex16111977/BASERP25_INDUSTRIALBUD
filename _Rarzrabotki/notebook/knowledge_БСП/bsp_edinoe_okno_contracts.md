# Контракты «единое окно» БСП (документ / справочник)

> Тип файла: ПОСТОЯННЫЙ (меняется при изменении типового эталона или набора подсистем).
> Полный вербатим — в `.claude/skills/bas-bsp-form/reference/{document-contract,catalog-contract}.md`.
> Здесь — суть для понимания и развития.

---

## 1. Что такое «единое окно»

Все типовые документы/справочники выглядят и ведут себя одинаково, потому что **каждый реализует
один и тот же набор контрактов БСП** в форме и менеджере. «Единое окно» = эта интеграция. Скил
`bas-bsp-form` вшивает её в новый `А_*` объект.

Базовый набор подсистем (решение пользователя — «единое окно»):
**ПодключаемыеКоманды** (меню) + **УправлениеСвойствами** (доп. реквизиты) + **ВерсионированиеОбъектов**
+ **РаботаСФайлами** + **СобытияФорм**; справочник дополнительно **УправлениеКонтактнойИнформацией**.

## 2. Командная панель (Form.xml) — корень меню

```xml
<AutoCommandBar name="ФормаКоманднаяПанель" id="-1">
    <Autofill>true</Autofill>
    <ChildItems>
        <Popup name="ПодменюСоздатьНаОсновании">  <!-- + ButtonGroup …Важное/…Обычное/…СмТакже -->
        <Popup name="ПодменюПечать"/>              <!-- без подгрупп -->
        <Popup name="ПодменюОтчеты">               <!-- + …Важное/…Обычное/…СмТакже -->
        <Popup name="ПодменюЗаполнить"/>           <!-- без подгрупп; пункт «Заполнить» -->
    </ChildItems>
</AutoCommandBar>
```

- `Autofill=true` → платформа сама даёт «Провести и закрыть/Записать/Провести/Пометка/Ещё».
- Имена подменю **каноничны** (БСП ищет по имени, менять нельзя). `id` присваивает `form-compile`.
- 🚫 **БАГ пустого меню:** `Autofill=false` при пустой `AutoCommandBar` → не рисуется ничего.
- 🚫 **Меню-контейнеры — ТОЛЬКО в `AutoCommandBar`** (`Popup`/`ButtonGroup`), НИКОГДА `UsualGroup` в теле
  формы. Контейнер в теле латентен пока пуст, но после регистрации документа в
  `ОпределитьОбъектыСКомандамиОтчетов` БСП «ВариантыОтчеты» наполняет `ПодменюОтчеты` → **лишние строки
  меню в карточке** (грабли #14, кейс `case_ozp_perenos_retrofit_menu.md`). Чек ретрофита:
  `name="ПодменюОтчеты"` раньше `</AutoCommandBar>`; после `</AutoCommandBar>` в теле нет `Подменю…`.
- 🚫 **Паритет `<Events>` ⇆ процедуры модуля:** каждый `<Event>` Form.xml обязан иметь `Процедура` в
  модуле, иначе «обработчик события не найден». При ретрофите сверять + трассировать git baseline
  (`git show HEAD:`) — dangling-обработчики живут в выгрузке латентно (грабли #15).

## 3. Документ — порядок вызовов в `ПриСозданииНаСервере`

| # | Подсистема | Вызов | Уровень |
|---|-----------|-------|---------|
| 1 | Свойства | `УправлениеСвойствами.ПриСозданииНаСервере(ЭтаФорма, ДопПараметры)` | 2 |
| 2 | Версионирование | `ВерсионированиеОбъектов.ПриСозданииНаСервере(ЭтотОбъект)` | 2 (только здесь!) |
| 3 | Меню | `ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект)` | **1 (минимум)** |
| 4 | СобытияФорм | `СобытияФорм.ПриСозданииНаСервере(ЭтаФорма, Отказ, СтандартнаяОбработка)` | 2 |
| 5 | Файлы | `РаботаСФайлами.ПриСозданииНаСервере(ЭтотОбъект, ПараметрыГиперссылки)` | 2 |

- **Уровень 1 (минимум — меню):** только п.3 + 4 обработчика (§5). Этого достаточно для меню.
- **Уровень 2 (полное окно):** все 5 + парные вызовы жизненного цикла + обработчики Свойств.

**Справочник** — порядок иной и добавляет КИ: `ВерсионированиеОбъектов` → `УправлениеСвойствами` →
**`УправлениеКонтактнойИнформацией`** → `ПодключаемыеКоманды` → `СобытияФорм`.

## 4. Асимметрия жизненного цикла (соблюдать точно)

| Подсистема | В каких серверных обработчиках вызывается |
|-----------|-------------------------------------------|
| `ВерсионированиеОбъектов` | **только** `ПриСозданииНаСервере` |
| `ПодключаемыеКоманды` | `ПриСоздании` + `ПриЧтении` (`ОбновитьКоманды`) + клиент (`ПриОткрытии`) |
| `УправлениеСвойствами` | `ПриСоздании` + `ПриЧтении` + `ОбработкаПроверкиЗаполнения` + `ПередЗаписью` + клиент |
| `СобытияФорм` | `ПриСоздании` + `ПриЧтении` + `ПослеЗаписи` |
| `РаботаСФайлами` | `ПриСоздании` + клиент (`ПриОткрытии`, `ОбработкаОповещения`) |
| `УправлениеКонтактнойИнформацией` (справочник) | `ПриЧтении` + `ОбработкаПроверкиЗаполнения` + `ПередЗаписью` |

**Первый аргумент намеренно разный:** `ЭтотОбъект` (ПодключаемыеКоманды/Версионирование) vs
`ЭтаФорма` (Свойства/КИ/СобытияФорм) — требование подсистем, не опечатка.

## 5. Обязательные обработчики формы (БСП ищет по имени)

**Меню (документ, паттерн `НачатьВыполнениеКоманды`):**
`ВыполнитьКомандуНаСервере` (&НаСервере) · `Подключаемый_ПродолжитьВыполнениеКомандыНаСервере` (&НаКлиенте, Экспорт) ·
`Подключаемый_ВыполнитьКоманду` (&НаКлиенте) · `Подключаемый_ОбновитьКоманды` (&НаКлиенте).
Третий аргумент везде — главный реквизит формы `Объект`.

> У справочников (Контрагенты) встречается альтернатива: `Подключаемый_ВыполнитьКомандуНаСервере(Контекст, Результат)`.
> Бери **один** паттерн по соответствующему эталону, не смешивай.

**Свойства (Уровень 2):** `СвойстваВыполнитьОтложеннуюИнициализацию` · `Подключаемый_ПриИзмененииДополнительногоРеквизита`
· `Подключаемый_СвойстваВыполнитьКоманду` · `ОбновитьЭлементыДополнительныхРеквизитов`.
**КИ (справочник):** 8 обработчиков `Подключаемый_КонтактнаяИнформация*` → делегаты в `УправлениеКонтактнойИнформациейКлиент.*`.

🚫 Вызвать `ПодключаемыеКоманды.ПриСозданииНаСервере` **без** этих обработчиков → ошибка в рантайме.

## 6. Модуль менеджера — контракты

```bsl
// Версионирование (точка расширения, тело можно пустое):
Процедура ПриОпределенииНастроекВерсионированияОбъектов(Настройки) Экспорт КонецПроцедуры
// Если у объекта есть печатные формы:
Процедура ДобавитьКомандыПечати(КомандыПечати) Экспорт …
// Справочник с запретом редактирования (как Номенклатура):
Функция ПолучитьБлокируемыеРеквизитыОбъекта() Экспорт … // + ЗапретРедактированияРеквизитовОбъектов.ЗаблокироватьРеквизиты(ЭтаФорма) в форме
```

**Контейнеры пусты по умолчанию:** «Печать»/«Отчёты»/«Заполнить» наполняются, только если есть
команды (печатные формы / варианты отчётов / методы менеджера); иначе подменю просто не
показывается — это норма.

## 7. Form.xml — что предопределить под Уровень 2 / справочник

- Пустые группы-контейнеры `ГруппаДополнительныеРеквизиты` (Свойства) и `ГруппаКонтактнаяИнформация` (КИ) —
  имена ровно как в параметре `ИмяЭлементаДляРазмещения`. Содержимое подсистемы создают программно.
- Реквизит формы `ПараметрыПодключаемыхКоманд` с пустым `<Type/>`.

## 8. Эталоны и ⚠️ legacy-оговорка

| Что | Эталон |
|-----|--------|
| Меню документа (наш `А_*`) | `Documents/А_ПередачаНачисленийМеждуПодразделениями/Forms/ФормаДокумента/` |
| Полный документ (форма+проведение+менеджер) | `Documents/РеализацияТоваровУслуг/Forms/ФормаДокумента/` + `Ext/ManagerModule.bsl` |
| Справочник | `Catalogs/Контрагенты/Forms/ФормаЭлемента/` |
| Справочник + запрет редактирования + Файлы | `Catalogs/Номенклатура/Forms/ФормаЭлемента/` |

> ⚠️ **`А_ПередачаНачислений` — эталон ТОЛЬКО формы/меню.** Его `ObjectModule.bsl` пишет движения
> **вручную** (`Движения.X.Записывать=Истина`, циклы), **не** вызывает `ПроведениеДокументов`, и у него
> **нет** `А_<Объект>Сервер`. Это legacy-анти-паттерн (см. `bas-common-module`). Проведение и
> организацию кода с него **не копировать** — бери `РеализацияТоваровУслуг`.

## 9. Q&A

**Q: Минимум, чтобы меню появилось?** `AutoCommandBar Autofill=true` + контейнеры подменю +
`ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект)` + 4 обработчика `Подключаемый_*`.
**Q: Почему у моего документа пустое меню?** Скорее всего `Autofill=false` при пустой панели.
**Q: Где «Заполнить»?** Контейнер `ПодменюЗаполнить` (подсистема ЗаполнениеОбъектов / доп. обработки).
**Q: Чем документ отличается от справочника?** Справочник добавляет `УправлениеКонтактнойИнформацией`
(8 обработчиков + группа КИ) и часто `ПолучитьБлокируемыеРеквизитыОбъекта`.
**Q: Версионирование вызывается в ПриЧтении?** Нет, только в `ПриСозданииНаСервере`.
