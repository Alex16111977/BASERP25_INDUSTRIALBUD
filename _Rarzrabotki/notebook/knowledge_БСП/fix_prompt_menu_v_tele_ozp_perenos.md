# Промт на исправление: «меню в теле документа» — А_ОтражениеЗПпоКазне + А_ПереносДвиженийИзКазны

> Самодостаточный промт для свежего агента (без контекста этой сессии). Дата: 2026-05-31.
> Конфигурация: BAS ERP 2.5 INDUSTRIALBUD, `C:\Configuration_downloads\BASERP25` (база `SQLSERVER\BaseERP`).

---

## ЗАДАЧА

В двух кастомных документах командные меню (Создать на основании / Отчёты / Печать / Глобальные команды / Заполнить) ошибочно лежат в **теле формы**, а не в командной панели. Из-за этого в карточке документа под кнопкой «Провести и закрыть» рисуются лишние строки меню: «Отчеты», «Подменю отчеты см также» и панель кнопок «Движения документа · Места использования · Связанные документы».

Перенести эти меню-контейнеры из тела в `AutoCommandBar`, приведя структуру к эталону типового документа **`Документ.А_ПередачаНачисленийМеждуПодразделениями.Форма.ФормаДокумента`**. После фикса меню должно быть в верхней панели (как у типовых), а тело — только с данными.

**Документы (оба, дефект идентичен):**
- `Documents/А_ОтражениеЗПпоКазне/Forms/ФормаДокумента/Ext/Form.xml`
- `Documents/А_ПереносДвиженийИзКазны/Forms/ФормаДокумента/Ext/Form.xml`

Это **balance-класс** документы: проведение пишет движения напрямую. **ObjectModule.bsl и логику проведения НЕ трогать.** Правки — только в `Form.xml` (раскладка командной панели). Модуль формы (`Form/Module.bsl`) менять не нужно — обработчики уже на месте.

## ОБЯЗАТЕЛЬНО ПРОЧИТАЙ ПЕРЕД КОДОМ (скилы стандартных документов)

Через Skill tool:
- **`bas-house-style`** — конвенции типовых объектов (читать первым).
- **`bas-bsp-form`** + `reference/document-contract.md` **§1.1** — контракт командной панели формы документа: `CommandSet` + кнопки `ФормаПровестиИЗакрыть`/`ФормаЗаписать`/`ФормаПровести` + каноничные контейнеры подменю (`ПодменюСоздатьНаОсновании`+Важное/Обычное/СмТакже, `ПодменюПечать`, `ПодменюОтчеты`+3, `ПодменюЗаполнить`, `ФормаГлобальныеКоманды`).
- **`form-edit`** / **`form-validate`** — точечная правка и валидация управляемой формы (уникальность id, компаньоны, ссылки команд).
- **`db-load-xml`**, **`db-update`** — загрузка в базу.
- **`bas-verify`** — финальный гейт.

Эталон раскладки (грунт, НЕ выдумывать): `Documents/А_ПередачаНачисленийМеждуПодразделениями/Forms/ФормаДокумента/Ext/Form.xml` — у него `ПодменюСоздатьНаОсновании`, `ПодменюПечать`, `ПодменюОтчеты` лежат как `<Popup>` **внутри** `<AutoCommandBar>`, а тело содержит только `ГруппаШапка` + `Pages`. Также сверься с `Documents/А_ФинРез_Баланс/Forms/ФормаДокумента/Ext/Form.xml` (там `ФормаГлобальныеКоманды` = `<ButtonGroup>` с `CommandSource=FormCommandPanelGlobalCommands`).

## ДИАГНОЗ (механизм, проверен)

1. Меню-контейнеры в этих формах объявлены как `<UsualGroup>` в **теле** формы (`<ChildItems>` сразу после `<Events>`), а не как `<Popup>` в `<AutoCommandBar>`. Лежат там с initial commit (латентно, пустые → почти невидимы).
2. Документы зарегистрированы в `ВариантыОтчетовПереопределяемый.ОпределитьОбъектыСКомандамиОтчетов` → БСП-подсистема «ВариантыОтчеты» наполнила `ПодменюОтчеты` командами (Связанные документы / Движения документа / Места использования).
3. Наполненная `UsualGroup` в теле стала видимой → лишние строки меню в карточке.

Правильно (эталон): эти контейнеры — `Popup`/`ButtonGroup` **внутри `AutoCommandBar`**, тогда они рисуются как выпадающие меню панели, «Связанные документы» попадает в выпадающее «Отчёты», а тело чистое.

## ЧТО СДЕЛАТЬ (для КАЖДОГО из 2 документов)

### Шаг 1. Удалить из тела формы (`<ChildItems>` корня формы) меню-контейнеры `UsualGroup`:
- `ПодменюСоздатьНаОсновании` (вместе с подгруппами `…Важное`/`…Обычное`/`…СмТакже`)
- `ФормаГлобальныеКоманды`
- `ПодменюОтчеты` (вместе с `ПодменюОтчетыВажное`/`…Обычное`/`…СмТакже`)
- `ПодменюЗаполнить`

После удаления тело формы должно начинаться сразу с групп данных:
- ОЗП: `ГруппаНомерДата` → `ГруппаШапка` → `Pages ГруппаСтраницы` → `Комментарий`.
- Перенос: `ГруппаШапка` → `Table Движения` → `Комментарий`.

### Шаг 2. Добавить в `<AutoCommandBar name="ФормаКоманднаяПанель" id="-1">` каноничные контейнеры (как у эталона Передачи), СОХРАНИВ всё уже существующее в панели:
- ОЗП — сохранить: кнопки `ФормаПровестиИЗакрыть`/`ФормаЗаписать`/`ФормаПровести`, `Popup ФормаГруппаЗаполнить`, `Popup ФормаГруппаСоздать`, `Button ФормаЗаполнитьВсе`.
- Перенос — сохранить: кнопки `ФормаПровестиИЗакрыть`/`ФормаЗаписать`/`ФормаПровести`, `Button ФормаЗаполнитьИзКазны`, `Button ФормаДвиженияДокумента`.

Добавить (каноничные имена обязательны — БСП ищет по имени):
- `<Popup name="ПодменюСоздатьНаОсновании">` + 3 `<ButtonGroup>`: `ПодменюСоздатьНаОснованииВажное`/`…Обычное`/`…СмТакже`
- `<Popup name="ПодменюПечать">`
- `<ButtonGroup name="ФормаГлобальныеКоманды"><CommandSource>FormCommandPanelGlobalCommands</CommandSource></ButtonGroup>`
- `<Popup name="ПодменюОтчеты">` + 3 `<ButtonGroup>`: `ПодменюОтчетыВажное`/`…Обычное`/`…СмТакже`
- `<Popup name="ПодменюЗаполнить">`

Порядок и атрибуты (Picture у Popup'ов, Representation) — копировать 1:1 из эталона Передачи. Проще всего: взять блоки `<Popup>`/`<ButtonGroup>` из `А_ПередачаНачислений` AutoCommandBar и вставить, переименовав ничего (имена совпадают).

### Шаг 3. Что НЕ трогать
- `<CommandSet>` (Post/PostAndClose/Write) — оставить.
- Команды `<Command>` ПровестиИЗакрыть/ЗаписатьДокумент/ПровестиДокумент и прикладные — оставить.
- `<Events>` — оставить как есть (**ОЗП = 5 событий**, **Перенос = 2**). НЕ добавлять/не удалять события.
- `Form/Module.bsl`, `ObjectModule.bsl`, модуль менеджера, регистрацию в `ВариантыОтчетовПереопределяемый` — НЕ трогать (уже корректны).

## ГРАБЛИ (не наступать)

- **Кодировка:** все XML — **UTF-8 BOM + CRLF**. `form-edit`/Edit сохраняют 1:1; если правишь скриптом — пересохрани с BOM и CRLF (0 одиночных LF).
- **Уникальность `id`:** новым элементам панели дать свободные числовые `id` (например диапазон 9200+), не пересекающиеся с существующими в файле. `form-validate` проверит. (Замечание: `<Command>`/`<Attribute>`/item — разные пространства id; ориентируйся на вердикт `form-validate`, 0 ошибок.)
- **`<Events>` ↔ модуль:** паритет уже корректен (каждый `<Event>` имеет процедуру в модуле). Не сломать его — события не трогаем.
- **Ложное срабатывание `form-validate`:** ошибки вида `attribute '~Список' not found` бывают только в форме **списка** (колонки динсписка) — формы документа это не касается; в форме документа таких быть не должно.
- **Частичная загрузка:** в списке файлов — обёртки `Forms/ФормаДокумента.xml` + документ-`.xml`, НЕ Ext-файлы напрямую. `-updateConfigDumpInfo` перегенерит весь `ConfigDumpInfo.xml` — в фича-коммит НЕ включать.
- **Конфигуратор:** если открыт — `db-load-xml` упадёт. Закрыть Конфигуратор перед загрузкой (или применить F7 в нём).

## ПРОВЕРКА (УСПЕХ НЕ ЗАЯВЛЯТЬ без неё)

1. `form-validate` на обеих `ФормаДокумента` — **0 ошибок** (warning версии 2.13 штатный).
2. Греп-сверка: в `<AutoCommandBar>` присутствуют `ПодменюОтчеты`/`ПодменюСоздатьНаОсновании`/`ПодменюПечать`/`ФормаГлобальныеКоманды`/`ПодменюЗаполнить`; в теле (`<ChildItems>` после `</AutoCommandBar>`/`<Events>`) их БОЛЬШЕ НЕТ.
3. `db-load-xml -Mode Partial` (обёртки форм + документ.xml) + `db-update -Dynamic+` — обе фазы exit 0.
4. **SMOKE пользователем в 1С Enterprise, СВЕЖАЯ сессия** (динамическое обновление не перестраивает открытую): в карточке обоих документов меню «Создать на основании / Печать / Отчёты / Заполнить» — в верхней панели; «Связанные документы» — в выпадающем «Отчёты» (Ctrl+Shift+S); **лишних строк меню в теле документа НЕТ**; «Провести и закрыть» (оранжевая, по Enter) + иконки Записать/Провести на месте.

**Принцип:** при «команда не там / не появляется» — трассировать код БСП и эталон, а не перебирать гипотезы.
