# Применение скилов: как писать промты, чтобы они включились

> Тип файла: ПОСТОЯННЫЙ. Практическая шпаргалка по запуску скилов `bas-*`.

---

## 1. Как скилы включаются

**Механизм — авто по полю `description`.** ИИ читает `description` каждого скила (там триггер-фразы)
и сам подгружает подходящий, когда промт совпадает по смыслу. **Слеш-команда не обязательна** —
достаточно описать задачу обычным языком, употребив триггер-слова.

**Цепочка подтягивается сама:** `bas-doc-new`/`bas-catalog-new` внутри обязывают прочитать
`bas-house-style` + `bas-common-module` + `bas-bsp-form`. Один промт «создай документ» = вся связка.

**Если хочешь наверняка** — назови скил явно: «используй скил `bas-bsp-form`».

## 2. Готовые промты (копируй, меняй имя объекта)

| Задача | Промт | Что включится |
|--------|-------|---------------|
| **Новый документ** | `Создай новый документ А_ЗаявкаНаРасход в типовом стиле, с табличной частью Товары — чтобы у формы было командное меню как у типовых документов` | doc-new → house-style + common-module + bsp-form |
| **Новый справочник** | `Создай справочник А_ВидыРабот как Номенклатура: 4 формы, с контактной информацией, в типовом стиле` | catalog-new (+ связка) |
| **Починить пустое меню** | `У документа А_МойДок на форме нет меню — пустая командная панель. Доделай форму как у типовых` | bsp-form |
| **Куда класть логику** | `Разложи логику документа А_МойДок в БСП-стиле — общий модуль на объект, тонкий модуль объекта` | common-module |
| **Регистр + движения** | `Создай регистр накопления А_МойРегистр и привяжи к нему движения документа А_МойДок` | register-new |
| **Проверка перед коммитом** | `Проверь документ А_МойДок перед коммитом: меню, контракты БСП, валидация, ревью` | bas-verify |

---

## 3. Советы для надёжного срабатывания

- **Назови тип объекта** (документ / справочник / регистр) — это главный триггер оркестратора.
- Добавь **«в типовом стиле»** / **«как у типовых»** / **«с меню как у типовых»** — включит
  house-style + bsp-form.
- Используй **префикс `А_`** в имени нового объекта (проектное правило: `А_` = кастом INDUSTRIALBUD).
- Для формы без меню — слова **«нет меню»**, **«пустая командная панель»**, **«доделай форму»**.
- Скил не подхватился? Допиши явно: **«используй `bas-bsp-form`»** — вызовется принудительно.
- Для расчётных документов (Реализация/Приобретение/ПКО/РКО) добавь **«с взаиморасчётами»** —
  подтянется `bas-doc-fill` (Курс/Кратность, иначе суммы = 0).

## 4. Что произойдёт после запуска (ожидаемый результат)

Для нового документа связка выдаёт:
1. **Метаданные** (`meta-compile`): прикладные реквизиты + ТЧ + `registerRecords` + `WriteSelected`.
2. **Формы** (минимум 3): `ФормаДокумента` с **autofill-панелью + контейнерами подменю** (меню не пустое!),
   `ФормаСписка`, `ФормаВыбора`.
3. **Модуль формы**: вызовы подсистем БСП в `ПриСозданииНаСервере` + обработчики `Подключаемый_*`.
4. **Тонкий модуль объекта**: `ОбработкаПроведения` → `ПроведениеДокументов`; остальное → `А_<Объект>Сервер`.
5. **Общий модуль `А_<Объект>Сервер`**: вся бизнес-логика (регионы #455).
6. **Модуль менеджера**: форвардер `ДанныеДокументаДляПроведения` + контракт версионирования.
7. **Проверка** через `bas-verify`.

Если меню вышло **пустым** — это баг `Autofill=false` при пустой панели; см. `bas-bsp-form` и
`bsp_skills_feedback_loop.md`.

## 5. Q&A

**Q: Нужно ли мне писать `/bas-doc-new`?**
Нет. Достаточно «создай документ … в типовом стиле». Скил включится по смыслу. Слеш — опционально.

**Q: Можно ли запустить только проверку существующего объекта?**
Да: «проверь документ А_X перед коммитом» → `bas-verify` (Python COM запросы, валидация, меню, контракты).

**Q: Как починить уже созданный документ без меню?**
«У документа А_X на форме пустая командная панель — доделай как у типовых» → `bas-bsp-form` вшивает
autofill-панель + `ПодключаемыеКоманды` + обработчики.

**Q: Что если объект не документ/справочник, а регистр?**
«Создай регистр накопления А_X» → `bas-register-new`. Если нужно привязать движения существующего
документа — «привяжи движения документа А_Y к регистру А_X».

## 6. Готовый промт: пакетная БСП-доработка документов (формы + состояние списка + «Связанные документы»)

Выстрадано на `А_ФинРез_Баланс`/`А_Передача` + пакет из 4 документов (2026-05-30). Копируй, подставь свои документы:

```text
ЗАДАЧА: Доработать по БСП «единое окно» документы BAS ERP 2.5: <СПИСОК ДОКУМЕНТОВ А_*>.
Цель каждому: (1) форма документа как у типовых (явные кнопки), (2) пиктограмма состояния
в форме списка, (3) команда «Связанные документы» в меню «Отчёты». Проведение/ObjectModule НЕ трогать.

ОБЯЗАТЕЛЬНО ПРОЧИТАЙ ПЕРВЫМ (опыт-эталон):
- Кейс: _Rarzrabotki/notebook/knowledge_БСП/case_a_finrez_balans_formy.md
- Скилы (Skill tool): bas-bsp-form (+ reference/document-contract.md §1.1 форма документа, §1.3 список +
  RowPictureDataPath + «Связанные документы»), bas-house-style, bas-doc-new, bas-verify.
  Перед кодом документа — consult-notebooklm (Rule #5).

ПО КАЖДОМУ ДОКУМЕНТУ (сначала Golden Sequence: get_metadata_structure — точные реквизиты, НЕ выдумывать):
1. ФормаДокумента (контракт §1.1, эталон простого документа Documents/АмортизацияОС): CommandSet(Post/
   PostAndClose/Write) + кнопки ФормаПровестиИЗакрыть(Text+DefaultButton)/ФормаЗаписать/ФормаПровести(Picture)
   + команды ПровестиИЗакрыть(Ctrl+Enter)/ЗаписатьДокумент(Ctrl+S,Write)/ПровестиДокумент(Post) + обработчики
   ОбщегоНазначенияУТКлиент.* + ПодключаемыеКоманды (источник Объект); <Events>=OnCreateAtServer+OnOpen
   (ДОЛЖНЫ совпадать с модулем); шапка без зазора. Создавать копией-адаптацией (Copy-Item+Edit), НОВЫЙ uuid.
2. ФормаСписка (§1.3, эталон Documents/А_ПередачаНачисленийМеждуПодразделениями/Forms/ФормаСписка):
   CommandSet(26) + Autofill=false форменной + меню на панели ТАБЛИЦЫ; ОБЯЗАТЕЛЬНО
   <RowPictureDataPath>Список.DefaultPicture</RowPictureDataPath> на <Table> (состояние Проведён/Пометка);
   MainTable=свой документ; модуль источник Элементы.Список.
3. «Связанные документы» — БСП «ВариантыОтчеты», нужны ОБА (СТРОГО ВМЕСТЕ, сначала хук, потом регистрация):
   а) Модуль менеджера Ext/ManagerModule.bsl (эталон Documents/ПриобретениеТоваровУслуг):
      #Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда
      #Область ПрограммныйИнтерфейс
      Процедура ДобавитьКомандыОтчетов(КомандыОтчетов, Параметры) Экспорт
          ВариантыОтчетовУТПереопределяемый.ДобавитьКомандуСтруктураПодчиненности(КомандыОтчетов);
      КонецПроцедуры
      #КонецОбласти
      #КонецЕсли
   б) Регистрация документа в ВариантыОтчетовПереопределяемый.ОпределитьОбъектыСКомандамиОтчетов:
      Объекты.Добавить(Метаданные.Документы.<Док>);
4. Если форм не было — зарегистрировать в метаданных: <Form> в ChildObjects + DefaultObjectForm/DefaultListForm.

ГРАБЛИ (стоили нескольких неверных попыток):
- ⚠ РЕГИСТРАЦИЯ БЕЗ ХУКА = RUNTIME-ОШИБКА «Метод объекта не обнаружен (ДобавитьКомандыОтчетов)» при открытии
  ЛЮБОЙ формы документа. Делать п.3а и п.3б вместе, грузить оба ДО открытия формы.
- «Связанные документы» — это «ВариантыОтчеты» (менеджер+регистрация), НЕ CommandParameterType (ложный путь).
  Только хук без регистрации — БСП не вызовет; только регистрация без хука — ошибка.
- Кодировка всех XML/BSL: UTF-8 BOM + CRLF (Copy-Item/Edit сохраняют; Write пишет LF/без BOM → пересохранить).
- <Events> Form.xml ОБЯЗАН совпадать с процедурами модуля.
- Контракт АмортизацияОС: CommandSet=3 (без SetDeletionMark), Autofill НЕ false, ПровестиИЗакрыть без Picture.
- Частичная загрузка: в listFile НОВОЙ формы — обёртка Forms/X.xml + документ.xml, НЕ Ext-файлы. Модуль
  менеджера — Ext/ManagerModule.bsl + документ.xml. -updateConfigDumpInfo перегенерирует весь ConfigDumpInfo —
  в фича-коммит не включать. Если открыт Конфигуратор — db-load-xml падает (блокировка), применять F7 или закрыть.

ПРОВЕРКА (УСПЕХ НЕ ЗАЯВЛЯТЬ без неё): form-validate (0 ошибок) + meta-validate; db-load-xml -Mode Partial +
db-update -Dynamic+; SMOKE пользователем в 1С Enterprise СВЕЖАЯ сессия (динобновление не перестраивает
открытую): красивая «Провести и закрыть» + иконки; пиктограмма состояния в списке; «Отчёты»→«Связанные
документы». Веб-клиент 1С агент вести надёжно не может — визуальное подтверждение за пользователем.
ГЛАВНЫЙ ПРИНЦИП: при «не появляется команда/элемент» — ТРАССИРОВАТЬ КОД БСП (кто/по какому условию вызывает),
а не гадать. Делать по одному документу с smoke-чекпоинтом.
```

**Главный урок порядка (поймали runtime-ошибкой):** «Связанные документы» = БСП «ВариантыОтчеты». Нужны
ОБА — хук менеджера `ДобавитьКомандыОтчетов` И регистрация в `ОпределитьОбъектыСКомандамиОтчетов` — и **строго
вместе**. Регистрация без хука → «Метод объекта не обнаружен (ДобавитьКомандыОтчетов)» при открытии формы.
