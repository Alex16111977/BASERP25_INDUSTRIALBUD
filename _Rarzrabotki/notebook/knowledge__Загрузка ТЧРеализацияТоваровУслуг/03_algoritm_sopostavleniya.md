# 03. Алгоритм сопоставления (`Сопоставить`)

Код — модуль объекта `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг/Ext/ObjectModule.bsl`:
- область «Сопоставление»: `Сопоставить`, `УстановитьВыбор`, `КандидатыИзОстатков`, `КандидатыИзСправочника`, `НовыйКандидат`,
  `ЛучшиеКандидаты`, `ОбъединитьЛучшие`;
- область «СлужебныеПроцедурыИФункции»: `НоменклатураПоКоду`, `ТочнаяНоменклатураВСправочнике`, `СохраненноеСопоставление`,
  `СохранитьСопоставление`, `УстановитьОтборОрганизации`, `ПериодОстатков`;
- экспорт: `ЗабытьСоответствие`, `ДанныеОстатка`, функции-константы `СпособКод()` … `ПорогПодсказки()`.

`Сопоставить` вызывается из `ПрочитатьИСопоставить` (шаг 1 обработки), когда файл уже прочитан в таблицу
([02](02_chtenie_fayla_i_nastroyki.md)). Формула балла «Схожість, %» — в [04](04_metrika_shozhesti.md).

## Конвейер за 30 секунд

Для каждой строки файла шаги проверяются по порядку. **Первый сработавший шаг выигрывает** (`Продолжить`), остальные не
выполняются.

| # | Шаг | Где ищет | «Як знайдено» (`Способ`) | Схожість | ✓ сам |
|---|---|---|---|---|---|
| 1 | Код 1С | `НоменклатураПоКоду` | «За кодом 1С» | 100 | **да** |
| 2 | Запомненный выбор | хранилище «Сопоставление» | «Вибрано раніше» | 100 | **да** |
| 3 | Точная назва среди остатков | ключ `КлючНазвания`, единственная карточка | «Точна назва» | 100 | **да** |
| 4 | Сходство среди остатков | `ЛучшиеКандидаты` по остаткам складов поиска | «Схоже — перевірте» | 60–100 | нет |
| 5а | Точная назва в справочнике | `ТочнаяНоменклатураВСправочнике` | «Точна назва» | 100 | **да** |
| 5б | Сходство по справочнику | `КандидатыИзСправочника` + остатки | «Поза залишками — перевірте» или «Схоже — перевірте» | 60–100 | нет |
| — | Ничего ≥ 60 | — | «Не знайдено — виберіть» | 0 | нет |

- **Автоподтверждение — только шаги 1, 2, 3, 5а.** Подсказки 4 и 5б подтверждает бухгалтер: ✓, двойной клик по
  варианту или кнопка «Підтвердити схожі ≥ 85 %» ([08](08_forma_i_instrukciya.md)).
- Шаги 5а/5б работают, только если включён флажок «Шукати в довіднику, якщо на складах не знайдено»
  (`ИскатьВнеОстатков`, по умолчанию Истина) **и** на остатках нет кандидата с баллом ≥ 60.

**Подготовка перед циклом** (один раз на файл):
1. `КандидатыИзОстатков()` — массив кандидатов с остатком.
2. `ИндексКандидатов(Кандидаты)` — IDF триграмм по этим кандидатам ([04](04_metrika_shozhesti.md)).
3. `СохраненноеСопоставление()` — память выборов.
4. `ПоТочномуКлючу` — Соответствие «ключ названия → **Массив** карточек остатков».

В каждой строке один раз считаются `Ключ = КлючНазвания(Наименование)` и `Признаки = ПризнакиНазвания(Наименование)`.

## Шаг 1. Код 1С

- Работает, только если в строке есть код: задана колонка кода (`КолонкаКод > 0`, по умолчанию **0** — шаг выключен).
- `НоменклатураПоКоду`:
  - `Справочники.Номенклатура.НайтиПоКоду(Код)`;
  - не нашлось и длина < 11 → второй поиск по коду, дополненному нулями слева до 11 знаков:
    `Прав("00000000000" + Код, 11)`.
- Код не нашёлся ни так, ни с нулями → сообщения нет, строка идёт дальше по конвейеру (шаг 2 и т.д.).
- Коды номенклатуры в BuhBud — **11 знаков**. На 09.10.2026 (COM-запрос, без групп) основные форматы —
  `00000019663` (20 546) и `00-00019346` (23 463); есть ещё `БП-…` (36) и `SKU nn` (9) ([FINDINGS](FINDINGS.md)).
  Дополнение нулями спасает только цифровой код, который Excel превратил в число («19663»). Коды `00-…`, `БП-…`,
  `SKU …` надо давать целиком.
- **Код — доверенный источник.** Группа, пометка удаления и похожесть названия не проверяются. Ревью 09.10 рассматривало
  это и признало «не дефектом» ([FINDINGS](FINDINGS.md)).
- Откуда берутся коды: «Excel з кодами 1С» (`ДвоичныеДанныеExcelСКодами`) пишет код **только для строк с ✓**. Раньше код
  писался и для подсказок, и при повторной загрузке они становились «За кодом 1С» с ✓ (ревью №6/№13,
  [07](07_vlozheniya_i_zhurnal.md)).

## Шаг 2. Запомненный выбор

**Хранилище.** `ХранилищеОбщихНастроек`:
- ключ объекта — `ВнешняяОбработка.ЗагрузкаТЧРеализацияТоваровУслуг` (`КлючНастроек()`);
- ключ настройки — `Сопоставление`;
- имя пользователя — `ОбщиеНастройкиЗагрузкиРеализации` (`ПользовательНастроек()`), **общее для всех бухгалтеров**;
- значение — Соответствие «ключ названия → `СправочникСсылка.Номенклатура`».

Чтение и запись чужих настроек идут в `УстановитьПривилегированныйРежим(Истина)` ([LESSONS](LESSONS.md)).

**Поиск в строке:**
1. По новому ключу `КлючНазвания(Наименование)`.
2. Не нашлось → по старому ключу `КлючНазванияДо0910(Наименование)`. Его запись берётся, **только если**
   `РазмерыЕстьВНазвании(Признаки, Запомненное.Наименование)`: каждый размер файла (мультимножество) есть в названии
   карточки. Старый ключ (до 09.10) склеивал числа, «1,5» = «15» (ревью №1/№12), поэтому без проверки размеров он опасен.
3. Карточка с пометкой удаления **не подставляется** — строка идёт дальше по конвейеру.

**Что записывается** (`СохранитьСопоставление`):
- вызывается из `ЗагрузитьВДокумент` **только после успешного `Записать`** документа;
- берутся все строки с ✓ и заполненной номенклатурой, как бы они ни были найдены: по коду, точной назве, вручную,
  подтверждённая подсказка;
- пишутся **только под новым ключом**;
- ошибка записи глотается (`Попытка`): в худшем случае карточки придётся подтвердить ещё раз.

**Что НЕ записывается:** анализ без загрузки, строки без ✓, строки «Знято бухгалтером».

**Забыть.** Кнопка «Забути вибір рядка» → `ЗабытьСоответствие(Наименование)` удаляет **оба** ключа (новый и старый). На
форме строка становится «Знято бухгалтером» без ✓.

**Область действия.** Ключ не зависит от контрагента, организации и документа: одинаковое название из любой накладной
даёт одну и ту же карточку. После загрузки форма показывает строки с ✓ (кроме «За кодом 1С») как «Вибрано раніше»
(`ЗагрузитьВДокументНаСервере`).

## Шаг 3. Точная назва среди остатков

- Кандидат остатков хранит `Ключ = КлючНазвания(Наименование)`. В `ПоТочномуКлючу` под ключом лежит **массив** карточек.
- **Ровно одна карточка** с ключом строки → «Точна назва», 100, ✓.
- **Две и больше** (дубли карточек или совпадение ключей) → автоподтверждения нет. Строка уходит на шаг 4, где обе
  карточки получают одинаковый балл и попадают в варианты (ревью №1).
- Ключ сохраняет границы чисел, поэтому отдельная проверка размеров здесь не нужна. Проверено через `ОценкаПары`
  09.10.2026:

  | Файл | Карточка | Ключ |
  |---|---|---|
  | «Болт M16*55» | «Болт М16х55» | `болт м 16 55` — равны |
  | «Лист 8,0 мм» | «Лист 8мм» | `лист 8 мм` — равны |
  | «Лист г/к 1,5 ст3» | «Лист г/к 15 ст3» | разные |
  | «Лист 1/2» | «Лист 12» | `лист 1 2` ≠ `лист 12` |
  | «Настил решітковий SP 34» | «Решітковий настил SP 34» | разные (порядок слов) — сходство 100 |
  | «Лист 1250*2500*5» | «Лист 5*1250*2500» | разные (порядок чисел) — сходство 100 |

- **Ключ не выбрасывает стоп-слова и не сортирует лексемы.** Переставленные слова или числа точной назвой не считаются. Их
  ловит шаг 4 с баллом 100, но уже без ✓. Устройство ключа — [04](04_metrika_shozhesti.md).

## Шаг 4. Сходство среди остатков

- `ЛучшиеКандидаты(Признаки, Кандидаты, Индекс, 5)`:
  - `ОценкаСходства` считается для **каждого** кандидата остатков;
  - отбрасываются баллы **< 20**;
  - остальные сортируются по убыванию, берутся первые **5**.
- Все пять записываются в таблицу `Варианты`, даже если строку потом найдёт шаг 5а.
- Лучший ≥ `ПорогПодсказки()` = **60** → `УстановитьВыбор(…, «Схоже — перевірте», балл, Подтверждено = Ложь)`, в
  «Пояснення» — пояснение лучшего варианта.
- Лучший < 60 или кандидатов нет → шаг 5 (если флажок), иначе «Не знайдено — виберіть».
- **Равные баллы.** Порядок не гарантирован: `ТаблицаЗначений.Сортировать` не стабильна (ревью №2). У дублей карточек
  выбирайте по колонкам «Залишок» и «Склад залишку» в вариантах.

## Шаг 5. Вне остатков

Запускается при `ИскатьВнеОстатков` и (нет вариантов остатков или лучший < 60).

**5а. Точная назва в справочнике** — `ТочнаяНоменклатураВСправочнике(Наименование)`:
- запрос `ПЕРВЫЕ 2` по `Справочник.Номенклатура`: не группа, не помечена на удаление, `Наименование = &Наименование`;
- сравнивается **сырое название из файла**, а не ключ;
- ровно одна карточка → «Точна назва», 100, ✓;
- варианты остатков из шага 4 остаются в нижней таблице.

**5б. Похожие в справочнике** — `КандидатыИзСправочника(Признаки)`:
1. Нужен **тип изделия** `Признаки.Тип`: первые 4 буквы первого значимого слова от 3 букв с кириллицей, не слова
   стандарта или марки ([04](04_metrika_shozhesti.md)). Тип пустой — кандидатов нет.
2. Запрос `ПЕРВЫЕ 500`: не группа, не помечена на удаление, `Наименование ПОДОБНО "%" + Тип + "%"`. Регистр не мешает:
   смоук 09.10 нашёл «Швелер 20П/У ст.3 пс 5, 12 м» по шаблону `%швел%`.
3. Для этих карточек строится **свой** IDF-индекс, считаются лучшие 5. В начало их пояснения добавляется
   «без залишку; ».
4. `ОбъединитьЛучшие(Лучшие, ЛучшиеСправочника, 5)` сливает два списка: сортировка по баллу, без повторов одной карточки,
   первые 5. Карточка, которая есть в обоих списках, остаётся с бо́льшим баллом: IDF у списков разный, поэтому балл одной
   и той же карточки в них может отличаться.
5. Лучший ≥ 60 → способ по его `Остаток`: > 0 — «Схоже — перевірте», 0 — «Поза залишками — перевірте». У кандидата из
   справочника `Остаток` всегда 0: структура кандидата его не знает.

`ПЕРВЫЕ 500` без сортировки может отрезать нужную карточку. Ревью 09.10 сочло это не дефектом, но исследование предлагает
улучшение ([05](05_issledovanie_metodov.md)).

## Не знайдено

`Способ` = «Не знайдено — виберіть», номенклатура пустая. «Пояснення»:
- «кандидатів немає»;
- или «найкращий N %: <пояснение лучшего>», например «найкращий 49 %: слова 67 %; розміри збіглися: м16; НЕМАЄ розмірів:
  s24».

Варианты с баллом от 20 видны внизу, бухгалтер выбирает из них двойным кликом или в колонке «Номенклатура 1С».

## Кандидаты из остатков (`КандидатыИзОстатков`)

Запрос (дословно, первая часть пакета):

```
ВЫБРАТЬ
	Ост.Субконто1 КАК Номенклатура,
	Ост.Субконто3 КАК Склад,
	СУММА(Ост.КоличествоОстаток) КАК Количество
ПОМЕСТИТЬ ВТОстатки
ИЗ
	РегистрБухгалтерии.Хозрасчетный.Остатки(&Период, , , Субконто3 В (&Склады) И Организация = &Организация) КАК Ост
ГДЕ
	Ост.Субконто1 ССЫЛКА Справочник.Номенклатура
	И (&БезОтбора
			ИЛИ Ост.Субконто1 В (&Номенклатура))
СГРУППИРОВАТЬ ПО
	Ост.Субконто1,
	Ост.Субконто3
ИМЕЮЩИЕ
	СУММА(Ост.КоличествоОстаток) > 0
```

Вторая часть берёт `ВТ.Номенклатура.Наименование`, `ВТ.Номенклатура.Код`, `ВТ.Склад.Наименование`, количество и сортирует
по наименованию и складу.

**Параметры:**

| Параметр | Значение |
|---|---|
| `Период` | `ПериодОстатков()`: `Новый Граница(КонецДня(Документ.Дата), ВидГраницы.Включая)`; без документа — конец текущего дня сеанса |
| `Склады` | колонка табличной части `Склады` — склады поиска ([02](02_chtenie_fayla_i_nastroyki.md)) |
| `Организация` | `Документ.Организация` через `УстановитьОтборОрганизации`. Без документа или организации условие вырезается из текста (`СтрЗаменить`) — остатки всех организаций |
| `БезОтбора`, `Номенклатура` | без отбора — все; с массивом — только он (для `ДанныеОстатка`) |

- **Счёт в условии не задан.** Берутся все счета, где Субконто1 — номенклатура, а Субконто3 — склад из списка. В BuhBud это
  205/209/221.
- **Организация в условии — исправление ревью №7.** BuhBud ведёт несколько своих фирм. Без отбора подсказка и счёт
  остатка могли прийти из чужой организации.
- **Свёртка в BSL.** Кандидат — одна карточка, `Остаток` = сумма по складам. `Склады` — текст «склад количество; …»
  (формат `ЧДЦ=3; ЧРГ=' '; ЧН=0`). Два склада с одинаковым названием видны как два одинаковых имени.
- **Структура кандидата** (`НовыйКандидат`): `Ссылка, Наименование, Код, Ключ, Остаток, Склады` плюс поля
  `ПризнакиНазвания`: `Размеры, Марки, Стандарты, Слова, Триграммы, Тип, Сторона`. `Код` берётся из запроса
  (`ВТ.Номенклатура.Код`, у справочника `Н.Код`) без лишнего чтения объектов. Так колонка «Код 1С» есть и в таблице, и в
  вариантах (коммит ea3812bffc).
- **Цифры на 09.10.2026** (документ ІБ00-000189, склады «Чорноморськ» ×2 и «Чорноморськ Списання»): **487** строк
  «номенклатура × склад» → **429** кандидатов. С отбором по организации и без — те же 487 строк: остатки есть у одной
  организации. Цифры дрейфуют вместе с остатками.
- **Тот же запрос с отбором.** `ДанныеОстатка(Номенклатура)` (экспорт) отдаёт форме остаток и склады карточки при ручном
  выборе (`ДанныеКарточкиНаСервере`).
- Запрос с отбором по организации проверен через Python COM до переноса в BSL (Rule #-1): 487 строк и с организацией, и
  без неё ([09](09_sborka_testy_priemka.md)).

## `УстановитьВыбор` — что пишется в строку

- `Номенклатура`, `КодКарточки` (= `Номенклатура.Код`), `Способ`, `Сходство`, `Подтверждено`.
- `ЕдиницаКарточки` = `Строка(Номенклатура.БазоваяЕдиницаИзмерения)`.
- `Остаток`, `СкладОстатка` — из кандидата остатков с той же ссылкой. Нет на остатках — 0 и пусто.
- Единицы несравнимы (`КоэффициентПересчета` = Неопределено) → «Пояснення»: «одиниці різні: файл «…», картка «…» —
  перевірте кількість».

Для строк «Схоже»/«Поза залишками» `Сопоставить` после этого **перезаписывает** пояснение текстом варианта, и
предупреждение о единицах пропадает. Остаётся оно у строк шагов 1–3 и 5а. При ручном выборе в колонке форма пишет своё
(`ДанныеКарточкиНаСервере`): «одиниця файлу «…», картки «…» (т ↔ кг перераховується)», а двойной клик по варианту
ставит пояснение варианта. При загрузке предупреждение выдаётся в любом случае ([06](06_zagruzka_v_dokument.md)).

После `Сопоставить` функция `ПрочитатьИСопоставить` копирует `Номенклатура/Способ/Сходство` в
`АвтоНоменклатура/АвтоСпособ/АвтоСходство`. Это предложение обработки до вмешательства бухгалтера, оно идёт в журнал
([07](07_vlozheniya_i_zhurnal.md)).

## Варианты

- Таблица `НоваяТаблицаВариантов`: `НомерСтроки, Номенклатура, КодКарточки, Сходство, Остаток, Склад, Пояснение`. До
  **5 на строку**, баллы ≥ 20.
- **Считаются только у строк, дошедших до шага 4.** У строк шагов 1–3 нижняя таблица пустая.
- Смоук 09.10.2026: 84 строки → **310** вариантов.
- На форме внизу: «Номенклатура 1С | Код 1С | Схожість, % | Залишок | Склад залишку | Чому запропоновано». Двойной клик
  (`КандидатыВыбор`) → «Вибрано вручну» с ✓ ([08](08_forma_i_instrukciya.md)).

## Способы и пороги

| «Як знайдено» | Функция | ✓ | Схожість | Кто ставит |
|---|---|---|---|---|
| За кодом 1С | `СпособКод()` | да | 100 | шаг 1 |
| Вибрано раніше | `СпособЗапомнено()` | да | 100 | шаг 2; форма после загрузки |
| Точна назва | `СпособТочно()` | да | 100 | шаги 3 и 5а |
| Схоже — перевірте | `СпособПохоже()` | нет | 60–100 | шаги 4/5б, лучший с остатком |
| Поза залишками — перевірте | `СпособВнеОстатков()` | нет | 60–100 | шаг 5б, лучший без остатка |
| Не знайдено — виберіть | `СпособНеНайдено()` | нет | 0 | ничего ≥ 60 |
| Вибрано вручну | форма `СпособВручную()` | да | 100 или балл варианта | выбор в колонке (100), двойной клик по варианту (его балл), ✓ заново у «Знято бухгалтером» (балл не меняется), перенос ручного выбора при повторном анализе (100) |
| Знято бухгалтером | форма `СпособСнято()` | нет | без изменений | сняли ✓ или «Забути вибір рядка» |

**Тексты способов — это ключи.** По ним работают:
- условное оформление (цвета строк, `ОформитьСпособ`);
- кнопка подтверждения (сравнение со `СпособПохоже()`);
- перенос ручного выбора при повторном анализе (сравнение со `СпособВручную()`, `ПрочитатьФайлНаСервере`);
- повторная ✓ у снятой строки (сравнение со `СпособСнято()`, `РаспознаваниеПодтвержденоПриИзменении`);
- переименование в «Вибрано раніше» после загрузки (все ✓, кроме `СпособКод()`, `ЗагрузитьВДокументНаСервере`);
- журнал ([07](07_vlozheniya_i_zhurnal.md)).

Фильтр-переключатель над таблицей (реквизит `Показать`: «Усі / Потребують рішення / Не знайдено / Підтверджені») от
текста не зависит: он смотрит колонку `Группа`, которую заполняет `ОбновитьИтогиФормы`. Поменяли текст — проверьте форму
([08](08_forma_i_instrukciya.md)).

| Порог | Значение | Где в коде |
|---|---|---|
| Вариант попадает в список | ≥ 20 | `ЛучшиеКандидаты` |
| Подсказка подставляется в строку | ≥ 60 | `ПорогПодсказки()` |
| Кнопка «Підтвердити схожі ≥ 85 %» | ≥ 85, только «Схоже — перевірте», без ✓ | `ПодтвердитьСхожиеНаСервере` (модуль формы) |
| Вариантов на строку | 5 | `Сопоставить` |
| Кандидатов справочника на строку | `ПЕРВЫЕ 500` | `КандидатыИзСправочника` |

- Кнопка не трогает «Поза залишками — перевірте», «Знято бухгалтером» и строки, где выбор забыли (ревью №11).
- Другая марка или стандарт ограничивают балл **75** ([04](04_metrika_shozhesti.md)). Такие подсказки никогда не
  подтверждаются кнопкой, только вручную.

## Что не ломать

- **Порядок шагов и правило «точно только 1–3 и 5а».** Автоподтверждение по сходству (даже 100) обходит проверку
  бухгалтера.
- **Ключ памяти.** Новая функция ключа делает старую память невидимой. Старую функцию надо заморозить, как
  `КлючНазванияДо0910`, и читать ею с проверкой размеров. Писать — только новым ключом.
- **`ПоТочномуКлючу` — массив.** С `Вставить` одной карточки выигрывает последняя по алфавиту, это ревью №1/№12.
- **Колонки `НоваяТаблицаРаспознавания`/`НоваяТаблицаВариантов` = колонки реквизитов формы.** Иначе
  `ЗначениеВРеквизитФормы` падает «параметр номер '2'» ([LESSONS](LESSONS.md)).
