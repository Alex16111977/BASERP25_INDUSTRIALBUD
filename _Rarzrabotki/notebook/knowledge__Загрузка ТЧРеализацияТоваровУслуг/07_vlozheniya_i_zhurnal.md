# 07. Вложения документа и журнал сопоставления; Excel с кодами

Код: модуль объекта `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг/Ext/ObjectModule.bsl` — функции
`ПрикрепитьФайлыЗагрузки`, `ПрикрепленныеФайлы`, `СтрокиЖурнала`, `ДвоичныеДанныеЖурнала`, `ДвоичныеДанныеExcelСКодами`,
процедуры `ДобавитьПрисоединенныйФайл`, `ОбновитьПрисоединенныйФайл`. В модуле формы — команда `ВыгрузитьВExcel`.

## Зачем вложения

Пользователь (09.10.2026): после загрузки файл должен прикрепляться к документу. Нужна **история**: по каким файлам шла
загрузка и как бухгалтер вручную подбирал наименования. Позже это **материал для обучения** алгоритма.

Отсюда две вещи в «Приєднаних файлах» документа (БСП, справочник `РеализацияТоваровУслугПрисоединенныеФайлы`):

| Вложение | Имя | Что внутри |
|---|---|---|
| Исходный файл накладной | имя файла как у бухгалтера (`Специфікація з АСУБЗ.xls`) | байты файла как есть |
| Журнал сопоставления | `Журнал зіставлення <имя файла без расширения>.xlsx` | по строке файла: автоподбор обработки, выбор бухгалтера, 21 колонка |

## Политика «середина»: один исходный файл, один обновляемый журнал

**Что было.** Первая версия добавляла при каждой загрузке копию накладной и новый журнал с меткой времени в имени.
После трёх загрузок у документа было **6 вложений**: 3 копии накладной и 3 журнала. Пользователь прислал скриншот:
«слишком много вложений… бухгалтер понажимает — будет много вложений, но нужен материал для исследования, найди
середину».

**Решение 09.10:**
- **Исходный файл — один.** Тот же файл (имя + расширение + размер) повторно не добавляется. Файл с тем же именем, но
  другим размером обновляется **на месте** (новая версия того же вложения, без новой копии).
- **Журнал — один на документ и имя файла.** При повторной загрузке он обновляется со **слиянием**:
  - «Автопідбір» остаётся **с первой загрузки** — это то, что предложила обработка до вмешательства бухгалтера;
  - «Обрано» — последний выбор;
  - «Завантажень» — сколько раз грузили.

→ Шума нет (вложений не больше двух на файл), а данные для калибровки не теряются.

## Порядок вызова

`ЗагрузитьВДокумент` (модуль объекта):
1. проверки, блокировка, `ЗаполнитьТоварыДокумента`, `ДокОбъект.Записать(РежимЗаписиДокумента.Запись)`;
2. `СохранитьСопоставление(Таблица)` — запоминание выбора ([03](03_algoritm_sopostavleniya.md));
3. `ПрикрепитьФайлыЗагрузки(Документ, Таблица, АдресФайла, ИмяФайла)`.

**Вложения идут после записи документа и вне его транзакции.** Ошибка прикрепления не откатывает загрузку:
`ПрикрепитьФайлыЗагрузки` вся в `Попытка` и возвращает текст ошибки. `ЗагрузитьВДокумент` дописывает его в
`Предупреждения`: «Файли до документа не прикріплено: …». Товары при этом уже записаны.

## `ПрикрепитьФайлыЗагрузки` — по шагам

1. `Момент = ТекущаяДатаСеанса()`, `Автор = Пользователи.ТекущийПользователь()`.
2. Из `ИмяФайла` выделяются имя без расширения и расширение (по последней точке; нет точки — `xlsx`). Путь отрезается
   по последнему `\` или `/`.
3. `ИмяЖурнала = "Журнал зіставлення " + ИмяБезРасширения`.
4. `Прикрепленные = ПрикрепленныеФайлы(Документ)`.
5. **Журнал.**
   - Ищется в `Прикрепленные` по ключу `НРег(ИмяЖурнала + ".xlsx")`.
   - Найден — `СтрокиЖурнала(ссылка)` читает прежние строки; нет — пустое соответствие.
   - `ДвоичныеДанныеЖурнала(...)` строит новый xlsx и заполняет `Итоги` (Загружено, Исправлено, Загрузок).
   - Описание вложения: «Завантаження з Excel: N-й раз, останнє dd.MM.yyyy HH:mm (Користувач). Рядків R, завантажено
     Z, виправлено бухгалтером V (проти першого автопідбору).»
   - Журнала не было — `ДобавитьПрисоединенныйФайл`; был — `ОбновитьПрисоединенныйФайл`.
6. **Исходный файл** — только если `ЭтоАдресВременногоХранилища(АдресФайла)`.
   - Размер = `ПолучитьИзВременногоХранилища(АдресФайла).Размер()`.
   - Ищется по `НРег(ИмяБезРасширения + "." + Расширение)`.
   - Нет — добавить с описанием «Вихідний файл накладної. » + описание журнала.
   - Есть, но `Размер` другой — `ОбновитьПрисоединенныйФайл`.
   - Есть и размер тот же — **ничего не делается** (описание исходного файла тоже не обновляется, обновляется только
     описание журнала).

**Признак «тот же файл» = имя + расширение (без учёта регистра) + размер в байтах.** Содержимое не хэшируется.

## `ПрикрепленныеФайлы` — какие вложения видит обработка

Запрос к `Справочник.РеализацияТоваровУслугПрисоединенныеФайлы`:
- `ВладелецФайла = &Документ`, `НЕ ПометкаУдаления`;
- `УПОРЯДОЧИТЬ ПО ДатаСоздания`.

Результат — `Соответствие`: «имя.расширение» в нижнем регистре → `Структура(Ссылка, Размер)`. При одинаковых именах
выигрывает **самое новое** (последний `Вставить` перезаписывает ключ).

Помеченные на удаление вложения не видны. Если бухгалтер пометил журнал на удаление, следующая загрузка создаст новый
журнал, и «Автопідбір» начнётся заново.

## Добавление и обновление через БСП

**`ДобавитьПрисоединенныйФайл(Владелец, Автор, ИмяБезРасширения, Расширение, Адрес, Описание)`** — обёртка над
`РаботаСФайлами.ДобавитьФайл(ПараметрыФайла, Адрес, , Описание)`. `ПараметрыФайла`:

| Ключ | Значение |
|---|---|
| `Автор` | текущий пользователь |
| `ВладелецФайлов` | документ реализации |
| `ИмяБезРасширения` | имя |
| `РасширениеБезТочки` | `xls` / `xlsx` |
| `ВремяИзмененияУниверсальное` | `ТекущаяУниверсальнаяДата()` — **обязательно** |

Без `ВремяИзмененияУниверсальное` БСП падала: «Поле объекта не обнаружено (ВремяИзмененияУниверсальное)». БСП читает
ключ без проверки наличия ([LESSONS](LESSONS.md)). Третий параметр `ДобавитьФайл` (адрес текста для полнотекстового
поиска) не передаётся.

**`ОбновитьПрисоединенныйФайл(ПрисоединенныйФайл, Адрес, Описание)`:**
- `РаботаСФайлами.ОбновитьФайл(ПрисоединенныйФайл, Структура("АдресФайлаВоВременномХранилище, АдресВременногоХранилищаТекста", Адрес, ""))`;
- описание меняется отдельной записью объекта файла, только если отличается.

**Хранение.** В BuhBud файлы БСП лежат **в базе**, томов нет. Поэтому откат транзакции в тесте убирает и вложения
(`tx_test2.py`, [09](09_sborka_testy_priemka.md)).

## Журнал сопоставления: формат (21 колонка)

Строится `ДвоичныеДанныеЖурнала(Таблица, Автор, Момент, ДокументСсылка, Предыдущие, Итоги)` как `ТабличныйДокумент` →
`Записать(..., ТипФайлаТабличногоДокумента.XLSX)`. Строка 1 — заголовки, далее по строке на **каждую** строку таблицы
сопоставления (и загруженные, и нет).

| № | Заголовок | Откуда |
|---|---|---|
| 1 | Рядок файлу | `НомерСтроки` — номер строки в Excel-файле |
| 2 | Назва з файлу | `Наименование` |
| 3 | Кількість | `Количество`, формат `ЧРД=,; ЧГ=0` |
| 4 | Од. | `Единица` (из файла) |
| 5 | Ціна без ПДВ | `Цена` |
| 6 | Сума без ПДВ | `Сумма` |
| 7 | Автопідбір: номенклатура | первая загрузка: `Строка(АвтоНоменклатура)` |
| 8 | Автопідбір: код | первая загрузка: `АвтоНоменклатура.Код` |
| 9 | Автопідбір: спосіб | первая загрузка: `АвтоСпособ` |
| 10 | Автопідбір: схожість, % | первая загрузка: `АвтоСходство` |
| 11 | Обрано: номенклатура | текущая `Номенклатура` |
| 12 | Обрано: код | текущая `Номенклатура.Код` |
| 13 | Обрано: спосіб | текущий `Способ` |
| 14 | Завантажено | «так», если `Подтверждено` и есть карточка |
| 15 | Виправлено бухгалтером | «так», если загружено и код 12 ≠ код 8 |
| 16 | Пояснення | `Пояснение` строки |
| 17 | Користувач | автор этой загрузки |
| 18 | Дата | момент этой загрузки, `dd.MM.yyyy HH:mm` |
| 19 | Документ | `Строка(ДокументСсылка)` |
| 20 | Завантажень | номер загрузки для строки |
| 21 | Перше завантаження | дата первой загрузки строки |

Все ячейки пишутся как **текст**. Числа — с десятичной запятой и без разделителя тысяч. При разборе журнала
(Python, Excel) числа надо переводить из текста.

**Где берутся `Авто*`.** `ПрочитатьИСопоставить` после `Сопоставить` копирует в каждую строку `АвтоНоменклатура`,
`АвтоСпособ`, `АвтоСходство` — то, что выбрал алгоритм. Ручные правки в форме (выбор карточки, ✓, варианты, «Забути»)
колонки `Авто*` не трогают. Повторное «Прочитати і зіставити» переносит только строки со способом «Вибрано вручну»
(ключ `НомерСтроки|Наименование`), а `Авто*` снова заполняет алгоритм ([08](08_forma_i_instrukciya.md)). Состояние
«Знято» и ✓ от «Підтвердити схожі» при повторном чтении не сохраняются (удаление из памяти после «Забути» остаётся).

## Слияние с прежним журналом

**`СтрокиЖурнала(ПрисоединенныйФайл)`:**
- `РаботаСФайлами.ДвоичныеДанныеФайла(...)` → временный xlsx → `ТабличныйДокумент.Прочитать`;
- для строк 2…конец: ключ `«колонка 1»|«колонка 2»` (рядок файлу | назва) → `Структура(АвтоНоменклатура, АвтоКод,
  АвтоСпособ, АвтоСходство, Загрузок, Первое)` из колонок 7, 8, 9, 10, 20, 21;
- **совместимость с журналом прежнего формата** без колонок 20–21: `Загрузок` пусто → 1, `Первое` пусто → колонка 18
  (Дата);
- любое исключение при чтении → пустое соответствие: новый журнал начнётся с текущего автоподбора. Автоподбор первой
  загрузки в этом случае теряется.

**`ДвоичныеДанныеЖурнала`, по каждой строке текущей таблицы:**
- ключ `Формат(НомерСтроки, "ЧГ=0") + "|" + СокрЛП(Наименование)`;
- есть в прежнем журнале — колонки 7–10 и 21 берутся оттуда, `Завантажень` = прежнее + 1;
- нет — автоподбор из текущей строки, `Завантажень` = 1, «Перше завантаження» = сейчас;
- `Загружено = Подтверждено И ЗначениеЗаполнено(Номенклатура)`;
- `Исправлено = Загружено И КодОбрано <> Было.АвтоКод`;
- `Итоги.Загрузок = Макс(Итоги.Загрузок, Было.Загрузок + 1)` — это «N-й раз» в описании.

**Нюансы, которые видны только из кода:**
- Журнал **пересобирается из текущей таблицы.** Строки прежнего журнала, которых нет в текущей таблице, пропадают. Так
  бывает, если файл с тем же именем изменился или сдвинулись номера строк.
- **«Виправлено бухгалтером» сравнивает коды, а не ссылки.** Автоподбор «Не знайдено» (код пуст) + ручной выбор
  карточки = «так».
- **«Обрано: спосіб» — способ на момент нажатия «2. Завантажити».** После загрузки форма меняет способ всех
  подтверждённых строк, кроме «За кодом 1С», на «Вибрано раніше». Вторая загрузка из той же формы запишет в колонку 13
  «Вибрано раніше».
- **«Завантажено = так» не учитывает пропуск строки при нулевом количестве** после пересчёта единиц (кг → т < 0,0005,
  [06](06_zagruzka_v_dokument.md)). Это редкий случай: строка в журнале «так», в документе её нет, причина — в
  предупреждении результата.
- **Журнал — на пару «документ + имя файла».** Тот же файл в другом документе — новый журнал. Его «Автопідбір» уже
  включает запомненные выборы («Вибрано раніше»), потому что память соответствий общая ([03](03_algoritm_sopostavleniya.md)).

## Как использовать журнал для калибровки (не реализовано, план)

Исследование ([05](05_issledovanie_metodov.md)): пороги 60/85 и множители подобраны на одной накладной АСУБЗ. Их надо
перепроверить по журналам следующих 1–2 накладных. Позже, когда наберутся подтверждённые пары (ориентир 200–300),
веса пересчитываются как **log2(m/u) по модели Fellegi–Sunter**.

**Сбор.**
- Запрос к `Справочник.РеализацияТоваровУслугПрисоединенныеФайлы`: `Наименование ПОДОБНО "Журнал зіставлення %"`,
  `НЕ ПометкаУдаления`.
- Чтение через `РаботаСФайлами.ДвоичныеДанныеФайла` (так делает `tx_test2.py`, функция `журнал`).

**Разметка из колонок.**

| Случай | Колонки | Смысл |
|---|---|---|
| Пара (2, 11), «Завантажено = так» | назва файла → выбранная карточка | **положительная** пара (match) |
| Пара (2, 7), «Виправлено = так», колонка 8 непуста | назва файла → автоподбор | **отрицательная** пара: алгоритм ошибся |
| «Завантажено = так», «Виправлено = ні», 9 = «Схоже — перевірте» | — | подсказка верна: точность зоны 60–84 / ≥ 85 |
| 9 = «Не знайдено — виберіть», загружено | — | промах полноты: карточка есть, алгоритм не нашёл |

«Виправлено = ні» само по себе ничего не говорит: в коде `Исправлено = Загружено И …`, поэтому у незагруженной строки
(✓ снят, карточки нет) всегда «ні». → Точность подсказки считать только по строкам с «Завантажено = так».

**Фильтр.** Для калибровки **самого алгоритма** брать строки, где колонка 9 — «Схоже — перевірте», «Поза залишками —
перевірте» или «Не знайдено — виберіть». Строки «Вибрано раніше», «За кодом 1С», «Точна назва» — это память и точные
совпадения, а не оценка сходства.

**Признаки пар.** В журнале только итоговая схожесть (кол. 10) и пояснение (кол. 16), составляющих T и N нет. Пересчитать
можно двумя способами:
- через COM: `ОценкаПары(НазваниеФайла, НазваниеКарточки)` возвращает `Сходство`, `Пояснение` («слова X %; розміри
  збіглися…; НЕМАЄ розмірів…; інша марка…») и ключи ([04](04_metrika_shozhesti.md));
- по эталону лаборатории `similarity_lab/simlib.py` ([05](05_issledovanie_metodov.md)).

Автоподбор в журнале — только **top-1**. Остальные 4 варианта не логируются.

## Excel с кодами 1С (`ДвоичныеДанныеExcelСКодами`)

Кнопка «Excel з кодами 1С» (команда `ВыгрузитьВExcel`, картинка `SaveFile`). Назначение: сохранить накладную с кодами
подтверждённых карточек, чтобы **в следующий раз грузить по коду** без проверки.

**Поток (модуль формы):**
- нет строк — «Немає рядків для вивантаження — спершу прочитайте файл.»;
- `АдресExcelСКодами()` (сервер): `ДвоичныеДанныеExcelСКодами(Распознавание)` → `ПоместитьВоВременноеХранилище(…, УникальныйИдентификатор)`;
- `НачатьПолучениеФайлов` с именем «Накладна з кодами 1С.xlsx», с диалогом;
- после сохранения `ВыгрузитьВExcelЗавершение` (Экспорт, обработчик оповещения) показывает: «Файл збережено. Код 1С —
  лише для рядків з ✓. Для завантаження за кодом: назва 2, кількість 3, од. 4, ціна 5, код 1С 6, сума 7.» Отмена
  диалога — без сообщения.

**Файл к документу не прикрепляется.**

**Колонки (9):**

| № | Заголовок | Значение |
|---|---|---|
| 1 | N | порядковый номер строки выгрузки (не номер строки исходного файла) |
| 2 | Назва з файлу | `Наименование` |
| 3 | Кількість | число с запятой |
| 4 | Од.вим. | единица файла |
| 5 | Ціна без ПДВ | цена |
| 6 | **Код 1С** | `Номенклатура.Код` — **только при `Подтверждено`** |
| 7 | Сума без ПДВ | сумма |
| 8 | Номенклатура 1С | имя карточки для **любой** строки с карточкой, в т.ч. неподтверждённой подсказки — для справки |
| 9 | Спосіб | текст способа; при загрузке **не читается** |

Колонки 2–5 и 7 совпадают с умолчаниями настроек. Для загрузки достаточно поставить «Код 1С» = 6.

**Почему код только у подтверждённых** — находка ревью №6/№13. Раньше код писался для любой строки с карточкой.
Повторная загрузка с кодом 6 превращала непроверенную подсказку 60–84 % в «За кодом 1С», 100 %, ✓. Она уходила в
документ и в общую память соответствий.

**Нюансы при загрузке этого файла обратно:**
- **Строки «Разом» в выгрузке нет.** `ИтогФайла` будет пуст, контроль покажет «У накладній немає рядка «Разом» —
  звірте суму вручну» ([08](08_forma_i_instrukciya.md)).
- **Настройки колонок сохраняются при чтении** (`СохранитьНастройки`, [02](02_chtenie_fayla_i_nastroyki.md)).
  «Код 1С = 6» останется и для следующей обычной накладной АСУБЗ, где колонка 6 — «Ціна з ПДВ».
  `НоменклатураПоКоду` дополняет короткий код нулями до 11 знаков. Поэтому **целая** цена без копеек («1500») может
  совпасть с кодом карточки `00000001500` и подтвердиться «За кодом 1С». Это вывод из кода, на данных не
  воспроизводилось.
  → После загрузки файла с кодами вернуть «Код 1С (0 — немає)» в 0.
