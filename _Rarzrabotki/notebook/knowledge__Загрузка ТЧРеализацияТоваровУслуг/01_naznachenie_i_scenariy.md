# 01. Назначение и сценарий работы

Внешняя обработка BAS Бухгалтерія (BuhBud, `bas_industrialbud`) **«Завантаження з Excel ТЧ Реалізація (зіставлення з
залишками)»**, имя объекта `ЗагрузкаТЧРеализацияТоваровУслуг`. Исходники:

- `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг.xml` — корень (реквизиты, ТЧ `Склады`, форма `Форма`, макет `Инструкция`);
- `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг/Ext/ObjectModule.bsl` — движок (чтение, сопоставление, загрузка);
- `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг/Forms/Форма/Ext/Form/Module.bsl` — тонкая форма-диспетчер;
- `_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг.epf` — собранный файл для карточки «Додаткові звіти й обробки».

Спецификация: `_Rarzrabotki/notebook/specs/2026-10-09-zagruzka-realizacii-sopostavlenie-design.md`.

## Зачем

Поставщик (пример — накладная АСУБЗ, `_Rarzrabotki/temp/Специфікація з АСУБЗ.xls`) присылает Excel со строками
«ТМЦ — кількість — од. — ціна без ПДВ — сума». Эти товары нужно **реализовать документом `РеализацияТоваровУслуг`**.
В накладной **нет кодов 1С**, названия поставщика не совпадают с названиями карточек:

| В накладной | Карточка в базе |
|---|---|
| «Болт M16\*55 (DIN 933) оц.» | «DIN933 Болт М16х55 8.8 цб пр (ISO 4017)» |
| «Арматура будівельна Ø12 A-III(A500С)» | «Арматура №12  А500С» |
| «Двері металеві утеплені 960\*2050мм» | «Двері металеві (утеплені) 960х2050 мм» |

Вручную подбирать 84 строки долго и легко ошибиться в размере (М16×55 против М16×65). Обработка:

1. читает файл и **сама предлагает карточку** для каждой строки — ищет среди **остатков складов** «Чорноморськ» и
   «Чорноморськ Списання», потому что реализуется то, что лежит на этих складах;
2. показывает бухгалтеру **таблицу сопоставления** с цветами, пояснениями и вариантами;
3. **загружает в документ только подтверждённые (✓) строки**, сумма строки — точно из файла;
4. **запоминает выбор** бухгалтера: в следующий раз та же назва найдётся сразу;
5. прикрепляет к документу **исходный файл и журнал сопоставления** — история и материал для обучения.

## Решения пользователя (хронология 09.10.2026)

Фиксируют, «почему так», — не менять без пользователя.

| № | Решение | Где в коде |
|---|---|---|
| 1 | Загрузка в `РеализацияТоваровУслуг`, товар искать **по названию**, поиск сужать остатками складов «Чорноморськ» и «Чорноморськ Списання»; «умная, с настройками»; если в Excel есть код 1С — находить карточку **однозначно** | `Сопоставить`, `КандидатыИзОстатков`, `СкладыПоУмолчанию`, `НоменклатураПоКоду` |
| 2 | **Склады — только для ПОИСКА**, все строки идут в текущий документ («Всё в текущий документ»); интерфейс — «Таблица сопоставления» | `ЗаполнитьТоварыДокумента` пишет всё в `ДокОбъект.Товары` |
| 3 | **«Сначала анализ сопоставления, потом загрузка»** — как в `_Rarzrabotki/Обработки/Загрузка лимитов.xml` | `ПрочитатьИСопоставить` → `ЗагрузитьВДокумент` |
| 4 | «Придумай методы сходства, изучи GitHub, косинусный поиск» → исследование | гибрид T + N + судьи, [04](04_metrika_shozhesti.md), [05](05_issledovanie_metodov.md) |
| 5 | После загрузки **прикреплять файл к документу** — история, «как бухгалтер вручную подбирал», потом для обучения | `ПрикрепитьФайлыЗагрузки`, [07](07_vlozheniya_i_zhurnal.md) |
| 6 | «Красивый дизайнерский интерфейс», как в `_Rarzrabotki/Рабочие места` и `_Rarzrabotki/Обработки` | форма в стиле `А_РозрахункиПДВЗаПершоюПодією`, [08](08_forma_i_instrukciya.md) |

| 8 | Закладка **«Інструкція»** — коротко и просто; инструкция и все заголовки — **на украинском** | макет `Инструкция`, uk-заголовки Form.xml |

| 10 | «Как делают HTML-инструкции для 1С на GitHub» → исследование | [08](08_forma_i_instrukciya.md), [FINDINGS](FINDINGS.md) |
| 11 | «Слишком много вложений… найди середину» | **один** исходный файл, **один** обновляемый журнал |
| 12 | «Где номенклатура 1С — рядом код 1С»: видеть код при загрузке по коду и **код карточки, чтобы найти её и построить остатки по оборотке** | колонки «Код 1С» (`КодКарточки`) и «Код з накладної» (`Код`), коммит `ea3812bffc` |

## Двухшаговый сценарий

```
 Документ Реалізація (не проведён)
        │ «Заповнити» → команда «Завантажити з Excel (зіставлення з залишками)»
        ▼
 Форма обработки ── выбрать файл ─► ШАГ 1  «1. Прочитати і зіставити»
                                        ПрочитатьИСопоставить(АдресФайла, ИмяФайла)
                                        ├─ чтение Excel (02)
                                        └─ Сопоставить: код → запомненное → точная назва →
                                           сходство среди остатков → вне остатков (03, 04)
        ▼
 Бухгалтер: ✓ / другая карточка / двойной клик по варианту /
            «Підтвердити схожі ≥ 85 %» / «Забути вибір рядка» / сверка итогов с «Разом»
        ▼
                                    ШАГ 2  «2. Завантажити в документ»
                                        ЗагрузитьВДокумент(Таблица, АдресФайла, ИмяФайла)
                                        ├─ ЗаполнитьТоварыДокумента → Записать (без проведения) (06)
                                        ├─ СохранитьСопоставление (запомнить выбор)
                                        └─ ПрикрепитьФайлыЗагрузки (файл + журнал) (07)
```

**Шаг 1 ничего не пишет в документ.** Он только строит таблицу `Распознавание` и варианты. Пишет он только настройки
пользователя (`СохранитьНастройки`, [02](02_chtenie_fayla_i_nastroyki.md)).

**Шаг 2 пишет документ в режиме `РежимЗаписиДокумента.Запись`** — без проведения. Проводит бухгалтер сам, после
проверки документа.

**Автоподтверждение — только для однозначных способов:** «За кодом 1С», «Вибрано раніше», «Точна назва». Подсказки по
сходству («Схоже — перевірте», «Поза залишками — перевірте») подтверждает человек. Строки без ✓ в документ не попадают.

**Повторный проход шага 1 сохраняет ручной выбор.** `ПрочитатьФайлНаСервере` (модуль формы) переносит строки со
способом «Вибрано вручну» в новый анализ по ключу «номер строки|назва».

**Выбор файла сразу запускает шаг 1:** `ВыбратьФайлЗавершение` вызывает `ПрочитатьФайлНаСервере`. Кнопка
«1. Прочитати і зіставити» без выбранного файла открывает выбор файла, с выбранным — перечитывает его.

## Запуск как дополнительная обработка БСП

`СведенияОВнешнейОбработке()` (модуль объекта, область `ОписаниеДляБСП`) регистрирует обработку:

| Параметр | Значение |
|---|---|
| `Вид` | `"ЗаполнениеОбъекта"` |
| `Назначение` | массив из `"Документ.РеализацияТоваровУслуг"` |
| `Наименование` | «Завантаження з Excel ТЧ Реалізація (зіставлення з залишками)» |
| `Версия` | `"1.0"` |
| `Информация` | «Аналіз зіставлення рядків накладної з номенклатурою за залишками складів і завантаження підтверджених рядків у товари реалізації» |
| `БезопасныйРежим` | `Ложь` |
| Команда: `Представление` | «Завантажити з Excel (зіставлення з залишками)» |
| `Идентификатор` | `"ЗагрузкаИзExcel"` |
| `Использование` | **`"ОткрытиеФормы"`** |
| `ПоказыватьОповещение` | `Ложь` |

- **`ОткрытиеФормы`** — БСП открывает основную форму обработки и передаёт в параметрах `ОбъектыНазначения` (массив
  ссылок). `ПриСозданииНаСервере` берёт первый элемент: `ДокументРеализации = Параметры.ОбъектыНазначения[0]` — с
  проверкой `Параметры.Свойство("ОбъектыНазначения")`, типа `Массив` и количества > 0.
- Дальше `ЗаполнитьНастройки(ДокументРеализации)` ставит `Документ` и добавляет **склад документа** к складам поиска.
- **В документе команда — под кнопкой «Заповнити»** (так написано в инструкции для бухгалтера).
- **Можно открыть как обычную внешнюю обработку** (Файл → Відкрити) и выбрать документ в поле «Реалізація». Тогда
  `ОбъектыНазначения` нет, `Документ` пустой до выбора. Отличие: склад документа, выбранного позже, **сам не
  добавляется** к складам поиска — `ЗаполнитьНастройки` вызывается только при создании формы. Организация и дата для
  остатков берутся из `Документ` в момент запроса (`УстановитьОтборОрганизации`, `ПериодОстатков`), то есть
  работают и при позднем выборе.
- **`БезопасныйРежим = Ложь` обязателен.** Код пишет временные файлы (`ПолучитьИмяВременногоФайла`, `Записать`) и
  включает `УстановитьПривилегированныйРежим(Истина)` для общих сопоставлений; в безопасном режиме это запрещено.
- **После каждой пересборки `.epf` файл надо перезагрузить в карточке** «Додаткові звіти й обробки»: база хранит
  старую версию у себя.

Как устроена форма при открытии (`ПриСозданииНаСервере`): настройки через `РеквизитФормыВЗначение("Объект")` →
`ЗаполнитьНастройки` → `ЗначениеВРеквизитФормы`; текст инструкции из макета `Инструкция`; видимость колонки «Код з
накладної» = `Объект.КолонкаКод > 0`; переключатель `Показать = "Все"`; условное оформление строк и легенда; итоги.
Подробно — [08](08_forma_i_instrukciya.md).

## Что бухгалтер получает на выходе

- В документе — строки `Товары`: номенклатура, количество **в единице карточки** (т ↔ кг пересчитываются, несравнимые
  единицы — без пересчёта, с предупреждением), сумма **как в накладной** (в документе с ПДВ в цене — плюс ставка),
  ставка и сумма ПДВ, счёт учёта — **счёт, на котором лежит остаток** ([06](06_zagruzka_v_dokument.md)).
- В «Приєднані файли» документа — накладная (одна копия) и «Журнал зіставлення <файл>.xlsx» (один, обновляется).
- Сообщение: «Завантажено в документ рядків: N на суму S без ПДВ…», предупреждения о единицах, «Вибір запам'ятовано…
  Якщо документ відкрито — закрийте і відкрийте його знову».

## Связь с прежними обработками

Образцы, которые дал пользователь, лежат в `_Rarzrabotki/temp/` основного каталога:

| Обработка | Документ | Как работает |
|---|---|---|
| `Загрузка ТЧТребованиеНакладная` | `ТребованиеНакладная` | БСП `ЗаполнениеОбъекта`, команда `ВызовКлиентскогоМетода`, форма `ЗапросПараметров` |
| `Загрузка ТЧСписание_ПеремещениеТоваров_170625` | `СписаниеТоваров` | то же |
| `Загрузка ПередачаМалоценныхАктивовВЭксплуатацию` | `ПередачаМалоценныхАктивовВЭксплуатацию` | то же |
| `_Rarzrabotki/Обработки/Загрузка лимитов` («Загрузка лимитов ДДС из Excel») | установка лимитов ДДС | **два шага: распознавание → загрузка**, таблица распознавания, запомненные сопоставления |

**Прежние загрузки ТЧ (Требование, Списание, Малоценка):**
- Excel читается через `Новый COMObject("Excel.Application")` в клиентской процедуре `Загрузить` формы `Форма` (у всех
  трёх) — нужен установленный Excel;
- товар ищется **только по коду** (`Справочники.Номенклатура.НайтиПоКоду`); числовой код из ячейки у всех трёх
  дополняется нулями до 11 знаков (`Прав("00000000000" + …, 11)`);
- счёт учёта — из `Хозрасчетный.Остатки` по жёсткому списку счетов с отбором по номенклатуре (`ОпределитьСчетУчетаБУ`):
  у Требования и Списания 201, 203, 205, 206, 207, 209, 221, 281; у Малоценки — `В ИЕРАРХИИ` 22, 112, 153. У всех трёх
  этот запрос без периода, организации и склада. Исключение — `ПеремещениеТоваров` в обработке Списания: счёт из
  `ПолучитьСведенияОНоменклатуре`;
- документ пишется `ДокОбъект.Записать()` без блокировки и без проверки проведения.

**Что взято и что изменено:**

| Было | Стало | Почему |
|---|---|---|
| Excel через COM | `ТабличныйДокумент.Прочитать` на сервере (`ПрочитатьТабличныйДокумент`) | Excel не нужен, работает xls и xlsx |
| Только код | Код → запомненное → точная назва → сходство | В накладных поставщика кодов нет |
| Счёт из остатков по списку счетов | Счёт остатка на **складах поиска** и **в организации документа** на дату документа, склад документа первым | Списание пойдёт оттуда, где товар реально лежит |
| Запись без проверок | `Заблокировать()`, проверка `Проведен` до и после блокировки | Не испортить проведённый документ |
| Один шаг | Два шага, как в «Загрузка лимитов» | Решение пользователя № 3 |

**Из «Загрузка лимитов» взят каркас** почти дословно (там тексты русские, здесь переведены на украинский): `НоваяТаблицаРаспознавания`,
`ПрочитатьТабличныйДокумент`, `ТекстЯчейки`, `ЧислоИзТекста`, «способы» как строковые функции
(`СпособЗапомнено`, `СпособПохоже`, `СпособНеНайдено`), `СохраненноеСопоставление`/`СохранитьСопоставление` в
`ХранилищеОбщихНастроек`. Нормализация «Загрузки лимитов» (`Нормализовать` — убрать пробелы и знаки
` № - ( ) " ' . , « » _ /`) стала основой старого ключа `КлючНазванияДо0910`.

Отличия от «Загрузки лимитов»:
- сопоставления **общие для всех бухгалтеров** (отдельное имя пользователя хранилища, привилегированный режим), а не
  у каждого свои;
- ключ точного совпадения **сохраняет границы чисел** («1,5» ≠ «15») — [03](03_algoritm_sopostavleniya.md);
- поиск по сходству — гибридная метрика с «судьями»-атрибутами — [04](04_metrika_shozhesti.md).

**Дизайн формы** — по домашнему образцу `_Rarzrabotki/Обработки/А_РозрахункиПДВЗаПершоюПодією/`: командная панель
с картинками, строка-резюме, закладки сверху, закладка «Інструкція» с HTML из макета.
