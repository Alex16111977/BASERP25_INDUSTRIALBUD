## Сборка EPF

**Команда** (скилл `epf-build`, скрипт `.claude/skills/epf-build/scripts/epf-build.ps1`):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Configuration_downloads\BASERP25\.claude\skills\epf-build\scripts\epf-build.ps1" `
  -V8Path "C:\Program Files\1cv8\8.3.20.1914\bin\1cv8.exe" `
  -InfoBaseServer "localhost" -InfoBaseRef "bas_industrialbud" -UserName "cfo" -Password "2442" `
  -SourceFile "<iso>\Загрузка ТЧРеализацияТоваровУслуг.xml" `
  -OutputFile "<iso>\Загрузка ТЧРеализацияТоваровУслуг.epf"
```

**Правила:**
1. **Собирать из изолированного каталога** `<iso>`. Туда копируются **только** корневой `.xml` и каталог обработки. В
   `_Rarzrabotki/temp/` лежат чужие обработки и прежний `.epf`.
   - Если база не указана, `epf-build.ps1` строит stub-базу и сканирует **все** `*.xml` каталога-источника, затягивая
     чужие типы.
   - В сессии каталоги `scratchpad\epf_iso1…epf_iso14` создавал вспомогательный `build_epf.ps1 <имя>`: `Copy-Item`
     корневого xml и каталога, затем вызов `epf-build.ps1`.
2. **`.ps1` с кириллицей сохранять в UTF-8 с BOM.** Без BOM Windows PowerShell 5.1 читает файл как 1251, и пути
   ломаются. Heredoc из Bash пишет без BOM ([LESSONS](LESSONS.md)).
3. **Сборка идёт ~16–50 с.** Готовый `.epf` копируется в `_Rarzrabotki/temp/` (финальная — из `epf_iso14`).
4. **Обработка для BuhBud собирается против `bas_industrialbud`.** С указанной серверной базой stub не создаётся,
   работает `DESIGNER /S localhost/bas_industrialbud /LoadExternalDataProcessorOrReportFromFiles`.
   - Если Конфигуратор BuhBud держит блокировку — вариант через stub-базу: обязательна изоляция источника и патч версии
     формата 2.17 → 2.13 (память проекта `epf_build_stub_isolation_gotcha`).

**Чего сборка НЕ делает.** `LoadExternalDataProcessorOrReportFromFiles` только **упаковывает** XML в `.epf`.
- Модуль формы не компилируется: его ошибки видны только при открытии формы в клиенте.
- Модуль объекта компилируется при `ВнешниеОбработки.Создать(...)` через COM, поэтому его ошибки ловят COM-тесты.
- `DESIGNER /CheckConfig` внешние обработки не проверяет (проверено 25.08.2026, память `feedback_epf_preflight_open_self`).
- Открывать форму через `ENTERPRISE /Execute` или computer-use **нельзя**: пользователь против окон на своём экране.
  Форму открывает он сам.

### `form_xcheck.py`

`python form_xcheck.py "<…>\_Rarzrabotki\temp\Загрузка ТЧРеализацияТоваровУслуг"`. Проверяет:
- каждый `Элементы.X` модуля формы есть в `Form.xml`;

## Диагностика ошибок формы через журнал регистрации

**Случай 09.10.** Пользователь открыл новую форму: модуль скомпилировался, дизайн принят. При чтении файла появилось
«Недопустимое значение параметра (параметр номер '2')». Ни строки, ни модуля в сообщении нет.

**Метод:** выгрузить ошибки журнала регистрации по COM — `python _Rarzrabotki/Python/test/zagruzka_realizacii/evlog.py 15`.
Суть скрипта:

```python
тз = c.NewObject("ТаблицаЗначений")
відбір = c.NewObject("Структура")
відбір.Вставить("ДатаНачала", datetime.datetime.now() - datetime.timedelta(minutes=ХВИЛИН) + datetime.timedelta(hours=3))  # COM сдвигает даты на −3 ч
рівні = c.NewObject("Массив"); рівні.Добавить(c.УровеньЖурналаРегистрации.Ошибка)
відбір.Вставить("Уровень", рівні)
c.UnloadEventLog(тз, відбір)   # английский алиас ВыгрузитьЖурналРегистрации: кириллическое имя через COM не резолвится
# печать: Дата, ИмяПользователя, ПредставлениеСобытия, Комментарий[:3000]
```

В `Комментарий` события — **стек с модулем и строкой**:
`{ВнешняяОбработка.ЗагрузкаТЧРеализацияТоваровУслуг.Форма.Форма.Форма(276)}: ЗначениеВРеквизитФормы(Результат.Таблица, "Распознавание")`.
Номер строки дрейфует: в текущем модуле этот вызов в `ПрочитатьФайлНаСервере`, ~277.

**Причина.** В реквизит формы `Распознавание` добавили колонку `Группа`, а ТЗ из `НоваяТаблицаРаспознавания` её не
имела. **`ЗначениеВРеквизитФормы` требует совпадения наборов колонок.**

**Исправление** — колонка `Группа` в `НоваяТаблицаРаспознавания` (коммит `70449f2a9d`). В `form_xcheck.py` добавлена
сверка наборов колонок.

→ Любую ошибку, которую видит пользователь в клиенте, сначала искать в журнале регистрации: там модуль и номер строки.

## Чек-лист выпуска новой версии

1. Правка BSL / генератора формы → `gen_form.py` (если менялась форма).
2. `form_xcheck.py` → только `Элементы.Добавить`.
3. `check_bsl_context.py` (BuhBud-вариант) → только известные ложные срабатывания (глобальные объекты платформы,
   свойства и реквизиты формы, список выше).
4. Новый или изменённый запрос → Python COM тест (Rule #-1).
5. Сборка из изолированного каталога → копия `.epf` в `_Rarzrabotki/temp/`.
6. `review_cases.py` (0 ошибок) → `epf_smoke.py` (сумма ТЧ = сумма файла подтверждённых) → `tx_test2.py` (ошибок нет).
7. Копия изменённых файлов в main (Rule #4), коммит, fast-forward main.
8. Пользователю: перезагрузить `.epf` в карточке и **открыть форму самому**. Если в клиенте ошибка — `evlog`.
