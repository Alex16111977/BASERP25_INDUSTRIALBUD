## Суть за 60 секунд

1. **Дополнительная обработка БСП** вида «Заполнение объекта» для `Документ.РеализацияТоваровУслуг`
   (`СведенияОВнешнейОбработке`).
   - В документе: «Заповнити» → «Завантажити з Excel (зіставлення з залишками)».
   - Режим `ОткрытиеФормы`: документ приходит в `Параметры.ОбъектыНазначения[0]`.
   - `БезопасныйРежим = Ложь` — для временных файлов и привилегированного режима ([01](01_naznachenie_i_scenariy.md)).
2. **Два шага, как в «Загрузка лимитов»:**
   - «1. Прочитати і зіставити» → `ПрочитатьИСопоставить`: таблица `Распознавание` и до 5 вариантов на строку. В
     документ **ничего не пишет**, сохраняет только настройки пользователя;
   - «2. Завантажити в документ» → `ЗагрузитьВДокумент`: только строки с ✓, `РежимЗаписиДокумента.Запись`, **без
     проведения** ([01](01_naznachenie_i_scenariy.md), [06](06_zagruzka_v_dokument.md)).
3. **Чтение на сервере** — `ТабличныйДокумент.Прочитать`, Excel не нужен.
   - Номера колонок настраиваются. Умолчания сняты с накладной АСУБЗ: первая строка 2, назва 2, кількість 3, од. 4,
     ціна 5, сума 7, код 0 (нет).
   - Строка итога — количество пустое, а название пустое или начинается с «Разом», «Всього», «Усього», «Итог»,
     «Всего». Её сумма идёт в `ИтогФайла`, с ним форма сверяет сумму строк: «✓ Сума рядків = «Разом»»
     ([02](02_chtenie_fayla_i_nastroyki.md)).
4. **Конвейер `Сопоставить` — первый сработавший шаг выигрывает:** код 1С → запомненный выбор → точная назва
   (единственная карточка среди остатков) → сходство среди остатков → при флажке: точная назва и сходство в
   справочнике.
   - **Автоподтверждение — только код, память и точная назва.** Подсказки по сходству подтверждает бухгалтер.
   - Склады поиска по умолчанию — по имени: «Чорноморськ» (в базе два элемента с этим именем) и «Чорноморськ
     Списання», плюс склад документа.
   - Остатки — `Хозрасчетный.Остатки` на конец дня документа, только организация документа ([03](03_algoritm_sopostavleniya.md)).
5. **«Схожість, %» = `min(стеля, Окр(100 × (0,5·T + 0,5·N) × множители))`** (`ОценкаСходства`):
   - T — косинус TF-IDF символьных триграмм **слов**, числа в T не входят;
   - N — доля размеров файла, найденных в карточке (мультимножество), × (1 − 0,05 × лишние размеры карточки, не больше
     4); у файла нет размеров — N = T (у карточки тоже нет) или 0,7;
   - «судьи»: размер файла не найден ≤ 49; у карточки нет размеров ≤ 70; другой тип изделия ≤ 40; праві/ліві ≤ 49;
     другая марка ×0,9, другой стандарт ×0,8, и у каждого стеля 75;
   - зоны: ≥ 85 — кнопка «Підтвердити схожі»; ≥ 60 — подсказка в строке; ≥ 20 — вариант внизу ([04](04_metrika_shozhesti.md)).

   Почему гибрид: чистые строковые метрики не различают М16×55 и М16×65 ([05](05_issledovanie_metodov.md)).
6. **Память соответствий — общая для всех бухгалтеров.**
   - `ХранилищеОбщихНастроек`: объект `ВнешняяОбработка.ЗагрузкаТЧРеализацияТоваровУслуг`, настройка «Сопоставление»,
     пользователь `ОбщиеНастройкиЗагрузкиРеализации`, привилегированный режим.
   - Пишется после успешной записи документа и только новым `КлючНазвания`: границы чисел сохранены, «1,5» ≠ «15».
   - Старым `КлючНазванияДо0910` не пишут. Им читают записи до 09.10, и только если размеры файла есть в карточке;
     «Забути вибір рядка» удаляет оба ключа ([03](03_algoritm_sopostavleniya.md), [LESSONS](LESSONS.md) §21, §29).
7. **Строка документа — через типовой обработчик** `РеализацияТоваровУслугФормы.ТоварыНоменклатураПриИзмененииНаСервере`:
   счета, ставка ПДВ, единица — как при ручном выборе. Дальше:
   - количество — в единице карточки; пересчёт только т ↔ кг, иначе предупреждение;
   - **сумма — точно из накладной**, цена = сумма / количество; в документе с ПДВ в цене — плюс ставка;
   - `СчетУчетаБУ` = счёт, на котором лежит остаток, сначала на складе документа;
   - «проведён» проверяется по ссылке и ещё раз после `Заблокировать()` ([06](06_zagruzka_v_dokument.md)).
8. **Вложения — «середина»** (решение пользователя). Исходный файл — один: то же имя и размер повторно не добавляется.
   Журнал «Журнал зіставлення <файл>.xlsx» — один на документ и файл, 21 колонка, обновляется со слиянием:
   «Автопідбір» — с первой загрузки, «Обрано» — последний выбор. Это размеченные данные для калибровки
   ([07](07_vlozheniya_i_zhurnal.md)).
9. **Форма генерируется** `gen_form.py` (только `Form.xml`):
   - заголовки ru + uk с одинаковым украинским текстом; цвета и шрифты — кодом;
   - набор колонок реквизитов `Распознавание`/`Варианты` = колонки ТЗ модуля объекта;
   - «Код 1С» (`КодКарточки`) — рядом с «Номенклатура 1С», в таблице и в вариантах; «Код з накладної» (`Код`) — только
     при `КолонкаКод > 0`;
   - инструкция — HTML из макета TextDocument в поле HTML-документа ([08](08_forma_i_instrukciya.md), [LESSONS](LESSONS.md) §1–§4).
10. **Выпуск.** Сборка `.epf` из изолированного каталога против `bas_industrialbud` **модуль формы не компилирует**.
    Поэтому: пре-флайт `form_xcheck.py`, COM-тесты, затем пользователь перезагружает `.epf` в карточке «Додаткові звіти
    й обробки» и сам открывает форму. Ошибку из клиента искать в журнале регистрации (`evlog.py`)
    ([09](09_sborka_testy_priemka.md)).
