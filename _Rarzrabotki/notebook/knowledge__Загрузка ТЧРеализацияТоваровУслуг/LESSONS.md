## Форма внешней обработки в BuhBud

**§1. Вместо надписей — технические имена (ПрочитатьФайл, НомерСтроки, ИмяФайла).**
Пользователь прислал скриншот: интерфейс выглядел «непрофессионально». В Form.xml заголовки были только с
`<v8:lang>ru</v8:lang>`, а язык интерфейса BuhBud — украинский (uk). Для uk платформа не нашла текста и показала имена.
→ Каждый `Title`/`ToolTip`/`InputHint` писать с двумя `v8:item`, ru и uk, оба по-украински. Так делает `текст()` в
`gen_form.py`; `form_xcheck.py` ловит «Title без uk». Синоним в корневом XML тоже ru + uk.

**§2. `&НаКлиентеНаСервере` в формах BuhBud и ERP не встречается ни разу.**
Общий код итогов нужен и на клиенте (✓, выбор карточки), и на сервере (после чтения файла).
→ Приём БСП: `&НаКлиентеНаСервереБезКонтекста Процедура ОбновитьИтогиФормы(Форма)`, вызов
`ОбновитьИтогиФормы(ЭтотОбъект)`. Внутри — только `Форма.Распознавание`, `Форма.Элементы.…`, `Форма.<реквизит>`.
Так же устроен `ПрименитьФильтр(Форма)`.

**§3. «Недопустимое значение параметра (параметр номер '2')» при чтении файла.**
Форма открылась, а на чтении упала.
- Стек из журнала регистрации: `{ВнешняяОбработка.ЗагрузкаТЧРеализацияТоваровУслуг.Форма.Форма.Форма(276)}:
  ЗначениеВРеквизитФормы(Результат.Таблица, "Распознавание")`.
- В реквизит формы `Распознавание` добавили колонку `Группа` для фильтра-переключателя. ТЗ из модуля объекта
  (`НоваяТаблицаРаспознавания`) её не имела.
- `ЗначениеВРеквизитФормы` требует **одинакового набора колонок** у ТЗ и реквизита-ТЗ формы.

→ Колонку добавлять в обоих местах, даже если заполняет её только форма (коммит `70449f2a9d`). `form_xcheck.py`
сверяет наборы `Распознавание` ↔ `НоваяТаблицаРаспознавания` и `Варианты` ↔ `НоваяТаблицаВариантов`.

**§4. `<TextColor>style:…</TextColor>` в Form.xml внешней обработки валит сборку исключением XDTO.**
Сообщение не указывает ни тег, ни строку. Известно с 06.2026, память `epf_load_xdto_textcolor`. В формах конфигурации
тот же тег загружается.
→ Цвета и шрифты задавать кодом в `ПриСозданииНаСервере`:
- `Элементы.ПодсказкаВарианты.ЦветТекста = ЦветаСтиля.ПоясняющийТекст`;
- `Новый Шрифт(, , Истина)` для итогов;
- `ЦветФона` у надписей легенды;
- условное оформление — `УсловноеОформление.Элементы.Добавить()`.

**§5. Сборка не компилирует модуль формы, а COM форму не открывает.**
`epf-build` (`/LoadExternalDataProcessorOrReportFromFiles`) только упаковывает XML в `.epf`: код не компилирует.
Модуль объекта компилируется при `ВнешниеОбработки.Создать` в COM-тестах, а модуль формы — только при открытии
формы в клиенте. Внешнее соединение форму не открывает. Запуск Enterprise `/Execute` пользователь запретил. Значит,
ошибки модуля формы — и компиляции, и выполнения — первым видит пользователь (память `feedback_epf_preflight_open_self`).
→ Пре-флайт перед выдачей:
- `form_xcheck.py`: `Элементы.X` существуют, обработчики `<Event>`/`<Action>` есть в модуле, DataPath ведут на
  реквизиты, у заголовков есть uk, наборы колонок совпадают;
- `check_bsl_context.py`: доступность общих модулей по директиве компиляции. ⚠ Скрипт
  `_Rarzrabotki\Python\test\check_bsl_context.py` (только в основном каталоге, в git не добавлен) подключается к
  **BaseERP** (`CONN_ERP`). Для обработки BuhBud нужна копия со строкой `Ref="bas_industrialbud";Usr="cfo"`: иначе
  общие модули сверяются с метаданными ERP (например, `РеализацияТоваровУслугФормы` есть в BuhBud, но не в ERP —
  будет ложная ошибка). Постоянной BuhBud-копии нет; 09.10 использовалась временная ([09](09_sborka_testy_priemka.md)).

Открывает форму пользователь.

**§6. Ошибку пользователя искать в журнале регистрации через COM.**
→ `evlog.py [хвилин]` (`_Rarzrabotki\Python\test\zagruzka_realizacii\`):
- вызывать `c.UnloadEventLog(ТЗ, Отбор)` — английский алиас `ВыгрузитьЖурналРегистрации`: кириллическое имя
  глобального метода через COM не резолвится;
- `Отбор` — Структура `ДатаНачала` и `Уровень = Массив(УровеньЖурналаРегистрации.Ошибка)`;
- **дата через COM сдвигается на −3 ч**, поэтому к `ДатаНачала` прибавлять 3 часа.

В `Комментарий` — стек с модулем и номером строки.

**§7. Скрытая командная панель таблицы ≠ запрет добавлять строки.**
Ревью: у `Распознавание` было только `CommandBarLocation=None`. `ChangeRowSet` по умолчанию true, поэтому Ins, F9 и Del
работали из контекстного меню и с клавиатуры.
- F9 на подтверждённой строке создавал копию с ✓ — товар грузился дважды.
- Ins давал пустую строку: номенклатура автоподтверждалась, а количество было 0.

В формах обработок конфигурации `ChangeRowSet` встречается 329 раз, всегда как false.
→ `<ChangeRowSet>false</ChangeRowSet>` и `<ChangeRowOrder>false</ChangeRowOrder>`: в `gen_form.py` это
`таблиця(…, rowset=False)`.

**§8. Флажок в таблице и порядок свойств Form.xml.**
- Без `EditMode=EnterOnInput` галочку нельзя поставить, не войдя в ячейку.
- Без `CheckBoxType` вместо галочки рисуется текст «Да/Нет».
- Порядок свойств взят из типовых форм BASEBuh ([08](08_forma_i_instrukciya.md)). Валидные `ChildItemsWidth` — `Equal`
  и `LeftNarrowest`; `LeftWidest` в формах не встречается.

→ Форму не писать руками, а менять `gen_form.py`: порядки свойств в нём уже зашиты.

**§9. HTML-инструкция.**
→ Образец — `А_РозрахункиПДВЗаПершоюПодією`:
- макет `Инструкция` типа **TextDocument** с HTML: `Ext\Template.txt`, UTF-8 с BOM, `<meta charset="utf-8">`;
- реквизит-строка `ТекстИнструкции` присваивается **один раз** в `ПриСозданииНаСервере`: позднее изменение поле
  иногда не перерисовывает;
- выводится в `HTMLDocumentField`.

Почему не другие варианты:
- **HTMLDocument** — WYSIWYG-редактор Конфигуратора переписывает разметку.
- **Скилл `/template-add`** для HTML создаёт `Ext/Template.html`, а это не формат дампа.

Ограничения движка: с 8.3.14 поле рисует старый WebKit. Без внешних ресурсов. CSS Grid, `var()` и ES6 проверять:
вёрстка инструкции сделана на `display:table`. Подробно — [08](08_forma_i_instrukciya.md), [FINDINGS](FINDINGS.md).

**§10. После пересборки пользователь видит старую версию.**
`.epf` закэширован в базе в карточке «Додаткові звіти й обробки».
→ После каждой сборки напоминать: перезагрузить файл в карточке.

## BSL и платформа

**§11. `ТабличныйДокумент.Область(R, C)` — не ячейка.**
→ Ячейку брать четырёхаргументной формой `Область(R, C, R, C)`: так сделано в `ТекстЯчейки` и при записи журнала.

**§12. `ЗаполнитьЗначенияСвойств` со списком свойств, разорванным переносом `|`, не работает.**
→ Список свойств писать одной строкой (`"Строк, Сумма, Пропущено, Предупреждения"`,
`"Номенклатура, Сходство, Остаток, Склад, Пояснение"`).

**§13. Старые сохранённые настройки «Колонки» не имели `КолонкаСумма`.**
Настройки, сохранённые до появления реквизита, его не содержат. Обращение к отсутствующему ключу `Структуры` — ошибка.
→ В `ЗаполнитьНастройки` читать только существующие ключи: цикл по списку имён и `Сохраненные.Свойство(Имя)`.
Отсутствующее остаётся со значением по умолчанию.

**§14. Общие соответствия лежат в `ХранилищеОбщихНастроек` под чужим именем пользователя.**
Отдельное имя `"ОбщиеНастройкиЗагрузкиРеализации"` нужно, чтобы выбор был общим для всех бухгалтеров. Читать и
писать настройки другого пользователя без привилегий нельзя.
→ `УстановитьПривилегированныйРежим(Истина)` вокруг `Загрузить`/`Сохранить`, затем `Ложь`
(`СохраненноеСопоставление`, `СохранитьСопоставление`, `ЗабытьСоответствие`).

**§15. `РаботаСФайлами.ДобавитьФайл` падал: «Поле объекта не обнаружено (ВремяИзмененияУниверсальное)».**
БСП читает это поле из параметров без проверки.
→ В `ПараметрыФайла` передавать `ВремяИзмененияУниверсальное = ТекущаяУниверсальнаяДата()` (`ДобавитьПрисоединенныйФайл`).

**§16. Псевдоним «В» в запросе зарезервирован.**
→ Переименовали. Псевдонимы — `Ост`, `ВТ`, `Н`, `С`, `Ф`. Псевдонимы, совпадающие с ключевыми словами запроса («В»,
«И», «ПО»), не использовать.

**§17. Проверка «проведён» по ссылке устаревает.**
Ревью: `Документ.Проведен` читался по ссылке до `ПолучитьОбъект`/`Заблокировать`.
- Данные по ссылке кэшируются в сеансе примерно на 20 с.
- Если документ провели в это окно, запись в режиме `Запись` оставляет его проведённым со старыми движениями.

→ После `ДокОбъект.Заблокировать()` повторно проверять `ДокОбъект.Проведен` (комментарий в коде: «могли провести,
поки бухгалтер перевіряв таблицю») и возвращать ту же ошибку «Документ проведено — скасуйте проведення…».

**§18. 0,4 кг на карточке в тоннах грузились строкой с количеством 0 и суммой 0.**
`Товары.Количество` — 15,3, неотрицательное: 0,0004 т при присвоении превращается в 0. Сумма файла терялась без
предупреждения.
→ `КоличествоДокумента = Окр(Количество × Коэффициент, 3)`. Если вышло 0 — строку не грузить и выдать
предупреждение «… дорівнює 0 — рядок не завантажено».

**§19. Без колонки суммы сумма «плыла» при пересчёте т → кг.**
Цена за кг округлялась до копеек после деления на 1000. Пример ревью: 5,25 т × 32 567,89 → 170 992,50 вместо
170 981,42 (+11,08 грн).
→ Сумма строки = `Окр(Цена × Количество файла, 2)` **до** пересчёта единиц, затем цена документа = сумма / количество
(`ЗаполнитьТоварыДокумента`).

**§20. Сообщения «Після виправлення погрішностей округлення сума ПДВ … змінилася (було …, стало …)».**
→ Это штатная механика самого документа при записи (±0,01), а не ошибка обработки. Не «исправлять».

## Сопоставление

**§21. Ключ точного совпадения склеивал разные размеры: «1,5» = «15», «1,25» = «125», «1/2» = «12».**
Старый `КлючНазвания` удалял пробелы, «,», «.», «-», «/», «*». Поэтому «Лист г/к 1,5 ст3» и «Лист г/к 15 ст3» давали
ключ «листгк15ст3». Шаги «Точна назва» и «Вибрано раніше» подтверждали карточку на 100 % в обход проверки размеров, а
`СохранитьСопоставление` закреплял ошибку для всех.
→ Ключ строится из лексем (`ЛексемыНазвания`), границы чисел сохраняются. Разделители не важны: «М16*55» = «M16х55»,
«8,0 мм» = «8мм». Регрессия `review_cases.py`: «1,5» против «15» → ключи разные, сходство 49.

**§22. «х» между числами принималась за префикс.**
В «М16х55» число 55 получало префикс «х» и уходило в марки. Размер терялся, и выбирались неверные болты вне остатков.
→ `Префикс = "х"`, если за две лексемы до числа стоит число, — это знак умножения, а не префикс. В ключе «х» между
числами отбрасывается.

**§23. Число после «ГОСТ 8732» считалось стандартом.**
`НайтиСловоПеред` смотрел на две лексемы назад. В «Труба ГОСТ 8732 57х3,5» диаметр 57 уходил в стандарты, а стандарты
сравнивались по **любому** общему элементу. Трубы 57, 76 и 89 получали по 98, класс прочности «8.8» против «5.8» — 100.
→ Стандарт — только число **сразу** после слова стандарта. Марки и стандарты сравниваются через `ВсеЕсть`: каждое
значение файла должно быть в карточке.

**§24. Диаметр «ф12» и профнастил «ПС-20-1150-0,7» уходили в марки.**
Буква впритык делала число маркой. Дефис наследовал класс от слова «пс». Итог: «ф16» против «ф12» — 100, «0,5» против
«0,7» — 100.
→ Префиксы `ф`, `d`, `dn`, `ду`, `дн` — диаметр, то есть размер. Через дефис класс марки наследуется, только если
предыдущая марка была с буквенным префиксом (`МаркаСПрефиксом`: «А2-70», «ст1-3»). Год стандарта после дефиса
пропускается: «ДСТУ 10704-91» = «ГОСТ 10704».

**§25. Однобуквенный суффикс профиля отбрасывался: «Швелер 12П» = «Швелер 12У» = 100.**
→ Буква из `"пубкшед"` впритык к размеру входит в размер: «12п» ≠ «12у», «20б1».

**§26. Другая марка давала только ×0,9, то есть 88–90 и зону «підтвердити».**
→ Несовпадение марки или стандарта (у карточки есть свои) — множитель **и стеля 75**: только «перевірте». Пример
регрессии: «Кутник 75х75х6 ст.3» против «S235» → 75.

**§27. Тип изделия нужно проверять в обе стороны.**
«Кріплення гакове до швелера 14» и «Швелер 14П» делят и слово, и число.
→ Типы совпали, если они равны или **каждый** тип — основа слова в другом названии. «Настил решітковий» =
«Решітковий настил», а «Швелер …» ≠ «Кріплення … до швелера». Иначе стеля 40.

**§28. Две карточки с одним ключом: побеждала последняя.**
`ПоТочномуКлючу` заполнялся через `Вставить`.
→ Хранить массив и автоподтверждать «Точна назва» только при **единственной** карточке. В справочнике то же:
`ТочнаяНоменклатураВСправочнике` берёт `ПЕРВЫЕ 2` и принимает только одну.

**§29. Смена ключа обнуляет запомненные выборы.**
Ключ сменился 09.10.
→ Старые записи читаются запасным `КлючНазванияДо0910`, но только если все размеры файла есть в названии карточки
(`РазмерыЕстьВНазвании`): старый ключ склеивал числа. `ЗабытьСоответствие` удаляет оба ключа.

**§30. Запросы остатков не учитывали организацию.**
`Справочник.Склады` без владельца: один склад может держать остатки нескольких своих компаний. Счёт строки мог прийти
от чужой организации.
→ `Организация = &Организация` в условии виртуальной таблицы — и в `КандидатыИзОстатков`, и в
`СчетаОстатковНоменклатуры`. Без документа условие вырезается (`УстановитьОтборОрганизации`). На 09.10 с условием и
без — те же 487 строк: в базе одна организация с остатками на этих складах.

**§31. «Excel з кодами 1С» писал код и для непроверенных подсказок.**
При повторной загрузке с колонкой кода 6 они возвращались как «За кодом 1С», с ✓, и запоминались.
→ Код — только для `Подтверждено`. Название подсказки — в колонке 8, для справки.

**§32. «Підтвердити схожі» подтверждал снятые и «забытые» строки.**
После снятия ✓ в строке оставались номенклатура и сходство 100.
→ Кнопка трогает только `Способ = «Схоже — перевірте»`. Снятие ✓ ставит «Знято бухгалтером», повторная ✓ — «Вибрано
вручну».

**§33. Склады-дубли по имени.**
Два элемента «Чорноморськ» (коды 00-000189 и 00-000332) плюс «Чорноморськ Списання». `СкладыПоУмолчанию` выбирает по
имени и получает 3 склада.
→ Для поиска это не мешает: склад без остатков ничего не добавляет. COM-запрос 09.10 (остатки > 0, номенклатура):
«Чорноморськ» 00-000189 — 172 позиции, «Чорноморськ Списання» 00-000217 — 315, на дубле 00-000332 остатков нет
(172 + 315 = те самые 487 строк номенклатура × склад). Выбирать **один** склад по имени нельзя: можно попасть на пустой дубль.

## Вложения и тесты

**§34. Вложения размножались.**
После 3 загрузок у документа было 6 вложений: 3 копии накладной и 3 журнала с меткой времени в имени. Пользователь
попросил «середину»: материал для обучения без мусора.
→ Исходный файл — один:
- то же имя и размер — не добавляется;
- то же имя, другой размер — `ОбновитьФайл` на месте.

Журнал — один на документ и файл, имя без времени. При каждой загрузке он обновляется со слиянием: автоподбор берётся
из первой загрузки. Проверка `tx_test2.py`: вложений 6 → 7 → 7.

**§35. Файлы БСП в BuhBud хранятся в базе (томов нет).**
→ Поэтому тест вложений идёт в транзакции `BeginTransaction` … `RollbackTransaction`, и откат чистый. Документы в
тестах не удалять. Если в базе включат тома, откат оставит файлы на диске.

**§36. Ожидания регрессии — инварианты, а не баллы.**
Баллы дрейфуют при любой правке весов.
→ В `review_cases.py` условия «≥ 85», «< 60», «ключи равны/разные». Цифры прогонов в базе знаний — с датой.

## Сборка, файлы, git

**§37. `.ps1` с кириллицей, записанный heredoc, ломает пути.**
Heredoc пишет UTF-8 без BOM. PowerShell 5.1 читает такой файл как 1251, и путь «Загрузка ТЧРеализацияТоваровУслуг»
превращается в кракозябры.
→ `.ps1` писать через Python `encoding="utf-8-sig"` или передавать кириллицу прямо в команде PowerShell (память
`feedback_cyrillic_ps1_bom`). Файлы дампа тоже держать с BOM: `Template.txt` и Form.xml — UTF-8 с BOM; `gen_form.py`
пишет Form.xml с BOM и CRLF.

**§38. Собирать из изолированного каталога.**
→ В отдельную папку копируется только корневой `…xml` и каталог обработки, без посторонних файлов: в
`_Rarzrabotki\temp` лежат десятки чужих обработок. Сборка — против `bas_industrialbud` ([09](09_sborka_testy_priemka.md)).

**§39. Слияние в грязный main: «файлы отличаются», хотя содержимое то же.**
При `autocrlf=true` рабочие копии в main с CRLF (и BOM), а blob в коммите с LF. Побайтная сверка даёт ложное
расхождение.
→ Сравнивать копии с blob коммита без учёта CRLF и BOM. Откатывать в main только файлы ветки
(память `feedback_merge_prep_only_branch_files`).
