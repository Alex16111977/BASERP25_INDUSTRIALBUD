## 5. Исследование методов сходства

Отдельный файл — [05](05_issledovanie_metodov.md). Главное:
- строковые метрики (Левенштейн, Jaro–Winkler, косинус) **не различают размеры**: М16×60 стоит рядом с М16×55;

## 6. Исследование HTML-инструкций (09.10.2026)

Вопрос пользователя: как на GitHub делают HTML-инструкции для обработок 1С. GitHub code search без авторизации
недоступен. Образцы взяты из выгрузок 8.3.20 в репозитории, дампов на GitHub (tree/raw API) и статей Infostart.

**Готовый образец в проекте** — `_Rarzrabotki/Обработки/А_РозрахункиПДВЗаПершоюПодією/` (то же в
`_Rarzrabotki/BASEBuh/DataProcessors/`): страница `СтраницаИнструкция` с `StdPicture.Information`, `HTMLDocumentField` →
реквизит-строка `ТекстИнструкции`, макет `Инструкция` типа TextDocument (UTF-8 с BOM, ~11 КБ). Загрузка одной строкой
в `ПриСозданииНаСервере`.

| Подход | Вывод |
|---|---|
| **Поле HTML-документа + строковый реквизит** | стандарт: полный HTML/CSS, своя прокрутка, тонкий и веб-клиент — **выбран** |
| Макет **TextDocument** | один файл `Ext/Template.txt`, не зависит от языка, удобный diff, Конфигуратор не переформатирует — **выбран** |
| Макет HTMLDocument | страницы ru/uk; WYSIWYG-редактор переписывает разметку и может испортить CSS |
| `ФорматированнаяСтрока` в декорации | без заголовков, списков и таблиц; в BuhBud понимает только `<b>` и `<a href>` — годится для легенды |
| Встроенная справка (F1) | отдельное окно, пользователь его не находит — только дополнение |

**Движок.** С 8.3.14.1565 тонкий и толстый клиенты Windows рисуют поле HTML через **WebKit** уровня Safari 12–13,
IE не используется. Надёжны блочная вёрстка, таблицы, `border-radius`, `linear-gradient`, `box-shadow`. CSS Grid,
`var()` и ES6 — проверять. Режим совместимости IE не возвращает (BuhBud — `Version8_3_12`).

**Подводные камни:**
- `<meta charset="utf-8">` обязателен, `Template.txt` — UTF-8 с BOM;
- без внешних ресурсов: ни CDN, ни веб-шрифтов; относительные пути не работают (HTML пишется во временный файл),
  картинки — только `data:image/png;base64`;
- ссылки проще не делать; если нужны — перехват `OnClick`;
- поле должно растягиваться, `Height` не задавать;
- HTML присваивать **один раз** в `ПриСозданииНаСервере`: позднее изменение реквизита иногда не перерисовывает поле;
- локальный скилл `/template-add` для HTML создаёт `Ext/Template.html` — это не формат дампа.

Как это применено в обработке — [08](08_forma_i_instrukciya.md), [LESSONS](LESSONS.md) §9.

## 7. Поведение документа `РеализацияТоваровУслуг` при записи

Сверено по выгрузке `_Rarzrabotki/BASEBuh/Documents/РеализацияТоваровУслуг/Ext/ObjectModule.bsl`, процедура
`ПередЗаписью`:
- **Округление ПДВ.** При `АвторасчетНДС` документ вызывает
  `УчетНДСКлиентСервер.ПересчитатьНДСсУчетомПогрешностиОкругления` для `Товары` и `Услуги`. Отсюда сообщения
  «Після виправлення погрішностей округлення сума ПДВ табличної частини Товари змінилася (було …, стало …)»: ±0,01
  по ТЧ. **Это штатная механика документа, а не ошибка обработки** ([LESSONS](LESSONS.md) §20).
- **Комиссия.** При договоре с комиссионером `ПередЗаписью` очищает `Услуги`. Обработка `Услуги` не трогает.
- **Сумма документа** пересчитывается: `УчетНДС.ПолучитьСуммуДокументаСНДС` по `Товары` и `Услуги`.
- **Режим `Запись`** не проверяет заполнение: пустой контрагент или договор всплывут при проведении.

**Нюанс сообщения обработки.** `Результат.Сумма` = Σ `Сумма` строк. В документе «Сума включає ПДВ» это сумма с ПДВ,
а форма пишет «на суму … без ПДВ». Тестовый документ был без ПДВ в цене, на практике не проверялось
([06](06_zagruzka_v_dokument.md)).
