# 06. Загрузка в документ (шаг 2)

Код — модуль объекта: `ЗагрузитьВДокумент` и `ЗаполнитьТоварыДокумента` (обе экспортные), `СчетаОстатковНоменклатуры`,
`КоэффициентПересчета`, `КлючЕдиницы`, `СохранитьСопоставление`, `УстановитьОтборОрганизации`, `ПериодОстатков`.
Вложения (`ПрикрепитьФайлыЗагрузки`) — в [07](07_vlozheniya_i_zhurnal.md). На форме — команда `ЗагрузитьВДокумент`
и `ЗагрузитьВДокументНаСервере`.

## Последовательность

```
Клиент (команда «2. Завантажити в документ»)
  ├─ нет документа        → «Виберіть документ реалізації.»
  ├─ таблица пуста        → «Спершу прочитайте і зіставте файл (кнопка «1. Прочитати і зіставити»).»
  └─ ГотовоСтрок = 0      → «Немає рядків з ✓ — підтвердіть картки в таблиці.»
Сервер: ЗагрузитьВДокументНаСервере → Обработка.ЗагрузитьВДокумент(Распознавание, АдресФайла, ИмяФайла)
  1. Документ пустой                         → Ошибка «Не вибрано документ реалізації.»
  2. Документ.Проведен (по ссылке)           → Ошибка «Документ проведено — скасуйте проведення і повторіть завантаження.»
  3. ПолучитьОбъект() + Заблокировать()      → исключение: «Документ заблоковано іншим користувачем або відкрито зі змінами: …»
  4. ДокОбъект.Проведен (свежий объект)      → та же ошибка о проведении
  5. ЗаполнитьТоварыДокумента(ДокОбъект, …)  → Строк = 0: «Немає підтверджених рядків з номенклатурою — позначте «✓» у таблиці.»
  6. ДокОбъект.Записать(РежимЗаписиДокумента.Запись) → исключение: «Документ не записано: …»
  7. СохранитьСопоставление(Таблица)         — запомнить выбор
  8. ПрикрепитьФайлыЗагрузки(…)              → ошибка становится предупреждением «Файли до документа не прикріплено: …»
```

- **Общей транзакции нет.** Документ пишется первым; сопоставления и вложения — после успешной записи. Ошибка
  вложений не откатывает документ, а только добавляет предупреждение.
- **До шага 6 в базу ничего не пишется.** Очистка и заполнение `Товары` идут в объекте в памяти. Ошибка на шагах 1–6
  оставляет документ как был.
- **Документ не проводится.** Проводит бухгалтер сам, после проверки.
- Обработка **не создаёт документ и не трогает шапку**: контрагент, договор, курс, тип цен — из самого документа.

## Блокировка и проверка проведения

**Проведённый документ грузить нельзя.** Запись проведённого документа в режиме `Запись` оставляет его проведённым,
а движения — по старым `Товарам`: документ и проводки разойдутся. → Отменить проведение, загрузить, провести.

**Проверка дважды** (находка ревью № 8):
- по ссылке `Документ.Проведен` — быстрый отказ до чтения объекта;
- **после `Заблокировать()`** — по свежему `ДокОбъект.Проведен`. Ссылка могла показать старое значение из кэша сеанса,
  а документ мог провести другой пользователь, пока бухгалтер проверял таблицу.

**`Заблокировать()`** не даст писать документ, который открыт у другого пользователя с изменениями: текст ошибки
так и говорит — «заблоковано іншим користувачем або відкрито зі змінами».

**Документ, открытый у самого бухгалтера без изменений,** блокировке не мешает (поведение платформы, отдельным тестом
не проверялось; текст ошибки с этим согласуется). Но открытая форма документа после
загрузки показывает старые товары. Клиент вызывает `ОповеститьОбИзменении(Объект.Документ)`, а в итоговом сообщении
просит: «Якщо документ відкрито — закрийте і відкрийте його знову».

## Очистка товаров (`ОчиститьТовары`)

- `Истина` → `ДокОбъект.Товары.Очистить()` перед заполнением. **Повторная загрузка заменяет товары, а не дублирует.**
- Галочка включается при каждом открытии формы (`ЗаполнитьНастройки`) и не сохраняется в настройках — решение
  пользователя № 9: «бухгалтер может несколько раз грузить».
- Галочку можно снять на «Налаштування» (поле не только для чтения). Тогда строки **дописываются** к существующим, и
  второе нажатие «Завантажити» добавит те же строки ещё раз. В ревью претензия «второе нажатие дублирует» опровергнута
  (обоснование в источниках не записано); с включённой галочкой повторная загрузка заменяет товары.
- ТЧ `Услуги` обработка не трогает. Но `ПередЗаписью` самого документа очищает `Услуги` при договоре с комиссионером
  (выгрузка BASEBuh, `Documents/РеализацияТоваровУслуг/Ext/ObjectModule.bsl`).
- Дедупликации по номеру строки файла нет. Защита от двойной загрузки одной строки — таблица сопоставления не даёт
  добавлять и копировать строки (`ChangeRowSet = false`, находка ревью № 14: F9 на подтверждённой строке давал
  двойную загрузку).

## Заполнение строки (`ЗаполнитьТоварыДокумента`)

Для каждой строки таблицы:
- **без ✓ или без номенклатуры** → `Пропущено + 1`, дальше;
- иначе — новая строка `Товары` по шагам ниже.

### 1. Типовой обработчик номенклатуры

```
СтрокаТоваров.Номенклатура = СтрокаФайла.Номенклатура;
РеализацияТоваровУслугФормы.ТоварыНоменклатураПриИзмененииНаСервере(СтрокаТоваров, ДанныеОбъекта);
```

**`ДанныеОбъекта`** — `Структура` с полями `Дата, ВидОперации, Организация, Склад, ТипЦен, ВалютаДокумента,
КурсВзаиморасчетов, КратностьВзаиморасчетов, СуммаВключаетНДС, ДоговорКонтрагента, ЭтоКомиссия, Реализация`.
Это **тот же набор**, что собирает типовая форма в `РеализацияТоваровУслугФормыКлиент.ПодготовитьПараметрыОбработкиТоварыНоменклатураПриИзменении`
(сверено по выгрузке `_Rarzrabotki/BASEBuh`).
- `ЭтоКомиссия` = договор заполнен и `ВидДоговора = Перечисления.ВидыДоговоровКонтрагентов.СКомиссионером` — так же
  считают форма документа и его `ПередЗаписью`;
- `Реализация = Истина`.

Типовой обработчик (`CommonModules/РеализацияТоваровУслугФормы`, выгрузка BASEBuh) делает то же, что при ручном
выборе номенклатуры в форме:
- сведения о номенклатуре — `БухгалтерскийУчетПереопределяемый.ПолучитьСведенияОНоменклатуре`;
- `ЕдиницаИзмерения` (базовая), `Коэффициент`, `Цена` (по типу цен документа), `СтавкаНДС`;
- счета и налоговое назначение строки — `Документы.РеализацияТоваровУслуг.ЗаполнитьСчетаУчетаВСтрокеТабличнойЧасти`
  (`СчетУчетаБУ`, `ПереданныеСчетУчетаБУ`, `СхемаРеализации` — если не комиссия, `НалоговоеНазначение`,
  `НалоговоеНазначениеДоходовИЗатрат`; каждое — только если в сведениях заполнено);
- суммы — `РассчитатьСуммуТабЧасти`, `РассчитатьСуммуНДСТабЧасти`.

**Зачем типовой обработчик, а не своё заполнение:** невидимые поля строки (счета, налоговое назначение, ставка)
заполняются ровно как у ручной строки, ничего не забыто.

### 2. Количество и единицы

```
КоэффициентЕдиниц = КоэффициентПересчета(СтрокаФайла.Единица, Строка(Номенклатура.БазоваяЕдиницаИзмерения))
КоличествоДокумента = Окр(СтрокаФайла.Количество × КоэффициентЕдиниц, 3)   // в документе 3 знака
```

**`КлючЕдиницы`** нормализует единицу: нижний регистр, `СокрЛП`, убрать пробел, точку и запятую, затем синонимы.

| Варианты в файле или карточке | Ключ |
|---|---|
| тн, тонн, тона | т |
| штук, штука | шт |
| м², квм, мкв | м2 |
| м³, кубм | м3 |
| літр, литр | л |
| пм, погм, мп | м |
| остальное | как есть (после нормализации): «шт.» → «шт», «кг» → «кг» |

**`КоэффициентПересчета`:**

| Файл → карточка | Коэффициент |
|---|---|
| единица файла пустая, или ключи равны | 1 |
| т → кг | 1000 |
| кг → т | 0,001 |
| иначе | `Неопределено` → коэффициент 1 и предупреждение |

- Предупреждение несравнимых единиц: «рядок N: одиниця файлу «X» ≠ одиниці картки «Y» — кількість перенесено без
  перерахунку». На АСУБЗ 09.10.2026 — **одно**: «рядок 29: одиниця файлу «т» ≠ одиниці картки «м»» (труба профільна
  40×40×3, подсказана карточка в метрах). → Выбрать карточку в тоннах или поправить количество в документе.
- **Нулевое количество после пересчёта** (кг → т, меньше 0,0005 т) → строка **не загружается**, `Пропущено + 1` и
  предупреждение «рядок N: кількість Q U в одиниці картки «Y» дорівнює 0 — рядок не завантажено» (находка ревью № 9:
  раньше шла строка с количеством 0 и суммой 0).
- Пример: «Арматура будівельна Ø12» 6,29770 т → в документе 6,298 т.

**Где бухгалтер видит разницу единиц до загрузки:**
- `УстановитьВыбор` пишет в пояснение «одиниці різні: файл «…», картка «…» — перевірте кількість». Но у
  строк-подсказок («Схоже», «Поза залишками») `Сопоставить` сразу затирает пояснение текстом сходства. Поэтому у
  жёлтых и оранжевых строк разница единиц до загрузки не видна (строка 29 АСУБЗ — так и было). Видна колонка «Од.
  картки».
- При ручном выборе (`ДанныеКарточкиНаСервере`, модуль формы) пояснение «одиниця файлу «…», картки «…» (т ↔ кг
  перераховується)». Оно сравнивает единицы простым `НРег(СокрЛП)`, без `КлючЕдиницы`: «шт.» против «шт» тоже даст
  пояснение. Текст про т ↔ кг выводится и там, где пересчёта нет (т против м).
- **Двойной клик по варианту** (`КандидатыВыбор`, модуль формы) сначала берёт `ДанныеКарточкиНаСервере`, но потом
  заменяет пояснение пояснением варианта — разница единиц снова не видна.
- **Окончательный ответ — предупреждение после загрузки.**

### 3. Счёт учёта = счёт остатка

После типового обработчика: если для номенклатуры найден счёт остатка и он отличается от `СчетУчетаБУ` — `СчетУчетаБУ`
заменяется. Остатка нет → остаётся счёт типового обработчика.

**`СчетаОстатковНоменклатуры(МассивНоменклатуры, СкладДокумента)`** — один запрос на все подтверждённые карточки:

```
ВЫБРАТЬ Ост.Субконто1 КАК Номенклатура, Ост.Счет КАК Счет,
        ВЫБОР КОГДА Ост.Субконто3 = &СкладДокумента ТОГДА 0 ИНАЧЕ 1 КОНЕЦ КАК Приоритет,
        Ост.КоличествоОстаток КАК Количество
ИЗ РегистрБухгалтерии.Хозрасчетный.Остатки(&Период, , , Субконто3 В (&Склады) И Организация = &Организация) КАК Ост
ГДЕ Ост.Субконто1 В (&Номенклатура) И Ост.КоличествоОстаток > 0
УПОРЯДОЧИТЬ ПО Приоритет, Количество УБЫВ
```

- **Первый счёт по карточке выигрывает:** сначала склад документа, затем счёт с большим остатком.
- **Склады** — список поиска обработки; **период** — `ПериодОстатков()` = конец дня даты документа включительно (без
  документа — конец текущего дня).
- **Организация** — `УстановитьОтборОрганизации`: организация документа в условии виртуальной таблицы; без
  документа или организации условие вырезается из текста запроса (`СтрЗаменить`). Отбор добавлен по находке ревью
  № 7: склад не принадлежит организации, а в BuhBud несколько своих компаний. Без отбора счёт мог прийти от чужой
  организации, и при проведении списание пошло бы с пустого счёта. Тот же отбор стоит в `КандидатыИзОстатков`.
- Счета остатков товаров в базе — **205, 209, 221** (`Хозрасчетный`: Субконто1 — номенклатура, Субконто3 — склад).
  Отбора по счёту в запросе нет. Претензия ревью «может выбрать 222 (МШП в експлуатації)» опровергнута (обоснование в
  источниках не записано).
- Проверено COM-тестом (Rule −1, 09.10.2026): запрос счетов — 490 строк; запрос кандидатов с отбором по организации
  и без — 487 строк (в базе одна организация с остатками на этих складах).

**Зачем:** при проведении реализация списывает товар со `СчетУчетаБУ` строки. Счёт по умолчанию из настроек
номенклатуры может не совпасть со счётом, где товар фактически лежит. Тогда проведение даст минус на одном счёте и
висящий остаток на другом.

### 4. Сумма, цена, ПДВ

```
СуммаСтроки = ?(Сумма файла > 0, Сумма файла, Окр(Цена файла × Количество файла, 2))   // до пересчёта единиц
Если СуммаСтроки > 0:
    Если ДокОбъект.СуммаВключаетНДС:
        СуммаСтроки = Окр(СуммаСтроки × (100 + УчетНДС.ПолучитьСтавкуНДС(СтавкаНДС)) / 100, 2)
    Цена = Окр(СуммаСтроки / Количество документа, 2)
    РассчитатьСуммуТабЧасти(строка)            // типовой: СуммаБезСкидки = Цена × Количество
    Сумма = СуммаСтроки; СуммаБезСкидки = СуммаСтроки + СуммаСкидки
Иначе:
    РассчитатьСуммуТабЧасти(строка)            // цена — из типа цен документа (типовой обработчик)
РассчитатьСуммуНДСТабЧасти(строка, ДокОбъект.СуммаВключаетНДС)
```

- **Сумма строки — точно из накладной.** Цена производная и округлена до копеек, поэтому `Цена × Количество` может
  отличаться от `Сумма` на копейки. Пример АСУБЗ (09.10.2026): Арматура №12 А500С — 6,298 т × 33 346,75 = 210 017,83,
  а `Сумма` = **210 017,84** (как в файле); ПДВ 20 % = 42 003,57; счёт 205.
- **Без колонки суммы** сумма = цена × количество **файла до пересчёта единиц** (находка ревью № 10). Раньше цена
  округлялась после пересчёта т → кг, и сумма «плыла»: 5,25 т по 32 567,89 давали +11,08 грн на строку.
- **Ни суммы, ни цены в файле** → цена из типа цен документа, сумма = цена × количество.
- **Файл — без ПДВ** (колонки «Ціна без ПДВ», «Сума без ПДВ»). В документе с ПДВ в цене сумма увеличивается на ставку строки.
- Если бухгалтер потом поменяет количество или цену в форме документа, типовой пересчёт `Сумма = Цена × Количество`
  может убрать копейку из файла.

`Результат.Строк` и `Результат.Сумма` — по загруженным строкам. `Результат.Сумма` = Σ `СтрокаТоваров.Сумма`.
**Нюанс по коду:** в документе с ПДВ в цене эта сумма — с ПДВ, а сообщение формы пишет «на суму … без ПДВ».
Тестовый документ был без ПДВ в цене, поэтому на практике это не проверялось.

## Запись документа

`ДокОбъект.Записать(РежимЗаписиДокумента.Запись)` запускает `ПередЗаписью` самого документа:
- **сообщения «Після виправлення погрішностей округлення сума ПДВ табличної частини Товари змінилася (було …, стало
  …)»** — штатная механика документа, не обработки. При `АвторасчетНДС` документ вызывает
  `УчетНДСКлиентСервер.ПересчитатьНДСсУчетомПогрешностиОкругления`: ±0,01 по ТЧ, сообщение на языке сеанса;
- `СуммаДокумента` пересчитывается документом.

Режим `Запись` не выполняет проверку заполнения. Пустые реквизиты шапки (контрагент, договор) всплывут при проведении.

## Запоминание выбора (`СохранитьСопоставление`)

Только после успешной записи. Для каждой строки **с ✓ и номенклатурой**:
`Сопоставление.Вставить(КлючНазвания(Наименование), Номенклатура)`. Запись идёт в общее `ХранилищеОбщихНастроек`
(пользователь «ОбщиеНастройкиЗагрузкиРеализации») в привилегированном режиме и в `Попытка` — ошибка не критична:
«наступного разу картки доведеться підтвердити знову».

- Запоминаются **все** подтверждённые строки, включая «За кодом 1С» и «Точна назва». Поэтому следующий файл **без
  колонки кода** найдёт эти названия как «Вибрано раніше».
- Пишется только **новый ключ** `КлючНазвания`. Запись со старым ключом (`КлючНазванияДо0910`) остаётся, но новый
  ключ проверяется первым ([03](03_algoritm_sopostavleniya.md)).
- Неподтверждённые строки не запоминаются. Неверный выбор → кнопка «Забути вибір рядка» (`ЗабытьСоответствие`
  удаляет оба ключа).

## Результат и что видит бухгалтер

`ЗагрузитьВДокумент` возвращает `Структура`: `Строк`, `Сумма`, `Пропущено`, `Ошибка`, `Предупреждения`.

**Пропущено** = строки без ✓ или без номенклатуры + строки с нулевым количеством после пересчёта.

После успеха `ЗагрузитьВДокументНаСервере` ставит всем строкам с ✓, кроме «За кодом 1С», способ **«Вибрано раніше»**:
строки зелёные, как будут при следующем чтении. Затем — итоги формы.

**Сообщение бухгалтеру** (`ПоказатьПредупреждение`) собирается из частей:

| Часть | Когда |
|---|---|
| «Завантажено в документ рядків: N на суму S без ПДВ.» | всегда |
| « Не завантажено (без ✓): K.» | `Пропущено > 0`; сюда входят и строки с нулевым количеством |
| « Попередні товари документа замінено.» | `ОчиститьТовары` |
| текст предупреждений | если есть |
| «Вибір запам'ятовано. Файл накладної і журнал зіставлення — у «Приєднаних файлах» документа. Якщо документ відкрито — закрийте і відкрийте його знову.» | всегда |

**Предупреждения** (через перевод строки):
- несравнимые единицы — «рядок N: одиниця файлу «X» ≠ одиниці картки «Y» — кількість перенесено без перерахунку»;
- нулевое количество — «рядок N: кількість … в одиниці картки «Y» дорівнює 0 — рядок не завантажено»;
- вложения — «Файли до документа не прикріплено: <ошибка>».

Ошибка (`Результат.Ошибка`) показывается отдельным предупреждением, документ при этом не изменён.
