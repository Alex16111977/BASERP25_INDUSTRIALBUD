## 🔴 Четыре ловушки чтения файлов

**1. Рабочий лист финотчёта называется «24,07,2026».** Имя устарело и не меняется от недели
к неделе. В книге 11 листов, первый — архивный «2022» с чужими цифрами. Брать лист **по имени**,
не по порядку и не по максимальному числу строк.

**2. `openpyxl` падает на файле «План факт».** `KeyError: 'xl/sharedStrings.xml'` — 1С выгружает
строковую таблицу как **`xl/SharedStrings.xml` с ЗАГЛАВНОЙ S**, а стандарт требует строчную.
Читать прямым разбором zip+XML, имя файла искать без учёта регистра:

```python
имя_строк = next((n for n in z.namelist() if n.lower() == "xl/sharedstrings.xml"), None)
```

**3. В финотчёте одни и те же числа стоят дважды — на разных уровнях иерархии.**
Отступ ячейки A (`alignment.indent`): **0 — заказчик**, 2 — контрагент под ним, 4 — договор.
У «Глобино-2» (отступ 0) и «АСТАРТА АГРО ПРОТЕЇН ТОВ» (отступ 2) K и H одинаковы.

**Суммировать только строки с отступом 0.** Иначе итог завышается: на 14.08 получалось
5 677 786,16 вместо 5 645 781,04.

**4. В плане-факте затраты и их план — отрицательные** (колонки I и J), маржа тоже может быть
отрицательной. В докладе показывать по модулю. Строка «МД IRC 2026» встречается дважды
(свёртка с дочерними и сама) — при суммировании затрат по подразделениям брать строки
до первого повтора, итог сверять со строкой «Разом».

## Генератор (с 17.08.2026)

Доклад собирает скрипт `_Rarzrabotki/Python/test/doklad_proizvodstvo.py <папка недели>`
(`--print-only` — только проверки). Он читает оба Excel, берёт прошлую неделю из соседней
папки с меньшей датой, строит HTML по вёрстке эталона и сам прогоняет проверки; не сошлось —
файл не пишется. Правки пользователя 17.08.2026, действующие для всех следующих недель:

- **порядок объектов — строго как в файле финотчёта сверху вниз** (на совещании Excel на
  экране, доклад читается строка в строку). Сортировка по убыванию K больше не применяется —
  ни в тексте, ни в таблице;
- **блока «Требует вашего подтверждения» нет** — трактовки идут прямо в тексте;
- **таблицы «Фактические затраты — по подразделениям» нет** — затраты только словами
  (итог + три крупнейших);
- таблица лимитов — в порядке строк файла «План факт» (сортировка по убыванию снята);
- имя объекта печатается как в Excel, короткое — в скобках, если отличается
  («Глобино-2 (Глобино)», «ПрАТ "ОРІЛЬ-ЛІДЕР" (МД МХП ОРІЛЬ)»).

⚠ **Отступы ячейки A в файле 14.08 обнулены** (файл пересохраняли) — правило ловушки 3
«суммировать строки с indent = 0» на нём даёт 11,2 млн вместо 5,6 млн. Рабочий признак
объекта: **жирный шрифт** ячейки A (кроме «Итого»), а строка-контрагент, идущая сразу под
объектом и повторяющая его E/F/H/K («АСТАРТА АГРО ПРОТЕЇН ТОВ» под «Глобино-2»), отсеивается.

⚠ **Секции между неделями сопоставляются по нормализованному имени**: на 07.08 объект
назывался «МД IRS 2026», на 14.08 — «МД IRC 2026» (S↔C). Без нормализации теряется фраза
«подано ещё на 1 255 254».

⚠ **Лимит: маржа-ПЛАН (колонка M), не факт (N)**. У «МД ВООЗ» M пустая при N = −138 500 —
лимит «—», а не 138 500; иначе итог 8 627 548,35 вместо эталонных 8 489 048,35.

## Структура доклада

**1. По файлу «Финансовый_отчет Производства».** Список объектов: сумма к получению,
состояние актов, что изменилось за неделю. Затем фраза об общей сумме и о том, сколько
реально ожидаем. Затем таблица: объект · сумма к получению · подано актов · состояние актов.

**2. По файлу «План факт».** Плановые и фактические поступления и затраты словами, затем
три таблицы: сводная (поступления и затраты), поступления по подразделениям, затраты
по подразделениям. Строки — только те, где факт ненулевой; в конце фраза «по остальным
подразделениям фактических поступлений и затрат нет».

**3. Плановый лимит по направлению «Производство».** Таблица подразделение · лимит · комментарий,
с итогом.

**4. Блок «Требует вашего подтверждения»** — всё, что не выводится из отчётов.

## Правила трактовки

Эти вещи в отчётах **не записаны**; в прошлых докладах их проставлял пользователь.
Считать по правилу и обязательно вынести в блок подтверждения.

**Состояние актов** — по колонке `H`:

| Условие | Формулировка |
|---|---|
| `H > 0` | поданы, не подписаны |
| `H = 0`, `K > 0` | все акты подписаны |
| `H = 0`, `K = 0`, есть оплата > выполнения | новых актов нет, предоплата N |
| `E = F ≠ 0`, `K = 0` | расчёты закрыты |
| всё по нулям | движений нет |

⚠ Признака подписания в отчёте нет. Если сумма ушла из `E` в `H` по сравнению с прошлой
неделей — это может быть снятая по ошибке отметка. Такой случай называть прямо в блоке
подтверждения (на 14.08 так вышло с МК Черноморск на 45 000).

**Ожидаем к поступлению** — сумма `K` тех объектов, у которых `H = 0`. Если у всех объектов
с ненулевым `K` есть неподписанные акты, так и писать: ожидаем ноль.

**Лимиты** — правило читается из комментариев доклада 10.08:

| Условие | Лимит |
|---|---|
| маржа план `M` отрицательная | `|M|`, комментарий «отрицательная маржа» |
| есть факт поступлений `F > 0` | `F`, комментарий «есть приход денег на F» |
| маржа положительная, прихода нет | `0`, «положительная маржа и нет прихода» |
| маржа не заполнена | «—» |

Итога лимитов в отчёте нет — он считается и помечается как наш подсчёт.

## Тон

Спокойно и по факту, без превосходных степеней и без обещаний. Не употреблять «освоєно».
Не считать количество позиций. Оценок людей и поиска виновных нет.

Изменения за неделю называть с причиной из самих отчётов: «сумма к получению снизилась,
потому что получены деньги и подписаны акты» — а не «ситуация улучшилась».

## Обязательная проверка перед выдачей

Скриптом, три слоя. Не сошлось — доклад не отдавать.

**Против исходных файлов:** сумма к получению и подано актов по каждому названному объекту;
итоги плана-факта (план и факт поступлений, план и факт затрат, оба процента).

**Внутренняя сходимость:**
- сумма `K` по строкам с отступом 0 = заявленный общий итог;
- сумма фактических поступлений по подразделениям = итог «Разом»;
- сумма фактических затрат по подразделениям = итог «Разом»;
- сумма лимитов = заявленный итог.

**В готовом HTML:** каждое ключевое число присутствует, и **нет чисел прошлой недели**,
кроме тех, что стоят в явных сравнениях («снизилась с …»).

## Чего не делать

- Не брать первый или последний лист финотчёта — только «24,07,2026».
- Не суммировать строки контрагентов вместе со строками заказчиков.
- Не выдумывать состояние актов там, где его нет в данных.
- Не давать в докладе аналитических врезок и трактовок сверх того, что спросили —
  их убирали из прошлых докладов ([`../knowledge_Письмо Директору/LESSONS.md`](../knowledge_Письмо%20Директору/LESSONS.md), пункт 5).
- Не считать первый вариант финальным: показать пользователю до совещания.
