## Три задачи

1. **Новый регистр сведений `А_ПараметрыДоговоровФинотчета`**: измерение Договор, пять ресурсов
   (бывшие реквизиты договора). Данные мигрируют из справочника, реквизиты `А_*` из
   `ДоговорыКонтрагентов` **удаляются**. Движок читает регистр.
2. **ТЧ «Расчет»: строка = договор** (шаг 7 спеки): добавить реквизиты Контрагент и Договор,
   печать становится многоуровневой — Підрозділ → Контрагент → Договор, K/C/D суммируются вверх.
3. **Вторая печатная форма «Фінансовий звіт з розшифровкою»**: те же уровни + под каждым
   договором строки ВСЕХ документов (оплаты и акты, проведённые и непроведённые с пометкой).
   Основной «Фінансовий звіт» остаётся директорским — до уровня договора, без документов.

## 1. Регистр сведений `А_ПараметрыДоговоровФинотчета`

**Непериодический, независимый** (решение пользователя: историчность НЕ нужна — одна
актуальная запись на договор).

| Часть | Имя | Тип | Примечание |
|---|---|---|---|
| Измерение | `Договор` | `CatalogRef.ДоговорыКонтрагентов` | **Ведущее** (Master=true) — записи умирают вместе с договором; обязательное |
| Ресурс | `СуммаСоглашения` | Число(15,2) | колонка C |

## 2. Миграция данных и удаление реквизитов справочника

**Строгий порядок — данные мигрируют ДО удаления реквизитов из базы:**

1. Загрузить в базу ТОЛЬКО регистр (частичная загрузка: `Configuration.xml` +
   `InformationRegisters/А_ПараметрыДоговоровФинотчета.xml`). Добавление нового объекта
   проходит без монопольного режима.
2. Python-скрипт миграции: прочитать из справочника все договоры, у которых заполнен
   хотя бы один из пяти реквизитов (на 14.08 таких **10**), записать в регистр
   (`РегистрыСведений.А_ПараметрыДоговоровФинотчета.СоздатьМенеджерЗаписи()`).
   Контроль после переноса: записей в регистре = договоров с параметрами; у договора
   «Договір підряду 06/04/26-МК Кривий РІГ» — СуммаСоглашения 7 961 800, процент 15,
   вариант «Виконання − оплата».
3. Удалить пять реквизитов `А_СуммаСоглашения`, `А_СуммаДЦ`, `А_ОбъектПримечание`,
   `А_ПроцентГарантийногоУдержания`, `А_ВариантФормулыИтога` из
   `Catalogs/ДоговорыКонтрагентов.xml` (реквизит `А_ИдКод` НЕ трогать!).
   Загрузка этой правки — реструктуризация **7 959** записей, нужен монопольный режим.
4. Переписать TSV-цикл параметров на регистр: `doc_finrep_dump_dogovorov.py` /
   `doc_finrep_load_dogovorov.py` читают/пишут регистр вместо реквизитов
   (ключ остаётся UUID договора; правило «пустое не затирает, ОЧИСТИТЬ — обнуляет» сохранить).
5. Из словаря `doc_finrep_uk.json` удалить раздел «договор» (ключи `А_*` реквизитов).

## 3. Движок: параметры из регистра

В `Ext/ObjectModule.bsl` функция `ПараметрыДоговоров(Итоги)` меняет ТОЛЬКО источник —
запрос к регистру (прогнать через Python COM до вставки):

```
ВЫБРАТЬ
	П.Договор КАК Договор,
	П.СуммаСоглашения КАК СуммаСоглашения,
	П.СуммаДЦ КАК СуммаДЦ,
	П.ОбъектПримечание КАК Примечание,
	П.ПроцентГарантийногоУдержания КАК ПроцентУдержания,
	П.ВариантФормулыИтога КАК ВариантФормулы
ИЗ
	РегистрСведений.А_ПараметрыДоговоровФинотчета КАК П
ГДЕ
	П.Договор В (&Договоры)
```

Формулы (`ИтогоПоФормулеДоговора`) не меняются. Договор без записи в регистре считается
по дефолту («Заборгованість + акти», процент 0) — как сейчас.

## 4. ТЧ «Расчет»: строка = договор

- Добавить в ТЧ реквизиты: `Контрагент` (`CatalogRef.Контрагенты`), `Договор`
  (`CatalogRef.ДоговорыКонтрагентов`). `Подразделение` остаётся (заказчик).
  Контрагент строки = владелец договора (`Договор.Владелец`).
- `ЗаполнитьСтрокиРасчета()`: вместо суммирования договоров в строку подразделения —
  **строка на каждый договор** с его E/F/G/H/J/K и B/C/D из регистра.
  `ВариантФормулы` строки — фактически применённый вариант (с учётом дефолта).
  Строк станет ~40 вместо 17 (по договорам с движением).
- Подразделение без движения (пустая карта договоров) по-прежнему даёт одну нулевую строку —
  с пустыми Контрагентом и Договором; К02 должен продолжать срабатывать.
- **Контроли К01/К02 агрегируют строки по подразделению**. К01 сверяет
  `СальдоПоПодразделениям` (уже есть в `Рассчитать()`) с агрегатами строк подразделения —
  через ТЧ сальдо не гонять. `Сальдо361` в ТЧ писать в ПЕРВУЮ строку каждого подразделения
  (для глаза), в остальных строках 0.
- Доклад (`МассивФразДоклада`) и `ТекстДокладаHTML()` сворачивают строки Расчет по
  подразделению — их внешний вид НЕ меняется.
- `ОбновитьСостояниеРасчета()` формы: «Рядків: N» теперь = строк-договоров; сумма — та же.
- Форма (`doc_finrep_form.json`): в таблицу «Результат» добавить колонки Контрагент и Договор
  (после Подразделения); master-detail `РасчетПриАктивизацииСтроки` фильтровать расшифровку
  по **Договору** строки (точнее, чем по подразделению; у РасшифровкаДокументов поле Договор есть).
- Переводы новых колонок — в словарь (`РасчетКонтрагент` → «Контрагент», `РасчетДоговор` → «Договір»).

## 5. Печать

Общий рендер с флагом `СРасшифровкой` — не дублировать код построчного вывода.

**«Фінансовий звіт» (кнопка 1, директорская)** — уровни:
- строка Підрозділа — зелёная заливка `Новый Цвет(226, 239, 217)`, жирная, суммы по договорам;
- строка Контрагента — жирная, суммы по его договорам (K контрагента = СУММА K договоров!);
- строка Договора — обычная: A = наименование договора (с отступом), B/C/D из регистра,
  E/F/G/H/J/K свои; I = 0;
- «РАЗОМ» — как сейчас.
Русская двухэтажная шапка, ширины, `ФиксацияСверху` — НЕ трогать (сделано 14.08).
Подстроки контрагентов из `СводРасшифровкиПоКонтрагентам()` больше не нужны —
уровень контрагента теперь настоящий; функцию удалить.

**«Фінансовий звіт з розшифровкою» (кнопка 2, новая)** — то же + под каждым договором
строки документов из ТЧ `РасшифровкаДокументов` этого договора:
- A = дата (`ДФ=dd.MM.yyyy`) + представление документа (с двойным отступом), шрифт 9;
- суммы по виду строки: `ВыполненныеРаботы` → E, `Оплата` → F,
  `АктПоданный`/`АктПоданныйНепроведенный` → H; B/C/D/I/J/K пустые;
- непроведённые (`НЕ ДокументПроведен`) — оранжевый текст `Новый Цвет(138, 90, 0)`
  и суффикс « (не проведено)»;
- сортировка внутри договора: по дате, затем по документу.
Команда формы `ПечатьОтчетРасшифровка`, кнопка в подменю «Друк» после «Фінансовий звіт»,
заголовок «Фінансовий звіт з розшифровкою» (ru и uk одинаково). В модуле объекта —
экспортная `СформироватьПечатьОтчетРасшифровка()`.

⚠ Расшифрованный отчёт — ~900 строк на боевом документе: это нормально, он рабочий,
не директорский. `АвтоМасштаб` оставить, ориентация та же (ландшафт).

## Грабли, на которые уже наступали

- **Загрузчик BSL не компилирует код** — обязателен COM-smoke, инстанцирующий объект (§9).
- **Configuration.xml: частичная загрузка УДАЛЯЕТ незарегистрированное** — перед КАЖДОЙ
  загрузкой с Configuration.xml сверять состав с живой базой (§21; готовый скрипт-аудит
  по типам метаданных был в сессии 14.08).
- **UpdateDBCfg требует монопольного режима** при реструктуризации — тонкий клиент
  пользователя (cfo) блокирует; сеанс не снимать, попросить закрыть.
- **Частичная загрузка формы — только обёртка** `Forms/ФормаДокумента.xml` (§17).
- **`Формат(0, "ЧДЦ=2")` печатает пустую строку** — в сообщениях `ЧН=0,00` (§11).
- **`СправочникСсылка + "строка"`** не приводится — ссылка справа или в `Строка()` (§10).
- **Пустая ссылка-заглушка в `В (&Параметр)`** ловит незаполненные поля — пустой массив легален (§1).
- **Не объявлять локальную переменную `Ссылка`** и процедуру `Выполнить` — зарезервированы.
- **grep-чек парности** `Функция/КонецФункции`, `Процедура/КонецПроцедуры` перед загрузкой.
- **Патчер uk запускать после каждой перегенерации** meta-/form-compile; проверка
  `xml.dom.minidom.parse()` до загрузки (§23).
- Полный список — [LESSONS.md](LESSONS.md).
