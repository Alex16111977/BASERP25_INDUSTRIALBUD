## 2. Блок «Казна» в документе

### Метаданные
- ТЧ **`СтатьиИсключенияКазны`**: реквизит `Статья` Строка(150). `ОбработкаЗаполнения`
  заполняет 6 статей по умолчанию: «Поступление от Фин агента», «Оплата Фин агентам»,
  «Транзит Исх», «Транзит Вх», «Внутригрупповые затраты», «Внутригрупповые доходы».
- ТЧ **`Казна`** (результатная, очищается при расчёте): `Подразделение`
  (CatalogRef.Подразделения, пусто если не сопоставлено), `ИмяВКазне` Строка(150),
  `ПоступленияПлан`, `ПоступленияФакт`, `ЗатратыПлан`, `ЗатратыФакт`, `МаржаПлан`,
  `МаржаФакт` — Число(15,2). Вкладка «Казна» на форме (после «Розрахунок»);
  форма пересобирается ТОЛЬКО из `doc_finrep_form.json` + патч Autofill + патчер uk.

### Заполнение (в `Рассчитать()`, после основного расчёта; сбой казны НЕ роняет расчёт — Попытка/Исключение, П34)
Механика — как `Отчеты.ПланФакт` казны (исходники: `_Rarzrabotki/Kazna/Reports/ПланФакт/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml`):
- **Факт** — `РН.БДДС.Обороты(НачалоМесяца(ДатаРасчета), КонецДня(ДатаРасчета), Авто)`:
  Доход = обороты статей В ИЕРАРХИИ группы доходов (знак по `НаправлениеДДС`),
  Расход — группы расходов. Группы — как параметры `&ГруппаДоход`/`&ГруппаРасход` варианта
  «Производство» (посмотреть сохранённый вариант отчёта в kazna или корни иерархии
  справочника СтатьиДвиженияДенежныхСредств).
- **План** — `РН.БюджетыНаМесяц.Обороты(НачалоМесяца, КонецМесяца(ДатаРасчета), Авто,
  ВидПериода = МЕСЯЦ)` (план берётся на ВЕСЬ месяц; факт — по дату расчёта).
- Отборы: `Направление = Производство`; `Подразделение` НЕ в («Главный офис»,
  «Цех металлоконструкций») — списком в коде; `СтатьяДвиженияДенежныхСредств.Наименование`
  НЕ в ТЧ `СтатьиИсключенияКазны` (сопоставление по НАИМЕНОВАНИЮ — справочника статей
  в BuhBud нет).
- Иерархия: у казны подразделения вложены («МД IRC 2026 15 м №6» → «МД IRC 2026») —
  свернуть до РОДИТЕЛЯ ВЕРХНЕГО уровня, сопоставить с `Справочники.Подразделения` BuhBud
  по имени (двойные пробелы значимы; не найдено → строка с пустым Подразделением, П33).
- ⚠ Весь запрос выполняется НА СТОРОНЕ казны (`Казна.NewObject("Запрос")`), в BuhBud
  возвращаются только строки/числа (LESSONS: COM-объекты не таскать).

### Контроли (после заполнения)
- **К12** (Предупреждение): подразделение из ТЧ `Казна` (с ненулевым фактом или планом)
  отсутствует среди строк расчёта финотчёта — «в казні є, у фінзвіті не світиться».
- **К13** (Предупреждение): `ПоступленияФакт` казны ≠ оборот **Кт 361 за той же месяц**
  по подразделению (отдельный запрос в BuhBud: `Хозрасчетный.Обороты(НачалоМесяца,
  КонецДня(ДатаРасчета), , Счет=361)`, Кт по подразделению договора, фильтр направления).
  Допуск 1 грн; текст замечания — обе суммы и разница (`ЧН=0,00`).

## 3. Динамика к прошлому отчёту

- Реквизит шапки **`ДокументСравнения`** (DocumentRef.А_ФинансовыйОтчетПроизводства).
  Автозаполнение при `Рассчитать()` если пуст: последний записанный непомеченный документ
  того же направления с `ДатаРасчета` меньше текущей.
- Печатная форма **«Динаміка»** (кнопка в подменю «Друк», команда `ПечатьДинамика`,
  экспортная `СформироватьПечатьДинамика()`), уровни с автогруппировкой как в основной печати:
  - шапка: обе даты; по підрозділу таблица «Показник | було | стало | зміна» для E/F/H/K
    (регламент `knowledge_Письмо Директору/03_dinamika_nedeli.md`: сравнивать отчёт с отчётом);
  - по договорам — строки с ненулевой зміною;
  - «Що дало зміну»: НОВІ документы (в текущей `РасшифровкаДокументов`, нет в прошлой;
    ключ Договор+Документ) — оплаты (СуммаКт), відвантаження/виконані роботи, акти —
    с датами, суммами и расшифровкой-ссылкой (клик открывает документ); ушедшие документы
    (были — исчезли) отдельным блоком;
  - улучшения сверху, ухудшения снизу; фразы-выводы экономиста под таблицами.
- **HTML-доклад «Динаміка»** (`ТекстДинамикиHTML()` + кнопка «Зберегти динаміку в HTML»):
  структура и тон — по `knowledge_Письмо Директору` (01_struktura, 02_pokazateli,
  03_dinamika, 04_takt) и образцу
  `_Rarzrabotki/Письмо Директору по отчетам на производство/12082026/Лист_МД_IRC_2026_12-08-2026.html`:
  по каждому объекту абзац («виконано робіт на…, оплачено…, подано актів…»), таблица динамики,
  перечень событий недели; без оценок и жаргона; числа в таблицах до копеек, в тексте — тыс. грн.
- Прошлый документ читается через `ДокументСравнения.ПолучитьОбъект()` — БЕЗ пересчёта
  (сравниваем записанные результаты; LESSONS «отчёты перевыпускают» — сравнивать отчёт с отчётом).

## Грабли (сверх LESSONS.md)

- Казна недоступна → П34, расчёт НЕ падает (паттерн уже в `ЗаполнитьПодразделенияИзКазны`).
- Скриншот План-факта и xlsx дают РАЗНЫЕ затраты-факт — состав статей-исключений различался;
  эталон = xlsx.
- «Ділення на 0» в отчёте казны — у вложенных IRC нет плана; при свёртке НЕ считать проценты.
- Значения уровней/статусов/видов — СТРОКИ («Помилка», «Попередження»…) — сравнивать строками.
- В kazna `Статья движения денежных средств` — справочник казны: в ТЧ хранить НАИМЕНОВАНИЯ.
- Печать — потоковая с автогруппировкой: `Вывести(БуферТабДок, Уровень)`; Вывести принимает
  ТабличныйДокумент, НЕ Область (рантайм-ошибка, ловит только smoke); ширины буферов идентичны.
- `ДокументСравнения` в дельте не пересчитывать — читать записанные ТЧ.
