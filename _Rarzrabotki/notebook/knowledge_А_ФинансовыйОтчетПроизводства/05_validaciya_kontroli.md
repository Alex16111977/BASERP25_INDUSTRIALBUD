# 05. Валидация и контроли

Два слоя. **П\*** — проверки параметров ДО расчёта, часть блокирует. **К\*** — контроли ПОСЛЕ
расчёта, все информируют. Оба слоя пишут в ТЧ `Контроль` и дублируются в панель сообщений
с привязкой к строке ТЧ.

> **Обновление 14.08.2026** (чистка ТЧ, параметры — из договора): удалены П10, П14, П19
> (проверки ТЧ-параметров подразделения), П22–П28 (корректировки/исключения) и К11
> (сводка исключений). К10 переформулирован: «проведіть документ або виправте первинку».
> Добавлены: **П33** — имя из kazna не найдено в справочнике; **П34** — не заполнена константа
> подключения / Казна недоступна / запрос не выполнился; **П35** — информация о числе
> добавленных из kazna подразделений.

## Как работает привязка к строке

```bsl
Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = Код + ": " + Текст;
Сообщение.Поле  = "Объект.Подразделения[0].ПроцентУдержания";
Сообщение.УстановитьДанные(ЭтотОбъект);
Сообщение.Сообщить();
```

Клик по сообщению ставит курсор в проблемное поле. `УстановитьДанные` обёрнут в
`Попытка/Исключение`: на незаписанном объекте привязка недоступна, текст всё равно покажется.

Платформенный `СообщениеПользователю` выбран вместо БСП-обёртки — меньше зависимостей.

## Уровни

`А_УровниКонтроляФинотчета`: **Ошибка** (блокирует расчёт), **Предупреждение**, **Информация**.
После `ПроверитьПараметры()` наличие хотя бы одной ошибки → расчёт не запускается,
статус `ЕстьЗамечания`.

## П* — параметры (до расчёта)

| Код | Уровень | Что ловит |
|---|---|---|
| П01 | Ошибка | ТЧ подразделений пуста или все строки выключены |
| П02 | Ошибка | подразделение указано дважды (с номерами обеих строк) |
| П03 | Ошибка | пустое подразделение в строке |
| П04 | Ошибка | не заполнена дата расчёта |
| П05 | Ошибка | начало периода позже даты расчёта |
| П06 | Предупр. | счета расчётов не заданы — подставлен 361 |
| П07 | Ошибка | у счёта второе субконто не «Договори» → разрез невозможен |
| П08 | Ошибка | пустой счёт в строке |
| П10 | Предупр. | процент удержания вне 0..100 — **обрезан** |
| П11 | Предупр. | параметр задан, но выбранная формула его не использует |
| П12 | Предупр. | подразделение помечено на удаление |
| П13 | Предупр. | дата расчёта в будущем |
| П14 | Предупр. | не задан вариант формулы — взят по умолчанию |
| П15 | Предупр. | договор из «Договорів додатково» уже входит по своему подразделению → **двойной счёт**, строка игнорируется |
| П16 | Ошибка | доп. договор отнесён к подразделению вне расчёта |
| П17 | Предупр. | дубль договора в «Договорах додатково» |
| П18 | Предупр. | ставка НДС = 0 |
| П19 | Предупр. | коэффициент актов вне 0..1 — обрезан |
| П20 | Ошибка | неизвестный вариант формулы |
| П21 | Ошибка | пустой договор в «Договорах додатково» |
| П22 | Ошибка | **корректировка без причины** |
| П23 | Ошибка | корректировка на подразделение вне расчёта |
| П24 | Предупр. | корректировка с суммой 0 |
| П25 | Ошибка | пустой документ в исключениях |
| П26 | Ошибка | **исключение документа без причины** |
| П27 | Предупр. | документ в исключениях дважды |
| П28 | Ошибка | в корректировке не выбрана колонка |
| П30 | Предупр. | подразделение из списка не найдено по наименованию |
| П31 | Предупр. | направление не задано — войдут договоры ВСЕХ направлений |
| П32 | Информ. | сколько подразделений добавлено по направлению и сколько пропущено без движений |

**П22 и П26 — принципиальные.** Ручная сумма и исключение документа без объяснения запрещены:
именно так «магическая константа 1 194 270» жила в Excel годами, и никто не знал, откуда она.

Часть проверок **чинит на месте и предупреждает**: П10 обрезает процент, П19 — коэффициент,
П06 подставляет счёт, П14 — вариант формулы, П15/П17 удаляют дублирующие строки.

## К* — контроли (после расчёта)

| Код | Уровень | Что показывает |
|---|---|---|
| К01 | Предупр. | сверка не сошлась: `Сальдо − H_проведённые ≠ G`, с разницей |
| К02 | Предупр. | по подразделению нет ни одного движения за период |
| К03 | Предупр. | договоры с оборотом вне расчёта: количество, сумма, пять крупнейших |
| К04 | Информ. | сколько непроведённых вошло в H и на какую сумму |
| К05 | Информ. | сколько проведённых без отметки «Оригінал» |
| К06 | Информ. | отрицательный итог к получению — переплата или неверная формула |
| К08 | Информ. | оплата без единого акта — аванс заказчика |
| К10 | Предупр. | **каждый** непроведённый документ поимённо с суммой |
| К11 | Предупр. | что исключено вручную: количество и сумма |

**К10 назван поимённо намеренно.** Непроведённый документ — самая частая причина расхождения
с ручным отчётом, и пользователь должен видеть конкретный документ, а не общую цифру.

**К01 вычитает только проведённую часть H** — непроведённых в сальдо нет. Первая версия
вычитала всё H и ругалась на каждую строку с непроведёнными ([LESSONS §4](LESSONS.md)).

без причины, исключение без причины. Каждый должен поднять свой код и правильно решить,
блокировать расчёт или нет.
