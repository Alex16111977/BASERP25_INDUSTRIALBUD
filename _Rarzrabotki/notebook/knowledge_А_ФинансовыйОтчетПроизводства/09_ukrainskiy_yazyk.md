# 09. Украинский язык интерфейса

## Симптом

Форма открывается, а вместо подписей — **имена элементов**: кнопка «Рассчитать» вместо
«Розрахувати», поле «ДатаРасчета», колонка «ДокументПроведен», значение «ВыполненныеРаботы»
в колонке «Вид». **Закладки страниц пустые** — у страницы имя не отображается вовсе.

Отображалась только вкладка «Контроль (9)», потому что её заголовок ставится кодом.

## Причина

В конфигурации `DefaultLanguage = Language.Украинский` — сеанс идёт на украинском.
А `form-compile` и `meta-compile` жёстко эмитят только `<v8:lang>ru</v8:lang>`:

```powershell
X "$indent`t`t<v8:lang>ru</v8:lang>"   # form-compile.ps1, строка 73
X "$indent`t`t<v8:lang>ru</v8:lang>"   # meta-compile.ps1, строка 219
```

Мультиязычности в DSL нет. Для украинского перевода не находится — платформа подставляет имя.

Масштаб на момент обнаружения:

| | uk | ru |
|---|---|---|
| Форма `РасчетКомплектаций` (эталон) | **90** | 2 |
| Метаданные `РасчетКомплектаций` | **82** | 75 |
| Наша форма | **0** | 24 |
| Наши метаданные | **0** | 75 |

Заголовки колонок таблиц берутся из **синонимов реквизитов ТЧ**, поэтому одной формы мало —
украинский нужен и в метаданных документа, и в перечислениях.

## Решение: словарь + идемпотентный патчер

`_Rarzrabotki/Python/test/doc_finrep_uk.json` — плоское соответствие «имя объекта → украинский
текст», сгруппированное по разделам (договор, документ, табличные части, реквизиты ТЧ,
перечисления, значения перечислений, форма, колонки формы). 159 записей.

`doc_finrep_patch_uk.py` проходит по XML документа, пяти перечислений, формы и справочника
договоров и вставляет пару `<v8:item><v8:lang>uk</v8:lang><v8:content>…</v8:content></v8:item>`
в каждый `<Synonym>` / `<Title>`, где uk ещё нет.

Русские подписи **остаются** — их видит разработчик в конфигураторе. Так же сделано в эталоне.

**Запускать после любой перегенерации** `meta-compile` / `form-compile` — иначе переводы
затираются. Идемпотентен: повторный прогон ничего не делает.

Имена без перевода печатаются списком: «немає перекладу для N імен — лишились російськими».
Молча пропускать нельзя.

## Два шаблона, а не один

**Метаданные** — имя в теге:

```
<Name>ДатаРасчета</Name>
<Synonym>…</Synonym>
```

**Форма** — имя в **атрибуте**, и между ним и `<Title>` есть другие теги:

```xml
<Button name="КнопкаРассчитать" id="2">
	<Type>UsualButton</Type>
	<CommandName>Form.Command.Рассчитать</CommandName>
	<Title>…
```

Поэтому для формы отдельный шаблон с негативным просмотром, чтобы не «убежать» в следующий
именованный элемент:

```python
r'(?P<голова><\w+ name="(?P<имя>[^"]+)"[^>]*>'
r'(?:(?!<\w+ name=)[\s\S])*?'
r'<(?P<тег>Title)>)(?P<тело>.*?)(?P<закрытие></(?P=тег)>)'
```

## 🔴 Грабля: нумерация групп в регексе

Первая версия использовала позиционные группы `m.group(1) + вставка + m.group(5)`. В шаблоне
для формы появилась лишняя группа, `m.group(5)` стало телом вместо закрывающего тега —
и `</Title>` **терялся**. XML стал невалидным.

→ Только **именованные группы**: `m.group("голова") + вставка + m.group("закрытие")`.
→ И обязательная проверка `xml.dom.minidom.parse()` **до** загрузки в базу. Она это и поймала;
сломанный файл в базу не попал.

## Результат

126 подписей: 73 в документе, 22 в форме, 25 в пяти перечислениях, 6 в реквизитах договора.
Все XML проверены на валидность.

## Что важно переводить

Не только видимые поля. **Значения перечислений** формируют содержимое колонок: без перевода
в колонке «Вид» стоит `ВыполненныеРаботы`, а не «Виконані роботи». **Синонимы реквизитов ТЧ**
дают заголовки колонок таблиц. **Заголовки страниц** без перевода дают пустые закладки.

## Проверка

Счётчик по каждому файлу: uk-подписей должно быть не меньше ru. Патчер печатает это сам:

```
+ А_ФинансовыйОтчетПроизводства.xml   додано 73, вже було 0  |  ru=75 uk=73
+ Ext/Form.xml                        додано 22, вже було 0  |  ru=24 uk=22
```

Разница ru−uk — это подписи, которых нет в словаре (обычно служебные, вроде `ExtendedTooltip`).
