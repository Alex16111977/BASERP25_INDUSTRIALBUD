> Все факты ниже **проверены COM-запросами к живым базам 2026-08-14** — перепроверять не нужно,
> но каждый НОВЫЙ запрос обязательно прогонять на живой базе до вставки в BSL (Rule #-1).

> Контекст по документу — база знаний `_Rarzrabotki/notebook/knowledge_А_ФинансовыйОтчетПроизводства/`,

## 1. Убрать «Зауваження до розрахунку»

В `Ext/ObjectModule.bsl` есть функция `ВывестиБлокЗамечаний(ТабДок, НомерСтроки, КолонокВсего)`.
Она вызывается дважды — в `СформироватьПечатьОтчет()` и `СформироватьПечатьДоклад()`.

Убрать **вызовы** из обеих печатных форм и саму функцию. Блок замечаний в `ТекстДокладаHTML()`
тоже убрать.

⚠ **ТЧ `Контроль` и вкладку «Контроль» на форме НЕ трогать** — контроль остаётся рабочим
инструментом расчёта, из печати уходит только его вывод. Коды П* и К* продолжают работать.

## 2. Шапка печатной формы — русская, двухэтажная

Эталон — `_Rarzrabotki/Доклады по производству/10082026/Финансовый_отчет Производства  07-08-2026.xlsx`,
лист «24,07,2026», строки 4–5. Одиннадцать колонок.

| Кол. | Верхний этаж (стр. 4) | Нижний этаж (стр. 5) |
|---|---|---|
| A | Контрагент | Договор |
| B | Примечание | *(объединено вертикально)* |
| C | Сумма утвержденного соглашения | *(объединено)* |
| D | Сумма ДЦ поданной на рассмотрение | *(объединено)* |
| E | Фактические данные на дату составления отчета *(объединено E:G)* | Выполненные работы грн. |
| F | *(часть объединения E:G)* | Оплачено грн. |
| G | *(часть объединения E:G)* | Задолженность, грн. (аванс-) |
| H | Поданные акты на рассмотрении | Акты поданные на Заказчика |
| I | Гарантийные платежи | *(объединено)* |
| J | Сумма незарегестрированного НДС по проведенным актам | *(объединено)* |
| K | ИТОГО сумма к получению | *(объединено)* |

Объединения из Excel: `B4:B5`, `C4:C5`, `D4:D5`, `I4:I5`, `J4:J5`, `K4:K5` — вертикальные;
`E4:G4` — горизонтальное. **A и H НЕ объединены** — у них два этажа с разным текстом.

Текст писать **дословно, включая опечатку «незарегестрированного»** — так в эталоне,
директор сверяет глазами.

Оформление: заливка светло-зелёная (в Excel — `#C6D9A0`), жирный шрифт, выравнивание по центру,
перенос по словам, границы по всем сторонам. Ширины колонок из Excel: A=45, B=48, C=18,5,
G=20,3, H=18,5, I=18,5; остальные по умолчанию.

⚠ **`ШиринаКолонки` ставить только на НЕобъединённой строке** — иначе платформа игнорирует.
В текущем коде для этого выделена пустая строка 3.

## 3. Кнопка «Заповнити» над ТЧ «Підрозділи»

### Источник — база kazna

**`Срвр="SQLSERVER";Ref="kazna";Usr="cfo";Pwd="2442"`** ⚠ пароль `cfo/2442`, НЕ `Администратор/24043`.

Список подразделений даёт **`РегистрНакопления.БюджетыНаМесяц`**, а НЕ `БДДС`:

```
ВЫБРАТЬ РАЗЛИЧНЫЕ
  Об.Подразделение.Наименование КАК Имя
ИЗ РегистрНакопления.БюджетыНаМесяц.Обороты(&НачалоМесяца, &ДатаРасчета, , Направление = &Направление) КАК Об
ГДЕ Об.Подразделение <> ЗНАЧЕНИЕ(Справочник.Подразделения.ПустаяСсылка)
УПОРЯДОЧИТЬ ПО Имя
```

где `&Направление` = `Справочники.Направления.НайтиПоНаименованию("Производство", Истина)` в kazna,
`&НачалоМесяца` = `НачалоМесяца(ДатаРасчета)`, `&ДатаРасчета` = `КонецДня(ДатаРасчета)`.

**Проверено:** за 01.08–07.08.2026 запрос даёт **15 подразделений, из них 14 — ровно те, что
в отчёте `План факт Производство на 07-08-2026.xlsx`**. Пятнадцатый — «Главный офис», в отчёте
его нет; исключать по имени (либо дать флаг «Включати Главний офіс», по умолчанию снят).

🔴 **`РегистрНакопления.БДДС` для этой задачи не годится** — его обороты за тот же период дают
всего **4 совпадения из 14**. Название отчёта «ПланФакт» туда толкает, но источник другой.

### Сопоставление kazna → BuhBud

Справочник `Подразделения` есть в обеих базах, имена совпадают **14/14**, UUID — только **12/14**
(«МД Кернел Кухня» и «МК Глобино» заведены независимо). **Сопоставлять по наименованию.**

⚠ В именах есть **двойные пробелы** («МД ПРООН Черкаси␣␣ДСНС», «МД ВООЗ␣␣2025») — при поиске
не «схлопывать». Не найденные по имени выносить в `Контроль` кодом П33, молча не пропускать.

### COM-подключение из BSL

Строку подключения хранить в новой константе `А_СтрокаПодключенияКазна` (тип Строка(200)),
чтобы не зашивать в код. Подключение оборачивать в `Попытка/Исключение`: kazna может быть
недоступна, и это не должно ронять форму.

Паттерн кросс-базового доступа — в `CLAUDE.md`, раздел «CROSS-BASE UUID lookup»: работает только
`V83.string(...)` (английское, строчными), кириллические методы через COM-прокси ненадёжны.
Здесь UUID не нужен — сопоставляем по имени, но COM-объекты всё равно нельзя приводить `Строка()`:
брать `.Наименование` **на стороне kazna** и передавать уже строку.

### Поведение кнопки

Диалог как у существующей «Заповнити підрозділи»: если ТЧ не пуста — спросить «перезаполнить
с нуля / добавить недостающие / отмена». Заполненные строки не дублировать.

## 4. Чистка табличных частей

## Грабли, на которые уже наступали

- **Загрузчик BSL не компилирует код.** «Load completed successfully» ничего не гарантирует —
  ошибка вылезет на исполнении. Обязателен COM-smoke, который инстанцирует объект и вызывает методы.
- **`СправочникСсылка + "строка"`** не приводится — ссылка должна быть справа или в `Строка()`.
- **Частичная загрузка формы**: в списке файлов ТОЛЬКО `Forms/<Форма>.xml`, иначе
  «Неизвестный объект метаданных …Form.…Ext».
- **`Формат(0, "ЧДЦ=2")` печатает пустую строку** — в сообщениях нужен `ЧН=0,00`.
- **Открытый конфигуратор на `bas_industrialbud` откатывает загрузку** — проверять
  `Get-CimInstance Win32_Process -Filter "Name='1cv8.exe'"`.
- **COM срезает время у даты**: записанная `ДатаРасчета` становится 00:00:00. Движок сам приводит
  к `КонецДня()` функцией `МоментРасчета()` — не ломать это.
- Полный список — [LESSONS.md](LESSONS.md).

## Чего НЕ делать

- Не трогать методику расчёта E/F/G/H — она проверена и сходится с Excel.
- Не удалять ТЧ «Контроль» и вкладку «Контроль» — убирается только вывод в печать.
- Не переводить шапку печатной формы на украинский: заказчик сверяет её с Excel.
- Не вводить обратно «коэффициент актов» — он сведён к проценту удержания.
