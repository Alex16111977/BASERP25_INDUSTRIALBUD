### Ключевий принцип Stage v3

**Один регістр сведень об'єднує 4 джерела даних** через `Источник`-вимір (ЕРП / Казна / План / ПланОбъекта). Кожна строка має заповнений лише ОДИН ресурс відповідно до `Источник`:
- `Источник=ЕРП` → `Сумма` + `СуммаВВалюте` (інші 3 = 0)
- `Источник=Казна` → `СуммаКазна` (інші 4 = 0)
- `Источник=План` → `СуммаПлан` (інші 4 = 0)
- `Источник=ПланОбъекта` → `СуммаПланОбъект` (інші 4 = 0)

Це дає змогу робити DAX-аналіз `план vs факт vs Казна` через single-pass `CALCULATE` з фільтром по `Источник`.

### Cross-month захист

`Документ.А_БюджетМесяц.ОбработкаПроведения` пише рухи з `Период = ДокументОснование.Дата` коли документ є коригуючим. Без додаткового фільтра в Branch 3 це призводить до cross-month колізії ключа в RecorderSubordinate Nonperiodical. Тому в `СформироватьЗапросСверткиDDS` додано `WHERE Пл.Регистратор.Дата МЕЖДУ &НачалоПериода И &КонецПериода` щоб брати лише плани з власною Датою у поточному місяці.

- Ф1/Ф2 split по Регістратор: ПКО/РКО → СуммаФ2, інше → СуммаФ1.
- ФизЛицо CASE: `ВЫБОР КОГДА Регистратор ССЫЛКА Документ.АвансовыйОтчет ТОГДА Регистратор.ПодотчетноеЛицо ИНАЧЕ NULL КОНЕЦ`.
- Аналитика CASE: `Контрагент.Наименование` else `ФизЛицо.Наименование` else "" — обрізана через `ВЫРАЗИТЬ КАК Строка(200)`.
- NULL fallback для `ВыручкаИСебестоимостьПродаж.ДокументДвижения` (375 рядків з NULL у лютому 2026 — без fallback виходять дублі ключа RecorderSubordinate).
- Фінальний SELECT з `СГРУППИРОВАТЬ ПО` 11 вимірах + `СУММА()` ресурсів — обов'язковий dedupe.
- Після `Загрузить()`: збір унікальних `ДокументДвижения` у Массив + виклик `РегистрыСведений.А_ДокументРасшифровка.ОбновитьПоДокументам(МассивДок)`.

**Кардинальність (Stage v2, лютий 2026):**
- `А_ОтчетPL_Свод` рядків = **3915** PL_ЕРП (раніше 3937 без розділення Source).
- Глобино-2 / PL_ЕРП / Виручка від продажу = **38 432 968.66 ₴** (acceptance gate, parity до копійки).

Деталі BSL: [olap_obrabotka_provedeniya.md](olap_obrabotka_provedeniya.md).

### ManagerModule.bsl — 2 експортних функції

#### `ОбновитьПоДокументам(МассивДокументов) Экспорт`
Універсальна процедура. Для кожного унікального документа:
1. `НабРез = РегистрыСведений.А_ДокументРасшифровка.СоздатьНаборЗаписей()`
2. `НабРез.Отбор.Документ.Установить(ДокСсылка)`
3. `НабРез.Прочитать()` → `Очистить()`
4. `НоваяЗапись = НабРез.Добавить()` → заповнити поля з `ДокСсылка.<реквізит>`
5. `НабРез.Записать()`

Поля заповнюються:
- `ДатаДокумента = ДокСсылка.Дата`
- `НомерЕРП = Лев(Строка(ДокСсылка.Номер), 20)`
- `ВидДокументаЕРП = Лев(ДокСсылка.Метаданные().Имя, 60)`
- `Комментарий = Лев(Строка(ДокСсылка.Комментарий), 1000)` (Попытка)
- `НомерБухгалтерский = Лев(Строка(ДокСсылка.А_НомерДокументаИзБух), 20)` (Попытка)
- `ВидДокументаБухгалтерия = ПолучитьВидBuhBud(ВидДокументаЕРП)`
- `ПредставлениеДокумента = ДокСсылка.Метаданные().Синоним + " " + НомерЕРП + " от " + Формат(ДокСсылка.Дата, "ДФ=dd.MM.yyyy")`

#### `ПолучитьВидBuhBud(ВидERP) Экспорт`
Хардкод-мапа ERP-вид → BuhBud-вид (12 пар, не всі ERP-документи мають парний BuhBud-документ — повертає "" для таких):
| ERP-вид | BuhBud-вид |
|---|---|
| ПриобретениеТоваровУслуг | ПоступлениеТоваровУслуг |
| РеализацияТоваровУслуг | РеализацияТоваровУслуг |
| ПриходныйКассовыйОрдер | ПриходныйКассовыйОрдер |
| РасходныйКассовыйОрдер | РасходныйКассовыйОрдер |
| ПоступлениеБезналичныхДенежныхСредств | ПоступлениеНаРасчетныйСчет |
| СписаниеБезналичныхДенежныхСредств | СписаниеСРасчетногоСчета |
| АвансовыйОтчет | АвансовыйОтчет |
| АктВыполненныхРабот | РеализацияТоваровУслуг |
| ВозвратТоваровПоставщику | ВозвратТоваровПоставщику |
| ВозвратТоваровОтКлиента | ВозвратТоваровОтКлиента |
| КорректировкаРеализации | КорректировкаРеализации |
| ОтражениеЗарплатыВФинансовомУчете | ОтражениеЗарплатыВРеглУчете |
