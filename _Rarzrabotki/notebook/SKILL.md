# Навыки и инструменты 1С-разработчика Middle–Senior

> **Назначение:** структурированная карта компетенций AI-ассистента для задач разработки на платформе
> 1С:Предприятие 8.3. Охватывает язык BSL, запросы, интеграции, DevOps, тестирование и soft-скиллы.
> Актуально на 2024–2026 гг. Платформа: 8.3.20+.

---

## 1. ПЛАТФОРМА И ЯЗЫК BSL

### 1.1 Базовые навыки платформы

1. Знание архитектуры клиент-сервер 1С: разделение контекста (клиент / сервер / общий), модели
   лицензирования, файловый и клиент-серверный варианты работы.
2. Свободное владение языком BSL: типы данных, коллекции (Массив, Структура, Соответствие, СписокЗначений,
   ТаблицаЗначений), процедуры/функции, параметры по умолчанию, директивы компиляции.
3. Управляемые формы: жизненный цикл формы, реквизиты, команды, условное оформление, расширения форм
   через расширения конфигурации.
4. Объекты метаданных: справочники, документы, регистры (накопления, сведений, бухгалтерии, расчёта),
   обработки, отчёты, перечисления, константы, планы видов характеристик, планы обмена.
5. Модули: объекта, менеджера, формы, общие модули (серверные, клиентские, КлиентСервер, ВызовСервера,
   ПовтИсп, Переопределяемый) — правила именования и разделение ответственности (#std469).
6. Области кода (#Область / #КонецОбласти): стандартная структура для модулей формы и общих модулей
   (#std455).

**Антипаттерны:**
- Код бизнес-логики в модуле формы вместо общего модуля или модуля объекта.
- Смешивание клиентского и серверного кода в одном модуле без директив компиляции.
- Использование `&НаСервере` вместо `&НаСервереБезКонтекста` там, где контекст формы не нужен
  (передаёт весь объект формы на сервер — мегабайты трафика при большой ТЧ).
- Прямой вызов одного обработчика события из другого — выносить логику в отдельную процедуру.

### 1.2 Стиль кода и стандарты

1. Именование в PascalCase: переменные, процедуры, функции, реквизиты (#std454).
2. Процедуры — инфинитив глагола: `ЗагрузитьКонтрагента()`. Функции — описание результата без «Получить»:
   `ПолноеИмя()`. Конструкторы — «Новый/Новое/Новая». Булевы проверки — «Это…» или причастие (#std647).
3. Документирование экспортных процедур: блок `// Параметры:` / `// Возвращаемое значение:` (#std453).
4. Удалять мёртвый код: закомментированные фрагменты, `// TODO`, `// debug`, неиспользуемые переменные.
5. Максимальная длина строки 120 символов, отступы — табуляция.
6. Инициализировать переменные до условных ветвей (иначе остаются `Неопределено` в нераскрытых ветках).

### 1.3 Транзакции и обработка ошибок

1. `НачатьТранзакцию()` — всегда ДО блока `Попытка`; `ЗафиксироватьТранзакцию()` — последняя строка
   внутри `Попытка`; `ОтменитьТранзакцию()` — первая строка в `Исключение`; `ВызватьИсключение` —
   обязательно, не глотать исключения.
2. Помнить: в 1С **нет вложенных транзакций**. `НачатьТранзакцию()` внутри уже открытой только
   увеличивает счётчик, но после первой ошибки транзакция «отравлена» — `ЗафиксироватьТранзакцию()`
   упадёт гарантированно.
3. Никогда не перехватывать ошибку записи внутри цикла с `Продолжить` в рамках одной транзакции.
4. Каждый блок `Исключение` обязан вызывать `ЗаписьЖурналаРегистрации` с
   `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.

**Антипаттерны:**
- `НачатьТранзакцию()` внутри `Попытка` — если сама функция упадёт, `ОтменитьТранзакцию()` вызовется
  на несуществующей транзакции.
- Пустой блок `Исключение` — ошибка скрыта, диагностика невозможна.
- `Попытка/Исключение; Продолжить` внутри цикла в открытой транзакции.

### 1.4 Работа с расширениями конфигурации

1. Расширения (с платформы 8.3.6) — предпочтительный способ доработки типовых конфигураций без снятия
   с поддержки.
2. Аннотации: `&Перед` и `&После` — безопасные перехватчики; `&Вместо` — с осторожностью (блокирует
   обновление типовой логики).
3. Назначение расширения: Исправление → Адаптация → Дополнение (порядок подключения при старте).
4. С платформы 8.3.17 — подписки на события через расширения; с 8.3.20 — определяемые типы,
   предопределённые элементы, общие реквизиты.
5. Использовать только публичный API БСП (`ПрограммныйИнтерфейс`), не вызывать `СлужебныйПрограммныйИнтерфейс`
   — сломается при обновлении версии БСП.

**Антипаттерны:**
- Использование `&Вместо` без крайней необходимости — полностью блокирует типовую логику.
- Вызов `СлужебныеПроцедурыИФункции` из расширения — ломается при любом обновлении конфигурации.
- Накопление расширений без документирования их взаимодействия.

## 2. РАБОТА С БД И ЗАПРОСАМИ

### 2.1 Оптимизация запросов

1. **Параметры виртуальных таблиц** для фильтрации измерений — не `ГДЕ`. Фильтр через `ГДЕ` строит
   всю ВТ, а потом фильтрует. Параметры ВТ работают при построении — кратно быстрее.
2. **Материализация ВТ**: перед `JOIN` с виртуальной таблицей — `ПОМЕСТИТЬ ВТ_...` плюс `ИНДЕКСИРОВАТЬ ПО`.
   Прямой `JOIN` с ВТ → SQL подзапрос → нет индексов.
3. **ВЫРАЗИТЬ()** для составного типа: `Регистратор.Номер` без `ВЫРАЗИТЬ()` = `LEFT JOIN` ко всем
   (50+) таблицам-типам. `ССЫЛКА` убирает строки, но не убирает `JOIN`'ы.
4. Временные таблицы **обязательно** индексировать по полям `JOIN` и `WHERE`.
5. `OR` в `WHERE` может блокировать индексы — заменять на `В()` или `ОБЪЕДИНИТЬ ВСЕ`.
6. `СГРУППИРОВАТЬ ПО` — убирает детали, уменьшает объём. `ИТОГИ` — добавляет итоговые строки, сохраняет
   детали. Не применять `ИТОГИ` без необходимости.
7. Не использовать `SELECT *` — лишний I/O и давление на сеть/память.
8. `ЕСТЬNULL(поле, 0)` для LEFT JOIN — иначе `NULL` ломает арифметику.

**Антипаттерны:**

| Антипаттерн | Последствие | Решение |
|---|---|---|
| Запросы в цикле | N раунд-трипов к СУБД | Пакетный запрос + временные таблицы |
| JOIN с ВТ напрямую | ВТ → подзапрос, нет индексов | Материализация через ПОМЕСТИТЬ |
| Фильтр ВТ через ГДЕ | Полное построение ВТ до фильтра | Параметры виртуальной таблицы |
| Точка через составной тип | LEFT JOIN ко всем таблицам типа | ВЫРАЗИТЬ() |
| OR в WHERE | Блокирует индексы | ОБЪЕДИНИТЬ ВСЕ или В() |
| Подзапросы в JOIN | СУБД не оптимизирует | Временные таблицы |
| Точка в цикле (Строка.Реф.Поле) | Запрос к БД на каждую строку | Получить поле в запросе |

### 2.2 Пакетные запросы и временные таблицы

1. `МенеджерВременныхТаблиц` — создаётся один на пакет, передаётся между запросами.
2. Передача табличной части в запрос через параметр-таблицу: `Запрос.УстановитьПараметр("Товары",
   Объект.Товары.Выгрузить())` + `ПОМЕСТИТЬ ВТ_Товары ИЗ &Товары`.
3. Уничтожать `МенеджерВременныхТаблиц` по завершении — освобождает память сервера СУБД.

### 2.3 СКД (Система Компоновки Данных)

1. Все пользовательские отчёты — через СКД. Программное формирование настроек СКД для нестандартных
   случаев.
2. Знание структуры схемы СКД: наборы данных (запрос, объект, объединение), вычисляемые поля,
   параметры, ресурсы, макеты оформления.
3. Типичная ошибка: отчёт без параметров виртуальных таблиц в тексте запроса СКД — полная выборка
   всей таблицы при любых пользовательских отборах.

## 3. ИНТЕГРАЦИИ И API

### 3.1 HTTP-сервисы и REST

1. Создание и публикация HTTP-сервисов в 1С (объект метаданных «HTTP-сервис»): методы GET/POST/PUT/DELETE,
   шаблоны URL, обработка параметров и тела запроса.
2. Работа с `HTTPСоединение`, `HTTPЗапрос`, `HTTPОтвет` на стороне клиента.
3. Базовая и токен-аутентификация, передача заголовков, обработка кодов ответа (200, 400, 401, 404, 500).
4. Веб-сервисы SOAP (WSDL): публикация через платформу, работа с `WSСсылки`, `WSПрокси`.

### 3.2 OData / Стандартный REST-интерфейс

1. Публикация стандартного OData-интерфейса: веб-сервер (IIS/Apache), настройка через конфигуратор.
2. Активация объектов: `УстановитьСоставСтандартногоИнтерфейсаOData`.
3. HTTP-глаголы: GET (чтение), POST (создание), PATCH (частичное обновление), PUT (полное обновление),
   DELETE (удаление).
4. Параметры запроса: `$filter`, `$select`, `$expand`, `$orderby`, `$top`, `$skip`, `$format`.
5. Ограничения: через OData недоступны отчёты, регламентные задания, журнал регистрации,
   внешние источники данных.

### 3.3 COM-интеграция

1. Создание `COMОбъект` / `COMОбъект("V83.Application")` для автоматизации 1С.
2. Освобождение COM-объектов в **обратном** порядке создания через присвоение `= Неопределено`.
3. Итерация COM-коллекций только через `Для ... По ... Цикл` с `.Получить(Индекс)`, не `Для Каждого`.
4. Предпочитать HTTP-сервисы COM для новых интеграций: кросс-платформа, нет версиозависимости.

**Антипаттерны:**
- COM-объекты без освобождения — утечка памяти сервера.
- `Для Каждого` на COM-коллекции — создаёт неосвобождаемый итератор.
- Новая интеграция через COM вместо HTTP-сервиса без обоснования.

### 3.4 JSON и XML

1. Сериализация через `ЗаписатьJSON` / `ПрочитатьJSON`, а также объектная техника через `СериализаторXDTO`.
2. `ЗаписьJSON` + `ЧтениеJSON` — потоковая работа с большими документами (не грузит весь объект в память).
3. XML: `ЗаписьXML`, `ЧтениеXML`, работа с `XDTO` (фабрика, пакеты, типы).
4. Основы XPath для разбора XML-ответов внешних сервисов.

### 3.5 Планы обмена и распределённые базы

1. Механизм планов обмена: узлы, регистрация изменений, формирование и загрузка сообщений.
2. Универсальный формат обмена (УФО) vs произвольный XML-обмен.
3. Обязательная проверка `ОбменДанными.Загрузка` в обработчиках `ПередЗаписью` / `ПриЗаписи`.
4. Типичная ошибка: отсутствие `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;` → двойные
   проводки, бесконечные циклы обмена.

## 4. ИНСТРУМЕНТЫ РАЗРАБОТКИ

### 4.1 IDE и редакторы

1. **Конфигуратор** (встроенный): разработка, отладка, хранилище конфигурации, синтаксический контроль,
   выгрузка/загрузка конфигурации.
2. **1C:EDT** (1C Enterprise Development Tools, Eclipse-based): современный IDE, поддержка Git напрямую,
   инкрементальная сборка, интеграция BSL Language Server.
3. **VS Code** + расширение `vsc-language-1c-bsl`: подсветка синтаксиса, автодополнение (через BSL LS),
   навигация, форматирование кода.
4. Настройка `settings.json` для BSL в VS Code: `bsl.languageServerEnabled`, `bsl.languageServerPath`.

### 4.2 Хранилище конфигурации и Git

1. Хранилище конфигурации 1С: захват/освобождение объектов, версии хранилища, групповая разработка.
2. **gitsync** (`oscript-library/gitsync`) — синхронизация хранилища 1С с Git-репозиторием (выгрузка
   в XML-исходники).
3. Git-флоу для 1С: ветки `main` / `develop` / `feature/...`, merge-request, конфликты XML-файлов.
4. Работа с исходниками конфигурации в текстовом виде (XML/BSL) — обязательный навык для CI/CD и
   code review.

### 4.3 Статический анализ

1. **BSL Language Server** (`1c-syntax/bsl-language-server`) — LSP-сервер: 180+ диагностик, интеграция
   с SonarQube, форматирование, анализ когнитивной сложности.
2. **sonar-bsl-plugin-community** (`1c-syntax/sonar-bsl-plugin-community`) — плагин SonarQube для
   BSL: Code Smell, Error, Security Hotspot, Vulnerability.
3. Запуск BSL LS в CLI-режиме: `java -jar bsl-language-server.jar --analyze` → JSON-отчёт → импорт
   в SonarQube.
4. Ключевые диагностики для code review:

| Диагностика | Тип | Что проверяет |
|---|---|---|
| `CreateQueryInCycle` | Error/Critical | Запросы внутри циклов |
| `BeginTransactionBeforeTryCatch` | Error | НачатьТранзакцию вне Попытка |
| `CommitTransactionOutsideTryCatch` | Error | ЗафиксироватьТранзакцию вне Попытка |
| `MissingCodeTryCatchEx` | Error | Пустой блок Исключение |
| `CognitiveComplexity` | CodeSmell/Critical | Когнитивная сложность метода |
| `JoinWithVirtualTable` | CodeSmell | JOIN с виртуальной таблицей |
| `JoinWithSubQuery` | CodeSmell | JOIN с подзапросом |
| `DataExchangeLoading` | Error/Critical | Отсутствие проверки ОбменДанными.Загрузка |
| `ExecuteExternalCode` | Vulnerability/Critical | Выполнение внешнего кода на сервере |
| `CommentedCode` | CodeSmell | Закомментированный код |

## 5. ТЕСТИРОВАНИЕ И КАЧЕСТВО КОДА

### 5.1 BDD-тестирование

1. **Vanessa Automation** (`Pr-Mex/vanessa-automation`) — BDD-фреймворк: Gherkin-сценарии (`.feature`),
   запись UI-тестов, видеодокументация выполнения, интеграция с Allure-отчётами.
2. **Vanessa-ADD** (`vanessa-opensource/add`) — объединяет xUnitFor1C (TDD) и Vanessa-Behavior (BDD).
3. Файловая структура проекта: `features/` — BDD-сценарии, `tests/` — TDD-тесты,
   `tools/JSON/vanessabddConf.json` — настройки запуска.

### 5.2 TDD и модульные тесты

1. **xUnitFor1C** — модульные тесты в стиле xUnit для BSL. Тест-кейсы как процедуры с именем `Тест_…`.
2. Тесты для: методов общих модулей, алгоритмов расчёта, валидации данных. Не тестировать запросы
   напрямую — выносить логику в отдельные функции.
3. Покрытие кода: **Coverage41C** — инструмент измерения покрытия для 1С.

### 5.3 Code Review — чеклист

**Блокирующий merge:**
- Запросы внутри циклов.
- Неправильный порядок транзакций (см. 1.3).
- Пустой блок `Исключение`.
- `Попытка/Исключение; Продолжить` внутри транзакции.
- Обращение к составному типу без `ВЫРАЗИТЬ()`.
- Отсутствие `ОбменДанными.Загрузка` в обработчиках записи.

**Требует исправления:**
- `&НаСервере` вместо `&НаСервереБезКонтекста` без необходимости.
- Фильтрация ВТ через `ГДЕ` вместо параметров.
- Прямой `JOIN` с виртуальной таблицей.
- COM-объекты без освобождения.

**Рекомендуется исправить:**
- Точка от ссылки в цикле.
- Прямой вызов обработчика события из другого.
- Магические числа/строки без именованных констант.
- Отсутствие документирования экспортных процедур.

## 6. CI/CD И DEVOPS

### 6.1 Типовой пайплайн для 1С

```
Разработка:    1C:EDT / VS Code + BSL Language Server (линтинг в реальном времени)
Версионирование: gitsync → Git (хранилище 1С ↔ XML-исходники в репозитории)
Сборка:        vanessa-runner (compilecf / compilecfe / compileepf)
Статанализ:    BSL Language Server → SonarQube (sonar-bsl-plugin-community)
Тестирование:  Vanessa-ADD (BDD + TDD), запуск через vanessa-runner
Деплой:        vanessa-runner (loadcf / loadcfe / update-dd), управление сессиями через RAC
Отчётность:    Allure Framework
```

### 6.2 vanessa-runner

1. **vanessa-runner** (`vanessa-opensource/vanessa-runner`) — CLI для управления 1С: создание ИБ,
   компиляция, синтаксический контроль, запуск тестов, деплой.
2. Конфигурация через `env.json` (параметры ИБ, пути, версия платформы).
3. Ключевые команды: `compile-cf`, `compile-cfe`, `syntax-check`, `run-bdd`, `run-unit`, `load-cf`,
   `update-dd`, `session-lock`, `session-kill`.

### 6.3 GitLab CI / GitHub Actions

1. Файл `.gitlab-ci.yml` / `.github/workflows/*.yml` — определяет stages: install → sync → build →
   test → sonar → deploy.
2. Переменные окружения для 1С-пайплайна: `GITSYNC_STORAGE_PATH`, `GITSYNC_V8VERSION`,
   `SONAR_HOST_URL`, `SONAR_TOKEN`, `VCI_CLUSTER_ADMIN`.
3. **vanessa-ci-scripts** (`johnnyshut/vanessa-ci-scripts`) — набор готовых скриптов для GitLab CI:
   `vci init` создаёт `.gitlab-ci.yml` с нуля. (Проект архивирован в 2025, но паттерны актуальны.)
4. **vanessa-usher** (`silverbulleters/vanessa-usher`) — Jenkins pipelines для 1С.
5. GitLab Runners: обязательно Windows-runner с правами пользователя (не системная учётная запись)
   для запуска 1С.

### 6.4 OneScript и opm

1. **OneScript** (`EvilBeaver/OneScript`) — автономный рантайм BSL вне платформы 1С: автоматизация,
   вспомогательные скрипты, кросс-платформенный (.NET).
2. **opm** — пакетный менеджер OneScript: `opm install gitsync`, `opm install vanessa-runner`.
3. Скрипты автоматизации на OneScript для задач, не требующих запуска полной платформы 1С.

## 7. SOFT-СКИЛЛЫ И БИЗНЕС-КОМПЕТЕНЦИИ

### 7.1 Понимание предметных областей

1. Бухгалтерский и налоговый учёт: план счетов, двойная запись, проводки, НДС, налог на прибыль,
   закрытие периода — необходимо для работы с 1С:БП, ERP, BAS.
2. Управленческий учёт: бюджетирование, ЦФО, управленческий баланс.
3. Логистика и складской учёт: ордерная схема, серии, ГТД, адресное хранение.
4. Кадровый учёт и расчёт зарплаты: тарифные системы, удержания, страховые взносы — для 1С:ЗУП.
5. Знание хотя бы одной типовой конфигурации на уровне пользователя — ключевое для эффективной
   доработки.

### 7.2 Работа с требованиями

1. Умение разделить задачу на: что хочет бизнес (цель) / что описывает аналитик (требование) /
   что нужно реализовать технически (решение).
2. Задавать вопросы до начала разработки: «Как часто используется?», «Сколько данных через год?»,
   «Что произойдёт при ошибке?».
3. Оценивать технический долг и риски при выборе архитектурного решения.
4. Документировать нетривиальные решения: почему выбрано именно так, а не иначе.

### 7.3 Middle vs Senior — ключевые различия

| Аспект | Middle | Senior |
|---|---|---|
| Кругозор | Видит 1С как замкнутую систему | Видит 1С как компонент IT-ландшафта (СУБД, сеть, ОС) |
| Первое действие при инциденте | Сразу запускает инструменты замера | Собирает контекст: бизнес-события, хронология |
| Результат оптимизации | Локальное ускорение кода | Устранение корневой причины, предотвращение рецидивов |
| Горизонт планирования | Спринт / задача | 2–5 лет: обновляемость, рост объёма, смена кадров |
| Язык общения с бизнесом | Технические термины | Риски, деньги, сроки |
| Тех. долг | Накапливает | Управляет: Bus Factor, отчуждаемая система, документация |

## 9. ПРОМПТ-ШАБЛОНЫ ДЛЯ AI-АССИСТЕНТА

### 9.1 Системный промпт — общий

```
Ты — опытный разработчик 1С:Предприятие 8.3 (платформа 8.3.20+).

ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА:
1. Код ТОЛЬКО на русском языке BSL
2. Указывай директивы компиляции (&НаКлиенте, &НаСервере, &НаСервереБезКонтекста)
3. Предпочитай &НаСервереБезКонтекста когда контекст формы не нужен
4. НИКОГДА не размещай запросы внутри циклов
5. НачатьТранзакцию() ПЕРЕД Попытка; ЗафиксироватьТранзакцию() — последняя строка в Попытка;
   ОтменитьТранзакцию() — первая строка в Исключение; ВСЕГДА ВызватьИсключение
6. Для составных типов (Регистратор, Владелец) в запросах — ВСЕГДА ВЫРАЗИТЬ()
7. Параметры виртуальных таблиц для фильтрации измерений, не WHERE
8. Не обращайся к реквизитам через точку от ссылки в циклах
9. Индексируй временные таблицы по полям JOIN/WHERE
10. Экспортные процедуры документируй (// Параметры: / Возвращаемое значение:)
```

### 9.2 Code Review

```
Проведи code review следующего кода 1С. Проверь по чеклисту:
1. Запросы в циклах
2. Правильность транзакций (НачатьТранзакцию перед Попытка, ЗафиксироватьТранзакцию последняя,
   ОтменитьТранзакцию первая, ВызватьИсключение обязательно)
3. Пустой блок Исключение
4. Точка от ссылки в цикле
5. Составные типы без ВЫРАЗИТЬ() в запросах
6. Фильтрация ВТ через ГДЕ вместо параметров
7. JOIN с виртуальными таблицами напрямую
8. &НаСервере вместо &НаСервереБезКонтекста
9. Отсутствие ИНДЕКСИРОВАТЬ ПО для временных таблиц
10. Отсутствие проверки ОбменДанными.Загрузка

Для каждой проблемы: строка → почему плохо → как исправить.
```

### 9.3 Генерация запроса

```
Регистр: [тип: остатки/обороты], измерения: [...], ресурсы: [...].
Задача: [что нужно получить].
Требования: параметры ВТ для измерений, временные таблицы вместо JOIN с ВТ,
ИНДЕКСИРОВАТЬ ПО по полям JOIN, ВЫРАЗИТЬ() для составных типов, ЕСТЬNULL() для LEFT JOIN.
```
