# Обробка «Завантаження з Excel ТЧ Реалізація (зіставлення з залишками)»

Дата: 09.10.2026. BAS Бухгалтерія (`bas_industrialbud`). Зовнішня обробка
`_Rarzrabotki/temp/Загрузка ТЧРеализацияТоваровУслуг.xml` (+ `.epf`), ім'я об'єкта `ЗагрузкаТЧРеализацияТоваровУслуг`.
Приклад накладної: `_Rarzrabotki/temp/Специфікація з АСУБЗ.xls` (84 рядки: ТМЦ, кількість, од., ціна без ПДВ, сума).

## Рішення користувача (brainstorming 09.10)
- Склади («Чорноморськ», «Чорноморськ Списання») — лише для ПОШУКУ карток за залишками; усі рядки йдуть у поточну
  реалізацію.
- Два кроки, як у «Загрузка лимитов»: 1) аналіз зіставлення, таблиця з підказками; 2) завантаження підтверджених рядків.
- Після завантаження до документа прикріплюються вихідний файл і журнал зіставлення (історія для навчання).

## Як відкрити
Додаткова обробка БСП, вид «Заполнение объекта», призначення `Документ.РеализацияТоваровУслуг`, команда «Завантажити
з Excel (зіставлення з залишками)» — режим «ОткрытиеФормы» (форма отримує документ з `Параметры.ОбъектыНазначения`).
Можна відкрити й як звичайну зовнішню обробку і вибрати документ у полі «Реалізація».

## Крок 1 — аналіз (ObjectModule.ПрочитатьИСопоставить)
Файл читається на сервері `ТабличныйДокумент.Прочитать` (xls/xlsx). Колонки налаштовуються (за замовчуванням: перший
рядок 2, назва 2, кількість 3, од. 4, ціна без ПДВ 5, сума без ПДВ 7, код 1С — 0/немає); налаштування й склади
запам'ятовуються. Порядок зіставлення рядка:
1. **Код 1С** (якщо задано колонку коду) — `НайтиПоКоду`, також з доповненням нулями до 11 знаків.
2. **Запам'ятований вибір** — `ХранилищеОбщихНастроек` («Сопоставление», спільне ім'я користувача, привілейований
   режим): ключ = нормалізована назва з файлу -> картка.
3. **Точна назва** серед залишків, потім у довіднику.
4. **Схожість серед залишків** складів пошуку (`Хозрасчетный.Остатки`, Субконто1 — номенклатура, Субконто3 — склад).
5. **Поза залишками** (прапорець) — картки довідника з типом виробу в назві (до 500), та сама оцінка.
Автопідтвердження — лише 1–3; підказки 4–5 підтверджує бухгалтер (✓, двійний клік по варіанту, «Підтвердити ≥ 85 %»).

### Оцінка схожості (за дослідженням методів, 09.10)
Висновок дослідження (rapidfuzz, string_grouper/ING TF-IDF, splink/Fellegi–Sunter, Unicode TR39): жодна «чиста» рядкова
метрика (косинус, Левенштейн, Jaro–Winkler, token_set, Monge–Elkan) не розрізняє розміри — неправильний розмір
(М16×55 проти М16×65) отримує майже той самий бал. Тому гібрид «метрика для кандидатів + судді-атрибути»:
- **Нормалізація** (скелет): НРег, латинські двійники -> кирилиця (a c e i o p x y k m t b h), ё->е, Ø прибирається,
  «г/к»->«гк», «х/к»->«хк», «4,0»->«4», провідні нулі.
- **Ключ точного збігу** (крок 2–3) — лексеми через пробіл, межі чисел зберігаються: «1,5» ≠ «15», «1/2» ≠ «12»;
  «х» між числами ігнорується («М16*55» = «M16х55»). Дві картки серед залишків з одним ключем — не автопідтверджуються.
  Старі запам'ятовані ключі (до 09.10, без меж чисел) читаються, лише якщо всі розміри файлу є в назві картки.
- **Розбір на поля**: тип виробу (основа 4 літери першого кириличного слова), розміри (числа ланцюжків «*»/«х»,
  «№», окремі; різьба «м16», ключ «s24» < 100; діаметр «ф12»/«d12»/«ду50» = «Ø12» = 12; літера профілю впритул —
  частина розміру: «12П» ≠ «12У», «20Б1»), марки (ст.245, 3пс, А500, 8.8, префікс-літери; через дефіс — лише від марки
  з літерами: «А2-70»; «ПС-20-1150-0,7» — 1150 і 0,7 розміри), стандарти (число безпосередньо після DIN/ISO/ДСТУ/
  ГОСТ; рік «-91» відкидається; «ГОСТ 8732 57х3,5» — 57 розмір, «DIN 933 8.8» — 8.8 клас міцності), сторона
  (праві/ліві). «х» між числами — множення.
- **T** — косинус TF-IDF символьних триграм слів (IDF по кандидатах).
- **N** — частка розмірів файлу, знайдених у картці (мультимножина), × (1 − 0,05 × зайві розміри картки, до 4).
- **Сходство = 100·(0,5·T + 0,5·N) × (інший стандарт 0,8) × (інша марка 0,9)**, стелі: розмір файлу відсутній у
  картці ≤ 49; тип виробу не збігся (двобічно) ≤ 40; праві/ліві ≤ 49; розміри лише у файлі ≤ 70; марка або стандарт
  файлу відсутні в картці (у картці є свої) ≤ 75 — лише «перевірте».
- Залишки — лише організації документа (умова віртуальної таблиці `Организация = &Организация`).
- Регресія за ревʼю 09.10 (`scratchpad/review_cases.py`, експортна `ОценкаПары(Файл, Картка)`): 15 випадків — 1,5/15,
  ГОСТ+діаметр, клас міцності, ф12/ф16, профнастил 0,5/0,7, швелер 12П/12У, М16 S24/М24 S16 — усі зелені.
- Зони: ≥ 85 — «Підтвердити схожі»; 60–84 — «перевірте»; < 60 — не підставляється (варіанти видно знизу).

На накладній АСУБЗ (09.10): 5 точних, 62 підказки серед залишків, 3 поза залишками, 14 не знайдено (позицій немає на
складах: листи 6/10/12/30, гайки М16 S24 / М20 S30, стрижні М12/М16). Болти — правильні розміри (М16*55 -> М16х55,
600 шт), «Гайка М16 S24» не підставляється як «М24 S16».

## Крок 2 — завантаження (ObjectModule.ЗагрузитьВДокумент)
Документ не проведений, блокується (`Заблокировать`). Рядок: `РеализацияТоваровУслугФормы.ТоварыНоменклатураПриИзмене
нииНаСервере` (рахунки, ставка ПДВ, одиниця), кількість у одиниці картки (т↔кг ×1000; інакше — попередження), сума з
файлу точно (ціна = сума / кількість; ПДВ у ціні — сума × (100 + ставка)/100), рахунок обліку — рахунок залишку (спершу
склад документа). Запис `РежимЗаписиДокумента.Запись`. Вибір запам'ятовується.

### Прикріплені файли (БСП «Приєднані файли») — без розмноження (рішення 09.10: «середина» між шумом і даними)
- **Вихідний файл** — один: той самий (ім'я + розмір) повторно не додається; той самий файл зі зміненим вмістом —
  оновлюється на місці (`РаботаСФайлами.ОбновитьФайл`).
- **«Журнал зіставлення <файл>.xlsx»** — один на документ і файл, при повторних завантаженнях оновлюється зі злиттям
  (ключ «рядок файлу|назва»): **автопідбір** (номенклатура, код, спосіб, схожість) — з ПЕРШОГО завантаження (що
  запропонувала обробка до втручання бухгалтера); **обрано** — останній вибір; «виправлено бухгалтером» = обраний код
  ≠ код першого автопідбору; «Завантажень», «Перше завантаження». 21 колонка. Це дані для калібрування ваг
  (Fellegi–Sunter log2(m/u)) і порогів.
- Опис: «Завантаження з Excel: N-й раз, останнє <дата> (<користувач>). Рядків, завантажено, виправлено бухгалтером».
- Перевірено (`scratchpad/tx_test2.py`, транзакція з відкатом): два завантаження поспіль -> +1 вкладення (журнал),
  вихідний файл не дублюється, у журналі «Завантажень» = 2, виправлення рядка 3 видно.

### Інші виправлення за ревʼю 09.10
- Проведення перевіряється після `Заблокировать()` (документ могли провести, поки бухгалтер перевіряв таблицю).
- Кількість у одиниці картки < 0,0005 (кг -> т) — рядок не завантажується, попередження (раніше — рядок з 0).
- Без колонки суми: сума рядка = ціна × кількість файлу до перерахунку одиниць (раніше ціна округлювалась після
  перерахунку т -> кг і сума «пливла»).
- «Excel з кодами 1С» — код лише для підтверджених рядків (інакше підказка при повторному завантаженні ставала «За
  кодом 1С»).
- «Підтвердити схожі ≥ 85 %» — лише рядки «Схоже — перевірте»; зняті ✓ («Знято бухгалтером») і «забуті» не чіпає.
- Таблиця зіставлення: не можна додавати/копіювати рядки (`ChangeRowSet=false`).
- «Очищати товари документа перед завантаженням» — увімкнено завжди при відкритті (повторне завантаження замінює).

## Форма (дизайн 09.10, стиль `А_РозрахункиПДВЗаПершоюПодією`)
- Командна панель з картинками: «1. Прочитати і зіставити» (Reread), «Підтвердити схожі ≥ 85 %» (CheckAll),
  «2. Завантажити в документ» (ExecuteTask, за замовчуванням), «Excel з кодами 1С» (SaveFile), «Забути вибір рядка».
- Шапка: Реалізація + Файл накладної; рядок-резюме (що робити далі).
- Закладки: **Зіставлення** (перемикач «Усі / Потребують рішення / Не знайдено / Підтверджені» через `ОтборСтрок` по
  колонці форми `Группа`; легенда кольорів = умовне оформлення; головна таблиця — єдиний розтягуваний елемент;
  **підсумки** «Усього в накладній» (рядків, кількість, сума без ПДВ, «Разом» з накладної + контроль ✓/⚠),
  «Готово до завантаження ✓», «Не підтверджено»; варіанти для рядка — 5 рядків), **Налаштування** (номери колонок
  TitleLocation=Top, опції, склади пошуку), **Інструкція** (HTML з макета `Инструкция` типу TextDocument, поле
  HTML-документа — як у `А_РозрахункиПДВЗаПершоюПодією`; движок WebKit з 8.3.14).
- Рядок підсумку накладної: рядок без кількості з порожньою назвою або «Разом/Всього/Итого» — його сума з колонки
  суми -> `ИтогФайла` (на АСУБЗ 5 731 100,43).
- Усі заголовки — українською (у Form.xml обидві мови ru/uk; без uk база показувала технічні імена).
- Генератор форми: `scratchpad/epf_gen/gen_form.py` (лише Form.xml; корінь XML і GUID не перегенеровуються).

## Перевірка
- COM smoke (`scratchpad/epf_smoke.py`): 84 рядки, суми документа = суми файлу підтверджених рядків.
- Транзакційний тест (`scratchpad/tx_test.py`): `BeginTransaction` -> `ЗагрузитьВДокумент` на ІБ00-000189 -> 22 рядки,
  2 прикріплені файли, журнал 84 рядки / 19 колонок, рядок «виправлено бухгалтером: так» -> `RollbackTransaction` ->
  документ порожній. Файли БСП зберігаються в базі (томів немає) — відкат чистий.
- Префлайт модулів (`check_bsl_context.py` на BuhBud) — лише хибні спрацювання (глобальні об'єкти платформи).
