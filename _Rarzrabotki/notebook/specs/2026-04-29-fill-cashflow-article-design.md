## 1. Context

Внешняя обработка — каркас без логики. Пользователь обновил структуру и хочет: по выбранной статье ДДС за период — увидеть всех **поставщиков** (только договоры `ТипДоговора = СПоставщиком`) с суммой по каждому договору и расшифровку до конкретных платёжных документов. Параллельно колонка «текущая статья у договора» (`А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно`) показывает, какая статья реально проставлена в реквизите договора — это позволяет видеть несоответствия. Кнопка «Обновить статью денег в договорах» опционально записывает выбранную статью в этот реквизит у отмеченных договоров.

Бизнес-цель: финансист берёт статью «Аренда сторонней техники», смотрит за квартал какие договоры в неё реально попали по факту платежей — и при необходимости проставляет их «основной принудительной» статьёй, чтобы будущие платежи автоматически классифицировались.

## 3. Архитектура и источник данных

### Регистр платежей (подтверждён через `execute_query`)
**`РегистрНакопления.ДвиженияДенежныеСредстваКонтрагент.Обороты`** — то же, что использует отчёт А_БДДС. На тестовом периоде 01.12.2025–31.03.2026 со статьёй «Аренда сторонней техники» и `ТипДоговора = СПоставщиком` возвращает **204 записи, итого 10 033 642,31 грн**.

Ключевые поля:
- `Регистратор` — документ платежа (Списание безналичных ДС / РКО / ПриобретениеТоваровУслуг и т.д.)
- `Контрагент`, `Партнёр`, `Договор` (полиморфный — нужна выгрузка `ВЫРАЗИТЬ … КАК Справочник.ДоговорыКонтрагентов`)
- `Подразделение`, `СтатьяДвиженияДенежныхСредств`, `ХозяйственнаяОперация`
- Ресурсы: `СуммаОплаты` (упр), `СуммаОплатыРегл`, `СуммаОплатыВВалютеПлатежа`. Используем `СуммаОплаты` (упр.учёт) — соответствует «факт упр. учёт» в А_БДДС.

### Правила запроса (Rule #-1 — проверены)
- `Договор` — полиморфное измерение → обязательны `ТИПЗНАЧЕНИЯ(Договор) = ТИП(Справочник.ДоговорыКонтрагентов)` и `ВЫРАЗИТЬ(Договор КАК Справочник.ДоговорыКонтрагентов)`.
- Фильтр статьи через `СтатьяДвиженияДенежныхСредств = &СтатьяДДС` работает.
- Параметр периода — обычная Дата (передаётся как `&НачалоПериода`, `&ОкончаниеПериода`).
- `СтатьяДДС.Наименование` использовать **нельзя** в продакшен-коде — можно случайно совпасть (в наших тестах через MCP — это обход глюка инструмента, в BSL пользуемся ссылкой).

## 4. Дизайн — три обработчика

### 4.1. `ВыбратьПериод(Команда)` (НОВЫЙ — добавляем)

Добавляется недостающий обработчик. Использует стандартный диалог `СтандартныйПериод`:

```bsl
&НаКлиенте
Процедура ВыбратьПериод(Команда)
    Диалог = Новый ДиалогРедактированияСтандартногоПериода;
    Диалог.Период.ДатаНачала = Объект.НачалоПериода;
    Диалог.Период.ДатаОкончания = Объект.ОкончаниеПериода;
    ОписаниеОповещения = Новый ОписаниеОповещения("ВыбратьПериодЗавершение", ЭтотОбъект);
    Диалог.Показать(ОписаниеОповещения);
КонецПроцедуры

&НаКлиенте
Процедура ВыбратьПериодЗавершение(Период, ДополнительныеПараметры) Экспорт
    Если Период <> Неопределено Тогда
        Объект.НачалоПериода = Период.ДатаНачала;
        Объект.ОкончаниеПериода = Период.ДатаОкончания;
    КонецЕсли;
КонецПроцедуры
```

### 4.2. `Заполнить(Команда)` → `ЗаполнитьНаСервере()` (ОСНОВНАЯ)

**Алгоритм:**
1. Проверить заполнение `Объект.СтатьяДвиженияДенежныхСредств`, `НачалоПериода`, `ОкончаниеПериода`. Если что-то пусто — `Сообщение` + выход.
2. Очистить `Объект.Расшифровка` и `Объект.РасшифровкаДокументы`.
3. Выполнить **один** запрос с двумя результатами (пакетный) — детализация по документам и свёртка по договорам.
4. Записать результаты в ТЗ.

**Текст запроса:**

```sql
ВЫБРАТЬ
    РегДДС.Регистратор КАК Регистратор,
    РегДДС.Контрагент КАК Контрагент,
    ВЫРАЗИТЬ(РегДДС.Договор КАК Справочник.ДоговорыКонтрагентов) КАК Договор,
    РегДДС.Подразделение КАК Подразделение,
    РегДДС.СуммаОплатыОборот КАК Сумма
ПОМЕСТИТЬ ВТ_Платежи
ИЗ
    РегистрНакопления.ДвиженияДенежныеСредстваКонтрагент.Обороты(
        &НачалоПериода,
        КОНЕЦПЕРИОДА(&ОкончаниеПериода, ДЕНЬ),
        Регистратор,
        СтатьяДвиженияДенежныхСредств = &СтатьяДДС
        И ТИПЗНАЧЕНИЯ(Договор) = ТИП(Справочник.ДоговорыКонтрагентов)
        И ВЫРАЗИТЬ(Договор КАК Справочник.ДоговорыКонтрагентов).ТипДоговора
            = ЗНАЧЕНИЕ(Перечисление.ТипыДоговоров.СПоставщиком)
    ) КАК РегДДС
ГДЕ
    РегДДС.СуммаОплатыОборот <> 0
;

// === Результат 1: детализация по документам (для ТЗ РасшифровкаДокументы) ===
ВЫБРАТЬ
    П.Контрагент          КАК Контрагент,
    П.Договор             КАК Договор,
    П.Подразделение       КАК Подразделение,
    П.Регистратор         КАК ДокументДенежныхСредств,
    П.Сумма               КАК СуммаДокумента
ИЗ
    ВТ_Платежи КАК П
УПОРЯДОЧИТЬ ПО
    Контрагент, Договор, ДокументДенежныхСредств.Дата
;

// === Результат 2: свёртка по договорам (для ТЗ Расшифровка) ===
ВЫБРАТЬ
    П.Контрагент    КАК Контрагент,
    П.Договор       КАК Договор,
    П.Договор.А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно
                    КАК А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно,
    П.Подразделение КАК Подразделение,
    СУММА(П.Сумма)  КАК Сумма
ИЗ
    ВТ_Платежи КАК П
СГРУППИРОВАТЬ ПО
    П.Контрагент, П.Договор, П.Подразделение,
    П.Договор.А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно
УПОРЯДОЧИТЬ ПО
    Контрагент, Договор
```

**Запись в ТЗ:**

```bsl
Результаты = Запрос.ВыполнитьПакет();      // 2 элемента
Объект.РасшифровкаДокументы.Загрузить(Результаты[0].Выгрузить());
Объект.Расшифровка.Загрузить(Результаты[1].Выгрузить());
// поле Обработан остаётся Ложь по умолчанию — пользователь сам отмечает
```

**Поле `Обработан`** — НЕ заполняется автоматически (по умолчанию `Ложь`). Пользователь сам ставит галки на договоры, в которые хочет записать статью.

### 4.3. `ОбновитьСтатьюДенегВДоговорах(Команда)` → `…НаСервере()` (ОПЦИОНАЛЬНАЯ)

Записывает выбранную `Объект.СтатьяДвиженияДенежныхСредств` в реквизит `А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно` тех договоров, у которых отмечен `Обработан=Истина`.

```bsl
&НаСервере
Процедура ОбновитьСтатьюДенегВДоговорахНаСервере()
    Если НЕ ЗначениеЗаполнено(Объект.СтатьяДвиженияДенежныхСредств) Тогда
        Сообщить(НСтр("ru='Не выбрана статья ДДС.'"));
        Возврат;
    КонецЕсли;

    Обновлено = 0;
    Пропущено = 0;

    Для Каждого СтрокаТЗ Из Объект.Расшифровка Цикл
        Если НЕ СтрокаТЗ.Обработан Тогда
            Пропущено = Пропущено + 1;
            Продолжить;
        КонецЕсли;
        Если НЕ ЗначениеЗаполнено(СтрокаТЗ.Договор) Тогда
            Продолжить;
        КонецЕсли;

        Попытка
            ДоговорОбъект = СтрокаТЗ.Договор.ПолучитьОбъект();
            Если ДоговорОбъект = Неопределено Тогда
                Продолжить;
            КонецЕсли;
            ДоговорОбъект.А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно
                = Объект.СтатьяДвиженияДенежныхСредств;
            ДоговорОбъект.Записать();
            // Перечитать в ТЗ для отображения новой текущей статьи
            СтрокаТЗ.А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно
                = Объект.СтатьяДвиженияДенежныхСредств;
            Обновлено = Обновлено + 1;
        Исключение
            Сообщить(СтрШаблон(
                НСтр("ru='Договор ""%1"": %2'"),
                СтрокаТЗ.Договор, ОписаниеОшибки()));
        КонецПопытки;
    КонецЦикла;

    Сообщить(СтрШаблон(
        НСтр("ru='Обновлено договоров: %1, пропущено (без галки): %2'"),
        Обновлено, Пропущено));
КонецПроцедуры
```

**Защита:** не записываем в договор, у которого `А_Необновлять = Истина` или `А_Обработан = Истина` (стандартная защита от перезаписи в этой конфигурации). Условие проверяем ДО `Записать`. Используем `ОбменДанными.Загрузка = Истина` чтобы не вызывать каскад типовых событий-обновлений.

```bsl
Если ДоговорОбъект.А_Необновлять Тогда
    Продолжить;
КонецЕсли;
ДоговорОбъект.А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно
    = Объект.СтатьяДвиженияДенежныхСредств;
ДоговорОбъект.ОбменДанными.Загрузка = Истина;
ДоговорОбъект.Записать();
```

## 10. Риски и закрытие

| Риск | Меры |
|------|------|
| Поле `Договор` полиморфное — попытка прочитать `.ТипДоговора` без `ВЫРАЗИТЬ` падает | Везде используем `ВЫРАЗИТЬ(Договор КАК Справочник.ДоговорыКонтрагентов)` |
| `ДвиженияДенежныеСредстваКонтрагент.Обороты` — параметры периода чувствительны к концу дня | `КОНЕЦПЕРИОДА(&ОкончаниеПериода, ДЕНЬ)` гарантирует включение последнего дня |

| Свёртка `Расшифровка` теряет договоры с одинаковым контрагентом+цехом, но разной «текущей статьёй» договора | Группировка включает `А_СтатьяДвиженияДенежныхСредствОснавнаяПринудительно` — каждое уникальное значение даёт свою строку |
