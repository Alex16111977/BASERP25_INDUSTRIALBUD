# ПРОМТ: перенос данных регистра `А_ПараметрыДоговоровФинотчета` в новую рабочую базу BuhBud

> Для сессии Claude Code. Рабочая папка `C:\Configuration_downloads\BASERP25`. Дата: 03.10.2026.
> **Код и метаданные регистра переносит пользователь сам. ИИ переносит только ДАННЫЕ регистра.**

---

## 1. Контекст

- Пользователь загружает в `bas_industrialbud` новую рабочую бухгалтерскую базу.
- Регистр сведений `А_ПараметрыДоговоровФинотчета` хранит параметры договоров для документа
  `А_ФинансовыйОтчетПроизводства`: сумма соглашения, ДЦ, предоплата, гарантийное удержание, НДС, сроки оплаты,
  статус и порядок в отчёте. Данные вносились вручную и скриптами 28–30.09.2026 и в новой базе отсутствуют.
- **Источник** — копия старой базы `Srvr="localhost";Ref="bas_industrialbudRazr";Usr="cfo";Pwd="2442"`. На 03.10.2026
  там 36 записей по 7 контрагентам: пустых и помеченных договоров нет.
- **Приёмник** — `Srvr="localhost";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"` после загрузки новой базы и кода.

## 2. Структура регистра (дамп `_Rarzrabotki/BASEBuh/InformationRegisters/А_ПараметрыДоговоровФинотчета.xml`)

Непериодический, запись независимая. В планы обмена не входит.

| Вид | Имя | Тип |
|---|---|---|
| Измерение | `Договор` | `СправочникСсылка.ДоговорыКонтрагентов` (ведущее, основной отбор) |
| Ресурсы — числа | `СуммаСоглашения`, `СуммаДЦ`, `СуммаПредоплаты`, `ОстатокПредоплатыНаДату`, `СуммаГарантийногоУдержания` | Число 15 |
| | `ПроцентГарантийногоУдержания`, `ПроцентУдержанияПослеАванса` | Число 6 |
| | `СрокОплатыДней` | Число 3 |
| | `ПорядокВОтчете` | Число 4 |
| Ресурсы — строки | `ОбъектПримечание` (200), `ВариантФормулыИтога` (30), `ПравилоНДС` (20), `БазаСрокаОплаты` (20), `УсловияДоговора` (1000), `СтатусВОтчете` (10) | Строка |
| Ресурс — дата | `ДатаЗачетаПредоплаты` | Дата и время |

Единственная ссылка — `Договор`. Перенос сводится к сопоставлению договоров и копированию 16 ресурсов как есть.

## 3. Порядок работы

### Шаг 0. Ворота: не начинать без подтверждения
1. Пользователь подтверждает, что новая база загружена в `bas_industrialbud` и код регистра в неё перенесён.
2. Через COM проверить, что в приёмнике есть `Метаданные.РегистрыСведений.А_ПараметрыДоговоровФинотчета`.
   Измерение и 16 ресурсов должны совпадать с источником по именам и типам. При любом расхождении — **стоп**,
   вывести разницу, ничего не писать.

### Шаг 1. Бэкапы (до любой записи)
- Источник целиком — в `_Rarzrabotki/Python/test/perenos_parametry_finotcheta/backup_source_<ГГГГММДД_ЧЧММ>.json`.
  По договору сохранить: UUID, `Наименование`, `Номер`, `Дата`, `Владелец` (UUID, `Наименование`, `КодПоЕДРПОУ`),
  `Организация` (UUID, `Наименование`), `ПометкаУдаления`. Все 16 ресурсов. Дату — компонентами
  (`ГОД/МЕСЯЦ/ДЕНЬ/ЧАС/МИНУТА/СЕКУНДА` в запросе), а не COM-датой.
- Текущие записи приёмника, если они есть, — в `backup_target_<…>.json` в том же формате.

### Шаг 2. Сопоставление договоров
1. **По UUID** (основной путь — базы одной линии): `Справочники.ДоговорыКонтрагентов.ПолучитьСсылку(Новый УникальныйИдентификатор(uuid))`.
   Обязательно проверить, что объект существует (`ПолучитьОбъект() <> Неопределено`): иначе это битая ссылка.
2. **Запасной ключ** — только если UUID не найден. Ключ:
   - владелец: `КодПоЕДРПОУ`, а если он пуст — `Наименование`;
   - организация;
   - номер;
   - наименование договора.

   **Дату в ключ не брать**: у части договоров она пустая (01.01.0001). Принимать только однозначное совпадение.
3. Не найден или найден неоднозначно — запись **не переносить**, вывести в отчёт с причиной.

### Шаг 3. Пробный прогон (без записи)
Отчёт в консоль и в `perenos_report.csv`. По каждой записи источника:
- договор — представление и способ сопоставления (UUID / ключ / НЕТ);
- запись в приёмнике — нет / совпадает / отличаются поля (каких);
- действие — создать / обновить / без изменений / пропуск.

Итог: сколько записей создать, обновить, пропустить.

### Шаг 4. Запись
- Если пробный прогон чистый (несопоставленных 0), записывать без отдельного вопроса. Если есть пропуски —
  показать их пользователю и ждать решения.
- Запись по ключу договора: `НаборЗаписей` с `Отбор.Договор = <договор приёмника>`, одна запись, `Записать(Истина)`.
  Заменяется только эта запись.
- Перед записью:
  - `НаборЗаписей.ОбменДанными.Загрузка = Истина`;
  - `НаборЗаписей.ДополнительныеСвойства.Вставить("ОтключитьМеханизмРегистрацииОбъектов", Истина)` — ничего
    не регистрировать к обмену (память `buhbud_zapis_bez_registracii_obmena`).
- Записи приёмника, которых нет в источнике, **не удалять** — только перечислить в отчёте.
- **Даты через COM сдвигаются на −3 ч.** Писать как `pywintypes.Time(datetime(г, м, д, ч, мин, с) + timedelta(hours=3))`
  (приём из `_Rarzrabotki/Python/test/pismo_2026_09/detal.py`). Пустую дату (01.01.0001) не присваивать вовсе:
  у ресурса она уже пустая, а год 1 через pywintypes падает.
- Числа и строки переносить как есть.

### Шаг 5. Проверка после записи (инвариант)
- Перечитать приёмник запросом.
- По каждой перенесённой записи все 16 ресурсов равны источнику: даты — покомпонентно, числа — до 2 знаков,
  строки — точно.
- Число записей в приёмнике = прежние записи + созданные.
- Повторный пробный прогон показывает «без изменений» по всем перенесённым записям — перенос идемпотентен.

### Шаг 6 (по желанию пользователя). Бизнес-проверка
Сформировать `А_ФинансовыйОтчетПроизводства` на одну дату в `bas_industrialbudRazr` и в `bas_industrialbud`.
Статусы и порядок договоров (К24–К26) и строки, которые зависят от параметров, должны совпасть. Расхождения
допустимы только там, где в новой базе другие документы, — каждое такое объяснить.

## 4. Правила

- Источник — **только чтение**. В приёмнике менять **только этот регистр**: справочники, документы и метаданные
  не трогать. Код переносит пользователь.
- Rule #-1: каждый запрос 1С сначала проверить через Python COM. Псевдонимы `В`, `И`, `ПО` зарезервированы.
  В BuhBud режим совместимости 8.3.12.
- Скрипт: `_Rarzrabotki/Python/test/perenos_parametry_finotcheta/perenos.py`. Запуск по умолчанию — пробный прогон;
  `--apply` — запись; `--rollback=<backup_target.json>` — вернуть приёмник к состоянию до переноса.
  Писать в worktree, копировать в основной каталог (Rule #4), закоммитить скрипт. Бэкапы — рядом.
- Минимум прогонов: пробный → запись → проверка. Без субагентов.
