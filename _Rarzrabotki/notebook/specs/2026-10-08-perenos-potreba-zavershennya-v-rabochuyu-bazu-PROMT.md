## 3. Порядок работы

### Шаг 0. Ворота: не начинать без подтверждения
1. Пользователь подтверждает, что новая база загружена в `BaseERP` и конфигурация в неё загружена.
2. COM-проверка приёмника:
   - есть `Метаданные.Документы.А_ПотребаЗавершенняПроекту`, `Метаданные.Отчеты.А_ПрогнозВиконанняССЗаПотребою`,
     `Метаданные.Роли.А_ПотребаЗавершенняПроектуРедактирование`;
   - реквизиты шапки и ТЧ совпадают с источником по именам и типам (`Тип.Типы()` сравнивать строками);
   - документ не входит ни в один план обмена (`ПланыОбмена[i].Состав.Содержит(...)` = Ложь), иначе **стоп**;
   - `КонфигурацияИзменена()` = Ложь (конфигурация БД применена).

   При любом расхождении — **стоп**, вывести разницу, ничего не писать.
3. Если конфигурации нет — сообщить пользователю, что грузить (файлы из основного каталога, частичная загрузка):
   - `Configuration.xml` (в нём строки `<Document>`, `<Role>`, `<Report>` этой задачи);
   - `Documents/А_ПотребаЗавершенняПроекту.xml`, `…/Ext/ObjectModule.bsl`, `…/Ext/ManagerModule.bsl`,
     `…/Forms/ФормаДокумента.xml`, `ФормаСписка.xml`, `ФормаВыбора.xml`;
   - `Roles/А_ПотребаЗавершенняПроектуРедактирование.xml` + `…/Ext/Rights.xml`;
   - `Reports/А_ПрогнозВиконанняССЗаПотребою.xml`, `…/Ext/ObjectModule.bsl`, `…/Templates/ОсновнаяСхемаКомпоновкиДанных.xml`;
   - `Subsystems/Производство/Subsystems/ВнутрицеховойУчет.xml`;
   - заодно — исправление `DataProcessors/СозданиеСотрудниковИзФизическихЛиц/Ext/ObjectModule.bsl`: процедура
     `Выполнить` → `ВыполнитьОбработку`. Без него `/CheckModules` даёт 101. Исправление сделано 08.10.2026, в базу ещё не загружено:

### Шаг 1. Бэкапы (до любой записи)
- Источник целиком — в `_Rarzrabotki/Python/test/perenos_potreba/backup_source_<ГГГГММДД_ЧЧММ>.xml`: XML-сериализация
  каждого документа (`СериализаторXDTO.ЗаписатьXML` объекта) плюс сводка JSON (UUID, номер, дата, подразделение, сумма, строк).
- Документы этого вида, если они уже есть в приёмнике, — в `backup_target_<…>.xml` в том же формате.

### Шаг 2. Проверка ссылок
- По каждому документу источника собрать все ссылки: `Подразделение`, `Ответственный`, `ОбщееНазвание`, `ЕдиницаСС`.
- В приёмнике найти **по UUID** (`Справочники.X.ПолучитьСсылку(Новый УникальныйИдентификатор(uuid))`) и проверить, что объект существует
  (`ПолучитьОбъект() <> Неопределено`). Базы одной линии, UUID должны совпасть.
- Запасной ключ — только при отсутствии UUID:
  - подразделение и загальна назва — по `Наименование` (СокрЛП), принимать только однозначное совпадение;
  - единица — по `Наименование`;
  - пользователь — по `Наименование`.
- Найдено по запасному ключу — в сериализованном XML заменить UUID на найденный. Не найдено — документ **не переносить**,
  показать пользователю (битых ссылок не писать).

### Шаг 3. Пробный прогон (без записи)
Отчёт в консоль и в `perenos_report.csv`, по каждому документу:
- номер, дата, подразделение, сумма, строк;
- ссылки: все по UUID / сколько по запасному ключу / сколько не найдено;
- документ в приёмнике: нет / совпадает / отличается (что именно);
- действие: создать / обновить / без изменений / пропуск.

### Шаг 4. Запись — через XDTO-сериализацию (сохраняет UUID, номер, дату с временем, флаги)
- В источнике: `ЗаписьXML.УстановитьСтроку()` → `СериализаторXDTO.ЗаписатьXML(ЗаписьXML, ДокОбъект)` → строка.
- В приёмнике: `ЧтениеXML.УстановитьСтроку(строка)` → `СериализаторXDTO.ПрочитатьXML(ЧтениеXML)` → объект.
  Затем `ОбменДанными.Загрузка = Истина` → `Записать()`.
  - Режим Загрузка: без `ПередЗаписью` и проверок, `Проведен` и `СуммаДокумента` пишутся как в источнике.
  - Через Python-даты **не** переносить: COM сдвигает даты на −3 ч (память `com_date_shift_3_hours`), а дата документа — момент
    списка, важен до секунды.
- Если пробный прогон чистый (пропусков 0), писать без отдельного вопроса. Иначе показать пропуски и ждать решения.
- Документы приёмника, которых нет в источнике, **не удалять**. `Удалить()` не вызывать.

### Шаг 5. Проверка после записи (инварианты)
- Число документов в приёмнике = прежние + созданные.
- По каждому документу XML-сериализация в приёмнике **совпадает** с источником (сравнение строк после нормализации порядка не нужно — формат
  одинаковый). Если отличается — вывести разницу полей.
- Отдельно: UUID, номер, `Дата` (`Формат(…, "ДФ='dd.MM.yyyy HH:mm:ss'")` на стороне 1С), `Проведен`, `ПометкаУдаления`,
  `СуммаДокумента`, количество строк и Σ `Сумма` ТЧ равны источнику.
- Повторный пробный прогон показывает «без изменений» — перенос идемпотентен.

### Шаг 6. Отчёт в новой базе

   - **Допустимые расхождения** — только из-за другого факта в новой базе. Если в ней есть закупки по проектам с датой после 08.10.2026 11:36:56,

## 4. Правила

- Источник — **только чтение**. В приёмнике менять **только документы `А_ПотребаЗавершенняПроекту`**: справочники, другие документы и
  метаданные не трогать. Конфигурацию грузит пользователь.
- Rule #-1: каждый запрос 1С сначала проверить через Python COM. Псевдонимы `В`, `И`, `ПО` зарезервированы.
- Python — `C:\Python313\python.exe`. Пароли — из `.v8-project.json`, не литералом в коде, который уйдёт в git. Для BaseERPRazr те же креды, что у id=erp.
- В BSL подключения — только `Srvr="localhost"`.
- Скрипт: `_Rarzrabotki/Python/test/perenos_potreba/perenos.py`.
  - Запуск по умолчанию — пробный прогон.
  - `--apply` — запись.
  - `--rollback=<backup_target.xml>` — вернуть приёмник к состоянию до переноса (документы, которых не было, пометить на удаление,
    не удалять).
  - Писать в worktree, копировать в основной каталог (Rule #4), закоммитить скрипт. Бэкапы — рядом, в git не класть.
- Минимум прогонов: пробный → запись → проверка → приёмка отчёта. Без субагентов.
