# ПРОМТ — внешний отчёт «Дебіторська заборгованість постачальників за строками боргу та статусами» (BuhBud)

**Роль:** главный бухгалтер и разработчик отчётов 1С.
**База:** `Srvr="SQLSERVER";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`.
**Отчёт:** `_Rarzrabotki/Отчеты/А_ОтчетПоДебиторскаяЗадолженностьПоставщиковПоСрокамДолгаИстатусам.xml` + одноимённая папка, собрать в `.erf`.
**Донор данных:** `_Rarzrabotki/BASEBuh/Reports/ДебиторскаяЗадолженностьПоставщиковПоСрокамДолгаРасширенная` — только читать, не менять.
**Правила:** Rule #-1 (каждый запрос сначала выполнить через Python COM), Rule #4 (правки копировать в основной каталог).
**Экономия:** один приёмочный скрипт, без агентов-проверяльщиков.

## Цель

1. **Данные** — как в типовом отчёте «Дебіторська заборгованість постачальників по строках боргу (розширена)»: те же запросы, ветки, интервалы и «в т.ч. прострочена».
2. **Интерфейс** — как у внешних отчётов проекта (образец — «Списання за нормами (бухоблік)»): общая БСП-форма `ФормаОтчета`, варианты, «Настройки…», регистрация в «Додаткові звіти».
3. **Новое поле «Статус»** с двумя значениями:
   - «Передоплата» — деньги, уплаченные поставщику;
   - «Немає оригіналу» — поставка без полученного оригинала.
4. **Вариант по умолчанию** повторяет рабочие настройки бухгалтера Шостак Жанети.

## Факты (исследовано 30.09.2026)

### 1. Папка нового отчёта — копия чужого отчёта

Файлы папки — копия `А_ОтчетПоСписаниюПоНормам_Бухгалтерский`. Внутри XML всё ещё старое имя, синоним и `MainDataCompositionSchema`, а модуль и СКД — от отчёта списаний.

Переписать целиком:
- `Name` = имя файла `А_ОтчетПоДебиторскаяЗадолженностьПоставщиковПоСрокамДолгаИстатусам`;
- новые `uuid`, `xr:ObjectId`, `xr:TypeId`, `xr:ValueId`;
- **`xr:ClassId` оставить** (`e41aff26-25cf-4bb6-b6c1-3f478a75f374`).

В папке ровно три файла: `Ext/ObjectModule.bsl`, `Templates/ОсновнаяСхемаКомпоновкиДанных.xml`,
`Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml`. Никаких `.bak`.

### 2. Типовой донор — механизм «Бухгалтерські звіти», не чистый СКД

Точки входа:
- модуль объекта вызывает `БухгалтерскиеОтчетыВызовСервера.ОбработкаСобытияПриКомпоновкеРезультата`;
- модуль менеджера `ПередКомпоновкойМакета` подставляет текст запроса `ПолучитьТекстЗапроса(КоличествоИнтервалов)`, параметры
  (`УстановитьПараметры`), поля интервалов (`ЗаполнитьПоляВСоответствииСоСпискомИнтервалов`) и внешний набор
  `ПросроченнаяЗадолженность` (`ПолучитьПросроченнуюЗадолженность`).

Основной запрос — объединение трёх веток:

| Ветка | Источник | `СчетНаОплату` | Сумма |
|---|---|---|---|
| 1 | Дебетовые остатки `Хозрасчетный.Остатки(&Период, счета с субконто Контрагенты+Договоры кроме забалансовых, &ИсключенныеСчета и НалоговыйКредитВсего; ВидыСубконто Контрагенты/Договоры/ДокументыРасчетов; ВидДоговора = С поставщиком)` | `Субконто3` (документ расчётов) | `СуммаРазвернутыйОстатокДт` |
| 2 | Проведённые `ПоступлениеТоваровУслуг` организации с `&ДатаНачалаБас` по `&Период`, которых нет в `РС.ОтправкаПолучениеДокументов` с `ДокументыПолучены = Истина` | сам документ, `Счет = NULL` | `СуммаДокумента` |
| 3 | То же для `ПоступлениеДопРасходов` | сам документ | `СуммаДокумента` |

Параметры и расчёт:
- `ДатаНачалаБас` = 01.07.2023, в типовом прописана жёстко.
- `ИсключенныеСчета` = `БухгалтерскиеОтчетыВызовСервера.ПолучитьСписокСчетовИсключаемыхИзРасчетаЗадолженности(2)`.
- Интервалы: `ТЧ Интервалы` (Значение = дней, по возрастанию). Колонки `ОстатокПериода1..N` плюс `ОстатокПериода(N+1)` «Понад X днів».
  Границы: первый интервал — от `НачалоДня(Дата) − Значение·сутки` до `КонецДня(Дата)`, следующие — от
  `НачалоДня(Дата) − Значение·сутки` до `КонецДня(Дата) − (Пред+1)·сутки`. Сумма колонок равна общей задолженности.
- Просрочка: срок оплаты — `Договор.СрокОплаты`, если `Договор.УстановленСрокОплаты`, иначе
  `Константы.СрокОплатыПоставщикам` (параметр запроса называется `СтандартныйСрокОплатыПокупателей`). Ветки те же.
  СКД связывает наборы по 4 ключам: Организация, Контрагент, Договор, СчетНаОплату.
- Поля СКД: Организация, Контрагент («Постачальник»), Договор, СчетНаОплату («Счет на оплату»), ОстатокДолга
  («Загальна заборгованість»), ОстатокПериодаK, ПросроченнаяЗадолженность («У т.ч. прострочена заборгованість»).
  Формат в типовом — `ЧЦ=15; ЧДЦ=0`.

## Решения (утверждены пользователем)

- **Статус — по источнику строки, а не по виду документа:**
  - ветка 1 (дебетовый остаток расчётов) → **«Передоплата»**;
  - ветки 2–3 (поступление без полученного оригинала) → **«Немає оригіналу»**.

  Так переплата 522,61 по двум надходженням не попадёт в «нет оригинала», и пустых статусов не будет.
- **Названия** — «Передоплата», а не «Передплата» (это «подписка»); «Немає оригіналу», а не «Не має оригінала».

## Решения исполнителя по умолчанию (принять как есть)

- **Имена полей** — как в типовом (`Организация`, `Контрагент`, `Договор`, `СчетНаОплату`, `ОстатокДолга`, `ОстатокПериодаK`,
  `ПросроченнаяЗадолженность`), плюс `Статус`. Тогда отборы и группировки бухгалтера переносятся один в один.
- **Организация** — обязательный параметр, как в типовом. По умолчанию — основная организация пользователя; если пусто —
  `ВызватьИсключение "Вкажіть організацію"`. Обособленные подразделения не поддерживаются: в группе их нет.
- **Интервалы** — параметр `Интервалы` (Строка, «Інтервали, днів»), по умолчанию `"7, 15, 30"`. Числа через запятую,
  сортировать по возрастанию, дубли и нули отбрасывать. Колонки и их заголовки строятся кодом как в типовом:
  «До 7 днів», «Від 8 до 15 днів», …, «Понад 30 днів».
- **`ДатаНачалаБас`** — параметр «Дата початку обліку в BAS», по умолчанию 01.07.2023, не в быстрых настройках.
- **Суммы** — `ЧЦ=15; ЧДЦ=2`: бухгалтеру нужны копейки, в типовом было 0.
- Диаграмма не нужна. Свёртку уровней не делать — в типовом всё развёрнуто.

  - служебные, их ставит код: `ВидыСубконтоКД`, `ИсключенныеСчета`, `НачалоИнтервалаK`, `КонецИнтервалаK`.

    интервалов добавляет код), колонки `СчетНаОплату.НомерВходящегоДокумента` и `Статус` на уровне документа;
  - все 11 отборов с теми же флагами использования, плюс отбор `Статус` = … (выключен) для быстрого выбора;
  - сортировка, условное оформление, макет «Море», заголовок.
- **Грабли** ([[erf_build_classid_and_stray_files]]):
  - при ссылочных типах объявить `xmlns:cfg` в корне `Template.xml`;
  - никакого `<use>` внутри `<parameter>`;
  - украинские «і/є» — только в заголовках, не в именах.

### Модуль объекта

1. `СведенияОВнешнейОбработке()` — как в образце. Информация: «Дебіторська заборгованість постачальників за строками боргу:
   передоплата та поставки без оригіналу».
2. `ПриКомпоновкеРезультата` → `СтандартнаяОбработка = Ложь; СформироватьОтчет(ДокументРезультат, ДанныеРасшифровки)`.
3. `СформироватьОтчет(ДокументРезультат, ДанныеРасшифровки = Неопределено) Экспорт`:
   1. `Настройки = КомпоновщикНастроек.ПолучитьНастройки()`, прочитать параметры: `КонецДня(Период)`, организация
      обязательна, интервалы разобрать из строки.
   2. Взять копию схемы (`ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных")`) и подставить `ТекстЗапросаОтчета(N)`.
   3. Перенести из донора `ЗаполнитьПоляВСоответствииСоСпискомИнтервалов`: поля `ОстатокПериода1..N+1` с заголовками,
      поля итога, колонки в выбранной папке. Добавлять только если колонки нет — пользовательские настройки не ломать.
   4. Выставить параметры: границы интервалов, `ВидыСубконтоКД` (Контрагенты, Договоры, ДокументыРасчетовСКонтрагентами),
      `ИсключенныеСчета`, `Период`, `Организация`, `ДатаНачалаБас`.
   5. Внешние наборы: `Новый Структура("ПросроченнаяЗадолженность", ПросроченнаяЗадолженность(...))`.
   6. Скомпоновать с `ДанныеРасшифровки`, чтобы двойной клик открывал документ. Заголовок вывода — «Дебіторська заборгованість
      постачальників за строками боргу та статусами на <дата> <організація>».
4. `ТекстЗапросаОтчета(КоличествоИнтервалов) Экспорт` — перенос `ПолучитьТекстЗапроса` донора. Экспорт нужен для Rule #-1:
   запрос проверяется через COM.
5. `ПросроченнаяЗадолженность(...)` — перенос `ПолучитьПросроченнуюЗадолженность` донора.
6. Хелперы `БухгалтерскиеОтчетыКлиентСервер.УстановитьПараметр` / `ДобавитьВыбранноеПоле` вызывать из конфигурации,
   не копировать.

### Как протянуть «Статус» через запросы (единственное изменение логики донора)

- В **каждой** ветке каждого `ОБЪЕДИНИТЬ ВСЕ` добавить поле литералом:
  - ветка 1: `ВЫРАЗИТЬ("Передоплата" КАК СТРОКА(20)) КАК Статус`;
  - ветки 2 и 3: `ВЫРАЗИТЬ("Немає оригіналу" КАК СТРОКА(20)) КАК Статус`.

  Это касается `ВзаиморасчетыОстатки`, `Обороты1..N`, а в просрочке — `ОстаткиДолга` и `ОборотыK`. `ВЫРАЗИТЬ` нужен, чтобы
  тип объединения не зависел от длины литерала.
- Везде, где ключ содержит `СчетНаОплату`, рядом добавить `Статус`: `ПОМЕСТИТЬ`/`ВЫБРАТЬ`, условия
  `ЛЕВОЕ СОЕДИНЕНИЕ … ПО … И X.Статус = Y.Статус`, `СГРУППИРОВАТЬ ПО`, `ИНДЕКСИРОВАТЬ ПО`, итоговый `ВЫБРАТЬ` и блок `{ВЫБРАТЬ …}`.
- Остальной текст, условия и счета — **один в один** с донором. Псевдонимы не менять: `В`, `И`, `ПО` зарезервированы.
