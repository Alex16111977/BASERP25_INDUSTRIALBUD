## 0. Цель и метод (экономика)

Экономия к кошторису СС при допущении директора: **докупаем только то, что в его списке, остальное недокупленное по СС больше
не покупаем.**

| | «План-факт» (старый метод) | Новый метод «за потребою» |
|---|---|---|
| Остаток к покупке | недокупленное количество до СС × цена СС по каждой загальній назві (`ПланНаФактГрн`) | сумма списка директора (с учётом закупок после даты списка) |
| Прогноз | Куплено + Залишок за СС (`ПрогнозГрн`) | Куплено + Залишок потреби |
| Экономия | План СС − Прогноз | План СС − Прогноз |

Свойства, которые код обязан сохранить:
1. **На дату списка итог проекта не зависит от сопоставления названий:** Прогноз = Σ Куплено + Σ Потреба. После даты списка
   зависит — через списание. Строки без загальної назви (текст) закупками не списываются никогда.
2. **Список = остаток к покупке на момент списка.** Проверено на данных: кушетка, столик, шафа 10 + 3 = 13 = план; обігрівач IRC 45 + 28 = 73.
3. **Закупки после момента списка списывают потребу** той же загальної назви (п. 3.4 шаг 4). Без этого через неделю отчёт задвоит
   купленное. Граница — **точный момент документа** (дата+время), а не конец дня: ПТУ приходят пачками вечером.
4. **Всё в гривнах с НДС.** План СС и факт закупок (`СебестоимостьТоваров.Стоимость`) с НДС. Цены директора тоже с НДС —
   подтверждено документами закупки: кондиционер 16 699 = 13 915,83 × 1,2; генератор 37 198,80.
5. **Знак.** Экономия > 0 — экономия, < 0 — перевитрата. В «План-факт» знак обратный.
6. **Прозрачность допущения — «Не докуповуємо (поза списком)».** Сюда входят:
   - Залишок за СС по загальним назвам, которых нет в списке;
   - недокупленное по СС количество сверх потребы по позициям из списка. Пример: ОСБ Адмін — остаток СС 386 шт, в списке 22 шт,
     скрыто 254 872,80.

   Это сумма, от покупки которой директор фактически отказывается.

### 3.2. Чтение файла

- **Маркер:** единственная непустая ячейка строки, начинается с «проект». Маркеров нет — весь лист.
- **Шапка:** в 1–3 строках после маркера распознано не меньше 4 полей.

  | Поле | Признак |

  | НазваСС | «вірна назва» / «загальна назва» / «назва сс» |
  | НазваТовару | «назва товару» / «найменування» |

  | ОдСС | «од» / «одиниц» + «сс» |

  | Дома | «будин» / «дім» |
  | ЦенаФайла | «ціна» |
  | Стоимость | «вартість» / «сума» |

  - Обязательны: (НазваСС или НазваТовару) и (ОбъемСС или КолФайла) и (Стоимость или ЦенаФайла).
  - «без пдв» в заголовке цены — флажок без НДС.
- **Данные:** до следующего маркера, конца листа или 3 пустых строк подряд.
  - Итоговая строка: обе «Назви» пусты и J — число, **или** в строке есть «разом/итого/всього/усього».
- **Значения строки:**
  - Сумма = Окр(J); если J нет — Окр(G×I).
  - Цена = Окр(I).
  - КоличествоСС = E, если E > 0, иначе G при N(D) = N(F), иначе 0 + предупреждение.
  - Дома — из `.Текст`, разделители → «,».
- **Контроль ИТОГО:** |Σ − ИТОГО| > 0,01 × N строк → ошибка, ТЧ не заполняется.

### 3.3. Сопоставление ОН
1. СокрЛП-имя, затем N(имя) — среди ОН строк Комплектующие активных СС подразделения. При дублях — с наибольшей суммой плана.
2. То же по справочнику (непомеченные; приоритет: есть Единица → есть ОсновнаяНоменклатура → меньший код). Предупреждение «Є в довіднику, але немає в СС проєкту».
3. Не найдено: если N начинается с «монтаж» — «Робота, не матеріал…», иначе «Не знайдено в довіднику — у звіті поза СС».
4. **Складена назва «A / B».** Части ищутся шагом 1. Строка относится к части с наибольшей суммой плана. Предупреждение «Складена назва: віднесено до X, покриває також …».
5. По «Назва товару» через Номенклатуру автоматически не искать.
6. `ЕдиницаСС` — единица плана этой ОН (с наибольшей суммой), иначе `ОН.Единица`. Если N(D) ≠ N(ЕдиницаСС) — предупреждение.

### 3.4. Отчёт `А_ПрогнозВиконанняССЗаПотребою` — данные
Форма `CommonForm.ФормаОтчета`. `ПриКомпоновкеРезультата` вызывает экспортную `СформироватьОтчет(ТабДок, ДанныеРасшифровки)`.
`УстановитьПривилегированныйРежим(Истина)` — на весь расчёт и компоновку.
Имена полей и параметров — **без і/є/ї** (украинский текст только в `title`).

- **Параметр `ДатаОтчета`** (Дата; пусто — текущая). Разворачивать `СтандартнаяДатаНачала` → `.Дата`. D = `КонецДня`.
- **Шаг 1. Документы потребы.** Последний проведённый с `Дата <= D` на подразделение: `УПОРЯДОЧИТЬ ПО Подразделение, МоментВремени УБЫВ`.
  - Момент списка L = `Док.Дата` (с временем).
  - Текст группировки `СписокПотребы` = «список від dd.MM.yyyy HH:mm (№ N)».
  - Проекты без документа в отчёт не попадают.
- **Шаг 2. План и факт.** `ПолучитьДанные(Новый СтандартныйПериод(Дата(2000,1,1), D))`, `Блок = "2. Матеріали"`.
  - Даты ПТУ — одним запросом.
  - Закупка «після списку», если `ПТУ.Дата > L`.
- **Шаг 3. Группы** по ключу 1.1.
  - Строки потребы без ОН — ключ `"|ТЕКСТ|" + N(назва)`.
  - Накопить: `ПланКол, ПланГрн, КупленоКол, КупленоГрн, ПослеКол, ПослеГрн, ЗалишокСС, ПотребаГрн, ПотребаКолСС, ПотребаКолФайла`, единицы закупок «після», единицу плана (строки с наибольшим `ПланГрн`).
- **Шаг 3а. Наборы списания.** Группы частей складеної назви объединяются (union-find) в один набор: закупки любой части списывают строку.
- **Шаг 4. Залишок потреби набора.**
  - `ПотребаГрн = 0` → 0.
  - `ПослеГрн = 0` → `ПотребаГрн`.
  - **Ветка «по количеству»** (только набор из одной группы), если выполнены все условия:
    - (а) у закупок «після» одна единица, и она равна N(ЕдиницаСС) (тогда кол-во `КоличествоСС`) или N(Единица) (тогда `Количество`) строк потребы;
    - (б) нет предупреждений «Одиниця…»/«…кількість…»;
    - (в) цена каждой строки потребы в пределах ±5 % от средней (однородность: «Сигналізація» из 4 разных изделий сюда не пройдёт);
    - (г) средняя цена «після» в [0,67; 1,5] × цены потребы;
    - (д) для `КоличествоСС`: цена потребы в [0,67; 1,5] × цены СС (ловит r42).

    Тогда `Макс(0, ПотребаКол − ПослеКол) × ПотребаГрн / ПотребаКол`.
  - Иначе — **по деньгам**: `Макс(0, ПотребаГрн − ПослеГрн)`.
  - Результат Окр(2), распределяется по группам набора пропорционально их потребе.
- **Шаг 5. `НеДокупаем`.**
  - Набор из одной группы без потребы → `ЗалишокСС`.
  - Одна группа с потребой, где есть план с `ПланКол > 0` и единица потребы = единица плана → `Макс(0, ЗалишокСС − КолСС_ост × ПланГрн / ПланКол)`, где `КолСС_ост = ПотребаКолСС × ЗалишокПотребы / ПотребаГрн`.
  - Группы составных наборов → 0.
- **Шаг 6. Признаки.**
  - `ОзнакаСС`:
    - «У кошторисі СС» — ОН есть в Комплектующие СС проекта, даже с планом 0; при плане 0 — «(план 0)»;
    - «Поза СС: є в довіднику»;
    - «Поза СС: робота» (монтаж);
    - «Поза СС: немає в довіднику».
  - `ЕтапНазва`: этап плановой строки с наибольшим `ПланГрн`. Если плановых строк нет — «Поза кошторисом СС».
- **Шаг 7. Строки набора** (`ДокументПотребы` и `СписокПотребы` — в **каждой** строке):

  | Вид рядка | Данные |
  |---|---|
  | «План СС» | план |
  | «Закупівля» / «Закупівля після списку» | `ПослеГрн` |
  | «Залишок за СС» | синтетика |
  | «Потреба» | `Аналитика` = Назва товару, `Документ` = документ потребы, `Дома` |
  | «Залишок потреби» | одна на группу: `ЗалишокПотребы`, `НеДокупаем` |

### 3.5. Отчёт — схема и вывод
- **Ресурсы — только канон «План-факт»:** колонка набора + `totalField` через `Сумма(поле набора)`, операторы ASCII.
  - Ссылаться на другой ресурс по имени нельзя: СКД молча берёт первую запись.
  - Формулы:
    - `ПрогнозПотреба = Сумма(КупленоГрн)+Сумма(ЗалишокПотребы)`;
    - `ЭкономияПотреба = Сумма(ПланГрн)-Сумма(КупленоГрн)-Сумма(ЗалишокПотребы)`;
    - `ЭкономияПроцент = ВЫБОР КОГДА Сумма(ПланГрн)=0 ТОГДА 0 ИНАЧЕ (…)/Сумма(ПланГрн)*100 КОНЕЦ`;
    - `ПрогнозСС`, `ЭкономияСС` — аналогично через `ЗалишокСС`;
    - `РазницаМетодов = Сумма(ЗалишокСС)-Сумма(ЗалишокПотребы)`;
    - `ЦенаПлан`, `ЦенаПотребы`, `ЦенаФакт`;
    - `ОтношениеЦен` = (ПотребаГрн/ПотребаКол)/(ПланГрн/ПланКол).
- **Варианты:**
  1. «Прогноз за потребою»: [Підрозділ, Список потреби] → Етап → Загальна назва. Колонки: План, Куплено, Потреба, Після списку, Залишок потреби, Прогноз, Економія, %, Прогноз за СС, Економія за СС, Різниця методів, Не докуповуємо. Экономия < 0 — красным.
  2. «… — детально»: + Ознака СС → Вид рядка → Аналітика+Будинки → Документ; количества и цены. Отношение цен вне [0,67; 1,5] — оранжевым.
  3. «Не докуповуємо (поза списком)»: [Підрозділ, Список] → Загальна назва, отбор группировки `НеДокупаем > 0`, сортировка по убыванию. Вывод отбора группировки выключен.
- **Быстрые настройки:** `ДатаОтчета` (userSettingID) и отбор `Подразделение`. ID уникальны в каждом варианте.
- **Вывод на украинском независимо от языка сеанса:**
  - `ВыводитьПараметрыДанных` и `ВыводитьОтбор` = НеВыводить;
  - заголовок собирается кодом: «<заголовок варианта> на dd.MM.yyyy. Відбір: Підрозділ = …»;
  - после вывода `ТабДок.НайтиТекст("Итого", …, ПоЯчейкеЦеликом)` → «Разом»;
  - группировка по тексту `СписокПотребы`, а не по ссылке (в ней русское «от»).
