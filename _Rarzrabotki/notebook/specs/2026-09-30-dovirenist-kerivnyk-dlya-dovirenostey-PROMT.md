# ПРОМТ — Доверенность (BuhBud): роль «Керівник для довіреностей» вместо заплатки в печати

**Роль:** главный бухгалтер + системный инженер 1С. Типовой механизм не ломать, а расширять.
**База:** `Srvr="SQLSERVER";Ref="bas_industrialbud";Usr="cfo";Pwd="2442"`.
**Исходники:** `_Rarzrabotki/BASEBuh`. Работать в worktree, после правки копировать в `C:\Configuration_downloads\BASERP25` (Rule #4).
**Экономия:** один целевой приёмочный тест, агентов-проверяльщиков не запускать.

## Цель

1. Для ТОВ «ІНДАСТРІАЛБУД» печать «Доручення на одну сторінку» совпадает с
   `_Rarzrabotki/temp/Довіреність нова.xlsx` ячейка в ячейку.
2. В коде нет ни одного ФИО.
3. Кто подписывает доверенности, бухгалтер задаёт сам — по каждой организации, с историей по датам, в типовой форме
   «Відповідальні особи».
4. Остальные организации печатаются по-типовому.

## Факты (проверено 30.09.2026 чтением кода и COM)

1. **Заплатка** — `Documents/Доверенность/Ext/ManagerModule.bsl`, функция `ПечатьДоверенности`, блок `//Тютюн … //КонецИзменений`
   в области «ОбратнаяСторонаПодвал»:
   - `СтрЗаменить(ФИОРуководителя, "ОЛЕКСАНДР ВОРОНЦОВ", "Манжула М.А.")` срабатывает во **всех** организациях, где руководитель
     Воронцов: ІНДАСТРІАЛБУД, ДЖИ ТРИ КОНСТРАКШН, Дмитровицька Долина, ВФ АССЕТС (до 05.03.2026), ФОП Воронцов. Во всех них
     печатается чужой подписант;
   - `Руководитель = "Керівник підприємства"` ставится всегда, а «Директор виконавчий» — только при точном совпадении строки.
     Для ІНДЕПТ СТІЛ, где Манжула действительно директор, условие не срабатывает: формат ДСТУ даёт «Максим МАНЖУЛА».
2. **Макет** `ПФ_MXL_UK_Доверенность` содержит параметр `Руководитель` — подпись-должность в подвале. Заполняет его только
   заплатка: типовой код заполняет лишь `ФИОРуководителя` и `ФИОГлавногоБухгалтера` (оба через `ИмяФамилияВФорматеДСТУ`).
   Бланк `ПФ_MXL_UK_ДоверенностьБланк` подписей не содержит — его не трогать.
3. **«Довіреність нова.xlsx»** совпадает с текущей печатью «ДоверенностьСтраница» документа ІБ00-000101 от 28.09.2026 во всех
   58 ячейках, кроме трёх:

   | Ячейка | Сейчас | Нужно |
   |---|---|---|
   | B37 | Директор виконавчий | Директор фінансовий |
   | K37 | Манжула М.А. | Постернак А.В. |
   | K39 | Маргарита АУЛОВА | Аулова М.В. |

   **Новый макет не нужен** — меняются только данные подписей.
4. **Типовой механизм ответственных лиц:**
   - хранение — РС `ОтветственныеЛицаОрганизаций`, периодический (секунда). Измерения: `СтруктурнаяЕдиница` (Организации),
     `ОтветственноеЛицо` (`Перечисление.ОтветственныеЛицаОрганизаций`). Ресурсы: `ФизическоеЛицо`, `Должность`;
   - значения перечисления: Руководитель, ГлавныйБухгалтер, РуководительКадровойСлужбы, Кассир,
     ОтветственныйЗаБухгалтерскиеРегистры;
   - цепочка чтения: `ОтветственныеЛицаБП.ОтветственныеЛица(Организация, Дата)` → `ОтветственныеЛицаБППовтИсп`
     (кэш) → `ОтветственныеЛицаБППереопределяемый.ОтветственныеЛица`. В последнем на каждое значение перечисления своя ветка
     `ИначеЕсли`;
   - результат — структура с ключами `<Роль>`, `<Роль>ФИО` (Фамилия/Имя/Отчество/Представление), `<Роль>Представление`,
     `<Роль>Должность`, `<Роль>ДолжностьПредставление`;
   - пустой каркас структуры — `ОтветственныеЛицаБП.ПустаяСтруктураОтветственныхЛиц()`, фиксированный массив имён.
5. **Интерфейс.** Карточка организации → «Всі відповідальні особи» → `РегистрСведений.ОтветственныеЛицаОрганизаций.ФормаСписка`.
   Список ролей строится циклом `Для каждого … Из Перечисления.ОтветственныеЛицаОрганизаций`, поэтому **новая роль появится
   в форме сама**, формы не менять.
6. **Обмены.** Регистр входит в состав типовых планов обмена (Полный, ПоОрганизации, УТ, Розница), но в правилах
   `_Rarzrabotki/ExChange/*` (ЕРП↔Бух, Казна↔Бух) не встречается.
7. **Данные:**
   - «Постернак Андрій Володимирович» есть в `ФизическиеЛица`;
   - в `Должности` есть «Фінансовий директор» и «Директор виконавчий», **нет** «Директор фінансовий»;
   - типовое `Представление` главбуха ІНДАСТРІАЛБУД — «Аулова␣␣М.В.» (двойной пробел), руководителя — «ВОРОНЦОВ О.В.»
     (заглавными, как хранится). Поэтому формат подписи делать своей функцией, а не брать `Представление`.

## Решения (утверждены пользователем)

- Вернуть типовой код печати, заплатку удалить полностью.
- Расширить типовой механизм: новая роль **«Керівник для довіреностей»**. Сейчас подписант доверенности ищется среди
  руководителей организации, а будет искаться по этой роли. Бухгалтер управляет ею по каждой организации с датой.
- Подписи в доверенности печатать в формате **«Прізвище І.Б.»** для всех организаций, и руководителя, и главбуха.
  Другие печатные формы не меняются.
- Если у организации роли «Керівник для довіреностей» нет, печатается типовое: «Керівник підприємства» + руководитель организации.
  У организаций Воронцова «Манжула» больше не подставляется.

Рядом с `ПечатьДоверенности` добавить служебную функцию:

```bsl
// Подпись в формате «Прізвище І.Б.» из структуры ФИО ответственного лица (Фамилия, Имя, Отчество, Представление).
// Фамилию, записанную целиком заглавными («ВОРОНЦОВ»), приводит к виду «Воронцов», каждую часть двойной фамилии отдельно.
Функция ФИОДляПодписиДоверенности(ФИО)
	
	Фамилия  = СокрЛП(ФИО.Фамилия);
	Имя      = СокрЛП(ФИО.Имя);
	Отчество = СокрЛП(ФИО.Отчество);
	Если ПустаяСтрока(Фамилия) Тогда
		Возврат СокрЛП(СтрЗаменить(ФИО.Представление, "  ", " "));
	КонецЕсли;
	
	Если Фамилия = ВРег(Фамилия) Тогда
		Части = СтрРазделить(Фамилия, "-");
		Для Индекс = 0 По Части.ВГраница() Цикл
			Части[Индекс] = ВРег(Лев(Части[Индекс], 1)) + НРег(Сред(Части[Индекс], 2));
		КонецЦикла;
		Фамилия = СтрСоединить(Части, "-");
	КонецЕсли;
	
	Инициалы = ?(ПустаяСтрока(Имя), "", ВРег(Лев(Имя, 1)) + ".")
		+ ?(ПустаяСтрока(Отчество), "", ВРег(Лев(Отчество, 1)) + ".");
	
	Возврат Фамилия + ?(ПустаяСтрока(Инициалы), "", " " + Инициалы);
	
КонецФункции
```

- Перед написанием поискать `Функция ФамилияИнициалы` в `CommonModules/ФизическиеЛицаКлиентСервер`. Если типовая функция даёт
  ровно «Постернак А.В.» / «Аулова М.В.» / «Воронцов О.В.» — использовать её, свою не писать.
- Макет: параметр `Руководитель` оставить — он нужен для должности подписанта. В Конфигураторе («Сравнить с конфигурацией
  поставщика» по `Документ.Доверенность`) подтвердить, что у поставщика в этой ячейке был текст «Керівник підприємства».
  Если там было другое — подставить в `НСтр` выше именно типовой текст.
