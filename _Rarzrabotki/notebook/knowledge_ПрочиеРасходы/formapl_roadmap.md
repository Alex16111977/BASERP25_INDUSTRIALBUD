## 4. Σ-инвариант реализации (критерий «не сломал»)

После КАЖДОГО этапа:
```
Σ Сумма (и СуммаУпр, СуммаРегл) по (период, организация) ПОСЛЕ == ЭТАЛОН ДО   (до копейки)
```
Меняется только разбивка по `ФормаPL` внутри той же суммы; общий итог регистра, P&L и баланс — неизменны.
`ПрочиеРасходы` не входит в управленческий баланс через `А_ВзСС`, но входит в P&L — поэтому
`Σ Sum_Fact` (P&L) тоже должен сойтись с эталоном.

## 5. Anti-patterns (что НЕ делать)

| Анти-паттерн | Почему плохо | Правильно |
|---|---|---|
| Перейти на прямую таблицу регистра в `А_ФинРез_PL` ради `ФормаPL` | не нужно (это измерение) + риск регресса Σ Приход→оборот (грабля 2026-05-21) | читать `ФормаPL` из `.Обороты`, сумма — `СуммаПриход` |
| Заменить `СУММА(СуммаПриход)` на оборот | факты обнуляются для подразделений с `РаспределениеПрочихЗатрат` | `СуммаПриход` + `ВидДвижения=Приход` |
| Массово перепровести все 129 регистраторов автономно | боевые данные, риск; memory `feedback_user_reposts_history_self` | код + smoke на 1–2 доках, историю перепроводит пользователь в UI |
| Пере-создавать ОЗФУ через COM | подвоение ТЧ (17_formapl_split §6) | только UI-кнопка |
| Положить `ФормаPL` мимо `ДополнительныеПоля` (хардкод в одну ветку) | потеряется в сторно/получателе кросс-орг | через `ДополнительныеПоля` (3 маркера) |
| Не задать значение по умолчанию для веток без формы | `ФормаPL` = пустая ссылка → «третья» форма в Своде | fallback `Форма1` (или по правилу финансиста) |
| BSL-запрос без Python COM теста | синтаксис/поля виртуальной таблицы (Rule #-1) | сначала Python COM, потом BSL |
