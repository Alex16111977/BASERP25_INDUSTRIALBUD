# PROMPT — `ФормаPL` для ВСЕХ прочих движений `ПрочиеРасходы` = Форма1 (register-level) + фикс `РаспределениеПрочихЗатрат`

> **Регистр:** `РегистрНакопления.ПрочиеРасходы`, измерение `ФормаPL` (`EnumRef.А_ФормыPL` = {Форма1, Форма2}).
> **Идея заказчика:** не лезть в код каждого из 129 документов, а поставить **дефолт на уровне записи в регистр**
> (`RecordSetModule.ПередЗаписью`): любое движение без явной `ФормаPL` → **Форма1**.
> **Исключение (делать ПЕРВЫМ):** `РаспределениеПрочихЗатрат` работает с **остатками** → должен наследовать `ФормаPL`
> из остатков, иначе общий дефолт затрёт Ф2-затраты в Ф1.
> **Статус:** дизайн согласован через `/superpowers:brainstorming`. Scope — `ПрочиеРасходы` (НЕ `А_ФинРез_PL`/отчёт).
> **База знаний:** `_Rarzrabotki/notebook/knowledge_ПрочиеРасходы/`. Этапы 1 (ОЗФУ) и 3 (РКО) уже сделаны.

ставят `ФормаPL` сами (ОЗФУ, РКО, РаспределениеПрочихЗатрат после фикса), дефолт **не трогает** (значение уже заполнено).

## 3. Архитектура решения (2 части, строгий порядок)

```
Часть A (ПЕРВОЙ): РаспределениеПрочихЗатрат — протянуть ФормаPL через цепочку остатков → движения
                  наследуют форму перераспределяемой затраты (Ф1 остаётся Ф1, Ф2 остаётся Ф2).
Часть B (ПОТОМ):  RecordSetModule.ПередЗаписью регистра — пустая ФормаPL → Форма1 (для всех прочих).
```

**Почему именно такой порядок.** Если сделать только Часть B, то движения `РаспределениеПрочихЗатрат` (у которых
своя `ФормаPL` пустая) общий дефолт затрёт в Форма1 → Ф2-затраты при перераспределении превратятся в Ф1, и парная
проводка (сторно у донора Ф2 ↔ Форма1 у получателя) перестанет схлопываться → разрез поедет. Поэтому
`РаспределениеПрочихЗатрат` сперва учим ставить `ФормаPL` самому (из остатков) — тогда дефолт его не тронет.

## 4. Часть A — `РаспределениеПрочихЗатрат`: наследовать `ФормаPL` из остатков

**Файл:** `Documents/РаспределениеПрочихЗатрат/Ext/ManagerModule.bsl`.
**Что делает документ:** читает `РегистрНакопления.ПрочиеРасходы.Остатки(...)` (≈стр. 64), джойнит реальную таблицу
регистра по измерениям (≈стр. 243-250: Организация, Подразделение, НаправлениеДеятельности, СтатьяРасходов,
АналитикаРасходов, НалоговоеНазначение — **без `ФормаPL`**), перераспределяет на направления и пишет движения
`ПрочиеРасходы` (пары Расход-донор / Приход-получатель).

**Правка — протянуть `ФормаPL` как ещё одно измерение по ВСЕЙ цепочке** (она доступна в `.Остатки`, т.к. измерение):
1. **`.Остатки(... , Измерения)`** (≈стр. 62-100): включить `ФормаPL` в выбираемые измерения остатков
   (`ПредварительныеОстаткиРасходов` / `ОстаткиРасходов`).
2. **JOIN остатков с реальной таблицей `ТекущиеДвижения`** (≈стр. 243-250) и с `Регистраторы` (≈стр. 373-378):
   добавить `ФормаPL` в условие соединения (иначе Ф1- и Ф2-остатки одной (Орг,Подр,Статья,…) свернутся вместе).
3. **`РасходыКРаспределению`** (≈стр. 306-398): протащить `ФормаPL` в SELECT и `СГРУППИРОВАТЬ ПО`/`ИНДЕКСИРОВАТЬ ПО`.
4. **Финальные движения** (Расход у донора + Приход у получателя): записывать `ФормаPL` = форма исходной затраты
   (из остатков). Расход-сторно у донора должно иметь ту же `ФормаPL`, что и исходное движение — иначе остаток
   по форме не обнулится.
5. Везде, где сейчас фигурируют измерения, `ФормаPL` идёт «спутником» (тот же приём, что `ФизическоеЛицо`/`ФормаPL`
   в ОЗФУ — см. [formapl_ozfu_done.md](formapl_ozfu_done.md)).

> ⚠️ `РаспределениеПрочихЗатрат` НЕ использует общий конструктор регистра с `ДополнительныеПоля` — у него
> собственный запрос остатков и движений; правки точечные по этому запросу.
> ⚠️ Если остатки на момент перепроведения ещё с пустой `ФормаPL` (история не доформирована) — движения выйдут
> пустыми и попадут под дефолт Форма1. Поэтому **порядок перепроведения**: сперва документы-источники, в конце —
> `РаспределениеПрочихЗатрат` (см. §6).

## 5. Часть B — register-level дефолт в `RecordSetModule.ПередЗаписью`

**Файл:** `AccumulationRegisters/ПрочиеРасходы/Ext/RecordSetModule.bsl`.
В самом начале `Процедура ПередЗаписью(Отказ, Замещение)` (ПЕРЕД `Если ОбменДанными.Загрузка …`, чтобы дефолт
срабатывал на ЛЮБОМ пути записи, включая запись расчётом партий/себестоимости) добавить:

```bsl
Процедура ПередЗаписью(Отказ, Замещение)

	// А_ФормаPL: дефолт формы учёта. Движения, которым документ-регистратор не задал ФормаPL явно
	// (ОЗФУ/РКО/РаспределениеПрочихЗатрат ставят сами), считаем официальной затратой → Форма1.
	Для Каждого Запись Из ЭтотОбъект Цикл
		Если НЕ ЗначениеЗаполнено(Запись.ФормаPL) Тогда
			Запись.ФормаPL = Перечисления.А_ФормыPL.Форма1;
		КонецЕсли;
	КонецЦикла;

	Если ОбменДанными.Загрузка
		Или РасчетСебестоимостиПрикладныеАлгоритмы.ДвиженияЗаписываютсяРасчетомПартийИСебестоимости(ЭтотОбъект) Тогда
		Возврат;
	КонецЕсли;
	// … далее существующий код без изменений …
```

**Почему в начале (до `Возврат`-ов):** иначе при ранних возвратах (Загрузка, запись расчётом партий) часть движений
останется с пустой `ФормаPL`. Цель — гарантировать, что НИ ОДНО движение `ПрочиеРасходы` не остаётся без формы.

> Остальной код `ПередЗаписью`/`ПриЗаписи` (контроль изменений для расчёта себестоимости) **НЕ менять** — он
> группирует по своим измерениям без `ФормаPL`, на него дефолт не влияет.

## 6. Инварианты (что нельзя сломать)

1. **Σ не меняется** ни по одному ресурсу (Сумма/СуммаУпр/СуммаРегл/…) — добавляется только значение измерения.
2. **ОЗФУ/РКО не трогаются:** их движения приходят с заполненной `ФормаPL` (Ф1/Ф2) → `ЗначениеЗаполнено`=Истина →
   дефолт пропускает. Проверить: после правки реперные ОЗФУ/РКО при перепроведении сохраняют свои Ф1/Ф2.
3. **РаспределениеПрочихЗатрат — балансовая целостность:** сторно у донора и регистрация у получателя имеют ОДНУ
   форму (исходную) → остаток по (форма) обнуляется у донора и появляется у получателя. Проверить: Σ по форме
   до/после перераспределения сходится; нет «зависших» Ф2→Ф1.
4. **Расчёт себестоимости/партий не затронут** (логика `ПриЗаписи` не меняется).
5. **Порядок перепроведения истории** (пользователь, в UI/где можно COM): сначала документы-источники
   (Приобретение, СписаниеНедостач, ВнутрПотребление, Амортизация, СБДС, АвансовыйОтчёт, ОЗФУ, РКО…), в конце —
   `РаспределениеПрочихЗатрат` (читает уже сформированные по форме остатки). Массово — не автономно
   (memory `feedback_user_reposts_history_self`).
