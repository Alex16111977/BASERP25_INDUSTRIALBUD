## 1. Цель

В регистре `ПрочиеРасходы` теперь есть измерение **`ФормаPL`** (Этапы 1-2 DONE). Отчёт `А_ОтчетPL` сравнивает
**план PL (Excel)** с **фактом 1С**. Сейчас план уже разнесён на Ф1/Ф2 (колонки `СуммаФ1`/`СуммаФ2`), а факт
показан ОДНОЙ колонкой `СуммаЕРП` (без разреза). **Задача — разнести факт по форме и добавить сравнение по форме:**

1. Добавить ресурс **`СуммаЕРПФ1`** и **`СуммаЕРПФ2`** — факт по форме учёта:
   - **расход**: `Р.ФормаPL = Форма2` → в `СуммаЕРПФ2`; иначе (Форма1 **или пусто**) → в `СуммаЕРПФ1`;
   - **доход и CoGS (себестоимость)** — целиком в **`СуммаЕРПФ1`** (Ф2 = 0).
2. Добавить ресурсы сравнения **`РазницаФ1`** и **`РазницаФ2`** по образцу существующего `Разница`:
   - `РазницаФ1 = Сумма(СуммаФ1) − Сумма(СуммаЕРПФ1)` (план Ф1 − факт Ф1);
   - `РазницаФ2 = Сумма(СуммаФ2) − Сумма(СуммаЕРПФ2)` (план Ф2 − факт Ф2).
3. **Существующие `СуммаЕРП` и `Разница` ОСТАЮТСЯ** (добавляем, не заменяем). Инвариант:
   `СуммаЕРПФ1 + СуммаЕРПФ2 = СуммаЕРП`, `РазницаФ1 + РазницаФ2 = Разница`.

> Факт расхода — это **измерение `ФормаPL`** в прямой таблице `ПрочиеРасходы` (как `А_ФизическоеЛицо`),
> доступно прямо в `втЕРП_Расх_Детали` без перехода на `.Обороты`. НЕ менять `СУММА(Р.Сумма)`+`ВидДвижения=Приход`
> (грабля §2.1 architecture_invariants — иначе факты подразделений с распределением обнулятся).

## 2. Структура `ПолучитьОбъединенныеДанные()` (что где)

Запрос строит плоскую ТЗ (внешний набор данных СКД). CTE → финальный UNION из 7 секций (`ВЫБРАТЬ * ИЗ вт… ГДЕ &Показ…`).

| ВТ / ветка | Стр. ~ | Роль | Что с Ф1/Ф2 |
|---|---|---|---|
| `втPL` | 119-137 | план из `А_ОтчетPL.ДанныеОтчета` (`СуммаФ1`/`СуммаФ2`/`СуммаPL`) | план уже разнесён |
| `втЕРП_Расх_Детали` | 162-259 | **факт расхода** из `ПрочиеРасходы` (ПРЯМАЯ табл., `СУММА(Р.Сумма)`, `ВидДвижения=Приход`) | **+ split по `Р.ФормаPL`** |
| `втЕРП_Доходы_Детали` | 265-323 | факт дохода (ВиР+ПрочиеДоходы) | весь → Ф1 |
| `втЕРП_CoGS_Детали` | 329-363 | себестоимость продаж | весь → Ф1 |

| `втPL_Строки` (UNION) | 404-424 | строки плана, ЕРП=0 | `СуммаЕРПФ1=0, СуммаЕРПФ2=0`, `РазницаФ1=СуммаФ1, РазницаФ2=СуммаФ2` |

каждой ветки** (выравнивание UNION): `СуммаЕРПФ1, СуммаЕРПФ2, РазницаФ1, РазницаФ2` (порядок одинаков во всех 7 ВТ,

## 5. Инварианты (что нельзя сломать)
1. `СуммаЕРПФ1 + СуммаЕРПФ2 = СуммаЕРП` построчно и в итогах; **Σ `СуммаЕРП` не меняется**.
2. `РазницаФ1 + РазницаФ2 = Разница` (следствие п.1 и план `СуммаФ1+СуммаФ2=СуммаPL`); Σ `Разница` не меняется.
3. Факт расхода = `СУММА(Р.Сумма)` по `ВидДвижения=Приход` (НЕ оборот) — §2.1/§3 architecture_invariants. НЕ трогать.
4. Привязка факта к PL через ДДС (`втPL_ДДС`) — не трогать. Число строк ТЗ не растёт (форма — внутри агрегата, не в GROUP BY).
5. Доход/CoGS целиком Ф1 (Ф2=0). Пустая `ФормаPL` расхода → Ф1 (дефолт согласован с Этапами 1-2).
