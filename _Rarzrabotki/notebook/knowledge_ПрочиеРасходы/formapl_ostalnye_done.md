## 2. ⚠️ КРИТИЧНЫЕ архитектурные находки (читать ПЕРВЫМ при доработках)

### 2.1 Движения `ПрочиеРасходы` распределения пишет ТОЛЬКО закрытие месяца, НЕ проведение документа
- **Кнопка «Провести» на `РаспределениеПрочихЗатрат` НЕ пишет `ПрочиеРасходы`.** Обработчик документа
  `РаспределениеПрочихЗатратЛокализация.ОбработкаПроведения` — **ПУСТОЙ**; `ДанныеДокументаДляПроведения`
  (ManagerModule ~1478) пишет только служебный `РеестрДокументов` + регл.учёт.
- **Движения пишет регламентная операция закрытия месяца** «Распределение расходов по направлениям деятельности»:
  `Выполнить_РаспределениеРасходовПоНаправлениямДеятельности` (ManagerModule ~3332) → вызывает
  `РаспределитьРасходыНаФинансовыйРезультат(Период, Организации)` (2 аргумента → **режим записи**).
- `РаспределитьРасходыНаФинансовыйРезультат(.., ДокументРаспределения=ref)` — **предварительный/отчётный** режим
  (для отчёта `БазаРаспределенияПроизводственныхРасходов`), возвращается БЕЗ записи (ManagerModule ~1116-1121).
- **Вывод:** чинить форму движений распределения надо в `РаспределитьРасходыНаФинансовыйРезультат`; тестировать —
  гонять операцию закрытия (или предв.режим через COM), а НЕ перепроводить документ.

### 2.2 Нетто-логика: двойной счёт текущего документа в предв.режиме (дефект, который обнажила форма)
Сумму к распределению реконструируют add-back движений. Текущий документ прибавляют ОБА:
`branch2` (общий add-back, ManagerModule ~257) И `branch3` (`&ДокументРаспределения`, ~272). В оригинале это
замаскировано проверкой `КОГДА Остатки.Сумма = 0 ТОГДА 0`. Добавление измерения `ФормаPL` **разворачивает**
нулевой остаток в ненулевые строки по формам (Ф1 +X, Ф2 +Y, (пусто) −(X+Y)) → `branch2` срабатывает → удвоение
(ОстаткиРасходов 1 374 953,46 → 2 749 906,92). **Фикс E15** в WHERE branch2:
```
И НЕ(&ПредварительныйРасчет И ТекущиеДвижения.Регистратор = &ДокументРаспределения)
```
В закрытии месяца `&ПредварительныйРасчет=Ложь` → условие неактивно → поведение не меняется; в предв.режиме
текущий документ исключается из branch2 (его даёт branch3) → удвоения нет. После E15 **предв.режим = зеркало
закрытия месяца** → можно проверять без записи.

### 2.3 Динамическое обновление НЕ доходит до активных сеансов
`/db-update -Dynamic+` обновляет конфигурацию на сервере, но **открытые клиентские сеансы 1С продолжают на старом
коде** до перезахода (грабля `feedback_designer_cache_invalidation`). Свежее COM-соединение видит правку, сеанс
пользователя — нет. **Симптом:** запустили закрытие — форма не проставилась, хотя код загружен. **Лечение:**
полностью перезапустить 1С + перевыполнить операцию (отменить выполнение → выполнить, иначе пропускает пересчёт).

### 2.4 Большинство движений `ПрочиеРасходы` пишется на закрытии месяца (расчёт себестоимости)
`ВнутреннееПотреблениеТоваров`, `СписаниеНедостачТоваров`, `АмортизацияОС` и т.п. пишут `ПрочиеРасходы` НЕ на
проведении документа, а на закрытии (cost-calc). Перепроведение такого документа кнопкой убирает его `ПрочиеРасходы`
(вернётся на ближайшем закрытии — это нормальное пред-закрытийное состояние). На регулярном проведении `ПрочиеРасходы`
пишут: ОЗФУ, РКО (форму ставят сами), `ПрочиеДоходыРасходы`, и др. **Часть B стоит ДО раннего `Возврат`** в
`ПередЗаписью`, поэтому ловит и cost-calc-движения.

## 3. Часть A — точки правки (15 шт., применены скриптом)

Скрипт: `Python/test/_apply_formapl_raspredelenie_edits.py` (атомарно, count==1 на якорь, скоуп — процедура
`РаспределитьРасходыНаФинансовыйРезультат` стр. 12-1337). Бэкап: `_raspredelenie_ManagerModule.bak_formapl`.

`ФормаPL` (измерение, доступно в `.Остатки`) протянута «спутником» по цепочке:
`ПредварительныеОстаткиРасходов` → `ОстаткиРасходов` (3 ветки UNION + JOIN по форме + GROUP BY) →
`РасходыКРаспределению` → `РаспределенныеРасходы` → `РезультатРаспределения` (3 ветки UNION + GROUP BY).
Движения пишутся циклом `ЗаполнитьЗначенияСвойств(НоваяЗапись, ВыборкаДетальная)` (~1161) → форму подхватывают сами.
+ E15 (нетто-фикс, §2.2).

**Грабли применения (учтены в скрипте):**
- Якоря `Расходы.X` совпадают с суффиксом `РаспределенныеРасходы.X` → левый lookbehind `(?<![А-Яа-яёЁ])`.
- Алиас `ВложенныйЗапрос` есть и у `ПогрешностиОкругления`, и у `РезультатРаспределения` → различать по соседям.
- Колонка НЕ последняя в SELECT → переносить запятую за новую колонку (иначе синтаксис `ВЫБОР`/след.поле ломается).
- В Python-replacement `\2` в НЕ-raw строке = `\x02` (управляющий) → закрывающую `";` писать литералом.
- Файл UTF-8 с BOM — сохранять кодировку.

## 4. Часть B — дефолт в `RecordSetModule.ПередЗаписью`

В начало `Процедура ПередЗаписью(Отказ, Замещение)` (ПЕРЕД `Если ОбменДанными.Загрузка … Возврат`):
```bsl
// А_ФормаPL: дефолт формы учёта. Движения без явной ФормаPL считаем официальной затратой → Форма1.
// РаспределениеПрочихЗатрат НЕ трогаем — оно наследует форму источника (в т.ч. законно пустую).
Для Каждого Запись Из ЭтотОбъект Цикл
	Если НЕ ЗначениеЗаполнено(Запись.ФормаPL)
		И НЕ (ТипЗнч(Запись.Регистратор) = Тип("ДокументСсылка.РаспределениеПрочихЗатрат")) Тогда
		Запись.ФормаPL = Перечисления.А_ФормыPL.Форма1;
	КонецЕсли;
КонецЦикла;
```
- Перед `Возврат` — чтобы ловить ВСЕ пути (вкл. cost-calc, §2.4).
- Исключение `РаспределениеПрочихЗатрат` по типу — чтобы дефолт не затёр зеркало Части A (в т.ч. законно пустое).
- ОЗФУ/РКО пропускаются автоматически (`ЗначениеЗаполнено` = Истина).

**Источники-состояние:** распределение зеркалит форму источника. Где источник ещё не размечен (март ОЗФУ не
перепроведён, банковские из СБДС) — `Расход` выходит пусто, и Часть B делает его Форма1 синхронно с источником
(когда тот тоже перепроведут). Это транзиторно: порядок перепроведения — сперва источники, в конце распределение.
