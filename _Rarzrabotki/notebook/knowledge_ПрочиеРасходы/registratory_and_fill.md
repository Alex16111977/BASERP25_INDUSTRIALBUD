## 1. Регистраторы (129 типовых документов)

`ПрочиеРасходы` — типовой регистр себестоимости/учёта расходов; в него пишет **129 типовых документов**
(подтверждено grep'ом `AccumulationRegister.ПрочиеРасходы<` по `Documents/*.xml`, 2026-06-08).

**PL-релевантные регистраторы** (те, что реально формируют операционные расходы ІНДАСТРІАЛБУД и видны в P&L —
по CASE в `А_ФинРез_PL` и `Отчет.А_ОтчетPL`):

| Документ | Роль в P&L | Аналитика (Контрагент/ФЛ) |
|---|---|---|
| `ОтражениеЗарплатыВФинансовомУчете` (ОЗП/ОЗФУ) | ФОТ, ЕСВ — основная статья расходов | `А_ФизическоеЛицо` (✅ заполняется) |
| `ПриобретениеТоваровУслуг` | услуги/материалы сторонних | Контрагент |
| `АктВыполненныхРабот` | работы подрядчиков | Контрагент |
| `РасходныйКассовыйОрдер` | расходы наличными | Контрагент |
| `СписаниеБезналичныхДенежныхСредств` | расходы безналом | Контрагент |
| `АвансовыйОтчет` | подотчётные расходы | `ПодотчетноеЛицо` (ФЛ) |
| `ВозвратТоваровПоставщику` / `ВозвратТоваровОтКлиента` | корректировки | Контрагент |
| `ПриходныйКассовыйОрдер` / `ПоступлениеБезналичныхДенежныхСредств` | возвраты/курсовые | Контрагент |
| `РеализацияТоваровУслуг` (ветка CoGS), `КорректировкаРеализации` | себестоимость продаж | Контрагент |
| **`РаспределениеПрочихЗатрат`** | закрытие месяца — перераспределение (донор/получатель) | — (см. инвариант [§4 architecture_invariants](architecture_invariants.md)) |
| `РасчетКурсовыхРазниц` | курсовые разницы | — |

**Прочие 120+ регистраторов** — производство, ОС/НМА (амортизация, переоценка, модернизация, списание),
складские операции, налоговые документы (НалоговаяНакладная, РегистрацияВходящегоНалоговогоДокумента),
ввод остатков и т.д. Полный список — grep выше или Конфигуратор (вкладка «Регистраторы» регистра).

> ⚠️ `РаспределениеПрочихЗатрат` — это ещё и тип реквизита `ДокументДвижения` (указатель на распределитель),
> и источник пар Приход/Расход. См. [architecture_invariants.md §4](architecture_invariants.md).

## 2. Два способа наполнения движений

| Способ | Кто использует | Можно ли протащить доп. поле |
|---|---|---|
| **Через конструктор регистра** `РегистрыНакопления.ПрочиеРасходы.ТекстЗапросаТаблица*(ДополнительныеПоля)` | документы, у которых наполнение идёт через этот общий конструктор (напр. **ОЗФУ**) | ✅ да, через `ДополнительныеПоля` |
| **Собственный запрос движений** в ManagerModule документа | большинство типовых (Приобретение, РКО, Акт и т.д.) | только правкой запроса самого документа (по согласованию) |

**Для `А_ФизическоеЛицо` и `ФормаPL`** интересен первый способ (он использован в ОЗФУ) — см. §3.
Механизм `ДополнительныеПоля` описан в [register_structure.md §5](register_structure.md).

## 3. ✅ Прецедент: `А_ФизическоеЛицо` в ОЗФУ (эталон для `ФормаPL`)

**Документ:** `Documents/ОтражениеЗарплатыВФинансовомУчете/Ext/ManagerModule.bsl`.
**Что сделано:** добавлен кастомный реквизит регистра `А_ФизическоеЛицо` (ФЛ-получатель ЗП) в движения
`ПрочиеРасходы`, чтобы в отчёте PL был drill-down «кому начислена зарплата».

### 3.1 Цепочка из 3 функций ОЗФУ

```
ТекстЗапросаТаблицаВтИсходныеПрочиеРасходы(Запрос, ТекстыЗапроса)   // строка ~2991
   └─ строит ВТ-источник с полем  ВТРасходыПоСтатьям.ФизическоеЛицо КАК А_ФизическоеЛицо
ТекстЗапросаТаблицаВтПрочиеРасходы(Запрос, ТекстыЗапроса)            // строка ~3104
   └─ вызывает  РегистрыНакопления.ПрочиеРасходы.ТекстЗапросаТаблицаВтПрочиеРасходы("А_ФизическоеЛицо")
ТекстЗапросаТаблицаПрочиеРасходы(Запрос, ТекстыЗапроса, Регистры)    // строка ~3118
   └─ вызывает  РегистрыНакопления.ПрочиеРасходы.ТекстЗапросаТаблицаПрочиеРасходы("А_ФизическоеЛицо")
```

### 3.2 Ключевые детали ВТ-источника `ВтИсходныеПрочиеРасходы` (ОЗФУ)

- В основной ветке (из `ВТНачисленнаяЗарплатаИВзносы`):
  ```sql
  ВТРасходыПоСтатьям.ФизическоеЛицо КАК А_ФизическоеЛицо   -- в SELECT
  ...
  СГРУППИРОВАТЬ ПО
      ...,
      ВТРасходыПоСтатьям.ФизическоеЛицо                    -- в GROUP BY (!)
  ```
- В ветке «выработка по прочим работам» (из `ВтТаблицаВыработкаСотрудников`), где ФЛ нет:
  ```sql
  ЗНАЧЕНИЕ(Справочник.ФизическиеЛица.ПустаяСсылка) КАК А_ФизическоеЛицо   -- fallback
  ```
- Имя поля (`А_ФизическоеЛицо`) **совпадает** с именем реквизита регистра — обязательно, т.к. подстановка
  делает буквально `,Строки.А_ФизическоеЛицо`.

### 3.3 Σ-инвариант (как проверяли «не сломал»)

`Σ Сумма` не изменилась от детализации: 156→843 строк движений на 1 ОЗП, `Σ = 7 581 561,27 ₽` неизменна.
Перепроведена история 2024–2026 Q1 (5/5 ОЗП OK, 4067/4067 движений получили `ФизическоеЛицо ≠ Пустая`)
через `_Rarzrabotki/Python/scripts/_reprovesti_ozp.py`. Источник: 
[../knowledge_PL/pl_report_architecture_analyst.md](../knowledge_PL/pl_report_architecture_analyst.md) §«Передумова для роботи Аналитика по ОЗП».

## 4. `ФормаPL` из ОЗФУ — ✅ РЕАЛИЗОВАНО (Этап 1, 2026-06-08)

> 🟢 По этому образцу `ФормаPL` **уже добавлен** для ОЗФУ — полная запись о реализации (точки правки, верификация
> Σ=эталон, безопасность общих ВТ): [formapl_ozfu_done.md](formapl_ozfu_done.md). Ниже — как это было сделано.

По образцу §3, для ОЗФУ (`ФормаPL` размечена в его ТЧ — см.
[../knowledge_А_ОтражениеЗПпоКазне/17_formapl_split.md](../knowledge_А_ОтражениеЗПпоКазне/17_formapl_split.md)):

1. В ВТ-источнике ОЗФУ (`ТекстЗапросаТаблицаВтИсходныеПрочиеРасходы`): добавить `… КАК ФормаPL` в SELECT
   (источник — `ВТНачисленнаяЗарплатаИВзносы.ФормаPL`) + добавить `ФормаPL` в `СГРУППИРОВАТЬ ПО`;
   в ветках без формы — fallback `ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма1) КАК ФормаPL` (или по правилу финансиста).
2. В вызовах конструктора регистра заменить `"А_ФизическоеЛицо"` → `"А_ФизическоеЛицо,ФормаPL"`
   (обе функции: `ТекстЗапросаТаблицаВтПрочиеРасходы` и `ТекстЗапросаТаблицаПрочиеРасходы`).
3. `ФормаPL` автоматически протащится во все 3 ветки финального запроса (3 маркера `//ДополнительныеПоля`).

> ✅ Выполнено по Rule #-1: полная цепочка проверена на BaseERP (ОЗФУ №000Ц-000005) — Σ=4 750 096,77=эталон,
> Ф1=4 008 996,77 / Ф2=741 100,00, ЕСВ→Ф1. Подтверждено, что 7 других потребителей общих ВТ схлопывают разрез
> (не задеты). Детали: [formapl_ozfu_done.md](formapl_ozfu_done.md). Скрипты: `verify_formapl_prochie_chain.py`,
> `discovery_formapl_prochie_rashody.py`.
>
> **Для НОВОГО регистратора** (если расширять scope): тот же приём + Python COM тест (Rule #-1) ПЕРЕД BSL.
> См. [formapl_roadmap.md](formapl_roadmap.md) Этап 3 и [tests_and_etalons.md](tests_and_etalons.md).
