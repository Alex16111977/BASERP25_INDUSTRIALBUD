## TL;DR (самое важное за 30 секунд)

1. **`ФормаPL` — это ИЗМЕРЕНИЕ** (не реквизит). Сделано измерением сознательно: измерения доступны в
   `.Обороты()`, а `А_ФинРез_PL` читает регистр именно через `ПрочиеРасходы.Обороты(...)`. Реквизит
   `А_ФизическоеЛицо` в `.Обороты` НЕдоступен (это уже вызвало регресс 2026-05-21).
2. **Расширяем, не переписываем.** Типовой регистр наполняют 129 документов. Новое поле протаскиваем через
   механизм `ДополнительныеПоля` ManagerModule **только** в нужных регистраторах. Прецедент — `А_ФизическоеЛицо`
   в ОЗФУ (`"А_ФизическоеЛицо"` → конструктор регистра, 3 маркера `//ДополнительныеПоля`).
3. **Σ-инвариант** — главный критерий «не сломал»: после добавления `ФормаPL` `Σ Сумма/СуммаУпр/СуммаРегл` по
   (период, организация) == эталон до копейки; меняется только разбивка внутри суммы.
4. **Этап 1 DONE (2026-06-08):** `ФормаPL` заполняется из **ОЗФУ** в движения `ПрочиеРасходы` (Ф1/Ф2),
   проверено (Σ=эталон). «Низ» (`А_ОтчетPL_Свод.ФормаPL` + `СуммаФ1/СуммаФ2`) тоже готов. Недостающее звено —
   **Этап 2** (отложен): `А_ФинРез_PL` пока НЕ читает `ФормаPL` и не разносит факт в `СуммаФ1/СуммаФ2`.
5. **Для P&L берём `СуммаПриход`**, не оборот (записи Расход = внутреннее перераспределение
   `РаспределениеПрочихЗатрат`).
6. **Перепроведение:** код + smoke на 1–2 доках; историю перепроводит пользователь в UI. ОЗФУ — только через UI
   (COM подвоит ТЧ).
