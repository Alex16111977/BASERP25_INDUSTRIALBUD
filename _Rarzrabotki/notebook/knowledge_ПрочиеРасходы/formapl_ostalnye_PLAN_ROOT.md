## 1. Корневой диагноз (трассировка)

`РаспределитьРасходыНаФинансовыйРезультат` реконструирует «сумму к распределению» из остатков + add-back движений.
Ветку **текущего документа** прибавляют ОБА источника:
- `branch2` — общий add-back всех движений распределения (стр. ~257, фильтр по типу регистратора);
- `branch3` — `&ДокументРаспределения` (движения именно этого документа, стр. ~272).

В оригинале двойной счёт **замаскирован** проверкой `КОГДА Остатки.Сумма = 0 ТОГДА 0` (свёрнутый нулевой остаток).
Добавление измерения `ФормаPL` **разворачивает** нулевой остаток в ненулевые строки по формам → `branch2` срабатывает →
двойной счёт обнажается. Это **латентный дефект нетто-логики**, а не следствие формы.

**Ключевой факт:** в режиме **закрытия месяца** (`&ДокументРаспределения = Неопределено`) `branch3` ПУСТ, и форма
протягивается корректно сама собой — `(пусто)` старого Расхода нетит add-back → 0 → пишутся чистые Ф1/Ф2. Двойной
счёт есть **только в предварительном/отчётном режиме**. Я ошибочно забраковал v1 по предварительному режиму.

## 2. Корневая правка (2 части, ОБЕ в `РаспределитьРасходыНаФинансовыйРезультат`)

### Часть 1 — `ФормаPL` интринсик распределению (14 правок, выверены)
Протянуть измерение `ФормаPL` по всей цепочке ВТ распределения (ПредварительныеОстаткиРасходов → ОстаткиРасходов
[3 ветки UNION + JOIN по форме + GROUP BY] → РасходыКРаспределению → РаспределенныеРасходы → РезультатРаспределения
[3 ветки UNION + GROUP BY]). Движения пишутся `ЗаполнитьЗначенияСвойств` — форму подхватывают сами.

### Часть 2 — устранить дефект нетто-логики (1 правка, E15)
В `branch2` (WHERE ~стр. 260) добавлено:
```
И НЕ(&ПредварительныйРасчет И ТекущиеДвижения.Регистратор = &ДокументРаспределения)
```
- **Закрытие месяца** (`&ПредварительныйРасчет = Ложь`): условие = Истина всегда → поведение НЕ меняется (add-back полный, нетит `(пусто)`).
- **Предварительный режим** (`= Истина`): текущий документ исключается из `branch2` (его и так даёт `branch3`) → двойного счёта нет.

Результат: **оба режима корректны**, и предварительный режим становится **точным зеркалом** закрытия месяца.

## 3. Почему это НЕ заплатка
- Форма — настоящее измерение распределения (Часть 1), а не пост-разбивка результата.
- Часть 2 чинит **реальный двойной счёт** в нетто-логике (он был и в оригинале, просто замаскирован). Это корректнее оригинала.
- Математика распределения (коэффициенты/база/округление) НЕ тронута.
