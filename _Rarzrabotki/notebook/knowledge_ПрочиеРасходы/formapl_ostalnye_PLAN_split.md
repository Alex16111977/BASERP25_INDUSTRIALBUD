# PLAN v2 (НА РЕВЬЮ) — разрез ФормаPL в РаспределениеПрочихЗатрат через РАЗБИВКУ Расхода по составу источника

> Замена провалившегося подхода «протянуть ФормаPL через остатки» (он удваивал — см. ниже).
> Статус: **ЧЕРНОВИК НА РЕВЬЮ**, код НЕ писать до подтверждения. Откат к оригиналу выполнен, база чистая.

---

## 1. Почему первый подход (v1) сломался — зафиксировано эмпирически

`РаспределитьРасходыНаФинансовыйРезультат` читает `ПрочиеРасходы.Остатки(...)`. Виртуальная таблица остатков
возвращает **только НЕнулевые** строки. Полностью распределённая статья (нетто-остаток = 0) → **нет строки**;
сумма реконструируется нетто-логикой (`КОГДА Остатки.Сумма = 0 ТОГДА 0`).

Добавление `ФормаPL` в чтение остатков **разворачивает нулевой остаток** в ненулевые строки по формам
(Ф1 +342 280,10 / Ф2 +1 032 673,36 / (пусто) −1 374 953,46). Нетто-логика начинает дважды считать → **удвоение**
(ОстаткиРасходов 1 374 953,46 → 2 749 906,92). Подтверждено baseline-замером.

**Вывод:** математику распределения (остатки/нетто/коэффициенты) трогать НЕЛЬЗЯ.

## 2. Идея v2 — разбивка результата по составу формы ИСТОЧНИКА

Распределение пишет `Расход`, закрывающий статью. Состав формы этого `Расхода` = состав формы **Приходов**
этой же (Орг, Подр, Статья, Аналитика). Берём долю Ф1/Ф2 из Приходов и **дробим каждое движение `Расход`** на
Ф1+Ф2. Математику распределения НЕ трогаем — разбивка идёт **отдельным слоем запроса ПОСЛЕ `РезультатРаспределения`**.

**Где:** новый ВТ-слой `РезультатСФормой` поверх `РезультатРаспределения` (стр. ~983-1105). Перенацелить
`ИТОГИ ПО Регистратор` (1111) и `СтрЗаменить(... "ПОМЕСТИТЬ РезультатРаспределения" ...)` (1114) на `РезультатСФормой`.

**Главный плюс — ТЕСТируемость:** `РезультатСФормой` остаётся `ПОМЕСТИТЬ` в предварительном режиме →
читается из МВТ через COM (как probe) → проверяю Ф1=342 280,10 / Ф2=1 032 673,36 на 279 **ДО загрузки и БЕЗ записи**.
v1-удвоения нет (нетто не тронут).

## 3. Состав запроса (2 новых ВТ)

### 3.1 `СоставФормыИсточника` (доля Ф1/Ф2 Приходов по комбинации)
```
ВЫБРАТЬ
    И.Организация, И.Подразделение, И.СтатьяРасходов, И.АналитикаРасходов,
    СУММА(ВЫБОР КОГДА И.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма1) ТОГДА И.Сумма ИНАЧЕ 0 КОНЕЦ) КАК СуммаФ1,
    СУММА(И.Сумма) КАК СуммаВсего
ПОМЕСТИТЬ СоставФормыИсточника
ИЗ РегистрНакопления.ПрочиеРасходы КАК И
ГДЕ И.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
    И И.Период МЕЖДУ &НачалоПериода И &КонецПериода
    И НЕ И.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.ПустаяСсылка)   -- только формленные источники
ГРУППА ПО И.Организация, И.Подразделение, И.СтатьяРасходов, И.АналитикаРасходов
ИНДЕКСИРОВАТЬ ПО Организация, Подразделение, СтатьяРасходов, АналитикаРасходов
```
`ДоляФ1 = СуммаФ1 / СуммаВсего`. Если для комбинации нет формленного источника (СуммаВсего отсутствует) → форма
не определяется → `Расход` остаётся **пусто** → Часть B сделает его Форма1 (для статей без ЗП-источника, напр. банковские).

### 3.2 `РезультатСФормой` (3 ветки UNION: Ф1 / Ф2 / пусто)
LEFT JOIN `РезультатРаспределения` к `СоставФормыИсточника` по (Орг, Подр, Статья, Аналитика):
- **Ветка Ф1** (где СуммаВсего > 0): все ресурсы × `ДоляФ1`, `ФормаPL = Форма1`.
  `Сумма_Ф1 = ВЫРАЗИТЬ(Р.Сумма * СоставФормыИсточника.СуммаФ1 / СоставФормыИсточника.СуммаВсего КАК ЧИСЛО(31,2))` (и так каждый ресурс).
- **Ветка Ф2** (где СуммаВсего > 0): `Ресурс_Ф2 = Р.Ресурс − Ресурс_Ф1` (ОСТАТОК — гарантирует Σ ресурса без потери копейки), `ФормаPL = Форма2`.
- **Ветка пусто** (где СоставФормыИсточника НЕ найден / СуммаВсего = 0): ресурсы как есть, `ФормаPL = ПустаяСсылка`.

Ресурсы под разбивку: `Сумма, СуммаБезНДС, СуммаУпр, СуммаУпрБезНДС, СуммаРегл, СуммаРеглБезНДС, НДСРегл,
ПостояннаяРазница, ВременнаяРазница, Расходы, РасходыРеглБезНДС, РасходыУпрБезНДС`. Прочие поля (Период, Регистратор,
Орг, Подр, Направление, НаправлениеДеятельностиПриемник, Статья, Аналитика, НалНазн, +НЕ УТ поля) — переносятся 1:1.

### 3.3 Запись движений (стр. 1138-1223) — БЕЗ правок
`ЗаполнитьЗначенияСвойств(НоваяЗапись, ВыборкаДетальная)` (1161) скопирует `ФормаPL` автоматически (она теперь в
`РезультатСФормой`). Фильтр «все суммы = 0» (1150) отсечёт пустые. Перенос существующих движений (1208) уже идёт
через `ПрочиеРасходы.*` — форму сохраняет.

## 4. Инварианты / почему НЕ удвоит
1. Нетто-математика (ПредварительныеОстаткиРасходов/ОстаткиРасходов/РасходыКРаспределению/РаспределенныеРасходы) —
   **не тронута** → ОстаткиРасходов = 1 374 953,46 (как оригинал). Разбивка идёт ПОСЛЕ.
2. Σ по каждому ресурсу сохраняется: Ф1 + Ф2 = исходный `Расход` (Ф2 = остаток).
3. Σ движений распределения == оригинал (число строк растёт: 1 → 2 на комбинацию со смешанной формой).
4. Баланс по форме закрывается: `Расход Ф1` = `Приход Ф1` источника (для полного распределения — точно).
