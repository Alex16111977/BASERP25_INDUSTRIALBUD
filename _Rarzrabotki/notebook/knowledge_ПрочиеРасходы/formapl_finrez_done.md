## 1. Что сделано

Файл: `Documents/А_ФинРез_PL/Ext/ObjectModule.bsl`, функция `СформироватьЗапросСверткиPL()`.

`А_ФинРез_PL` теперь читает измерение **`ФормаPL`** из `ПрочиеРасходы.Обороты` и пишет его в
`РегистрСведений.А_ОтчетPL_Свод` (измерение `ФормаPL` + ресурсы `СуммаФ1`/`СуммаФ2` там УЖЕ были).
**Эвристика ПКО/РКО заменена на реальную `Р.ФормаPL`.**

| Правка | Где | Суть |
|---|---|---|
| CTE `втЕРП_Расх` | SELECT + GROUP BY | + `Р.ФормаPL КАК ФормаPL` (измерение, доступно в `.Обороты`) |
| Ветка ПЛАН | была 1 строка → стало 2 (UNION) | Форма1: `СуммаФ1_Excel=PL.СуммаФ1, Сумма_Excel=PL.СуммаФ1`; Форма2: `СуммаФ2_Excel=PL.СуммаФ2, Сумма_Excel=PL.СуммаФ2`. **Безопасно: проверено `СуммаФома1+СуммаФорма2=Сумма` для ВСЕХ док-тов `А_ОтчетPL` (Расхождение=0)** → Σ Сумма_Excel не меняется. |
| Ветки ФАКТ-РАСХОД (с PL и без PL) | 2 ветки | эвристика ПКО/РКО → `ВЫБОР КОГДА Р.ФормаPL = Форма2 ТОГДА Ф2 ИНАЧЕ Ф1`. Пусто→Форма1 (дефолт согласован с Частью B). |
| Ветки ФАКТ-CoGS, ФАКТ-ДОХОД (с PL и без PL) | 3 ветки | `ФормаPL = Форма1` константой; доход эвристику ПКО → весь в `СуммаФ1` (доход = Форма1 целиком). |
| Финальный SELECT | SELECT + GROUP BY | + `втРезультат.ФормаPL` (mirror-знак по `ТипСтатьи` НЕ тронут). |

**19-я колонка `ФормаPL` добавлена во ВСЕ 6 веток UNION** (выравнивание) + ветка ПЛАН разбита на 2 (Ф1/Ф2).

## 2. Верификация (Rule #-1 → BSL, потом smoke)

### 2.1 Запросный тест (RED→GREEN), декабрь 2025 + январь/февраль 2026
Скрипт `Python/test/test_finrez_pl_formapl_query.py`: извлекает ОРИГИНАЛЬНЫЙ запрос из живого BSL (эталон ДО),
прогоняет МОДИФИЦИРОВАННЫЙ, сверяет инварианты. На **идентичном снимке данных** (один момент):

| | Σ Сумма (факт) | Σ Сумма_Excel | Σ СуммаФ1_Excel | Σ СуммаФ2_Excel |
|---|---|---|---|---|
| BASE (эталон) | 6 335 599,46 | −9 886 111,81 | 465 005,53 | −10 351 117,34 |
| MOD (ФормаPL) | 6 335 599,46 | −9 886 111,81 | 465 005,53 | −10 351 117,34 |
| **Δ** | **0,00** | **0,00** | **0,00** | **0,00** |

Разбивка Ф1/Ф2 факта сдвинулась на ±3 418 533,72 (эвристика → реальная форма) — это цель. Построчно
`Ф1+Ф2=Сумма` и `Ф1_Excel+Ф2_Excel=Сумма_Excel`. Кросс-проверка: MOD `Σ СуммаФ2` факта **точно** = обороту
`ПрочиеРасходы` по `Форма2` (декабрь 11 061 210,00; янв 12 106 540,95; фев 8 527 369,83 — до копейки).

### 2.2 Генерация BSL из проверенного запроса
Скрипт собирает BSL-текст функции из проверенного `MOD_Q` (escape `"`→`""`, `|`-префиксы) и пишет полный
модуль; round-trip `from_bsl_func(generated)==MOD_Q` гарантирует, что в BSL ушёл ровно проверенный текст
(`_ObjectModule_new.bsl`). Скопировано в worktree + основную конфигурацию, загружено, обновлено динамически.

### 2.3 Smoke (структурный) — `smoke2_finrez_pl_formapl_struct.py`
Перепроведён боевой №00000000001 (декабрь 2025) через COM. В регистре: ФормаPL = {Форма1, Форма2},
**пустых строк нет**, построчно `Ф1+Ф2=Сумма` и `Ф1_Excel+Ф2_Excel=Сумма_Excel`, `Σ(Ф1+Ф2)=Σ Сумма`.

## 3. ⚠️ Грабли / находки

### 3.1 Живая база дрейфует — Σ нельзя сверять «до vs после перепроведения»
Декабрь 2025 в момент работы **активно перезакрывался** (РаспределениеПрочихЗатрат / закрытие месяца):
`ПрочиеРасходы` по `Форма2` колебался между ~11,06 млн (устоявшееся) и ~17,13 млн (транзит во время закрытия),
число строк свёртки 4515⇄4841. Поэтому **первый smoke с моделью «снимок ДО (старый код) vs ПОСЛЕ (новый код)»
дал ложный FAIL** (Δ Σ ≈ 26 тыс.) — сравнивал устаревший снимок с текущим.
**Правильно:** Σ-инвариант проверять `BASE_Q` vs `MOD_Q` в ОДИН момент (Δ=0,00, см. `verify_finrez_pl_formapl_drift.py`),
а в регистре — только **структурные** инварианты (Ф1+Ф2=Сумма, нет пустой ФормаPL), которые верны для любого снимка.

### 3.2 План разносится на 2 строки безопасно
`Документ.А_ОтчетPL.ДанныеОтчета`: `СуммаФома1 + СуммаФорма2 = Сумма` выполняется для ВСЕХ документов
(проверено: Расхождение=0). Поэтому разбивка плана на Форма1/Форма2 не меняет Σ Сумма_Excel
(вопрос §4.4 промта о согласовании с финансистом — снят данными).

### 3.3 ФормаPL — измерение, читается из `.Обороты` без перехода на прямую таблицу
Подтверждает [architecture_invariants.md §2](architecture_invariants.md): `СУММА(Р.СуммаПриход)` сохранён,
регресс «оборот вместо прихода» (2026-05-21) не повторён.

### 3.4 MCP execute_query НЕ биндит дату в виртуальную таблицу
`ПрочиеРасходы.Обороты(&Нач,…)` через MCP падает «Несоответствие типов (Параметр 1)» — только Python COM
(Rule #-1). Прямые таблицы/`Документ.…ДанныеОтчета` через MCP работают.
