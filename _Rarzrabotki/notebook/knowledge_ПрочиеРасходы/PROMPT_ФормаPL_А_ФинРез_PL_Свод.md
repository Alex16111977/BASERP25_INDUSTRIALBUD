## 1. Цель и контекст

`ПрочиеРасходы` теперь несёт измерение **`ФормаPL`** (Этап 1 ОЗФУ + Этап «остальные» — DONE). Документ `А_ФинРез_PL`
сворачивает факт расходов/доходов из `ПрочиеРасходы.Обороты`/`ПрочиеДоходы.Обороты` + план (Excel) в
`А_ОтчетPL_Свод`. **Задача:** при свёртке читать `ФормаPL` факта и:
1. писать измерение **`ФормаPL`** в Свод;
2. факт расхода класть в ресурс **`СуммаФ1`** (если `ФормаPL = Форма1`) или **`СуммаФ2`** (если `Форма2`);
3. **доходы — все как `Форма1`** (`ФормаPL = Форма1`, `СуммаФ1` = вся сумма дохода, `СуммаФ2 = 0`);
4. **план (PL_Excel) тоже разносить по измерению `ФормаPL`** (см. §4.4).

> ⚠️ **Сейчас факт уже дробится на `СуммаФ1`/`СуммаФ2`, но ПО ЭВРИСТИКЕ** (ПКО/РКО → `СуммаФ2`, всё остальное →
> `СуммаФ1`, см. ObjectModule стр. ~397-408 и 467-476). **Эту эвристику заменить на реальную `Р.ФормаPL`.**
> Измерение `ФормаPL` сейчас в свёртку НЕ пишется (Свод его имеет, но факт грузится с пустой формой).

## 4. Точные правки BSL (номера строк сверить на актуальном файле)

### 4.1 `втЕРП_Расх` (SELECT ~180 + GROUP BY ~188-191)
+ `Р.ФормаPL КАК ФормаPL` в SELECT и в `СГРУППИРОВАТЬ ПО`. (`ФормаPL` — измерение, доступно в `.Обороты`.)
Аналогично — если `втЕРП_CoGS`/`втЕРП_Дох` нужно различать форму; для CoGS/дохода форма константная (см. §3), CTE не трогаем.

### 4.2 Ветка ФАКТ-РАСХОД (375-411)
- Добавить колонку `ФормаPL` (на позицию 19): `ВЫБОР КОГДА Р.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма2) ТОГДА ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма2) ИНАЧЕ ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма1) КОНЕЦ`.
- **Заменить эвристику ПКО/РКО** (397-408) на форму:
  - `СуммаФ1` = `ВЫБОР КОГДА Р.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма2) ТОГДА 0 ИНАЧЕ Р.СуммаЕРП КОНЕЦ`,
  - `СуммаФ2` = `ВЫБОР КОГДА Р.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма2) ТОГДА Р.СуммаЕРП ИНАЧЕ 0 КОНЕЦ`,
  - `Сумма` = `Р.СуммаЕРП` (без изменений).

### 4.3 Ветки ФАКТ-CoGS (417-441) и ФАКТ-ДОХОД (447-477)
- + колонка `ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма1)` (константа).
- **Доход:** заменить эвристику ПКО (467-476) → `СуммаФ1 = СУММА(Д.СуммаЕРП)`, `СуммаФ2 = 0` (доход весь Форма1).
- **CoGS:** уже `СуммаФ1=СуммаЕРП, СуммаФ2=0` — оставить, добавить только `ФормаPL=Форма1`.

### 4.4 Ветка ПЛАН (350-372) — РАЗНЕСТИ по `ФормаPL` (две строки)
План сейчас одна строка с `СуммаФ1_Excel`+`СуммаФ2_Excel`. Разнести на 2 строки UNION (или JOIN к 2-строчной
ВТ форм): **Форма1** (`ФормаPL=Форма1`, `СуммаФ1_Excel = PL.СуммаФ1`, `СуммаФ2_Excel=0`, `Сумма_Excel = PL.СуммаФ1`)
и **Форма2** (`ФормаPL=Форма2`, `СуммаФ1_Excel=0`, `СуммаФ2_Excel = PL.СуммаФ2`, `Сумма_Excel = PL.СуммаФ2`).
> ⚠️ **Проверить:** `PL.СуммаPL` (Excel-итого) = `PL.СуммаФ1 + PL.СуммаФ2`? Если нет — `Сумма_Excel` итог изменится
> (станет Ф1+Ф2). Согласовать с финансистом: класть `СуммаPL` на Форма1 целиком, или разнос корректен (Ф1+Ф2=итог).

### 4.5 Финальный SELECT (585-645)
+ `втРезультат.ФормаPL КАК ФормаPL` в SELECT и в `СГРУППИРОВАТЬ ПО` (иначе строки Ф1/Ф2 свернутся). Mirror-знак
по `ТипСтатьи` на `СуммаФ1`/`СуммаФ2` (617-623) **уже есть** — не трогать.

## 5. Инварианты (что нельзя сломать)
1. **Σ факта не меняется:** `СуммаФ1 + СуммаФ2 = Сумма` в каждой строке; Σ `Сумма` по периоду == эталон ДО правки.
   Меняется только разбивка Ф1/Ф2 (была по эвристике ПКО/РКО → стала по реальной `ФормаPL`).
2. **Mirror-знак** по `ТипСтатьи` (Расход → −, Доход → +) — сохранить на всех ресурсах (вкл. `СуммаФ1`/`СуммаФ2`).
3. **Привязка факта к PL-статье** через `СтатьяРасходов.А_СтатьяДвиженияДенежныхСредств ↔ втPL_ДДС` — не трогать.
4. **Дубли ключа Свода:** ключ Свода теперь включает `ФормаPL` → строки Ф1/Ф2 одной (Орг,Подр,Статья,…) НЕ конфликтуют
   (это цель). `Комментарий` — по-прежнему `МАКСИМУМ(…)` (грабля 31.03.2026).
5. **Грабля `.Обороты` vs прямая таблица:** читать `СуммаПриход` из `.Обороты` (НЕ оборот; см. architecture_invariants §3).
   `ФормаPL` — измерение, доступна в `.Обороты` без перехода на прямую таблицу.
