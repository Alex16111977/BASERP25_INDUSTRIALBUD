# 07. Связанные объекты конфигурации и данных

## Документ `А_ОтчетPL` — источник факта закрытых месяцев

Один документ = один лист Excel за один месяц. 908 документов, 2024-01-31 … 2026-06-30,
26–33 документа в месяц на 23–30 подразделений.

**Датируется ПОСЛЕДНИМ днём месяца** (проверено: `ДЕНЬ(Дата)` = 31/28/30 у всех).
Отчёт работает не с датой, а с месяцем документа: `ГОД(Дата) * 100 + МЕСЯЦ(Дата)`.
Какой месяц читается из документа, а какой из регистров ЕРП, задаёт закон источника
(20.08.2026, исключений нет): последний месяц периода — ТОЛЬКО регистры ЕРП, все более
ранние — ТОЛЬКО документы `А_ОтчетPL`, месяц без документа — ноль (файл разбора
10_versiya3 удалён 28.08.2026, история в git).

Реквизиты шапки: `Организация`, `Подразделение`, `ПодразделениеСтрока`,
`НаправлениеДеятельности`, `ВключатьДочерние`, `НеПроводитьВСверку`, `СуммаДокумента`,
`Ответственный`, `Комментарий`.

Табличные части:

| ТЧ | Реквизиты | Использует отчёт |
|---|---|---|
| `ДанныеОтчета` | Статья, Комментарий, **СуммаФома1**, СуммаФорма2, Сумма, ТипСтроки, СтрокаЛиста | да — источник факта закрытых месяцев и накопительного |
| `ИтогиПоГруппам` | Группа, СуммаФ1_Excel, СуммаФ2_Excel, Сумма_Excel, Сумма_Расчёт, Расхождение | нет (ground-truth для сверки водопада) |
| `ИтогиОбщие` | Показатель, ВидПоказателя, СуммаФ1, СуммаФ2, СуммаИтого | нет (ground-truth для сверки водопада) |

> ⚠️ Реквизит `СуммаФома1` — без «р». Опечатка в метаданных, менять нельзя.

### 🔴 Реквизит `ВключатьДочерние` ≠ параметр отчёта `СводыНаправлений`

Это РАЗНЫЕ сущности: оба названия про «дочерние», но живут они на разных уровнях
и отвечают за разное.

| | `ВключатьДочерние` | `СводыНаправлений` |
|---|---|---|
| Что это | **реквизит документа** `А_ОтчетPL` | **параметр отчёта** в СКД, Булево, по умолчанию Ложь |
| Заголовок / где виден | в шапке документа | «Своды направлений (иначе объекты)» |
| Область | одна строка журнала | весь отчёт целиком |
| Что делает | помечает документ как свод-документ направления | выбирает, КАКОЙ набор документов читать |

У донора `А_ОтчетPL` параметр СКД тоже назывался `ВключатьДочерние` — при переносе он
переименован в `СводыНаправлений` именно чтобы развести эти два понятия.

Связь одна: во всех ветках запроса, читающих документ, стоит условие
`Д.ВключатьДочерние = &СводыНаправлений`. `СводыНаправлений = Ложь` — отчёт читает
объектные документы; `Истина` — только свод-документы направлений, и факт ЕРП тогда
сворачивается на подразделение свода (`втСводныеПодразделения` → `втКартаУровней`).
Смешивать наборы нельзя — это задвоение.

`ВключатьДочерние = Истина` — свод-документ (лежит на родителе: Строительство, Производство,
Логистика, PL_Свод, PL_ЦО). 4–5 таких в месяц.

> ⚠️ **Флаг `ВключатьДочерние` — это СЛОЙ документов, а не «покрытие месяца».**
> Он делит документы на объектные (`Ложь`) и своды направлений (`Истина`) и сопоставляется
> с параметром `&СводыНаправлений`. С 20.08.2026 «покрытие месяца документом» не считается
> ВООБЩЕ: регистры берутся только за последний месяц периода, всё раньше — только документы.
> Исторический разбор задвоения июня-2026 (136 356,27 вместо 70 381,03), из-за которого
> когда-то вводили ветвевой ключ, — файл разбора удалён 28.08.2026, история в git.

`НеПроводитьВСверку = Истина` — 12 документов (12.2025–03.2026), ВСЕ свод-документы по
направлениям. Означает «не сверять с ЕРП», не «черновик». Из накопительного не исключаются.

Наполнение документов — Python-пайплайн `_Rarzrabotki/Python/PnL/scripts/` (шаги 01–17):
чтение Excel, сопоставление статей, загрузка групп/статей/документов, заполнение `Сорт`.
См. [`knowledge_PL`](../knowledge_PL/KNOWLEDGE_MAP_PL.md).

## Справочники PL

`А_Статьи_PL` — статьи PL. Реквизиты: `Код`, `Наименование`, `Группа`, `Сорт`,
`НаименованиеДляОтчетаНаРусском` (для параметра «Названия на русском», 21.08.2026;
заполнен у всех элементов `А_Статьи_PL` и `А_ГруппаСтатей_PL`).
ТЧ **`Статьи`** содержит список `СтатьяДвиженияДенежныхСредств` — это МОСТ ДДС→PL,
через который к статьям PL привязываются и ЕРП-факт, и бюджет объекта.

Уникальность «одна ДДС — только у одной PL-статьи» гарантирует модуль объекта
(`А_Статьи_PL.ПередЗаписью`). Поэтому соединение по ДДС не двоит.

Ключевые коды статей:

| Код | Статья | Роль |

| 000000001 | Выручка от продаж (товаров, работ, услуг) | услуги/работы |
| 000000002 | Доход от прочей операционной деятельности | товарная выручка |
| 000000055 | Финансовый доход | водопад |
| 000000056 | Финансовые расходы | водопад |
| 000000057 | Затраты на налог на прибыль | дочерняя строка показателя 130 |
| 000000058 | Дивиденды | из отчёта удалена БЕЗУСЛОВНО (21.08.2026): `УдалитьСтрокиДивидендов` + фильтр `&КодДивидендов`; исключена и из базы «% затрат» |

## Регистры ЕРП — источник факта

| Регистр | Что даёт | Ветка |
|---|---|---|
| `РегистрНакопления.ПрочиеРасходы` | ВСЕ расходы, включая ЗП, амортизацию, аренду, материалы | `втЕРП_Расх_Детали` |
| `РегистрНакопления.ВыручкаИСебестоимостьПродаж` | Выручка (`СуммаВыручки`) и себестоимость (`Стоимость`) | `втЕРП_Доходы_Детали`, `втЕРП_CoGS_Детали` |
| `РегистрНакопления.ПрочиеДоходы` | Прочие доходы: курсовые, финансовая деятельность | `втЕРП_Доходы_Детали` |

**Расходы:** `СуммаЕРП = СУММА(Сумма)` ТОЛЬКО по `ВидДвижения = Приход`. Расход НЕ вычитается —
иначе у подразделений с `РаспределениеПрочихЗатрат` (например Астарта) оборот обнуляется
и суммы исчезают из PL. Разметка Ф1/Ф2 — по реквизиту `ФормаPL`.

**Выручка:** расщепляется по измерению `ТипЗапасов`. Услуга и АгентскаяУслуга →
`СтатьиДоходов.ВыручкаОтПродаж` → PL 000000001; товарные типы → `&СтатьяДоходовТовар` →
PL 000000002. Параметр даёт функция `ПолучитьСтатьюДоходовТовара` (ищет `СтатьяДоходов`,
чья `А_СтатьяДвиженияДенежныхСредств` входит в ТЧ Статьи PL-статьи 000000002; приоритет
у наименования «Прочие доходи»). Если такой нет — вся выручка остаётся на 000000001.

**CoGS:** себестоимость вешается на одну спец-ДДС с флагом
`СтатьиДвиженияДенежныхСредств.А_ПриёмникСебестоимостиПродажPL`. Функция
`ПолучитьДДСПриёмникCoGS`; при пустой ссылке ветка даёт 0 строк. На 18.08.2026 флаг стоит
на ДДС «Себестоимость реализации».

Расшифровка измерения «Аналитика»: длинные цепочки `ВЫБОР КОГДА Регистратор ССЫЛКА Документ.X
ТОГДА ВЫРАЗИТЬ(…).Контрагент` перенесены из донора, но с 27–28.08.2026 РАСШИРЕНЫ (v9–v11):
РКО с операцией «Прочая выдача ДС» и непустым комментарием → комментарий;
СписаниеНедостачТоваров / ВнутреннееПотреблениеТоваров / ПрочиеДоходыРасходы →
`ВЫРАЗИТЬ(Комментарий, Строка(200))` (пустой комментарий = пусто); АмортизацияОС →
карточка ОС (`Р.АналитикаРасходов` = `Справочник.ОбъектыЭксплуатации`, строка статьи
дробится на карточки). CASE продублирован в ОБЕИХ копиях (ВЫБРАТЬ и ГРУППИРОВАТЬ ПО)
`втЕРП_Расх_Детали`.

## Бюджеты: план объекта и фиксы

`Документ.А_БюджетМесяц` → `РегистрНакопления.А_БюджетыНаМесяц` (это единственный регистр
движений документа). В интерфейсе документ называется «Бюджет(за период)»; он же приходит
в поле `Документ` при расшифровке бюджетных строк — обе бюджетные ветки отдают
`Б.Регистратор`, а не `НЕОПРЕДЕЛЕНО`.

Реквизиты шапки: `Подразделение`, `Месяц`, `ВидПериода`, `ВидВерсии`, `Направление`,
`Лимит`, `ДокументОснование`, `ПоказательБюджета`, `Ответственный`, `Комментарий`.
ТЧ — `Показатели` и `ПоказателиБДДС`; отчёт в табличные части НЕ ходит, суммы берутся
из регистра.

Измерения `А_БюджетыНаМесяц`: `Подразделение`, `СтатьяДвиженияДенежныхСредств`, `Месяц`,
`ВидПериода`, `Направление`, `ВидОплаты`. Ресурс один — `Сумма`.

`ВидПериода` — `Перечисление.А_ВидыПериодовБюджетирования`, ЧЕТЫРЕ значения:
Неделя / Месяц / Объект / **Фиксы**. Отчёт читает два из них:

| `ВидПериода` | Что это для отчёта | Куда попадает |
|---|---|---|
| `Объект` | план объекта — общая сумма бюджета, без разбивки по месяцам | колонка «План итого» (сорт 900100) |
| `Фиксы` | месячная НОРМА постоянных затрат направления | ресурсы `ФиксФ1` / `ФиксФ2` / `ФиксИтого` внутри КАЖДОЙ месячной колонки |

`Фиксы` — 5 документов на 5 корневых направлениях, все от 01.01.2026, но действующие
на КАЖДЫЙ месяц отчёта: по периоду ввода норма не фильтруется, ровно как план объекта.
Берётся норма, ДЕЙСТВУЮЩАЯ на месяц колонки — `МАКСИМУМ(Месяц)` среди записей
с `Месяц <= месяца колонки` (таблица `втФиксСрез`); без среза две заведённые нормы
молча сложились бы и норма удвоилась.

### Измерение `ВидОплаты` = разрез Ф1 / Ф2

`ВидОплаты` имеет тип `Перечисление.ТипыДенежныхСредств` и раскладывается ровно в ту же
пару, что и факт: **Безналичные → Ф1, Наличные → Ф2**, итого = сумма обоих.
Расщеплены ОБЕ бюджетные ветки:

| Ветка | Ф1 (безнал) | Ф2 (нал) |
|---|---:|---:|
| Фиксы | 2 857 872,00 | 1 424 936,00 |
| План объекта | 2 495 798 625,36 | 222 947 355,00 |

Итог фиксов по компании — 4 282 808,00, это эталон приёмки.

Подробно: план объекта — [03_plan_obekta.md](03_plan_obekta.md),
фиксы, отклонение и флажки блоков — [11_fiksy_norma_i_otklonenie.md](11_fiksy_norma_i_otklonenie.md).

## Отчёт-донор `А_ОтчетPL`

`_Rarzrabotki/Отчеты/А_ОтчетPL` (зеркало в конфигурации `Reports/А_ОтчетPL`).
Сравнивает документы PL с данными 1С; 4 варианта настроек, из которых
`А_ОтчетPL_ВидКакВExcel` («PL как в Excel (факт)») стал основой нашего отчёта.

Что взято дословно: четыре CTE ЕРП-факта (`втPL_ДДС`, `втЕРП_Расх_Детали`,
`втЕРП_Доходы_Детали`, `втЕРП_CoGS_Детали`), функции `ПолучитьДДСПриёмникCoGS`,
`ПолучитьСтатьюДоходовТовара`, `РассчитатьВодопадКолонки`, структура вариантa и оформление.

Что изменено: выброшены ветки Казны и плановых Ф1/Ф2 из документов; донорская
`ПолучитьОбъединенныеДанные` стала `ПолучитьДанные`, а её запрос — пакетом из 11 временных
таблиц (действующий текст — `v11_full.sql`); параметр `ВключатьДочерние` переименован в
`СводыНаправлений`; вместо фиксированного набора колонок ось строится в `ТаблицаКолонок`:
месяцы периода (ГГГГММ) → «PL с начала года» (890000) → «Накопительный PL» (900000) →
«План итого» (900100), и `РассчитатьВодопадКолонки` вызывается для КАЖДОЙ колонки оси;
добавлены бюджетные ветки — план объекта и фиксы.

**Правки донора в наш отчёт автоматически не попадают.** Если в `А_ОтчетPL` меняются
ЕРП-ветки (например правила расщепления выручки), изменение надо перенести руками.

## Что НЕ используется (осознанно)

**План по СС для производственных подразделений.** В Excel листы `МК *` / `МД *` несут блок
«План по СС | Факт PnL | Diff» — плановая себестоимость из `А_СтруктураСебестоимости`,
НЕ влитая в казну. Решение пользователя (18.08.2026): источник плана один — бюджет объекта.
Производство получает план там, где бюджет заведён (МД ООН, МД Кернел Кухня, ЕМС малий,
МД ІОМ, МД Первомайск ПА, МД ООН 27/28 — 7 объектов).

Фиксы (`ВидПериода = Фиксы`) этого решения не отменяют: это не второй источник плана,
а месячная норма постоянных затрат направления, и с планом объекта она в одной колонке
не пересекается.

Если понадобится второй источник плана — потребуется отдельный слой маппинга
«работы/материалы СС → статьи PL» и своя приёмка. Ориентир по механике —
отчёты `А_ОтчетПоСписаниюНаПроизводство*` и
[`knowledge_ПланФактныйПроизводствоПолный`](../knowledge_ПланФактныйПроизводствоПолный/KNOWLEDGE_MAP.md).

**Данные из Казны.** Ветки `втКазна_*` донора в наш отчёт не перенесены: отчёт строится
только по данным 1С.
