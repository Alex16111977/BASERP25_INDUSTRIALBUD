# 13. Контур «Ввод остатков PL» и своды книги (31.08.2026)

## Зачем
Закрытые до начала месяца объекты выпадали из накопительных колонок свод-листов
книги (состав сводов строился только из строк РС `А_СтруктураВыгрузкиОтчетаPLвЕксел`
— активных листов). Решение финансиста: зафиксировать «PL с начала года» и
«Накопительный PL» на 30.06.2026 документами остатков и строить накопительные
СТРОГО от них.

## Остатки — ПО-ЛИСТОВО (решение финансиста 31.08.2026)
Документ на каждый лист книги, Комментарий = «Остатки PL на 30.06.2026 — лист «X»»:
- объектный лист → объектный слой его подразделений (сам + дочерние по дереву);
- лист «Только это подразделение» (ЦО-листы) → объектный слой корня;
- свод-лист (ОтчетПоНаправлению) → СВОД-слой корня направления;
- строки без листа (закрытые, Староконстантинов-свод и пр.) → документ
  «ВНЕ ЛИСТОВ (закрытые и прочие)» (386 строк);
- PL_Свод — агрегат, своего документа НЕТ.
Итого 31 документ, 1246 строк, суммарно == прежнему единому набору до копейки.
Раскладчик: `raskladka_ostatkov_po_listam_2026-08-31.py` (идемпотентен по комментарию).

**Контроль в ПередЗаписью:** комбинация Подразделение × СтатьяPL × СводНаправления —
ровно в ОДНОМ проведённом документе (запрос по регистру против ТЧ через
`&ТаблицаКлючей`); пересечение = отказ с именем конфликтующего документа.

## Запрос v12 (отличия от v11)
1. Документная накопительная ветка: `И ГОД(Док.Дата)*100+МЕСЯЦ(Док.Дата) > &МесяцОстатков`.
2. Новая ветка ОБЪЕДИНИТЬ ВСЕ из `РегистрНакопления.А_ОстаткиОтчетаPL` в колонки
   890000/900000: `ГДЕ Ост.СводНаправления = &СводыНаправлений`, суммы через
   `ВЫБОР КОГДА КЛ.КолонкаСорт = 890000 ТОГДА …СНачалаГода ИНАЧЕ …Накопительно КОНЕЦ`,
   Документ = Ост.Регистратор (расшифровка ведёт на документ остатков листа).
3. `&МесяцОстатков` ставит модуль: `МесяцДокументаОстатков()` — ГГГГ*100+ММ даты
   последнего проведённого документа; нет ни одного → ВызватьИсключение.

## Выгрузка книги (ВыгрузкаОтчетаPLвExcel, с 31.08.2026)
- Строится отчётом `А_ОтчетPL_ПолныйЕРП_Остатки` (не действующим!).
- Свод направления и PL_Свод — СЛОЙ СВОДОВ: `УстановитьСводыНаправлений`
  (параметр СводыНаправлений=Истина поверх варианта) + пара отборов: «В списке» =
  корень направления (PL_Свод — корни всех строк-сводов; ЦО отсекает «Не в группе ЦО»
  самого варианта). Состав листов книги на цифры сводов больше НЕ влияет.
- Функции СоставСводаНаправления/СоставОбщегоСвода УДАЛЕНЫ (мёртвый код).
- Объектные и ЦО-листы — механика прежняя (объектный слой, состав/корень).
- .epf пересобран (при занятом BaseERP — через BaseERPRazr).

## Грабли
- Частичная загрузка НОВЫХ объектов: Configuration.xml + корневые XML объектов +
  модули; формы — ТОЛЬКО корневой `Forms/<Форма>.xml` (явный Ext → «Неизвестный
  объект метаданных»). Реструктуризация двух пустых таблиц — минуты (принятие
  изменений всей конфигурации), пользователи в Предприятии не мешают.
- Пакетный сеанс загрузки виден как «Конфигуратор» в списке сеансов — его
  завершение = срыв загрузки («Сеанс работы завершен администратором»).
- `-listFile` у DumpConfigToFiles 8.3.20 ждёт ИМЕНА ОБЪЕКТОВ («Configuration»),
  не имена файлов, и БЕЗ BOM; выгрузка требует ConfigDumpInfo.xml в каталоге.
- Клонирование отчёта: регенерировать UUID ТОЛЬКО в корневых XML метаданных;
  в СКД Template.xml UUID НЕ трогать — `dcsset:right` хранит ссылки-значения
  отборов вариантов (регенерация ломает отборы).
- Алиас `В` в запросе = оператор В (IN) — «Ожидается имя»; у ВариантыОтчетов
  НЕТ ПометкиУдаления; у Организаций НЕТ Кода.
- Дерево ≠ направление: закрытые объекты переносят в группу/направление
  «Закрытые обьекты» или направление пусто — отбор по А_НаправлениеДеятельности
  теряет их; свод-слой (свод-доки корня) закрытых СОДЕРЖИТ.
