# LESSONS — грабли и как их обходить

## 🚨 Инварианты отчёта (не менять — сломается смысл)

### 🔴 Источник факта задаёт ПЕРИОД. Исключений нет

Последний календарный месяц периода — ТОЛЬКО регистры ЕРП, все более ранние — ТОЛЬКО
документы `А_ОтчетPL`, месяц без документа — НОЛЬ. Наличие документа не проверяется,
персональных правил для отдельных статей (амортизация и любые другие) нет и заводить
их нельзя. Правило целиком:
[12_novaya_forma_ebitda_ebit.md](12_novaya_forma_ebitda_ebit.md).

Пункт «месяц без документа по ветке — регистры» действовал 19–20.08.2026 и ОТМЕНЁН
заказчиком: −33 018 762,27 за январь–июнь 2026 приняты сознательно, ради предсказуемости.
Дыры закрываются документами PL, а не кодом отчёта.

Два способа сломать его молча:
* смешать источники ВНУТРИ одного месяца — ровно то задвоение, из-за которого правило
  и переписали;
* ключевать признак «месяц закрыт документом» на ТОЧНОМ подразделении. Документ лежит
  на родителе, движения ЕРП размазаны по дочерним: июнь-2026 «МК Глобино», МШП
  показывал 136 356,27 вместо 70 381,03.

### Бюджет объекта: не резать по `Направление`, не резать по `Месяц`, не выбирать версию

Три правила из [03_plan_obekta.md](03_plan_obekta.md). Каждое выглядит как «лишняя строгость»,
пока не посмотришь на данные. Самая коварная — попытка «убрать двойной счёт» выбором последней
версии: первичный документ уже отсторнирован в движениях, и выбор версии ЛОМАЕТ сумму.

### Один флаг `СводыНаправлений` на обе части факта

Документная часть берёт свод-документы, ЕРП-часть — ветку иерархии. Разные флаги = двойной счёт.
Параметр отчёта называется `СводыНаправлений`; `ВключатьДочерние` — это РЕКВИЗИТ документа
`А_ОтчетPL`, с которым параметр сравнивается. Путать их нельзя: реквизит разделяет объектные
документы и своды направлений, а не «покрывает ли документ дочерние подразделения».

## Сборка .erf

### «Исключение XDTO при чтении файла Template.xml» — два источника

Сообщение не даёт ни строки, ни причины и съедает циклы сборки. Проверять В ЭТОМ ПОРЯДКЕ:

**1. Незадекларированный префикс `cfg`.** Корень `Template.xml` донора объявляет только
`dcscom / dcscor / dcsset / v8 / v8ui / xs / xsi` — донор нигде не использует ссылочные типы.
Как только появляется параметр СО ССЫЛОЧНЫМ ТИПОМ (в версии 1 это был `Подразделение`
с `<v8:Type>cfg:CatalogRef.СтруктураПредприятия</v8:Type>`), сборка падает. Лечение:

    <DataCompositionSchema xmlns="http://v8.1c.ru/8.1/data-composition-system/schema"
        xmlns:cfg="http://v8.1c.ru/8.1/data/enterprise/current-config" …>

**2. Элемент `<use>Always</use>` внутри `<parameter>`.** Такого элемента в XDTO-схеме параметра
СКД нет. Обязательность параметра делается проверкой в модуле (`ВызватьИсключение`),
а не разметкой.

### Посторонние файлы в каталоге исходников

`Template.xml.bak_skd_formapl` лежит в папке донора `А_ОтчетPL`. При клонировании его копировать
НЕЛЬЗЯ — платформа сканирует каталог и ожидает ровно свой набор файлов, иначе сборка падает
с сообщением про несуществующий файл объекта. Состав правильной папки:

    Ext/ObjectModule.bsl
    Templates/ОсновнаяСхемаКомпоновкиДанных.xml
    Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml

То же правило для ЛЮБЫХ файлов `.bak`: резервные копии модуля и макета (версии 2, 3, 4)
держать вне каталога отчёта — в `scratchpad/bak`. Соблазн «положу рядом, чтобы не искать»
стоит одного круга непонятной сборки.

### GUID при клонировании

Регенерировать: `uuid` корня `<ExternalReport>`, `<xr:ObjectId>`, `<xr:TypeId>`, `<xr:ValueId>`,
`uuid` макета в `ОсновнаяСхемаКомпоновкиДанных.xml`.
**НЕ трогать `<xr:ClassId>`** — это константа класса «внешний отчёт»
(`e41aff26-25cf-4bb6-b6c1-3f478a75f374`), её регенерация даёт «Неверный идентификатор класса
хранимого объекта».

### Занятый Конфигуратор

    С этой информационной базой уже работает конфигуратор: компьютер: SQLSERVER, сеанс: 1

Собирать против `Srvr="SQLSERVER";Ref="BaseERPRazr"` — метаданные совпадают, результат идентичен.
Это штатный обход, а не костыль.

## СКД

### Diff и % освоения на %-строках водопада

Первая версия показывала на строке «Рентабельность продукции, %» значение `0.05` в Diff
и `81%` в освоении. Рентабельность хранится ДОЛЕЙ; разница долей — это процентные пункты,
а «освоение рентабельности» смысла не имеет.

Итоги таких полей обязаны ветвиться по `ВидСтроки`: на `ПоказательПроцент` — свой формат,
иначе процент читается как сумма. **Сами поля `Diff` и `% освоения` из схемы удалены в версии 2**
(их роль играет ось колонок), но правило ветвления живёт дальше — сейчас оно применено
к `СуммаФ1` / `СуммаФ2` / `СуммаИтого` и к `Отклонение` / `ВыполнениеНормы`.

### Тотал процента не может ссылаться на поле с итогом-ВЫБОР

Итоги `СуммаФ1` / `СуммаФ2` / `СуммаИтого` заданы через `ВЫБОР`, который на строках-показателях
возвращает СТРОКУ. Поле `Процент`, сославшись на них, на листовых группировках даёт NULL.
Решение — клон `СуммаСтатья` с простым итогом `Сумма(…)`, на него и ссылается процент.
(В версии 1 клонов было два — `СуммаЕРПСтатья` и `СуммаНакопСтатья`, по одному на блок колонок.)

### Группировки со смешанным содержимым

`СортЛиста = 130` и `160` содержат И строку-показатель, И дочернюю статью (000000057 / 000000058) —
так устроен Excel-outline. Любой итог по этим группировкам обязан фильтровать по `ВидСтроки`,
иначе показатель складывается со статьёй.

### Контрольные строки — текстом, не ресурсом

Строка «Контроль плана: по статьям X + без статьи PL Y = Z» держит числа в `СтрокаЛиста`.
Положить их в ресурс нельзя — итоги СКД посчитают план дважды. (В версии 1 таким ресурсом
был `ПланОбъекта`; с версии 2 план живёт в общих `СуммаФ1` / `СуммаФ2` / `СуммаИтого`
колонки 900100.)

### Длина строкового поля должна совпадать с BSL

`СтрокаЛиста` в модуле объявлена как Строка(250) — в СКД должно быть столько же.
У донора было 200; при клонировании синхронизировать.

### Правка Template.xml

Только Python-скриптом: файл на табах, Edit-инструменты их теряют. После каждой правки —
`xml.etree.ElementTree.parse` как минимальный контроль. Регексы для вырезания блоков писать
с якорем на ТОЧНЫЙ отступ: `\t\t\t<dcsset:selection>` матчится и внутри
`\t\t\t\t\t<dcsset:selection>` — легко испортить XML незаметно.

## BSL

### Реквизит называется `СуммаФома1`

Без «р». Опечатка в метаданных `Документ.А_ОтчетPL`, зафиксирована. Писать по памяти
«СуммаФорма1» → «Поле не найдено». Имена брать из метаданных, не с клавиатуры.

### Наивные grep-чеки врут

`Для Каждого` 18 против `КонецЦикла` 22 — норма, потому что есть четыре `Пока … Цикл`
(числа по модулю на 19.08.2026; при правке пересчитывай, а не сверяйся с этими).
Нечётное число кавычек в строке — норма для многострочных литералов с продолжением `|`.
Настоящее доказательство компиляции — успешный `СкомпоноватьРезультат` через COM.

### Запретные имена

Локальные переменные `Ссылка` и `Выполнить` не использовать: первая конфликтует
с системным свойством и даёт молчаливые сбои внутри `Попытка`, вторая не компилируется.

### `КонецФункция` / `КонецПроцедура`

Опечатки без «и»/«ы» не компилируются, а ошибка вылезает на СЛЕДУЮЩЕЙ строке — глазами
не найти. Grep-чек парности перед сборкой.

## Запросы

### Расходы: только Приход, не оборот

`СуммаЕРП = СУММА(Сумма)` ТОЛЬКО по `ВидДвижения = Приход`. Вычитать Расход нельзя:
у подразделений с `РаспределениеПрочихЗатрат` (Астарта) оборот = 0 и суммы исчезают из PL.

### Алиасы, совпадающие с ключевыми словами

`КАК ПО`, `КАК ИЗ`, `КАК КАК`, `КАК В`, `КАК И` ломают синтаксис. `ПО` особенно коварно — это
и «Подразделение Организаций», и ключевое слово соединения; `В` — оператор вхождения,
`И` — конъюнкции. Безопасные короткие псевдонимы: `Вт`, `Ист`, `КЛ`, `МД`.

### COM сдвигает даты

При передаче `datetime` параметром через `V83.COMConnector` дата теряет сутки; лечение —
прибавлять 3 часа. В BSL проблемы нет. В тестах либо `+timedelta(hours=3)`, либо литерал
`ДАТАВРЕМЯ(...)` прямо в тексте запроса.

### Перечисления через COM

`str()` перечисления в Python врёт — сравнивать только по ссылке, а в запросах использовать
`ЗНАЧЕНИЕ(Перечисление.…)`.

## Методология

### План — БДДС, факт — начисление

Сравнение кассового бюджета с P&L по начислению методологически неточно: НДС, авансы, момент
признания различаются. Компания так делает и в Excel, но отчёт обязан это проговаривать.
Иначе Diff читают как ошибку учёта.

### Занижённый факт ≠ перерасход

Документы начинаются с 2024-01; у девяти объектов их нет вовсе. Без вывода дат
`Накопительно с / Документы PL по / ЕРП с / План актуален на` в шапке заниженный накопительный
факт выглядит как «бюджет освоен на 30 %» — и это неверный вывод.

### Устаревший план

`ПланАктуаленНа` Глобино-2 = 16.05.2025 при факте по 06.2026. Освоение 116 % по выручке —
это сочетание годовалого плана и разной методологии, а не перевыполнение.

### Молча терять деньги нельзя

18,5 млн непокрытого плана по Глобино-2 (24 % у Нежина 4) обязаны быть видны отдельной строкой
плюс контрольной суммой. Плановый отчёт, который тихо роняет часть бюджета, хуже чем бесполезен.

## Разное

### Правки донора не переносятся автоматически

Отчёт — клон `А_ОтчетPL`, а не расширение. Если в доноре меняются ЕРП-ветки (правила расщепления
выручки по `ТипЗапасов`, приёмник CoGS), изменение надо перенести руками.

### Приёмка — полный путь пользователя

`ВнешниеОтчеты.Создать` → загрузка варианта → параметры → `СкомпоноватьРезультат` → чтение ячеек.
Проверка через внутренние функции в обход формы приёмкой не считается.

### Украинские буквы в именах полей

`і`, `є`, `ї` в ИМЕНАХ полей набора и СКД не использовать — только в заголовках (`title`).
Заголовки этого отчёта переведены на русский 18.08.2026.

## Версия 2 (18.08.2026) — новые грабли

### Группировка колонок по полю с итогом запрещена

Любое поле с выражением `totalField` СКД считает РЕСУРСОМ, а группировать колонки таблицы
по ресурсу нельзя, если в строках есть включённые группировки. Симптом:
«Не допускается группировка по полю - ресурсу в колонках таблицы…».
У `КолонкаСорт` итога НЕТ, вместо него `role/dimension=true`; подпись тянется
`presentationExpression`-ом через ресурс `КолонкаPL`.

### РасположениеИтогов=None у КОЛОНОЧНОЙ группировки обнуляет всю таблицу

Макет собирается, шапки колонок рисуются, а все ячейки пустые. В таблице СКД значение ячейки —
это и есть итог колоночной группировки. Лишний столбец «Итого» снимается параметром
`ГоризонтальноеРасположениеОбщихИтогов = None`, а не свойством группировки.
У СТРОЧНЫХ группировок `РасположениеИтогов = None` по-прежнему безопасен.

### Одна граница не работает в помесячном разрезе

«Последний документ до начала периода» для периода январь–июнь равен декабрю 2025, поэтому
признак «после границы» истинен для всех месяцев периода и не отсекает ничего — месяцы дублируют
документы ровно вдвое. Лечилось помесячным признаком «месяц закрыт документом» (`втМесяцыДок`);
с 20.08.2026 таблица удалена, а разделение источников делает прямой фильтр по месяцу
(`= &ПоследнийМесяц` у регистров, `<> &ПоследнийМесяц` у документов) — задвоение невозможно
по построению.

### Соединение месяцев по датам ломается на переходе летнего времени

Сдвиг дат через COM зависит от DST: фиксированная компенсация +3 ч верна летом и врёт зимой,
январь–март просто не соединялись. Соединять месячные ветки по ЧИСЛОВОМУ ключу ГГГГММ.

### Документы А_ОтчетPL лежат не на конце дня

Проверено серверным `ЧАС(Дата)`: 550 документов на 20:59:59 и 358 на 21:59:59, ни один не равен
`КОНЕЦПЕРИОДА(Дата, ДЕНЬ)`. Сравнение границы по timestamp затягивает в хвост вечер граничного дня
(Глобино-2: 21 831 006 / 633 записи вместо 20 310 644 / 515). Сравнивать границу ПО МЕСЯЦУ.

### `Формат(x, "ЧГ=3")` группирует только последнюю тройку

Даёт «1086186 004» вместо «1 086 186 004». Для обычной разрядности `ЧГ` не указывать вовсе —
`Формат(x, "ЧДЦ=0")`.

### `Месяц` — имя встроенной функции

Локальная переменная `Месяц` затеняет её, и `Месяц(Месяц)` не компилируется. Использовать `ТекМесяц`.

### `Тип()` недоступен через COM

`erp.Тип(...)`, `erp.Type(...)`, `erp.ТипЗнч(...)` — все падают. Единственный рабочий способ:
`erp.NewObject("ОписаниеТипов", "<имя типа>").Типы().Получить(0)`.

### Алиас `В` в запросе

`... КАК В` — синтаксическая ошибка: `В` это оператор вхождения. Тот же класс, что `ПО` и `ИЗ`.

### Данные меняются под ногами

Утром 18.08.2026 у Глобино-2 было 5 незамапленных ДДС бюджета на 18 935 323, к вечеру —
ноль: их замапили по ходу работы. Эталоны приёмки, завязанные на «непокрытый план», надо брать
на объекте, где он реально есть (Астарта. Тищенки — 40 343 938), либо перепроверять перед прогоном.

## Версия 3 (19.08.2026) — новые грабли

### Срез строк при замене текста запроса в модуле

Номер строки `Запрос.Текст =` — это ещё НЕ литерал: литерал начинается со следующей строки.
Срез `строки[:н-1]` затирает саму строку `Запрос.Текст =`, и модуль молча превращается
в синтаксический мусор — ошибка вылезает только в Конфигураторе, через сборку и загрузку.
Нужен `строки[:н]` плюс assert: строка `н` действительно начинается с `Запрос.Текст =`,
а строка `к` оканчивается на `";`.

### Модуль хранится в LF с BOM

`Ext/ObjectModule.bsl` — UTF-8 с BOM, переводы строк LF (проверено: ни одного символа CR
на 1449 строк). Запись из Python в режиме CRLF (`newline="\r\n"`) переписала бы файл
целиком и дала бессмысленный diff во всю длину модуля. Открывать на запись
с `newline="\n"`, BOM сохранять (`encoding="utf-8-sig"`).

### Ещё два зарезервированных псевдонима

К `ПО`, `ИЗ`, `КАК` добавились `В` (оператор вхождения) и `И` (конъюнкция) — подробности
в разделе «Запросы» выше.

## Версия 4 (19.08.2026) — новые грабли

### Любая ветка объединения обязана СОЕДИНЯТЬСЯ с `втКолонкиPL`

Две ветки зашивали номер колонки константой — `900000` (накопительные документы)
и `900100` (план объекта) — и с осью колонок не соединялись. Флажок убирал колонку
из `втКолонкиPL`, а ветка всё равно отдавала строки: «Накопительный PL» продолжал
печататься при снятом `ВыводитьНакопительный`. Лечение: обе ветки получили
`ВНУТРЕННЕЕ СОЕДИНЕНИЕ втКолонкиPL ПО КЛ.КолонкаСорт = <константа>` и берут подпись
из `КЛ.КолонкаПредставление`. **Новая ветка без соединения с осью колонок = флажки её
не видят.** Механика блоков — [11_fiksy_norma_i_otklonenie.md](11_fiksy_norma_i_otklonenie.md).

### Отбор группировки прячет статью с нулевым фактом

Базовый отбор группировки «Статья PL» — `СуммаФ1 Заполнено ИЛИ СуммаФ2 Заполнено`.
Для сверки с нормой он НЕВЕРЕН: статья, где норма есть, а факта нет, — это стопроцентная
экономия, и её обязано быть видно. Симптом: итог нормы не сходится с суммой видимых строк
(по «Производство» показывалось 978 542 из 1 170 531). В настройке «отчет по фиксам»
условие дополнено `... ИЛИ ФиксФ1 Заполнено ИЛИ ФиксФ2 Заполнено`.

### `ВариантНастроек.Настройки` — ТОЛЬКО ДЛЯ ЧТЕНИЯ

Присвоить варианту готовый объект настроек нельзя. И читать настройки сохранённого варианта
из XML как источник — тоже: там лежат только те параметры, что были на момент сохранения,
новых флажков среди них нет, и `ПараметрыДанных.Элементы.Найти()` вернёт `Неопределено`.
Настройки для нового предопределённого варианта готовит КОМПОНОВЩИК — он подмешивает полный
список параметров схемы. Дальше платформа сериализует их автономно, и корневой тег
переименовывается в `dcsset:settings`: пространство имён то же
(`http://v8.1c.ru/8.1/data-composition-system/settings`), поэтому дети остаются валидными
без перепрефиксовки, а блок `<settingsVariant>` вставляется перед `</DataCompositionSchema>`.

### Пустой `Документ` ломает расшифровку МОЛЧА

Бюджетные ветки отдавали `НЕОПРЕДЕЛЕНО` вместо регистратора: суммы при этом верные,
а в расшифровке не видно, чем введена норма и чем план. Обе ветки берут `Б.Регистратор`
(это `Документ.А_БюджетМесяц`, в интерфейсе «Бюджет(за период)»), `втФиксНорма` протаскивает
его через срез. При добавлении любой новой ветки повторять аудит «строк без документа»:
на 01.06–31.07.2026 их ноль — 146 фикс-строк, 2 542 месячных, 10 584 накопительных,
1 082 плановых.
