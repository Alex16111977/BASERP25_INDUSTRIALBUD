# 04. Показатели, колонки и формулы итогов

Показатели отчёта = ресурсы и вычисляемые поля; колонки — это измерение `КолонкаСорт`,
а не отдельные поля. Итоги на группировках считает СКД по `totalField` из `Template.xml`.

## Ось колонок

Фиксированных «13 колонок» версии 1 больше нет. Колонки строит `ТаблицаКолонок` и они
становятся ИЗМЕРЕНИЕМ `КолонкаСорт` (подпись выводится через `presentationExpression`
из `КолонкаPL`):

| `КолонкаСорт` | Подпись | Что внутри |
|---|---|---|
| `Год × 100 + Месяц` | «июль 2026» | факт месяца + норма-фикс, действующая на этот месяц |
| `900000` | Накопительный PL | накопительный факт за всю историю |
| `900100` | План итого | бюджет объекта |

Месячные колонки строятся от `НачалоМесяца(НачалоПериода)` — неполный период
разворачивается до целого месяца. План идёт последним (сорт `900100`), как просил
финансист: сначала факт по месяцам, затем накопительный итог, и только потом план.

Каждый блок гасится своим флажком (`ВыводитьМесяцы`, `ВыводитьНакопительный`,
`ВыводитьПлан`); если сняты все три, `ТаблицаКолонок` выбрасывает исключение —
выводить нечего.

Фикс НЕ отдельная колонка: это ресурсы `ФиксФ1` / `ФиксФ2` / `ФиксИтого` внутри
месячных колонок (см. [11_fiksy_norma_i_otklonenie.md](11_fiksy_norma_i_otklonenie.md)).

Заголовки — русские (переведены 18.08.2026, до этого были украинские).

## Кто наполняет `СуммаФ1` / `СуммаФ2` / `СуммаИтого`

Отдельных полей на каждый блок (`НакопДок`, `НакопЕРП`, `ПланОбъекта` версии 1) больше нет:
суммы одни на все колонки, а блок различается значением `КолонкаСорт`. Всё собирает один
пакет запроса, ветки объединения:

| Ветка объединения | В какие колонки | Что даёт |
|---|---|---|
| `втЕРП_Расх_Детали` (регистр `ПрочиеРасходы`) | месяц `= МесяцКлюч` и `900000` | факт затрат |
| `втЕРП_ДохCoGS_PL` (выручка, прочие доходы, CoGS) | месяц `= МесяцКлюч` и `900000` | факт доходов и себестоимости продаж |
| ТЧ `Документ.А_ОтчетPL.ДанныеОтчета`, месяц ≠ `&ПоследнийМесяц` | месяц документа | факт закрытого месяца |
| ТЧ `Документ.А_ОтчетPL.ДанныеОтчета`, месяц `< &ПоследнийМесяц` | `900000` | накопительная часть из документов |
| `РегистрНакопления.А_БюджетыНаМесяц`, `ВидПериода = Объект` | `900100` | план объекта |
| `втФиксНорма` | каждая месячная колонка | норма в `ФиксФ1/ФиксФ2/ФиксИтого`, нули в факт |

Дублей нет потому, что ЕРП-ветки берут ТОЛЬКО последний месяц периода
(`ГОД(Период) * 100 + МЕСЯЦ(Период) = &ПоследнийМесяц`), а документные — все месяцы, кроме
последнего. Пересечения по построению нет, проверять «закрыт ли месяц документом» не нужно.
Само правило (исключений нет) — в
[12_novaya_forma_ebitda_ebit.md](12_novaya_forma_ebitda_ebit.md).

Чем закрыт каждый месяц, видно не по отдельным полям, а по строке раскрытия
`ИсточникиФакта` в шапке подразделения (даты `НакопительноС`, `ДокументыПо`, `ЕРПС`,
`ПланАктуаленНа`).

## Ф1 / Ф2 — откуда берётся разделение

В ЕРП-части: `Р.ФормаPL = ЗНАЧЕНИЕ(Перечисление.А_ФормыPL.Форма2)` в регистре `ПрочиеРасходы`.
Доходы и CoGS целиком идут в Ф1 (в этих регистрах разметки ФормаPL нет).

В документной части: реквизиты ТЧ `СуммаФома1` и `СуммаФорма2`.

> ⚠️ Реквизит называется **`СуммаФома1`** — без «р». Это опечатка в метаданных документа,
> она зафиксирована и менять её нельзя (сломается всё, что на неё ссылается).

В бюджетных ветках (план объекта и фикс) разрез свой — измерение `ВидОплаты` регистра
`А_БюджетыНаМесяц`: `Наличные` → Ф2, всё остальное → Ф1. Раскладка та же, что у факта,
поэтому Ф1 плана сравним с Ф1 факта.

## Вычисляемые поля (3)

Выражения — дословно из `Template.xml`, блок `calculatedField`.

| Поле | Заголовок | Выражение на строке |
|---|---|---|
| `Процент` | % суммы затрат в общем объеме | `ВЫБОР КОГДА НЕ (ВидСтроки = "Статья") ИЛИ БазаПроцента = 0 ТОГДА NULL КОГДА СуммаСтатья / БазаПроцента * 100 < 0.5 И СуммаСтатья / БазаПроцента * 100 > -0.5 ТОГДА "0%" ИНАЧЕ Формат(СуммаСтатья / БазаПроцента * 100, "ЧДЦ=0") + "%" КОНЕЦ` |
| `Отклонение` | Отклонение от фикса, грн | `ВЫБОР КОГДА НЕ (ВидСтроки = "Статья") ИЛИ ФиксИтого = 0 ТОГДА NULL ИНАЧЕ СуммаИтого - ФиксИтого КОНЕЦ` |
| `ВыполнениеНормы` | Выполнение нормы, % | `ВЫБОР КОГДА НЕ (ВидСтроки = "Статья") ИЛИ ФиксИтого = 0 ТОГДА NULL КОГДА СуммаИтого / ФиксИтого * 100 < 0.5 И СуммаИтого / ФиксИтого * 100 > -0.5 ТОГДА "0%" ИНАЧЕ Формат(СуммаИтого / ФиксИтого * 100, "ЧДЦ=0") + "%" КОНЕЦ` |

`Отклонение` = факт − норма, плюс означает перерасход. Где нормы нет (`ФиксИтого = 0`) —
NULL, а не «минус весь факт»: пустая ячейка честнее выдуманного сравнения.

Значения между −0.5 % и +0.5 % показываются как «0%», а не как пустота — так же, как в донор-отчёте.

## База процента

`БазаПроцента` заполняется в BSL на каждой строке и равна «итого затрат» СВОЕЙ пары
(подразделение × колонка) — у каждой месячной колонки, у накопительной и у плана база своя:

    СС + ДР + ОПЗ + МЗ + АЗ + НС + ФинРасходы(056) + НалогНаПрибыль(057) + Дивиденды(058)

У строк группы «Операционный доход» (код группы 000000006) база НЕ заполняется — в Excel
«%» у доходных строк пуст.

## Клон суммы для процента — зачем он есть

`СуммаСтатья` — точная копия `СуммаИтого` с ПРОСТЫМ итогом `Сумма(…)`.

Причина: итог основных сумм задан через `ВЫБОР`, который на строках-показателях возвращает
СТРОКУ («33,85%»). Тотал `Процент`, сославшись на такое поле, на листовых группировках
получает NULL. Клон с простым итогом решает проблему. Приём унаследован от донора,
где он уже был описан комментарием в коде.

## Итоги `totalField` (19 штук)

Четыре категории.

**Категория 1 — суммы факта с ветвлением по типу строки** (`СуммаФ1`, `СуммаФ2`,
`СуммаИтого`). Схема одна:

    ВЫБОР
      КОГДА в группе есть строка ВидСтроки = "ПоказательПроцент"
        ТОГДА ВЫБОР КОГДА Сумма(Знаменатель только таких строк) = 0 ТОГДА NULL
              ИНАЧЕ Формат(Сумма(числитель) / Сумма(знаменателя) * 100, "ЧДЦ=2") + "%" КОНЕЦ
      КОГДА в группе есть строка ВидСтроки = "Показатель"
        ТОГДА Сумма(только таких строк)
      ИНАЧЕ Сумма(всех)
    КОНЕЦ

Зачем ветвление: группировка `СортЛиста = 130` («Прибыль после вычета финансовых затрат»)
содержит И строку-показатель, И дочернюю статью 000000057 «Затраты на налог на прибыль»
(так устроен Excel-outline). Без фильтра итог сложил бы показатель со статьёй.

**Категория 2 — простые суммы** (`СуммаСтатья`, `Знаменатель`, `ФиксФ1`, `ФиксФ2`,
`ФиксИтого`) — обычный `Сумма(…)`.

**Категория 3 — максимумы для скалярных полей** (`БазаПроцента`, `СортЛиста`, `КолонкаPL`,
`НакопительноС`, `ДокументыПо`, `ЕРПС`, `ПланАктуаленНа`, `ИсточникиФакта`). Эти поля
одинаковы у всех строк своей пары, `Максимум` просто протаскивает значение на уровень
группировки.

**Категория 4 — вычисляемые** (`Процент`, `Отклонение`, `ВыполнениеНормы`). Все три
блокируются на нелистовых строках условием
`Максимум(ВЫБОР КОГДА ВидСтроки = "Статья" ТОГДА 0 ИНАЧЕ 1 КОНЕЦ) = 1 ТОГДА NULL`:

| Итог | Формула |
|---|---|
| `Процент` | `Сумма(СуммаСтатья) / Максимум(БазаПроцента) * 100`, формат `ЧДЦ=0`, `+ "%"`; NULL при `Максимум(БазаПроцента) = 0` |
| `Отклонение` | `Сумма(СуммаИтого) - Сумма(ФиксИтого)`; NULL при `Сумма(ФиксИтого) = 0` |
| `ВыполнениеНормы` | `Сумма(СуммаИтого) / Сумма(ФиксИтого) * 100`, формат `ЧДЦ=0`, `+ "%"`; NULL при `Сумма(ФиксИтого) = 0` |

Ключевое: `Отклонение` и `ВыполнениеНормы` на итогах считаются как
`Сумма(факт) − Сумма(нормы)` и `Сумма(факт) / Сумма(нормы)`, а не как сумма построчных
отклонений или среднее процентов. Поэтому они верны на ЛЮБОМ уровне свёртки — по статье,
по группе статей, по подразделению, по всей ветке направления.

## Водопад прибыли — свой в каждой паре (подразделение × колонка)

`РассчитатьВодопадКолонки(Данные, К)` вызывается ТРИ раза — с ключами `Ф1`, `Ф2`, `Ит` —
для каждой записи накопителя `Итоги`. Ключ накопителя — УИД подразделения плюс
`КолонкаСорт` через `"|"`, то есть водопад считается отдельно в каждом месяце, отдельно
в накопительной колонке и отдельно в плане. Семи фиксированных баз версии 1
(`Н1`, `НИ`, `ПЛ` и т. д.) больше нет — их роль играет `КолонкаСорт`.

Формулы (те же, что в доноре, сверены с `Документ.А_ОтчетPL.ИтогиОбщие`):

1. Маржинальный доход = ОД − СС
2. Операционная прибыль = Маржинальный − ОПЗ − МЗ − АЗ
3. Прибыль после вычета финансовых затрат = Операционная + ФинДоход(055) − ФинРасходы(056)
4. Прибыль до вычета налогов = после фин. затрат − ДР
5. Чистый доход = до налогов − НС − НалогНаПрибыль(057)
6. Прибыль в распоряжении компании = Чистый − Дивиденды(058)
7. Рентабельность продукции, % = Прибыль в распоряжении / ОД

Строки-проценты (`Маржинальный доход, %`, `Операционная прибыль, %`,
`Рентабельность продукции, %`) хранят в суммах ЧИСЛИТЕЛЬ, а в поле `Знаменатель` —
операционный доход ТОЙ ЖЕ пары. Долю хранить нельзя: сумма долей не имеет смысла.
Итог берёт `Сумма(числитель) / Сумма(знаменателя)` и потому верен на любом уровне
свёртки; при нулевом ОД колонки получается NULL, а не деление на ноль.

**Плановая рентабельность против фактической на сегодня — главный KPI этого отчёта.**
Именно ради неё водопад считается и по плановой базе, а не только по факту.
