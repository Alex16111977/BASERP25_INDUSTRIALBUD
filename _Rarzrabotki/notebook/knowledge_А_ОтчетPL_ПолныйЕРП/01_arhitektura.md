# 01. Архитектура: программная компоновка СКД

## Почему отчёт программный

Чистым СКД-запросом отчёт не собирается по трём причинам.

Во-первых, оси колонок нет в данных: месяцы периода, «Накопительный PL» и «План итого»
строит BSL (`ТаблицаКолонок`) и передаёт в запрос параметром-таблицей `&КолонкиPL`; состав
оси зависит от периода и от флажков блоков. Во-вторых, строки-показатели
водопада прибыли (Маржинальный доход, Операционная прибыль, Чистый доход, Рентабельность)
не существуют в данных — они считаются из агрегатов групп и добавляются в таблицу синтетически.
В-третьих, «полный шаблон» листа требует нулевых строк для статей, у которых нет ни факта,
ни плана: без них лист PL выглядит дырявым и не совпадает с Excel построчно.

Отчёт унаследовал этот подход от донора `А_ОтчетPL` (вариант `А_ОтчетPL_ВидКакВExcel`),
откуда взяты дословно четыре сложные CTE ЕРП-факта.

## Поток данных

`ПриКомпоновкеРезультата` (строка 21 модуля) выполняет восемь шагов.

**Шаг 0 — период.** `Период` читается напрямую через
`КомпоновкаДанныхКлиентСервер.ПолучитьПараметр`; при незаполненной границе —
`ВызватьИсключение «Заполните параметр Период»`. Это ЕДИНСТВЕННАЯ обязательная настройка.
Параметра `Подразделение` в отчёте НЕТ: отбор по подразделению делает штатная СКД любым
способом — в иерархии, списком, по группе. Замер 18.08.2026: полный скан базы 0,4–1,9 с,
ограничивать выборку отбором на входе незачем.

**Шаг 0.1 — флажки.** `ЗначениеПараметра` (обёртка над `ПолучитьПараметр` с дефолтом) читает
`СводыНаправлений`, `ПоказИтогиПрибыли`, `ПолныйШаблон`, `ПоказатьСлужебныеСтроки`,
`ТолькоСтатьиСФиксами` и собирает структуру `Блоки` из `ВыводитьМесяцы`,
`ВыводитьНакопительный`, `ВыводитьПлан`, `ВыводитьФиксы`. Снятый флажок блока — это НЕ отбор:
колонки не создаётся вовсе, поэтому её ветка запроса данные и не читает.

**Шаг 1 — данные.** `ПолучитьДанные(НачалоПериода, КонецПериода, СводыНаправлений, Блоки)` —
ОДИН пакетный запрос из 12 временных таблиц, отдающий сразу всю таблицу значений: факт ЕРП,
документный факт, план объекта и норму-фикс в единой форме строки. Отдельных запросов
«факт за период», «ЕРП-хвост», «документы», «план» больше нет. Правило выбора источника —
**регистры только за последний месяц периода, всё раньше только документы `А_ОтчетPL`,
исключений нет** — живёт внутри пакета ОДНИМ условием
`ГОД(Период) * 100 + МЕСЯЦ(Период) = &ПоследнийМесяц` в четырёх ЕРП-ветках. Таблицы
`втМесяцыДок` больше нет. См. [12_novaya_forma_ebitda_ebit.md](12_novaya_forma_ebitda_ebit.md).

**Шаг 2 — читаемый вид колонки.** Колонка `ВидКолонки` по `КолонкаСорт`:
900100 → «План объекта», 900000 → «Накопительный PL», остальное → «Месяц». Нужна, чтобы
в сохранённых настройках отбор шёл словами, а не числом 900 100.

**Шаг 3 — `Аналитика1`.** Строковое представление для группировки: у строк документа
`А_ОтчетPL` это `Комментарий` (комментарий финансиста из Excel), у остальных — `Аналитика`
(контрагент / физлицо / подотчётник).

**Шаг 4 — разметка листа.** `ДополнитьВидКакВExcel` — строки листа, полный шаблон, водопад,
контрольные строки. См. [05_razmetka_lista.md](05_razmetka_lista.md).

**Шаг 5 — подпись бюджетных строк без статьи PL.** Строки бюджета и нормы, чей ДДС не
привязан к статье PL, сворачивались бы в безымянную группу и читались как сбой отчёта.
Им проставляется `СтрокаЛиста = «Бюджет без статьи PL»` — только там, где разметка листа
не задала свою подпись.

**Шаг 6 — фильтр по фиксам.** При `ТолькоСтатьиСФиксами` процедура `ОставитьСтатьиСФиксами`
выбрасывает статьи без заведённой нормы. Строго ПОСЛЕ разметки: полный шаблон дорисовал бы
удалённые статьи обратно. См. [11_fiksy_norma_i_otklonenie.md](11_fiksy_norma_i_otklonenie.md).

**Шаг 7 — раскрытие источников.** `ЗаполнитьРаскрытиеИсточников` добавляет пять колонок
и заполняет их у ВСЕХ строк. Идёт ПОСЛЕ разметки — иначе строки-показатели и строки полного
шаблона остались бы без дат.

Дальше — стандартная компоновка: `ВнешниеНаборыДанных = Новый Структура("Данные", ТаблицаДанных)`,
`КомпоновщикМакетаКомпоновкиДанных` → `ПроцессорКомпоновкиДанных` →
`ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент`.

## Ключевой приём: ось колонок — параметр запроса

Оси нет в данных, поэтому её строит BSL и отдаёт в запрос как таблицу значений
`&КолонкиPL` (`КолонкаСорт`, `КолонкаПредставление`, `МесяцДата`), а запрос кладёт её
в `втКолонкиPL`. Регистровые ветки соединяются с осью условием

    ПО (КЛ.КолонкаСорт > 0 И КЛ.КолонкаСорт < 900000 И Д.МесяцКлюч = КЛ.КолонкаСорт)
        ИЛИ КЛ.КолонкаСорт = 900000

— одна и та же строка факта попадает и в свой месяц, и в «Накопительный PL». Отсюда
и правило «месяцы — ЧАСТЬ накопительного, а не добавка к нему».

Зачем так, а не через `ВЫБОР` с нулями в чужих колонках: флажок блока просто не добавляет
строку в таблицу колонок, и ветка запроса перестаёт читать данные — снять «Месяцы» на
длинном периоде это самый дешёвый способ ускорить отчёт. Если сняты все флажки и таблица
колонок пуста, `ТаблицаКолонок` бросает исключение: выводить нечего.

Финальное объединение — шесть веток, каждая отдаёт ОДИН И ТОТ ЖЕ набор из 18 колонок
(чужие суммы = 0), поэтому склейка бесплатна и типы таблицы значений описывать не надо:

| Ветка | Источник | Колонки оси |
|---|---|---|
| Расходы ЕРП | `втЕРП_Расх_Детали` | месяцы + 900000 |
| Доходы и CoGS ЕРП | `втЕРП_ДохCoGS_PL` | месяцы + 900000 |
| Документы помесячно | `Документ.А_ОтчетPL.ДанныеОтчета` | месяцы (кроме `&ПоследнийМесяц`) |
| Документы накопительно | `Документ.А_ОтчетPL.ДанныеОтчета` | 900000 (месяцы < `&ПоследнийМесяц`) |
| План объекта | `РегистрНакопления.А_БюджетыНаМесяц`, ВидПериода = Объект | 900100 |
| Норма-фикс | `втФиксНорма` | месяцы |

Плюс 14 колонок, добавляемых в BSL:

* `ПриКомпоновкеРезультата` — ВидКолонки, Аналитика1;
* `ДополнитьВидКакВExcel` — ВидСтроки, СтрокаЛиста, СортЛиста, ПоказыватьСтатью,
  БазаПроцента, СуммаСтатья, Знаменатель;
* `ЗаполнитьРаскрытиеИсточников` — НакопительноС, ДокументыПо, ЕРПС, ПланАктуаленНа,
  ИсточникиФакта.

Итого 32 — ровно столько полей в наборе данных СКД.

Сумм «за период» и «накопительно» больше НЕ бывает в одной строке: разрез задаёт
`КолонкаСорт`, суммы всегда лежат в одной паре `СуммаФ1 / СуммаФ2` (+ `СуммаИтого`).

`Подразделение` — это `ПодразделениеОтчета` из `втКартаУровней`: при `СводыНаправлений`
движение поднимается на ближайшего предка, у которого есть свод-документ направления,
иначе остаётся на своём подразделении. Свёртку ветки под нужный уровень делает уже отбор СКД.

## Роли файлов

| Файл | Роль |
|---|---|
| `Ext/ObjectModule.bsl` | Вся логика. Единственный источник истины |
| `Templates/…/Ext/Template.xml` | 32 поля набора, 3 вычисляемых поля, 19 итогов, 12 параметров, 3 варианта настроек |
| `Templates/ОсновнаяСхемаКомпоновкиДанных.xml` | Описание макета (имя, тип `DataCompositionSchema`) |
| `А_ОтчетPL_ПолныйЕРП.xml` | Корневой XML: имя, синоним, `DefaultForm = CommonForm.ФормаОтчета` |

Форма своя не делается: отчёт использует типовые формы БСП
(`ФормаОтчета` / `ФормаНастроекОтчета` / `ФормаВариантаОтчета`).
