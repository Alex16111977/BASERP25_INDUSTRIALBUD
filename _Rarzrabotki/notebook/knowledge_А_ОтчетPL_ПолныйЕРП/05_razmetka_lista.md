# 05. Разметка листа: ДополнитьВидКакВExcel

Процедура (строка 1337) превращает плоскую таблицу источников в структуру Excel-листа PL:
двухуровневые строки, полный шаблон, водопад прибыли, контрольные строки.

Сигнатура: `ДополнитьВидКакВExcel(ТаблицаДанных, ПоказИтогиПрибыли, ПолныйШаблон = Истина,
ПоказатьСлужебныеСтроки = Истина, НазванияНаРусском = Ложь)`. Пятый параметр (21.08.2026)
переключает тексты строк листа и водопада на `НаименованиеДляОтчетаНаРусском` с фолбэком;
числа от него не зависят.

Вызывается из `ПриКомпоновкеРезультата` ПОСЛЕ `ПолучитьДанные`, `УдалитьСтрокиДивидендов`
и служебных колонок `ВидКолонки` / `Аналитика1`, но ДО подписи корзины «Бюджет без статьи PL»,
до `ОставитьСтатьиСФиксами`, до заполнения раскрытия источников и до
`ЗаполнитьРусскиеНаименования`.

## Добавляемые колонки

| Колонка | Тип | Смысл |
|---|---|---|
| `ВидСтроки` | Строка(30) | `Статья` · `Показатель` · `ПоказательПроцент` · `ПланБезСтатьиPL` · `Контроль` |
| `СтрокаЛиста` | Строка(250) | Название строки уровня 1 (группа / показатель / текст контроля) |
| `СортЛиста` | Число(5,0) | Позиция строки на листе |
| `ПоказыватьСтатью` | Булево | Раскрывать ли до уровня 2 (статьи PL) |
| `БазаПроцента` | Число(17,2) | Знаменатель «% затрат» — свой у пары (подразделение × колонка) |
| `СуммаСтатья` | Число(17,2) | Клон `СуммаИтого` с простым итогом (числитель «% затрат») |
| `Знаменатель` | Число(17,2) | Знаменатель %-строк водопада (операционный доход той же колонки) |

Изначально всем строкам ставится `ВидСтроки = "Статья"`, `ПоказыватьСтатью = Истина`,
`СуммаСтатья = СуммаИтого` (NULL приводится к нулю).
При `ПоказИтогиПрибыли = Ложь` процедура на этом и заканчивается.

## Порядок строк листа (СортЛиста)

| 20 | Себестоимость проданой продукции | группа 000000001 |
| 30 | Дополнительные расходы | группа 000000007 |
| 40 / 50 | **Маржинальный доход, грн / %** | водопад |
| 60 | Общепроизводственные затраты | группа 000000003 |
| 70 | Маркетинговые затраты | группа 000000005 |
| 80 | Административные затраты | группа 000000002 |
| 100 / 110 | **EBITDA, грн / %** | водопад |
| 115 | Амортизация | статья 000000068 (вынесена из ОПЗ) |
| 120 / 125 | **EBIT / Операционная прибыль, грн / %** | водопад |
| 130 | Финансовая деятельность (нетто) | группа 000000004 + показатель-нетто |
| 140 | Налоги и сборы | группа 000000008 + статья 000000057 |

| 910 | План без статьи PL (ДДС не привязана) | непокрытый бюджет |

Это форма листа 21.08.2026 (низ водопада — EBITDA/EBIT, см.
[12_novaya_forma_ebitda_ebit.md](12_novaya_forma_ebitda_ebit.md)). Старый низ
(«Операционная прибыль» 100/110, «Прибыль после вычета финансовых затрат» 130,
«Прибыль до вычета налогов» 150, «Дивиденды» под 160, «Прибыль в распоряжении компании» 180)
ОТМЕНЁН 21.08.2026. При «Названия на русском» Вкл строки 120/125 называются
«EBIT / Операционный доход, грн/%», а строка 190 — «Чистый доход, %».

Соответствие «код группы → позиция» задано соответствием `ПозицииГрупп` прямо в коде;
Амортизация (000000068) и Налог на прибыль (000000057) размечаются ПО КОДУ статьи
раньше группы — так они покидают ОПЗ и финансовую деятельность соответственно.

## Дочерние статьи показателей (Excel-outline)

ОТМЕНЕНО 21.08.2026 (новая форма листа): статьи 000000057 и 000000058 больше не вкладываются
подстроками в показатели 130/160. Действующее правило:

- `000000057` «Налог на прибыль» уходит из финансовой деятельности в строку листа
  «Налоги и сборы» (сорт 140) — вместе с группой 000000008;
- `000000058` «Дивиденды» исключена из отчёта целиком: `УдалитьСтрокиДивидендов` чистит
  данные ДО разметки, а фильтр `&КодДивидендов` в запросе статей не даёт полному шаблону
  дорисовать её нулевую строку.

Строки двух видов по-прежнему живут в группировке 130 «Финансовая деятельность»
(статьи группы 000000004 + показатель-нетто), поэтому формулы итогов обязаны фильтровать
по `ВидСтроки` — см. [04_pokazateli_formuly.md](04_pokazateli_formuly.md).

## Аккумуляция для водопада

Собирается соответствие `Итоги`. Ключ — ПАРА (подразделение × колонка), склеенная строкой
`УникальныйИдентификатор|КолонкаСорт`: пара «ссылка + число» ключом соответствия быть не может.
Значение — структура из тринадцати «троек» (`ОД`, `СС`, `ДР`, `ОПЗ`, `Аморт`, `МЗ`, `АЗ`,
`НС`, `ФинДоход`, `ФинРасхКом`, `ФинРасхПроц`, `КурсРазн`, `НалогНаПрибыль`), каждая
с полями `Ф1, Ф2, Ит`. Тройки «Дивиденды» нет — статья исключена из отчёта (21.08.2026).
Накопительный итог, «PL с начала года» и план — не поля тройки, а отдельные колонки оси:
месяцы (ГГГГММ) → «PL с начала года» (890000) → «Накопительный PL» (900000) →
«План итого» (900100) (файл 09_versiya2_os_kolonok.md удалён 28.08.2026, история в git).

Строка попадает в тройку по коду статьи (055/056/057/068/075/076 — спец-статьи из
`КодыОсобыхСтатей`, разбираются РАНЬШЕ группы) либо по коду группы.
Строки с нулями по всем трём суммам пропускаются.

Параллельно по той же паре копятся `ПланВсего` и `ПланБезСтатьи` (только по колонке 900100)
и флаг `ЕстьДокумент` — они нужны контрольным строкам. Считаются в ТОМ ЖЕ цикле, чтобы
не делать второй проход по таблице.

## Полный шаблон (ПолныйШаблон = Истина)

Для каждой пары (подразделение × колонка) добавляются НУЛЕВЫЕ строки по всем статьям
`А_Статьи_PL`, которых нет в данных этой пары (кроме «Дивидендов» 000000058 —
фильтр `&КодДивидендов` в запросе статей). Без этого лист выглядит дырявым и не совпадает
с Excel построчно: финансист привык видеть все статьи, в том числе пустые.

Строки полного шаблона имеют `ВидСтроки = "Статья"`, `ПоказыватьСтатью = Истина` и нули
во всех суммах.

## Строки-показатели

`ДобавитьСтрокуПоказателя` (строка 1703) создаёт синтетическую строку: `СтатьяPL`, `Группа`,
`Документ` пустые (в расшифровку не попадает), `ПоказыватьСтатью = Ложь`, суммы `СуммаФ1`,
`СуммаФ2`, `СуммаИтого` = значения водопада этой колонки.

У %-строк (`ВидСтроки = "ПоказательПроцент"`) в суммах лежит ЧИСЛИТЕЛЬ, а в поле `Знаменатель` —
операционный доход той же колонки. Итог СКД делит сумму числителей на сумму знаменателей,
поэтому процент верен на любом уровне свёртки; знак «%» добавляют тоталы при выводе.

## Контрольные строки

`ДобавитьКонтрольныеСтроки` (строка 1631) добавляет до двух строк на подразделение и вызывается
ТОЛЬКО при `ПоказатьСлужебныеСтроки = Истина` (см. ниже).

**Контроль плана (920).** Ставится в колонку «План итого» (900100) тех подразделений, у которых
план ненулевой. Текст: «Контроль плана: по статьям X + без статьи PL Y = Z
(регистр А_БюджетыНаМесяц)». Числа хранятся ТЕКСТОМ в `СтрокаЛиста`, а НЕ в ресурсах —
иначе итоги СКД посчитали бы план дважды. Это осознанное решение, а не небрежность.

**Предупреждение (921).** Ставится в колонку «Накопительный PL» (900000) тех подразделений,
у которых НИ В ОДНОЙ строке не встретился документ `А_ОтчетPL` (флаг `ЕстьДокумент`):
«Внимание: документов А_ОтчетPL по объекту нет — накопительный факт собран целиком
из регистров ЕРП и может быть занижен». Актуально для девяти объектов
(Щедро. Флекситанки, дома «Подгорцы», МД ООН 27/28, МД ІОМ).

## Параметр «Показывать служебные строки»

`ПоказатьСлужебныеСтроки` (Булево, по умолчанию Истина) — четвёртый параметр процедуры.
Управляет ТОЛЬКО строками `ВидСтроки = "Контроль"`: контролем плана и предупреждением
об отсутствии документов PL. Это диагностика для финансиста; в отчёте, который уходит
директору, флаг снимают.

Корзины «План без статьи PL» и «Бюджет без статьи PL» флагом НЕ управляются: это реальные
деньги бюджета, а не диагностика. Спрятать их — потерять деньги из итога.

## Строки без структуры PL

Строка, у которой не определилась ни группа, ни специальный код:

- если строка стоит в колонке «План итого» (`КолонкаСорт = 900100`) →
  `ВидСтроки = "ПланБезСтатьиPL"`, сорт 910 (непокрытая ДДС бюджета);
- иначе → «Вне структуры PL», сорт 900 (аномалия ЕРП: ДДС или СтатьяДоходов не привязаны
  ни к одной `А_Статьи_PL`).

Обе строки не раскрываются до статьи (`ПоказыватьСтатью = Ложь`), но остаются видимыми
и попадают в итоги — деньги не исчезают. У «Вне структуры PL» `ВидСтроки` при этом остаётся
`"Статья"` — на `"ПланБезСтатьиPL"` он меняется только у корзины плана.

## Подпись корзины «Бюджет без статьи PL»

Разметка подписывает не всё: при `ПоказИтогиПрибыли = Ложь` (настройка «отчет по фиксам»)
процедура выходит сразу после первого цикла, и у строк без статьи PL `СтрокаЛиста` остаётся
ПУСТОЙ. В отчёте они сворачиваются в БЕЗЫМЯННУЮ группу и читаются как сбой.

Поэтому `ПриКомпоновкеРезультата` проходит таблицу ещё раз, уже после разметки, и ставит
`СтрокаЛиста = «Бюджет без статьи PL»` строкам, у которых `СтатьяPL` не заполнена,
`СтрокаЛиста` пуста и при этом есть норма (`ФиксИтого <> 0`) либо это колонка плана (900100).
Только там, где разметка листа не задала свою подпись.

Скрывать такие строки нельзя: без них итог нормы не объясняется суммой видимых —
по «Производство» это 140 420,00 из 1 170 531. Подробнее —
[11_fiksy_norma_i_otklonenie.md](11_fiksy_norma_i_otklonenie.md).

## Отбор `ОставитьСтатьиСФиксами` — строго ПОСЛЕ разметки

`ОставитьСтатьиСФиксами` (строка 148) удаляет строки-статьи, по которым норма не заведена
ни в одной колонке (`ФиксИтого = 0` И `ФиксФ1 = 0` И `ФиксФ2 = 0`). Включается параметром
`ТолькоСтатьиСФиксами`. Фиксы покрывают 26 статей из ~90 — без отбора лист на две трети пустой.

Строки водопада и контроля (`ВидСтроки <> "Статья"`) не трогаются: без них лист развалится.

Порядок вызова жёсткий: сначала `ДополнитьВидКакВExcel`, потом `ОставитьСтатьиСФиксами`.
Наоборот нельзя — полный шаблон дорисует удалённые статьи обратно нулевыми строками.
