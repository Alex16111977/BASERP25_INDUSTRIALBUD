# 05. Отчёт: схема СКД, варианты, вывод

## Устройство

- **Формы:** `CommonForm.ФормаОтчета`, `ФормаНастроекОтчета`, `ФормаВариантаОтчета` — стандартная форма БСП.
- **Компоновка программная.** `ПриКомпоновкеРезультата` выставляет `СтандартнаяОбработка = Ложь` и вызывает экспортную
  `СформироватьОтчет(ДокументРезультат, ДанныеРасшифровки)`. Через COM виден только экспортный метод, приёмка идёт через него.
- **Набор данных** — объектный `Детали`, ТЗ из `ПолучитьДанные`.
- **Схема генерируется** скриптом `_Rarzrabotki/Python/test/potreba_zavershennya/gen_schema.py <путь к Template.xml>`.
  Руками XML не править: изменить генератор и сгенерировать оба носителя.

## Ресурсы — только канон «План-факт»

Каждый ресурс — колонка набора (в строках 0 или значение) плюс `totalField`. Выражение пишется **только через
`Сумма(поле набора)`**, операторы ASCII. Ссылаться на другой ресурс по имени нельзя: СКД молча берёт значение первой
записи ([LESSONS](LESSONS.md)).

| Поле | Заголовок | totalField |
|---|---|---|
| `ПланКол` / `ПланГрн` | План СС, к-сть / грн | `Сумма(…)` |
| `КупленоКол` / `КупленоГрн` | Куплено, к-сть / грн | `Сумма(…)` |
| `ПослеГрн` | Куплено після списку, грн | `Сумма(ПослеГрн)` |
| `ЗалишокСС` | Залишок за СС, грн | `Сумма(ЗалишокСС)` |
| `ПотребаКол` / `ПотребаГрн` | Потреба, к-сть (од. СС) / Потреба за списком, грн | `Сумма(…)` |
| `ЗалишокПотребы` | Залишок потреби, грн | `Сумма(ЗалишокПотребы)` |
| `ПрогнозПотреба` | Прогноз за потребою, грн | `Сумма(КупленоГрн)+Сумма(ЗалишокПотребы)` |
| `ЭкономияПотреба` | Економія за потребою, грн | `Сумма(ПланГрн)-Сумма(КупленоГрн)-Сумма(ЗалишокПотребы)` |
| `ЭкономияПроцент` | Економія, % | `ВЫБОР КОГДА Сумма(ПланГрн)=0 ТОГДА 0 ИНАЧЕ (…)/Сумма(ПланГрн)*100 КОНЕЦ` |
| `ПрогнозСС` | Прогноз за СС, грн | `Сумма(КупленоГрн)+Сумма(ЗалишокСС)` |
| `ЭкономияСС` | Економія за СС, грн | `Сумма(ПланГрн)-Сумма(КупленоГрн)-Сумма(ЗалишокСС)` |
| `РазницаМетодов` | Різниця методів, грн | `Сумма(ЗалишокСС)-Сумма(ЗалишокПотребы)` |
| `НеДокупаем` | Не докуповуємо (поза списком), грн | `Сумма(НеДокупаем)` |
| `ЦенаПлан` / `ЦенаПотребы` / `ЦенаФакт` | Ціна СС / потреби / факту | `ВЫБОР … Сумма(Грн)/Сумма(Кол) …` |
| `ОтношениеЦен` | Ціна потреби / ціна СС | `(ПотребаГрн/ПотребаКол)/(ПланГрн/ПланКол)` через `Сумма` |

Измерения:
- `Подразделение`, `ДокументПотребы`;
- `СписокПотребы` — текст «список від dd.MM.yyyy HH:mm (№ N)»;
- `ЕтапНазва`, `НазваЗагальна` — строка, по ней и группируем, чтобы дубли карточек ОН шли одной строкой;
- `ОбщееНазвание`, `ОзнакаСС`, `ВидРядка`, `Аналитика`, `Документ`, `Дома`.

В именах полей нет «і/є/ї», украинский текст только в `title`.

## Варианты (зарегистрированы в БСП)

1. **«Прогноз за потребою»** (`ПрогнозЗаПотребою`), основной.
   - Группировки: [Підрозділ, Список потреби] → Етап → Загальна назва.
   - Колонки: План, Куплено, Потреба за списком, Куплено після списку, Залишок потреби, Прогноз, Економія, %,
     Прогноз за СС, Економія за СС, Різниця методів, Не докуповуємо.
   - Если «Економія за потребою» < 0 — красный текст (#C00000) в ячейках «Економія за потребою» и «Економія, %».
     «Економія за СС» не подсвечивается.
2. **«Прогноз за потребою — детально»** (`ПрогнозЗаПотребоюДетально`).
   - Группировки: + Ознака СС → Вид рядка → Аналітика + Будинки → Документ.
   - Колонки: План к-сть/грн, Ціна СС, Куплено к-сть/грн, Ціна факту, Потреба к-сть/грн, Ціна потреби, Ціна потреби / ціна
     СС, Куплено після списку, **Залишок за СС**, Залишок потреби, Прогноз, Економія, %, Прогноз за СС, Економія за СС,
     Не докуповуємо. «Різниці методів» здесь нет.
   - Красная экономия — как в варианте 1.
   - Если `ОтношениеЦен` > 1,5 или (< 0,67 и ≠ 0) — фон #FFE0B0 в ячейках «Ціна потреби» и «Ціна потреби / ціна СС».
     Так ловятся ошибки единиц.
3. **«Не докуповуємо (поза списком)»** (`НеДокуповуемо`).
   - Группировки: [Підрозділ, Список потреби] → Загальна назва, сортировка по убыванию «Не докуповуємо».
   - Колонки: План, Куплено, Залишок за СС, Потреба за списком, Не докуповуємо.
   - Отбор группировки `НеДокупаем > 0`, вывод строки отбора выключен (`ВыводитьОтбор = DontOutput` на группировке).

**Быстрые настройки** — `ДатаОтчета` и отбор `Подразделение`. `userSettingID` уникальны в каждом варианте. В рабочей
базе пользователь сохранил свои варианты «Прогноз за потребою — детально - моя» и «Прогноз за потребою - мой вариант»;
xlsx директору 08.10 сделаны из пользовательского варианта.

## Украинский вывод независимо от языка сеанса

Платформа печатает «Параметры:», «Отбор:», «Итого» и представления ссылок («… от …») на языке сеанса. У Администратора
через COM это русский. Поэтому:

- **Шапка.** `ВыводитьПараметрыДанных` и `ВыводитьОтбор` = `НеВыводить`. Заголовок собирает `УстановитьУкраинскуюШапку`:
  «<заголовок варианта> на dd.MM.yyyy. Відбір: Підрозділ = МД IRC 2026». Виды сравнения переведены вручную
  (`ОписаниеОтбора`: «=», «у списку», «в ієрархії»…).
- **Итоги.** После вывода `ЗаменитьТекстЯчеек(ТабДок, "Итого", "Разом")`: `НайтиТекст` по ячейке целиком.
- **Документ потребы.** Группировка по тексту `СписокПотребы` («список від …»), а не по ссылке с русским «от».

## Выгрузка xlsx для директора

`_Rarzrabotki/Python/test/potreba_zavershennya/vygruzka_xlsx.py --date ГГГГ-ММ-ДД --podr "<подразделение>" --variant <ключ> --out <файл.xlsx>`.

- Формирует отчёт **путём формы БСП** — `ВариантыОтчетов.СформироватьОтчет` с быстрыми настройками — и пишет xlsx.
- `--variant` — только ключ предопределённого варианта (`ПрогнозЗаПотребою`, `ПрогнозЗаПотребоюДетально`,
  `НеДокуповуемо`). Пользовательские варианты скрипт не формирует.
- `ТабличныйДокумент.Записать` выполняет серверный процесс 1С, поэтому писать надо сразу в целевую папку: временная
  папка пользователя ему недоступна.
- Итоги для письма брать **только из сохранённого xlsx** (перечитать файл), не пересчитывать.

Письмо 08.10.2026 с объяснением колонок: `_Rarzrabotki/Производство домов/Новая папка/Лист_директору_прогноз_за_потребою_08-10-2026.html`.

## Поля оплаты (15.10.2026)

| Поле | Заголовок | Итог |
|---|---|---|
| `ОплаченоНеНадійшло` | Оплачено, не надійшло, грн | `Сумма(ОплаченоНеНадійшло)` |
| `Оплачено` | Оплачено (закупівлі), грн | `Сумма(Оплачено)` |
| `Борг` | Борг постачальнику, грн | `Сумма(Борг)` |

- В прогноз и экономию не входят.
- Выведены в вариантах «Прогноз за потребою» и «— детально» после «Економія за СС»; в «Не докуповуємо» их нет.
- Измерение `Документ` дополнено типом `ДокументСсылка.ЗаказПоставщику` (строки счетов).
- Схема по-прежнему из `gen_schema.py`.
- Пользовательский вариант «Прогноз за потребою — детально - моя» хранится в базе и генератором не перезаписывается.
  Колонки в него добавлены скриптом `tovary_schetov_kazna/obnovit_moy_variant.py` (через API компоновки:
  `Выбор.Элементы.Вставить`, тип — через `Новый ОписаниеТипов(...).Типы()[0]`, так как функции `Тип` в COM нет).
