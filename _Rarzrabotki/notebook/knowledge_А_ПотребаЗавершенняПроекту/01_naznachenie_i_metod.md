# 01. Назначение и метод (экономика)

## Зачем

Прежний отчёт «План-факт» (`А_ПланФактныйПроизводствоПолный`, вариант «План на факт») считает прогноз так: всё, что не
докуплено до количества СС, ещё будет куплено по цене СС. Директор же знает, что докупать будем только то, что в его
списке, а остальное больше не покупаем. На 08.10.2026 это давало по IRC 3,5 % экономии вместо 13,2 %.

Директор присылает список (файл Excel по проектам): позиция, «вірна назва згідно СС», количество, цена, сумма, дома.
Документ хранит этот список, отчёт считает экономию по нему.

## Формулы

| | «План-факт» (старый метод) | «За потребою» (новый) |
|---|---|---|
| Остаток к покупке | недокупленное **количество** до СС × **цена СС** по каждой загальній назві (`ПланНаФактГрн`) | **сумма из списка директора** (с учётом закупок после даты списка) |
| Прогноз | Куплено + Залишок за СС | Куплено + Залишок потреби |
| Экономия | План СС − Прогноз | План СС − Прогноз |

**Главная колонка — «Економія за потребою».** «Прогноз за СС / Економія за СС» оставлены только для сравнения.

## Свойства, которые код обязан сохранить

1. **На дату списка итог проекта не зависит от сопоставления названий:** Прогноз = Σ Куплено + Σ Потреба. После даты
   списка зависит — через списание закупками (п. 3). Строки без загальної назви (текст) не списываются никогда.
2. **Список — это остаток к покупке на момент списка, а не полная потребность.** Проверено на данных:
   - кушетка, столик, шафа: 10 куплено + 3 в списке = 13 по плану;
   - обігрівач IRC: 45 + 28 = 73;
   - обігрівач Адмін: 12 + 12 = 24.
3. **Закупки после момента списка списывают потребу.** Граница — **дата и время документа**, а не конец дня: накладные
   приходят пачками вечером, а список директора составлен утром.
   - Без этого отчёт через неделю покажет и закупку, и ту же строку списка.
   - На дату списка списания нет, поэтому Прогноз = Куплено + Потреба.
4. **Всё в гривнах с НДС.**
   - План СС с НДС; факт закупок — `СебестоимостьТоваров.Стоимость`, тоже с НДС.
   - Цены директора с НДС, это подтверждено документами закупки: кондиционер IRC 13 915,83 без НДС → 16 699 с НДС, у директора 16 699.
   - Если файл когда-нибудь придёт без НДС, в форме есть флажок «Ціни у файлі без ПДВ (при завантаженні +20 %)».
5. **Знак.** Экономия больше нуля — экономия, меньше нуля — перерасход. В «План-факт» знак обратный: `ОтклонениеПрогнозГрн` = Прогноз − План.
6. **«Не докуповуємо (поза списком)»** — то, от покупки чего директор фактически отказывается:
   - залишок за СС по загальним назвам, которых нет в списке;
   - недокупленное по СС количество сверх списка по позициям из списка. Пример: ОСБ Адмін — по СС не докуплено
     386 листов, в списке 22, значит 364 листа «не докупаем».

## План × количество домов, список — как есть

- **План СС** умножен на количество домов внутри «План-факт». Норма в ТЧ СС заложена на 1 дом:
  - IRC: СС «15 м» × 6 + СС «30 м» × 7 = 13 домов;
  - Адмін: × 4 дома.
- **Список директора не умножается.** Количество в строке — итог для домов из колонки «Будинок». Например, кондиционеры
  IRC — 5 шт на дома 3–7. Колонка «Будинок» только справочная.

## Что убрано из списка

Строки «Монтаж кондиціонерів» (IRC 35 000, Адмін 112 000) пользователь 08.10.2026 удалил из документов. Это работы, а не
материалы: в СС монтаж заложен в ТЧ «Работы», а отчёт сравнивает материалы с материальной частью сметы. Загрузчик такие
строки помечает предупреждением «Робота, не матеріал…», но не удаляет — решение за пользователем.

## Как читать экономию

Экономия верна при условии, что всё в «Не докуповуємо» действительно не нужно. Как показал разбор 08.10.2026
([FINDINGS](FINDINGS.md)), «Не докуповуємо» неоднородно. В нём смешаны:

- позиции, уже купленные под другой загальною назвою (фиктивный недокуп);
- «бумажная» экономия из-за ошибок цены или единицы в СС;
- позиции, без которых дом не сдать (обшивка, кабель, молниезащита, пожарная безопасность).

Это вопрос качества СС и справочника загальних назв, а не отчёта. Отчёт делает это видимым.
