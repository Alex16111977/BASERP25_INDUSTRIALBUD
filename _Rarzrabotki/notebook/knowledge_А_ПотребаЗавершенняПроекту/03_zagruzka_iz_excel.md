# 03. Загрузка списка из Excel

Код — модуль менеджера документа: `ПрочитатьФайлПотребы` разбирает файл, `ЗаполнитьПотребу` подбирает загальні назви.
Python-эталон разбора — `_Rarzrabotki/Python/test/potreba_zavershennya/parse_file_etalon.py`: независимая реализация на
openpyxl. На файле директора 08.10.2026 разбор 1С совпал с ним по всем 46 строкам и 9 полям (`НазваСС`, `НазваТовару`,
`ОдСС`, `ОбъемСС`, `Од`, `КолФайла`, `Дома`, `ЦенаФайла`, `Стоимость`); тексты предупреждений не сравниваются.

## Формат файла директора (эталон)

`_Rarzrabotki/Производство домов/1Копия потреба Адмін та Ірс.xlsx`:

- **`Лист1` содержит разделы.** Строка-маркер (объединённая A:J) → строка заголовков → строки данных → итоговая строка
  **без подписи**, только `J = SUM(...)`. Маркеры:
  - «Проект ІRS» — І кириллическая, R и S латинские;
  - «Проект Адмін».
- **Колонки:**

  | Колонка | Заголовок | Примечание |
  |---|---|---|
  | A | Назва товару | |
  | B | Вірна назва Згідно СС | |
  | C | (скрыта, дублирует F) | |
  | D | Од вим згідно СС | |
  | E | Вірний обєм згідно СС | формула |
  | F | Одиниця виміру | |
  | G | К-сть | |
  | H | Будинок | |
  | I | Ціна | |
  | J | Вартість | |

  В заголовках бывают двойные и хвостовые пробелы.
- **Листы «Заг назви IRC/OOH»** — выгрузка ERP «загальна назва → номенклатура», это не данные. Разбор их отсекает:
  в шапке нет «Ціна/Вартість».

## Чтение (`ПрочитатьФайлПотребы`)

- **Только `.xlsx`.** `.xls` — отказ с понятным текстом.
- **Порядок чтения:**
  - двоичные данные пишутся во временный файл;
  - читаются `ТабличныйДокумент.Прочитать(..., СпособЧтенияЗначенийТабличногоДокумента.Значение)`;
  - временный файл и хранилище удаляются в `Попытка`.

  Excel и COM не нужны. Ошибка чтения — «Не вдалося прочитати файл. Якщо він відкритий в Excel — збережіть і повторіть.»
  плюс `КраткоеПредставлениеОшибки`.
- **Листы.** `Прочитать` склеивает все видимые листы. Каждый лист — именованная область с типом `Строки`, её имя искажено
  (`Заг назви IRC` → `Заг_назви_IRC`). Номер строки файла = строка табличного документа − `Область.Верх` + 1.
- **Числа и текст.** Числа брать из `.Значение`: в `.Текст` неразрывный пробел и округление по формату ячейки. Текст —
  из `.Текст`. «Будинок» — из `.Текст`: дробь 6.7 в `.Текст` даёт «6,7».
- **Нормализация N(s):**
  - NBSP → пробел, апострофы `’ ʼ ‘ ´ \`` → `'`, схлопнуть пробелы;
  - `СокрЛП`, `НРег`, латинская i → і;
  - для заголовков и маркеров дополнительно убрать `'` и `-`.
- **Маркер раздела** — единственная непустая ячейка строки, начинающаяся с «проект». Маркеров нет — весь лист считается
  одним разделом.
- **Шапка** — в 1–3 строках после маркера (без маркеров — в первых 20), распознано не меньше 4 полей:

  | Поле | Признак (после нормализации) |
  |---|---|
  | НазваСС | «вірна назва», «загальна назва», «назва згідно сс», «назва сс» |
  | НазваТовару | «назва товару», «найменування» или заголовок ровно «товар» |
  | ОбъемСС | («обєм», «обсяг», «кількість», «ксть») + слово «сс» |
  | ОдСС | («од», «одиниц») + «сс» |
  | Од | «одиниц» / «од вим» без «сс»; ближайшая **слева** от К-сть (F, а не скрытая C) |
  | КолФайла | «ксть», «кількість», «кть», «колво» без «сс» |
  | Дома | «будин», «дім» |
  | ЦенаФайла | «ціна» |
  | Стоимость | «вартість», «сума» |

  - Обязательно: (НазваСС или НазваТовару) и (ОбъемСС или КолФайла) и (Стоимость или ЦенаФайла).
  - «без пдв» в заголовке «Ціна» или «Вартість/Сума» → флажок «без НДС». Флажок только включается, сам не снимается.
    При загрузке с флажком `Цена` и `Сумма` умножаются на 1,2.
- **Данные** — до следующего маркера, конца листа или трёх пустых строк подряд.
  - Итоговая строка: обе «Назви» пусты и J — число, **или** в строке есть «разом», «итого», «всього», «усього».
  - Строка данных: есть назва и хотя бы одно число среди E, G, I, J.
- **Значения строки:**
  - `Сумма` = Окр(J, 2); если J нет — Окр(G × I, 2). Если |J − G×I| > 0,01, предупреждение «Вартість ≠ К-сть × Ціна».
  - `Цена` = Окр(I, 2); если I нет — Окр(Сумма / G, 2) при G ≠ 0, иначе 0.
  - `КоличествоСС` = E, если E > 0. Иначе G, если единицы D и F совпадают. Иначе 0 и предупреждение «Не визначено кількість в од. СС».
  - `Дома` — разделители `. ; пробел` → `,`.
- **Контроль ИТОГО.** |Σ строк − Окр(ИТОГО)| > 0,01 × N строк → **ошибка, ТЧ не заполняется**. Это защищает от жёсткого
  диапазона `SUM(J3:J26)` при вставке строки. Округление по строкам допустимо: Адмін Σ 710 208,30 при ИТОГО 710 208,31.

## Подбор загальної назви (`ЗаполнитьПотребу`)

Ключ имени — `СокрЛП`, вторым проходом — N(имя).

**Пустая «Вірна назва згідно СС»** → ОН не подбирается, предупреждение «Немає назви згідно СС — у звіті поза СС».

**Складена назва «A / B»** (например, «Вікно металопластикове / Двері металопластикові») — отдельная ветка, до шагов 1–3:
- части ищутся **только среди ОН СС проекта** (как шаг 1), по справочнику не ищутся;
- строка относится к части с наибольшим планом;
- предупреждение «Складена назва: віднесено до «X», покриває також: …» — в списке все найденные части, включая выбранную;
- ни одной части нет в СС — ОН пустой и «Складена назва — частин немає в СС проєкту, оберіть загальну назву вручну»;
- отчёт объединяет группы частей в один набор списания ([04](04_otchet_raschet.md)).

Обычная назва:

1. **Среди ОН из строк `Комплектующие` активных СС подразделения документа.** При дублях имени берётся карточка с
   наибольшей суммой плана. Внутри одного проекта неоднозначных имён нет, а между проектами есть — например, «Кутики
   (металопрокат)». Поэтому сначала ищем в своём проекте.
2. **По всему справочнику** среди непомеченных. Приоритет: заполнена `Единица`, затем `ОсновнаяНоменклатура`, затем меньший
   код. Предупреждение «Є в довіднику, але немає в СС проєкту».
3. **Не найдено.** Если N начинается с «монтаж» — «Робота, не матеріал: у плані матеріалів СС бюджету немає (він у роботах
   СС), закупівлею не списується». Иначе — «Не знайдено в довіднику — у звіті поза СС». ОН остаётся пустым.

**По «Назва товару» через Номенклатуру автоматически не ищем:** это даёт неверные ОН, например «Лінолеум» → «Лінолеум стіни».

`ЕдиницаСС` — единица плана (`ЕдиницаОбщееНазвание`) этой ОН в СС проекта с наибольшей суммой, иначе `ОН.Единица`. Если
единица файла (D) после нормализации не совпадает с ней — предупреждение «Одиниця у файлі «D» ≠ одиниці СС «X»». Это не
блокирует загрузку: деньги главные, количество справочное. Например, «м3» против «куб».
