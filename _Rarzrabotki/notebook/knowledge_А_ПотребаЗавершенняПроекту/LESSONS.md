# LESSONS — грабли

Каждая стоила отладки. Формат: что произошло → почему → как правильно.

> Самые дорогие — §1 (СКД молча берёт первую запись), §5 (ключ `Количество`) и §10 (перезапись main выгрузкой).

---

## Отчёт и СКД

**§1. Ресурс, который ссылается на другой ресурс, считается неверно и без ошибки.**
Выражение `Сумма(ПланГрн) − Прогноз` компонуется, но даёт значение первой детальной записи, а не итог. Ресурс без
поля набора молча пропадает из вывода.
→ Каждый ресурс — колонка набора плюс `totalField` только через `Сумма(поле набора)`; операторы ASCII `-` и `*`, не «−».

**§2. Платформенный вывод на языке сеанса.** Через COM сеанс Администратора русский, поэтому в xlsx директору попали
«Параметры:», «Отбор:», «Итого», «… от …».
→ Шапку собирать кодом (`ВыводитьПараметрыДанных`/`ВыводитьОтбор` = НеВыводить), «Итого» → «Разом» через `НайтиТекст`,
документ выводить своим текстом («список від …»).

**§3. В элементе пользовательских настроек отбора нет `ЛевоеЗначение`.**
«Свойство не поддерживается элементом коллекции пользовательских настроек».
→ Искать по `ИдентификаторПользовательскойНастройки`, который берётся из `Настройки.Отбор.Элементы`, где `ЛевоеЗначение` есть.

**§4. `ТабличныйДокумент.Записать` из результата БСП пишет серверный процесс 1С.**
Файл в TEMP пользователя получился недоступным: PermissionError.
→ Писать сразу в целевую папку.

## BSL

**§5. Ключ `Количество` в `Структура`.** Через COM `стр.Количество` читается как **метод** `Структура.Количество()`,
а не как значение ключа. В BSL это работает, но путает.
→ Не называть ключи как методы `Структура`: в строке разбора ключ `КолФайла`, в ТЧ значение переносится явно.

**§6. Локальная переменная `Закупки` — это имя общего модуля ERP.**
«Поле объекта недоступно для записи (Закупки)».
→ Перед загрузкой сверять локальные имена с `ls CommonModules`. Переменную переименовали в `МассивЗакупок`.

**§7. `WebЦвета.Бордовый` в платформе нет.**
Форма документа падала при открытии: «Поле объекта не обнаружено (Бордовый)». COM этого не ловит: модуль формы
компилируется только при открытии.
→ Имена констант платформы проверять COM-пробой, например `getattr(b.WebЦвета, "ТемноКрасный")`. Работают
`БледноЗолотистый`, `ТемноКрасный`, `Кирпичный`, `ТемноБордовый`.

**§8. Буквы «і/є/ї» в идентификаторах.**
→ Ключи структур и имена полей — русскими буквами (`Стоимость`, `ЦенаФайла`, `ДатаОтчета`, `ПослеГрн`, `НеДокупаем`).
Украинский текст — только в синонимах и заголовках.

## COM и Python

**§9. Глобальных `Формат`/`Format` через COM нет, а наивная Python-дата, переданная в 1С, сдвигается на −3 ч.**
Даты, прочитанные из 1С, приходят с `tzinfo` и сами по себе не сдвинуты, но сравнивать их с наивными нельзя.
→ Дату для сравнения брать запросом (`ГОД/МЕСЯЦ/ДЕНЬ/ЧАС/МИНУТА/СЕКУНДА`) → наивный `datetime`. Даты в 1С передавать +3 ч
(так `priemka.py` восстанавливает дату документа после отката). Документы между базами переносить XDTO-сериализацией,
а не через Python-даты.

## Загрузка конфигурации и файлы

**§10. Основной каталог перезаписали выгрузкой из Конфигуратора.**
08.10 в 16:19 пользователь выгрузил новую базу в main. Правка обработки (`Выполнить` → `ВыполнитьОбработку`) затёрлась,
и загрузилась старая версия.
→ Перед загрузкой сверять свой файл с текущим main и править уже свежую выгрузку точечно.

**§11. `meta-compile` и `role-compile` переформатируют весь `Configuration.xml`.**
→ Снять копию до запуска, восстановить после и вставить одну строку `<Document>`/`<Role>`/`<Report>` (count = 1).
`git checkout` не использовать: он сотрёт другие вставки. `role-compile` пишет синоним только `ru` — дописать `uk`.

**§12. `template-add` переписывает XML отчёта с пробелом в пустых тегах** (`<DefaultForm />`).
→ Заменять регулярным выражением `<Тег\s*/>`.

**§13. Полный `/CheckModules` по BaseERP идёт минутами и цепляет чужие ошибки.**
Например, `Обработка.СозданиеСотрудниковИзФизическихЛиц`: процедура `Выполнить` и латиница в `ГоловнаяОрganизацияСсылка`;
исправлено 08.10.
→ По указанию пользователя проверять точечно: COM `Создать()` / `СоздатьДокумент()`, загрузка и обновление — одной
командой `db-load-xml … -UpdateDB`.

**§14. Hook запрещает Edit/Write файлов основного каталога из worktree.**
→ Писать в worktree и копировать `cp`, затем `cmp`. Скрипты, которых нет в git (гейт `erp_preflight_config.py`),
скопировать в worktree, поправить и вернуть.

**§15. Git Bash превращает аргументы `/путь` в `C:/Program Files/Git/путь`**: так сломался `git sparse-checkout set`.
→ `export MSYS_NO_PATHCONV=1`.

**§16. Скриптовая правка Python-строк с `\t`/`\n` через heredoc не совпадает с исходником** из-за экранирования.
→ Многострочные правки делать Edit-инструментом, а скриптовые — с `assert count == 1`.

## Экономика

**§17. Количество в группе из разнородных позиций ничего не значит.** Септик (кольца, днища, люки), двери (полотна,
лиштва, петли), сигнализация (централь и датчики), метизы М10–М48.
→ Отчёт не должен делать по ним выводов «куплено всё»: списание по количеству только при однородности (±5 %).
Источник проблемы — СС и карточки номенклатуры ([FINDINGS](FINDINGS.md)).

**§18. Итоги для письма — только из сохранённого xlsx.** Ничего не пересчитывать
(память `pismo_direktoru_format_0909_faktory`).

## 15.10.2026 — товары счетов и оплата

- **`НомерСтроки` нельзя называть измерение регистра сведений** («Недопустимое имя измерения»). Пакетная загрузка при этом
  не падает, а **висит** на диалоге у пользователя. Лог пустой, пока диалог не закрыт.
- **Построчное «не надійшло» без ограничения по заказу завышало итог в 8 раз** (9,04 млн вместо 1,03 млн). Строки счёта
  без номенклатуры не стыкуются с поступлениями по товару. Итог по заказу ограничивать «Счёт − Получено».
- **Сумма счёта Казны — с ПДВ**, а в Excel счетов часто без ПДВ: 98 из 131 «расхождений» снялись множителем 1,2.
  Бывает и ПДВ 7% (АТОН), и ФОП без ПДВ.
- **Конкурентный лист** — несколько поставщиков в одном файле: брать блок с итогом = сумме счёта.
- **xlsx из 1С без `sharedStrings.xml`**: openpyxl падает — пересохранять через Excel COM.
- В обычном запросе `Номенклатура.А_ОбщееНазваниеНоменклатуры` доступно (ограничение было только в СКД «План-факт»).
