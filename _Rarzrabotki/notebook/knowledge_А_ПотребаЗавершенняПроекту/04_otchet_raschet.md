# 04. Отчёт: расчёт данных (`ПолучитьДанные`)

Модуль `Reports/А_ПрогнозВиконанняССЗаПотребою/Ext/ObjectModule.bsl`, одинаковый у `.erf`. Привилегированный режим
включается в начале `СформироватьОтчет` на весь расчёт и компоновку: запросы к ПТУ и `Этап.Наименование` не должны зависеть
от прав пользователя.

## Параметр

`ДатаОтчета` (Дата). Пусто — текущая дата сеанса. Форма БСП передаёт значение как `СтандартнаяДатаНачала`, поэтому
`ЗначениеДатыОтчета` разворачивает его в `.Дата`. Момент отчёта = `КонецДня(ДатаОтчета)`. Отбор по подразделению —
штатный отбор СКД по полю `Подразделение`: внешний набор он фильтрует сам.

## Шаги

1. **Документы потребы** (`ПоследниеДокументыПотребы`). На каждое подразделение берётся последний проведённый и не
   помеченный документ с `Дата <= момент`, порядок `МоментВремени УБЫВ`. Момент списка = **`Док.Дата` с временем**.
   Проекты без документа в отчёт не попадают.
2. **План и факт.** `Отчеты.А_ПланФактныйПроизводствоПолный.Создать().ПолучитьДанные(Новый СтандартныйПериод(Дата(2000,1,1), момент))`:
   - строки с `Блок = "2. Матеріали"` и только подразделений из шага 1;
   - вид строки «План-факт» определяется по `Документ`: план — `СправочникСсылка.А_СтруктураСебестоимости`; закупка —
     заполненная `ДокументСсылка.ПриобретениеТоваровУслуг`; синтетика «залишок за СС» — пустая ПТУ с `ПланНаФактГрн`;
   - даты закупок — одним запросом по ПТУ. Закупка «після списку», если `ПТУ.Дата > момент списка`.
3. **Группы** (`КлючГруппы`) — копия `КлючГруппыПланНаФакт` «План-факт», она не экспортная:
   - `UUID(Подразделение) + "|ОН|" + СокрЛП(ОН.Наименование)`;
   - без ОН: `"|НОМ|" + UUID(Номенклатура)`, иначе `"|НОМТЕКСТ|" + ВРег(СокрЛП(Аналитика))`;
   - строка потребы без ОН: `"|ТЕКСТ|" + N(НазваниеСС или НазваниеТовара)`.

   По группе копятся: `ПланКол`, `ПланГрн`, `КупленоКол`, `КупленоГрн`, `ПослеКол`, `ПослеГрн`, `ЗалишокСС`
   (Σ `ПланНаФактГрн`), `ПотребаГрн`, `ПотребаКолСС`, `ПотребаКолФайла`; единицы закупок «після»; единица и этап плановой
   строки с наибольшим `ПланГрн`.
4. **Наборы списания** (`СвязатьСкладеныеНазвания`). Только для строк потребы со «/» в `НазваниеСС` и заполненной ОН:
   группа каждой части (ключ `…|ОН|` + часть **как есть**, без нормализации) объединяется (union-find) с группой строки.
   Закупки любой части списывают эту строку.
5. **Залишок потреби набора** (`РассчитатьЗалишокПотребы`):
   - `ПотребаГрн = 0` → 0;
   - `ПослеГрн = 0` → `ПотребаГрн`;
   - **по количеству** (`ЗалишокПоКоличеству`, только набор из одной группы), если выполнено всё:
     1. `ПослеКол > 0`, у закупок «після» ровно одна единица, и она равна N(ЕдиницаСС) **последней** строки потребы
        при `ПотребаКолСС > 0` (тогда количество = `КоличествоСС`) или N(Единица) при `ПотребаКолФайла > 0`
        (тогда `Количество`);
     2. в строках потребы нет предупреждений «Одиниця…» / «…кількість…»;
     3. цена каждой строки потребы в пределах ±5 % от средней — однородность. Например, «Сигналізація» из 4 разных
        изделий сюда не пройдёт;
     4. средняя цена закупок «після» в [0,67; 1,5] × цены потребы;
     5. для `КоличествоСС`, если единица плана та же: цена потребы в [0,67; 1,5] × цены СС. Ловит ошибку единиц, как
        у плинтуса r42.

     Тогда `Макс(0, ПотребаКол − ПослеКол) × ПотребаГрн / ПотребаКол`;
   - иначе **по деньгам**: `Макс(0, ПотребаГрн − ПослеГрн)`;
   - результат Окр(2) распределяется по группам набора пропорционально их потребе, копеечный остаток — последней.

   Это та же логика, что правила 2 и 4 `ЗаполнитьПланНаФакт`, только база — список директора, а не СС.
6. **«Не докуповуємо» (`НеДокупаем`):**
   - набор из одной группы без потребы → `ЗалишокСС`;
   - одна группа с потребой → `Макс(0, Окр(ЗалишокСС − КолСС_ост × ПланГрн / ПланКол, 2))`, где
     `КолСС_ост = ПотребаКолСС × ЗалишокПотребы / ПотребаГрн`. Условия: есть план, `ПланКол > 0`, `ПотребаКолСС > 0` и
     `ЕдиницаСС` **всех** строк потребы = единица плана (`ЕдиницаПотребыКакВПлане`). Хоть одно не выполнено → 0.
     Так «Не докуповуємо» включает и частичный недокуп: потреба меньше остатка СС по количеству;
   - группы составных наборов → 0, они покрыты складеною строкою.
7. **Признаки** (`ЗаполнитьПризнакиГрупп`):
   - `ОзнакаСС`:
     - «У кошторисі СС» — ОН есть в `Комплектующие` СС проекта, даже с планом 0; при нулевом плане с пометкой «(план 0)»;
     - «Поза СС: є в довіднику»;
     - «Поза СС: робота» — назва начинается с «монтаж»;
     - «Поза СС: немає в довіднику».
   - `ЕтапНазва` — этап плановой строки с наибольшим `ПланГрн`; план есть, а этап пустой — «Без етапу». Если плановых
     строк нет — «Поза кошторисом СС».
8. **Строки набора** (`ВывестиСтроки`). `ДокументПотребы` и `СписокПотребы` проставляются в **каждой** строке, иначе
   проект распался бы на две группы:

   | `ВидРядка` | Из чего | Ресурсы |
   |---|---|---|
   | «План СС» | плановые строки | ПланКол, ПланГрн |
   | «Закупівля» / «Закупівля після списку» | закупки до или после момента списка | КупленоКол, КупленоГрн, ПослеГрн |
   | «Залишок за СС» | синтетика «План-факт» | ЗалишокСС |
   | «Потреба» | строки документа: Аналитика = Назва товару, Документ = документ потребы, Дома | ПотребаКол (= КоличествоСС), ПотребаГрн |
   | «Залишок потреби» | одна на группу, только если `ЗалишокПотребы ≠ 0` или `НеДокупаем ≠ 0` | ЗалишокПотребы, НеДокупаем |

Колонки результата (`СоздатьПустуюТаблицу`):
- измерения: `Подразделение`, `ДокументПотребы`, `СписокПотребы`, `ЕтапНазва`, `НазваЗагальна`, `ОбщееНазвание`,
  `ОзнакаСС`, `ВидРядка`, `Аналитика`, `Документ` (ПТУ | СС | потреба), `Дома`;
- ресурсы — числа, в том числе вычисляемые с нулём в строках, их считает `totalField` ([05](05_otchet_skd_i_vyvod.md)).

## Зачем именно так

- **План и факт — только из `ПолучитьДанные`.** Другой источник дал бы цифры, отличные от «План-факт», и письма
  директору разошлись бы. Эталон «Прогноз за СС» = «План на факт» проверяется приёмкой.
- **Граница — момент документа, а не конец дня.** Накладные приходят вечером, а список составлен утром.
- **Однородность при списании по количеству.** «Сигналізація виявлення диму» Адміна — четыре разных изделия в одной
  группе: централь 21 728,40, ручний сповіщувач 2 041,20, оповіщувач 4 210,80, акумулятор 2 284,80. Средняя цена по
  такой группе против закупки одной централи (29 999) давала ошибку до десятков тысяч ([LESSONS §17](LESSONS.md)).
