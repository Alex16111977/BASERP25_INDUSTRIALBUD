# 08. Как работать и как дорабатывать

## Пользователю: новый список директора

1. **Создать документ.** «Виробництво → Внутрішньоцеховий облік → Потреба на завершення проєкту → Створити».
   - **Дата** = момент, на который составлен список. От него отчёт отсчитывает «закупки после списка».
   - **«Підрозділ проєкту»** — подразделение, на котором ведётся СС проекта («МД IRC 2026», «МД ООН Админ»).
2. **Нажать «Заповнити з Excel» и выбрать файл.**
   - Если в файле несколько разделов «Проект …», выбрать свой.
   - Если ТЧ уже заполнена — подтвердить замену.
   - Если цены в файле без НДС, перед загрузкой поставить флажок «Ціни у файлі без ПДВ (при завантаженні +20 %)».
     Если в заголовке «Ціна»/«Вартість» написано «без ПДВ», флажок включится сам.
3. **Просмотреть строки:**
   - **бледно-золотистый фон** ячеек «Загальна назва» и «Назва згідно СС» — строка без загальної назви, её выбрать
     вручную, если нужно;
   - **тёмно-красный текст** «Попередження» — не та единица, складена назва, работа вместо материала.

   Работы — например, «Монтаж кондиціонерів» — удалить: это не материалы.
4. **Провести** — значит «список затверджено». Непроведённый документ — черновик, отчёт его не видит.
5. **Отчёт «Прогноз виконання СС за потребою»:** дата и підрозділ. Главная колонка — «Економія за потребою».
   Для директора удобнее выгрузить вариант «Не докуповуємо»: это то, от чего он отказывается, и это стоит подтвердить.
6. **Новый список — новый документ.** Старые остаются историей, отчёт берёт последний проведённый на дату.

Доступ: роли `А_ПотребаЗавершенняПроектуРедактирование` и `ПодсистемаПроизводство`.

## Разработчику: правила доработки

- **Два носителя отчёта.** Боевой — встроенный `Reports/…`, внешний `.erf` — для быстрых итераций.
  - Модуль `Ext/ObjectModule.bsl` одинаков в обоих.
  - Схема — из `gen_schema.py`, сгенерировать в оба `…/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml`.
  - Корневой `Templates/*.xml` у каждого носителя свой: там свой uuid, не копировать.
  - Во встроенном отчёте main схема может быть пересериализована платформой после выгрузки из Конфигуратора. Разница
    формата — не дефект.
- **Сборка `.erf`.** `epf-build.ps1` против BaseERP (localhost), исходники изолировать во временный каталог.
  - Сборка через BuhBud вырежет ссылочные типы, которых там нет.
  - Если открыт Конфигуратор — ждать: сборка и загрузка падают на блокировке.
- **План и факт брать только из `ПолучитьДанные` «План-факт».** Если меняется ключ `КлючГруппыПланНаФакт` в «План-факт»,
  повторить его в `КлючГруппы` этого отчёта: функция не экспортная, её код продублирован.
- **Новый ресурс отчёта:**
  1. колонка в `СоздатьПустуюТаблицу`;
  2. поле в `gen_schema.py` (RES), `totalField` только через `Сумма(поле набора)`;
  3. добавить в варианты;
  4. сгенерировать оба носителя;
  5. собрать `.erf`, загрузить встроенный, прогнать `priemka.py` на обоих.
- **Новая колонка в ТЧ документа:** `meta-edit`, затем форма через `gen_forms.py` или `form-edit`, затем модуль менеджера.
  - Если колонка заполняется из файла — правило в `ПолеЗаголовка` и в `parse_file_etalon.py`, чтобы эталон и 1С совпадали.
  - Ключ структуры строки не называть как метод `Структура` (`Количество`!) — [LESSONS](LESSONS.md).
- **Загрузка в базу** — по [06](06_zagruzka_i_perenos.md): Partial, гейт, точечная проверка, `db-update`. Полный
  `/CheckModules` по базе не гонять.
- **Любой новый запрос** — сначала `q_zaprosy.py` (Rule #-1).
- **После правки** — `priemka.py --builtin` (и `--erf`). Эталонов-чисел нет, только инварианты: сумма и дата документа
  для проверки отката читаются из базы. Дата отчёта по умолчанию 2026-10-08 — для нового списка передать `--date`.
