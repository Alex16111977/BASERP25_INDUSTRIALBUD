## `priemka.py` — что проверяется (только инварианты)

**[1] На дату отчёта, по каждому проекту:**
- Σ План, Σ Куплено, Σ Залишок за СС = суммам `ПолучитьДанные` «План-факт»; «Прогноз за СС» = Σ `ПрогнозГрн` «План-факт».
- Σ Потреба = `СуммаДокумента`.
- На дату списка: «Куплено після списку» = 0 и «Залишок потреби» = «Потреба» в каждой группе. **Может законно не
  пройти**, если в базе есть закупки, датированные позже момента списка того же дня.
- 0 ≤ «Не докуповуємо» ≤ «Залишок за СС»; в группах без потребы «Не докуповуємо» = «Залишок за СС».
- Части складеної назви Адміна («Вікно…», «Двері…») — «Не докуповуємо» = 0.
- В отчёте ровно два проекта — подразделения документов потребы.
- Документ потребы одинаков во всех строках проекта.

**[2] Списание (в транзакции с откатом):**
- Дата документа IRC ставится на день раньше последней закупки по ОН списка (в старой базе 08.10 это 27.09.2026 12:00,
  в рабочей — 02.10.2026 12:00). Закупок нет — SKIP.
- Есть группы с закупками после списка; 0 ≤ Залишок ≤ Потреба; в группах без закупок после списка Залишок = Потреба.
- Залишок = **независимый пересчёт на Python** (`expected_remainders`, ветки «кількість» и «гроші»).
- Без ОН потреба не списывается (Σ залишку = Σ потреби).
- На дату списка итог прогноза не зависит от сопоставления ОН.
- После отката документ не изменился: сумма и дата сверяются с прочитанными **до** транзакции (жёстких чисел нет), дата
  восстанавливается из того же чтения.

**[3] Компоновка:**
- у всех полей набора задан тип;
- все 3 варианта дают таблицу;
- пустая дата (так открывается форма) работает;
- дата как `СтандартнаяДатаНачала` (как в форме БСП) работает.

Путь формы БСП дополнительно проверяет `vygruzka_xlsx.py`: он формирует отчёт через `ВариантыОтчетов.СформироватьОтчет`.

**Ориентир** (печать, не assert) — цифры **первого** письма директору: IRC — прогноз 9 808 849,48, экономия
1 487 875,76, старая база, с монтажом. Цифры дрейфуют вместе с закупками и правками документов, жёстких чисел в assert
