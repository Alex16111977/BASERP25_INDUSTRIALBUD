## 🎯 МЕТА ВСЬОЇ СИСТЕМИ

Перенести фактично виплачену зарплату з **Казни (BuhKazn)** + бухгалтерські **податки (ZUP_1)** + управлінські **нарахування (ZUP_2)** в регламентний облік ERP — спочатку у проміжний документ **`А_ОтражениеЗПпоКазне`**, потім у підлеглий **`Документ.НачислениеЗарплаты`** (для проведення в реєстри розрахунку), і далі у **`Документ.ОтражениеЗарплатыВФинансовомУчете`** (для проведення у бухоблік на рахунки 661/65/642 тощо).

## 🔧 ПРОЦЕДУРИ МОДУЛЯ `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`

### Основні (експортовані — викликаються з форми)

#### 1. `ЗаполнитьОтражениеЗарплатыВФинансовомУчетеИзБазЗП()` (рядок ~29)
**Що робить**: Завантажує `РаспределениеКазна` з бази BuhKazn + виконує `ПривязатьСотрудников`.

Викликає послідовно:
1. `ЗагрузитьРаспределениеКазна_ОтражениеЗП()` — основна логіка
2. `ПривязатьСотрудников_ОтражениеЗП()` — допривʼязка ФЛ за ІНН

#### 2. `ЗагрузитьНалогиИУдержанияИзЗарплатыБух()` (рядок ~392)
**Що робить**: Завантажує `НалогиБухгалтерия` + `УдержанияБухгалтерия` з бази **ZUP_1**.

Запит до ZUP_1 — об'єднання двох регістрів через `ОБЪЕДИНИТЬ ВСЕ`:
- **Частина 1** (НДФЛ/ВС): `РегистрНакопления.ВзаиморасчетыПоНДФЛ.Обороты`
  - `СуммаНалога = СУММА(НалогПриход)` — сума утриманого податку
  - `СуммаДохода = СУММА(ДоходПриход)` — база доходу
  - `СуммаФОТ = 0`, `СуммаБазы = 0` (заглушки)
- **Частина 2** (ЄСВ): `РегистрРасчета.ВзносыВФонды`
  - `СуммаФОТ = СУММА(Результат)` — нарахований ЄСВ
  - `СуммаБазы = СУММА(База)` — база ЄСВ
  - `СуммаНалога = 0`, `СуммаДохода = 0`

Заповнення `НалогиБухгалтерия` через `ЗаписатьНалогиВТЧ_Бух`:
```bsl
НоваяСтрока.Сумма       = СтрокаТЗ.СуммаНалога ИЛИ СтрокаТЗ.СуммаФОТ;  // fallback
НоваяСтрока.СуммаНДФЛ   = СтрокаТЗ.СуммаНалога;
НоваяСтрока.СуммаФОТ    = СтрокаТЗ.СуммаФОТ;
НоваяСтрока.СуммаДохода = СтрокаТЗ.СуммаДохода;
НоваяСтрока.База        = СтрокаТЗ.СуммаБазы;
```

Заповнення `УдержанияБухгалтерия` (виконавчі листи з Получателем) — через `ЗаписатьУдержанияВТЧ_Бух` + пошук контрагента через `НайтиКонтрагентаПоУд_Бух`.

#### 3. `ЗаполнитьНачисленияУпризЗуп2()` (рядок ~772)
**Що робить**: Завантажує `НачисленияУпр` + `УдержанияУпр` з бази **ZUP_2** (управлінська ЗП).

Джерело: `Документ.НачислениеЗарплатыРаботникам` за поточний місяць.
Маппінг: `Физлицо.КодПоДРФО → Справочник.ФизическиеЛица.А_КодПоДРФО` в ERP.

#### 4. `ЗаполнитьДляОтражения_ДокументОтражениеЗарплатыВФинансовомУчете()` (рядок ~933)
**Що робить**: На основі `НалогиБухгалтерия` + `НачисленияУпр` + `РаспределениеКазна` заповнює:
- `НачисленнаяЗарплатаИВзносыПоФизлицам`
- `НачисленныйНДФЛ`

**3-фазний алгоритм** (Op 1, Op 2, Op 3):

**Op 1** — `_ОтрЗП_ЗаполнитьНачисленияИзНалогов`:
- Фільтр: `СтрокаНалога.СуммаФОТ > 0` (тільки ФОТ-рядки!)
- Розподіляє ФОТ по підрозділах через `_ОтрЗП_ПодготовитьРаспредПоПодразделениям`
- Fallback 1: якщо нема розподілу за конкретним податком → беремо базовий розподіл сотрудника
- Fallback 2: якщо нема навіть базового → підрозділ "ЦО"

**Op 2** — `_ОтрЗП_ЗаполнитьНачисленияЗП`:
- **Op 2a**: Для ФізОсіб з `НачисленияУпр` → сума = `НачисленияУпр.Сумма` + **валоризація** (`СуммаНДФЛ` з `НалогиБухгалтерия`)
- **Op 2b**: Для ФізОсіб з `РаспределениеКазна` яких НЕМАЄ в `НачисленияУпр` → сума з Казни + валоризація
- **Валоризація** = додавання утриманого НДФЛ+ВС до "чистої" суми → отримуємо **gross**
- Розподіл по підрозділах — через `_ОтрЗП_РаспределитьNETПоПодр`

**Op 3** — `_ОтрЗП_ЗаполнитьНДФЛИзНалогов`:
- Фільтр: `СтрокаНалога.СуммаНДФЛ > 0` (тільки НДФЛ/ВС-рядки!)
- ВидОперации: НДФЛ / ВоенныйСбор за `ТипНалога`
- Розподіл по підрозділах аналогічно Op 1

**Критичні правила**:
- НЕ змішувати фільтри `Сумма` і `СуммаНДФЛ`/`СуммаФОТ` — ЄСВ-рядки (де `Сумма = СуммаФОТ` через fallback) можуть помилково попасти в НДФЛ.
- НЕ віднімати `УдержанияУпр` від суми (штрафи йдуть окремо в підлеглий НачислениеЗарплаты).

#### 5. `СоздатьДокументНачисления()` (рядок ~1682)
**Що робить**: Find-Or-Create підлеглого `Документ.НачислениеЗарплаты` (звʼязок через реквізит `А_ДокОтражениеЗПпоКазне`).

**Guard**: батько має бути `Проведен` (інакше виходить з повідомленням).

**Алгоритм**:

1. **Очищення**: розпровести існуючий НЗ + очистити ТЧ
2. **Заповнення шапки** НЗ: `Дата`, `Организация`, `МесяцНачисления`, `ПорядокВыплаты = Зарплата`, `А_ДокОтражениеЗПпоКазне = Ссылка`

3. **`Начисления` (вид "Оклад (Зарплата)")**:
   - Кеш `КешСотрПоФизЛицу = _НЗ_ПобудуватиКешСотрудникПоФизЛицу()` (Сотрудники по ФізЛицу для організації)
   - Мапа `МапПодразОргПоСотруднику = _НЗ_ПобудуватиМапПодразОргПоСотруднику()` — будує `Сотрудник → {ПодрОрг → СумаЧастка, Итого}` через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению` (конвертує СтруктураПредприятия → ПодразделенияОрганизаций)
   - Лічильник `СтрЛічильник = Структура("Значение")` — обхід відсутності pass-by-ref у BSL
   - **Крок 1**: Цикл по `НачисленияУпр` → `_НЗ_ДодатиРядкиНачисленияПоПодразделениях(НЗ, Сотр, ВидНачисленияОсновний, СтрНач.Сумма, ...)` (БЕЗ валоризації — gross тільки в `НачисленнаяЗарплатаИВзносыПоФизлицам`)
   - **Крок 2** (fallback): для ФізОсіб з Казни без НачисленияУпр → беремо `СумаНачПоФЛ_Казна`
   - **Крок 3** (штрафи): `УдержанияУпр` → ВидНачисленияШтраф (`"Штраф (упр)"`) з МІНУСОМ

4. **`Удержания`** (вид "Алименты бух"): з `УдержанияБухгалтерия` + `Получатель = Субконто1` (Контрагент)
5. **`НДФЛ`**: з `НалогиБухгалтерия` (фільтр `СуммаНДФЛ > 0`):
   - `НР.Доход = СтрНБ.СуммаДохода` (з ZUP_1 напряму)
   - `НР.Налог = СтрНБ.СуммаНДФЛ`
   - `НР.ВидСтавки`: `Основная` для НДФЛ, `ВоенныйСбор` для ВС
   - `НР.КодДохода`: 101 / ВЗ
6. **`ВзносыФОТ`**: з `НалогиБухгалтерия` (фільтр `СуммаФОТ > 0`):
   - `НР.База = СтрНБ.База` (з ZUP_1 напряму)
   - `НР.Результат = СтрНБ.СуммаФОТ`
   - `НР.БазаВзноса = МАКС(База, МинЗП=8000)`
   - `НР.БазаДоначисление = МАКС(0, МинЗП - База)`
   - `НР.КатегорияЕСВ = "Наемный работник на общих основаниях"` (або "Инвалид")
   - `НР.СтатьяНалоговойДекларации = "Начисление ЕСВ работодателями (22 %)"`
7. **`ФизическиеЛица`**: унікальні з усіх ТЧ
8. **Запис з проведенням** + виклик `_НЗ_ОчиститиПерерасчетЗарплаты(Организация, НачПер, КонПер)` — видалення записів `РегистрСведений.ПерерасчетЗарплаты` за період (щоб не з'являлось попередження "Требуется доначисление").

## 🔑 КРИТИЧНІ НЮАНСИ

### 1. Резолв підрозділу з Казни — застосовується ОДИН РАЗ при заповненні
У Казні поле `Подразделение` часто = `"Главный офис"` (код `00-000043`) — це **заглушка**. Реальний підрозділ визначається через **Напрямок діяльності** через `А_Привилегированный.А_ПолучитьПодразделениеПоНаправлениюИПодразделениюКазны(Направление, Подразделение)`.

**Архітектура**: ця функція викликається **один раз** у `ЗагрузитьРаспределениеКазна_ОтражениеЗП` (рядок ~216) при заповненні ТЧ. Тому всі **9 циклів** по `РаспределениеКазна` у модулі автоматично читають вже **реальний** підрозділ.

```bsl
Если ЗначениеЗаполнено(ПодразделениеКазны) Тогда
    Подразделение = А_Привилегированный.А_ПолучитьПодразделениеПоНаправлениюИПодразделениюКазны(
        НаправлениеДеятельности, ПодразделениеКазны);
КонецЕсли;
```

### 2. PIVOT-агрегація БДДС по 4 колонках
Запит до Казни розділяє суму на 4 поля через CASE WHEN:
- `СуммаНачисления` = коли `СтатьяДДС.А_Налог` пустий (базове нарахування)
- `СуммаФОТ` = коли `А_Налог.Наименование ПОДОБНО "ЕСВ%"`
- `СуммаНалогов` = коли `А_Налог` непустий і НЕ "ЕСВ%"
- `Сумма` = загальна

Це дозволяє читати окремі компоненти зарплати без повторного запиту.

### 3. Валоризація (gross = net + НДФЛ+ВС) — ТІЛЬКИ у НачисленнаяЗарплата...
- `НачисленнаяЗарплатаИВзносыПоФизлицам.Сумма` = **gross** (з валоризацією) — для бухоблікового рахунку 661
- `Документ.НачислениеЗарплаты.Начисления.Результат` = **як є** з НачисленияУпр (без валоризації) — для регістру розрахунку

### 4. Підрозділ у `Документ.НачислениеЗарплаты.Начисления` — це `Справочник.ПодразделенияОрганизаций` (НЕ СтруктураПредприятия!)
Зв'язок: `ПодразделенияОрганизаций.А_Подразделение = СтруктураПредприятия.Ссылка` (близнюки як `Сотрудники`/`ФизическиеЛица`).

Конвертація — через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению(СтруктПідр)` — створює елемент `ПодразделенияОрганизаций` якщо нема, з рекурсивною ієрархією, `Владелец = А_ПолучитьОрганизациюУпр()`.

### 5. Очистка ПерерасчетЗарплаты після створення НЗ
Документ створюється кодом — ручні правки не передбачені. Записи `РегистрСведений.ПерерасчетЗарплаты` від `ПриемНаРаботу`/`КадровыйПеревод` створюють непотрібне попередження "Требуется доначисление". Очищаємо їх через `_НЗ_ОчиститиПерерасчетЗарплаты(Организация, НачПер, КонПер)`.

### 6. Виклик з форми (кнопка "Заполнить все")
```bsl
ДокументОбъект.ЗаполнитьНачисленияУпризЗуп2();
ДокументОбъект.ЗагрузитьНалогиИУдержанияИзЗарплатыБух();
ДокументОбъект.ЗаполнитьОтражениеЗарплатыВФинансовомУчетеИзБазЗП();
ДокументОбъект.ЗаполнитьДляОтражения_ДокументОтражениеЗарплатыВФинансовомУчете();
ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);  // КРИТИЧНО — перед СоздатьДокументНачисления

```

### 7. Алиаси у запитах 1С — НЕ використовувати зарезервовані слова
- ❌ `КАК ПО` (зарезервоване для `ЛЕВОЕ СОЕДИНЕНИЕ ... ПО ...`)
- ✅ `КАК ПодрОрг`, `КАК Партн`

### 8. ZUP_1 регістр `ВзаиморасчетыПоНДФЛ` — поля з суфіксом `Приход`/`Расход`
Це **сальдовий** регістр. Поля з `.Обороты()`:
- `НалогПриход` (нарахований податок)
- `ДоходПриход` (база доходу)
- НЕ "Налог" чи "Доход" напряму!

### 9. ZUP_1 регістр `ВзносыВФонды` — РегистрРасчета
Поля напряму: `Результат`, `База` (без префіксів). `Сотрудник` тут — ВИМІРЮВАННЯ (не реквізит, як у `ВзаиморасчетыПоВзносамВФонды`).

### 10. Коди видів розрахунку
- `"Оклад (Зарплата)"` — основне нарахування у НачислениеЗарплаты (НЕ "Оплата по окладу" і НЕ "Оклад по окладу")
- `"Штраф (упр)"` — для штрафів УдержанияУпр з мінусом
- Шукаємо за **найменуванням**, не за кодом — бо коди можуть дублюватися
- `"Алименты бух"` — у Удержания (код "УША")

### Розташування коду
- **Процедура**: `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`, область `#Область ЕРП_ДокументОтражениеЗарплатыВФинансовомУчете`
- **Виклик з форми**: `Forms/ФормаДокумента/Ext/Form/Module.bsl`, у `ЗаполнитьВсеНаСервере()` після `СоздатьДокументНачисления()` + окрема кнопка (Command id="7")
- **Python тест**: `_Rarzrabotki/Python/test/test_create_otrazhenie_zp_v_fin_uchete.py`

### Алгоритм (9 кроків)

1. **Guard**: батько `А_ОтражениеЗПпоКазне` має бути проведений (`Проведен = Истина`)
2. **Find-Or-Create**: пошук існуючого `Документ.ОтражениеЗарплатыВФинансовомУчете` за реквізитом-зв'язком `А_ДокОтражениеЗПпоКазне = Ссылка`. Якщо знайдено — розпровести, очистити 5 ТЧ. Якщо ні — `СоздатьДокумент()`
3. **Шапка**: `Дата`, `Организация`, `ПериодРегистрации = НачалоМесяца(Дата)` (тип Місяць!), `Сводно = Ложь`, `ПроводкиПоРаботникам = Истина`, `А_ДокОтражениеЗПпоКазне = Ссылка`
4. **ТЧ `НачисленнаяЗарплатаИВзносыПоФизлицам`**: копія 1-в-1 з однойменної ТЧ батька. `Организация` ЗАВЖДИ переписується з шапки батька. Пропускаються рядки з нульовими `Сумма` і `ВзносыВсего`
5. **ТЧ `НачисленнаяЗарплатаИВзносы`** (СВЕРТКА): згортка заповненої ТЧ дочки `…ПоФизлицам` по ключу `(Организация, ПодразделениеПредприятия, ВидОперации, СпособОтраженияЗарплатыВБухучете, ГруппаУчетаНачислений, Налог)`, сума `Сумма + ВзносыВсего`. Інваріант: `SUM(свертка) == SUM(деталізація)`
6. **ТЧ `НачисленныйНДФЛ`**: копія 1-в-1 з батька. **КРИТИЧНО**: `СпособОтраженияЗарплатыВБухучете` явно обнуляється (як в еталонному документі 000Ц-000002)
7. **ТЧ `УдержаннаяЗарплата`** ← `УдержанияБухгалтерия` батька:
   - Совпадающі поля через `ЗаполнитьЗначенияСвойств`
   - **ПодразделениеПредприятия**: у джерелі часто ПУСТЕ. Підтягується з `НачисленнаяЗарплатаИВзносыПоФизлицам` батька по `ФизическоеЛицо` — береться підрозділ з **максимальним** начисленням (Сумма). Удержания НЕ розбиваються по підрозділах — один рядок = один підрозділ
   - **СтатьяАктивовПассивов**: якщо у джерелі — ГРУПА (баг заповнення), підміняється на предопределённий елемент `ПланыВидовХарактеристик.СтатьиАктивовПассивов.ПрочиеПассивы`
   - Поля `Контрагент, ЦельВыдачи, СтатьяДоходов, АналитикаДоходов` — залишаються пустими (їх немає у джерелі)
8. **ТЧ `ФизическиеЛица`**: унікальні ФізОсоби з трьох ТЧ дочки (`…ПоФизлицам` + `НачисленныйНДФЛ` + `УдержаннаяЗарплата`)

- **`А_РаспределениеКазна`** — не копіюємо, не чистимо (за рішенням квітень 2026)
- **`А_РаспределениеНалоги`** — не заповнюємо
- **`НачисленныеОтпускаЗаСчетРезерва`**, **`НачисленныеПроцентыПоЗаймам`** — не використовуються
