# Невидимі реквізити документів BAS ERP 2.5 — Таблиця ризиків при обміні/програмному створенні

Цей документ описує поля які UI заповнює автоматично, але при створенні через обмін (BuhBud/Казна) або програмно — пропускаються. Результат: документ записаний, але регістри пусті, звіти неправильні, взаєморозрахунки нульові.

Конфігурація: BAS ERP 2.5 (v2.13), ТОВ ІНДАСТРІАЛБУД
Потік даних: BuhBud -> ERP, Казна -> ERP

---

== ДОКУМЕНТ: ПриобретениеТоваровУслуг (Придбання товарів/послуг) ==

Джерело обміну: ПоступлениеТоваровУслуг (BuhBud) -> ПриобретениеТоваровУслуг (ERP)
Кількість в базі: ~2965 документів

ОБМІННА ПРОЦЕДУРА: ОбновитьПоступлениеНаПослеОбмена()
Умова спрацювання: А_ВведенВЕРП = Ложь І А_Обработан = Ложь
Що робить: ОЧИЩУЄ Товары, РасшифровкаПлатежа, ВидыЗапасов, ЭтапыГрафикаОплаты і перебудовує з документа-джерела
ОБХІД: Встановити А_ВведенВЕРП = Истина ПЕРЕД записом

КАСТОМНИЙ КОД (А_СобытияОбъектов.ПриобретениеТоваровУслуг_ПередЗаписью):
Якщо заповнено Договор.Подразделение І ХозОперация НЕ ЗакупкаЧерезПодотчетноеЛицо -> Подразделение = Договор.Подразделение

Таблиця ризиків шапки:

Поле: Курс
Де автозаповнюється: ОбработкаЗаполнения/форма при виборі валюти
Що буде якщо пропустити: СуммаВзаиморасчетов = Сумма * 0 / Кратність = 0. НУЛЬОВІ взаєморозрахунки!
Рівень ризику: КРИТИЧНИЙ
Рішення: Курс = 1

Поле: Кратність (Кратность)
Де автозаповнюється: ОбработкаЗаполнения/форма при виборі валюти
Що буде якщо пропустити: Ділення на 0, СуммаВзаиморасчетов = 0
Рівень ризику: КРИТИЧНИЙ
Рішення: Кратність = 1

Поле: СуммаВзаиморасчетов (шапка)
Де автозаповнюється: ВзаиморасчетыСервер при проведенні
Що буде якщо пропустити: Може бути 0 якщо Курс/Кратність пусті
Рівень ризику: ВИСОКИЙ

Поле: ВалютаВзаиморасчетов
Де автозаповнюється: форма при виборі Договора
Що буде якщо пропустити: Можливі помилки валютних перерахунків
Рівень ризику: ВИСОКИЙ
Рішення: ВалютаВзаиморасчетов = Валюта документа

Поле: Подразделение
Де автозаповнюється: А_СобытияОбъектов — з Договор.Подразделение (якщо ХозОп != ЗакупкаЧерезПодотчетноеЛицо)
Що буде якщо пропустити: Пустий підрозділ, неправильний розподіл витрат
Рівень ризику: ВИСОКИЙ

Поле: ГруппаФинансовогоУчета
Де автозаповнюється: Форма при виборі Договора
Що буде якщо пропустити: Неправильний облік, регістри можуть не записатись
Рівень ризику: ВИСОКИЙ

Поле: А_ВведенВЕРП
Де автозаповнюється: НЕ заповнюється автоматично (за замовч. Ложь)
Що буде якщо пропустити: ОбновитьПоступлениеНаПослеОбмена() ЗАТРЕ всі дані! Товари, РасшифровкаПлатежа будуть очищені
Рівень ризику: КРИТИЧНИЙ
Рішення: А_ВведенВЕРП = Истина

Поле: ХозяйственнаяОперация
Де автозаповнюється: Форма/ОбработкаЗаполнения
Що буде якщо пропустити: Неправильне проведення, рухи по невірних регістрах
Рівень ризику: ВИСОКИЙ

Поле: Партнер
Де автозаповнюється: Форма при виборі Контрагента
Що буде якщо пропустити: Помилка взаєморозрахунків (Партнер = власник Договора)
Рівень ризику: ВИСОКИЙ
Рішення: ДенежныеСредстваСервер.ПолучитьПартнераПоКонтрагенту(Контрагент)

Поле: Организация
Де автозаповнюється: А_СобытияОбъектов (для ЗаказПоставщику) або ИнициализироватьДокумент
Що буде якщо пропустити: Документ без організації — критична помилка
Рівень ризику: КРИТИЧНИЙ

Поле: Договор
Де автозаповнюється: Форма при виборі Контрагента/Партнера
Що буде якщо пропустити: Не створюється ОбъектРасчетов — взаєморозрахунки не працюють
Рівень ризику: КРИТИЧНИЙ

Поле: ПорядокРасчетов
Де автозаповнюється: З Договора
Що буде якщо пропустити: Невірний порядок взаєморозрахунків
Рівень ризику: ВИСОКИЙ

Поле: СтавкаНДС (в рядках Товары)
Де автозаповнюється: Форма при виборі Номенклатури
Що буде якщо пропустити: УВАГА: це Справочник.СтавкиНДС (НЕ перечисление!). UUID "Без НДС" = 7f3fede6-6ea2-11f0-a2de-bccbaebe2890
Рівень ризику: ВИСОКИЙ

Таблиця ризиків табличної частини Товары:

Поле: СуммаСНДС
Що буде: Використовується для розрахунку СуммаВзаиморасчетов. Якщо 0 — взаєморозрахунки нульові
Рівень: КРИТИЧНИЙ

Поле: СуммаВзаиморасчетов (рядок)
Що буде: Нульові рухи по регістрах взаєморозрахунків
Рівень: КРИТИЧНИЙ
Рішення: = СуммаСНДС

Поле: ИдентификаторСтроки
Що буде: Платформа може згенерувати сама, але краще заповнити
Рівень: СЕРЕДНІЙ
Рішення: Строка(Новый УникальныйИдентификатор)

Поле: КодСтроки
Що буде: Порушення порядку рядків
Рівень: НИЗЬКИЙ

Покрокова інструкція створення ПриобретениеТоваровУслуг програмно:
1. Встановити А_ВведенВЕРП = Истина (ПЕРШИМ ДІЛОМ!)
2. Заповнити Организация, Контрагент, Партнер
3. Заповнити Договор (з нього візьмуться Подразделение, ГруппаФинансовогоУчета)
4. Встановити Курс = 1, Кратність = 1
5. Встановити ВалютаВзаиморасчетов = Валюта
6. Встановити ХозяйственнаяОперация
7. В рядках Товары: заповнити СуммаСНДС, СуммаВзаиморасчетов = СуммаСНДС
8. Встановити СтавкаНДС = Справочники.СтавкиНДС.НайтиПоНаименованию("Без НДС") (або потрібна ставка)

== ДОКУМЕНТ: РеализацияТоваровУслуг (Реалізація товарів/послуг) ==

Джерело обміну: РеализацияТоваровУслуг (BuhBud) -> РеализацияТоваровУслуг (ERP)
Кількість в базі: ~221 документів

ОБМІННА ПРОЦЕДУРА: ОбновитьРеализацияТоваровУслугПослеОбмена()
Умова: якщо А_Обработан = Ложь
Що робить:
- Встановлює РеализацияПоЗаказам = Истина (якщо ЗаказКлиента заповнений)
- Копіює з Договора: ГруппаФинансовогоУчета, Подразделение
- Встановлює Статус = Отгружено
- Встановлює ВариантОформленияПродажи = РеализацияТоваровУслуг
- Встановлює СпособДоставки = Самовывоз
- Перебудовує Товары з А_Товары та А_Услуги
- Заповнює СуммаВзаиморасчетов в рядках = СуммаСНДС
- Генерує ИдентификаторСтроки та КодСтроки

Таблиця ризиків шапки:

Поле: Курс | Ризик: КРИТИЧНИЙ | Рішення: = 1
Поле: Кратність | Ризик: КРИТИЧНИЙ | Рішення: = 1
Поле: Статус | Ризик: ВИСОКИЙ | Рішення: Перечисления.СтатусыРеализацийТоваровУслуг.Отгружено
Поле: ФормаОплаты | Ризик: ВИСОКИЙ | Рішення: Перечисления.ФормыОплаты.Безналичная
Поле: ГруппаФинансовогоУчета | Ризик: ВИСОКИЙ | Автозаповнення з Договора в обмінній процедурі
Поле: Подразделение | Ризик: ВИСОКИЙ | Автозаповнення з Договора
Поле: ВалютаВзаиморасчетов | Ризик: ВИСОКИЙ | = Валюта документа
Поле: Организация | Ризик: КРИТИЧНИЙ | ИнициализироватьДокумент
Поле: Валюта | Ризик: ВИСОКИЙ | ЗначениеНастроекПовтИсп.ПолучитьВалютуРегламентированногоУчета()
Поле: АвторасчетНДС | Ризик: ВИСОКИЙ | НДСИсходящийСервер — якщо пропущено, НДС може перерахуватись некоректно
Поле: ДатаПереходаПраваСобственности | Ризик: ВИСОКИЙ | Встановлюється в ПередЗаписью на пусту дату якщо НЕ РеализацияБезПереходаПраваСобственности

Таблиця ризиків табличної частини Товары:

Поле: СуммаСНДС | Ризик: КРИТИЧНИЙ | = Сумма + СуммаНДС (або = Сумма якщо ЦенаВключаетНДС)
Поле: СуммаВзаиморасчетов | Ризик: КРИТИЧНИЙ | = СуммаСНДС
Поле: Склад (рядок) | Ризик: СЕРЕДНІЙ | = Склад з шапки
Поле: ИдентификаторСтроки | Ризик: НИЗЬКИЙ | автогенерація GUID

ПОПЕРЕДЖЕННЯ: При ПередЗаписью з АвторасчетНДС=Истина — СуммаВзаиморасчетов в рядках може бути СКИНУТО на 0!
Рішення: або заповнювати АвторасчетНДС правильно, або ставити його в Ложь.

== ДОКУМЕНТ: ПриходныйКассовыйОрдер (Прихідний касовий ордер) ==

Джерело обміну: ПриходныйКассовыйОрдер (BuhBud/Казна) -> ПриходныйКассовыйОрдер (ERP)
Кількість в базі: ~676 документів

ОБМІННА ПРОЦЕДУРА: ОбновитьПриходныйКассовыйОрдерПослеОбмена()
Умова: А_ОбработанКазна = Ложь
Що робить:
- ОЧИЩУЄ РасшифровкаПлатежа!
- Перезаписує ХозяйственнаяОперация (напр. на ПрочееПоступлениеДС)
ОБХІД: А_ОбработанКазна = Истина

КАСТОМНИЙ КОД (А_СобытияОбъектов.ПриходныйКассовыйОрдер_ПередЗаписью):
Для кожного рядка РасшифровкаПлатежа: якщо Подразделение пусте -> Подразделение = Подразделение з шапки

Таблиця ризиків:

Поле: А_ОбработанКазна | Ризик: КРИТИЧНИЙ | Рішення: = Истина (інакше РасшифровкаПлатежа буде очищена!)
Поле: ХозяйственнаяОперация | Ризик: КРИТИЧНИЙ | Буде перезаписана якщо А_ОбработанКазна = Ложь
Поле: Подразделение | Ризик: ВИСОКИЙ | Копіюється в РасшифровкаПлатежа кастомним кодом
Поле: Курс | Ризик: КРИТИЧНИЙ | = 1
Поле: Кратність | Ризик: КРИТИЧНИЙ | = 1
Поле: Касса | Ризик: ВИСОКИЙ | НЕ має поля Валюта — валюта береться з Касса.ВалютаДенежныхСредств

Табличні частини:
Поле: РасшифровкаПлатежа.Подразделение | Ризик: ВИСОКИЙ | Автозаповнення з шапки (А_СобытияОбъектов)
Поле: РасшифровкаПлатежа.СуммаВзаиморасчетов | Ризик: ВИСОКИЙ | = Сумма * Курс / Кратність

== ДОКУМЕНТ: ПоступлениеБезналичныхДенежныхСредств (Надходження безготівкових ДС) ==

Джерело обміну: ПоступлениеНаРасчетныйСчет (BuhBud) -> ПоступлениеБезналичныхДенежныхСредств (ERP)
Код конвертації ПослеЗагрузки: 4328 символів (один з найбільших!)

Таблиця ризиків:

Поле: Курс | КРИТИЧНИЙ | = 1
Поле: Кратність | КРИТИЧНИЙ | = 1
Поле: Подразделение | ВИСОКИЙ | ФизическиеЛицаУТ.ПодразделениеФизическогоЛица()
Поле: СуммаВзаиморасчетов (в рядках) | КРИТИЧНИЙ | ВзаиморасчетыСервер.ЗаполнитьСуммуВзаиморасчетовВТабличнойЧасти()
Поле: Организация (в рядках РасшифровкаПлатежа) | ВИСОКИЙ | ДенежныеСредстваСервер.ЗаполнитьОрганизациюВТабличнойЧасти()
Поле: СтатьяДоходов | ВИСОКИЙ | Автозаповнюється залежно від ХозОперации (ЗаймыВыданные для ПогашениеЗаймаСотрудником, ОплатаТруда для зарплатних)

КАСТОМНИЙ КОД (А_ДоработкаДокументыПриЗаписи):
- Якщо ХозОперация = ПоступлениеДенежныхСредствСДругогоСчета -> автоматично створює парний СписаниеБезналичныхДС
- Викликає СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению

== ДОКУМЕНТ: СписаниеБезналичныхДенежныхСредств (Списання безготівкових ДС) ==

Джерело обміну: СписаниеСРасчетногоСчета (BuhBud) -> СписаниеБезналичныхДенежныхСредств (ERP)
Код конвертації ПослеЗагрузки: 4357 символів (найбільший!)

Таблиця ризиків:

Поле: Курс | КРИТИЧНИЙ | = 1
Поле: Кратність | КРИТИЧНИЙ | = 1
Поле: СуммаВзаиморасчетов (в рядках) | КРИТИЧНИЙ | ВзаиморасчетыСервер.ЗаполнитьСуммуВзаиморасчетовВТабличнойЧасти()
Поле: Организация (в рядках) | ВИСОКИЙ | автозаповнення
Поле: НомерПоручения | НИЗЬКИЙ | ДенежныеСредстваСервер.СформироватьНомерПоручения()

КАСТОМНИЙ КОД (А_ДоработкаДокументыПриЗаписи) — СКЛАДНА ЛОГІКА:
1. ХозОп = ПеречислениеДенежныхСредствНаДругойСчет -> створює парний ПоступлениеБезналичныхДС
2. ХозОп = ВыплатаЗарплатыПоЗарплатномуПроекту -> проводить/відміняє Ведомості
3. ХозОп = ОплатаПоставщику -> ОНОВЛЮЄ ЗаказПоставщику (А_СтатьяДДС, Договор)
4. А_ФинАгент пустий -> створює А_ОказаниеУслугМеждуПодразделениями

КРИТИЧНИЙ РИЗИК: Запис цього документа АВТОМАТИЧНО модифікує інші документи!

== ДОКУМЕНТ: ЗаказПоставщику (Замовлення постачальнику) ==

Джерело обміну: СчетНаОплатуПоставщика (BuhBud) -> ЗаказПоставщику (ERP)
Кількість в базі: ~8438 документів (найбільше!)

КАСТОМНИЙ КОД (А_СобытияОбъектов.ЗаказПоставщику_ПередЗаписью):
- Организация = А_Привилегированный.А_ПолучитьОрганизациюУпр() (ПРИМУСОВО!)
- Якщо А_ДоговорИзБанка заповнений -> Договор = А_ДоговорИзБанка
- З Договора: Подразделение, НаправлениеДеятельности, ГруппаФинансовогоУчета
- Для нових: Статус = Согласован, Приоритет = "Середній"
- Забороняє зміну Договора/Валюти якщо є проведені документи приходу (крім ролі А_Гермес)

КРИТИЧНИЙ РИЗИК: Организация ЗАВЖДИ перезаписується кастомним кодом! Якщо в BuhBud інша — буде затерта.

Таблиця ризиків:

Поле: Организация | КРИТИЧНИЙ | ПРИМУСОВО заповнюється з А_ПолучитьОрганизациюУпр()
Поле: Договор | КРИТИЧНИЙ | Від нього залежать Подразделение, НаправлениеДеятельности, ГруппаФинансовогоУчета
Поле: Статус | ВИСОКИЙ | = Согласован (для нових)
Поле: Валюта | ВИСОКИЙ | Заборона зміни після створення документів приходу

== ДОКУМЕНТ: ЗаказКлиента (Замовлення клієнта) ==

Джерело обміну: СчетНаОплатуПокупателю (BuhBud) -> ЗаказКлиента (ERP)
Кількість в базі: ~685 документів

ОБМІННА ПРОЦЕДУРА: ОбновитьЗаказКлиентаНаПослеОбмена()
Умова: А_Обработан = Ложь (якщо Истина — ВСЯ процедура пропускається!)
Що робить:
- Встановлює Статус = КОбеспечению
- Встановлює Приоритет = "Середній"
- Встановлює СпособДоставки = Самовывоз
- Копіює з Договора: ГруппаФинансовогоУчета, Подразделение

== ЗАГАЛЬНІ ПРАВИЛА для ВСІХ документів з взаєморозрахунками ==

Обов'язкові поля при програмному створенні БУДЬ-ЯКОГО документа з розрахунками:

1. Курс = 1 (КРИТИЧНО! Без цього СуммаВзаиморасчетов = 0)
2. Кратність = 1 (КРИТИЧНО! Ділення на 0)
3. СуммаВзаиморасчетов в шапці
4. СуммаСНДС в рядках Товары
5. СуммаВзаиморасчетов = СуммаСНДС в рядках Товары
6. Валюта та ВалютаВзаиморасчетов
7. Договор (від нього ОбъектРасчетов, ГруппаФинансовогоУчета, Подразделение)
8. ПорядокРасчетов
9. ГруппаФинансовогоУчета

Флаги для обходу обмінних процедур:
- А_ОбработанКазна = Истина (для ПКО, РКО)
- А_ВведенВЕРП = Истина (для ПриобретениеТоваровУслуг)
- А_Обработан = Истина (для деяких документів)

Формула взаєморозрахунків:
СуммаВзаиморасчетов = Сумма * Курс / Кратність
Якщо Курс = 0 або Кратність = 0 -> СуммаВзаиморасчетов = 0 -> НУЛЬОВІ рухи по регістрах!
