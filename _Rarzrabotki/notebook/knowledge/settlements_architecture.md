# Архітектура взаєморозрахунків BAS ERP 2.5 INDUSTRIALBUD

Цей документ описує як працюють взаєморозрахунки — найскладніша підсистема ERP яка найчастіше "ламається" при програмному створенні документів та обміні.

---

== ФОРМУЛА СУМИ ВЗАЄМОРОЗРАХУНКІВ ==

Головна формула (з CommonModules/ВзаиморасчетыСервер, рядок 1841):

СуммаВзаиморасчетов = (СуммаДокумента * КурсВалютыДокумента * КратностьВзаиморасчетов) / (КурсВзаиморасчетов * КратностьДокумента)

Для документів в гривні (Валюта = ВалютаВзаиморасчетов = UAH):
- КурсВалютыДокумента = 1
- КратностьВалютыДокумента = 1
- КурсВзаиморасчетов = 1
- КратностьВзаиморасчетов = 1

Тому: СуммаВзаиморасчетов = СуммаДокумента * 1 * 1 / (1 * 1) = СуммаДокумента

Точна функція розрахунку коефіцієнта (рядок 11171 ВзаиморасчетыСервер):

Функция КоэффициентПоКурсуИКратности(СистемныеНастройки, Валюта, ВалютаВзаиморасчетов, Курс, Кратность)
  Якщо Курс = 0 АБО Кратність = 0 Тоді
    Повернути 0    <-- КРИТИЧНО! Нульовий коефіцієнт = нульова сума!
  ІнакшеЯкщо Валюта = ВалютаВзаиморасчетов Тоді
    Повернути 1    <-- Однакова валюта — без конвертації
  ІнакшеЯкщо ВалютаВзаиморасчетов != ВалютаРеглУчета І Валюта = ВалютаРеглУчета Тоді
    Повернути Кратність / Курс    <-- З облікової у валюту взаєморозрахунків
  Інакше
    Повернути Курс * Кратність    <-- Загальний випадок
  КінецьЯкщо
КінецьФункції

Потім (рядок 11262):
СуммаВзаиморасчетов = Округлити(ТаблицаТовары.Итог(СуммаСНДС) * КоэффициентПересчета, 2)

ПРОБЛЕМА: Якщо поля Курс або Кратність НЕ заповнені (= 0):
- КоэффициентПоКурсуИКратности повертає 0
- СуммаВзаиморасчетов = Сума * 0 = 0
РЕЗУЛЬТАТ: Регістри взаєморозрахунків записують нулі!

Джерело даних для курсу: РегистрСведений.КурсыВалют.СрезПоследних(Дата, Валюта)
Якщо курс не знайдено — використовується ЕСТЬNULL(..., 1) тобто 1.

== ЛАНЦЮЖОК ВИКЛИКУ ПРИ ПРОВЕДЕННІ ==

1. Документ.ПередЗаписью() -> ВзаиморасчетыСервер.ПередЗаписью()
   (рядок 6373 ВзаиморасчетыСервер)

2. ВзаиморасчетыСервер.ПередЗаписью() виконує (тільки при РежимЗаписи = Проведение):
   a. ПроверитьЗаполнитьРеквизит("ПорядокРасчетов") - перевіряє/заповнює порядок розрахунків
   b. ПроверитьЗаполнитьРеквизит("ОплатаВВалюте") - перевіряє оплату в валюті
   c. ПроверитьЗаполнитьСуммуВзаиморасчетов() - РОЗРАХУНОК СУМИ за формулою вище
   d. ПроверитьЗаполнитьСуммыВзаиморасчетовВТабличнойЧасти() - суми в рядках ТЧ
   e. ПроверитьЗаполнитьЭтапыГрафикаОплаты() - графік оплати
   f. ПроверитьЗаполнитьРасшифровкуПлатежа() - розшифровка платежу

3. ОбъектыРасчетовСервер.ПроверитьОбъектыРасчетовПередЗаписью() - перевіряє/створює ОбъектРасчетов

ВАЖЛИВО: Крок 2 виконується ТІЛЬКИ при РежимЗаписи = Проведение! Якщо документ тільки записується (не проводиться) — суми взаєморозрахунків НЕ перераховуються.

== ЩО ТАКЕ ОБЪЕКТРАСЧЕТОВ ==

ОбъектРасчетов — це запис в регістрі відомостей який зв'язує документ з конкретним об'єктом взаєморозрахунків.

Створюється автоматично з Договора (ДоговорыКонтрагентов) процедурою:
ОбъектыРасчетовСервер.ПроверитьСоздатьОбъектРасчетов(Договор, ...)

ОбъектРасчетов містить:
- Договор (посилання на ДоговорыКонтрагентов)
- Контрагент
- Партнер
- Организация
- НаправлениеДеятельности
- Объект (документ-підстава — ЗаказКлиента, ЗаказПоставщику, або сам Договор)

Логіка вибору (рядки 390-391 ВзаиморасчетыСервер):
- Якщо ПорядокРасчетов = ПоДоговорамКонтрагентов -> ОбъектРасчетов вказує на ДОГОВОР
- Якщо ПорядокРасчетов = ПоЗаказамНакладным -> ОбъектРасчетов вказує на ЗАМОВЛЕННЯ (ЗаказКлиента)

Без ОбъектРасчетов:
- Рухи по РасчетыСКлиентамиПоСрокам не формуються
- ВедомостьРасчетовСПартнерами не показує заборгованість

Для створення ОбъектРасчетов ОБОВ'ЯЗКОВО потрібен заповнений Договор (для договірного порядку) або ЗаказКлиента (для замовленого порядку)!

---

== НОВА vs СТАРА АРХІТЕКТУРА ВЗАЄМОРОЗРАХУНКІВ ==

В BAS ERP 2.5 використовується НОВА архітектура (НоваяАрхитектураВзаиморасчетов = TRUE).

Стара архітектура:
- Регістр: РасчетыСКлиентами (оперативний)
- Реєстратор: сам документ (РеализацияТоваровУслуг, ПКО тощо)
- Поля: Долг, КОплате

Нова архітектура:
- Фінансовий регістр: РасчетыСКлиентамиПоСрокам
- Реєстратор: СЛУЖБОВИЙ ДОКУМЕНТ РегистраторРасчетов (НЕ сам вихідний документ!)
- Поля: ДолгРегл, ПредоплатаРегл (НЕ Сумма, НЕ КОплате!)

Оперативний регістр РасчетыСКлиентами продовжує використовуватись, але для ФІНАНСОВОЇ звітності (ВедомостьРасчетовСПартнерами) використовується РасчетыСКлиентамиПоСрокам.

РегистраторРасчетов — це службовий документ. Він створюється автоматично платформою для кожного руху взаєморозрахунків. Тому коли ви дивитесь записи в регістрі РасчетыСКлиентамиПоСрокам — реєстратором буде РегистраторРасчетов, а НЕ РеализацияТоваровУслуг або ПКО.

== РАСШИФРОВКА ПЛАТЕЖА (РасшифровкаПлатежа) ==

Таблична частина яка є в грошових та товарних документах. Містить деталізацію: по яких замовленнях/договорах розподіляються суми.

Автозаповнення:
- ВзаиморасчетыСервер.ПроверитьЗаполнитьРасшифровкуПлатежа() — при проведенні
- Для товарних документів: ЗаполнитьСуммыРасшифровкиНакладной()
- Для грошових документів: різні ЗаполнитьРасшифровкуПлатежаПоXXX()

Для автозаповнення ОБОВ'ЯЗКОВО потрібні ненульові:
- СуммаДокумента
- СуммаВзаиморасчетов
Якщо вони = 0 (через Курс/Кратність = 0) — РасшифровкаПлатежа буде пустою!

---

== ПРОЦЕДУРА ЗаполнитьСуммуВзаиморасчетовВТабличнойЧасти ==

(рядок 1614 ВзаиморасчетыСервер)

Заповнює поле СуммаВзаиморасчетов в КОЖНОМУ рядку табличної частини (Товары).
Використовує ту ж формулу з курсами валют.

Для гривневих документів: СуммаВзаиморасчетов = СуммаСНДС (сума з ПДВ).

ВАЖЛИВО: Якщо СуммаСНДС = 0 в рядку — СуммаВзаиморасчетов теж = 0!

== ДІАГНОСТИКА "РОЗРИВІВ" ВЗАЄМОРОЗРАХУНКІВ ==

Симптоми:
1. ВедомостьРасчетовСПартнерами показує 0 замість суми
2. УправленческийБаланс — неправильні дебітори/кредитори
3. Звірка ERP vs BuhBud — розбіжності по контрагентах

Причини (в порядку частоти):
1. Курс = 0 або Кратність = 0 → СуммаВзаиморасчетов = 0
2. Договор не заповнений → ОбъектРасчетов не створений → немає рухів
3. СуммаСНДС = 0 в рядках Товары → нульові рядки взаєморозрахунків
4. А_ВведенВЕРП або А_Обработан неправильно встановлені → обмінна процедура затерла дані
5. РасшифровкаПлатежа очищена обмінною процедурою (А_ОбработанКазна = Ложь)
6. ГруппаФинансовогоУчета пуста → документ не потрапляє в правильну групу обліку

Як перевірити:
1. Відкрити документ, подивитись Курс і Кратність (повинні бути = 1 для гривні)
2. Перевірити СуммаВзаиморасчетов в шапці (повинна = СуммаДокумента)
3. Перевірити СуммаВзаиморасчетов в рядках Товары
4. Подивитись рухи документа по регістрах — чи є записи в РасчетыСКлиентами/Поставщиками
5. Перевірити чи існує РегистраторРасчетов для цього документа

Як виправити:
1. Встановити Курс = 1, Кратність = 1
2. Заповнити СуммаВзаиморасчетов = СуммаДокумента
3. Перепровести документ (відмінити проведення → провести заново)

---

== ПОРЯДОК РОЗРАХУНКІВ (ПорядокРасчетов) ==

Перечисление.ПорядокРасчетов визначає деталізацію взаєморозрахунків:
- ПоДоговорамКонтрагентов — розрахунки по договорах
- ПоЗаказамНакладным — розрахунки по замовленнях
- ПоНакладным — розрахунки по накладних

Заповнюється з Договора або автоматично в ПроверитьЗаполнитьРеквизит().
