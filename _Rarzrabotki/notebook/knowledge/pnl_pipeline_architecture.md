# PnL Pipeline Architecture — Python загрузка Excel → 1С BAS ERP 2.5

Этот документ описывает полную архитектуру загрузки PnL-отчётов из Excel-файлов финансиста в конфигурацию BAS ERP 2.5 INDUSTRIALBUD. Описывает каждый скрипт, JSON-файл, place of truth для mapping, как А_Статьи_PL привязаны к СтатьиДвиженияДенежныхСредств через ТЧ "Статьи".

Конфигурация: BAS ERP 2.5 (v2.13), ТОВ ІНДАСТРІАЛБУД
Python pipeline: `C:\Configuration_downloads\BASERP25\_Rarzrabotki\Python\PnL\`
Источники Excel: `C:\Configuration_downloads\BASERP25\_Rarzrabotki\PL\<Месяц>\!PL по компании <Месяц>.xlsx`

---

== НАЗНАЧЕНИЕ ==

Финансист ведёт PnL (план-факт) в Excel-файлах (по одному на месяц). Каждый лист Excel = одно подразделение (или сводный лист по направлению). Pipeline загружает данные листов в 1С как документы Документ.А_ОтчетPL (по одному на лист × месяц), а сверку plan vs fact выполняет отчёт Отчет.А_ОтчетPL.

Результат в 1С:
- 82 документа А_ОтчетPL (по состоянию на 2026-04-18)
- 5 сводных листов × 3 месяца = 15 документов с ВключатьДочерние=Истина
- 4788 строк ТЧ ДанныеОтчета суммарно

---

== КЛЮЧЕВОЙ АРХИТЕКТУРНЫЙ СДВИГ (2026-04-18) ==

PLACE OF TRUTH для mapping "лист Excel → Подразделение/НаправлениеДеятельности/ВключатьДочерние" = Документ.А_РасшифровкаЛистов в 1С (UI финансиста), а НЕ config.py.

Причина: финансист правит mapping в клиенте 1С через документы А_РасшифровкаЛистов. Python читает этот mapping и применяет. config.py содержит только начальные overrides для fuzzy-алгоритма и скрипта 13 (первоначальное заполнение А_РасшифровкаЛистов).

3 документа А_РасшифровкаЛистов в базе:
- №000000001 (31.12.2025) — Декабрь 2025, 31 строк
- №000000002 (31.01.2026) — Январь 2026, 29 строк
- №000000003 (28.02.2026) — Лютий 2026, 31 строк

Каждый документ имеет ТЧ Расшифровка с полями:
- ИмяЛиста (Строка) — точное имя листа Excel
- ПодразделениеСтрока (Строка) — копия имени листа
- Подразделение (Справочник.СтруктураПредприятия) — подразделение 1С
- НаправлениеДеятельности (Справочник.НаправленияДеятельности) — направление
- ВключатьДочерние (Булево) — True для сводов по направлению

== СКРИПТЫ И JSON-ФАЙЛЫ (ПОЛНАЯ КАРТА) ==

Все JSON в `data/json/`. Все скрипты в `scripts/`.

СКРИПТ: 01_extract_excel_to_json.py
Что делает: парсит все visible PnL-листы из 3 Excel-файлов, извлекает строки (article, sum_f1, sum_f2, total) + group_totals + general_totals.
Читает: EXCEL_FILES из config.py
Пишет: 01_raw_sheets.json (28/27/29 листов по 3 периодам, ~4942 строк)
Важно (2026-04-18): фильтр `is_summary_sheet` удалён — сводные листы (PL_ЦО, MAN №*, МК *, МД *, Техника, PL_Логистика) тоже парсятся. Листы без месячного заголовка в row 2 (Метрики, Индекс, расчет) автоматически отсекаются функцией find_month_columns.

СКРИПТ: 02_extract_unique_articles.py
Что делает: собирает уникальные имена статей из 01_raw_sheets.json, группирует дубли (casefold + normalize пробелов), детектирует fuzzy-дубли (threshold=92).
Читает: 01_raw_sheets.json
Пишет: 02_unique_articles.json ({total, articles: [{name, variants, group, type_statii, uuid:""}]}) — 72 статьи
Важно: поле uuid остаётся пустым — заполняется скриптом 02b.

СКРИПТ: 02b_fetch_article_uuids.py (новый, 2026-04-18)
Что делает: по каждой статье из 02 ищет Справочник.А_Статьи_PL.НайтиПоНаименованию (сначала по каноническому имени, потом по variants). Проставляет uuid. НЕ создаёт новых элементов каталога.
Читает: 02_unique_articles.json (для списка имён)
Пишет: 02_unique_articles.json (перезаписывает с проставленными uuid)
Цель: нужен перед 08 (08 требует uuid статьи чтобы заполнить ТЧ ДанныеОтчета через `ref_by_uuid`).
Типичный результат: 60 из 72 found, 12 не найдено (это обычно Excel-комментарии типа "Выручка ФЗ - 5 018 436грн", не реальные статьи).

СКРИПТ: 03_extract_dds_from_erp.py
Что делает: дампит Справочник.СтатьиДвиженияДенежныхСредств из 1С.
Пишет: 04_dds_articles.json ({items: [{uuid, name, code, parent, is_group}]}) — все ДДС-статьи.

СКРИПТ: 04_match_articles.py
Что делает: fuzzy-матч каждой PnL-статьи (02_unique_articles) со списком ДДС (04_dds_articles). Выдаёт 1:N mapping (одна PL-статья → несколько подходящих ДДС).
Алгоритм: fuzz.ratio, fuzz.token_set_ratio, fuzz.partial_ratio → max.
Пороги: FUZZY_AUTO_THRESHOLD=85 (auto-match), FUZZY_CANDIDATE_THRESHOLD=70 (кандидат для ручной проверки).
Overrides: config.MANUAL_DDS_OVERRIDES (5 фикс. маппингов: "Логистические затраты" → "Транспортные расходы" и т.п.).
Читает: 02_unique_articles.json + 04_dds_articles.json
Пишет: 05_mapping_pl_to_dds.json

СКРИПТ: 04b_match_statya_dohodov.py
Что делает: для доходных PL-статей ищет соответствие в ПВХ.СтатьиДоходов (для реквизита А_Статьи_PL.СтатьяДоходов).
Пишет: 10_mapping_statya_dohodov.json

СКРИПТ: 05_build_groups.py
Что делает: читает названия групп из 02_unique_articles (поле "group"), находит/создаёт в каталоге А_ГруппаСтатей_PL.
Пишет: 03_groups_pl.json ({groups: [{name, uuid}]})

СКРИПТ: 06_extract_struct_from_erp.py
Что делает: дампит Справочник.СтруктураПредприятия (все 358 подразделений) с реквизитами А_НаправлениеДеятельности, А_ЭтоПодразделениеНаправление, Родитель.
Пишет: 06_struct_predpr.json ({items: [{uuid, name, code, parent_uuid, parent_name, direction_uuid, direction_name, is_direction}]}) — 358 items, 170 с направлением, 8 корневых направлений (is_direction=True).

СКРИПТ: 07_match_sheets_to_struct.py
Что делает: fuzzy-матч имён листов Excel с именами подразделений 1С. Применяет config.MANUAL_SHEET_TO_STRUCT_OVERRIDES.
Логика direction_uuid: либо явно указано в override, либо подтягивается из 06 по struct_uuid.
Читает: 01_raw_sheets.json + 06_struct_predpr.json + config.MANUAL_SHEET_TO_STRUCT_OVERRIDES
Пишет: 07_mapping_sheet_to_struct.json ({mappings: [{sheet_name, struct_uuid, struct_name, match_type, direction_uuid, direction_name, include_children, candidates}]}) — ~30 mappings

СКРИПТ: 08_prepare_documents.py (переписан 2026-04-18)
Что делает: собирает 82 документа для загрузки в А_ОтчетPL. MAPPING берётся НЕ из 07_mapping, а из Документ.А_РасшифровкаЛистов в 1С (через COM).
Алгоритм:
1. Через COM читает все непомеченные А_РасшифровкаЛистов.
2. Для каждого периода строит dict {sheet_name → {struct_uuid, direction_uuid, include_children}} из ТЧ Расшифровка.
3. Проходит 01_raw_sheets.json: для каждого листа ищет mapping в А_Расшифровке по sheet_name.
4. Если Подразделение не заполнено в ТЧ → пропускает.
5. Если Направление пусто в ТЧ — FALLBACK на 06_struct_predpr.direction_uuid (по struct_uuid подразделения).
6. Статьи матчит по 02_unique_articles (by normalized name), берёт uuid оттуда.
Читает: 01_raw_sheets.json, 02_unique_articles.json, 03_groups_pl.json, 06_struct_predpr.json + Документ.А_РасшифровкаЛистов из 1С
Пишет: 08_documents_to_import.json ({documents: [{date, sheet_name, podrazdelenie_uuid, direction_uuid, include_children, rows, group_totals, general_totals}]}) — 82 документа, 4822 строк

СКРИПТ: 09_delete_existing_docs.py
Что делает: разовое удаление всех А_ОтчетPL (использовалось при первоначальной миграции).

СКРИПТ: 10_upload_groups.py
Что делает: создаёт/обновляет элементы Справочник.А_ГруппаСтатей_PL.

СКРИПТ: 11_upload_articles.py
Что делает: создаёт/обновляет элементы Справочник.А_Статьи_PL. Заполняет ТЧ Статьи связями на ДДС (из 05_mapping_pl_to_dds.json), реквизит СтатьяДоходов (из 10_mapping_statya_dohodov.json), Группа (из 03_groups_pl.json).
ВНИМАНИЕ: модуль объекта А_Статьи_PL имеет guard (ПередЗаписью), который отказывает в записи если новая статья хочет взять ДДС, уже используемую в другой PL-статье (при условии что эта ДДС имеет обороты). Guard защищает от дублирования привязок.
Читает: 02_unique_articles.json + 03_groups_pl.json + 05_mapping_pl_to_dds.json + 10_mapping_statya_dohodov.json
Пишет: обновляет 02_unique_articles.json (перезаписывает с uuid созданных/найденных статей).

СКРИПТ: 12_upload_documents.py
Что делает: upsert документов А_ОтчетPL по (date_month, ПодразделениеСтрока). Создаёт новые, обновляет существующие. Очищает и перезаполняет 3 ТЧ (ДанныеОтчета, ИтогиПоГруппам, ИтогиОбщие). Записывает с Проведением.
Заполняет шапку: Организация, Подразделение, НаправлениеДеятельности, ВключатьДочерние, ПодразделениеСтрока.
Читает: 08_documents_to_import.json + 02_unique_articles.json
Пишет: 09_import_log.json (результаты new/upd/failed)

СКРИПТ: 13_fill_rasshifrovka_listov.py
Что делает: первоначальное заполнение ТЧ Расшифровка в 3 документах А_РасшифровкаЛистов. Использует 07_mapping_sheet_to_struct.json (config.MANUAL_SHEET_TO_STRUCT_OVERRIDES).
ВАЖНО: после того как финансист поправит ТЧ Расшифровка в UI, 13 БОЛЬШЕ НЕ запускается (или запускается с осторожностью, т.к. очистит ручные правки). В текущей архитектуре 13 — одноразовый шаг при появлении нового месяца.
Читает: 07_mapping_sheet_to_struct.json + EXCEL_FILES (для visible sheets)
Пишет: заполняет ТЧ документов 1С + backup в 13_backup_*.json

СКРИПТ: 14_migrate_otchetpl_napravlenie.py
Что делает: разовая миграция — для существующих А_ОтчетPL проставляет НаправлениеДеятельности и ВключатьДочерние (из mapping в А_Расшифровке либо из Подразделение.А_НаправлениеДеятельности). Не перетирает уже правильные значения.
Использует ОбменДанными.Загрузка=True чтобы обойти валидацию ПередЗаписью.

Используется в 04_match_articles.

Используется в 04b_match_statya_dohodov.

SUMMARY_SHEET_PATTERNS, SUMMARY_SHEET_EXACT: УСТАРЕЛИ после 2026-04-18 (фильтр не применяется в excel_parser.py), оставлены для совместимости.

== СПРАВОЧНИК А_СТАТЬИ_PL И СВЯЗЬ С ДДС ==

Справочник А_Статьи_PL (каталог статей PnL) имеет:

ШАПКА (реквизиты):
- Наименование (стандарт)
- Группа → Справочник.А_ГруппаСтатей_PL
- СтатьяДвиженияДенежныхСредств → Справочник.СтатьиДвиженияДенежныхСредств (legacy поле, сейчас используется ТЧ Статьи для 1:N связи; при записи равно первой строке ТЧ)
- СтатьяДоходов → ПланВидовХарактеристик.СтатьиДоходов (только для доходных статей, из 10_mapping)
- ТипСтатьи → Перечисление.А_ТипСтатьиPL (Доход, Расход, ОперационныйИтог, Информационный)
- А_СозданоАвтоматически (Булево) — маркер что статья создана скриптом, не вручную

ТАБЛИЧНАЯ ЧАСТЬ "Статьи" (связи 1:N):
- СтатьяДвиженияДенежныхСредств → Справочник.СтатьиДвиженияДенежныхСредств

Одна PL-статья может иметь несколько связанных ДДС (например "Материалы" PL связан с ДДС "Материалы стройка", "Материалы производство", "Материалы офис"). При записи документа А_ОтчетPL для каждой строки суммируются обороты ЕРП по ВСЕМ связанным ДДС через ТЧ Статьи.

ГАРДЫ ЦЕЛОСТНОСТИ В МОДУЛЕ ОБЪЕКТА А_Статьи_PL (Catalogs/А_Статьи_PL/Ext/ObjectModule.bsl, ~4 правила ПередЗаписью):
1. У статьи должно быть заполнено Группа (кроме whitelist кодов типа 000000028, 000000056 — инвест./финансовая деятельность).
2. У статьи должна быть минимум 1 строка в ТЧ Статьи (заполненная ДДС).
3. Шапочная СтатьяДвиженияДенежныхСредств = первая строка ТЧ (автоматически).
4. АДАПТИВНАЯ УНИКАЛЬНОСТЬ: одна ДДС не может принадлежать 2+ PL-статьям, ЕСЛИ эта ДДС имеет обороты за последние 12 месяцев (через виртуальную таблицу АДР). Если ДДС без оборотов — shared-zontik разрешён.

Правило 4 защищает от "ошибки дублирования" когда финансист пытается добавить ДДС которая уже используется в другой PL-статье с оборотами. Скрипт 11_upload_articles падает с COM-error в этом случае.

ОБНОВЛЕНИЕ А_Статьи_PL (обычный workflow):
1. Запустить 04_match_articles → 05_mapping_pl_to_dds.json с fuzzy-маппингом PL-статьи → ДДС
2. Проверить unmapped_articles.txt, добавить в MANUAL_DDS_OVERRIDES конкретные исправления
3. Запустить 04 повторно — применит overrides
4. Запустить 05_build_groups → создаст отсутствующие группы
5. Запустить 10_upload_groups (если есть новые)
6. Запустить 11_upload_articles → создаст новые статьи, обновит связи
7. При ошибке "дубль ДДС" — проверить другую PL-статью где эта ДДС используется (dds_duplicate.csv)

ВАЖНО при обновлении: скрипт 11 заменяет ВСЮ ТЧ Статьи (очищает и заполняет заново из 05_mapping). Любые ручные правки в ТЧ Статьи будут перетёрты.

== ДИАГНОСТИКА ==

Не все листы Excel попали в А_ОтчетPL
- Проверить 08_documents_to_import.json: поля skipped_no_mapping_list и skipped_no_podr_list.
- skipped_no_mapping = лист есть в Excel но отсутствует в ТЧ А_Расшифровки → финансист должен добавить в UI.
- skipped_no_podr = в ТЧ есть строка но Подразделение не заполнено → финансист должен проставить.

ТЧ ДанныеОтчета пустая у документа (rows=0 в stdout 12)
- Причина: в 02_unique_articles.json у статей пустой uuid (не сматчены с каталогом).
- Фикс: запустить 02b_fetch_article_uuids.py перед 08.

Направление в А_ОтчетPL пустое у документа
- Проверить Документ.А_РасшифровкаЛистов — строку данного листа в ТЧ Расшифровка.
- Если Направление пустое И Подразделение заполнено — 08 подхватит fallback из 06_struct_predpr (А_НаправлениеДеятельности подразделения).
- Если и Подразделение пустое — 08 пропустит лист совсем.

Открывается не тот вариант отчёта при сверке
- См. report_open_from_form.md — параметр формы `КлючВарианта` (не `ВариантКлюч`!).

== ПРОБЛЕМА 2026-04-29: фейковые "новые" статьи при импорте Березня 2026 ==

При добавлении нового месяца (Березень 2026) скрипт `11_upload_articles.py` попытался создать **9 "новых" статей**, которых раньше не было в `Catalog.А_Статьи_PL`. После анализа выяснилось:

**Из 9 кандидатов:**
- **1 опечатка**: "Арена сторонней техники" в Excel вместо корректного "Аренда сторонней техники" (locked в БД).
- **8 строк-комментариев финансиста** с числовыми суммами в названии (столбец B, лист Excel):
  - "Кернел кухня - - 4 554 246грн"
  - "Кернел кухня - 0 грн"
  - "ВООЗ 2025 - -2 647 040 грн"
  - "ВООЗ 2025 - 3,7 млн грн согл сс"
  - "МД ООН 2025 - -996 544грн 8 домов"
  - "МД ООН 2025 - 0,7 млн грн 8 домов согл сс"
  - "Затраты ЦО"
  - "Затраты ЦО - 5 018 436грн на которие нет прямого влияния"

**Корень проблемы:** функция `classify_row()` в `scripts/utils/excel_parser.py` фильтровала строки-итоги через `config.TOTAL_ROW_KEYWORDS`, среди которых был только литерал `", грн"` — с ведущей запятой. Но в Березень-Excel финансист писал суммы без запятой перед "грн" ("246грн", "грн согл сс"), поэтому строки проходили как `kind="detail"` и попадали в `02_unique_articles.json` как новые статьи.

**Симптом в 11_upload_articles.py:**
- Платформенный гард `Справочник.А_Статьи_PL.МодульОбъекта.ПередЗаписью` для расходных PL-статей требует обязательную ДДС в шапке. У "Затраты ЦО" mapping не нашёл ДДС → запись падала с ошибкой `«ДДС обязательна для расходной статьи»`.
- Для статьи "Арена сторонней техники" fuzzy-mapper назначил ДДС `Аренда сторонней техники`, которая уже была в locked-статье `Аренда сторонней техники` → платформа падала с ошибкой `«ДДС не может использоваться одновременно в нескольких PL-статьях, если по ней есть обороты в АДР»`.

**Исправление (системное, 4 точки):**

1. **`scripts/utils/excel_parser.py`** — regex-паттерн «число + единица валюты» в названии:
   ```python
   _COMMENT_VALUE_RE = re.compile(
       r"\d[\d\s ,.\-]*\s*(грн|тыс|млн|тис)\b",
       re.IGNORECASE,
   )
   ```
   В `classify_row()`: если `_COMMENT_VALUE_RE.search(s)` → `return "summary"` (не статья).

2. **`config.EXTRA_COMMENT_NAMES`** — set точных имён подгрупп без чисел ("Затраты ЦО"). В `classify_row()` сравнивается через `_norm_name`.

3. **`config.ARTICLE_NAME_ALIASES`** — dict `{Excel-имя-с-опечаткой: каноничное-имя-в-Catalog}`. Применяется в:
   - `02_extract_unique_articles.py` при сборе raw-имён (alias-ы сворачиваются в каноничную статью).
   - `08_prepare_documents.py` при поиске `by_norm` (rows с alias-именем матчатся на каноничную статью).

   ```python
   ARTICLE_NAME_ALIASES = {
       "Арена сторонней техники": "Аренда сторонней техники",
   }
   ```

4. **`scripts/11_upload_articles.py`** — два предохранителя:
   - SKIP-NEW для расходных без ДДС: если новая статья и `type_statii=Расход` и `dds_by_pl[name]` пуст → пропустить (не создавать); финансист должен создать вручную.
   - try/except вокруг `obj.Записать()`: при `«ДДС не может использоваться одновременно»` → SKIP-CONFLICT (с логом), цикл продолжается.

**Результат после фикса (повторный прогон 11):**
- `locked=60 created=0 found=3 skipped_no_dds=0` — ни одна "новая" статья не создаётся, locked не зачеплены.
- `02_unique_articles.json` сократился с 72 до 63 уникальных статей.

**Применять при добавлении любого нового месяца:**
- Если в `02_unique_articles.json` появляется "новая" статья — сначала через `execute_query` поискать в БД по подобному имени (`Наименование ПОДОБНО %name%`). Часто это уже locked-статья с опечаткой → добавить в `ARTICLE_NAME_ALIASES`.
- Если название содержит число с валютой и regex не схватил (другая валюта/формат) — расширить `_COMMENT_VALUE_RE`.
- Точные подгруппы без чисел → в `EXTRA_COMMENT_NAMES`.
