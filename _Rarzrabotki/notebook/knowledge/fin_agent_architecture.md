# Архітектура підсистеми Фінансових Агентів (ФінАгенти) — BAS ERP 2.5 INDUSTRIALBUD

Підсистема ФінАгентів обробляє грошові потоки через посередників (фінансових агентів: Коло, Діла, Банко тощо). Гроші від контрагентів надходять спочатку на рахунок фінагента, потім фінагент перераховує їх на рахунок організації з утриманням комісії.

Потік даних: Казна (BuhKazn) -> обмін -> ERP (BaseERP) -> обробка ОбновитьПриходДенегОтФинАгентаПослеОбмена

---

== ФУНДАМЕНТАЛЬНЕ ПРАВИЛО: ПІДРОЗДІЛ ОБОВ'ЯЗКОВИЙ В КОЖНОМУ ПОШУКУ ==

Підрозділ (Подразделение / СтруктураПредприятия) — це ФУНДАМЕНТАЛЬНИЙ вимір в конфігурації ІНДАСТРІАЛБУД.
Управлінський баланс будується ДО РІВНЯ ПІДРОЗДІЛІВ. Кожна гривня повинна бути прив'язана до конкретного підрозділу.

НІКОЛИ НЕ МОЖНА:
- Шукати платіжки, документи, залишки БЕЗ фільтра по Подразделение
- Пропонувати fallback "а давайте пошукаємо без підрозділу"
- Створювати документи з пустим Подразделение
- Ігнорувати розбіжність підрозділів між пов'язаними документами

ЧОМУ: Якщо платіжка з підрозділу "Строительство" потрапить в документ підрозділу "Логістика" — управлінський баланс покаже неправильні залишки по ОБОХ підрозділах. Це не просто помилка в одному документі — це СИСТЕМНА помилка яка ламає фінансову звітність.

ЯКЩО підрозділ не знайдений при пошуку:
- Сообщить() з деталями (який підрозділ шукали, який документ)
- Пропустити рядок (Продолжить)
- НЕ шукати без підрозділу
- Користувач сам розбереться чому підрозділ не збігається

== КЛЮЧОВІ ОБ'ЄКТИ ==

Документ: А_ПриходДенегОтФинАгента
Призначення: Фіксує приход грошей від фінансового агента на касу організації
Кількість в базі: ~119
Реєстратор регістру: А_ДенежныеСредстваФинАгенты
Прапорці: А_Обработан, А_ВведенВЕРП, А_Необновлять

Реквізити шапки:
- Организация, ФинАгент (Справочник.А_ФинАгенты), Касса
- СуммаДокумента, А_ПроцентФинАгента, СуммаКомиссииФА
- СтатьяДвиженияДенежныхСредств (код "УТ-001082" = Поступление от Фин агента)
- А_СтатьяДвиженияДенежныхСредствКазна (стаття ДДС з Казни)
- А_Подразделение (підрозділ з Казни), А_НаправлениеДеятельности (напрямок з Казни)
- Подразделение (розрахований ERP підрозділ)
- НоменклатураЗатрат (код "00-00000326" = Юридичні послуги — для комісії)
- СтатьяЗатратКомиссия (код "100000032" = РКО_Плата за РКО)
- ДокументКазна (рядок — номер документа з Казни)
- А_НеСовпадаетПодразделение (прапорець розбіжності)

Таблична частина А_РасшифровкаФинАгент:
- ФинАгент (Справочник.А_ФинАгенты)
- ДокументПередачи (Документ.СписаниеБезналичныхДенежныхСредств) — ПЛАТІЖКА яка перерахувала гроші фінагенту
- Направление (НаправленияДеятельности)
- Сумма, СуммаКомиссииФА

ПРОБЛЕМА: Після обміну з Казни поле ДокументПередачи може бути ПУСТИМ (не знайдена платіжка при обміні)

Таблична частина РасшифровкаПлатежа:
- Контрагент, ДокСписаниеБезналичныхДенежныхСредств, ОбъектРасчетов
- Сумма, А_ПроцентФинАгента, СуммаКомиссии, Подразделение
Заповнюється автоматично процедурою ОбновитьПриходДенегОтФинАгентаПослеОбмена()

Регістр: А_ДенежныеСредстваФинАгенты
Тип: Залишковий (остатки)
Реєстратори: А_ПриходДенегОтФинАгента, СписаниеБезналичныхДенежныхСредств, КорректировкаРегистров

Виміри:
- ФинАгент (Справочник.А_ФинАгенты)
- ДокументПередачи (Документ.СписаниеБезналичныхДенежныхСредств) — та сама платіжка
- НаправлениеДеятельности, Подразделение
- Контрагент, ДоговорКонтрагента, ОбъектРасчетов

Ресурси:
- Сумма — основна сума
- СуммаКомиссии — комісія фінагента
- СуммаСКомиссией — сума разом з комісією

== ПОТІК ГРОШЕЙ ЧЕРЕЗ ФІНАГЕНТА ==

Крок 1: Контрагент платить фінагенту (гроші на рахунку фінагента)
  -> Документ: СписаниеБезналичныхДенежныхСредств (ПЛАТІЖКА)
  -> Рух: А_ДенежныеСредстваФинАгенты (Приход) з ДокументПередачи = ця платіжка

Крок 2: Фінагент перераховує на касу організації (мінус комісія)
  -> Документ: А_ПриходДенегОтФинАгента
  -> Рух: А_ДенежныеСредстваФинАгенты (Расход) з тим самим ДокументПередачи

Крок 3: А_ПриходДенегОтФинАгента автоматично створює підлеглі документи:
  -> ПриходныйКассовыйОрдер (прихід на касу) — ХозОперация = ВозвратДенежныхСредствОтПоставщика
  -> РасходныйКассовыйОрдер (комісія фінагента) — ХозОперация = ОплатаПоставщику
  -> ПриобретениеТоваровУслуг (послуга комісії) — ХозОперация = ЗакупкаУПоставщика

== ОБМІННА ПРОЦЕДУРА: ОбновитьПриходДенегОтФинАгентаПослеОбмена() ==

Умова: А_Обработан = Ложь
Що робить:
1. Визначає Подразделение через А_Привилегированный.А_ПолучитьПодразделениеПоНаправлениюИПодразделениюКазны()
2. Встановлює довідкові дані: СтатьяДДС = "УТ-001082", СтатьяЗатратКомиссия = "100000032", НоменклатураЗатрат = "00-00000326"
3. ОЧИЩУЄ РасшифровкаПлатежа
4. Цикл по А_РасшифровкаФинАгент:
   - Бере ДокументПередачи (платіжку)
   - Бере А_ПроцентФинАгента з платіжки
   - Цикл по РасшифровкаПлатежа ПЛАТІЖКИ:
     - Розподіляє суму по рядках пропорційно
     - Заповнює Контрагент, Сумма, СуммаКомиссии, ОбъектРасчетов, Подразделение
   - Якщо залишок суми > 0 — додає до останнього рядка
5. Встановлює А_Обработан = Истина

КРИТИЧНИЙ МОМЕНТ: Якщо ДокументПередачи ПУСТИЙ — цикл по СтрокаТЗ.ДокументПередачи.РасшифровкаПлатежа НЕ виконається (немає рядків). Результат: РасшифровкаПлатежа залишиться пустою → неправильні рухи по регістрах.

---

== ПРОБЛЕМА: ПУСТИЙ ДокументПередачи ==

Причина: При обміні з Казни (BuhKazn) платіжка (СписаниеБезналичныхДенежныхСредств) може ще не існувати в ERP на момент обміну А_ПриходДенегОтФинАгента. Або обмін не зміг знайти відповідність.

Статистика: ~8 документів А_ПриходДенегОтФинАгента мають рядки в А_РасшифровкаФинАгент з пустим ДокументПередачи.

Рішення: Шукати ПЕРШУ платіжку по регістру А_ДенежныеСредстваФинАгенты по двох критеріях: ФинАгент + Подразделение. Дата платіжки ПІСЛЯ дати документа А_ПриходДенегОтФинАгента (бо приход грошей в касу часто раніше ніж банківська платіжка).

Бізнес-логіка: Фінагент бере гроші у клієнта і віддає в касу ОДРАЗУ, а по банку платіжка (СписаниеБезналичныхДС) проходить ПІЗНІШЕ. Тому дивимось "в майбутнє" від дати документа.
Суму НЕ перевіряємо — беремо першу підходящу по ФинАгент + Подразделение (платіжка гарантовано існує бо банк вже звірений).
КРИТИЧНО: Пошук БЕЗ Подразделение ЗАБОРОНЕНИЙ! Підрозділ — фундаментальний вимір для управлінського балансу. Якщо платіжка потрапить не в той підрозділ — баланс зламається до рівня підрозділів. Якщо платіжка не знайдена по ФинАгент+Подразделение — Сообщить і пропустити рядок, НЕ шукати без підрозділу.

Запит для пошуку платіжки:
ВЫБРАТЬ ПЕРВЫЕ 1
    ДокументПередачи,
    ДокументПередачи.Дата КАК ДатаПлатежки,
    ДокументПередачи.Номер КАК НомерПлатежки,
    Сумма
ИЗ РегистрНакопления.А_ДенежныеСредстваФинАгенты
ГДЕ ФинАгент = &ФинАгент
    И Подразделение = &Подразделение
    И ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
    И ДокументПередачи <> ЗНАЧЕНИЕ(Документ.СписаниеБезналичныхДенежныхСредств.ПустаяСсылка)
    И Период >= &ДатаДокумента
УПОРЯДОЧИТЬ ПО Период

== СТВОРЕННЯ ПІДЛЕГЛИХ ДОКУМЕНТІВ ==

А_ПриходДенегОтФинАгента створює 3 підлеглих документи (патерн Find-Or-Create):

1. ПриходныйКассовыйОрдер (ПКО):
   - ХозяйственнаяОперация = ВозвратДенежныхСредствОтПоставщика
   - А_ОбработанКазна = Истина, А_ВведенВЕРП = Истина
   - Касса = Касса з шапки
   - СуммаДокумента = Сума рядка
   - Дата = Дата + 1 (наступна секунда)
   - А_ПриходДенегОтФинАгента = Ссылка (зв'язок з батьківським)

2. РасходныйКассовыйОрдер (РКО) — комісія:
   - ХозяйственнаяОперация = ОплатаПоставщику
   - А_ОбработанКазна = Истина, А_ВведенВЕРП = Истина
   - СуммаДокумента = СуммаКомиссии
   - Дата = Дата + 2
   - А_ПриходДенегОтФинАгента = Ссылка + А_ПриходныйКассовыйОрдерОтФинАгента = ПКО

3. ПриобретениеТоваровУслуг — послуга комісії:
   - ХозяйственнаяОперация = ЗакупкаУПоставщика
   - А_ВведенВЕРП = Истина, А_Обработан = Истина
   - Курс = 1, Кратность = 1
   - СуммаДокумента = СуммаКомиссии
   - ТЧ Товары: Номенклатура = НоменклатураЗатрат, СтавкаНДС = "Без НДС", СписатьНаРасходы = Истина
   - Дата = Дата + 3

КРИТИЧНІ ПРАПОРЦІ:
- А_ОбработанКазна = Истина — для ПКО/РКО (інакше РасшифровкаПлатежа буде очищена!)
- А_ВведенВЕРП = Истина — для всіх трьох (інакше обмінна процедура затре дані!)
- А_Обработан = Истина — для ПриобретениеТоваровУслуг
- Курс = 1, Кратность = 1 — для ПриобретениеТоваровУслуг (інакше СуммаВзаиморасчетов = 0!)

== ЗВ'ЯЗКИ МІЖ ОБ'ЄКТАМИ ==

А_ПриходДенегОтФинАгента
  |-- А_РасшифровкаФинАгент.ДокументПередачи -> СписаниеБезналичныхДенежныхСредств (ПЛАТІЖКА)
  |     |-- СписаниеБезналичныхДС.РасшифровкаПлатежа -> ОбъектРасчетов, Контрагент
  |
  |-- створює ПриходныйКассовыйОрдер (А_ПриходДенегОтФинАгента = Ссылка)
  |-- створює РасходныйКассовыйОрдер (А_ПриходДенегОтФинАгента = Ссылка)
  |-- створює ПриобретениеТоваровУслуг (А_ПриходДенегОтФинАгента = Ссылка)

Регістр А_ДенежныеСредстваФинАгенты:
  Приход: СписаниеБезналичныхДенежныхСредств (гроші пішли фінагенту)
  Расход: А_ПриходДенегОтФинАгента (фінагент перерахував організації)
  Залишок: скільки грошей ще у фінагента
