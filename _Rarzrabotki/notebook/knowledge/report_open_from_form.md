# Відкриття звіту з форми документа BAS ERP 2.5 — правильна передача Варіанту та Відбору

Цей документ описує єдино правильний спосіб відкрити звіт у заданому варіанті з попередньо встановленим відбором з форми документа (або іншої керованої форми). Базований на реальному досвіді виправлення кнопки «Открыть сверку с ЕРП» на формі документа `А_ОтчетPL` (квітень 2026).

**Остання редакція: 2026-04-19** — додано критичний розділ про `Параметры.Отбор → РежимОтображения=Недоступный` та правильне рішення через `ПользовательскиеНастройки.Элементы` за userSettingID.

Конфігурація: BAS ERP 2.5 (v2.13), БСП (бібліотека стандартних підсистем).
Тип відкриття: через `ОткрытьФорму("Отчет.ИмяОтчета.Форма", ПараметрыФормы, Власник)`, де форма успадковує `CommonForm.ФормаОтчета` з БСП.

---

== КОРЕНЕВА ПРОБЛЕМА №1: імена параметрів БСП ==

БСП `CommonForm.ФормаОтчета` (файл `CommonForms/ФормаОтчета/Ext/Form/Module.bsl`) приймає конкретні імена параметрів. Неправильне ім'я ігнорується — і БСП відкриває дефолтний варіант звіту з дефолтним відбором.

ПРАВИЛЬНІ ІМЕНА ПАРАМЕТРІВ (перевірено по коду БСП):

Параметр: **КлючВарианта**
Тип: Строка
Призначення: Ім'я варіанту СКД що відкривається (збігається з `<dcsset:name>` у `Template.xml` схеми компоновки).
Де використовується в БСП: рядки 127, 143, 304, 307, 1526, 1527 модуля `CommonForm.ФормаОтчета`.

ПОМИЛКОВІ ІМЕНА ЯКІ НЕ ПРАЦЮЮТЬ (не використовуйте):
- `ВариантКлюч` (частий typo — саме цей параметр не розпізнається БСП, відкривається дефолтний варіант)

Параметр: **Отбор** ⚠️ ОБЕРЕЖНО — ДЕТАЛЬНО ДИВ. РОЗДІЛ «КОРЕНЕВА ПРОБЛЕМА №2»
Тип: Структура — ключ=Ім'яПоля, значення=Значення відбору (один елемент або Массив/СписокЗначений для множинного відбору)
Призначення: **Фіксовані (недоступні для редагування) відбори**, які БСП додає до компоновщика налаштувань після завантаження варіанту.
Де обробляється в БСП: рядок 372 — `ОтчетыСервер.УстановитьФиксированныеОтборы(ФормаПараметры.Отбор, ...)`

Параметр: **ПользовательскиеНастройки**
Тип: ПользовательскиеНастройкиКомпоновкиДанных
Призначення: Перевизначення параметрів/фільтрів користувацьких налаштувань (Період, і **редагований** відбір).

Параметр: **СформироватьПриОткрытии**
Тип: Булево
Призначення: Якщо Істина — звіт формується автоматично одразу після відкриття форми.

== 🔥 КОРЕНЕВА ПРОБЛЕМА №2: `Параметры.Отбор` робить фільтр **НЕДОСТУПНИМ** ==

**СИМПТОМ:** після відкриття звіту з форми документа пользователь не може перетягнути фільтр у шапку звіту (пункт меню «В шапке отчёта» не працює або скидається). У діалозі «Пользовательские настройки элемента» у фільтра стоїть «Режим редактирования: Недоступный».

**КОРЕНЬ (задокументована поведінка БСП):** параметр `Отбор` призначений для **фіксованих (read-only) відборів** — наприклад, коли документ-список передає відбір за Організацією у звіт-підлеглий, де пользователь не повинен змінювати. Це реалізовано в `CommonModules/ОтчетыСервер/Ext/Module.bsl`, процедура `УстановитьФиксированныеОтборы`:

```bsl
Процедура УстановитьФиксированныеОтборы(СтруктураОтборов, НастройкиКД, НастройкиОтчета) Экспорт
    ...
    Недоступный = РежимОтображенияЭлементаНастройкиКомпоновкиДанных.Недоступный;
    Для Каждого КлючИЗначение Из СтруктураОтборов Цикл
        ...
        ПараметрКД.РежимОтображения = Недоступный;   // ← ключ проблеми
        ...
        ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбора(
            ОтборыКД, Имя, Значение, ВидСравненияКД, , Істина, Недоступный, "");
    КонецЦикла;
КонецПроцедуры
```

Кожен елемент зі структури `Параметры.Отбор` стає елементом відбору з `РежимОтображения = Недоступный`, тобто **без можливості редагування користувачем**.

**ПОМИЛКОВІ СПРОБИ ФІКСУ (не працюють):**
1. Ставити `<viewMode>QuickAccess</viewMode>` у XML варіанту — БСП перезаписує цей режим на `Недоступный` runtime.
2. Правити `<viewMode>` через skd-edit — допомагає тільки якщо відкривати звіт **без** параметра `Отбор`. При передачі `Отбор` режим знову стає Недоступним.
3. Чистити хранилище пользовательських налаштувань — не допомагає, БСП перевизначає щоразу.

**ПРАВИЛЬНЕ РІШЕННЯ: передавати відбір через `ПользовательскиеНастройки`, а НЕ через `Отбор`**

`ПользовательскиеНастройки` — це колекція елементів, які пользователь **може** редагувати (параметри, фільтри з `userSettingID`). Якщо встановити значення відбору у цій колекції, `РежимОтображения` **успадковується з XML варіанту** (`Обычный` або `QuickAccess`) і НЕ переозначається на `Недоступный`.

== ПРАВИЛЬНИЙ ПАТТЕРН: виклик з форми документа ==

```bsl
&НаКлиенте
Процедура ОткрытьСверкуСЕРП(Команда)

    // 1) Вибрати ключ варіанту
    Якщо Объект.ВключатьДочерние И ЗначениеЗаполнено(Объект.НаправлениеДеятельности) Тогда
        ВариантКлюч = "А_ОтчетPL_РасшифровкаПоНаправлению";
        ПодразделениеОтбора = Неопределено;
        НаправлениеОтбора = Объект.НаправлениеДеятельности;
    Иначе
        ВариантКлюч = "А_ОтчетPL_РасшифровкаДокументаОтчетPL";
        ПодразделениеОтбора = ?(ЗначениеЗаполнено(Объект.Подразделение), Объект.Подразделение, Неопределено);
        НаправлениеОтбора = Неопределено;
    КонецЕсли;

    // 2) Сформувати пользовательські налаштування з періодом І відбором (єдиним каналом)
    ПользовательскиеНастройки = СформироватьПользовательскиеНастройкиОтчета(
        Объект.Дата, ВариантКлюч, ПодразделениеОтбора, НаправлениеОтбора);

    // 3) Параметри форми — БЕЗ «Отбор»!
    ПараметрыФормы = Новый Структура;
    ПараметрыФормы.Вставить("КлючВарианта", ВариантКлюч);
    Если ПользовательскиеНастройки <> Неопределено Тогда
        ПараметрыФормы.Вставить("ПользовательскиеНастройки", ПользовательскиеНастройки);
    КонецЕсли;
    ПараметрыФормы.Вставить("СформироватьПриОткрытии", Истина);

    ОткрытьФорму("Отчет.А_ОтчетPL.Форма", ПараметрыФормы, ЭтаФорма);

КонецПроцедуры
```

== ПРАВИЛЬНЕ ФОРМУВАННЯ ПОЛЬЗОВАТЕЛЬСКИХ НАСТРОЕК (Період + Відбір) ==

**Критичний нюанс:** у `ПользовательскиеНастройки.Элементы` свойство `ЛевоеЗначение` **недоступно** (викине помилку «Свойство 'ЛевоеЗначение' не поддерживается элементом коллекции пользовательских настроек»). Шукати треба за `ИдентификаторПользовательскойНастройки` — GUID, який ми отримуємо з основних налаштувань (`Настройки.Отбор.Элементы`, де `ЛевоеЗначение` доступне).

```bsl
&НаСервереБезКонтекста
Функция СформироватьПользовательскиеНастройкиОтчета(Дата, ВариантКлюч,
    ПодразделениеОтбора = Неопределено, НаправлениеОтбора = Неопределено)

    Отчет = Отчеты.А_ОтчетPL.Создать();
    Вариант = Отчет.СхемаКомпоновкиДанных.ВариантыНастроек.Найти(ВариантКлюч);
    Если Вариант = Неопределено Тогда
        Возврат Неопределено;
    КонецЕсли;

    Компоновщик = Новый КомпоновщикНастроекКомпоновкиДанных;
    Источник = Новый ИсточникДоступныхНастроекКомпоновкиДанных(Отчет.СхемаКомпоновкиДанных);
    Компоновщик.Инициализировать(Источник);
    Компоновщик.ЗагрузитьНастройки(Вариант.Настройки);

    Период = Новый СтандартныйПериод;
    Период.ДатаНачала = НачалоМесяца(Дата);
    Период.ДатаОкончания = КонецМесяца(Дата);

    // ШАГ 1: прочитати GUID-и відборів з варіантних налаштувань
    // (тут ЛевоеЗначение доступне).
    ИдентификаторПодразд = "";
    ИдентификаторНапр = "";
    Для Каждого ЭлВариантного Из Компоновщик.Настройки.Отбор.Элементы Цикл
        Если ТипЗнч(ЭлВариантного) = Тип("ЭлементОтбораКомпоновкиДанных") Тогда
            ИмяПоля = Строка(ЭлВариантного.ЛевоеЗначение);
            Если ИмяПоля = "Подразделение" Тогда
                ИдентификаторПодразд = ЭлВариантного.ИдентификаторПользовательскойНастройки;
            ИначеЕсли ИмяПоля = "НаправлениеДеятельности" Тогда
                ИдентификаторНапр = ЭлВариантного.ИдентификаторПользовательскойНастройки;
            КонецЕсли;
        КонецЕсли;
    КонецЦикла;

    // ШАГ 2: пройти по ПользовательскиеНастройки та встановити значення за GUID-ом.
    Для Каждого Элемент Из Компоновщик.ПользовательскиеНастройки.Элементы Цикл
        ТипЭл = ТипЗнч(Элемент);

        // Параметр Період (userSettingID = строка "Период")
        Если ТипЭл = Тип("ЗначениеПараметраНастроекКомпоновкиДанных")
            И Элемент.ИдентификаторПользовательскойНастройки = "Период" Тогда
            Элемент.Значение = Период;
            Элемент.Использование = Истина;

        // Елемент відбору (userSettingID = GUID, знайшли на ШАГ 1)
        ИначеЕсли ТипЭл = Тип("ЭлементОтбораКомпоновкиДанных") Тогда
            Идентификатор = Элемент.ИдентификаторПользовательскойНастройки;

            Если Идентификатор = ИдентификаторПодразд И ЗначениеЗаполнено(ПодразделениеОтбора) Тогда
                СписокЗначений = Новый СписокЗначений;
                СписокЗначений.Добавить(ПодразделениеОтбора);
                Элемент.ПравоеЗначение = СписокЗначений;
                Элемент.Использование = Истина;

            ИначеЕсли Идентификатор = ИдентификаторНапр И ЗначениеЗаполнено(НаправлениеОтбора) Тогда
                СписокЗначений = Новый СписокЗначений;
                СписокЗначений.Добавить(НаправлениеОтбора);
                Элемент.ПравоеЗначение = СписокЗначений;
                Элемент.Использование = Истина;
            КонецЕсли;
        КонецЕсли;
    КонецЦикла;

    Возврат Компоновщик.ПользовательскиеНастройки;

КонецФункции
```

**Важливо:**
1. Для параметра Період userSettingID має бути строкою (напр. "Период"), а не згенерованим UUID.
2. Для відбору userSettingID — GUID, який СКД генерує автоматично. Читаємо його з `Настройки.Отбор` на першому кроці.
3. Для `comparisonType=InList`/`InListByHierarchy` правостороннє значення — завжди `СписокЗначений`, навіть якщо одне значення (додайте його у список).
4. `Элемент.Использование = Истина` — без цього БСП проігнорує фільтр.

== СКД-ВАРІАНТ: правильна структура XML фільтру ==

Щоб фільтр зберігся редагованим після відкриття з документа, у XML варіанту він має бути у форматі, який платформа 1С сохраняє без нормалізації:

```xml
<dcsset:filter>
    <dcsset:item xsi:type="dcsset:FilterItemComparison">
        <dcsset:use>false</dcsset:use>
        <dcsset:left xsi:type="dcscor:Field">Подразделение</dcsset:left>
        <dcsset:comparisonType>InListByHierarchy</dcsset:comparisonType>
        <dcsset:right xsi:type="v8:ValueListType">
            <v8:valueType/>
            <v8:lastId xsi:type="xs:decimal">-1</v8:lastId>
        </dcsset:right>
        <dcsset:viewMode>Normal</dcsset:viewMode>
        <dcsset:userSettingID>43fffebb-fede-4af3-9a9d-112dce5ef8ff</dcsset:userSettingID>
    </dcsset:item>
</dcsset:filter>
```

**Критичні вимоги (перевірено через `/db-dump-xml` після `/db-load-xml`):**

1. `<dcsset:comparisonType>` має бути `InListByHierarchy` (для ієрархічних довідників) або `InList` (для звичайних) — **НЕ** `Equal`.
2. `<dcsset:right>` — тип `v8:ValueListType` з `<v8:lastId>-1</v8:lastId>` — **НЕ** `dcscor:DesignTimeValue`.
3. `<dcsset:viewMode>` — значення `Normal` — **НЕ** `QuickAccess` (платформа відкидає QuickAccess при Equal+DesignTimeValue, зберігає лише при InList+ValueListType).
4. `<dcsset:userSettingID>` — GUID (можна ручним `new Guid` або скопіювати зі стандартного варіанту).

**Ідентичний формат використовує стандартний звіт АнализДоходовРасходов** — можна подивитись `Reports/АнализДоходовРасходов/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml` (рядки 10928-10938) як реферанс.

**Коли пользователь робить «В шапке отчёта»** — БСП змінює `viewMode` з `Normal` на `QuickAccess` у персональному хранилищі налаштувань (не у XML!). Це нормально — XML варіанту залишається з `Normal`, а пользовательський вибір зберігається окремо.

== ПОШИРЕНІ ПОМИЛКИ ТА ДІАГНОСТИКА ==

**ПОМИЛКА 1: Відкривається дефолтний варіант «Основний»**
ПРИЧИНА: Використано `ВариантКлюч` замість `КлючВарианта` у ПараметрыФормы.
ДІАГНОСТИКА: На вкладці відкритого звіту заголовок = синонім звіту (напр. «Сравнение PL с 1С»), а не назва варіанту («Расшифровка по направлению»).
ФІКС: `ПараметрыФормы.Вставить("КлючВарианта", ВариантКлюч)` — правильне ім'я.

**ПОМИЛКА 2: Фільтр з документа → у шапці звіту стоїть «Недоступний», не можна прибрати/перетягнути**
ПРИЧИНА: Відбір переданий через `Параметры.Отбор`, БСП ставить `РежимОтображения = Недоступный`.
ДІАГНОСТИКА: В діалозі «Пользовательские настройки элемента» «Режим редактирования» = «Недоступный» (заблокований).
ФІКС:
1. Видалити `ПараметрыФормы.Вставить("Отбор", ...)` з клієнтського коду.
2. Додати функцію формування `ПользовательскиеНастройки` з встановленням значень відбору за GUID (див. приклад вище).
3. Передати через `ПараметрыФормы.Вставить("ПользовательскиеНастройки", ...)`.

**ПОМИЛКА 3: «Свойство ЛевоеЗначение не поддерживается элементом коллекции пользовательских настроек»**
ПРИЧИНА: Спроба читати `Элемент.ЛевоеЗначение` з колекції `Компоновщик.ПользовательскиеНастройки.Элементы` — там це свойство недоступно.
ФІКС: Пройти спочатку по `Компоновщик.Настройки.Отбор.Элементы` (там ЛевоеЗначение є), зберегти GUID-и, потім пройти по `ПользовательскиеНастройки.Элементы` і порівнювати за `ИдентификаторПользовательскойНастройки` (GUID).

**ПОМИЛКА 4: Період звіту = поточний місяць замість дати документа**
ПРИЧИНА: `userSettingID` параметра Період — згенерований UUID, а код шукає `ИдентификаторПользовательскойНастройки = "Период"` (рядок).
ФІКС: Замінити userSettingID в XML варіанту з UUID на строковий "Период".

**ПОМИЛКА 5: `<viewMode>QuickAccess</viewMode>` з XML «зникає» після `/db-load-xml`**
ПРИЧИНА: Платформа 1С при завантаженні XML з `comparisonType=Equal` та `<right xsi:type="dcscor:DesignTimeValue">` **відкидає** `viewMode` — після `/db-dump-xml` поля не буде в XML.
ФІКС: Використати формат як у стандартному АнализДоходовРасходов — `InList`/`InListByHierarchy` + `<right xsi:type="v8:ValueListType">`. Тоді `viewMode=Normal` зберігається і не губиться при dump/load циклах.

**ПОМИЛКА 6: Фільтр з use=false все одно відображається включеним**
ПРИЧИНА: БСП при склейці переданого Отбор з налаштуваннями варіанту може скинути `<use>false</use>`.
ФІКС: Просто видалити фільтр з варіанту (через `skd-edit remove-filter`), не намагайтесь тримати його вимкненим.

== ПЕРЕВІРКА ЧЕРЕЗ PYTHON COM ==

Щоб переконатись що варіант коректний — відкрити через COM та роздрукувати вміст налаштувань:

```python
import win32com.client
v8 = win32com.client.Dispatch("V83.COMConnector")
```

== КЛЮЧОВІ ТЕЗИ ==

1. **Ім'я параметра варіанту: `КлючВарианта`** (не `ВариантКлюч`).
2. **`Параметры.Отбор` робить фільтр Недоступним** — використовувати тільки для справді фіксованих відборів, які пользователь НЕ повинен змінювати.
3. **Для редагованого відбору — `ПользовательскиеНастройки`** з встановленням значень за `ИдентификаторПользовательскойНастройки` (GUID, взятим з `Настройки.Отбор.Элементы`).
4. **Для фільтру в XML варіанту** — формат `InList`/`InListByHierarchy` + `<right xsi:type="v8:ValueListType">` + `<viewMode>Normal</viewMode>` (перевірено через `/db-dump-xml`).
5. **`ЛевоеЗначение`** доступне тільки в `Настройки.Отбор.Элементы`, **не** в `ПользовательскиеНастройки.Элементы`.
