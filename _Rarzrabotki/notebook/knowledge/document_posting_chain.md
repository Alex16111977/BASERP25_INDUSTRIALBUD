# Ланцюжок подій при записі/проведенні документів BAS ERP 2.5 INDUSTRIALBUD

## Загальна послідовність подій

При записі/проведенні будь-якого документа в ERP виконується така послідовність:

1. ОбработкаЗаполнения() — тільки при створенні нового документа
2. Підписка А_ДоработкаДокументыПередЗаписью → А_СобытияОбъектов.А_ДоработкаДокументыПередЗаписью()
3. МодульОбъекта.ПередЗаписью() — стандартний код документа
4. МодульОбъекта.ПриЗаписи() — стандартний код
5. Підписка А_ДоработкаДокументыПриЗаписи → А_СобытияОбъектов.А_ДоработкаДокументыПриЗаписи()
6. ОбработкаПроведения() — рухи по регістрах (тільки при проведенні)

ВАЖЛИВО: Підписки на події (пункти 2 і 5) спрацьовують ЗАВЖДИ — і при ручному створенні, і при обміні, і при програмному створенні. Виключення: якщо ОбменДанными.Загрузка = True (але НЕ всі процедури перевіряють цей прапорець!).

## Кастомний модуль А_СобытияОбъектов

Це загальний модуль з властивістю ExternalConnection=true (виправлено — раніше було false, що викликало помилку "Обработчик события не найден" при COM-з'єднаннях).

### Підписка А_ДоработкаДокументыПередЗаписью

Обробляє наступні типи документів:

== ЗаказПоставщику ==
Що робить:
- Примусово встановлює Организация з А_Привилегированный.А_ПолучитьОрганизациюУпр()
- Якщо заповнено А_ДоговорИзБанка → копіює в Договор
- З Договора копіює: Подразделение, НаправлениеДеятельности, ГруппаФинансовогоУчета
- Для нових документів: Статус = Согласован, Приоритет = "Середній"
- Для існуючих: забороняє зміну Договора/Валюти якщо є проведені документи приходу (якщо немає ролі А_Гермес)

РИЗИК ПРИ ОБМІНІ: Організація буде перезаписана! Якщо в BuhBud інша організація — вона затреться.
РИЗИК: Подразделение, НаправлениеДеятельности, ГруппаФинансовогоУчета беруться з Договора — якщо Договор пустий або неправильний, ці поля будуть пустими.

== ЗаказКлиента ==
Що робить:
- Якщо заповнено А_ДоговорИзБанка → копіює в Договор

== ПриходныйКассовыйОрдер ==
Що робить:
- Для кожного рядка РасшифровкаПлатежа: якщо Подразделение пусте → заповнює з шапки документа

РИЗИК: Якщо в шапці Подразделение пусте і в РасшифровкаПлатежа теж — залишиться пустим.

== РасходныйКассовыйОрдер ==
Аналогічно ПКО:
- Для кожного рядка РасшифровкаПлатежа: якщо Подразделение пусте → заповнює з шапки

== ПриобретениеТоваровУслуг ==
Що робить:
- Якщо заповнено Договор.Подразделение І ХозОперация НЕ ЗакупкаЧерезПодотчетноеЛицо → Подразделение = Договор.Подразделение

РИЗИК: Подразделение перезаписується з Договора. Якщо Договор пустий — Подразделение пусте.

== СписаниеБезналичныхДенежныхСредств ==
Що робить: НІЧОГО (процедура пуста, тільки коментар // Возврат;)

---

### Підписка А_ДоработкаДокументыПриЗаписи

Обробляє наступні типи документів:

== СписаниеБезналичныхДенежныхСредств ==
Складна логіка:
- Якщо ХозОперация = ПеречислениеДенежныхСредствНаДругойСчет → автоматично створює ПоступлениеБезналичныхДенежныхСредств (парний документ)
- Якщо ХозОперация = ВыплатаЗарплатыПоЗарплатномуПроекту:
  - При проведенні: проводить пов'язані Ведомості
  - При відміні проведення: відміняє проведення Ведомостей
- Якщо ХозОперация = ОплатаПоставщику:
  - Оновлює ЗаказПоставщику: записує А_СтатьяДвиженияДенежныхСредств та А_ДоговорИзБанка/Договор з РасшифровкаПлатежа
  - Ставить ОбменДанными.Загрузка = Истина на ЗаказПоставщику щоб не спрацьовували підписки
- Якщо А_ФинАгент пустий → викликає СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению

КРИТИЧНИЙ РИЗИК: При записі СписаниеБезналичныхДС автоматично модифікуються інші документи (ЗаказПоставщику, Ведомості, ОказаниеУслуг)!

== ПоступлениеБезналичныхДенежныхСредств ==
- Якщо ХозОперация = ПоступлениеДенежныхСредствСДругогоСчета → створює парний документ СписаниеБезналичныхДС
- Викликає СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению

== РасходныйКассовыйОрдер ==
- Викликає СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению

== АвансовыйОтчет ==
- Викликає ОбновитьАвансовыйОтчетПослеОбмена() яка:
  1. Видаляє всі існуючі ПриобретениеТоваровУслуг пов'язані з цим АО
  2. Групує А_Товары по Контрагент + ДоговорКонтрагента
  3. Для кожної групи створює новий ПриобретениеТоваровУслуг з правильним заповненням:
     - Курс = 1, Кратность = 1
     - А_ВведенВЕРП = Истина (щоб обмінна процедура не затерла!)
     - ВалютаВзаиморасчетов = Валюта документа
     - СуммаВзаиморасчетов в рядках = СуммаСНДС
     - ХозяйственнаяОперация = ЗакупкаЧерезПодотчетноеЛицо

КРИТИЧНИЙ: Кожна запис АвансовыйОтчет АВТОМАТИЧНО перестворює всі пов'язані ПриобретениеТоваровУслуг!

== ПринятиеКУчетуОС ==
- Створює ВнутреннееПотреблениеТоваров по ПринятиеКУчетуОС

---

## Процедура СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению

Викликається з ПриЗаписи для: СписаниеБезналичныхДС, ПоступлениеБезналичныхДС, РасходныйКассовыйОрдер

Умова: Если Источник.Проведен И Источник.А_Распределение.Количество() > 0

Що робить:
1. Шукає існуючий А_ОказаниеУслугМеждуПодразделениями по ДенежныйДокумент
2. Якщо знайдено — оновлює (відміняє проведення, очищає А_Распределение)
3. Якщо не знайдено — створює новий
4. Заповнює дату, організацію, А_Распределение з грошового документа
5. Проводить документ

РИЗИК: Якщо грошовий документ має А_Распределение — автоматично створюється/оновлюється А_ОказаниеУслугМеждуПодразделениями.

---

## Перевірка А_ПроверкаНаРазрешенияПроведенияВУчете

Викликається на ПОЧАТКУ А_ДоработкаДокументыПередЗаписью для ВСІХ документів.
Перевіряє дозвіл на проведення в учете (деталі в модулі А_СобытияОбъектов).

---

## Стандартні "обмінні" процедури в ObjectModule документів

Крім кастомних підписок, стандартні модулі документів мають свої обмінні процедури:

== ПриходныйКассовыйОрдер / РасходныйКассовыйОрдер ==
В ПередЗаписью: ОбновитьПриходныйКассовыйОрдерПослеОбмена()
Умова: якщо А_ОбработанКазна = Ложь
Що робить:
- Очищає РасшифровкаПлатежа
- Перезаписує ХозяйственнаяОперация
ОБХІД: Встановити А_ОбработанКазна = Истина ПЕРЕД записом

== ПриобретениеТоваровУслуг ==
В ПередЗаписью: ОбновитьПоступлениеНаПослеОбмена()
Умова: якщо А_ВведенВЕРП = Ложь І А_Обработан = Ложь
Що робить:
- Очищає Товары, РасшифровкаПлатежа, ВидыЗапасов, ЭтапыГрафикаОплаты
- Перебудовує з документа-джерела
ОБХІД: Встановити А_ВведенВЕРП = Истина ПЕРЕД записом

## Підписки на події (довідники)

А_ДоработкаСправочникиПередЗаписью обробляє:
- ДоговорыКонтрагентов — складна логіка заповнення полів
- Номенклатура — кастомна логіка
- СтатьиДвиженияДенежныхСредств — кастомна логіка
- Сотрудники — кастомна логіка
- Склады — кастомна логіка
- Кассы — заповнення А_Организация
- БанковскиеСчетаОрганизаций — пуста процедура
- Партнеры — якщо заповнено А_Подразделение → Наименование = А_Подразделение; ЮрФизЛицо = Компания
- Контрагенты — ЮрФизЛицо = ЮрЛицо; ЮридическоеФизическоеЛицо = ЮридическоеЛицо
- СтатьиРасходов — заповнення А_СтатьяРасходовДляРасходовБудущегоПериода

А_ДоработкаСправочникиПриЗаписи обробляє:
- ФизическиеЛица
- Склады
- СтруктураПредприятия
- БанковскиеСчетаОрганизаций
- Кассы
- СтатьиРасходов

## Проблема ExternalConnection

Модуль А_СобытияОбъектов повинен мати ExternalConnection=true в XML:
<ExternalConnection>true</ExternalConnection>

Якщо false — при COM-підключенні (Python тести, зовнішні обробки через COM) буде помилка:
"Обработчик события не найден: А_ДоработкаДокументыПередЗаписью"

ОбменДанными.Загрузка = True НЕ допомагає — платформа перевіряє наявність модуля-обробника ДО виконання, незалежно від прапорця завантаження.

---

## Сесійні параметри при COM/HTTP

При роботі через COM-підключення або HTTP-сервіс (MCP) деякі сесійні параметри НЕ ініціалізуються:
- РаздельныйУчетПостатейныхПроизводственныхЗатратПоНалогообложениюНДС — через це ПриобретениеТоваровУслуг не проводиться через MCP
- Інші параметри НДС

Вирішення: використовувати тільки Записать() через COM/MCP, а Проведение робити через інтерфейс 1С або фоновим завданням.

## Чек-лист для безпечного програмного створення документа

1. Встановити А_ОбработанКазна = Истина (для ПКО/РКО)
2. Встановити А_ВведенВЕРП = Истина (для ПриобретениеТоваровУслуг)
3. Встановити Курс = 1, Кратность = 1
4. Заповнити СуммаВзаиморасчетов в шапці та рядках
5. Заповнити Подразделение (бо А_СобытияОбъектов може заповнити з Договора, але якщо Договор пустий — буде пустим)
6. Заповнити НаправлениеДеятельности
7. Заповнити ГруппаФинансовогоУчета
8. Врахувати що ПриЗаписи можуть автоматично створюватись ІНШІ документи (ОказаниеУслуг, парні банківські)
