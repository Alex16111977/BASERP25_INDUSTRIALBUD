# Кастомні об'єкти А_ — BAS ERP 2.5 INDUSTRIALBUD

Всі об'єкти з префіксом А_ — кастомні доробки конфігурації для ТОВ ІНДАСТРІАЛБУД.

---

== ПАТЕРН: СТВОРЕННЯ ПІДЛЕГЛИХ ДОКУМЕНТІВ (Delete-Then-Create) ==

В конфігурації ІНДАСТРІАЛБУД використовується єдиний патерн для створення підлеглих документів з батьківських. Цей патерн застосовується в: А_ОказаниеУслугМеждуПодразделениями, А_АрендаТехники, А_СобытияОбъектов (АвансовыйОтчет).

Послідовність дій (ОБОВ'ЯЗКОВА):

Фаза 1 — ПОМІТИТИ НА ВИДАЛЕННЯ ВСІ існуючі підлеглі (БЕЗ УМОВ, ЦИКЛОМ):
  Запит БЕЗ "ПЕРВЫЕ 1": знайти ВСІ підлеглі документи по реквізиту-зв'язку
  Цикл по ВСІХ знайдених (навіть якщо їх 2-3 через баг або дублі):
    - Якщо Проведен → Записать(ОтменаПроведения)
    - УстановитьПометкуУдаления(Истина)
  ВАЖЛИВО: Помічати БЕЗ УМОВ — не перевіряти "вже помічений чи ні", не пропускати жодного!
  Це захист від дублів — якщо через баг створилось 3 документи, всі 3 будуть помічені.

Фаза 2 — ПЕРЕВІРКА чи потрібно створювати:
  Якщо батьківський НЕ проведений → Возврат (всі підлеглі вже помічені на видалення)

Фаза 3 — ПОВТОРНИЙ ЗАПИТ → знайти помічений → переиспользовать або створити новий:
  Повторно виконати той самий запит (підлеглі вже помічені на видалення але ще існують)
  Якщо знайдений:
    - Зняти помітку видалення (УстановитьПометкуУдаления(Ложь))
    - Очистити табличні частини
    - Переиспользовать цей документ (НЕ створювати новий!)
  Якщо НЕ знайдений (перший раз):
    - СоздатьДокумент()

Фаза 4 — ЗАПОВНИТИ підлеглий:
  1. Заповнити шапку (Дата, Организация, зв'язок з батьківським)
  2. ОБОВ'ЯЗКОВО: А_Обработан = Истина, А_ВведенВЕРП = Истина
  3. Заповнити табличні частини з даних батьківського документа
  4. Записать(РежимЗаписиДокумента.Проведение)

РЕЗУЛЬТАТ: Навіть якщо було 3 дублі — всі 3 помічені на видалення, один переиспользований, два залишились з поміткою.

ТИПОВІ ПОМИЛКИ ЩО НЕ МОЖНА ДОПУСКАТИ:
  - НЕ використовувати "ПЕРВЫЕ 1" в запиті Фази 1 — пропустиш дублі!
  - НЕ створювати новий якщо є помічений на видалення — будуть дублі!
  - НЕ ставити А_Обработан = Ложь — обмінна процедура затре дані!
  - НЕ забувати А_ВведенВЕРП = Истина — обмінна процедура очистить ТЧ!

Виклик процедури — з ПриЗаписи батьківського документа (НЕ з ПередЗаписью!):
  Процедура ПриЗаписи(Отказ)
    Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;
    СоздатьПідлеглийДокумент();
  КонецПроцедуры

ЧОМУ Find-Or-Create а не завжди Create:
- Один батьківський = один підлеглий (без дублів!)
- Підлеглий документ ПЕРЕЗАПОВНЮЄТЬСЯ при кожному проведенні батьківського (очистка ТЧ + нове заповнення)
- Якщо батьківський розпроведений — підлеглий помічається на видалення
- Це гарантує консистентність: підлеглий завжди відповідає поточному стану батьківського
- ПОМИЛКА: створювати новий кожного разу → купа дублів документів!

ПРИКЛАДИ ВИКОРИСТАННЯ:
- А_АрендаТехники.ПриЗаписи → створює А_ОказаниеУслугМеждуПодразделениями (ТЧ Услуги)
- А_ОказаниеУслугМеждуПодразделениями.СоздатьРеализацииПоОказанииУслугНаСервере → створює РеализацияТоваровУслуг + ПриобретениеТоваровУслуг
- А_ОказаниеУслугМеждуПодразделениями.СоздатьДенежныеДокументы → створює СписаниеБезналичныхДС + ПоступлениеБезналичныхДС
- А_СобытияОбъектов.АвансовыйОтчет_ПриЗаписи → видаляє старі ПриобретениеТоваровУслуг і створює нові
- А_СобытияОбъектов.СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению → створює А_ОказаниеУслугМеждуПодразделениями з грошових документів

КРИТИЧНІ ПРАПОРЦІ при створенні підлеглого документа:
- А_Обработан = Истина — БЕЗ ЦЬОГО обмінна процедура затре дані при наступному записі!
- А_ВведенВЕРП = Истина — БЕЗ ЦЬОГО обмінна процедура очистить ТЧ Товары/РасшифровкаПлатежа!
- А_ОбработанКазна = Истина — для ПКО/РКО: БЕЗ ЦЬОГО очиститься РасшифровкаПлатежа!
- Курс = 1, Кратність = 1 — БЕЗ ЦЬОГО СуммаВзаиморасчетов = 0!

== КАСТОМНІ ДОКУМЕНТИ ==

Документ: А_ОказаниеУслугМеждуПодразделениями
Призначення: Внутрішні послуги між підрозділами (розподіл витрат)
Кількість в базі: 153
Особливості:
- Створюється АВТОМАТИЧНО при записі грошових документів (СписаниеБезналичныхДС, ПоступлениеБезналичныхДС, РКО) якщо є табличні частина А_Распределение
- Логіка створення в А_СобытияОбъектов.СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению()
- Шукає/створює договори покупця і постачальника за критеріями: Организация, Подразделение, А_ПодразделениеОказаниеУслугПодразделению
- Раніше також шукав по А_СтатьяДвиженияДенежныхСредствОказаниеУслугПодразделению (планується видалення цього критерію)
- Має процедуру СоздатьДоговорыЕРПНаСервере() — кнопка для ручного створення договорів

Документ: А_ОтражениеЗарплатыВУчете
Призначення: Відображення зарплати в фінансовому обліку (аналог стандартного ОтражениеЗарплатыВУчете)
Кількість в базі: 40
Особливості:
- Кастомний аналог стандартного документа
- В правилах обміну: ОтражениеЗарплатыВУчете (BuhBud) -> А_ОтражениеЗарплатыВУчете (ERP)
- Використовує регістр А_НачисленнаяЗарплатаИВзносыПоФизлицам
- Зв'язок з Сотрудники і ФизическиеЛица

Документ: А_РаспределениеЗаработнойПлаты
Призначення: Розподіл зарплати по підрозділах/проектах/напрямках діяльності
Кількість в базі: 26

Документ: А_ТабельУчетаРабочегоВремени
Призначення: Табель обліку робочого часу
Кількість в базі: 335

Документ: А_БюджетМесяц
Призначення: Місячний бюджет (план vs факт)
Кількість в базі: 255
Особливості:
- Рухає регістр А_БюджетыНаМесяц
- Використовується звітом А_БДДС для порівняння бюджет vs факт

Документ: А_ОтгрузкаПродукции
Призначення: Кастомний документ відвантаження продукції
Кількість в базі: 253

Документ: А_ПриходДенегОтФинАгента
Призначення: Прихід грошей від фінансового агента (казначейство)
Кількість в базі: 119
Особливості:
- Інтеграція з Казною
- Поле А_НаправлениеДеятельности (кастомне! з префіксом А_)
- НЕ має поля Валюта — береться з Касса.ВалютаДенежныхСредств

Документ: А_АрендаТехники
Призначення: Оренда техніки
Кількість в базі: 4

Документ: А_ПереносДвиженийИзКазны
Призначення: Перенесення «вільних» рухів регістру БДДС бази Казни (BuhKazn) у власний оборотний регістр ERP — для замикання прогалин звіту звірки `А_СравнитьОстаткиДенегЕРПсКазной`.
Особливості:
- Один документ = один місяць (реквізит шапки `Месяц`).
- Кнопка «Заповнити з Казни» — COM-зʼєднання до BuhKazn, запит до `РегистрНакопления.БДДС` (`НЕ ПланФакт`), маппінг довідників Казни → ERP.
- ОбробкаПроведення — інженерний пакетний паттерн `Запрос → Выгрузить() → Загрузить(ТЗ)` (одна операція замість тисяч `.Добавить()`).
- ТЧ названа `СтрокиДвижений`, а не `Движения` — імʼя `Движения` зарезервоване платформою.
- Реквізит шапки `Месяц`, а не `Период` — `Период` зарезервоване стандартним атрибутом `Date`.
- НЕ учасник обміну ERP↔Казна (не потребує `А_ОбработанКазна` / `А_ВведенВЕРП`).
- Детальний гайд: див. `perenos_dvizheniy_iz_kazny.md`.

== КАСТОМНІ ПОЛЯ В СТАНДАРТНИХ ДОКУМЕНТАХ ==

Поле: А_ОбработанКазна (Boolean)
Використовується в: ПриходныйКассовыйОрдер, РасходныйКассовыйОрдер
Призначення: Якщо Истина — обмінна процедура ОбновитьПКО/РКОПослеОбмена НЕ спрацьовує
Коли ставити: При програмному створенні ПКО/РКО щоб не затерлись РасшифровкаПлатежа і ХозяйственнаяОперация

Поле: А_ВведенВЕРП (Boolean)
Використовується в: ПриобретениеТоваровУслуг, ВзаимозачетЗадолженности
Призначення: Якщо Истина — обмінна процедура НЕ очищує Товары/РасшифровкаПлатежа
Коли ставити: При програмному створенні цих документів

Поле: А_Обработан (Boolean)
Використовується в: Практично ВСІ документи обміну
Призначення: Якщо Истина — обмінна процедура ОбновитьXXXПослеОбмена пропускається
Встановлюється автоматично: В кінці обмінної процедури

Поле: А_НаправлениеДеятельности
Використовується в: Документи (КАСТОМНИЙ реквізит з префіксом А_!)
УВАГА: Стандартне поле НаправлениеДеятельности теж існує. Кастомне поле А_НаправлениеДеятельности — інше!

Поле: А_ДоговорИзБанка
Використовується в: ЗаказКлиента, ЗаказПоставщику
Призначення: Договір отриманий з банківської виписки. В А_СобытияОбъектов копіюється в стандартне поле Договор.

Поле: А_СтатьяДвиженияДенежныхСредств
Використовується в: ЗаказПоставщику
Призначення: Стаття ДДС з банківської виписки. Заповнюється з СписаниеБезналичныхДС при ОплатаПоставщику.

Поле: А_НеСовпадаетПодразделение / А_НеСовпадаетНаправление
Використовується в: ПКО, РКО, ПоступлениеБезнал, СписаниеБезнал
Призначення: Прапорці що підрозділ/напрямок в РасшифровкаПлатежа не співпадає з шапкою. Заповнюється процедурою ПроверкаПодразделенияВДокументеНаСовпадение() в А_СобытияОбъектов.
