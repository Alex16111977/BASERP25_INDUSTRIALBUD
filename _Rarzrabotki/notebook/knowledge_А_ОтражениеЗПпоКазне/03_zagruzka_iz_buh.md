# 03. Блок 2 — Загрузка налогов и удержаний из zup_1

> Главная процедура: `ЗагрузитьНалогиИУдержанияИзЗарплатыБух()` (BSL 392-572)
> Запись в ТЧ: `ЗаписатьНалогиВТЧ_Бух` (BSL 576-651) + `ЗаписатьУдержанияВТЧ_Бух` (BSL 654-717)
> Поиск контрагента-получателя: `НайтиКонтрагентаПоУд_Бух` (BSL 725-753)

⚠️ **Важная поправка к PROMPT.md:** реальный источник — **`zup_1`** (BAS ЗУП регламент), а НЕ BuhBud (BAS Бухгалтерія). Connection string: `Srvr="SQLSERVER";Ref="zup_1";Usr="cfo";Pwd="2442"`.

---

## 1. Назначение

Заполнить 2 ТЧ из базы регламентированного учёта ЗУП:
- **`НалогиБухгалтерия`** ← НДФЛ + ВС (`РегНакопл.ВзаиморасчетыПоНДФЛ`) + ЕСВ (`РегРасчет.ВзносыВФонды`)
- **`УдержанияБухгалтерия`** ← алименты / исп.листы (`РегРасчет.УдержанияРаботниковОрганизаций` + `Документ.ИсполнительныйЛист`)

Период — месяц текущей Даты документа.

## 2. Структура zup_1 (discovery 2026-05-26)

## 4. Передача массива ЕДРПОУ как параметр в COM-запрос

В отличие от Блока 1 (где Кстамена.БДДС фильтровался по флагу организации), в zup_1 нет аналогичного флага — приходится передавать список ЕДРПОУ организаций ERP, у которых стоит `А_ВБалансе = Истина`.

⚠️ **Особенность COM-параметра типа «Массив»:** массив создаётся **в контексте V83**, а не ERP:

```bsl
// Получили массив в ERP
ЗапросОрганизаций = Новый Запрос;
ЗапросОрганизаций.Текст =
"ВЫБРАТЬ Организации.КодПоЕДРПОУ КАК КодПоЕДРПОУ
|ИЗ Справочник.Организации КАК Организации
|ГДЕ Организации.А_ВБалансе = ИСТИНА И Организации.КодПоЕДРПОУ <> """"";
масКодПоЕДРПОУ = Новый Массив;
ВыборкаОрг = ЗапросОрганизаций.Выполнить().Выбрать();
Пока ВыборкаОрг.Следующий() Цикл
    масКодПоЕДРПОУ.Добавить(ВыборкаОрг.КодПоЕДРПОУ);
КонецЦикла;

// Переносим в контекст V83
масКодПоЕДРПОУ_V83 = V83.NewObject("Массив");
Для Каждого КодЕДРПОУ Из масКодПоЕДРПОУ Цикл
    масКодПоЕДРПОУ_V83.Добавить(КодЕДРПОУ);
КонецЦикла;

// Передаём v83-массив в zup_1-запрос
ЗапросНал.УстановитьПараметр("масКодПоЕДРПОУ", масКодПоЕДРПОУ_V83);
```

Без этой конвертации параметр «массив» через COM не работает.

```sql
        ИЛИ У.ВидРасчета.Код = "00009")                                            -- подотчётные «Утримання підзвітних ГК»
    И КодыОрг.КодПоЕДРПОУ В (&масКодПоЕДРПОУ)
СГРУППИРОВАТЬ ПО ... У.ВидРасчета.Код ...
```

⚠️ **2026-06-04 — фильтр расширен.** Раньше брались ТОЛЬКО удержания с `ДокументОснование = ИсполнительныйЛист`
(алименты). Удержание с пустым основанием (напр. **«Утримання підзвітних ГК», Код 00009** — возврат подотчётных
при увольнении) **отсекалось** → не попадало в `УдержанияБухгалтерия` → не вычиталось в А_ВзСС → «зависало»
в отчёте сверки (Гуняга +400). Теперь whitelist по `ВидРасчета.Код` («00009») добавляет такие удержания.
- Алименты (ИЛ): Получатель (`ДокументОснование.Получатель`) — `Контрагент` (взыскатель: ВДВС, банк, ФОП).
- Подотчётные (00009): `ДокументОснование` пуст, получателя нет.

## 7. Сериализация результатов через `ЗначениеВСтрокуВнутр`

Когда оба COM-запроса выполнены и **в ТЗ только примитивные поля** (строки, числа, без COM-references на справочники Казны/Буха), можно безопасно использовать `ЗначениеВСтрокуВнутр` в Казне → `ЗначениеИзСтрокиВнутр` в ERP:

```bsl
ТЗНалогов = ЗапросНал.Выполнить().Выгрузить();
стр_ТЗНал = V83.ЗначениеВСтрокуВнутр(ТЗНалогов);

ТЗУдержаний = ЗапросУд.Выполнить().Выгрузить();
стр_ТЗУд = V83.ЗначениеВСтрокуВнутр(ТЗУдержаний);

V83 = Неопределено;
V8 = Неопределено;

ТаблицаНалогов   = ЗначениеИзСтрокиВнутр(стр_ТЗНал);
ТаблицаУдержаний = ЗначениеИзСтрокиВнутр(стр_ТЗУд);
```

⚠️ **Этот паттерн работает ТОЛЬКО потому, что:**
- В ТЗ нет ссылок на справочники Казны/Буха (типа `Сотрудник` или `Организация` как Reference)
- Все нужные поля — `СотрудникИНН`, `СотрудникНаименование`, `КодДохода` — **строки** (примитивы)
- Результат — `ВзаиморасчетыПоНДФЛ.Сотрудник.Физлицо.КодПоДРФО`, а не сам `.Сотрудник`

**Если в выборку добавить, например, `У.Сотрудник КАК Сотрудник`** — после десериализации в ERP это будет невалидный reference типа `СправочникСсылка.Сотрудники` (из контекста ЗУП, не ERP). См. CLAUDE.md «BuhBud — ЗначениеВСтрокуВнутр across different databases».

## 8. Заполнение ТЧ `НалогиБухгалтерия` (BSL 576-651)

```bsl
Для Каждого СтрокаТЗ Из ТаблицаНалогов Цикл
    ИННСотрудника = СокрЛП("" + СтрокаТЗ.СотрудникИНН);

    // Матчинг сотрудника по ИНН через Справочник.Сотрудники.А_КодПоДРФО
    СотрудникERP = Справочники.Сотрудники.НайтиПоРеквизиту("А_КодПоДРФО", ИННСотрудника);

    // Матчинг организации по ЕДРПОУ
    ОрганизацияERP = Справочники.Организации.НайтиПоРеквизиту("КодПоЕДРПОУ", СокрЛП("" + СтрокаТЗ.КодПоЕДРПОУ));

    // КодДохода → Справочник.ВидыДоходовНДФЛ
    КодДоходаЗУП = СокрЛП("" + СтрокаТЗ.КодДохода);
    ВидДоходаНДФЛERP = Справочники.ВидыДоходовНДФЛ.НайтиПоКоду(КодДоходаЗУП);

    НоваяСтрока = НалогиБухгалтерия.Добавить();
    // ... заполнение полей

    // ТипНалога — парсинг кода дохода:
    //   "101", "ВЗ" — нет, но "101" — все цифры → НДФЛ
    //   "ВЗ" — есть буквы → ВоенныйСбор
    Если СтрДлина(КодДоходаЗУП) > 0 Тогда
        КодЦифровий = Истина;
        Для Счет = 1 По СтрДлина(КодДоходаЗУП) Цикл
            Симв = Сред(КодДоходаЗУП, Счет, 1);
            Если НЕ (Симв >= "0" И Симв <= "9") Тогда
                КодЦифровий = Ложь;
                Прервать;
            КонецЕсли;
        КонецЦикла;
        Если КодЦифровий Тогда
            НоваяСтрока.ТипНалога = Перечисления.ТипыНалогов.НДФЛ;
        Иначе
            НоваяСтрока.ТипНалога = Перечисления.ТипыНалогов.ВоенныйСбор;
        КонецЕсли;
    КонецЕсли;
КонецЦикла;
```

**Правило `Сумма`:**
- `Сумма = СуммаНалога` (когда НалогПриход ≠ 0, т.е. НДФЛ/ВС)
- `Сумма = СуммаФОТ` (когда ВзносыВФонды.Результат ≠ 0, т.е. ЕСВ)

## 9. Заполнение ТЧ `УдержанияБухгалтерия` (BSL ~708) — ветвление по типу удержания

Кешируются константные ссылки **вне цикла** (и алиментные, и подотчётные):
```bsl
ПрочиеПассивы     = ПланыВидовХарактеристик.СтатьиАктивовПассивов.НайтиПоНаименованию("Прочие пассивы");
СчетУчета6853     = ПланыСчетов.Хозрасчетный.НайтиПоКоду("6853");
СчетУчета3721     = ПланыСчетов.Хозрасчетный.НайтиПоКоду("3721");
ГруппаУчетаЗарплата = Справочники.ГруппыУчетаНачисленийИУдержаний.Зарплата;
ВидОперацииАлименты = Перечисления.ВидыОперацийПоЗарплате.АлиментыПрочиеИсполнительныеЛисты;
```

Для каждой строки матчинг сотрудника по ИНН (`А_КодПоДРФО`), затем **ветвление** `ЭтоПодотчетне = (Ряд.КодВида = "00009")`:

| Поле | Алименты (ИЛ) | Подотчётне (Код 00009) |
|---|---|---|
| **`ВидОперации`** | АлиментыПрочиеИсполнительныеЛисты | **УдержаниеНеизрасходованныхПодотчетныхСумм** — триггер типового проведения в РН.ДенежныеСредстваУПодотчетныхЛиц |
| `СчетУчета` | 6853 | **3721** «Расчеты с подотчетными лицами» |
| `Субконто1` | Контрагент-Получатель (`НайтиКонтрагентаПоУд_Бух`, §10) | **ФизическоеЛицо** (regl-субконто 3721) |
| `СтатьяАктивовПассивов` | «Прочие пассивы» | **НЕ ставить** — ПАП «Денежные средства (у подотчетных лиц)» идёт через «Движения баланса» от регистра (поставить статью = задвоить ПАП) |
| `ГруппаУчетаНачислений` | Зарплата | Зарплата |

Для подотчётного `НайтиКонтрагентаПоУд_Бух` **пропускается** (получателя нет). ⚠️ С `ВидОперации=УдержаниеНеизрасходованныхПодотчетныхСумм`
типовой ОЗФУ САМ пишет регистр `ДенежныеСредстваУПодотчетныхЛиц` (Расход) + регл-счёт 3721 + ПАП через «Движения баланса».
Подотчётне **НЕ переносится** в ПередачаНач (`_ПНМП_ЗаполнитьУдержания` пропускает). См. LESSONS §24.

⚠️ Поле `Контрагент` в ТЧ НЕ заполняется — Получатель идёт в `Субконто1` (стандарт `000Ц-000002`).
⚠️ Типовое проведение ОЗФУ читает `Удержания.СтатьяАктивовПассивов` + `АналитикаАктивовПассивов` + `Субконто1`
из строки `УдержаннаяЗарплата` (ОЗФУ.ManagerModule ~596-597) → ПАП-движение и regl-проводка. Поэтому достаточно
выставить поля на строке ОЗП — они дотекают в ОЗФУ через `ЗаполнитьЗначенияСвойств`.

## 10. Функция `НайтиКонтрагентаПоУд_Бух` (BSL 725-753) — 3-уровневый fallback

```bsl
Функция НайтиКонтрагентаПоУд_Бух(ЄДРПОУ, ІНН, Ім_я)
    // 1. По КодПоЕДРПОУ (основной для юридических лиц: ВДВС и т.д.)
    Если НЕ ПустаяСтрока(ЄДРПОУ) Тогда
        К = Справочники.Контрагенты.НайтиПоРеквизиту("КодПоЕДРПОУ", ЄДРПОУ);
        Если ЗначениеЗаполнено(К) Тогда Возврат К; КонецЕсли;
    КонецЕсли;
    // 2. По КодПоЕДРПОУ с ИНН (для ФОП — ИНН часто записывают в КодПоЕДРПОУ)
    Если НЕ ПустаяСтрока(ІНН) Тогда
        К = Справочники.Контрагенты.НайтиПоРеквизиту("КодПоЕДРПОУ", ІНН);
        Если ЗначениеЗаполнено(К) Тогда Возврат К; КонецЕсли;
    КонецЕсли;
    // 3. Fallback — точное совпадение по Наименованию
    Если НЕ ПустаяСтрока(Ім_я) Тогда
        К = Справочники.Контрагенты.НайтиПоНаименованию(Ім_я, Истина);  // ТочноеСоответствие=Истина
        Если ЗначениеЗаполнено(К) Тогда Возврат К; КонецЕсли;
    КонецЕсли;
    Возврат Справочники.Контрагенты.ПустаяСсылка();
КонецФункции
```
