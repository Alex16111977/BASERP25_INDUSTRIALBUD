# 09. Документ `ВедомостьНаВыплатуЗарплатыВКассу` — структура и заполнение

> Целевой документ для задачи «выплата ЗП по подразделениям из Казны».
> Структура изучена через MCP 1С (`mcp__1c-workerp__get_metadata_structure`) — 2026-05-26.

---

## 1. Назначение

Типовой ERP-документ. Регистрирует **факт выплаты зарплаты через кассу** для одного подразделения за один период.

**Архитектурные ограничения:**
- В шапке **ОДНО `Подразделение`** (тип `Справочник.ПодразделенияОрганизаций`).
- Все строки ТЧ `Зарплата` относятся к этому подразделению.
- При проведении пишет в `РегистрНакопления.ЗарплатаКВыплате` с минусом по ключу (ФизЛицо × Подр × ДокументОснование).

**Следствие для задачи:** для каждого подразделения нужна **отдельная ведомость**. Если в `РаспределениеФ2` Казны 5 разных подразделений — получим 5 ведомостей.

## 3. Табличные части

### 3.1 ТЧ `Состав` — список физлиц

| Реквизит | Тип |
|---|---|
| `ИдентификаторСтроки` | УникальныйИдентификатор |
| `ФизическоеЛицо` | СправФизическиеЛица |

Уникальные ФЛ из ТЧ `Зарплата` (дубль для подписи ведомости).

### 3.2 ТЧ `Зарплата` — **главная** (детали выплаты)

| Реквизит | Тип | Назначение |
|---|---|---|
| `ИдентификаторСтроки` | УникальныйИдентификатор | Уник.ID строки |
| **`Сотрудник`** | СправСотрудники | Сотрудник |
| **`ФизическоеЛицо`** | СправФизическиеЛица | ФЛ |
| **`Подразделение`** | СправПодразделенияОрганизаций | Подразделение (равно шапке!) |
| `ПериодВзаиморасчетов` | Дата | Период взаиморасчетов |
| `СтатьяФинансирования` | СправСтатьиФинансированияЗарплата | |
| `СтатьяРасходов` | СправСтатьиРасходовЗарплата | |
| **`ДокументОснование`** | Composite ref (НачислениеЗарплаты, Премия, Отпуск, БольничныйЛист, ...) | Документ, который начислил эту сумму |
| **`КВыплате`** | Число | Сумма к выплате |
| `КомпенсацияЗаЗадержкуЗарплаты` | Число | |
| `ГруппаУчетаНачислений` | СправГруппыУчетаНачисленийИУдержаний | Обычно «Зарплата» |

⚠️ `ДокументОснование` — composite ref включает **`Документ.НачислениеЗарплаты`** (это документ, который мы создаём через `СоздатьДокументНачисления()` из родителя `А_ОтражениеЗПпоКазне`).

### 3.3 ТЧ `НДФЛ`, `ВзносыФОТ`, `Основания`, `ДополнительныеРеквизиты`

Заполняются если `ПорядокЗаполненияНалогов <> БезНалогов`. Для базовой задачи **не критичны** — можно начать без них.

## 4. Источник для заполнения

Типовой механизм ERP при кнопке «Заполнить»:

1. **Запрос к `РегистрНакопления.ЗарплатаКВыплате.Остатки`** на `ПериодРегистрации` с фильтром `Организация` + `Подразделение`.
2. Получает строки `(ФизЛицо × Сотрудник × Подразделение × ДокументОснование × СтатьяФинансирования × СтатьяРасходов × ГруппаУчетаНачислений × ПериодВзаиморасчетов) → СуммаКВыплате`.
3. Записывает каждую строку в ТЧ `Зарплата`.
4. Параллельно (если `ПорядокЗаполненияНалогов <> БезНалогов`) — запрос к регистрам `РасчетыНалогоплательщиковСБюджетомПоНДФЛ` + `ВзносыПоОрганизациям` для ТЧ НДФЛ и ВзносыФОТ.

⚠️ Для нашей задачи **источник остатков `ЗарплатаКВыплате` — это документ `НачислениеЗарплаты`** (создаётся через `СоздатьДокументНачисления` в родителе `А_ОтражениеЗПпоКазне`). Этот документ кладёт `+СуммаКВыплате` по подразделениям.

## 5. Связь со старшими документами

```
[ERP] Документ.НачислениеЗарплаты (создан из А_ОтражениеЗПпоКазне)
   │   ТЧ Начисления (Сотр × Подр × Результат)
   │   ТЧ Удержания
   │   ТЧ НДФЛ
   │   ТЧ ВзносыФОТ
   │
   │  ОбработкаПроведения → +ЗарплатаКВыплате (по Сотр × Подр × ФЛ)
   │
   ↓
[РегистрНакопления.ЗарплатаКВыплате] — остатки готовы к выплате
   │
   │  Фильтр: Организация + Подразделение + ПериодВзаиморасчетов
   │
   ↓
[ERP] Документ.ВедомостьНаВыплатуЗарплатыВКассу (создаётся N штук!)
       — одна на каждое уникальное Подразделение из остатков
       — ТЧ Зарплата = строки ЗарплатаКВыплате по этому Подр
       — Σ КВыплате = СуммаПоДокументу шапки
       — ДокументОснование строк = НачислениеЗарплаты
   │
   │  ОбработкаПроведения → −ЗарплатаКВыплате (та же ключевая комбинация)
   │
   ↓
[РегистрНакопления.ЗарплатаКВыплате] — остаток обнулён ⇒ зарплата выплачена
```

## 6. Возможные варианты СпособВыплаты в шапке

`Справочник.СпособыВыплатыЗарплаты` — перечень способов:
- «Через кассу» (наш случай — для ВедомостьВКассу)
- «На лицевые счета в банке» — для ВедомостьВБанк
- «Перечислением на счёт» — для ВедомостьПеречислением
- «Через раздатчика» — для ВедомостьРаздатчиком

**Уточнить при разработке:** какой конкретный элемент справочника использовать для наличной выплаты из Казны.

---

## 7. Подразделение в `ЗарплатаКВыплате` vs `СтруктураПредприятия`

⚠️ **Подразделение в ЗарплатаКВыплате — это `СправПодразделенияОрганизаций`** (НЕ `СтруктураПредприятия`!).

При проведении `НачислениеЗарплаты` подразделение записывается из ТЧ `Начисления.Подразделение` = `ПодразделенияОрганизаций`. В свою очередь, наш `СоздатьДокументНачисления` конвертирует `СтруктураПредприятия` (из РаспределениеКазна родителя) в `ПодразделенияОрганизаций` через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению(...)`.

**Это значит:** к моменту, когда мы будем строить ведомости, в `ЗарплатаКВыплате` уже лежат остатки по `ПодразделенияОрганизаций` — конвертация делать не нужно, просто GROUP BY.

## 8. Что нужно для задачи «Создать N ведомостей по подразделениям»

### Минимальный сценарий

1. **Найти все подразделения с ненулевым остатком** в `ЗарплатаКВыплате` за `Организация` + `ПериодРегистрации`:
   ```sql
   ВЫБРАТЬ РАЗЛИЧНЫЕ
       Остатки.Подразделение
   ИЗ
       РегистрНакопления.ЗарплатаКВыплате.Остатки(
           &КонецПериода,
           Организация = &Организация
       ) КАК Остатки
   ГДЕ Остатки.СуммаКВыплатеОстаток > 0
   ```

2. **Для каждого подразделения** — создать новую `ВедомостьНаВыплатуЗарплатыВКассу`:
   - Шапка: `Организация`, `Подразделение`, `ПериодРегистрации`, `Касса` (по умолчанию или из подразделения), `СпособВыплаты = "Через кассу"`, `ПорядокЗаполненияНалогов = "БезНалогов"` (или включить НДФЛ)
   - ТЧ `Зарплата` — заполнить запросом к остаткам с фильтром по этому подразделению
   - ТЧ `Состав` — уникальные ФЛ
   - `СуммаПоДокументу = Σ КВыплате`

3. **Записать с проведением** → `ЗарплатаКВыплате` обнулена по этому подразделению.

### Что брать из РаспределениеФ2/А_РаспределениеЗП в Казне

Если задача — «формировать ведомости **на основе** распределения из Казны»:

- Из `РаспределениеФ2` (ERP, найденного по UUID 1:1 из Казны) → берём ТЧ `Распределение` (Сотр × Подр × СуммаНачисления).
- Группируем по `Подразделение` → получаем список уникальных подразделений + Σ по каждому.
- Для каждого подразделения — создаём ведомость + наполняем ТЧ Зарплата из остатков `ЗарплатаКВыплате` (отфильтрованных по Сотр из ТЧ Распределение Ф2 + Подр).

### Альтернативный сценарий: ведомость = распределение

Можно вообще пропустить запрос к `ЗарплатаКВыплате` и наполнить ТЧ `Зарплата` ведомости **напрямую из ТЧ Распределение** Ф2 / А_РаспределениеЗП:

```bsl
Для Каждого СтрРаспред Из Документ.РаспределениеФ2.Распределение Цикл
    // Группируем по Подразделению (требует промежуточной ТЗ)
    ...
КонецЦикла;
```

Но в этом случае **ведомость не уменьшит регистр `ЗарплатаКВыплате`** правильно — нужно соблюдать ключи (`ДокументОснование`, `СтатьяФинансирования`, и т.д.) — иначе после проведения ведомости остаток не сойдётся.

**Рекомендация:** использовать остатки регистра как первичный источник, а ТЧ Распределение Ф2 — как **матчер** для фильтрации сотрудников/подразделений конкретной выплаты.

## 9. Антипаттерны / ловушки

| Антипаттерн | Почему |
|---|---|
| Одна ведомость на N подразделений | В шапке ОДНО Подразделение — типовая логика проведения упадёт |
| Подразделение из СтруктураПредприятия | В регистре `Подразделение` = `ПодразделенияОрганизаций` — конвертация обязательна |
| Пропустить ДокументОснование в ТЧ Зарплата | Без него `ЗарплатаКВыплате` не уменьшится — остатки «зависнут» |
| Создавать ведомость до проведения НачислениеЗарплаты | В регистре нет остатков → ведомость окажется пустой |
| `ПорядокЗаполненияНалогов = НДФЛИВзносы` без ТЧ НДФЛ/ВзносыФОТ | Проведение упадёт на проверке заполнения |
| Не заполнять ТЧ `Состав` | Печатные формы будут пустые (но проведение пройдёт) |
| `СтатьяФинансирования`/`СтатьяРасходов` в шапке не равны строкам ТЧ | Регистр запишет по строке — ведомость станет неконсистентна |
| `Сторно = Истина` в `ЗарплатаКВыплате` без чёткой причины | Это для перепроведения, не использовать просто так |
