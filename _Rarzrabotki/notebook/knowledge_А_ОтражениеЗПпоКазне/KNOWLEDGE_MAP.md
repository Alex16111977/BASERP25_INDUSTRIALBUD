> Документ-агрегатор: тянет данные ЗП из **3-х внешних баз** (BuhKazn + zup_1 + zup_2), наполняет 7 ТЧ и порождает 2 подчинённых документа (`НачислениеЗарплаты` + `ОтражениеЗарплатыВФинансовомУчете`).

## TL;DR за 60 секунд

Документ `А_ОтражениеЗПпоКазне` (синоним «Отражение зп по казне») — кастомный документ-агрегатор, который:

1. **Подключается к 3 внешним базам через `V83.COMConnector`:**
   - `BuhKazn` (Казна) — РегНакопл.БДДС + Документ.РаспределениеЗаработнойПлаты + Документ.РаспределениеФ2
   - `zup_1` (BAS ЗУП регламент) — РегНакопл.ВзаиморасчетыПоНДФЛ + РегРасчет.ВзносыВФонды + РегРасчет.УдержанияРаботниковОрганизаций
   - `zup_2` (BAS ЗУП управленческий) — Документ.НачислениеЗарплатыРаботникам.{Начисления,Удержания}

2. **Наполняет 7 табличных частей:** `РаспределениеКазна`, `НалогиБухгалтерия`, `УдержанияБухгалтерия`, `НачисленияУпр`, `УдержанияУпр`, `НачисленнаяЗарплатаИВзносыПоФизлицам`, `НачисленныйНДФЛ`.

3. **Использует cross-base UUID 1:1** (через правила обмена `_Rarzrabotki/ConvertERP/`) для поиска ERP-документа `А_РаспределениеЗаработнойПлаты` по UUID регистратора из Казны. Паттерн: `V83.string(...)` lowercase (CLAUDE.md §«Cross-base UUID lookup»).

4. **Создаёт 2 подчинённых документа:**
   - `Документ.НачислениеЗарплаты` (ЗУП-документ начисления — 4 ТЧ: Начисления, Удержания, НДФЛ, ВзносыФОТ)
   - `Документ.ОтражениеЗарплатыВФинансовомУчете` (типовой документ отражения — 5 ТЧ)

5. **Движения регистров (1 шт.):** `РегистрНакопления.А_ДенежныеСредстваФинАгенты`. Документ САМ движений почти не делает — это аггрегатор для последующих документов.

**Период документа = весь месяц** (`НачалоМесяца(Дата)..КонецМесяца(Дата)`). По дате документа определяется месяц, за который собирается ЗП из всех 3-х баз.
