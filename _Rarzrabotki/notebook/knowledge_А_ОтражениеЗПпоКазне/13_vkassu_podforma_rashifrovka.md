## 1. Зачем

Типовая `CommonForms.РедактированиеЗарплатыСтрокиВедомости` редактирует ТЧ `Зарплата` ВКассу, где **нет** реквизита `СтатьяДвиженияДенежныхСредств`. Наша СтатьяДДС живёт в кастомной ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам`. Пользователь должен видеть и редактировать её при двойном клике на сотруднике в ТЧ Состав или по кнопке «Изменить зарплату» — **только в форме документа ВКассу** (не в Перечислением/ВБанк/Раздатчиком).

## 4. Уроки

### Урок №1: подформа как `v8:ValueTable` с явными колонками

Атрибут формы — это **ТЗ с явно объявленными колонками**, а не `DocumentTabularSection`. Это даёт изоляцию: подформа работает с **копией** ТЧ, и редактирование не модифицирует документ напрямую — изменения возвращаются только через `ОписаниеОповещения` → серверная процедура → Удалить-Добавить.

### Урок №2: `/form-compile` + `/form-add` намного лучше ручного XML

`/form-compile` (cc-1c-skills) генерирует валидный Form.xml из JSON DSL за один шаг — 46 элементов + namespace + companion-элементы (ContextMenu, ExtendedTooltip, AutoCommandBar) автоматически. Только два предупреждения: версия 2.13 vs 2.17/2.20 (несущественно), тип `UUID` без префикса (поправил вручную на `v8:UUID`).

`/form-add` создаёт метаданное формы + регистрирует в составе документа (нам пришлось делать регистрацию вручную из-за блокировки файла во время первого вызова, но это разовая проблема).

### Урок №3: `ПолучитьФорму` недоступна через V83.COMConnector

Тест метаданных формы через `erp.ПолучитьФорму(...)` падает с `Connect.ПолучитьФорму`. Метаданные формы проверяются через `Метаданные.Документы.Найти` + `Формы.Получить` + `Реквизиты.Получить`. Получение реальной формы доступно только в управляемом клиенте 1С.

### Урок №4: возврат изменений ТОЛЬКО через временное хранилище

Если в подформе попытаться передать ТЗ напрямую через `Параметры` — клиентский код 1С не примет (только примитивы + ссылки + Структура + Массив). Поэтому правильный паттерн БСП: `ПоместитьВоВременноеХранилище(ТЗ, УникальныйИдентификатор)` → передать **строку** адреса в Параметры → `ПолучитьИзВременногоХранилища(адрес)` на принимающей стороне.

### Урок №5: pattern «удалить + добавить» вместо in-place update

Подформа возвращает **полную копию** строк выбранного ФЛ (могут быть добавлены или удалены строки). Самый чистый способ интеграции — удалить ВСЕ старые строки этого ФЛ из ТЧ документа + добавить ВСЕ строки из подформы. Сохраняет порядок, не теряет добавленные/удалённые.

### Урок №6: блокировка XML при form-add (повторный запуск нужен)

Первый запуск `/form-add` упал на регистрации в Documents/.xml с ошибкой "user-mapped section open". Файл был открыт чем-то параллельно (может быть IDE). Скрипт ОК создал метаданное+Form.xml+Module.bsl, но не зарегистрировал. Регистрация делается вручную через Edit (одна строка `<Form>А_ФормаСпискаРасшифровкиПоФЛ</Form>` после существующих).

### Урок №7: унификация структуры формы с ТЧ.Зарплата (2026-05-27 вечер)

Изначально подформа имела 7 редактируемых колонок (включая ОтработаноЧасов и Сумма). ## 5. Поведение

| Сценарий | Результат |
|---|---|
| Двойной клик на сотруднике в ТЧ Состав | Открывается **наша** А_ФормаСпискаРасшифровкиПоФЛ с фильтром по ФЛ, редактируемая |
| Кнопка «Изменить зарплату» (на выделенной строке) | Открывает **нашу** форму вместо типовой |
| Пользователь добавил/удалил/изменил строки и нажал ОК | Изменения попадают в ТЧ А_Расшифровка документа ВКассу. `Модифицированность=Истина` |
| Отмена | Изменения не сохраняются |
| Другие документы (ВКассу.Перечислением/ВБанк/Раздатчиком) | Не задеты — у них своя форма документа |
| Редактирование ТЧ Зарплата | Не через нашу форму. Если нужно — пользователь работает с TableBox Зарплата в основной форме |
