# 08. Документы РаспределениеЗП и РаспределениеФ2 — структура в Казне и в ERP

> Подготовка для задачи «Формировать Ведомости на выплату ЗП по подразделениям».
> Изучено: 2026-05-26 (исходники Казны: `_Rarzrabotki/Kazna/Documents/`, MCP ERP).

---

## 1. Назначение двух документов

| Документ | Где живёт | ВидОплаты | Назначение |
|---|---|---|---|
| `Документ.РаспределениеЗаработнойПлаты` | Казна (BuhKazn) + ERP (по UUID 1:1) | **Безналичные** | Распределение зарплаты по подразделениям для **безналичной** выплаты (на карту) → порождает `ПлатежноеПоручениеИсходящее` в Казне |
| `Документ.РаспределениеФ2` | Казна (BuhKazn) + ERP (по UUID 1:1) | **Наличные** | Распределение зарплаты по подразделениям для **наличной** выплаты (через кассу) → порождает `РасходныйКассовыйОрдер` в Казне |

В обоих случаях один сотрудник может работать в **нескольких подразделениях** — ТЧ `Распределение` содержит запись на каждую пару (Сотрудник × Подразделение).

---

## 2. Структура в Казне

### 2.1 `Документ.РаспределениеЗаработнойПлаты` (Казна)

**Реквизиты шапки:**
- `Организация`, `Комментарий`, `Ответственный`, `КассаДатаС`, `КассаДатаПо`, `Направление`, `ОтбиратьТабельПоОрганизации`, `ОпределятьНаправлениеПоТабелю`, `УчитыватьАванс`

**Табличные части:**

| ТЧ | Реквизиты |
|---|---|
| `Сотрудники` | `Сотрудник`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов` |
| `Распределение` | `Сотрудник`, **`Подразделение`**, `ОтработаноЧасов`, `СуммаЗатрат`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`, `Направление` |
| `СотрудникиИсключения` | `Сотрудник`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`, **`СуммаВыплаты`** |

**Размер реального документа `№000000302` (15.05.2026):**
- Сотрудники — 126 строк
- Распределение — **143 строки** (т.е. 17 сотрудников работают в нескольких подразделениях)
- СотрудникиИсключения — 14 строк (сторно по уже выплаченным)

### 2.2 `Документ.РаспределениеФ2` (Казна)

Структура **аналогична** РаспределениеЗП, но без `СотрудникиИсключения` и без `СуммаФОТ`/`СуммаНалогов` в ТЧ Сотрудники:

| ТЧ | Реквизиты |
|---|---|
| `Сотрудники` | `Сотрудник`, `СуммаНачисления` (=Перечисления) |
| `Распределение` | `Сотрудник`, **`Подразделение`**, `ОтработаноЧасов`, `СуммаЗатрат`, `СуммаНачисления`, `Направление` |

Размер `№000000075` (20.05.2026): структура та же, но обычно меньше строк (наличная выплата — для кадрового резерва).

## 3. Структура в ERP (зеркало Казны через UUID 1:1)

ERP-документы имеют **те же** ТЧ, но добавлены поля для матчинга сотрудника:

### 3.1 `Документ.А_РаспределениеЗаработнойПлаты` (ERP)

| ТЧ | Реквизиты |
|---|---|
| `Сотрудники` | `Сотрудник`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`, **`ИНН`**, **`ФИО`**, **`КодСотрудникаКазна`** |
| `Распределение` | `Сотрудник`, **`Подразделение`** (СтруктураПредприятия), `ОтработаноЧасов`, `СуммаЗатрат`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`, `Направление` |
| `СотрудникиИсключения` | `Сотрудник`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`, `СуммаВыплаты` |

⚠️ `Подразделение` в ERP — **`СтруктураПредприятия`**, а не `ПодразделенияОрганизаций`. Для ведомости нужна конвертация через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению(СтруктураПредприятия)`.

### 3.2 `Документ.РаспределениеФ2` (ERP)

| ТЧ | Реквизиты |
|---|---|
| `Сотрудники` | `Сотрудник`, `СуммаНачисления` (=Перечисления), `ФИО`, `ИНН`, `КодСотрудникаКазна` |
| `Распределение` | `Сотрудник`, `Подразделение`, `ОтработаноЧасов`, `СуммаЗатрат`, `СуммаНачисления`, `Направление` |

## 4. Логика проведения в Казне → БДДС

### 4.1 РаспределениеЗП (Казна) — 3 движения на каждую строку Распределение

См. `_Rarzrabotki/Kazna/Documents/РаспределениеЗаработнойПлаты/Ext/ObjectModule.bsl` (строки 1-84).

Для **каждой** строки ТЧ Распределение пишутся **3 движения** в `РегистрНакопления.БДДС`:

| # | Движение | Сумма | СтатьяДДС | Подразделение | ВидОплаты |
|---|---|---|---|---|---|
| 1 | **Начислено (NET)** | `СуммаНачисления − СуммаНалогов` | `Сотрудник.СтатьяЗарплата` (fallback: `Сотрудник.Родитель.СтатьяЗарплата`) | Из ТЧ | **Безналичные** |
| 2 | **Удержано с сотрудника** | `СуммаНалогов` | `Сотрудник.СтатьяУдержанияСЗарплаты` | Из ТЧ | Безналичные |
| 3 | **ФОТ (ЕСВ)** | `СуммаФОТ` | `Сотрудник.СтатьяНачисленияНаЗарплату` | Из ТЧ | Безналичные |

Дополнительно: для строк `СотрудникиИсключения` пишутся **сторно-движения** с минусом — пропорциональное распределение `СуммаВыплаты` по подразделениям сотрудника.

### 4.2 РаспределениеФ2 (Казна) — 1 движение на строку Распределение

См. `_Rarzrabotki/Kazna/Documents/РаспределениеФ2/Ext/ObjectModule.bsl`.

Только **1 движение** в БДДС: «Начислено», `ВидОплаты = Наличные`, статья = `Сотрудник.СтатьяЗарплата`.

Все НДФЛ/ВС/ЕСВ движения у Ф2 **закомментированы** — потому что Ф2 — это форма для **наличного аванса** или досрочной выплаты, без отделения налогов.

## 5. Логика РКО Казны на основании РаспределениеФ2 (ключевое!)

См. `_Rarzrabotki/Kazna/Documents/РасходныйКассовыйОрдер/Ext/ObjectModule.bsl` строки 45-79.

`ОбработкаЗаполнения` при `ТипЗнч(ДанныеЗаполнения) = Тип("ДокументСсылка.РаспределениеФ2")`:

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|   Распределение.Подразделение,
|   СУММА(Распределение.СуммаНачисления) КАК Сумма,
|   Распределение.Направление,
|   Распределение.Сотрудник.СтатьяЗарплата КАК СтатьяДвиженияДенежныхСредств
|ИЗ
|   Документ.РаспределениеФ2.Распределение КАК Распределение
|ГДЕ
|   Распределение.Ссылка = &Основание
|СГРУППИРОВАТЬ ПО
|   Распределение.Направление,
|   Распределение.Подразделение,
|   Распределение.Сотрудник.СтатьяЗарплата";
Запрос.УстановитьПараметр("Основание", ДанныеЗаполнения.Ссылка);

Пока Выборка.Следующий() Цикл
    Нстрока = Расшифровка.Добавить();
    ЗаполнитьЗначенияСвойств(Нстрока, Выборка);
КонецЦикла;
ДокументОснование = ДанныеЗаполнения;
СуммаДокумента = Расшифровка.Итог("Сумма");
```

**Что происходит:**
- ТЧ Распределение Ф2 (Сотрудник × Подразделение) **СВЁРТЫВАЕТСЯ** в ТЧ Расшифровка РКО **(Подразделение × Направление × СтатьяЗП)** через GROUP BY.
- В Расшифровке РКО **НЕТ сотрудника** — только агрегат по подразделению + статье ДДС + направлению.
- `ДокументОснование = РаспределениеФ2`.
- `СуммаДокумента = Σ(СуммаНачисления)` по всей ТЧ Распределение.

⚠️ **Это значит: 1 РаспределениеФ2 → 1 РКО Казны.** Не N РКО по подразделениям. Все суммы в одном РКО, но в ТЧ Расшифровка лежат данные по подразделениям.

### 5.1 Проведение РКО Казны (если есть Расшифровка)

См. строки 105-122 ObjectModule.bsl РКО:

```bsl
Если Расшифровка.Количество() > 0 Тогда
    Движения.БДДС.Очистить();
    Для каждого Стр Из Расшифровка Цикл
        Движение = Движения.БДДС.Добавить();
        Движение.Период = Дата;
        Движение.Активность = Истина;
        Движение.ВидОплаты = Перечисления.ВидыДенежныхСредств.Наличные;
        Движение.СтатьяДвиженияДенежныхСредств = Стр.СтатьяДвиженияДенежныхСредств;
        Движение.Подразделение = Стр.Подразделение;
        Движение.НаправлениеДДС = Перечисления.НаправленияДвиженийДенежныхСредств.Расход;
        Движение.СуммаРасход = Стр.Сумма;
        Движение.Сумма = Стр.Сумма;
        Движение.ДокументОснование = ДокументОснование;
        Движение.Направление = Стр.Направление;
    КонецЦикла;
КонецЕсли;
```

Из БДДС записи РКО — Регистратор=РКО, **Сотрудник пустой!** (потому что в Расшифровке сотрудника нет). Это отличие от движений РаспределениеФ2, где Сотрудник заполнен.

## 6. Цепочка документов выплаты — Казна → ERP

### 6.1 Наличная выплата (Форма #2)

```
[Казна] Документ.РаспределениеФ2 (ТЧ Распределение: Сотр × Подр × Сумма)
   │
   │  ОбработкаПроведения → БДДС (ВидОплаты=Наличные, Сотрудник заполнен)
   │
   ↓
[Казна] Документ.РасходныйКассовыйОрдер (ввод на основании Ф2)
   │   ДокументОснование = РаспределениеФ2
   │   Расшифровка = ТЧ Распределение Ф2 свёрнута по (Подр × Направление × СтатьяЗП)
   │   СуммаДокумента = Σ(СуммаНачисления)
   │
   │  ОбработкаПроведения РКО → БДДС (Регистратор=РКО, Сотрудник=ПУСТО, по Подр)
   │
   ↓
[ERP] Документ.РаспределениеФ2 (UUID 1:1 — через ConvertERP)
   │   Используется в А_ОтражениеЗПпоКазне.РаспределениеКазна — статьи для НДФЛ/ЕСВ
   │
   ↓
[ERP] Документ.ВедомостьНаВыплатуЗарплатыВКассу (нужно создать!)
       — одна ведомость на одно ПОДРАЗДЕЛЕНИЕ
       — N ведомостей если в РаспределениеФ2 N подразделений
```

### 6.2 Безналичная выплата (через карты)

```
[Казна] Документ.РаспределениеЗаработнойПлаты (ТЧ Распределение: Сотр × Подр × {СуммаНач, СуммаФОТ, СуммаНалогов})
   │
   │  ОбработкаПроведения → БДДС × 3 (Начислено NET + Удержано + ФОТ, ВидОплаты=Безналичные)
   │
   ↓
[Казна] Документ.ПлатежноеПоручениеИсходящее (банк-перечисление)
       (либо одно общее, либо несколько по подразделениям)
   │
   ↓
[ERP] Документ.А_РаспределениеЗаработнойПлаты (UUID 1:1)
   │
   ↓
[ERP] Документ.ВедомостьНаВыплатуЗарплатыВБанк
       или Документ.ВедомостьНаВыплатуЗарплатыПеречислением
       — одна ведомость на одно подразделение
```

## 7. Регистр-ключ: `РегистрНакопления.ЗарплатаКВыплате` (ERP)

⚠️ **Это регистр, на остатках которого строятся ведомости.**

| Категория | Поля |
|---|---|
| **Измерения** | `Организация`, `ФизическоеЛицо`, `СтатьяФинансирования`, `СтатьяРасходов`, **`Сотрудник`**, **`Подразделение`** (ПодразделенияОрганизаций!), `ПериодВзаиморасчетов`, `ДокументОснование`, `ГруппаУчетаНачислений` |
| **Ресурс** | `СуммаКВыплате` |
| **Регистраторы (+)** | `НачислениеЗарплаты`, `Премия`, `Отпуск`, `Командировка`, `Увольнение`, `БольничныйЛист`, `МатериальнаяПомощь`, ... |
| **Регистраторы (-)** | `ВедомостьНаВыплатуЗарплатыВКассу`, `ВедомостьНаВыплатуЗарплатыВБанк`, `ВедомостьНаВыплатуЗарплатыПеречислением`, `ВедомостьНаВыплатуЗарплатыРаздатчиком`, `ПодтверждениеЗачисленияЗарплаты`, `ДоходВНатуральнойФорме`, ... |

**Логика:**
- При проведении `НачислениеЗарплаты` (из `СоздатьДокументНачисления` нашего родителя) → `+СуммаКВыплате` по строкам (Сотр × Подр × ФизЛица × ...).
- Каждое ФизЛицо может иметь **несколько** записей по разным Подразделениям (т.к. сотрудник работает в нескольких).
- При проведении **`ВедомостьНаВыплатуЗарплатыВКассу`** → `−СуммаКВыплате` по строкам ТЧ Зарплата.
- **В шапке Ведомости — ОДНО `Подразделение` (ПодразделенияОрганизаций).** Это значит для каждого подразделения нужна отдельная ведомость.

### 7.1 Пример: один сотрудник, 2 подразделения

```
НачислениеЗарплаты проводится → ЗарплатаКВыплате:
  (Орг=ТОВ, ФЛ=Иванов, Сотр=Иванов, Подр="Цех 1", ПервичВзаиморасч=Дек.2025, СуммаКВыплате=12 000)
  (Орг=ТОВ, ФЛ=Иванов, Сотр=Иванов, Подр="ЦО",   ПервичВзаиморасч=Дек.2025, СуммаКВыплате= 8 000)

Чтобы выплатить через ВедомостьНаВыплатуЗарплатыВКассу:
  Ведомость №1 (Подразделение="Цех 1"): ТЧ Зарплата = [Иванов 12 000]
  Ведомость №2 (Подразделение="ЦО"):    ТЧ Зарплата = [Иванов  8 000]
```
