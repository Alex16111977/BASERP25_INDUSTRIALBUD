# 02. Блок 1 — Загрузка из Казны (BuhKazn)

> Главная процедура: `ЗагрузитьРаспределениеКазна_ОтражениеЗП()` (BSL строки 52-271)
> Cross-base UUID lookup: `А_НайтиДокументПоУИД_ОтражениеЗП` (BSL 277-304)
> Привязка сотрудников: `ПривязатьСотрудников_ОтражениеЗП` (BSL 314-366)

---

## 1. Назначение

Заполнить ТЧ `РаспределениеКазна` данными из базы Казна (`BuhKazn`):
- Источник — `РегистрНакопления.БДДС` Казны
- Фильтр регистраторов — `Документ.РаспределениеЗаработнойПлаты` + `Документ.РаспределениеФ2`
- Период — месяц текущей даты документа (`НачалоМесяца(Дата)..КонецМесяца(Дата)`)
- Дополнительный фильтр для РаспределениеЗП: `Регистратор.Организация.А_ПереносЕРП = Истина` (только организации, помеченные для переноса в ERP)

После загрузки сразу вызывается `ПривязатьСотрудников_ОтражениеЗП` — для строк, где не найден сотрудник по ИНН.

Entry point — экспортная процедура `ЗаполнитьОтражениеЗарплатыВФинансовомУчетеИзБазЗП()` (BSL 29-40), которая вызывает 2 шага.

## 2. COM-подключение к Казне

```bsl
СтрокаПодключения = "Srvr=""SQLSERVER"";Ref=""BuhKazn"";Usr=""cfo"";Pwd=""2442""";
Попытка
    V8 = Новый COMОбъект("V83.COMConnector");
    V83 = V8.Connect(СокрЛП(СтрокаПодключения));
Исключение
    Сообщить("ЗагрузитьРаспределениеКазна: Помилка підключення до Казни: " + ОписаниеОшибки());
    Возврат;
КонецПопытки;
```

После завершения — ОБЯЗАТЕЛЬНО:
```bsl
V83 = Неопределено;
V8 = Неопределено;
```

⚠️ COM-объект **в Казне** должен закрываться ДО использования его данных в ERP (иначе долго висит сессия 1С).

**Ключевые поля в БДДС Казны (discovery):**
- Измерения: `Подразделение`, `СтатьяДвиженияДенежныхСредств`, `ПланФакт`, `ВидОплаты`, `ДокументОснование`, `Секция`, `Этаж`, `НаправлениеДДС`, `Направление`
- Ресурсы: `Сумма`, `СуммаПриход`, `СуммаРасход`, `СтараяСумма`
- Реквизиты: `Комментарий`, `Сотрудник`, `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов`

⚠️ В Казне `СуммаНачисления`, `СуммаФОТ`, `СуммаНалогов` — это **реквизиты** регистра (не ресурсы!). Документ `Документ.РаспределениеЗаработнойПлаты` при проведении пишет их в БДДС вместе с движениями. Источник истины — `_Rarzrabotki/Kazna/Documents/РаспределениеЗаработнойПлаты/Ext/ObjectModule.bsl`.

## 4. Cross-base UUID lookup (КРИТИЧЕСКИ ВАЖНО)

Для каждой строки результата запроса извлекается UUID регистратора Казны:

```bsl
УИДСтр = V83.string(СтрТЗ.Регистратор.УникальныйИдентификатор());
```

⚠️ **Только `V83.string(...)` (английский lowercase) — все остальные варианты НЕ работают:**

| Что НЕ работает | Почему |
|---|---|
| `Строка(V83_UUID)` | Возвращает пустоту или `'None'` (`Строка()` в ERP не сериализует COM-объект из Казни) |
| `XMLСтрока(V83_UUID)` | Исключение «Ошибка преобразования данных XML» (ERP XML-сериализатор отбрасывает чужой COM-объект) |
| `V83.XMLСтрока(V83_UUID)` | Ненадёжно через COM dispatch (Cyrillic dispatch issues) |
| `V83.String(V83_UUID)` (capitalized) | Может работать в Python, но в BSL предпочтительно lowercase |

Подробнее — [LESSONS.md §1](LESSONS.md), CLAUDE.md «Cross-base UUID lookup».

### Функция А_НайтиДокументПоУИД_ОтражениеЗП (BSL 277-304)

```bsl
Функция А_НайтиДокументПоУИД_ОтражениеЗП(УИДСтрока, ВидДокумента)
    Если ПустаяСтрока(УИДСтрока) Тогда
        Возврат Неопределено;
    КонецЕсли;
    Попытка
        УИД = Новый УникальныйИдентификатор(УИДСтрока);
        Если ВидДокумента = "А_РаспределениеЗаработнойПлаты" Тогда
            ДокСсылка = Документы.А_РаспределениеЗаработнойПлаты.ПолучитьСсылку(УИД);
        ИначеЕсли ВидДокумента = "РаспределениеФ2" Тогда
            ДокСсылка = Документы.РаспределениеФ2.ПолучитьСсылку(УИД);
        Иначе
            Возврат Неопределено;
        КонецЕсли;
        // КРИТИЧНО: проверка реального существования (не bitten ref)
        Если ДокСсылка.ПолучитьОбъект() <> Неопределено Тогда
            Возврат ДокСсылка;
        КонецЕсли;
    Исключение
    КонецПопытки;
    Возврат Неопределено;
КонецФункции
```

⚠️ Имя локальной переменной `ДокСсылка` (НЕ `Ссылка`!) — `Ссылка` зарезервировано системой для свойства документа. См. [LESSONS.md §2](LESSONS.md).

⚠️ `ДокСсылка.ПолучитьОбъект() <> Неопределено` — обязательная проверка. `ПолучитьСсылку(УИД)` всегда возвращает ссылку, даже если объекта не существует — только `ПолучитьОбъект()` дёргает реальную запись.

## 5. Архитектурное обоснование UUID 1:1

Правила обмена в `_Rarzrabotki/ConvertERP/` гарантируют:
- `РаспределениеЗаработнойПлаты` (Казна) → `А_РаспределениеЗаработнойПлаты` (ERP) — **тот же UUID**
- `РаспределениеФ2` (Казна) → `РаспределениеФ2` (ERP) — **тот же UUID**

Подтверждение в самой ERP — стандартный регистр `РегистрСведений.СоответствияОбъектовИнформационныхБаз` (БСП) хранит маппинг для узла `ПланОбмена.КазначействоBASERP`:
```
УникальныйИдентификаторПриемника (Строка) = UUID из BuhKazn
УникальныйИдентификаторИсточника (Composite Ref) = ERP-ссылка
```

**Но прямой UUID lookup быстрее и проще** — не требует JOIN с РегСведений + работает 1:1 (что соответствует контракту правил обмена).

## 6. Обход результата запроса (без сериализации)

Важно: `ЗначениеВСтрокуВнутр(ТЗ)` **НЕЛЬЗЯ** для результата COM-запроса к Казне, так как:
- ТЗ содержит **COM-references** (БДДС.Регистратор как ДокументСсылка.РаспределениеЗаработнойПлаты)
- В ERP такого типа не существует → десериализация делает refs невалидными → `XMLСтрока()` или `.УникальныйИдентификатор()` падают

**Правильный паттерн** — прямой обход COM-таблицы, пока соединение живо:

```bsl
ДанныеРядков = Новый Массив;  // массив структур ERP-side

Для і = 0 По ТЗ.Количество() - 1 Цикл
    СтрТЗ = ТЗ.Получить(і);

    // Извлекаем UUID СРАЗУ (COM ещё жив)
    УИДСтр = V83.string(СтрТЗ.Регистратор.УникальныйИдентификатор());

    // Сохраняем примитивы в ERP-структуру
    СтруктураРяда = Новый Структура;
    СтруктураРяда.Вставить("ПодразделениеКод",  СокрЛП("" + СтрТЗ.ПодразделениеКод));
    СтруктураРяда.Вставить("СтатьяКод",         СокрЛП("" + СтрТЗ.СтатьяКод));
    // ... остальные поля как примитивы
    СтруктураРяда.Вставить("УИДРегистратора",   УИДСтр);

    ДанныеРядков.Добавить(СтруктураРяда);
КонецЦикла;

// Теперь COM можно закрывать — все данные уже в ERP-side структурах
V83 = Неопределено;
V8 = Неопределено;
```

Только после этого начинается заполнение ТЧ `РаспределениеКазна`, используя ERP-side данные + `А_НайтиДокументПоУИД_ОтражениеЗП` для каждой строки.

## 7. Разрешение «заглушки» подразделения

После заполнения базовых полей строки делается дополнительный шаг:

```bsl
// ПодразделениеКазны = по коду из БДДС
ПодразделениеКазны = Справочники.СтруктураПредприятия.НайтиПоКоду(Ряд.ПодразделениеКод);

// КРИТИЧНО: подразделение "Главный офис" (00-000043) — это ЗАГЛУШКА в Казне.
// Реальное подразделение определяется через А_НаправлениеДеятельности.
Подразделение = ПодразделениеКазны;
Если ЗначениеЗаполнено(ПодразделениеКазны) Тогда
    Подразделение = А_Привилегированный.А_ПолучитьПодразделениеПоНаправлениюИПодразделениюКазны(
        НаправлениеДеятельности, ПодразделениеКазны);
    Если НЕ ЗначениеЗаполнено(Подразделение) Тогда
        Подразделение = ПодразделениеКазны;  // fallback
    КонецЕсли;
КонецЕсли;
```

Это делается **ОДИН РАЗ** при заполнении ТЧ — все последующие читатели (`Op 1`, `Op 2`, `Op 3`, `СоздатьДокументНачисления`) уже получают реальное подразделение.

## 8. Привязка сотрудников (3-уровневая)

Процедура `ПривязатьСотрудников_ОтражениеЗП` (BSL 314-366) запускается СРАЗУ после `ЗагрузитьРаспределениеКазна_ОтражениеЗП`. Алгоритм:

```
1. Построить кеш ФИО → Сотрудник из уже заполненных строк (где Сотрудник заполнен)
2. Для строк с пустым Сотрудник:
   2.1. Lookup в кеше по ФИО
   2.2. Если нет — поиск по ИНН через А_КодПоДРФО (мог появиться после обмена)
   2.3. Если нет — автосоздание через А_Привилегированный.СоздатьСотрудникаИзКазны(ФИО, ИНН, КодКазны)
3. После создания — запись в кеш для последующих строк той же ФИО
```

**ИНН в ERP:** реквизит `Справочник.Сотрудники.А_КодПоДРФО` (НЕ типовой `ИНН`!).

## 9. Результаты выполнения

Сообщения, которые видит пользователь:
- `"Завантажено з Казни: N рядків. UUID витягнуто: M, помилок: K"` (N = строк из БДДС, M = успешный UUID lookup, K = провалов)
- `"Перша помилка XMLСтрока: ..."` (если K > 0)
- `"Увага: N рядків без ДокРаспределениеЗП (документа в ERP не знайдено за UUID)"` (если есть пропуски в обмене)
- `"Привʼязка сотрудників: X з Y порожніх"` (после `ПривязатьСотрудников_ОтражениеЗП`)

Diagnostic-лог пишется в файл `_Rarzrabotki/Python/test/debug_a_otrazhenie.txt` — для Python-тестов, где `Сообщить` не перехватывается.
