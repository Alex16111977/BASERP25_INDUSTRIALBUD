# 10. Полный поток выплаты ЗП по подразделениям (Казна → ERP → Ведомости)

> Сборка из материалов файлов 02, 05, 06, 08, 09 + общей архитектуры из `_Rarzrabotki/notebook/knowledge/payroll_architecture.md`.
> Цель: подготовить разработку механизма **«Из РаспределениеФ2 / А_РаспределениеЗаработнойПлаты — создать N ведомостей на выплату ЗП по подразделениям»**.

---

## 1. Главная идея

Один сотрудник может работать **в нескольких подразделениях** одновременно. Поэтому:
- Начисления в `НачислениеЗарплаты` (ЗУП-документ) детализированы по `(Сотрудник × Подразделение)`.
- `РегистрНакопления.ЗарплатаКВыплате` содержит остатки по `(ФЛ × Сотр × Подр × ДокОснование × ...)`.
- Каждая **`ВедомостьНаВыплатуЗарплатыВКассу`** в шапке имеет **одно Подразделение** — значит, для каждого активного подразделения с остатком нужна **отдельная ведомость**.

Из Казны приходит «факт распределения» в виде:
- `РаспределениеФ2` (наличная выплата) — ТЧ Распределение `(Сотр × Подр × СуммаНачисления)`
- `А_РаспределениеЗаработнойПлаты` (безналичная) — ТЧ Распределение `(Сотр × Подр × СуммаНачисления + СуммаФОТ + СуммаНалогов)`

Эти документы — **источник истины** для какие именно сотрудники в каких подразделениях должны получить выплату по конкретному циклу.

## 4. Что нужно реализовать (наша задача)

### 4.1 Триггер

Скорее всего — **новая экспортная процедура** в `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`:
```bsl
Процедура СоздатьВедомостиНаВыплатуПоПодразделениям() Экспорт
    // 1. Guard: Проведен + НачислениеЗарплаты создано и проведено
    // 2. Найти все Подр × Сотр из РаспределениеКазна с заполненным ДокРаспределениеЗП
    // 3. Для каждого уникального Подр:
    //    a. Get-or-Create ВедомостьНаВыплатуЗарплатыВКассу (по А_ДокОтражениеЗПпоКазне + Подр)
    //    b. Запросить остатки ЗарплатаКВыплате(КонецПериода, Орг=..., Подр=...)
    //    c. Записать ТЧ Зарплата + Состав
    //    d. Заполнить шапку (Касса, СтатьяФинансирования, СтатьяРасходов, СпособВыплаты)
    //    e. Записать с проведением
    // 4. Сообщить количество созданных ведомостей + Σ КВыплате
КонецПроцедуры
```

Альтернатива — отдельная **обработка** (`_Rarzrabotki/Обработки/СоздатьВедомостиНаВыплатуЗПпоКазне.epf`) с формой выбора `А_ОтражениеЗПпоКазне` + Расход/наличные/безналичные.

### 4.2 Find-Or-Create (как в СоздатьДокументНачисления)

Связь дочка→родитель — через **новый реквизит** `Документ.ВедомостьНаВыплатуЗарплатыВКассу.А_ДокОтражениеЗПпоКазне` (или другое имя).

⚠️ **Тут есть проблема:** в типовом `ВедомостьНаВыплатуЗарплатыВКассу` такого реквизита нет. Нужно **добавить его через расширение** (CFE) — см. `_Rarzrabotki/notebook/knowledge/exchange_erp_kazna.md` и общую инфраструктуру.

Альтернатива — связь через **`Документ.ВедомостьНаВыплатуЗарплатыВКассу.КраткийСоставДокумента`** (Строка) — нестандартно, но не требует расширения. **Не рекомендую** — лучше CFE-реквизит.

### 4.3 Запрос к ЗарплатаКВыплате (для одного подразделения)

```sql
ВЫБРАТЬ
    Остатки.ФизическоеЛицо КАК ФизическоеЛицо,
    Остатки.Сотрудник КАК Сотрудник,
    Остатки.Подразделение КАК Подразделение,
    Остатки.ПериодВзаиморасчетов КАК ПериодВзаиморасчетов,
    Остатки.СтатьяФинансирования КАК СтатьяФинансирования,
    Остатки.СтатьяРасходов КАК СтатьяРасходов,
    Остатки.ДокументОснование КАК ДокументОснование,
    Остатки.ГруппаУчетаНачислений КАК ГруппаУчетаНачислений,
    Остатки.СуммаКВыплатеОстаток КАК КВыплате
ИЗ
    РегистрНакопления.ЗарплатаКВыплате.Остатки(
        &КонецПериода,
        Организация = &Организация
        И Подразделение = &Подразделение
        И ПериодВзаиморасчетов МЕЖДУ &НачПериода И &КонецПериода
    ) КАК Остатки
ГДЕ Остатки.СуммаКВыплатеОстаток > 0
```

Параметры:
- `&Организация` — из шапки родителя
- `&Подразделение` — текущее обрабатываемое
- `&НачПериода` / `&КонецПериода` — границы месяца Дата родителя

### 4.4 Получить список уникальных подразделений

Из ТЧ `РаспределениеКазна` родителя (где Сумма > 0):

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    Распределение.Подразделение КАК ПодразделениеСтруктуры
ИЗ Документ.А_ОтражениеЗПпоКазне.РаспределениеКазна КАК Распределение
ГДЕ Распределение.Ссылка = &Ссылка
    И Распределение.Сумма > 0
    И ЗначениеЗаполнено(Распределение.Подразделение)
```

⚠️ Это `СтруктураПредприятия`. Нужно конвертировать в `ПодразделенияОрганизаций` через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению(СтруктПодр)`.

Альтернатива — запросить **уникальные подразделения прямо из `ЗарплатаКВыплате`** (там уже `ПодразделенияОрганизаций`):

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    Остатки.Подразделение КАК Подразделение
ИЗ
    РегистрНакопления.ЗарплатаКВыплате.Остатки(
        &КонецПериода,
        Организация = &Организация
        И ПериодВзаиморасчетов МЕЖДУ &НачПериода И &КонецПериода
    ) КАК Остатки
ГДЕ Остатки.СуммаКВыплатеОстаток > 0
```

**Рекомендация:** использовать второй вариант — там уже типизация правильная + автоматически отсекаются ФЛ без остатков.

### 4.5 Распределение ОДНОГО сотрудника на N подразделений

Один сотрудник → N строк `ЗарплатаКВыплате` (по подразделениям) → N строк в N разных ведомостях.

**Пример (Иванов работает в "Цех 1" и "ЦО"):**

```
ЗарплатаКВыплате остатки за дек.2025:
  | ФЛ      | Сотр     | Подр    | ДокОснование    | СуммаКВыплате |
  | Иванов  | Иванов И | Цех 1   | НачисленияЗП    |  12 000       |
  | Иванов  | Иванов И | ЦО      | НачисленияЗП    |   8 000       |

Создаём:

Ведомость №1 (Подр = "Цех 1"):
  ТЧ Зарплата:
    | ФЛ      | Сотр     | Подр    | ДокОснование | КВыплате |
    | Иванов  | Иванов И | Цех 1   | НачисленияЗП | 12 000   |
  ТЧ Состав: [Иванов]
  СуммаПоДокументу = 12 000

Ведомость №2 (Подр = "ЦО"):
  ТЧ Зарплата:
    | ФЛ      | Сотр     | Подр    | ДокОснование | КВыплате |
    | Иванов  | Иванов И | ЦО      | НачисленияЗП |  8 000   |
  ТЧ Состав: [Иванов]
  СуммаПоДокументу = 8 000
```

## 5. Реквизиты шапки ведомости — откуда брать

| Реквизит ведомости | Откуда брать |
|---|---|
| `Организация` | Шапка родителя `А_ОтражениеЗПпоКазне.Организация` |
| `Подразделение` | Текущее уникальное Подр из остатков |
| `ПериодРегистрации` | `НачалоМесяца(А_ОтражениеЗПпоКазне.Дата)` |
| `Дата` | `А_ОтражениеЗПпоКазне.Дата` (или текущая, или конец месяца) |
| `Касса` | По умолчанию из `Подразделение.Касса` (если есть) или из `Организация.КассаОсновная` — **уточнить с пользователем** |
| `СпособВыплаты` | `Справочник.СпособыВыплатыЗарплаты.НайтиПоНаименованию("Через кассу")` — **уточнить** |
| `ПорядокЗаполненияНалогов` | `Перечисление.ПорядокЗаполненияНалогов.БезНалогов` (на старте), потом возможно добавим НДФЛ |
| `СтатьяФинансирования` | Берётся из строки ТЧ Зарплата (если все одинаковые) или из шапки родителя |
| `СтатьяРасходов` | Аналогично |
| Подписанты (Руководитель, Кассир и т.д.) | Из настроек организации/подразделения, либо оставить пустыми |
| `СуммаПоДокументу` | `Σ КВыплате` из ТЧ Зарплата |

## 6. Дополнительные вопросы (надо уточнить с пользователем перед разработкой)

| Вопрос | Варианты |
|---|---|
| 1. Использовать остатки `ЗарплатаКВыплате` или ТЧ Распределение Ф2 напрямую? | **(Рек.) Остатки**, ТЧ — как фильтр сотрудников. |
| 2. Один цикл ведомостей или 2 разных (наличная/безналичная)? | Скорее всего **только наличная** (ВедомостьВКассу) для Ф2; для безнал РаспределениеЗП — отдельный цикл с `ВедомостьВБанк`/`Перечислением` |
| 3. Связь дочка→родитель — CFE-реквизит или строковый комментарий? | **(Рек.) CFE-реквизит** `А_ДокОтражениеЗПпоКазне` |
| 4. `Касса` — одна для всех ведомостей или своя для каждого подразделения? | Уточнить — обычно одна общая, но могут быть филиальные кассы |
| 5. Что делать с `ПерерасчетЗарплаты` после ведомостей? | Аналогично НачислениеЗарплаты — очищать через утиль `_НЗ_ОчиститиПерерасчетЗарплаты`? |
| 6. Заполнять ли НДФЛ/Взносы в ведомости? | Зависит от учётной политики — уточнить |
| 7. Что делать если в Казне РКО уже проведён, но в ERP ведомость ещё не создана? | Find-Or-Create + при перепроведении — отмена + перезапись (как в НачислениеЗарплаты) |

## 8. Critical rules / антипаттерны

| Правило | Источник |
|---|---|
| Перед написанием BSL-запроса — **Python COM тест** | CLAUDE.md Rule #-1 |
| **`Подразделение`** в `ЗарплатаКВыплате` = `ПодразделенияОрганизаций` (НЕ `СтруктураПредприятия`) | MCP `get_metadata_structure` |
| Find-Or-Create связь — через CFE-реквизит, не через `Комментарий` | knowledge/custom_objects_guide.md |
| `НачислениеЗарплаты` должен быть **проведён** перед созданием ведомостей | Иначе остатки `ЗарплатаКВыплате` пустые |
| `СтатьяФинансирования`/`СтатьяРасходов` в шапке = в ТЧ (или вообще не заполнять в шапке) | Иначе неконсистентность в регистре |
| `ДокументОснование` строки = `НачислениеЗарплаты` (не `А_ОтражениеЗПпоКазне`!) | Связь к регистру `ЗарплатаКВыплате` |
| `ПорядокЗаполненияНалогов = БезНалогов` на старте | Чтобы не падать на проверке ТЧ НДФЛ/ВзносыФОТ |
| Подразделение «Главный офис» (00-000043) — **заглушка** в Казне → резолв через `А_Привилегированный` уже сделан в РаспределениеКазна | См. [02_zagruzka_iz_kazni.md](02_zagruzka_iz_kazni.md) §7 |
