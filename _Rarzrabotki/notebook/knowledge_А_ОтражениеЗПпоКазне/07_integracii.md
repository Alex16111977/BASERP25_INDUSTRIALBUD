## 4. Cross-base UUID lookup (Казна↔ERP)

### Архитектурное обоснование

Правила обмена в `_Rarzrabotki/ConvertERP/` гарантируют **UUID 1:1** для следующих пар:

| Тип в Казне | Тип в ERP | UUID совпадает |
|---|---|---|
| `Документ.РаспределениеЗаработнойПлаты` | `Документ.А_РаспределениеЗаработнойПлаты` | ✓ |
| `Документ.РаспределениеФ2` | `Документ.РаспределениеФ2` | ✓ |
| `Документ.ПриходныйКассовыйОрдер` | `Документ.ПриходныйКассовыйОрдер` (или `А_ПриходДенегОтФинАгента` если `_ФинАгент` заполнен) | ✓ |
| `Документ.ПлатежноеПоручениеВходящее` | `Документ.ПоступлениеБезналичныхДенежныхСредств` | ✓ |
| `Документ.РасходныйКассовыйОрдер` | `Документ.РасходныйКассовыйОрдер` | ✓ |
| `Документ.ПлатежноеПоручение` | `Документ.СписаниеБезналичныхДенежныхСредств` | ✓ |

Подтверждение в самой ERP — стандартный регистр `РегистрСведений.СоответствияОбъектовИнформационныхБаз` (БСП).

### Канонический паттерн в BSL

```bsl
// STEP 1: Извлечь UUID как строку через УДАЛЁННЫЙ контекст V83
УИДСтр = V83.string(СтрТЗ.Регистратор.УникальныйИдентификатор());

// STEP 2: Создать ЛОКАЛЬНЫЙ UUID-объект и lookup по типу
УИД = Новый УникальныйИдентификатор(УИДСтр);
ДокСсылка = Документы.А_РаспределениеЗаработнойПлаты.ПолучитьСсылку(УИД);

// STEP 3: Проверить, что документ ФИЗИЧЕСКИ существует (не broken ref)
Если ДокСсылка.ПолучитьОбъект() <> Неопределено Тогда
    // Найден — использовать ДокСсылка
КонецЕсли;
```

⚠️ **Только `V83.string(...)` — английский lowercase.** Все альтернативы (`Строка()`, `XMLСтрока()`, `V83.XMLСтрока()`, `V83.String()` capitalized) либо не работают, либо ненадёжны через COM dispatch. Детали — в [LESSONS.md §1](LESSONS.md).

⚠️ **Никогда не объявляй локальную переменную `Ссылка`** — конфликтует со системным свойством объекта. Используй `ДокСсылка`, `РезСсылка`, `НайденнаяСсылка`. Детали — в [LESSONS.md §2](LESSONS.md).

## 5. Сериализация результатов COM-запроса

### Когда МОЖНО использовать `ЗначениеВСтрокуВнутр`/`ЗначениеИзСтрокиВнутр` (между разными базами)

Когда ТЗ содержит **только примитивы** (строки, числа, даты, булево) — нет ссылок на справочники чужой базы:

```bsl
// OK: все поля строки/числа
СУММА(У.Результат) КАК Сумма,
У.ДокументОснование.Номер КАК НомерИЛ,
У.ДокументОснование.Получатель.КодПоЕДРПОУ КАК ЕДРПОУПолучателя
```

Это используется в Блоке 2 для передачи результата запроса из zup_1 в ERP.

### Когда НЕЛЬЗЯ

Когда ТЗ содержит ссылки на справочники чужой базы (даже как `Поле КАК Имя`):

```bsl
// FAIL: У.Сотрудник — это СправочникСсылка.Сотрудники ИЗ ZUP_1, не из ERP!
У.Сотрудник КАК Сотрудник,
У.ВидРасчета КАК ВидРасчета  // FAIL: ПланВидовРасчета.* из ZUP_1
```

После десериализации в ERP — refs невалидные (типов из чужой базы здесь нет). `.УникальныйИдентификатор()` или `XMLСтрока()` падают.

**Правильно:** изымать ссылки через ".Поле" (КодПоДРФО, Наименование, КодПоЕДРПОУ):
```bsl
У.Сотрудник.Физлицо.КодПоДРФО КАК СотрудникИНН  // OK — строка
```

Подробнее — [LESSONS.md §3](LESSONS.md), CLAUDE.md «BuhBud — ЗначениеВСтрокуВнутр across different databases».

## 6. Закрытие COM-сессий

⚠️ **ОБЯЗАТЕЛЬНО** после COM:
```bsl
V83 = Неопределено;
V8 = Неопределено;
```

Без этого COM-сессия 1С (1cv8.exe) на сервере SQL висит несколько минут даже после завершения BSL — мешает другим процессам и блокирует пользователей.

Особенно критично, если процедура вызывается из формы документа — после нажатия кнопки пользователь ждёт.

## 7. Привилегированный режим

Документ объявлен с:
```xml
<PostInPrivilegedMode>true</PostInPrivilegedMode>
<UnpostInPrivilegedMode>true</UnpostInPrivilegedMode>
```

Это позволяет вызывать привилегированные процедуры из `А_Привилегированный`:
- `А_Привилегированный.А_ПолучитьПодразделениеПоНаправлениюИПодразделениюКазны(Направление, ПодразделениеКазны)` — разрешение заглушки «Главный офис»
- `А_Привилегированный.СоздатьСотрудникаИзКазны(ФИО, ИНН, КодКазны)` — автосоздание сотрудника
- `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению(СтруктураПредприятия)` — конвертация СтруктураПредприятия→ПодразделенияОрганизаций

## 8. Целевые регистры (после проведения дочек)

После создания `ОтражениеЗарплатыВФинансовомУчете` наполняются (типовая логика ERP):

| Регистр | Назначение |
|---|---|
| `РегистрНакопления.А_НачисленнаяЗарплатаИВзносыПоФизлицам` | Управ.учёт ЗП по физлицам |
| `РегистрНакопления.НачисленнаяЗарплатаИВзносы` | Свод для проводок |
| `РегистрНакопления.НачисленныйНДФЛ` | НДФЛ + ВС по физлицам |
| `РегистрНакопления.УдержаннаяЗарплата` | Удержания (исп.листы) |
| `РегистрБухгалтерии.Хозрасчетный` | Бух.проводки: Дт 23/91/92 — Кт 661 (начислено); Дт 661 — Кт 6411 (НДФЛ); Дт 661 — Кт 6853 (исп.листы); Дт 23/91/92 — Кт 651 (ЕСВ) |
| `РегистрНакопления.ВзаиморасчетыССотрудниками` | Расчёт с сотрудником (к выплате) |

После создания `НачислениеЗарплаты` (ЗУП-аналог):
| Регистр | Назначение |
|---|---|
| `РегистрРасчета.Начисления` | Начисления ЗУП |
| `РегистрРасчета.Удержания` | Удержания ЗУП |
| `РегистрНакопления.ВзаиморасчетыПоНДФЛ` | НДФЛ к расчёту с бюджетом |
| `РегистрНакопления.НачисленияВзносы` | Взносы (ЕСВ) |
