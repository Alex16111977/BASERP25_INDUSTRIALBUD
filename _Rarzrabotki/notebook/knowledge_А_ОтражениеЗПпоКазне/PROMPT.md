## 1. Что представляет собой документ `А_ОтражениеЗПпоКазне`

**Документ-агрегатор** для отражения зарплаты в финансовом и бухгалтерском учёте на основании данных из двух внешних баз 1С:

- **BuhKazn (Казна)** — управленческий учёт зарплаты по сотрудникам/подразделениям/направлениям
- **BuhBud (BAS Бухгалтерія)** — налоговый/регламентированный учёт (НДФЛ, ЕСВ, военный сбор, удержания)

Документ **НЕ имеет движений по регистрам** (RegisterRecords пуст) — это **документ-источник данных** для последующего создания:
- ЗУП-документа «Начисление зарплаты» (`Документ.НачислениеЗарплатыСотрудникам` или похожий)
- Документа «Отражение зарплаты в финансовом учёте» (типовой или кастомный `А_ОтражениеЗарплатыВУчете`)

### Реквизиты документа

| Реквизит | Тип |
|---|---|
| `Организация` | Справочник.Организации |
| `Ответственный` | Справочник.Пользователи |
| `Комментарий` | Строка |

### Табличные части (7 шт.)

| ТЧ | Назначение | Источник заполнения |
|---|---|---|
| **`РаспределениеКазна`** | Распределение зарплаты по сотрудникам/подразделениям/направлениям из Казны (с UUID документа-регистратора) | Загрузка из BuhKazn (РегНакопл.БДДС, документы РаспределениеЗаработнойПлаты / РаспределениеФ2) |
| `НачисленнаяЗарплатаИВзносыПоФизлицам` | Начисления для документа отражения в фин.учёте (per ФизЛицо/Подразделение/ВидОперации/Способ) | Расчёт из БухБуд налогов |
| `НачисленныйНДФЛ` | НДФЛ для документа отражения | Расчёт из БухБуд налогов |
| `НалогиБухгалтерия` | Налоги из БухБуд (НДФЛ/ЕСВ/Военсбор/прочие) per Сотрудник/КодДохода/ТипНалога | Загрузка из BuhBud |
| `УдержанияБухгалтерия` | Удержания из БухБуд (алименты, исп.листы, профвзносы) per ФизЛицо | Загрузка из BuhBud |
| `НачисленияУпр` | Начисления управленческого учёта per ФизЛицо/ВидРасчёта | Расчёт из ТЧ налогов (NET = Сумма_Начисления − Сумма_Налогов) |
| `УдержанияУпр` | Удержания управленческого учёта | Аналогично |

## 5. Anti-patterns (не делать)

| Anti-pattern | Почему |
|---|---|
| Использовать `Строка(UUID)` для COM-UUID | Возвращает `'None'` или пустоту. **Использовать `V83.string(UUID)` lowercase** |
| Использовать `XMLСтрока(UUID)` для cross-base UUID | Бросает «Ошибка преобразования XML». Использовать `V83.string()` |
| Объявлять локальную переменную `Ссылка` | Конфликтует с системным свойством `.Ссылка`. **Использовать `ДокСсылка`/`РезСсылка`** |
| Использовать `Сериализовать через ЗначениеВСтрокуВнутр` между BuhKazn/BuhBud и ERP с разными типами справочников | После десериализации ссылки невалидны. Итерировать COM-таблицы напрямую через `V83.String()`, `V83.ЗначениеЗаполнено()` |
| Запрашивать `СубконтоДт1` напрямую из `РегистрБухгалтерии.Хозрасчетный` | Поле НЕ доступно в основной таблице. Использовать ВТ `ОстаткиИОбороты` (там `Субконто1`) |
| Использовать `В ИЕРАРХИИ` внутри `СУММА(ВЫБОР КОГДА ...)` | Запрещено платформой. Разделить на UNION ALL |
| Передавать Python `datetime` как параметр запроса в COM-запрос с виртуальной таблицей | tz-сдвиг. Использовать `ДАТАВРЕМЯ(2026,4,1,0,0,0)` инлайн в SQL |
| Использовать `Количество` в `РегистрБухгалтерии.Хозрасчетный` | Поле не существует (корреспондентный регистр). **Использовать `КоличествоДт`/`КоличествоКт`** |
| Создавать knowledge без discovery (без COM-тестов) | Высокий риск выдумывания имён полей/таблиц. **Сначала COM, потом markdown.** |
| Копировать описание процедур из BSL дословно | Лучше — структурировать по «что делает / какие входы / какие выходы / ловушки» |
| Игнорировать существующие knowledge базы как образец | Несовместимость стиля. **Прочитать KNOWLEDGE_MAP knowledge_НеоборотныеАктивы и knowledge_Balanse** |
