## §1. Cross-base UUID: только `V83.string(...)` (английский lowercase)

**Проблема:** при попытке извлечь UUID документа Казны для поиска документа в ERP получаешь либо пустую строку, либо exception.

| Что НЕ работает | Результат |
|---|---|
| `Строка(V83_UUID)` | возвращает `""` или `'None'` — `Строка()` в ERP не сериализует COM-объект чужой базы |
| `XMLСтрока(V83_UUID)` | **Exception:** «Ошибка преобразования данных XML» — XML-сериализатор ERP отбрасывает чужой COM-объект |
| `V83.XMLСтрока(V83_UUID)` | Ненадёжно через COM dispatch (Cyrillic method names через прокси V83.COMConnector) |
| `V83.String(...)` (capitalized) | Может работать в Python, но в BSL предпочтительно lowercase |

**Единственный работающий паттерн:**
```bsl
УИДСтр = V83.string(СтрТЗ.Регистратор.УникальныйИдентификатор());
```

**Why:** BSL COM-proxy предпочитает английские имена методов в lowercase. Этот паттерн используется в production-обработках `Обработка_ПлатежВЕРП`, `ПометитьНаУдалениеБухАкты`.

**How to apply:** для любого cross-base lookup используй `V83.string(REF.УникальныйИдентификатор())`. Никогда — `Строка()` или `XMLСтрока()` на чужом COM-объекте.

⚠️ См. также CLAUDE.md «Cross-base UUID lookup» — детальный разбор всех вариантов.

## §2. `Ссылка` — зарезервированное имя локальной переменной

**Проблема:** объявление `Ссылка = Документы.X.ПолучитьСсылку(УИД)` ломает работу `ПолучитьОбъект()` внутри `Попытка/Исключение` — исключение возникает молча.

**Why:** `Ссылка` в BSL конфликтует со системным свойством `.Ссылка` любого объекта документа. Платформа пытается разрешить имя как свойство объекта, а не как локальную переменную.

**WRONG:**
```bsl
Ссылка = Документы.А_РаспределениеЗаработнойПлаты.ПолучитьСсылку(УИД);  // тихо ломается
Если Ссылка.ПолучитьОбъект() <> Неопределено Тогда ... // молчаливый exception
```

**CORRECT:**
```bsl
ДокСсылка = Документы.А_РаспределениеЗаработнойПлаты.ПолучитьСсылку(УИД);
Если ДокСсылка.ПолучитьОбъект() <> Неопределено Тогда ...
```

**How to apply:** никогда не называй локальную переменную `Ссылка`. Используй `ДокСсылка`, `РезСсылка`, `НайденнаяСсылка`, `ОснСсылка`.

## §3. `ЗначениеВСтрокуВнутр` между разными базами с разными типами справочников

**Проблема:** сериализация `ТаблицаЗначений`, содержащей ссылки на справочники чужой базы, в строку через `V83.ЗначениеВСтрокуВнутр(ТЗ)` и десериализация в ERP через `ЗначениеИзСтрокиВнутр(стр)` дают **невалидные ссылки**, на которых `.УникальныйИдентификатор()`, `XMLСтрока()` и `ЗначениеЗаполнено()` падают молча (внутри Попытка) или с exception.

**Why:** в ZUP/Казна — `Справочник.Сотрудники`/`Справочник.БанковскиеСчета`/etc. В ERP этих типов **не существует** (или они другие). После десериализации в ERP rebuild ссылки с типом «незнакомый» → она ведёт себя как broken ref.

**Конкретный пример из CLAUDE.md (СинхронизироватьТовары):**
- BuhBud имеет `Справочник.БанковскиеСчета`
- ERP имеет `Справочник.БанковскиеСчетаОрганизаций`
- После `ЗначениеИзСтрокиВнутр` в ERP — ссылка невалидна
- `.УникальныйИдентификатор()` бросает exception (молчит в Попытка)

**OK** для ТЗ с примитивами (строки/числа/даты/булево):
```sql
-- В zup_1 → ТЗ → в ERP — OK
У.Сотрудник.Физлицо.КодПоДРФО КАК СотрудникИНН,    -- строка
У.ДокументОснование.Получатель.КодПоЕДРПОУ КАК ЕДРПОУПолучателя,  -- строка
СУММА(У.Результат) КАК Сумма                       -- число
```

**FAIL** для ТЗ со ссылками:
```sql
У.Сотрудник КАК Сотрудник  -- СправочникСсылка.Сотрудники ИЗ zup_1, не из ERP
```

**How to apply:** в COM-запросах ВСЕГДА извлекать ссылки через ".Поле.Поле" до примитивов. Никаких `КАК Сотрудник`/`КАК Контрагент` через ЗначениеВСтрокуВнутр между базами с РАЗНЫМИ типами справочников.

## §4. Rule #-1 — Python COM test BEFORE BSL для запросов к чужим базам

**Проблема:** в Казне и ЗУП есть свои особенности (например, `ВзаиморасчетыПоНДФЛ.Доход` → реально `ДоходПриход` для оборотов; `Сумма` в Хозрасчетном → `КоличествоДт`/`КоличествоКт`). Без Python COM-теста запрос упадёт в Designer/Enterprise с непонятной ошибкой.

**Why:** запросы к чужим базам нельзя проверить через MCP `execute_query` — он работает только с ERP. Только Python COM позволяет реально выполнить запрос на BuhKazn / zup_1 / zup_2 и поймать ошибки до того, как они попадут в продакшен.

**Pattern, который уже находил ошибки в этом проекте (CLAUDE.md):**
- `ВзаиморасчетыПоНДФЛ.Доход` → реально `ДоходПриход` (сальдовый регистр)
- `ЛЕВОЕ СОЕДИНЕНИЕ ... КАК ПО` → реально `КАК ПодрОрг` (`ПО` зарезервировано)
- `Сотрудник.Физлицо.Наименование` у `.Обороты()` где Сотрудник — **реквизит**, не измерение → недоступно

**How to apply:** прежде чем писать ЛЮБОЙ COM-запрос в BSL — сначала прогнать его через Python COM:
```python
import win32com.client, sys
sys.stdout.reconfigure(encoding='utf-8')

v8 = win32com.client.Dispatch("V83.COMConnector")
zup1 = v8.Connect('Srvr="SQLSERVER";Ref="zup_1";Usr="cfo";Pwd="2442"')

q = zup1.NewObject("Запрос")
q.Текст = """..."""
try:
    r = q.Выполнить().Выгрузить()
    print(f"OK, rows={r.Количество()}")
except Exception as e:
    if hasattr(e, 'excepinfo') and e.excepinfo:
        print(f"FAIL: {e.excepinfo[2]}")
    else:
        print(f"FAIL: {e}")
```

Только после успешного запуска — переносить в BSL.

## §5. COM-сессии нужно закрывать ЯВНО

**Проблема:** после COM-вызовов оставшиеся ссылки `V8` / `V83` держат сессию 1cv8.exe на сервере несколько минут (даже после завершения BSL), что блокирует других пользователей.

**WRONG:**
```bsl
Попытка
    V8 = Новый COMОбъект("V83.COMConnector");
    V83 = V8.Connect(...);
    // ... запрос
Исключение
    // не закрыл COM
КонецПопытки;
// V83/V8 живут до конца сессии BSL
```

**CORRECT:**
```bsl
Попытка
    V8 = Новый COMОбъект("V83.COMConnector");
    V83 = V8.Connect(...);
    // ... запрос
Исключение
    V83 = Неопределено;
    V8 = Неопределено;
    ВызватьИсключение "...";
КонецПопытки;
V83 = Неопределено;
V8 = Неопределено;
```

**How to apply:** ВСЕГДА освобождать `V83 = Неопределено; V8 = Неопределено` в обоих ветках Попытка/Исключение.

## §6. Передача массива в COM-запрос — через NewObject в контексте V83

**Проблема:** обычный ERP-массив (`Новый Массив`), переданный как параметр в COM-запрос к Казне/ЗУП, не работает — V83 не понимает его тип.

**WRONG:**
```bsl
масКодПоЕДРПОУ = Новый Массив;
масКодПоЕДРПОУ.Добавить("40645273");
ЗапросНал.УстановитьПараметр("масКодПоЕДРПОУ", масКодПоЕДРПОУ);  // FAIL
```

**CORRECT:**
```bsl
масКодПоЕДРПОУ = Новый Массив;
// ... fill in ERP-context

// Convert to V83-context
масКодПоЕДРПОУ_V83 = V83.NewObject("Массив");
Для Каждого КодЕДРПОУ Из масКодПоЕДРПОУ Цикл
    масКодПоЕДРПОУ_V83.Добавить(КодЕДРПОУ);
КонецЦикла;

ЗапросНал.УстановитьПараметр("масКодПоЕДРПОУ", масКодПоЕДРПОУ_V83);
```

**How to apply:** любой массив, передаваемый как параметр через COM, должен быть создан через `V83.NewObject("Массив")`.

## §7. Сальдовый регистр накопления → префиксы `Приход`/`Расход`/`Оборот`

**Проблема:** запрос `ВЫБРАТЬ Регистр.Налог ИЗ РегистрНакопления.ВзаиморасчетыПоНДФЛ.Обороты(...)` падает — «Поле не найдено».

**Why:** регистр **сальдовый** (НЕ оборотный), поэтому в виртуальной таблице `.Обороты()` поля имеют префиксы:
- `НалогПриход`, `НалогРасход`, `НалогОборот`
- `ДоходПриход`, `ДоходРасход`, `ДоходОборот`

Без префикса — поле не существует.

**CORRECT:**
```sql
ВЫБРАТЬ
    СУММА(ВзаиморасчетыПоНДФЛ.НалогПриход) КАК СуммаНалога,
    СУММА(ВзаиморасчетыПоНДФЛ.ДоходПриход) КАК СуммаДохода
ИЗ
    РегистрНакопления.ВзаиморасчетыПоНДФЛ.Обороты(&НачП, &КонП,,) КАК ВзаиморасчетыПоНДФЛ
```

**How to apply:** перед использованием `.Обороты()` сальдового регистра — проверить структуру через `mcp__1c-workerp__get_metadata_structure` или Python `kazna.Метаданные.РегистрыНакопления.Найти(...)`. Поля будут с префиксами.

## §8. ФильтрФЛ обязателен для всех ТЧ ЗУП-документа после Начислений

**Проблема:** проведение `НачислениеЗарплаты` падает с ошибкой `«Сотрудник пустой»` для регистра `ВзаиморасчетыССотрудниками`.

**Why:** для ФизЛица, у которого нет записи в ТЧ `Начисления`, нет соответствующего Сотрудника. Если в ТЧ Удержания / НДФЛ / ВзносыФОТ попадает такое ФизЛицо — запись регистра падает.

**CORRECT:**
```bsl
// После заполнения Начислений — построить множество "что в Начислениях"
ФЛВНачисленияхСет = Новый Соответствие;
Для Каждого СтрН Из НЗ.Начисления Цикл
    Если ЗначениеЗаполнено(СтрН.Сотрудник) Тогда
        ФЛ = СтрН.Сотрудник.ФизическоеЛицо;
        Если ЗначениеЗаполнено(ФЛ) Тогда
            ФЛВНачисленияхСет.Вставить(ФЛ, Истина);
        КонецЕсли;
    КонецЕсли;
КонецЦикла;

// Все следующие циклы — фильтр по этому множеству
Для Каждого СтрНБ Из НалогиБухгалтерия Цикл
    Если ФЛВНачисленияхСет[СтрНБ.Сотрудник.ФизическоеЛицо] = Неопределено Тогда
        Продолжить;  // ОБЯЗАТЕЛЬНО
    КонецЕсли;
    // ... заполнение НДФЛ или ВзносыФОТ
КонецЦикла;
```

**How to apply:** в `СоздатьДокументНачисления` после ТЧ Начислений — строить множество ФизЛиц и фильтровать все остальные ТЧ.

## §9. Подмена группы «Прочие пассивы» в `СтатьяАктивовПассивов`

**Проблема:** проведение `ОтражениеЗарплатыВФинансовомУчете` падает, потому что `СтатьяАктивовПассивов = ГРУППА "Прочие пассивы"` (не элемент).

**Why:** в ТЧ `УдержанияБухгалтерия` родителя случайно записана ссылка на ГРУППУ, а не предопределённый ЭЛЕМЕНТ. ERP проверяет тип и отказывается работать с группой.

**CORRECT:**
```bsl
ПрочиеПассивыЭлемент = ПланыВидовХарактеристик.СтатьиАктивовПассивов.ПрочиеПассивы;  // предопределённый ЭЛЕМЕНТ

Если ЗначениеЗаполнено(НоваяСтр.СтатьяАктивовПассивов)
    И НоваяСтр.СтатьяАктивовПассивов.ЭтоГруппа Тогда
    НоваяСтр.СтатьяАктивовПассивов = ПрочиеПассивыЭлемент;
КонецЕсли;
```

**How to apply:** при копировании из родителя в дочку — проверять `.ЭтоГруппа` и подменять на предопределённый элемент.

## §10. Изменение TZ-чувствительных datetime в COM-параметрах

**Проблема:** Python `datetime` (особенно tz-aware) при передаче в COM-параметр запроса проседает в TZ-сдвиг (несколько часов), и фильтр `МЕЖДУ &НачП И &КонП` выдаёт неожиданные результаты.

**Why:** COM-маршаллер не унифицирует TZ — Python `datetime(2026, 4, 1, 0, 0, 0, tzinfo=tz)` может стать в 1С `2026-03-31 22:00:00`.

**WRONG:**
```python
q.УстановитьПараметр("НачП", datetime(2026, 4, 1, 0, 0, 0))  # без TZ-aware
# или
q.УстановитьПараметр("НачП", datetime(2026, 4, 1, 0, 0, 0, tzinfo=tz_utc))  # с TZ
```

**CORRECT — inline в SQL:**
```python
q.Текст = """
ВЫБРАТЬ ...
ИЗ ...
ГДЕ Регистр.Период МЕЖДУ ДАТАВРЕМЯ(2026, 4, 1, 0, 0, 0) И ДАТАВРЕМЯ(2026, 4, 30, 23, 59, 59)
"""
```

**How to apply:** для критичных периодов — inline через `ДАТАВРЕМЯ(...)` в SQL, не как параметр.

## §11. `В ИЕРАРХИИ` внутри агрегата (СУММА/ВЫБОР) запрещено

**Проблема (из CLAUDE.md):** `СУММА(ВЫБОР КОГДА X В ИЕРАРХИИ (...) ТОГДА Y ИНАЧЕ 0 КОНЕЦ)` — выдаёт ошибку «Не допускается использование вложенных запросов и операции В ИЕРАРХИИ внутри агрегатных функций».

**Why:** платформа не умеет компилировать `В ИЕРАРХИИ` в скалярное выражение внутри агрегата.

**Workaround:** `UNION ALL` с `В ИЕРАРХИИ` в `WHERE`:
```sql
ВЫБРАТЬ Сумма КАК Приход, 0 КАК Расход
ИЗ ... ГДЕ СчетДт В ИЕРАРХИИ (...)
ОБЪЕДИНИТЬ ВСЕ
ВЫБРАТЬ 0, Сумма
ИЗ ... ГДЕ СчетКт В ИЕРАРХИИ (...)
```

**How to apply:** если нужна агрегация с фильтром по иерархии — разбивай на 2 запроса через UNION ALL.

## §12. В Хозрасчетный (корреспондентный) нет поля `Количество`

**Проблема:** запрос к `РегистрБухгалтерии.Хозрасчетный` с полем `Количество` падает — «Поле не найдено».

**Why:** регистр **корреспондентный** (Корреспонденция = Истина), поэтому количество разделено по сторонам: `КоличествоДт` + `КоличествоКт`. Аналогично — `СчетДт`/`СчетКт`, `СубконтоДт1-3`/`СубконтоКт1-3`. `Сумма` НЕ разделена (одно поле).

**WRONG:**
```sql
ВЫБРАТЬ СУММА(Д.Количество) ИЗ РегистрБухгалтерии.Хозрасчетный КАК Д
```

**CORRECT:**
```sql
ВЫБРАТЬ
    СУММА(Д.КоличествоДт - Д.КоличествоКт) КАК Количество
ИЗ РегистрБухгалтерии.Хозрасчетный КАК Д
```

⚠️ Это применимо и к BuhBud, и к ERP — оба используют корреспондентный Хозрасчетный.

## §13. Создание сотрудника из чужой базы — через `А_Привилегированный`

**Проблема:** прямое создание `Справочник.Сотрудники` через `СоздатьЭлемент()` в обработке часто требует привилегий (доступ к Физическим Лицам, заполнение паспортов и т.д.).

**Solution:** все создания идут через привилегированную процедуру `А_Привилегированный.СоздатьСотрудникаИзКазны(ФИО, ИНН, КодКазны)`:

```bsl
НайдСотр = А_Привилегированный.СоздатьСотрудникаИзКазны(ФИОК, ІННК, КодК);
```

Это происходит **ТОЛЬКО** если поиск по ФИО (кеш) и ИНН (А_КодПоДРФО) не дал результата.

**How to apply:** для любых operations, требующих повышенных прав в Документах из обработок — использовать `А_Привилегированный.*`. Документ объявлен с `<PostInPrivilegedMode>true</PostInPrivilegedMode>`.

## §14. ОЧЕНЬ ВАЖНО: реальный источник Налогов/Удержаний — `zup_1`, не `BuhBud`

**Проблема:** PROMPT.md описывает архитектуру так, как будто данные приходят из BuhBud (BAS Бухгалтерія). Реальный код подключается к **`zup_1`** (BAS ЗУП регламент).

**Why:** PROMPT.md был основан на устаревшем предположении. Реальный код в `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl` (строка 422):
```bsl
СтрокаПодключенияЗУП = "Srvr=""SQLSERVER"";Ref=""zup_1"";Usr=""cfo"";Pwd=""2442""";
```

**How to apply:** при работе с этим документом — учитывать что:
- Для НалогиБухгалтерия + УдержанияБухгалтерия — connection `zup_1`
- Для НачисленияУпр + УдержанияУпр — connection `zup_2`
- К BuhBud (BAS Бухгалтерія) обращений **нет**

Однако антипаттерны из CLAUDE.md по BuhBud (КоличествоДт/Кт в Хозрасчетный, СубконтоДт1 недоступно в основной таблице) — **актуальны** для других задач/процессоров и могут пригодиться позднее.

## §15. `СуммаНДФЛ ≠ 0`, НЕ `Сумма ≠ 0` для фильтрации НДФЛ-строк

**Проблема:** Op 3 (`_ОтрЗП_ЗаполнитьНДФЛИзНалогов`) ошибочно записывает ЕСВ-строки в НачисленныйНДФЛ — потому что в НалогиБухгалтерия `Сумма` имеет fallback на `СуммаФОТ` для ЕСВ.

**Why:** Сумма для НДФЛ-строк = СуммаНДФЛ, для ЕСВ-строк = СуммаФОТ. Если фильтровать `Сумма > 0` — оба типа попадают.

**WRONG:**
```bsl
Если СтрокаНалога.Сумма = 0 Тогда Продолжить; КонецЕсли;  // ЕСВ-строки тоже пройдут
```

**CORRECT:**
```bsl
// Берём ТОЛЬКО строки с НДФЛ/ВС (СуммаНДФЛ > 0)
Если СтрокаНалога.СуммаНДФЛ = 0 Тогда Продолжить; КонецЕсли;
```

Аналогично для Op 1 — фильтр на СуммаФОТ:
```bsl
Если СтрокаНалога.СуммаФОТ = 0 Тогда Продолжить; КонецЕсли;
```

**How to apply:** в смешанных ТЧ типа НалогиБухгалтерия (НДФЛ+ВС+ЕСВ в одной таблице) — фильтровать ВСЕГДА по специфическому полю суммы (`СуммаНДФЛ` для НДФЛ/ВС, `СуммаФОТ` для ЕСВ), НЕ по общему `Сумма`.
