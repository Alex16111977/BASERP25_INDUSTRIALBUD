# 18 — Ф1: выравнивание gross-up «Удержание» под `НачисленныйНДФЛ` (Приход = перенос до копейки)

> **🟢 РЕАЛИЗОВАНО 2026-06-01.** Устранён копеечный разрыв (−0.01) в `РегистрНакопления.А_ВзаиморасчетыССотрудниками` (отчёт «Взаиморасчёты с сотрудниками для баланса»): по Форме1 начисления (NET «Зарплата управл») и их налоги совпадают до 0.01 между дочерним `ОтражениеЗарплатыВФинансовомУчете` (Приход) и `А_ПередачаНачисленийМеждуПодразделениями` (перенос).

## TL;DR

- **Проблема:** в отчёте по Шишкіної (дек.2025) Ф1 Спецтехника показывал остаток **−0.01** (Приход 6685.70 ≠ перенос 6685.71).
- **Корень:** официальный Ф1-НДФЛ разбит по подразделениям **дважды по разным ключам** — gross-up строка «Удержание с админ зарплату» в `НачисленнаяЗарплатаИВзносыПоФизлицам` (Op2, равномерно: 1997.03/1997.03) и ТЧ `НачисленныйНДФЛ` (Op3, налог-за-налогом: 1997.02/1997.04). Регистр Приход = `Начислено − НачисленныйНДФЛ`, перенос = «Зарплата управл» → разница `(Удержание − НДФЛ) = ±0.01` на подразделение.
- **Фикс:** новая процедура `_ОтрЗП_ВыровнятьУдержаниеСНДФЛ(Справочные)` перестраивает gross-up «Удержание» Ф1 **ровно под `НачисленныйНДФЛ` per (ФЛ, Подр)**. Σ per ФЛ сохраняется → `Начислено − НДФЛ = «Зарплата управл»` до копейки → Приход(ОЗФУ) = перенос(ПередачаНач).
- **НЕ трогаем:** разрыв «начислено ↔ выплачено» (−110.26 Ф1, +128.58 Ф2, итого +18.32) — **норма** (timing: банк доплатит в след. месяце / касса выплатит меньше). Это разница начисление(Бухгалтерия) ↔ фактическая выплата(Казна), сводить к нулю за месяц НЕ надо.

## 1. Корень разрыва −0.01 (подтверждено Python COM, эталон Шишкіна дек.2025)

Один и тот же официальный Ф1-НДФЛ (3994.06 = НДФЛ 3125.79 + ВоенСбор 868.27) присутствует в ОЗФУ **дважды**:

| Представление | Где | Кто создаёт | Разбивка по подр (Произв / Спец) |
|---|---|---|---|
| gross-up «Удержание с админ зарплату» | `НачисленнаяЗарплатаИВзносыПоФизлицам` (Ф1) | `_ОтрЗП_СоздатьСтрокиNETФЛ_Новый` (Op2) | **1997.03 / 1997.03** (равномерно, по весам Казны-удержаний) |
| ТЧ `НачисленныйНДФЛ` (Ф1) | отдельная ТЧ | `_ОтрЗП_ЗаполнитьНДФЛИзНалогов` (Op3) | **1997.02 / 1997.04** (налог-за-налогом: НДФЛ и ВС отдельными проходами `остаток-на-последнем`) |

Регистр Приход (`А_ВзСС.ManagerModule.ЗаполнитьИзОтраженияЗП`) = `Σ НачисленнаяЗарплата(Налог=пусто) − НачисленныйНДФЛ` = («Зарплата управл» 6685.71 + «Удержание» 1997.03) − НДФЛ.
- Произв: 6685.71 + 1997.03 − 1997.02 = **6685.72**
- Спец: 6685.71 + 1997.03 − 1997.04 = **6685.70**

Перенос `ПередачаНачислений.Начисления` (`_ПНМП_ЗаполнитьНачисления`) = «Зарплата управл» (не-удержание Ф1) = **6685.71 / 6685.71**.

→ Спецтехника: Приход 6685.70 vs перенос 6685.71 = **−0.01**.

## 2. Фикс — `_ОтрЗП_ВыровнятьУдержаниеСНДФЛ(Справочные)`

`Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`. Вызывается в `ЗаполнитьДляОтражения_ДокументОтражениеЗарплатыВФинансовомУчете` **ПОСЛЕ** `_ОтрЗП_РазметитьФормаPL` (когда `ФормаPL` проставлено обеим ТЧ) и **ДО** `_ОтрЗП_ПроставитьОргБухВсемФорма1` (он дозаполнит пустой ОргБух).

Алгоритм:
1. Собрать `НачисленныйНДФЛ` Ф1 per (ФЛ, Подр) (с посыланиями).
2. Найти старые gross-up «Удержание» Ф1 (`Способ.А_ЭтоУдержание И ВзносыВсего = 0`): сохранить шаблон per ФЛ (Способ/ВидОперации/ГруппаУчета) + ОргБух per (ФЛ,Подр), пометить на удаление.
3. Удалить старые «Удержание» (с конца — индексы не сдвигаются).
4. Добавить «Удержание» = `НачисленныйНДФЛ` per (ФЛ, Подр) (ОргБух из карты; пустой дозаполнит `_ОтрЗП_ПроставитьОргБухВсемФорма1`).

**Инвариант:** Σ`НачисленныйНДФЛ` per ФЛ = `НДФЛДляФЛ` = старое Σ`Удержание` per ФЛ → **Σ per ФЛ сохраняется**, меняется только по-подразделенческая раскладка (≤ копейки). Поэтому фикс **физически не может** изменить суммы крупнее 0.01 и Σ по ФЛ.

После фикса: `Начислено − НДФЛ` = «Зарплата управл» (т.к. «Удержание» = НДФЛ по подр) → регистр Приход = перенос до копейки. Налоги переноса (`_ПНМП_ЗаполнитьНалоги` читает `НачисленныйНДФЛ` напрямую) совпадают с ОЗФУ по построению.

## 4. Глобально + отложенное

- **Копеечный класс (|Δ|≤0.02) глобально = 0** после фикса (по всем документам/ФЛ). Фикс закрывает округление везде, где есть NET-ФЛ структура (gross-up «Удержание»).
- **🟡 196 ФЛ с КРУПНЫМ расхождением (|Δ|>0.02) — ОТЛОЖЕНО (отдельная задача).** Это **GROSS-style** ФЛ: «Зарплата управл» — это GROSS без отдельной строки «Удержание», поэтому `Начислено − НДФЛ`(take-home) ≠ «Зарплата управл»(GROSS). До-существующее, фикс п.2 их **не трогает** (нет gross-up «Удержание»). Если возьмём — привести их «Зарплата управл» к take-home + gross-up «Удержание», как у NET-ФЛ.

## 6. Грабли

1. **Один НДФЛ — один ключ разбивки.** Если налог попадает в две ТЧ (gross-up «Удержание» + `НачисленныйНДФЛ`), разбивать обе по подразделениям **одинаково**. Разные проходы `остаток-на-последнем` (один общей суммой, другой налог-за-налогом) дают расхождение копеек. Решение — производная: строить «Удержание» ИЗ `НачисленныйНДФЛ` (а не независимо).
2. **Порядок вызова критичен.** `_ОтрЗП_ВыровнятьУдержаниеСНДФЛ` — ПОСЛЕ `РазметитьФормаPL` (иначе `ФормаPL` ещё не проставлен → фильтр `= Форма1` отсеет всё) и ДО `ПроставитьОргБухВсемФорма1` (он дозаполнит ОргБух новым строкам).
3. **Σ-preserving — ключ безопасности.** Фикс перераспределяет внутри ФЛ, не меняя итог по ФЛ → не может задеть крупные суммы. Это позволило отделить «свой» класс (копейки) от до-существующих структурных расхождений.
4. **Python COM: enum через `XMLСтрока`, пустые ссылки через `ЗначениеЗаполнено`, ТЧ итерировать индексно** (`.Получить(i)`). `str(перечисление)` = `'<COMObject>'` → фильтр тихо пропускает всё → **ложный GREEN** (поймано на первом прогоне). См. [LESSONS §20/§21](LESSONS.md).
