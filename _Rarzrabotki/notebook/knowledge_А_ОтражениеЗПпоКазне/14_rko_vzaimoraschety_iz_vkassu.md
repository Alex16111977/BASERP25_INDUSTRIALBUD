## 1. Что сделано

Расширена процедура `ЗаполнитьИзРКО` в `AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl`. Добавлена развилка по типу `ДокОбъект.Ведомость`:

| Случай | Источник данных | Подразделение в регистре |
|---|---|---|
| `Ведомость = ВедомостьНаВыплатуЗарплатыВКассу` (наша) | ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам | `Рш.Подразделение.А_Подразделение` (ПодрОрг → СтрПредпр через реквизит `А_Подразделение`) — **разрез по подразделениям** |
| Ведомость пустая или другого типа | ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации (старая логика) | `Д.Подразделение` (СтрПредпр из шапки) |

## 2. Поток данных

```
[РКО проведено с Ведомость = наша ВКассу]
                ↓
   AccumulationRegisters/А_ВзаиморасчетыССотрудниками/Ext/ManagerModule.bsl
   Процедура ЗаполнитьИзРКО(ДокОбъект):
     ├─ ЭтоНашаВКассу = ТипЗнч(Ведомость) = Тип("ДокументСсылка.ВедомостьНаВыплатуЗарплатыВКассу")
     ├─ Если Истина → запрос по ТЧ.А_РасшифровкаВыплатыЗарплатаПоФизлицам:
     │      Подразделение = Рш.Подразделение.А_Подразделение  ← ПодрОрг → СтрПредпр
     │      Σ = СУММА(Рш.КВыплате)
     │      Группировка per (Орг, СтрПредпр, ФЛ)
     ├─ Иначе → старая логика (ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации)
     └─ Цикл: для каждой строки результата → Запись в регистр (ВидДвижения=Расход)
                ↓
   Регистр накопления А_ВзСС наполнен в разрезе подразделений.
   Сальдо Приход − Расход (по ФЛ × СтрПредпр) = чистый долг работодателя перед ФЛ.
```

## 3. Уроки

### Урок №1: реквизит ПодрОрг → СтрПредпр называется `А_Подразделение`

Справочник `ПодразделенияОрганизаций` в этом проекте имеет **кастомный** реквизит `А_Подразделение` (тип `Справочник.СтруктураПредприятия`), а **не** типовое `Подразделение`.

Точечная навигация в запросе: `Рш.Подразделение.А_Подразделение` → СтрПредпр (с автоматическим LEFT JOIN на справочник).

Ловушка: если попытаться `.Подразделение` — получим ошибку «Поле не найдено». В первом черновике плана было `Подразделение.Подразделение` (типовая конвенция БСП), но реальная структура справочника отличается. Это типичная ситуация для проектов с префиксом `А_`.

### Урок №2: фильтр выбора ведомости в РКО матчит по Кассе

Если `РКО.Касса ≠ ВКассу.Касса` — типовой подбор ведомости в РКО не находит её. Решение для эталона: вручную сменить Кассу в ВКассу через MCP/COM с `vk.ОбменДанными.Загрузка = True` (чтобы не запускать типовую логику перезаполнения ТЧ).

### Урок №3: разрез по подразделениям — ключевая особенность

В шапке РКО Подразделение **одно**. В строках А_Расшифровки могут быть **разные** подразделения. Новая логика создаёт **N движений регистра** per (Орг, СтрПредпр, ФЛ).

На эталонном РКО N0000052986 получилось **12 уникальных СтрПредпр** в движениях регистра (Автокран XCMG, Виброкаток, МАЗ 264, МАЗ 265, РДК 250, Самосвал Камаз, Самосвал МАЗ, Телескоп 1, Телескоп 2, Телескоп JCB 535-140 №4, Экскаватор JCB 220, Экскаватор JCB 3CX 2008) — для будущих отчётов управленческого баланса в разрезе фондов/техники.

### Урок №4: обратная совместимость через развилку `ЭтоНашаВКассу`

Старая ветка (ТЧ.ВыплатаЗаработнойПлаты + 3 хозоперации `ВыплатаЗарплатыЧерезКассу/Раздатчиком/Работнику`) полностью сохранена. РКО без нашей ВКассу или с другим типом ведомости (`ВедомостьНаВыплатуЗарплатыВБанк`, `ВедомостьНаВыплатуЗарплатыПеречислением`, `ВедомостьНаВыплатуЗарплатыРаздатчиком`) работает по типовому пути.

### Урок №5 (2026-05-29): РКО.ПриЗаписи блокирует ВКассу через `А_Необновлять`

В `Documents/РасходныйКассовыйОрдер/Ext/ObjectModule.bsl:1127-1131` есть подпись: когда РКО проведён с `ХозяйственнаяОперация = ВыплатаЗарплатыЧерезКассу` и заполненной Ведомостью, выполняется:

```bsl
ДокВедомость.А_Необновлять = Источник.Проведен;   ← Истина при проведении РКО
ДокВедомость.Записать();
// Также: Ф2.А_Необновлять = Источник.Проведен, Ф2.Закрытый = Источник.Проведен
```

Это **системная подпись**, наша логика её не вводит. Эффект:
- После проведения РКО ВКассу заблокирована от перезаписи из А_ОтражениеЗПпоКазне (см. [15_vkassu_skip_neobnovlyat.md](15_vkassu_skip_neobnovlyat.md)).
- Распроведение РКО автоматически сбрасывает флаг в Ложь.

Эта подпись и наш гард в `_ОЗП_СоздатьВКассуИзФ2` (с 2026-05-29) — две части одного контракта: «занятая РКО ВКассу не модифицируется». Без этой подписи гард в нашей процедуре не имел бы смысла.

### Урок №5: остаток процедуры (цикл записи) универсален

В исходном коде `ЗаполнитьИзРКО` после Запрос.Текст идёт `Результат = Запрос.Выполнить().Выгрузить()` и цикл `Для Каждого СтрТЗ Из Результат Цикл → Запись.Добавить()`. Этот блок **не изменялся** — он работает одинаково для обеих веток, потому что обе ветки возвращают набор колонок (Организация, Подразделение, ФизическоеЛицо, ВидДвижения, СуммаВзаиморасчетов). Чистый принцип: одна точка выходов, разные источники.
