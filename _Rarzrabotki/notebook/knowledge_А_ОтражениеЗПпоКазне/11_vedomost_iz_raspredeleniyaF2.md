## 3. Критичные находки и уроки

### Урок №1: типовая ВедомостьПередЗаписью чистит ТЧ Зарплата без матча в Составе (hotfix v3 — РЕШЕНО)

При вызове `ВыкВКассу.Записать(...)` типовой код `CommonModule.ВзаиморасчетыССотрудникамиБазовый.ВедомостьПередЗаписью` (стр. 1135-1154) перебирает ТЧ Зарплата и **удаляет все строки, у которых ИдентификаторСтроки не совпадает ни с одной строкой ТЧ Состав**.

В v1 строки Зарплата получали свои уникальные UID, строки Состав — свои — рассинхрон → все строки Зарплата чистились.

**Решение (hotfix v3):** строить ТЧ Состав **СНАЧАЛА**, фиксировать карту `ФЛ→UID`, а каждой строке Зарплата проставлять `ИдентификаторСтроки = карта[ФЛ]`. Так несколько строк Зарплата по одному ФЛ имеют одинаковый UID, совпадающий с UID одной строки Состав → платформа их не трогает. Поскольку у ТЧ Состав только 2 поля (ИдентификаторСтроки + ФизическоеЛицо), синхронизация `ЗаполнитьЗначенияСвойств(СтрокаЗарплаты, СтрокаСостава, ПоляСостава)` перетирает лишь `ФизическоеЛицо` (с того же на то же) — другие поля Зарплата (Сотрудник, Подразделение, КВыплате, ПериодВзаим, ГруппаУчёта) не задеваются.

### Урок №2: проведение с движениями (hotfix v3)

После hotfix v3 ВКассу пишется через `РежимЗаписиДокумента.Проведение` БЕЗ `ОбменДанными.Загрузка=Истина` (платформа запрещает Проведение в режиме загрузки). Типовая `ВедомостьЗарегистрироватьВыплату` формирует движения по РН.ЗарплатаКВыплате и РН.ВзаиморасчетыССотрудниками.

**Особенность:** Σ движений ≠ Σ ТЧ Зарплата — типовой механизм доагрегирует остатки задолженности по ФЛ из регистра ЗКВ. На эталоне `000Ц-000001`: ТЧ=84 155.25 (10 строк) vs Движения=87 812.74 (11 строк, Δ +3 657.49). На нашей `000Ц-000002`: ТЧ=348 800 (31 строка) vs Движения=354 382.51 (32 строки, Δ +5 582.51 — закрытие задолженности Дубінько С.В. из остатка регистра).

Это **типовое поведение БСП**, не аномалия. Если в будущем понадобится 1:1 (только наши строки в движениях) — потребуется перетирать `Движения.ЗарплатаКВыплате` после `Записать(Проведение)` или ставить `ВводНачальныхДанных=Истина` (отключает регистрацию выплаты целиком).

### Урок №3: алиас `КАК В` зарезервирован

В Python тесте `idempotency` запрос `ВЫБРАТЬ КОЛИЧЕСТВО(*) КАК Кол ИЗ Документ.ВКассу КАК В` падал с «Ожидается имя». Буква `В` — оператор `В ИЕРАРХИИ` / `В` (in-list). Использовать `КАК Вед` / `КАК Док`.

### Урок №4: COM-объекты в Python нельзя сравнивать через `str()`

`str(vk.Подразделение)` всегда возвращает `<COMObject <unknown>>`. Нужно:
- Для имени: `vk.Подразделение.Наименование`
- Для пустоты: `vk.Подразделение.Пустая()`
- Для сравнения ссылок: `erp.string(ref.УникальныйИдентификатор())` → UUID-строка

### Урок №5: doctype в `-Files` для db-load-xml

При попытке `-Files "Forms/ФормаДокумента/Ext/Form.xml,Forms/ФормаДокумента/Ext/Form/Module.bsl"` 1С падает с «Неизвестный объект метаданных Document.РаспределениеФ2.Form.ФормаДокумента.Ext». Правильно: `-Files "Forms/ФормаДокумента.xml"` — это метаданное формы, 1С сам подцепляет Ext/* как часть формы.

### Урок №6: источник ТЧ Зарплата — ТЧ Распределение Ф2, не ТЧ Сотрудники (hotfix v2)

Первая версия (commit `656d60d3a`) заполняла ТЧ Зарплата из агрегата ТЧ Сотрудники Ф2 — **1 строка на ФЛ**, шапочное `Подразделение=ЦО`. Двойной клик на сотруднике в UI открывает подформу «Редактирование зарплаты сотрудника», которая группирует ТЧ Зарплата по ФизЛицу и **показывает каждую строку как отдельную запись по подразделению**. Если строк-источников 1 — подформа пуста, потому что типовая подформа не считает себя «расшифровкой» при одной строке.

Эталон 000Ц-000001 от 31.01.2026 показал, что в работающей типовой ВКассу **N строк на ФЛ**: каждая со своим `Подразделение`, `ПериодВзаиморасчетов`, `ГруппаУчётаНачислений="Зарплата (661)"`. Подформа открывается полнотой.

Hotfix v2 (commit `<этот коммит>`): источник ТЧ Зарплата = **ТЧ Распределение Ф2** (детализация по (Сотр × Подр × Период) — 31 строк для эталона), каждая строка с реальным Подразделением (через `КешПодрОрг` СтрПредпр→ПодрОрг) и предопределённой группой "Зарплата (661)".

Уроки:
- Σ инвариант сохранён: Σ ТЧ Зарплата = 348 800 = Σ ТЧ Распределение = Σ ТЧ Сотрудники. Меняется только детализация.
- ТЧ Состав остаётся уникальные ФЛ (21) — расходимся только в Зарплата.
- `ДокументОснование` оставлен пустым: composite-тип реквизита не включает РаспределениеФ2, а ссылку на НачислениеЗарплаты у нас нет. Связь родитель→дочка делается через шапочный реквизит `А_РаспределениеФ2`.

### Урок №7: шапка по образцу типовой ВКассу (hotfix v2)

| Реквизит | v1 | hotfix v2 (по образцу 000Ц-000001) |
|---|---|---|
| Подразделение шапки | ЦО (НайтиПоНаименованию) | **ПУСТО** (как в эталоне) |
| СпособВыплаты | НайтиПоНаименованию("Через кассу") | **`Справочники.СпособыВыплатыЗарплаты.Зарплата`** (предопределённый, Наим="Зарплата за месяц") |
| Организация | из шапки Ф2 | **Касса.Владелец** (если касса найдена; иначе fallback на Ф2.Организация) |
| ПроцентВыплаты | 0 (по умолчанию) | **100** |
| ПорядокЗаполненияНалогов | БезНалогов | БезНалогов (без изменений — НДФЛ не заполняем) |

Использовать предопределённое имя справочника надёжнее `НайтиПоНаименованию`: устойчиво к локализации Наименования.

### Урок №8: ТЧ А_Расшифровка зеркалит ТЧ.Зарплата 1:1 (унификация 2026-05-27)

С 2026-05-27 ТЧ `А_РасшифровкаВыплатыЗарплатаПоФизлицам` имеет **13 полей** вместо 8:

- **11 полей зеркалят ТЧ.Зарплата** (общие поля): ИдентификаторСтроки, Сотрудник, ФизическоеЛицо, Подразделение, ПериодВзаиморасчетов, СтатьяФинансирования, СтатьяРасходов, ДокументОснование (DefinedType.ДокументОснованиеЗарплатыКВыплате), КВыплате (было Сумма — переименовано с сохранением UUID, данные мигрировали), КомпенсацияЗаЗадержкуЗарплаты, ГруппаУчётаНачислений.
- **2 специфичных** (наши): НаправлениеДеятельности, СтатьяДвиженияДенежныхСредств.
- **Удалено:** ОтработаноЧасов (не использовалось для расчётов).

В Шаге 8 заполнение теперь:
```bsl
Для Каждого СтрЗ Из ВыкВКассу.Зарплата Цикл
    НовСтр = ВыкВКассу.А_РасшифровкаВыплатыЗарплатаПоФизлицам.Добавить();
    ЗаполнитьЗначенияСвойств(НовСтр, СтрЗ, ПоляЗеркала);  // 11 полей
    НовСтр.НаправлениеДеятельности = Направление;          // из шапки Ф2
    НовСтр.СтатьяДвиженияДенежныхСредств = СтатьяДДС;     // словарь или Сотр.СтатьяЗарплата
КонецЦикла;
```

Связь со строками Зарплата 1:1 через ИдентификаторСтроки. **Свёртка не нужна.**
