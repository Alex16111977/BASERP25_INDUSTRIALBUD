## 3. Уроки

### Урок №1: переиспользование вместо дублирования

Старая Ф2-процедура уже умеет Find-Or-Create + шапка + Состав + Зарплата + А_Расшифровка + проведение. Не дублируем эту логику — расширяем 2 опциональными параметрами. Альтернатива (отдельная процедура с copy-paste) — двойная поддержка и риск разъезда логики при будущих изменениях.

### Урок №2: ключ словаря (Сотр_UID|ПодрОрг_UID)

Связь строки А_Расшифровки ↔ строка ТЧ.РаспределениеКазна — по паре (Сотрудник, ПодрОрг). В ТЧ.РаспределениеКазна Подразделение — это `Справочник.СтруктураПредприятия`, а в А_Расшифровке Подразделение — `Справочник.ПодразделенияОрганизаций`. Конвертация СтрПредпр → ПодрОрг через `А_Привилегированный.ОбеспечитьПодразделенияОрганизацийПоПодразделению` — обязательна **с обеих сторон** (и при сборе словаря в А_ОтражениеЗПпоКазне.ObjectModule, и при поиске статьи в Ф2.ObjectModule), иначе ключи не совпадут.

### Урок №3: тип реквизита `ДокРаспределениеЗП`

Поле composite: `Документ.РаспределениеФ2, Документ.А_РаспределениеЗаработнойПлаты`. Фильтруем строки **только тип РаспределениеФ2** через `ТипЗнч(СтрРК.ДокРаспределениеЗП) <> Тип("ДокументСсылка.РаспределениеФ2")`. Строки с А_РаспределениеЗаработнойПлаты пропускаем + счётчик `ПропускТипов` в финальном сообщении.

### Урок №4: ложно-зелёные тесты после Find-Or-Create

Тест расширения процедуры (Task 2 plan) показался "PASS" сразу до доставки BSL — потому что:
- ВКассу 000Ц-000002 уже существовала с заполненным А_ОтражениеЗПпоКазне (от ручного ввода)
- При Find-Or-Create процедура НЕ очищает реквизиты шапки кроме явно перезаписанных
- Случайно Сотрудник.СтатьяЗарплата совпадал со статьёй из ТЧ.РаспределениеКазна для эталонных 21 пар

Решение: в начале теста **удалять** существующую ВКассу для чистого старта. Это обнажает реальное поведение процедуры с/без новых параметров.

### Урок №5: А_Привилегированный доступен из Python COM

CommonModule `А_Привилегированный` имеет `ExternalConnection=true`, поэтому метод `ОбеспечитьПодразделенияОрганизацийПоПодразделению` вызывается из Python COM напрямую через `getattr(erp, "А_Привилегированный")` (Cyrillic атрибут — нужен `getattr`, прямой `erp.А_Привилегированный` через pywin32 работает не всегда). Удобно для построения эталонного словаря в тестах.

### Урок №6: WARN-строки в А_Расшифровке — это норма

Тест `statyaddc` показал 42 строки с пустой СтатьейДДС (Сотрудник.Главный_офис) — для них нет матча в ТЧ.РаспределениеКазна. Это **по дизайну** (опция "Оставить пусто + WARN" из спеки) — РаспределениеКазна не покрывает всех сотрудников Ф2 (только тех, кому реально выплачивали через кассу). Не баг.
