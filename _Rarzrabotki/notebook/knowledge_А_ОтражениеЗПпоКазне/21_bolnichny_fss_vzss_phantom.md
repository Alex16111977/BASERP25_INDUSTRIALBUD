## TL;DR

- **Симптом:** Григоренко О.М. (ІНДАСТРІАЛБУД) — А_ВзСС **Форма1** фев.2026: Приход **2 585,83 (GROSS)**,
  Расход (выплата) **1 991,09 (NET)** → фантомный остаток **594,74** (= НДФЛ 465,45 + ВЗ 129,29).
- **Гипотеза прома H1 уточнена и ЧАСТИЧНО опровергнута:** фантом возникает **НЕ у всех** больничных-ФСС,
  а ТОЛЬКО когда **`GROSSбух(661) < НДФЛ_total`** — у ФЛ нет (или мало) регулярной ЗП на 661, и весь
  официальный доход за месяц — это больничный ФСС на 663. **Эмпирически: 1 из 3** больничных-ФСС ФЛ (только Григоренко).
- **Корень:** Op2a `_ОтрЗП_СоздатьСтрокиNETФЛ_Новый` строит NET `«Зарплата»Ф1 = max(0, GROSSбух − НДФЛ)`
  (clamp к 0, **ObjectModule.bsl:2068**) **и** gross-up `«Удержание» = НДФЛ`. При `GROSSбух=0` строка
  «Зарплата»Ф1 клампится к 0 → больничный НДФЛ **никем не поглощается**, а **осиротевший** gross-up
  «Удержание»(+594,74) гасит НачисленныйНДФЛ(−594,74) в группировке регистра → больничный GROSS остаётся
  Приходом. Op4 step-4 (`_ОтрЗП_ЗаполнитьБольничныеИзФондов`, **ObjectModule.bsl:1284-1296**) чинит ровно
  этот случай для `0 < ГБ < НД`, но имеет гард **`ГБ > 0`** (line 1291) → **пропускает чистый ФСС-больничный (ГБ=0)**.

## 2. Механизм (реплика группировки А_ВзСС.ManagerModule.ЗаполнитьИзОтраженияЗП до копейки)

Регистр строит per `(Орг, Подр, ФЛ, ФормаPL, ОргБух)`: `Σ[ +НачЗарплата(Налог=пусто, кроме 4 ВидОп)
− НачисленныйНДФЛ − УдержаннаяЗарплата ]`; ВидДв=Приход при Σ>0 (`ManagerModule.bsl:97-170`).

**Григоренко, ОЗФУ 000Ц-000002, Форма1:**

| Строка ТЧ | Сумма | → в А_ВзСС |
|---|---:|---:|
| «Удержание с зарплаты производств.» (Налог пусто, А_ЭтоУдержание) | 594,74 | **+594,74** |
| «Больничные за счет ФСС» (Налог пусто) | 2 585,83 | **+2 585,83** |
| «Начисления на зарплату» (ЕСВ, Налог=ЕСТЬ, Сумма=0) | 0 | 0 (не в движ) |
| НачисленныйНДФЛ (НДФЛ 465,45 + ВЗ 129,29) | 594,74 | **−594,74** |
| УдержаннаяЗарплата | — | 0 строк |
| **Σ группы (Производство, Ф1) = ПРИХОД** | | **2 585,83** |

`«Удержание»(+594,74)` **точно гасит** `НачисленныйНДФЛ(−594,74)` → больничный GROSS не уменьшается. Расход (выплата СписаниеБезнал NET) = 1 991,09 → **остаток 594,74**.

## 3. Причина — clamp + осиротевший gross-up (diag п.3)

| ФЛ | GROSSбух(661) | НДФЛ | больнФСС(663) | «Зарплата»Ф1 NET | clamp? | фантом |
|---|---:|---:|---:|---:|:--:|---:|
| Хурсін Тарас | 33 911,05 | 8 727,83 | 4 036,05 | **25 183,22** (=33911−8728) | нет | **0,00** ✓ |
| Ямковий В.Ю. | 18 000,00 | 4 563,12 | 1 839,67 | **13 436,88** (=18000−4563) | нет | **0,00** ✓ |
| **Григоренко** | **0,00** | 594,74 | 2 585,83 | **0,00** (clamp) | **ДА** | **594,74** ❌ |

- Хурсін/Ямковий: `«Зарплата»Ф1 NET = GROSSбух − НДФЛ_total` поглощает больничный НДФЛ → больничный GROSS
  добавляется, а его НДФЛ уже вычтен в «Зарплате» → нетто-эффект больничного = NET → баланс 0.
- Григоренко: `GROSSбух=0 < НДФЛ` → `Ф1Сумма = max(0, 0 − 594,74) = 0` (**clamp, line 2068**) → потеря
  вычитания НДФЛ; gross-up «Удержание» остался (Op2a создаёт его при `НДФЛДляФЛ≠0`) и осиротел → гасит НачисленныйНДФЛ.

> **Важно:** GROSS-модель больничного сама по себе КОРРЕКТНА (А_ВзСС сам вычитает НачисленныйНДФЛ →
> take-home, см. комментарий ObjectModule.bsl:1331-1334). Баг — **осиротевший** gross-up «Удержание», который
> съедает НДФЛ ДО того, как он успеет уменьшить больничный. Это случается, когда «Зарплата»Ф1 клампится к 0.

## 4. Реализованный фикс (Вариант A)

**Locus:** `_ОтрЗП_ЗаполнитьБольничныеИзФондов` Op4 step-4 (`ObjectModule.bsl:1291-1300`).

**Принцип:** gross-up «Удержание» не должен превышать NET-базу «Зарплаты», которую он грос-апит. При clamp
(`GROSSбух ≤ НДФЛ`) «Удержание» ограничено до `Макс(0, GROSSбух)`. Step-4 уже это делал для `0<ГБ<НД`,
но гард `ГБ > 0` пропускал `ГБ = 0` (чистый ФСС-больничный без 661, как Григоренко).

```diff
- Если ГБ > 0 И ГБ < НД И УдержРядокПоФЛ[ФЛ] <> Неопределено Тогда
+ Если ГБ < НД И УдержРядокПоФЛ[ФЛ] <> Неопределено Тогда
      Р = УдержРядокПоФЛ[ФЛ];
-     Р.Сумма = ГБ;
+     Р.Сумма = Макс(0, ГБ);
      Р.СпособОтраженияЗарплатыВБухучете = СпособЗП;
  КонецЕсли;
```

Для Григоренко: «Удержание»→«первые5дней»=0 → осиротевший gross-up обнуляется → НачисленныйНДФЛ напрямую
гасит больничный GROSS → Приход = 2585,83 − 594,74 = **1991,09 = NET** ✓. `0<ГБ<НД` — без изменений
(`Макс(0,ГБ)=ГБ`); `ГБ≥НД` (Хурсін/Ямковий) — не входят; `ГБ<0` — теперь `Макс(0,ГБ)=0` (раньше пропускался).

> Вариант B (класть больничный сразу NET в step-5 + удалять «Удержание») — отвергнут: трогает больше,
> а Вариант A переиспользует существующий step-4 механизм (консистентность с `0<ГБ<НД`).
