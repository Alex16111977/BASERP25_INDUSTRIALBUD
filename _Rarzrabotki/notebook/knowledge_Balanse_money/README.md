# knowledge_Balanse_money

> **База знаний** по задаче исследования и устранения **Расхождение=Истина** в
> `РегистрСведений.А_ОтчётБаланс_Свод` по источникам **Денежные средства**
> (Безналичные / Наличные / Подотчётные / **В пути**) для ТОВ ІНДАСТРІАЛБУД.
>
> Контролируемая процедура: `Документ.А_ФинРез_Баланс.ObjectModule.bsl` →
> `Функция Свод_ДенежныеСредства(СтруктураШапки, Отказ)`, строки 621-845.
>
> **Эталон расшифровки:** штатный отчёт `Отчёт.УправленческийБаланс` +
> вызываемые им детальные отчёты `Отчёт.ВедомостьПоДенежнымСредствам` /
> `Отчёт.ВедомостьПоДенежнымСредствамУПодотчетныхЛиц`.

## 🎯 Статус: 🔴 ОТКРЫТО (стартовая инвентаризация 2026-05-23)

Из CSV-выгрузки пользователя за период декабрь 2025 — апрель 2026:
- ~100 строк Расхождение=Истина по статьям «Денежные средства *»
- Главные узлы: **Глобино-2 / в пути** (−17 М), **КГ Подгорцы / в пути** (−19,8 М), **Строительство / в пути** (+29,4 М), **ЦО / безналичные** (±19,2 М), **(пусто) / безналичные** (+19,2 М)

См. [`FINDINGS.md`](FINDINGS.md) — стартовый детектив.

## 🚨 Главная архитектурная находка (БАГ в Свод_ДенежныеСредства)

В системе **4 регистра** для аналитики денег:

| # | `РегистрНакопления.*` | Аналитика | Статья ПВХ.СтатьиАктивовПассивов | В `Свод_ДенежныеСредства` |
|---|---|---|---|---|
| 1 | `ДенежныеСредстваБезналичные` | БанковскийСчет, Подразделение | «Денежные средства (безналичные)» | ✅ используется (BSL 686-693) |
| 2 | `ДенежныеСредстваНаличные` | Касса, Подразделение | «Денежные средства (наличные)» | ✅ используется (BSL 705-711) |
| 3 | `ДенежныеСредстваУПодотчетныхЛиц` | ПодотчётноеЛицо | «Денежные средства (у подотчётных лиц)» | ✅ используется (BSL 722-728) |
| 4 | **`ДенежныеСредстваВПути`** | **ВидПереводаДенежныхСредств, Получатель, Отправитель, Контрагент, Валюта** | «Денежные средства в пути» | ❌ **НЕ используется — БАГ** |

(плюс `ДенежныеСредстваВКассахККМ` для ККМ-операций — отдельный нишевый случай).

### Доказательство существования регистра №4

В шаблоне `Reports/ВедомостьПоДенежнымСредствам/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml` стр. 1754:
```sql
РегистрНакопления.ДенежныеСредстваВПути.ОстаткиИОбороты(, , Авто, , {(Организация).*, (ВидПереводаДенежныхСредств), (Получатель).*, (Отправитель).*, (Контрагент).*, (Валюта).*})
```

Штатный отчёт **ВедомостьПоДенежнымСредствам** этот регистр читает и показывает расшифровку. Но `Свод_ДенежныеСредства` (BSL 621-845) этого регистра **не вызывает** — соответствующего блока `ОБЪЕДИНИТЬ ВСЕ ... РегистрНакопления.ДенежныеСредстваВПути.ОстаткиИОбороты ...` в `втДС` НЕТ.

### Эффект бага

`втПАП` фильтруется по `Источник В (&МассивИст)` где `МассивИст` ВКЛЮЧАЕТ `ДенежныеСредстваВПути` (стр. 625). Поэтому любая запись `ПрочиеАктивыПассивы` с `Источник=ДенежныеСредстваВПути` попадает в `втПАП`, но НЕ имеет парной строки в `втДССт` → `Δ = ПАП − 0` → автоматический плуг **Расхождение=Истина**.

Из выгрузки пользователя видно ~14 подразделений с плугом по статье «Денежные средства в пути» — суммарно ΣABS ≈ 73 М UAH к апрелю 2026.

### Фикс (требует дополнительной аналитики маппинга)

⚠️ **АРХИТЕКТУРНАЯ ДЕТАЛЬ:** В регистре `РН.ДенежныеСредстваВПути` **НЕТ измерения Подразделение**. Измерения: Организация, ВидПереводаДенежныхСредств, Получатель, Отправитель, Контрагент, Валюта.

Поэтому простое добавление ветки UNION ALL с группировкой по Подразделению **невозможно** — его в регистре нет.

**Эмпирическое подтверждение** (скрипт `03_drill_vputi.py 2025-12`):
- ПАП итого КМ за декабрь по статье «В пути»: **25 000 UAH** (net по 19 подразделениям)
- РН.ВПути итого КМ за декабрь: **25 000 UAH** (агрегат)
- **Итого Δ = 0**, но per-Подразделение в ПАП: Глобино-2 −2 650 000, Строительство +4 959 278, Подгорцы +661 000, и т.д.

ПАП пишет per-Подразделение (через документ-источник), регистр.ВПути — глобально без подразделения. Чтобы свод сошёлся, нужен **маппинг Получатель/Отправитель → Подразделение** (через реквизит подразделения в Кассе/БанковскомСчёте).

### Подходы

| # | Подход | Сложность | Эффект |
|---:|---|---|---|
| **A** | Добавить в `втДС` ветку с маппингом: `ВЫБОР КОГДА Получатель.Подразделение ЕСТЬNULL ТОГДА Отправитель.Подразделение ИНАЧЕ Получатель.Подразделение КОНЕЦ` | средняя | устраняет per-Подр расхождение, требует тщательного выбора Получатель vs Отправитель в зависимости от ВидПеревода |
| B | Добавить ветку без Подразделения (всё в `ПустаяСсылка`) — тогда per-Подр расхождение в ПАП vs Свод сохранится | низкая | НЕ решает проблему — плуги остаются на per-Подр уровне |
| C | Tolerable — оставить плуги. Net=0 на итог по организации, но per-Подр баланс некорректен | 0 | плохо для бюджетирования по подразделениям |
| D | Изменить логику записи ПАП — писать «в пути» без подразделения (Подразделение=ПустаяСсылка) — тогда совпадёт с регистром | средняя | ломает все исторические данные и отчёты per-Подр |

**Рекомендация:** Подход **A** с маппингом — рабочий путь. Логику взять из штатного отчёта `ВедомостьПоДенежнымСредствам` где Получатель/Отправитель идут с раскрытием реквизитов `*.Подразделение`.
