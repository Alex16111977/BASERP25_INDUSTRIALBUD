## 1. Архитектурные особенности денег vs клиентов

### 1.1 Ключ группировки — НЕ ДокументРегистратор

В отличие от РСКПС/РСППС (memory `feedback_balans_live_code_source_of_truth`),
регистры **ДенежныеСредства*** имеют:
- `Регистратор` = сам первичный документ (ПКО/РКО/ПлатежноеПоручение/...)
- НЕТ реквизита `ДокументРегистратор`
- Ключ группировки в `Свод_ДенежныеСредства`: **(Орг, Подр, Объект)** где Объект = БанковскийСчет / Касса / ПодотчётноеЛицо

```python
# Сверка ПАП vs ДенежныеСредстваБезналичные:
# Ключ — БанковскийСчет, НЕ ДокументРегистратор
```

### 1.2 «Денежные средства в пути» — БЕЗ источника-регистра

В `Свод_ДенежныеСредства` (BSL стр. 621-845):
- `втДС` имеет ТРИ ветки UNION ALL: Безналичные / Наличные / Подотчётные
- ВЕТКИ "В ПУТИ" НЕТ
- При этом `втПАП` фильтруется по `МассивИст` который ВКЛЮЧАЕТ "Денежные средства в пути"

➡️ Любая запись `ПАП.ВПути` → плуг `Расхождение=Истина` с `Δ = ПАП - 0`.

См. memory `balans_vputi_no_analitika_bydesign` — в типовом BAS ERP "В пути" by-design не имеет аналитики.

### 1.3 «Подразделение = ПустаяСсылка» как валидная группа

В отличие от расчётов с партнёрами, в денежных регистрах:
- Банковский счёт ЦО может быть БЕЗ подразделения (`Подразделение = ПустаяСсылка`)
- ПАП-проводка может писаться по подразделению ЦО (`Подразделение = "0Ц-000007"`)
- Это даёт **зеркальные плуги** ±X на (ЦО / Подр-пусто)

**Скрипт должен обрабатывать оба варианта** (`ЕСТЬNULL(Подразделение, ПустаяСсылка) КАК Подр` — как в формуле свода).

## 2. SQL-паттерн сверки ПАП vs Регистр.Денежные*

```sql
// Денежные (Безналичные) per (Подр, БанковскийСчет)
ВЫБРАТЬ
    ЕСТЬNULL(Б.Подразделение, ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)) КАК Подр,
    Б.БанковскийСчет КАК БС,
    СУММА(Б.СуммаНачальныйОстаток) КАК НО,
    СУММА(Б.СуммаКонечныйОстаток) КАК КО
ИЗ РегистрНакопления.ДенежныеСредстваБезналичные.ОстаткиИОбороты(
    &НачМес, &КонМес, , , Организация = &Орг) КАК Б
СГРУППИРОВАТЬ ПО ЕСТЬNULL(Б.Подразделение, ПустаяСсылка), Б.БанковскийСчет

// ПАП.Безнал per (Подр) — БанковскийСчет НЕТ в ПАП
ВЫБРАТЬ
    ЕСТЬNULL(Т.Подразделение, ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)) КАК Подр,
    СУММА(ВЫБОР КОГДА Т.Период < &НачМес ТОГДА signed ИНАЧЕ 0 КОНЕЦ) КАК НО,
    СУММА(signed) КАК КО
ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК Т
ГДЕ Т.Организация = &Орг И Т.Период <= &КонМес
    И Т.Источник = ЗНАЧЕНИЕ(Перечисление.ИсточникиУправленческогоБаланса.ДенежныеСредстваБезналичные)
СГРУППИРОВАТЬ ПО ЕСТЬNULL(Т.Подразделение, ПустаяСсылка)
```

## 3. Антипаттерны (НЕ ПОВТОРЯТЬ)

| # | Антипаттерн | Правильно |
|---|---|---|
| 1 | `ДокументРегистратор` как ключ сверки | Для денег — `БанковскийСчет/Касса/ПодотчётноеЛицо` |
| 2 | Передать "Денежные средства в пути" как параметр для поиска источника-регистра | Регистра нет; искать причину в ПАП (какой документ пишет проводку) |
| 3 | Игнорировать `Подразделение = ПустаяСсылка` | Обрабатывать через `ЕСТЬNULL(..., ПустаяСсылка)` |
| 4 | Перепроведение всех денежных документов через COM для устранения плуга | Деньги не имеют РегистраторРасчётов — но! Memory `feedback_com_repost_skips_registrator_raschetov` не относится напрямую. Однако смысл правки — не в перепроведении документов, а в исправлении ПОДРАЗДЕЛЕНИЯ в карточке банковского счёта/кассы |

## 4. Принципы для будущих сессий

1. **Сначала прочитать `SCRIPTS_CATALOG.md`** — взять готовый, не плодить дубли
2. **Источник истины — live BSL** (`Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl` стр. 621)
3. **Сверка** — `(Орг, Подр, Объект)`, не ДокументРегистратор
4. **Даты СЕРВЕРНО** через ДАТАВРЕМЯ в тексте запроса (memory `feedback_balans_etalon_period_serverside`)
5. **Использовать `_common.py`** (наследует утилиты от klient + добавляет refs для денег)
6. **"В пути" — архитектура,** не баг данных. Решать через выбор подхода A/B/C/D (см. README §A)
7. **Перед массовыми правками** — gate `32_verify_uprbalance_report.py` (если есть; иначе скопировать из klient)
