# Промт — Диагностика per-документ декабрь 2025 (Безнал + Налич)

## TL;DR

Найти **конкретные документы-регистраторы** за декабрь 2025 (ТОВ ІНДАСТРІАЛБУД) которые
формируют расхождение ПАП vs РН.ДенежныеСредстваБезналичные / РН.ДенежныеСредстваНаличные.

Расхождение происходит когда:
- **ПАП.Подр ≠ Регистр.Подр** (асимметрия группировки — главный кейс ЦО↔(пусто) ±19,2 М)
- **|ПАП.Σ − Регистр.Σ| > 0,01** (расхождение сумм)
- **ПАП есть, Регистра нет** (или наоборот)

Скрипт `diag_dec25_money_per_doc.py` — JOIN ПОЛНОЕ ПАП vs РН.* по `Регистратор`, агрегация per
`(Регистратор, Источник)`, фиксация `ПАП.Подр` и `Регистр.Подр` отдельно, выявление нарушителей.

## Алгоритм скрипта

### Шаг 1 — Соединение и резолв rfs

Через `_common.py`:
```python
erp = connect_erp()
refs = get_refs(erp)   # Орг, Ист_Безнал, Ист_Налич, ...
```

### Шаг 2 — Запрос ПАП per (Регистратор, Подр, Источник)

```sql
ВЫБРАТЬ
    Т.Регистратор КАК Регистратор,
    ЕСТЬNULL(Т.Подразделение, ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)) КАК Подр,
    Т.Источник КАК Источник,
    СУММА(ВЫБОР КОГДА Т.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
            ТОГДА Т.Сумма ИНАЧЕ -Т.Сумма КОНЕЦ) КАК ΣПАП
ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК Т
ГДЕ Т.Организация = &Орг
    И Т.Период >= ДАТАВРЕМЯ(2025,12,1,0,0,0)
    И Т.Период <= ДАТАВРЕМЯ(2025,12,31,23,59,59)
    И Т.Источник В (&Ист_Безнал, &Ист_Налич)
СГРУППИРОВАТЬ ПО Т.Регистратор, ЕСТЬNULL(Т.Подразделение, ...), Т.Источник
```

### Шаг 3 — Запрос Регистр.Безнал per (Регистратор, Подр, БС)

```sql
ВЫБРАТЬ
    Б.Регистратор КАК Регистратор,
    ЕСТЬNULL(Б.Подразделение, ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)) КАК Подр,
    Б.БанковскийСчет КАК БС,
    СУММА(ВЫБОР КОГДА Б.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
            ТОГДА Б.Сумма ИНАЧЕ -Б.Сумма КОНЕЦ) КАК ΣРег,
    "Безнал" КАК ТипРег
ИЗ РегистрНакопления.ДенежныеСредстваБезналичные КАК Б
ГДЕ Б.Организация = &Орг
    И Б.Период >= ДАТАВРЕМЯ(2025,12,1,0,0,0)
    И Б.Период <= ДАТАВРЕМЯ(2025,12,31,23,59,59)
СГРУППИРОВАТЬ ПО Б.Регистратор, ЕСТЬNULL(Б.Подразделение, ...), Б.БанковскийСчет
```

Аналогично для Налич (с `Б.Касса` вместо `Б.БанковскийСчет`, и `ТипРег = "Налич"`).

### Шаг 4 — JOIN в Python

Используем оба результата как dicts по ключу `Регистратор-UUID`. Для каждого Регистратор:
- Сложить все строки ПАП → set `pap_podrs`, Σ `ΣПАП`
- Сложить все строки Регистр → set `reg_podrs`, Σ `ΣРег`
- Определить `ТипНарушения`:
  - `ASYM_PODR` — `pap_podrs ≠ reg_podrs` и `|ΣПАП − ΣРег| < 0,01`
  - `DIFF_SUMM` — `|ΣПАП − ΣРег| > 0,01`
  - `MISSING_REG` — есть ПАП нет Регистра
  - `MISSING_PAP` — есть Регистр нет ПАП
  - `OK` — pap_podrs == reg_podrs и сумма совпадает (не выводить)

### Шаг 5 — CSV вывод

Колонки:
```
Регистратор | ТипДок | Дата | Номер | ПАП_Подр | Регистр_Подр | БС/Касса | ПАП_Σ | Регистр_Σ | ΔΣ | ТипНарушения
```

Сортировка: `|ΔΣ|` desc (или для ASYM_PODR — по `|ΣПАП|` desc).

### Шаг 6 — Сводка в консоль

```
Всего регистраторов нарушителей: N
  ASYM_PODR:   N1  (Σ ΣПАП = X)
  DIFF_SUMM:   N2  (Σ ΔΣ = Y)
  MISSING_REG: N3
  MISSING_PAP: N4
```

Также вывести **топ-10** по `|ΔΣ|` desc — кратко: тип/дата/номер/Σ.

## Антипаттерны

- ❌ JOIN по `(Регистратор, Подр)` — потеряем строки с разным Подр (это и есть искомое расхождение); JOIN только по `Регистратору + Источник`
- ❌ `ОстаткиИОбороты` — не даёт Регистратор; нужна прямая таблица регистра
- ❌ Daterange через `SetParameter(datetime)` без серверного `ДАТАВРЕМЯ` — memory `feedback_balans_etalon_period_serverside`
- ❌ Путать `ИстБезнал` (Перечисление.ИсточникиУправленческогоБаланса) с `ТипыДенежныхСредств` (другое перечисление)
- ❌ Использовать `Регистр.Период МЕЖДУ` — для прямой таблицы можно, но проверить что `Период` существует как поле в данном регистре (для РН.Безнал/Налич — да, есть)
- ❌ **`rec.Источник == refs["Ист_Безнал"]`** — COM-сравнение ссылок перечисления **ненадёжно** (даёт неверный результат → ложные MISSING_REG для всех 2306 записей в первом запуске). Использовать строковое сравнение через `S(rec.Источник) == S(refs["Ист_Безнал"])`

## Что делать с результатом

После получения CSV списка нарушителей:
1. **ASYM_PODR группа** — открыть карточки соответствующих БС/Касс. В большинстве случаев у БС/Кассы НЕ заполнено Подразделение, а в шапке документа Подр заполнен. Решение — **заполнить Подразделение в карточке БС/Кассы** (тогда регистр получит Подр и совпадёт с ПАП).
2. **DIFF_SUMM** — редкие кейсы где Σ разная: смотреть документ вручную (возможно битое движение).
3. **MISSING_REG/PAP** — документ пишет только в одну таблицу: подозрение на битое проведение или особую логику.

После точечных правок — массовое перепроведение проблемных документов через UI 1С Enterprise или COM.
