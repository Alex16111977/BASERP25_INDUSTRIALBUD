## Симптом

На депозитном счёте (`ТАСдепозитБудUA693395002610201537072000001`, март 2026) анализ документов даёт десятки строк «Списание безналичных ДС 000Ц-…» со статусом **«Переказ: документ не знайдено в Бух»**. Это НЕ ошибка данных — обработка не знает второй (входящий) вариант схемы перевода.

## Архитектура (проверена фактами на живых базах, пример 000Ц-000187)

Перевод между своими счетами отражается в базах по-разному. **Два зеркальных варианта**:

**Вариант A — исходящий (уже реализован в обработке, v3):**
BuhBud: один документ `СписаниеСРасчетногоСчета` (Дт 311-приёмник / Кт 311-источник), его UUID = UUID ERP-**Списания**. Парное ERP-Поступление создаётся подпиской; связь: `Поступление.А_СписаниеБезналичныхДенежныхСредств → Списание`.

**Вариант B — входящий/возврат с депозита (НЕ покрыт, его и чинить):**
BuhBud: один документ `ПоступлениеНаРасчетныйСчет` («Надходження», напр. 00DL-9066: Дт 311-текущий / Кт 313-депозит, 44 602 752,10), его **UUID = UUID ERP-Поступления** (a7f34d57-1649-11f1-8109-00155dce3d04). Парное **ERP-Списание (000Ц-000187, UUID 33bcb30a-2090-11f1-a2e6-8a1890236e3d) создаётся ЛОКАЛЬНО в ERP** — его UUID в Бух не существует **by design**.

**Механизм создания подчинённого Списания (вариант B):**
`ПодпискаНаСобытие А_ДоработкаДокументыПриЗаписи (OnWrite)` → `А_СобытияОбъектов.А_ДоработкаДокументыПриЗаписи` (диспетчер, строки ~1153) → `ПоступлениеБезналичныхДенежныхСредств_ПриЗаписи` (строки ~1106: если ХозОперация = `ПоступлениеДенежныхСредствСДругогоСчета`) → `А_Привилегированный.СоздатьСписаниеБезналичныхДенежныхСредствПоПоступлениеБезналичныхДенежныхСредств(Ссылка)` (строки ~598-680): создаёт/восстанавливает Списание с тем же временем/суммой, зеркальными счетами (БанковскийСчет = БанковскийСчетОтправитель Поступления, Получатель = БанковскийСчет Поступления), ХозОп `ПеречислениеДенежныхСредствНаДругойСчет`, автономер (отсюда «000Ц-»), `Записать(Проведение)`. Анти-цикл — гард по `А_ПоступлениеБезналичныхДенежныхСредств`/`А_СписаниеБезналичныхДенежныхСредств`.

**Связь хранится ТОЛЬКО в одну сторону:** `Списание.А_ПоступлениеБезналичныхДенежныхСредств → Поступление` (единственный реквизит Списания типа DocumentRef.ПоступлениеБезналичныхДенежныхСредств, проверено перебором всех 87 реквизитов). Обратный `Поступление.А_СписаниеБезналичныхДенежныхСредств` в варианте B **ПУСТ** (он заполняется только в варианте A).

## Что сделать в ObjectModule.bsl обработки

1. **Запрос Фазы 2** (`АнализДокументов_ПоСчету`): добавить колонку

   (рядом с существующей `ПарноеСписание`). **Rule #-1: запрос сначала Python COM тестом.**

2. **`ОбробитиДокументиЕРП`, ветка `ЭтоСписаниеПеревод`:** порядок выбора UUID Бух-документа:
   - если `ЗначениеЗаполнено(СтрДок.ПарноеПоступление)` → `UIDБухПеревода = Строка(СтрДок.ПарноеПоступление.УникальныйИдентификатор())` (вариант B — Бух-документ «Надходження» имеет UUID Поступления); `НС.UIDДокумента` оставить = UUID Списания;
   - иначе как сейчас: UUID соответствия / собственный UUID Списания (вариант A).
   Сверка суммы уже корректна: `ПроверитьПереводВBuhBud` считает пер-счётный поток Дт(X)−Кт(X) через `ДвиженияССубконто` — для депозитного X=313-счёт у Надходження Кт-поток = −44 602 752,10 = СуммаЕРП Списания → «Переказ: синхронно».
   В `ПроверитьПереводВBuhBud` тип-фоллбек расширить: если соответствие по UID не найдено, пробовать тип `ПоступлениеНаРасчетныйСчет` (сейчас фоллбек жёстко `СписаниеСРасчетногоСчета`) — лучше: фоллбек-список из двух типов, найден — тот и берём.

3. **Обратная проверка `ПроверитьДокументыBuhBud`:** в карту покрытых UUID добавлять `ПарноеПоступление` Списаний (симметрично существующему `ПарноеСписание` Поступлений):
   `Если ЗначениеЗаполнено(СтрДок.ПарноеПоступление) Тогда масUIDерп.Вставить(ВРег(Строка(СтрДок.ПарноеПоступление.УникальныйИдентификатор())), Истина); КонецЕсли;`
   — иначе Бух-«Надходження» на депозитном счёте даёт ложную строку «Переказ: вхідна сторона в ЕРП не зв'язана».

4. Статусы/действия — существующие («Переказ: синхронно» серым, расхождение суммы — честный статус без действия).
