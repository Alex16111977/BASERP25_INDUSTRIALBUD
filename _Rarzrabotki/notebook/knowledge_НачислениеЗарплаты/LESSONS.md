# LESSONS — грабли knowledge_НачислениеЗарплаты

Антипаттерны и неочевидные факты, найденные при разборе. Для повторного применения.

---

## 1. Не доверять описанию задачи — проверять данными (Iron Law)

Промт утверждал «у Григоренко Σ Казны = −240.69, оклада нет», ОЗФУ-спека — «Σ СуммаНачисления = 9242.31, оклад 8809 есть».
**Противоречие.** Разрешилось только прогоном COM: это **ДВА разных Григоренко** (Олександр — больничный;
Ілля — оклад). Всегда снимать baseline из БД, а не строить фикс на тексте.

## 2. НачислениеЗарплаты ≠ ОЗФУ по регистрам — НЕ двойной счёт

Соблазн: «оба подчинённых пишут больничный → удвоится». Факт: `НачислениеЗарплаты` **не регистратор**
`А_ВзаиморасчетыССотрудниками` (0 движений). Баланс держит только ОЗФУ. Всегда проверять список
регистраторов регистра (`get_metadata_structure`) и эмпирически `КОЛИЧЕСТВО(*) ГДЕ Регистратор=&Док`.

## 3. «Оклад (Зарплата)» и «Штраф (упр)» — дубль кода `ОКЛН `

Оба вида расчёта имеют ОДИН код. Код ищет их `НайтиПоНаименованию`, не `НайтиПоКоду`. При анализе
строк различать по `Начисление.Наименование`, не по коду.

## 4. Положительный «Штраф (упр)» — это управ-сторно, не штраф

`Штраф (упр).Результат = −УдержанияУпр.Сумма`. Если `УдержанияУпр.Сумма < 0` (ручная правка родителя),
выходит **положительный** «штраф» — так в управленческий слой «вписали» больничный, которого нет в
`НачисленияУпр` (случай Горбачовой: +8771.70 = её ФСС). Не принимать за ошибку расчёта — это «хак-протечка».

## 5. Маркер больничного «за счёт фондов» = `Σ НачисленияБухЗасчетФондов > 0`

Точно даёт нужные 3 ФЛ и НЕ цепляет управленческих с лёгким больничным (Сніжко: лікарняні 2260.44, но
управ-сумма доминирует, ФСС=0). Не использовать «есть больничный вид в `НачисленияБух`» как маркер — он
ловит лишних.

## 6. Тройная сверка «правильной» суммы

`bukhGROSS (= Σ НачисленияБух + Σ ФСС) == ОЗФУ Форма1`, а `take-home (= bukhGROSS − НДФЛ) == нетто А_ВзСС`
от ОЗФУ. Три независимых источника совпали до копейки — это и есть якорь приёмки. Декрет (Горбачова):
НДФЛ=0 → take-home = GROSS.

## 7. Регрессию мерить по СОБСТВЕННЫМ ТЧ/движениям документа

Для НачислениеЗарплаты регресс-критерий — его `Начисления/Удержания/НДФЛ/ВзносыФОТ` и `ЗарплатаКВыплате`,
а НЕ `А_ВзСС` (это регистр ОЗФУ). Изменись ровно 3 ФЛ; остальные ~187 — byte-identical (тест A3).

## 8. main-config vs worktree РАЗЛИЧАЮТСЯ — править main, не делать cp worktree→main

В main-config есть ОЗФУ-фикс (`_ОтрЗП_ЗаполнитьБольничныеИзФондов`), в worktree `goofy-chaplygin` — НЕТ.
COM/Designer грузит из main-config. `cp worktree→main` затрёт ОЗФУ-фикс. Правки — строго в main-config;
git синхронизировать отдельно и аккуратно.

## 9. Загрузка конфигурации блокируется открытым Конфигуратором

`LoadConfigFromFiles` падает «Ошибка блокировки информационной базы для конфигурирования», если открыт
Конфигуратор (даже чужая сессия). Программно его закрывать нельзя (риск потери несохранённого). Это внешний
блокер — освобождает пользователь. COM-подключения (V83.COMConnector) этот лок НЕ держат (они enterprise, не Designer).

## 10. COM-перезапись НачислениеЗарплаты надёжна (в отличие от взаиморасчётных документов)

`НачислениеЗарплаты` — не документ новой архитектуры взаиморасчётов, он не теряет `РегистраторРасчётов`.
Поэтому смок-перезапись 1 документа через COM корректна. Но историю перепроводит пользователь в UI.

## 11. Python COM: строки/перечисления/UUID

- Числа из `Выгрузить()` парсить через `float(S(x).replace('\xa0','').replace(' ','').replace(',','.'))`.
- Ключ ФЛ — `erp.XMLСтрока(ref)` (стабильный UUID), имя — `S(ref)`. `Строка(UUID)` не работает.
- Перечисления сравнивать в ЗАПРОСЕ через `ЗНАЧЕНИЕ(Перечисление.ТипыНалогов.НДФЛ)`, не в Python.
- Кириллица в `python -c` портится — писать скрипт в файл, запускать `python file.py`.

## 12. Декрет не облагается НДФЛ — риск пересчёта при проведении

У Горбачовой `НалогиБухгалтерия.СуммаНДФЛ=0`. После установки GROSS-«оклада» 17543.40 типовое проведение
НЕ должно начислить 18% НДФЛ. Это нужно проверить в смоке (`ЗарплатаКВыплате`=17543.40). Если проведение
пересчитывает НДФЛ с начислений — потребуется спец-обработка декрета.
