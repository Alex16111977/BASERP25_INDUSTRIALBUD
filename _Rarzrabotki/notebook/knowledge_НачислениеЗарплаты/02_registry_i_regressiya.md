# 02. Регистры-потребители и критерий регрессии

**Решающий факт для дизайна фикса и регрессии:** надо точно знать, КАКИЕ регистры питает
`НачислениеЗарплаты`, чтобы (а) не бояться двойного счёта с ОЗФУ и (б) правильно мерить регрессию.

---

## Кто питает `А_ВзаиморасчетыССотрудниками` (баланс)

Список регистраторов регистра (из метаданных `РегистрНакопления.А_ВзаиморасчетыССотрудниками`):

```
РасходныйКассовыйОрдер, ПриходныйКассовыйОрдер, СписаниеБезналичныхДенежныхСредств,
ОтражениеЗарплатыВФинансовомУчете (ОЗФУ),  ← вот он
А_ПередачаНачисленийМеждуПодразделениями, НачальнаяЗадолженностьПоЗарплате,
ПоступлениеБезналичныхДенежныхСредств
```

> 🟢 **`Документ.НачислениеЗарплаты` в этом списке ОТСУТСТВУЕТ.**
> Эмпирически (контрольный пример 000Ц-000005):
> - ОЗФУ `000Ц-000001` → А_ВзСС: **555 движений**
> - НачислениеЗарплаты `000Ц-000005` → А_ВзСС: **0 движений**

**Вывод:** баланс взаиморасчётов держит **ОЗФУ** (уже починен, коммит `e0fdcb45a`).
Дефект «Оклад −240.69» в НачислениеЗарплаты **НЕ портит баланс** и **не создаёт двойного счёта** с ОЗФУ.

---

## Что питает `НачислениеЗарплаты`

Эмпирически (Регистратор = 000Ц-000005):

| Регистр | Тип | Движений | Что это |
|---|---|---:|---|
| `ЗарплатаКВыплате` | НакопР | **524** | Сколько выплатить каждому ФЛ (ресурс `СуммаКВыплате`). Нетто-приход. |
| `РасчетыНалогоплательщиковСБюджетомПоНДФЛ` | НакопР | 342 | Расчёты по НДФЛ |
| `ИсчисленныйНДФЛ` | НакопР | 342 | Исчисленный НДФЛ |

`ЗарплатаКВыплате`: измерения `Организация, ФизическоеЛицо, Сотрудник, Подразделение,
СтатьяФинансирования, СтатьяРасходов, ПериодВзаиморасчетов, ДокументОснование, ГруппаУчетаНачислений`;
ресурс `СуммаКВыплате`; `НачислениеЗарплаты` — регистратор.

> 🔴 **Где дефект «Оклад −240.69» реально вредит:** расчётный листок сотрудника, база НДФЛ/ЕСВ
> и `ЗарплатаКВыплате`. У Григоренко при «Оклад» = −240.69 и НДФЛ 1235.24 выходит **отрицательная
> сумма к выплате** — бессмыслица для бухгалтера, хотя баланс и не страдает.

## Связь «правильных» сумм между документами (тройная сверка)

Для больничного ФЛ все три источника сходятся до копейки:

```
bukhGROSS = Σ НачисленияБух + Σ НачисленияБухЗасчетФондов     (родитель, бухгалтерия)
          = ОЗФУ Форма1 (Σ НачисленнаяЗарплатаИВзносыПоФизлицам, ФормаPL=Форма1)
take-home = bukhGROSS − НДФЛ
          = нетто А_ВзаиморасчетыССотрудниками (Приход−Расход) от регистратора ОЗФУ
```

Контрольный пример:

| ФЛ | bukhGROSS (=ОЗФУ Ф1) | НДФЛ+ВС | take-home (=А_ВзСС нетто = цель ЗарплатаКВыплате) |
|---|---:|---:|---:|
| Григоренко Олександр | 5370.57 | 1235.24 | **4135.33** |
| Горбачова Лариса (декрет) | 17543.40 | 0 (декрет не облагается) | 17543.40 |
| Ямковий Володимир | 13923.97 | 3202.51 | **10721.46** |

## Критерий регрессии для фикса НачислениеЗарплаты

> ⚠️ Регрессию мерить по **СОБСТВЕННЫМ ТЧ/движениям НачислениеЗарплаты**, а НЕ по А_ВзСС (это регистр ОЗФУ).

1. **A1 (нет мусора):** в `НЗ.Начисления` нет ни одной отрицательной строки с видом ≠ «Штраф (упр)».
2. **A2 (GROSS):** для каждого ФЛ с `ФСС>0`: `Σ НЗ.Начисления (все виды) == bukhGROSS` (±0.01).
3. **A3 (нулевая регрессия):** множество ФЛ, у кого изменилась запись `(nz_oklad, nz_shtraf, nz_total)`,
   == множество ФЛ с `ФСС>0` (ровно 3). Остальные ~187 ФЛ — byte-identical.
4. **Якорь выплат:** после смока `ЗарплатаКВыплате` нетто по 3 больничным == take-home (4135.33 / 17543.40 / 10721.46).

Тесты: `test_nz_fix_verify.py` (A1/A2/A3, read-only) + `test_nz_smoke_green.py` (перезапись + якорь выплат).

> ⚠️ **Риск для декрета (проверить в смоке):** при перепроведении типовая логика НачислениеЗарплаты
> НЕ должна пересчитывать НДФЛ с GROSS-«оклада» Горбачовой (17543.40 × 18%). Должна использовать
> заполненную ТЧ `НДФЛ` (там 0 для декрета). Если пересчитает — выплата Горбачовой упадёт → смок поймает (A2/якорь).
