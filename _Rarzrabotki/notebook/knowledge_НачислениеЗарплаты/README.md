# knowledge_НачислениеЗарплаты

База знаний по подчинённому документу **`Документ.НачислениеЗарплаты`**, который создаётся из
`Документ.А_ОтражениеЗПпоКазне` процедурой **`СоздатьДокументНачисления()`**, и по дефекту
«больничный/плуг» в табличной части `Начисления`.

- **Организация:** ТОВ «ІНДАСТРІАЛБУД» (UUID own-org см. memory `own_organization_edrpou`)
- **База:** BaseERP (`Srvr="localhost";Ref="BaseERP";Usr="Администратор";Pwd="24043"`)
- **Контрольный пример:** `НачислениеЗарплаты 000Ц-000005 от 31.01.2026` (родитель `А_ОтражениеЗПпоКазне 000000002`, ОЗФУ-брат `000Ц-000001`)
- **Модуль с логикой:** `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`

## TL;DR (60 секунд)

**Что за документ.** `НачислениеЗарплаты` — один из ДВУХ подчинённых, которые `А_ОтражениеЗПпоКазне`
создаёт по Find-Or-Create (реквизит `А_ДокОтражениеЗПпоКазне`):
1. **ОЗФУ** = `ОтражениеЗарплатыВФинансовомУчете` (баланс, питает `А_ВзаиморасчетыССотрудниками`) — **уже починен** (коммит `e0fdcb45a`).
2. **НачислениеЗарплаты** = типовой расчётный документ (питает `ЗарплатаКВыплате`, `ИсчисленныйНДФЛ`).

**Дефект.** Для сотрудников БЕЗ управленческого начисления (`НачисленияУпр`) «Оклад (Зарплата)»
берётся из Казны (`РаспределениеКазна.СуммаНачисления`), а НЕ из бухгалтерии. У чисто-больничных
это даёт мусор: у **Григоренко Олександра** Казна на «Производство» = **−240.69** → отрицательный «Оклад»;
а больничный из бухгалтерии (994.55 первые-5-дней + 4376.02 ФСС = **5370.57**) вообще не читается.

**Радиус.** Ровно **3 ФЛ** с больничным «за счёт фондов» (`НачисленияБухЗасчетФондов > 0`):
Григоренко Олександр, Горбачова Лариса (декрет), Ямковий Володимир. Остальные ~187 — корректны by-design.

**Фикс (зеркало ОЗФУ).** Процедура `_НЗ_НормалізуватиБольничные`: для ФЛ с ФСС>0 итог «Оклада» =
`Σ НачисленияБух + Σ НачисленияБухЗасчетФондов` (bukhGROSS), разнос по подразделению Казны;
плуг-«Оклад» и штраф-хак сносятся. Net Горбачовой инвариантен; Григоренко/Ямковий выправляются.
