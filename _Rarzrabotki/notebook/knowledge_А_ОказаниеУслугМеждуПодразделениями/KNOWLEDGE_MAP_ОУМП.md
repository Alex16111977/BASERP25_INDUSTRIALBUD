# KNOWLEDGE MAP — Документ `А_ОказаниеУслугМеждуПодразделениями` (ОУМП)

> **Назначение:** on-disk база знаний по кастомному документу
> `Документ.А_ОказаниеУслугМеждуПодразделениями` (BAS ERP 2.5 INDUSTRIALBUD).
> Документ — **оркестратор**: сам он не делает ни одного движения по регистрам, а создаёт и
> связывает другие документы (реализации, приобретения, оплаты) и разносит затраты внешней
> закупки по подразделениям-потребителям.
>
> Структура папки повторяет `knowledge_А_ПередачаНачисленийМеждуПодразделениями/` (ПНМП).
> Это **другой** документ: ПНМП переносит обязательства по ЗП, ОУМП — услуги и деньги между
> подразделениями. Общего кода у них нет.
>
> Для разработчика/инженера 1С. **Прочитать первым.**

## TL;DR (за 60 секунд)

1. **Что это.** Документ фиксирует оплату внешнему поставщику и раскладывает её по
   подразделениям-потребителям. Сам движений не делает: его работа — родить подчинённые
   документы (реализации/приобретения между подразделениями, оплаты) и связать акт поставщика
   с распределением затрат.
2. **Откуда берётся.** Автоматически при записи платежа: подписка на `ПриЗаписи`
   `СписаниеБезналичныхДенежныхСредств` вызывает `СоздатьДокументОказаниеУслугМеждуПодразделениямиПоРаспределению`,
   которая находит-или-создаёт документ по реквизиту `ДенежныйДокумент`, перезаливает
   `А_Распределение` из платежа и **сбрасывает `А_Обработан = Ложь`**. Второй создатель —
   `А_АрендаТехники`. Подробно: [[oump_zhiznennyy_cikl]].
3. **Гарды.** `ОбновитьОказаниеУслугМеждуПодразделениямиПослеОбмена()` (вызывается первой строкой
   `ПередЗаписью`) выходит по `А_ВведенВЕРП ИЛИ Закрытый ИЛИ Проверил`, затем по `А_Обработан`.
   Значит **`Закрытый` — не отметка, а выключатель**: после него документ перестаёт
   переобновляться обменом.
4. **Подбор приобретения.** Кнопка «Подобрать приобретение» и автоподбор ищут акт поставщика по
   ключу «контрагент + организация + сумма ±1 грн + окно ±45 дней», сортируя кандидатов
   «договор → тот же месяц → ближайшая дата». Правило выведено из 39 исторических связок, а не
   придумано: [[oump_podbor_priobreteniya]].
5. **Полный цикл по акту.** После подбора в акте ставится обратная ссылка, заполняется
   `А_Распределение`, строки **разносятся по подразделениям пропорционально оплате** и документ
   перепроводится. Сумма акта и НДС сохраняются копейка в копейку: [[oump_cikl_akta]].
6. **Чего нельзя трогать.** Акт, где есть строки, приходуемые на склад (`СписатьНаРасходы = Ложь`),
   автоматика не изменяет вообще — количество товара делить по подразделениям нельзя.
7. **Оплаты.** Кнопка «Создать оплаты» строит из ТЧ `Деньги` пару документов: безнал — списание и
   поступление, наличка — РКО и ПКО. Договор подбирается по второй стороне и статье ДДС, объекты
   расчётов заполняются одной общей процедурой. Без расшифровки платежа взаиморасчётов не будет:
   [[oump_oplaty_kassa_i_dogovory]].

## FAQ

**Документ проводится — куда он пишет?**
Никуда. `RegisterRecords` пуст, `ОбработкаПроведения` в модуле нет. Учётный результат дают
подчинённые документы, которые он создаёт, и акт поставщика, который он распределяет.

**Почему документ сам перезаписался и затёр мои правки?**
Потому что перезаписали платёж. Подписка `СписаниеБезналичныхДенежныхСредств_ПриЗаписи` при
**каждой** записи платежа перезаливает `Дата`, `Организация`, `ДенежныйДокумент`, `Комментарий`,
`А_Распределение` и сбрасывает `А_Обработан`. `ПриобретениеТоваров` и `Закрытый` она не трогает.

**Как остановить автообновление конкретного документа?**
Взвести `Закрытый` (или `Проверил`, или `А_Необновлять`). Автоподбор взводит `Закрытый` сам,
когда нашёл приобретение, — это и есть фиксация документа.

**Почему автоподбор ничего не подставил?**
Три частые причины: в договоре платежа не взведён
`ДоговорыКонтрагентов.А_ПодбиратьДокументПриобретениеВБюджетнойОперации`; кандидатов не один;
акт ещё не создан (в 10 из 39 эталонов акт появлялся на 17–49 дней позже документа —
подбор повторится при следующей записи платежа, пока не взведён `Закрытый`).

**Почему цикл отказался распределять акт?**
Одна из четырёх причин, каждая возвращается текстом: акт закреплён за другим оказанием услуг;
изменение запрещено датой запрета; в акте есть складские строки (`СписатьНаРасходы = Ложь`);
табличная часть `Товары` пуста и нет строк `А_Услуги`, откуда взять ставку НДС.

**Почему по наличной строке не создались ордера?**
Либо в строке `Деньги` вместо кассы стоит банковский счёт и не найдена касса по умолчанию
«Касса ЦО», либо форма оплаты не наличная и не безналичная. Реквизит составного типа
«банк или касса», и банковский счёт в `Документ.Касса` молча обнуляется.

**Деньги по ордеру прошли, а задолженности нет — почему?**
Не заполнена `РасшифровкаПлатежа`: именно из неё строится `ОбъектРасчетов`, носитель
взаиморасчётов. Шапочный реквизит `Договор` расчётами не управляет.

**Что будет с НДС при разнесении?**
Ничего. НДС строки разносится **остатком**, а не пересчитывается по ставке — сумма частей
всегда равна исходному НДС строки. Строки «Без ПДВ» остаются без НДС.
