## Выгрузка книги Excel (потребитель №1)

`_Rarzrabotki/Обработки/ВыгрузкаОтчетаPLвExcel/Ext/ObjectModule.bsl`:
`Отчеты.А_ОтчетPL_ПолныйЕРП_Остатки.Создать()`, настройки пользовательского
варианта листа грузятся в компоновщик, подставляется Период и отборы:

- **объектный лист** — подразделение «В группе из списка» (пара отборов из
  варианта: «В списке» + «В группе из списка»);
- **лист «Только это подразделение»** (ЦО-листы) — корень «В списке»;
- **свод направления и PL_Свод** — СЛОЙ СВОДОВ: `УстановитьСводыНаправлений`
  (параметр СводыНаправлений=Истина поверх варианта) + корень направления
  (PL_Свод — корни всех строк-сводов; ЦО отсекается условием «Не в группе ЦО»
  самого варианта). Состав листов книги на цифры сводов НЕ влияет — закрытые
  объекты сидят в свод-остатках корней.

**Варианты книги (с 01.09.2026 — «PL: …», отчёта остатков; регистр перепривязан):**
| Вариант | Отбор | Листы |
|---|---|---|
| PL: Месяц, PL накопительный | пара с ИЛИ («В списке» + «В группе из списка») | объектные |
| PL: Месяц, PL с начала года | пара с ИЛИ | объектные |
| PL: Месяц, PL с начала года (для ЦО направлений) | ОДИН «Подразделение В списке» | ЦО-листы (ТолькоЭто: корень, вид «Равно» ставит обработка) |
| PL: Месяц, PL с начала года (для свода) | ОДИН «Подразделение В группе из списка» | своды направлений |
| PL: (без направления ЦО): Месяц, PL с начала года | «В группе из списка» + «Не в группе ЦО» | PL_Свод |
Для сводов одного «В группе из списка» ДОСТАТОЧНО (решение финансиста
01.09.2026): на слое сводов строки лежат на самом корне, «в группе корня» их
пропускает. Обработка поддерживает ОБА стиля: пара → корень «В списке»;
без пары → значение кладётся в одиночный элемент «Подразделение»
(свод направления — корень, PL_Свод — `ЗаполнитьОдиночныйОтборСписком`
корнями строк-сводов). Устаревшего fallback по полю «НаправлениеДеятельности»
больше нет.

## Эталонные цифры

**По правилу 02.09.2026 (строка «Операционный доход», период 01.07–31.08.2026, свод):**
Спецтехника: Июль 3 205 500,00; «PL с начала года» = 12 404 410,34 + 3 205 500,00 + ЕРП-август
(02.09.2026: 2 937 277,02 → 18 547 187,36); «Накопительный PL» = 59 608 148,03 + июль + август.
Строительство: Июль 59 680 456,99; 890000 = 339 313 061,76 + 59 680 456,99 + август (65 289 742,34 → 464 283 261,09).
Период «только август» даёт те же накопительные (июль вне периода, но в них).
Август и позже — ЖИВЫЕ, в тестах считать запросом.

## Грабли (проверены фактом)

- Документ `А_ОтчетPL` с датой > 30.06.2026 игнорируется ПОЛНОСТЬЮ (и в месячных, и в
  накопительных) — даже если проведён.
- Накопительные включают ЕРП-месяцы, не попавшие в период (период «август» содержит июль).
- Свод-варианты «(для свода)» и «(без направления ЦО)» с 02.09.2026 хранят `СводыНаправлений = Да`;
  объектные — Нет. Интерактивный свод = книга.
- Для периодов с концом ≤ 30.06.2026 последний месяц теперь из документа, не из ЕРП
  (Глобино-2, май-2026 ОД: 43 049 236,83 → 43 605 205,86).

- **Нет проведённого документа остатков** → отчёт падает с исключением — так
  задумано; создать/провести `А_ВводОстатковОтчетаPL`.
- Закрытый объект в интерактивном отборе покажет НУЛИ в накопительных
  (его остатки не зафиксированы) — принято финансистом 31.08.2026.
- Сборка внешнего .erf: при занятом конфигураторе BaseERP собирать через
  `BaseERPRazr` (те же креды). В корневом XML внешнего клона `xr:ClassId` —
  ПЛАТФОРМЕННЫЙ id класса, не регенерировать; `GeneratedType name` и
  `MainDataCompositionSchema` несут имя отчёта.
- Клонирование: UUID регенерировать ТОЛЬКО в корневых XML метаданных; в СКД
  Template.xml UUID не трогать — `dcsset:right` хранит значения отборов вариантов.
- Частичная загрузка в конфигурацию: модули прямым путём; правка СКД —
  корневым `Templates/ОсновнаяСхемаКомпоновкиДанных.xml`.
- Пользовательские варианты — живые данные (могут нести свои группировки,
  например «Аналитика»); приёмки отключают их перед ячеечной сверкой.
- Представления документов в расшифровке: РКО «…ордер N…» (ЛАТИНСКАЯ N);
  АмортизацияОС «Амортизация ОС (2.1) 000Ц-…»; ВнутреннееПотреблениеТоваров имеет
  ДВА представления по операции; ПрочиеДоходыРасходы — «Регистрация расходов».
- Запросы: алиасы В/ПО/ИЗ/КАК запрещены; ИМЕЮЩИЕ не использовать; у
  `Справочник.Организации` нет поля Код. Отбор вариантов по отчёту: поле «Отчет»
  составное — фильтровать через `ВЫРАЗИТЬ(Вар.Отчет КАК
  Справочник.ИдентификаторыОбъектовМетаданных).ПолноеИмя`; поля
  «ВариантПользователя» в справочнике нет.
