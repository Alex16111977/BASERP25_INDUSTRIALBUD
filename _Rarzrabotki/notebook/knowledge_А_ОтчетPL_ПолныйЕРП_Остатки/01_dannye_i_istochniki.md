# 01. Конвейер данных: откуда берётся каждая цифра

## Точка фиксации остатков

**Документ `А_ВводОстатковОтчетаPL`** (шапка: Организация, Ответственный,
Комментарий; ТЧ «Остатки»: Подразделение, СводНаправления, СтатьяPL,
СуммаФ1СНачалаГода, СуммаФ2СНачалаГода, СуммаФ1Накопительно, СуммаФ2Накопительно).
Прямые движения 1:1 в **РН `А_ОстаткиОтчетаPL`** (обороты; измерения =
Подразделение × СтатьяPL × СводНаправления, ресурсы = 4 суммы).

Введено ПО-ЛИСТОВО: 30 документов на 30.06.2026 23:59:59, по одному на лист книги
выгрузки, Комментарий = «Остатки PL на 30.06.2026 — лист «X»». Свод-листы несут
СВОД-слой корня направления (СводНаправления=Истина), объектные листы — объектный
слой своих подразделений. Подразделения без листа (закрытые объекты) НЕ
зафиксированы — решение финансиста: интерактивный отбор по закрытому объекту даст
нули в накопительных, своды не страдают (закрытые сидят в свод-остатках корней).

**Объектный слой Спецтехники и ЦО (02.09.2026):** эти корни велись только сводом;
инвариант «каждый корень — в обоих слоях» восстановлен копиями: документы
№00000000032 (Спецтехника, 35 строк) и №00000000033 (ЦО, 30 строк), те же суммы,
`СводНаправления = Ложь`, комментарий «… (объектный слой)»; скрипт
`_Rarzrabotki/Python/test/create_ostatki_obekt_sloy_2026-09-02.py` (идемпотентен,
контроль равенства слоёв). Документы `А_ОтчетPL` и остатки больше не загружаются.

Контроль в `ПередЗаписью` документа: комбинация Подразделение × СтатьяPL ×
СводНаправления — ровно в ОДНОМ проведённом документе (иначе отчёт задвоил бы);
проверка запросом регистра против ТЧ через `&ТаблицаКлючей`.
Серверная `ЗаполнитьИзДокументовPL()` заполняет ТЧ из проведённых А_ОтчетPL
по дату документа (оба слоя, нулевые строки отбрасываются) — кнопка на форме.

## Запрос v14 (`ПолучитьДанные`, один пакет)

Порядок временных таблиц: `втСводныеПодразделения → втПредкиПодразделений →
втКартаУровней → втКолонкиPL → втPL_ДДС → втЕРП_Расх_Детали →
втЕРП_Доходы_Детали → втЕРП_CoGS_Детали → втЕРП_ДохCoGS_PL → финальное
объединение`.

`втСводныеПодразделения` = подразделения документов с `ВключатьДочерние` ∪ свод-слой
РН остатков (документы заморожены — регистр надёжнее).

Ветки финального ОБЪЕДИНИТЬ ВСЕ (правило 02.09.2026):
1. **ЕРП-расходы** (`втЕРП_Расх_Детали` ← РН.ПрочиеРасходы) — `Период МЕЖДУ &НачалоЕРП
   И &КонецПериода` (все месяцы ПОСЛЕ границы остатков по конец периода); аналитика
   по типу регистратора (см. 02). Строки месяцев периода → месячные колонки, все
   строки → 900000, строки с `МесяцКлюч >= &КлючНачалаГода` → 890000.
2. **ЕРП-доходы и CoGS** (`втЕРП_ДохCoGS_PL` ← ВыручкаИСебестоимостьПродаж +
   ПрочиеДоходы) — тот же диапазон; доход через ПКО = Ф2, остальное Ф1.
3. **Документы А_ОтчетPL** (только месячные колонки): `Док.Проведен`,
   `Док.ВключатьДочерние = &СводыНаправлений`, `Док.Дата <= &ГраницаОстатков` и в
   периоде; суммы из ТЧ ДанныеОтчета (`СуммаФома1`/`СуммаФорма2`). В накопительные
   колонки документы НЕ читаются (ветка удалена 02.09.2026).
4. **РН `А_ОстаткиОтчетаPL` → накопительные колонки**: `Ост.Период = &ГраницаОстатков`,
   `Ост.СводНаправления = &СводыНаправлений`; 900000 — `…Накопительно`; 890000 —
   `…СНачалаГода` только при `&ОстаткиВГодуПериода` (год границы = год конца периода);
   Документ = Ост.Регистратор — расшифровка ведёт на документ остатков.
5. **План** (`А_БюджетМесяц`, ВидПериода=Объект) → колонка 900100.
6. **Фиксы** (`втФиксНорма`) → ресурсы ФиксФ1/ФиксФ2/ФиксИтого месячных колонок.

Параметры запроса ставит модуль: `НачалоПериода/КонецПериода` (из параметра
Период), `ГраницаОстатков` = константа `ГраницаОстатков()` = 30.06.2026 23:59:59,
`НачалоЕРП` = 01.07.2026, `ОстаткиВГодуПериода` = Год(границы) = Год(КонецПериода),
`КлючНачалаГода` = ГОД(КонецПериода)×100+1, `КолонкиPL` — ТЗ оси колонок
(`ТаблицаКолонок` по флажкам блоков), `СводыНаправлений`, `ДДСCoGS`,
`СтатьяДоходовТовар`, `ВыводитьФиксы`. Параметров `ПоследнийМесяц`/`МесяцОстатков` нет.

## Карта уровней (`втКартаУровней`)

Каждое подразделение ЕРП-движений мапится на «подразделение отчёта»:
при `СводыНаправлений = Ложь` — на объект (узел, по которому ведутся документы
PL), при Истина — на корень направления. Строки регистров с ПУСТЫМ подразделением
в отчёт НЕ попадают.

## Конвейер BSL после запроса (`ПриКомпоновкеРезультата`)

1. `ПолучитьДанные` → ТаблицаДанных (внешний набор «Данные»).
2. `УдалитьСтрокиДивидендов` — статья 000000058 удаляется безусловно.
3. Колонки ВидКолонки («Месяц»/«PL с начала года»/«Накопительный PL»/«План
   объекта») и Аналитика1 (у строк из А_ОтчетPL — комментарий финансиста, иначе
   строковое представление аналитики).
4. `ДополнитьВидКакВExcel` — сердце отчёта: агрегаты по парам
   (подразделение × колонка) в Соответствии «Итоги» (тройки Ф1/Ф2/Ит по
   категориям ОД/СС/ДР/ОПЗ/Аморт/МЗ/АЗ/НС/ФинДоход/ФинРасхКом/ФинРасхПроц/
   КурсРазн/НалогНаПрибыль; особые статьи по КОДУ раньше группы), полный шаблон
   (нулевые строки всех статей), разметка строк листа (СтрокаЛиста/СортЛиста),
   база «% затрат» по отбору компоновщика (см. 02), водопад показателей
   (`РассчитатьВодопадКолонки` + `ДобавитьСтрокуПоказателя`), контрольные
   служебные строки (по флажку).
5. `ЗаполнитьРаскрытиеИсточников` — служебные поля ИсточникиФакта/ДокументыПо/
   ЕРПС/НакопительноС/ПланАктуаленНа.
6. `ЗаполнитьРусскиеНаименования` — СтатьяPLРус/ГруппаРус из реквизита
   `НаименованиеДляОтчетаНаРусском` (оба режима).
7. Компоновка с настройками компоновщика; `УстановитьЗаголовкиФ1Ф2(+ВСтруктуре)`
   безусловно перекрывает подписи «Сумма по Ф1, грн»/«Сумма по Ф2, грн»;
   после вывода — `РусифицироватьСлужебныеТексты` (чистит украинские
   платформенные надписи шапки).

Ключевые процедуры модуля: `ПриКомпоновкеРезультата`, `ПолучитьДанные`,
`ТаблицаКолонок`, `ГраницаОстатков`, `ДополнитьВидКакВExcel`,
`БазыЗатратПоОтбору`, `МножествоПодразделенийОтбора`,
`СобратьУсловияОтбораПодразделений`, `РассчитатьВодопадКолонки`,
`КодыОсобыхСтатей`, `УдалитьСтрокиДивидендов`, `ЗаполнитьРусскиеНаименования`,
`УстановитьЗаголовкиФ1Ф2`, `РусифицироватьСлужебныеТексты` (Экспорт),
`ЗаполнитьРаскрытиеИсточников`, `ОставитьСтатьиСФиксами`.
