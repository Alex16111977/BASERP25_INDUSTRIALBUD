## TL;DR (за 60 секунд)

1. **Бизнес-проблема.** Начисление ЗП/налогов делается на реальном подразделении работы сотрудника
   (Глобино-2, ЦО, Автокран XCMG…). Но выплата идёт через кассы/счета целевых юр.лиц
   (ІНДЕПТ СТІЛ → `Производство`, ТОВ ІНДАСТРІАЛБУД / ДЖИ ТРИ → `Строительство`). → дисбаланс
   управ.баланса **по подразделениям**: на реальном висит начисление без денег, на целевом — выплата без начисления.
2. **Решение.** Новый документ переносит **обязательства** (не затраты!) с реального подразделения на целевое:
   модель **«3 ТЧ ↔ 3 статьи ПАП»** — `Начисления`(NET)→«Оплата труда»(+ А_ВзСС per ФЛ),
   `Налоги`(per ТипНалога)→«Налоги»(Аналитика=ТипНалога), `Удержания`→«Прочие пассивы».
3. **Движения.** На **исходном** подразделении — РЕВЕРС начисления ОЗФУ (для пассивной статьи = Приход),
   на **целевом** — КОПИЯ (Расход). А_ВзСС — инверсно (исходное Расход / целевое Приход, разрез ФизЛицо).
   Каждая строка net-zero → Σ КО по организации НЕ меняется, баланс сдвигается между подразделениями.
4. **Целевое подразделение определяется ПРОПОРЦИОНАЛЬНО** (связь сотрудник↔юр.лицо many-to-many):
   веса per Сотрудник из `ТЧ.РаспределениеКазна` родителя; целевое = `Организация.А_ПодразделениеЗарплатаБух`.
   Доля юр.лиц без целевого («Управленческая организация», ~36%) остаётся на исходном — управучёт через кассу.
5. **Суммы — только из дочернего ОЗФУ** (он постит ПАП) → Σ ТЧ = ПАП до копейки (G1–G3 = 0).
6. **Find-Or-Create** по `А_ДокументОснование`; идемпотентно. **Без бух.проводок (Хозрасчетный), без новых движений ДДС/статей.**
