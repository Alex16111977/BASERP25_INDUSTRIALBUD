# ПНМП — Логика проведения (движения регистров)

> `ОбработкаПроведения` нового документа. Карта движений ПАП (3 статьи) + вызов А_ВзСС.
> Принцип «реверс на исходном / копия на целевом». Знаки. Net-zero.
> Код: `Documents/А_ПередачаНачисленийМеждуПодразделениями/Ext/ObjectModule.bsl`.

---

## Принцип: реверс на исходном / копия на целевом

Начисление дочернего ОЗФУ кладёт обязательство (пассив) на **реальное** подразделение работы.
Документ передачи «перебрасывает» его на **целевое** подразделение юр.лица-плательщика:

- на **ИсходномПодразделении** — пишем **РЕВЕРС** движения начисления (гасим обязательство там, где его больше не платят);
- на **ЦелевомПодразделении** — пишем **КОПИЮ** движения начисления (ставим там, где касса юр.лица платит).

Каждая строка ТЧ → пара движений (исходное + целевое) с равной суммой → **Σ по организации = 0**
(net-zero). Σ КО управ.баланса по организации НЕ меняется; баланс сдвигается между подразделениями.

## Карта движений ПАП

Все движения: `Организация` = шапка (ТОВ ІНДАСТРІАЛБУД), `Источник = Перечисления.ИсточникиУправленческогоБаланса.ПустаяСсылка()`,
`ВидИсточника = Перечисления.ВидыИсточниковДвижений.ПустаяСсылка()` (как у ОЗФУ для этих статей).

| Статья (ПВХ.СтатьиАктивовПассивов) | Источник суммы (ТЧ) | Аналитика | Исходное подр. | Целевое подр. |
|---|---|---|---|---|
| **Оплата труда** | Начисления (агрегат по подр) | — (пусто) | **Приход** Σ | **Расход** Σ |
| **Налоги** | Налоги (агрегат по подр × ТипНалога) | `ТипНалога` | **Приход** Σ | **Расход** Σ |
| **Прочие пассивы** | Удержания (агрегат по подр) | — (пусто) | **Приход** Σ | **Расход** Σ |

Все три статьи — **пассивные**; начисление ОЗФУ для них = **Расход** (рост обязательства), поэтому
реверс на исходном = **Приход**, копия на целевом = **Расход** (для положительной суммы).

### Реализация (одним запросом по 3 ТЧ + цикл)
`ОбработкаПроведения` собирает агрегат по 3 ТЧ через `ОБЪЕДИНИТЬ ВСЕ` (группировка по
ИсходноеПодразделение/ЦелевоеПодразделение [+ ТипНалога]), затем для каждой строки:

```bsl
Сум = ?(Выборка.Сумма > 0, Выборка.Сумма, -Выборка.Сумма);
Если Выборка.Сумма > 0 Тогда
    ВидДвИсх = ВидДвиженияНакопления.Приход;  ВидДвЦел = ВидДвиженияНакопления.Расход;
Иначе
    ВидДвИсх = ВидДвиженияНакопления.Расход;  ВидДвЦел = ВидДвиженияНакопления.Приход;
КонецЕсли;
_ПАП_ДобавитьДвижение(Статья, ТипНалога, ИсходноеПодразделение, ВидДвИсх, Сум);
_ПАП_ДобавитьДвижение(Статья, ТипНалога, ЦелевоеПодразделение, ВидДвЦел, Сум);
```

`_ПАП_ДобавитьДвижение` заполняет Аналитику только при непустом ТипНалога (для «Налоги»); для ОТ/ПрочПас — пусто.
Строки с `Сумма=0` или незаполненным Исходным/Целевым — пропускаются.
В UNION-запросе для ОТ/ПрочПас `ТипНалога = ЗНАЧЕНИЕ(Перечисление.ТипыНалогов.ПустаяСсылка)` (консистентный тип, не НЕОПРЕДЕЛЕНО).

## Движения А_ВзСС (только «Оплата труда», разрез ФизическоеЛицо)

Вызывается в конце `ОбработкаПроведения`:
```bsl
РегистрыНакопления.А_ВзаиморасчетыССотрудниками.ЗаполнитьИзПередачиНачислений(ЭтотОбъект);
```
Логика (`ManagerModule.ЗаполнитьИзПередачиНачислений`, образец — `ЗаполнитьИзОтраженияЗП`):
читает ТЧ Начисления, на **исходном** подр. пишет `−Сумма` (Знач), на **целевом** `+Сумма`, свёртка
per (Подразделение, ФЛ) с `ИМЕЮЩИЕ Σ<>0` → знак определяет ВидДвижения:

| Подразделение | Знач | ВидДвижения А_ВзСС |
|---|---|---|
| Исходное | −Сумма | **Расход** (для положит. NET) |
| Целевое | +Сумма | **Приход** |

**А_ВзСС инверсно ПАП(ОТ):** А_ВзСС хранит ПРЯМОЙ долг работодателя перед ФЛ (Приход = рост долга),
ПАП «Оплата труда» — пассив (Расход = рост обязательства). Поэтому на одном подразделении ВидДвижения
ПАП(ОТ) и А_ВзСС **противоположны** → инвариант `А_ВзСС(подр) = −ПАП(ОТ)(подр)` (см. [pnmp_balans_invariant.md](pnmp_balans_invariant.md)).

«Налоги» и «Прочие пассивы» в А_ВзСС **не пишутся** (долг перед бюджетом/получателями, не перед сотрудником).

## Net-zero (по построению)

Для каждой статьи и каждого подразделения движение документа само по себе Σ по организации = 0
(Приход на исходном + равный Расход на целевом). После `ОЗФУ + документ передачи`:
- **исходное подразделение:** начисление + реверс = 0 (на перенесённую долю обязательство ушло);
- **целевое подразделение:** копия начисления (обязательство пришло — его погасит РКО/СБДС).

Итог по организации не меняется. Затраты («Расходы текущего периода» в ОЗФУ) **НЕ трогаются** — остаются
на реальном подразделении (где выполнена работа).

> ⚠️ **Если документ пишет только ОДИН регистр** (ПАП(ОТ) без А_ВзСС или наоборот) — инвариант
> `Свод_ОплатаТруда` сломается (появятся плуги). Пишем ОБА согласованно. Это проверяет тест balanse.
