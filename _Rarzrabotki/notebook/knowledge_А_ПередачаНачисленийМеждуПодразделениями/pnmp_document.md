# ПНМП — Структура документа

> Реквизиты шапки, 3 табличные части, движения регистров, метаданные, точки кода.
> Проверено через MCP `get_metadata_structure` на live BaseERP (2026-05-30).

---

## Шапка (6 реквизитов)

| Реквизит | Тип | Назначение |
|---|---|---|
| `Дата` | Дата | стандарт |
| `Номер` | Строка(9), переменная, автонумерация, проверка уникальности, периодичность Год | стандарт |
| `Организация` | `СправочникСсылка.Организации` | управ.орг = **ТОВ ІНДАСТРІАЛБУД** (= ПАП.Организация) |
| `А_ДокументОснование` | составной: `ДокументСсылка.ОтражениеЗарплатыВФинансовомУчете` + `ДокументСсылка.А_ОтражениеЗПпоКазне` | документ-источник; **ключ Find-Or-Create**. Сейчас = родитель `А_ОтражениеЗПпоКазне`; после перехода на ERP — `ОтражениеЗарплатыВФинансовомУчете` |
| `Комментарий` | Строка (неогр.) | стандарт |
| `Ответственный` | `СправочникСсылка.Пользователи` | стандарт |

| `ПериодВзаиморасчетов` | Дата (= НачалоМесяца(Дата)) |
| `ДокОснованиеСтроки` | составной: `Документ.{НачислениеЗарплаты, ОтражениеЗарплатыВФинансовомУчете, А_ОтражениеЗПпоКазне}` (= дочерний ОЗФУ) |
| `ИдентификаторСтроки` | Строка(36) — `Строка(Новый УникальныйИдентификатор())` (у 1С нет примитивного типа УникальныйИдентификатор для реквизитов) |

**Дополнительные поля по ТЧ:**

| ТЧ | Доп.поля | → статья ПАП | А_ВзСС |
|---|---|---|---|
| **Начисления** (NET per ФЛ) | — | «Оплата труда» (без аналитики) | ✅ per ФизЛицо |
| **Налоги** | `ТипНалога`(Перечисление.ТипыНалогов), `Налог`(Справочник.Налоги), `КодДохода`(Справочник.ВидыДоходовНДФЛ) | «Налоги» (Аналитика = ТипНалога) | — |

> (по целевым подразделениям), т.к. NET дробится пропорционально (см. [pnmp_zapolnenie_proporcia.md](pnmp_zapolnenie_proporcia.md)).
> `ИдентификаторСтроки` различает строки.

## Движения регистров (RegisterRecords)

Документ объявляет движения в **2 регистра** (в XML документа, элемент `<RegisterRecords>`):
- `AccumulationRegister.ПрочиеАктивыПассивы` (типовой) — это правит метаданные **только нового
  кастомного документа** (новый документ добавляется в составной тип `Регистратор` ПАП); структуру ПАП НЕ трогаем.
- `AccumulationRegister.А_ВзаиморасчетыССотрудниками` (кастомный).

Свойства документа: `Posting=Allow`, `RealTimePosting=Deny`, `RegisterRecordsDeletion=AutoDelete`
(распроведение очищает движения автоматически → отдельная `ОбработкаУдаленияПроведения` не нужна).

## Структура регистров-приёмников (для справки)

**`ПрочиеАктивыПассивы` (ПАП):** Измерения `Организация`, `Подразделение`(СтруктураПредприятия),
`НаправлениеДеятельности`, `Статья`(ПВХ.СтатьиАктивовПассивов), `Аналитика`(составная, вкл. ТипыНалогов/ФизическиеЛица).
Ресурс `Сумма`. Реквизиты `Источник`(Перечисление.ИсточникиУправленческогоБаланса), `ВидИсточника`.
Документ пишет с `Источник = ПустаяСсылка`, `ВидИсточника = ПустаяСсылка` (как ОЗФУ для ОТ/Налогов/ПрочПассивов).

**`А_ВзаиморасчетыССотрудниками` (А_ВзСС):** Измерения `Организация × ФизическоеЛицо × Подразделение`(СтрПредпр).
Ресурс `СуммаВзаиморасчетов`. Регистраторы: РКО, ПКО, СБДС, ОЗФУ, ПостБезнал + **новый документ ПНМП**.
