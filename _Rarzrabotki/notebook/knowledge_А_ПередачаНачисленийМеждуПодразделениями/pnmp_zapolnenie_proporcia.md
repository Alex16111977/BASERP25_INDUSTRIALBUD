# ПНМП — Заполнение ТЧ: источник, кнопка, пропорциональное дробление

> Как кнопка «Создать передачу начислений» наполняет 3 ТЧ. Источник сумм, Find-Or-Create,
> пропорциональное распределение по целевым подразделениям.
> Код: `Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`, область `ЕРП_СоздатьПередачуНачисленийМеждуПодразделениями`.

---

## Поток (кнопка → метод объекта родителя)

Кнопка в форме `А_ОтражениеЗПпоКазне` → `&НаКлиенте СоздатьПередачуНачислений` → `&НаСервере` →
`ДокументОбъект.СоздатьПередачуНачисленийМеждуПодразделениями()`. Алгоритм метода:

```
0. GUARD: родитель Проведён.
1. ОЗФУ = _ПНМП_НайтиДочернийОЗФУ(Ссылка)   // ОтражениеЗарплатыВФинансовомУчете где
   //                                          А_ДокОтражениеЗПпоКазне = родитель И Проведен
   GUARD: ОЗФУ найден — иначе Сообщить + Возврат.
2. Веса = _ПНМП_ПостроитьВеса(Ссылка)        // из ТЧ.РаспределениеКазна родителя
3. Док = _ПНМП_НайтиИлиСоздать(Ссылка)        // Find-Or-Create по А_ДокументОснование
   // если найден: распровести, очистить 3 ТЧ; иначе СоздатьДокумент()
4. Заполнить шапку (Дата/Организация/Ответственный/А_ДокументОснование/Комментарий).
5. _ПНМП_ЗаполнитьНачисления(Док, ОЗФУ, Веса)
   _ПНМП_ЗаполнитьНалоги(Док, ОЗФУ, Веса)
   _ПНМП_ЗаполнитьУдержания(Док, ОЗФУ, Веса)
6. Док.Записать(РежимЗаписиДокумента.Проведение).  // Сообщить итог
```

## Источник СУММ — дочерний ОЗФУ (НЕ ТЧ родителя)

Суммы переноса читаются из **дочернего `ОтражениеЗарплатыВФинансовомУчете`** — именно он постит ПАП,
поэтому Σ ТЧ = ПАП по построению (гейты G1–G3 = 0). Запросы:

- **Начисления (NET)** = `НачисленнаяЗарплатаИВзносыПоФизлицам`(Налог=Пустая, **−4 ВидОперации**: отпускные оценочные,
  сдельно-доход, компенсация отпуска оценочные, ежегодный отпуск оценочные) − `НачисленныйНДФЛ` − `УдержаннаяЗарплата`,
  per (ФЛ, ПодразделениеПредприятия). **Точная логика `А_ВзСС.ManagerModule.ЗаполнитьИзОтраженияЗП`.**
- **Налоги** = `НачисленныйНДФЛ` (ТипНалога НДФЛ/ВС, КодДохода) + ЕСВ из `НачисленнаяЗП.ВзносыВсего`
  (где `Налог.Наименование ПОДОБНО "ЕСВ%"`, ТипНалога=НачисленныйЕСВ).
- **Удержания** = `УдержаннаяЗарплата` per (ФЛ, ПодразделениеПредприятия).

> ⚠️ `РаспределениеКазна.Сумма` (на эталоне 7 530 371,76) **НЕ равна** ПАП-компонентам (это казначейские
> суммы выплат) → используется ТОЛЬКО как **веса**, не как суммы переноса.

## Пропорциональное дробление (правило целевого) — решение пользователя 2026-05-29

Связь **сотрудник ↔ юр.лицо (ОргБух) — many-to-many** (на эталоне 75/178 ФЛ оплачены из >1 юр.лица).
Поэтому одно целевое на ФЛ присвоить нельзя — обязательство дробится.

**Веса per Сотрудник** (`_ПНМП_ПостроитьВеса`, из `ТЧ.РаспределениеКазна` родителя):
```sql
ВЫБРАТЬ РК.Сотрудник.ФизическоеЛицо КАК ФЛ, РК.Сотрудник, РК.Организация КАК ОргБух,
        РК.Организация.А_ПодразделениеЗарплатаБух КАК ЦелПодр, СУММА(РК.Сумма) КАК Вес
ИЗ Документ.А_ОтражениеЗПпоКазне.РаспределениеКазна КАК РК
ГДЕ РК.Ссылка = &Осн И РК.Сотрудник <> ЗНАЧЕНИЕ(Справочник.Сотрудники.ПустаяСсылка)
СГРУППИРОВАТЬ ПО РК.Сотрудник.ФизическоеЛицо, РК.Сотрудник, РК.Организация, РК.Организация.А_ПодразделениеЗарплатаБух
```
В BSL строится `Соответствие ФЛ → Структура("Список" [Сотрудник/ОргБух/ЦелПодр/Вес — только с целевым], "Всего" [Σ ВСЕХ весов, вкл. без целевого])`.

**Дробление** (`_ПНМП_Распределить`): для каждой суммы (ФЛ, ИсхПодр) →
`доля = Окр(Сумма × вес[Сотрудник] / Всего[ФЛ], 2)` на каждое юр.лицо-с-целевым; строка ТЧ
(ФЛ, Сотрудник, ОргБух, ИсхПодр, ЦелПодр=Орг.А_ПодразделениеЗарплатаБух, доля).

**Доля без целевого («Управленческая организация») НЕ переносится** — остаётся в знаменателе `Всего`,
но строки ТЧ для неё не создаются → остаётся на исходном подразделении (управленческий учёт, идёт через
кассу наличными — отдельный механизм). На эталоне: ВесСЦелью/ВсегоВес = 4 811 341,76 / 7 530 371,76 ≈ **64%**
→ переносится ~62–76% (per-ФЛ варьируется), остальное на исходном.

> **Покрытие весами — 100% ФЛ** (веса считаются per ФЛ, а не per (ФЛ×подр)), поэтому подразделенческие
> несовпадения РаспределениеКазна↔ОЗФУ не теряют сотрудников.

## Find-Or-Create + идемпотентность

`_ПНМП_НайтиИлиСоздать(Родитель)`: ищет `Документ.А_ПередачаНачисленийМеждуПодразделениями`
где `А_ДокументОснование = Родитель`. Если найден — снять пометку удаления, распровести, очистить 3 ТЧ;
иначе `СоздатьДокумент()`. → повторное нажатие кнопки = **тот же документ**, те же ТЧ/движения (Δ=0).

## Грабли (заполнение)

1. **NET ≠ начисления.** ТЧ Начисления хранит чистый NET (начисления − НДФЛ − ВС − удержания), НЕ сырое
   `НачисленнаяЗарплата.Сумма`. Поле ВидОперации при netting сворачивается → в ТЧ Начисления его нет.
2. **`НачисленнаяЗарплата.Организация` = управ.орг** (ТОВ ІНДАСТРІАЛБУД), НЕ ОргБух → ОргБух берём из
   `РаспределениеКазна.Организация` per Сотрудник (там реальные ІНДЕПТ СТІЛ / ДЖИ ТРИ / Управленческая).
3. **`Сотрудник` в ТЧ — из РаспределениеКазна** (однозначен per Сотрудник). ФЛ→Сотрудник напрямую неоднозначен.
4. **`Получатель` в Удержания** — сейчас пусто (источник `УдержаннаяЗарплата`; получатель не извлекается). Аудит-поле, ПАП «Прочие пассивы» аналитику не использует.
5. **Округление** — `Окр(..., 2)` поштучно; копеечный остаток от дробления остаётся на исходном (балансу
   не вредит — каждая строка net-zero сама по себе).
