## Грабли реализации (уроки)

1. **NET ≠ начисления.** ПАП «Оплата труда» = начисления − НДФЛ − ВС − удержания (NET к выплате), НЕ сырое
   `НачисленнаяЗарплата.Сумма`. ТЧ Начисления хранит NET (ВидОперации при netting сворачивается).
2. **ИсходноеПодразделение = `Справочник.СтруктураПредприятия`** (а НЕ ПодразделенияОрганизаций, как предполагал
   исходный промт). `НачисленнаяЗарплата.ПодразделениеПредприятия` уже СтрПредпр → **конвертация `А_Подразделение`
   НЕ нужна** (она для РКО — knowledge 14, где источник Ведомость).
3. **Писать ОБА регистра** (ПАП(ОТ) + А_ВзСС) согласованно с инверсными знаками — иначе Свод_ОплатаТруда плуги.
4. **Связь сотрудник↔юр.лицо many-to-many** → пропорциональное дробление по весам РаспределениеКазна;
   `РаспределениеКазна.Сумма` ≠ ПАП → только веса, не суммы.
5. **66 пред-существующих плугов ОТ** — не от документа (доказано Часть1), вне scope.
6. **form-edit пул id** считает по корню формы, не видит id в Popup командной панели → выдал занятые 578/579;
   проверять уникальность вручную (`grep -oE 'id="[0-9]+"' | sort | uniq -d`), исправлять подстрочной заменой.
   Кнопка легла в тело формы (form-edit не вставляет в командную-панель Popup через `into`).
7. **MCP execute_query**: `ЗначениеЗаполнено()` запрещён в языке запросов (использовать `<> ПустаяСсылка`);
   нельзя `УПОРЯДОЧИТЬ ПО ПРЕДСТАВЛЕНИЕ(...)`; сериализатор JSON падает на сырых enum/ref — возвращать ПРЕДСТАВЛЕНИЕ/строки.
8. **Python COM**: `row[col]` не поддерживается у строки ValueTable — использовать `getattr(row, col)` или `.Колонка`;
   `erp.string(ref.УникальныйИдентификатор())` для UUID; режим записи — `erp.РежимЗаписиДокумента.Проведение`.
9. **db-load-xml требует закрытый Конфигуратор** (иначе «Ошибка блокировки информационной базы»);
   форму грузить через метаданное `Forms/ФормаДокумента.xml`, не Ext напрямую.
