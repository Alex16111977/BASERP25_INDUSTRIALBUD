## TL;DR

После ручного перепроведения декабря 2025 пользователем через UI и перепроведения `А_ФинРез_Баланс` декабря через COM, в `РегистрСведений.А_ОтчётБаланс_Свод` для декабря 2025 по РСКПС/РСППС осталось **2 строки Расхождение=Истина** — обе по подразделению **ЦО** (0Ц-000007), пара ±36 408,04 (net=0):

| Подр | Статья | Source | СуммаКМ |
|---|---|---|---:|
| ЦО | Задолженность клиентов (00000000002) | РСКПС | +36 408,04 |
| ЦО | Полученные авансы (00000000010) | РСКПС | −36 408,04 |

На сводном уровне (Σ ЗадКл + ПолучАв) расхождения нет — net=0.

## Виновник

**Документ:** `Ввод начальных остатков авансов, полученных от клиентов 0Ц-00000083 от 31.10.2025 0:00:00`
**Тип:** `ВводОстатков`
**ХозОперация:** Ввод остатков авансов клиентов
**Подразделение (в ПАП):** ЦО (агрегировано)

### Конкретная строка ТЧ `РасчетыСПартнерами` (25 строк всего, виновна 1)

| Поле | Значение |
|---|---|
| Партнёр / Контрагент | **Благодійний фонд "ЮЕйДрім" БО** |
| Договор | `13/06/22-1 від 13.06.2022` |
| ОбъектРасчётов | `13/06/22-1 від 13.06.2022` |
| Сумма (в ТЧ) | −36 408,04 (отрицательный «аванс» = на самом деле клиент НАМ должен) |
| Доп.строка предоплаты | 161,96 (копейки реальной предоплаты) |

### Что происходит

Этот партнёр в ТЧ внесён с **отрицательной суммой аванса** (т.к. реально он нам должен 36 408,04). Документ `ВводОстатков` с ХозОперацией `ВводОстатковАвансовКлиентов` обрабатывает отрицательный аванс по-разному в двух регистрах:

| Регистр | Что записал | Сумма |
|---|---|---:|
| **РСКПС (детально)** | ДолгУпр (для отрицательного аванса) | −36 408,04 |
| **РСКПС (детально)** | ПредоплатаУпр (копейки) | 161,96 |
| **ПАП (агрегировано по ЦО)** | Источник=РСКПС, Статья=ПолученныеАвансы | (объединено с 24 другими строками ЦО) |
| **ПАП Статья=ЗадолженностьКлиентов** | НЕ ЗАПИСАНА | 0 |

Из-за этого `Свод_РасчетыСПартнерами` видит:
- ЗадКл: РСКПС=−36 408,04, ПАП=0 → плуг **+36 408,04**
- ПолучАв: РСКПС=−161,96 + (с инверсией) на самом деле учитывает суммарно −809 567,28, ПАП=−845 975,32 → плуг **−36 408,04**

### Как должна была быть записана строка ТЧ

Для партнёра с долгом (а не авансом) нужно использовать **другой документ ввода остатков** — `ВводОстатковЗадолженностиКлиентов` (или ХозОперация `ВводОстатковЗадолженностиКлиентов`), где сумма пишется в ТЧ положительной как Долг. Тогда:
- РСКПС.ДолгУпр = +36 408,04 → проектируется в ПАП.ЗадолженностьКлиентов
- РСКПС.ПредоплатаУпр = 0
- ПАП.ЗадКл = +36 408,04, ПАП.ПолучАв = 0 (для этого партнёра)
- Свод сошёлся бы.

### Архитектурная асимметрия проводок

| Регистр / статья | Сумма | Что означает |
|---|---:|---|
| РСКПС.ДолгУпр (Расход) | −36 408,04 | клиент должен нам 36 408 (отрицательный аванс) |
| РСКПС.ПредоплатаУпр | +809 567,28 | клиенты дали авансов 809 567 |
| ПАП.ПолученныеАвансы | −845 975,32 | агрегировано (РСКПС.ДолгУпр + (−РСКПС.ПредоплатаУпр) = −36 408 + (−809 567) = −845 975) |
| ПАП.ЗадолженностьКлиентов | 0 | НЕ записана |

В Свод_РасчетыСПартнерами:
- по ЗадКл-ветке: РСКПС даёт −36 408,04, ПАП даёт 0 → плуг +36 408,04
- по ПолАв-ветке: РСКПС даёт −(+809 567,28) = −809 567,28, ПАП даёт −845 975,32 → плуг −36 408,04

ВводОстатков **агрегирует** долг и аванс в одну статью ПолученныеАвансы в ПАП, в то время как РСКПС хранит их **раздельно**. Это by-design поведение типового документа BAS ERP для авансов с отрицательным сальдо.
