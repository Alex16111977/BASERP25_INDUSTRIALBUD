## Решение

### Выбранная стратегия: **Подход A — снять фильтр `<>ПереносАванса` в `ДвАктПас`**

**Обоснование** (по требованию пользователя — править код типовой обработки):

1. **Системность**: проблема в типовой обработке `DataProcessors/ДвиженияАктивовПассивов/Ext/ManagerModule.bsl` — она должна быть исправлена в одном месте (а не размазана по 3+ локальным веткам документов).
2. **Унификация**: после правки **все** документы с ХозОп=ПереносАванса корректно проектируются в ПАП через ДвАктПас (новые типы документов в будущем будут работать автоматически).
3. **Минимальный объём правки**: 4 строки фильтра в 1 файле vs ~3 × 30 строк локальных веток в 3 файлах.
4. **Управление риском двойного учёта**: будет верифицировано в Phase 4. Если регрессия покажет рост Σ Δ в обратную сторону — rollback по плану §3.5.4 spec.

### Verification план (Phase 4)

**Критерий PASS (acceptance):**
- Глобино-2 / 31.12.2025 / ЗадКл: Δ должна сократиться с −7 194 594,73 до 0 ±0,01 (или близко)
- Σ Δ по 117 кандидатам должна **сократиться** ровно на 24 957 229,26 (величина Σ_отрезано)
- Σ Δ по остальным (2952 − 117 = 2 835 пар) должна остаться **неизменной**
- Штатный `Отчёт.УправленческийБаланс` per организация: 278 093 267,32 / 288 787 750,11 — должно сохраниться (Σ-инвариант не зависит от внутренних статей)

**Критерий FAIL (rollback):**
- Σ Δ выросла в обратную сторону (двойной учёт)
- Штатный отчёт изменил per-организацию Σ
- Регрессия на нормальных сделках (33-36) показала Δ ≠ 0

### Принцип "не заплатки" (по требованию пользователя)

Документы из C3 (~95 М вне scope) **не лечатся** этой правкой. Если после применения они останутся с расхождением — это **другой класс проблемы** и потребует **отдельной задачи**:
- ВводОстатков задолженности (−260 М брутто, нетто −91 М) — особый случай переноса начальных остатков, может требовать архитектурного аудита
- Поступление безналичных + Возврат ДС от поставщика — потенциально та же логика что у нас
- ВзаимозачётЗадолженности — отдельный документ-механизм

Их анализ — Phase 5+ (за пределами текущего плана).
