- **Не удалять документы в тестах** (memory `feedback_no_doc_delete_in_tests`).
- Перед написанием Python-скрипта проверить `SCRIPTS_CATALOG.md`, переиспользовать

- Даты в запрос передавать СЕРВЕРНО (`ДАТАВРЕМЯ(ГГГГ,М,Д,...)` в тексте), не `SetParameter(datetime)`

## 2. ДОРАБОТКА — 4 дефекта (исправить)

### Д1 — Фатальный баг параметров (Module.bsl, строки ~80–82)
Сейчас:
```bsl
Запрос.УстановитьПараметр("НачалоПериода", Объект.НачалоПериода);
Запрос.УстановитьПараметр("ОкончаниеПериода", КонецДня(Объект.ОкончаниеПериода));
Запрос.УстановитьПараметр("НачалоПериода", Объект.ТабличнаяЧастьКонтрагенты.Выгрузить().ВыгрузитьКолонку("Контрагент")); // ❌ затирает дату массивом; &масКонтрагент не установлен
```
В тексте запроса используется `&масКонтрагент`, но он НЕ устанавливается, а `НачалоПериода`
перезаписывается массивом контрагентов → `Выполнить()` падает («Параметр не установлен: масКонтрагент»),
а если бы не падал — `Период МЕЖДУ &НачалоПериода ...` сломалось бы (дата стала массивом).
**Фикс:** третья строка должна устанавливать `масКонтрагент`:
```bsl
Запрос.УстановитьПараметр("масКонтрагент", Объект.ТабличнаяЧастьКонтрагенты.Выгрузить().ВыгрузитьКолонку("Партнер"));
```

### Д2 — «ПоСрокам» берут `.Регистратор` вместо `.ДокументРегистратор`
В union ветки `РасчетыСКлиентамиПоСрокам` и `РасчетыСПоставщикамиПоСрокам` сейчас берут
`.Регистратор` — а это служебный документ `РегистраторРасчётов`, НЕ первичник. Перепроводить
служебный регистратор бессмысленно/вредно.
**Фикс:** в обеих «ПоСрокам»-ветках брать `.ДокументРегистратор` (в `ВЫБРАТЬ` и `СГРУППИРОВАТЬ ПО`),
дату — `.ДокументРегистратор.Дата`, добавить отсев пустого `ДокументРегистратор`.
Операционные регистры `РасчетыСКлиентами` / `РасчетыСПоставщиками` остаются на `.Регистратор`
(там Регистратор = первичник). Внешняя группировка по `Регистратор` дедуплицирует пересечения.

### Д3 — Пустая ТЧ контрагентов
`Контрагент В ИЕРАРХИИ(&масКонтрагент)` с пустым массивом вернёт пусто.
**Фикс:** булев гард (как `ИспользоватьФильтрПодр` в дисбаланс-обработке):
```bsl
МассивКонтр = Объект.ТабличнаяЧастьКонтрагенты.Выгрузить().ВыгрузитьКолонку("Партнер");
Запрос.УстановитьПараметр("ФильтроватьПоКонтрагентам", МассивКонтр.Количество() > 0);
Запрос.УстановитьПараметр("масКонтрагент", МассивКонтр);
```
В каждой ветке условие:
```
(НЕ &ФильтроватьПоКонтрагентам ИЛИ регАналитикаУчетаПоПартнерам.Партнер В ИЕРАРХИИ(&масКонтрагент))
```
Пустая ТЧ → перепровести по всем контрагентам за период (поведение, как у сиблинга
«РасчетыСПоставщиками за период», который без фильтра гонит всё).

### Д4 — Режим записи: одиночная `Записать(Проведение)`
Сейчас `Записать(ОтменаПроведения)` + `Записать(Проведение)` (2 записи). Эталонная
`А_ОбработкаДисбаланса` использует одиночную `Записать(РежимЗаписиДокумента.Проведение)` —
она атомарно перепроводит И триггерит подписки, включая создание `РегистраторРасчётов`.
**Фикс:** заменить на одиночную `Записать(РежимЗаписиДокумента.Проведение)` в транзакции.
Сохранить упорядочивание по `МИНИМУМ(Дата)` (хронология важна для FIFO ОбъектаРасчётов).

> ⚠️ Эта обработка запускается В Enterprise (серверная команда формы) — это легальный путь,
> НЕ COM. Запрет COM-репоста (раздел 0) к запуску самой обработки не относится.
