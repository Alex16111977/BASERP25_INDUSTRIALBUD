## 1. Архитектурные паттерны BAS ERP 2.5

### 1.1 Двойная регистрация: ПАП + РСКПС/РСППС

В BAS ERP 2.5 расчёты с партнёрами регистрируются **в двух регистрах**:

| Регистр | Назначение | Регистратор |
|---|---|---|
| `РегистрНакопления.ПрочиеАктивыПассивы` (ПАП) | Управленческий баланс | сам первичный документ |
| `РегистрНакопления.РасчетыСКлиентамиПоСрокам` (РСКПС) | ВРСК / по срокам | **`Документ.РегистраторРасчётов`** (служебный) |
| `РегистрНакопления.РасчетыСПоставщикамиПоСрокам` (РСППС) | ВРСП / по срокам | **`Документ.РегистраторРасчётов`** (служебный) |

Связь РСКПС/РСППС с первичным документом — через **реквизит `ДокументРегистратор`** записи, НЕ через поле `Регистратор`.

### 1.2 Механизм «Оперативные взаиморасчёты»

Записи РСКПС/РСППС создаются **отложенно** через `Документ.РегистраторРасчётов` после проведения первичного документа. Это типовая логика BSP.

При перепроведении первичного документа:
1. ПАП обновляется сразу (`Документ.ОбработкаПроведения`)
2. РСКПС обновляется через `ВзаиморасчётыСервер.ПроведениеВозвратаОплатыКлиенту` → создаёт записи через `РегистраторРасчётов`
3. Управ.баланс берёт сводку из ПАП

### 1.3 Проекция РСКПС → ПАП

В типовой обработке `DataProcessors/ДвиженияАктивовПассивов/Ext/ManagerModule.bsl`
есть процедуры:
- `ДобавитьТекстЗапросаРасчетыСКлиентамиПоСрокам` (~стр. 1211)
- `ДобавитьТекстЗапросаРасчетыСПоставщикамиПоСрокам` (~стр. 1361)

Они проектируют РСКПС/РСППС-записи в ПАП по статьям:
- ДолгУпр → `ЗадолженностьКлиентов` (или `ЗадолженностьСобственныхОрганизаций` для НашеПредприятие)
- ПредоплатаУпр → `ПолученныеАвансы` (с инверсией знака)
- Зеркально для поставщиков

**До правки** в этих процедурах стоял фильтр `И Т.ХозяйственнаяОперация <> ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ПереносАванса)` в 4 местах (1275, 1323, 1428, 1476).

**После правки FIX-2026-05-23** — фильтр удалён. Маркер сохранён в коде.

## 2. Принципы Python COM работы с 1С

### 2.1 Получение ссылок

```python
# ✗ НЕ работает: UUID без дефисов
uid = erp.NewObject("УникальныйИдентификатор", "80d3000c29bbac2311e653f06bee36b2")

# ✓ Работает: через справочные методы
org = erp.Справочники.Организации.НайтиПоРеквизиту("КодПоЕДРПОУ", "40645273")
podr = erp.Справочники.СтруктураПредприятия.НайтиПоКоду("00-000298")

istochnik = erp.Перечисления.ИсточникиУправленческогоБаланса.РасчетыСКлиентамиПоСрокам
```

### 2.2 Сериализация UUID и типов

```python
# ✗ str(ref.УникальныйИдентификатор()) возвращает '<COMObject <unknown>>'
# ✓ Делегировать в 1С:
uuid_str = erp.String(ref.УникальныйИдентификатор())

# ✓ Имя типа документа:
```

### 2.3 Даты

```python

q.УстановитьПараметр("НМ", datetime.datetime(2025, 12, 1))

# ✓ Серверно через ДАТАВРЕМЯ() прямо в тексте запроса:
```

## 3. SQL-язык запросов 1С — особенности

### 3.1 Функции которых НЕТ

| Хочется | НЕТ в 1С | Замена |
|---|---|---|
| `АБС(X) > Y` | `АБС()` отсутствует | `X > Y ИЛИ X < -Y` |
| `IN (SELECT ...)` в виртуальной таблице | сложные условия | подзапрос через `ПОМЕСТИТЬ` |

### 3.2 Реквизиты vs Измерения в виртуальных таблицах

```sql
-- ✗ НЕ работает (Источник = реквизит ПАП, не измерение)
ИЗ РегистрНакопления.ПрочиеАктивыПассивы.ОстаткиИОбороты(
    , &Дата, , , Источник = &Источник И ...
) КАК Т

-- ✓ Работает (через ОСНОВНУЮ таблицу с signed-агрегацией)
СУММА(ВЫБОР КОГДА Т.ВидДвижения = ЗНАЧЕНИЕ(ВидДвиженияНакопления.Приход)
            ТОГДА Т.Сумма ИНАЧЕ -Т.Сумма КОНЕЦ) КАК signed
ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК Т
ГДЕ ... И Т.Источник = &Источник
```

### 3.3 Составной тип в `ТИПЗНАЧЕНИЯ()`

```sql
-- ✗ НЕ работает (составной тип не приводится через ВЫРАЗИТЬ в строку)
ВЫРАЗИТЬ(ТИПЗНАЧЕНИЯ(Т.Регистратор) КАК Строка(150))

-- ✓ Получать тип в Python:
SELECT Т.Регистратор КАК ДокРеф, ...
# Python:
тип = ref.Метаданные().Имя
```

### 3.4 Спецсимволы в алиасах

```sql
-- ✗ Парсер может не понять
СУММА(...) КАК Σ

-- ✓ Использовать ASCII alias:
СУММА(...) КАК Sum_signed
```

### 3.5 Условие ПРЕДСТАВЛЕНИЕ в WHERE

```sql
-- ✗ "Неверные параметры в операции"
ГДЕ ПРЕДСТАВЛЕНИЕ(Д.Ссылка) = &Имя
ГДЕ ПРЕДСТАВЛЕНИЕ(Д.Ссылка) В (&Имена)

-- ✓ Парсить Номер из представления и искать по Номер + Дата:
ГДЕ Д.Номер = &Ном И Д.Дата МЕЖДУ &Дн И &Дк
```

## 4. Антипаттерны диагностики (3 неверные редакции FINDINGS)

### Ред.1: «Пустой ОбъектРасчетов в шапке»

**Гипотеза:** документы с пустой шапкой `ОбъектРасчетов` не пишут в РСКПС.

**Опровергнуто:** ОбъектРасчетов **в шапке** действительно пустой, но в **ТЧ `РасшифровкаПлатежа`** есть Заказы клиента с подразделением Глобино-2. РСКПС-движения создаются — но через `РегистраторРасчётов`, не через сам платёжный документ.

**Урок:** не делать выводы по реквизиту шапки документа без проверки ТЧ и реальных движений в регистрах.

### Ред.2: «Механизм Оперативные взаиморасчёты не пересчитал»

**Гипотеза:** регламент закрытия месяца не запущен или не завершён.

**Опровергнуто:** пользователь подтвердил скриншотом — регламент за декабрь 2025 успешно выполнен (зелёная галочка «Все операции выполнены успешно»).

**Урок:** перед гипотезой «регламент не запущен» сначала спрашивать пользователя или проверять через `Регистр.ВыполненныеРегламентныеОперацииЗакрытияМесяца` (или похожий).

### Ред.3: «Архитектурная асимметрия»

**Правильная гипотеза.** Документ пишет в ПАП через 2 пути:
- Локальная функция `ТекстЗапросаТаблицаПрочиеАктивыПассивы` — пишет пару `+ПолучАв / -ДенСр`
- Типовая обработка `ДвАктПас` через РСКПС — должна писать пару `+ЗадКл / -ПолучАв`, но **фильтр `<>ПереносАванса` блокирует**

В сумме — половина проводок (`+ЗадКл`) отсутствует.

**Урок методологии:** сверка ПАП vs РСКПС/РСППС **по `ДокументРегистратор`** (не `Регистратор`) сразу покажет асимметрию.

## 5. Паттерны диагностики

### 5.1 Правильная сверка двух регистров

```sql
-- ПАП: Регистратор = первичный документ
ВЫБРАТЬ Т.Регистратор КАК Док, ... ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК Т

-- РСКПС: ДокументРегистратор = первичный документ (Регистратор = служебный)
ВЫБРАТЬ Р.ДокументРегистратор КАК Док, ... ИЗ РегистрНакопления.РасчетыСКлиентамиПоСрокам КАК Р

-- FULL OUTER JOIN по ключу `Док`
ВЫБРАТЬ ... ИЗ втПАП ПОЛНОЕ СОЕДИНЕНИЕ втРСК ПО ...
```

### 5.2 Drill-down документа

Когда есть подозрительный документ:

```python
# Все его проводки в ПАП
q.Текст = """ВЫБРАТЬ ... ИЗ РегистрНакопления.ПрочиеАктивыПассивы
            ГДЕ Регистратор = &Док"""

# Все его проводки в РСКПС (через ДокументРегистратор)
q.Текст = """ВЫБРАТЬ ... ИЗ РегистрНакопления.РасчетыСКлиентамиПоСрокам
            ГДЕ ДокументРегистратор = &Док"""

# Прочесть реквизиты документа
obj = ref.ПолучитьОбъект()
for поле in ("Партнер", "ОбъектРасчетов", "ХозяйственнаяОперация", ...):
    print(f"{поле}: {erp.String(getattr(obj, поле))}")

# Табличные части (РасшифровкаПлатежа)
тч = obj.РасшифровкаПлатежа
for i in range(тч.Количество()):
    стр = тч.Получить(i)
    print(f"  ОР={erp.String(стр.ОбъектРасчетов)}, Сумма={стр.Сумма}")
```

### 5.3 Поиск «не пара» документов

Документы которые пишут в одном регистре, но не пишут в другом:

```sql
-- Только_ПАП: есть в ПАП, нет в РСКПС
ВЫБРАТЬ ... ИЗ втПАП КАК ПАП
ЛЕВОЕ СОЕДИНЕНИЕ втРСК КАК РСК ПО ПАП.Док = РСК.Док
ГДЕ РСК.Док ЕСТЬ NULL

-- Только_РСКПС: есть в РСКПС, нет в ПАП
ВЫБРАТЬ ... ИЗ втРСК КАК РСК
ЛЕВОЕ СОЕДИНЕНИЕ втПАП КАК ПАП ПО РСК.Док = ПАП.Док
ГДЕ ПАП.Док ЕСТЬ NULL
```

## 6. Memory которые нужно знать

Из глобальной memory (`MEMORY.md`) релевантные пункты:

- **`feedback_no_doc_delete_in_tests`** — НЕ удалять документы в тестах, всегда Get-or-Create
- **`feedback_designer_cache_invalidation`** — после `cp .bsl` обязательно `db-load-xml -updateConfigDumpInfo` (skill делает это автоматически)
- **`feedback_use_db_skills_for_config_load`** — не запускать 1cv8.exe вручную, использовать `/db-load-xml` + `/db-update`
- **`feedback_balans_etalon_period_serverside`** — даты передавать серверно (ДАТАВРЕМЯ в тексте запроса), не через `SetParameter(datetime)`
- **`feedback_no_typical_register_changes`** — типовые **регистры** не трогать. (NB: типовые **обработки** правка возможна по explicit consent — наш кейс)
- **`feedback_balans_live_code_source_of_truth`** — при balans-задачах источник истины = live код `ObjectModule.bsl`, не документация
- **`balans_klpost_etalon_drift`** — эталоны Клиенты/Поставщики дрейфуют (12 061 406,77 / -62 529 012,68 актуально, не 12 338 631,09)
- **`broken_refs_detection`** — как определять битые ссылки через Python COM
- **`rs_otchetbalans_svod_orphans`** — сироты РС от удалённых документов; не использовать `Удалить()`

## 7. Lessons о роли системного инженера

### 7.1 STOP когда обнаруживается методологическая ошибка

При разработке скрипта 25 я обнаружил что **моя формула в скрипте 20 асимметрична** (ПАП фильтрует по 4 статьям, РСК берёт всё) — это давало ложную Σ Δ = −120 М вместо реальных ~25 М.

**Правильное поведение:** немедленный STOP, спросить пользователя, не нагнетать сценарий. См. checkpoint в FINDINGS.md «STOP point».

### 7.2 Принять scope ограничение

Пользователь явно сказал «фокус на 24,9 М ПереносАванса, остальное вне scope». Не пытаться объяснить все 120 М — это **другие классы проблем**.

### 7.3 Честно фиксировать побочные эффекты

После применения Подхода A — побочный эффект (рост Δ годовой по 3 подразделениям). **Не скрывать**, явно зафиксировать в `VERIFY_REPORT.md`. Дать опции (продолжить vs откат vs расследовать).

### 7.4 Backup всегда

Перед правкой типового кода — backup .bsl × 4 в `_backup/`. Rollback план готов на каждом этапе (5 минут).

### 7.5 Trace-маркер в правке

Каждая правка кода имеет маркер `FIX-2026-05-23` — позволяет:
- Найти где правили (grep)
- Понять контекст через дату
- Связать с FINDINGS / STRATEGY_DECISION
