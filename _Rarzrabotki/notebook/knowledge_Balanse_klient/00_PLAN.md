## Этап 1 — Контрольные остатки (4 точки × 2 регистра)

### 01 `01_balance_pap_klient_globino2.py`

**Что ищет:** начальные и конечные остатки статьи "Задолженность клиентов"
в регистре `ПрочиеАктивыПассивы` для подразделений ГРУППЫ "Глобино-2"
на 4 контрольных датах: 01.11/30.11/01.12/31.12.

**Как считает (формула):**
```
signed = ВЫБОР Приход +Сумма ИНАЧЕ -Сумма
НМ_<месяц> = Σ signed по Период < НачМес
КМ_<месяц> = Σ signed по Период <= КонМес
фильтр:
  Организация = &ТОВ
  Подразделение В ИЕРАРХИИ (&ПодрГлобино2)
  Источник = ЗНАЧЕНИЕ(...РасчетыСКлиентамиПоСрокам)
  Статья = &ЗадолженностьКлиентов
  НЕ Статья В ИЕРАРХИИ (СтатьиНеВходящиеВБаланс)  // OD-3
```

**Что даёт:** 4 цифры + общий разрез по подразделениям группы Глобино-2
(сколько каждое подразделение даёт в общий долг).

**Self-check:** НМ_дек должен быть = КМ_ноя = **43 998 627,87** (со скриншота).

**Артефакт:** `_artifacts/01_pap_balances.json` + print-таблица.

### 02 `02_balance_rsk_klient_globino2.py`

**Что ищет:** то же что 01, но через регистр-расшифровку `РасчетыСКлиентамиПоСрокам`
(тот, что использует штатный отчёт `ВедомостьРасчетовСКлиентами`).

**Как считает (формула):**
```
Используем виртуальную таблицу .ОстаткиИОбороты(&НачМес, &КонМес,,,
    Партнер <> &НашеПредприятие
    И ВЫБОР КОГДА Р.ОбъектРасчетов.Подразделение = ПустаяСсылка
            ТОГДА Р.ОбъектРасчетов.Договор.Подразделение
            ИНАЧЕ Р.ОбъектРасчетов.Подразделение КОНЕЦ В ИЕРАРХИИ(&ПодрГлобино2)
)
JOIN АналитикаУчетаПоПартнерам АП ПО Р.АналитикаУчетаПоПартнерам = АП.КлючАналитики
ГДЕ АП.Организация = &ТОВ

ресурс остатка: ДолгУпрНачальныйОстаток / ДолгУпрКонечныйОстаток (БЕЗ signed)
ресурс оборота: ДолгУпр (signed по ВидДвижения внутри VT)
```

**Что даёт:** 4 цифры зеркально к 01.

**Self-check:** КМ_ноя должен быть **43 998 627,87** (или близко — допускается
±0.01 на округлении).

**Артефакт:** `_artifacts/02_rsk_balances.json` + print-таблица.

### 03 `03_reconcile_balances.py`

**Что ищет:** Δ(ПАП − РСКПС) на 4 точках; локализация месяца расхождения.

**Как считает:**
```
читаем 01_pap_balances.json и 02_rsk_balances.json
для каждой точки: Δ = ПАП_остаток - РСКПС_остаток
ожидание:
    Δ_НМ_ноя = 0
    Δ_КМ_ноя = Δ_НМ_дек = 0     (это была начальная точка где сходилось)
    Δ_КМ_дек ≠ 0                  ← ИСКОМОЕ РАСХОЖДЕНИЕ
```

**Что даёт:** размер расхождения декабря (число + знак: ПАП больше или меньше РСКПС),
подтверждение что эталон ноября действительно сходится.

**Артефакт:** `_artifacts/03_balance_reconciliation.csv` + assert.

## Этап 2 — Движения по регистратору за декабрь

### 04 `04_movements_pap_by_recorder.py`

**Что ищет:** все обороты ПАП декабря по статье/Глобино-2, агрегированные по
**Регистратору** (документу-источнику движения).

**Как считает:**
```sql
ВЫБРАТЬ
    ПАП.Регистратор КАК Регистратор,
    ВЫРАЗИТЬ(ПАП.Регистратор КАК Документ.<все типы>) — для типа
    ПАП.Подразделение КАК ПодразделениеПАП,
    СУММА(ВЫБОР КОГДА ПАП.ВидДвижения = Приход ТОГДА ПАП.Сумма ИНАЧЕ -ПАП.Сумма КОНЕЦ) КАК СигнедСумма_ПАП,
    СУММА(ВЫБОР КОГДА ПАП.ВидДвижения = Приход ТОГДА ПАП.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Приход_ПАП,
    СУММА(ВЫБОР КОГДА ПАП.ВидДвижения = Расход ТОГДА ПАП.Сумма ИНАЧЕ 0 КОНЕЦ) КАК Расход_ПАП
ИЗ РегистрНакопления.ПрочиеАктивыПассивы КАК ПАП
ГДЕ ПАП.Период МЕЖДУ &НачМес И &КонМес
    И ПАП.Организация = &ТОВ
    И ПАП.Подразделение В ИЕРАРХИИ (&ПодрГлобино2)
    И ПАП.Источник = &ИсточникРСК
    И ПАП.Статья = &СтатьяЗадКл
СГРУППИРОВАТЬ ПО ПАП.Регистратор, ПАП.Подразделение
```

**Что даёт:** список документов декабря с их вкладом в Σ_ПАП.

**Self-check:** Σ всех СигнедСумма_ПАП по документам == КМ_дек − НМ_дек из скрипта 01.

**Артефакт:** `_artifacts/04_pap_docs.csv` (Регистратор, ТипДок, Дата, Номер, Подразделение, Приход, Расход, Σ).

### 05 `05_movements_rsk_by_recorder.py`

**Что ищет:** обороты РСКПС декабря по тем же фильтрам, по Регистратору.

**Как считает:**
```sql
ВЫБРАТЬ
    Р.Регистратор КАК Регистратор,
    -- Подразделение: ОбъектРасчетов.Подразделение fallback Договор.Подразделение
    ВЫБОР КОГДА Р.ОбъектРасчетов.Подразделение = ПустаяСсылка
          ТОГДА Р.ОбъектРасчетов.Договор.Подразделение
          ИНАЧЕ Р.ОбъектРасчетов.Подразделение
    КОНЕЦ КАК ПодразделениеРСК,
    СУММА(ВЫБОР КОГДА Р.ВидДвижения = Приход ТОГДА Р.ДолгУпр ИНАЧЕ -Р.ДолгУпр КОНЕЦ) КАК Сигнед_РСК,
    СУММА(ВЫБОР КОГДА Р.ВидДвижения = Приход ТОГДА Р.ДолгУпр ИНАЧЕ 0 КОНЕЦ) КАК Приход_РСК,
    СУММА(ВЫБОР КОГДА Р.ВидДвижения = Расход ТОГДА Р.ДолгУпр ИНАЧЕ 0 КОНЕЦ) КАК Расход_РСК
ИЗ РегистрНакопления.РасчетыСКлиентамиПоСрокам КАК Р
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.АналитикаУчетаПоПартнерам КАК Аналит
        ПО Р.АналитикаУчетаПоПартнерам = Аналит.КлючАналитики
ГДЕ Р.Период МЕЖДУ &НачМес И &КонМес
    И Аналит.Организация = &ТОВ
    И Р.Партнер <> ЗНАЧЕНИЕ(Справочник.Партнеры.НашеПредприятие)
    И ВЫБОР КОГДА Р.ОбъектРасчетов.Подразделение = ПустаяСсылка
            ТОГДА Р.ОбъектРасчетов.Договор.Подразделение
            ИНАЧЕ Р.ОбъектРасчетов.Подразделение
      КОНЕЦ В ИЕРАРХИИ (&ПодрГлобино2)
СГРУППИРОВАТЬ ПО Р.Регистратор, <Подразделение>
```

**Что даёт:** список документов декабря с их вкладом в Σ_РСКПС.

**Self-check:** Σ всех Сигнед_РСК по документам == КМ_дек − НМ_дек из скрипта 02.

**Артефакт:** `_artifacts/05_rsk_docs.csv`.

### 06 `06_reconcile_movements.py`

**Что ищет:** для каждого документа Δ_doc = Σ_ПАП − Σ_РСКПС; топ-расхождений.

**Как считает:**
```
load 04_pap_docs.csv и 05_rsk_docs.csv (Pandas или dict-merge)
FULL OUTER JOIN по UUID Регистратора:
    Δ_doc = Σ_ПАП_doc - Σ_РСКПС_doc
    (если документа нет в одной из таблиц — соответствующая сумма = 0)
сортировать по |Δ_doc| DESC
assert: Σ всех Δ_doc по документам ≈ Δ_КМ_дек (из скрипта 03)
    (допуск ±0.01 на округлении)
```

**Что даёт:**
- список документов где Δ_doc ≠ 0 (это и есть «движут разные суммы»);
- категоризация: документы-только-ПАП (вклад в ПАП есть, в РСКПС нет) /
  только-РСКПС / в обоих но разные суммы;
- закрытие баланса: сумма всех Δ_doc должна давать общий Δ_КМ_дек.

**Артефакт:** `_artifacts/06_docs_with_diff.csv` (Регистратор, ТипДок, Дата, Номер,
ПодрПАП, ПодрРСК, Σ_ПАП, Σ_РСКПС, Δ_doc, КатегорияРасхождения).

## Этап 3 — Drill-down топ-3 расхождений

### 07 `07_drilldown_top_diff.py`

**Что ищет:** для топ-3 документов с максимальным \|Δ_doc\|:
1. Реквизиты документа (тип, дата, номер, контрагент, договор, подразделение, сумма).
2. Все строки движений ПАП по этому регистратору.
3. Все строки движений РСКПС по этому регистратору.
4. Почему сумма разная — формула расхождения в терминах полей регистров.

**Как считает:** для каждого UUID топ-3 — 3 запроса:
- `ВЫБРАТЬ * ИЗ Документ.<Тип> ГДЕ Ссылка = &Док` (реквизиты + СтрокаПодразделение)
- `ВЫБРАТЬ * ИЗ РегистрНакопления.ПрочиеАктивыПассивы ГДЕ Регистратор = &Док` (движения ПАП)
- `ВЫБРАТЬ * ИЗ РегистрНакопления.РасчетыСКлиентамиПоСрокам ГДЕ Регистратор = &Док` (движения РСКПС)

**Что даёт:** строит MD-блок в `FINDINGS.md` с конкретными выводами:
- какие подразделения у документа в ПАП vs в РСКПС;
- какие записи ПАП «не нашли пару» в РСКПС;
- что нужно исправить (диагностический совет, без правки кода).

**Артефакт:** `_artifacts/07_drilldown_top3.md` + аппендится в `FINDINGS.md`.
