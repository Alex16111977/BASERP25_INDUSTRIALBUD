осмотром. Ни один этап не начинается, пока предыдущий не зелёный. Запросы 1С прогоняются через
Python COM **до** попадания в BSL (Rule #-1) — на этом контуре правило окупилось дважды.

## Регламент сопровождения

**Обычный цикл (данные поменялись в 1С):**
```
1. перепровести документы А_Отчет_ПланФактныйПроизводство (по одному на подразделение)
2. cd _Rarzrabotki\Olap_Factory\Py_Olap && .venv\Scripts\python.exe main.py
3. .venv\Scripts\python.exe tests\verify_olap_factory.py
4. Refresh в Power BI
```

**Если менялся состав измерений или ресурсов регистра** — добавляется шаг перед ETL:
```
.venv\Scripts\python.exe mapping\refresh_mapping.py
.venv\Scripts\python.exe scripts\introspect_planfakt_fields.py
# правка _FldNNN в pipelines\fact_planfact_proizvodstvo.json
```
Платформенные номера полей зависят от порядка реквизитов и сдвигаются молча.

**Если добавилась колонка в SQL** — дописать её в список колонок в `scripts\build_pbip.py`
и пересобрать модель. Коннектор `Sql.Database` кеширует схему; без явного списка новая колонка
не появится даже после Full Refresh.

**Чего не делать:** не трогать `_Rarzrabotki\Olap\Ai_Olap` (это чужой контур PnL/Cashflow/Balance);
не менять значения `Перечисление.А_ТипыСтрокПланФактПроизводство` — строки используются в DAX
буквально; не удалять документы, только перепроводить.
