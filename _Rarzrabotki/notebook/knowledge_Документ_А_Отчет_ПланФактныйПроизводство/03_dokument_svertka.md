# Документ-свёртка А_Отчет_ПланФактныйПроизводство: запрос, постобработки, ETC

Файл описывает **источник данных** контура План-факт производства: документ, который при проведении
собирает историю и записывает её в `РегистрСведений.А_ПланФактПроизводство_Свод`. Дальше по цепочке —
`Отчёт.А_ПланФактныйПроизводствоСвод` и ETL Olap_Factory → Power BI. Рабочий отчёт
`А_ПланФактныйПроизводствоПолный` **не трогали** — он остался эталоном сверки, алгоритм ниже
портирован из него 1:1 (заявлено в шапке модуля, строки 11–12).

## 4. 🔴 Инварианты, которые нельзя менять

* **Множитель `ВТ_СС.Домов`** в ветках 1 и 2 (строки 161, 197, 199). Убрать — план схлопнется до одного дома,
  а факт останется полным: план-факт и весь ETC поедут в минус по всем подразделениям с `КоличествоДомов > 1`.
  `ВЫБОР ... ИНАЧЕ 1` защищает от нуля: `КоличествоДомов = 0` умножило бы план на ноль.
* **`СТ.Стоимость` берётся «брутто»** (строка 255) — отбор жёстко `ВидДвижения = Приход` (259),
  расход не вычитается. Так считает отчёт-эталон. Добавите нетто (Приход − Расход) — цифры перестанут
  сходиться с `А_ПланФактныйПроизводствоПолный`, и сверка развалится.
* **Факт (ветки 3 и 4) соединяется с `ВТ_Подр1`, а не с `ВТ_СС`** (строки 228, 257) — соединение
  `ПО ИСТИНА` с таблицей из одной строки нужно только чтобы протащить `Подразделение` в выборку.
  Замените `ВТ_Подр1` на `ВТ_СС` — каждая факт-строка размножится на число активных СС подразделения,
  факт вырастет кратно (у подразделения их обычно десятки).
* **`НАЧАЛОПЕРИОДА(..., ДЕНЬ)`** в ветках 3–5 (206, 235, 267). Периодичность регистра — `Day`
  (`InformationRegisterPeriodicity=Day`, строка 155 XML регистра). Без усечения времени две записи
  одного дня с одинаковыми измерениями дадут «Запись с такими ключевыми полями существует».
  Об этом же предупреждает комментарий в модуле, строки 112–113.
* **`ВЫРАЗИТЬ(Регистратор КАК ...)`** в поле `Документ` (217, 246, 278) — измерение `Документ`
  составное и допускает ровно 4 типа: `ПриобретениеТоваровУслуг`, `А_СтруктураСебестоимости`,
  `А_ТабельУчетаРабочегоВремени`, `А_ВыполнениеРаботМодулей`. Без `ВЫРАЗИТЬ` в колонку попадёт
  общий тип регистратора и запись не пройдёт по типу.
* **`Единица` и `НоменклатураНаименование` — только через `МАКСИМУМ`** (307–308). Это реквизиты
  регистра, не измерения. Перенесёте их в `СГРУППИРОВАТЬ ПО` — появятся строки, различающиеся
  лишь реквизитом, но одинаковые по ключу регистра → конфликт ключа при записи.

## 6. ETC («План на факт»), полные правила

Группировка — **нетто по группе**, stage/cat-agnostic: берутся ВСЕ строки с `Блок = "2. Матеріали"`
(план и факт вместе, строки 378–381). Ключ группы строит `КлючГруппыПланНаФакт` (468–486) по приоритету:

1. `UUID(Подразделение) + "|ОН|" + СокрЛП(ОбщееНазвание.Наименование)`; если имя пустое — UUID общего названия;
2. иначе `... + "|НОМ|" + UUID(Аналитика)`, если `Аналитика` — номенклатура;
3. иначе `... + "|НОМТЕКСТ|" + ВРег(СокрЛП(Аналитика))`, если `Аналитика` — непустая строка;
4. иначе `... + "|НОМ|"`.

Накопление (399–409):
```
Группа.ПланКол += Окр(Ч(ПланКол), 2);   Группа.ФактКол += Окр(Ч(ФактКол), 2);
Группа.ПланГрн += Ч(ПланГрн);           Группа.ФактГрн += Ч(ФактГрн);
```
🔴 **`Окр(..., 2)` намеренно** (комментарий 395–398): ТЗ отчёта-эталона хранит количества как
`Число(18,2)`, методология выверена бухгалтером на этих числах; без округления ETC расходится —
замер 01.08.2026: IRS +217,57 / ВООЗ +243,08 / ОРІЛЬ +228,38. В самом регистре количества — `18,3`.

Реквизиты-представители группы (`Категория`, `Этап`, `ОбщееНазвание`, `Единица`) берутся со строки
с **максимальным `ПланГрн`** (403–409). Дефолт до первого срабатывания: `Категория = "Виробництво"`,
`Этап` пустой (391–392).

Расчёт по группе (414–427), порядок обязателен:

| Условие | Результат |
|---|---|
| `ПланГрн <= 0` | строка **не создаётся** |
| `ПланКол <= 0` | `Макс(0, ПланГрн − ФактГрн)` |
| `ФактКол <= 0` | `ПланГрн` **ровно** (деньги не вычитаются) |
| иначе | `Макс(0, ПланКол − ФактКол) * (ПланГрн / ПланКол)` |
| `ПланНаФакт <= 0` | строка **не создаётся** |

Синтетическая строка (428–455): `Период = ДатаСнимка`, `ТипСтроки = ПланНаФакт`,
`Блок = "2. Матеріали"`, `ПодразделениеИсполнитель` пусто, `Работа` = пустая номенклатура,
`Документ` = пустая `А_СтруктураСебестоимости`, `НоменклатураНаименование = ""`,
все семь остальных ресурсов = 0, заполняется только `ПланНаФактГрн`.
🔴 Развилка 438–444: если `ОбщееНазвание` заполнено — `Аналитика` и `Единица` **обнуляются**;
иначе берутся из группы. Иначе одна и та же группа дала бы строки, различающиеся номенклатурой,
и ETC задвоился бы в отчёте.

## 7. `Ч()` и явный дедуп

**`Функция Ч(ЗначениеЧисла)` (463–465)** — `?(ТипЗнч(...) = Тип("Число"), ..., 0)`.
Причина в комментарии 460–462: `ТаблицаЗначений.Добавить()` на таблице, полученной из
`Запрос.Выгрузить()`, кладёт в числовые колонки **NULL, а не 0** (тип колонки запроса допускает NULL),
измерено 01.08.2026. Любая арифметика с NULL даст исключение или мусор, поэтому через `Ч()` проходят
все числа из ТЗ, а синтетические строки обнуляются явно.

**`СвернутьПоКлючуРегистра(ТЗ)` (534–569)** строит результат в `ПустаяТаблицаДвижений()` (601–644),
индексируя строки ключом `КлючРегистра` (571–586) = `Формат(Период, "ДФ=yyyyMMdd")` + 11 измерений
через `ПредставлениеКлюча` (588–598: `Неопределено → ""`, строка → `"S:" + ВРег(СокрЛП(...))`,
ссылка → `Тип + ":" + UUID`). Ресурсы суммируются, реквизиты берутся с первой строки ключа
(`ЗаполнитьЗначенияСвойств`).

Зачем дедуп, если запрос уже сгруппирован: **обе постобработки ломают уникальность после группировки**.
Постобработка №1 меняет `Этап`/`Категория` у факт-строк — две ранее разные строки становятся
одинаковыми по ключу; ETC добавляет строки, которые могут совпасть с уже существующими.
Регистр — `WriteMode=RecorderSubordinate`, регистратор в ключ **не входит**, поэтому дубль ключа
= отказ проведения «Запись с такими ключевыми полями существует». Уберёте `СвернутьПоКлючуРегистра` —
проведение начнёт падать не всегда, а только на подразделениях с дублями, то есть плавающе.

Типы колонок `ПустаяТаблицаДвижений` сверены с регистром: часы и количества — `Число(18,3)`,
гривны — `Число(18,2)`, `Блок`/`Категория` — строка 50, `Аналитика` — строка 200 + `Номенклатура` +
`ФизическиеЛица`, `НоменклатураНаименование` — строка 150. Меняете типы в регистре — правьте и здесь,
иначе `Загрузить(ТЗДвижений)` порежет значения молча.

## 8. Что вычищено от донора `А_ФинРез_PL`
