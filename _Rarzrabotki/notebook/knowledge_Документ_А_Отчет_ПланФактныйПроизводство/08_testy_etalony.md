## Два допуска, которые НЕ являются дефектом

🔴 **`ВиконанняЧасы` и `ФактКол` не совпадут с рабочим отчётом** — он округляет их построчно
до 2 знаков (`Число(18,2)` в его таблице значений). Правильные значения:
`СебестоимостьТоваров.Количество` = 218 575,249 (отчёт даёт 218 575,310),
`А_ВыполнениеРаботМодулей.ЧасыВыполнение` = 3 930,958 (отчёт даёт 3 931,00).
Эталон по этим двум — **первоисточник**.

🔴 **ETC при узком периоде не равен «отчётному»** — в новом контуре он фиксируется на дату
снимка, а рабочий отчёт пересчитывал его под окно. Сверять ETC только на **полном** периоде.

## Инварианты вместо абсолютных чисел

Абсолютные суммы дрейфуют вместе с данными. Стабильно проверяемое:

* количество строк витрины == количество записей регистра 1С;
* все 8 ресурсов SQL == 1С до копейки;
* 0 FK-сирот по 8 связям;
* 0 строк вне диапазона Calendar, `Period` в человеческом году (не 4026);
* повторное проведение документов не меняет ни одного числа;
* при сужении периода План/ПланКол/ПланГрн/ETC **не меняются**, Факт и Виконання **уменьшаются**;
* `А_ОтчетPL_Свод` — ровно один регистратор и 56 692 записи (PL-контур не задет).
