# 08. Проверка цифр — без неё письмо не отправляется

**★★ Обязательный этап.** Письмо читает директор, у него на руках те же приложения. Любое
расхождение обесценивает весь документ.

## Правило номер один

**Каждая цифра письма сверяется с отчётом-источником программно (openpyxl), а не глазами.**
После сборки письма прогоняется скрипт-сверка: он вытаскивает значения из xlsx и проверяет, что
именно эти строки присутствуют в HTML.

Что проверять всегда:

- итоги: план СС, план на факт, экономия и её процент;
- каждая строка ТОП-7 экономии и ТОП-7 перерасхода + суммы «Разом ТОП-7» и их доли;
- все позиции вне сметы и их итог;
- по работам: табель, виконання, відхилення, проценты;
- динамика: значения прошлой недели, разницы, «п.п.»;
- что **старых чисел не осталось** в тексте после обновления.

## Правило номер два: сальдо должно сходиться

Экономия = сумма снижений − сумма превышений. Если не сходится — где-то взяты позиции из другого
среза отчёта. Пример проверки (05.08): 1 101 583,27 − 467 876,50 = 633 706,77 ✔.

## Ловушка округления

Сумма округлённых слагаемых может не совпасть с итогом.

Реальный случай (доклад 10.08): в тексте стояли округлённые затраты 322 248 + 5 244 + 3 354 = 330 846,
а итог в отчёте — 330 845. Разница в 1 грн заметна директору.
**Решение:** в тексте давать точные значения (322 247,95 / 5 243,53 / 3 353,52).

Второй случай (письмо про EV): сумма строк табличной части документов 1 095,63 против оборотов
регистра 1 095,61 — разная точность хранения. **Итог всегда сверять по отчёту**, а не по документам.

## Ловушка перевыпуска отчётов

Отчёты переформировывают, и файлы в папке меняются задним числом.

- 05.08: файлы были перевыпущены — экономия 626 416,93 → 633 706,77, виконання 1 796,50 → 1 976,50.
- 10.08: пришли деньги ОРІЛЬ 391 440,55 — поменялся и финотчёт, и план-факт.

**Перед письмом:** проверить дату изменения файлов и, если они свежее прошлого прогона, пересчитать
всё письмо целиком, а не точечно.

## Что делать с собственными расчётами

Цифры, которых в отчёте нет (итог «ожидаем», сумма лимитов, доля ТОП-7), — считать можно, но:

1. пометить пользователю: «эту строку посчитал я, в отчёте её нет»;
2. предложить убрать;
3. проверить арифметику отдельно.

## Чек-лист перед отправкой

- [ ] все суммы совпали с отчётом (скрипт-сверка пройдена);
- [ ] сальдо экономии сходится;
- [ ] проценты пересчитаны и совпадают с отчётными;
- [ ] в тексте нет чисел из прошлой недели;
- [ ] округления в тексте не конфликтуют с итогом;
- [ ] дата в заголовке = дата отчётов;
- [ ] собственные итоги отмечены пользователю;
- [ ] печать — один лист.

## Где лежат скрипты-сверки

Разовые скрипты этой практики — в `_Rarzrabotki/Python/test/` и рабочем scratchpad сессии

## Автоконтроли генератора (с 21.08.2026)

`pismo_generator.py` не пишет файл, пока не сойдутся шесть проверок. Если письмо собирается
руками — прогнать их так же:

| Контроль | Условие |
|---|---|
| Факторы | ціновий + кількісний = відхилення прогнозу, невязка ≤ 0,02 |
| Состав количественного | поза кошторисом + понад план = кількісний фактор |
| Полнота недельного разбора | сумма дельт по позициям = изменение «План на факт» |
| Этапы | сумма выполнения по этапам = «Виконання, год» из шапки |
| Запрещённая фраза | «тенденція позитивна» отсутствует |
| Жаргон | «освоєно» отсутствует |

Замеры 19.08.2026: факторы −1 381 874,19 + 800 709,23 = −581 164,97; дельты +90 321,65;
этапы 2 952,63.

**Проверка метода на прошлой неделе остаётся обязательной**: прогон по файлам 12.08 обязан
дать числа отправленного письма — ТОП-7 экономии 708 003,17, ТОП-7 перерасхода 298 878,54,
поза кошторисом 208 497,86.
