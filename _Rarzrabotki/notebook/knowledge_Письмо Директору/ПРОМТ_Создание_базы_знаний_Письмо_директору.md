## Цель

Собрать базу знаний, по которой ИИ (или новый экономист) **без переизобретения** сможет:

1. написать директору **еженедельное письмо** по отчётам план-факт (материалы + работы);
2. **прокомментировать отчёт** — объяснить, что означает показатель, откуда цифра, почему она такая;
3. **ответить на вопросы директора** по письму;
4. сделать **доклад по производству** — шпаргалку для зачитывания вслух.

Критерий успеха: получив новые выгрузки отчётов, ИИ по этой базе делает письмо **с первого раза
в принятом виде** — без круга правок «убери это / верни то», которые уже пройдены живьём.

## Канон, который ОБЯЗАН попасть в базу (добыт практикой, не переизобретать)

### Структура письма
- Порядок разделов: **По матеріалах → По роботах → Додатки** (задан пользователем; в первой версии
  было наоборот — переставили).
- Приложения — **два файла отчётов**, они и есть детализация; в письме её не дублировать.
- Язык писем — **украинский**, доклада — **русский** (по языку источника).

### Показатели и терминология
- **«Освоєно» — жаргон, в письме не употреблять.** Правильно: **«виконано робіт у нормо-годинах»**,
  в отчёте это колонка **«Виконання, год»**.
- Не путать два процента: **«% виконання до факту» = Виконання / Факт (табель)**;
  **«% вик. (год)» = Факт / План**. Готовность проекта = Виконання / План.
- «Переліміт по годинах» = Факт − Виконання; в % считается **от табеля**.
- Формула для объяснения: `Виконано, год = норма годин на будинок × % виконання` (по каждому дому).
- «План на факт» = прогноз затрат материалов; экономия = План СС − План на факт.

### Что НЕ писать (проверено правками)
- ❌ счётчики позиций («по 58 позиціях отримано зниження…, по 50 позиціях — перевитрата») — убрано;
- ❌ строку «План СС» в таблице динамики — он не меняется;
- ❌ аналитические врезки-выводы («Наибольшая сумма к получению — …, поэтому не включается»),
  если пользователь просит только констатацию;
- ❌ то, что пользователь просил не подсвечивать (пример: разрез объекта 30 м);
- ❌ собственные допущения и трактовки цифр — «строго как в отчётах».

### Тактичность (письмо читает директор производства)
- Перерасход: показывать таблицей, но формулировать как рабочий вопрос —
  *«найімовірніше це заміна матеріалу або уточнення обсягів; прошу коротко прокоментувати причину»*.
- Позиции вне сметы: *«це не зауваження до роботи — такі позиції з'являються, коли проєкт уточнюють
  уже на виробництві… прошу внести до кошторису, щоб звіт не показував їх як перевитрату»*.
- Если попросили убрать просьбу — оставить **только сумму-констатацию** + таблицу позиций.
- Никаких имён и оценок работы людей.

### Динамика недели (обязательный блок с 05.08)
- Таблица «Показник | прошлая дата | текущая дата | Зміна за тиждень».
- Отдельно «Что дало изменение»: позиции-драйверы улучшения и ухудшения с суммой влияния.
- По работам показывать связку: прирост выполнения против прироста табеля — это и есть вывод
  («виконання зростає швидше за списання → переліміт скоротився»).

### Ответы на вопросы директора
- Отвечать **по одному вопросу — один блок**, заголовком повторять сам вопрос.
- Если термин был неудачный — **мягко признать**: *«перепрошую за формулювання — це професійний
  жаргон, і в листі я вжив його некоректно»*, затем дать правильный.
- Подкреплять примером расчёта из приложенного отчёта (норма × % = часы).
- Указывать источник данных: документ-табель (номер, дата, период), дату среза.

### Доклад по производству
- Источник текста — **docx пользователя**, формулировки переносить дословно.
- Формат: **текст-шпаргалка для зачитывания** (строка на объект) **+ таблица под ним**.
- Ключевые суммы — крупно/жирно; «ожидаем» — зелёным, «не ожидаем» — красным.
- Один лист А4, печать книжная.

### Проверка цифр (без этого письмо не отправляется)
- Каждая сумма — **сверена с отчётом-источником** скриптом (openpyxl), а не глазами.
- Итоги, которые считает ИИ (например «Итого ожидаем»), — **помечать пользователю** и предлагать убрать.
- ⚠️ Округления: сумма округлённых слагаемых может не сойтись с итогом (было 330 846 против 330 845) —
  тогда в тексте давать **точные** значения.
- ⚠️ Отчёты **перевыпускают**: перед письмом сверять дату файла и пересчитывать (было: ОРІЛЬ 391 440
  перешёл из «ожидаем» в «получено», поступления 1 317 348,7 → 1 708 789,25).

## Требования к качеству базы

1. Каждый факт — **со ссылкой на файл-источник** (путь + что именно там смотреть).

5. Файлы ≤ 25 КБ, без код-блоков (правило NotebookLM).
