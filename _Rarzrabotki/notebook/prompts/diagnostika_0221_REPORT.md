## 1. Симптом (подтверждён)

Забаланс **0221**: количество по номенклатуре списывается в 0, а **сумма (БО) остаётся**. На 2026-07-13 — **67 позиций** «Кол = 0 и Сумма ≠ 0» (на 30.06 — 66). Пример из промта воспроизведён 1:1: «Біта РZ 2*50 мм», Склад «ІС Цех МШП ПРООН», Контрагент «ІНДАСТРІАЛБУД» → приход 341 ед / 24 536,93; расход 341 ед / 23 988,13; **резидуум 548,80 при 0 ед**.

Регистр `Хозрасчетный`: ресурсы **Сумма и Количество независимы** — поэтому Кол=0 при Сумма≠0 технически возможно.

---

## 2. ПОДТВЕРЖДЁННЫЙ ROOT-CAUSE

**Структурный дисбаланс двух систем оценки на суммовом забалансовом счёте 0221:**
приход считается по **суммовой цене документа**, а расход — по **партионной стоимости из отдельного регистра**, не синхронизированного 1:1 с суммой на самом счёте. Количество сходится (Σприход = Σрасход), сумма — нет.

### Механизм по коду (`_Rarzrabotki/BASEBuh/`)

**Приход Дт 0221** — `ПоступлениеТоваровУслуг` (суммовой): каждый приход дебетует 0221 на сумму своей строки ТЧ. Цена/ед по одной и той же номенклатуре скачет (для «Біта»: 8,43 … 71 … 352 … 556 за ед).

**Расход Кт 0221** — все расходные документы делегируют в
`CommonModules/УправлениеЗапасамиПартионныйУчет/Ext/Module.bsl`:
- `ДвижениеПартийТоваров` (стр. 7) → `СписаниеСоСклада` (стр. 41);
- цикл гашения управляется **КОЛИЧЕСТВОМ**: `КоличествоОсталосьПогасить = Окр(СтрокаДокумента.Количество,3,1)` (стр. **64**);
- сумма проводки = **партионная стоимость**: при `Себестоимость = 0` (расходные докы её не заполняют) `Стоимость = Окр(СтрокаПартии.Стоимость × КоэффСписания, 2, 1)` (стр. **195-196**), `КоэффСписания = Кол/ОстатокПартии` (стр. 187);
- забалансовая проводка **односторонняя Кт 0221**: `Проводка.СчетКт = СчетУчета` (стр. 227), `Проводка.Сумма = Стоимость` (стр. **259**); ветка `СчетДт` не ставится, т.к. корсчёт балансовый ≠ забалансовый (стр. 230);
- источник `СтрокаПартии.Стоимость` — дерево `ДеревоПартийТоваровНаСкладахБух` (стр. 44), т.е. **партионный регистр**, а не остаток счёта 0221.

Поскольку база оценки прихода (цена документа) и расхода (партионная стоимость + округление `Окр(…,2,1)` на каждом движении) не совпадают, при полном списании количества остаётся разница суммы. Для «Біта»: 24 536,93 − 23 988,13 = **548,80** (2,2% — это не округление, а расхождение баз).

### Почему эталонный МШП-механизм резидуума НЕ даёт (контраст)

`CommonModules/ПроцедурыМалоценныеАктивы/Ext/Module.bsl` (счёт `МЦ`) берёт стоимость **из остатка ТОГО ЖЕ счёта**: `ХозрасчетныйОстатки.СуммаОстатокДт КАК Стоимость` (стр. **628**), а коэффициент — по количеству того же остатка (`ПроизвестиСписаниеМалоценныхАктивов`, стр. 500-507, `СуммаПроводки = КоэфСписания × Стоимость`, стр. 300). При полном количестве коэф=1 → списывается вся сумма остатка → **самореконсиляция, резидуума нет**.

Ключевая разница: эталон читает стоимость **из самого счёта**, а `СписаниеСоСклада` — **из стороннего партионного регистра**. Поэтому на 0221 расход не обнуляет сумму счёта.

## 5. Рекомендации

### 5.1 Чтобы не оставлять резидуум впредь
Проблема **структурная** (суммовой забаланс + партионное списание из стороннего регистра), а не «баг возврата». Отсюда:

- **(A) Регламент + обработка закрытия [рекомендуется немедленно].** Периодически (при закрытии периода) прогонять обработку, которая берёт все триплеты 0221 «Кол=0, Сумма≠0» и формирует корректирующую `ОперациюБух`. Типовую не трогает.
- **(B) Архитектурный фикс по образцу эталона.** При списании последней единицы триплета брать сумму не из партионного регистра, а из **остатка суммы самого 0221** (как `ПроцедурыМалоценныеАктивы`, Module.bsl:628) → самореконсиляция. Только **расширением/подпиской** на `СписаниеСоСклада` или пост-обработкой движений, с разрешения (Rule про типовые объекты).
- **(C) Убрать суммовой учёт на 0221,** если счёт нужен лишь для количественного контроля материалов у контрагента/на складе. Метаданно-учётное решение, согласовать.
- ❌ Вариант промта «патчить `ВозвратТоваровПоставщику` под балансовую стоимость» — **отклонить**: возврат уже списывает по партионной стоимости и даёт лишь 5,5% расхода; дрейф от Требования (78%) это не устранит.

### 5.2 Закрыть текущие 67
- `ОперацияБух` по каждому триплету: Организация + субконто **точно** Контрагент/Номенклатура/Склад как в остатке; Количество = 0; для +резидуума — Кт 0221 на сумму, для −резидуума — Дт 0221 на модуль; корсчёт — по методике заказчика (прочие расходы/доходы или технический).
- ⚠️ **Субконто должно совпадать 1:1** — иначе создаётся зеркальный резидуум (урок «Кухни»). Зеркальные ±пары сначала свести (одна пара = один дрейф), затем закрывать нетто.
- Оптимально — одна обработка, читающая перечень §4 и формирующая проводки автоматически по точным триплетам.
- Дату и корсчёт согласовать (влияние на учёт); без согласования не проводить (§8 промта).
