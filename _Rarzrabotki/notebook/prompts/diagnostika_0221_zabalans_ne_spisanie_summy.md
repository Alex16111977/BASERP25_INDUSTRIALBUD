## 1. СИМПТОМ
Забалансовий рахунок **0221** («Малоцінні активи в експлуатації», суб-рахунок 022; кількісно-сумовий, забалансовий, 3 субконто: Номенклатура / Контрагенти / Склади). По номенклатурі **кількість списується повністю (напр. 23→0), а СУМА (БО) лишається** (напр. **548,80 при 0 од**).

Приклад зі скриншота (ОСВ 0221 за червень 2026, ТОВ «ІНДЕПТ СТІЛ», Номенклатура «Біта PZ 2*50 мм», Склад «ІС Цех МШП ПРООН», Контрагент «ІНДАСТРІАЛБУД ТОВ»):

- У ширшому вікні (весь рух по цій номенклатурі): прихід 0221 = **24 536,93 / 341 од**, списання = **23 988,13 / 341 од** → резидуум **548,80 / 0**.

## 2. ПІДТВЕРДЖЕНИЙ ROOT-CAUSE (перевірити самостійно, §4)
**Документ `ВозвратТоваровПоставщику` списує МШП із забалансу 0221 за ЦІНОЮ ПОВЕРНЕННЯ, а не за балансовою вартістю МШП на 0221.** Тому при повному списанні кількості сума-різниця (балансова − повернена) осідає на 0221 без кількості.

Механізм (точні файли/процедури — `BASEBuh\`):
- `Documents\ВозвратТоваровПоставщику\Ext\ObjectModule.bsl`:
  - `ПодготовитьТаблицуТоваров` (~р.349-485): формує рядок списання `СчетУчетаБУ=0221`, **`Себестоимость=0`**, `Сумма=ціна повернення`, **`СписыватьПоУказаннойСтоимости=Ложь`** (~р.448). `ЗаполнитьТоварыПоОснованию` (~р.20-103) копіює Кількість/Ціну/Суму/Счет з поступлення, але `Себестоимость` НЕ заповнює.
  - `ДвиженияПоРегистрам` (~р.564-840): для звичайного повернення (гілка «Иначе», ~р.835-838) **делегує списання** у типовий `УправлениеЗапасамиПартионныйУчет.ДвижениеПартийТоваров(...)`. Власного руху Кт 0221 не пише.
- `CommonModules\УправлениеЗапасамиПартионныйУчет\Ext\Module.bsl`:
  - `ВыполнитьСписание` (~р.534-767) → `СписаниеСоСклада` (~р.41-529): створює **односторонню** проводку **Кт 0221** (~р.223-259; `СчетДт` не ставиться, бо кор-рахунок балансовий ≠ забалансовий). Гасіння партій керується **КІЛЬКІСТЮ** (`КоличествоОсталосьПогасить`) — цикл спиняється по вичерпанню кількості. `Проводка.Сумма = Стоимость`, а `Стоимость` при `Себестоимость=0 / СписыватьПоУказаннойСтоимости=Ложь` = **сумі рядка ТЧ (ціна повернення)**.
- **Наслідок:** сума руху Кт 0221 = сумі рядка повернення, а не балансовій вартості залишку 0221. Кількість → 0, різниця лишається сумою.

**Як мало б бути (еталон):** `CommonModules\ПроцедурыМалоценныеАктивы\Ext\Module.bsl` — канонічне списання МШП із 0221 **за Партією/балансовою вартістю**: `СуммаПроводки = КоэфСписання × Стоимость_залишку`, де `КоэфСписання = ОсталосьСписать / Остаток` (за кількістю). При повному списанні кількості коеф=1 → списується вся балансова `Стоимость` → **резидууму бути не може**. Цей модуль викликають лише 3 документи: `СписаниеМалоценныхАктивовИзЭксплуатации`, `ПеремещениеМалоценныхАктивовВЭксплуатации`, `ПередачаМалоценныхАктивовВЭксплуатацию`. **`ВозвратТоваровПоставщику` його НЕ викликає** — звідси дефект.

## 5. ЗАГАЛЬНА ДІАГНОСТИКА — перелік усіх залишків (Python COM, Rule #-1)
```python

if sys.stdout.encoding != 'utf-8':
    sys.stdout.reconfigure(encoding='utf-8')
v8 = win32com.client.Dispatch("V83.COMConnector")

# ПІДТВЕРДИТИ порядок субконто: счет.ВидыСубконто -> Номенклатура/Контрагенти/Склади
q = buh.NewObject("Запрос")
q.Текст = """
ВЫБРАТЬ
    Ост.Субконто1 КАК Субконто1,
    Ост.Субконто2 КАК Субконто2,
    Ост.Субконто3 КАК Субконто3,
    Ост.СуммаОстатокДт КАК Сумма,
    Ост.КоличествоОстатокДт КАК Количество
ИЗ РегистрБухгалтерии.Хозрасчетный.Остатки(&НаДату, Счет = &Счет) КАК Ост
ГДЕ Ост.КоличествоОстатокДт = 0 И Ост.СуммаОстатокДт <> 0
УПОРЯДОЧИТЬ ПО Сумма УБЫВ
"""
q.УстановитьПараметр("Счет", счет)
q.УстановитьПараметр("НаДату", datetime.datetime(2026, 6, 30, 23, 59, 59))
try:
    r = q.Выполнить().Выгрузить()
    print(f"Зависань 0221 (Кіл=0, Сума<>0): {r.Количество()}")
    итого = 0
    for i in range(r.Количество()):
        s = r.Получить(i)
        итого += float(s.Сумма)
        if i < 30:
            print(f"  {s.Субконто1} | {s.Субконто2} | {s.Субконто3} -> {s.Сумма}")
    print(f"Сума резидуумів: {итого}")
except Exception as e:
    print("FAIL:", e.excepinfo[2] if hasattr(e,'excepinfo') and e.excepinfo else e)
```

## 6. РЕКОМЕНДАЦІЯ ВИПРАВЛЕННЯ (дві частини)

### 6.1 На майбутнє (щоб повернення не лишало резидуум)
Проблема концептуальна: **повернення постачальнику — не правильний спосіб знімати МШП із експлуатації.** Варіанти (обрати за узгодженням із замовником):
- **(A, організаційний, без коду):** перед поверненням постачальнику робити `СписаниеМалоценныхАктивовИзЭксплуатации` (знімає 0221 за балансовою вартістю → 0/0), а повернення оформляти вже з балансового рахунку запасів. Найбезпечніше, без правок типової.
- **(B, патч проведення):** у `ВозвратТоваровПоставщику` для рядків зі `СчетУчетаБУ` = забалансовий МШП (0221) списувати за балансовою вартістю залишку 0221 (виставляти `Себестоимость`/`СписыватьПоУказаннойСтоимости=Истина` з `Хозрасчетный.Остатки(0221, Субконто=Партія).СуммаОстатокДт/КоличествоОстаток`, або викликати `ПроцедурыМалоценныеАктивы`). ⚠️ Зміна типової конфігурації — лише з дозволу; краще розширенням/підпискою.
- Оцінити плюси/мінуси кожного, дати рекомендований.

### 6.2 Закрити наявні ~67 залишків
- Сформувати документ **`ОперацияБух`** (ручна операція) з рухами **Кт 0221** на суму кожного резидууму у розрізі його субконто (Номенклатура/Контрагент/Склад/Партія), кількість = 0 → обнуляє «мертву» суму. Кор-рахунок Дт — за методикою замовника (напр. рахунок витрат/іншого списання; узгодити).
- Або одна обробка, що масово формує такі коригувальні рухи по всьому переліку §5.
