Итог: отчёт «Сверка ЕРП(Форма1) vs Бух 661/663» по каждому (ФЛ × юр.лицо) = 0.

## 3. Корневая причина
- «Зарплата управл» Ф1 `ОрганизацияБухгалтерия` берётся из Казны (`РаспределениеКазна.ДокРаспределениеЗП.Организация`) — **корректно**.
- Но **НДФЛ/ВС теряют организацию**: `_ОтрЗП_ЗаполнитьНДФЛИзНалогов` разносит НДФЛ по ПОДРАЗДЕЛЕНИЯМ (Казна) и для multi-org ФЛ сваливает на подразделение «ЦО», а `_ОтрЗП_ЗаполнитьСтрокуНДФЛ` ставит `Организация = шапка документа`. Точный per-org из `НалогиБухгалтерия.Организация` игнорируется.
- gross-up «Удержание» Ф1 (= НДФЛ, добавленный обратно для расчёта take-home в движении) у multi-org ФЛ садится на ОДНО юр.лицо.
- В движении А_ВзСС «Оплата труда»: `НачисленнаяЗарплата(«Зарплата управл»+«Удержание») − НачисленныйНДФЛ`, агрегировано по `ОрганизацияБухгалтерия`. Т.к. «Удержание» и НДФЛ на РАЗНЫХ юр.лицах — по юр.лицу не гасятся → разлёт = НДФЛ+ВС.

## 4. Новый алгоритм (подтверждён бухгалтером — ЯВНО по организации)

**Принцип:** НДФЛ/ВС закреплены за юр.лицом из `НалогиБухгалтерия.Организация`. Это юр.лицо проходит сквозняком до баланса. «Зарплата управл» НЕ трогать (она уже верна).

| # | Поле | Что заполнять |
|---|---|---|
| 1 | `А_ОтражениеЗПпоКазне.НачисленныйНДФЛ.ОрганизацияБухгалтерия` (поле уже добавлено пользователем; проверить, что есть в метаданных) | `= НалогиБухгалтерия.Организация` строки-источника |
| 2 | gross-up «Удержание» Ф1 (`НачисленнаяЗарплата`, А_ЭтоУдержание) | `ОрганизацияБухгалтерия` = та же, что у НДФЛ (per юр.лицо) |
| 3 | `ОтражениеЗарплатыВФинансовомУчете.НачисленныйНДФЛ.ОрганизацияБухгалтерия` (типовое поле) | копировать из п.1 при создании ОЗФУ |
| 4 | `А_ПередачаНачисленийМеждуПодразделениями.Налоги.ОрганизацияБухгалтерия` | брать из `НачисленныйНДФЛ.ОрганизацияБухгалтерия` (не из «первой ОргБух физлица») |

**Контроль (Воронцов):** по каждому юр.лицу `ЗПупр + Удержание − НДФЛ = выплата → 0`:
ДЖИ ТРИ 15 746,50 + 4 703,50 − 4 703,50 = 15 746,50 = выплата → **0**; ІНД 123 200 + 36 800 − 36 800 = 123 200 → **0**.

## 5. Карта кода (`Documents/А_ОтражениеЗПпоКазне/Ext/ObjectModule.bsl`)
- `_ОтрЗП_ЗаполнитьНДФЛИзНалогов` (~2221) → строки НДФЛ/ВС из `НалогиБухгалтерия` (поле `Организация` есть в ТЧ!).
- `_ОтрЗП_ЗаполнитьСтрокуНДФЛ(НоваяСтрока, СтрокаНалога, Сумма, Подразделение, СпособОтражения, ВидОперации, ТипНалога, Справочные)` (~2282) → **сюда добавить присвоение ОргБух**.
- `_ОтрЗП_ВыровнятьУдержаниеСНДФЛ` (~2312) → выравнивает «Удержание»↔НДФЛ; сейчас ключ **(ФЛ, Подразделение)** → сделать **(ФЛ, Подразделение, ОрганизацияБухгалтерия)** и проставлять ОргБух у пересозданных «Удержание».
- `СоздатьДокументОтражениеЗарплатыВФинансовомУчете` (~3140) → копирование ТЧ `НачисленныйНДФЛ` в ОЗФУ (проверить, что `ОрганизацияБухгалтерия` копируется; если через `ЗаполнитьЗначенияСвойств` — копируется авто при совпадении имён полей).
- `_ПНМП_ЗаполнитьНалоги(Док, СотрудникПоФЛ, ОргБухПоФЛ)` (~3960) и `_ПНМП_ПостроитьОргБухПоФЛ` (~3793, берёт ПЕРВУЮ ОргБух на ФЛ) → для НДФЛ-строк брать `Стр.ОрганизацияБухгалтерия` из `НачисленныйНДФЛ`, не из мапы «первой орг».
- ⚠️ **Ключевой enabler:** заполнитель движения `РегистрНакопления.А_ВзаиморасчетыССотрудниками` от ОЗФУ (Форма1 «Оплата труда»). **Подтвердить, что `ОрганизацияБухгалтерия` для НДФЛ-вычета берётся из `НачисленныйНДФЛ.ОрганизацияБухгалтерия`.** Если типовой/кастомный заполнитель берёт `Организация` (шапку) — это тоже часть фикса. Найти через поиск создания движений А_ВзСС.

## 7. Реализация (точные правки BSL — каждую сперва прогнать логикой через Python COM)
1. **`_ОтрЗП_ЗаполнитьСтрокуНДФЛ`**: добавить
   `НоваяСтрока.ОрганизацияБухгалтерия = ?(ЗначениеЗаполнено(СтрокаНалога.Организация), СтрокаНалога.Организация, Организация);`
2. **`_ОтрЗП_ВыровнятьУдержаниеСНДФЛ`**: агрегировать `НачисленныйНДФЛ` Ф1 по ключу `(ФЛ | Подразделение | ОрганизацияБухгалтерия)`; при пересоздании «Удержание»-строк ставить `НовСтр.ОрганизацияБухгалтерия` из ключа НДФЛ. (Σ per ФЛ сохраняется.)
3. **`СоздатьДокументОтражениеЗарплатыВФинансовомУчете`**: гарантировать копирование `ОрганизацияБухгалтерия` в `ОЗФУ.НачисленныйНДФЛ`.
4. **`_ПНМП_ЗаполнитьНалоги`**: для НДФЛ-строк `ОрганизацияБухгалтерия = Стр.ОрганизацияБухгалтерия` (из `НачисленныйНДФЛ`); ЕСВ-строки — из `НачисленнаяЗарплата.ОрганизацияБухгалтерия`. Убрать использование «первой ОргБух» для налогов.
5. Если §5 ⚠️ показал, что движение А_ВзСС НДФЛ берёт ОргБух не из `НачисленныйНДФЛ.ОрганизацияБухгалтерия` — поправить заполнитель движения.

**После правок:** скопировать `ObjectModule.bsl` (и метаданные, если меняли) в основную конфигурацию (если работа в worktree); `/db-load-xml -Mode Partial` (включить `Documents/А_ОтражениеЗПпоКазне.xml` + `Ext/ObjectModule.bsl`) + `/db-update -Dynamic+`.

## 10. Грабли
- Python COM: перечисления через `erp.XMLСтрока`, пустые ссылки `erp.ЗначениеЗаполнено`; `str()` от enum = `<COMObject>` (ложно «пусто»).
- `НалогиБухгалтерия` использует измерение **`Сотрудник`** (не ФизическоеЛицо) + поле **`Организация`** (это per-org источник). `НачисленныйНДФЛ` использует `ФизическоеЛицо` + теперь `ОрганизацияБухгалтерия`.
- **«Зарплата управл» ОргБух НЕ трогать** — она уже верна (из Казны).
- НДФЛ **И** «Удержание» — ОБА должны лечь на per-org, иначе по юр.лицу не сойдётся.
- Не сломать фикс Op2b (Op2b ветка идёт через `_ОтрЗП_СоздатьСтрокиNETФЛ_Новый`).
- `/db-load-xml` должен включить XML метаданных (новое поле `НачисленныйНДФЛ.ОрганизацияБухгалтерия`), не только `.bsl`.
- Перепроведение ОЗФУ/ПередачаНач — только UI (COM задваивает ТЧ ОЗФУ).
