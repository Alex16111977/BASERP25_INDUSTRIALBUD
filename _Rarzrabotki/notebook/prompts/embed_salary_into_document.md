Мені потрібно встроїти логіку імпорту зарплати з зовнішніх обробок прямо в документ НачислениеЗарплаты. Зараз це працює через зовнішні обробки — треба перенести в модуль об'єкта документа як процедуру ЗаполнитьНачисленияИзБазЗП() Экспорт.

ОБОВ'ЯЗКОВО спочатку проконсультуйся з NotebookLM (notebook_id="3303acdb-2d7f-4879-9f13-78705ab3fb8c"):

1. Запитай: "Як працюють 4 обробки зарплати (ЗаполнениеНачисленійЗП, Загрузити начисления из зп упр, Обновити начисления по бух данным, Заповнити ОтражениеЗП)? Яка логіка заповнення ТЧ А_Начисления, А_Удержания, А_НачисленияБух? Як потім з них заповнюється основна ТЧ Начисления?"

2. Запитай: "Яка різниця між zup_1 (регламентна ЗП, ОсновныеНачисленияРаботниковОрганизаций) та zup_2 (управлінська ЗП, НачислениеЗарплатыРаботникам)? Які поля доступні в кожній базі?"

3. Запитай: "Які критичні правила при COM-підключенні до ЗУП баз? Дати як datetime, маппінг по КодПоДРФО, серіалізація?"

Якщо NotebookLM не знає деталей — прочитай знання з _Rarzrabotki/notebook/knowledge/payroll_architecture.md напряму.

Потім вивчи код обох обробок-джерел:
1. _Rarzrabotki/Обработки/Загрузить начисления из зп упр/Forms/Форма/Ext/Form/Module.bsl — НАЙКРАЩА обробка, вже має повну логіку:
   - Етап 1: COM до zup_2 → А_Начисления + А_Удержания (детальні)
   - Етап 2: А_Начисления → Начисления (основна ТЧ) через А_НайтиСотрудникаПоФизЛицу + А_НайтиВидРасчетаПоКоду
   - Етап 3: А_НачисленияБух → Начисления (ТІЛЬКИ ФізОсоби яких НЕМАЄ в А_Начисления, суммуючи по ФізЛіцо)
   - Також заповнює ТЧ Удержания + ФизическиеЛица

2. _Rarzrabotki/Обработки/ЗаполнениеНачисленийЗП/Forms/Форма/Ext/Form/Module.bsl — заповнює ТІЛЬКИ А_НачисленияБух з zup_1 (регламентна)

Логіка процедури ЗаполнитьНачисленияИзБазЗП() Экспорт:

ФАЗА 1 — Завантаження з zup_2 (управлінська ЗП):
  1.1. COM-підключення до zup_2 (Srvr="SQLSERVER";Ref="zup_2";Usr="cfo";Pwd="2442")
  1.2. Запит до Документ.НачислениеЗарплатыРаботникам.Начисления (ВСІ за місяць)
  1.3. Запит до Документ.НачислениеЗарплатыРаботникам.Удержания (ВСІ за місяць)
  1.4. Маппінг ФізОсоба по КодПоДРФО через Соответствие (кеш!)
  1.5. Заповнення А_Начисления + А_Удержания

ФАЗА 2 — Завантаження з zup_1 (регламентна ЗП):
  2.1. COM-підключення до zup_1 (Srvr="SQLSERVER";Ref="zup_1";Usr="cfo";Pwd="2442")
  2.2. Запит до РегистрРасчета.ОсновныеНачисленияРаботниковОрганизаций (фільтр: ВидРасчета.Код <> "00021", А_ВБалансе=Істина)
  2.3. Маппінг Організація по КодПоЕДРПОУ, ФізОсоба по КодПоДРФО (через Справочник.ФизическиеЛица.НайтиПоРеквизиту)
  2.4. Заповнення А_НачисленияБух

ФАЗА 3 — Переніс в основні ТЧ:
  3.1. Очистити Начисления, Удержания, ФизическиеЛица
  3.2. Зібрати набір ФізОсіб з А_Начисления (для виключення дублів)
  3.3. А_Начисления → Начисления (кожен рядок, з Сотрудник = А_НайтиСотрудникаПоФизЛицу, Начисление = А_НайтиВидРасчетаПоКоду)
  3.4. А_НачисленияБух → Начисления (ТІЛЬКИ ФізОсоби яких НЕМАЄ в А_Начисления! Суммувати по ФізЛіцо по організаціях!)
  3.5. А_Удержания → Удержания
  3.6. Заповнити ФизическиеЛица (унікальні)
  3.7. Встановити шапку: Организация, МесяцНачисления, ПорядокВыплаты = Зарплата

Файл для зміни: Documents/НачислениеЗарплаты/Ext/ObjectModule.bsl

ПЕРЕД написанням коду:
1. Спершу Python тест — перевір що COM до zup_1 і zup_2 працює і повертає дані за потрібний місяць
2. Перевір що процедури А_НайтиСотрудникаПоФизЛицу та А_НайтиВидРасчетаПоКоду існують в А_Привилегированный
3. Перевір структуру ТЧ Начисления через get_metadata_structure

КРИТИЧНО:
- Дати передавати як datetime в Python тестах (НЕ рядки!)
- НЕ серіалізувати COM-таблиці через ЗначениеВСтрокуВнутр для zup_2 — ітерувати напряму (структури даних через масив)
- Для zup_1 серіалізація OK (там примітивні типи)
- Підрозділ ОБОВ'ЯЗКОВИЙ — без нього управлінський баланс ламається
- А_Обработан = Истина, А_ВведенВЕРП = Истина — якщо документ має ці прапорці
- Кеш ФізОсіб через Соответствие (НЕ НайтиПоРеквизиту в циклі — повільно!)
