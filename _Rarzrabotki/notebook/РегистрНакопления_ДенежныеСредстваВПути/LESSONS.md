## ⭐ Архитектурное правило

**Подразделение для движения в РНДС.ВПути берётся ИЗ ШАПКИ ДОКУМЕНТА:**
```sql
ДанныеДокумента.Подразделение  КАК Подразделение
```

**Не** из `Касса.Подразделение` / `БанковскийСчет.Подразделение` — это текущее значение реквизита, а не историческое на момент проводки. Правильный паттерн — взять из шапки, по аналогии с РНДС.Наличные (`Documents/ПриходныйКассовыйОрдер/Ext/ManagerModule.bsl:1599-1675`).

## SQL-особенности 1С

### ❌ НЕ работает: подзапрос в SELECT
```sql
ВЫБРАТЬ
    ...,
    (ВЫБРАТЬ ПЕРВЫЕ 1 Д.Подразделение ИЗ Документ.ПостБезнал КАК Д ГДЕ Д.Ссылка = &Ссылка) КАК Подразделение,
    ...
```
Даёт ошибку «Синтаксическая ошибка ВЫБРАТЬ».

### ✅ Альтернативы
- **Колонка в ВТ:** если есть `ПОМЕСТИТЬ ВтТаблица` — добавить нужное поле в её SELECT. Тогда снаружи `ВтТаблица.Подразделение` работает (пример: ПКО блоки 4-5 через `ТаблицаКурсовыхРазниц.Подразделение`).
- **ЛЕВОЕ СОЕДИНЕНИЕ:** тяжелее, но допустимо.
- **Параметр `&Подразделение`:** требует правки в основной процедуре проведения (где формируется пакет запросов).

### ❌ НЕ работает: `-- комментарии`
Только `//` (1С) или вообще без комментариев в передаваемом тексте запроса.

### ❌ НЕ работает: `ДАТАВРЕМЯ(y, m+1, 1, 0, 0, -1)`
Секунду -1 не парсит. Только `КОНЕЦПЕРИОДА(ДАТАВРЕМЯ(y,m,15), МЕСЯЦ)`.

## Edit-патч

### ✅ Edit с `replace_all: false`

5+3+3+8 = 19 блоков SELECT с **похожей** структурой только в 4 файлах ManagerModule. `replace_all: true` задеть соседние блоки. Уникальный контекст = WHERE с ХозОп.

### Шаблон вставки

Перед строкой `&ХозяйственнаяОперация` (или `&СтатьяДвиженияДенежныхСредств` если ХозОп нет):
```sql
|	ДанныеДокумента.Подразделение                                                КАК Подразделение,
|	&ХозяйственнаяОперация                                                       КАК ХозяйственнаяОперация,
```

Для блоков работающих с временной таблицей `ТаблицаКурсовыхРазниц` (если она содержит Подразделение):
```sql
|	ТаблицаКурсовыхРазниц.Подразделение                                          КАК Подразделение,
```

## COM-репост: безопасность

| ХозОп | РСКПС/РСППС? | COM-репост |
|---|---|---|
| Конвертация валюты | НЕТ | ✅ безопасно |
| Перечисление на другой счёт | НЕТ | ✅ безопасно |
| Поступление с другого счёта | НЕТ | ✅ безопасно |
| Инкассация ДС | НЕТ | ✅ безопасно |
| Снятие наличных ДС | НЕТ | ✅ безопасно |
| Поступление из кассы на РС | НЕТ | ✅ безопасно |
| Поступление оплаты от клиента | ДА | ⚠ ТОЛЬКО UI |
| Оплата поставщику | ДА | ⚠ ТОЛЬКО UI |
| Возврат ДС от поставщика / клиенту | ДА | ⚠ ТОЛЬКО UI |
| Поступление оплаты ПК (эквайринг) | ДА (через РасшифровкаПлатежа) | ⚠ ТОЛЬКО UI |

Memory: `feedback_com_repost_skips_registrator_raschetov` — массовое COM-перепроведение документов с РСКПС/РСППС в новой архитектуре теряет РегистраторРасчётов → парная проводка ПАП не формируется.

**В pilot_03 скриптах СписаниеБезнал/ПостБезнал** встроен safety-check: если у документа есть движения в РСКПС/РСППС — выход с STOP-кодом.

## Пакет проведения — единый

Когда ОДИН файл ManagerModule имеет синтаксическую ошибку SQL — при `db-update` загружается успешно (1С не валидирует SQL до выполнения), но при попытке провести ЛЮБОЙ документ — падает с ошибкой о синтаксисе.

Симптом: проводим СписаниеБезнал → ошибка `Синтаксическая ошибка` из текста запроса который характерен для ПостБезнал.

Объяснение: пакет запросов проведения через `ПроведениеДокументов.ВыполнитьПакет` строится из всех `ТекстЗапросаТаблица*` функций. Если ОДИН из текстов невалиден — весь пакет ломается.

**Решение:** откатить ошибочный файл из `_backup/` → перезагрузить → проверить остальные.
