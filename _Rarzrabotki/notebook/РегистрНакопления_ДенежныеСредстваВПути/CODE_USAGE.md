## Группировка источников Подразделения

### Группа A — Банк↔Касса (БС и Касса есть явно): 5 фактических документов
**Документы:** СписаниеБезнал, ПоступлениеБезнал, РКО, ПКО, ОтражениеРасхождений

**Правило:** `Подразделение = Подразделение(Отправитель)`:
- Если Отправитель — `БанковскийСчет` (наш) → `БанковскийСчет.Подразделение`
- Если Отправитель — `Касса` → `Касса.Подразделение`
- Если Отправитель = НЕОПРЕДЕЛЕНО (внешний контрагент, например в КонвертацииВалюты от Контрагента) → `Получатель.Подразделение`
- Для ОтражениеРасхождений — параметр `&Подразделение` уже передаётся.

### Группа B — Кассы ККМ (внутри подразделения): 6 документов розницы
**Документы:** ВыемкаИзККМ, ВнесениеВККМ, ЧекККМ, ЧекККМВозврат, РеализацияПодСерт, ВозвратПодСерт, ОтчётОРозничныхПродажах

**Правило:** `Подразделение = КассаККМ.Подразделение` (шапочное поле).

### Группа C — Эквайринг
**Документы:** ОтчетБанкаПоОпЭкв, ОперацияПоПК, ВводОстатковРПЭкв, ВводОстатков

**Правило:** `Подразделение` из шапки (уже есть). Если шапочного нет — `ЭквайринговыйТерминал.КассаККМ.Подразделение`.

### Группа D — Переоценка
**Документ:** РасчетКурсовыхРазниц

**Правило:** **особый** — при переоценке регистр читает свои записи и пишет в него же. Нужно извлекать Подр **из существующих записей** (через JOIN со справочниками БС/Кассы/КассыККМ) либо из новой колонки `Подразделение` самого регистра когда она появится.

## Где будет миграция данных (для существующих записей)

Все 12 ManagerModule уже регистрируют обработчик обновления:
```bsl
Обработчик.Процедура = "РегистрыНакопления.ДенежныеСредстваВПути.ОбработатьДанныеДляПереходаНаНовуюВерсию";
```

В `AccumulationRegisters/ДенежныеСредстваВПути/Ext/ManagerModule.bsl` есть эта функция (видимо template для будущих миграций). Сюда можно встроить логику массового заполнения Подразделения для существующих записей через JOIN с БС/Кассой.
