# PROGRESS — статус доработки `РегистрНакопления.ДенежныеСредстваВПути.Подразделение`

> Хронология добавления измерения `Подразделение` в типовой регистр и доработки проведений 5 фактических документов.

## Цель

В типовом регистре `РегистрНакопления.ДенежныеСредстваВПути` нет измерения `Подразделение`. Из-за этого:
- `Свод_ДенежныеСредства` (`Documents/А_ФинРез_Баланс/Ext/ObjectModule.bsl` стр. 621-845) не может агрегировать «в пути» per-Подр
- В `А_ОтчётБаланс_Свод` ~56 групп Расхождение=Истина по статье «Денежные средства в пути» (ΣABS ≈ 170 М UAH за дек25-апр26)

Архитектурный принцип (по аналогии с `РНДС.ДенежныеСредстваНаличные`): Подразделение в РНДС.ВПути берётся **из шапки документа** (`ДанныеДокумента.Подразделение`).

## Уроки (с разбора 4 пилотов)

### 1. Источник Подразделения — шапка документа

✅ ПРАВИЛЬНО: `ДанныеДокумента.Подразделение` (по аналогии с РНДС.Наличные стр. 1599-1675 ManagerModule ПКО)
❌ НЕПРАВИЛЬНО: `Касса.Подразделение` / `БанковскийСчет.Подразделение` (это текущее значение реквизита, не историческое; пользователь явно указал на эту ошибку в пилоте №1 — переделано)

### 2. Подзапросы `(ВЫБРАТЬ ...)` в SELECT 1С НЕ работают

Урок ПостБезнал блоки 5-6 (курсовые): попытка `(ВЫБРАТЬ ПЕРВЫЕ 1 Д.Подразделение ИЗ Документ.ПостБезнал КАК Д ГДЕ Д.Ссылка = &Ссылка) КАК Подразделение` — FAIL «Синтаксическая ошибка ВЫБРАТЬ».

✅ Альтернативы:
- Добавить колонку в саму временную таблицу (если она формируется в этом же файле — например `ТаблицаКурсовыхРазниц` уже имела `Подразделение`)
- Использовать `ЛЕВОЕ СОЕДИНЕНИЕ` (но усложняет)
- Параметр запроса (требует правки основной процедуры)

### 3. Edit с `replace_all: false` + уникальный контекст

Все 4 пилота — 5+3+3+8 = 19 блоков SELECT с похожей структурой в одном файле. `replace_all: true` ломает соседние блоки. Использовать `replace_all: false` + достаточно строк контекста (WHERE с уникальной ХозОп).

### 4. Структура SELECT отличается между документами

| Документ | Наличие `&ХозяйственнаяОперация` в SELECT | Куда вставлять Подразделение |
|---|---|---|
| ПКО, РКО, ПостБезнал | ДА | перед `&ХозяйственнаяОперация` |
| СписаниеБезнал | НЕТ (только `&СтатьяДвиженияДенежныхСредств`) | перед `&СтатьяДвиженияДенежныхСредств` |

### 5. Безопасность COM-репоста

Зависит от ХозОп документа:
- ✅ **Безопасно для COM**: Конвертация валюты, Перечисление на другой счёт, Поступление с другого счёта, Инкассация (межбанк, без РСКПС/РСППС)
- ⚠ **Только UI**: Оплата поставщику, Поступление оплаты от клиента, Возврат ДС (есть РСКПС/РСППС → memory `feedback_com_repost_skips_registrator_raschetov`)

В pilot_spis_03/pilot_post_03 встроен safety-check (выходит с STOP если есть РСКПС/РСППС движения).

### 6. Закрывать Конфигуратор перед /db-load-xml

При открытом Конфигураторе db-load-xml выдаёт «Ошибка блокировки информационной базы для конфигурирования». Закрыть → повторить.

### 7. /db-update -Dynamic+ применяется мгновенно

После `db-update` уже можно COM-перепроводить документы — новая структура регистра доступна сразу.

### 8. ManagerModule пакет проведения — единый

Когда ОДИН ManagerModule имеет синтаксическую ошибку в SQL — ломается весь пакет проведения. Симптом: COM-репост одного документа падает с ошибкой о синтаксисе из ДРУГОГО файла. Решение: откатить ошибочный файл и проверять каждый отдельно.
