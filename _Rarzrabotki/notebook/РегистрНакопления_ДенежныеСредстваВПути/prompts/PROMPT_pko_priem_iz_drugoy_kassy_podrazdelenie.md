## TL;DR (роль финансиста/бухгалтера баланса)

«Денежные средства в пути» — транзитный (клиринговый) актив между двумя плечами перемещения денег между кассами:
- **РКО «Выдача в другую кассу»** → **Приход** в РН `ДенежныеСредстваВПути` (деньги ушли из кассы-отправителя).
- **ПКО «Поступление из другой кассы»** → **Расход** в РН `ДенежныеСредстваВПути` (деньги дошли в кассу-получатель).

Транзитный остаток сворачивается в ноль **только если оба плеча на ОДНОМ Подразделении = отправителя**. РКО уже проводит Подразделение отправителя (своя шапка). ПКО же проводил Подразделение **получателя** (своя шапка), из-за чего per-Подразделение зависали незакрытые сальдо (+ у отправителя, − у получателя) и сыпались плуги `Расхождение=Истина` в `А_ОтчётБаланс_Свод`.

**Цель:** ПКО должен проводить Подразделение **отправителя** (`А_ПодразделениеОтправитель` = Подразделение парного РКО) в ОБА регистра: `ДенежныеСредстваВПути` (Расход) и `ПрочиеАктивыПассивы` (статья «Денежные средства в пути»).

## Пример (тест-пара)

| Документ | Касса | Подр. шапки | А_ПодразделениеОтправитель | Сумма |
|---|---|---|---|---|
| РКО **N0000052985** (08.12.2025 13:53:50) | 2 Касса Строительство | Строительство | — (нет реквизита) | 800 000 |
| ПКО **N0000023550** (08.12.2025 13:53:51) | Касса Глобино-2 | Глобино-2 | **Строительство** | 800 000 |

Связь: `РКО.КассаПолучатель = ПКО.Касса = Касса Глобино-2`; `РКО.Подразделение = ПКО.А_ПодразделениеОтправитель = Строительство`.

## Три точки доработки

### 1. Проведение в `ДенежныеСредстваВПути` — источник Подразделения
Файл `Documents/ПриходныйКассовыйОрдер/Ext/ManagerModule.bsl`, функция `ТекстЗапросаДенежныеСредстваВПути`, **только БЛОК 1** (ХозОп `ПоступлениеДенежныхСредствИзДругойКассы`, ВидДвижения=Расход). Вместо `ДанныеДокумента.Подразделение КАК Подразделение,`:
```
ВЫБОР
    КОГДА ДанныеДокумента.А_ПодразделениеОтправитель <> ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)
        ТОГДА ДанныеДокумента.А_ПодразделениеОтправитель
    ИНАЧЕ ДанныеДокумента.Подразделение
КОНЕЦ КАК Подразделение,
```
Блоки 2–5 (Инкассация/Конвертация/курсовые) НЕ трогать.

### 2. Заполнение реквизитов отправителя (поиск парного РКО)
Файл `Documents/ПриходныйКассовыйОрдер/Ext/ObjectModule.bsl`:
- Новая экспортная процедура `А_ЗаполнитьПодразделениеОтправителяПоРКО()` — идемпотентна (только при `ХозОп=ПоступлениеДСИзДругойКассы` И незаполненном `А_ПодразделениеОтправитель`), ищет парный РКО и заполняет `А_ДокРасходныйКассовыйОрдерПередачиДенег` + `А_ПодразделениеОтправитель`.
- Вызов добавлен в `ОбновитьПриходныйКассовыйОрдерПослеОбмена()` перед `А_ОбработанКазна = Истина;` (под гардом ХозОп) → новые ПКО из обмена Казны заполняются автоматически.

**Запрос поиска парного РКО (валидирован Rule #-1, 0 ложных пар на 443 ПКО):**
```
ВЫБРАТЬ ПЕРВЫЕ 1
    РКО.Ссылка КАК Ссылка, РКО.Подразделение КАК Подразделение
ИЗ Документ.РасходныйКассовыйОрдер КАК РКО
ГДЕ РКО.Проведен = ИСТИНА
    И РКО.ХозяйственнаяОперация = ЗНАЧЕНИЕ(Перечисление.ХозяйственныеОперации.ВыдачаДенежныхСредствВДругуюКассу)
    И РКО.Организация = &Организация
    И РКО.КассаПолучатель = &КассаПолучатель      // = ПКО.Касса
    И РКО.СуммаДокумента = &СуммаДокумента
    И РКО.Валюта = &Валюта
    И РКО.Дата <= &Дата
    И (НЕ &ОтправительЗаполнен ИЛИ РКО.Касса = &КассаОтправитель)
УПОРЯДОЧИТЬ ПО РКО.Дата УБЫВ
```

### 3. Проекция управленческого баланса — ПАП «в пути» (ГЛАВНАЯ НЕОЧЕВИДНАЯ ТОЧКА!)
Строка `ПрочиеАктивыПассивы` со статьёй «Денежные средства в пути» формируется НЕ из движения ВПути, а проекцией упр.баланса, которая **игнорирует измерение ВПути.Подразделение** и заново берёт Подразделение из шапки документа-регистратора через каскад `МАКСИМУМ(ВЫБОР …)`.
Файл `DataProcessors/ДвиженияАктивовПассивов/Ext/ManagerModule.bsl`, процедура `ДобавитьТекстЗапросаДенежныеСредстваВПути`. В каскад, СРАЗУ ПОСЛЕ ветки `ДокРКО.Подразделение` и ПЕРЕД веткой `ДокПКО.Подразделение`, добавлена приоритетная ветка:
```
КОГДА ДокПКО.А_ПодразделениеОтправитель <> ЗНАЧЕНИЕ(Справочник.СтруктураПредприятия.ПустаяСсылка)
    И ДокПКО.А_ПодразделениеОтправитель ЕСТЬ НЕ NULL
ТОГДА ДокПКО.А_ПодразделениеОтправитель
```
`ДокПКО` уже соединён (`ЛЕВОЕ СОЕДИНЕНИЕ Документ.ПриходныйКассовыйОрдер КАК ДокПКО ПО Т.Регистратор = ДокПКО.Ссылка`). РКО-плечо изолировано: для РКО-регистратора `ДокПКО = NULL` → ветка no-op, работает `ДокРКО.Подразделение`.

> **Урок:** фикс только п.1 (ВПути) НЕдостаточен — verify показал ПАП «в пути» = Глобино-2. ПАП правится отдельно в п.3.
