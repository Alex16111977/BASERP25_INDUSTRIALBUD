# 05. Как дорабатывать

Любая правка идёт по одному маршруту. Порядок обязателен: шаги ловят разные грабли.

## 1. Где править

| Что меняем | Где |
|---|---|
| Логика, шапка, умолчания (BSL) | `_Rarzrabotki/Отчеты/<имя>/Ext/ObjectModule.bsl` (единственный рукописный файл модуля) |
| Запрос | И в BSL `ТекстЗапросаОтчета`, и в Python `otchet_debitorka_statusy_zapros.py::текст_запроса` — **одинаково** |
| Поля, ресурсы, параметры, вариант СКД | `otchet_debitorka_statusy_generate.py::макет_скд` |
| Отборы бухгалтера в варианте | `otchet_debitorka_statusy_otbory.xml` (без ссылочных значений — см. [LESSONS §1](LESSONS.md)) и `ОтборыПоУмолчанию()` в модуле |
| Метаданные отчёта | генератор: `корневой_xml()` — внешний, `корневой_xml_конфигурации()` — встроенный |

Сгенерированные файлы (`Template.xml`, корневые XML, модуль встроенного отчёта) руками не править.

## 2. Проверить запрос до кода (Rule #-1)

```
python _Rarzrabotki/Python/test/otchet_debitorka_statusy_zapros.py
```
Должно быть `OK` для N=3 и N=5, а «строк, где Σинтервалов ≠ Загальна» — 0.

## 3. Сгенерировать исходники

```
python _Rarzrabotki/Python/test/otchet_debitorka_statusy_generate.py
```
Пишет внешнюю копию (`_Rarzrabotki/Отчеты/`) и встроенную (`_Rarzrabotki/BASEBuh/Reports/`) в worktree.
Затем — скопировать в основной каталог `C:\Configuration_downloads\BASERP25` (Rule #4).

Быстрая проверка макета без сборки:
- прочитать `Template.xml` через `СериализаторXDTO.ПрочитатьXML` в базе;
- выполнить `КомпоновщикМакетаКомпоновкиДанных.Выполнить(схема, вариант)`.

## 4а. Внешний `.erf`

```
epf-build.ps1 -InfoBaseServer SQLSERVER -InfoBaseRef bas_industrialbud -UserName cfo -Password 2442 `
  -SourceFile <временный каталог>\<имя>.xml -OutputFile _Rarzrabotki\Отчеты\<имя>.erf
```
- Исходники — во временный каталог: ровно корневой XML и папка, без `.bak`.
- Собирать **только против `bas_industrialbud`**: в ERP нет документов BuhBud.
- «Исключение XDTO при чтении Template.xml» ищется бисекцией копий макета ([LESSONS §2](LESSONS.md)).

## 4б. Встроенный отчёт

1. **Аудит перед загрузкой `Configuration.xml`**: все живые объекты базы (COM `Метаданные.*`) должны быть
   зарегистрированы в `Configuration.xml` основного каталога. Иначе частичная загрузка удалит недостающие.
   Если `Configuration.xml` не меняется — его в список не включать.
2. Частичная загрузка `db-load-xml -Mode Partial`. Если сменились только модуль или макет, в списке достаточно:
   - `Reports/<имя>/Ext/ObjectModule.bsl`;
   - `Reports/<имя>/Templates/ОсновнаяСхемаКомпоновкиДанных.xml` и `.../Ext/Template.xml`;
   - `Reports/<имя>.xml`.
3. `/CheckModules`, затем `db-update -Server`. Открытый Конфигуратор блокирует — попросить закрыть.
4. После загрузки — повторный аудит: число объектов не уменьшилось.

## 5. Обновить вариант в БСП

Если менялись варианты (ключ, представление, состав), без смены версии конфигурации обработчики БСП не запустятся.
Вызвать через COM:
```python
п = bh.NewObject("Структура"); п.Вставить("РазделенныеОбработчики", None)
bh.ВариантыОтчетов.ОперативноеОбновлениеОбщихДанныхКонфигурации(п)
bh.ВариантыОтчетов.ОперативноеОбновлениеРазделенныхДанныхКонфигурации()
```
Проверка — запись отчёта в `Справочник.ВариантыОтчетов` и `Справочник.ПредопределенныеВариантыОтчетов`.

## 6. Приёмка

```
python _Rarzrabotki/Python/test/otchet_debitorka_statusy_priemka.py --config
python _Rarzrabotki/Python/test/otchet_debitorka_statusy_priemka.py            # если пересобирали .erf
```
Итог должен быть «ВСЁ ЗЕЛЁНОЕ».

## 7. Git

- Коммит в рабочей ветке (сообщение на русском), merge в локальный main только файлами ветки.
- **Не коммитить из worktree:** `Configuration.xml` и роли `ДобавлениеИзменениеДанныхБухгалтерии`,
  `ЧтениеДанныхБухгалтерии`. Их актуальные версии живут только в основном каталоге.
- Пользователи видят изменения после перезапуска 1С: обновление БД динамическое.
