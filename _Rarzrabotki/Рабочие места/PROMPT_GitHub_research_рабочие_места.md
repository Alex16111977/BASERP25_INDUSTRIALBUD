## 1. Рабочее определение «Рабочего места» (эталон уровня)

**РМ = самостоятельный объект-приложение** (чаще `ВнешнийОтчёт`/`Обработка`, реже объект конфигурации), у которого главная управляемая форма **не редактирует ОДНУ запись, а оркеструет процесс роли в едином окне**:

- данные живут в реквизитах объекта и его табличных частях («корзина»), а не в одной записи документа;
- форма пакетно формирует/изменяет **цепочку из многих документов** сразу;
- multi-panel master-detail и/или wizard-навигация (`Pages/Page` как шаги);
- тяжёлая логика делегирована в `ManagerModule`/общие модули, форма — тонкий слой оркестрации;
- длительные фоновые операции, программное условное оформление, динамическая перестройка под функц.опции/права.

> Короче: обычная форма = «одна запись, один экран ввода». **РМ = единое окно роли, оркеструющее процесс из многих объектов** с master-detail/wizard, фоновыми расчётами и пакетным формированием документов.

### Таксономия РМ (4 класса — линейка для классификации находок)

| Класс | Суть | Эталоны (типовые) |
|---|---|---|
| **A. Операционный формирователь-«корзина»** | Менеджер роли набирает корзину и одним действием формирует/проводит пакет документов; wizard + master-detail + транзакционный оркестратор | ПомощникПродаж, ОбеспечениеПотребностей |
| **B. Диспетчер-планировщик-визуализатор** | Панель отборов → визуализация в детали (Гант / дерево рейсов) + drag&drop, drill-down, фоновый расчёт, сессионные блокировки | ПооперационноеПланирование2_2, РабочееМестоМенеджераПоДоставке |
| **C. Групповой редактор связанных документов** | Чтение разворачивает группу документов в реквизиты/ТЧ формы, запись сворачивает в массив операций Создать/Изменить/Удалить и транзакционно пишет | РедактированиеПоследовательностиЭтаповПроизводства |
| **D. Служебно-административный инструмент** | РМ администратора над механизмами платформы (обмен, регистрация изменений); универсальный движок над всеми метаданными, динсписки с подменой запроса, version-gated БСП | РегистрацияИзмененийДляОбменаДанными |

### Шкала сложности (tier) — для оценки релевантности

| Tier | Признаки | Брать? |
|---|---|---|
| **1** | Одна форма-обёртка над списком/документом, без master-detail, без фона, без оформления кодом | ❌ отсев (хелло-ворлд) |
| **2** | 1–2 формы, одна таблица + шапка-фильтры, синхрон, минимум оформления, нет wizard/Ганта/дерева | ❌ как правило отсев |
| **3** | **Целевой минимум.** Master-detail из 2 панелей, пакетные действия над выделением, программное условное оформление, 2–3 формы, возможно 1 фоновая операция | ✅ брать |
| **4** | Multi-panel master-detail ИЛИ wizard, неск. вспом. форм, обмен через временное хранилище, оформление кодом, пакетные операции | ✅ приоритет |
| **5** | 4+ форм; модуль формы 6–12 тыс. строк; master-detail+wizard/Гант/дерево; неск. фоновых операций ИЛИ транзакционное создание 10–12 типов документов; делегирование в ManagerModule; блокировки; динамика под опции/права | ✅✅ эталон, разбирать в первую очередь |

> Все 6 наших образцов в `_Rarzrabotki/Рабочие места/` — **tier 5**. Это калибрует планку: примитив отсекаем, целимся в tier 3+.

## 2. «Кирпичики» РМ — что искать в коде и извлекать в базу знаний

При разборе находок ищи и фиксируй как рецепты (с кодом) эти повторяющиеся паттерны:

1. **Wizard на страничных группах** — `Элементы.Страницы.ТекущаяСтраница = Элементы.СтраницаХ`, единая `УстановитьСтраницыПомощника`, «Шаг N из 5», `КнопкаПоУмолчанию` на шаге.
2. **Длительные фоновые операции** — `ДлительныеОперации.ВыполнитьВФоне/ЗапуститьВыполнениеВФоне` + `ПараметрыВыполненияВФоне(УникальныйИдентификатор)` + `ДлительныеОперацииКлиент.ОжидатьЗавершение/ОткрытьФормуДлительнойОперации`; результат через `ПоместитьВоВременноеХранилище`.
3. **Единый диспетчер нескольких фоновых операций** — реквизит `ТекущаяФоноваяОперация` + `Подключаемый_ПроверитьВыполнениеЗадания` ветвит на нужный `Завершен*`; `ПодключитьОбработчикОжидания` с нарастающим интервалом.
4. **Программное условное оформление кодом** — `УсловноеОформление.Элементы.Добавить` с `ПолеКомпоновкиДанных`/`ЭлементОтбораКомпоновкиДанных`/`ГруппаИли` и Оформление (Видимость/ТолькоПросмотр/ЦветФона/Текст/ОтметкаНезаполненного); цвета через `ЦветаСтиля.*` (не XDTO в Form.xml).
5. **Master-detail** — `ПриАктивизацииСтроки` + `ОбработчикОжидания`: активная строка мастера пересчитывает деталь (панель рекомендаций / Гант / товары к доставке).
6. **Динсписки с произвольным запросом** — `ManualQuery=true`, рантайм-подмена `ТекстЗапроса`, сборка с учётом функц.опций.
7. **Программное дерево** (`ValueTree`-реквизит) — из пакетного запроса через `Выборка.СледующийПоЗначениюПоля` вложенными циклами.
8. **СКД внутри формы для отборов** — `РеквизитФормыВЗначение("Объект").ПолучитьМакет(СКД)` → `ИсточникДоступныхНастроекКомпоновкиДанных` → двусторонняя синхронизация простые↔ОтборыКомпоновки.
9. **Обмен между формами** — `ПоместитьВоВременноеХранилище`/`ПолучитьИзВременногоХранилища` по `УникальныйИдентификатор` формы (коллекции не сериализуются в реквизиты).
10. **Пакетные действия над выделением** — `ПолучитьВыделенныеВСпискеСтроки` → массив id → процедура `*НаСервере` (заполнить склад/цены/серии/дату, отметить, провести/отменить выделенные).
11. **Транзакционный оркестратор создания документов** — `НачатьТранзакцию` → отмена проведения старого комплекта → создание N типов → проведение → откат при `Отказ`.
12. **Редактирование группы документов как единого объекта** — развернуть (`ЗаполнитьЗначенияСвойств` по выборкам) / свернуть в массив операций Создать/Изменить/Удалить.
13. **Динамика под функц.опции и права** — десятки `УстановитьВидимость*/УстановитьДоступность*`, `ПолучитьФункциональнуюОпцию`.
14. **Drag&drop** — `НачалоПеретаскивания/ПроверкаПеретаскивания/Перетаскивание/ОкончаниеПеретаскивания` + пересчёт веса/объёма.
15. **Drill-down / расшифровка** — `ДиаграммаГантаОбработкаРасшифровки` (DetailProcessing), навигационные ссылки в форматированных строках-досье, `ОбработкаНавигационнойСсылки`.
16. **Программное добавление колонок/реквизитов формы** — `Форма.ИзменитьРеквизиты` + `ЭлементыФормы.Вставить(Тип("ПолеФормы"))`.
17. **БСП клиент/сервер разделение** — `&НаКлиенте/&НаСервере/&НаСервереБезКонтекста/&НаКлиентеНаСервереБезКонтекста` для переиспользуемой безконтекстной логики.
18. **Сессионные блокировки РМ** — через регистр + `НомерСеанса/НачалоСеанса` (`ПолучитьСеансыИнформационнойБазы` в привилегированном режиме); авто-снятие зависших.
19. **Персистентность состояния** — `ХранилищеНастроекДанныхФорм`/`ХранилищеОбщихНастроек` с `КлючОбъекта/КлючНастроек` и белым списком `СохраняемыеНастройки()`.
20. **Защита при закрытии** — `ПередЗакрытием` с диалогом «Данные изменены. Записать?» + очистка; защитный ранний выход `Если Параметры.Свойство("АвтоТест") Тогда Возврат`.
21. **Интеграция оборудования** — `МенеджерОборудованияКлиент`, `ОбработатьШтрихкоды`, ТСД, карты лояльности.
22. **Интеграция БСП** — `ПодключаемыеКоманды`, `Свойства` (доп.реквизиты), `СозданиеНаОсновании`, печать через `ManagerModule`, version-gated позднее связывание (`Вычислить()`/`Метаданные.ОбщиеМодули.Найти`).
23. **Диаграмма Ганта** — `GanttChartField`, `ПараметрыВывода`, периодичность День/Неделя/Месяц, расшифровка точек.

### Признаки «годного» репозитория/файла (repo_signals)
- Структура исходников: `ExternalReport/<Имя>.xml` + `<Имя>/Ext/ObjectModule.bsl` + `Forms/<Имя>/Ext/{Form.xml, Form/Module.bsl}`; либо `DataProcessors/<Имя>/` с `ManagerModule.bsl` и `Commands/`.
- Корневой тег `<ExternalReport>`/`<DataProcessor>` в `<MetaDataObject>`, `GeneratedType`, `DefaultForm` → управляемая форма.
- Несколько форм; большой `Form.xml` (тысячи строк; `Pages/Page`, `Table`, `ValueTree`, `GanttChartField`).
- BSL-паттерны из §2 в `Module.bsl`.
- Делегирование в крупный `ManagerModule.bsl` или общие модули (`ПродажиСервер`, `ДоставкаТоваров`, `ОбеспечениеСервер`…).
- Дампы типовых конфигураций ИЛИ авторские коллекции с лицензией и `СведенияОВнешнейОбработке`.
- Локализация ru/uk, `Ext/Help/`, `Configuration.xml` version 2.x, BSP-модули в составе.

### Анти-сигналы (отсев)
- Учебные хелло-ворлды (одна форма + кнопка «Выполнить»).
- Обычные печатные формы и простые отчёты на чистом СКД без формы-оркестратора.
- Не-РМ обработки (конвертеры выгрузки/загрузки, разовые скрипты, заполнятели реквизитов без интерактива).
- Штатные формы документа/списка (`BaseForm = ФормаДокумента/ФормаСписка`).
- Репо только с бинарниками `.epf/.erf` без распакованных XML-исходников.
- Курсы/туториалы «Управляемые формы для начинающих», «Гостевая книга», «Записная книжка».
- Расширения (CFE)/патчи методов без собственного РМ; фрагменты кода без структуры объекта.
- Тривиальный wizard из 2 шагов без фона и пакетного создания документов, < 200 элементов формы.

## 5. Скелет базы знаний «Рабочие места 1С: как разрабатывать»

0. Что такое РМ: определение, отличие от формы документа/списка, критерии необходимости (процесс роли, много объектов, фоновые расчёты).
1. Таксономия РМ (A–D) с эталонами.
2. Шкала сложности 1–5 + чек-лист самооценки проектируемого РМ.
3. Архитектурный скелет: ExternalReport/DataProcessor + формы + ObjectModule/ManagerModule + общие модули; куда класть логику (тонкая форма vs движок).
4. Каркас главной формы: wizard на `Pages/Page` ИЛИ multi-panel master-detail; шапка-отборы; командные панели.
5. Master-detail и деталь-визуализация: `ПриАктивизацииСтроки`+обработчик ожидания; панель рекомендаций; программное дерево; Гант + расшифровка.
6. Длительные фоновые операции: `ВыполнитьВФоне`, единый диспетчер `ТекущаяФоноваяОперация`, форма прогресса, отмена, результат через временное хранилище.
7. Обмен между формами и хранение: временное хранилище по UID; реквизиты-ТЧ/деревья; почему не сериализуются коллекции.
8. Программное условное оформление кодом: рецепты (только-просмотр, отметка незаполненного, цвет приоритета/отмены).
9. Динсписки и СКД в форме: ManualQuery + подмена `ТекстЗапроса`, отборы через `ПользовательскиеНастройки`, синхронизация простые↔компоновка.
10. Пакетные операции и интерактив: `ПолучитьВыделенныеВСпискеСтроки`→`*НаСервере`, drag&drop, контекстные команды, drill-down/навигационные ссылки.
11. Транзакционное формирование документов и редактирование группы как единого объекта (развернуть/свернуть).
12. Динамическая адаптация формы: функц.опции и права, перестройка под вид операции, зависимые `СвязиПараметровВыбора`.
13. Интеграции: БСП (`ПодключаемыеКоманды`, Свойства, СозданиеНаОсновании, печать), оборудование, version-gated позднее связывание.
14. Сессионные блокировки, персистентность настроек, защита при закрытии, `АвтоТест`-выход.
15. Сборка/тестирование РМ: `epf-build`/`erf-build`, изоляция источника при stub-cfg, smoke через win32com, грабли выгрузки ExternalReport vs Обработка.

## 6. Формат итогового отчёта исследования

1. **Каталог** (таблица из §3) — все находки tier 3–5.
2. **Топ-N разборов** (tier 4–5) — по §4, с рецептами кода.
3. **Сводный набор рецептов** по «кирпичикам» §2 — наполнение разделов 4–14 базы знаний.
4. **Список «изучить глубже»** — репо/объекты, достойные отдельного прохода.
5. **Честные пробелы** — что не нашлось / где доступ ограничен / какие каналы пустые.
