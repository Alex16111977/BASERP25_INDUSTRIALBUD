## 1. 🚧 Жёсткие правила (метод, проверен)

### 1.1. Токен и поиск (аутентифицированный GitHub Code Search)
- Токен лежит в `C:\Configuration_downloads\BASERP25\.claude\gh_token.txt` (Personal Access Token, classic, для публичного кода scope не нужен). **Не печатать токен в чат/лог.**
- Поиск — через REST API в PowerShell (НЕ через `mcp__github__search_code` — он падает «Requires authentication»):
```powershell
$token = (Get-Content "C:\Configuration_downloads\BASERP25\.claude\gh_token.txt" -Raw).Trim()
$headers = @{ Authorization = "Bearer $token"; "User-Agent" = "research"; Accept = "application/vnd.github+json" }
$q = [uri]::EscapeDataString('Подключаемый_ПроверитьВыполнениеЗадания')   # БЕЗ language-квалификатора
$r = Invoke-RestMethod -Uri "https://api.github.com/search/code?q=$q&per_page=30" -Headers $headers
$r.items | ForEach-Object { $_.repository.full_name + " :: " + $_.path }
Start-Sleep -Seconds 5   # пейсинг ОБЯЗАТЕЛЕН между запросами
```
- **Пейсинг ~5 секунд** между search-запросами — иначе вторичный rate-limit `HTTP 403`. Контроль живости — латинский запрос `setState language:javascript` (даёт сотни тысяч).
- **Кириллица индексируется** (`ВыполнитьВФоне`→1720). НЕ использовать `language:"1C Enterprise"` (обнуляет) и `language:1C-Enterprise` (`422`).
- Чтение деревьев/файлов репо — `mcp__github__get_file_contents` (rate-limit мягкий) и/или WebFetch на `raw.githubusercontent.com`. WebSearch (`site:github.com ...`) — для дискавери по описаниям.

### 1.2. Скачивание
- `git clone --depth 1 https://github.com/<owner>/<repo>.git "C:\Configuration_downloads\BASERP25\_Rarzrabotki\Рабочие места\GitHub\<ИмяПапки>"` — поверхностный клон (экономит место/время; обновление = `git pull`). Репо публичные, авторизация не нужна.
- Если папка проекта уже есть — не клонировать заново, а обновить: `git -C "<путь>" pull --depth 1` (или `git -C "<путь>" fetch --depth 1 && git -C "<путь>" reset --hard origin/<ветка>`).
- В корневой `.gitignore` проекта (`C:\Configuration_downloads\BASERP25\.gitignore`) добавить строку `_Rarzrabotki/Рабочие места/GitHub/` (если ещё нет) — чтобы чужие репо со своими `.git` не попали в коммит основного проекта.
- После каждого клона — доложить размер папки (некоторые конфигурации — сотни МБ).

## 8. Грабли (учесть — из памяти метода)

- `mcp__github__search_code` падает на аутентификации → только REST `/search/code` с токеном из файла.
- Браузерный логин GitHub ≠ API-токен; выемку токена из Credential Manager **не делать** (блокируется). Нужен PAT в файле.
- Кириллица ищется; `language:`-квалификатор ломает/обнуляет; пейсинг 5с против `403`.
- Ложные позитивы по латинским сигнатурам (`GanttChartField` находит TS-проекты типа `nkdk`) — обязательна верификация типа проекта.
- Тяжёлый сетевой Workflow с массой WebFetch **зависает** — поиск/скачивание делать **foreground** последовательно с пейсингом, не распараллеливать на десятки агентов (общий rate-limit не параллелится).
- Полные конфигурации (ERP/УТ/ЗУП) большие — shallow clone обязателен; при нехватке места рассмотреть sparse-checkout только `DataProcessors/`+`Reports/`+`CommonForms/`.
