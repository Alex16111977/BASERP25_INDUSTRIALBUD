## 0. Что такое «Рабочее место» в 1С

**РМ = самостоятельный объект-приложение** (чаще `ВнешнийОтчёт`/`Обработка`, реже объект конфигурации), у которого главная управляемая форма **не редактирует ОДНУ запись, а оркеструет целостный бизнес-процесс роли в едином окне**.

Семь архитектурных отличий от обычной формы документа/списка (выведены из 6 эталонов):

1. **Форма не привязана к одной записи** — данные живут в реквизитах объекта-отчёта/обработки и в табличных частях (часто это «корзина» или цепочка из множества документов сразу).
2. **Multi-panel master-detail** — шапка-отборы/условия + мастер-таблица + деталь (боковая «панель рекомендаций», дерево, диаграмма Ганта); активная строка мастера управляет деталью.
3. **Wizard-навигация** — страничные группы `Pages/Page` как шаги мастера вместо линейной формы.
4. **Оркестрация, а не CRUD** — форма тонкая, тяжёлая логика в `ManagerModule`/общих модулях; результат — транзакционное пакетное создание/изменение/удаление группы документов.
5. **Длительные фоновые операции** — с обработчиком ожидания и формой прогресса для тяжёлых расчётов.
6. **Программное условное оформление и динамическая перестройка формы** под функц.опции/права/вид операции — одна форма обслуживает множество сценариев.
7. **Пакетные действия над выделением, drag&drop, drill-down, интеграция оборудования, сессионные блокировки.**

> Коротко: обычная форма = «одна запись, один экран ввода». **РМ = единое окно роли, оркеструющее процесс из многих объектов** с master-detail/wizard, фоновыми расчётами и пакетным формированием документов.

**Когда нужен РМ (критерии):** (а) пользователь обслуживает целостный процесс роли, а не вводит один документ; (б) задействовано много объектов/документов одновременно; (в) есть тяжёлые расчёты (планирование, обеспечение, прогноз) — кандидаты на фон; (г) нужна визуализация-деталь (дерево/Гант/панель). Если хватает штатной формы документа/списка — РМ не нужен.

## 1. Таксономия РМ (4 класса)

| Класс | Суть | Локальные эталоны |
|---|---|---|
| **A. Операционный формирователь-«корзина»** | Менеджер роли набирает корзину и одним действием формирует/проводит пакет документов; wizard + master-detail + транзакционный оркестратор. Тяжёлая логика — в обработке/общих модулях. | `ПомощникПродаж` (12 типов документов одним действием), `ОбеспечениеПотребностей` (мастер из 5 шагов) |
| **B. Диспетчер-планировщик-визуализатор** | Панель отборов определяет набор данных → визуализация в детали (Гант / 3-уровневое дерево рейсов) с drag&drop, drill-down по расшифровке, фоновым расчётом, сессионными блокировками и фиксацией результата. | `ПооперационноеПланирование2_2` (Гант), `РабочееМестоМенеджераПоДоставке` (дерево рейсов + drag&drop) |
| **C. Групповой редактор связанных документов** | Чтение разворачивает группу документов в реквизиты/ТЧ формы, запись сворачивает обратно в массив операций Создать/Изменить/Удалить и транзакционно пишет (в фоне). | `РедактированиеПоследовательностиЭтаповПроизводства` |
| **D. Служебно-административный инструмент** | РМ администратора над механизмами платформы (обмен, регистрация изменений). Универсальный движок над ВСЕМИ типами метаданных, динсписки с подменой запроса, version-gated БСП через позднее связывание. | `РегистрацияИзмененийДляОбменаДанными` |

Класс выбирают по доминирующему сценарию. Гибриды возможны (напр., A с элементами B).

## 2. Шкала сложности (tier) + чек-лист самооценки

| Tier | Признаки |
|---|---|
| **1** | Одна форма-обёртка над списком/документом; без master-detail, без фона, без оформления кодом |
| **2** | 1–2 формы, одна таблица + шапка-фильтры, синхрон, минимум оформления; нет wizard/Ганта/дерева |
| **3** | **Целевой минимум.** Master-detail из 2 панелей; пакетные действия над выделением; программное условное оформление; 2–3 формы; возможно 1 фоновая операция |
| **4** | Multi-panel master-detail ИЛИ wizard; неск. вспом. форм; обмен через временное хранилище; оформление кодом; пакетные операции (фон опционален) |
| **5** | 4+ форм; модуль формы 6–12 тыс. строк; master-detail + wizard/Гант/дерево; неск. (4–6) фоновых операций ИЛИ транзакц. создание 10–12 типов документов; делегирование в `ManagerModule`; сессионные блокировки; динамика под опции/права |

**Чек-лист проектируемого РМ (поставь tier честно):**
- [ ] Сколько форм? (1 → tier ≤2; 4+ → tier 5)
- [ ] Есть master-detail (активная строка → деталь)?
- [ ] Wizard на `Pages/Page` ИЛИ multi-panel?
- [ ] Есть тяжёлый расчёт → нужен фон?
- [ ] Пакетное создание/проведение документов в транзакции?
- [ ] Программное условное оформление?
- [ ] Динамика под функц.опции/права?
- [ ] Визуализация-деталь (дерево/Гант)?

> Все 6 локальных эталонов — tier 5. Это калибрует планку «как у типовых».

## 3. Архитектурный скелет РМ

```
ВнешнийОтчёт/Обработка «МоёРМ»
├── Ext/ObjectModule.bsl        ← локальный движок (или пусто, если логика в общих модулях)
├── Forms/
│   ├── Форма/                  ← ГЛАВНАЯ форма-оркестратор (тонкая)
│   │   └── Ext/Form/Module.bsl
│   ├── ВыборX/                 ← вспомогательные диалоги-сателлиты
│   └── Настройка/              ← форма параметров РМ
└── (в конфигурации) ManagerModule.bsl ← тяжёлый движок (алгоритм)
```

**Где живёт логика (ключевое правило):**
- **Форма** — тонкий слой UI/оркестрации: обработчики событий, навигация, диалоги, запуск фона, отрисовка.
- **Движок** (`ObjectModule`/`ManagerModule`/общий модуль) — расчёты, запросы, формирование документов. Вызывается из формы и из фоновых заданий.
- Паттерн моста форма↔движок: `ОбъектОбработки = РеквизитФормыВЗначение("Объект")` → вызвать экспортный метод → `ЗначениеВРеквизитФормы(ОбъектОбработки, "Объект")`.

> Эталон тонкой формы: локальная обработка `СозданиеКомплектацийБух` — вся логика в `ObjectModule` (экспорт), форма лишь дёргает `РассчитатьАнализ()`/`ЗаполнитьДокументыПоАнализу()`.

## 4. Каркас главной формы

### 4а. Wizard на страничных группах (`Pages/Page`)
```bsl
&НаКлиенте
Процедура УстановитьСтраницыПомощника(НомерШага)
    Элементы.Страницы.ТекущаяСтраница = Элементы["СтраницаШаг" + НомерШага];
    Элементы.НадписьШаг.Заголовок   = "Крок " + НомерШага + " із 5";
    Элементы.КнопкаНазад.Доступность  = (НомерШага > 1);
    Элементы.КнопкаДалее.Доступность  = (НомерШага < 5);
    // КнопкаПоУмолчанию на каждом шаге — через ОпределитьКнопкуПоУмолчанию(НомерШага)
КонецПроцедуры
```
Применяют `ОбеспечениеПотребностей` (5 шагов), `ПомощникПродаж` (5 панелей `СтраницаПартнер→Корзина→ОплатаОтгрузка→Доставка→Документы`).

### 4б. Multi-panel master-detail
Шапка-отборы (Horizontal) + мастер-таблица + деталь (правая панель / дерево / Гант), несколько командных панелей. Применяют `РабочееМестоМенеджераПоДоставке`, `ПооперационноеПланирование2_2`.

### 4в. Шапка-отборы
Быстрые фильтры с `ChoiceParameters` (только подходящие значения) и зависимыми `СвязиПараметровВыбора`; см. §12.

## 5. Master-detail и деталь-визуализация

### 5а. Деталь по активной строке (через обработчик ожидания)
```bsl
&НаКлиенте
Процедура МастерТаблицаПриАктивизацииСтроки(Элемент)
    // дебаунс: не дёргать сервер на каждый клик при прокрутке
    ПодключитьОбработчикОжидания("ОбновитьДеталь", 0.2, Истина);
КонецПроцедуры

&НаКлиенте
Процедура ОбновитьДеталь()
    ТекСтрока = Элементы.МастерТаблица.ТекущиеДанные;
    Если ТекСтрока <> Неопределено Тогда
        ЗаполнитьПанельРекомендацийНаСервере(ТекСтрока.Номенклатура, ТекСтрока.Склад);
    КонецЕсли;
КонецПроцедуры
```
Эталон: `ОбеспечениеПотребностей` — `ЗапасыПриАктивизацииСтрокиОбработчикОжидания` наполняет «Панель рекомендаций».

### 5б. Программное дерево (`ValueTree`) из пакетного запроса
```bsl
Выборка = Результат.Выбрать(); // плоская выборка, упорядоченная по ключам группировки
Пока Выборка.СледующийПоЗначениюПоля("Задание") Цикл
    ВеткаЗадания = ДеревоРейсов.Строки.Добавить();
    ВеткаЗадания.Задание = Выборка.Задание;
    ВыборкаПунктов = Выборка.Выбрать();
    Пока ВыборкаПунктов.СледующийПоЗначениюПоля("ПунктМаршрута") Цикл
        ВеткаПункта = ВеткаЗадания.Строки.Добавить();
        ВеткаПункта.Пункт = ВыборкаПунктов.ПунктМаршрута;
        // ... листья
    КонецЦикла;
КонецЦикла;
```
Эталон: `РабочееМестоМенеджераПоДоставке` (дерево рейсов Задание→Пункт→строки).

### 5в. Диаграмма Ганта + расшифровка
`GanttChartField`, периодичность День/Неделя/Месяц, обработка расшифровки точек (drill-down) — см. §10. Эталон: `ПооперационноеПланирование2_2`.

## 6. Длительные фоновые операции

### 6а. Запуск
```bsl
&НаСервере
Функция ЗапуститьРасчётВФоне()
    ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор);
    ПараметрыВыполнения.НаименованиеФоновогоЗадания = "Розрахунок";
    Возврат ДлительныеОперации.ВыполнитьВФоне(
        "Обработки.МоёРМ.РассчитатьВФоне", ПараметрыМетода, ПараметрыВыполнения);
КонецФункции
```

### 6б. Ожидание (клиент)
```bsl
&НаКлиенте
Процедура РассчитатьЗавершение(РезультатЗапуска)
    Если РезультатЗапуска = Неопределено Тогда Возврат; КонецЕсли;
    Оповещение = Новый ОписаниеОповещения("ПриЗавершенииОперации", ЭтотОбъект);
    ПараметрыОжидания = ДлительныеОперацииКлиент.ПараметрыОжидания(ЭтотОбъект);
    ДлительныеОперацииКлиент.ОжидатьЗавершение(РезультатЗапуска, Оповещение, ПараметрыОжидания);
КонецПроцедуры
```
Метод фона кладёт результат: `ПоместитьВоВременноеХранилище(Результат, ПараметрыМетода.АдресРезультата)`.

### 6в. Единый диспетчер нескольких фоновых операций
Реквизит `ТекущаяФоноваяОперация` (строка-тип) + один обработчик ветвит на нужный «Завершен*»:
```bsl
&НаКлиенте
Процедура ПриЗавершенииОперации(Результат, ДопПараметры) Экспорт
    Если Результат = Неопределено ИЛИ Результат.Статус = "Отменено" Тогда Возврат; КонецЕсли;
    Если Результат.Статус = "Ошибка" Тогда ОбработатьОшибку(Результат); Возврат; КонецЕсли;
    Если    ТекущаяФоноваяОперация = "Расчёт"  Тогда ЗавершитьРасчёт(Результат.АдресРезультата);
    ИначеЕсли ТекущаяФоноваяОперация = "Запись" Тогда ЗавершитьЗапись(Результат.АдресРезультата);
    ИначеЕсли ТекущаяФоноваяОперация = "Вывод"  Тогда ЗавершитьВывод(Результат.АдресРезультата);
    КонецЕсли;
КонецПроцедуры
```
Эталон: `ПооперационноеПланирование2_2` (4 типа фоновых операций через `Подключаемый_ПроверитьВыполнениеЗадания`, нарастающий интервал `КоэффициентУвеличенияИнтервала=1.2`).

> **Грабли:** результат фона передаётся ТОЛЬКО через временное хранилище по адресу; нельзя возвращать большие структуры напрямую.

### 6г. Реальный референс с GitHub (форма ожидания длительной операции)
Источник: [cpr1c/it · CommonForms/ДлительнаяОперация/Module.bsl](https://github.com/cpr1c/it/blob/main/src/%D0%A1%D0%A0%D0%9C/src/CommonForms/%D0%94%D0%BB%D0%B8%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F%D0%9E%D0%BF%D0%B5%D1%80%D0%B0%D1%86%D0%B8%D1%8F/Module.bsl) (эталонная БСП-форма, CC BY 4.0). Реальный код опроса задания с **растущим интервалом** и корректной отменой:
```bsl
&НаКлиенте
Процедура ПриОткрытии(Отказ)
    Если Параметры.ВыводитьОкноОжидания Тогда
        ИнтервалОжидания = ?(Параметры.Интервал <> 0, Параметры.Интервал, 1);
        ПодключитьОбработчикОжидания("Подключаемый_ПроверитьВыполнениеЗадания", ИнтервалОжидания, Истина);
    КонецЕсли;
КонецПроцедуры

&НаКлиенте
Процедура Подключаемый_ПроверитьВыполнениеЗадания()
    Задание = ПроверитьЗаданиеВыполнено(ФормаЗакрывается); // &НаСервере
    Статус = Задание.Статус;
    Если Статус = "Выполнено" Тогда
        Закрыть(РезультатВыполнения(Задание)); Возврат;
    ИначеЕсли Статус = "Ошибка" Тогда
        Закрыть(РезультатВыполнения(Задание)); Возврат;
    КонецЕсли;
    Если Параметры.Интервал = 0 Тогда                 // адаптивный backoff
        ИнтервалОжидания = Мин(ИнтервалОжидания * 1.4, 15);
    КонецЕсли;
    ПодключитьОбработчикОжидания("Подключаемый_ПроверитьВыполнениеЗадания", ИнтервалОжидания, Истина);
КонецПроцедуры

&НаСервере
Функция ПроверитьЗаданиеВыполнено(ФормаЗакрывается)
    Задание = ДлительныеОперации.ОперацияВыполнена(ИдентификаторЗадания, Ложь,
        Параметры.ВыводитьПрогрессВыполнения, Параметры.ВыводитьСообщения);
    Если Параметры.ПолучатьРезультат И Задание.Статус = "Выполнено" Тогда
        Задание.Вставить("Результат", ПолучитьИзВременногоХранилища(Параметры.АдресРезультата));
    КонецЕсли;
    Если ФормаЗакрывается Тогда
        ДлительныеОперации.ОтменитьВыполнениеЗадания(ИдентификаторЗадания);
        Задание.Статус = "Отменено";
    КонецЕсли;
    Возврат Задание;
КонецФункции
```
Ключевое: интервал опроса не фиксированный, а растёт `×1.4` до 15с (меньше нагрузки на сервер при долгих задачах); при закрытии формы во время выполнения — `ДлительныеОперации.ОтменитьВыполнениеЗадания`. Прогресс показывается через `Задание.Прогресс` (Процент/Текст). Подтверждает наш §6в (диспетчер по `Подключаемый_*`).

## 7. Обмен между формами и хранение данных

- **Между формами** — строго через `ПоместитьВоВременноеХранилище(Значение, УникальныйИдентификатор)` / `ПолучитьИзВременногоХранилища(Адрес)`, привязка к UID вызывающей формы.
- **Коллекции формы (ТЗ/дерево) не сериализуются в реквизиты** → перед помещением: `ДанныеФормыВЗначение(ТаблицаФормы, Тип("ТаблицаЗначений"))` или `РеквизитФормыВЗначение(...)`; обратно — `ЗначениеВДанныеФормы`.
```bsl
ТЗ  = РеквизитФормыВЗначение("МояТаблица");
Адрес = ПоместитьВоВременноеХранилище(ТЗ, УникальныйИдентификатор);
ОткрытьФорму("...Форма", Новый Структура("Адрес", Адрес), ЭтотОбъект);
```
Эталоны: все 6. Универсальный безопасный геттер результата фона: `РезультатРасчётаПоИмени(Адрес, ИмяСвойства, ПоУмолчанию)` с проверкой `ЭтоАдресВременногоХранилища` + `ТипЗнч=Структура` + `.Свойство(...)`.

## 8. Программное условное оформление кодом

```bsl
&НаСервере
Процедура УстановитьУсловноеОформление()
    Элемент = УсловноеОформление.Элементы.Добавить();

    Отбор = Элемент.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
    Отбор.ЛевоеЗначение  = Новый ПолеКомпоновкиДанных("ТабличнаяЧастьОстатков.ПонадНорму");
    Отбор.ВидСравнения   = ВидСравненияКомпоновкиДанных.Больше;
    Отбор.ПравоеЗначение = 0;

    Оформляемое = Элемент.Поля.Элементы.Добавить();
    Оформляемое.Поле = Новый ПолеКомпоновкиДанных("ТЧОПонадНорму");

    Элемент.Оформление.УстановитьЗначениеПараметра("ЦветФона", ЦветаСтиля.ПолеПомеченноеНаУдаление);
КонецПроцедуры
```
Рецепты: цвет по приоритету/отмене; `ТолькоПросмотр`/`Доступность` по правам; `Видимость` (скрыть колонку по варианту оформления); отметка незаполненного обязательного поля (`ОбщегоНазначенияУТ.УстановитьСнятьОтметкуНезаполненного` в УТ/ERP). ## 11. Транзакционное формирование документов / редактирование группы

## 12. Динамическая адаптация формы (функц.опции, права, вид операции)

- `ПолучитьФункциональнуюОпцию(...)` + десятки `УстановитьВидимость*/УстановитьДоступность*`; одна форма обслуживает множество включённых функционалов.

## 14. Блокировки, персистентность, защита при закрытии

- **Сессионные блокировки РМ:** через регистр сведений + `НомерСеанса`/`НачалоСеанса` (`ПолучитьСеансыИнформационнойБазы` в привилегированном режиме); авто-снятие зависших при отмене/закрытии. Эталон: `ПооперационноеПланирование2_2` (`БлокировкиПооперационногоРасписания2_2`).
- **Персистентность состояния:** `ХранилищеНастроекДанныхФорм`/`ХранилищеОбщихНастроек` с `КлючОбъекта`/`КлючНастроек` и белым списком `СохраняемыеНастройки()`.
- **Защита при закрытии:** `ПередЗакрытием` с диалогом «Дані змінено. Записати?» + очистка результатов/блокировок.
- **Защитный ранний выход:** `Если Параметры.Свойство("АвтоТест") Тогда Возврат;` в `ПриСозданииНаСервере` (для программного получения формы анализатором).

## 15. Сборка и тестирование РМ

- Сборка: навыки `epf-build` (.epf) / `erf-build` (.erf) из XML-исходников; форма — `form-compile`/`form-edit`.
- **Изоляция источника при сборке через stub-cfg** (когда Designer держит lock): собирать из изолированного temp (только наша .xml + папка), иначе подхватываются чужие типы. Версия формата stub-cfg 2.17→2.13 под реальную Configuration.xml. См. [epf_build_stub_isolation_gotcha].
- **Грабли XDTO:** `<TextColor>style:...>` в Form.xml внешней обработки валит сборку — цвета задавать кодом. См. [epf_load_xdto_textcolor].
- **Smoke через win32com:** `ВнешниеОбработки.Создать(path, Ложь)`; даты — ставить полдень (pywintypes сдвигает день); кириллич. глоб.функции недоступны через прокси, англ. `String` работает; только Python313. См. [win32com_epf_smoke_gotchas].
- Запросы РМ — сначала Python COM тест, потом в BSL (CLAUDE.md Rule #-1).
